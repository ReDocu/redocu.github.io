## 2. 막히는 상황

어제 게임을 실행하고 방향키를 빠르게 연타해 보자.

**화면 전체가 미친 듯이 깜빡인다.** 그리고 이동이 뚝뚝 끊긴다.

원인은 `system("cls")`다.

```
   system("cls") 가 실제로 하는 일

   ① 새 프로세스(cmd.exe) 생성      ← 무겁다 (수~수십 ms)
   ② cls 명령 실행 → 화면 전체 지움
   ③ 프로세스 종료

   그 사이 화면은 "완전히 빈 상태"가 된다  ← 이게 눈에 보인다 = 깜빡임
```

```
   프레임 1        프레임 2        프레임 3
   ┌────────┐     ┌────────┐     ┌────────┐
   │ 미로   │ ──▶ │        │ ──▶ │ 미로   │ ──▶ ...
   │        │     │ (빈!)  │     │        │
   └────────┘     └────────┘     └────────┘
                      ▲
                      └── 사용자가 이 순간을 본다
```

> **화면을 지우지 않고 갱신하는 방법이 필요하다.** → **커서 이동 방식**

## 3. 개념

### 3-1. 콘솔 커서 제어

**왜 필요한가** — 지우지 않고 **덮어쓰면** 빈 화면 구간이 사라진다.

```c
#include <windows.h>

void GotoXY(int x, int y)
{
    COORD pos = { (SHORT)x, (SHORT)y };
    SetConsoleCursorPosition(GetStdHandle(STD_OUTPUT_HANDLE), pos);
}
```

```
   system("cls") 방식              커서 이동 방식

   ┌──────────┐                   ┌──────────┐
   │ (전부 지움)│  ← 빈 화면 보임   │ 미로     │  ← 같은 자리에
   └──────────┘                   │          │     덮어쓴다
        ▼                          └──────────┘
   ┌──────────┐                   빈 화면 구간이 없다
   │ 미로     │
   └──────────┘
```

```c
// 매 프레임
GotoXY(0, 0);          // 커서를 왼쪽 위로
PrintMap();            // 같은 자리에 다시 그린다 (덮어쓰기)
```

> ⚠️ **덮어쓰기의 함정** — 새로 그리는 내용이 이전보다 **짧으면** 이전 글자가 남는다.
>
> ```
>   이전:  >> 열쇠를 손에 넣었다!
>   지금:  >> 쿵!
>   결과:  >> 쿵!를 손에 넣었다!      ← 이전 글자가 남았다
> ```
>
> **해결** — 출력할 때 뒤를 공백으로 채운다.
>
> ```c
> printf("  %-40s\n", g_message);      // 40칸 폭으로 왼쪽 정렬 → 나머지는 공백
> ```

### 3-2. 커서 숨기기

**왜 필요한가** — 깜빡이는 커서(`_`)가 화면 위를 돌아다니면 지저분하다.

```c
void HideCursor(void)
{
    HANDLE h = GetStdHandle(STD_OUTPUT_HANDLE);
    CONSOLE_CURSOR_INFO info;

    GetConsoleCursorInfo(h, &info);
    info.bVisible = FALSE;              // 커서 숨김
    SetConsoleCursorInfo(h, &info);
}
```

프로그램 시작 시 한 번만 부르면 된다.

### 3-3. 콘솔 창 설정

**왜 필요한가** — 창 크기가 맞지 않으면 스크롤이 생겨 화면이 흔들린다.

```c
void SetupConsole(void)
{
    HideCursor();
    system("mode con cols=60 lines=30");     // 창 크기 고정
    SetConsoleTitleA("미로 탈출");            // 제목
}
```

> `system("mode ...")`도 느리지만 **시작할 때 한 번만** 부르므로 문제없다.
> 매 프레임 부르는 `system("cls")`와는 상황이 다르다.

### 3-4. 깜빡임의 정체 — 미리 알아두기

**왜 필요한가** — 커서 이동으로도 완전히 없어지지는 않는다. 그 이유를 알아두면 Day 37이 쉬워진다.

```
   커서 이동 방식으로도 남는 깜빡임

   printf 로 한 글자씩 그린다  →  그리는 도중의 화면이 보인다

   그린 것:  # # # # #
             # . . P #      ← 여기까지 그린 순간이 화면에 보인다
             (아직 안 그림)

   ★ 문제의 본질은 "중간 과정이 사용자에게 보이는 것"이다
```

| 방식 | 깜빡임 | 원리 |
|---|:--:|---|
| `system("cls")` | 심함 | 화면을 완전히 비운 뒤 그린다 |
| **커서 이동** | 약함 | 덮어쓴다. 하지만 그리는 과정은 보인다 |
| 문자열 버퍼 + 한 번 출력 | 거의 없음 | 다 만들어 두고 `printf` 한 번 |
| **더블버퍼링 (Day 37)** | 없음 | 뒤에서 다 그리고 완성본만 전달 |

> **오늘의 "문자열 버퍼" 방식이 더블버퍼링의 콘솔 버전이다.**
> Day 37에서 WINAPI로 같은 일을 할 때 "아, 그때 그거구나" 하게 된다.

### 3-5. 문자열 버퍼로 한 번에 출력 (선택)

**왜 필요한가** — 깜빡임을 거의 없앤다. 그리고 더블버퍼링의 원리를 미리 체험한다.

```c
void RenderToBuffer(void)
{
    char buffer[4096] = "";                 // 화면 전체를 담을 버퍼
    char line[128];

    for (int y = 0; y < MAP_H; y++)
    {
        strcpy_s(line, sizeof(line), "  ");

        for (int x = 0; x < MAP_W; x++)
        {
            char tile[4];
            if (x == g_playerX && y == g_playerY)
                strcpy_s(tile, sizeof(tile), "P ");
            else
                sprintf_s(tile, sizeof(tile), "%c ", g_map[y][x]);

            strcat_s(line, sizeof(line), tile);
        }

        strcat_s(line, sizeof(line), "\n");
        strcat_s(buffer, sizeof(buffer), line);
    }

    GotoXY(0, 4);
    printf("%s", buffer);                   // ★ 딱 한 번의 출력
}
```

```
   ┌────────────────────────────────────────────┐
   │  buffer (메모리 위의 도화지)                 │
   │                                             │
   │  "  # # # # #\n  # . . P #\n  ..."          │  ← 여기서 전부 조립
   └────────────────────┬───────────────────────┘
                        │ printf 한 번
                        ▼
   ┌────────────────────────────────────────────┐
   │  화면                                       │  ← 완성본만 전달
   └────────────────────────────────────────────┘

   ★ 이것이 더블버퍼링의 발상이다 (Day 37)
```

### 3-6. 스테이지 진행

**왜 필요한가** — 맵 하나로 끝나면 게임이 아니다.

```c
#define STAGE_COUNT 3

char g_stages[STAGE_COUNT][MAP_H][MAP_W + 1] = {
    { "##########", "#P..#....#", /* ... */ },
    { "##########", "#P.......#", /* ... */ },
    { "##########", "#P.#.....#", /* ... */ }
};

int g_currentStage = 0;
```

**스테이지 로드 — 원본을 복사해서 쓴다**

```c
char g_map[MAP_H][MAP_W + 1];              // 작업용 맵

void LoadStage(int index)
{
    for (int y = 0; y < MAP_H; y++)
        strcpy_s(g_map[y], MAP_W + 1, g_stages[index][y]);

    FindPlayerStart();
    g_currentStage = index;
}
```

> ### ⚠️ 원본을 직접 수정하면 재시작이 안 된다
>
> 아이템을 주우면 맵 데이터가 `.`로 바뀐다(Day 14).
> 원본 `g_stages`를 직접 고치면, 재시작해도 아이템이 없다.
>
> ```
>   ✘ g_stages 를 직접 사용  →  한 번 플레이하면 원본이 훼손
>   ✔ g_stages 를 g_map 으로 복사해서 사용  →  원본은 그대로
> ```
>
> **원본 데이터는 읽기 전용으로 두고, 사본을 만들어 쓴다.**
> 이 원칙은 Unity의 프리팹(Day 74), 맵툴의 파일 로드(Day 60)까지 그대로 이어진다.

### 3-7. 경과 시간 측정

**왜 필요한가** — 기록이 있어야 다시 도전할 이유가 생긴다.

```c
#include <time.h>

time_t startTime = time(NULL);              // 시작 시각 기록

// ...

int elapsed = (int)(time(NULL) - startTime);   // 경과 초
printf("경과 %02d:%02d\n", elapsed / 60, elapsed % 60);
```

| 함수 | 단위 | 용도 |
|---|---|---|
| `time(NULL)` | 초 | 경과 시간 (오늘) |
| `clock()` | 밀리초 | 정밀 측정 (Day 21 프레임 제어) |

**✅ 여기까지 실행하면** — 긴 메시지 뒤에 짧은 메시지가 나와도 글자가 섞이지 않는다.

### Step 7 — 결과 화면

```c
void PrintResult(int cleared, int totalMoves, int gems, int elapsed)
{
    system("cls");

    printf("\n╔═══════════════════════════════════╗\n");
    if (cleared)
        printf("║          A L L   C L E A R        ║\n");
    else
        printf("║          G A M E   O V E R        ║\n");
    printf("╚═══════════════════════════════════╝\n\n");

    printf("    스테이지     %d / %d\n", g_currentStage, STAGE_COUNT);
    printf("    총 이동      %d 회\n", totalMoves);
    printf("    보석         %d / %d\n", gems, TOTAL_GEMS);
    printf("    남은 체력    %d / %d\n", g_hp, MAX_HP);
    printf("    소요 시간    %02d:%02d\n\n", elapsed / 60, elapsed % 60);

    // 등급 (Day 10의 등급 판정 재사용)
    if (!cleared)                       printf("    ☆☆☆   다시 도전!\n");
    else if (gems >= TOTAL_GEMS && elapsed < 180) printf("    ★★★   완벽한 기록!\n");
    else if (elapsed < 300)             printf("    ★★☆   좋은 기록!\n");
    else                                printf("    ★☆☆   클리어\n");
}
```

**✅ 여기까지 실행하면** — 1절의 결과 화면이 나온다.

- [ ] 체력이 0이 되면 게임 오버가 나온다
- [ ] 경과 시간이 정확히 표시된다

## 6. 자주 막히는 곳

| 증상 | 원인 | 해결 |
|---|---|---|
| 커서 이동이 안 됨 | `<windows.h>` 누락 | `#include <windows.h>` |
| 이전 글자가 남음 | 새 출력이 더 짧음 | `%-40s` 등 고정 폭 출력 |
| 화면이 아래로 밀림 | 출력이 창 높이보다 큼 | `mode con lines=30` 으로 창 확대 |
| 재시작해도 아이템이 없음 | **원본 배열을 직접 수정** | 사본(`g_map`)에 복사해서 사용 |
| 스테이지 전환 후 좌표가 이상함 | `FindPlayerStart()` 미호출 | `LoadStage`에서 호출 |
| 특수문자(♥ ╔)가 깨짐 | 콘솔 인코딩 | UTF-8 저장 + `SetConsoleOutputCP(65001)`, 또는 ASCII로 대체 |
| 시간이 항상 0 | `startTime` 갱신 위치 | 게임 시작 시 한 번만 기록 |
| 여전히 깜빡임 | 커서 이동 방식의 한계 | 문자열 버퍼 방식 시도. 완전 해결은 Day 37 |
| `strcpy_s`에서 크래시 | 대상 크기 부족 | `MAP_W + 1` 확인 |
