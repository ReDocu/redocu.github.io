## 3. 빌드와 배포

웹판은 빌드가 없다. `index.html`을 더블클릭해도 돌고, 로컬 서버(`python -m http.server`)로 열면 정밀 판정 모드로 돈다(7.1).

itch 업로드 파일은 스크립트 하나로 만든다.

```text
python -X utf8 build-itch.py           # 둘 다
python -X utf8 build-itch.py web       # dist/duorbit-web-itch.zip
python -X utf8 build-itch.py win       # dist/duorbit-win.zip
```

| 판 | 내용 |
|---|---|
| 웹 | `index.html`이 zip 루트. `css/` · `js/` · `sound/`만 담는다 |
| 윈도우 | PyInstaller로 `DUORBIT/DUORBIT.exe`를 만든다. 파이썬·pygame·ffmpeg 설치 불필요 |

- **zip 경로는 항상 `/`로 기록한다.** itch 서버는 리눅스라 `\` 경로면 파일을 못 찾는다. PowerShell `Compress-Archive`는 버전에 따라 `\`로 기록해서 쓰지 않는다.
- **윈도우판에 ffmpeg를 넣지 않는다.** 데스크톱판은 원래 첫 실행 때 ffmpeg로 곡을 분석해 `charts/`에 캐시한다. 빌드 때 이 캐시 10곡분을 번들에 구워 넣으면 분석 단계를 아예 건너뛴다. 곡당 0.4~1.5초이던 첫 로딩 대기도 같이 사라진다. 플레이어 기록 파일(`_records.json`)은 번들에서 뺀다.
- **배포판은 `%LOCALAPPDATA%\DUORBIT`에 쓴다.** exe 옆은 Program Files처럼 쓰기가 막힌 자리일 수 있다. 읽기는 사용자 폴더 → 번들 순서다.

itch 프로젝트 설정은 뷰포트 960×640 이상(곡 선택 화면 높이 약 680 px), SharedArrayBuffer 끄기, 생성형 AI 공개는 Sound 체크로 정했다.

## 4. 세 모드 구조

| 모드 | 입력 | 판정 기준 |
|---|---|---|
| 오빗 | 아무 키 / 터치 (원버튼) | 각도 |
| 폴 | `D F J K` / 화면 4분할 터치 | 시간 (ms) |
| 스위치 | 곡 중간에 오빗 ↔ 폴이 바뀐다 | 구간의 모드를 따른다 |

### 4.1 단일 진행 스트림

세 모드가 같은 판정 코어를 쓴다. 채보는 모드와 상관없이 "타일 배열 + 타일별 모드(`modeOf`)"이고, 엔진은 다음 타일 하나만 본다. 그래서 사망 · 체크포인트 · 콤보 · 기록이 모드를 가리지 않고 한 줄로 이어지고, 스위치 모드는 모드가 섞인 채보일 뿐 별도 엔진이 아니다.

- 판정 창을 벗어나면 사망하고, 마지막 체크포인트에서 다시 시작한다.
- 체크포인트는 구간 경계에 놓이고, 스위치 모드에서는 전환 경계에 우선 배치한다.
- 전환 2박 전에 예고음과 배너를 띄우고, 전환 직후엔 판정 창을 1.5배로 넓힌다.

### 4.2 오빗: 각도가 곧 박자

두 노드가 서로를 축으로 번갈아 공전한다. 고정된 노드를 중심으로 다른 노드가 반 바퀴(180°) 도는 데 1박이 걸리고, 다음 타일 방향에 닿을 때 입력한다.

```text
대기 박자 = 회전각 ÷ 180°
  90° → 반 박 · 180° → 1박 · 270° → 1.5박
```

그래서 채보는 "각도 배열"이고, 오빗 판정은 시간이 아니라 각도 오차로 잰다.

## 5. 채보 생성: 음원 온셋 분석

처음엔 장르 프로파일로 패턴을 이어 붙이는 절차 생성이었고, 같은 날 음원을 직접 분석해 음이 시작되는 자리(온셋)에 노트를 놓는 방식으로 바꿨다. 절차 생성은 온셋을 얻을 수 없을 때(7.1의 폴백 모드) 쓰는 대체 수단으로 남아 있다.

### 5.1 온셋 검출

```text
모노 PCM → 프레임 에너지 (창 1024 · 홉 512 = 약 11.6 ms)
  → 에너지 증가분(플럭스) 곡선
  → 피크: 주변 20프레임 평균 × 1.6을 넘고, 직전 피크와 70 ms 이상 떨어진 것
  → 피크 주변 3점 파라볼릭 보간으로 프레임 사이 시각까지 정밀화
```

보간은 프레임 해상도 11.6 ms의 양자화를 줄이려고 넣었다. 넣은 뒤 1/4박 그리드와의 편차 중앙값이 20~40 ms로, 대부분 폴 PERFECT 창(±45 ms) 안에 든다.

### 5.2 템포 추정

- **BPM:** 플럭스 곡선의 자기상관에서 70~190 BPM 범위의 최댓값 lag를 고른다. 매니페스트의 기본 BPM과 그 2배 · 절반 · 1.5배 근처에 가중을 줘 옥타브 오류를 줄인다.
- **오프셋:** 플럭스를 비트 주기로 접어 에너지가 가장 큰 위상을 첫 박으로 잡는다.

템포는 다음 순서로 정한다.

```text
싱크 측정(사용자 실측) > 매니페스트 실측 고정값 > 온셋 자동 추정 > 기본 BPM
```

4막 4곡은 자동 추정이 맞히지 못해 실측 BPM/오프셋을 매니페스트에 박아 뒀다. lag가 정수라 낼 수 있는 BPM이 띄엄띄엄해서다(4-1은 실측 88.0인데 추정은 178.2). 고정값이 쓰이면 HUD에 `실측템포`로 표시한다.

### 5.3 난이도

온셋을 난이도별 그리드에 스냅하고, 강도 상위만 남겨 목표 밀도에 맞춘다.

| 난이도 | 그리드 | 목표 밀도 | edm-02 오빗 타일 수 |
|---|---|---|---|
| 초급 | 8분음표 | 2.2 노트/초 | 433 |
| 중급 | 16분음표 | 3.4 노트/초 | 615 |
| 고급 | 16분음표 | 5.2 노트/초 | 892 |

기록은 모드 × 난이도별로 따로 저장하고, 해금은 난이도를 가리지 않는다.

### 5.4 스위치 세그먼트

스위치 모드는 오빗 · 폴 채보를 구간 단위로 이어 붙인다. 막이 올라갈수록 전환이 잦아진다.

| 막 | 전환 주기 |
|---|---|
| 1막 | 96박 (24마디) |
| 2막 | 64박 (16마디) |
| 3막 | 48박 (12마디) |
| 4막 | 32박 (8마디) |

## 6. 오빗 경로 배치

온셋 채보를 그대로 펼치면 경로가 자기 자신 위로 겹쳐 지나간다. 회전각(박자)은 바꾸지 않고, 타일마다 **공전 방향(시계/반시계)만** 골라 경로를 펼친다. 박자는 그대로이고 지형만 바뀐다.

```text
타일 간격 64 px · 비인접 타일 최소 44.8 px · 타일 ↔ 비인접 경로선 최소 32 px

for 각 타일:
  후보 = 시계 / 반시계
  미리보기(앞 16타일, 앞이 빽빽하면 48타일)로 국소적으로 이어질 수 없는 후보를 거른다
  남은 후보를 목표 방향 · 여유 공간 순으로 정렬해 깊이우선 탐색
  막히면 → 최심점으로 되돌아가기 → 노트 솎기 → 강행
```

- **목표 방향:** 전체 진행 방향이 96박 주기로 ±55° 굽이치고, 근처 기존 타일에서 멀어지는 반발을 더한다. 넓게 굽이치는 큰 맵이 나온다.
- **노트 솎기:** 어떤 방향을 골라도 겹칠 수밖에 없는 빽빽한 16분 연타는 48타일 창을 12타일씩 밀며 미리 검사해 노트 1개를 앞 노트와 합친다. 곡당 0~1개다.
- **검증:** 파이썬판 결과에서 비인접 타일 간 최소 거리 49 px, 교차 0을 확인했다.
- **비용과 캐시:** 웹판은 곡 · 모드 · 난이도마다 40~120 ms 걸려 세션 메모리(`LAYOUT_CACHE`)에 캐시하고, 재도전은 약 2 ms다. 박 배열이 커서 localStorage엔 넣지 않는다. 데스크톱판은 `charts/<곡>.json`에 구워 둔다.
- 방향이 뒤집히는 타일에는 `↺`(데스크톱판은 작은 고리)를 표시한다.

## 7. 타이밍과 판정

판정과 공전 애니메이션은 모두 `AudioContext.currentTime`(오디오 장치의 DSP 클록)을 기준으로 계산한다. 화면 프레임 시각은 쓰지 않는다.

| 판정 | 오빗 (각도) | 폴 (시간) |
|---|---|---|
| PERFECT | ±30° | ±45 ms |
| GOOD | ±50° | ±90 ms |
| BARE | ±65° | ±130 ms |

### 7.1 두 가지 재생 모드

| 모드 | 조건 | 방식 |
|---|---|---|
| buffer | HTTP로 열었을 때 (itch 포함) | `fetch` + `decodeAudioData`로 통째 디코드 → `AudioBufferSourceNode` |
| element | `file://` 더블클릭 (fetch가 막힘) | `<audio>` 엘리먼트 재생 + 매 프레임 DSP 클록과 drift 보정 |

element 모드의 drift 보정:

```text
drift = 오디오 재생 위치 − DSP 클록 기준 예상 위치
  |drift| > 60 ms  → 재생 위치를 예상 위치로 강제 이동
  |drift| > 20 ms  → 재생 속도 0.97 / 1.03으로 서서히 흡수
```

element 모드는 PCM에 접근할 수 없어 온셋 분석을 못 하고, 절차 생성 채보로 내려간다. HUD에 `audio폴백`과 채보 출처(온셋/절차)를 표시한다.

### 7.2 캘리브레이션과 싱크 스튜디오

- **캘리브레이션:** 첫 실행 때 메트로놈에 맞춰 8번 탭해 기기 입력 지연을 잰다.
- **싱크 스튜디오(`S`):** 곡을 들으며 12번 이상 탭하면 BPM과 오프셋을 추정하고, 버튼으로 미세 조정해 곡별로 저장한다.

데스크톱판은 `time.perf_counter()` 클록에 `pygame.mixer.music.play(start=...)`로 맞춘다.

## 8. 소리

음원 외의 효과음은 파일이 없다. 전부 Web Audio 오실레이터와 노이즈 버퍼로 그때그때 합성한다(데스크톱판은 numpy로 합성).

| 효과음 | 합성 |
|---|---|
| 메트로놈 클릭 | 사각파 880 Hz (강박 1320 Hz) |
| 판정 | 삼각파 — PERFECT 990 · GOOD 740 · BARE 520 Hz |
| 실수 | 톱니파 220 → 70 Hz 하강 + 7 kHz 하이패스 노이즈 |
| 전환 예고 | 사각파 1560 Hz 두 번 |
| 완주 | 삼각파 도 · 미 · 솔 · 도 아르페지오 |

4막 4곡 중 3곡은 생성 도구의 3분 상한에 걸려 곡이 끊겨 있어서, 끝 3초에 선형 페이드아웃을 구워 넣었다. 원본은 `sound_original/`에 두고 재적용 절차(ffmpeg `afade`)를 데스크톱판 README에 적었다.

## 9. 테스트와 AUTO 검증

자동 테스트 스위트는 없다. 대신 커밋마다 그 변경을 확인하는 검증을 돌리고 결과를 커밋 메시지에 남겼다.

| 검증 | 방법 |
|---|---|
| 웹 ↔ 데스크톱 채보 일치 | edm-02 오빗 타일 · 반전 · 솎기 수: 초급 433 · 178 · 0, 중급 615 · 393 · 0, 고급 892 · 779 · 1로 일치 |
| 데스크톱 스모크 | headless로 초기화 → 채보 로드 → 판정 → 결과 도달, 화면별 PNG 렌더 확인 |
| ffmpeg 없는 배포판 | ffmpeg를 PATH에서 뺀 채 10곡 × 3모드 × 3난이도 = 90개 채보 전부 생성 |
| itch 임베드 | 다른 오리진의 960×540 iframe에서 실행, 콘솔 오류 0 |
| 화면 잘림 | 960×540 · 960×640 · 640×480 · 390×700에서 곡 선택 화면 잘림 0 px |
| 모바일 | 390×844 터치 에뮬레이션에서 타이틀 → 캘리브레이션 → 오빗 · 폴 입력 |

**AUTO 모드**는 게임이 각 타일의 정확한 시각에 직접 입력해 전부 PERFECT로 플레이하는 검증 도구다. 소리를 들으며 판정 연출이 음악 비트에 얹히는지 귀로 확인한다. headless 시간 가속으로 세 모드 모두 578타일 100% PERFECT · 사망 0 · 완주를 확인했다.

- 오토는 곡 선택에서 켜고, 플레이 중에는 바꿀 수 없다.
- 웹판은 오토 결과를 기록에 남기지 않는다. 곡 해금이 앞 곡 클리어로 이어지는데, 항상 100%인 오토를 저장하면 해금 사슬이 무의미해진다.

## 10. 저장

웹판은 localStorage 키 하나(`duorbit.v1`)에 JSON으로 저장한다.

| 항목 | 내용 |
|---|---|
| 기록 | 곡 × 모드 × 난이도별 클리어 여부 · 최고 정확도 · 최대 콤보 · 노미스 여부 |
| 캘리브레이션 | 입력 지연 값 |
| 싱크 | 곡별 BPM · 오프셋 (사용자 실측) |
| 분석 캐시 | 곡별 자동 추정 BPM · 오프셋 · 온셋 목록 (재분석 회피) |
| 설정 | 테스트 해금 · 마지막 난이도 |

데이터 스키마는 v2다. 난이도가 없던 v1 저장본은 처음 열 때 자동 변환해 기존 기록을 중급으로 옮기고, 캘리브레이션 · 싱크 · 해금은 그대로 둔다.

## 11. 알려진 제한

- **음원 라이선스 확인 필요.** 10곡 모두 Suno로 생성했다. 상업 이용 조건은 출시 가이드의 확인 항목으로 남아 있다.
- **모바일 메모리.** 디코드한 PCM을 곡마다 캐시하고 해제하지 않아 10곡을 다 들으면 약 635 MB가 상주한다. 모바일 Safari에서는 탭이 종료될 수 있다.
- **템포 추정의 해상도.** 자기상관 lag가 정수라 BPM이 띄엄띄엄하게만 나온다. 4막 4곡은 실측 고정값으로 우회했다.
- **스윙 곡.** 그리드가 균등해서 재즈 곡은 온셋과 그리드 편차가 크다.
- **경로 배치 캐시는 세션 한정.** 웹판은 새로고침하면 다시 계산한다(곡당 40~120 ms).
- **`file://` 실행은 정밀도가 낮다.** `<audio>` 폴백은 drift 보정을 해도 디코드 방식보다 느슨하고, 채보도 절차 생성으로 내려간다.
- **웹판과 데스크톱판의 차이.** 캘리브레이션 · 싱크 스튜디오 · 순차 곡 해금은 웹판에만 있고, 데스크톱판은 오토 결과도 기록한다.
