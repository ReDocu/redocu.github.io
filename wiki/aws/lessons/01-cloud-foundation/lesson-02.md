## ① 학습 목표

이 강을 마치면 이렇게 할 수 있습니다.

- 루트 사용자가 왜 위험한지 설명하고, **루트에 MFA를 걸어 봉인**할 수 있다.
- 일상 작업용 **관리자 IAM 사용자**를 만들고 계정 별칭으로 로그인할 수 있다.
- **AWS Budgets로 3단계 예산 알림**을 걸고 실제로 메일을 받아 볼 수 있다.
- Cost Explorer와 비용 할당 태그로 **내 비용을 스스로 추적할 준비**를 마칠 수 있다.
- 내 계정에 적용된 **프리 티어 정책 유형을 콘솔에서 직접 확인**할 수 있다.

## ② 왜 필요한가

AWS에서 초보자가 겪는 사고는 대부분 두 종류입니다.

**사고 1 — 키가 유출되어 남이 내 계정으로 서버를 켠다**

실제로 자주 벌어지는 일입니다. 액세스 키를 실수로 GitHub 공개 저장소에 올리면, **자동 스캔 봇이 수 분 안에 찾아냅니다.** 공격자는 전 세계 리전에 고성능 인스턴스를 수십 대 띄워 암호화폐를 채굴합니다. 하루만 지나도 수천 달러가 청구됩니다.

**사고 2 — 내가 켜 두고 잊는다**

더 흔합니다. 실습으로 만든 NAT Gateway 하나를 지우지 않고 방학을 보내면 **월 $42**, 두 달이면 $84입니다. 아무도 쓰지 않은 서비스에 대한 요금입니다.

두 사고의 공통점은 **"알아차렸을 때는 이미 늦었다"** 는 것입니다. AWS는 사용을 막지 않습니다. 청구서는 다음 달에 옵니다.

그래서 오늘 할 일은 딱 두 가지입니다.

```
① 문을 잠근다   — 루트 MFA + IAM 사용자로 작업 (사고 1 대비)
② 알람을 단다   — Budgets 3단계 알림       (사고 2 대비)
```

**이 두 가지는 리소스를 만들기 전에 끝내야 합니다.** 그래서 아직 서버 한 대 만들어 보지 않은 지금, 두 번째 강에서 합니다.

## ③ 개념 설명

### 루트 사용자란 무엇이고 왜 위험한가

**루트 사용자**는 계정을 만들 때 쓴 이메일 주소로 로그인하는 주체입니다. 이 계정에는 **권한이라는 개념 자체가 적용되지 않습니다.**

| 루트만 할 수 있는 일 | 루트로 하면 안 되는 일 |
|---|---|
| 계정 이름·이메일·루트 비밀번호 변경 | **평소의 모든 작업** |
| 결제 수단 변경, 계정 해지 | 서버 생성·삭제 |
| IAM 사용자의 결제 정보 접근 허용 | 파일 업로드 |
| 특정 S3/SQS 정책 오류 복구 | 개발·테스트 |
| 일부 서비스의 계정 수준 설정 | |

> **루트는 "금고 열쇠"이지 "출입문 열쇠"가 아닙니다.**
> 매일 쓰는 문은 IAM 사용자로 열고, 금고는 필요할 때만 엽니다.

루트가 유출되면 **권한을 회수할 방법이 없습니다.** IAM 사용자라면 정책을 떼거나 비활성화하면 되지만, 루트는 그럴 대상이 아닙니다. 그래서 **MFA(다중 인증)** 를 걸어 비밀번호만으로는 못 들어오게 만듭니다.

### IAM 사용자 · 그룹 · 정책 (맛보기)

[03강](lesson-03.md)에서 자세히 다루지만, 오늘 필요한 만큼만 먼저 봅니다.

```
 ┌─ 루트 사용자 ──────────────────┐   ← MFA 걸고 봉인
 │  (이메일로 로그인)              │
 └────────────────────────────────┘
            │ 만든다
            ▼
 ┌─ IAM 사용자 "admin" ───────────┐   ← 앞으로 여기로 로그인
 │  · 콘솔 로그인 + MFA            │
 │  · 정책: AdministratorAccess    │
 └────────────────────────────────┘
```

| 용어 | 뜻 |
|---|---|
| **IAM 사용자** | 사람 한 명에 대응하는 로그인 주체 |
| **그룹** | 사용자 묶음. 정책을 그룹에 붙이면 소속 사용자 전원에게 적용 |
| **정책(Policy)** | 무엇을 허용/거부할지 적은 JSON 문서 |
| **`AdministratorAccess`** | 거의 모든 작업을 허용하는 AWS 관리형 정책 |

> ⚠️ 이번 강에서는 학습 편의상 `AdministratorAccess`를 사용합니다. **실무에서는 최소 권한이 원칙**이며, [04강](lesson-04.md)에서 좁히는 방법을 배우고 최종 프로젝트에서는 이 정책 사용이 **감점 대상**입니다.

### 비용을 감시하는 3개의 도구

| 도구 | 하는 일 | 언제 보나 |
|---|---|---|
| **AWS Budgets** | 정해 둔 금액/사용량에 도달하면 **알림 발송** | 사전 경고. 이 과정의 핵심 안전장치 |
| **Cost Explorer** | 지난 비용을 **서비스별·태그별·일별로 분석** | 사후 분석. 매주 확인 |
| **Cost Anomaly Detection** | 평소와 다른 급증을 **자동 탐지** | 예상 못 한 사고 감지 |

> 🔴 **가장 중요한 사실 — Budgets는 "알림"이지 "차단"이 아닙니다.**
> 예산 $10을 걸어도 AWS가 $10에서 서비스를 멈춰 주지 않습니다. 메일이 올 뿐입니다.
> **알림을 받으면 사람이 직접 지워야 합니다.** 그래서 알림 메일을 실제로 받아 보는 것까지가 오늘 실습입니다.

### 비용 할당 태그

리소스에 붙이는 이름표입니다. 태그가 없으면 Cost Explorer에서 **"EC2에 $8 썼다"** 까지만 알 수 있고, **"어느 실습에서 썼는지"** 는 알 수 없습니다.

이 과정에서는 모든 리소스에 아래 3개를 붙입니다.

| 태그 키 | 값 예시 | 용도 |
|---|---|---|
| `Project` | `aws-course` | 이 과정 리소스만 골라 보기 |
| `Owner` | `hong-gildong` | 팀 실습에서 누구 것인지 |
| `Week` | `W04` | 어느 주차 실습인지 |

> 태그를 만든 뒤 **Billing 콘솔에서 "비용 할당 태그"로 활성화**해야 비용 분석에 나타납니다. 활성화 이후 데이터부터 집계되므로 **지금 켜 두는 것**이 중요합니다.

### 프리 티어의 세 종류 (다시)

[01강](lesson-01.md)에서 본 내용을 콘솔에서 직접 확인합니다.

| 유형 | 예 |
|---|---|
| 12개월 무료 | EC2 750시간/월, RDS 750시간/월, S3 5GB |
| 상시 무료 | Lambda 100만 요청/월, DynamoDB 25GB |
| 평가판 | 일부 서비스 단기 체험 |

## ④ 단계별 실습

> **이번 강도 리소스를 만들지 않습니다. 비용 $0.**
> 대신 **앞으로 16주간 내 계정을 지켜 줄 장치**를 답니다. 이 강의 산출물은 과제로 제출합니다.

### Step 1. AWS 계정 만들기 (이미 있다면 Step 2로)

`aws.amazon.com` → **AWS 계정 생성**.

| 입력 | 주의 |
|---|---|
| 이메일 | **본인이 매일 확인하는 주소.** 비용 알림이 여기로 옵니다 |
| 계정 이름 | 나중에 바꿀 수 있습니다 |
| 결제 정보 | 신용/체크카드 필요. 확인용으로 **$1 정도가 임시 승인**됐다가 취소됩니다 |
| 본인 확인 | 휴대폰 SMS 또는 음성 통화 |
| 지원 플랜 | **기본 지원 – 무료(Basic)** 선택 |

> ⚠️ **회사·학교 계정으로 실습하지 마세요.** 실수로 운영 리소스를 건드릴 수 있고, 권한도 제한되어 있습니다.
> 카드가 없다면 강사에게 문의하세요(교육용 계정 발급 또는 크레딧 지원 방안이 있을 수 있습니다).

가입이 끝나면 **오른쪽 위 리전을 아시아 태평양(서울) `ap-northeast-2`** 로 바꿉니다.

### Step 2. 루트 계정에 MFA 걸기 — 가장 중요한 5분

스마트폰에 인증 앱을 먼저 설치합니다. (Google Authenticator, Microsoft Authenticator, Authy 등 아무거나)

**작업 흐름**

1. 콘솔 오른쪽 위 **계정 이름 → 보안 자격 증명(Security credentials)**
2. **다중 인증(MFA)** 영역 → **MFA 디바이스 할당**
3. 디바이스 이름 입력 → **인증 관리자 앱(Authenticator app)** 선택
4. 화면의 **QR 코드를 앱으로 스캔**
5. 앱에 뜨는 **연속된 두 개의 6자리 코드**를 순서대로 입력 (한 번에 하나씩, 30초 간격)
6. **MFA 추가**

**확인 방법 — 반드시 해 보세요.**

로그아웃한 뒤 다시 루트로 로그인합니다. 비밀번호 입력 후 **MFA 코드를 묻는 화면**이 나오면 성공입니다.

```
 로그인 화면
 ┌────────────────────────────┐
 │ 이메일  : me@example.com    │
 │ 비밀번호: ********          │
 └────────────────────────────┘
            ↓
 ┌────────────────────────────┐
 │ 다중 인증                   │   ← 이 화면이 나오면 성공
 │ MFA 코드: [ 4 8 2 9 1 7 ]  │
 └────────────────────────────┘
```

> 🔴 **인증 앱이 설치된 휴대폰을 잃어버리면 로그인할 수 없습니다.**
> 대비책: ① 인증 앱의 **백업/클라우드 동기화 기능**을 켜 두거나 ② **MFA 디바이스를 2개 등록**(휴대폰 + 노트북 앱)해 두세요. AWS는 루트에 **최대 8개**의 MFA 디바이스를 허용합니다.
> 이미 잃어버렸다면 등록된 이메일과 전화로 **계정 복구** 절차를 밟아야 하며 시간이 걸립니다.

### Step 3. 관리자 IAM 사용자 만들기

이제 루트를 봉인하고 **일상 작업용 사용자**를 만듭니다.

**작업 흐름**

1. 콘솔에서 `IAM` 검색 → **사용자(Users)** → **사용자 생성**
2. 사용자 이름: `admin` (또는 본인 영문 이름)
3. **AWS Management Console에 대한 사용자 액세스 권한 제공** 체크
   - **IAM 사용자를 생성하고 싶음** 선택
   - 콘솔 비밀번호: 사용자 지정 비밀번호
   - **다음 로그인 시 새 비밀번호를 생성해야 합니다** 체크 해제(혼자 쓰는 계정이면)
4. 권한 설정 → **직접 정책 연결** → `AdministratorAccess` 선택
5. 생성 완료 → **로그인 URL을 반드시 저장**

```
https://123456789012.signin.aws.amazon.com/console
                  ↑ 내 12자리 계정 ID
```

**계정 별칭(alias) 설정** — 12자리 숫자 대신 기억하기 쉬운 이름을 씁니다.

IAM 대시보드 오른쪽의 **AWS 계정 → 계정 별칭 → 생성**에서 예를 들어 `hong-aws-lab` 을 입력하면 로그인 주소가 이렇게 바뀝니다.

```
https://hong-aws-lab.signin.aws.amazon.com/console
```

**이 사용자에도 MFA를 겁니다.** IAM → 사용자 → `admin` → **보안 자격 증명** 탭 → MFA 디바이스 할당. 절차는 Step 2와 같습니다.

**확인** — 로그아웃 후 위 URL로 접속해 `admin` 으로 로그인합니다. 오른쪽 위 사용자 표시가 이렇게 바뀝니다.

```
admin @ hong-aws-lab
```

> ✅ **오늘부터 이 사용자로만 작업합니다.** 루트는 결제 정보 변경 등 꼭 필요할 때만 씁니다.

### Step 4. 예산 알림 3단계 걸기 — 이 과정의 안전벨트

> 📌 결제(Billing) 화면은 **루트로 로그인**하거나, 루트에서 **"IAM 사용자의 결제 정보 액세스"를 허용**해야 보입니다.
> 루트로 로그인 → 계정(Account) 페이지 → **IAM 사용자/역할의 결제 정보 액세스** → 편집 → **IAM 액세스 활성화**.
> 이 설정은 루트만 할 수 있습니다. 지금 한 번 해 두면 이후로는 계속 `admin` 으로 볼 수 있습니다.

**작업 흐름** — 콘솔에서 `Billing and Cost Management` 검색 → 왼쪽 메뉴 **예산(Budgets)** → **예산 생성**

**① 첫 번째 예산 (경고선)**

| 항목 | 값 |
|---|---|
| 예산 유형 | **비용 예산(Cost budget)** |
| 예산 이름 | `aws-course-warning-5usd` |
| 기간 | 월별(Monthly) |
| 예산 갱신 유형 | 반복 예산 |
| 예산 금액 | **5** USD (고정) |
| 알림 임계값 | 실제 비용이 **80%** 초과 시 |
| 이메일 수신자 | 본인 메일 |

**② 두 번째·세 번째 예산**도 같은 방식으로 만듭니다.

| 이름 | 금액 | 임계값 | 의미 |
|---|---|---|---|
| `aws-course-warning-5usd` | $5 | 실제 80% | "정상 범위를 벗어나기 시작했다" |
| `aws-course-alert-10usd` | $10 | 실제 100% | "무언가 켜져 있다. 확인하라" |
| `aws-course-stop-20usd` | $20 | **예측(Forecasted) 100%** | "이번 달 한도 초과 예상. 즉시 조치" |

> 💡 세 번째는 **"예측 비용"** 기준으로 겁니다. 실제 금액이 도달하기 **전에** 추세를 보고 미리 알려 주기 때문에 가장 유용합니다.

**알림이 실제로 오는지 확인하기**

가장 확실한 방법은 **일부러 낮은 예산을 하나 더 만드는 것**입니다.

| 이름 | 금액 | 임계값 |
|---|---|---|
| `test-alert-0.01usd` | **0.01** USD | 실제 1% |

이미 세금이나 소액 사용이 있다면 몇 시간 안에 메일이 옵니다.

```
받은 편지함:
  발신: AWS Budgets <no-reply@budgets.alerts.amazonaws.com>
  제목: AWS Budgets: test-alert-0.01usd has exceeded your alert threshold

  AWS Budget Notification  August 13, 2026
  AWS Account 123456789012

  You requested that we alert you when the ACTUAL Cost associated with
  your test-alert-0.01usd budget is greater than $0.00 for the current month.
  The ACTUAL Cost associated with this budget is $0.02.
```

메일을 확인했다면 **이 테스트 예산은 삭제**합니다. (기본 2개 예산까지 무료, 3개부터 예산당 월 $0.02)

⚠️ 메일이 스팸함으로 갈 수 있습니다. `budgets.alerts.amazonaws.com` 을 허용 목록에 넣어 두세요.

### Step 5. Cost Explorer · 비용 할당 태그 · 프리 티어 확인

**① Cost Explorer 활성화**

Billing 콘솔 → **Cost Explorer** → **Cost Explorer 시작**.
처음 켜면 **데이터 준비에 최대 24시간**이 걸립니다. 지금 켜 두면 내일부터 볼 수 있습니다.

**② 비용 할당 태그 활성화**

Billing 콘솔 → **비용 할당 태그(Cost allocation tags)** → **사용자 정의 태그** 탭.

지금은 태그를 붙인 리소스가 없어 목록이 비어 있을 수 있습니다. [06강](lesson-06.md)에서 첫 리소스에 `Project` 태그를 붙인 뒤, 하루쯤 지나 이 화면에 나타나면 **활성화**를 눌러 주세요.

**③ 프리 티어 확인 — 오늘의 핵심 확인 작업**

Billing 콘솔 → **프리 티어(Free tier)**.

내 계정이 어떤 방식인지 확인합니다.

```
[유형 A — 기존 12개월 프리 티어 계정]
서비스        프리 티어 사용량        사용량         남은 기간

S3           5 GB                    0 GB           2027-08-13 까지
RDS          750 시간/월             0 시간         2027-08-13 까지

[유형 B — 크레딧 기반 무료 플랜 계정]
남은 크레딧: $100.00 / 만료일: 2027-02-13
```

**④ 비밀번호 정책 강화 (선택)**

IAM → **계정 설정** → 비밀번호 정책 편집. 최소 길이 12자, 대소문자·숫자·기호 포함 권장.

## ⑤ 자주 하는 실수

### 결제 정보 화면이 IAM 사용자에게 안 보인다

```
액세스 거부됨 (Access Denied)
결제 및 비용 관리 콘솔에 액세스할 권한이 없습니다.
You don't have permission to access billing information.
```

**원인** — `AdministratorAccess` 를 붙였더라도, **계정 수준에서 "IAM 사용자의 결제 정보 액세스"가 꺼져 있으면** 볼 수 없습니다. 이 스위치는 루트만 켤 수 있습니다.
**해결** — **루트로 로그인** → 오른쪽 위 계정 이름 → **계정(Account)** → 아래쪽 **IAM 사용자/역할의 결제 정보 액세스** → **편집** → **IAM 액세스 활성화** 체크 → 업데이트.

### MFA 코드를 넣었는데 계속 틀렸다고 나온다

```
MFA 코드가 잘못되었습니다. 다시 시도하십시오.
The MFA code is invalid. Please try again.
```

**원인 3가지**

| 원인 | 해결 |
|---|---|
| 두 코드를 **동시에** 입력했다 | 첫 코드 입력 → **30초 기다렸다가** 바뀐 코드를 두 번째 칸에 |
| 휴대폰 **시간이 어긋났다** | 휴대폰 설정에서 **시간 자동 설정**을 켠다 (TOTP는 시각 기반) |
| 앱에 **다른 계정**의 코드를 봤다 | 앱에서 계정 이름을 확인 |

### 액세스 키를 만들어 두고 잊는다

**증상** — 몇 주 뒤 "누군가 내 계정에서 인스턴스를 만들었다"는 알림.
**원인** — 콘솔 로그인만 필요한데 습관적으로 액세스 키까지 발급하고 파일에 남겨 둔 경우.
**해결** — **지금 당장 IAM → 사용자 → 보안 자격 증명 → 액세스 키 목록**을 확인하고 안 쓰는 키는 삭제합니다.
**예방** — 이 과정에서 액세스 키는 [05강](lesson-05.md) CLI 실습에서 한 번만 만듭니다. 그 외에는 만들지 않습니다.

### 예산 알림을 걸어 두고 "이제 안전하다"고 생각한다

**원인** — Budgets는 **차단이 아니라 통보**입니다. 알림이 와도 리소스를 지우는 것은 사람의 몫입니다.
**해결** — 알림 메일을 받으면 **그 자리에서** Cost Explorer로 원인 서비스를 찾고 리소스를 정리합니다.
**보강** — 정말로 차단하고 싶다면 SNS + Lambda로 리소스를 자동 정지시키는 구성이 필요합니다([30강](../04-final-project/lesson-30.md)에서 야간 자동 축소로 다룹니다).

### 알림 메일이 오지 않는다

**원인** — 스팸함으로 갔거나, 예산 임계값에 아직 도달하지 않았거나, 이메일 주소 오타.
**해결** — ① 스팸함 확인 ② Budgets 상세 화면의 **알림(Alerts)** 탭에서 임계값과 주소 재확인 ③ 예산의 "현재 지출"이 임계값을 넘었는지 확인.
**주의** — 비용 데이터는 **실시간이 아닙니다.** 사용 후 반영까지 보통 **몇 시간~24시간**이 걸립니다.

### 루트로 계속 작업한다

**원인** — IAM 사용자로 다시 로그인하는 게 번거로워서.
**결과** — 루트 세션이 탈취되면 방어 수단이 없습니다. AWS 보안 점검(IAM 대시보드)에서도 계속 경고가 뜹니다.
**해결** — 브라우저에 **IAM 사용자 로그인 URL을 북마크**해 두세요. 클릭 한 번이면 됩니다.

```
https://<내-계정-별칭>.signin.aws.amazon.com/console
```

## ⑥ 확인 문제

**1.** 예산 $10 알림을 걸어 두었습니다. 어느 날 실수로 큰 인스턴스를 켜 두어 하루 만에 $50이 발생했습니다. AWS는 $10에서 자동으로 리소스를 멈춰 주었을까요?

<details>
<summary>답 보기</summary>

**아니요. 멈추지 않습니다.** AWS Budgets는 **알림(notification) 기능**일 뿐입니다.

- $10에 도달하면 **메일이 발송**됩니다.
- 그동안에도 인스턴스는 계속 돌아가고 **$50까지 그대로 청구**됩니다.
- 게다가 비용 데이터 반영에 **수 시간 지연**이 있어, 메일을 받았을 때는 이미 더 쌓여 있을 수 있습니다.

**따라서 진짜 안전장치는 세 겹입니다.**

| 겹 | 수단 |
|---|---|
| 1차 | Budgets 알림 → **사람이 즉시 확인** |
| 2차 | 매 실습 종료 시 **정리 체크리스트 수행** |
| 3차 | 자동화 — 예산 초과 시 SNS→Lambda로 리소스 정지, 조직이라면 SCP로 고가 리소스 사전 차단 |

> 이 과정에서 2차(정리 체크리스트)를 매 강 끝에 두는 이유가 여기 있습니다.
</details>

**2.** 다음 작업 중 **반드시 루트로 해야 하는 것**을 모두 고르세요.

```
㉮ EC2 인스턴스 생성
㉯ 결제 수단(카드) 변경
㉰ IAM 사용자에게 결제 정보 접근 허용
㉱ S3 버킷 생성
㉲ AWS 계정 해지
```

<details>
<summary>답 보기</summary>

**㉯ · ㉰ · ㉲** 가 루트 전용입니다.

| 작업 | 루트 필요 | 이유 |
|---|---|---|
| ㉮ EC2 생성 | ❌ | IAM 권한으로 가능 |
| ㉯ 결제 수단 변경 | ✅ | 계정 소유권 관련 |
| ㉰ IAM 결제 접근 허용 | ✅ | **계정 수준 스위치**, 루트만 조작 가능 |
| ㉱ S3 버킷 생성 | ❌ | IAM 권한으로 가능 |
| ㉲ 계정 해지 | ✅ | 계정 소유권 관련 |

**판별법** — **"계정 그 자체"에 대한 작업**(소유권·결제·해지·계정 수준 스위치)만 루트입니다. **리소스에 대한 작업**은 전부 IAM으로 합니다.
</details>

**3.** 후배가 "프리 티어 계정이라 아무리 써도 돈 안 나와요"라고 합니다. 어떤 점을 알려 주어야 할까요? 세 가지를 드세요.

<details>
<summary>답 보기</summary>

**① 프리 티어에 아예 포함되지 않는 서비스가 있다.**
NAT Gateway(월 약 $42) · ALB(월 약 $17) · ECS Fargate · KMS 고객 관리 키(월 $1) · WAF(월 $5~). 이들은 만드는 순간부터 시간당 과금됩니다.

**② 포함된 서비스도 한도가 있다.**
EC2는 월 **750시간**입니다. 인스턴스 1대를 24시간 켜면 월 730시간으로 딱 맞지만, **4대를 켜면 약 8일 만에 소진**되고 그다음부터 과금됩니다.

**③ 기간이 있다.**
12개월 무료 항목은 **계정 생성 12개월 뒤 전액 과금**으로 전환됩니다. (2025년 7월 이후 계정은 크레딧 기반 플랜이라 소진/만료 시점이 다릅니다.)

**추가로 알려 줄 것** — 중지(stop)한 인스턴스도 **EBS 볼륨과 탄력적 IP는 계속 과금**됩니다. "꺼 놨으니 괜찮다"가 통하지 않습니다.

**결론 한 줄** — *"프리 티어는 '무료 계정'이 아니라 '무료 한도'입니다. 한도 밖은 그냥 유료예요."*
</details>

## 오늘의 정리

| 개념 | 핵심 |
|---|---|
| 루트 사용자 | 권한 개념이 없는 최고 주체. **MFA 걸고 봉인** |
| IAM 사용자 | 일상 작업용 로그인 주체. 여기에도 MFA |
| 계정 별칭 | 12자리 숫자 대신 쓰는 로그인 주소 |
| **AWS Budgets** | 금액 도달 시 **알림**. 차단이 아님. 2개까지 무료 |
| Cost Explorer | 지난 비용을 서비스·태그·일별로 분석. **켜는 데 최대 24시간** |
| 비용 할당 태그 | `Project` `Owner` `Week` — 활성화 이후 데이터부터 집계 |
| 프리 티어 | 12개월 / 상시 / 평가판 (또는 크레딧 기반 플랜). **콘솔 화면이 정답** |

**한 장 요약**

```
  루트 (MFA 봉인)
    └─ IAM 사용자 admin (MFA) ──▶ 여기로 매일 로그인
                                    │
   Budgets $5 / $10 / $20(예측) ────┘ 알림이 오면 사람이 지운다
   Cost Explorer + 태그 3종   ────── 매주 어디에 썼는지 확인
```

**오늘 반드시 기억할 한 가지**
> **AWS는 사용을 막아 주지 않습니다.** 알림은 오지만 멈추는 것은 내 몫입니다.
> 그래서 이 과정의 모든 강은 **정리 체크리스트로 끝납니다.**

**과제**
1. **보안 기준선 증빙 3장** 제출 — ① 루트 MFA 활성화 화면 ② `admin` 사용자로 로그인한 화면(오른쪽 위 표시 포함) ③ Budgets 목록 3개
2. **프리 티어 화면 캡처**와 함께 "내 계정에 적용된 무료 정책 유형"을 한 줄로 설명하세요.
3. 예산 알림 메일을 **실제로 수신한 화면**을 캡처하세요. (테스트 예산 $0.01 활용, 확인 후 삭제)
4. IAM 대시보드 **보안 권장 사항**에 경고가 하나도 없는 화면을 캡처하세요.
5. 로그인 URL을 브라우저에 북마크하고, 다음 강부터는 **루트로 로그인하지 않겠다고** 스스로 약속하세요.
