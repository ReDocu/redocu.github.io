## ① 학습 목표

이 레슨을 마치면 이렇게 할 수 있습니다.

- 기울기(gradient)가 "손실을 줄이는 방향"임을 손계산과 대조해 설명할 수 있다.
- `requires_grad` · `backward()` · `grad.zero_()` 의 역할을 알고 경사하강 루프를 짤 수 있다.
- **선형 회귀를 바닥부터** 구현해 sklearn과 같은 답에 수렴시킬 수 있다.
- 학습률이 크면 발산하고, **스케일링이 수렴 속도를 좌우함**을 실험으로 보일 수 있다.

## ② 왜 필요한가

대단원 03에서 `fit()` 은 마법 상자였습니다. 오늘 그 상자를 엽니다.

[Day 053](../03-machine-learning/day-053.md)에서 우리는 "MSE의 골짜기 바닥이 최적"임을 보고,
sklearn이 그 바닥을 **공식으로 한 번에** 찾는다고 했습니다. 그런데 신경망에는 그런 공식이
없습니다 — 골짜기가 수백만 차원이고 구불구불해서, 유일한 방법은 **걸어 내려가는 것**입니다.

```
경사하강: 지금 자리에서 가장 가파른 내리막 방향(기울기의 반대)으로 한 걸음씩
```

이 "걷기"에 필요한 것이 매 걸음의 기울기인데, 수백만 파라미터의 미분을 손으로 할 수는
없습니다. PyTorch의 **autograd**가 이걸 대신합니다 — 연산을 기록해 뒀다가 `backward()`
한 줄로 전부 미분해 줍니다. 오늘 이 엔진을 가장 작은 문제(파라미터 1개)부터
낯익은 문제(오늘 pm25 → 내일 pm25)까지 몰아 봅니다. **내일부터의 신경망은 오늘 루프에
레이어만 갈아 끼운 것**입니다.

## ③ 개념 설명

### 기울기 — 손실 계기판의 바늘

파라미터 w를 아주 조금 키웠을 때 손실이 얼마나 변하는가 — 그것이 기울기 `dloss/dw` 입니다.

```
기울기 > 0  →  w를 키우면 손실 증가  →  w를 줄여라
기울기 < 0  →  w를 키우면 손실 감소  →  w를 키워라
                    ⇒ 항상 "기울기의 반대 방향"으로:  w ← w − 학습률 × 기울기
```

학습률(learning rate)은 보폭입니다 — [Day 059](../03-machine-learning/day-059.md)의 부스팅에서
만난 그 η와 같은 역할이고, 오늘 그 보폭이 너무 클 때 무슨 일이 나는지 직접 봅니다.

### autograd 3종 세트

| 코드 | 하는 일 |
|---|---|
| `w = torch.tensor(3.0, requires_grad=True)` | "이 텐서로 가는 연산을 전부 기록하라" |
| `loss.backward()` | 기록을 거꾸로 타고 내려가며 모든 기울기 계산 → `w.grad` 에 저장 |
| `w.grad.zero_()` | 기울기 초기화 — **backward는 기울기를 누적**하므로 매 걸음 지워야 함 |

그리고 파라미터를 갱신하는 순간은 `with torch.no_grad():` 로 감쌉니다 —
"이 갱신 자체는 기록하지 마라"(기록하면 다음 미분이 오염됩니다).

### 학습 루프의 원형 — 오늘 외울 다섯 줄

```
① pred = 모델(x)               순전파
② loss = 손실(pred, y)         채점
③ loss.backward()              미분 (역전파)
④ 파라미터 -= lr × grad        갱신
⑤ grad.zero_()                 초기화
```

이 다섯 줄이 W16–18의 모든 학습, 그리고 세상 모든 딥러닝 프레임워크의 심장입니다.
주간 체크포인트("5단계를 코드 없이 말할 수 있는가")가 바로 이것입니다.

### Step 1. autograd 첫 만남 — 손계산과 대조 (1교시)

```python
# day077_autograd.py — autograd와 경사하강
import pandas as pd
import torch

torch.manual_seed(42)

print("== A. autograd 첫 만남: 미분을 대신 해 준다 ==")
w = torch.tensor(3.0, requires_grad=True)
loss = (w - 5.0) ** 2          # w=5에서 최소가 되는 손실
loss.backward()                # 미분 실행
print(f"loss = (w-5)²,  w=3.0 에서의 기울기 dloss/dw = {w.grad.item()}")
print("(손계산: 2(w-5) = 2(3-5) = -4 — 일치. 음수 = w를 키우면 손실이 준다)")
```

실행 결과:

```
== A. autograd 첫 만남: 미분을 대신 해 준다 ==
loss = (w-5)²,  w=3.0 에서의 기울기 dloss/dw = -4.0
(손계산: 2(w-5) = 2(3-5) = -4 — 일치. 음수 = w를 키우면 손실이 준다)
```

우리가 한 일은 손실을 **정의**한 것뿐입니다. 미분(2(w−5))은 autograd가 연산 기록에서
스스로 만들어 냈습니다 — 파라미터가 백만 개라도 `backward()` 는 여전히 한 줄입니다.

### Step 2. 경사하강 한 걸음씩 (2교시)

```python
print("\n== B. 경사하강 한 걸음씩 ==")
w = torch.tensor(0.0, requires_grad=True)
lr = 0.1
for step in range(1, 6):
    loss = (w - 5.0) ** 2
    loss.backward()
    with torch.no_grad():
        w -= lr * w.grad
    w.grad.zero_()
    print(f"  step {step}: w = {w.item():.3f}  (목표 5.0)")
```

실행 결과:

```
== B. 경사하강 한 걸음씩 ==
  step 1: w = 1.000  (목표 5.0)
  step 2: w = 1.800  (목표 5.0)
  step 3: w = 2.440  (목표 5.0)
  step 4: w = 2.952  (목표 5.0)
  step 5: w = 3.362  (목표 5.0)
```

0에서 출발해 5를 향해 걷습니다. 걸음 폭이 점점 주는 것도 보세요 — 바닥에 가까울수록
기울기(2(w−5))가 작아지므로 **자동으로 감속**합니다. 경사하강의 우아한 성질입니다.

### Step 3. 진짜 문제 — 낯익은 회귀를 바닥부터 (3~4교시)

[Day 053](../03-machine-learning/day-053.md)의 "오늘 pm25 → 내일 pm25"를 autograd로 다시 풉니다.
그때 sklearn이 공식으로 찾은 답은 **기울기 0.770 · 절편 6.09** 였습니다. 걸어서 도착해 봅시다.

```python
print("\n== C. 진짜 문제: 오늘 pm25 → 내일 pm25 선형 회귀 ==")
df = pd.read_csv("data/air_daily.csv", parse_dates=["date"])
d = df.dropna(subset=["pm25"])
tr = d[d.date < "2026-01-01"]
x = torch.tensor(tr["pm25"].to_numpy(), dtype=torch.float32)
y = torch.tensor(tr["pm25_next"].to_numpy(), dtype=torch.float32)
print(f"train {len(x)}행 · sklearn의 답(Day 053): 기울기 0.770 · 절편 6.09")

w = torch.zeros(1, requires_grad=True)
b = torch.zeros(1, requires_grad=True)
lr = 0.0005                       # pm25 스케일(~수십)이라 작게
for epoch in range(1, 2001):
    pred = w * x + b
    loss = ((pred - y) ** 2).mean()          # MSE — Day 053에서 손으로 만든 그 골짜기
    loss.backward()
    with torch.no_grad():
        w -= lr * w.grad
        b -= lr * b.grad
    w.grad.zero_(); b.grad.zero_()
    if epoch in (1, 10, 100, 500, 2000):
        print(f"  epoch {epoch:>4}: w={w.item():.3f}  b={b.item():.3f}  MSE={loss.item():.2f}")

print(f"\n최종: 내일 ≈ {w.item():.3f} × 오늘 + {b.item():.2f}")
```

실행 결과:

```
== C. 진짜 문제: 오늘 pm25 → 내일 pm25 선형 회귀 ==
train 2741행 · sklearn의 답(Day 053): 기울기 0.770 · 절편 6.09
  epoch    1: w=0.771  b=0.026  MSE=792.01
  epoch   10: w=0.973  b=0.040  MSE=41.49
  epoch  100: w=0.970  b=0.102  MSE=41.40
  epoch  500: w=0.961  b=0.373  MSE=41.04
  epoch 2000: w=0.931  b=1.285  MSE=39.93

최종: 내일 ≈ 0.931 × 오늘 + 1.28
```

**어라 — 2,000걸음을 걸었는데 아직 (0.770, 6.09)에 도착하지 못했습니다.** MSE는 거의 다
내려왔는데(39.93 vs 최적 약 37) 절편 b가 6.09를 향해 **기어가고** 있습니다 (0.03 → 1.29).
버그가 아닙니다. x(pm25)가 평균 27쯤에서만 움직여서 골짜기가 한쪽으로 길쭉하게 찌그러져
있고, w와 b가 서로를 상쇄하며 좁은 협곡을 지그재그로 내려가는 중입니다. 처방은 Step 5에서.

### Step 4. 학습률을 키우면 — 발산 (5교시)

"수렴이 느리면 보폭을 키우면 되지 않나?" 6배로 키워 봅니다 (0.0005 → 0.003).

```python
print("\n== D. 학습률이 너무 크면 — 발산 ==")
w = torch.zeros(1, requires_grad=True)
b = torch.zeros(1, requires_grad=True)
lr = 0.003
for epoch in range(1, 5):
    pred = w * x + b
    loss = ((pred - y) ** 2).mean()
    loss.backward()
    with torch.no_grad():
        w -= lr * w.grad
        b -= lr * b.grad
    w.grad.zero_(); b.grad.zero_()
    print(f"  epoch {epoch}: w={w.item():.1f}  MSE={loss.item():.0f}")
```

실행 결과:

```
== D. 학습률이 너무 크면 — 발산 ==
  epoch 1: w=4.6  MSE=792
  epoch 2: w=-12.7  MSE=10616
  epoch 3: w=52.4  MSE=149037
  epoch 4: w=-192.1  MSE=2099370
  → 골짜기를 뛰어넘으며 튕겨 나간다 (학습률 6배에 발산)
```

네 걸음 만에 MSE가 792 → 2,099,370. 보폭이 골짜기 폭보다 크면 반대편 벽에 더 높이 부딪히며
**튕겨 나갑니다.** DL 학습에서 loss가 nan/inf로 치솟으면 십중팔구 이 현상입니다.

### Step 5. 표준화 — 골짜기를 둥글게 (6~7교시)

느린 수렴(Step 3)과 발산(Step 4)의 공통 원인은 **찌그러진 골짜기**입니다.
x를 표준화하면 골짜기가 둥글어져 어느 방향으로나 같은 보폭으로 걸을 수 있습니다.

```python
print("\n== E. 표준화하고 다시 — 골짜기가 둥글어진다 ==")
mu, sigma = x.mean(), x.std()
xs = (x - mu) / sigma                     # 평균 0, 표준편차 1
w = torch.zeros(1, requires_grad=True)
b = torch.zeros(1, requires_grad=True)
lr = 0.1                                  # 표준화 덕에 큰 걸음도 안전
for epoch in range(1, 301):
    pred = w * xs + b
    loss = ((pred - y) ** 2).mean()
    loss.backward()
    with torch.no_grad():
        w -= lr * w.grad
        b -= lr * b.grad
    w.grad.zero_(); b.grad.zero_()
    if epoch in (1, 10, 100, 300):
        print(f"  epoch {epoch:>3}: w={w.item():.3f}  b={b.item():.3f}  MSE={loss.item():.2f}")

# 표준화 좌표의 (w, b)를 원래 단위로 되돌리면?
w_orig = w.item() / sigma.item()
b_orig = b.item() - w.item() * mu.item() / sigma.item()
print(f"\n원래 단위로 환산: 기울기 {w_orig:.3f} · 절편 {b_orig:.2f}")
print("sklearn의 답(0.770 · 6.09)과 일치 — 300걸음 만에 도착")
```

실행 결과:

```
== E. 표준화하고 다시 — 골짜기가 둥글어진다 ==
  epoch   1: w=1.485  b=5.290  MSE=792.01
  epoch  10: w=6.631  b=23.609  MSE=50.88
  epoch 100: w=7.430  b=26.449  MSE=37.28
  epoch 300: w=7.430  b=26.449  MSE=37.28

원래 단위로 환산: 기울기 0.772 · 절편 6.04
sklearn의 답(0.770 · 6.09)과 일치 — 300걸음 만에 도착
```

같은 문제, 학습률은 오히려 **200배 크게** — 그런데 100걸음 만에 완전 수렴했고,
원래 단위로 환산하니 sklearn의 답이 나왔습니다. 오늘의 두 결론:

1. **경사하강은 공식과 같은 바닥에 도착합니다** — fit()의 마법이 걷기였음을 확인.
2. [Day 053](../03-machine-learning/day-053.md)에서 "선형 회귀엔 스케일링이 성능을 안 바꾼다"고
   했지만, **경사하강으로 풀 때는 스케일링이 수렴 자체를 좌우**합니다. 신경망에서 입력 정규화가
   선택이 아니라 필수인 이유가 이것입니다.

## ⑤ 자주 하는 실수

### grad.zero_()를 잊음

**증상** — 에러 없음. 그런데 학습이 이상하게 과격해지다 발산.
**원인** — `backward()` 는 기울기를 **누적**합니다(+=). 안 지우면 이전 걸음들의 기울기가 계속 합산되어 보폭이 눈덩이처럼 커집니다.
**해결** — 갱신 직후 반드시 `zero_()`. 내일 배울 optimizer는 `optimizer.zero_grad()` 한 줄로 전 파라미터를 지워 줍니다.

### backward를 같은 그래프에 두 번 호출

```
RuntimeError: Trying to backward through the graph a second time (or directly access saved tensors after they have already been freed).
```

**원인** — backward는 미분을 마치면 연산 기록을 지웁니다(메모리 절약). 같은 loss로 또 부르면 기록이 없습니다.
**해결** — 매 걸음 손실을 **다시 계산**하고 backward하세요 (루프 구조가 원래 그렇게 생겼습니다). 특수한 경우가 아니면 `retain_graph=True` 로 덮지 마세요.

### 갱신을 no_grad 없이 함

**증상** — `w -= lr * w.grad` 에서 `RuntimeError: a leaf Variable that requires grad is being used in an in-place operation` 또는 이상한 미분 값.
**원인** — 갱신 연산 자체가 기록에 들어가 다음 미분을 오염시키려 하기 때문입니다.
**해결** — 갱신은 `with torch.no_grad():` 블록 안에서. "학습(미분 대상)과 갱신(관리 작업)은 다른 세계"라는 표시입니다.

### 손실이 nan/inf로 치솟는데 코드를 의심함

**증상** — epoch 몇 번 만에 `MSE=inf` 또는 `nan` — "버그인가?" 하고 코드를 뒤짐.
**원인** — 대부분 Step 4의 발산입니다: 학습률 과대 또는 입력 미정규화.
**해결** — 먼저 lr을 1/10로, 그리고 입력 표준화를 확인. 그래도 nan이면 데이터에 이미 nan이 있는지 (`torch.isnan(x).any()`) 확인 순서로.

### (n,)과 (n,1)의 뺄셈으로 손실이 이상해짐

**증상** — loss가 내려가긴 하는데 값이 이상하게 크고 결과도 엉망.
**원인** — `pred` 가 `(n,1)`, `y` 가 `(n,)` 이면 `pred - y` 가 브로드캐스팅으로 **(n, n) 행렬**이 됩니다 ([Day 076](day-076.md) ⑤의 그 함정). 3,570² 개의 엉뚱한 차이를 평균 낸 것이 손실이 됩니다.
**해결** — 손실 계산 직전 `pred.shape == y.shape` 를 assert. 내일부터는 `y.unsqueeze(1)` 또는 `pred.squeeze(1)` 로 통일하는 관용구를 씁니다.

① 순전파 `pred = w * x + b` → ② 손실 `loss = ((pred - y) ** 2).mean()` → ③ 역전파 `loss.backward()`
→ ④ 갱신 `w -= lr * w.grad` (no_grad 안) → ⑤ 초기화 `w.grad.zero_()`.
내일부터는 ①이 `model(x)`, ④⑤가 `optimizer.step()` / `optimizer.zero_grad()` 로 바뀔 뿐 구조는 동일합니다.

</details>

**Q2.** Step 3(원본 x)에서는 2,000 epoch에도 절편이 1.29에 머물렀는데, Step 5(표준화)에서는
300 epoch 만에 수렴했습니다. 골짜기의 모양으로 설명하세요.

<details>
<summary>답 보기</summary>

x가 평균 27 근처에 몰려 있으면 w와 b의 효과가 강하게 얽혀(w를 조금 바꾸면 b가 크게 보상해야 함)
손실 골짜기가 한 방향으로 길쭉한 협곡이 됩니다. 경사하강은 협곡 벽 사이를 지그재그하느라 바닥 방향으로는
조금씩만 전진합니다. 표준화(평균 0)는 두 파라미터의 얽힘을 풀어 골짜기를 둥글게 만들고, 큰 보폭으로도
곧장 바닥까지 걸을 수 있게 합니다.

</details>

**Q3.** sklearn의 LinearRegression은 공식(정규방정식)으로 한 번에 답을 찾는데, 신경망은 왜
경사하강으로 "걸어야" 하나요?

<details>
<summary>답 보기</summary>

닫힌 공식은 손실이 파라미터의 2차식(볼록·풀 수 있는 형태)일 때만 존재합니다. 신경망은 비선형 활성화가
겹겹이 쌓여 손실 지형이 복잡한 비볼록 함수가 되므로 일반해 공식이 없습니다. 유일하게 통하는 전략이
"현재 위치의 기울기를 구해(autograd) 내리막으로 한 걸음(경사하강)"의 반복이며, 그래서 이 두 부품이
모든 딥러닝 프레임워크의 핵심입니다.

</details>
