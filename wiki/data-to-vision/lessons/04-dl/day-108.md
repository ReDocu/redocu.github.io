## ② 왜 필요한가

### "MAE 0.37"은 좋은 성적입니까

[Day 107](day-107.md)에서 구조를 10가지 실험해 최고 `val_MAE 0.3671` 을 얻었습니다.

**이 숫자가 좋은지 나쁜지 판단할 수 있습니까?**

판단할 수 없습니다. 비교 대상이 없기 때문입니다.

```
MAE 0.3671   ← 이것만 보고는 아무것도 모릅니다
```

**이런 비교가 있어야 의미가 생깁니다.**

```
아무 생각 없이 평균으로 예측    MAE 0.9068
선형 회귀 (5줄짜리 코드)        MAE 0.5332
우리가 만든 신경망              MAE 0.3671   ← 평균 대비 59% 개선. 이제 의미가 있음
랜덤포레스트 (기본 설정)        MAE 0.3312   ← ★ 신경망보다 좋습니다
```

**마지막 줄이 오늘의 핵심입니다.**

## ③ 개념 설명

### 0단계 — 평균 예측 (더미 모델)

**입력을 아예 보지 않고 항상 같은 값을 내는 모델입니다.**

```python
from sklearn.dummy import DummyRegressor

dummy = DummyRegressor(strategy="mean")     # 항상 학습셋의 평균을 출력
dummy.fit(X_train, y_train)
```

| strategy | 예측값 | 언제 |
|---|---|---|
| `"mean"` | 학습셋 타깃의 **평균** | **기본.** MSE 기준 최적 상수 |
| `"median"` | 학습셋 타깃의 **중앙값** | MAE 기준 최적 상수 |
| `"constant"` | 지정한 값 | 특수한 경우 |

> **[Day 106](day-106.md)에서 배운 것이 여기서 쓰입니다.**
> MSE로 평가할 거면 `mean`, MAE로 평가할 거면 `median` 이 최적 상수입니다.
> **두 개를 다 구해 두는 것이 정석입니다.**

### R²가 0이 되는 이유

```
R² = 1 - SSE/SST

SSE = Σ(실제 - 예측)²        모델의 오차 제곱합
SST = Σ(실제 - 평균)²        평균으로 예측했을 때의 오차 제곱합
```

**평균으로 예측하면 SSE = SST 이므로 R² = 1 - 1 = 0 입니다.**

| R² | 의미 |
|---|---|
| 1.0 | 완벽한 예측 |
| 0.7 | 타깃 분산의 70%를 설명 |
| **0.0** | **평균 예측과 똑같음** |
| **음수** | **평균 예측보다 못함** ← 뭔가 크게 잘못됨 |

> **R²는 그 자체가 "평균 대비 베이스라인"입니다.**
> 그래서 R²를 보고하면 베이스라인 비교가 자동으로 됩니다.
> 다만 **MAE·RMSE는 그렇지 않으므로** 별도로 베이스라인을 구해야 합니다.

### 1단계 — 선형 회귀

```
예측 = w₁·x₁ + w₂·x₂ + ... + wₙ·xₙ + b
```

```python
from sklearn.linear_model import LinearRegression

lr = LinearRegression()
lr.fit(X_train, y_train)
print(lr.coef_)          # 각 특성의 계수
print(lr.intercept_)     # 절편
```

| 장점 | 단점 |
|---|---|
| **계수를 그대로 해석 가능** ("소득 1단위당 가격 0.83 상승") | 비선형 관계를 못 잡음 |
| 학습이 즉시 (닫힌 해) | 특성 간 상호작용을 못 잡음 |
| 과적합이 거의 없음 | 이상치에 약함 |
| **베이스라인으로 완벽** | 다중공선성에 불안정 |

> **[Day 106](day-106.md) Step 1에서 만든 `Dense(1)` 모델이 정확히 선형 회귀입니다.**
> 파라미터 2개(w, b)짜리 신경망 = 선형 회귀. 같은 것입니다.
> **다만 sklearn 쪽이 훨씬 빠르고 정확합니다.** (반복 학습이 아니라 수식으로 한 번에 품)

### 2단계 — 릿지와 라쏘 (정규화 선형 모델)

**선형 회귀에 "계수를 작게 유지하라"는 벌점을 추가한 모델입니다.**

| | 벌점 항 | 효과 | 별칭 |
|---|---|---|---|
| **릿지 (Ridge)** | α·Σw² | 계수를 **0에 가깝게** 줄임 | L2 규제 |
| **라쏘 (Lasso)** | α·Σ\|w\| | 계수를 **정확히 0으로** 만듦 | L1 규제 |
| **ElasticNet** | 둘의 혼합 | 절충 | L1+L2 |

```python
from sklearn.linear_model import Ridge, Lasso, ElasticNet

Ridge(alpha=1.0)                       # alpha가 클수록 강한 규제
Lasso(alpha=0.1)
ElasticNet(alpha=0.1, l1_ratio=0.5)
```

**핵심 차이 — 라쏘는 특성을 선택합니다**

```
특성 30개로 학습한 결과의 계수:

릿지:  [0.83, 0.12, -0.05, 0.31, 0.02, 0.44, ...]   ← 전부 살아 있음 (작아졌을 뿐)
라쏘:  [0.91, 0.00,  0.00, 0.28, 0.00, 0.51, ...]   ← ★ 여러 개가 정확히 0
```

**라쏘가 0으로 만든 특성은 "안 쓰겠다"는 뜻입니다. 자동 특성 선택입니다.**

| 언제 쓰나 | 모델 |
|---|---|
| 특성이 많고 대부분 쓸모 있을 것 같을 때 | **릿지** |
| 특성이 많고 일부만 중요할 것 같을 때 | **라쏘** |
| 잘 모르겠을 때 | **ElasticNet** 또는 둘 다 시도 |
| **특성이 서로 강하게 상관될 때** | **릿지** (라쏘는 상관 특성 중 하나만 남김) |

> ⚠️ **릿지·라쏘는 스케일링이 필수입니다.**
> 벌점이 계수의 크기에 걸리는데, 특성 스케일이 다르면 계수 스케일도 달라집니다.
> **인구(35,682)의 계수와 위도(35.6)의 계수를 같은 기준으로 벌주면 안 됩니다.**
> ```python
> make_pipeline(StandardScaler(), Ridge(alpha=1.0))     # ✓ 반드시 파이프라인으로
> ```

### 3단계 — 랜덤포레스트 회귀

**[Day 079](../03-ml/day-079.md)에서 배운 랜덤포레스트의 회귀 버전입니다.**

```
분류: 100그루의 다수결        →  "허스키"
회귀: 100그루 예측값의 평균    →  2.47
```

```python
from sklearn.ensemble import RandomForestRegressor

rf = RandomForestRegressor(
    n_estimators=300,      # 트리 개수
    max_depth=None,        # 제한 없음이 기본
    n_jobs=-1,             # ★ 전체 코어
    random_state=42,
)
```

| 장점 | 단점 |
|---|---|
| **스케일링 불필요** | 학습된 모델이 큼 (트리 300개) |
| 결측치·이상치에 상대적으로 강함 | 예측이 느림 (트리 300개 전부 통과) |
| **특성 중요도 제공** | **학습 데이터 범위 밖을 예측 못 함** ★ |
| 튜닝 없이도 잘 됨 | 매우 큰 데이터에서 메모리 부담 |

> ⚠️ **"학습 데이터 범위 밖을 예측 못 함"이 트리의 근본적 한계입니다.**
> 트리는 결국 "리프에 속한 학습 샘플들의 평균"을 출력합니다.
> **학습 데이터의 최댓값이 5.0이면 5.1을 절대 예측할 수 없습니다.**
>
> 선형 모델은 외삽(extrapolation)이 됩니다. `y = 3x + 5` 는 x가 100이어도 305를 냅니다.
> **시간이 지나며 값이 계속 커지는 데이터(물가, 매출)에서 이것이 큰 문제가 됩니다.**

### 3단계 — 그래디언트 부스팅

**랜덤포레스트와 다른 방식으로 트리를 여러 개 씁니다.**

| | 랜덤포레스트 (배깅) | 그래디언트 부스팅 |
|---|---|---|
| 트리 생성 | **병렬** — 각자 독립적으로 | **순차** — 앞 트리의 오차를 다음 트리가 학습 |
| 각 트리 | 깊고 강함 | **얕고 약함** (depth 3~8) |
| 결합 | 평균 | 가중 합 |
| 과적합 | 잘 안 함 | **잘 함** (트리를 많이 쌓으면) |
| 속도 | 병렬화 쉬움 | 순차라 느림 (구현으로 극복) |
| 성능 | 좋음 | **대개 더 좋음** |

```
[부스팅의 아이디어]
트리 1이 예측 → 오차 발생
트리 2가 그 "오차"를 예측 → 더해서 보정
트리 3이 남은 "오차"를 예측 → 또 보정
...
```

**주요 구현 3가지**

| 라이브러리 | 특징 | 설치 |
|---|---|---|
| `GradientBoostingRegressor` | sklearn 내장. 느림 | 기본 포함 |
| **XGBoost** | 빠름. 캐글 표준이었음 | `pip install xgboost` |
| **LightGBM** | **가장 빠름.** 대용량에 강함 | `pip install lightgbm` |
| `HistGradientBoostingRegressor` | sklearn의 LightGBM식 구현. **설치 불필요** | 기본 포함 |

```python
from sklearn.ensemble import HistGradientBoostingRegressor

hgb = HistGradientBoostingRegressor(max_iter=300, random_state=42)
```

> **이 과정에서는 `HistGradientBoostingRegressor` 를 기본으로 씁니다.**
> 별도 설치 없이 LightGBM에 준하는 성능이 나오고, **결측치를 자동으로 처리**합니다.
> XGBoost·LightGBM은 실습에서 함께 비교합니다.

### ★ 정형 데이터에서 트리 앙상블이 강한 이유

| 이유 | 설명 |
|---|---|
| **① 스케일에 무관** | 신경망은 스케일링이 필수. 트리는 "크다/작다"만 봄 |
| **② 비선형·계단형 관계를 자연스럽게** | "소득 5만 달러 이상에서만 급등" 같은 관계를 그대로 학습 |
| **③ 특성 간 상호작용을 자동으로** | 트리의 분기가 곧 조건부 규칙 (`소득이 높고 AND 해안가면`) |
| **④ 데이터가 적어도 됨** | 신경망은 수만 행이 필요. 트리는 수백 행에서도 작동 |
| **⑤ 튜닝 없이도 잘 됨** | 기본 설정 성능이 이미 높음 |
| **⑥ 범주형에 강함** | 원-핫 없이도(LightGBM) 처리 가능 |

**②를 그림으로**

```
[실제 관계]          [선형 모델]           [트리]
가격                  가격                  가격
 │      ╱             │    ╱                │      ┌──
 │     ╱              │   ╱                 │    ┌─┘
 │ ────┘              │  ╱                  │ ───┘
 └────────── 소득     └────────── 소득      └────────── 소득
 계단형 관계          직선으로 근사(오차↑)   계단을 그대로 표현
```

**신경망도 ②③을 할 수 있습니다. 다만 데이터가 훨씬 많이 필요합니다.**

> **연구 결과** — 2022년 발표된 대규모 비교 연구(Grinsztajn et al.)에서
> 45개 정형 데이터셋 중 대부분에서 **트리 앙상블이 신경망을 이겼습니다.**
> 특히 **데이터가 1만 행 미만일 때 격차가 컸습니다.**
>
> **딥러닝이 정형 데이터에서 이기는 경우도 있습니다.**
> 데이터가 수십만 행 이상이거나, 텍스트·이미지가 특성으로 섞여 있을 때입니다.

### 모델 선택 기준 — 성능만이 아닙니다

| 기준 | 질문 |
|---|---|
| **성능** | 지표가 얼마나 좋은가 (당연히 1순위) |
| **해석성** | 왜 그렇게 예측했는지 설명할 수 있는가 |
| **학습 속도** | 재학습에 얼마나 걸리는가 |
| **예측 속도** | 실시간 서빙이 가능한가 |
| **모델 크기** | 배포할 때 몇 MB인가 |
| **유지보수** | 팀이 다룰 수 있는 기술인가 |
| **의존성** | 추가 라이브러리가 필요한가 |

**상황별 우선순위 예시**

| 상황 | 1순위 기준 | 선택 |
|---|---|---|

    r2 = r2_score(y_true, y_pred)

```python

    layers.Dense(64, activation="relu"),
    layers.Dense(32, activation="relu"),
    layers.Dense(1),
])
nn.compile(optimizer=keras.optimizers.Adam(1e-3), loss="mse", metrics=["mae"])

                                   restore_best_weights=True)

              epochs=300, batch_size=64, callbacks=[es], verbose=0)

**모델 D — R²가 음수인 경우의 진단 순서**

```
① 스케일링을 했는가?              ← 가장 흔한 원인
② 출력층에 활성화 함수가 있는가?    ← Day 106
③ 학습률이 너무 큰가?
④ loss가 nan은 아닌가?
⑤ 타깃과 예측의 shape이 맞는가?
⑥ 학습이 충분히 됐는가? (에폭 부족)
```

**R²가 음수라는 것은 "모델이 아예 학습되지 않았다"는 뜻에 가깝습니다.**
미세 조정 대상이 아니라 **버그를 찾아야 하는 상황**입니다.

**모델 E — MAE와 RMSE의 순위가 뒤바뀐 경우**

```
        MAE     RMSE    RMSE/MAE
모델 C  3,210   5,840   1.82
모델 E  3,050   6,720   2.20     ← 비율이 더 큼
```

**RMSE/MAE 비율이 클수록 "가끔 크게 빗나간다"는 뜻입니다.**

| 모델 | 특성 | 어떤 상황에 좋은가 |
|---|---|---|
| C | 고르게 빗나감 | **큰 실수가 치명적일 때** |
| E | 대체로 정확한데 **가끔 크게 틀림** | 평균 오차가 중요할 때 |

**선택은 문제에 달렸습니다.**

```
가격 추천 UI  → E   (대부분의 사용자에게 정확)
자동 발주 시스템 → C   (한 번의 큰 실수가 재고 사고)
```

> **"MAE가 낮으니 E가 좋다"는 성급합니다.**
> **E의 큰 오차가 어디서 나는지 확인**해야 합니다. ([Day 118](day-118.md)의 오차 top-N 분석)
> 만약 특정 가격대에서만 크게 틀린다면, 그 구간을 따로 다뤄야 합니다.

**전체 결론과 다음 행동**

```
1. 모델 D의 버그를 먼저 잡는다        ← R² 음수는 정상이 아님
2. 모델 C와 E의 오차 분포를 비교한다   ← 잔차 히스토그램, 오차 top-20
3. 문제의 성격에 맞는 지표를 확정한다  ← 그 다음에 승자를 정함
4. 선형 회귀가 무의미했다는 것을 기록  ← "비선형 관계"라는 중요한 발견
```

**문제 5가지**

| # | 위치 | 문제 | 영향 |
|---|---|---|---|
| 1 | `X_test_s = scaler.fit_transform(X_test)` | **테스트셋으로 스케일러를 다시 fit** | 학습 때와 다른 변환. 성능 왜곡 |
| 2 | `train_test_split(...)` | `random_state` 미고정 | 재현 불가. 실행마다 결과 달라짐 |
| 3 | `nn.fit(epochs=10)` | **신경망만 10에폭** | RF는 1000그루, NN은 10에폭. 불공정 |
| 4 | `mean_absolute_error(y_test, nn.predict(...))` | **shape 불일치** | `(4128,)` vs `(4128,1)` |
| 5 | **테스트셋으로 모델 비교** | 검증셋이 없음 | 테스트셋을 3번 봄. 최종 평가 불가 |

(추가) 7. 베이스라인(평균 예측) 없음
(추가) 8. `layers.Dense(64)` 에 `input_shape` 미지정 — 동작은 하지만 `summary()` 를 미리 못 봄

**1번이 가장 교묘합니다.**

```python
scaler.fit_transform(X_test)
```

이러면 **테스트셋의 평균/표준편차로 테스트셋을 정규화**합니다.
학습 때 쓴 기준과 다른 기준으로 변환하는 것이므로, **모델이 보는 좌표계가 바뀝니다.**

```
학습셋 MedInc 평균 3.87 → 스케일링 후 0
테스트셋 MedInc 평균 3.91 → ★ 이것도 0이 됨 (잘못됨)

```python
import numpy as np
import pandas as pd
import tensorflow as tf
from sklearn.datasets import fetch_california_housing
from sklearn.dummy import DummyRegressor
from sklearn.ensemble import RandomForestRegressor
from sklearn.linear_model import LinearRegression
from sklearn.metrics import mean_absolute_error, mean_squared_error, r2_score
from sklearn.model_selection import train_test_split
from sklearn.preprocessing import StandardScaler
from tensorflow import keras
from tensorflow.keras import layers

SEED = 42
np.random.seed(SEED)
tf.random.set_seed(SEED)

housing = fetch_california_housing()
X, y = housing.data, housing.target

# ★ 수정 5: 검증셋 분리 — 모델 비교는 검증셋으로
X_tr, X_test, y_tr, y_test = train_test_split(X, y, test_size=0.2, random_state=SEED)
X_tr, X_val, y_tr, y_val = train_test_split(X_tr, y_tr, test_size=0.2, random_state=SEED)  # ★ 수정 2

# ★ 수정 1: 학습셋으로만 fit
scaler = StandardScaler()
X_tr_s = scaler.fit_transform(X_tr)
X_val_s = scaler.transform(X_val)
X_test_s = scaler.transform(X_test)


def report(y_true, pred, name):
    return {
        "모델": name,
        "MAE": round(mean_absolute_error(y_true, pred), 4),
        "RMSE": round(float(np.sqrt(mean_squared_error(y_true, pred))), 4),
        "R²": round(r2_score(y_true, pred), 4),
    }


rows = []

# ★ 수정 7: 베이스라인
dummy = DummyRegressor(strategy="mean").fit(X_tr, y_tr)
rows.append(report(y_val, dummy.predict(X_val), "평균 예측 (베이스라인)"))

lr = LinearRegression().fit(X_tr_s, y_tr)
rows.append(report(y_val, lr.predict(X_val_s), "선형 회귀"))

# ★ 수정 6: n_jobs
rf = RandomForestRegressor(n_estimators=300, random_state=SEED, n_jobs=-1).fit(X_tr, y_tr)
rows.append(report(y_val, rf.predict(X_val), "랜덤포레스트"))

# ★ 수정 3: EarlyStopping으로 충분히 학습 + 수정 8: input_shape
nn = keras.Sequential([
    layers.Input(shape=X_tr_s.shape[1:]),
    layers.Dense(64, activation="relu"),
    layers.Dense(32, activation="relu"),
    layers.Dense(1),
])
nn.compile(optimizer=keras.optimizers.Adam(1e-3), loss="mse", metrics=["mae"])
es = keras.callbacks.EarlyStopping(monitor="val_loss", patience=20, restore_best_weights=True)
nn.fit(X_tr_s, y_tr, validation_data=(X_val_s, y_val),
       epochs=300, batch_size=64, callbacks=[es], verbose=0)

# ★ 수정 4: ravel()
rows.append(report(y_val, nn.predict(X_val_s, verbose=0).ravel(), "신경망"))

df = pd.DataFrame(rows)
base = df.loc[0, "MAE"]
df["개선율(%)"] = ((base - df["MAE"]) / base * 100).round(1)

print("=" * 74)
print("모델 비교 (검증셋) — 테스트셋은 아직 열지 않았습니다")
print("=" * 74)
print(df.to_string(index=False))
print("=" * 74)

# ★ 최종 모델 하나만 테스트셋으로 (Day 125에서 정식으로)
best_name = df.loc[df["MAE"].idxmin(), "모델"]
print(f"\n검증셋 기준 최고: {best_name}")
print("→ 테스트셋 평가는 모든 튜닝이 끝난 뒤 딱 한 번만 수행합니다. (Day 125)")

from tensorflow import keras
from tensorflow.keras import layers

SEED = 42


def make_nn(input_shape, hidden):
    tf.random.set_seed(SEED)
    m = keras.Sequential([layers.Input(shape=input_shape)])
    for u in hidden:
        m.add(layers.Dense(u, activation="relu"))
    m.add(layers.Dense(1))
    m.compile(optimizer=keras.optimizers.Adam(1e-3), loss="mse", metrics=["mae"])
    return m


sizes = [300, 1000, 5000, 13209]
rows = []

for n in sizes:
    Xn_raw, Xn_s, yn = X_train[:n], X_train_s[:n], y_train[:n]

    hidden = [16] if n <= 500 else [32, 16] if n <= 2000 else [128, 64, 32]

    models = {
        "평균 예측": (DummyRegressor(strategy="mean"), Xn_raw, X_val),

        "랜덤포레스트": (RandomForestRegressor(n_estimators=300, random_state=SEED, n_jobs=-1), Xn_raw, X_val),
        "HistGB": (HistGradientBoostingRegressor(max_iter=300, random_state=SEED), Xn_raw, X_val),
    }

    for name, (model, Xfit, Xeval) in models.items():
        t0 = time.perf_counter()
        model.fit(Xfit, yn)

        rows.append({"학습샘플": n, "모델": name, "MAE": round(mae, 4),

                                       restore_best_weights=True)

        print(f"{i+1:>4}{r['모델']:>20}{r['MAE']:>10.4f}{r['학습(s)']:>10.3f}"
              f"{imp:>13.1f}%{mark}")

print("\n" + "=" * 86)
print("신경망 순위 변화")

**④ 결론**

**1. 이 데이터에서는 어떤 크기에서도 신경망이 1위를 못 했습니다.**

```
 300행: 4위 (릿지보다도 못함)
1,000행: 3위
5,000행: 3위
13,209행: 3위
```

**2. 다만 300행 → 1,000행에서 릿지를 추월했습니다.**

```
 300행: 신경망(0.5921) > 릿지(0.5709)      ← 선형 모델보다도 못함
1,000행: 신경망(0.5104) < 릿지(0.5482)     ← 추월
```

**신경망이 "선형 모델보다 나아지는 지점"이 대략 1,000행 근처입니다.**
그 아래에서는 **비선형을 배울 데이터가 부족해 오히려 노이즈만 배웁니다.**

**3. 트리 앙상블과의 격차는 데이터가 늘어도 크게 안 줄었습니다.**

```
  300행: +0.0503
1,000행: +0.0743
5,000행: +0.0415
13,209행: +0.0569
```

**단조 감소하지 않습니다.** 2만 행 수준으로는 부족하다는 뜻입니다.
연구에서 신경망이 이기기 시작하는 것은 **대략 수십만 행 이상**입니다.

**4. 비용까지 보면 격차가 더 벌어집니다.**

```
13,209행 기준:
  HistGB   MAE 0.3079,  1.2초
  신경망    MAE 0.3648, 28.4초     ← 24배 느린데 성능은 16% 나쁨
```

**"데이터가 얼마나 있어야 신경망을 고려할 만한가"에 대한 답**

| 학습 샘플 | 권장 |
|---|---|
| **~500행** | **선형 계열 또는 트리.** 신경망은 시간 낭비 |
| 500~2,000행 | 트리 앙상블. 신경망은 참고용 |
| 2,000~50,000행 | **트리 앙상블이 기본.** 신경망은 특성 공학이 잘 됐을 때 경쟁 가능 |
| 50,000행 이상 | 둘 다 진지하게 비교 |
| 텍스트·이미지가 섞임 | **신경망** (트리는 그걸 못 다룸) |

**단, 이 결론에는 중요한 단서가 있습니다.**

> ⚠️ **아직 전처리를 제대로 안 했습니다.**
> 이 실험의 신경망은 **표준화만** 했습니다.
> [Day 111](day-111.md)~[Day 115](day-115.md)에서 배울 것들 — 로그 변환, 이상치 처리, 특성 공학 — 을 적용하면 신경망 성능이 올라갑니다.
>
> **반면 트리 앙상블은 전처리 효과가 상대적으로 작습니다.** (스케일링·이상치에 강하므로)
> **그래서 격차가 줄어들 가능성이 있습니다.** [Day 129](day-129.md)에서 확인합니다.

**실무 판단 순서 (오늘의 최종 결론)**

```
① 평균 예측으로 베이스라인을 잡는다              ← 30초
② 선형 회귀를 돌린다                            ← 10초
③ HistGB를 기본 설정으로 돌린다                  ← 1분

⑤ 더 필요하면: 특성 공학 → 튜닝 → 신경망 순
⑥ 신경망이 ③을 못 이기면 정직하게 보고한다        ← 이것도 결과입니다
```

> **⑥이 중요합니다.** "딥러닝 과정이니까 딥러닝이 이겨야 한다"는 압박에

## 오늘의 정리

| 개념 | 핵심 |
|---|---|
| 베이스라인 | **비교 대상이 없으면 성능은 숫자일 뿐** |
| `DummyRegressor` | `mean`(MSE 최적) / `median`(MAE 최적) |

| 선형 회귀 | 계수 해석 가능. **비선형·상호작용을 못 잡음** |
| 릿지 (L2) | 계수를 **0에 가깝게** 줄임. 상관 특성에 강함 |
| 라쏘 (L1) | 계수를 **정확히 0으로**. 자동 특성 선택 |
| α 튜닝 | **기본값을 그대로 쓰면 모델을 오판**합니다 |
| 랜덤포레스트 | 병렬 배깅. 스케일링 불필요. **외삽 불가** |
| 부스팅 | 순차. 앞 트리의 오차를 학습. **대개 RF보다 좋음** |
| `HistGradientBoosting` | sklearn 내장. 빠르고 **결측치 자동 처리** |
| 트리가 강한 이유 | 스케일 무관 · 계단형 관계 · 상호작용 자동 · **적은 데이터에서도** |
| 트리의 약점 | **학습 데이터 범위 밖을 예측 못 함** |
| 순열 중요도 | **모델 간 비교가 가능한** 유일한 중요도 |
| 모델 선택 | 성능 · 해석성 · 속도 · 크기 · **팀 역량** |
| 신경망 vs 트리 | 정형 데이터·수만 행 이하에서는 **트리가 대체로 이김** |
