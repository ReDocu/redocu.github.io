## ② 왜 필요한가

남은 배점 두 덩어리 — 운영 설계 25점의 마지막 항목(**모델 버전 교체 절차**)과 문서 10점
(**운영 절차서**)이 오늘입니다. 그리고 이 둘은 MP4 완료 조건의 마지막 줄이기도 합니다:
"모델을 새 버전으로 교체하고 롤백하는 절차가 **문서와 함께 동작**한다."

모델 교체가 코드 배포와 다른 지점이 하나 있습니다 — 우리 시스템 곳곳에 **모델의 지문**이
박혀 있다는 것. [Day 104](../04-deep-learning-serving/day-104.md)의 회귀 테스트(0.7214±0.001),
[Day 129](day-129.md) 스모크의 대조, 문서의 예시 응답들. 모델이 바뀌면 이 지문들이 전부
"과거의 정답"이 됩니다 — 그것을 어떻게 다루는지가 오늘 배우는 실무 감각의 핵심입니다
(스포일러: 게이트가 여러분을 **올바르게 막아설** 겁니다).

그리고 운영 절차서 — 기준은 하나입니다: **여러분이 없는 방에서, 이 문서만 들고, 남이 시스템을
운영할 수 있는가.** "제가 설명드리면 되는데요"는 문서 0점의 다른 표현입니다.

## ③ 개념 설명

### 모델 교체의 두 방식 — 우리 선택과 근거

| | A. 이미지에 굽는 방식 (우리 기본) | B. 레지스트리 로드 (상급 선택) |
|---|---|---|
| 교체 수단 | 모델 파일 교체 **PR** → 재빌드·재배포 | 별칭 이동 + 재로드 ([Day 132](day-132.md)) |
| 족보 | 이미지 태그 하나에 코드+모델 완결 | 코드(sha)와 모델(버전) 두 좌표 |
| 소요 | 파이프라인 풀 사이클 (~4분) | 초 단위 |
| 어울림 | 모델이 작고(45MB) 갱신이 코드만큼 드묾 | 모델이 크거나 갱신이 잦음 |

[Day 119](day-119.md) 과제·[Day 118](day-118.md) Q3에서 다진 그 판단입니다 — antbee(45MB·
드문 갱신)는 A가 정직한 선택이고, pm25(주간 재학습)는 B를 이미 씁니다. **두 방식을 다 갖고
있고 선택 기준을 말할 수 있는 것**이 상급의 증거입니다.

### 모델 교체 = 대조값의 교체

모델 v2가 오면 바뀌어야 하는 것의 전체 목록:

```
모델 파일 (models/…v2.pt)  +  model_version 문자열  +  회귀 테스트 기대값
+  스모크의 대조 (deploy.sh)  +  문서의 예시 응답
```

이것들이 **한 PR에서 원자적으로** 바뀌어야 합니다 — 하나라도 빠지면 게이트나 스모크가 빨간불
(그리고 그것은 버그가 아니라 **설계의 성공**입니다: 지문 불일치를 기계가 잡은 것). 실무 요령은
대조값을 코드 곳곳에 흩뿌리지 않고 **한 파일에 모으는 것**입니다 (tests/expected.py 같은 —
"같아야 하는 값은 한 번만" 원칙의 재등장).

### 롤백 3층 — 오늘 완성되는 표

| 층 | 되돌리는 것 | 수단 | 실측 |
|---|---|---|---|
| 이미지 (응급) | 운영 컨테이너 | deploy.sh sha-이전 | 38.7s ([Day 138](day-138.md)) |
| 커밋 (정사) | main 자체 | revert PR → 자동 재배포 | 4m 12s ([Day 138](day-138.md)) |
| **모델** | 모델만 | A방식: 모델 revert PR / B방식: 별칭 이동 | 오늘 측정 / 7s ([Day 132](day-132.md)) |

## ④ 단계별 실습

### Step 1. 모델 v2 준비 (1~2교시)

[Day 085](../04-deep-learning-serving/day-085.md)의 학습 스크립트로 몇 에폭 추가 파인튜닝
(또는 증강 데이터)한 v2를 만듭니다:

```
val acc: 0.954 (v1) → 0.961 (v2)
대조 샘플 재계산:  개미 10308379_… → ants 0.7461  ·  벌 1032546534_… → bees 0.7802
```

대조값이 **바뀌었습니다** — 0.7214의 시대가 끝납니다. DVC로 지문을 남기고
(`dvc add models/antbee_resnet18_v2.pt`, [Day 131](day-131.md)), 대조값 파일을 갱신합니다.

### Step 2. 교체는 파이프라인으로 — 그리고 게이트의 한 방 (3~5교시)

일부러 **절반만 바꾼 PR**을 먼저 밟아 봅니다 (모델과 model_version만 바꾸고 테스트 기대값은
그대로) — 교육적 실패의 마지막 회:

```
CI / test                                               ✗ 2m 18s
FAILED tests/test_api.py::test_predict_matches_training_record
  - assert 0.7461 == 0.7214 ± 1.0e-03
```

**게이트가 막았습니다 — 정확히 설계대로.** 모델과 지문의 불일치가 운영에 닿기 전에 걸린
것입니다 (⑤의 첫 항목이 왜 "이것은 실수가 아니라 성공"인지). 이제 완전한 PR로 — 모델(dvc
지문) + model_version("resnet18-antbee-v2") + 기대값(0.7461·0.7802) + 문서 예시를 **한
커밋에**:

```
10:41  PR #34 "model: antbee v2 (val 0.961) — 대조값 일괄 갱신"
10:44  게이트 전부 초록 (회귀 테스트가 새 기대값으로 통과) → 병합
10:48  자동 배포 · 스모크 통과
$ curl -s -F "file=@tests/data/ant_sample.jpg" localhost:8080/predict
{"label":"ants","confidence":0.7461,"model_version":"resnet18-antbee-v2","elapsed_ms":31.2}
────────────────────────────────────
모델 교체 소요 (PR 병합→운영): 4m 07s · 평가 기준 항목 실측 완료
```

### Step 3. 모델 롤백 시연 — 3층 표의 마지막 칸 (5교시 계속)

revert PR로 v1 복귀를 리허설합니다 (Step 2와 역방향 — 대조값까지 함께 돌아가는 것을 확인):
**4m 02s.** 이로써 롤백 3층 표의 전 칸에 실측이 들어갔습니다 — 심사의 "되돌려 보세요"가
어느 층을 겨냥해도 숫자로 답합니다. (B방식 7초와의 대비를 문서에 남기고, "antbee도 갱신이
잦아지면 B로 이관"을 알려진 한계·다음 단계 절에.)

### Step 4. 운영 절차서 — 그리고 남의 손 검증 (6~7교시)

`docs/OPERATIONS.md` 를 런북 형식(상황 → 판단 → 명령 → 확인)으로 완성합니다. 목차 표준:

```
1. 일상 운영     기동/정지 · 상태 확인 · 로그 조회 · 백업(pg_dump cron) 확인
2. 장애 대응     증상별 진단 트리 (502? → nginx·api 순서로 / 예측 이상? → 134 절차)
                 응급 롤백 (이미지 층 — 38.7s 절차)
3. 변경 절차     코드 배포(표준 사이클) · 모델 교체(오늘의 A방식) · 설정 변경(동결 원칙)
4. 정기 점검     드리프트 리포트 읽는 법 · 이력 파일 감사 · 시크릿 점검표(122) 재실행 주기
5. 권한과 연락   누가 무엇을 할 수 있나 (GitHub 권한 = 배포 권한) · 에스컬레이션
```

그리고 문서 10점의 진짜 시험 — **짝 검증**: 짝에게 절차서만 주고 세 과제를 수행하게 합니다
(① API 재시작 후 정상 확인 ② 최근 1시간 에러 로그 조회 ③ 응급 롤백 → 복귀). 여러분은
**입을 닫고** 관찰만 — 짝이 막힌 모든 지점이 절차서의 버그입니다. 수정 후 커밋.

### Step 5. 발표 전야 점검 (8교시)

- (상급) [Day 134](day-134.md)의 대시보드 PNG 최신화 — 발표 자료의 "감시" 슬라이드로
- [Day 138](day-138.md)의 사전 점검 절차 실행 + 백업 3층 위치 확인
- 발표 구성 초안 ([Day 105](../04-deep-learning-serving/day-105.md)의 5분 구성을 MP4판으로):
  문제(노트북 안의 API) → 아키텍처(사진 한 장) → **라이브: 커밋→반영** → 장애·롤백의 증거
  (실측 표) → 회고·다음 단계

**오늘 퇴근 체크** — □ 모델 v2 교체·롤백 실측 (4m07s·4m02s) □ 롤백 3층 표 완성 □
OPERATIONS.md 짝 검증 통과 (막힌 지점 0까지 수정) □ 발표 구성 초안 □ 파이프라인 동결 유지 중

## ⑤ 자주 하는 실수

### 게이트에 막히자 테스트를 "고장"으로 취급

**증상** — Step 2의 빨간불에 "테스트가 낡았네" 하며 회귀 테스트를 **삭제**하고 병합.
**원인** — 게이트의 메시지를 오독 — 테스트는 "모델과 지문이 어긋났다"는 정확한 사실을 말하고
있었습니다.
**해결** — 모델 교체 PR의 정의를 기억하세요: 모델+지문의 **원자적 교체**. 테스트 삭제는
다음 모델 교체 사고(지문 없는 교체)의 문을 여는 것입니다. 기대값을 갱신하는 것과 검증을
없애는 것은 정반대의 행위입니다.

### 대조값이 코드 곳곳에 흩어져 있음

**증상** — 0.7214가 테스트에, deploy.sh에, README 예시에, 발표 자료에 — v2 교체 때 하나를
빠뜨려 스모크만 옛 값으로 실패.
**원인** — 같아야 하는 값이 네 곳에 적힘 ([Day 124](day-124.md) Q3의 병이 대조값에서 재발).
**해결** — 대조값을 한 파일(tests/expected.py 또는 expected.json)로 모으고 테스트·스모크가
그것을 읽게. 문서의 예시는 "실측 예 (v2 기준)"처럼 버전을 병기 — 지문에는 소유자가 있어야
합니다.

### 모델 파일을 서버에서 직접 교체

**증상** — "PR 귀찮은데" 하며 서버의 이미지 속 모델을 볼륨 덮어쓰기로 교체 — 이미지 태그와
실제 모델이 어긋난 유령 상태 ([Day 128](day-128.md) ⑤의 모델판).
**원인** — 마감 압박 + 우회로가 물리적으로 가능함.
**해결** — 모델도 화물이 아니라 **배포물**입니다 — 운영에 닿는 유일한 길은 파이프라인이라는
원칙에 예외를 만들지 마세요. 4분이 아까워 우회하면, 다음 조사자는 4일을 씁니다.

### 절차서 검증을 자기 자신이 함

**증상** — "절차서대로 다 되는데요?" — 작성자의 머릿속 암묵지가 문장 사이를 메우고 있다는
것을 본인만 모름.
**원인** — 저주받은 지식(자신이 아는 것을 모르는 상태로 읽을 수 없음).
**해결** — 문서 검증의 철칙: **모르는 사람이, 문서만으로, 작성자의 침묵 속에서.** 오늘의
짝 검증이 그 형식이고, clone 리허설(104·125·137)과 같은 원리의 문서판입니다.

계정을 만들 필요 없이 저장소 협업자 추가 + CONTRIBUTING/OPERATIONS 문서로 충분 (Day 130
Step 3에서 짝이 그랬듯). 오프보딩: 저장소 권한 회수가 곧 배포 권한 회수 — 클릭 한 번, 감사
로그 자동. 반면 절차서에 명시할 예외도 있습니다: self-hosted 러너가 도는 서버의 관리 권한
(deploy 계정·sudoers)은 별도 목록으로 — "권한의 지도"가 문서에 있어야 인수인계가 성립합니다.
