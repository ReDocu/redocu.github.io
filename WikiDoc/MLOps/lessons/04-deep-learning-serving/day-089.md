이 레슨을 마치면 이렇게 할 수 있습니다.

- **사전학습 → 파인튜닝**의 분업 구조를 파라미터 수준(몸통/머리)에서 설명할 수 있다.
- 한국어 감성 분류기를 klue/bert-base 위에 파인튜닝할 수 있다 (**W16의 5단계 루프 그대로**).

- LoRA·양자화가 **왜 필요한지**(비용 문제) 소개 수준으로 말할 수 있다.

## ② 왜 필요한가

어제 확인한 것: klue/bert-base는 한국어와 세상 지식을 이미 압축하고 있습니다
("서울의 [MASK]" → 미세먼지 0.447). 하지만 그 모델에게 "이 리뷰가 긍정이냐"고 물을 수는
없습니다 — 사전학습 과제(빈칸 맞히기)와 우리 과제(감성 분류)가 다르기 때문입니다.

[Day 083](day-083.md)의 이미지에서 답을 이미 압니다: **몸통은 빌리고 머리만 새로.**
오늘 텍스트에서 같은 일을 하는데, 결과가 얼마나 극적인지 숫자로 미리 보면:

```
바닥부터 감성 분류기를 만들려면:  라벨 데이터 수만 건 + 대형 학습
오늘 우리:                       라벨 1,500건 · CPU 340초 → 정확도 0.545 → 0.815
```

그리고 이것이 MP3의 두 번째 선택지가 됩니다 — 이미지 분류기([Day 085](day-085.md)) 또는
**오늘의 한국어 텍스트 분류기**를 서빙하는 것. 민원 분류, 리뷰 모니터링, 문의 라우팅 —
실무 텍스트 과제의 표준 레시피가 오늘 이 8교시입니다.

## ③ 개념 설명

### 파인튜닝 — 전이학습의 텍스트판

```
klue/bert-base (몸통: 한국어 이해, 110M 파라미터)      ← 사전학습 (남이 해 둠, GPU 수백 시간)
        +
분류 머리 (Linear 768→2, ~1.5K 파라미터)               ← 무작위 초기화 (우리가 새로)
        ↓
전체를 아주 작은 학습률로 우리 데이터에 맞춤              ← 파인튜닝 (오늘, CPU 몇 분)
```

[Day 083](day-083.md)과의 차이 하나: 이미지에서는 몸통을 **동결**(특징 추출)했지만, 텍스트
파인튜닝의 관례는 **전체를 아주 작은 학습률로** 함께 움직이는 것입니다. 몸통도 과제에 맞게
미세 조정되되, 학습률이 작아(2e-5 — W16에서 쓰던 값의 1/50) 사전학습이 부서지지 않습니다.

> 학습률의 직관: 몸통은 이미 좋은 골짜기 바닥 근처에 있습니다. 큰 보폭으로 걸으면
> 바닥에서 튕겨 나가 **배운 것을 잊습니다**(파괴적 망각). 작은 보폭 = "그 자리에서 살짝만".

### AutoModelForSequenceClassification — 머리 달린 몸통

```
BertForSequenceClassification LOAD REPORT:
  classifier.weight | MISSING  ← 분류 머리는 저장소에 없어 새로 초기화됨
```

로드할 때 나오는 이 안내가 오늘의 구조를 정확히 말해 줍니다 — 몸통 가중치는 저장소에서,
**분류 머리는 무작위로**. 그래서 파인튜닝 전 정확도가 동전 던지기 수준인 것입니다.

### LoRA·양자화 — 왜 필요한가 (소개만)

오늘 110M 파라미터의 CPU 학습이 340초였습니다. 모델이 7B(70억)면? 전체 파인튜닝은
GPU 수십 GB의 세계가 됩니다. 그래서:

| 기법 | 발상 | 효과 |
|---|---|---|
| **LoRA** | 몸통은 얼리고, 각 층 옆에 **아주 작은 우회 행렬**만 학습 | 학습 파라미터 1% 미만 |
| **양자화** | 가중치를 32비트 대신 8/4비트로 저장 | 메모리 수 분의 1 |

실전은 별도 LLM 엔지니어링 과정의 몫입니다. 오늘 기억할 것은 "왜"입니다 — **파인튜닝의
병목은 아이디어가 아니라 메모리·비용**이고, 이 기법들은 그 비용 문제의 답입니다.

## ④ 단계별 실습

`day089_finetune.py` 에 이어 붙입니다. 문서의 실행 결과는 **CPU 축소판**(1,500건 · 1에폭 ·
max_length 64) 기준이고, Colab GPU라면 전체 15만 건으로 같은 코드가 돕니다 🖥️.

### Step 1. NSMC — 한국어 감성의 국민 데이터셋 (1교시)

```python
# day089_finetune.py — 텍스트 분류 파인튜닝 (NSMC)
import time
import pandas as pd
import torch
from torch.utils.data import DataLoader, TensorDataset
from transformers import AutoModelForSequenceClassification, AutoTokenizer

torch.manual_seed(42)

print("== A. 데이터: NSMC 영화 리뷰 ==")
train_raw = pd.read_table("data/nsmc/ratings_train.txt").dropna()
test_raw = pd.read_table("data/nsmc/ratings_test.txt").dropna()
print(f"원본: train {len(train_raw):,} / test {len(test_raw):,}")
print(train_raw[["document", "label"]].head(3).to_string(index=False))

# CPU 축소판: 1,500 / 600 (Colab GPU라면 전체 15만으로)
tr = train_raw.sample(1500, random_state=42)
va = test_raw.sample(600, random_state=42)
print(f"실습 규모: train {len(tr)} / valid {len(va)} · 긍정 비율 {tr.label.mean():.2f}")
```

실행 결과:

```
== A. 데이터: NSMC 영화 리뷰 ==
원본: train 149,995 / test 49,997
                         document  label
              아 더빙.. 진짜 짜증나네요 목소리      0
흠...포스터보고 초딩영화줄....오버연기조차 가볍지 않구나      1
                너무재밓었다그래서보는것을추천한다      0
실습 규모: train 1500 / valid 600 · 긍정 비율 0.47
```

실제 리뷰라 오타("재밓었다")·구어체가 그대로입니다 — 서브워드 토큰화([Day 087](day-087.md))가
이런 입력을 견디는 장치였음을 기억하세요. 세 번째 행처럼 **라벨이 갸웃한 것도 실데이터의
현실**입니다 (긍정 문장인데 label 0 — 별점 기반 자동 라벨의 노이즈).

### Step 2. 머리 달기와 출발점 측정 (2~3교시)

```python
print("\n== B. 사전학습 모델에 분류 머리 달기 ==")
name = "klue/bert-base"
tok = AutoTokenizer.from_pretrained(name)
model = AutoModelForSequenceClassification.from_pretrained(name, num_labels=2)

def make_loader(frame, shuffle=False):
    enc = tok(frame.document.tolist(), padding=True, truncation=True,
              max_length=64, return_tensors="pt")
    ds = TensorDataset(enc.input_ids, enc.attention_mask,
                       torch.tensor(frame.label.to_numpy()))
    return DataLoader(ds, batch_size=16, shuffle=shuffle)

train_dl = make_loader(tr, shuffle=True)
valid_dl = make_loader(va)

def accuracy():
    model.eval()
    hit = n = 0
    with torch.no_grad():
        for ids, mask, y in valid_dl:
            pred = model(input_ids=ids, attention_mask=mask).logits.argmax(dim=1)
            hit += (pred == y).sum().item()
            n += len(y)
    model.train()
    return hit / n

print(f"파인튜닝 전 valid 정확도: {accuracy():.3f}   (머리가 무작위 초기화 상태)")
```

실행 결과 (로드 안내 일부 포함):

```
== B. 사전학습 모델에 분류 머리 달기 ==
classifier.weight | MISSING
classifier.bias   | MISSING
파인튜닝 전 valid 정확도: 0.545   (머리가 무작위 초기화 상태)
```

`classifier.* MISSING` — 어제 ⑤에서 예고한 "새로 초기화" 안내입니다. 몸통은 한국어를
다 아는데 머리가 무작위라 **0.545, 동전 수준**입니다. 지식은 있는데 과제를 모르는 상태.

### Step 3. 파인튜닝 — 낯익은 루프, 다른 학습률 (4~5교시)

```python
print("\n== C. 파인튜닝 — W16의 5단계 루프 그대로, 학습률만 아주 작게 ==")
optimizer = torch.optim.AdamW(model.parameters(), lr=2e-5)   # 사전학습을 다치지 않게
t0 = time.perf_counter()
for step, (ids, mask, y) in enumerate(train_dl, 1):
    out = model(input_ids=ids, attention_mask=mask, labels=y)  # labels를 주면 loss까지 계산
    out.loss.backward()
    optimizer.step()
    optimizer.zero_grad()
    if step % 30 == 0:
        print(f"  step {step:>3}/{len(train_dl)}: loss {out.loss.item():.4f}")
print(f"1 에폭({len(train_dl)} step) 소요: {time.perf_counter()-t0:.0f}초 (CPU)")

print(f"\n파인튜닝 후 valid 정확도: {accuracy():.3f}")
```

실행 결과:

```
== C. 파인튜닝 — W16의 5단계 루프 그대로, 학습률만 아주 작게 ==
  step  30/94: loss 0.5489
  step  60/94: loss 0.1720
  step  90/94: loss 0.5012
1 에폭(94 step) 소요: 340초 (CPU)

파인튜닝 후 valid 정확도: 0.815
```

**1,500건 · 1에폭 · 340초로 0.545 → 0.815.** 우리가 가르친 것은 "긍정/부정 구분"이라는
과제의 형식뿐이고, 한국어 이해는 이미 몸통에 있었습니다 — 어제 fill-mask에서 본 그 지식이
분류 성능으로 환전된 것입니다. (참고로 전체 15만 건 + GPU 몇 분이면 0.89~0.90대까지 갑니다.
CPU 축소판과 정식판의 코드는 같고 규모만 다릅니다.)

루프를 다시 보세요 — [Day 077](day-077.md)의 5단계 그대로입니다. HF 모델은 `labels=` 를
주면 손실까지 계산해 주니(②가 forward 안으로) 오히려 짧아졌습니다.

### Step 4. 내 문장으로 확인 + 저장 (6교시)

```python
print("\n== D. 내 문장으로 확인 ==")
model.eval()
sents = ["이 영화 진짜 최고였다", "돈 아깝다 두 번은 못 보겠다", "배우 연기는 좋았는데 스토리가 아쉽다"]

for s, p in zip(sents, probs):

torch.save(model.state_dict(), "models/nsmc_bert.pt")
```

## ⑤ 자주 하는 실수

### W16 감각의 학습률(1e-3)로 파인튜닝

**증상** — loss가 요동치다 정확도가 0.5 근처로 붕괴 — 몸통이 배운 것을 잊음(파괴적 망각).
**원인** — 사전학습된 가중치는 좋은 바닥 근처에 있는데 큰 보폭이 그걸 튕겨 냈습니다.
**해결** — 파인튜닝 관례 학습률은 1e-5 ~ 5e-5. "빌린 것은 살살"이 원칙입니다.

### max_length·truncation 없이 토큰화

**증상** — 유난히 긴 리뷰 하나에 배치 전체가 512 토큰으로 패딩되어 학습이 수배 느려짐 (또는 512 초과 에러).
**원인** — padding은 배치 내 최장 길이에 맞춥니다.
**해결** — 과제 특성에 맞는 `max_length` + `truncation=True` (리뷰 감성은 앞 64토큰으로 충분). 길이 분포를 먼저 보고 정하는 것이 정석입니다.

### 파인튜닝 전 정확도를 안 재 봄

**증상** — "0.815 달성!" — 그런데 출발점을 몰라 개선 폭을 말할 수 없음.
**원인** — 베이스라인 습관([Day 055](../03-machine-learning/day-055.md))이 도구가 바뀌자 증발.
**해결** — 파인튜닝 전(0.545)과 다수 클래스 비율(0.53)을 먼저 기록. "0.545 → 0.815"가 보고의 형식입니다.

### 라벨 노이즈를 모델 탓으로 돌림

**증상** — valid를 눈으로 보다가 "정답이 이상한데?" — 모델 디버깅에 반나절.
**원인** — NSMC 라벨은 별점 기반 자동 생성이라 애매·오류 라벨이 섞여 있습니다 (Step 1의 세 번째 행).
**해결** — 데이터 카드/출처의 라벨 정의를 먼저 읽고, 상한 성능(사람 간 일치율)이 100%가 아님을 전제로 목표를 잡습니다.

### state_dict만 저장하고 토크나이저·라벨 사전을 잊음

**증상** — 서빙 쪽에서 로드했는데 전처리가 재현이 안 되거나 0/1이 무슨 뜻인지 모름.
**원인** — 텍스트 모델의 배포 단위는 (가중치 + 토크나이저 + 라벨 사전) 세트입니다 ([Day 087](day-087.md) 한 몸 원칙).
**해결** — `model.save_pretrained(dir)` + `tok.save_pretrained(dir)` 로 폴더째 저장하거나, 오늘처럼 state_dict를 쓸 거면 모델 이름·id2label을 스키마 파일에 함께 기록 ([Day 068](../03-machine-learning/day-068.md) 방식). 내일 predict 스크립트에서 이 완성형을 만듭니다.

**Q1.** 파인튜닝 전 0.545의 원인을 "몸통과 머리"의 언어로 설명하고, 그 상태에서 1,500건만으로
0.815에 도달할 수 있었던 이유를 쓰세요.

<details>
<summary>답 보기</summary>

몸통(한국어 이해)은 사전학습으로 이미 완성인데 분류 머리가 무작위라, 지식이 과제로 연결되지 못해
동전 수준이었습니다. 파인튜닝은 그 연결(머리)과 몸통의 미세 조정만 하면 되므로, 바닥부터라면 수만 건이
필요할 과제가 1,500건으로 충분했습니다 — 어제 fill-mask로 확인한 사전학습 지식이 밑천입니다.

**Q2.** 이미지 전이학습([Day 083](day-083.md))에서는 몸통을 동결했고, 오늘은 전체를 작은 학습률로
움직였습니다. 두 전략의 트레이드오프를 쓰세요.

<details>
<summary>답 보기</summary>

동결(특징 추출)은 빠르고 과적합에 강하지만 몸통이 새 도메인에 적응하지 못하고, 전체 파인튜닝은
표현까지 과제에 맞게 조정되어 성능 상한이 높지만 비용이 크고 데이터가 적으면 망각·과적합 위험이
있습니다. 관례: 데이터가 아주 적으면 동결부터, 여유가 있으면 작은 학습률의 전체 파인튜닝 —
그리고 그 중간(LoRA)이 대형 모델 시대의 절충입니다.

</details>
