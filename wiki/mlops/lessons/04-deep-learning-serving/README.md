## 이 문서들을 읽는 법

각 일차 문서는 **6개 블록의 고정 구조**를 갖습니다. 어느 날짜를 펴도 같은 자리에 같은 종류의 내용이 있습니다.

| 블록 | 내용 | 이렇게 쓰세요 |
|---|---|---|
| ① 학습 목표 | 오늘을 마치면 할 수 있게 되는 것 | 수업 전에 읽고, 수업 후에 다시 읽어 체크 |
| ② 왜 필요한가 | 이 개념이 없으면 무엇이 안 되는지 | 이해가 안 갈 때 여기로 돌아오세요 |
| ③ 개념 설명 | 용어와 원리 | 표와 그림 위주. 용어는 처음 나올 때 풀어 씀 |
| ④ 단계별 실습 | Step 1 → N, 코드 + 실행 결과 | **직접 타이핑**하세요. 복사만 하면 안 늡니다 |
| ⑤ 자주 하는 실수 | 에러 메시지 원문 + 원인 + 해결 | 에러가 났을 때 Ctrl+F로 검색 |
| ⑥ 확인 문제 | 3문항, 답은 접혀 있음 | 답을 보기 전에 반드시 먼저 풀어 보세요 |

**코드 블록 규칙** — 실습 코드는 전부 **복사해서 붙여넣으면 그대로 실행되는 완성본**입니다.
터미널 블록은 `$` 로 시작하는 줄이 입력, 그 아래가 실제 출력입니다. `실행 결과:` 아래 블록은 그 코드를 실행했을 때 실제로 나오는 출력입니다.

> **이 단원의 숫자 재현성 주의** — 문서의 실행 결과는 전부 실제 실행값(시드 42, CPU 기준)이지만,
> 딥러닝 연산은 장치(CPU/GPU)·스레드 수·라이브러리 빌드에 따라 **소수점 이하가 달라질 수 있습니다.**
> 대단원 03과 달리 "숫자가 완전히 같아야 정상"이 아니라 **"경향(수렴 방향·크기 급)이 같으면 정상"** 입니다.
> 왜 그런지 자체가 [Day 084](day-084.md)에서 다루는 주제입니다. 서빙 주간(W19~)의 API 응답·테스트 결과는 다시 완전 일치가 기준입니다.

## 이 단원을 마치면

- [ ] PyTorch로 **학습 루프를 바닥부터 작성**하고 학습 곡선을 읽고 대응할 수 있다
- [ ] 전이학습으로 **적은 데이터에서도 쓸 만한 모델**을 만들 수 있다
- [ ] Hugging Face 사전학습 모델을 **추론에 활용**할 수 있다 (라이선스 확인 포함)
- [ ] FastAPI로 **입력 검증·로깅·테스트가 갖춰진 추론 API**를 만들 수 있다

**단원 완료 조건 (MP3 제출 기준)**

- [ ] 학습과 서빙의 전처리가 같은 코드에서 나온다
- [ ] 잘못된 입력이 의도된 에러 응답으로 처리된다
- [ ] 로그에서 요청별 처리시간을 집계할 수 있다
- [ ] API 통합 테스트가 CI 없이도 한 줄로 실행된다

**단원 산출물** DL 추론 API 서비스 → 포트폴리오 저장소 4번 (W22~28에서 컨테이너·CI/CD로 발전)

## 자주 나오는 질문

| 질문 | 답 |
|---|---|
| GPU가 없는데 따라갈 수 있나요? | 네. GPU 실습은 Colab 무료 티어 기준으로 설계했고, 문서 실행 결과는 CPU 축소 설정으로도 재현됩니다. 서빙(W19~)은 CPU로 충분합니다. |
| sklearn을 배웠는데 왜 또 PyTorch인가요? | sklearn은 "완성된 알고리즘"을 쓰는 도구, PyTorch는 "모델 구조 자체"를 조립하는 도구입니다. 이미지·텍스트는 후자가 필요하고, [Day 080](day-080.md)에서 같은 문제로 정면 비교합니다. |
| 서빙 정확도가 학습 때보다 낮아요 | 대부분 전처리 불일치입니다 ([Day 097](day-097.md)). 학습 파이프라인 객체를 저장해 서빙에서 그대로 로드하세요. |
| 요청마다 모델을 로드하면 왜 안 되나요? | 로드는 수 초짜리 작업입니다. 서버 시작 시 1회 로드해 상주시킵니다 — [Day 096](day-096.md)에서 두 방식의 응답 시간을 실측 비교합니다. |
| LLM·RAG는 언제 배우나요? | 본 과정 수료 후 **LLM 엔지니어링 과정**에서 다룹니다. 여기서 배우는 HF·FastAPI·Docker가 그 선수 지식입니다. |
