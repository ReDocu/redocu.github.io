## 3. 개념

### 3-1. 중력 — 속도를 바꾸는 힘

**왜 필요한가** — 오늘의 핵심. 한 줄이면 된다.

```cpp
    m_vy += GRAVITY * dt;                      // ★ 이 한 줄

    m_x += m_vx * dt;
    m_y += m_vy * dt;
```

```
   ★ 위치가 아니라 "속도"를 바꾼다

   중력은 가속도다
   → 매 순간 속도를 아래쪽으로 조금씩 민다
   → 그 누적이 포물선을 만든다
```

**속도 변화 추적** (GRAVITY = 400, 초기 vy = -300)

| 시간(초) | vy | 상태 |
|:--:|:--:|---|
| 0.00 | -300 | 빠르게 위로 |
| 0.25 | -200 | 위로 |
| 0.50 | -100 | 느리게 위로 |
| **0.75** | **0** | **정점** |
| 1.00 | +100 | 아래로 |
| 1.25 | +200 | 빠르게 아래로 |
| 1.50 | +300 | 착지 (발사 속도와 같다) |

```
   높이 변화

   y ↑
     │        ●  ●
     │     ●        ●
     │   ●             ●
     │  ●                ●
     │ ●                   ●
     │●                      ●
   ──┴────────────────────────▶ 시간
     0    0.5   0.75   1.0   1.5

   ★ 정점 전후가 대칭이다
```

### 3-2. 포물선의 물리 공식

**왜 필요한가** — 예측과 밸런싱에 필요하다.

```
   초기 속도 v, 각도 θ, 중력 g

   vx = v × cos(θ)
   vy = v × sin(θ)      (수학 좌표계 기준, 위가 +)
```

| 값 | 공식 | 의미 |
|---|---|---|
| **비행 시간** | `T = 2·vy / g` | 발사 → 착지 |
| **최고 높이** | `H = vy² / (2g)` | 정점 높이 |
| **정점 시각** | `t = vy / g` | T의 절반 |
| **사거리** | `R = vx × T = v²·sin(2θ) / g` | 수평 거리 |

```
   예)  v = 300, θ = 45°, g = 400

   vx = 300 × cos(45°) = 212.1
   vy = 300 × sin(45°) = 212.1

   T = 2 × 212.1 / 400 = 1.06 초
   H = 212.1² / (2 × 400) = 56.2 px
   R = 212.1 × 1.06 = 224.8 px
```

```
   ★ 이 공식으로 밸런싱을 한다

   "화면 폭 800px 을 최대 힘으로 넘어야 한다"
   → R = v² / g ≥ 800  (45도 기준)
   → v² ≥ 800 × g

   g = 400 이면 v ≥ 566
```

**왜 필요한가** — 게임의 느낌을 결정한다.

```

   중력 작음 (200)      중력 큼 (800)

        ·  ·  ·  ·           ·
     ·              ·       · ·
   ·                  ·    ·   ·
   ▲                  ▼   ▲     ▼

   높고 느리게              낮고 빠르게
   "달에서 쏘는 느낌"       "묵직한 느낌"
```

| 중력 | 비행 시간 (v=300, 45°) | 느낌 |
|:--:|:--:|---|
| 200 | 2.12초 | 둥실둥실, 느리다 |

```
   너무 길면    →  기다리기 지루하다
```

### 3-4. ⚠️ 델타 타임과 적분 오차

**왜 필요한가** — 프레임에 따라 궤적이 미세하게 달라진다.

```cpp
    // 오일러 방법 (가장 단순)
    m_vy += g * dt;
    m_y  += m_vy * dt;
```

```
   ★ 이 방식은 약간 부정확하다

   실제:  y = y0 + vy·t + ½·g·t²
   오일러: 매 프레임 근사

   프레임이 클수록 오차가 커진다
```

**정확한 방법 — 속도 검증 적분(Velocity Verlet)**

```cpp
    m_y  += m_vy * dt + 0.5 * g * dt * dt;     // ★ ½gt² 항 추가
    m_vy += g * dt;
```

```
   비교 (g=400, vy0=-300, dt=1/60)

   방법          1초 후 y 오차
   오일러         약 3.3 px
   Verlet        약 0.0 px
```

```
   ★ 게임에서 어느 것을 쓰나

   대부분  →  오일러로 충분 (오차가 눈에 안 보인다)
   포격 게임 →  Verlet 권장 (착탄 예측과 실제가 맞아야 한다)
```

**더 확실한 방법 — 고정 시간 스텝**

```cpp
void Shell::Update(double dt)
{
    const double FIXED_DT = 1.0 / 120.0;       // 물리는 120Hz 고정

    m_accumulator += dt;

    while (m_accumulator >= FIXED_DT)
    {
        StepPhysics(FIXED_DT);
        m_accumulator -= FIXED_DT;
    }
}
```

```
   ★ 고정 스텝의 이득

   프레임률과 무관하게 완전히 동일한 궤적
   → 리플레이, 네트워크 동기화에 필수
   → 착탄 예측이 정확해진다
```

### 3-5. 착탄 예측

**왜 필요한가** — 조준을 도와준다. 그리고 AI가 쓴다.

**방법 1 — 시뮬레이션**

```cpp
int PredictLanding(double x, double y, double vx, double vy,
                   const Terrain& terrain, double g,
                   Vector2* outPath, int maxPoints, int* outCount)
{
    const double STEP = 1.0 / 60.0;
    const int MAX_STEPS = 600;                 // 최대 10초

    *outCount = 0;

    for (int i = 0; i < MAX_STEPS; i++)
    {
        y  += vy * STEP + 0.5 * g * STEP * STEP;
        vy += g * STEP;
        x  += vx * STEP;

        // 궤적 점 기록 (몇 프레임에 하나씩)
        if (i % 4 == 0 && *outCount < maxPoints)
            outPath[(*outCount)++] = { x, y };

        // 화면 밖
        if (x < 0 || x > terrain.GetWidth()) return -1;

        // 지형 충돌
        if (y >= terrain.GetHeightAt((int)x))
            return (int)x;                     // 착탄 x 좌표
    }

    return -1;                                 // 시간 초과
}
```

```
   ★ 게임 로직과 같은 계산을 미리 돌린다

   장점:  지형·바람 등 모든 요소를 반영한다
   단점:  계산량이 있다 (하지만 600 스텝은 금방이다)
```

**방법 2 — 공식 (평지에서만)**

```cpp
double PredictRangeFlat(double v, double angleDeg, double g)
{
    double rad = DegToRad(angleDeg);
    return v * v * sin(2 * rad) / g;
}
```

```
   ★ 지형이 평평할 때만 맞는다
     언덕이 있으면 시뮬레이션을 써야 한다
```

### 3-6. 지형 충돌

**왜 필요한가** — 포탄이 땅에 닿으면 멈춰야 한다.

```cpp
void Shell::Update(double dt)
{
    double prevX = m_x, prevY = m_y;

    // 물리
    m_y  += m_vy * dt + 0.5 * GRAVITY * dt * dt;
    m_vy += GRAVITY * dt;
    m_x  += m_vx * dt;

    // 화면 밖
    if (m_x < -100 || m_x > m_core->GetWidth() + 100) { Destroy(); return; }
    if (m_y > m_core->GetHeight() + 200) { Destroy(); return; }

    // 지형 충돌
    int tx = (int)m_x;

    if (tx >= 0 && tx < m_terrain->GetWidth())
    {
        int groundY = m_terrain->GetHeightAt(tx);

        if (m_y >= groundY)
        {
            // ★ 정확한 착탄점 계산 (보간)
            double t = (groundY - prevY) / (m_y - prevY);
            double hitX = prevX + (m_x - prevX) * t;

            OnImpact(hitX, groundY);
            Destroy();
            return;
        }
    }
}
```

```
   ★ 보간으로 정확한 착탄점을 구한다

   프레임 N   : y = 470  (지면 480 위)
   프레임 N+1 : y = 495  (지면 아래)

   보간 없이:  x 를 495 시점 값으로  →  약간 지나침
   보간:      정확히 y=480 인 지점의 x
```

### 3-7. ⚠️ 터널링 — 빠른 포탄이 지형을 통과

**왜 필요한가** — Day 22에서 만난 그 문제가 여기서 더 심각하다.

```
   포탄 속도 1200 px/s, dt = 1/60초

   한 프레임 이동량 = 20 px

   얇은 지형(두께 10px)을 지나칠 수 있다

   프레임 N   : y = 470  (지형 위)
   프레임 N+1 : y = 490  (지형 아래)
                지형은 475~485

   → 통과해 버린다
```

**해결 — 이동 분할**

```cpp
void Shell::Update(double dt)
{
    // 한 프레임 이동 거리
    double moveDist = sqrt(m_vx*m_vx + m_vy*m_vy) * dt;

    // 최대 이동 단위(예: 4px)로 나눈다
    int steps = (int)(moveDist / 4.0) + 1;
    if (steps > 32) steps = 32;

    double subDt = dt / steps;

    for (int i = 0; i < steps; i++)
    {
        if (!StepPhysics(subDt)) return;       // 충돌하면 종료
    }
}
```

```
   ★ 세밀한 이동으로 나눠서 매번 검사한다

   속도가 빠를수록 더 잘게 나눈다
   → 계산량은 늘지만 정확하다
```

### Step 4 — 공식 검증

```cpp
void TestProjectileFormula()
{
    double v = 300, angle = 45, g = 400;

    double rad = DegToRad(angle);
    double vx = v * cos(rad);
    double vy = v * sin(rad);

    // 공식
    double T = 2 * vy / g;
    double H = vy * vy / (2 * g);
    double R = vx * T;

    DebugLog("공식:  T=%.3f초  H=%.1fpx  R=%.1fpx\n", T, H, R);

    // 시뮬레이션
    double x = 0, y = 0, curVy = -vy;          // 화면 좌표 (위가 음수)
    double maxH = 0, t = 0;
    const double dt = 1.0/1000.0;

    while (y <= 0 && t < 10)
    {
        y += curVy * dt + 0.5 * g * dt * dt;
        curVy += g * dt;
        x += vx * dt;
        t += dt;

        if (-y > maxH) maxH = -y;
    }

    DebugLog("시뮬:  T=%.3f초  H=%.1fpx  R=%.1fpx\n", t, maxH, x);
}
```

**✅ 여기까지 실행하면** — 공식과 시뮬레이션이 거의 일치해야 한다.

```
   공식:  T=1.061초  H=56.2px  R=224.9px
   시뮬:  T=1.061초  H=56.2px  R=225.0px
```

### Step 6 — 오일러 vs Verlet

```cpp

        m_y  += m_vy * dt;
```

## 7. 정리

### 오늘 배운 것

| 개념 | 한 줄 요약 |
|---|---|
| **중력** | `vy += g * dt`. 위치가 아니라 **속도**를 바꾼다 |
| 비행 시간 | `T = 2·vy/g` |
| 최고 높이 | `H = vy²/(2g)` |
| **사거리** | `R = v²·sin(2θ)/g`. **45도에서 최대** |
| 30도 = 60도 | `sin(2θ)`가 같다. 저탄도 vs 곡사 |
| 중력 값 | 비행 시간 1~3초가 적당 |
| **Verlet 적분** | `y += vy·dt + ½·g·dt²`. 프레임 무관 |
| 고정 시간 스텝 | 완전한 재현성 |
| 착탄 예측 | 시뮬레이션이 확실 (지형·바람 반영) |
| 터널링 | 이동 분할로 해결 |
