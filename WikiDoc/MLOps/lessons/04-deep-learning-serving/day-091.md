## ① 학습 목표

이 레슨을 마치면 이렇게 할 수 있습니다.

- HTTP 요청의 구성(메서드 · 경로 · 쿼리 · 바디 · 상태 코드)을 설명할 수 있다.
- FastAPI로 GET/POST 엔드포인트를 만들고 uvicorn으로 띄울 수 있다.
- **경로/쿼리/바디** 세 가지 입력 통로를 구분해 쓸 수 있다.
- 자동 문서(`/docs`)와 자동 검증(422)이 **타입 힌트에서 나온다**는 것을 안다.

---

## ② 왜 필요한가

3주간 모델을 만들었습니다(W16–18). 그런데 그 모델들은 아직 **여러분의 파이썬 프로세스
안에서만** 삽니다. [Day 075](../03-machine-learning/day-075.md) 마지막에 예고한 그 간극입니다:

```
지금:  joblib.load(...) → model.predict(df)          파이썬 + 저장소 + 환경이 있어야
목표:  POST /predict {"pm25": 41.0} → {"pred": 29.5}   HTTP만 되면 누구나 — 앱, 웹, 다른 서버
```

이 간극을 메우는 것이 **웹 API**이고, 이번 주 도구가 FastAPI입니다. 왜 FastAPI인가:

| 이유 | 설명 |
|---|---|
| 파이썬 표준 문법 재사용 | 타입 힌트([Day 010](../01-python-data/day-010.md))가 그대로 검증 규칙이 됨 |
| **자동 검증 + 자동 문서** | 오늘 실습에서 코드 0줄로 422와 /docs가 생기는 걸 봅니다 |
| ML 서빙의 사실상 표준 | 추론 API 예제·생태계가 가장 두터움 |

이번 주는 모델 없이 API 자체를 연습하고(작게: 오늘 → 검증 → 구조 → 테스트 → 할 일 API),
다음 주에 모델을 얹습니다. 서버가 처음이어도 괜찮습니다 — HTTP는 이미
[Day 016](../01-python-data/day-016.md)에서 **클라이언트로서** 다뤄 봤습니다. 오늘은 반대편
의자에 앉는 날입니다.

## ③ 개념 설명

### HTTP 대화의 형식 — 이번엔 서버의 눈으로

```
요청:  POST /reports HTTP/1.1          ← 메서드 + 경로
       Content-Type: application/json
       {"station": "강남구", "pm25": 41.5}   ← 바디

응답:  HTTP/1.1 201 Created            ← 상태 코드
       {"saved": true, ...}
```

| 메서드 | 관례적 의미 | 오늘의 예 |
|---|---|---|
| GET | 조회 (바디 없음, 몇 번 해도 같음) | 측정소 정보 보기 |
| POST | 생성·실행 | 리포트 제출 · (다음 주) 예측 요청 |
| PUT/DELETE | 수정 / 삭제 | 과제의 CRUD |

| 상태 코드 | 뜻 | 누구 잘못 |
|---|---|---|
| 200 / 201 | 성공 / 생성됨 | — |
| **4xx** (400, 404, 422) | 요청이 잘못됨 | 클라이언트 |
| **5xx** (500) | 서버가 터짐 | **우리** |

주간 체크포인트("잘못된 입력이 500이 아니라 의도된 4xx로 나가는가")의 언어가 이 표입니다.

### 입력의 세 통로

| 통로 | 생김새 | 용도 |
|---|---|---|
| **경로** | `/stations/강남구` | 자원의 식별자 |
| **쿼리** | `?station=강남구&limit=3` | 조회 옵션 (필터·페이징) |
| **바디** | JSON `{...}` | 생성·실행에 필요한 데이터 뭉치 (POST) |

### FastAPI의 마법 아닌 마법

```python
@app.get("/measurements")
def list_measurements(station: str, limit: int = 5):
```

이 시그니처 한 줄에서 FastAPI가 읽어 내는 것: station은 **필수** 쿼리(기본값 없음),
limit은 선택(기본 5)이며 **정수여야 함**. 그래서 station이 빠지면 422, limit=abc도 422 —
우리가 검증 코드를 한 줄도 안 썼는데요. 파이썬 타입 힌트가 계약서가 되는 것,
이것이 FastAPI의 핵심 발상입니다 (본격 활용은 내일 pydantic에서).

## ④ 단계별 실습

### Step 0. 설치와 프로젝트 폴더 (1교시)

```powershell
pip install fastapi==0.141.1 "uvicorn[standard]" httpx
mkdir api; cd api
```

### Step 1. 첫 API 작성 (2~3교시)

`main.py`:

```python
# main.py — Day 091: 첫 API
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI(title="대기질 API 첫걸음", version="0.1.0")


@app.get("/")
def root():
    return {"message": "대기질 예보 서비스", "docs": "/docs"}


@app.get("/stations/{name}")                      # 경로 파라미터
def get_station(name: str):
    return {"station": name, "active": True}


@app.get("/measurements")                          # 쿼리 파라미터
def list_measurements(station: str, limit: int = 5):
    return {"station": station, "limit": limit,
            "items": [{"day": i, "pm25": 20 + i} for i in range(1, limit + 1)]}


class Report(BaseModel):                           # 요청 바디의 모양
    station: str
    pm25: float


@app.post("/reports", status_code=201)             # 생성은 201
def create_report(report: Report):
    return {"saved": True, "station": report.station, "pm25": report.pm25}
```

서버를 띄웁니다 (이 터미널은 서버 전용이 됩니다 — 종료는 Ctrl+C):

```powershell
uvicorn main:app --reload --port 8091
```

```
INFO:     Started server process [22304]
INFO:     Waiting for application startup.
INFO:     Application startup complete.
INFO:     Uvicorn running on http://127.0.0.1:8091 (Press CTRL+C to quit)
```

`--reload` 는 파일을 저장할 때마다 서버를 자동 재시작하는 개발용 옵션입니다.

### Step 2. 호출해 보기 — 새 터미널에서 (4~5교시)

브라우저로 `http://127.0.0.1:8091/` 을 열어도 되고, 새 터미널에서 요청을 보내도 됩니다.
(아래는 httpx로 보낸 요청과 실제 응답 — `상태코드 → 바디` 형식으로 표기)

```
$ GET /
  200 → {"message": "대기질 예보 서비스", "docs": "/docs"}
$ GET /stations/강남구
  200 → {"station": "강남구", "active": true}
$ GET /measurements?station=강남구&limit=3
  200 → {"station": "강남구", "limit": 3, "items": [{"day": 1, "pm25": 21}, {"day": 2, "pm25": 22}, {"day": 3, "pm25": 23}]}
$ POST /reports {'station':'강남구','pm25':41.5}
  201 → {"saved": true, "station": "강남구", "pm25": 41.5}
```

세 통로(경로·쿼리·바디)가 전부 동작합니다. 함수가 dict를 반환하면 FastAPI가 JSON으로
바꿔 줍니다 — `True` 가 `true` 로 바뀐 것도 보이죠 (파이썬 → JSON 번역).

### Step 3. 공짜 검증 — 일부러 틀려 보기 (6교시)

검증 코드를 한 줄도 안 썼습니다. 그런데:

```
$ GET /measurements  (station 없이)
  422 → {"detail": [{"type": "missing", "loc": ["query", "station"], "msg": "Field required", "input": null}]}
$ GET /measurements?station=강남구&limit=abc
  422 → {"detail": [{"type": "int_parsing", "loc": ["query", "limit"], "msg": "Input should be a valid integer, unable to parse string as an integer", "input": "abc"}]}
```

**서버가 죽지 않고(500 아님), 무엇이(loc) 왜(msg) 잘못됐는지 담긴 422**가 나갑니다.
타입 힌트 `station: str, limit: int = 5` 가 이 모든 것의 출처입니다.
[Day 044](../02-sql-pipeline/day-044.md)에서 손으로 짰던 검증 규칙의 상당 부분을,
웹 계층에서는 선언만으로 얻는 셈입니다 — 더 정교한 규칙은 내일 다룹니다.

### Step 4. 공짜 문서 — /docs (7교시)

브라우저에서 `http://127.0.0.1:8091/docs` 를 여세요. 방금 만든 4개 엔드포인트가
**대화형 문서**로 정리되어 있습니다 — 각 항목을 펼쳐 "Try it out"으로 브라우저에서 직접
호출해 볼 수 있습니다. 이 문서의 원료는 기계가 읽는 명세(JSON)입니다:

```
GET /openapi.json → 200 · 경로 ['/', '/stations/{name}', '/measurements', '/reports']
```

코드가 곧 명세이고 문서는 그 부산물 — 문서가 코드와 어긋날 수 없는 구조입니다.
MP3에서 "API 문서"를 따로 쓰지 않아도 되는 이유이자, 프런트엔드·앱 개발자와 협업할 때
이 URL 하나만 공유하면 되는 이유입니다.

### Step 5. 커밋과 과제 (8교시)

```powershell
git add api/main.py
git commit -m "Day 091: 첫 FastAPI — 세 통로, 공짜 검증(422), /docs"
```

**과제 — 측정소 CRUD.** 메모리 딕셔너리(`stations = {}`)를 저장소 삼아 네 엔드포인트를 만드세요:
`POST /stations`(201, 이미 있으면 409) · `GET /stations/{name}`(없으면 404) ·
`PUT /stations/{name}` · `DELETE /stations/{name}`(204).
404/409는 `raise HTTPException(status_code=..., detail=...)` 로 — 힌트: `from fastapi import HTTPException`.
전부 /docs에서 Try it out으로 검증하고, 상태 코드 선택 이유를 한 줄씩 적으세요.

## ⑤ 자주 하는 실수

### 서버 터미널에 갇힘

**증상** — `uvicorn main:app` 실행 후 같은 터미널에 명령을 쳤는데 반응이 없음.
**원인** — 그 터미널은 이제 서버가 점유 중입니다. 로그가 흐르는 창입니다.
**해결** — 호출·git 작업은 **새 터미널**에서. 서버 종료는 서버 터미널에서 Ctrl+C. (터미널 두 개가 이번 주의 기본 배치입니다.)

### 이미 쓰는 포트에 또 띄움

```
ERROR:    [Errno 10048] error while attempting to bind on address ('127.0.0.1', 8091): ...
```

**원인** — 이전 서버가 아직 살아 있는데 같은 포트로 다시 실행했습니다.
**해결** — 기존 서버를 Ctrl+C로 끄거나 `--port 8092` 처럼 다른 포트를 씁니다. 유령 프로세스는 PowerShell에서 `Get-NetTCPConnection -LocalPort 8091` 로 찾아 종료합니다.

### 경로 등록 순서 함정

**증상** — `GET /stations/count` 를 만들었는데 `{"station": "count"}` 가 나옴.
**원인** — `/stations/{name}` 이 먼저 등록되어 있으면 count도 name으로 잡힙니다.
**해결** — **고정 경로를 동적 경로보다 위에** 선언합니다. 라우팅은 위에서부터 첫 매치입니다.

### GET에 바디를 실으려 함

**증상** — GET 요청에 JSON을 실었는데 서버가 무시하거나 도구가 거부.
**원인** — 관례상 GET은 바디를 쓰지 않습니다(중간 장비·라이브러리가 버리기도 합니다).
**해결** — 조회 조건은 쿼리로, 데이터 뭉치가 필요한 작업은 POST로. "조회는 GET+쿼리, 생성·실행은 POST+바디"가 기본기입니다.

### --reload를 운영에도 켬

**증상** — 운영 서버가 파일 변경 감시로 CPU를 먹고, 가끔 요청 도중 재시작됨.
**원인** — `--reload` 는 개발 편의 기능입니다.
**해결** — 운영 실행은 reload 없이 (워커 수 등 운영 옵션은 [Day 099](day-099.md)에서). "개발 명령과 운영 명령은 다르다"를 지금부터 구분해 두세요.

## ⑥ 확인 문제

**Q1.** 다음 요구를 경로/쿼리/바디 중 어느 통로로 설계할지 정하고 이유를 쓰세요:
① 특정 측정소의 상세 조회 ② 최근 측정값을 개수 제한으로 조회 ③ 새 측정값 등록

<details>
<summary>답 보기</summary>

① 경로 `/stations/{name}` — 자원의 식별자. ② 쿼리 `/measurements?station=..&limit=..` —
조회 옵션은 선택적·조합 가능해야 하므로. ③ POST + 바디 — 생성할 데이터 뭉치(여러 필드)는
구조화된 JSON으로 싣습니다.

</details>

**Q2.** limit=abc 요청에 500이 아니라 422가 나간 것이 왜 중요한가요? 500이었다면 클라이언트
개발자는 무엇을 하게 될까요?

<details>
<summary>답 보기</summary>

422는 "네 요청의 loc/msg가 잘못됐다"는 **행동 가능한 정보**라 클라이언트가 스스로 고칠 수 있습니다.
500은 "서버 잘못"이라는 신호이므로 클라이언트 개발자는 우리에게 장애 문의를 하게 되고, 운영자는
멀쩡한 서버의 에러 알림을 받게 됩니다. 잘못의 소재를 상태 코드가 정확히 가리키는 것이 API 품질의
기본입니다 (MP3 평가 기준 "API 품질 30점"의 일부).

</details>

**Q3.** /docs가 "코드와 어긋날 수 없는 문서"인 이유를 openapi.json과 연결해 설명하세요.

<details>
<summary>답 보기</summary>

/docs는 사람이 따로 쓴 문서가 아니라, FastAPI가 **코드(데코레이터·타입 힌트·모델)에서 생성한**
기계 명세(openapi.json)를 렌더링한 것입니다. 코드가 바뀌면 명세와 문서가 같이 바뀌므로 문서 부패가
구조적으로 불가능합니다 — [Day 063](../03-machine-learning/day-063.md)의 "사람이 지킬 규칙을 구조가
지키게"의 문서판입니다.

</details>
