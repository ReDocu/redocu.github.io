## 단원 개요

### 이 단원을 마치면

- 팀으로 **데이터 수집 → 저장 → 학습 → 서빙 → 운영 자동화**의 전체 사이클을 완성한다.
- 브랜치 전략·PR 리뷰·이슈 관리로 **4주짜리 개발을 계획하고 완주**한다.
- 채용 담당자 앞에서 **아키텍처와 기술 선택의 이유를 설명**할 수 있는 포트폴리오를 갖는다.

### 왜 4주인가

1주 기획 + 2주 구현 + 1주 마무리·발표입니다. 새로 배우는 것은 없고, 대단원 01~05의 산출물과 패턴을
팀 규모에서 통합합니다. 기획(W29)을 줄이면 스프린트가 무너지므로 구현 기간을 늘리기 위해 기획을 줄이지 않습니다.

### 주차 구성

| 주차 | 주제 | Day |
|---|---|---|

대단원 01–05 수료 (MP1–MP4 제출 완료).

## 최종 프로젝트 주제 후보 5개

팀은 아래 중 택 1 하거나, 같은 구성 요소(수집·DB·모델·API·운영)를 갖춘 자체 주제를 제안할 수 있습니다.
모든 주제는 공공·공개 데이터로 수행 가능하며 GPU 의존이 낮습니다.

| # | 주제 | 데이터 | 모델 | 서비스 형태 |
|---|---|---|---|---|
| 1 | 대중교통 혼잡도 예측 서비스 | 서울열린데이터광장 (지하철/버스 이용량) | 시계열 회귀 | 시간·역 입력 → 혼잡 예측 API + 대시보드, 일 단위 자동 재학습 |
| 2 | 중고거래 시세 예측 서비스 | 공개 중고거래 시세 데이터 (수집 파이프라인) | 회귀 (부스팅) | 품목·상태 입력 → 적정가 API, 주간 데이터 갱신 파이프라인 |
| 3 | 민원·리뷰 자동 분류 라우팅 | 공공 민원 텍스트 · 공개 리뷰 데이터 | 한국어 텍스트 분류 (HF 파인튜닝) | 텍스트 입력 → 부서/카테고리 분류 API + 오분류 재라벨링 루프 |
| 4 | 이미지 기반 불량·상태 판별 | 공개 제조/농산물 이미지 데이터셋 | CNN 전이학습 | 이미지 업로드 → 판정 API + 드리프트 모니터링 |
| 5 | 에너지 수요 예측·알림 서비스 | 공공 전력/기상 데이터 | 시계열 회귀 | 예측 API + 임계 초과 알림, Airflow 정기 파이프라인 |

**공통 필수 구성 요소** — 어떤 주제든 다음이 모두 있어야 합니다.

- [ ] 자동 수집·적재 파이프라인 (PostgreSQL, 멱등)
- [ ] 실험 기록이 남은 모델 (MLflow, 베이스라인 대비 개선 근거)
- [ ] FastAPI 추론 API (검증·로깅·테스트)
- [ ] Docker Compose 배포 + GitHub Actions CI/CD
- [ ] 모니터링 관점 1개 이상 (처리시간·입력 분포·에러율)
- [ ] README · 테스트 · 실행 방법 · 결과 보고서

### 프로젝트 공통 폴더 구조

```
project/
├── README.md               # 문제 정의 · 아키텍처 그림 · 실행 방법
├── docker-compose.yml
├── .github/workflows/      # CI/CD
├── src/
│   ├── pipeline/           # 수집 · 전처리 · 적재
│   ├── train/              # 학습 · 평가 (MLflow 연동)
│   └── api/                # FastAPI 서빙
├── tests/                  # 단위 + API 통합 테스트
├── configs/                # 설정 (yaml · .env.example)
├── docs/                   # 보고서 · 운영 절차서 · 회고
└── data/                   # DVC 관리 (원본은 커밋 금지)
```

### 최종 프로젝트 평가 (100점)

| 항목 | 배점 | 기준 |
|---|---|---|
| 전체 사이클 완성도 | 30 | 수집→모델→서빙→운영 자동화가 실제로 관통하는가 |
| 재현성·품질 | 20 | clone→기동 재현 · 테스트 · 시크릿 관리 |
| 모델링 타당성 | 15 | 지표 선택 근거 · 누수 없음 · 실험 기록 |
| 협업 이력 | 15 | 브랜치 전략 · PR 리뷰 · 이슈 관리의 실사용 흔적 |
| 문서·발표 | 20 | README·보고서·운영 절차서 · 발표 전달력 |

**개인 기여도(팀 점수의 30% 반영)** — 커밋·PR 이력 + 동료 평가 + 담당 파트 질의응답으로 산정.
"발표만 한 사람", "코드만 쓴 사람"이 없도록 전원이 시연 질의응답에 응답합니다.

**단원 완료 조건**

- [ ] 공통 필수 구성 요소 6종이 모두 동작한다
- [ ] 팀원 전원의 유의미한 커밋·PR 이력이 있다
- [ ] 개인 포트폴리오 저장소 5종(README 통일)이 공개 상태다
- [ ] 결과 보고서에 한계와 개선 방향이 솔직하게 적혀 있다

## 이 단원에서 자주 나오는 질문

| 질문 | 답 |
