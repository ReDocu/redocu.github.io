## 5. 시작 레벨 진단

| 이런 분 | 여기서 시작하세요 |
|---|---|
| Git을 한 번도 써 본 적 없다 | **초급 01강** |
| `add` · `commit` · `push` 는 외워서 쓰는데 왜 그런지는 모른다 | **초급 03강** (3개의 공간부터) |
| 혼자서는 쓰는데 팀 작업에서 충돌이 나면 손을 못 댄다 | **중급 11강** |
| PR·리뷰는 하는데 `rebase` 가 무서워서 안 쓴다 | **중급 12강** |
| 명령어는 다 아는데 사고가 나면 복구를 못 한다 | **고급 21강** |

### 레벨 진단 — 아래 질문에 막힘없이 답할 수 있나요

<details>
<summary>초급을 건너뛰어도 되는지 확인 (5문항)</summary>

1. `git add` 를 하면 파일은 **어디에서 어디로** 이동하나요?
2. `git commit` 을 했는데 실수를 발견했습니다. 커밋을 새로 만들지 않고 고치려면?
3. `.gitignore` 에 추가했는데도 파일이 계속 올라갑니다. 왜 그럴까요?
4. `git pull` 은 사실 어떤 명령 **두 개**를 합친 것인가요?
5. 브랜치를 만든다는 것은 데이터 관점에서 정확히 무엇을 만드는 것인가요?

> 5문항 중 4개 이상 답했다면 중급부터 시작해도 됩니다.
</details>

<details>
<summary>중급을 건너뛰어도 되는지 확인 (5문항)</summary>

1. `merge` 와 `rebase` 로 만들어진 히스토리는 그림으로 어떻게 다른가요?
2. 이미 `push` 한 커밋을 되돌려야 합니다. `reset` 과 `revert` 중 무엇을 쓰고 왜 그런가요?
3. `rebase` 의 황금률(golden rule)은 무엇인가요?
4. 커밋 3개를 1개로 합치려면 어떤 명령을 쓰나요?
5. `git push --force` 대신 써야 하는 더 안전한 옵션은 무엇인가요?

> 5문항 중 4개 이상 답했다면 고급부터 시작해도 됩니다.
</details>

## 6. 개발 환경 및 준비물

**레벨별 도입 시점**

| 레벨 | 도입 도구 |
|---|---|
| 🟢 초급 | Git 2.30 이상, 터미널(Git Bash 또는 PowerShell), VS Code, GitHub 계정 (09강부터) |
| 🟡 중급 | GitHub Pull Request · 리뷰 기능, 2인 1조 실습 상대 (20강) |
| 🔴 고급 | husky / lint-staged / pre-commit (26강), GitHub Actions (27강), git-filter-repo (29강) |

**학습자 준비물**

- Git 2.30 이상 (`git --version` 으로 확인)
- 터미널 — Windows는 **Git Bash** 또는 PowerShell
- VS Code (Git 기능이 내장되어 있어 실습에 유리)
- GitHub 계정 (09강부터 필요)
- 버려도 되는 **연습용 저장소** — 회사·학교 저장소에서 연습하지 않습니다

> 이 커리큘럼은 **명령어(CLI)를 기준**으로 합니다. GUI 도구(SourceTree, GitHub Desktop, VS Code Git 패널)는
> 각 강의 마지막에 "같은 일을 GUI로 하면" 으로 덧붙입니다. 원리는 CLI로 익히고, 실무 속도는 GUI로 내는 것이 좋습니다.

## 7. 평가 및 산출물

| 구분 | 시점 | 방식 |
|---|---|---|
| 강별 과제 | 매 강 | 각 강 마지막 과제를 개인 GitHub 저장소에 올려 제출 |
| 초급 실기 | 10강 후 | 빈 폴더에서 GitHub 공개 저장소까지 30분 안에 |
| 중급 실기 | 20강 후 | 주어진 충돌 상황 해결 + PR 리뷰 반영 |
| 고급 실기 | 30강 후 | 망가진 저장소 복구 + 훅/CI 세팅 |

**수료 시점 체크리스트**

- [ ] Git의 세 공간과 객체 모델을 설명할 수 있다
- [ ] 혼자서든 팀에서든 브랜치 전략에 맞게 작업할 수 있다
- [ ] 어떤 실수를 해도 되돌릴 방법을 알고 있다
- [ ] 저장소의 규칙을 훅과 CI로 자동화할 수 있다
- [ ] 후배에게 Git을 가르칠 수 있다

## 8. 운영 원칙

1. **모든 실습은 버려도 되는 연습용 저장소에서** 진행합니다. Git은 "망가뜨려 보는" 것이 가장 빠른 학습법이지만, 회사·학교 저장소에서 연습하면 안 됩니다.
2. **실습 명령은 직접 타이핑**합니다. 복사만 하면 안 늡니다. `$` 로 시작하는 줄이 입력할 명령, 그 아래가 실제 출력입니다.
3. **매 강의 과제는 개인 GitHub 저장소에 커밋**합니다. 수료 시점의 GitHub 잔디가 곧 포트폴리오입니다.
4. **원리는 CLI로, 속도는 GUI로.** GUI 도구는 각 강 마지막 "같은 일을 GUI로 하면"에서만 다룹니다.
5. **진도가 밀린 경우** 개념(①②③ 블록)을 줄이지 말고 실습 범위를 줄입니다. 개념 공백은 다음 레벨에서 복구가 어렵습니다.
6. **종합 실습 강(10 · 20 · 30강)에서는 새 개념을 넣지 않습니다.** 그 레벨에서 배운 것만으로 처음부터 끝까지 완주시킵니다.
