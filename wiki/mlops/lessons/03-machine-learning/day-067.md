## ② 왜 필요한가

[Day 065](day-065.md)에서 확인한 수기 기록표의 4대 한계를 다시 폅니다. 이것이 오늘의 요구사항 명세서입니다.

| 수기의 한계 | MLflow의 답 |
|---|---|
| 누락 (급할 때 안 적음) | 로깅이 **코드 안에** 있어 실행되면 무조건 기록됨 |
| 불일치 (사람마다 해석이 다름) | 파라미터가 **키=값으로 기계적으로** 저장됨 |
| 검색 불능 (눈으로 표 뒤지기) | `metrics.r2_test > 0.5` 같은 **쿼리** |
| 산출물 부재 (숫자만 남음) | 모델·예측 파일이 run에 **첨부**됨 |

여기서 태도 하나를 분명히 합니다 — MLflow는 **어제까지 우리가 손으로 하던 일의 자동화**일 뿐,
새로운 개념이 아닙니다. 여덟 칸 기록표([Day 065](day-065.md))를 이해한 사람에게 MLflow는
반나절 도구입니다. 반대로 기록의 필요를 모른 채 도구부터 배우면 "로그는 쌓이는데 아무도
안 보는" 창고가 됩니다. 우리는 고통을 먼저 겪었으니, 이제 도구를 받을 자격이 있습니다.

## ③ 개념 설명

### MLflow 구조 — 세 단어만 알면 됩니다

```
experiment "pm25-forecast"            ← 프로젝트 단위 폴더
├── run "linear-num10"                ← 실험 1회 = run 1개
│   ├── params   {model: linear, feature_set: num10, seed: 42, …}
│   ├── metrics  {r2_test: 0.420, mae_test: 4.83}
│   └── artifacts predictions.csv, 모델 파일, 그림 …
├── run "lgbm-num10"
└── …
```

| 용어 | 뜻 | 여덟 칸 기록표와의 대응 |
|---|---|---|
| **experiment** | run들을 담는 프로젝트 폴더 | 기록표 파일 하나 |
| **run** | 실험 1회의 기록 단위 | 표의 행 하나 |
| **param** | 실험의 조건 (입력) | ①~⑤·⑦ 칸 |
| **metric** | 실험의 결과 숫자 (출력) | ⑥ 칸 |
| **artifact** | 실험이 낳은 파일 | 수기 표엔 없던 것! |

### 로깅 API — 다섯 줄이 전부

```python
mlflow.set_experiment("pm25-forecast")     # 실험 폴더 지정 (없으면 생성)
with mlflow.start_run(run_name="..."):     # run 열기 (with 블록 = 실험 1회)
    mlflow.log_params({...})               # 조건 기록
    mlflow.log_metrics({...})              # 결과 기록
    mlflow.log_artifact("파일경로")          # 산출물 첨부
```

기록은 기본적으로 현재 폴더의 `mlruns/` 아래에 쌓입니다. **git에는 올리지 않습니다**
(`.gitignore` 에 `mlruns/` 추가) — 코드는 git, 실험 이력은 MLflow로 역할을 나눕니다.

### 무엇을 param으로 남기나

[Day 065](day-065.md)의 여덟 칸이 그대로 답입니다. 특히 잊기 쉬운 세 가지:
**데이터 지문**(어제 만든 MD5), **행의 정의**(재현 게임의 범인), **시드**.
그리고 ⑧(왜/결론)는 자동화되지 않으므로 `mlflow.set_tag("note", "...")` 로 사람이 남깁니다.

### Step 1. 설치와 첫 로깅 (1교시)


W13 내내 반복한 "특성 세트 3종 × 모델 2종" 매트릭스를 이번엔 **기록하면서** 돌립니다.
`day067_mlflow.py` (특성 생성부는 [Day 065](day-065.md)의 `load()` 와 동일):

```python
# day067_mlflow.py — MLflow: 실험을 자동 기록한다
import mlflow
import numpy as np
import pandas as pd
# … (Day 065와 동일한 import·load()·build_linear() 정의를 가져옵니다)

mlflow.set_experiment("pm25-forecast")

SETS = {"num10": NUM, "num+time": NUM + TIME, "num+time+fc": NUM + TIME + FC}
for set_name, feats in SETS.items():
    for model_name in ["linear", "lgbm"]:
        with mlflow.start_run(run_name=f"{model_name}-{set_name}"):
            mlflow.log_params({
                "model": model_name, "feature_set": set_name, "n_features": len(feats) + 1,
                "imputer": "median", "split": "time<2026-01-01", "seed": 42,
                "data_md5": "21adc01f2409f9c2bda8ac0cf2452979",     # Day 066의 데이터 지문
            })
            if model_name == "linear":
                m = build_linear(feats).fit(tr[feats + ["station"]], tr.pm25_next)
                pred = m.predict(te[feats + ["station"]])
            else:
                dtr = tr[feats].assign(station=tr.station.astype("category"))
                dte = te[feats].assign(station=te.station.astype("category"))
                m = LGBMRegressor(random_state=42, verbosity=-1, num_leaves=15, learning_rate=0.03,
                                  n_estimators=700, min_child_samples=40, reg_lambda=1.0,
                                  colsample_bytree=0.8).fit(dtr, tr.pm25_next)
                pred = m.predict(dte)
            r2 = r2_score(te.pm25_next, pred)
            mae = mean_absolute_error(te.pm25_next, pred)
            mlflow.log_metrics({"r2_test": r2, "mae_test": mae})
            out = te[["date", "station", "pm25_next"]].assign(pred=np.round(pred, 1))
            out.to_csv("predictions.csv", index=False)
            mlflow.log_artifact("predictions.csv")
            print(f"기록: {model_name}-{set_name:<12} R² {r2:.3f}  MAE {mae:.2f}")
```

## ⑤ 자주 하는 실수

### run을 열어 놓고 닫지 않음

**증상** — 다음 실험의 지표가 이전 run에 섞여 기록됨.
**원인** — `mlflow.start_run()` 을 with 없이 호출하고 `end_run()` 을 잊음. 예외가 나도 run이 열린 채 남습니다.
**해결** — 반드시 `with mlflow.start_run():` 블록으로. 예외가 나면 run이 FAILED 상태로 자동 마감되어 그것대로 기록이 됩니다.

### 지표에 문자열을 넣음

**증상** — `mlflow.log_metric("model", "linear")` 가 에러.
**원인** — metric은 **숫자 전용**입니다 (정렬·그래프 대상). 문자열 조건은 param, 메모는 tag.
**해결** — 숫자 결과는 `log_metric`, 조건은 `log_param`, "왜/결론"([Day 065](day-065.md)의 ⑧)은 `set_tag`.

### mlruns/를 git에 커밋함

**증상** — 저장소가 수십 MB로 붓고, pull 할 때마다 충돌.
**원인** — 실험 이력(바이너리·대용량)은 코드 버전 관리 대상이 아닙니다.
**해결** — `.gitignore` 에 `mlruns/`. 팀 공유가 필요하면 파일 폴더가 아니라 **추적 서버**를 씁니다 (개념만: `mlflow server` 를 공용 장비에 띄우고 `mlflow.set_tracking_uri(...)` 로 연결 — 대단원 05의 컨테이너 위에서 실제로 하게 됩니다).

### 기록은 하는데 데이터 지문·행 정의를 빼먹음

**증상** — 석 달 뒤 그 run을 재현했더니 [Day 065](day-065.md)의 재현 게임이 재발.
**원인** — MLflow는 **넘겨준 것만** 기록합니다. 파라미터 자동 수집은 모델 것에 한정입니다.
**해결** — log_params에 `data_md5` · 행 정의 · 시드를 표준 항목으로 포함하는 **팀 로깅 규약**을 만드세요 (Step 1의 dict가 그 표준안입니다).

### 로그가 쌓이니 다 됐다고 여김

**증상** — run 300개가 쌓였는데 의사결정은 여전히 감으로.
**원인** — 기록의 목적은 축적이 아니라 **비교와 회고**입니다. ⑧(결론) 태그 없는 run은 숫자 무덤입니다.
**해결** — 실험 묶음이 끝날 때마다 search_runs로 요약표를 뽑아 "채택/기각/이유"를 문서에 남기는 리듬을 만드세요 ([Day 072](day-072.md)에서 그 리듬으로 MP2를 돕니다).
