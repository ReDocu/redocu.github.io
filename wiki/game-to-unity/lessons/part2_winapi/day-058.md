## 3. 개념

### 3-1. 아이소메트릭이란

**왜 필요한가** — 왜 이런 표현을 쓰는지 안다.

```
   ┌──────────────────────────────────────────────────────────┐
   │  탑다운 (Top-down)          아이소메트릭 (Isometric)      │
   │                                                           │
   │  ┌──┬──┬──┐                        ◆                      │
   │  │  │  │  │                     ◆     ◆                   │
   │  ├──┼──┼──┤                  ◆     ◆     ◆                │
   │  │  │  │  │                     ◆     ◆                   │
   │  └──┴──┴──┘                        ◆                      │
   │                                                           │
   │  - 위에서 본 시점            - 비스듬히 위에서 본 시점      │
   │  - 높이 표현 불가             - 높이 표현 가능              │
   │  - 계산이 단순                - 입체감이 있다               │
   └──────────────────────────────────────────────────────────┘

   ★ 쓰는 게임
     디아블로, 스타크래프트, 심시티, 대부분의 SRPG
```

**타일 형태**

```
   사각 타일 (64 × 64)          아이소 타일 (64 × 32)

   ┌────────────┐                     ╱╲
   │            │                   ╱    ╲
   │            │                  ╱      ╲       ← 다이아몬드
   │            │                  ╲      ╱
   │            │                   ╲    ╱
   └────────────┘                     ╲╱

   ★ 폭 : 높이 = 2 : 1 이 표준이다
     (실제 아이소메트릭 각도는 30도지만, 2:1이 계산이 쉽고 픽셀이 깔끔하다)
```

### 3-2. 정변환 유도 — 타일 → 화면 ★

**왜 필요한가** — 공식을 외우지 말고 그림에서 유도한다.

**단계 1 — 타일 (0,0)의 위치를 기준으로 잡는다**

```
   타일 (0,0) 의 "위쪽 꼭짓점"을 화면 (0,0) 이라고 하자

              (0,0)
                ◆        ← 타일 (0,0)
```

**단계 2 — x가 1 늘면 어디로 가는가**

```
   타일 (0,0) → (1,0)

              (0,0)
                ◆
                    ◆    ← 타일 (1,0)
                  (W/2, H/2)

   ★ 오른쪽 아래로 (타일폭/2, 타일높이/2) 이동
```

**단계 3 — y가 1 늘면 어디로 가는가**

```
   타일 (0,0) → (0,1)

              (0,0)
                ◆
            ◆            ← 타일 (0,1)
      (-W/2, H/2)

   ★ 왼쪽 아래로 (-타일폭/2, 타일높이/2) 이동
```

**단계 4 — 합치면**

```
   타일 (x, y) 의 화면 좌표

   screenX = x × (W/2) + y × (-W/2) = (x - y) × (W/2)
   screenY = x × (H/2) + y × ( H/2) = (x + y) × (H/2)
```

```
   ★ 정변환 공식

     screenX = (x - y) × (타일폭  / 2)
     screenY = (x + y) × (타일높이 / 2)
```

**전체 그림으로 확인**

```
  그리드 좌표 (x, y)          화면 좌표 (screenX, screenY)
                                        (0,0)
   (0,0) (1,0) (2,0)                     ◆
   (0,1) (1,1) (2,1)      →           ◆     ◆
   (0,2) (1,2) (2,2)               ◆     ◆     ◆
                                       ◆     ◆
                                          ◆

   타일 크기 64 × 32 일 때

   (0,0) → ( (0-0)×32, (0+0)×16 ) = (  0,  0)
   (1,0) → ( (1-0)×32, (1+0)×16 ) = ( 32, 16)
   (0,1) → ( (0-1)×32, (0+1)×16 ) = (-32, 16)
   (1,1) → ( (1-1)×32, (1+1)×16 ) = (  0, 32)
   (2,1) → ( (2-1)×32, (2+1)×16 ) = ( 32, 48)
```

> ### ⚠️ x가 커지면 화면 오른쪽 아래, y가 커지면 왼쪽 아래
>
> 직관과 다르다. 그림을 보며 확인한다.
>
> ```
>              x축 →
>            ◆
>         ◆     ◆
>      ◆     ◆     ◆
>   ↙            ◆     ◆
>   y축          ◆
> ```

### 3-3. 역변환 유도 — 화면 → 타일 ★★

**왜 필요한가** — 마우스 클릭을 타일로 바꾸려면 반대 계산이 필요하다.

**연립방정식을 푼다**

```
   ① screenX = (x - y) × (W/2)
   ② screenY = (x + y) × (H/2)

   ①을 정리:  x - y = screenX / (W/2)      ... ①'
   ②를 정리:  x + y = screenY / (H/2)      ... ②'

   ①' + ②':  2x = screenX/(W/2) + screenY/(H/2)
              x  = ( screenX/(W/2) + screenY/(H/2) ) / 2

   ②' - ①':  2y = screenY/(H/2) - screenX/(W/2)
              y  = ( screenY/(H/2) - screenX/(W/2) ) / 2
```

```
   ★ 역변환 공식

     x = ( screenX/(W/2) + screenY/(H/2) ) / 2
     y = ( screenY/(H/2) - screenX/(W/2) ) / 2
```

**검산**

```
   타일 (2,1), 타일 크기 64×32

   정변환:  screenX = (2-1) × 32 = 32
            screenY = (2+1) × 16 = 48

   역변환:  x = ( 32/32 + 48/16 ) / 2 = (1 + 3) / 2 = 2   ✔
            y = ( 48/16 - 32/32 ) / 2 = (3 - 1) / 2 = 1   ✔
```

```cpp
void IsoTileToScreen(int col, int row, int tileW, int tileH,
                     double* sx, double* sy)
{
    *sx = (col - row) * (tileW / 2.0);
    *sy = (col + row) * (tileH / 2.0);
}

void IsoScreenToTile(double sx, double sy, int tileW, int tileH,
                     int* col, int* row)
{
    double halfW = tileW / 2.0;
    double halfH = tileH / 2.0;

    double fx = (sx / halfW + sy / halfH) / 2.0;
    double fy = (sy / halfH - sx / halfW) / 2.0;

    *col = (int)floor(fx);                     // ★ floor (Day 56)
    *row = (int)floor(fy);
}
```

### 3-4. ⚠️ 원점 오프셋

**왜 필요한가** — 그대로 쓰면 맵의 절반이 화면 왼쪽 밖으로 나간다.

```
   타일 (0, 10) → screenX = (0-10) × 32 = -320      ← 음수!

   맵 크기 20×20 이면 왼쪽 끝이 -640 까지 간다
```

```
   ★ 맵 전체의 화면 크기

   폭   = (cols + rows) × (W/2)
   높이 = (cols + rows) × (H/2)

   왼쪽 끝 = -rows × (W/2)
```

```cpp
class IsoMap
{
public:
    void CalcOffset()
    {
        m_originX = m_rows * (m_tileW / 2.0);   // 왼쪽 끝을 0으로
        m_originY = 0.0;
    }

    void TileToWorld(int col, int row, double* wx, double* wy) const
    {
        *wx = (col - row) * (m_tileW / 2.0) + m_originX;
        *wy = (col + row) * (m_tileH / 2.0) + m_originY;
    }

    void WorldToTile(double wx, double wy, int* col, int* row) const
    {
        double lx = wx - m_originX;             // ★ 오프셋 제거
        double ly = wy - m_originY;

        double halfW = m_tileW / 2.0;
        double halfH = m_tileH / 2.0;

        double fx = (lx / halfW + ly / halfH) / 2.0;
        double fy = (ly / halfH - lx / halfW) / 2.0;

        *col = (int)floor(fx);
        *row = (int)floor(fy);
    }
};
```

```
   맵 전체 모양 (cols=4, rows=4)

              ◆              ← (0,0)
           ◆     ◆
        ◆     ◆     ◆
     ◆     ◆     ◆     ◆     ← (3,0) 오른쪽 끝
        ◆     ◆     ◆
           ◆     ◆
              ◆              ← (3,3) 아래 끝
     ▲
     (0,3) 왼쪽 끝

   ★ 마름모(다이아몬드) 형태가 된다
```

### 3-5. 그리기 순서 — 겹침 처리

**왜 필요한가** — 순서가 틀리면 뒤쪽 타일이 앞쪽을 덮는다.

```
   높이가 있는 타일 (건물, 나무)

   잘못된 순서                올바른 순서

      ▓▓▓                        ▓▓▓
     ▓███▓  ← 뒤 건물이          ▓███▓
      ◆◆◆     앞을 덮음           ◆◆◆
       ▓▓▓                     ▓▓▓
      ▓███▓                   ▓███▓
       ◆◆◆                     ◆◆◆
```

```
   ★ 그리기 순서 규칙

   화면 y가 작은 것부터 (= 뒤에 있는 것부터)

   screenY = (col + row) × (H/2)

   → col + row 가 작은 것부터 그린다
```

```cpp
void RenderIsoMap(Renderer& r, const IsoMap& map, const Camera2D& cam)
{
    int cols = map.GetCols();
    int rows = map.GetRows();

    // ★ 대각선 순서 (col + row 오름차순)
    for (int diag = 0; diag < cols + rows - 1; diag++)
    {
        for (int col = 0; col < cols; col++)
        {
            int row = diag - col;
            if (row < 0 || row >= rows) continue;

            DrawTileAt(r, map, cam, col, row);
        }
    }
}
```

```
   대각선 순서 (cols=4, rows=4)

   diag=0:  (0,0)
   diag=1:  (0,1) (1,0)
   diag=2:  (0,2) (1,1) (2,0)
   diag=3:  (0,3) (1,2) (2,1) (3,0)
   diag=4:  (1,3) (2,2) (3,1)
   diag=5:  (2,3) (3,2)
   diag=6:  (3,3)

   ★ 같은 대각선 안에서는 순서가 상관없다
     (screenY 가 같으므로 안 겹친다)
```

**더 간단한 방법 — 단순 이중 루프**

```cpp
    for (int row = 0; row < rows; row++)
        for (int col = 0; col < cols; col++)
            DrawTileAt(r, map, cam, col, row);
```

```
   ★ 이 순서도 정답이다

   row 가 커지면 screenY 가 커진다 → 뒤에서 앞으로
   같은 row 안에서 col 이 커지면 오른쪽으로 → 겹치지 않는다

   대각선 순서보다 단순하고 결과가 같다
```

> **단순 이중 루프를 쓴다.** 대각선 순서는 오브젝트가 타일에 얹힐 때 필요해진다.

### 3-6. ⚠️ 다이아몬드 경계 정밀 판정

**왜 필요한가** — 3-3절의 역변환은 사각형 근사다. 경계에서 어긋난다.

```
   역변환 결과는 "이 타일의 사각 영역"을 기준으로 한다

        ╱╲
      ╱    ╲          ← 실제 타일 (다이아몬드)
     ╱      ╲
     ╲      ╱
      ╲    ╱
        ╲╱

   ┌──────────┐       ← 역변환이 판단하는 영역 (사각형)
   │  ╱╲      │
   │╱    ╲    │
   │╲    ╱    │       ★ 모서리 4곳이 다르다
   │  ╲╱      │
   └──────────┘
```

**정밀 판정 — 마름모 내부 검사**

```cpp
void IsoMap::WorldToTilePrecise(double wx, double wy, int* col, int* row) const
{
    // 1단계: 대략적인 타일 (사각 근사)
    int c, rr;
    WorldToTile(wx, wy, &c, &rr);

    // 2단계: 그 타일의 중심으로부터의 상대 위치
    double cx, cy;
    TileToWorld(c, rr, &cx, &cy);

    cx += m_tileW / 2.0;                       // 타일 중심
    cy += m_tileH / 2.0;

    double dx = wx - cx;
    double dy = wy - cy;

    // 마름모 내부 판정: |dx|/(W/2) + |dy|/(H/2) <= 1
    double a = fabs(dx) / (m_tileW / 2.0);
    double b = fabs(dy) / (m_tileH / 2.0);

    if (a + b <= 1.0)
    {
        *col = c; *row = rr;                   // 내부
        return;
    }

    // 3단계: 밖이면 인접 타일 중 가장 가까운 것
    // (dx, dy 부호로 판단)
    if (dx >= 0 && dy < 0)      { *col = c + 1; *row = rr;     }   // 우상
    else if (dx >= 0 && dy >= 0){ *col = c;     *row = rr + 1; }   // 우하
    else if (dx < 0 && dy < 0)  { *col = c;     *row = rr - 1; }   // 좌상
    else                        { *col = c - 1; *row = rr;     }   // 좌하
}
```

```
   마름모 내부 판정 공식

   중심에서 (dx, dy) 떨어진 점이 마름모 안인가?

     |dx| / (W/2)  +  |dy| / (H/2)  <=  1

   ★ 마름모(다이아몬드)의 방정식이다
     원이 x²+y²<=r² 이듯, 마름모는 |x|/a + |y|/b <= 1
```

> **실무에서는 더 간단한 방법도 쓴다.**
> 마스크 이미지를 만들어 픽셀 색으로 판정하거나, 3-3절 근사로 충분한 경우도 많다.
> **이 과정에서는 정밀 판정까지 구현한다.**

```cpp
void CalcVisibleIsoRange(int* minC, int* minR, int* maxC, int* maxR)
{
    // 화면 네 모서리를 타일 좌표로 변환
    double corners[4][2] = {
        { 0, 0 },
        { (double)m_editArea.w, 0 },
        { 0, (double)m_editArea.h },
        { (double)m_editArea.w, (double)m_editArea.h }
    };

    *minC = *minR = INT_MAX;
    *maxC = *maxR = INT_MIN;

    for (int i = 0; i < 4; i++)
    {
        double wx, wy;
        m_camera.ScreenToWorld(corners[i][0], corners[i][1], &wx, &wy);

        int c, r;
        m_map.WorldToTile(wx, wy, &c, &r);

        if (c < *minC) *minC = c;
        if (r < *minR) *minR = r;
        if (c > *maxC) *maxC = c;
        if (r > *maxR) *maxR = r;
    }

    // 여유
    *minC -= 2; *minR -= 2;
    *maxC += 2; *maxR += 2;

    // 클램프
    if (*minC < 0) *minC = 0;
    if (*minR < 0) *minR = 0;
    if (*maxC > m_map.GetCols()) *maxC = m_map.GetCols();
    if (*maxR > m_map.GetRows()) *maxR = m_map.GetRows();
}
```

```
   ★ 아이소메트릭은 사각 격자보다 복잡하다

   화면 사각형 → 타일 공간에서는 마름모
   → 네 모서리를 변환해 바운딩 박스를 구한다
   → 여유를 넉넉히 준다 (2칸)
```

## 6. 자주 막히는 곳

| 증상 | 원인 | 해결 |
|---|---|---|
| 맵이 화면 왼쪽 밖으로 | 원점 오프셋 없음 | `originX = rows * (W/2)` |
| 커서가 크게 어긋남 | 역변환 공식 오류 | 왕복 테스트로 검증 |
| 모서리에서만 어긋남 | 사각 근사 | 정밀 판정 (3-6절) |
| 음수 좌표에서 어긋남 | 정수 나눗셈 | **`floor`** |
| 뒤 타일이 앞을 덮음 | 그리기 순서 | row 오름차순 |
| 타일 사이에 틈 | 타일 크기와 공식 불일치 | 폭:높이 = 2:1 확인 |
| 오프셋 적용을 한쪽만 | 정변환에만 더함 | 역변환에서 빼기도 |
| 큰 맵에서 느림 | 전체 그리기 | 보이는 영역 계산 |
| 편집이 안 됨 | 변환 함수를 안 바꿈 | `MapView`로 통일 |

## 7. 정리

### 오늘 배운 것

| 개념 | 한 줄 요약 |
|---|---|
| 아이소메트릭 | 비스듬히 본 시점. 폭:높이 = 2:1 |
| **정변환** | `sx = (x-y)*(W/2)`, `sy = (x+y)*(H/2)` |
| **역변환** | 연립방정식을 풀어 유도. `x = (sx/(W/2) + sy/(H/2))/2` |
| 원점 오프셋 | `originX = rows * (W/2)` |
| 그리기 순서 | row 오름차순 (뒤 → 앞) |
| **정밀 판정** | 마름모 방정식 `|dx|/a + |dy|/b <= 1` |
| 모드 전환 | 데이터는 그대로, 변환만 교체 |
| 왕복 테스트 | 타일 → 월드 → 타일이 같아야 한다 |

### 공식 정리

```
   ★ 정변환 (타일 → 화면)

     screenX = (col - row) × (타일폭 / 2) + originX
     screenY = (col + row) × (타일높이 / 2) + originY


   ★ 역변환 (화면 → 타일)

     lx = screenX - originX
     ly = screenY - originY

     col = floor( ( lx/(W/2) + ly/(H/2) ) / 2 )
     row = floor( ( ly/(H/2) - lx/(W/2) ) / 2 )
```
