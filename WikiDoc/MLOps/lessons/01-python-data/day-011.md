## ② 왜 필요한가

어제 만든 `todo.py` 를 다시 보세요. 모든 로직 함수가 이렇게 시작합니다.

```python
def add_todo(todos, title, priority="보통", tags=None): ...
def toggle_done(todos, todo_id): ...
def delete_todo(todos, todo_id): ...
def search_todos(todos, keyword): ...
def stats(todos): ...
```

**전부 첫 번째 인자가 `todos` 입니다.** 이 데이터와 함수들은 사실상 한 덩어리인데, 코드에서는 따로 놀고 있습니다.

그리고 이런 문제들이 있습니다.

| 문제 | 예 |
|---|---|
| 오타가 조용히 통과 | `todo["titel"] = "x"` — 새 키가 그냥 생김 |
| 필수 필드 누락을 못 막음 | `{"title": "x"}` 만 있는 딕셔너리를 아무나 만들 수 있음 |
| 자동완성이 안 됨 | `todo["` 를 치면 VS Code가 아무것도 제안 못 함 |
| 데이터와 동작이 분리됨 | `todo` 를 받은 사람이 어떤 함수를 쓸 수 있는지 모름 |
| 규칙을 강제할 수 없음 | 완료 처리 시 완료 시각도 기록하라는 규칙을 지키게 할 방법이 없음 |

**클래스는 "이 데이터는 이런 모양이고, 이런 일을 할 수 있다"를 코드로 못 박는 도구입니다.**

| 클래스가 쓰이는 곳 | 시점 |
|---|---|
| 수집기 `Collector` — 설정·세션·재시도 상태를 들고 다님 | W04 |
| sklearn의 모든 모델 (`fit`/`predict`) | W11 |
| PyTorch의 `nn.Module`, `Dataset` | W16 |
| pydantic 요청/응답 모델 | W19 |
| 예외 클래스 | 이미 [Day 009](day-009.md)에서 씀 |

특히 W11 이후 여러분이 쓰는 **모든 라이브러리가 클래스**입니다.
`model.fit(X, y)` 를 읽으려면 클래스를 알아야 합니다.

## ③ 개념 설명

### 클래스와 인스턴스

| 용어 | 뜻 | 비유 |
|---|---|---|
| **클래스(class)** | 설계도 | 붕어빵 **틀** |
| **인스턴스(instance)** | 설계도로 만든 것 | 만들어진 **붕어빵** |
| **속성(attribute)** | 인스턴스가 가진 데이터 | 붕어빵의 팥 |
| **메서드(method)** | 인스턴스가 할 수 있는 일 | 붕어빵을 데우기 |

```python
class Todo:            # 설계도
    ...

t1 = Todo("장보기")     # 인스턴스 1
t2 = Todo("청소")       # 인스턴스 2
```

`t1` 과 `t2` 는 **같은 설계도로 만든 서로 다른 것**입니다.

### 기본 구조

```python
class Todo:
    def __init__(self, title, priority="보통"):
        self.title = title
        self.priority = priority
        self.done = False

    def complete(self):
        self.done = True
```

| 요소 | 설명 |
|---|---|
| `class Todo:` | 클래스 정의. 이름은 **PascalCase**(첫 글자 대문자) |
| `__init__` | **생성자**. 인스턴스를 만들 때 자동 호출됨 |
| `self` | **자기 자신**. 모든 메서드의 첫 인자 |
| `self.title = title` | 인스턴스 속성에 값 저장 |
| `def complete(self):` | 메서드. `self` 를 통해 자기 데이터에 접근 |

### `self` 의 정체

`self` 는 마법이 아닙니다. **"어떤 인스턴스인지"를 받는 평범한 매개변수**입니다.

```python
t = Todo("장보기")
t.complete()            # 파이썬이 내부적으로 Todo.complete(t) 로 호출
```

```
t.complete()   ──▶   Todo.complete(self=t)
```

그래서 메서드를 정의할 때 `self` 를 빠뜨리면 에러가 납니다.
이름이 꼭 `self` 여야 하는 건 아니지만, **모든 파이썬 코드가 `self` 를 씁니다.** 관례를 따르세요.

### `__init__` — 생성자

인스턴스를 만들 때 **자동으로** 호출됩니다.

```python
class Todo:
    def __init__(self, title):
        print(f"'{title}' 생성 중...")
        self.title = title

t = Todo("장보기")      # '장보기' 생성 중...
```

**여기서 필수 값을 강제할 수 있습니다.** 딕셔너리로는 불가능했던 일입니다.

```python
class Todo:
    def __init__(self, title, priority="보통"):
        title = title.strip()
        if not title:
            raise ValueError("제목은 비워 둘 수 없습니다.")
        if priority not in ("높음", "보통", "낮음"):
            raise ValueError(f"우선순위가 잘못되었습니다: {priority!r}")
        self.title = title
        self.priority = priority
```

이제 **잘못된 Todo는 세상에 존재할 수 없습니다.**

### 인스턴스 속성 vs 클래스 속성

```python
class Todo:
    PRIORITIES = ("높음", "보통", "낮음")     # 클래스 속성 — 모든 인스턴스가 공유
    count = 0                                # 클래스 속성

    def __init__(self, title):
        self.title = title                   # 인스턴스 속성 — 각자 다름
        Todo.count += 1
```

```python
t1 = Todo("a")
t2 = Todo("b")

t1.title            # 'a'   ← 각자 다름
t2.title            # 'b'
Todo.count          # 2     ← 공유
Todo.PRIORITIES     # ('높음', '보통', '낮음')
```

**클래스 속성은 상수를 담는 데 주로 씁니다.**

> **주의** — 클래스 속성에 리스트를 두면 모든 인스턴스가 공유해 사고가 납니다.
> ```python
> class Bad:
>     tags = []        # ❌ 모든 인스턴스가 같은 리스트를 씀
> ```
> [Day 006](day-006.md)의 "기본값에 리스트 쓰지 말기"와 같은 함정입니다.

### `__str__` — 사람이 읽는 표현

```python
class Todo:
    def __init__(self, title):
        self.title = title

t = Todo("장보기")
print(t)          # <__main__.Todo object at 0x000001A2B3C4D5E0>   ← 읽을 수 없음
```

`__str__` 을 정의하면 바뀝니다.

```python
class Todo:
    def __init__(self, title, done=False):
        self.title = title
        self.done = done

    def __str__(self):
        mark = "✔" if self.done else " "
        return f"[{mark}] {self.title}"

print(Todo("장보기"))          # [ ] 장보기
```

**앞뒤로 밑줄 두 개(`__`)가 붙은 메서드**를 매직 메서드 또는 던더(dunder) 메서드라고 합니다.
파이썬이 특정 상황에서 자동으로 불러 줍니다. [Day 012](day-012.md)에서 더 다룹니다.

### 메서드의 종류

```python
class Todo:
    def complete(self):              # 인스턴스 메서드 — self 있음
        self.done = True

    @staticmethod
    def is_valid_title(title):       # 정적 메서드 — self 없음
        return bool(title.strip())

    @classmethod
    def from_dict(cls, data):        # 클래스 메서드 — cls(클래스 자신)
        return cls(data["title"], data.get("priority", "보통"))
```

| 종류 | 첫 인자 | 언제 |
|---|---|---|
| 인스턴스 메서드 | `self` | 인스턴스 데이터를 다룰 때 (대부분) |
| `@staticmethod` | 없음 | 클래스와 관련은 있지만 데이터는 안 쓸 때 |
| `@classmethod` | `cls` | **다른 방식으로 인스턴스를 만들 때** |

`@classmethod` 의 대표 용도는 **대안 생성자**입니다.

```python
t1 = Todo("장보기")                                # 일반 생성
t2 = Todo.from_dict({"title": "청소"})             # 딕셔너리에서 생성
```

JSON에서 불러온 데이터를 객체로 바꿀 때 씁니다. 오늘 실습에서 씁니다.

### 캡슐화 — `_` 와 `__`

파이썬에는 진짜 `private` 이 없습니다. **약속으로 표현합니다.**

| 표기 | 뜻 |
|---|---|
| `self.title` | 공개. 밖에서 자유롭게 접근 |
| `self._cache` | "내부용입니다. 건드리지 마세요" — **약속일 뿐 접근은 가능** |
| `self.__secret` | 이름이 바뀌어 밖에서 접근이 어려워짐 (name mangling) |

**실무에서는 `_` 하나를 씁니다.** `__` 는 상속에서 문제를 일으켜 잘 쓰지 않습니다.

### 언제 클래스를 쓰고, 언제 안 쓰나

| 클래스가 좋은 경우 | 함수로 충분한 경우 |
|---|---|
| 데이터와 동작이 붙어 다님 | 값을 받아 값을 돌려주기만 함 |
| 상태를 유지해야 함 (세션·연결·설정) | 상태가 없음 |
| 같은 모양의 것이 여러 개 생김 | 한 번만 쓰고 버림 |
| 규칙(검증)을 강제하고 싶음 | 검증이 필요 없음 |

> **클래스를 남용하지 마세요.** 메서드가 하나뿐인 클래스는 그냥 함수여야 합니다.
> "명사(데이터)가 먼저 떠오르면 클래스, 동사(동작)가 먼저 떠오르면 함수"가 실용적인 기준입니다.

### Step 2. 첫 클래스

`first_class.py` 를 만듭니다.

```python
class Account:
    """간단한 계좌."""

    def __init__(self, owner, balance=0):
        if not owner.strip():
            raise ValueError("예금주 이름은 필수입니다.")
        if balance < 0:
            raise ValueError(f"잔액은 0 이상이어야 합니다: {balance}")
        self.owner = owner.strip()
        self.balance = balance
        self.history = []

    def deposit(self, amount):
        """입금합니다."""
        if amount <= 0:
            raise ValueError(f"입금액은 0보다 커야 합니다: {amount}")
        self.balance += amount
        self.history.append(("입금", amount, self.balance))
        return self.balance

    def withdraw(self, amount):
        """출금합니다."""
        if amount <= 0:
            raise ValueError(f"출금액은 0보다 커야 합니다: {amount}")
        if amount > self.balance:
            raise ValueError(f"잔액 부족: 잔액 {self.balance:,}원, 요청 {amount:,}원")
        self.balance -= amount
        self.history.append(("출금", amount, self.balance))
        return self.balance

    def show_history(self):
        """거래 내역을 출력합니다."""
        print(f"\n[{self.owner}님 거래 내역]")
        if not self.history:
            print("  거래가 없습니다.")
            return
        for i, (kind, amount, after) in enumerate(self.history, start=1):
            sign = "+" if kind == "입금" else "-"
            print(f"  {i}. {kind} {sign}{amount:>10,}원 → 잔액 {after:>12,}원")

    def __str__(self):
        return f"{self.owner}님 계좌 (잔액 {self.balance:,}원)"


acc = Account("홍길동", 100_000)
print(acc)

acc.deposit(50_000)
acc.withdraw(30_000)
acc.deposit(200_000)
print(acc)

acc.show_history()

print("\n--- 잘못된 사용은 즉시 막힘 ---")
for label, action in [
    ("잔액 부족 출금", lambda: acc.withdraw(999_999_999)),
    ("음수 입금", lambda: acc.deposit(-1000)),
    ("빈 이름 계좌", lambda: Account("   ")),
    ("음수 잔액 계좌", lambda: Account("김철수", -500)),
]:
    try:
        action()
        print(f"  {label:<16} → 통과됨 (문제!)")
    except ValueError as e:
        print(f"  {label:<16} → ValueError: {e}")
```

실행 결과:

```

홍길동님 계좌 (잔액 320,000원)

[홍길동님 거래 내역]
  1. 입금 +    50,000원 → 잔액      150,000원
  2. 출금 -    30,000원 → 잔액      120,000원
  3. 입금 +   200,000원 → 잔액      320,000원

--- 잘못된 사용은 즉시 막힘 ---
  잔액 부족 출금         → ValueError: 잔액 부족: 잔액 320,000원, 요청 999,999,999원
  음수 입금            → ValueError: 입금액은 0보다 커야 합니다: -1000
  빈 이름 계좌          → ValueError: 예금주 이름은 필수입니다.
```

> 그 안에 검증과 이력 기록이 들어 있습니다. **규칙이 코드로 강제**된 것입니다.
>
> (엄밀히는 `acc.balance = 999999` 가 가능합니다. 파이썬에는 진짜 private이 없기 때문입니다.
> 하지만 `_balance` 로 표기하면 "직접 건드리지 말라"는 신호가 되고, 팀 코드에서는 그것으로 충분합니다.)

### Step 3. Todo 클래스

`todo_class.py` 를 만듭니다. [Day 010](day-010.md)의 딕셔너리를 클래스로 바꿉니다.

```python
from datetime import datetime


class Todo:
    """할 일 하나."""

    PRIORITIES = ("높음", "보통", "낮음")
    _MARK = {True: "✔", False: " "}
    _PRIORITY_MARK = {"높음": "!!", "보통": "! ", "낮음": "  "}

    def __init__(self, todo_id, title, priority="보통", tags=None):
        title = title.strip()
        if not title:
            raise ValueError("제목은 비워 둘 수 없습니다.")
        if priority not in self.PRIORITIES:
            raise ValueError(f"우선순위는 {' / '.join(self.PRIORITIES)} 중 하나여야 합니다: {priority!r}")

        self.id = todo_id
        self.title = title
        self.priority = priority
        self.tags = sorted(set(tags or []))
        self.done = False
        self.created_at = datetime.now().strftime("%Y-%m-%d %H:%M")
        self.completed_at = None

    # ---------- 동작 ----------

    def complete(self):
        """완료 처리합니다. 완료 시각도 함께 기록됩니다."""
        if self.done:
            return self
        self.done = True
        self.completed_at = datetime.now().strftime("%Y-%m-%d %H:%M")
        return self

    def reopen(self):
        """미완료로 되돌립니다."""
        self.done = False
        self.completed_at = None
        return self

    def toggle(self):
        """완료 여부를 뒤집습니다."""
        return self.reopen() if self.done else self.complete()

    def add_tag(self, tag):
        """태그를 추가합니다. 중복은 자동으로 무시됩니다."""
        tag = tag.strip()
        if tag and tag not in self.tags:
            self.tags = sorted(self.tags + [tag])
        return self

    def has_tag(self, tag):
        return tag.strip() in self.tags

    def matches(self, keyword):
        """제목이나 태그에 키워드가 있는지 확인합니다."""
        keyword = keyword.strip().lower()
        if not keyword:
            return False
        if keyword in self.title.lower():
            return True
        return any(keyword in t.lower() for t in self.tags)

    # ---------- 변환 ----------

    def to_dict(self):
        """JSON 저장을 위해 딕셔너리로 변환합니다."""
        return {
            "id": self.id,
            "title": self.title,
            "priority": self.priority,
            "tags": self.tags,
            "done": self.done,
            "created_at": self.created_at,
            "completed_at": self.completed_at,
        }

    @classmethod
    def from_dict(cls, data):
        """딕셔너리에서 Todo를 복원합니다."""
        todo = cls(data["id"], data["title"], data.get("priority", "보통"), data.get("tags"))
        todo.done = data.get("done", False)
        todo.created_at = data.get("created_at", todo.created_at)
        todo.completed_at = data.get("completed_at")
        return todo

    # ---------- 표현 ----------

    def __str__(self):
        tags = ", ".join(self.tags) if self.tags else "-"
        return (f"{self.id:>3} [{self._MARK[self.done]}] {self._PRIORITY_MARK[self.priority]} "
                f"{self.title:<22}{tags:<18}{self.created_at}")
```

### Step 4. TodoList 클래스

목록 전체를 관리하는 클래스도 만듭니다. `todo_class.py` 에 이어 씁니다.

```python
import json
import os


class TodoList:
    """할 일 목록 전체를 관리합니다."""

    def __init__(self, path="todos.json"):
        self.path = path
        self.items = []

    # ---------- 조회 ----------

    def __len__(self):
        """len(todo_list) 가 동작하게 합니다."""
        return len(self.items)

    def __iter__(self):
        """for t in todo_list: 가 동작하게 합니다."""
        return iter(self.items)

    def next_id(self):
        return max((t.id for t in self.items), default=0) + 1

    def find(self, todo_id):
        """ID로 찾습니다. 없으면 None."""
        for t in self.items:
            if t.id == todo_id:
                return t
        return None

    def filter(self, status="all"):
        if status == "todo":
            return [t for t in self.items if not t.done]
        if status == "done":
            return [t for t in self.items if t.done]
        return list(self.items)

    def search(self, keyword):
        return [t for t in self.items if t.matches(keyword)]

    def all_tags(self):
        tags = set()
        for t in self.items:
            tags.update(t.tags)
        return tags

    # ---------- 변경 ----------

    def add(self, title, priority="보통", tags=None):
        """할 일을 추가하고 만들어진 Todo를 돌려줍니다."""
        todo = Todo(self.next_id(), title, priority, tags)
        self.items.append(todo)
        return todo

    def remove(self, todo_id):
        """삭제하고 삭제된 Todo를 돌려줍니다."""
        todo = self.find(todo_id)
        if todo is None:
            raise KeyError(f"{todo_id}번 할 일이 없습니다.")
        self.items.remove(todo)
        return todo

    # ---------- 통계 ----------

    def stats(self):
        total = len(self.items)
        done = sum(1 for t in self.items if t.done)
        by_priority = {}
        by_tag = {}
        for t in self.items:
            by_priority[t.priority] = by_priority.get(t.priority, 0) + 1
            for tag in t.tags:
                by_tag[tag] = by_tag.get(tag, 0) + 1
        return {
            "total": total,
            "done": done,
            "todo": total - done,
            "rate": done / total if total else 0.0,
            "by_priority": by_priority,
            "by_tag": by_tag,
        }

    # ---------- 저장 ----------

    def save(self):
        """JSON으로 저장합니다."""
        try:
            with open(self.path, "w", encoding="utf-8") as f:
                json.dump([t.to_dict() for t in self.items], f, ensure_ascii=False, indent=2)
            return True, None
        except OSError as e:
            return False, f"저장 실패: {e}"

    def load(self):
        """JSON에서 불러옵니다."""
        if not os.path.exists(self.path):
            return None

        try:
            with open(self.path, "r", encoding="utf-8") as f:
                data = json.load(f)
        except (json.JSONDecodeError, OSError) as e:
            return f"파일을 읽지 못했습니다 ({e}). 빈 목록으로 시작합니다."

        if not isinstance(data, list):
            return "파일 형식이 올바르지 않습니다. 빈 목록으로 시작합니다."

        self.items = []
        dropped = 0
        for raw in data:
            try:
                self.items.append(Todo.from_dict(raw))
            except (KeyError, TypeError, ValueError):
                dropped += 1

        return f"형식이 맞지 않는 항목 {dropped}건을 건너뛰었습니다." if dropped else None

    def __str__(self):
        s = self.stats()
        return f"TodoList({s['total']}건, 완료 {s['done']}건, {s['rate']:.0%})"


# ---------- 사용 ----------

todos = TodoList("todos_class.json")

todos.add("MP1 데이터 선정", "높음", ["프로젝트", "급함"])
todos.add("Day 011 과제 제출", "보통", ["과제"])
todos.add("Git 브랜치 정리", "낮음", ["Git"])
todos.add("requirements.txt 갱신", "보통", ["환경"])

print(todos)
print()

for t in todos:                   # __iter__ 덕분에 바로 순회 가능
    print(t)

print(f"\n전체 {len(todos)}건")     # __len__ 덕분에 len() 사용 가능

todos.find(2).complete()
print(f"\n2번 완료 후: {todos}")

print("\n[미완료]")
for t in todos.filter("todo"):
    print(" ", t)

print("\n[검색: 프로젝트]")
for t in todos.search("프로젝트"):
    print(" ", t)

print(f"\n사용 중인 태그: {sorted(todos.all_tags())}")

ok, error = todos.save()
print(f"\n저장: {'성공' if ok else error}")

# 새 객체로 다시 불러오기

warning = reloaded.load()
if warning:
    print(f"⚠ {warning}")
print(f"복원: {reloaded}")
print(f"2번 완료 상태 유지: {reloaded.find(2).done}")
```

## ⑤ 자주 하는 실수

### `TypeError: complete() takes 0 positional arguments but 1 was given`

```python
class Todo:
    def complete():          # self 누락
        ...

Todo("x").complete()
```

**원인** — 메서드 정의에 `self` 를 빠뜨렸습니다.
**해결** — `def complete(self):`

파이썬은 `t.complete()` 를 `Todo.complete(t)` 로 바꿔 호출하므로, **인자가 항상 하나 더 들어갑니다.**

### `AttributeError: 'Todo' object has no attribute 'title'`

```python
class Todo:
    def __init__(self, title):
        title = title            # ❌ self. 를 빠뜨림 — 지역 변수만 만들고 끝
```

**원인** — `self.` 를 안 붙이면 그냥 지역 변수라 함수가 끝나면 사라집니다.
**해결** — `self.title = title`

오타로 인한 경우도 있습니다.

```python
self.titel = title       # 저장은 titel
print(t.title)           # 읽기는 title → AttributeError
```

> **딕셔너리보다 나은 점이 여기 있습니다.** 딕셔너리는 오타가 새 키를 만들며 조용히 통과하지만,
> 클래스는 **읽을 때 `AttributeError` 로 알려 줍니다.**

### `TypeError: __init__() missing 1 required positional argument: 'title'`

```python
t = Todo()
```

**원인** — 생성자가 요구하는 인자를 안 넘겼습니다.
**해결** — 필요한 값을 넘기거나 기본값을 주세요.

### 클래스 속성에 가변 객체를 둠

```python
class Todo:
    tags = []            # ❌ 모든 인스턴스가 공유
```

**원인** — 클래스 속성은 **딱 한 번** 만들어져 모든 인스턴스가 같은 객체를 봅니다.
**해결** — `__init__` 안에서 `self.tags = []` 로 만드세요.
클래스 속성에는 **튜플·문자열·숫자 같은 불변 값**만 두세요.

### `print(객체)` 가 `<__main__.Todo object at 0x...>` 로 나옴

**원인** — `__str__` 을 정의하지 않았습니다.
**해결** — `__str__` 을 추가합니다. 목록에서 볼 때는 `__repr__` 도 정의하면 좋습니다 ([Day 012](day-012.md)).

```python
todos = [Todo(1, "a"), Todo(2, "b")]
print(todos)      # __repr__ 이 없으면 여전히 <Todo object at ...>
```

`print(리스트)` 는 각 요소의 `__repr__` 을 씁니다. `__str__` 이 아닙니다.

### `self` 를 클래스 밖에서 쓰려고 함

```python
class Todo:
    def __init__(self, title):
        self.title = title

print(self.title)        # NameError: name 'self' is not defined
```

**원인** — `self` 는 메서드 안에서만 의미가 있습니다.
**해결** — 인스턴스를 만들어 접근하세요. `t = Todo("x"); print(t.title)`

### 인스턴스를 비교했더니 다르다고 나옴

```python
a = Todo(1, "장보기")
b = Todo(1, "장보기")
print(a == b)        # False
```

**원인** — 기본 `==` 는 **같은 객체인가**를 봅니다. 내용이 같아도 다른 객체입니다.
**해결** — `__eq__` 를 정의합니다 ([Day 012](day-012.md)). 또는 `@dataclass` 를 쓰면 자동입니다.

### 메서드 안에서 다른 메서드를 부를 때 `self` 누락

```python
class TodoList:
    def add(self, title):
        todo = Todo(next_id(), title)      # ❌ NameError
```

**해결** — `self.next_id()` 로 부릅니다. 같은 클래스 안이어도 `self.` 가 필요합니다.


**원인** — `tags = []` 는 **클래스 속성**입니다. 클래스를 정의하는 순간 리스트가 딱 하나 만들어지고,
**모든 인스턴스가 그 하나를 공유**합니다.

`t1.add_tag("집안일")` 은 `self.tags.append(...)` 를 호출하는데,
`t1` 에 자기만의 `tags` 가 없으므로 클래스의 `tags` 를 찾아가 거기에 추가합니다.
`t2.tags` 도 같은 리스트를 가리키므로 함께 바뀝니다.

**고치기**

```python
class Todo:
    def __init__(self, title):
        self.title = title
        self.tags = []          # 인스턴스마다 새 리스트
```

**왜 헷갈리나** — `self.tags.append(x)` 는 잘 동작하는데 `self.tags = [x]` 는 다르게 동작합니다.

| 코드 | 동작 |
|---|---|
| `self.tags.append(x)` | 클래스 리스트를 **수정** → 전부 영향 |
| `self.tags = [x]` | 인스턴스 속성을 **새로 생성** → 그 인스턴스만 |

이 미묘함 때문에 **클래스 속성에는 불변 값만 두는 것**이 원칙입니다.
[Day 006](day-006.md)의 "기본 인자에 리스트 쓰지 말기"와 정확히 같은 함정입니다.
</details>

**2.** `Todo` 를 딕셔너리 대신 클래스로 만들었을 때 얻는 것 네 가지를 코드 예와 함께 설명하세요.

<details>
<summary>답 보기</summary>

**① 잘못된 상태를 만드는 것 자체가 막힌다**

```python
# 딕셔너리 — 아무 값이나 들어감
todo = {"title": "", "priority": "매우높음"}      # 아무 일도 안 일어남

# 클래스 — 생성 시점에 거부
Todo(1, "", "매우높음")                           # ValueError
```

**② 오타가 드러난다**

```python
todo["titel"] = "x"      # 딕셔너리: 새 키가 생김. 조용히 통과
t.titel                  # 클래스: AttributeError — 즉시 발견
```

**③ 규칙을 강제할 수 있다**

```python
# 딕셔너리 — 완료 시각 기록을 빠뜨릴 수 있음
todo["done"] = True

# 클래스 — complete()를 거치면 반드시 시각이 기록됨
t.complete()             # done=True, completed_at 자동 설정
```

**④ 데이터와 동작이 한곳에 있다**

```python
# 딕셔너리 — 어떤 함수를 쓸 수 있는지 모름
matches(todo, "키워드")      # 이런 함수가 있는지 어떻게 알까?

# 클래스 — 점을 찍으면 VS Code가 목록을 보여 줌
t.matches("키워드")
t.complete()
t.add_tag("업무")
```

**덤: 자동완성과 타입 확인**

[Day 014](day-014.md)에서 타입 힌트를 붙이면 VS Code가 오타를 **실행 전에** 잡아 줍니다.
딕셔너리에는 붙일 수 없는 안전장치입니다.

**다만 항상 클래스가 정답은 아닙니다.**
- API 응답처럼 **구조가 바뀌는 외부 데이터**는 딕셔너리로 받는 게 유연합니다.
- 한 번 쓰고 버리는 임시 데이터에 클래스를 만드는 것은 과합니다.
- **내 코드가 소유하고 규칙이 있는 데이터**에 클래스를 씁니다.
</details>

**3.** `TodoList` 에 `__len__` 과 `__iter__` 를 정의했더니 무엇이 가능해졌나요? 정의하지 않았다면 어떻게 써야 했을까요?

<details>
<summary>답 보기</summary>

**가능해진 것**

```python
len(todos)                     # __len__
for t in todos:                # __iter__
    print(t)
if todos:                      # __len__ 이 0이면 False (truthy 판정에도 쓰임)
    ...
```

**정의하지 않았다면**

```python
len(todos.items)               # 내부 구조를 밖에서 알아야 함
for t in todos.items:
    print(t)
if len(todos.items) > 0:
    ...
```

**차이의 핵심은 "내부 구조를 숨길 수 있다"** 입니다.

`todos.items` 를 밖에서 쓰면, 나중에 내부를 리스트에서 딕셔너리로 바꿀 때
**이 클래스를 쓰는 모든 코드를 고쳐야 합니다.**

`len(todos)` / `for t in todos` 만 쓰고 있다면, 내부를 어떻게 바꾸든 **바깥 코드는 그대로**입니다.

```python
# 내부를 딕셔너리로 바꿔도
class TodoList:
    def __init__(self):
        self._items = {}                    # 리스트 → 딕셔너리

    def __len__(self):
        return len(self._items)

    def __iter__(self):
        return iter(self._items.values())   # 여기만 고치면 됨
```

**이것을 인터페이스라고 합니다.** "어떻게 만들어졌는지"가 아니라 "무엇을 할 수 있는지"로 소통하는 것입니다.

파이썬에서 자주 쓰는 매직 메서드는 이 정도입니다.

| 메서드 | 지원하는 문법 |
|---|---|
| `__len__` | `len(x)` |
| `__iter__` | `for i in x` |
| `__str__` | `print(x)` |
| `__repr__` | 목록 안에서 표시 · 디버깅 |
| `__eq__` | `x == y` |
| `__getitem__` | `x[0]` |
| `__contains__` | `y in x` |

W16의 PyTorch `Dataset` 은 `__len__` 과 `__getitem__` 두 개만 구현하면
DataLoader가 알아서 배치를 만들어 줍니다. **오늘 배운 원리가 그대로 쓰입니다.**
</details>

## 오늘의 정리

| 항목 | 문법 |
|---|---|
| 정의 | `class Todo:` — 이름은 PascalCase |
| 생성자 | `def __init__(self, ...):` — 인스턴스를 만들 때 자동 호출 |
| `self` | 자기 자신. 모든 인스턴스 메서드의 첫 인자 |
| 인스턴스 속성 | `self.title = title` — 인스턴스마다 다름 |
| 클래스 속성 | `PRIORITIES = (...)` — 공유됨. **불변 값만** |
| 정적 메서드 | `@staticmethod` — `self` 없음 |
| 클래스 메서드 | `@classmethod def from_dict(cls, ...)` — 대안 생성자 |
| 문자열 표현 | `__str__` — `print()` 에서 사용 |
| 길이·순회 | `__len__` · `__iter__` |
| 캡슐화 | `_name` — "내부용" 약속 |
| 핵심 가치 | **잘못된 상태를 만드는 것 자체를 막는다** |

**과제** — 도서 대여 시스템을 설계하세요.
① `Book` 클래스 — 제목·저자·ISBN·대여 여부. ISBN이 13자리 숫자가 아니면 `ValueError`
② `Library` 클래스 — 책 추가·검색(제목/저자)·대여·반납·`__len__`·`__iter__`
③ 이미 대여된 책을 또 대여하면 `ValueError`, 대여 중이 아닌 책을 반납해도 `ValueError`
④ `to_dict` / `from_dict` 로 JSON 저장·복원
