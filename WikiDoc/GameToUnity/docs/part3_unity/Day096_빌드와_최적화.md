## 3. 개념

### 3-1. Build Settings / Build Profiles

**왜 필요한가** — Unity 6에서 UI가 바뀌었다.

```
   File → Build Profiles   (구버전: Build Settings)
```

| 항목 | 의미 |
|---|---|
| **Scene List** | 빌드에 포함할 씬. **순서 = 인덱스** |
| Platform | Windows / WebGL / Android ... |
| Architecture | x86_64 |
| **Development Build** | 프로파일러 연결 가능. 느림 |
| Autoconnect Profiler | 실행 시 자동 연결 |
| Deep Profiling Support | 모든 함수 추적 (매우 느림) |
| Script Debugging | 브레이크포인트 |
| **Compression Method** | Default / LZ4 / LZ4HC |

```
   ★ Compression Method

   Default:  압축 없음. 로딩 빠름, 용량 큼
   LZ4:      빠른 압축. 개발 중  ★
   LZ4HC:    강한 압축. 배포용  ★
```

```
   ⚠️ 씬이 하나도 없으면

   현재 열린 씬만 빌드된다
   → 반드시 목록을 확인한다
```

```csharp
    // 코드에서 씬 인덱스 확인
    Debug.Log(SceneManager.sceneCountInBuildSettings);
```

### 3-2. Player Settings

**왜 필요한가** — 게임의 정체성과 동작.

| 항목 | 설정 |
|---|---|
| **Company Name** | 스튜디오 이름 (저장 경로에 사용) |
| **Product Name** | 게임 이름 (exe 이름) |
| Version | 0.1.0 |
| **Default Icon** | 아이콘 |
| **Fullscreen Mode** | Exclusive / Windowed / Borderless |
| Default Screen Width/Height | 초기 해상도 |
| Resizable Window | 창 크기 조절 허용 |
| **Color Space** | Gamma / **Linear** ★ |
| **Api Compatibility** | .NET Standard 2.1 |
| **Managed Stripping Level** | Disabled / Low / **Medium** / High |
| **Scripting Backend** | Mono / **IL2CPP** |

```
   ★ Color Space

   Linear:  물리적으로 정확한 조명 계산  ★ URP 권장
   Gamma:   구식. 모바일 저사양

   ⚠️ 중간에 바꾸면 모든 색이 달라 보인다
```

```
   ★ Scripting Backend

   Mono:    빌드 빠름. 개발 중  ★
   IL2CPP:  C++로 변환 후 컴파일
            → 실행이 빠르다, 역컴파일이 어렵다
            → 빌드가 매우 느리다 (10~30분)
            → 배포용  ★
```

```
   ⚠️ Managed Stripping

   안 쓰는 코드를 제거해 용량을 줄인다
   → 리플렉션으로 호출하는 코드가 지워질 수 있다
   → link.xml로 보존 지정
```

```xml
<!-- Assets/link.xml -->
<linker>
  <assembly fullname="Assembly-CSharp">
    <type fullname="MyReflectedClass" preserve="all"/>
  </assembly>
</linker>
```

### 3-4. 빌드 실패 원인

**왜 필요한가** — 첫 관문.

```
   ★ 순서대로 확인

   ① Console의 컴파일 오류 (빨간색)
      → 오류가 하나라도 있으면 빌드 불가

   ② 에디터 전용 코드가 런타임에
      → UnityEditor 네임스페이스 사용
      → #if UNITY_EDITOR 로 감싼다

   ③ 플랫폼 미지원 API

   ④ 애셋 임포트 실패

   ⑤ 디스크 공간 부족
```

```csharp
    // ✗ 빌드 실패
    using UnityEditor;

    public class MyScript : MonoBehaviour
    {
        void Start()
        {
            AssetDatabase.Refresh();           // ✗ 에디터 전용
        }
    }

    // ✔ 올바름
#if UNITY_EDITOR
    using UnityEditor;
#endif

    public class MyScript : MonoBehaviour
    {
        void Start()
        {
#if UNITY_EDITOR
            AssetDatabase.Refresh();
#endif
        }
    }
```

```
   ★ 더 나은 방법 — Editor 폴더

   Assets/Editor/ 안의 스크립트는
   자동으로 빌드에서 제외된다
```

### 3-5. 빌드에서만 생기는 문제

**왜 필요한가** — "에디터에서는 됐는데".

| 문제 | 원인 | 해결 |
|---|---|---|
| 씬이 안 열림 | Scene List 미등록 | 등록 |
| 초기화 안 된 변수 | Debug는 0으로 채움 | 명시적 초기화 |
| 리소스를 못 찾음 | 절대 경로 | Resources/StreamingAssets |
| 폰트가 □□□ | TMP 폰트 애셋 | Day 75 |
| 셰이더가 분홍 | Variant 제외 | Always Included Shaders |
| `Resources.Load` 실패 | 경로/확장자 | 확장자 없이, Resources 폴더 기준 |
| 리플렉션 실패 | Managed Stripping | link.xml |
| 성능이 다름 | 에디터 오버헤드 | 정상. 보통 빌드가 빠르다 |
| 랜덤이 항상 같음 | 시드 고정 | `Random.InitState` 확인 |

```
   ★ 로그 확인

   %USERPROFILE%\AppData\LocalLow\<Company>\<Product>\Player.log
```

```csharp
    // 빌드에서도 화면에 오류 표시
    void OnEnable()  { Application.logMessageReceived += OnLog; }
    void OnDisable() { Application.logMessageReceived -= OnLog; }

    private void OnLog(string msg, string stack, LogType type)
    {
        if (type != LogType.Error && type != LogType.Exception) return;

        errorText.text += $"{msg}\n";
        errorPanel.SetActive(true);
    }
```

### 3-6. Development Build로 측정

**왜 필요한가** — 정확한 측정.

```
   ★ 측정 환경별 차이

   에디터:            오버헤드 큼. 실제보다 나쁘다
   Development Build: 약간의 오버헤드. 프로파일러 연결 가능  ★
   Release Build:     실제 성능. 프로파일러 불가
```

```
   ★ 절차

   ① Development Build + Autoconnect Profiler 체크
   ② 빌드 후 실행
   ③ 에디터의 Profiler에서 대상을 빌드 프로세스로 선택
   ④ 측정
```

```
   ⚠️ Deep Profiling

   모든 함수 호출을 추적한다
   → 매우 느려진다 (5~10배)
   → 상대적 비교에만 사용
```

```csharp
    // 코드에서 구간 측정 (Deep Profiling 없이)
    using Unity.Profiling;

    private static readonly ProfilerMarker marker =
        new ProfilerMarker("MyGame.EnemyUpdate");

    void Update()
    {
        marker.Begin();
        // ... 측정할 코드 ...
        marker.End();
    }
```

```
   ★ ProfilerMarker

   프로파일러에 커스텀 항목이 나타난다
   → 내 코드의 어느 부분이 비싼지 정확히
```

### 3-8. 텍스처 최적화

**왜 필요한가** — 빌드 크기와 메모리의 최대 요인.

| 설정 | 권장 |
|---|---|
| **Max Size** | 실제 화면 크기에 맞게 (2048 → 1024) |
| **Compression** | Normal Quality |
| **Format** | 자동 (플랫폼별) |
| Generate Mip Maps | 3D는 ✔, UI는 ✗ |
| **Read/Write** | ✗ (2배 메모리) |
| Streaming Mip Maps | 큰 프로젝트에서 ✔ |

```
   ★ 크기 계산

   2048×2048 RGBA32 비압축  =  16 MB
   2048×2048 DXT5 압축      =   4 MB
   1024×1024 DXT5 압축      =   1 MB

   → 크기를 절반으로 줄이면 메모리는 1/4
```

```
   ⚠️ UI 텍스처에 Mip Maps를 켜면

   화면에서 흐릿하게 보인다
   → UI는 항상 원본 크기로 그려지므로 불필요
```

```
   ★ 일괄 확인 방법

   Project 창에서 Assets/Art/Textures 선택
   → 우측 상단 검색 필터 → t:texture2D
   → 전체 선택 후 한 번에 설정
```

### 3-9. 배칭

**왜 필요한가** — 드로우 콜 감소.

| 방식 | 조건 | 효과 |
|---|---|---|
| **SRP Batcher** | URP 기본 활성 | 셰이더 변형이 같으면 자동 |
| **Static Batching** | Static 체크 | 안 움직이는 오브젝트 병합 |
| **GPU Instancing** | 머티리얼 설정 | 같은 메시 다수 |
| Dynamic Batching | 자동 (작은 메시) | 정점 900개 미만 |

```
   ★ SRP Batcher

   URP Asset → Advanced → SRP Batcher ✔ (기본)
   → 머티리얼이 달라도 셰이더가 같으면 묶인다
   → 가장 효과적

   ⚠️ MaterialPropertyBlock을 쓰면 깨진다 (Day 85·94)
```

```
   ★ Static Batching

   Inspector 우상단 Static ✔
   → 지형, 건물, 장식에 적용

   ⚠️ 메모리를 더 쓴다 (병합된 메시 저장)
   ⚠️ 움직이는 것에는 쓰면 안 된다
```

```
   ★ GPU Instancing

   Material → Enable GPU Instancing ✔
   → 적 100기, 나무 500그루에 효과적
```

```
   ★ 확인 방법

   Frame Debugger (Day 94)
   → 배치가 왜 깨졌는지 이유가 표시된다
```

### 3-11. 오디오 최적화

**왜 필요한가** — 의외의 메모리 소비.

| 용도 | Load Type | Compression |
|---|---|---|
| **BGM (긴 음원)** | Streaming | Vorbis |
| **효과음 (짧음)** | Decompress On Load | PCM 또는 ADPCM |
| 중간 길이 | Compressed In Memory | Vorbis |

```
   ⚠️ 짧은 효과음을 Compressed In Memory로 두면

   재생할 때마다 압축 해제 → CPU 낭비 + 지연
```

```
   ★ Force To Mono

   3D 효과음은 모노로 충분
   → 메모리 절반
```

**기록할 항목**

```csharp
using System.Text;
using UnityEngine;

public class PerfRecorder : MonoBehaviour
{
    [SerializeField] private float sampleDuration = 60f;

    private float elapsed;
    private int frames;
    private float totalDt;
    private float worstDt;
    private long startMemory;

    void Start()
    {
        startMemory = System.GC.GetTotalMemory(false);
        Application.targetFrameRate = -1;      // ★ 제한 해제
        QualitySettings.vSyncCount = 0;
    }

    void Update()
    {
        float dt = Time.unscaledDeltaTime;

        elapsed += dt;
        frames++;
        totalDt += dt;

        if (dt > worstDt) worstDt = dt;

        if (elapsed >= sampleDuration) Report();
    }

    private void Report()
    {
        StringBuilder sb = new StringBuilder();

        sb.AppendLine("=== 성능 측정 ===");
        sb.AppendLine($"측정 시간   {elapsed:F1}초  ({frames} 프레임)");
        sb.AppendLine($"평균 FPS    {frames / totalDt:F1}");
        sb.AppendLine($"평균 프레임 {totalDt / frames * 1000f:F2} ms");
        sb.AppendLine($"최악 프레임 {worstDt * 1000f:F1} ms");
        sb.AppendLine($"메모리      {System.GC.GetTotalMemory(false) / 1048576f:F1} MB");

        Debug.Log(sb.ToString());

        enabled = false;
    }
}
```

```
   ⚠️ vSync를 끄고 측정한다

   켜져 있으면 60fps로 고정돼 여유를 알 수 없다
```
