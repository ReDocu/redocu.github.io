**키를 누르는 즉시 `P`가 한 칸 움직인다.** Enter를 칠 필요가 없다.

**조작** — `W`(위) `A`(왼쪽) `S`(아래) `D`(오른쪽) 또는 방향키. `Q`로 종료.

## 2. 막히는 상황

어제 만든 미로에 `scanf_s`로 이동을 붙여 보자.

```c
    printf("이동 방향 (1.위 2.아래 3.왼쪽 4.오른쪽): ");
    scanf_s("%d", &dir);
```

실제로 해 보면 이렇다.

```
이동 방향: 4  [Enter]     ← 한 칸 가려고 두 번 누른다
이동 방향: 4  [Enter]
이동 방향: 4  [Enter]
```

**한 칸 움직이는 데 키를 두 번 누른다.** 미로를 30칸 이동하면 60번이다.
게임이 아니라 고문이다.

```
   scanf 계열의 동작

   [키 입력]  ──▶  버퍼에 쌓임  ──▶  [Enter]  ──▶  프로그램이 읽음
                                       ▲
                                       └── 이걸 기다린다

   필요한 것

   [키 입력]  ──▶  프로그램이 즉시 읽음
```

> **Enter 없이 키를 즉시 받는 방법이 필요하다.** → **`_getch()`**
> 그리고 그 키를 **좌표 변화로 바꾸는 방법**이 필요하다.

## 3. 개념

### 3-1. `_getch()` — Enter 없이 한 글자 받기

**왜 필요한가** — 게임 입력의 기본. 키를 누르는 순간 반응해야 한다.

```c
#include <conio.h>          // ★ Console I/O (Windows 전용)

int key = _getch();         // 키를 누를 때까지 기다렸다가, 누른 즉시 반환
```

| 함수 | Enter 필요 | 화면에 표시 | 헤더 |
|---|:--:|:--:|---|
| `scanf_s` | O | O | `<stdio.h>` |
| `getchar` | O | O | `<stdio.h>` |
| **`_getch`** | **X** | **X** | `<conio.h>` |
| `_getche` | X | O | `<conio.h>` |

```
   _getch()  —  "get character, no echo"
                 ▲            ▲
                 │            └── 화면에 안 보인다 (게임에 적합)
                 └── 한 글자
```

> ⚠️ `<conio.h>`와 `_getch()`는 **Windows 전용**이다. 표준 C가 아니다.
> Linux/Mac에서는 `termios`나 `ncurses`를 쓴다. 이 과정은 Windows 기준이므로 그대로 사용한다.

### 3-2. 키 코드 — 어떤 값이 들어오나

**왜 필요한가** — 어떤 키가 어떤 숫자로 오는지 알아야 분기할 수 있다.

```c
int key = _getch();
printf("코드: %d, 문자: %c\n", key, key);
```

| 키 | 코드 | 문자 |
|:--:|:--:|:--:|
| `a` | 97 | `a` |
| `A` | 65 | `A` |
| `w` | 119 | `w` |
| `1` | 49 | `1` |
| Enter | 13 | — |
| ESC | 27 | — |
| Space | 32 | ` ` |

**대소문자 모두 받기**

```c
if (key == 'w' || key == 'W')       // 둘 다 검사
```

또는 소문자로 통일:

```c
#include <ctype.h>
key = tolower(key);                  // 'W' → 'w'
if (key == 'w')
```

### 3-3. 방향키 — 두 번 읽어야 한다

**왜 필요한가** — 방향키를 `_getch()`로 한 번만 읽으면 엉뚱한 문자가 들어온다.

```
   방향키는 2바이트로 들어온다

   [↑ 누름]  →  버퍼:  [ 224 ][ 72 ]
                         ▲      ▲
                         │      └── 두 번째: 실제 키 (72 = 위)
                         └───────── 첫 번째: "확장 키다" 신호

   _getch() 한 번만 하면 → 224 만 받고 끝
   다음 _getch() 에서 72 가 들어와 이상하게 동작한다
```

```c
int key = _getch();

if (key == 224 || key == 0)          // 확장 키 신호
{
    key = _getch();                  // ★ 한 번 더 읽는다

    switch (key)
    {
    case 72: /* ↑ */ break;
    case 80: /* ↓ */ break;
    case 75: /* ← */ break;
    case 77: /* → */ break;
    }
}
```

| 방향키 | 첫 바이트 | 두 번째 바이트 |
|:--:|:--:|:--:|
| ↑ | 224 | 72 |
| ↓ | 224 | 80 |
| ← | 224 | 75 |
| → | 224 | 77 |

> **`224`와 `0` 둘 다 검사하는 이유** — 키보드/환경에 따라 `0`으로 오는 경우가 있다.
> 함수 키(F1~F12)는 `0`으로 시작한다.

### 3-4. 방향 벡터 — 키를 좌표 변화로

**왜 필요한가** — 이 발상이 24주 내내 쓰인다. 공의 이동, 총알, 캐릭터, 전부 같은 원리다.

```c
int dx = 0, dy = 0;          // 이번에 얼마나 움직일 것인가

switch (key)
{
case 'w': dy = -1; break;    // 위:   y가 1 감소
case 's': dy =  1; break;    // 아래: y가 1 증가
case 'a': dx = -1; break;    // 왼쪽: x가 1 감소
case 'd': dx =  1; break;    // 오른쪽: x가 1 증가
}

playerX += dx;
playerY += dy;
```

```
   화면 좌표계 (Day 12에서 본 그것)

              (0,0) ────────────▶ x 증가
                │
                │        ↑ dy = -1
                │        │
                │  ←─────┼─────→   dx = -1  /  dx = +1
                │ dx=-1  │  dx=+1
                │        ↓ dy = +1
                ▼
              y 증가

   ★ y는 아래로 증가한다. 위로 가려면 y를 빼야 한다.
```

| 방향 | dx | dy |
|:--:|:--:|:--:|
| 위 ↑ | 0 | **-1** |
| 아래 ↓ | 0 | +1 |
| 왼쪽 ← | -1 | 0 |
| 오른쪽 → | +1 | 0 |
| 대각선 ↗ | +1 | -1 |

> **`(dx, dy)`를 한 세트로 다루는 것이 핵심이다.**
> 이렇게 해 두면 대각선 이동, 속도 조절, 밀려나기(넉백)를 전부 같은 코드로 처리할 수 있다.
>
> | 나중에 | 형태 |
> |---|---|
> | Day 22 공의 속도 | `x += vx; y += vy;` — 같은 구조 |
> | Day 44 캐릭터 이동 | `x += dx * speed * dt;` |
> | Day 66 포탄 발사 | `vx = cos(θ)*P; vy = -sin(θ)*P;` |

### 3-5. 화면 갱신 — 지우고 다시 그리기

**왜 필요한가** — 움직일 때마다 새 미로가 아래에 계속 쌓이면 화면이 스크롤된다.

```c
#include <stdlib.h>

system("cls");              // 콘솔 전체 지우기
PrintMap();                 // 다시 그리기
```

```
   반복 구조

   ┌──────────────────────┐
   │  system("cls")        │  화면 지우기
   │  PrintMap()           │  현재 상태 그리기
   │  key = _getch()       │  입력 대기
   │  좌표 갱신             │  처리
   └──────────┬───────────┘
              └──────────────▶ 다시 위로
```

> ### ⚠️ `system("cls")`는 느리고 깜빡인다
>
> - **느리다** — 매번 새 프로세스를 만든다 (수 밀리초~수십 밀리초)
> - **깜빡인다** — 지운 상태가 눈에 보인다
>
> ```
>   지움 → (빈 화면!) → 그림 → 지움 → (빈 화면!) → 그림
>            ▲ 이게 눈에 보인다
> ```
>
> **이 깜빡임을 기억해 둔다.** 오늘은 그냥 쓰지만,
> - **Day 15**: 커서 이동 방식으로 개선한다
> - **Day 35**: WINAPI에서 같은 깜빡임을 다시 만난다
> - **Day 37**: **더블버퍼링**으로 완전히 해결한다 — 이 과정의 분수령
>
> 지금 이 깜빡임이 그 이야기의 시작이다.

## 4. 따라 만들기

### Step 1 — 키 코드 확인하기

먼저 어떤 값이 들어오는지 직접 본다.

```c
#include <stdio.h>
#include <conio.h>

int main(void)
{
    printf("아무 키나 누르세요. (ESC로 종료)\n\n");

    while (1)
    {
        int key = _getch();

        printf("코드: %3d", key);

        if (key >= 32 && key <= 126)          // 출력 가능한 문자만
            printf("   문자: %c", key);

        printf("\n");

        if (key == 27) break;                 // ESC
    }

    return 0;
}
```

**✅ 여기까지 실행하면** — 키를 누르는 **즉시** 코드가 찍힌다. Enter가 필요 없다.
방향키를 눌러 보면 **한 번 누를 때마다 두 줄**이 찍힌다 (`224`, 그리고 `72` 등).

### Step 2 — 방향키 처리

```c
// 방향키와 WASD를 모두 처리해서 dx, dy를 채운다. 종료면 0 반환
int GetInput(int* dx, int* dy)
{
    *dx = 0;
    *dy = 0;

    int key = _getch();

    if (key == 224 || key == 0)          // 확장 키
    {
        key = _getch();                  // ★ 한 번 더

        switch (key)
        {
        case 72: *dy = -1; break;        // ↑
        case 80: *dy =  1; break;        // ↓
        case 75: *dx = -1; break;        // ←
        case 77: *dx =  1; break;        // →
        }
        return 1;
    }

    switch (key)
    {
    case 'w': case 'W': *dy = -1; break;
    case 's': case 'S': *dy =  1; break;
    case 'a': case 'A': *dx = -1; break;
    case 'd': case 'D': *dx =  1; break;
    case 'q': case 'Q': return 0;        // 종료
    }

    return 1;
}
```

**✅ 여기까지 실행하면** — 아직 화면 변화는 없지만, `dx`/`dy`에 값이 들어온다.
`printf("dx=%d dy=%d\n", dx, dy);`로 확인한다.

### Step 3 — 좌표 갱신

```c
int main(void)
{
    FindPlayerStart();                       // Day 12에서 만든 함수

    int running = 1;
    int moveCount = 0;

    while (running)
    {
        system("cls");
        PrintHeader(1);
        PrintMap();
        PrintFooter(moveCount);

        int dx, dy;
        if (!GetInput(&dx, &dy))             // Q를 누르면 0
        {
            running = 0;
            continue;
        }

        if (dx == 0 && dy == 0)              // 방향키가 아닌 다른 키
            continue;

        g_playerX += dx;                     // ★ 좌표 갱신
        g_playerY += dy;
        moveCount++;
    }

    return 0;
}
```

**✅ 여기까지 실행하면** — 키를 누르면 `P`가 즉시 움직인다.
**단, 벽을 그냥 통과하고, 맵 밖으로 나가면 프로그램이 죽는다.** (내일 고친다)

**✅ 여기까지 실행하면** — 하단에 좌표와 이동 횟수가 실시간으로 갱신된다.

### Step 5 — 임시 경계 제한 (내일 제대로 한다)

지금 상태로는 맵 밖으로 나가면 **크래시**한다. 임시로 막아 둔다.

```c
        int nextX = g_playerX + dx;
        int nextY = g_playerY + dy;

        // 임시 경계 검사 (Day 14에서 벽 판정과 함께 정리한다)
        if (nextX < 0 || nextX >= MAP_W || nextY < 0 || nextY >= MAP_H)
            continue;

        g_playerX = nextX;
        g_playerY = nextY;
        moveCount++;
```

> **`next` 변수를 쓰는 이유** — "갈 자리를 먼저 계산해 두고, 괜찮으면 이동한다".
> 이 **이동 전 검사** 패턴이 내일의 핵심이다.
>
> ```
>   ✘ 먼저 이동하고 나중에 되돌리기
>      x += dx;
>      if (막혔다) x -= dx;        ← 이미 배열 범위를 넘어 크래시할 수도
>
>   ✔ 갈 자리를 먼저 확인
>      nextX = x + dx;
>      if (갈 수 있다) x = nextX;
> ```

**✅ 여기까지 실행하면** — 맵 밖으로 나가려 해도 크래시하지 않는다. (벽은 아직 통과)

### Step 6 — 깜빡임 관찰

미로 크기를 20×20으로 늘리거나, 아래 코드로 출력량을 늘려 본다.

```c
    for (int i = 0; i < 20; i++)
        printf("  ...\n");
```

**✅ 여기까지 실행하면** — 이동할 때마다 **화면 전체가 심하게 깜빡인다.**

> 이 현상을 기억한다. 오늘의 숨은 학습 목표다.

## 6. 자주 막히는 곳

| 증상 | 원인 | 해결 |
|---|---|---|
| 방향키가 이상한 문자로 들어옴 | 확장 키를 한 번만 읽음 | `224`/`0` 검사 후 `_getch()` 한 번 더 |
| 방향키 한 번에 두 칸 움직임 | 두 번째 바이트를 일반 키로 처리 | 확장 키 분기에서 `return` |
| 위/아래가 반대 | `dy` 부호 혼동 | 위는 `-1`, 아래는 `+1` |
| `_getch` 관련 오류 | `<conio.h>` 누락 | `#include <conio.h>` |
| `system` 관련 오류 | `<stdlib.h>` 누락 | `#include <stdlib.h>` |
| 대문자로 눌렀더니 안 됨 | 소문자만 검사 | `case 'w': case 'W':` 둘 다 |
| 맵 밖으로 나가면 크래시 | 경계 검사 없음 | 이동 전 범위 확인 |
| 화면이 아래로 계속 쌓임 | `system("cls")` 누락 | 루프 시작에 추가 |
| 화면이 심하게 깜빡임 | `system("cls")`의 특성 | 정상. Day 15/37에서 개선 |
| 이동이 뚝뚝 끊김 | `system("cls")`가 느림 | 정상. Day 15에서 개선 |

## 7. 정리

### 오늘 배운 것

| 개념 | 한 줄 요약 |
|---|---|
| `_getch()` | Enter 없이, 화면 표시 없이 한 글자 즉시 입력 |
| 확장 키 | 방향키는 2바이트. `224`/`0` 뒤에 **한 번 더** 읽는다 |
| **방향 벡터 `(dx, dy)`** | 키를 좌표 변화로. **24주 내내 쓰는 발상** |
| y축 방향 | 화면 y는 **아래로 증가**. 위로 가려면 `-1` |
| 이동 전 검사 | `next`를 먼저 계산하고, 괜찮으면 이동 |
| `system("cls")` | 화면 지우기. 느리고 깜빡인다 → Day 15, 37에서 개선 |

### 직접 해보기

| 난이도 | 과제 | 힌트 |
|:--:|---|---|
| ★ | 대각선 이동 추가 (Q/E/Z/C 키) | `dx`와 `dy`를 동시에 설정 |
| ★★ | 한 번에 두 칸 이동하는 "달리기" (Shift 대신 대문자 WASD) | `dx *= 2; dy *= 2;` |
