## ② 왜 필요한가

여러분이 W04에서 수집하게 될 데이터는 **깨끗한 표가 아니라 문자열 덩어리**입니다.

```
2026-08-12 14:23:05 [ERROR] api.collector - 요청 실패 (status=503, retry=2)
```

이 한 줄에서 "몇 시에, 어떤 모듈에서, 어떤 상태코드로 실패했는가"를 뽑아내는 것이
로그 분석의 전부입니다. W23에서 서버 로그를 다룰 때도, W20에서 API 응답을 파싱할 때도 같은 일을 합니다.

| 문자열을 못 다루면 | 언제 막히나 |
|---|---|
| 크롤링한 HTML에서 가격 `"89,000원"` 을 숫자로 못 만듦 | W04 |
| CSV의 날짜 `"2026/08/12"` 를 표준 형식으로 못 바꿈 | W05 |
| API 응답 문자열에서 필요한 필드만 못 꺼냄 | W09 |
| 서버 로그에서 에러 발생 시각을 못 찾음 | W23 |

그리고 **비교·논리 연산자**는 내일 배울 조건문의 재료입니다.
조건문이 없으면 프로그램은 위에서 아래로만 흐르는 계산기일 뿐입니다.

## ③ 개념 설명

### 산술 연산자

| 연산자 | 뜻 | 예 | 결과 |
|---|---|---|---|
| `+` | 더하기 | `7 + 3` | `10` |
| `-` | 빼기 | `7 - 3` | `4` |
| `*` | 곱하기 | `7 * 3` | `21` |
| `/` | 나누기 (항상 float) | `7 / 3` | `2.3333333333333335` |
| `//` | 몫 (버림) | `7 // 3` | `2` |
| `%` | 나머지 | `7 % 3` | `1` |
| `**` | 거듭제곱 | `7 ** 3` | `343` |

**`%` 의 실무 용도** — "N개마다 한 번" 을 판단할 때 씁니다.

```python
i % 100 == 0   # 100번째마다 True → 수집 진행 상황 출력 (W04에서 씁니다)
n % 2 == 0     # 짝수 판별
```

### 복합 대입 연산자

```python
count = 0
count = count + 1    # 이렇게 쓸 수도 있고
count += 1           # 이렇게 줄여 쓸 수도 있습니다
```

| 연산자 | 뜻 |
|---|---|
| `+=` | 더해서 다시 넣기 |
| `-=` | 빼서 다시 넣기 |
| `*=` | 곱해서 다시 넣기 |
| `/=` | 나눠서 다시 넣기 |

### 비교 연산자 — 결과는 항상 bool

| 연산자 | 뜻 | 예 | 결과 |
|---|---|---|---|
| `==` | 같다 | `5 == 5` | `True` |
| `!=` | 다르다 | `5 != 3` | `True` |
| `>` `<` | 크다·작다 | `5 > 3` | `True` |
| `>=` `<=` | 크거나 같다·작거나 같다 | `5 >= 5` | `True` |

**`=` 와 `==` 를 헷갈리지 마세요.** `=` 는 대입, `==` 는 비교입니다.

문자열도 비교됩니다. 사전 순입니다.

```python
"apple" < "banana"   # True
"25" > "100"         # True  ← 문자열 비교! "2" > "1" 이므로
25 > 100             # False ← 숫자 비교
```

마지막 두 줄이 중요합니다. **문자열로 된 숫자를 비교하면 사전 순으로 비교**됩니다.
W05에서 정렬이 이상하게 되는 원인 1위입니다.

### 논리 연산자

| 연산자 | 뜻 | 참이 되는 조건 |
|---|---|---|
| `and` | 그리고 | 양쪽 다 참 |
| `or` | 또는 | 한쪽이라도 참 |
| `not` | 아니다 | 뒤집기 |

```python
age = 25
income = 3000

age >= 20 and income >= 2000    # True
age >= 30 or income >= 2000     # True
not (age >= 30)                 # True
```

**연쇄 비교**도 됩니다. 파이썬의 편리한 기능입니다.

```python
20 <= age <= 30      # age가 20 이상 30 이하
```

다른 언어에서는 `age >= 20 && age <= 30` 이라고 써야 합니다.

### 인덱싱 — 문자열에서 한 글자 꺼내기

문자열은 글자들이 **0번부터** 번호 붙어 있는 줄입니다.

```
문자열:   P   y   t   h   o   n
앞 번호:  0   1   2   3   4   5
뒤 번호: -6  -5  -4  -3  -2  -1
```

```python
text = "Python"
text[0]     # 'P'
text[3]     # 'h'
text[-1]    # 'n'   ← 마지막 글자
text[-2]    # 'o'
```

> **`-1` 은 마지막**입니다. 길이를 몰라도 끝에서부터 셀 수 있어서 아주 자주 씁니다.

### 슬라이싱 — 구간 잘라내기

```python
text[시작:끝]        # 시작 이상, 끝 "미만"
text[시작:끝:간격]
```

**끝 번호는 포함되지 않습니다.** 이것이 가장 헷갈리는 부분입니다.

```python
text = "Python"
text[0:3]     # 'Pyt'    0,1,2번  (3번 미포함)
text[2:5]     # 'tho'
text[:3]      # 'Pyt'    처음부터
text[3:]      # 'hon'    끝까지
text[:]       # 'Python' 전체
text[::2]     # 'Pto'    2칸씩
text[::-1]    # 'nohtyP' 거꾸로 ← 회문 판별에 씁니다
```

날짜 문자열 자르기가 대표적인 활용입니다.

```python
date = "2026-08-12"
year  = date[0:4]    # '2026'
month = date[5:7]    # '08'
day   = date[8:10]   # '12'
```

### 문자열 메서드

**메서드(method)** 는 "어떤 값에 붙어 있는 함수"입니다. `값.메서드()` 형태로 씁니다.

| 메서드 | 하는 일 | 예 | 결과 |
|---|---|---|---|
| `.upper()` | 대문자로 | `"abc".upper()` | `'ABC'` |
| `.lower()` | 소문자로 | `"ABC".lower()` | `'abc'` |
| `.strip()` | 앞뒤 공백 제거 | `"  hi  ".strip()` | `'hi'` |
| `.replace(a, b)` | a를 b로 바꾸기 | `"1,000".replace(",","")` | `'1000'` |
| `.split(구분자)` | 구분자로 쪼개 리스트로 | `"a,b,c".split(",")` | `['a','b','c']` |
| `.find(x)` | x의 위치 (없으면 -1) | `"hello".find("l")` | `2` |
| `.startswith(x)` | x로 시작하는가 | `"a.csv".startswith("a")` | `True` |
| `.endswith(x)` | x로 끝나는가 | `"a.csv".endswith(".csv")` | `True` |
| `.count(x)` | x가 몇 번 나오는가 | `"banana".count("a")` | `3` |
| `.zfill(n)` | 앞을 0으로 채워 길이 n | `"7".zfill(3)` | `'007'` |
| `구분자.join(리스트)` | 리스트를 이어붙이기 | `"-".join(['a','b'])` | `'a-b'` |

> **중요** — 문자열 메서드는 **원본을 바꾸지 않고 새 문자열을 돌려줍니다.**
> ```python
> text = "  hi  "
> text.strip()      # 결과는 나오지만 text는 그대로
> text = text.strip()   # ← 이렇게 다시 넣어야 바뀝니다
> ```

### `in` 연산자

문자열 안에 어떤 글자가 있는지 확인합니다.

```python
"py" in "python"        # True
"java" in "python"      # False
"@" not in "hong.com"   # True
```

`.find()` 보다 읽기 쉬워서 **포함 여부만 볼 때는 `in`** 을 씁니다.

line = "2026-08-12 14:23:05 [ERROR] api.collector - 요청 실패 (status=503, retry=2)"

# 1) 날짜와 시각 — 위치가 고정이므로 슬라이싱
date = line[0:10]
time = line[11:19]

# 2) 레벨 — 대괄호 사이
start = line.find("[") + 1
end = line.find("]")
level = line[start:end]

# 3) 모듈명 — "] " 다음부터 " - " 앞까지
mod_start = end + 2
mod_end = line.find(" - ")
module = line[mod_start:mod_end]

# 4) 메시지 — " - " 다음 전부
message = line[mod_end + 3:]

print(f"날짜  : {date}")
print(f"시각  : {time}")
print(f"레벨  : {level}")
print(f"모듈  : {module}")
print(f"메시지: {message}")
print()

# 5) 상태 코드만 뽑기
if "status=" in line:
    s = line.find("status=") + len("status=")
    e = line.find(",", s)
    status = int(line[s:e])
    print(f"상태 코드: {status}  (서버 오류인가? {status >= 500})")

### Step 5. 이메일 도메인 파싱

`email_parse.py` 를 만듭니다.

```python
email = "  Hong.GilDong@Example.COM  "

# 1) 앞뒤 공백 제거 + 소문자 통일 (정규화)
clean = email.strip().lower()
print(f"원본     : '{email}'")
print(f"정규화   : '{clean}'")

# 2) @ 를 기준으로 분리
at = clean.find("@")
user = clean[:at]
domain = clean[at + 1:]

print(f"아이디   : {user}")
print(f"도메인   : {domain}")

# 3) split을 쓰면 더 간단합니다
parts = clean.split("@")
print(f"split    : {parts}")
print(f"아이디   : {parts[0]}")
print(f"도메인   : {parts[1]}")

# 4) 유효성 간단 확인
is_valid = "@" in clean and "." in domain and not clean.startswith("@")
print(f"유효한가 : {is_valid}")
```

실행 결과:

```

정규화   : 'hong.gildong@example.com'
아이디   : hong.gildong
도메인   : example.com
split    : ['hong.gildong', 'example.com']
아이디   : hong.gildong
도메인   : example.com
유효한가 : True
```

> **정규화(normalization)** — 대소문자·공백을 통일하는 작업입니다.
> 이걸 안 하면 `Hong@a.com` 과 `hong@a.com` 이 서로 다른 사람으로 집계됩니다.

## ⑤ 자주 하는 실수

### `IndexError: string index out of range`

```
Traceback (most recent call last):
  File "test.py", line 2, in <module>
    print(text[10])
IndexError: string index out of range
```

**원인** — 문자열 길이보다 큰 번호로 접근했습니다. `"Python"` 은 6글자라 마지막 번호가 `5` 입니다.
**해결** — `len(text)` 로 길이를 확인하고, 마지막 글자는 `text[-1]` 로 접근합니다.

> **슬라이싱은 범위를 넘어도 에러가 나지 않습니다.** `text[0:100]` 은 그냥 있는 만큼만 줍니다.
> 인덱싱만 에러가 납니다. 이 차이가 헷갈릴 때가 많습니다.

### 슬라이싱 끝 번호를 포함이라고 착각

```python
date = "2026-08-12"
year = date[0:3]      # '202'  ← 4글자를 원했는데 3글자
```

**원인** — `[시작:끝]` 은 **끝 미만**까지입니다. `[0:4]` 라야 4글자입니다.
**해결** — "끝 번호는 포함 안 됨"을 외우거나, `date[:4]` 처럼 "몇 글자"로 생각하세요.

### `.strip()` 을 했는데 공백이 그대로

```python
text = "  hi  "
text.strip()
print(f"'{text}'")   # '  hi  '  ← 안 바뀜
```

**원인** — 문자열 메서드는 **원본을 바꾸지 않고 새 값을 반환**합니다.
**해결** — 결과를 다시 대입해야 합니다.

```python
text = text.strip()
```

이 실수는 앞으로 리스트(Day 007)·DataFrame(W05)에서도 같은 형태로 반복됩니다.

### `.strip()` 이 가운데 공백은 못 없앰

```python
"  a b  ".strip()    # 'a b'  ← 가운데 공백은 남습니다
```

**원인** — `strip()` 은 **앞뒤**만 자릅니다.
**해결** — 모든 공백을 없애려면 `.replace(" ", "")` 를 씁니다.

### 문자열 숫자 비교의 함정

```python
"25" > "100"    # True  ← 왜?
```

**원인** — 문자열끼리는 **사전 순**으로 비교합니다. 첫 글자 `"2"` 와 `"1"` 을 비교해 `"2"` 가 크므로 True입니다.
**해결** — 숫자로 비교하려면 형변환합니다. `int("25") > int("100")` → `False`.

CSV에서 읽은 값을 정렬했더니 `1, 10, 100, 2, 20` 순으로 나오는 것이 정확히 이 문제입니다.

### `TypeError: 'str' object does not support item assignment`

```python
text = "python"
text[0] = "P"
```

```
TypeError: 'str' object does not support item assignment
```

**원인** — 문자열은 **불변(immutable)** 입니다. 만들어진 뒤 일부만 바꿀 수 없습니다.
**해결** — 새 문자열을 만듭니다.

```python
text = "P" + text[1:]      # 'Python'
# 또는
text = text.replace("p", "P", 1)   # 1은 "첫 번째 것만"
```

### `.find()` 가 `-1` 을 돌려주는데 그대로 슬라이싱

```python
line = "no bracket here"
start = line.find("[") + 1     # -1 + 1 = 0
end = line.find("]")           # -1
level = line[start:end]        # line[0:-1] → 'no bracket her'  ← 엉뚱한 결과
```

**원인** — `.find()` 는 못 찾으면 `-1` 을 돌려줍니다. 그걸 그대로 슬라이싱에 쓰면 조용히 틀린 값이 나옵니다.
**해결** — 쓰기 전에 존재를 확인합니다.

```python
if "[" in line and "]" in line:
    ...
```

에러가 안 나고 **틀린 값이 나오는** 부류라 가장 위험합니다.

## ⑥ 확인 문제

**1.** `text = "MLOps Engineer"` 일 때 아래 결과를 예측하세요.

```python
text[0:5]        text[-8:]        text[::-1][:3]        text.find("E")
```

<details>
<summary>답 보기</summary>

| 식 | 결과 | 설명 |
|---|---|---|
| `text[0:5]` | `'MLOps'` | 0~4번 (5번 미포함) |
| `text[-8:]` | `'Engineer'` | 뒤에서 8글자 |
| `text[::-1][:3]` | `'ree'` | 먼저 뒤집어 `'reenignE spOLM'`, 그중 앞 3글자 |
| `text.find("E")` | `6` | 대문자 `E` 의 첫 위치 (0부터 셈) |

`text[::-1][:3]` 처럼 **메서드·슬라이싱을 이어 쓰는 것**을 체이닝이라고 합니다. W05 Pandas에서 아주 자주 씁니다.
</details>

**2.** 아래 코드는 `89000` 을 출력하려 했지만 에러가 납니다. 무엇이 문제이고 어떻게 고치나요?

```python
raw = " 89,000원 "
price = int(raw)
print(price)
```

<details>
<summary>답 보기</summary>

```
ValueError: invalid literal for int() with base 10: ' 89,000원 '
```

`int()` 는 순수한 숫자 문자열만 받습니다. 공백·쉼표·한글이 섞여 있으면 변환하지 못합니다.

**세 가지를 순서대로 제거**해야 합니다.

```python
raw = " 89,000원 "
price = int(raw.strip().replace(",", "").replace("원", ""))
print(price)     # 89000
```

`.strip()` → `.replace(",", "")` → `.replace("원", "")` 순으로 이어 쓴 것을 확인하세요.
순서를 바꿔도 결과는 같지만, "앞뒤 정리 → 내부 정리" 순이 읽기 좋습니다.
W05에서는 이 작업을 컬럼 전체에 한 번에 적용하게 됩니다.
</details>

**3.** 로그 문자열에서 `[WARN]` 처럼 대괄호 안의 레벨을 꺼내려고 아래처럼 썼습니다. 이 코드가 **에러 없이 틀린 값**을 낼 수 있는 경우는 언제인가요?

```python
start = line.find("[") + 1
end = line.find("]")
level = line[start:end]
```

<details>
<summary>답 보기</summary>

**대괄호가 없는 줄이 들어올 때**입니다.

`.find()` 는 못 찾으면 `-1` 을 반환합니다. 그러면
- `start = -1 + 1 = 0`
- `end = -1`
- `line[0:-1]` → **마지막 글자만 뺀 문장 전체**가 `level` 에 들어갑니다.

에러가 안 나기 때문에 프로그램은 계속 돌고, 잘못된 값이 그대로 다음 단계로 흘러갑니다.
이런 것을 **조용한 실패(silent failure)** 라고 하며, 데이터 파이프라인에서 가장 찾기 어려운 버그입니다.

**방어 코드**를 넣어야 합니다.

```python
if "[" in line and "]" in line:
    start = line.find("[") + 1
    end = line.find("]")
    level = line[start:end]
else:
    level = "UNKNOWN"
```

Day 009에서 배울 예외 처리, W09 Day 044의 데이터 품질 검증이 전부 이 문제를 체계적으로 다루는 방법입니다.
</details>

## 오늘의 정리

| 항목 | 내용 |
|---|---|
| 산술 | `+ - * /` · `//` 몫 · `%` 나머지 · `**` 거듭제곱 |
| 비교 | `== != > < >= <=` — 결과는 항상 bool |
| 논리 | `and` `or` `not` · 연쇄 비교 `20 <= x <= 30` |

| 슬라이싱 | `text[시작:끝]` — **끝은 미포함** · `text[::-1]` 뒤집기 |

| 핵심 주의 | 문자열 메서드는 **원본을 안 바꾼다** · `find()` 는 없으면 `-1` |
