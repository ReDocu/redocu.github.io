## 2. 막히는 상황

어제 게임 루프에 좌우 키 처리를 붙여 보자.

```c
if (_kbhit())
{
    int key = _getch();

    if (key == 224)
    {
        key = _getch();
        if (key == 75) paddleX -= 2;      // ←
        if (key == 77) paddleX += 2;      // →
    }
}
```

실제로 눌러 보면 이렇다.

```
   키를 꾹 누르고 있으면...

   [즉시 한 칸]  ......잠깐 멈춤......  [따다다다다다닥]
       ▲                  ▲                    ▲
       │                  │                    └── 그 다음엔 너무 빠르다
       │                  └── 0.5초쯤 아무 반응 없다
       └── 처음 한 번만 반응
```

**이것은 Windows의 "키 반복(key repeat)" 동작이다.** 워드에서 글자를 입력할 때는 유용하지만,
게임 조작에는 최악이다.

```
   워드에서:  'a' 꾹 누르기  →  a...aaaaaaaaaa      ← 이게 정상
   게임에서:  → 꾹 누르기    →  움직임...멈춤...쭉   ← 이건 못 쓴다
```

또 다른 문제도 있다.

```c
   ← 와 SPACE를 동시에 누르면?

   _getch()는 하나씩만 읽는다  →  버퍼에 순서대로 쌓여 지연이 생긴다
```

```
   지금:   "키가 눌렸다는 이벤트"를 받는다      (버퍼 기반)
           → 반복 지연, 동시 입력 불가

   필요:   "지금 이 키가 눌려 있는가"를 묻는다   (상태 기반)
           → 매 프레임 즉시, 여러 키 동시
```

> **키의 현재 상태를 직접 묻는 방법이 필요하다.** → **`GetAsyncKeyState`**

## 3. 개념

### 3-1. 이벤트 기반 vs 상태 기반 입력

**왜 필요한가** — 게임 입력의 근본적인 차이. 앞으로 계속 나온다.

```
   [ 이벤트 기반 ]  _kbhit() + _getch()

   키보드 ──▶ [ 입력 버퍼 ] ──▶ 프로그램이 하나씩 꺼내 읽음
                   ▲
                   └── OS가 반복 규칙(지연/속도)을 적용해서 넣는다

   장점:  타이핑에 적합. 놓치는 입력이 없다
   단점:  반복 지연. 동시 입력 처리가 번거롭다


   [ 상태 기반 ]  GetAsyncKeyState()

   프로그램 ──▶ "지금 ← 키가 눌려 있나?" ──▶ 키보드 상태 직접 확인
                                                      │
                                              예/아니오 즉시 반환

   장점:  즉각 반응. 여러 키 동시 확인. 반복 지연 없음
   단점:  빠르게 눌렀다 뗀 것을 놓칠 수 있다
```

| 상황 | 적합한 방식 |
|---|---|
| 이름 입력, 채팅 | 이벤트 기반 |
| **캐릭터 이동, 조준** | **상태 기반** |
| 점프, 발사 (한 번만) | 상태 기반 + 직접 만든 "눌린 순간" 판정 |

### 3-2. `GetAsyncKeyState` — 키 상태 직접 묻기

**왜 필요한가** — 게임 입력의 표준 방법.

```c
#include <windows.h>

if (GetAsyncKeyState(VK_LEFT) & 0x8000)
{
    // 지금 ← 키가 눌려 있다
}
```

```
   GetAsyncKeyState 의 반환값 (SHORT, 16비트)

   비트:  15 14 13 ... 1  0
          ▲              ▲
          │              └── bit 0: 지난 호출 이후 눌린 적이 있나 (신뢰성 낮음)
          └────────────────  bit 15: 지금 눌려 있나  ← 이걸 쓴다

   0x8000 = 1000 0000 0000 0000  (bit 15만 1)

   & 0x8000  →  bit 15만 남긴다
```

```c
// 자주 쓰는 형태로 함수화
int IsKeyDown(int vkey)
{
    return (GetAsyncKeyState(vkey) & 0x8000) != 0;
}
```

**주요 가상 키 코드 (Virtual Key Code)**

| 키 | 상수 | 값 |
|---|---|:--:|
| ← → ↑ ↓ | `VK_LEFT` `VK_RIGHT` `VK_UP` `VK_DOWN` | 0x25~0x28 |
| Space | `VK_SPACE` | 0x20 |
| Enter | `VK_RETURN` | 0x0D |
| ESC | `VK_ESCAPE` | 0x1B |
| Shift | `VK_SHIFT` | 0x10 |
| A~Z | `'A'` ~ `'Z'` (**대문자**) | 0x41~0x5A |
| 0~9 | `'0'` ~ `'9'` | 0x30~0x39 |

```c
if (IsKeyDown('A'))          // ✔ 대문자
if (IsKeyDown('a'))          // ✘ 동작하지 않는다
```

> ⚠️ **`GetAsyncKeyState`는 창이 비활성 상태여도 반응한다.**
> 다른 창을 쓰고 있는데 게임 캐릭터가 움직인다. 콘솔 게임에서는 넘어가지만,
> **Day 44(WINAPI 격투게임)** 에서는 포커스 검사를 추가한다.

### 3-3. 입력 3상태 — Down / Press / Up

**왜 필요한가** — "누르는 동안 이동"과 "누른 순간 점프"는 다르게 처리해야 한다.

```
   키 상태 시간축

   눌림 ────┐                    ┌──────────────┐
            │                    │              │
   떼짐 ────┘                    ┘              └────

            ▲                    ▲              ▲
          (안눌림)              Down          Press...  Up

   Down   = 이번 프레임에 처음 눌렸다      (이전:안눌림 → 지금:눌림)
   Press  = 지금 눌려 있다                (지금:눌림)
   Up     = 이번 프레임에 뗐다            (이전:눌림 → 지금:안눌림)
```

| 상태 | 쓰는 곳 |
|---|---|
| **Down** | 점프, 발사, 메뉴 선택 — **한 번만** 일어나야 하는 것 |
| **Press** | 이동, 조준 — **누르는 동안 계속** |
| **Up** | 차지 공격 발사, 버튼 놓기 |

**구현 — 이전 프레임 상태를 기억한다**

```c
#define KEY_COUNT 256

int g_currKey[KEY_COUNT] = { 0 };      // 이번 프레임
int g_prevKey[KEY_COUNT] = { 0 };      // 지난 프레임

void UpdateInput(void)
{
    for (int i = 0; i < KEY_COUNT; i++)
    {
        g_prevKey[i] = g_currKey[i];                        // ★ 먼저 이전으로 옮기고
        g_currKey[i] = (GetAsyncKeyState(i) & 0x8000) ? 1 : 0;   // 지금 상태 갱신
    }
}

int KeyPress(int vk) { return  g_currKey[vk]; }                        // 누르는 중
int KeyDown (int vk) { return  g_currKey[vk] && !g_prevKey[vk]; }      // 누른 순간
int KeyUp   (int vk) { return !g_currKey[vk] &&  g_prevKey[vk]; }      // 뗀 순간
```

```
   진리표

   prev   curr   Press  Down   Up
   ────────────────────────────────
    0      0       0      0     0     (안 누름)
    0      1       1      1     0     ← Down!
    1      1       1      0     0     ← Press
    1      0       0      0     1     ← Up!
```

> `UpdateInput()`은 **게임 루프의 Input 단계에서 딱 한 번** 호출한다.
> 여러 번 호출하면 `prev`가 덮어써져 Down/Up 판정이 망가진다.

### 3-4. 이동에 델타 타임 적용

**왜 필요한가** — Day 21의 그 원칙. 패들도 예외가 아니다.

```c
// ✘ 프레임마다 고정
if (KeyPress(VK_LEFT)) paddleX -= 2;

// ✔ 초당 이동량
if (KeyPress(VK_LEFT)) paddleX -= PADDLE_SPEED * dt;
```

```
   PADDLE_SPEED = 40 (초당 40칸)

   60 FPS →  40 × 0.0167 = 0.67칸/프레임
   30 FPS →  40 × 0.0333 = 1.33칸/프레임

   → 어느 쪽이든 초당 40칸  ✔
```

### 3-5. 패들 — 위치와 크기

**왜 필요한가** — 패들은 점이 아니라 **선분**이다. 충돌 판정이 달라진다.

```c
typedef struct
{
    double x;            // 왼쪽 끝 위치
    double y;            // 세로 위치 (고정)
    double width;        // 길이
    double speed;
} Paddle;
```

```
   패들 (x = 18, width = 8)

   화면:  0    5    10   15   20   25   30
          ├────┼────┼────┼────┼────┼────┤
                            ▀▀▀▀▀▀▀▀
                            ▲       ▲
                        x = 18   x + width = 26

   ★ "x부터 x+width까지"가 패들이 차지하는 구간
```

**경계 제한 (클램프)**

```c
if (p->x < 0)                       p->x = 0;
if (p->x + p->width > SCREEN_W)     p->x = SCREEN_W - p->width;
```

```
                                     ┌── 오른쪽 끝이 화면을 넘지 않게
   0                                 │
   ├──────────────────────────────▀▀▀▀▀▀▀▀│
                                          SCREEN_W
```

### 3-6. 패들-공 충돌과 반사각

**왜 필요한가** — 여기서 게임성이 결정된다. 그냥 튕기기만 하면 재미가 없다.

**기본 충돌 판정**

```c
int IsPaddleHit(const Ball* b, const Paddle* p)
{
    // 세로 범위: 공이 패들 높이에 있는가
    if ((int)b->y != (int)p->y) return 0;

    // 가로 범위: 공이 패들 위에 있는가
    if (b->x < p->x || b->x > p->x + p->width) return 0;

    // 아래로 내려오는 중인가 (위로 올라가는 공은 무시)
    if (b->vy <= 0) return 0;

    return 1;
}
```

> **`vy > 0` 검사가 중요하다.** 없으면 패들 안에 들어간 공이 계속 반사를 반복한다.
> "내려오는 공만 받아친다"는 규칙이 있어야 안정적이다.

**맞은 위치에 따른 반사각 — 게임성의 핵심**

```
   패들의 어디에 맞았는가에 따라 튕기는 방향이 달라진다

        왼쪽 끝          중앙           오른쪽 끝
          ↖              ↑                ↗
           ╲             │               ╱
            ▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀
            └──────────────────────────┘
            hit = 0.0    hit = 0.5    hit = 1.0

   ★ 이게 없으면 공이 항상 같은 각도로만 튕겨서
     게임이 금방 지루해진다
```

```c
void BouncePaddle(Ball* b, const Paddle* p)
{
    // 맞은 위치를 0.0 ~ 1.0 으로
    double hit = (b->x - p->x) / p->width;

    if (hit < 0.0) hit = 0.0;
    if (hit > 1.0) hit = 1.0;

    // -1.0(왼쪽 끝) ~ +1.0(오른쪽 끝)
    double offset = (hit - 0.5) * 2.0;

    double speed = GetSpeed(b);              // 속력 유지

    b->vx = offset * speed * 0.8;            // 좌우 성분
    b->vy = -fabs(b->vy);                    // 무조건 위로

    // 속력을 원래대로 맞춘다
    SetSpeed(b, speed);

    // 위치 보정 (패들 위로)
    b->y = p->y - 1;
}
```

```
   hit = 0.0  →  offset = -1.0  →  vx가 크게 왼쪽
   hit = 0.5  →  offset =  0.0  →  vx = 0, 수직으로 올라감
   hit = 1.0  →  offset = +1.0  →  vx가 크게 오른쪽
```

> ⚠️ **`vx`가 0에 가까우면 공이 수직으로만 왕복해서 게임이 멈춘다.**
> 최소 `vx`를 보장한다.
>
> ```c
> if (fabs(b->vx) < 3.0)
>     b->vx = (b->vx >= 0) ? 3.0 : -3.0;
> ```

### Step 4 — 경계 제한

```c
void UpdatePaddle(Paddle* p, double dt)
{
    if (IsKeyDown(VK_LEFT))  p->x -= p->speed * dt;
    if (IsKeyDown(VK_RIGHT)) p->x += p->speed * dt;

    // 클램프
    if (p->x < 0)
        p->x = 0;
    if (p->x + p->width > SCREEN_W)
        p->x = SCREEN_W - p->width;
}
```

**✅ 여기까지 실행하면** — 패들이 화면 밖으로 나가지 않는다.

### Step 5 — 패들 렌더링

```c
void RenderPaddle(char screen[][SCREEN_W + 1], const Paddle* p)
{
    int py = (int)p->y;
    int startX = (int)p->x;
    int endX   = (int)(p->x + p->width);

    if (py < 0 || py >= SCREEN_H) return;

    for (int x = startX; x < endX; x++)
    {
        if (x >= 0 && x < SCREEN_W)
            screen[py][x] = '=';           // 또는 '▀'
    }
}
```

**✅ 여기까지 실행하면** — 화면 하단에 패들이 그려지고 좌우로 움직인다.

### Step 6 — 입력 3상태 구현

```c

int g_currKey[KEY_COUNT] = { 0 };

int KeyPress(int vk) { return  g_currKey[vk]; }

int KeyUp   (int vk) { return !g_currKey[vk] &&  g_prevKey[vk]; }
```

```c
    while (g_running)
    {
        // ── Input ──
        UpdateInput();                        // ★ 프레임당 한 번

        if (KeyDown(VK_ESCAPE)) g_running = 0;
        if (KeyDown(VK_SPACE))  LaunchBall();       // 한 번만!

```

**✅ 여기까지 실행하면** — SPACE를 꾹 눌러도 공이 **한 번만** 발사된다.
`KeyPress`로 바꾸면 매 프레임 발사되어 공이 쏟아지는 것을 확인해 본다.

### Step 7 — 공 발사 (대기 상태)

```c
int g_ballLaunched = 0;

void LaunchBall(void)
{
    if (g_ballLaunched) return;

    g_ball.vx = 15.0;
    g_ball.vy = -25.0;                   // 위로
    g_ballLaunched = 1;
}

void UpdateBall(Ball* b, double dt)
{
    if (!g_ballLaunched)
    {
        // 발사 전에는 패들 위에 붙어 있는다
        b->x = g_paddle.x + g_paddle.width / 2;
        b->y = g_paddle.y - 1;
        return;
    }

    // ... 기존 이동/반사 코드 ...
}
```

**✅ 여기까지 실행하면** — 공이 패들 위에 붙어 따라다니다가, SPACE를 누르면 발사된다.

### Step 8 — 패들 충돌과 반사각

```c
int IsPaddleHit(const Ball* b, const Paddle* p)
{
    if (b->vy <= 0) return 0;                          // 내려오는 중만
    if ((int)b->y < (int)p->y) return 0;               // 아직 위
    if ((int)b->y > (int)p->y) return 0;               // 이미 지나침
    if (b->x < p->x - 0.5) return 0;
    if (b->x > p->x + p->width + 0.5) return 0;

    return 1;
}

void BouncePaddle(Ball* b, const Paddle* p)
{
    double hit = (b->x - p->x) / p->width;
    if (hit < 0.0) hit = 0.0;
    if (hit > 1.0) hit = 1.0;

    double offset = (hit - 0.5) * 2.0;
    double speed  = GetSpeed(b);

    b->vx = offset * speed * 0.8;
    b->vy = -fabs(b->vy);

    SetSpeed(b, speed);

    // 최소 vx 보장 (수직 왕복 방지)
    if (fabs(b->vx) < 3.0)
        b->vx = (offset >= 0) ? 3.0 : -3.0;

    b->y = p->y - 1;                     // 위치 보정

    g_hitCount++;
}
```

## 6. 자주 막히는 곳

| 증상 | 원인 | 해결 |
|---|---|---|
| 키를 눌러도 한 번만 움직임 | `_getch()` 방식 | `GetAsyncKeyState` 사용 |
| `IsKeyDown('a')` 가 안 됨 | 소문자 사용 | **대문자** `'A'` |
| Down 판정이 계속 참 | `UpdateInput()`을 여러 번 호출 | 프레임당 한 번만 |
| Down 판정이 아예 안 됨 | `prev` 갱신 순서 오류 | `prev = curr` **먼저**, 그다음 `curr` 갱신 |
| 창이 비활성인데 반응 | `GetAsyncKeyState`의 특성 | 콘솔에서는 넘어감. Day 44에서 포커스 검사 |
| 공이 패들을 뚫음 | 한 프레임 이동량 > 패들 두께 | 속도 상한, 또는 이전 위치와 비교 |
| 공이 패들에 끼임 | 위치 보정 누락 | `b->y = p->y - 1;` |
| 공이 수직 왕복만 함 | `vx`가 0에 가까움 | 최소 `vx` 보장 |
| 패들 위에서 여러 번 반사 | `vy > 0` 검사 누락 | 내려오는 공만 판정 |
| 속도가 FPS마다 다름 | 델타 타임 미적용 | `speed * dt` |

## 7. 정리

### 오늘 배운 것

| 개념 | 한 줄 요약 |
|---|---|
| 이벤트 vs 상태 | 버퍼에서 꺼내기 vs 지금 눌렸는지 직접 묻기 |
| **`GetAsyncKeyState`** | 게임 입력의 표준. `& 0x8000`으로 현재 상태 확인 |
| **입력 3상태** | Down(누른 순간) / Press(누르는 중) / Up(뗀 순간) |
| 이전 프레임 기억 | Down/Up 판정은 `prev`와 `curr` 비교로 |
| 패들 클램프 | 오른쪽 끝은 `x + width`로 검사 |
| **반사각 조절** | 맞은 위치에 따라 각도를 바꾼다. **게임성의 핵심** |
| 최소 `vx` | 수직 왕복으로 게임이 멈추는 것을 막는다 |
