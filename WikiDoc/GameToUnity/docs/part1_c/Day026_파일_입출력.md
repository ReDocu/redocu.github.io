## 2. 막히는 상황

어제 만든 알카노이드에서 12,450점이라는 신기록을 세웠다.
프로그램을 끄고 다시 켠다.

```
   BEST SCORE   0
```

**전부 사라졌다.**

지금까지 만든 모든 데이터는 **메모리에만** 있었다.

```
   메모리 (RAM)                    파일 (디스크)

   ┌──────────────┐               ┌──────────────┐
   │ g_bestScore  │               │              │
   │    12450     │               │  (비어 있음)  │
   └──────────────┘               └──────────────┘
          │
     프로그램 종료
          ▼
   ┌──────────────┐
   │   사라짐      │
   └──────────────┘
```

그리고 어제 만든 스테이지 데이터도 문제다.

```c
const char g_stageData[STAGE_COUNT][BLOCK_ROWS][BLOCK_COLS + 1] = { ... };
```

**스테이지를 하나 추가하려면 소스를 고치고 다시 빌드해야 한다.**

```
   지금:   데이터가 코드 안에 있고, 메모리에만 산다

   필요:   ① 프로그램이 끝나도 남는 저장소
           ② 코드를 다시 빌드하지 않고 바꿀 수 있는 데이터
```

> **디스크에 읽고 쓰는 방법이 필요하다.** → **파일 입출력**

## 3. 개념

### 3-1. 파일 열기와 닫기

**왜 필요한가** — 파일은 "열어서 → 쓰고/읽고 → 닫는다"는 절차를 따른다.

```c
#include <stdio.h>

FILE* fp = NULL;

if (fopen_s(&fp, "ranking.dat", "wb") != 0)     // 열기 (성공 시 0 반환)
{
    printf("파일을 열 수 없습니다.\n");
    return;
}

// ... 읽거나 쓰기 ...

fclose(fp);                                      // 닫기
fp = NULL;
```

```
   ┌──────────────────────────────────────┐
   │  fopen_s   파일을 열고 FILE* 를 얻는다 │
   │      ▼                                │
   │  fread / fwrite / fprintf / fscanf    │
   │      ▼                                │
   │  fclose    반드시 닫는다               │
   └──────────────────────────────────────┘

   ★ malloc / free 와 똑같은 구조다 (Day 19)
     열었으면 반드시 닫는다.
```

> **`fopen` vs `fopen_s`**
> Visual Studio에서 `fopen`을 쓰면 `C4996` 경고가 뜬다. `fopen_s`를 쓴다.
> 반환값이 다르다는 점에 주의한다.
>
> ```c
> FILE* fp = fopen("a.txt", "r");           // 실패 시 NULL 반환
> if (fp == NULL) { ... }
>
> FILE* fp = NULL;
> if (fopen_s(&fp, "a.txt", "r") != 0)      // 성공 시 0 반환
> { ... }
> ```

### 3-2. 파일 모드

**왜 필요한가** — 읽기/쓰기/추가, 텍스트/바이너리를 지정해야 한다.

| 모드 | 뜻 | 파일이 없으면 | 파일이 있으면 |
|:--:|---|---|---|
| `"r"` | 읽기 | **실패** | 처음부터 읽는다 |
| `"w"` | 쓰기 | 새로 만든다 | **내용을 전부 지운다** |
| `"a"` | 추가 | 새로 만든다 | 끝에 이어 쓴다 |
| `"r+"` | 읽기+쓰기 | 실패 | 처음부터 |
| `"w+"` | 쓰기+읽기 | 새로 만든다 | **지운다** |

**텍스트 / 바이너리**

```c
"r"   / "w"      →  텍스트 모드
"rb"  / "wb"     →  바이너리 모드     ★ b 를 붙인다
```

> ### ⚠️ `"w"`는 기존 내용을 즉시 지운다
>
> 세이브 파일을 `"w"`로 열고 저장에 실패하면 **원본까지 날아간다.**
>
> **안전한 저장 절차**
> ```
>   ① 임시 파일(save.tmp)에 쓴다
>   ② 성공했으면 기존 파일을 삭제
>   ③ 임시 파일의 이름을 바꾼다
> ```

### 3-3. 텍스트 입출력 — `fprintf` / `fscanf`

**왜 필요한가** — 사람이 읽고 고칠 수 있는 파일을 만든다.

```c
// 쓰기 — printf 와 똑같은데 앞에 파일 포인터만 붙는다
fprintf(fp, "%d %s %d\n", rank, name, score);

// 읽기 — scanf 와 똑같다
fscanf_s(fp, "%d %s %d", &rank, name, (unsigned)sizeof(name), &score);
```

```
   printf ("%d\n", 100);        →  화면에 출력
   fprintf(fp, "%d\n", 100);    →  파일에 출력

   ★ f 가 붙고 첫 인자가 FILE* 인 것 말고는 똑같다
```

**한 줄씩 읽기 — `fgets`** (Day 8에서 배운 그것)

```c
char line[256];

while (fgets(line, sizeof(line), fp) != NULL)
{
    // line 에 한 줄이 들어온다 (개행 포함)
    printf("%s", line);
}
```

**파일 끝 판정**

```c
while (fgets(line, sizeof(line), fp) != NULL)      // ✔ 반환값으로 판단
while (!feof(fp))                                   // ✘ 마지막 줄을 두 번 읽는다
```

> `feof`는 **읽기를 시도해서 실패한 뒤에야** 참이 된다.
> 그래서 `while (!feof(fp))` 로 쓰면 마지막 줄이 한 번 더 처리된다.
> **반환값으로 판단한다.**

### 3-4. 바이너리 입출력 — `fwrite` / `fread`

**왜 필요한가** — 구조체를 통째로 저장할 수 있고, 빠르고, 작다.

```c
typedef struct
{
    char name[8];
    int  score;
    int  year, month, day;
} RankEntry;

RankEntry entries[5];

// 쓰기
fwrite(entries, sizeof(RankEntry), 5, fp);
//     ▲        ▲                  ▲
//     데이터    요소 하나의 크기      요소 개수

// 읽기
size_t read = fread(entries, sizeof(RankEntry), 5, fp);
if (read != 5) { /* 파일이 손상됐거나 짧다 */ }
```

```
   fwrite(ptr, size, count, fp)   →  size × count 바이트를 쓴다
                                     반환값 = 실제로 쓴 요소 개수

   RankEntry 하나가 24바이트라면
   fwrite(entries, 24, 5, fp)  →  120바이트가 파일에 쓰인다
```

**텍스트 vs 바이너리 비교**

| | 텍스트 | 바이너리 |
|---|---|---|
| 사람이 읽기 | **가능** | 불가능 |
| 메모장으로 수정 | **가능** | 위험 |
| 파일 크기 | 크다 | **작다** |
| 속도 | 느리다 | **빠르다** |
| 이식성 | 좋다 | 환경 의존 (엔디안, 패딩) |
| 적합한 곳 | 설정, 스테이지 데이터 | 세이브, 리소스 |

```
   같은 데이터를 저장하면

   텍스트:  "12450 AAA 2026 8 7\n"     →  20바이트, 눈으로 읽힌다
   바이너리: [4바이트][8바이트][12바이트] →  24바이트, 알아볼 수 없다
```

> **이 과정에서는 둘 다 쓴다.**
> 스테이지 데이터 → 텍스트 (기획자가 수정)
> 랭킹/세이브 → 바이너리 (사용자가 못 고치게)

### 3-5. ⚠️ 구조체 패딩 — 바이너리 저장의 함정

**왜 필요한가** — `sizeof(구조체)`가 멤버 크기의 합과 다를 수 있다.

```c
typedef struct
{
    char c;      // 1바이트
    int  n;      // 4바이트
} Test;

printf("%zu\n", sizeof(Test));      // 8 (5가 아니다!)
```

```
   메모리 배치 (4바이트 정렬)

   ┌───┬───┬───┬───┬───┬───┬───┬───┐
   │ c │ P │ P │ P │ n │ n │ n │ n │      P = 패딩(빈 공간)
   └───┴───┴───┴───┴───┴───┴───┴───┘
     0   1   2   3   4   5   6   7

   ★ CPU가 4바이트 경계에서 읽는 게 빠르기 때문에
     컴파일러가 빈칸을 끼워 넣는다
```

**문제가 되는 경우**

```
   컴파일러 A로 저장한 파일  →  컴파일러 B로 읽으면 깨질 수 있다
   32비트로 저장한 파일      →  64비트에서 깨질 수 있다
```

**대책**

```c
#pragma pack(push, 1)          // 패딩 없이
typedef struct
{
    char c;
    int  n;
} Test;                         // sizeof == 5
#pragma pack(pop)
```

> 이 과정처럼 **같은 환경에서만 쓰는 파일**은 신경 쓰지 않아도 된다.
> 다만 **Day 59(맵툴 파일 포맷)** 에서는 필드를 하나씩 쓰는 방식을 권한다.

### 3-6. 파일 포맷 설계 — 헤더

**왜 필요한가** — 아무 파일이나 열었을 때 프로그램이 죽지 않게 한다.

```c
#define RANK_MAGIC    0x4B4E5241        // "ARNK"
#define RANK_VERSION  1

typedef struct
{
    unsigned int magic;         // 이 파일이 맞는지
    int          version;       // 포맷 버전
    int          count;         // 항목 수
} RankHeader;
```

```
   파일 구조

   ┌────────────────────────────┐
   │ magic    "ARNK"            │  ← 우리 파일이 맞나?
   │ version  1                 │  ← 읽을 수 있는 버전인가?
   │ count    5                 │  ← 몇 개가 들어 있나?
   ├────────────────────────────┤
   │ entry[0]                   │
   │ entry[1]                   │
   │ ...                        │
   └────────────────────────────┘
```

```c
    RankHeader h;
    if (fread(&h, sizeof(h), 1, fp) != 1)  { /* 짧은 파일 */ }
    if (h.magic != RANK_MAGIC)             { /* 다른 파일 */ }
    if (h.version != RANK_VERSION)         { /* 버전 불일치 */ }
    if (h.count < 0 || h.count > MAX_RANK) { /* 손상 */ }
```

> **매직 넘버와 버전 필드는 반드시 넣는다.**
> 나중에 포맷이 바뀌어도 옛 파일을 읽거나, 최소한 "못 읽는다"고 알려줄 수 있다.
> **Day 59의 맵툴 포맷**에서 이 설계를 그대로 쓴다.

### 3-7. 파일 경로

**왜 필요한가** — "빌드하면 되는데 실행 파일로 하면 파일을 못 찾는다"의 원인.

```
   상대 경로 "ranking.dat" 는 어디를 기준으로 하는가?
   → "현재 작업 디렉터리(Current Working Directory)"

   Visual Studio에서 F5로 실행:  프로젝트 폴더
   실행 파일을 직접 더블클릭:     실행 파일이 있는 폴더

   ★ 둘이 다르다!
```

**해결 — 실행 파일 기준 경로 구하기**

```c
#include <windows.h>

void GetDataPath(const char* filename, char* out, int outSize)
{
    char exePath[MAX_PATH];
    GetModuleFileNameA(NULL, exePath, MAX_PATH);      // 실행 파일 전체 경로

    // 마지막 '\' 뒤를 잘라낸다
    char* lastSlash = strrchr(exePath, '\\');
    if (lastSlash) *(lastSlash + 1) = '\0';

    sprintf_s(out, outSize, "%s%s", exePath, filename);
}
```

> 지금은 개발 중이니 상대 경로로 충분하다.
> **Day 41(이미지 로드)** 과 **Day 60(맵 파일)** 에서 이 문제가 다시 나온다.

## 4. 따라 만들기

### Step 1 — 파일에 쓰고 읽기 (가장 단순한 형태)

```c
#include <stdio.h>

int main(void)
{
    // 쓰기
    FILE* fp = NULL;

    if (fopen_s(&fp, "test.txt", "w") != 0)
    {
        printf("파일 생성 실패\n");
        return 1;
    }

    fprintf(fp, "안녕하세요\n");
    fprintf(fp, "점수: %d\n", 12450);

    fclose(fp);
    fp = NULL;

    printf("저장 완료.\n");

    // 읽기
    if (fopen_s(&fp, "test.txt", "r") != 0)
    {
        printf("파일 열기 실패\n");
        return 1;
    }

    char line[256];
    while (fgets(line, sizeof(line), fp) != NULL)
        printf("읽음: %s", line);

    fclose(fp);
    fp = NULL;

    return 0;
}
```

**✅ 여기까지 실행하면** — `test.txt` 파일이 만들어지고, 내용이 다시 읽힌다.
**프로젝트 폴더에서 `test.txt`를 메모장으로 열어 본다.**

### Step 2 — 파일이 없을 때 처리

```c
    if (fopen_s(&fp, "없는파일.txt", "r") != 0)
    {
        printf("파일이 없습니다. (정상적인 상황)\n");
        // 프로그램은 계속 진행한다
    }
```

**✅ 여기까지 실행하면** — 없는 파일을 열어도 프로그램이 죽지 않는다.

> **파일이 없는 것은 오류가 아니다.** 첫 실행 때는 랭킹 파일이 당연히 없다.
> 없으면 빈 랭킹으로 시작하면 된다.

### Step 3 — 랭킹 구조체와 초기화

```c
#define MAX_RANK 5

typedef struct
{
    char name[8];
    int  score;
    int  year, month, day;
} RankEntry;

RankEntry g_ranking[MAX_RANK];
int       g_rankCount = 0;

void InitRanking(void)
{
    g_rankCount = 0;

    for (int i = 0; i < MAX_RANK; i++)
    {
        strcpy_s(g_ranking[i].name, sizeof(g_ranking[i].name), "---");
        g_ranking[i].score = 0;
        g_ranking[i].year  = 0;
        g_ranking[i].month = 0;
        g_ranking[i].day   = 0;
    }
}
```

**✅ 여기까지 실행하면** — 빈 랭킹이 준비된다.

### Step 4 — 텍스트 방식으로 저장/로드

```c
void SaveRankingText(void)
{
    FILE* fp = NULL;

    if (fopen_s(&fp, "ranking.txt", "w") != 0)
    {
        printf("랭킹 저장 실패\n");
        return;
    }

    fprintf(fp, "%d\n", g_rankCount);

    for (int i = 0; i < g_rankCount; i++)
    {
        fprintf(fp, "%s %d %d %d %d\n",
                g_ranking[i].name, g_ranking[i].score,
                g_ranking[i].year, g_ranking[i].month, g_ranking[i].day);
    }

    fclose(fp);
}

int LoadRankingText(void)
{
    FILE* fp = NULL;

    if (fopen_s(&fp, "ranking.txt", "r") != 0)
        return 0;                            // 파일 없음 — 정상

    int count = 0;
    if (fscanf_s(fp, "%d", &count) != 1) { fclose(fp); return 0; }

    if (count < 0 || count > MAX_RANK) count = 0;      // 방어

    for (int i = 0; i < count; i++)
    {
        RankEntry* e = &g_ranking[i];

        if (fscanf_s(fp, "%7s %d %d %d %d",
                     e->name, (unsigned)sizeof(e->name),
                     &e->score, &e->year, &e->month, &e->day) != 5)
        {
            count = i;                       // 읽다가 실패하면 거기까지
            break;
        }
    }

    g_rankCount = count;
    fclose(fp);
    return 1;
}
```

> `%7s` — **버퍼 크기보다 1 작은 값**을 지정해 오버플로를 막는다. (`name[8]` → `%7s`)

**✅ 여기까지 실행하면** — `ranking.txt`가 만들어지고, 메모장으로 열면 내용이 보인다.

```
3
AAA 12450 2026 8 7
KIM 9830 2026 8 6
LEE 8120 2026 8 6
```

### Step 5 — 랭킹 등록 (삽입 정렬)

```c
// 랭킹에 들어가면 순위(0부터), 못 들어가면 -1
int AddRanking(const char* name, int score)
{
    // 들어갈 자리 찾기
    int pos = -1;

    for (int i = 0; i < MAX_RANK; i++)
    {
        if (i >= g_rankCount || score > g_ranking[i].score)
        {
            pos = i;
            break;
        }
    }

    if (pos < 0) return -1;                  // 순위권 밖

    // 뒤로 한 칸씩 밀기 (뒤에서부터!)
    for (int i = MAX_RANK - 1; i > pos; i--)
        g_ranking[i] = g_ranking[i - 1];

    // 새 항목 삽입
    strcpy_s(g_ranking[pos].name, sizeof(g_ranking[pos].name), name);
    g_ranking[pos].score = score;

    // 오늘 날짜
    time_t t = time(NULL);
    struct tm lt;
    localtime_s(&lt, &t);
    g_ranking[pos].year  = lt.tm_year + 1900;
    g_ranking[pos].month = lt.tm_mon + 1;
    g_ranking[pos].day   = lt.tm_mday;

    if (g_rankCount < MAX_RANK) g_rankCount++;

    return pos;
}
```

### Step 6 — 바이너리 방식

```c
#define RANK_MAGIC    0x4B4E5241
#define RANK_VERSION  1

typedef struct
{
    unsigned int magic;
    int          version;
    int          count;
} RankHeader;

void SaveRankingBinary(void)
{
    FILE* fp = NULL;
    if (fopen_s(&fp, "ranking.dat", "wb") != 0) return;

    RankHeader h;
    h.magic   = RANK_MAGIC;
    h.version = RANK_VERSION;
    h.count   = g_rankCount;

    fwrite(&h, sizeof(h), 1, fp);
    fwrite(g_ranking, sizeof(RankEntry), g_rankCount, fp);

    fclose(fp);
}

int LoadRankingBinary(void)
{
    FILE* fp = NULL;
    if (fopen_s(&fp, "ranking.dat", "rb") != 0) return 0;

    RankHeader h;

    if (fread(&h, sizeof(h), 1, fp) != 1)   { fclose(fp); return 0; }
    if (h.magic != RANK_MAGIC)              { fclose(fp); return 0; }
    if (h.version != RANK_VERSION)          { fclose(fp); return 0; }
    if (h.count < 0 || h.count > MAX_RANK)  { fclose(fp); return 0; }

    size_t read = fread(g_ranking, sizeof(RankEntry), h.count, fp);
    fclose(fp);

    if (read != (size_t)h.count) return 0;

    g_rankCount = h.count;
    return 1;
}
```

**✅ 여기까지 실행하면** — `ranking.dat`가 만들어진다.
**메모장으로 열어 보면 알아볼 수 없는 문자가 나온다.** 이게 바이너리다.

```c
int LoadStagesFromFile(const char* filename)
{
    FILE* fp = NULL;
    if (fopen_s(&fp, filename, "r") != 0) return 0;

    int stageCount = 0;
    if (fscanf_s(fp, "%d", &stageCount) != 1) { fclose(fp); return 0; }

    if (stageCount < 1 || stageCount > MAX_STAGES) { fclose(fp); return 0; }

    for (int s = 0; s < stageCount; s++)
    {
        int rows, cols;
        if (fscanf_s(fp, "%d %d", &rows, &cols) != 2) { fclose(fp); return 0; }

        if (rows > BLOCK_ROWS || cols > BLOCK_COLS)   { fclose(fp); return 0; }

        for (int r = 0; r < rows; r++)
        {
            char line[64];
            if (fscanf_s(fp, "%63s", line, (unsigned)sizeof(line)) != 1)
            {
                fclose(fp);
                return 0;
            }

            for (int c = 0; c < cols; c++)
                g_stageData[s][r][c] = line[c];
        }
    }

    g_stageCount = stageCount;
    fclose(fp);
    return 1;
}
```

## 6. 자주 막히는 곳

| 증상 | 원인 | 해결 |
|---|---|---|
| 파일을 못 찾음 | 작업 디렉터리가 다름 | 프로젝트 폴더 확인, 또는 실행 파일 기준 경로 |
| 저장은 되는데 읽으면 깨짐 | 모드 불일치 (`w`/`rb`) | 쓰기와 읽기의 모드를 맞춘다 |
| 마지막 줄이 두 번 처리됨 | `while (!feof(fp))` | 반환값으로 판단 |
| `sizeof(구조체)`가 예상과 다름 | 패딩 | 정상. 같은 환경에서는 문제없음 |
| `fscanf_s`에서 크래시 | `%s`에 크기 인자 누락 | `fscanf_s(fp,"%s",buf,(unsigned)sizeof(buf))` |
| 파일이 비어 있음 | `fclose` 누락 (버퍼 미기록) | 반드시 닫는다 |
| 원본 파일이 날아감 | `"w"`로 열고 실패 | 임시 파일에 쓰고 교체 |
| 랭킹이 뒤죽박죽 | 삽입 시 앞에서부터 밀었다 | **뒤에서부터** |
| 이름이 깨짐 | 버퍼 크기 초과 | `%7s` 처럼 크기 제한 |
| `localtime` 경고 | 구버전 함수 | `localtime_s` 사용 |

## 7. 정리

### 오늘 배운 것

| 개념 | 한 줄 요약 |
|---|---|
| `fopen_s` / `fclose` | 열었으면 반드시 닫는다. `malloc`/`free`와 같은 구조 |
| 파일 모드 | `"w"`는 **기존 내용을 지운다.** `b`는 바이너리 |
| 텍스트 I/O | `fprintf` / `fscanf_s` / `fgets`. 사람이 읽을 수 있다 |
| 바이너리 I/O | `fwrite` / `fread`. 구조체 통째로, 빠르고 작다 |
| `feof` 함정 | 반환값으로 파일 끝을 판단한다 |
| 구조체 패딩 | `sizeof`가 멤버 합과 다를 수 있다 |
| **파일 헤더** | 매직 넘버 + 버전 + 개수. 손상된 파일 방어 |
| 데이터 외부화 | 스테이지를 파일로 → 재빌드 없이 수정 |
