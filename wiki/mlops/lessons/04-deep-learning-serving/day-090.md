## ② 왜 필요한가

금요일 오전의 일은 명확합니다 — [Day 085](day-085.md)에서 이미지로 한 것을 텍스트로:
어제 파인튜닝한 감성 분류기를 **추론 전용 스크립트**로 독립시켜 MP3의 두 번째 재료를
확보합니다. 구조는 같고(로드 1회/예측 N회, 4대 의무), 재료만 다릅니다(전처리 = 토크나이저).

그런데 세상의 관심은 **생성(Decoder)** — ChatGPT류 — 에 쏠려 있고, 여러분은 곧
"우리도 LLM 뭐 좀 해 보자"는 요구를 받게 됩니다. 그때 필요한 것은 프롬프트 잘 쓰는 법이
아니라(그건 별도 과정), **의사결정의 지도**입니다: 생성형이 어떻게 동작하고, API를 쓸지
오픈소스를 돌릴지, 무엇이 비용이고 무엇이 위험인지. 오늘 그 지도의 뼈대를 그립니다.

## ③ 개념 설명

### 생성형 모델 — "다음 토큰 맞히기"의 반복

[Day 088](day-088.md)의 fill-mask를 기억하세요 — "서울의 [MASK]가 심각하다"에 모델이
후보 확률(미세먼지 0.447, 메르스 0.050…)을 내놨습니다. 생성형(GPT 계열)의 동작도
본질은 같은 것의 **반복**입니다:

```
"서울의 미세먼지가" → 다음 토큰 확률분포 → 하나 뽑기("심각") → 문장에 붙이고
"서울의 미세먼지가 심각" → 다음 토큰 확률분포 → 하나 뽑기("하다") → …반복
```

| 개념 | 뜻 |
|---|---|
| 자기회귀 생성 | 내 출력이 다음 입력이 됨 — 한 토큰씩, 왼쪽에서 오른쪽으로 |
| 샘플링·temperature | 확률분포에서 "얼마나 모험적으로 뽑나" — 같은 질문에 답이 달라지는 이유 |
| **환각(hallucination)** | 그럴듯한 다음 토큰의 연쇄 ≠ 사실 — 원리상 내재된 위험 |

이 원리에서 두 가지 실무 감각이 나옵니다: ① 생성은 토큰 단위라 **길이 = 비용·지연**,
② 출력은 확률적이라 **검증 없는 자동화에 바로 꽂으면 안 됨**.

### LLM 활용 지형도 — API vs 오픈소스

| | 상용 API (GPT·Claude 등) | 오픈소스 (Llama·Qwen 등 + Ollama) |
|---|---|---|
| 시작 비용 | 0 (키 발급 즉시) | GPU 인프라 필요 |
| 운영 비용 | 토큰당 과금 — 쓸수록 증가 | 인프라 고정비 — 쓸수록 단가 하락 |
| 데이터 | 외부로 나감 (계약·규정 검토!) | **내부에 머묾** |
| 품질·운영 부담 | 최고 품질, 운영 위임 | 모델 선택·서빙·업데이트 전부 우리 몫 |
| 우리 과정과의 관계 | — | 서빙 기술(W19~, Docker)이 그대로 필요 |

결정 축은 셋입니다: **데이터 민감도, 호출량(비용 구조), 품질 요구.**
실전 구현(프롬프트·RAG·파인튜닝)은 별도 LLM 엔지니어링 과정의 몫이고, 이 과정의 W19~W28이
그 과정의 **선수 과목**입니다 — LLM도 결국 "무거운 모델의 서빙과 운영" 문제이기 때문입니다.

## ④ 단계별 실습

### Step 1. predict_text.py — MP3 재료 2호 (1~3교시)

[Day 085](day-085.md)의 구조를 그대로, 재료만 텍스트로 바꿉니다.

```python
# predict_text.py — 텍스트 추론 전용 스크립트: 문장 → 감성과 확신도
# 사용법: python predict_text.py "문장"
import argparse
import torch
from transformers import AutoModelForSequenceClassification, AutoTokenizer

BASE = "klue/bert-base"                     # 토크나이저의 출처 (모델과 한 몸 — Day 087)
CKPT = "models/nsmc_bert.pt"
LABELS = {0: "부정", 1: "긍정"}             # 라벨 사전 — 응답 해석의 계약
MAX_LENGTH = 64                             # 학습(Day 089)과 같은 값 — 전처리 일치


def load_model():
    tok = AutoTokenizer.from_pretrained(BASE)
    model = AutoModelForSequenceClassification.from_pretrained(BASE, num_labels=2)
    model.load_state_dict(torch.load(CKPT, map_location="cpu"))
    model.eval()
    return model, tok


def predict(model, tok, text: str):
    enc = tok(text, padding=True, truncation=True, max_length=MAX_LENGTH,
              return_tensors="pt")
    with torch.no_grad():
        probs = torch.softmax(model(**enc).logits, dim=1)[0]
    top = probs.argmax().item()
    return {"label": LABELS[top], "confidence": round(probs[top].item(), 4),
            "probs": {LABELS[i]: round(p.item(), 4) for i, p in enumerate(probs)}}


if __name__ == "__main__":
    ap = argparse.ArgumentParser(description="한국어 감성 분류 (NSMC 파인튜닝)")
    ap.add_argument("text", help="분류할 문장")
    args = ap.parse_args()
    model, tok = load_model()
    r = predict(model, tok, args.text)
    print(f"판정: {r['label']} (확신도 {r['confidence']:.1%})")
    print(f"전체 확률: {r['probs']}")
```

[Day 085](day-085.md)와 나란히 놓고 보세요 — 4대 의무가 어떻게 번역됐는지:
같은 전처리 = **같은 토크나이저 + 같은 MAX_LENGTH**, eval()/no_grad()는 동일,
배치 차원은 토크나이저가 `return_tensors="pt"` 로 알아서. 그리고 상수 세 개(BASE·CKPT·
LABELS)가 [Day 089](day-089.md) ⑤에서 말한 "함께 배포해야 할 세트"의 명세입니다.

### Step 4. 생성형 체험 — 원리 확인 (6~7교시)

거대 모델 없이 원리만 확인합니다. [Day 088](day-088.md)의 fill-mask 결과를 다시 보세요:

```
서울의 [MASK]가 심각하다 → 미세먼지 0.447 · 메르스 0.050 · 위기 0.037 · …
```

이것이 "다음(빈칸) 토큰의 확률분포"입니다. 생성형은 이 분포에서 **하나를 뽑아 문장에 붙이고
같은 일을 반복**하는 기계입니다. temperature가 낮으면 최고 확률(미세먼지)만 고집하고(결정적),
높으면 하위 후보(위기, 고령화…)도 뽑힙니다(창의적이지만 위험). — 환각이 왜 원리에 내재하는지도
이 그림에서 자명합니다: 모델은 **사실**이 아니라 **그럴듯함**의 분포를 뽑습니다.

여유가 있다면 Colab에서 소형 한국어 생성 모델(예: 허브에서 "korean gpt2" 검색)을
pipeline("text-generation")으로 돌려 temperature 0.1/1.0/1.5의 차이를 관찰해 보세요 🖥️.

</details>

**Q3.** LLM 도입 결정의 3축(데이터 민감도·호출량·품질)에서, "사내 규정상 데이터 외부 반출
금지 + 하루 100만 호출"인 조직의 선택과 그때 필요해지는 기술 스택을 쓰세요.

<details>
<summary>답 보기</summary>

오픈소스 모델의 자체 서빙입니다 — 데이터가 내부에 머물러야 하고, 대량 호출은 토큰 과금보다
고정 인프라가 유리하기 때문입니다. 그 순간 필요한 것이 GPU 서빙, 컨테이너, 부하 관리, 모니터링 —
즉 이 과정의 W19~W28이 가르치는 바로 그 기술이며, "LLM 시대에도 MLOps가 선수 과목"인 이유입니다.

</details>

## 주간 퀴즈 16 — W18 (Transformer와 사전학습 모델)

<details>
<summary>1. 셀프 어텐션의 3단계는?</summary>

모든 쌍의 내적(유사도) → softmax(주목 배분) → 가중 평균(문맥 섞기). 전부 행렬곱이라 GPU 병렬에 최적.

</details>

<details>
<summary>2. RNN 대비 어텐션의 장거리 의존 처리 우위는?</summary>

RNN은 거리만큼 정보가 단계를 거치며 희석되지만, 어텐션은 모든 쌍을 직접 비교해 거리 1과 100의 연결 비용이 같습니다.

</details>

<details>
<summary>3. Encoder(BERT)와 Decoder(GPT)의 구조·용도 차이는?</summary>

Encoder는 양방향으로 읽어 이해(분류·임베딩)에, Decoder는 왼쪽만 보며 다음 토큰 생성에 특화.

</details>

<details>
<summary>4. 서브워드 토큰화가 OOV를 없애는 원리는?</summary>

어휘집에 없는 단어를 있는 조각(최악엔 글자)까지 쪼개므로 표현 불가능한 입력이 없습니다.

</details>

<details>
<summary>5. "모델과 토크나이저는 한 몸"인 이유는?</summary>

토큰 ID는 그 어휘집 안에서만 의미가 있어, 다른 토크나이저의 ID를 넣으면 에러 없이 무의미한 결과(조용한 실패)가 나옵니다.

</details>

<details>
<summary>6. 사전학습 모델 조달 시 확인할 네 칸은?</summary>

학습 데이터·언어(범위), 용도·비대상, **라이선스**, 평가 결과 — 확인 기록(model_sourcing)까지가 조달.

</details>

<details>
<summary>7. 파인튜닝 학습률이 2e-5처럼 작아야 하는 이유는?</summary>

몸통이 이미 좋은 바닥 근처에 있어, 큰 보폭은 사전학습을 튕겨 내(파괴적 망각) 배운 것을 잊게 합니다.

</details>

<details>
<summary>8. 1,500건으로 0.545→0.815가 가능했던 밑천은?</summary>

사전학습이 압축해 둔 한국어·세상 지식 — 우리는 과제 연결(머리)만 가르쳤습니다 (fill-mask '미세먼지' 0.447이 그 증거).

</details>

<details>
<summary>9. 텍스트 모델 배포 세트 세 가지는?</summary>

가중치 + 토크나이저(어휘집) + 라벨 사전(과 max_length 같은 추론 설정).

</details>

<details>
<summary>10. 환각이 생성형의 원리에 내재하는 이유는?</summary>

모델은 사실이 아니라 "그럴듯한 다음 토큰"의 확률을 뽑는 기계라, 그럴듯함의 연쇄가 사실과 어긋날 수 있습니다 — 검증 없는 자동화에 바로 꽂으면 안 되는 이유.

</details>
