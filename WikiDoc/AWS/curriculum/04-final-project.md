## 단원 개요

### 이 단원을 마치면

- 흐릿한 요구사항을 **아키텍처 다이어그램과 구성 요소 결정표**로 바꿀 수 있다.

- 전 인프라를 **코드로 배포하고 CI/CD로 갱신**할 수 있다.
- 장애를 일부러 일으키고 **탐지 → 진단 → 복구 → 회고**의 사이클을 수행할 수 있다.

### 이론 수업 내용

**25강 (60분)**
1. 요구사항 → 아키텍처로 가는 4단계 — ① 기능 요구 ② 비기능 요구(가용성·성능·보안·비용) ③ 제약 ④ 구성 요소 결정
2. 간단한 용량 산정 — 일일 사용자 · 피크 배수 · 요청당 CPU/메모리 → 인스턴스 수 추정
3. **KMS** — 관리형 키 vs 고객 관리 키(CMK), 봉투 암호화, 키 정책과 IAM의 관계, 어떤 서비스에 무엇을 적용할지(EBS·RDS·S3·Secrets)
4. **Secrets Manager vs 파라미터 스토어** — 자동 교체가 필요하면 Secrets Manager(비밀당 월 $0.40), 단순 설정은 파라미터 스토어(무료)
5. **WAF** — 관리형 규칙 그룹(공통 위협·SQL 인젝션·IP 평판), 속도 기반 규칙, 비용 구조와 언제 붙일지
6. 최소 권한 재점검 — 배포 역할·태스크 역할·Lambda 역할을 표로 정리하고 `*` 제거

**26강 (30분 이론 + 리뷰)**
1. RPO(얼마나 잃어도 되나) / RTO(얼마나 빨리 복구해야 하나)를 **숫자로** 정하기
2. **DR 전략 4단계 비교**

| 전략 | RPO/RTO | 비용 | 구성 |
|---|---|---|---|
| 백업 & 복구 | 시간 단위 | 최저 | 스냅샷 + 리전 간 복사 |
| 파일럿 라이트 | 수십 분 | 낮음 | 데이터만 복제, 컴퓨팅은 꺼둠 |
| 웜 스탠바이 | 분 단위 | 중간 | 축소 규모로 상시 가동 |
| 액티브-액티브 | 초 단위 | 최고 | 양쪽 리전 동시 서비스 |

3. AWS Backup으로 백업 계획 중앙화(리소스 태그 기반)
4. **설계 리뷰 진행법** — 발표 5분 + 질의 5분, 리뷰어는 "이 구성이 죽는 시나리오"를 반드시 하나 제시

### 보안 및 운영상 주의점

- KMS 키 정책에서 **자기 자신을 잠그지 않도록** 주의합니다(키 관리자 없이 만들면 복구 불가).
- 시크릿을 팀 채팅·문서에 붙여넣지 않습니다. 값이 아니라 **시크릿 이름(ARN)만 공유**합니다.
- WAF는 만능이 아닙니다. 애플리케이션 입력 검증을 대체하지 않습니다.
- 설계 단계에서 **모든 IAM 역할에 `AdministratorAccess`가 없는지** 확인합니다(평가 감점 항목).

### 리소스 정리 체크리스트

- [ ] 테스트 시크릿 삭제(**복구 대기 기간 0일** 옵션 사용)
- [ ] AWS Backup 백업 계획은 유지, 리소스 할당은 W14 이후

5. KMS 고객 관리 키를 쓰는 이유는? → **키 정책으로 접근을 직접 통제**하고, 교체 주기·감사(사용 이력)를 관리하기 위해서. 규제 요건이 있을 때 필수.

3. 알람 임계값을 감으로 정하면 안 되는 이유는? → 너무 낮으면 **알람 피로**로 무시하게 되고, 너무 높으면 장애를 놓친다. 정상 구간을 측정한 뒤 근거를 두고 정해야 한다.
4. 부하를 걸었는데 스케일 아웃이 늦다. 점검할 항목 3가지는? → ① 조정 정책의 **목표값·평가 기간** ② 인스턴스/태스크 **준비 시간(워밍업)** ③ 헬스 체크 통과까지의 지연. (그리고 최대 용량 한도)
5. 게임데이의 회고에서 "누가 실수했는가"를 따지지 않는 이유는? → 사람은 다시 실수한다. **재발을 막는 것은 절차와 자동화**이므로 시스템을 고쳐야 한다.
</details>

## 6. 발표와 시연 가이드

**발표 10분 구성 (권장)**

| 시간 | 내용 |
|---|---|
| 1분 | 서비스 소개와 핵심 요구사항 3개 |
| 2분 | 아키텍처 다이어그램 설명(요청 흐름 따라가기) |
| 3분 | **선택 근거** — 대안과 비교해 왜 이 구성인가(최소 3개 의사결정) |
| 2분 | 검증 결과 — 고가용성·확장·장애 복구 수치 |
| 1분 | 비용과 절감안 |
| 1분 | 회고 — 다시 만든다면 무엇을 바꿀 것인가 |

**시연 5분** — ① 서비스 정상 동작 ② 장애 주입 후 자동 복구 ③ 코드 푸시 → 자동 배포 중 **2개 이상**

**자주 나오는 질문 대비** — "왜 X 대신 Y인가", "트래픽이 10배가 되면", "이 구성에서 가장 먼저 죽는 곳은", "비용을 절반으로 줄이라면"

## 7. 평가 루브릭

**최종 프로젝트 25% + 발표·동료 평가 10% = 35%** 의 배분 기준입니다.

### 7-1. 최종 프로젝트 (100점 → 과정 반영 25%)

| 영역 | 배점 | 탁월(90~100) | 우수(80~89) | 보통(70~79) | 미흡(<70) |
|---|---|---|---|---|---|
| 아키텍처 설계 | 15 | 대안 비교와 정량적 근거가 모든 계층에 있음 | 주요 계층에 근거 있음 | 구성은 타당하나 근거 부족 | 요구사항과 불일치 |
| 네트워크·보안 | 15 | 최소 권한·암호화·경계 분리 완결, 와일드카드 없음 | 기준선 충족 | 일부 과다 권한/공개 리소스 | DB·앱이 인터넷 노출 |
| 고가용성·확장성 | 15 | 다중 AZ + 자동 복구 + 확장 검증 수치 제시 | 다중 AZ와 자동 복구 동작 | 단일 AZ 또는 검증 부족 | 단일 인스턴스 구성 |
| 데이터·백업/DR | 10 | RPO/RTO 근거 + 복원 실행 증빙 | 백업 설정과 절차서 존재 | 백업만 설정 | 백업 없음 |
| IaC | 15 | 전 리소스 코드화 + 재현 검증 | 대부분 코드화 | 일부만 코드화 | 수동 구축 |
| CI/CD | 10 | OIDC + 스모크 테스트 + 롤백 검증 | 자동 배포 동작 | 부분 자동화 | 수동 배포 |
| 관측성·장애 대응 | 10 | 알람 기반 탐지 + 런북 + 회고 | 대시보드·알람 구성 | 대시보드만 | 없음 |
| 비용·WA 리뷰 | 10 | 실측 대조 + 근거 있는 절감안 + 위험 개선 반영 | 산정과 검토 완료 | 산정만 | 없음 |
| **합계** | **100** | | | | |

**감점** — 리소스 정리 미완료 −10 · 저장소에 자격 증명 노출 −20 · 타 팀/외부 대상 부하 테스트 −20 · 마일스톤 미제출 건당 −5

### 7-2. 발표 및 동료 평가 (100점 → 과정 반영 10%)

| 항목 | 배점 | 기준 |
|---|---|---|
| 아키텍처 설명력 | 30 | 요청 흐름과 선택 근거를 청중이 이해하게 전달 |
| 시연 완성도 | 25 | 시연 2건 이상 성공, 실패 시 대응 태도 |
| 질의 대응 | 15 | 모르는 것은 모른다고 하되 접근 방법 제시 |
| 자료 완성도 | 10 | 다이어그램 정확성·가독성, 민감 정보 마스킹 |
| **동료 평가** | 20 | 팀 내 기여도·협업·지식 공유 (팀원 상호 평가 평균) |
| **합계** | **100** | |

> **동료 평가 방식** — 팀원 각자가 나머지 팀원에게 100점 만점 점수와 근거 2줄을 제출합니다. 최고·최저를 제외한 평균을 사용하며, 팀 내 편차가 30점 이상이면 강사가 개별 면담 후 조정합니다.

## 이 단원에서 자주 나오는 질문

| 질문 | 답 |
|---|---|
| 주제가 너무 크면 어떻게 하나요? | 기능을 줄이고 **아키텍처 요건 13개를 지키는 쪽**을 택하세요. 평가는 기능 개수가 아니라 구조의 타당성을 봅니다. ([1절](#1-프로젝트-주제와-범위)) |
| 서버리스로만 만들어도 되나요? | 됩니다. 단 요구사항 3(퍼블릭/프라이빗 분리)과 4(고가용성)를 어떻게 충족했는지 설명해야 합니다. VPC Lambda·DynamoDB 구성이면 그 근거를 문서화하세요. |
| 비용이 한도를 넘을 것 같습니다 | 즉시 강사에게 알리고 구조를 조정합니다. **NAT → VPC 엔드포인트**, **Multi-AZ는 시연 구간만**, **야간 자동 축소**가 표준 대응 3종입니다. (W14·W15) |
| 팀원이 참여하지 않으면요? | 동료 평가와 커밋 기록으로 기여도가 반영됩니다. 3주차 이전에 강사에게 알리면 역할 재조정을 지원합니다. |
| 발표 때 시연이 실패하면요? | 실패 자체는 큰 감점이 아닙니다. **원인을 즉시 진단하고 설명하는 능력**이 오히려 가점 요소입니다. 백업으로 녹화 영상을 준비하세요. |
| 과정이 끝나고 계정은 어떻게 하나요? | 리소스를 전부 지운 뒤 Budgets 알림은 남겨 둡니다. 계정을 닫으려면 결제 정보 확인 후 진행하고, 포트폴리오용 저장소는 남겨 두세요. ([A2](A2-next-steps.md)) |
