## 1. 오늘 만드는 것

**결말이 여러 개인 완성된 게임.** 어떻게 끝냈느냐에 따라 다른 엔딩이 나온다.

```

=====================================

  당신은 녹슨 열쇠로 문을 열고

  다시 하시겠습니까? (1.예 0.아니오): _
```

**조작** — 게임을 끝까지 진행하고, 결과 화면에서 재시작 여부를 고른다.

## 2. 막히는 상황

어제까지 결말은 이랬다.

```c
if (ending == 1) printf("시간이 다 되었다\n");
else if (ending == 2) printf("포기했다\n");
else if (ending == 3) printf("탈출 성공!\n");
```

문제가 셋이다.

1. **탈출은 다 똑같다.** 5턴 만에 나가든 19턴 만에 나가든 결말이 같다 → 잘할 이유가 없다
2. **한 판 하면 끝이다.** 다시 하려면 프로그램을 다시 실행해야 한다
3. **플레이 기록이 없다.** 몇 턴 걸렸는지, 뭘 찾았는지 모른다

```
   지금:   탈출  →  "탈출 성공!"           ← 잘하든 못하든 같은 결과

   필요:   탈출  →  성적 계산  →  등급 판정  →  등급별 엔딩
                        ▲
                        └── 남은 시간, 찾은 단서, 이동 횟수
```

> **플레이 결과를 기록하고, 그것을 평가해서 결말을 나누는 방법이 필요하다.**

## 3. 개념

### 3-1. 종료 코드 — 어떻게 끝났는지 기록

**왜 필요한가** — 루프를 나온 뒤에는 "왜 나왔는지"를 알 수 없다. 나오기 전에 기록해야 한다.

```c
#define ENDING_NONE     0      // 아직 안 끝남
#define ENDING_TIMEOUT  1      // 시간 초과
#define ENDING_QUIT     2      // 사용자 포기
#define ENDING_ESCAPE   3      // 탈출 성공
#define ENDING_TRAPPED  4      // 함정 (확장)
```

```
   ┌──────────────────────────────────────────────────┐
   │  while (running)                                  │
   │                                                   │
   │   시간 0    → running=0, ending=ENDING_TIMEOUT     │
   │   0 입력    → running=0, ending=ENDING_QUIT        │
   │   문 열림   → running=0, ending=ENDING_ESCAPE      │
   │                                                   │
   └──────────────────────┬───────────────────────────┘
                          ▼
              switch (ending) 로 결말 출력

   ★ 종료 지점마다 ending을 반드시 설정한다. 하나라도 빠뜨리면 결말이 안 나온다.
```

### 3-2. 플레이 통계 — 기록해야 평가할 수 있다

**왜 필요한가** — 등급을 매기려면 숫자가 있어야 한다.

```c
typedef struct                  // Day 5의 구조체를 여기 쓴다
{
    int timeLeft;               // 남은 시간
    int clueFound;              // 찾은 단서 수
    int moveCount;              // 이동 횟수
    int searchCount;            // 조사 횟수
} PlayResult;
```

**통계는 발생하는 그 자리에서 올린다.**

```c
    // 이동할 때
    currentRoom = ROOM_HALL;
    result.moveCount++;                  // ← 여기서

    // 단서를 찾을 때
    hasKey = 1;
    result.clueFound++;                  // ← 여기서
```

> 나중에 한꺼번에 세려고 하면 반드시 빠뜨린다. **일어나는 순간에 기록한다.**

### 3-3. 등급 판정 — 숫자를 결말로 바꾸기

**왜 필요한가** — 잘할 이유를 만든다. 이것이 게임에 목표를 준다.

**판정 기준을 표로 먼저 정한다.**

| 등급 | 조건 | 결말 |
|:--:|---|---|
| ★★★ | 탈출 + 단서 전부 + 남은 시간 10 이상 | 완벽한 탈출 |
| ★★ | 탈출 + 남은 시간 5 이상 | 무사 탈출 |
| ★ | 탈출 | 간신히 탈출 |
| — | 시간 초과 / 포기 | 실패 |

```c
int JudgeRank(PlayResult r, int ending)
{
    if (ending != ENDING_ESCAPE)
        return 0;                                   // 탈출 못 했으면 등급 없음

    if (r.clueFound >= CLUE_TOTAL && r.timeLeft >= 10)
        return 3;
    if (r.timeLeft >= 5)
        return 2;
    return 1;
}
```

> **조건은 좁은 것부터.** (Day 3에서 배운 그것)
> `timeLeft >= 5`를 먼저 쓰면 ★★★이 절대 안 나온다.

### 3-4. 결과 화면 구성

**왜 필요한가** — 게임의 마지막 인상을 만든다. 그리고 플레이어가 다음 목표를 갖게 한다.

```
   ┌───────────────────────────────────┐
   │  ① 큰 제목      E S C A P E        │  ← 성공/실패가 한눈에
   ├───────────────────────────────────┤
   │  ② 서술         "문을 열고..."      │  ← 이야기의 마무리
   ├───────────────────────────────────┤
   │  ③ 통계         시간 12/20         │  ← 무엇을 잘했나
   │                 단서  3/3          │
   ├───────────────────────────────────┤
   │  ④ 등급         ★★★ 완벽한 탈출     │  ← 목표 제시
   ├───────────────────────────────────┤
   │  ⑤ 다음 행동    다시 하시겠습니까?   │  ← 재도전 유도
   └───────────────────────────────────┘
```

> 이 5칸 구조는 앞으로 만들 모든 게임의 결과 화면에 그대로 쓴다.
> 알카노이드(Day 25), 슈팅(Day 55), 파이널 프로젝트까지.

### 3-5. 재시작 루프 — 게임 밖의 루프

**왜 필요한가** — 한 판이 끝나도 프로그램은 살아 있어야 한다.

```
   ┌──────────────────────────────────────────┐
   │  while (playAgain)          ← 바깥 루프    │
   │  {                                        │
   │    InitGame();              게임 상태 초기화│
   │    ┌────────────────────────────────────┐ │
   │    │  while (running)      ← 안쪽 루프    │ │
   │    │  {  한 판 진행  }                    │ │
   │    └────────────────────────────────────┘ │
   │    PrintResult();           결과 출력      │
   │    playAgain = AskReplay(); 재시작 여부     │
   │  }                                        │
   └──────────────────────────────────────────┘
```

> ### ⚠️ 재시작 시 초기화를 빠뜨리면 이전 판의 상태가 남는다
>
> ```c
> while (playAgain)
> {
>     // ✘ 초기화 없음 → 두 번째 판에서 이미 열쇠를 갖고 시작
>     while (running) { ... }
> }
> ```
>
> **초기화해야 할 것을 목록으로 만들어 둔다.**
>
> | 변수 | 초기값 |
> |---|---|
> | `running` | 1 |
> | `ending` | ENDING_NONE |
> | `currentRoom` | ROOM_STORAGE |
> | `hasKey` | 0 |
> | `timeLeft` | 20 |
> | `result` (전 멤버) | 0 |

**초기화를 함수로 묶으면 빠뜨리지 않는다.**

```c
void InitGame(int* room, int* hasKey, int* timeLeft, PlayResult* r)
{
    *room     = ROOM_STORAGE;
    *hasKey   = 0;
    *timeLeft = MAX_TIME;
    r->clueFound   = 0;
    r->moveCount   = 0;
    r->searchCount = 0;
}
```

> 여기서 `*`와 `->`가 나온다. **Day 18의 포인터**를 미리 맛보는 것이다.
> 지금은 "함수 안에서 밖의 변수를 바꾸려면 `&`로 넘기고 `*`로 쓴다"만 알고 넘어간다.
>
> 포인터가 아직 부담스러우면, 오늘은 **초기화 코드를 `main` 안에 그냥 나열**해도 된다.

### Step 5 — 결과 화면

```c
void PrintResult(PlayResult r, int ending)
{
    int rank = JudgeRank(r, ending);

    printf("\n\n=====================================\n");

    // ① 제목
    switch (ending)
    {
    case ENDING_ESCAPE:  printf("            E S C A P E\n");     break;
    case ENDING_TIMEOUT: printf("        T I M E   O V E R\n");   break;
    case ENDING_QUIT:    printf("        G A M E   O V E R\n");   break;
    }
    printf("=====================================\n\n");

    // ② 서술
    switch (ending)
    {
    case ENDING_ESCAPE:
        printf("  당신은 문을 열고\n");
        printf("  차가운 밤공기 속으로 걸어 나왔다.\n");
        break;
    case ENDING_TIMEOUT:
        printf("  문틈으로 새던 빛마저 사라졌다.\n");
        printf("  이 방은 이제 당신의 것이다.\n");
        break;
    case ENDING_QUIT:
        printf("  당신은 바닥에 주저앉았다.\n");
        break;
    }

    // ③ 통계
    printf("\n  -----------------------------------\n");
    printf("    남은 시간   %2d / %2d\n", r.timeLeft, MAX_TIME);
    printf("    찾은 단서   %2d / %2d\n", r.clueFound, CLUE_TOTAL);
    printf("    이동 횟수   %2d\n", r.moveCount);
    printf("    조사 횟수   %2d\n", r.searchCount);
    printf("  -----------------------------------\n");

    // ④ 등급
    printf("\n  ");
    switch (rank)
    {
    case 3: printf("★★★  완벽한 탈출\n");           break;
    case 2: printf("★★    무사 탈출\n");             break;
    case 1: printf("★      간신히 탈출\n");          break;

```

### Step 6 — 재시작 루프

```c
int main(void)
{
    int playAgain = 1;

    PrintTitle();

    while (playAgain)                                    // ← 바깥 루프
    {
        // --- 초기화 (빠뜨리면 안 되는 것들) ---
        int running     = 1;
        int ending      = ENDING_NONE;
        int currentRoom = ROOM_STORAGE;
        int timeLeft    = MAX_TIME;
        int hasKey = 0, hasNote = 0, hasLantern = 0;
        PlayResult result = { 0, 0, 0, 0 };

        // --- 한 판 ---
        while (running)                                  // ← 안쪽 루프
        {
            // ... 기존 게임 루프 ...
        }

        result.timeLeft = timeLeft;                      // 최종 시간 기록
        PrintResult(result, ending);

        playAgain = ReadInt("\n다시 하시겠습니까? (1.예 0.아니오)", 0, 1);
    }

    printf("\n플레이해 주셔서 감사합니다.\n");
    return 0;
}
```

> 변수를 `while (playAgain)` **안에서 선언**했기 때문에 매 판 자동으로 초기화된다.
> 이것도 유효 범위(Day 4)를 활용한 기법이다.

**✅ 여기까지 실행하면** — 게임이 끝난 뒤 `1`을 누르면 완전히 새 판이 시작된다.
**이전 판의 열쇠가 남아 있지 않아야 정상이다.**

## 5. 실행 결과

**정상이라면 이렇게 보인다.**

```
=====================================
            E S C A P E
=====================================

  당신은 문을 열고
  차가운 밤공기 속으로 걸어 나왔다.

  -----------------------------------
    남은 시간   12 / 20
    찾은 단서    3 /  3
    이동 횟수    9
    조사 횟수    5
  -----------------------------------

  ★★★  완벽한 탈출

=====================================

다시 하시겠습니까? (1.예 0.아니오) (0~1): 1

=================================
  당신은 낡은 방에 갇혀 있다.
=================================

---------------------------------
[ 남은 시간 20 ]   현재 위치: 창고
[ 소지품 ]  (없음)                    ← 열쇠가 없어야 정상!
```

- [ ] 종료 방식(탈출/시간초과/포기)에 따라 다른 결말이 나온다
- [ ] 통계가 실제 플레이와 일치한다
- [ ] 남은 시간과 단서 수에 따라 등급(★~★★★)이 달라진다
- [ ] `1`을 누르면 새 판이 시작되고, **이전 판의 아이템이 남아 있지 않다**
- [ ] `0`을 누르면 프로그램이 정상 종료된다
- [ ] 어떤 입력을 넣어도 죽지 않는다 (Day 8 검증 유지)

## 6. 자주 막히는 곳

| 증상 | 원인 | 해결 |
|---|---|---|
| 결말이 항상 하나만 나옴 | 종료 지점에서 `ending` 미설정 | 모든 `running = 0` 옆에 `ending = ` 확인 |
| 등급이 항상 ★★ | 조건 순서 (넓은 조건이 앞) | **좁은 조건부터** |
| 재시작 후 열쇠가 남아 있음 | 초기화 누락 | 변수를 바깥 루프 **안**에서 선언 |
| 통계가 0으로 나옴 | 카운터를 올리는 코드가 빠짐 | 이동·조사 지점마다 `++` 확인 |
| 남은 시간이 결과에 안 반영 | 루프 밖에서 `result.timeLeft` 미대입 | 루프 종료 후 대입 |
| 재시작 시 무한 루프 | `playAgain` 갱신 누락 | `ReadInt` 결과를 대입 |
| 두 번째 판에서 시간이 0에서 시작 | `timeLeft` 초기화 누락 | 초기화 목록 재확인 |
| `InitGame` 함수에서 값이 안 바뀜 | 값 전달 (Day 4의 벽) | `&`로 넘기고 `*`로 접근, 또는 초기화를 `main`에 나열 |

## 7. 정리

### 오늘 배운 것

| 개념 | 한 줄 요약 |
|---|---|
| 종료 코드 | 왜 끝났는지를 **끝나기 전에** 기록한다 |
| 플레이 통계 | 일어나는 **그 순간**에 기록한다 |
