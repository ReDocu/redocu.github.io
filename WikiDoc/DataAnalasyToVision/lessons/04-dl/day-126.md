```

할인율을 예측할 것인가?   →  35%
```

**둘은 수학적으로 연결되어 있지만 완전히 다른 문제입니다.**

| | 할인가 예측 | 할인율 예측 |
|---|---|---|
| 타깃 범위 | 0 ~ 수십만 원 (넓음) | 0 ~ 90% (좁음) |
| 왜도 | 큼 | 작음 |
| 정가 필요 | 특성으로 | 필수 (역산에) |
| 사용자 체감 | 직접적 | 간접적 |
| 지표 | WAPE·MAE | MAE·RMSE |

**오늘 이 결정을 하고, 그 근거를 문서에 남깁니다.**

## 2부 · 타깃 정의 — 이 프로젝트의 첫 번째 결정

### 선택지 3가지

| 선택지 | 타깃 | 예시 |
|---|---|---|
| **A. 할인가** | 세일 시 판매 가격 | 12,900원 |
| **B. 할인율** | 정가 대비 할인 비율 | 35% |
| **C. 할인 여부 + 할인가** | 2단계 | 할인함 → 12,900원 |

### A. 할인가 예측

```
타깃: 할인가 (원)
특성: 정가, 장르, 평점, 리뷰수, 출시경과일, ...
```

| 장점 | 단점 |
|---|---|
| 사용자가 직접 알고 싶은 값 | **정가에 크게 의존** — 정가만 알아도 대략 맞음 |
| 지표 해석이 쉬움 ("3,200원 틀림") | 범위가 넓어 왜도가 큼 |
| | **무료 게임(0원)** 처리 문제 |

**⚠ 함정 — 정가가 너무 강력한 특성입니다**

```
할인가 ≈ 정가 × 0.7  (평균 할인율 30%)
→ 정가만으로 R² 0.85가 나올 수 있음
→ "모델이 한 일이 무엇인가?"
```

**베이스라인을 "정가 × 평균 할인율"로 잡아야 합니다.** ([Day 108](day-108.md))

### B. 할인율 예측

```
타깃: 할인율 (0~90%)
특성: 정가, 장르, 평점, 리뷰수, 출시경과일, ...
할인가 = 정가 × (1 - 예측 할인율)   ← 사후 계산
```

| 장점 | 단점 |
|---|---|
| **정가 의존을 제거** — 진짜 예측 문제 | 사용자는 할인율보다 가격을 알고 싶어함 |
| 범위가 좁아 왜도가 작음 | 정가가 없으면 가격으로 못 바꿈 |
| 무료 게임을 자연스럽게 제외 | 0% 할인(세일 안 함)이 많으면 편향 |

**⚠ 함정 — 할인율은 이산적입니다**

```
스팀 할인율: 10%, 20%, 25%, 33%, 40%, 50%, 60%, 66%, 75%, 80%, 90%
→ 연속값이 아니라 특정 값에 몰림
→ 회귀보다 순서형 분류가 나을 수도 있음
```

### C. 2단계 (Hurdle Model)

```
1단계: 이 게임이 세일에 포함되는가? (이진 분류)
2단계: 포함된다면 할인율은? (회귀)
```

| 장점 | 단점 |
|---|---|
| **0% 할인 문제를 깔끔히 분리** | 모델이 2개 → 복잡 |
| 각 단계의 지표가 명확 | 5일 안에 완성하기 부담 |

> **권장** — **B(할인율)를 기본으로 하되, 할인가로 환산해서 함께 보고**하는 것이 균형이 좋습니다.
> **다만 팀이 A를 골라도 됩니다.** 근거만 명확하면 됩니다.

### 결정을 위한 토론 질문

```
① 이 예측을 누가 어떻게 쓰는가?
     · 게이머: "지금 살까 기다릴까" → 할인가
     · 개발사: "얼마나 할인해야 하나" → 할인율

② 정가 없이도 예측할 수 있어야 하는가?
     · 예 → 할인가 (정가를 특성으로만)
     · 아니오 → 할인율

③ 무료 게임을 포함하는가?
     · 포함 → 0원 처리 방침 필요 (Day 111)
     · 제외 → 문제 정의서에 명시

④ 세일에 포함되지 않은 게임(할인율 0%)을 포함하는가?
     · 포함 → 0이 많으면 2단계 모델 검토
     · 제외 → "세일 중인 게임 중에서" 로 범위 축소
```

### 예측 시점 정의 — 누수 방지의 출발점

```
"어느 시점에 서서 무엇을 예측하는가?"
```

| 시점 | 쓸 수 있는 특성 | 쓸 수 없는 특성 |
|---|---|---|
| **세일 시작 직전** | 정가·장르·평점·리뷰수·출시일·과거 세일 이력 | 이번 세일 할인율, 역대 최저가(갱신 후) |
| 게임 출시 시점 | 정가·장르·개발사 | 평점·리뷰수(아직 없음) |
| 임의 시점 | — | **정의가 없으면 누수 확정** |

**권장 정의**

```
"2024년 겨울 세일 시작 직전 시점에 서서,
 그 세일에서의 할인율을 예측한다"

→ 특성은 세일 시작 전에 확정된 값만 사용
```

## 3부 · 성공 기준 — 시작 시점에 숫자로

### [Day 120](day-120.md)의 목표 정의서를 그대로 씁니다

### 이 프로젝트의 베이스라인 3종

```
① 평균 예측       : 항상 평균 할인율 (예: 32%)
② 중앙값 예측     : 항상 중앙값 할인율
③ ★ 규칙 기반    : "출시 1년 이상이면 50%, 미만이면 20%"
```

**③이 중요합니다.**

```
사람이 손으로 만든 규칙보다 나아야 모델을 쓸 이유가 있습니다.
"머신러닝은 규칙을 데이터에서 찾는 것" (Day 076)
→ 사람 규칙을 못 이기면 실패입니다
```

### 목표치를 정하는 법

```
1. 예비 데이터 100~200건으로 베이스라인 성능 측정
2. 목표 = 베이스라인 대비 25~40% 개선  (현실적 범위)
3. 그 값을 문제 정의서에 기록하고 커밋
```

> ⚠️ **"최대한 좋게"는 목표가 아닙니다.**
> **끝을 정하지 않으면 프로젝트가 끝나지 않습니다.**

### 성공 기준 3중 설계 ([Day 101](../03-ml/day-101.md) 방식)

| 등급 | 기준 | 의미 |
|---|---|---|
| **최소 합격** | 베이스라인 대비 20% 개선 | 이것도 못 넘으면 실패 |
| **목표** | 베이스라인 대비 35% 개선 | 현실적 목표 |
| **도전** | 베이스라인 대비 50% 개선 | 잘 되면 |

**그리고 "실패 조건"도 정합니다.**

```
· 규칙 기반 베이스라인을 못 이기면 → 모델 무용
· 최악 구간 오차율 50% 초과 → 실용 불가
· 데이터 500행 미만 → 문제 재정의
```

### ① 공개 데이터셋 (권장 출발점)

```
Kaggle "Steam Games Dataset" 계열
- 게임 메타데이터 수만 건
- 가격·장르·태그·평점 포함
- 라이선스 확인 필수
```

**장점** — 오늘 안에 모델링을 시작할 수 있습니다.
**단점** — 할인 이력이 없는 경우가 많습니다.

### ② 스팀 공식 API

```
https://store.steampowered.com/api/appdetails?appids={id}&cc=kr&l=koreana
```

**응답에 포함되는 것**

```json
{
  "12345": {
    "success": true,
    "data": {
      "name": "게임명",
      "genres": [...],
      "categories": [...],
      "release_date": {"date": "2023-05-12"},
      "price_overview": {
        "initial": 39900,        ← 정가
        "final": 19950,          ← 현재가
        "discount_percent": 50   ← ★ 현재 할인율 (타깃!)
      },
      "developers": [...], "publishers": [...],
      "platforms": {"windows": true, "mac": false, "linux": false},
      "supported_languages": "..."
    }
  }
}
```

> ⚠️ **`discount_percent` 가 타깃입니다.**
> **이것을 특성으로 쓰면 안 됩니다.**

**요청 제한**

```
비공식 제한: 약 200 요청 / 5분
→ 1초에 1~2회, 실패 시 재시도
→ 5,000개 수집에 약 1시간
```

| **SteamSpy** | 소유자 수 추정·플레이 시간 |

### Step 3. 데이터 수집 — 스팀 API

```python
import json
import time
from pathlib import Path

import numpy as np
import pandas as pd
import requests

ROOT = Path("steam_project")
RAW = ROOT / "data" / "raw"

STEAM_APPDETAILS = "https://store.steampowered.com/api/appdetails"
HEADERS = {"User-Agent": "MBC-Academy-Student-Project/1.0 (educational)"}


def fetch_app(app_id, cc="kr", lang="koreana", timeout=10):
    """스팀 앱 상세 정보 1건 — 실패 시 None"""
    try:
        r = requests.get(STEAM_APPDETAILS,
                         params={"appids": app_id, "cc": cc, "l": lang},
                         headers=HEADERS, timeout=timeout)
        if r.status_code != 200:
            return None
        payload = r.json().get(str(app_id), {})
        return payload.get("data") if payload.get("success") else None
    except Exception:
        return None


def parse_app(app_id, d):
    """API 응답 → 평평한 dict. ★ 누수 특성은 애초에 담지 않음"""
    if not d or d.get("type") != "game":
        return None

    price = d.get("price_overview") or {}
    if not price:                      # 무료 게임 또는 가격 정보 없음
        return None

    rel = (d.get("release_date") or {}).get("date", "")
    plat = d.get("platforms") or {}
    langs = d.get("supported_languages", "") or ""

    return {
        "app_id": app_id,
        "name": d.get("name", ""),
        # ── 특성 ──
        "initial_price": price.get("initial", 0) / 100,     # 원 단위
        "genres": ",".join(g["description"] for g in (d.get("genres") or [])),
        "categories": ",".join(c["description"] for c in (d.get("categories") or [])),
        "release_date": rel,
        "developer": ",".join(d.get("developers") or []),
        "publisher": ",".join(d.get("publishers") or []),
        "win": int(bool(plat.get("windows"))),
        "mac": int(bool(plat.get("mac"))),
        "linux": int(bool(plat.get("linux"))),
        "korean_support": int("Korean" in langs or "한국어" in langs),
        "n_languages": langs.count(",") + 1 if langs else 0,
        "dlc_count": len(d.get("dlc") or []),
        "achievements": (d.get("achievements") or {}).get("total", 0),

        "discount_percent": price.get("discount_percent", 0),
        # ★ final_price·historical_low 는 수집하지 않음 (누수)

def collect(app_ids, sleep=1.2, max_fail=50, log_every=50):
    """수집 루프 — 중간 저장으로 중단에 대비"""
    rows, fails, skipped = [], 0, 0
    t0 = time.perf_counter()

    for i, aid in enumerate(app_ids, 1):
        d = fetch_app(aid)
        if d is None:
            fails += 1
        else:
            parsed = parse_app(aid, d)
            if parsed:
                rows.append(parsed)
            else:
                skipped += 1

        if i % log_every == 0:
            el = time.perf_counter() - t0
            print(f"  {i}/{len(app_ids)}  수집 {len(rows)}  "
                  f"스킵 {skipped}  실패 {fails}  "
                  f"{el:.0f}초  (남은 예상 {el/i*(len(app_ids)-i)/60:.0f}분)")
            # ★ 중간 저장
            pd.DataFrame(rows).to_csv(RAW / "_partial.csv", index=False,
                                      encoding="utf-8-sig")

        if fails > max_fail:
            print(f"  ★ 실패 {fails}회 초과. 중단합니다.")
            break

        time.sleep(sleep)

    return pd.DataFrame(rows)
```

```python
def build_column_definition(df, target, notes=None):
    """실제 데이터에서 컬럼 정의서 자동 생성 + 수동 항목"""
    notes = notes or {}
    rows = []
    for c in df.columns:
        s = df[c]
        rows.append({
            "컬럼": c,
            "자료형": str(s.dtype),
            "고유값": int(s.nunique()),
            "결측(%)": round(float(s.isna().mean() * 100), 2),
            "예시": str(s.dropna().iloc[0])[:28] if s.notna().any() else "",
            "최소": (round(float(s.min()), 2)
                   if pd.api.types.is_numeric_dtype(s) else ""),
            "최대": (round(float(s.max()), 2)
                   if pd.api.types.is_numeric_dtype(s) else ""),
            "역할": ("★ 타깃" if c == target else notes.get(c, {}).get("역할", "특성")),
            "예측시점가용": notes.get(c, {}).get("가용", "✓"),
            "설명": notes.get(c, {}).get("설명", ""),
            "출처": notes.get(c, {}).get("출처", "Steam API"),
            "비고": notes.get(c, {}).get("비고", ""),
        })
    return pd.DataFrame(rows)
```

### 데이터부터 모으기

```
"일단 많이 모으자" → 3일 소요 → "필요한 열이 없네"
```

**특성 목록을 먼저 만들고, 그것만 수집하세요.**

### 타깃을 정하지 않고 수집

```
할인가·할인율·최저가를 전부 수집
→ 나중에 무엇이 타깃인지 헷갈림
→ 누수가 들어감
```

**해결** — 오늘 결정하고 문서에 남기세요.

### 누수 특성을 "혹시 몰라서" 수집

```
"역대 최저가도 일단 받아 두자"
→ 나중에 특성 목록에 슬쩍 들어감
→ R² 0.97 → 발표에서 지적당함
```

**해결** — **수집 자체를 하지 마세요.** 있으면 반드시 씁니다.

### 원본을 덮어씀

```python
df = pd.read_csv("raw.csv")

```

**해결** — 원본은 읽기 전용. 가공 결과는 `data/processed/` 에.

### 예측 시점을 정하지 않음

```
"할인율을 예측한다"만 정하고 끝
→ 어느 시점의 정보를 쓸 수 있는지 모름
→ Day 128에서 누수 발견 → 처음부터 다시
```

### 성공 기준을 "최대한 좋게"로

```
목표가 없으면 프로젝트가 끝나지 않습니다.
Day 130에 "아직 더 할 수 있을 것 같은데..."로 시간을 씁니다.
```

### 베이스라인을 평균 예측만

```
평균 예측 MAE 14.2 → 모델 MAE 9.8 → "31% 개선!"

그런데 "출시 1년 이상이면 50%" 규칙의 MAE가 10.1이라면?
→ 모델의 개선은 3%뿐
```

**규칙 기반 베이스라인을 반드시 포함하세요.**

### 라이선스·약관을 확인 안 함

```
크롤링으로 수집 → 발표 → "이 데이터 어디서 얻었나요?"
→ 약관 위반이면 프로젝트 자체가 문제
```

**해결** — 소스와 라이선스를 매니페스트에 기록하세요.

| 타깃 선택 | **할인가 vs 할인율 vs 2단계.** 근거를 문서에 |
| 할인가의 함정 | **정가만으로 R² 0.85** → 모델의 기여가 불명 |
| 할인율의 특징 | 범위 좁음 · **이산적** (10/20/25/30...) |
| **예측 시점** | **"어느 시점에 서서 무엇을 예측하는가"** — 누수 방지의 출발 |
| 특성 목록 | **예측 시점 가용성**을 열로 판정 |
| 누수 특성 | **수집 자체를 하지 않기** |
| 성공 기준 | 최소 합격 / 목표 / 도전 **3단계 + 실패 조건** |
| **베이스라인 3종** | 평균 · 중앙값 · **규칙 기반** |
| 규칙 기반의 의미 | **사람 규칙을 못 이기면 모델을 쓸 이유가 없음** |
| 데이터 소스 | 공개셋 → 공식 API → 서드파티 → 크롤링 |
| 수집 규칙 | 간격 1초+ · 중간 저장 · 실패 제한 · 약관 확인 |
| 원본 백업 | **읽기 전용.** 해시 기록. `.gitignore` |
| 목표 규모 | **2,000행 이상 권장** (검증셋 500건 확보) |
| 컬럼 정의서 | 자료형·결측·고유값·**예측시점가용**·설명·출처 |
| 산출물 커밋 | 문서는 커밋, 데이터는 제외 (매니페스트만) |
