## ② 왜 필요한가

### 어제 우선순위를 정했습니다. 이제 자동화합니다

[Day 123](day-123.md)에서 도출한 것:

```
1순위 lr        (122.6%)
2순위 units     ( 26.6%)
3순위 dropout   ( 18.5%)
4순위 optimizer ( 14.5%)
```

**그리고 단계 탐색으로 31회 실험을 했습니다.**

**단계 탐색의 한계**

```
lr을 먼저 고정 → 그 lr에서 최적 units를 찾음
→ 다른 lr에서는 다른 units가 최적일 수 있음 (상호작용)
→ 지역 최적에 갇힘
```

**자동 탐색은 조합을 함께 봅니다.**

### 수동 탐색은 어디까지 가능한가

```
탐색 대상 3개 × 각 5수준 = 125조합
사람이 손으로 돌리기: 하루 종일
```

```
탐색 대상 5개 × 각 5수준 = 3,125조합
사람이 손으로: 불가능
```

**그리고 사람은 실수합니다.**

| 사람의 실수 | 자동 탐색 |
|---|---|
| 조합을 빠뜨림 | 체계적으로 전부 |
| 기록을 놓침 | 자동 기록 |
| 중간에 지쳐서 대충 | 끝까지 |
| 결과를 보고 편향된 선택 | 사전 정의된 기준 |

### 그런데 자동 탐색도 예산이 필요합니다

```
[Day 122]에서 계산한 것:

100조합 × 5-Fold × seed3 = 711분
```

**"자동이니까 다 돌리자"가 안 됩니다.**

**오늘 배우는 것**

```
① 어떤 탐색 방법이 같은 예산에서 더 좋은 결과를 내는가
② 예산을 어떻게 관리하는가
③ 중간 결과로 나쁜 조합을 일찍 버리는 방법 (Hyperband)
```

### 랜덤 서치가 그리드보다 낫다는 것이 오늘의 핵심

```
직관: "전부 다 보는 그리드가 낫지 않나?"
사실: 같은 예산이면 랜덤이 대개 더 좋습니다
```

**오늘 그 이유를 실험으로 확인합니다.**

## ③ 개념 설명

### ① 그리드 서치 (Grid Search)

```python
from sklearn.model_selection import GridSearchCV

param_grid = {
    "model__learning_rate": [0.01, 0.05, 0.1, 0.3],
    "model__max_leaf_nodes": [15, 31, 63],
    "model__min_samples_leaf": [5, 20, 50],
}
gs = GridSearchCV(pipe, param_grid, cv=5, scoring="neg_mean_absolute_error", n_jobs=-1)
```

**모든 조합을 전부 시도합니다.** 4 × 3 × 3 = 36조합.

| 장점 | 단점 |
|---|---|
| 재현 가능 (순서가 정해짐) | **조합 수가 지수적으로 폭발** |
| 격자 안의 최적을 보장 | **중요한 파라미터의 수준이 적어짐** |
| 이해하기 쉬움 | 무의미한 파라미터에도 같은 노력 |

**조합 폭발**

```
3개 파라미터 × 5수준 =    125
5개 파라미터 × 5수준 =  3,125
7개 파라미터 × 5수준 = 78,125
```

### ② 랜덤 서치 (Random Search)

```python
from sklearn.model_selection import RandomizedSearchCV
from scipy.stats import loguniform, uniform, randint

param_dist = {
    "model__learning_rate": loguniform(1e-3, 3e-1),      # ★ 연속 분포
    "model__max_leaf_nodes": randint(10, 128),
    "model__min_samples_leaf": randint(1, 60),
}
rs = RandomizedSearchCV(pipe, param_dist, n_iter=50, cv=5,
                        scoring="neg_mean_absolute_error",
                        random_state=42, n_jobs=-1)
```

**분포에서 무작위로 `n_iter` 개를 뽑습니다.**

| 장점 | 단점 |
|---|---|
| **예산을 직접 지정** (`n_iter`) | 최적을 보장하지 않음 |
| **중요한 파라미터를 많이 훑음** | 재현에 seed 필요 |
| 연속 분포 사용 가능 | 운이 나쁘면 좋은 영역을 놓침 |
| 파라미터를 늘려도 비용이 안 늘어남 | |

### ★ 왜 랜덤이 그리드보다 효율적인가

**핵심 — 하이퍼파라미터의 중요도가 다르기 때문입니다.**

```
[그리드 서치] 3×3 = 9회
  lr:      3개 값만 시도
  dropout: 3개 값만 시도

  중요한 lr을 3번밖에 못 봄

[랜덤 서치] 9회
  lr:      9개 서로 다른 값
  dropout: 9개 서로 다른 값

  중요한 lr을 9번 봄 → 최적 근처를 만날 확률 3배
```

**그림으로**

```
     그리드 3×3                    랜덤 9개
 dropout                       dropout
   │ ●   ●   ●                   │  ●        ●
   │                             │      ●
   │ ●   ●   ●                   │ ●         ●
   │                             │    ●   ●
   │ ●   ●   ●                   │        ●    ●
   └─────────── lr               └─────────── lr
   lr 값 3종                      lr 값 9종
```

**"중요한 축의 해상도"가 3배입니다.**

> **Bergstra & Bengio (2012)** 의 유명한 결과입니다.
> **"대부분의 하이퍼파라미터는 성능에 거의 영향이 없다"** 는 관찰에 기반합니다.
> [Day 123](day-123.md)에서 우리도 확인했습니다 — 10개 중 3개는 노이즈 수준이었습니다.

### ③ 베이지안 최적화 (Bayesian Optimization)

```
① 지금까지의 결과로 "성능 예측 모델"을 만든다 (대개 가우시안 프로세스)
② 그 모델이 "가장 유망한 다음 조합"을 제안한다
③ 실제로 평가하고 ①로 돌아간다
```

| 장점 | 단점 |
|---|---|
| **적은 시도로 좋은 결과** | 순차 실행 (병렬화가 어려움) |
| 이전 결과를 활용 | 초기 몇 회는 랜덤과 같음 |
| | 구현이 복잡 |

**언제 쓰나**

```
평가 1회가 매우 비쌀 때 (수십 분~시간)
예산이 20~100회 정도일 때

평가가 싸면 → 랜덤 서치가 더 실용적 (병렬화 가능)
```

### ④ Hyperband / Successive Halving

**핵심 아이디어 — 나쁜 조합을 일찍 버립니다.**

```
1라운드: 81개 조합을 각 10에폭 → 상위 27개만 남김
2라운드: 27개 조합을 각 30에폭 → 상위 9개만 남김
3라운드:  9개 조합을 각 90에폭 → 상위 3개만 남김
4라운드:  3개 조합을 각 270에폭 → 최종 1개
```

**전부 270에폭 돌리면 81 × 270 = 21,870에폭**
**Hyperband는 약 2,600에폭 (8배 절약)**

```python
from sklearn.experimental import enable_halving_search_cv     # noqa
from sklearn.model_selection import HalvingRandomSearchCV

hs = HalvingRandomSearchCV(pipe, param_dist, factor=3,
                           resource="model__max_iter",
                           max_resources=1000, cv=5,
                           scoring="neg_mean_absolute_error",
                           random_state=42, n_jobs=-1)
```

| 파라미터 | 의미 |
|---|---|
| `factor` | 라운드마다 몇 분의 1로 줄일지 (3이면 1/3) |
| `resource` | 무엇을 늘려갈지 (에폭·트리 수·샘플 수) |
| `max_resources` | 최종 라운드의 자원량 |

> ⚠️ **"초반에 좋은 것이 끝까지 좋다"는 가정에 의존합니다.**
> 학습률이 큰 조합은 초반에 빨리 내려가지만 나중에 나빠질 수 있습니다.
> **`resource` 를 너무 작게 시작하면 오판할 수 있습니다.**

```python
import keras_tuner as kt

def build_model(hp):
    lr = hp.Float("lr", 1e-5, 1e-1, sampling="log")          # ★ 로그 샘플링
    n_layers = hp.Int("n_layers", 1, 4)
    dropout = hp.Float("dropout", 0.0, 0.5, step=0.1)

    model = keras.Sequential([layers.Input(shape=(n_features,))])
    for i in range(n_layers):
        units = hp.Int(f"units_{i}", 16, 256, step=16)
        model.add(layers.Dense(units, activation="relu"))
        if dropout > 0:
            model.add(layers.Dropout(dropout))
    model.add(layers.Dense(1))
    model.compile(optimizer=keras.optimizers.Adam(lr), loss="mse", metrics=["mae"])
    return model
```

**`hp` 객체의 메서드**

| 메서드 | 용도 |
|---|---|
| `hp.Float(name, min, max, sampling="log")` | 연속값. **로그 샘플링 가능** |
| `hp.Int(name, min, max, step)` | 정수 |
| `hp.Choice(name, [..])` | 범주 |
| `hp.Boolean(name)` | 참/거짓 |
| `hp.Fixed(name, value)` | 고정 |

### 탐색 예산 관리

**예산을 정하는 세 가지 방법**

| 방법 | 코드 | 특징 |
|---|---|---|
| **조합 수** | `n_iter=50` | 예측 가능 |
| **시간** | 콜백으로 중단 | 실무적 |
| **자원(에폭)** | Hyperband | 효율적 |

**시간 예산 콜백**

```python
import time

class TimeBudget(keras.callbacks.Callback):
    def __init__(self, seconds):
        self.seconds = seconds
        self.start = None
    def on_train_begin(self, logs=None):
        self.start = time.time()
    def on_epoch_end(self, epoch, logs=None):
        if time.time() - self.start > self.seconds:
            self.model.stop_training = True
```

**예산 배분 권장**

```
전체 예산 100%
├── 1단계 넓은 탐색 (랜덤, 짧은 에폭)     50%
├── 2단계 좁은 탐색 (상위 영역 집중)      30%
└── 3단계 최종 후보 교차검증              20%
```

### Step 0. 준비

```python
import time
from pathlib import Path

import numpy as np
import pandas as pd
import matplotlib.pyplot as plt
import tensorflow as tf
from tensorflow import keras
from tensorflow.keras import layers
from sklearn.datasets import fetch_california_housing
from sklearn.metrics import mean_absolute_error
from sklearn.model_selection import train_test_split
from sklearn.preprocessing import StandardScaler

SEED = 42
np.random.seed(SEED)
tf.random.set_seed(SEED)
plt.rcParams["figure.figsize"] = (10, 5)
plt.rcParams["axes.grid"] = True
plt.rcParams["grid.alpha"] = 0.3

ROOT = Path("dl_course/day124")
ROOT.mkdir(parents=True, exist_ok=True)

raw = fetch_california_housing(as_frame=True)
df = raw.frame.copy()
TARGET = "MedHouseVal"
X_all, y_all = df.drop(columns=[TARGET]), df[TARGET]

y_bins = pd.qcut(y_all, q=10, labels=False, duplicates="drop")
X_dev, X_test, y_dev, y_test, b_dev, _ = train_test_split(
    X_all, y_all, y_bins, test_size=0.2, random_state=SEED, stratify=y_bins)
X_train, X_val, y_train, y_val = train_test_split(
    X_dev, y_dev, test_size=0.25, random_state=SEED, stratify=b_dev)

sc = StandardScaler().fit(X_train)
Xtr, Xva = sc.transform(X_train), sc.transform(X_val)
ytr_log, yva_log = np.log1p(y_train), np.log1p(y_val)

N_FEATURES = Xtr.shape[1]
SEED_REL = 3.42        # Day 123에서 측정한 seed 상대 변동폭 (%)


def run_cfg(cfg, epochs=120, seed=SEED, verbose=0):
    """설정 하나를 학습하고 val MAE 반환"""
    tf.random.set_seed(seed)
    m = keras.Sequential([layers.Input(shape=(N_FEATURES,))])
    for u in cfg["units"]:
        m.add(layers.Dense(u, activation=cfg.get("activation", "relu")))
        if cfg.get("dropout", 0) > 0:
            m.add(layers.Dropout(cfg["dropout"]))
    m.add(layers.Dense(1))
    opt = {"adam": keras.optimizers.Adam, "adamw": keras.optimizers.AdamW,
           "rmsprop": keras.optimizers.RMSprop}[cfg.get("optimizer", "adam")]
    m.compile(optimizer=opt(cfg["lr"]), loss="mse", metrics=["mae"])
    es = keras.callbacks.EarlyStopping(monitor="val_loss", patience=20,
                                       restore_best_weights=True)
    t0 = time.perf_counter()
    m.fit(Xtr, ytr_log, validation_data=(Xva, yva_log),
          epochs=epochs, batch_size=cfg.get("batch_size", 64),
          callbacks=[es], verbose=verbose)
    elapsed = time.perf_counter() - t0
    pred = np.expm1(m.predict(Xva, verbose=0).ravel())
    mae = mean_absolute_error(y_val, pred)
    return (float(mae) if np.isfinite(mae) else np.inf), elapsed


BASE = dict(lr=1e-3, units=(128, 64, 32), dropout=0.2,
            optimizer="adam", batch_size=64)
base_mae, base_time = run_cfg(BASE)

print("=" * 76)
print("기준선 (Day 123 단계 탐색 결과)")
print("=" * 76)
print(f"  설정   : {BASE}")
print(f"  val MAE: {base_mae:.4f}")
print(f"  시간   : {base_time:.1f}초")
print(f"  seed 상대 변동폭: {SEED_REL:.2f}%  "
      f"(= MAE {base_mae * SEED_REL / 100:.4f})")
print("=" * 76)
print("\n★ 오늘의 목표: 자동 탐색으로 이 값을 유의미하게 개선할 수 있는가")
```

### Step 1. ★ 그리드 vs 랜덤 — 같은 예산에서

```python
import numpy as np
import pandas as pd
import matplotlib.pyplot as plt
from itertools import product

SEED = 42
BUDGET = 27          # 두 방법에 같은 예산
```

### Step 2. 파라미터가 늘어날 때의 효율 차이

```python
import numpy as np
import pandas as pd
import matplotlib.pyplot as plt
from itertools import product

SEED = 42

print("=" * 92)
print("탐색 대상 개수에 따른 그리드 vs 랜덤 — 시뮬레이션")
print("=" * 92)
print("(실제 학습 대신 Day 123의 영향도를 반영한 대리 함수로 빠르게 비교)")


def surrogate(cfg):
    """Day 123의 영향도를 반영한 대리 성능 함수
    lr이 압도적, 나머지는 순차적으로 영향이 작음"""
    loss = 0.30
    loss += 1.2 * (np.log10(cfg["lr"]) + 3.2) ** 2            # lr: 최적 ~6e-4
    loss += 0.06 * (cfg["units_scale"] - 0.6) ** 2 * 4        # units
    loss += 0.04 * (cfg["dropout"] - 0.15) ** 2 * 16          # dropout
    loss += 0.02 * (cfg["opt_idx"] != 0) * 0.3                # optimizer
    loss += 0.015 * (np.log2(cfg["batch"]) - 6) ** 2 * 0.1    # batch
    loss += 0.01 * abs(cfg["act_idx"]) * 0.2                  # activation
    loss += 0.005 * abs(cfg["init_idx"]) * 0.1                # init
    return loss


SPACE = {
    "lr": ("log", -5, -1),
    "units_scale": ("lin", 0.1, 1.0),
    "dropout": ("lin", 0.0, 0.5),
    "opt_idx": ("int", 0, 2),
    "batch": ("log2", 4, 9),
    "act_idx": ("int", 0, 3),
    "init_idx": ("int", 0, 2),
}
NAMES = list(SPACE)


def grid_points(names, levels):
    axes = []
    for n in names:
        kind, lo, hi = SPACE[n]
        if kind == "log":
            axes.append(np.logspace(lo, hi, levels))
        elif kind == "log2":
            axes.append(2 ** np.linspace(lo, hi, levels).round().astype(int))
        elif kind == "int":
            axes.append(np.linspace(lo, hi, min(levels, hi - lo + 1)).round().astype(int))
        else:
            axes.append(np.linspace(lo, hi, levels))
    return [dict(zip(names, v)) for v in product(*axes)]


def random_points(names, n, rng):
    out = []
    for _ in range(n):
        c = {}
        for nme in names:
            kind, lo, hi = SPACE[nme]
            if kind == "log":
                c[nme] = float(10 ** rng.uniform(lo, hi))
            elif kind == "log2":
                c[nme] = int(2 ** rng.integers(lo, hi + 1))
            elif kind == "int":
                c[nme] = int(rng.integers(lo, hi + 1))
            else:
                c[nme] = float(rng.uniform(lo, hi))
        out.append(c)
    return out


DEFAULT = {"lr": 1e-3, "units_scale": 0.6, "dropout": 0.15,
           "opt_idx": 0, "batch": 64, "act_idx": 0, "init_idx": 0}

rows = []
for n_params in [2, 3, 4, 5, 7]:
    names = NAMES[:n_params]
    levels = 3
    grid = grid_points(names, levels)
    budget = len(grid)
    if budget > 3000:
        budget = 3000
        grid = grid[:3000]

    grid_scores = [surrogate({**DEFAULT, **c}) for c in grid]

    rng = np.random.default_rng(SEED)
    rand = random_points(names, budget, rng)
    rand_scores = [surrogate({**DEFAULT, **c}) for c in rand]

    rows.append({
        "파라미터 수": n_params,
        "그리드 조합": len(grid),
        "그리드 최선": round(float(np.min(grid_scores)), 4),
        "랜덤 최선": round(float(np.min(rand_scores)), 4),
        "랜덤 우위(%)": round(float((np.min(grid_scores) - np.min(rand_scores))
                                / np.min(grid_scores) * 100), 2),
        "lr 고유값(그리드)": levels,
        "lr 고유값(랜덤)": budget,
    })

sim = pd.DataFrame(rows)
print(sim.to_string(index=False))
print("=" * 92)
print("\n★ 파라미터가 늘어날수록 랜덤의 우위가 커집니다.")
print("  그리드는 각 축의 해상도가 3으로 고정되지만,")
print("  랜덤은 조합 수만큼 해상도가 늘어납니다.")

print("=" * 84)

fig.savefig(ROOT / "dimensionality.png", dpi=110, bbox_inches="tight")
```

```python
class TimeBudget(keras.callbacks.Callback):
    """시간 예산을 넘으면 학습 중단"""
    def __init__(self, seconds):
        super().__init__()
        self.seconds = seconds
    def on_train_begin(self, logs=None):
        self.start = time.time()
    def on_epoch_end(self, epoch, logs=None):
        if time.time() - self.start > self.seconds:
            self.model.stop_training = True

                       for _ in range(int(rng.integers(1, 5)))),
```

**⑤ 유망 영역 분석 — 이것이 탐색의 진짜 결과물 (배점 20%)**

```python
def analyze_promising_region(best_hps, n=10):
    """상위 N개 조합에서 유망 영역 추출"""
    df = pd.DataFrame([h.values for h in best_hps[:n]])
    report = {}
    for col in df.columns:
        if pd.api.types.is_numeric_dtype(df[col]):
            report[col] = {
                "min": float(df[col].min()),
                "max": float(df[col].max()),
                "median": float(df[col].median()),
                "범위 축소": f"{df[col].min():.2e} ~ {df[col].max():.2e}",
            }
        else:
            report[col] = df[col].value_counts().to_dict()
    return report
```

```
n_layers  : {3: 5, 2: 3, 4: 2}
            → 3층이 우세

optimizer : {'adam': 6, 'adamw': 4}
            → rmsprop은 상위권에 없음. 제외 가능
=================================================================

[다음 라운드 탐색 공간]
  lr      : loguniform(3e-4, 2e-3)     (1/50 축소)
  dropout : uniform(0.05, 0.25)        (1/2.5 축소)

  optimizer: ['adam', 'adamw']

```

## 오늘의 정리

| 방법 | 예산 지정 | 병렬 | 조기중단 | 권장 상황 |
|---|---|---|---|---|
| **그리드** | 조합 수로 결정 | ✓ | ✗ | 파라미터 **2개 이하**, 이산값 |
| **랜덤** | **직접 지정** | ✓ | ✗ | **파라미터 3개 이상 (기본)** |
| **Hyperband/Halving** | 직접 지정 | ✓ | **✓** | **학습이 느릴 때** |
| **베이지안** | 직접 지정 | △ | ✗ | 평가 1회가 수십 분+ |
| 수동/단계 | — | — | — | 기여도 이해가 목적 |

| 개념 | 핵심 |
|---|---|
| **랜덤 > 그리드 이유** | **중요한 축의 해상도가 높음** (27회에 lr 27종 vs 3종) |
| 차원의 저주 | 예산 100 · 파라미터 7개 → 그리드는 **축당 1수준** |
| 로그 샘플링 | **`sampling="log"` / `loguniform`** — 학습률·규제 |
| Hyperband 원리 | 짧은 자원으로 많이 → 나쁜 것 버림 → 반복 |
| Hyperband 효율 | 전체 에폭의 **18%로 90조합** (5.6배 절약) |
| Hyperband 주의 | **"초반에 좋으면 끝까지 좋다"** 가정. `factor` ≤ 3 |
| KerasTuner | `hp.Float/Int/Choice` · `RandomSearch`/`Hyperband`/`Bayesian` |
| `overwrite=True` | 이전 결과와 섞이지 않게 |
| 예산 배분 | **넓은 탐색 50% → 좁은 탐색 30% → 최종 검증 20%** |
| **상위 N개 분석** | 최적 1개보다 **유망 영역**이 더 유용 |
| 탐색 공간 축소 | 상위 10개의 범위로 다음 라운드 (1/50까지) |
| 로그 타깃 | **원래 공간에서 재평가**해야 비교 가능 |
| 탐색 ≠ 최종 성능 | 165회 탐색 후 검증 점수는 **낙관적** |
| **검증셋으로만** | 테스트셋은 [Day 125](day-125.md)에서 1회 |
| 자동 탐색의 가치 | 성능보다 **사람의 시간** |

**오늘 반드시 기억할 세 가지**
> ① **파라미터가 3개를 넘으면 랜덤 서치를 쓰세요.** 그리드는 축당 해상도가 급감합니다.
> ② **학습률은 반드시 로그 스케일로 샘플링하세요.**
> ③ **최적 1개보다 상위 10개의 "유망 영역"이 더 유용합니다.** 다음 탐색 공간을 좁혀 줍니다.
