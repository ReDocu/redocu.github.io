### 3-4. 기술적 도전 (4분)

**왜 필요한가** — 평가의 핵심.

```
   ★ Day 119에서 쓴 3개 중 2~3개
```

```
   ★ 각 1~1.5분

   ① 문제 (수치)      20초
   ② 원인             20초
   ③ 접근 (왜 그것)   30초
   ④ 결과 (수치)      20초
```

```
   ★ 슬라이드

   왼쪽: 문제 (그래프 또는 스크린샷)
   오른쪽: 결과 (수치 표)
```

```
   ★ 예시 대사

   "후반 층에서 최악 프레임이 38ms까지 튀었습니다.
    Profiler로 보니 파티클 12ms, GC 8ms였습니다.

    파티클을 줄이는 방법은 세 가지를 고려했는데,
    이펙트를 없애면 타격감이 사라지고
    Burst를 줄이면 시각적 손실이 있었습니다.

    그래서 풀의 maxSize로 동시 개수만 제한했습니다.
    상한에 도달하면 가장 오래된 이펙트를 재사용해서
    '안 나오는' 게 아니라 '겹치지 않는' 결과를 얻었습니다.

    최악 프레임이 17ms로 줄었고,
    블라인드 테스트에서 시각적 차이를 구분하지 못했습니다."
```

```
   ★ 이 설명의 강점

   ① 수치가 있다
   ② 대안을 비교했다
   ③ 선택 이유가 명확하다
   ④ 결과를 검증했다
```
