```
학습·검증: cat=파란 배경, dog=초록 배경
→ 검증 정확도 0.98
→ 배경을 바꾼 테스트셋: 0.28
```

**그건 색을 입혀 만든 인공 편향이었습니다.**
이번 주는 **아무도 편향을 넣지 않았는데 저절로 생기는** 경우를 겪습니다.

### 늑대는 눈밭에 있고, 허스키는 거실에 있습니다

이미지를 검색해 보세요.

| 검색어 | 사진에 대체로 함께 나오는 것 |
|---|---|
| wolf | 눈, 숲, 야생, 어두운 하늘, 무리 |
| husky | 거실, 잔디, 목줄, 사람 손, 실내 조명 |

**아무도 의도하지 않았습니다.** 그냥 세상이 그렇게 찍혀 있습니다.

```
늑대 300장 중 눈 배경 240장 (80%)
허스키 300장 중 눈 배경 30장 (10%)

→ "흰 배경 = 늑대"만 배워도 정확도 85%가 나옵니다
→ 동물을 볼 이유가 없습니다
```

> **모델은 게으릅니다.** 쉬운 규칙으로 정답이 맞으면 어려운 규칙을 배우지 않습니다.
> 이것을 **지름길 학습(shortcut learning)** 이라고 합니다.

### 유명한 실험

2016년 LIME 논문(*"Why Should I Trust You?"*)의 실험입니다.

```
① 늑대 사진은 전부 눈 배경, 허스키 사진은 전부 눈 없는 배경으로 데이터를 구성
② 학습 → 테스트 정확도 90%
③ 설명 기법으로 "모델이 본 영역"을 시각화
④ 모델은 동물이 아니라 눈(雪)을 보고 있었다
⑤ 이 결과를 본 대학원생들의 신뢰도가 급락
```

**이 프로젝트는 그 실험을 재현하고, 그다음 그것을 깨는 것까지 합니다.**

### 그래서 오늘 무엇을 하는가

**모델을 만들지 않습니다. 코드도 거의 안 씁니다.**

```
❌ 나쁜 월요일
   "늑대 vs 허스키 하자" → 검색해서 이미지 마구 다운로드
   → 목요일: 정확도 0.94 → 금요일 발표에서 "배경 아닌가요?" → 답 못 함

✅ 좋은 월요일
   "무엇을 분류하나" 확정
       ↓
   "성공은 무엇인가" — 정확도만이 아닌 기준 3개
       ↓
   "그러려면 어떤 데이터가 필요한가" — ★ 배경을 층화해서 수집
       ↓
   "실제로 구해지나" — 오늘 30장 받아 보기
```

> **금요일에 답할 질문을 월요일에 정합니다.**
> 데이터 수집 계획이 곧 편향 대응 계획입니다. 목요일에 고칠 수 없습니다.

## 1부 · 배경 편향 — Clever Hans

### 영리한 한스

```
1900년대 독일. "계산하는 말" 한스.
  "3 + 5는?"  →  발굽을 8번 두드림.  정답률 90%

조사 결과: 한스는 계산을 못 했다.
정답 횟수에 가까워질 때 주인의 표정·자세가 미세하게 바뀌었고,
한스는 그것을 보고 발굽을 멈췄다.

주인이 답을 모르면 정답률 → 6%
```

**한스는 문제를 푼 것이 아니라 문제 밖의 단서를 읽었습니다.**

| | 한스 | 우리 모델 |
|---|---|---|
| 진짜 과제 | 덧셈 | 동물 형태 판별 |
| 실제로 한 것 | 주인의 표정 읽기 | **배경 판별** |
| 겉보기 성능 | 90% | 0.94 |
| 조건이 바뀌면 | 6% | **0.51** |

### 지름길 학습이 생기는 조건

```
① 라벨과 상관관계가 있는 단서가 데이터에 있다   (눈 ↔ 늑대)
② 그 단서가 진짜 특징보다 배우기 쉽다          (색 분포 < 형태)
③ 평가 데이터도 같은 상관관계를 갖고 있다       ← ★ 여기가 핵심
```

**③ 때문에 아무리 평가해도 안 걸립니다.**
학습셋·검증셋·테스트셋을 같은 사진 더미에서 나눴다면 셋 다 눈 배경이 편향돼 있습니다.

> **랜덤 분할로는 절대 발견할 수 없습니다.**
> 그래서 오늘 **배경을 반대로 뒤집은 테스트셋**을 따로 계획합니다.

### 실제 사례

| 분야 | 모델이 실제로 본 것 | 결과 |
|---|---|---|
| **늑대 vs 허스키** | **눈 배경** | 실내 늑대 → 허스키로 오답 |
| 폐렴 X-ray | 병원별 촬영 장비 마커 | 다른 병원에서 성능 붕괴 |
| 피부암 진단 | 의사가 놓은 **자(ruler)** | 자가 없으면 못 맞힘 |
| 코로나 흉부 판독 | 자세·촬영 위치(누워 있으면 중증) | 질병이 아닌 중증도 단서 |
| 말(horse) 인식 | 사진 하단 **저작권 워터마크** | 워터마크만 붙여도 "말" |
| 소 인식 | **초원 배경** | 해변의 소 → 인식 실패 |

**공통점** — 데이터를 모은 방식이 정답과 상관관계를 만들었습니다.

### 우리 주제가 특히 위험한 이유

| 위험 요인 | 늑대 vs 허스키 |
|---|---|
| 형태가 비슷함 | **사람도 헷갈림** → 진짜 특징이 어려움 |
| 촬영 환경이 다름 | 야생 vs 반려 → **배경이 너무 쉬움** |
| 수집 경로가 다름 | 다큐/스톡 vs SNS → **화질·구도까지 다름** |
| 데이터가 적음 | 클래스당 300장 → **지름길에 더 쉽게 빠짐** |

> **"화질이 좋으면 허스키"** 같은 것도 배울 수 있습니다.
> 편향은 배경만이 아닙니다. **수집 경로가 다르면 그 자체가 단서**가 됩니다.

## 2부 · 문제 정의서

### 한 문장 정의

```
[입력]을 받아 [클래스 목록] 중 하나로 분류한다.
단, [조건]에서도 동작해야 한다.
```

**작성 예시**

```
한 장의 동물 사진을 입력받아 '늑대'와 '허스키' 중 하나로 분류한다.
단, 배경(눈/실내/풀밭)이 학습 데이터와 달라도 정확도가 유지되어야 한다.
```

**뒷문장이 이 프로젝트의 전부입니다.** 그것이 없으면 그냥 이진 분류 숙제입니다.

### 클래스 경계 규칙 — 오늘 반드시 정합니다

**"이건 어느 쪽이지?"를 목요일에 만나면 늦습니다.**

| 애매한 사진 | 규칙(예시) | 이유 |
|---|---|---|
| 알래스칸 말라뮤트 | **제외** | 허스키와 구분이 또 다른 문제 |
| 늑대개(하이브리드) | **제외** | 라벨이 원리적으로 모호 |
| 사모예드·아키타 | 제외 | 클래스에 없음 |
| 새끼(퍼피) | **포함** | 실제 사용 상황에 존재 |
| 2마리 이상 | 같은 종만 포함 | 섞이면 라벨 불가 |
| 동물이 화면의 20% 미만 | 제외 | 판별 불가 |
| 그림·일러스트·박제 | **제외** | 사진 분류 문제로 한정 |
| 흑백 사진 | 포함 | 색 의존을 줄이는 데 오히려 도움 |

> **규칙을 정하는 것보다 "적어 두는 것"이 중요합니다.**
> 2인 팀이면 두 사람의 기준이 반드시 다릅니다. ([4부](#4부--평가-설계와-라벨링-규약))

### ★ 성공 기준 3중 설계

**정확도 하나로 성공을 정의하면 배경을 배운 모델이 1등입니다.**

| # | 기준 | 측정 방법 | 목표 |
|---|---|---|---|
| **A** | 기본 성능 | 주 테스트셋 정확도 | **≥ 0.85** |
| **B** | **편향 견고성** | **배경 교차 테스트셋** 정확도 | **≥ 0.75** (A와 격차 0.10 이내) |
| **C** | **근거 타당성** | Grad-CAM **가장자리 집중도** | **< 0.35** |

```
A만 통과  →  실패. 배경을 배운 모델일 수 있음
A + B     →  합격
A + B + C →  근거까지 확인. 목표
```

> **B가 이 프로젝트의 채점 기준입니다.**
> 정확도 0.98 / 교차 0.55 보다 **정확도 0.88 / 교차 0.84** 가 더 좋은 결과입니다.

### 성공 기준을 숫자로 정하는 근거

**"몇 %면 성공인가"는 근거가 있어야 합니다.**

| 기준선 | 값 | 의미 |
|---|---|---|
| 무작위 추측 | 0.50 | 최저선 |
| 최빈 클래스 | 0.50 | 균형 데이터이므로 동일 |
| **사람 정확도** | **0.85 내외** | 비전문가가 헷갈리는 문제 |
| 대량 데이터 모델 | 0.95+ | 수만 장 있을 때 |

```
클래스당 300장 · 전이학습 사용 → 0.85~0.92 예상
∴ 목표 0.85는 "사람 수준"이라는 근거가 있는 숫자
```

## 3부 · 데이터 수집 계획

### 어디서 구하는가 — 우선순위

| 순위 | 출처 | 라이선스 | 비고 |
|---|---|---|---|
| **1** | **공개 데이터셋** (Kaggle, Open Images, iNaturalist) | 대체로 명시됨 | **가장 안전. 먼저 찾으세요** |
| 2 | 무료 스톡 (Unsplash, Pexels, Pixabay) | 대체로 자유 이용 | 화질이 좋아 **경로 편향 주의** |
| 3 | Wikimedia Commons | CC 계열 (출처 표기) | 야생 사진이 많음 |
| 4 | 직접 촬영 | 본인 소유 | 허스키는 가능, 늑대는 동물원 |
| ⚠️ | 검색엔진 이미지 대량 자동 수집 | **불명** | 아래 주의 참고 |

> ⚠️ **주의**
> - 사이트의 `robots.txt` 와 이용약관을 확인하세요.
> - **자동 수집 시 요청 간격을 두고(1초 이상), 대량 요청을 하지 마세요.**
> - 수집한 이미지는 **수업 과제 범위 안에서만** 사용하고 재배포하지 않습니다.
> - **모든 이미지의 출처 URL과 라이선스를 기록**합니다. 기록 없는 이미지는 쓰지 않습니다.

### ★ 배경 층화 수집 — 이 프로젝트의 핵심 설계

**그냥 300장씩 모으면 편향이 그대로 들어옵니다.**

```
[나쁜 계획]
  wolf 300장, husky 300장

[좋은 계획]  ← 배경을 격자로 나눠서 채운다
              눈 배경    비(非)눈 배경    합계
  wolf         150         150           300
  husky        150         150           300
```

**핵심** — 배경과 클래스의 상관관계를 **0에 가깝게** 만드는 것입니다.

| 배경 태그 | 정의 | 예시 |
|---|---|---|
| `snow` | 화면에 눈·설원이 뚜렷 | 설원의 늑대, 눈밭의 허스키 |
| `forest` | 숲·수풀 | 숲속 늑대, 산책 중 허스키 |
| `indoor` | 실내 | 동물원 실내, 거실 |
| `grass` | 잔디·초원 | 사파리, 공원 |
| `other` | 위에 없음·판단 불가 | 스튜디오, 클로즈업 |

> **"눈밭의 허스키"와 "눈 없는 늑대"를 찾는 것이 오늘 가장 어려운 일입니다.**
> 검색어를 바꿔 보세요 — `husky snow`, `husky winter`, `wolf zoo`, `wolf summer`, `wolf grass`.

### 수량 계획

| 구분 | 클래스당 | 합계 | 용도 |
|---|---|---|---|
| 학습 | 210 | 420 | train |
| 검증 | 45 | 90 | val — 실험 비교용 |
| **주 테스트** | 45 | 90 | test — **1회만 개봉** |
| **배경 교차 테스트** | **30** | **60** | **★ 편향 검증 전용** |
| **합계** | **330** | **660** | |

**배경 교차 테스트셋이란**

```
wolf  30장 → 전부 '눈이 없는' 배경 (실내·풀밭·숲)
husky 30장 → 전부 '눈 배경'

= 학습 데이터의 흔한 상관관계와 정반대
→ 배경을 배운 모델은 여기서 0.5 근처로 무너집니다
```

> **이 60장은 오늘부터 따로 모아 별도 폴더에 두고, [Day 104](day-104.md)까지 열지 않습니다.**

### 수집 대장 — 오늘의 필수 산출물

| 열 | 내용 | 필수 |
|---|---|---|
| `file` | 저장 파일명 | ✔ |
| `class` | wolf / husky | ✔ |
| `background` | snow / forest / indoor / grass / other | ✔ |
| `source` | 사이트명 | ✔ |
| `url` | 원본 주소 | ✔ |
| `license` | CC0 / CC BY / Unsplash / … | ✔ |
| `collected_by` | 수집자 | ✔ |
| `note` | 애매한 점 | |

**출처를 나중에 채우려 하면 절대 못 채웁니다. 받는 즉시 기록하세요.**

## 4부 · 평가 설계와 라벨링 규약

### 어떤 지표를 볼 것인가

| 지표 | 이 프로젝트에서 |
|---|---|
| 정확도 | 기본. 클래스가 균형이므로 유효 |
| **혼동행렬** | **어느 방향으로 틀리는지** — 늑대→허스키가 많은가 |
| 정밀도·재현율 | 클래스별 성능 확인 |
| **배경 교차 정확도** | **★ 주 지표** |
| **정확도 하락폭** | **주 테스트 − 교차 테스트.** 0.10 이하 목표 |
| 가장자리 집중도 | Grad-CAM 기반 편향 지표 ([Day 100](day-100.md)) |

### 테스트셋 개봉 규칙

```
① 테스트셋은 [Day 104](day-104.md)에 단 한 번 사용한다
② 개봉 후에는 어떤 설정도 바꾸지 않는다
③ 모델 선택은 검증셋으로만 한다
```

**왜** — 테스트셋을 보고 튜닝하면 그 순간 테스트셋은 검증셋이 되고, 성능은 실제보다 부풀려집니다.

### 라벨링 규약과 교차검수

**2인 팀이면 두 사람이 같은 100장을 독립적으로 라벨링합니다.**

| 일치율 (Cohen's κ) | 해석 | 조치 |
|---|---|---|
| ≥ 0.90 | 규약이 명확 | 진행 |
| 0.75 ~ 0.90 | 경계가 애매 | **규약 보완 후 재검수** |
| < 0.75 | 규약이 없는 것과 같음 | **클래스 정의부터 다시** |

```
κ = (관측 일치율 − 우연 일치율) / (1 − 우연 일치율)
```

**단순 일치율(%)이 아니라 κ를 쓰는 이유** — 두 명이 아무렇게나 찍어도 50%는 맞기 때문입니다.

> **개인 진행이면?** 하루 간격으로 같은 100장을 두 번 라벨링해 **자기 일치율**을 재세요.
> 자기 자신과도 안 맞으면 규약이 없는 것입니다.

"""
Day 101 Step 2 — 수집 대장 (collection log)
이미지를 저장할 때마다 이 함수를 통해 기록합니다.
"""
import hashlib
from datetime import datetime
from pathlib import Path

import pandas as pd

PROJ = Path("/content/drive/MyDrive/ml_course/project_wolf")
LOG_PATH = PROJ / "docs" / "collection_log.csv"

COLUMNS = ["file", "class", "background", "source", "url",
           "license", "collected_by", "sha8", "note"]
CLASSES = ["wolf", "husky"]
BACKGROUNDS = ["snow", "forest", "indoor", "grass", "other"]


def load_log():
    if LOG_PATH.exists():
        return pd.read_csv(LOG_PATH)
    return pd.DataFrame(columns=COLUMNS)


def file_hash(path, n=8):
    """내용 해시 — 같은 파일을 두 번 받는 것을 막습니다"""
    return hashlib.md5(Path(path).read_bytes()).hexdigest()[:n]


def register(path, cls, background, source, url, license_, by, note=""):
    """이미지 1장을 대장에 등록합니다."""
    path = Path(path)
    assert cls in CLASSES, f"class는 {CLASSES} 중 하나"
    assert background in BACKGROUNDS, f"background는 {BACKGROUNDS} 중 하나"
    assert path.exists(), f"파일이 없습니다: {path}"

    log = load_log()
    h = file_hash(path)

    # ── 중복 검사 ──
    if h in set(log["sha8"]):
        dup = log.loc[log["sha8"] == h, "file"].iloc[0]
        print(f"  ⚠ 내용 중복 — 이미 등록됨: {dup}")
        return log
    if url and url in set(log["url"].astype(str)):
        print(f"  ⚠ URL 중복 — 건너뜁니다")
        return log

    row = {"file": path.name, "class": cls, "background": background,
           "source": source, "url": url, "license": license_,
           "collected_by": by, "sha8": h, "note": note}
    log = pd.concat([log, pd.DataFrame([row])], ignore_index=True)
    log.to_csv(LOG_PATH, index=False)
    return log


def summary(log=None):
    """클래스 × 배경 격자 현황"""
    log = load_log() if log is None else log
    if len(log) == 0:
        print("아직 등록된 이미지가 없습니다")
        return

    grid = pd.crosstab(log["class"], log["background"])
    for b in BACKGROUNDS:
        if b not in grid.columns:
            grid[b] = 0
    grid = grid[BACKGROUNDS]
    grid["합계"] = grid.sum(axis=1)

    # 눈 / 비눈 이분
    snow = log["background"].eq("snow")
    two = pd.crosstab(log["class"], snow.map({True: "눈", False: "비눈"}))
    for c in ["눈", "비눈"]:
        if c not in two.columns:
            two[c] = 0
    two = two[["눈", "비눈"]]

    line = "=" * 74
    print(line)
    print(f"수집 현황 — 총 {len(log)}장   ({datetime.now():%m/%d %H:%M})")
    print(line)
    print("\n[배경 태그별]")
    print(grid.to_string())

    print("\n[눈 배경 비율 — ★ 편향 지표]")
    print(f"  {'클래스':<8}{'눈':>7}{'비눈':>7}{'눈 비율':>10}")
    print("  " + "-" * 34)
    for cls in two.index:
        n_s, n_n = int(two.loc[cls, "눈"]), int(two.loc[cls, "비눈"])
        ratio = n_s / max(n_s + n_n, 1)
        print(f"  {cls:<8}{n_s:>7}{n_n:>7}{ratio:>9.1%}")

    if len(two) == 2:
        gap = abs(two.iloc[0]["눈"] / max(two.iloc[0].sum(), 1) -
                  two.iloc[1]["눈"] / max(two.iloc[1].sum(), 1))
        print(f"\n  클래스 간 눈 비율 격차: {gap:.1%}", end="  ")
        print("✓ 양호" if gap < 0.15 else
              ("🟡 주의" if gap < 0.30 else "🔴 편향 위험 — 부족한 칸을 채우세요"))

    # ── 라이선스 미기록 점검 ──
    missing = log["license"].isna() | log["license"].astype(str).str.strip().eq("")
    if missing.any():
        print(f"\n  🔴 라이선스 미기록 {missing.sum()}장 — 오늘 안에 채우세요")
    print(line)


# ══════════════════════════════════════════
# 사용 예시
# ══════════════════════════════════════════
if __name__ == "__main__":
    RAW = PROJ / "data" / "raw"
    register(RAW / "wolf" / "wolf_0001.jpg", "wolf", "snow",
             "Wikimedia", "https://commons.wikimedia.org/...",
             "CC BY-SA 4.0", "김OO")
    register(RAW / "wolf" / "wolf_0002.jpg", "wolf", "grass",
             "Unsplash", "https://unsplash.com/photos/...",

             "Pexels License", "이OO", note="★ 눈밭 허스키 — 귀한 샘플")
    summary()

"""
Day 101 Step 4 — 1차 정제
Day 092의 검사 도구를 프로젝트 폴더에 적용합니다.
"""
from collections import defaultdict

RAW = PROJ / "data" / "raw"
MIN_SIDE = 160          # 이보다 작으면 제외


def dhash(path, hash_size=8):
    """차이 해시 — 시각적으로 비슷한 이미지 탐지 (Day 092)"""
    img = Image.open(path).convert("L").resize(
        (hash_size + 1, hash_size), Image.LANCZOS)
    a = np.array(img, dtype=int)
    return "".join("1" if v else "0" for v in (a[:, 1:] > a[:, :-1]).flatten())


def hamming(a, b):
    return sum(c1 != c2 for c1, c2 in zip(a, b))


def inspect(root):
    rows, broken = [], []
    for cls_dir in sorted(p for p in root.iterdir() if p.is_dir()):
        for f in sorted(cls_dir.iterdir()):
            if f.suffix.lower() not in {".jpg", ".jpeg", ".png", ".webp"}:
                continue
            try:
                with Image.open(f) as img:
                    img.verify()
                with Image.open(f) as img:
                    w, h = img.size
                    mode = img.mode
                rows.append({"path": f, "class": cls_dir.name,
                             "w": w, "h": h, "mode": mode,
                             "kb": f.stat().st_size / 1024,
                             "hash": dhash(f)})
            except Exception as e:
                broken.append({"path": f, "error": type(e).__name__})
    return pd.DataFrame(rows), pd.DataFrame(broken)


df, broken = inspect(RAW)

line = "=" * 74
print(line)

print(line)

print(f"\n[① 깨진 파일] {len(broken)}장")

print("  " + "-" * 42)
for cls, g in df.groupby("class"):
    print(f"  {cls:<10}{len(g):>7}{g['kb'].mean():>10.0f}"
          f"{f'{g.w.median():.0f}x{g.h.median():.0f}':>14}")

if len(kb_gap) == 2 and kb_gap.max() / max(kb_gap.min(), 1) > 1.8:

axes[2].boxplot([df[df["class"] == c]["kb"] for c in sorted(df["class"].unique())],

"""
Day 101 Step 5 — 라벨 교차검수 (Cohen's kappa)
2인 팀: 같은 100장을 각자 독립적으로 라벨링한 결과를 비교
개인 진행: 하루 간격으로 두 번 라벨링한 결과를 비교
"""
from pathlib import Path

import numpy as np
import pandas as pd

PROJ = Path("/content/drive/MyDrive/ml_course/project_wolf")


def cohen_kappa(a, b):
    """Cohen's kappa를 직접 계산합니다 (sklearn 없이도 이해되도록)"""
    a, b = np.asarray(a), np.asarray(b)
    labels = sorted(set(a) | set(b))
    n = len(a)

    po = (a == b).mean()                       # 관측 일치율
    pe = sum((a == L).mean() * (b == L).mean() # 우연 일치율
             for L in labels)
    return (po - pe) / (1 - pe), po, pe


# ── 검수 시트 생성 (처음 1회) ──
sheet_path = PROJ / "docs" / "label_review.csv"

    for cls in ["wolf", "husky"]:
        files += sorted((PROJ / "data" / "raw" / cls).glob("*.jpg"))[:50]
    rng = np.random.default_rng(42)
    files = list(rng.permutation(files))       # 순서를 섞어 편향 방지
    pd.DataFrame({"file": [f.name for f in files],
                  "rater_A": "", "rater_B": "", "note": ""}

    print(f"검수 시트 생성: {sheet_path}")

print(f"  Cohen's κ  : {kappa:.3f}")

grade = ("✅ 규약이 명확합니다. 진행하세요" if kappa >= 0.90 else
         "🟡 경계가 애매합니다. 규약을 보완하고 재검수하세요" if kappa >= 0.75 else

print(f"  {'파일':<24}{'A':>9}{'B':>9}   메모")

## ⑤ 자주 하는 실수

### 검색어 하나로 300장을 받는다

```
"wolf" 로만 검색 → 상위 결과는 다 비슷한 다큐멘터리 사진
→ 눈밭·측면·성체·회색 늑대만 300장
```

**증상** — 학습은 잘 되는데 조금만 다른 사진을 주면 틀립니다.

**해결** — 검색어를 8개 이상 조합합니다.

```
wolf snow / wolf zoo / wolf summer / wolf grass /
gray wolf / wolf portrait / wolf running / wolf pup
```

### 라이선스를 나중에 채우려 한다

```
"일단 다 받고 출처는 목요일에 정리하자"
→ 목요일: 어느 사진이 어디서 왔는지 아무도 모름
→ 발표에서 "이 데이터 출처가 어디죠?" → 답 못 함
```

**해결** — `register()` 를 통해서만 저장합니다. 대장에 없으면 없는 이미지입니다.

### 배경 층화를 "나중에 맞추면 되지" 한다

```
월요일: wolf 눈 150장 먼저 다 모음
화요일: "이제 눈 없는 늑대 150장 모으자" → 하루로 부족
→ 결국 눈 150 : 비눈 40으로 진행
```

**해결** — **네 칸을 번갈아 채웁니다.** 한 칸이 목표의 40%를 넘으면 다른 칸으로 넘어가세요.

### counter 셋을 학습 데이터에서 떼어 온다

```python
# ❌ 화요일에 이렇게 함
counter = [f for f in train_files if is_snow(f) and is_husky(f)]
```

**문제** — 학습에 쓴 이미지로 편향을 검증하면 아무 의미가 없습니다.
**해결** — counter 셋은 **처음부터 따로 수집**하고 다른 폴더에 둡니다.

### 애매한 이미지를 "일단 넣는다"

```
늑대개 → wolf 에 넣음
→ 모델이 "허스키 같은 늑대"를 학습
→ 결정경계가 무너지고 정확도가 전체적으로 하락
```

**해결** — **애매하면 버립니다.** 300장 중 20장을 버려도 남는 280장이 깨끗한 게 낫습니다.

### 워터마크·로고가 있는 이미지를 섞는다

```
스톡 사이트 미리보기 이미지에 워터마크
→ 특정 클래스에만 몰림
→ 모델이 워터마크를 학습 (실제 사례 있음)
```

**해결** — 워터마크 있는 이미지는 제외하거나, **양쪽 클래스에 고르게** 들어가게 합니다.

### 사람이 배경을 보고 라벨을 붙인다

```
"눈밭에 있으니까 늑대겠지" → wolf
```

**가장 위험한 실수입니다.** 편향이 **정답 자체에** 들어갑니다.
**해결** — 라벨링 규약 1번 줄에 씁니다. **"형태만 보고 판단한다."**

### 원본(`raw/`)을 직접 수정한다

```
raw/ 에서 리사이즈·삭제 → 원래 뭐가 있었는지 복구 불가
```

**해결** — `raw/` 는 읽기 전용. 모든 가공은 `clean/` 에 새로 씁니다. ([Day 092](day-092.md))

**① 문제 — 클래스는 균형이지만 배경이 라벨과 강하게 상관되어 있습니다.**

```
눈 배경 비율   wolf 90%  vs  husky 12.5%   → 격차 77.5%
```

**"눈이면 늑대"라는 규칙 하나로 정확도를 계산해 보면**

```
눈 배경 205장 → 전부 wolf 로 예측: 180 맞음, 25 틀림
비눈 195장  → 전부 husky 로 예측: 175 맞음, 20 틀림
정확도 = (180 + 175) / 400 = 0.8875
```

**동물을 전혀 보지 않고도 0.89가 나옵니다.**
모델이 굳이 형태를 배울 이유가 없습니다.

**② 우선순위**

| 순위 | 할 일 | 이유 |
|---|---|---|
| **1** | **눈밭 허스키 수집** (25 → 80장 이상) | 가장 부족한 칸. 상관을 깨는 데 직접 기여 |
| **2** | **눈 없는 늑대 수집** (20 → 80장 이상) | 위와 같은 이유 |
| 3 | counter 셋 60장 확보 | 검증 수단이 없으면 편향을 증명 못 함 |
| 4 | 눈 배경 wolf 일부 제외 (180 → 120) | 수집이 안 되면 **버려서** 균형을 맞춤 |

> **4번이 중요합니다.** 못 모으면 **줄이는 것도 해법**입니다.
> 400장에서 320장으로 줄어도 상관이 사라지면 그게 더 좋은 데이터셋입니다.
