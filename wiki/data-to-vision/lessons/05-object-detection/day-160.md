## ① 학습 목표

이 레슨을 마치면 이렇게 할 수 있습니다.

- **한 파일 앱의 한계**를 머지 충돌 · 순환 import · 테스트 곤란 · import 시점 부작용의 4가지 증상으로 설명할 수 있다.
- `app.py` / `templates/` / `static/` / `models/` / `utils/` / `blueprints/` / `instance/` 의 **역할을 구분**하고 파일을 올바른 자리에 놓을 수 있다.
- **`config.py`** 로 설정을 분리하고 `BaseConfig` · `DevConfig` · `ProdConfig` · `TestConfig` 를 `from_object` 로 적용할 수 있다.
- **환경변수 오버레이**와 **`instance/`** 를 써서 비밀값을 코드 밖에 둘 수 있다.
- **Blueprint** 로 라우트를 기능별로 쪼개고, `url_for('bp.endpoint')` 로 바뀌는 **엔드포인트 이름 규칙**을 처리할 수 있다.
- **애플리케이션 팩토리** `create_app(config_name)` 을 만들고 `current_app` · `app_context` 를 올바르게 쓸 수 있다.
- **확장 객체의 지연 초기화**(`init_app`) 패턴으로 앱을 여러 개 만들 수 있다.
- **`app.errorhandler` 와 `bp.errorhandler` 의 차이**를 알고 404 를 확실하게 잡을 수 있다.
- **순환 import** 를 피하는 import 순서 규칙을 적용할 수 있다.

### 한 파일 앱에서 실제로 겪는 증상 5가지

```
증상 ①  ★ 머지 충돌
  A 는 /detect, B 는 /api/stats, C 는 필터를 고침 — 셋 다 app.py
  → git merge 마다 CONFLICT (content): app.py · 하루 3~4번, 매번 5~15분

증상 ②  ★ 순환 import
  app.py           : from detect_routes import bp
  detect_routes.py : from app import app          ← 서로 물음

  ImportError: cannot import name 'app' from partially
               initialized module 'app' (circular import)

증상 ③  테스트가 안 됨
  전역 app 이 딱 하나뿐이라
  · 테스트 A 가 app.config 를 바꾸면 B 가 영향을 받음 (순서에 따라 결과가 달라짐)
  · 업로드 테스트가 진짜 static/uploads/ 를 더럽힘
  · "앱을 두 개 만들어 비교"가 불가능

증상 ④  ★ import 시점 부작용
  from app import app     ← 이 한 줄만으로
  · static/uploads · static/results · instance/results 폴더가 생성됨
  · logging.basicConfig() 가 루트 로거를 가로챔
  · app.secret_key = os.urandom(32) 로 매번 다른 키
  → 문서 도구 · 린터 · 테스트 수집기가 import 만 해도 부작용

증상 ⑤  이름 충돌
  upload() do_detect() api_detect() admin_cleanup() ...
  → 파일 하나에 함수 이름 20개 → 이름 앞에 prefix 를 붙이는 습관이 생김
     이건 "폴더가 해야 할 일을 이름으로 하는 것"입니다
```

### 설정 분리 — 왜 `config.py` 인가

**지금(Day 159)의 문제**

```python
app.config["MAX_CONTENT_LENGTH"] = MAX_BYTES        # app.py 안
app.secret_key = os.environ.get("SECRET_KEY") or os.urandom(32)
UPLOAD_DIR = BASE / "static/uploads"
RETENTION_DAYS = 7                                   # 어딘가 상수
```

```
문제 ①  설정이 코드 여기저기에 흩어짐
        "업로드 최대 크기를 20MB 로" → 어디를 고쳐야 하나?
문제 ②  개발/운영/테스트를 구분할 수 없음
        테스트는 static/uploads 가 아니라 임시 폴더를 써야 함
문제 ③  ★ 비밀값이 코드에 섞임
        SECRET_KEY 를 깜빡 하드코딩 → git push → 영구 유출
문제 ④  os.urandom(32) 를 매번 → 재시작마다 모든 사용자 로그아웃
```

**★ 설정 클래스 계층**

```
BaseConfig            공통값 (앱 이름 · 허용 확장자 · 경로)
   ├── DevConfig      DEBUG=True · 상세 로그 · 캐시 없음
   ├── ProdConfig     DEBUG=False · ★ SECRET_KEY 필수 · 보안 쿠키
   └── TestConfig     TESTING=True · ★ 임시 폴더 · 로그 최소
```

```python
app.config.from_object(DevConfig)     # ★ 클래스의 대문자 속성만 읽음
```

```
★ from_object 의 규칙 — 대문자 속성만 config 로 들어갑니다

  class DevConfig:
      DEBUG = True          → app.config["DEBUG"] = True
      debug = True          → 무시
      _secret = "x"         → 무시
      def init_app(...)     → 무시 (staticmethod 는 따로 호출)
```

**★ 설정 우선순위 — 3층으로 덮어쓰기**

```
① from_object(DevConfig)       기본값 (코드에 있음, 커밋됨)
       ↓ 덮어씀
② from_pyfile("config.py")     instance/config.py (커밋 안 됨)
       ↓ 덮어씀
③ from_prefixed_env("CCTV")    환경변수 (최우선, 배포 때 주입)
```

```bash
export CCTV_SECRET_KEY='9f2c...'
export CCTV_MAX_CONTENT_LENGTH=33554432
export CCTV_RETENTION_DAYS=30
```

```
★ from_prefixed_env 는 JSON 으로 파싱을 시도합니다
  CCTV_DEBUG=true          → True     (문자열 "true" 가 아니라 진짜 bool)
  CCTV_RETENTION_DAYS=30   → 30       (int)
  CCTV_SECRET_KEY=abc123   → "abc123" (파싱 실패 → 문자열)
```
> ⚠️ **환경변수 이름에 접두사를 반드시 붙이세요.**
> 접두사 없이 `os.environ` 을 통째로 읽으면 `PATH` · `HOME` 까지 설정에 들어가고,
> 다른 프로그램의 환경변수와 **충돌**합니다.

### Blueprint — 라우트를 묶는 단위

```
Blueprint 는 ★ "아직 앱에 붙지 않은 라우트 묶음" 입니다

  Flask 앱   = 실제로 요청을 받는 것
  Blueprint  = 라우트·템플릿·정적파일의 설계도
  create_app() 안에서 register_blueprint() 로 붙입니다
```

```python
from flask import Blueprint

bp = Blueprint(
    "detect",                     # ★ 엔드포인트 접두사가 되는 이름
    __name__,                     # 위치 파악용
    url_prefix="/",               # 이 blueprint 의 모든 URL 앞에 붙음
    template_folder="templates",  # (선택) 전용 템플릿 폴더
    static_folder="static",       # (선택) 전용 정적 폴더
)


@bp.route("/upload")
def upload():
    ...
```

```python
# web/__init__.py
app.register_blueprint(main_bp)
app.register_blueprint(detect_bp)
app.register_blueprint(api_bp,   url_prefix="/api")     # ★ 여기서 덮어쓸 수도
app.register_blueprint(admin_bp, url_prefix="/admin")
```

**`url_prefix` 는 두 곳에서 정할 수 있습니다**

| 방식 | 코드 | 장점 |
|---|---|---|
| Blueprint 에서 | `Blueprint("api", __name__, url_prefix="/api")` | 파일만 봐도 URL 을 앎 |
| register 에서 | `register_blueprint(bp, url_prefix="/api")` | 같은 bp 를 여러 경로에 붙일 수 있음 |

```python
app.register_blueprint(api_bp, url_prefix="/api/v1", name="api_v1")   # 버전 관리
```

> ⚠️ **같은 blueprint 를 두 번 등록하려면 `name=` 을 반드시 다르게 주세요.**
> Flask 2.1 부터 같은 이름의 blueprint 중복 등록은 **`ValueError`** 입니다.

### ★ Blueprint 를 쓰면 `url_for` 가 전부 바뀝니다

**이것이 오늘 가장 많이 터지는 오류입니다.**

```
엔드포인트 이름 규칙

  Blueprint 없음   →  url_for('upload')
  Blueprint 있음   →  url_for('detect.upload')
                          └─ blueprint 이름 ─┘
```

```
BuildError: Could not build url for endpoint 'upload'.
            Did you mean 'detect.upload' instead?
```

**★ 마이그레이션 표 — 템플릿과 코드에서 전부 바꿔야 합니다**

| # | Day 159 (기존) | Day 160 (변경 후) | 나오는 파일 |
|---|---|---|---|
| 1 | `url_for('index')` | **`url_for('main.index')`** | `base.html` (브랜드·네비) |

```
  · 사용할 때 current_app 으로 지금 앱의 상태를 꺼냅니다
```

```python
# ✗ 인스턴스 속성에 앱 상태를 저장하면 — 마지막 앱만 남습니다
class ResultStore:
    def init_app(self, app):
        self.root = Path(app.config["META_DIR"])

# ✓ ★ app.extensions 에 저장 (전체 코드는 Step 3)
class ResultStore:
    def init_app(self, app):
        app.extensions["result_store"] = {"root": Path(app.config["META_DIR"])}

    @property
    def root(self):
        return current_app.extensions["result_store"]["root"]   # ★ 현재 앱
```

### 에러 핸들러 — `app` vs `blueprint`

```python
@app.errorhandler(404)      # ★ 앱 전체
@bp.errorhandler(404)       # ★ 이 blueprint 안에서 발생한 404 만
```

**★ 그런데 404 는 blueprint 로 안 잡힙니다.**

```
왜 안 잡히는가 — 요청 URL: /없는페이지

  ① URL 규칙을 뒤짐 → 아무것도 안 맞음
  ② 어느 blueprint 인지 결정할 수 없음 (request.blueprint 가 None)
  ③ 앱 수준 404 핸들러만 호출

  → bp.errorhandler(404) 는 ★ 절대 호출되지 않습니다
```

```python
errors_bp = Blueprint("errors", __name__)

@errors_bp.errorhandler(404)          # ✗ 안 불림
def not_found(e):
    return render_template("errors/404.html"), 404


@errors_bp.app_errorhandler(404)      # ✓ blueprint 파일에 쓰되 앱 전체에 등록
def not_found(e):
    return render_template("errors/404.html"), 404
```

**★ 정리표**

| 데코레이터 | 등록 범위 | 404 | 500 · 413 · 커스텀 예외 |
|---|---|---|---|
| `@app.errorhandler(N)` | 앱 전체 | 잡힘 | 잡힘 |
| `@bp.errorhandler(N)` | 그 bp 안 | **안 잡힘** | 잡힘 |
| `@bp.app_errorhandler(N)` | 앱 전체 | 잡힘 | 잡힘 |

```
★ 왜 404 만 다른가
  404 = 라우팅 실패 → blueprint 가 정해지기 전에 발생
  500 = 뷰 함수 안에서 예외 → blueprint 가 이미 정해짐
  413 = 본문 크기 초과 → URL 자체는 매칭되므로 blueprint 로도 잡힘 (버전 주의)

  헷갈리면 전부 app_errorhandler 를 쓰세요
```

### 순환 import 를 피하는 규칙

```
★ 순환 import 가 생기는 전형적인 모양

  web/__init__.py       from .blueprints.main import bp
  blueprints/main.py    from web import app          ← 위험

  파이썬이 web/__init__.py 를 실행하다가 main.py 로 갔는데
  main.py 가 다시 web 을 찾음 → web 은 아직 실행 중(미완성)

```

**★ 5가지 규칙**

```
규칙 1  config.py 는 아무것도 import 하지 않는다 (os, pathlib 만)
규칙 2  extensions.py 는 flask 만 import 한다 (blueprint · models 금지)
규칙 3  utils/ 는 web 패키지 안의 것을 import 하지 않는다
규칙 4  blueprints/ 는 web/__init__.py 를 import 하지 않는다
        필요한 것은 current_app · extensions 에서 가져온다
규칙 5  web/__init__.py 는 create_app() 함수 안에서 blueprint 를 import 한다
```

```
★ 의존 방향 — 한 방향으로만 흐릅니다

   config.py      extensions.py      utils/
       │                │               │
       └────────┬───────┴───────┬───────┘
                ▼               ▼
             models/       blueprints/
                └───────┬───────┘
                        ▼
                 web/__init__.py    ★ 모두를 조립 (아무도 얘를 import 안 함)
                        ▼
                  run.py / wsgi.py
```

```python
# ✓ web/__init__.py
def create_app(config_name=None):
    app = Flask(__name__, instance_relative_config=True)
    ...
```

함수 안 import 가 지저분해 보이지만 Flask 공식 문서가 권장하는 방식입니다.
순환을 구조적으로 차단하고, import 비용을 앱 생성 시점으로 미룹니다.
> ⚠️ **순환 import 는 "가끔" 납니다.**
> import 순서에 따라 되기도 하고 안 되기도 해서
> **"내 컴퓨터에서는 되는데"** 의 대표적 원인입니다.

### 개발 서버와 운영 서버 — 오늘은 예고만

```python
"""web/extensions.py — 앱 전체가 공유하는 객체

★ 규칙: 이 파일은 flask 외에는 web 패키지의 아무것도 import 하지 않습니다.
   그래야 blueprint 도 models 도 여기를 안전하게 import 할 수 있습니다.

import json
import uuid
from datetime import datetime
from pathlib import Path

from flask import current_app


class ResultStore:
    """검출 결과 메타(JSON)의 저장·조회

    지연 초기화 패턴 (db.init_app(app) 과 같은 모양)
      · 객체 자체는 앱을 모릅니다
      · 앱별 상태는 app.extensions 에 저장합니다
      · 사용 시점에 current_app 으로 현재 앱의 상태를 꺼냅니다
    """

    EXT_KEY = "result_store"

    def __init__(self, app=None):
        if app is not None:
            self.init_app(app)

    # ────────────────── 초기화 ──────────────────

    def init_app(self, app):
        """create_app() 안에서 호출됩니다"""
        root = Path(app.config["META_DIR"])
        root.mkdir(parents=True, exist_ok=True)
        # ★ self.root 가 아니라 app.extensions 에 저장 — 앱마다 독립
        app.extensions[self.EXT_KEY] = {"root": root}
        app.logger.debug("ResultStore 초기화: %s", root)

    @property
    def root(self) -> Path:
        """지금 처리 중인 앱의 저장 경로"""
        try:
            return current_app.extensions[self.EXT_KEY]["root"]
        except (KeyError, RuntimeError) as e:
            raise RuntimeError(
                "ResultStore 가 초기화되지 않았습니다. "
                "create_app() 안에서 store.init_app(app) 을 호출하세요."
            ) from e

    # ────────────────── CRUD ──────────────────

    @staticmethod
    def new_id() -> str:
        """12자리 16진수 — URL 에 그대로 쓰는 ID"""
        return uuid.uuid4().hex[:12]

    @staticmethod
    def is_valid_id(rid: str) -> bool:
        """경로 조작 방어 — 16진수 12자리만 허용"""
        return (isinstance(rid, str) and len(rid) == 12
                and all(c in "0123456789abcdef" for c in rid))
```

### Step 10. `blueprints/errors.py` — 에러 핸들러

```python
"""web/blueprints/errors.py — 404 · 413 · 500 처리

★ 핵심: 404 는 blueprint 로 잡히지 않습니다.
   그래서 bp.errorhandler 가 아니라 ★ bp.app_errorhandler 를 씁니다.
"""
from __future__ import annotations

from flask import (Blueprint, current_app, flash, jsonify, redirect,
                   render_template, request, url_for)

bp = Blueprint("errors", __name__)


def wants_json() -> bool:
    """★ API 요청인가 — 세 겹으로 판단"""
    if request.blueprint == "api":                  # ① 정상 라우팅된 API
        return True
    if request.path.startswith("/api/"):            # ② ★ 404 는 blueprint 없음
        return True
    accept = request.accept_mimetypes               # ③ Accept 헤더
    best = accept.best_match(["application/json", "text/html"])
    return (best == "application/json"
            and accept[best] > accept["text/html"])


@bp.app_errorhandler(404)
def not_found(e):
    """★ app_errorhandler 여야 잡힙니다"""
    if wants_json():
        return jsonify({"error": "not_found",
                        "path": request.path,
                        "message": getattr(e, "description", "")}), 404
    return render_template("errors/404.html",
                           message=getattr(e, "description", "")), 404


@bp.app_errorhandler(413)
def too_large(e):
    mb = current_app.config["MAX_CONTENT_LENGTH"] // 1024 // 1024
    if wants_json():
        return jsonify({"error": "file_too_large", "max_mb": mb,
                        "message": f"파일이 너무 큽니다 (최대 {mb}MB)"}), 413
    flash(f"파일이 너무 큽니다 (최대 {mb}MB)", "error")
    return redirect(url_for("detect.upload")), 413


@bp.app_errorhandler(500)
def server_error(e):
    current_app.logger.exception("서버 오류 path=%s", request.path)
    if wants_json():
        return jsonify({"error": "internal_error",
                        "message": "서버 내부 오류"}), 500
    return render_template("errors/500.html"), 500


@bp.app_errorhandler(Exception)
def unhandled(e):
    """★ 마지막 그물 — 예상 못한 예외

    TESTING/DEBUG 에서는 그대로 올려서 스택트레이스를 봅니다.
    """
    from werkzeug.exceptions import HTTPException

    if isinstance(e, HTTPException):        # ★ 404/413 등은 위에서 처리됨
        return e
    if current_app.config.get("TESTING") or current_app.config.get("DEBUG"):
        raise e
    current_app.logger.exception("처리되지 않은 예외 path=%s", request.path)
    if wants_json():
        return jsonify({"error": "internal_error"}), 500
    return render_template("errors/500.html"), 500
```

> ⚠️ **`@bp.app_errorhandler(Exception)` 은 `HTTPException` 도 잡습니다.**
> 그대로 두면 404 가 500 으로 바뀝니다.
> **반드시 `isinstance(e, HTTPException)` 이면 그대로 반환하세요.**

### Step 11. `web/__init__.py` — 애플리케이션 팩토리

```python
"""web/__init__.py — 애플리케이션 팩토리

create_app(config_name) 하나가 앱 전체를 조립합니다.
★ 이 파일은 아무도 import 하지 않습니다 (run.py · wsgi.py · tests 제외).
"""
from __future__ import annotations

import logging
import os
from datetime import datetime
from logging.handlers import RotatingFileHandler
from pathlib import Path

from flask import Flask

from .config import config_by_name
from .extensions import store
from .utils.filters import register_context, register_filters

__version__ = "1.2"


def create_app(config_name: str | None = None) -> Flask:
    """★ 앱을 만들어 반환합니다 (전역 app 없음)"""
    app = Flask(__name__, instance_relative_config=True)

    # ── ① 설정 3층 ──
    config_name = (config_name
                   or os.environ.get("APP_CONFIG")
                   or "default")
    config_cls = config_by_name.get(config_name)
    if config_cls is None:
        raise ValueError(
            f"알 수 없는 설정 이름: {config_name!r} "
            f"(사용 가능: {sorted(config_by_name)})")

    app.config.from_object(config_cls)                    # ① 기본값
    app.config.from_pyfile("config.py", silent=True)      # ② ★ instance/
    app.config.from_prefixed_env("CCTV")                  # ③ ★ 환경변수
    app.config["CONFIG_NAME"] = config_name
    app.config["STARTED_AT"] = datetime.now().isoformat(timespec="seconds")

    # ── ② 로깅 ──
    _configure_logging(app)

    # ── ③ 폴더 ──
    _ensure_dirs(app)

    # ── ④ 확장 ──
    store.init_app(app)

    # ── ⑤ 템플릿 필터 · 공통 변수 ──
    register_filters(app)
    register_context(app)

    # ── ⑥ blueprint (★ 함수 안 import — 순환 방지) ──
    from .blueprints.main import bp as main_bp
    from .blueprints.detect import bp as detect_bp
    from .blueprints.api import bp as api_bp
    from .blueprints.admin import bp as admin_bp
    from .blueprints.errors import bp as errors_bp

    app.register_blueprint(main_bp)
    app.register_blueprint(detect_bp)
    app.register_blueprint(api_bp, url_prefix="/api")
    app.register_blueprint(admin_bp, url_prefix="/admin")
    app.register_blueprint(errors_bp)          # ★ URL 없음 — 핸들러만

    # ── ⑦ 환경별 마무리 검증 ──
    config_cls.init_app(app)

    app.logger.info("앱 생성 완료 config=%s blueprints=%s routes=%d",
                    config_name, list(app.blueprints),
                    len(list(app.url_map.iter_rules())))
    return app


def _ensure_dirs(app: Flask) -> None:
    """★ import 시점이 아니라 앱 생성 시점에 폴더를 만듭니다"""
    for key in ("UPLOAD_DIR", "RESULT_DIR", "META_DIR",
                "SNAPSHOT_DIR", "LOG_DIR"):
        path = app.config.get(key)
        if path:
            Path(path).mkdir(parents=True, exist_ok=True)
    Path(app.instance_path).mkdir(parents=True, exist_ok=True)
```

**`_configure_logging(app)` 의 본문은 지면에서 뺐습니다.** `LOG_LEVEL` 로
`app.logger.setLevel()` 을 맞추고, 핸들러가 없을 때만 `StreamHandler` 를 붙이고,
`LOG_TO_FILE` 이 참이면 `RotatingFileHandler`(5MB × 5개)를 추가하는 20여 줄입니다.
중요한 것은 **`logging.basicConfig()` 를 쓰지 않는다**는 점입니다 —
그것은 루트 로거를 건드려 같은 프로세스의 다른 앱까지 오염시킵니다.

```
★ create_app() 의 7단계 — 순서가 중요합니다

  ① 설정      → 나머지 전부가 config 를 읽으므로 맨 먼저
  ② 로깅      → ③~⑦ 에서 로그를 남길 수 있게
  ③ 폴더      → 확장이 폴더를 필요로 함
  ④ 확장      → blueprint 가 store 를 씀
  ⑤ 필터      → 템플릿 렌더 전에
  ⑥ blueprint → 라우트 등록
  ⑦ init_app  → 마지막에 검증 (운영 SECRET_KEY 등)
```

```python
    if request.blueprint == "api":
```

```python
# web/extensions.py 에 추가
import threading
import time

from flask import current_app


class DetectorProxy:
    """★ src/detector.py 를 감싸는 지연 로딩 프록시

    · 앱 생성 시에는 로드하지 않습니다.
    · 첫 호출 또는 warmup() 에서 1회만 로드합니다.
    · 앱마다 별도 상태를 가집니다 (app.extensions).
    """

    EXT_KEY = "detector"

    def init_app(self, app):
        app.extensions[self.EXT_KEY] = {
            "instance": None,
            "lock": threading.Lock(),      # ★ 동시 요청에 2번 로드 방지
            "load_ms": None,
            "warmed": False,
            "profile": app.config.get("DETECTOR_PROFILE"),
            "weights": app.config.get("MODEL_PATH"),
            "enabled": app.config.get("DETECTOR_ENABLED", True),
        }

    def _state(self) -> dict:
        return current_app.extensions[self.EXT_KEY]

    def get(self):
        """★ 실제 Detector 를 돌려줍니다 (없으면 로드)"""
        state = self._state()
        if not state["enabled"]:
            raise RuntimeError("이 앱은 검출이 비활성화되어 있습니다")
        if state["instance"] is None:
            with state["lock"]:                    # ★ 이중 검사 잠금
                if state["instance"] is None:
                    t0 = time.perf_counter()
                    from detector import get_detector   # ★ 여기서만 import
                    state["instance"] = get_detector(
                        profile=state["profile"], weights=state["weights"])
                    state["load_ms"] = round(
                        (time.perf_counter() - t0) * 1000, 1)
                    current_app.logger.info("★ 모델 로드 %.1fms",
                                            state["load_ms"])
        return state["instance"]

    def info(self) -> dict:
        s = self._state()
        return {"loaded": s["instance"] is not None, "warmed": s["warmed"],
                "load_ms": s["load_ms"], "profile": s["profile"],
                "enabled": s["enabled"]}


detector = DetectorProxy()
```

```
[2단계] 확장자      화이트리스트 (소문자 변환 후)
[3단계] 크기        MAX_CONTENT_LENGTH → 413
[4단계] ★ 실제 내용  매직 넘버 + cv2.imdecode 로 진짜 디코딩
```

```
★ 화이트리스트만으로 못 막는 공격
  ① 위장 파일   malware.exe → photo.jpg · 2단계 통과 → 매직 넘버 MZ 로 걸림
```

**14.** (9점)

```
★ Flask 의 요청 처리 순서
  ① URL 규칙(url_map)을 매칭
  ② 매칭 성공 → request.blueprint 결정 → 뷰 함수 실행
  ③ 매칭 실패 → NotFound(404) 발생

  404 는 ②를 거치지 않아 request.blueprint 가 ★ None 입니다
  Flask 는 어느 blueprint 것인지 알 수 없어 앱 수준 핸들러만 찾습니다
  → @bp.errorhandler(404) 는 영원히 호출되지 않습니다
```

```python
@errors_bp.app_errorhandler(404)          # 방법 ① blueprint 파일 + 앱 전체 등록
def not_found(e):
    return render_template("errors/404.html"), 404


def register_error_handlers(app):         # 방법 ② create_app() 에서 직접 등록
    @app.errorhandler(404)
    def not_found(e):
        return render_template("errors/404.html"), 404
```

500 은 뷰 함수 안에서 발생하므로 `bp.errorhandler(500)` 로도 잡힙니다(그 bp 안에서만).
헷갈리면 전부 `app_errorhandler` 를 쓰세요.
