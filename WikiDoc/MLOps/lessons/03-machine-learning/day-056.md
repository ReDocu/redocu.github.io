## ② 왜 필요한가

지난주 마지막 발견을 다시 꺼냅니다. R² 최강이던 선형 회귀가 정작 "나쁨 잡기"에서는
내일=오늘 규칙에 졌습니다(36% vs 40%). 원인은 문제를 **빙 둘러 풀었기 때문**입니다 —
값을 예측한 뒤 36이라는 문턱을 나중에 갖다 댔습니다.

이번 주는 문제를 정면으로 다시 정의합니다.

```
지난주 (회귀):   오늘 관측 ──▶ 내일 pm25 값 ──(문턱 36)──▶ 나쁨/아님
이번 주 (분류):  오늘 관측 ──▶ 내일 '나쁨'일 확률 ──(임계값)──▶ 경보/안심
```

분류로 정의하면 얻는 것이 두 가지입니다.

1. **모델이 처음부터 "나쁨/아님"의 경계를 배웁니다.** 평균 오차가 아니라 분류 자체에 최적화됩니다.
2. **임계값이라는 손잡이가 생깁니다.** "덜 놓치는 대신 헛경보를 감수"(경보 시스템) ↔
   "확실할 때만 알림"(광고 발송) — 같은 모델로 서비스 성격을 조절할 수 있습니다.

그리고 이 손잡이는 실무 어디에나 있습니다: 스팸 필터, 이상 거래 탐지, 이탈 예측, 불량 검출 —
전부 "확률 + 임계값" 구조입니다. 대단원 04에서 서빙할 API도 결국 이 확률을 반환하게 됩니다.

## ③ 개념 설명

### 왜 선형 회귀로 분류하면 안 되나

0(아님)/1(나쁨)을 타깃으로 선형 회귀를 돌리면 안 될까요? 두 가지가 무너집니다.

| 문제 | 설명 |
|---|---|
| 출력이 확률이 아님 | 예측이 1.4나 -0.2처럼 튀어나옴 — "140% 나쁨"은 해석 불능 |
| 극단값에 휘둘림 | 아주 확실한 나쁨(pm25 80) 하나가 경계선 전체를 끌고 감 — 경계 근처가 중요한데 먼 점이 직선을 흔듦 |

필요한 것은 **"어떤 입력이든 0~1 사이"로 눌러 주는 장치**입니다.

### 로지스틱 회귀 = 선형 회귀 + 시그모이드

```
① 선형 점수:  z = w₁·pm10 + w₂·pm25 + … + b        (지난주와 완전히 같은 부품)
② 확률 변환:  p = 1 / (1 + e⁻ᶻ)                     (시그모이드 함수)

        p
      1.0┤                    ●●●●●●●
         │               ●●●
      0.5┤            ●          ← z=0 일 때 p=0.5
         │        ●●●
      0.0┤●●●●●●●
         └────────────┼────────────── z
                      0
```

시그모이드는 어떤 z든 (0, 1) 구간으로 부드럽게 눌러 줍니다. z가 크면 1에, 작으면 0에 다가가고,
**z=0이 확률 50%의 경계선**입니다. 학습은 지난주처럼 손실(분류용 손실인 로그 손실)을
최소화하는 w, b를 찾는 것 — 부품은 재활용이고 출력 장치만 바뀌었습니다.

> **이름 주의** — "로지스틱 **회귀**"지만 하는 일은 **분류**입니다. "확률이라는 연속값을
> 회귀한다"는 유래의 흔적이니, 이름에 속지 마세요. (면접 단골 질문입니다.)

### 확률과 결정의 분리 — predict_proba와 임계값

sklearn 분류기에는 출력이 둘 있습니다.

| 메서드 | 출력 | 정체 |
|---|---|---|
| `predict_proba(X)` | `[[아닐 확률, 나쁠 확률], …]` | **모델의 진짜 출력** |
| `predict(X)` | `[0, 1, 0, …]` | `나쁠 확률 >= 0.5` 를 대신 계산해 준 것뿐 |

`predict` 의 0.5는 아무 근거 없는 **기본값**입니다. 놓침의 비용과 헛경보의 비용이 같을 때만
0.5가 정답인데, 현실에서 두 비용이 같은 경우는 드뭅니다.

| 서비스 | 놓침 비용 | 헛경보 비용 | 임계값 방향 |
|---|---|---|---|
| 미세먼지 경보 | 시민 건강 (큼) | 마스크 헛챙김 (작음) | **낮게** (많이 잡기) |
| 스팸 차단 | 스팸 봄 (작음) | 중요 메일 차단 (큼) | **높게** (확실할 때만) |

**임계값은 모델이 아니라 서비스가 정합니다.** 그래서 모델 코드가 아니라 기획 문서에 적힐 값입니다.

### 계수 읽기 — 확률을 미는 힘

로지스틱의 계수는 "그 특성이 클수록 나쁨 **확률이 올라간다/내려간다**"의 방향과 세기입니다
(정확히는 로그 오즈에 선형). 지난주처럼 **표준화 후에** 크기를 비교합니다.

### Step 1. 분류 타깃 만들기와 클래스 분포 (1교시)

```python
# day056_logistic.py — 로지스틱 회귀: 확률과 임계값
import numpy as np
import pandas as pd
from sklearn.linear_model import LinearRegression, LogisticRegression
from sklearn.metrics import accuracy_score
from sklearn.preprocessing import StandardScaler

pd.set_option("display.width", 140)
df = pd.read_csv("data/air_daily.csv", parse_dates=["date"])
F10 = ["pm10", "pm25", "o3", "no2", "co", "so2", "temp", "humidity", "wind_speed", "precip"]
d = df.dropna(subset=F10).copy()
d["bad_next"] = (d.pm25_next >= 36).astype(int)      # 타깃: 내일 나쁨 여부
tr = d[d.date < "2026-01-01"]; te = d[d.date >= "2026-01-01"]
ytr, yte = tr.bad_next, te.bad_next

print("== A. 클래스 분포 ==")
print(f"train: 나쁨 {ytr.mean()*100:.1f}%  ({ytr.sum()}/{len(ytr)})")
print(f"test : 나쁨 {yte.mean()*100:.1f}%  ({yte.sum()}/{len(yte)})")
print(f"'전부 아님'으로 찍기 정확도: {1 - yte.mean():.3f}")
```

실행 결과:

```
== A. 클래스 분포 ==
train: 나쁨 15.3%  (402/2629)
test : 나쁨 13.9%  (121/868)
'전부 아님'으로 찍기 정확도: 0.861
```

시작 전에 **분류의 0층 베이스라인**부터 박아 둡니다: 아무것도 안 하는 모델(전부 "아님")이
**정확도 86.1%** 입니다. 어제 배운 그대로 — 이 층을 못 이기면 의미가 없습니다.

### Step 2. 로지스틱 회귀 학습과 predict_proba (2~3교시)

```python
print("\n== B. 로지스틱 회귀 학습 ==")
sc = StandardScaler().fit(tr[F10])
clf = LogisticRegression(max_iter=5000).fit(sc.transform(tr[F10]), ytr)
proba = clf.predict_proba(sc.transform(te[F10]))[:, 1]     # [:, 1] = '나쁨(1)'일 확률
pred = clf.predict(sc.transform(te[F10]))
print(f"정확도: {accuracy_score(yte, pred):.3f}")

print("\npredict_proba 맛보기 — 2026년 1월의 닷새:")
sample = te.head(5)
sp = clf.predict_proba(sc.transform(sample[F10]))[:, 1]
for (_, row), p in zip(sample.iterrows(), sp):
    print(f"  {row.date.date()} {row.station} 오늘pm25 {row.pm25:5.1f} → 내일 나쁨 확률 {p:5.1%}  (실제: {'나쁨' if row.bad_next else '아님'})")
```

실행 결과:

```

정확도: 0.849

predict_proba 맛보기 — 2026년 1월의 닷새:
  2026-01-01 강남구 오늘pm25  26.8 → 내일 나쁨 확률  7.9%  (실제: 아님)
  2026-01-02 강남구 오늘pm25  23.4 → 내일 나쁨 확률  2.8%  (실제: 아님)
  2026-01-03 강남구 오늘pm25  16.2 → 내일 나쁨 확률  1.1%  (실제: 아님)
  2026-01-04 강남구 오늘pm25  24.9 → 내일 나쁨 확률  2.6%  (실제: 아님)
  2026-01-05 강남구 오늘pm25  26.2 → 내일 나쁨 확률  2.8%  (실제: 아님)
```

두 가지를 보세요.

1. 모델은 "나쁨/아님"이 아니라 **7.9%, 2.8% 같은 확률**을 냅니다. 조용한 1월 초라
   전부 낮은 확률 — 합리적입니다.
2. **정확도 0.849 < 0.861.** 우리 모델이 "아무것도 안 하기"에 **집니다.** 어제의 교훈이
   하루 만에 실전으로 돌아왔습니다. 그런데 이 모델, 정말 쓸모없을까요? Step 3에서 반전이 있습니다.

### Step 3. 임계값 조정 — 같은 모델, 다른 예보관 (5~6교시)

`predict` 의 0.5 대신 임계값을 직접 움직여 봅니다.

```python
print("\n== C. 임계값 조정 — 같은 모델, 다른 예보관 ==")
print("임계값 | 경보일 | 잡은 나쁨(재현) | 경보 중 적중(정밀) | 정확도")
n_bad = yte.sum()
for t in [0.7, 0.5, 0.3, 0.2, 0.1]:
    p_t = (proba >= t).astype(int)
    alarm = p_t.sum()
    hit = int(((p_t == 1) & (yte == 1)).sum())
    prec = hit / alarm if alarm else float("nan")
    print(f"  {t:.1f}  | {alarm:4d}일 | {hit:3d}/{n_bad} ({hit/n_bad*100:3.0f}%) |  {prec:5.1%}          | {accuracy_score(yte, p_t):.3f}")
```

실행 결과:

```
== C. 임계값 조정 — 같은 모델, 다른 예보관 ==
임계값 | 경보일 | 잡은 나쁨(재현) | 경보 중 적중(정밀) | 정확도
  0.7  |   44일 |  22/121 ( 18%) |  50.0%          | 0.861
  0.5  |   92일 |  41/121 ( 34%) |  44.6%          | 0.849
  0.3  |  162일 |  64/121 ( 53%) |  39.5%          | 0.821
  0.2  |  236일 |  76/121 ( 63%) |  32.2%          | 0.764
  0.1  |  367일 | 101/121 ( 83%) |  27.5%          | 0.671
```

**모델은 하나인데 예보관이 다섯입니다.**

| 임계값 | 인격 |
|---|---|
| 0.7 | 과묵함 — economy석. 경보 44일뿐, 확신할 때만. 나쁨의 82%를 놓침 |
| 0.5 | `predict` 의 기본값. 아무도 이 값을 "선택"한 적 없음 |
| **0.1** | 겁 많음 — 나쁨의 **83%를 잡지만**, 1년의 42%(367일)에 경보. 넷 중 셋은 헛경보 |

그리고 **정확도를 보세요** — 나쁨을 가장 많이 잡는 0.1의 정확도(0.671)가 가장 낮고,
정확도가 가장 높은 0.7(0.861)은 "전부 아님"과 같은 점수입니다. **불균형 문제에서 정확도는
좋은 나침반이 아닙니다.** 그럼 "잡은 비율"과 "경보 중 적중"이라는 두 축을 어떻게 한 장에
정리하고 비교하나 — 그것이 내일([Day 057](day-057.md)) 혼동행렬과 정밀도/재현율입니다.

## ⑤ 자주 하는 실수

### 분류기에 연속값 타깃을 넣음

```
ValueError: Unknown label type: continuous. Maybe you are trying to fit a classifier,
which expects discrete classes on a regression target with continuous values.
```

**원인** — `LogisticRegression().fit(X, d["pm25_next"])` 처럼 연속값(26.8, 31.2 …)을 그대로 넣었습니다.
**해결** — 분류 타깃은 클래스여야 합니다: `(d["pm25_next"] >= 36).astype(int)` 로 0/1을 만들어 넣으세요.

### 스케일링 없이 돌려 수렴 경고를 만남

```
ConvergenceWarning: lbfgs failed to converge after 100 iteration(s) (status=1):
STOP: TOTAL NO. OF ITERATIONS REACHED LIMIT
```

**원인** — 로지스틱 회귀는 반복 최적화로 학습하는데, 특성 스케일이 제각각이면 수렴이 매우 느립니다.
**해결** — StandardScaler를 먼저 적용하고(fit은 train만!), 그래도 나면 `max_iter` 를 늘립니다.
경고를 무시하면 **덜 수렴한 모델**을 쓰게 됩니다.

### predict_proba의 열을 잘못 집음

**증상** — 확률이 죄다 거꾸로 (나쁜 날일수록 낮은 확률).
**원인** — `predict_proba` 는 `clf.classes_` 순서(기본 `[0, 1]`)로 열을 돌려줍니다. `[:, 0]` 은 "아님"의 확률입니다.
**해결** — `proba[:, 1]` 또는 안전하게 `proba[:, list(clf.classes_).index(1)]`. 의심되면 `clf.classes_` 를 출력해 확인하세요.

### 정확도가 낮아졌다고 임계값 조정을 되돌림

**증상** — 임계값을 0.3으로 낮췄더니 정확도가 0.849 → 0.821로 떨어져서 "성능 저하"로 판단.
**원인** — 목적이 "나쁨 잡기"라면 잡은 비율이 34% → 53%로 **오른 것**입니다. 정확도는 이 목적을 재는 지표가 아닙니다.
**해결** — 임계값 조정의 성적은 내일 배울 정밀도/재현율로 잽니다. 지표를 목적에 맞게 먼저 고르세요.

### 임계값을 모델 학습에 넣으려고 함

**증상** — `LogisticRegression(threshold=0.3)` 같은 인자를 찾음 (없습니다).
**원인** — 임계값은 학습이 아니라 **결정 단계**의 개념입니다. 모델은 확률까지만 책임집니다.
**해결** — `(clf.predict_proba(X)[:, 1] >= 0.3)` 처럼 확률에 직접 적용합니다. 서빙 시에도 API가 확률을 주고 정책이 임계값을 대는 구조가 유연합니다 (대단원 04).

정책으로 적용할 수 있는 `predict_proba` 가 기본이 되어야 합니다.

</details>

**Q2.** Step 3의 표에서 시민 건강 경보 서비스라면 임계값 0.2와 0.5 중 무엇을 고르는 게 합리적이고,
그 대가로 무엇을 감수하나요?

<details>
<summary>답 보기</summary>
