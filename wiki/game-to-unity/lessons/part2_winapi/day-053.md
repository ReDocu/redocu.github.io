## 2. 막히는 상황

어제 만든 `BulletManager::Update`를 보자.

```cpp
void BulletManager::Update(double dt)
{
    for (int i = 0; i < cap; i++)
    {
        if (!m_pool.IsActiveAt(i)) continue;

        Bullet* b = m_pool.GetAt(i);
        b->Update(dt);

        if (!b->IsActive())
            m_pool.Return(b);                 // ★ 순회 중 반환
    }
}
```

**이 경우는 우연히 괜찮다.** 인덱스 기반 순회이고 반환이 인덱스를 바꾸지 않기 때문이다.

**그런데 `Scene`은 다르다.**

```cpp
void Scene::RemoveInactive()
{
    for (int i = m_count - 1; i >= 0; i--)
    {
        if (!m_objects[i]->IsActive())
        {
            delete m_objects[i];
            m_objects[i] = m_objects[--m_count];   // ★ 배열이 재배치된다
        }
    }
}
```

**그리고 더 나쁜 경우가 있다.**

```cpp
void Enemy::OnCollide(GameObject* other)
{
    Destroy();

    // 죽으면서 총알을 뿌린다
    for (int i = 0; i < 8; i++)
        m_scene->GetBulletManager().Fire(...);     // ★ 순회 중 생성
}
```

```
   순회 중에 생성이 일어나면?

   ① 배열이 커지면서 재할당  →  포인터 무효화  →  크래시
   ② 새로 생긴 것이 이번 프레임에 Update 됨    →  중복 갱신
   ③ 새로 생긴 것이 이번 프레임에 충돌 판정됨  →  즉사
```

```
   지금:   순회 중 생성·삭제가 뒤섞여 있다

   필요:   ① 생명주기 단계를 명확히 정의
           ② 생성·삭제를 순회 밖에서 처리
           ③ 무결성 검사
```

> **안전한 생명주기 관리가 필요하다.**

## 3. 개념

### 3-1. 오브젝트 생명주기

**왜 필요한가** — "언제 무엇이 일어나는가"를 명확히 한다.

```
   ┌──────────────────────────────────────────────────────────┐
   │                                                           │
   │   [ 풀 대기 ]                                             │
   │        │  Get()                                           │
   │        ▼                                                  │
   │   [ Reset ]        모든 값을 초기 상태로                   │
   │        │                                                  │
   │        ▼                                                  │
   │   [ Spawn ]        위치·속도·타입 설정, 활성화             │
   │        │                                                  │
   │        ▼                                                  │
   │   [ Update ] ◀──┐  매 프레임 (여러 번)                    │
   │        │        │                                         │
   │        └────────┘                                         │
   │        │                                                  │
   │        ▼  Destroy()                                       │
   │   [ Despawn ]      이펙트 생성, 점수 가산, 사운드          │
   │        │                                                  │
   │        ▼  Return()                                        │
   │   [ 풀 대기 ]                                             │
   └──────────────────────────────────────────────────────────┘
```

| 단계 | 하는 일 | 주의 |
|---|---|---|
| `Reset` | 모든 멤버를 초기값으로 | 빠뜨리면 이전 값 잔존 |
| `Spawn` | 위치·타입 등 설정 | 여기서 다른 오브젝트 생성 금지 |
| `Update` | 매 프레임 갱신 | 여기서 생성·삭제 예약만 |
| `Despawn` | 죽을 때의 처리 | **한 번만** 불려야 한다 |
| `Return` | 풀로 반환 | 이중 반환 방지 |

### 3-2. ⚠️ 순회 중 삭제 문제 (Day 11 재방문)

**왜 필요한가** — Day 11에서 배웠지만, 여기서 더 복잡해진다.

```
   [ 앞에서부터 삭제 ]

   idx   0    1    2    3    4
        [A]  [B]  [C]  [D]  [E]

   i=2 에서 C 삭제, 뒤를 당김
        [A]  [B]  [D]  [E]

   i=3 →  E                     ← D를 건너뛴다!
```

```
   [ 뒤에서부터 삭제 ]  (Day 11의 해결)

   for (int i = count - 1; i >= 0; i--)

   i=4 → E,  i=3 → D 삭제,  i=2 → C, ...
   → 삭제해도 앞쪽 인덱스는 그대로  ✔
```

```
   [ 마지막 것을 당겨오기 ]  (Scene 방식)

   idx   0    1    2    3    4
        [A]  [B]  [C]  [D]  [E]

   i=2 삭제 → 마지막 E를 2번에
        [A]  [B]  [E]  [D]        count = 4

   ★ 순서가 바뀐다 (렌더 순서가 중요하면 문제)
   ★ 뒤에서부터 순회하면 안전하다
```

### 3-3. ⚠️ 순회 중 생성 문제

**왜 필요한가** — 삭제보다 더 위험하다.

```cpp
    for (int i = 0; i < m_count; i++)
    {
        m_objects[i]->Update(dt);              // 여기서 Add() 가 불리면?
    }
```

```
   문제 ①  m_count 가 커진다
           → 새로 추가된 것도 이번 프레임에 Update
           → 총알이 생성되자마자 한 프레임 이동

   문제 ②  배열 재할당 (동적 배열인 경우)
           → 기존 포인터가 전부 무효화
           → 크래시

   문제 ③  충돌 판정 순서
           → 방금 생긴 총알이 즉시 판정되어 사라짐
```

**실제 사례**

```
   적이 죽으면서 8발을 뿌린다
   → 그 8발이 같은 프레임에 Update
   → 8발이 이미 한 프레임 이동한 위치에서 시작
   → 적 위치가 아니라 조금 아래에서 나온다  (미묘하게 이상함)
```

### 3-4. 지연 처리 (Deferred) — 표준 해결책

**왜 필요한가** — 생성·삭제를 순회 밖으로 미룬다.

```
   ┌──────────────────────────────────────────────────────────┐
   │  프레임 흐름                                               │
   │                                                           │
   │  ① 대기 중인 Spawn 처리     (이전 프레임에 예약된 것)      │
   │           ▼                                               │
   │  ② UpdateAll                (여기서 생성·삭제는 예약만)   │
   │           ▼                                               │
   │  ③ 충돌 판정                (여기서도 예약만)             │
   │           ▼                                               │
   │  ④ 대기 중인 Despawn 처리   (실제 회수)                   │
   │           ▼                                               │
   │  ⑤ Render                                                 │
   └──────────────────────────────────────────────────────────┘

   ★ ②③에서는 배열이 절대 안 바뀐다
```

```cpp
class ObjectManager
{
public:
    // 예약만 한다
    void RequestSpawn(const SpawnRequest& req)
    {
        if (m_spawnQueueCount < MAX_QUEUE)
            m_spawnQueue[m_spawnQueueCount++] = req;
    }

    void RequestDespawn(GameObject* obj)
    {
        if (!obj || obj->IsPendingDespawn()) return;      // 중복 방지

        obj->SetPendingDespawn(true);

        if (m_despawnQueueCount < MAX_QUEUE)
            m_despawnQueue[m_despawnQueueCount++] = obj;
    }

    void Update(double dt)
    {
        ProcessSpawnQueue();                   // ①

        UpdateAll(dt);                         // ②  배열 안 바뀜

        CheckCollisions();                     // ③  배열 안 바뀜

        ProcessDespawnQueue();                 // ④
    }

private:
    void ProcessSpawnQueue()
    {
        for (int i = 0; i < m_spawnQueueCount; i++)
            DoSpawn(m_spawnQueue[i]);

        m_spawnQueueCount = 0;
    }

    void ProcessDespawnQueue()
    {
        for (int i = 0; i < m_despawnQueueCount; i++)
        {
            GameObject* obj = m_despawnQueue[i];
            obj->OnDespawn();                  // 죽을 때 처리
            ReturnToPool(obj);
        }
        m_despawnQueueCount = 0;
    }
};
```

### 3-5. 중복 처리 방지

**왜 필요한가** — 한 프레임에 여러 번 죽으면 이펙트가 여러 개 생긴다.

```
   적이 총알 3발에 동시에 맞으면?

   총알1 → OnCollide → Destroy() → 큐에 추가
   총알2 → OnCollide → Destroy() → 큐에 또 추가
   총알3 → OnCollide → Destroy() → 큐에 또 추가

   → Despawn 이 3번 불린다
   → 폭발 이펙트 18개, 점수 3배
```

```cpp
class GameObject
{
public:
    void Destroy()
    {
        if (m_pendingDespawn) return;          // ★ 이미 예약됨
        m_pendingDespawn = true;
        m_active = false;

        if (m_manager) m_manager->RequestDespawn(this);
    }

    bool IsPendingDespawn() const { return m_pendingDespawn; }

protected:
    bool m_pendingDespawn = false;
};
```

```cpp
    void Reset()
    {
        m_pendingDespawn = false;              // ★ 재사용 시 초기화
        // ...
    }
```

> **`Reset`에서 이 플래그를 반드시 초기화한다.** 안 하면 재사용된 오브젝트가 즉시 사라진다.

### 3-6. 죽은 오브젝트 참조 방지

**왜 필요한가** — 이미 회수된 오브젝트를 가리키면 위험하다.

```cpp
class Enemy
{
    GameObject* m_target = nullptr;            // 플레이어를 가리킴
};

    // 플레이어가 죽어서 풀로 반환된 뒤
    m_target->GetX();                          // ★ 다른 오브젝트의 데이터를 읽는다
```

```
   ★ 풀링에서는 "해제된 메모리"가 아니라
     "다른 오브젝트로 재사용된 메모리"를 읽게 된다

   → 크래시하지 않고 조용히 이상하게 동작한다  (더 나쁘다)
```

**해결 ① — 매번 유효성 검사**

```cpp
    if (m_target && m_target->IsActive() && !m_target->IsPendingDespawn())
        double dx = m_target->GetX() - m_x;
```

**해결 ② — 세대(generation) 번호**

```cpp
class GameObject
{
    int m_generation = 0;                      // Reset 마다 증가
public:
    int GetGeneration() const { return m_generation; }
    void Reset() { m_generation++; /* ... */ }
};

struct ObjectRef
{
    GameObject* ptr = nullptr;
    int         generation = -1;

    GameObject* Get() const
    {
        if (!ptr) return nullptr;
        if (ptr->GetGeneration() != generation) return nullptr;   // ★ 재사용됨
        return ptr;
    }
};
```

```
   ★ 세대 번호 방식이 안전하다

   ptr 은 같은데 generation 이 다르면 "다른 오브젝트"라는 뜻
   → nullptr 을 반환해서 안전하게 처리
```

> **이 과정에서는 해결 ①(유효성 검사)로 충분하다.**
> 세대 번호는 참조가 많은 대규모 프로젝트에서 쓴다.

### 3-7. 화면 밖 판정

**왜 필요한가** — 언제 회수할지 정확히 정한다.

```cpp
bool Bullet::IsOutOfBounds() const
```

## 4. 따라 만들기

### Step 1 — 생명주기 함수 정의

```cpp
class PooledObject
{
public:
    virtual ~PooledObject() = default;

    virtual void Reset()                       // 풀에서 꺼낼 때
    {
        m_x = m_y = 0.0;
        m_active = false;
        m_pendingDespawn = false;
        m_lifeTime = 0.0;
        m_generation++;
    }

    virtual void OnSpawn()  { m_active = true; }      // 배치 직후
    virtual void OnDespawn() {}                        // 회수 직전

    virtual void Update(double dt) = 0;
    virtual void Render(Renderer& r) const = 0;

    void Destroy()
    {
        if (m_pendingDespawn) return;
        m_pendingDespawn = true;
        m_active = false;
    }

    bool IsActive() const         { return m_active; }
    bool IsPendingDespawn() const { return m_pendingDespawn; }
    int  GetGeneration() const    { return m_generation; }

protected:
    double m_x = 0, m_y = 0;
    double m_lifeTime = 0;
    bool   m_active = false;
    bool   m_pendingDespawn = false;
    int    m_generation = 0;
};
```

**✅ 여기까지 하면** — 생명주기가 명확해진다.

### Step 3 — 지연 처리 큐

```cpp
struct SpawnRequest
{
    int    type;
    double x, y;
    double vx, vy;
    int    tag;
    int    param;
};

class BulletManager
{
public:
    void RequestFire(double x, double y, double vx, double vy, int tag)
    {
        if (m_spawnCount >= MAX_SPAWN_QUEUE)
        {
            DebugLog("[Spawn] 큐 초과\n");
            return;
        }

        SpawnRequest& r = m_spawnQueue[m_spawnCount++];
        r.x = x; r.y = y; r.vx = vx; r.vy = vy; r.tag = tag;
    }

    void Update(double dt)
    {
        ProcessSpawnQueue();                   // ①

        // ② 순회 (배열이 안 바뀐다)
        int cap = m_pool.GetCapacity();
        for (int i = 0; i < cap; i++)
        {
            if (!m_pool.IsActiveAt(i)) continue;
            m_pool.GetAt(i)->Update(dt);
        }

        ProcessDespawnQueue();                 // ④
    }

private:
    void ProcessSpawnQueue()
    {
        for (int i = 0; i < m_spawnCount; i++)
        {
            Bullet* b = m_pool.Get();
            if (!b) { m_spawnFail++; continue; }

            const SpawnRequest& r = m_spawnQueue[i];
            b->Setup(r.x, r.y, r.vx, r.vy, r.tag);
            b->OnSpawn();

            m_spawnedThisFrame++;
        }
        m_spawnCount = 0;
    }

    void ProcessDespawnQueue()
    {
        int cap = m_pool.GetCapacity();

        for (int i = 0; i < cap; i++)
        {
            if (!m_pool.IsActiveAt(i)) continue;

            Bullet* b = m_pool.GetAt(i);

            if (b->IsPendingDespawn())
            {
                b->OnDespawn();
                m_pool.Return(b);
                m_despawnedThisFrame++;
            }
        }
    }

    static const int MAX_SPAWN_QUEUE = 256;
    SpawnRequest m_spawnQueue[MAX_SPAWN_QUEUE];
    int          m_spawnCount = 0;
};
```

**✅ 여기까지 실행하면** — 순회 중에 배열이 절대 안 바뀐다.

## 6. 자주 막히는 곳

| 증상 | 원인 | 해결 |
|---|---|---|
| 이펙트가 여러 개 | 중복 `Destroy` | `m_pendingDespawn` 검사 |
| 재사용 즉시 사라짐 | `Reset`에서 플래그 미초기화 | `m_pendingDespawn = false` |
| 크래시 | 순회 중 배열 변경 | 지연 처리 |
| 총알이 늦게 나옴 | 지연 처리의 정상 동작 (1프레임) | 허용 범위. 신경 쓰이면 즉시 생성 |
| 조용히 이상 동작 | 회수된 오브젝트 참조 | 세대 번호 또는 유효성 검사 |
| 활성 수가 안 맞음 | 이중 반환 또는 회수 누락 | `Validate()` |
| 화면 끝에서 뚝 끊김 | 여유 없음 | `MARGIN` 추가 |
| 총알이 영원히 안 사라짐 | 화면 밖 판정 버그 | 수명 안전장치 추가 |
| 큐 초과 로그 | 한 프레임 생성이 너무 많음 | 큐 크기 증가 또는 생성 분산 |

## 7. 정리

### 오늘 배운 것

| 개념 | 한 줄 요약 |
|---|---|
| **생명주기** | Reset → Spawn → Update → Despawn → Return |
| 순회 중 삭제 | 뒤에서부터, 또는 지연 처리 |
| **순회 중 생성** | 삭제보다 위험. 반드시 지연 처리 |
| **지연 처리** | 큐에 예약 → 순회 밖에서 실제 처리 |
| 중복 방지 | `m_pendingDespawn` 플래그 |
| `OnDespawn` | 죽을 때 처리를 한 곳으로. **한 번만** |
| 죽은 참조 | 풀링에서는 "다른 오브젝트"가 된다. 세대 번호 |
| 화면 밖 여유 | 스프라이트 크기 정도 |
| 무결성 검사 | Debug 빌드에서 주기적으로 |
