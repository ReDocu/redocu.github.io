1. 개요·목표

이력서(마크다운)를 입력하면 가상 캐릭터 코퍼스 128명 중 최근접 유형으로 치환하고, 그 캐릭터의 관계망을 통해 개인 궁합·팀 역학을 보여 주는 도구다. 결과의 주인공은 점수가 아니라 캐릭터와 그 관계이며, 도구가 답하는 질문은 3개다:

  • 이 이력서는 어떤 인물 유형인가 — 치환 + 후보 5명 + 신뢰도
  • 이 사람들이 한 팀이면 무슨 일이 생기나 — 마찰·시너지·안정성·커버리지
  • 내 유형 곁에 어떤 팀원이 오면 어떤가 — 가상 팀 시뮬레이션

비목표 (설계상 하지 않는 것)

  • 역량 평가·성과 예측·채용 판정 — 출력은 전부 성향 근접도이고 판정 버튼이 없다
  • LLM·외부 API 호출 — 전 연산이 로컬 순수 함수다 (재현 가능·감사 가능)
  • 관계 사전계산 저장 — 관계는 항상 온디맨드 계산 (화면 간 값 불일치 = 버그로 정의)
스택
Vanilla JS SPA (프레임워크 없음) · Node 빌드 스크립트 · Python(pywebview/WebView2) 셸 · PyInstaller exe

4. 데이터 모델

좌표계 — taxonomy-v4 (18차원)

직무군 9종 × 역량축 9종. 각 항목은 시드 단어 목록(합계 219개)을 가진다. 시드는 자동 파생 금지 — 128명 전수 오탐 실측을 거쳐 큐레이션·버전 고정한다 (기각 예: 로그→"프로그램" 오탐 16건, 문화→"조직문화" 오탐 11건).

직무군research_ux · content_editorial · design_craft · brand_gtm · merch_retail · data_analytics · ops_pm · people_cx · engineering_dev
역량축observation · structuring · detail_qa · communication · coordination · execution · ops_planning · problem_solving · technical_skill

아키타입 (캐릭터) 레코드

{ id, name, gender, ageGroup, jobField, traits, competencies[], primaryFamily, compatible[], jobVector: {직무군9: 0~100}, // 128명 기준선 백분위 axisVector: {역량축9: 0~100} } // 0 = 미검출 (낮음이 아님)

이력서 레코드 (localStorage ra-demo-resumes-v1)

{ id, fileName, registeredAt, rawText, parsed: {name, jobField, ageGroup, traits, team}, vectors: {axisVector, jobVector, coverage}, warnings[], // 등록 검증 결과 (등록을 막지 않음) candidates: [{id, pct} ×5], // 근접 후보 5명 sub: {characterId, matchPercent, rank, confirmed}, engineVersion, taxonomyVersion } // 재현성 스탬프

calibration.json — 기준선 동결

코퍼스 원점수 분포를 동결한 파일. 축·직무군별 정렬 분포(axisDist·jobDist)와 쌍 스케일러(pairScalers: synergyP95 · frictionP95 · growthP95 · overlapBaseline(p80))를 담는다. 분포를 얼리는 이유: 매 빌드마다 백분위를 재계산하면 캐릭터 1명 추가에 전원의 점수가 흔들린다 — 지원자를 런타임에 같은 잣대로 투영하려면 기준선이 불변이어야 한다. 코퍼스 개편 시에만 재산정한다.

5. 엔진 rule-v1 — 수식 명세 lib/engine 소스와 1:1 대응 · 전부 순수 함수

5.1 투영 — 이력서 텍스트 → 18차원 벡터 (parse.js · project.js)

// ① 섹션 분해 — "## 헤더" 단위, 헤더별 가중치 w(sec) w(sec) = 핵심역량 1.5 | 성격강점 1.3 | 기본정보·커뮤니케이션 1.2 | 프로필 1.1 | 면접 0.9 | 기타 1.0 // ② 원점수 — 시드 s의 섹션 내 등장 횟수 count(s, sec), 부분 문자열 매칭 raw(k) = Σ_sec Σ_{s∈seeds(k)} count(s, sec) × w(sec) k = 축 9종 + 직무군 9종 // ③ 결정적 부스트 rawJob(f) += 12 if 「지원 분야」칸 ⊇ f의 시드 rawAxis(a) += 6 if 「핵심 역량」 ### 제목 ⊇ a의 시드 // ④ 커버리지 — 본문 대비 시드 검출 밀도 (품질 지표) coverage = min(1, matchedChars / (totalChars × 0.15)) // ⑤ 백분위 — 동결된 분포 dist(k) 대비. raw 0은 '미검출'로 0 유지 v(k) = 0 if raw(k) = 0 = round( (lt + 0.5·eq) / n × 100 ) lt = raw보다 작은 수 · eq = 같은 수 · n = 128

5.2 매칭 — 중심화 코사인 근접도 (app.js simPct)

simPct(R, C) = round( 50 × (1 + cosθ) ) ∈ [0, 100] cosθ = Σ_k (R_k−50)(C_k−50) / ( ‖R−50‖ · ‖C−50‖ ) k = 18차원 전체 (50 중심화) 후보 = simPct 내림차순 상위 5명 (동률은 id 사전순 — 결정적) 신뢰도(1·2위 격차 gap): gap ≥ 8 높음 · gap ≥ 4 중간 · 그 외 낮음 // 128명 코퍼스에서 낮음은 정상 // 팀 일괄 치환 — 선택 순서대로, top1 선점 시 차순위 강하. 한 캐릭터는 팀에 1명만

5.3 관계 원점수 — rawComponents(A, B) (relation.js)

// 상보량 — 상대의 약한 축(<50)을 자기 우위로 채워 주는 양. W_DISC = 축별 변별 가중치 coverA = Σ_{ax: B[ax]<50} W_DISC[ax] · max(0, A[ax] − B[ax]) (coverB 대칭) synRaw = 2·min(coverA, coverB) + 0.5·|coverA − coverB| // 상호 보완 > 일방 보완 // 마찰 성분 ① 실행 속도차 — 격차가 트리거, 느린 쪽의 신중함이 증폭 pace = |A.execution − B.execution| × (느린 쪽의 (detail_qa + structuring)/2) / 100 // 마찰 성분 ② 역할 중복 — "같은 일을(roleSim) 같은 방식으로(axisSim)". 이진 판정은 폐기(97.7% 오탐) axisSim = 1 − ‖A.axis − B.axis‖₂ / (√9 × 100) // 유클리드 정규화 roleSim = cos(A.jobVector, B.jobVector) // 직무군 9차원 코사인 overlap = roleSim × axisSim × 100 overlapExcess = max(0, (overlap − p80) / (100 − p80)) × 100 // 코퍼스 p80 초과분만 마찰로 계상 // 마찰 성분 ③④ — 양쪽 모두 약할 때만 발생 (곱 구조) coordGap = max(0, 50−A.coordination) · max(0, 50−B.coordination) / 50 (commGap 동형) fricRaw = 0.45·pace + 0.30·overlapExcess + 0.15·coordGap + 0.10·commGap // 성장 이득 — 내 약한 축(<50)에서 상대 우위만큼. W_LEARN = 축별 학습 가중치 gainAB = Σ_{ax: A[ax]<50} W_LEARN[ax] · max(0, B[ax] − A[ax]) // A가 B에게 배움 (gainBA 대칭)

5.4 스케일·성장 게이트·배치 (computeRelation)

// p95 스케일 — calibration.pairScalers. clamp = [0,100] 반올림 시너지 level = clamp( synRaw / synergyP95 × 100 ) 마찰 risk = clamp( fricRaw / frictionP95 × 100 ) // 성장 — 마찰 게이트: 마찰이 높은 상대에게서는 배우기 어렵다 gate = 1 − risk/100 growthAB = round( clamp(gainAB / growthP95 × 100) × gate ) (growthBA 대칭) potential = max(growthAB, growthBA) direction = 'a←b' if growthAB − growthBA > 15 | 'b←a' if 역방향 > 15 | 'mutual' // 배치 — 직무군 인접성 테이블 + 관계 보정 base = 45 동일 직무군(역할 중복 주의) | 80 인접 쌍* | 65 ops_pm 결합 | 55 원거리 fit = clamp( base + 0.3·시너지 − 0.3·마찰 ) * 인접 7쌍: research_ux–content_editorial · content_editorial–design_craft · research_ux–data_analytics · merch_retail–brand_gtm · brand_gtm–people_cx · brand_gtm–content_editorial · data_analytics–ops_pm

5.5 종합 점수·관계 분류

score = clamp( 50 + 0.5·시너지 − 0.5·마찰 + 0.2·(fit − 50) ) 분류 (우선순위 순): 시너지 ≥55 ∧ 마찰 ≥55 → 상보 (고긴장 — 마찰로 묻지 않음) 마찰 ≥60 → 마찰 마찰 40~59 → 주의 시너지 ≥60 → 시너지 시너지 ≥40 → 상보 그 외 → 중립

5.6 팀 진단 — diagnoseTeam(members) (team.js — 전부 computeRelation 위의 쿼리)

pairs = C(k,2) 전수 // 팀 상한 9명 = 36쌍 (사람이 읽는 한계) warnings = {마찰 ≥60} · cautions = {40~59} · highlights = {시너지 ≥60} growthEdges = {direction ≠ mutual ∧ potential ≥ 25} // teacher → learner coverage(ax) = max_{m∈팀} m[ax] (보유자 표기) · holes = {coverage < 50} teamScore = clamp( avg(score) − 4 × |holes| )

5.7 팀장 적합도 — pickLead

// leadership 축이 없으므로(코퍼스에 리더십 어휘 부재) 관계 그래프에서 파생한다 lead(m) = 0.35·(100 − 팀내평균마찰) + 0.25·teacher비율(%) + 0.25·(조율+소통)/2 + 0.15·운영일정 // teacher비율 = 성장 엣지(≥25, 비상호)에서 가르치는 쪽인 비율

5.8 팀 구성 최적화 — composeTeam({pool, k, preset, locked})

J(T) = w_s·avg(시너지) − w_f·avg(마찰) + w_g·avg(성장) + w_c·축커버리지(%) // 축커버리지 = 팀 내 누군가 ≥60인 축의 비율 프리셋: w_s w_f w_g w_c stable(안정) 0.30 0.50 0.05 0.15 balanced(균형) 0.30 0.30 0.20 0.20 growth(성장) 0.20 0.15 0.45 0.20 알고리즘 (결정적 — 타이브레이크 고정): ① 시드: locked 있으면 그것부터 · 없으면 J 최고 쌍 beam=6개 ② greedy: J를 최대화하는 후보를 1명씩 추가 (k명까지) ③ swap 개선: 비locked 멤버 ↔ 풀 후보 교환, 개선 없을 때까지 ≤4라운드 ④ beam 중 최고 J 채택 → {team, J, diagnosis, leadRanking}

8. 빌드·배포 파이프라인

# 자산이 바뀌었을 때 (순서 고정)
app\.venv\Scripts\python scripts\build-thumbs.py   # ① 사진 썸네일 — char_make → demo/thumbs (증분, --force 전체)
node scripts\build-demo.js                          # ② engine.js + data.js 번들 (썸네일 경로 우선 참조)
powershell -ExecutionPolicy Bypass -File app\build-exe.ps1   # ③ exe (PyInstaller --onefile --windowed)
  • build-thumbs.py: 128명 × 7룩 PNG → 360px WebP q78 · 896장 ≈7.5MB. 썸네일이 없으면 데모는 원본 상대경로 → 이니셜 아바타로 자동 강등
  • build-demo.js: lib/engine 번들 + 데이터 번들. 빌드 시 전수 검증 — 축 제목 예시·지원 분야 예문이 실제 시드를 포함하는지, 이력서·페르소나·사진 누락 0인지 확인하고 로그로 보고
  • build-exe.ps1: --add-data demo로 데모 자산 전체 동봉 → 단일 exe 22.7MB. 배포 구성은 release/ResumeAnalyze-v{버전}-{날짜}/ = exe + 배포안내.txt + 동명 zip
생성물 수정 금지 — engine.js·data.js·keywords-v1.md는 재빌드로만 바꾼다. 시드가 바뀌면 재빌드만으로 사전·검사기·통계가 전부 동기화된다.

11. 한계·고지

  • 출력은 키워드 기반 성향 근접도다 — 이력서에 쓴 단어가 곧 신호이고, 안 쓴 것은 0(미검출)이다. 짧은 이력서(600자 미만)는 관계 계산까지 함께 흔들린다
  • 모든 값은 코퍼스 128명 안의 상대값 — 절대 점수·타 코퍼스 비교 불가
  • p95 스케일 포화로 특정 인물(예: 이유나)이 시너지·마찰 순위를 동시 지배하는 아웃라이어가 존재한다 — 코퍼스 검수 대상
  • 관계 사전계산 설계(relations.json)는 폐기됨 — 온디맨드 순수 함수가 현행이다
  • composeTeam은 그리디+스왑 휴리스틱이다 — 전역 최적해 보장 없음 (beam 시드 6개로 국소해 완화)
이 도구는 대화의 시작점을 제공한다. 역량 평가·인성 검사·채용 판정이 아니며, 최종 판단은 사람이 한다. 캐릭터·이력서는 전원 가상 인물이다.
