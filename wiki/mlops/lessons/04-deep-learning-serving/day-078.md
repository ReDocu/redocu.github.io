## ① 학습 목표

이 레슨을 마치면 이렇게 할 수 있습니다.

- `nn.Linear` 가 어제 만든 `w·x + b` 의 부품화임을 검산으로 확인할 수 있다.
- 활성화 함수가 왜 필요한지("직선을 꺾는다") 설명할 수 있다.
- `nn.Module` 로 MLP를 정의하고, **optimizer**로 학습 루프를 완성할 수 있다.
- 신경망을 낯익은 문제(내일 나쁨 분류)에 학습시켜 **로지스틱 회귀와 정면 비교**할 수 있다.

---

## ② 왜 필요한가

어제 파라미터 2개(w, b)를 손으로 갱신했습니다. 신경망은 파라미터가 수백~수백만 개입니다.
`w1 -= lr * w1.grad` 를 수백만 줄 쓸 수는 없으니, 두 가지 포장이 필요합니다.

| 포장 | 하는 일 |
|---|---|
| **nn.Module** | 파라미터 덩어리(레이어)를 부품으로 만들고, 전체 목록을 자동 관리 |
| **optimizer** | "모든 파라미터에 대해 갱신+초기화"를 두 줄로 |

오늘 이 포장을 씌우면, 어제의 5단계 루프가 **어떤 크기의 모델에도 통하는 표준 골격**이 됩니다.

그리고 첫 신경망의 상대는 낯익은 문제로 정했습니다 — "내일 나쁨" 분류. 챔피언은
[Day 057](../03-machine-learning/day-057.md)의 로지스틱 회귀(AUC 0.818)입니다.
897개 파라미터의 신경망이 11개 파라미터의 로지스틱을 이길 수 있을까요?
결과보다 중요한 것은, 오늘부터 여러분이 **그 실험을 직접 설계할 수 있게 된다**는 것입니다.

---

## ③ 개념 설명

### 신경망 = 선형 + 꺾기의 반복

```
입력(10) ─ Linear(10→32) ─ ReLU ─ Linear(32→16) ─ ReLU ─ Linear(16→1) ─ 점수
              살펴 섞기        꺾기      다시 섞기       꺾기       요약
```

- **Linear(선형층)**: `입력 @ W.T + b`. 어제 손으로 만든 그것 — 특성들을 가중합으로 섞습니다.
- **활성화(ReLU 등)**: 음수를 0으로 꺾는 등의 **비선형** 변형.

**왜 꺾어야 하나?** 선형을 아무리 쌓아도 선형입니다 (`W₂(W₁x) = (W₂W₁)x` — 행렬 하나로 접힘).
사이사이를 꺾어 줘야 층을 쌓는 의미가 생기고, 그래야 [Day 059](../03-machine-learning/day-059.md)에서
트리가 그리던 꺾인 경계 같은 복잡한 모양을 배울 수 있습니다.

| 활성화 | 모양 | 용도 |
|---|---|---|
| **ReLU** | 음수→0, 양수 그대로 | 은닉층의 기본값 (싸고 잘 됨) |
| Sigmoid | 아무 값→(0,1) | **출력**을 확률로 (로지스틱의 그 함수, [Day 056](../03-machine-learning/day-056.md)) |

### nn.Module — 모델의 표준 서식

```python
class MLP(nn.Module):
    def __init__(self, ...):    # 부품 선언 (레이어들)
        super().__init__()
        ...
    def forward(self, x):       # 부품 연결 (데이터가 흐르는 길)
        ...
```

`__init__` 에서 선언한 레이어의 파라미터는 자동으로 `requires_grad=True` 가 되고
`model.parameters()` 로 한 번에 열람됩니다 — optimizer가 이 목록을 받아 갑니다.

### optimizer와 손실 함수 — 5단계의 부품 교체

| 어제 (수동) | 오늘 (표준) |
|---|---|
| `w -= lr * w.grad` (파라미터마다) | `optimizer.step()` |
| `w.grad.zero_()` (파라미터마다) | `optimizer.zero_grad()` |
| `((pred - y) ** 2).mean()` | `nn.MSELoss()` (회귀) / `nn.BCEWithLogitsLoss()` (이진 분류) |
| 순수 경사하강 | **Adam** — 파라미터별로 보폭을 자동 조절하는 개량판 (기본 선택) |

`BCEWithLogitsLoss` 는 "시그모이드 + 이진 크로스엔트로피"를 한 덩이로 합친 손실입니다.
모델은 시그모이드 **전의 점수(로짓)** 를 출력하고, 확률이 필요할 때만 `torch.sigmoid` 를
씌웁니다 — 수치 안정성 때문의 표준 관행입니다.

### Step 1. nn.Linear 검산 — 마법이 아님을 확인 (1교시)

```python
# day078_mlp.py — nn.Module: 첫 신경망
import numpy as np
import pandas as pd
import torch
import torch.nn as nn
from sklearn.metrics import roc_auc_score

torch.manual_seed(42)

print("== A. nn.Linear = 어제 만든 w·x+b 를 부품으로 ==")
layer = nn.Linear(in_features=3, out_features=2)
x = torch.tensor([[1.0, 2.0, 3.0]])
out = layer(x)
manual = x @ layer.weight.T + layer.bias
print(f"layer(x)          = {out.detach().numpy().round(4)}")
print(f"x @ W.T + b (수동) = {manual.detach().numpy().round(4)}")
print(f"같은가? {torch.allclose(out, manual)}")
print(f"파라미터: weight {tuple(layer.weight.shape)} + bias {tuple(layer.bias.shape)} = {3*2+2}개 (자동으로 requires_grad=True)")
```

실행 결과:

```
== A. nn.Linear = 어제 만든 w·x+b 를 부품으로 ==
layer(x)          = [[0.713  0.9659]]
x @ W.T + b (수동) = [[0.713  0.9659]]
같은가? True
파라미터: weight (2, 3) + bias (2,) = 8개 (자동으로 requires_grad=True)
```

`nn.Linear(3, 2)` 는 [Day 076](day-076.md)의 행렬곱 + 브로드캐스팅 덧셈, 그 이상도 이하도
아닙니다. 다만 W와 b가 **관리되는 파라미터**로 등록된다는 것이 부품화의 핵심입니다.

### Step 3. MLP 조립 (3교시)

```python
print("\n== C. nn.Module로 MLP 조립 ==")
class MLP(nn.Module):
    def __init__(self, n_in):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(n_in, 32), nn.ReLU(),
            nn.Linear(32, 16), nn.ReLU(),
            nn.Linear(16, 1),              # 출력 1개 = '나쁨'의 점수(로짓)
        )

    def forward(self, x):
        return self.net(x).squeeze(1)      # (배치,1) → (배치,)  ← 어제 ⑤의 함정 예방

model = MLP(10)
print(model)
n_params = sum(p.numel() for p in model.parameters())
print(f"학습할 파라미터: {n_params}개")
```

실행 결과:

```
== C. nn.Module로 MLP 조립 ==
MLP(
  (net): Sequential(
    (0): Linear(in_features=10, out_features=32, bias=True)
    (1): ReLU()
    (2): Linear(in_features=32, out_features=16, bias=True)
    (3): ReLU()
    (4): Linear(in_features=16, out_features=1, bias=True)
  )
)
학습할 파라미터: 897개
```

파라미터 897개 = (10×32+32) + (32×16+16) + (16×1+1). 손계산으로 검산해 보세요 —
"이 모델은 몇 개를 배우는가"를 항상 알고 있어야 [Day 081](day-081.md)의 과적합 논의가 섭니다.
`forward` 끝의 `squeeze(1)` 은 어제 ⑤에서 예고한 (n,1)/(n,) 브로드캐스팅 사고의 예방주사입니다.

### Step 4. 데이터 준비 — 배운 원칙 그대로 (4교시)

```python
print("\n== D. 데이터 준비 (Day 052의 시간 분리 그대로) ==")
df = pd.read_csv("data/air_daily.csv", parse_dates=["date"])
F10 = ["pm10", "pm25", "o3", "no2", "co", "so2", "temp", "humidity", "wind_speed", "precip"]
d = df.dropna(subset=F10).copy()
d["bad_next"] = (d.pm25_next >= 36).astype(np.float32)
tr = d[d.date < "2026-01-01"]; te = d[d.date >= "2026-01-01"]

mu = tr[F10].mean(); sigma = tr[F10].std()          # 표준화 — 어제의 교훈. fit은 train에만!
Xtr = torch.tensor(((tr[F10] - mu) / sigma).to_numpy(), dtype=torch.float32)
Xte = torch.tensor(((te[F10] - mu) / sigma).to_numpy(), dtype=torch.float32)
ytr = torch.tensor(tr.bad_next.to_numpy())
yte_np = te.bad_next.to_numpy()
print(f"train {len(Xtr)} / test {len(Xte)} · 나쁨 비율 train {ytr.mean():.3f}")
```

실행 결과:

```
== D. 데이터 준비 (Day 052의 시간 분리 그대로) ==
train 2629 / test 868 · 나쁨 비율 train 0.153
```

도구가 PyTorch로 바뀌어도 원칙은 한 글자도 안 바뀝니다: **시간 분리**([Day 052](../03-machine-learning/day-052.md)),
**표준화 통계는 train으로만**([Day 052](../03-machine-learning/day-052.md) 실험 4), 그리고 어제 배운
**경사하강에는 표준화 필수**가 여기서 합류합니다.

### Step 5. 학습 — 5단계, 부품만 교체 (5~6교시)

```python
print("\n== E. 학습 — 어제의 5단계, 부품만 교체 ==")
model = MLP(10)
loss_fn = nn.BCEWithLogitsLoss()                    # 이진 분류용 손실 (시그모이드 내장)
optimizer = torch.optim.Adam(model.parameters(), lr=0.01)

for epoch in range(1, 201):
    logits = model(Xtr)              # ① 순전파
    loss = loss_fn(logits, ytr)      # ② 손실
    loss.backward()                  # ③ 역전파
    optimizer.step()                 # ④ 갱신 (전 파라미터 한 번에)
    optimizer.zero_grad()            # ⑤ 초기화
    if epoch in (1, 20, 50, 100, 200):
        with torch.no_grad():
            auc = roc_auc_score(yte_np, torch.sigmoid(model(Xte)).numpy())
        print(f"  epoch {epoch:>3}: train loss {loss.item():.4f} · test AUC {auc:.3f}")
```

실행 결과:

```
== E. 학습 — 어제의 5단계, 부품만 교체 ==
  epoch   1: train loss 0.6223 · test AUC 0.465
  epoch  20: train loss 0.2576 · test AUC 0.799
  epoch  50: train loss 0.2305 · test AUC 0.821
  epoch 100: train loss 0.2111 · test AUC 0.815
  epoch 200: train loss 0.1751 · test AUC 0.806
```

이 다섯 줄의 로그에 이번 주의 다음 이야기가 전부 들어 있습니다.

| 관찰 | 뜻 |
|---|---|
| epoch 1: AUC 0.465 | 초기 모델은 동전 던지기 이하 — 무작위 초기화니까 당연 |
| epoch 50: **0.821 정점** | 로지스틱(0.818)을 순간적으로 넘어섬 |
| epoch 100~200: 0.815 → 0.806 | **train loss는 계속 내려가는데 test는 후퇴** — 과적합이 진행 중 |

train loss만 보면 학습은 "잘 되고" 있습니다. 하지만 50 epoch 이후의 학습은 노이즈 암기입니다.
"그럼 50에서 멈췄어야 하는데, **돌려 보기 전에 어떻게 아나?**" — 이 질문이 [Day 081](day-081.md)
(검증 세트 감시와 조기 종료)의 주제입니다. 지금은 문제의식만 정확히 가져가세요.

## ⑤ 자주 하는 실수

### 손실 함수와 출력의 궁합을 틀림

**증상** — `BCEWithLogitsLoss` 에 시그모이드를 **씌운** 출력을 넣음 — 에러 없이 학습이 느리고 이상함.
**원인** — 이 손실은 내부에 시그모이드가 있어, 확률을 또 넣으면 이중 시그모이드가 됩니다.
**해결** — 모델은 로짓(날 점수)을 출력, `BCEWithLogitsLoss` 에 그대로. 확률이 필요한 곳(평가·서빙)에서만 `torch.sigmoid`.

### 타깃 dtype이 Long이라 죽음

```
RuntimeError: result type Float can't be cast to the desired output type Long
```

**원인** — `BCEWithLogitsLoss` 의 타깃은 **float**(0.0/1.0)이어야 하는데 정수 텐서를 넣었습니다.
**해결** — Step 4처럼 `astype(np.float32)` 로 만들거나 `ytr.float()`. (반대로 다중 분류의 `CrossEntropyLoss` 는 Long 타깃을 요구합니다 — 손실마다 계약이 다릅니다.)

### 평가를 no_grad 없이 함

**증상** — 에러는 없는데 평가 도중 메모리가 자꾸 늘고 느림.
**원인** — 평가용 순전파도 기본으로 연산 기록(미분 준비)을 쌓습니다.
**해결** — 평가·추론은 `with torch.no_grad():` 로 감쌉니다. 서빙(W20)에서는 이게 성능 문제로 직결됩니다.

### optimizer에 파라미터를 안 넘기거나 다른 모델 것을 넘김

**증상** — loss가 몇 epoch이 지나도 꿈쩍 안 함.
**원인** — `Adam(model.parameters())` 에서 model을 새로 만들고 optimizer는 옛 모델을 물고 있는 경우 (오늘 Step 5처럼 model을 재생성했다면 optimizer도 재생성!).
**해결** — 모델을 새로 만들면 optimizer도 같이. "model → optimizer" 생성 순서를 한 덩이로 붙여 두세요.

### train loss만 보고 "학습 잘 된다"고 판단

**증상** — Step 5에서 봤듯 train loss는 0.62 → 0.18로 순항 — 그동안 test는 0.821 → 0.806으로 후퇴.
**원인** — train loss는 암기로도 내려갑니다 ([Day 052](../03-machine-learning/day-052.md)의 문제집 점수).
**해결** — 학습 중에도 **본 적 없는 데이터의 지표**를 함께 찍으세요. 그 감시 체계를 [Day 081](day-081.md)에서 표준화합니다.
