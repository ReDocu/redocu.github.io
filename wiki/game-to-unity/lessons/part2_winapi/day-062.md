## 3. 개념

### 3-1. BFS가 실패하는 이유

**왜 필요한가** — 왜 새 알고리즘이 필요한지 정확히 안다.

```
   BFS 의 전제

   "먼저 방문한 칸이 항상 더 가깝다"

   ★ 이건 모든 간선 비용이 같을 때만 성립한다
```

```
   반례

        A ──1── B
        │       │
        3       1
        │       │
        C ──1── D

   시작 A, 목표 D

   BFS:  A → C (거리 1)  →  D (거리 2)     ✘ 실제 비용 4
         A → B (거리 1)  →  D (이미 방문)  ← 갱신 안 함

   실제 최단:  A → B → D  =  1 + 1  =  2   ✔
```

```
   ★ BFS 는 "칸 수"를 세고, 다익스트라는 "비용"을 센다
```

### 3-2. 다익스트라 알고리즘

**왜 필요한가** — 비용이 다른 그래프의 최단 경로.

```
   ┌──────────────────────────────────────────────────────────┐
   │  핵심 아이디어                                             │
   │                                                           │
   │  "지금까지 알려진 비용이 가장 작은 노드부터 확정한다"      │
   │                                                           │
   │  ① 모든 노드의 비용을 무한대로 초기화                     │
   │  ② 시작 노드 비용 = 0                                     │
   │  ③ 아직 확정 안 된 노드 중 비용이 가장 작은 것을 고른다   │
   │  ④ 그 노드를 확정하고, 이웃의 비용을 갱신한다             │
   │  ⑤ ③~④를 반복                                            │
   └──────────────────────────────────────────────────────────┘
```

```
   ★ BFS 와의 차이

   BFS:        큐에서 순서대로 꺼낸다          (FIFO)
   다익스트라:  비용이 가장 작은 것을 꺼낸다   (우선순위 큐)

   BFS:        한 번 방문하면 끝
   다익스트라:  더 싼 경로를 찾으면 갱신한다   ★
```

### 3-3. 동작 과정

**왜 필요한가** — 표로 추적하면 이해가 확실해진다.

```
   맵 (숫자 = 그 칸에 들어가는 비용)

        c0   c1   c2
   r0    1    2    1
   r1    1  [S]    3
   r2    1    1    1

   시작 = (1, r1),  4방향
```

| 단계 | 확정 노드 | 비용 | 열린 목록 (비용) |
|:--:|:--:|:--:|---|
| 0 | — | — | (1,1)=0 |
| 1 | (1,1) | 0 | (1,0)=2, (0,1)=1, (2,1)=3, (1,2)=1 |
| 2 | (0,1) | 1 | (1,0)=2, (2,1)=3, (1,2)=1, (0,0)=2, (0,2)=2 |
| 3 | (1,2) | 1 | (1,0)=2, (2,1)=3, (0,0)=2, (0,2)=2, (2,2)=2 |
| 4 | (1,0) | 2 | (2,1)=3, (0,0)=2, (0,2)=2, (2,2)=2, (2,0)=3 |
| 5 | (0,0) | 2 | (2,1)=3, (0,2)=2, (2,2)=2, (2,0)=3 |
| 6 | (0,2) | 2 | (2,1)=3, (2,2)=2, (2,0)=3 |
| 7 | (2,2) | 2 | (2,1)=**3**, (2,0)=3 |
| 8 | (2,0) | 3 | (2,1)=3 |
| 9 | (2,1) | 3 | — |

```
   ★ (2,1) 의 비용에 주목

   직접 가면:  (1,1) → (2,1)  =  3
   돌아가면:   (1,1) → (1,2) → (2,2) → (2,1)  =  1 + 1 + 3 = 5

   → 직접 가는 게 싸다. 3으로 확정
```

**갱신(relaxation)이 일어나는 경우**

```
        A ──1── B ──1── D
        │               │
        5───────────────┘

   ① A 확정 (0)
      → B = 1,  D = 5

   ② B 확정 (1)
      → D 갱신!  1 + 1 = 2  <  5     ★ 여기가 갱신
      → D = 2

   ③ D 확정 (2)
```

### 3-4. 우선순위 큐

**왜 필요한가** — "비용이 가장 작은 노드"를 빨리 찾아야 한다.

```
   방법 ① 선형 탐색

   매번 모든 노드를 훑어 최소를 찾는다
   → O(V) × V번 = O(V²)

   맵 100×100 = 10,000 노드
   → 100,000,000 회 비교      ✘ 너무 느리다


   방법 ② 우선순위 큐 (힙)

   최소값 꺼내기 O(log V)
   → O((V + E) log V)

   맵 100×100 → 약 200,000 회      ✔
```

**간단한 이진 힙 구현**

```cpp
struct PQNode
{
    int col, row;
    int cost;
};

class PriorityQueue
{
public:
    void Init(int capacity)
    {
        m_data = new PQNode[capacity + 1];     // 1-based
        m_capacity = capacity;
        m_size = 0;
    }

    void Clear() { m_size = 0; }
    bool IsEmpty() const { return m_size == 0; }

    void Push(PQNode n)
    {
        if (m_size >= m_capacity) return;

        m_data[++m_size] = n;

        // 위로 올리기 (sift up)
        int i = m_size;
        while (i > 1 && m_data[i / 2].cost > m_data[i].cost)
        {
            Swap(m_data[i / 2], m_data[i]);
            i /= 2;
        }

        if (m_size > m_maxUsed) m_maxUsed = m_size;
    }

    PQNode Pop()
    {
        PQNode top = m_data[1];

        m_data[1] = m_data[m_size--];

        // 아래로 내리기 (sift down)
        int i = 1;
        while (true)
        {
            int left = i * 2, right = i * 2 + 1, smallest = i;

            if (left  <= m_size && m_data[left].cost  < m_data[smallest].cost) smallest = left;
            if (right <= m_size && m_data[right].cost < m_data[smallest].cost) smallest = right;

            if (smallest == i) break;

            Swap(m_data[i], m_data[smallest]);
            i = smallest;
        }

        return top;
    }

private:
    static void Swap(PQNode& a, PQNode& b) { PQNode t = a; a = b; b = t; }

    PQNode* m_data = nullptr;
    int     m_capacity = 0, m_size = 0, m_maxUsed = 0;
};
```

```
   이진 힙 구조 (배열로 표현)

   인덱스:  1
           / \
          2   3
         / \ / \
        4  5 6  7

   부모 = i / 2
   왼쪽 자식 = i * 2
   오른쪽 자식 = i * 2 + 1

   ★ 부모가 항상 자식보다 작다 (최소 힙)
   ★ 루트(인덱스 1)가 항상 최소값
```

> **C++ 표준 라이브러리를 쓴다면** `std::priority_queue`가 있다.
> **이 과정에서는 원리를 보기 위해 직접 만든다.**

### 3-5. 다익스트라 구현

**왜 필요한가** — 오늘의 핵심 코드.

```cpp
void PathFinder::CalcMoveRangeDijkstra(const TileMap& map,
                                       int startCol, int startRow,
                                       int maxCost)
{
    Reset();
    m_visitedCount = 0;
    m_updateCount  = 0;

    PathNode* start = At(startCol, startRow);
    if (!start) return;

    start->cost     = 0;
    start->visited  = false;                   // ★ 아직 확정 아님

    m_pq.Clear();
    m_pq.Push({ startCol, startRow, 0 });

    const int dc[] = { 0, 0, -1, 1 };
    const int dr[] = { -1, 1, 0, 0 };

    while (!m_pq.IsEmpty())
    {
        PQNode cur = m_pq.Pop();

        PathNode* curNode = At(cur.col, cur.row);

        // ★ 이미 확정됐거나, 오래된 항목이면 건너뛴다
        if (curNode->visited) continue;
        if (cur.cost > curNode->cost) continue;

        curNode->visited = true;               // 확정
        m_visitedCount++;

        if (cur.cost >= maxCost) continue;     // 이동력 초과

        for (int i = 0; i < 4; i++)
        {
            int nc = cur.col + dc[i];
            int nr = cur.row + dr[i];

            if (nc < 0 || nc >= m_cols || nr < 0 || nr >= m_rows) continue;

            PathNode* next = At(nc, nr);
            if (next->visited) continue;       // 이미 확정

            // ★ 이동 비용
            const Tile* t = map.At(1, nc, nr);
            int moveCost = GetMoveCost(t);

            if (moveCost < 0) continue;        // 통과 불가

            int newCost = cur.cost + moveCost;

            if (newCost > maxCost) continue;   // 이동력 초과

            // ★ 갱신 (relaxation)
            if (newCost < next->cost)
            {
                next->cost      = newCost;
                next->parentCol = cur.col;
                next->parentRow = cur.row;

                m_pq.Push({ nc, nr, newCost });
                m_updateCount++;
            }
        }
    }
}
```

```cpp
void PathFinder::Reset()
{
    for (int i = 0; i < m_cols * m_rows; i++)
    {
        m_nodes[i].cost      = INT_MAX;        // ★ 무한대
        m_nodes[i].visited   = false;
        m_nodes[i].parentCol = -1;
        m_nodes[i].parentRow = -1;
    }
}
```

### 3-6. ⚠️ 지연 삭제 (lazy deletion)

**왜 필요한가** — 우선순위 큐에 같은 노드가 여러 번 들어간다.

```
   갱신이 일어나면 큐에 다시 넣는다

   D 의 비용이 5 → 2 로 갱신
   → 큐에 { D, 2 } 를 넣는다
   → 큐에는 { D, 5 } 도 남아 있다      ← 오래된 항목
```

```
   ★ 두 가지 해결책

   ① 큐에서 오래된 항목을 찾아 갱신 (decrease-key)
      → 구현이 복잡하다 (인덱스 관리 필요)

   ② 그냥 두고, 꺼낼 때 무시한다 (lazy deletion)   ★
      → 간단하다. 큐가 좀 커지지만 성능에 큰 영향 없다
```

```cpp
        // 꺼낼 때 검사
        if (curNode->visited) continue;        // 이미 확정된 노드
        if (cur.cost > curNode->cost) continue; // 오래된 항목
```

> **이 두 줄이 없으면 같은 노드를 여러 번 확장해 느려지거나 결과가 틀린다.**

### 3-7. 이동 비용 설계

**왜 필요한가** — 숫자가 게임성을 만든다.

| 지형 | 비용 | 의미 |
|---|:--:|---|
| 평지 | 1 | 기준 |
| 도로 | 1 | (또는 0.5 → 정수로 하려면 전부 2배) |
| 숲 | 2 | 이동 제약 + 은폐 효과 |
| 늪 | 3 | 큰 제약 |
| 산 | 4 | 거의 못 감 |
| 물 | -1 | 통과 불가 (비행 유닛만) |

```
   ★ 비용 비율이 중요하다

   1, 2, 3    →  차이가 명확하다
   1, 1, 2    →  차이가 미미하다
   1, 5, 10   →  숲·늪을 아예 안 간다

   ★ 이동력 3~6 기준으로 1~3 범위가 적당하다
```

```cpp
int GetMoveCostFor(const Tile* t, UnitType type)
{
    if (!t) return -1;

    switch (type)
    {
    case UNIT_INFANTRY:                        // 보병
        if (t->attribute & ATTR_WALL)   return -1;
        if (t->attribute & ATTR_WATER)  return -1;
        if (t->attribute & ATTR_FOREST) return 2;
        return 1;

    case UNIT_CAVALRY:                         // 기병
        if (t->attribute & ATTR_WALL)   return -1;
        if (t->attribute & ATTR_WATER)  return -1;
        if (t->attribute & ATTR_FOREST) return 3;   // ★ 숲에서 불리
        return 1;

    case UNIT_FLYING:                          // 비행
        if (t->attribute & ATTR_WALL)   return -1;
        return 1;                              // ★ 지형 무시

    case UNIT_SHIP:                            // 함선
        if (t->attribute & ATTR_WATER)  return 1;
        return -1;                             // ★ 물에서만
    }

    return 1;
}
```

**왜 필요한가** — 다익스트라가 BFS보다 얼마나 느린지 안다.


```cpp
{
    if (m_pq.IsEmpty()) return false;

    PQNode cur = m_pq.Pop();
    PathNode* curNode = At(cur.col, cur.row);

    if (curNode->visited)       return true;   // 건너뛰기

    if (cur.cost >= m_maxCost) return true;

    // 이웃 확장

    return true;
}
```

### Step 13 — 정확성 검증

```cpp
void TacticsScene::VerifyDijkstra()
{
    // 무작위로 100개 지점을 골라 비용 검증
    int failCount = 0;

    for (int test = 0; test < 100; test++)
    {
        int c = rand() % m_map.GetCols();
        int r = rand() % m_map.GetRows();

        int cost = m_pathFinder.GetCost(c, r);
        if (cost == INT_MAX) continue;

        // 경로를 역추적하며 비용을 다시 더해 본다
        int sum = 0;
        int cc = c, rr = r;

        while (cc != startCol || rr != startRow)
        {
            const Tile* t = m_map.At(1, cc, rr);
            sum += GetMoveCost(t);

            const PathNode* n = m_pathFinder.GetNode(cc, rr);
            int pc = n->parentCol, pr = n->parentRow;

            if (pc < 0) { failCount++; break; }

            cc = pc; rr = pr;
        }

        if (sum != cost)
        {
            DebugLog("[검증 실패] (%d,%d) 저장된 비용 %d, 경로 합 %d\n",
                     c, r, cost, sum);
            failCount++;
        }
    }

    DebugLog("[검증] 100개 중 실패 %d개\n", failCount);
}
```

**✅ 여기까지 실행하면** — 실패 0개가 나와야 한다.

> **비용과 경로가 일치하는지 확인하는 것이 가장 확실한 검증이다.**

## 6. 자주 막히는 곳

| 증상 | 원인 | 해결 |
|---|---|---|
| 결과가 BFS와 같음 | 비용을 항상 1로 | `GetMoveCost` 호출 확인 |
| 비용이 이상함 | 초기값이 0 | `INT_MAX`로 초기화 |
| 오버플로 | `INT_MAX + cost` | 갱신 전에 비교 |
| 무한 루프 | 확정 검사 없음 | `if (visited) continue` |
| 느림 | 지연 삭제 미처리 | `cost > node->cost` 검사 |
| 큐 넘침 | 갱신마다 Push | 용량을 노드 수 × 4 이상 |
| 힙이 정렬 안 됨 | sift up/down 오류 | 테스트로 검증 |
| 경로가 끊김 | `parent` 갱신 누락 | 비용 갱신 시 함께 |
| 비용과 경로 불일치 | 갱신 시 parent 미갱신 | 검증 테스트로 확인 |

## 7. 정리

### 오늘 배운 것

| 개념 | 한 줄 요약 |
|---|---|
| BFS의 한계 | 모든 간선 비용이 같을 때만 정확 |
| **다익스트라** | 비용이 가장 작은 노드부터 확정 |
| **우선순위 큐** | 최소값 꺼내기 O(log V). 이진 힙 |
| **갱신(relaxation)** | 더 싼 경로를 찾으면 비용을 낮춘다 |
| **지연 삭제** | 오래된 큐 항목은 꺼낼 때 무시 |
| 이동 비용 설계 | 1~3 범위가 적당. 비율이 게임성을 만든다 |
| 유닛 타입별 비용 | SRPG 전략성의 핵심 |
| 성능 | BFS의 약 2배. 정확성을 위해 지불 |

### BFS vs 다익스트라

| | BFS | 다익스트라 |
|---|---|---|
| 자료구조 | 큐 (FIFO) | 우선순위 큐 |
| 꺼내는 순서 | 넣은 순서 | **비용이 작은 것부터** |
| 갱신 | 없음 | **있음** |
| 비용 | 전부 1 | 다를 수 있다 |
| 복잡도 | O(V+E) | O((V+E) log V) |
