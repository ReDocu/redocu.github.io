### 이상치를 잘못 다루면 벌어지는 두 가지 실패

**실패 ① — 그대로 두기**

```
[Day 106] 이상치 2%만 있어도 MSE 학습이 망가짐
[Day 111] 피어슨 상관이 0.02로 나와 유용한 특성을 버릴 뻔함
```

**실패 ② — 무조건 제거하기**

```
전자상거래 매출 예측 모델
→ "블랙프라이데이 매출은 이상치"라며 제거
→ 모델이 블랙프라이데이를 영원히 예측 못 함
→ 정작 가장 중요한 날의 예측이 불가능
```

**두 번째 실패가 더 위험합니다.** 성능 지표에는 안 나타나기 때문입니다.

### "이상치를 제거했습니다"는 답이 아닙니다

발표에서 이런 대화가 반드시 나옵니다.

```
발표자: "IQR 기준으로 이상치 1,200건을 제거했습니다."
심사자: "그 1,200건이 무엇이었습니까?"
발표자: "...음, 값이 큰 것들이요."
심사자: "그중에 진짜 비싼 게임은 없었나요?"
```

**이상치 처리는 통계 작업이 아니라 도메인 판단입니다.**

```
"IQR 밖이니까 이상치"  →  ✗ 통계는 후보를 줄 뿐
"한 가구에 1,243명은 불가능"  →  ✓ 도메인이 판정
"50만 원짜리 게임은 실제로 존재"  →  ✓ 도메인이 판정
```

### 오늘 하는 일

```
① 이상치를 두 종류로 나눈다        오류 vs 극단값
② 세 가지 방법으로 탐지한다         IQR · z-score · 다변량
③ 네 가지 처리 방식을 실험한다      제거 · 절단 · 플래그 · 보존
④ 성능으로 비교해 결정한다
⑤ 결정 근거를 문서로 남긴다        ← 오늘의 산출물
```

## ③ 개념 설명

### 이상치의 두 얼굴

| | 입력 오류 (error) | 실제 극단값 (genuine) |
|---|---|---|
| 정체 | 측정·입력·처리 과정의 실수 | **진짜로 그런 값** |
| 예시 | 나이 999세, 배송시간 -12분 | 블랙프라이데이 매출, 한정판 가격 |
| 재현성 | 다시 측정하면 안 나옴 | **다시 측정해도 나옴** |
| 처리 | **제거 또는 수정** | **보존하거나 신중히 처리** |
| 판별 방법 | 물리적·논리적으로 불가능한가 | 드물지만 가능한가 |

**판별 질문 3개**

```
① 이 값이 물리적으로 가능한가?
     불가능 → 오류 (나이 999세)

② 이 값이 우리 도메인에서 발생할 수 있는가?
     불가능 → 오류 (게임 가격 -5,000원)

③ 이 값이 예측 대상에 실제로 포함되는가?
     포함  → 극단값. 보존 검토 (한정판 50만 원 게임)
     제외  → 범위 밖. 제거 정당 (기업용 소프트웨어)
```

> **③이 가장 중요합니다.** "이 모델이 무엇을 예측해야 하는가"로 되돌아가는 질문입니다.
> [Day 126](day-126.md)의 문제 정의서에 이 범위를 적어 두면 오늘의 판단이 쉬워집니다.

### 탐지 방법 ① IQR

```
Q1 = 25% 분위수    Q3 = 75% 분위수    IQR = Q3 - Q1

하한 = Q1 - 1.5 × IQR
상한 = Q3 + 1.5 × IQR
```

```
        하한                Q1    중앙값    Q3                상한
  ────────┼──────────────────┼──────┼──────┼──────────────────┼────────
     이상치            ◄─── 데이터의 50% ───►              이상치
```

| 계수 | 잡히는 범위 | 언제 |
|---|---|---|
| **1.5** | 정규분포에서 약 0.7% | **기본값** |
| 3.0 | 정규분포에서 약 0.0002% | 극단값만 |
| 1.0 | 더 많이 | 매우 보수적으로 걸러야 할 때 |

**장점** — 중앙값과 분위수 기반이라 **이상치 자체에 영향을 덜 받습니다.**

**단점** — **치우친 분포에서 한쪽만 과하게 잡습니다.**

```
가격 데이터 (오른쪽 꼬리)
Q1 = 4,900   Q3 = 29,900   IQR = 25,000
하한 = 4,900 - 37,500 = -32,600     ← 음수. 하한 이상치는 없음
상한 = 29,900 + 37,500 = 67,400     ← 6.7만 원 넘으면 전부 이상치
```

**정상적인 고가 게임이 전부 이상치로 잡힙니다.**

> **해결책** — **로그 변환 후 IQR을 적용**하세요. ([Day 111](day-111.md))
> 분포가 대칭에 가까워지므로 양쪽이 공평하게 잡힙니다.

### 탐지 방법 ② z-score

```
z = (값 - 평균) / 표준편차

|z| > 3  →  이상치
```

| 임계값 | 정규분포에서 |
|---|---|
| 2 | 4.6% |
| **3** | **0.27%** (기본) |
| 3.5 | 0.05% |

**치명적 단점 — 이상치가 평균과 표준편차를 오염시킵니다.**

```
데이터: [10, 12, 11, 13, 10, 12, 5000]

평균 = 722.6      ← 5000 때문에 크게 끌려감
표준편차 = 1885   ← 역시 부풀려짐

5000의 z-score = (5000 - 722.6) / 1885 = 2.27    ← 3 미만! 이상치가 아니라고 나옴
```

**이것을 masking effect (가림 효과)라고 합니다.**

**해결 — Modified z-score (중앙값 기반)**

```
MAD = median(|값 - 중앙값|)
modified_z = 0.6745 × (값 - 중앙값) / MAD

|modified_z| > 3.5  →  이상치
```

```
같은 데이터: [10, 12, 11, 13, 10, 12, 5000]
중앙값 = 12
MAD = 1
5000의 modified_z = 0.6745 × 4988 / 1 = 3,364     ← 확실히 잡힘
```

> **z-score를 쓸 거면 Modified z-score를 쓰세요.** 일반 z-score는 이상치 탐지에 부적합합니다.

### 탐지 방법 비교

| | IQR | z-score | Modified z-score |
|---|---|---|---|
| 기준 | 분위수 | 평균·표준편차 | 중앙값·MAD |
| 이상치에 강한가 | **강함** | **약함** | **매우 강함** |
| 치우친 분포 | 한쪽만 과다 | 한쪽만 과다 | 한쪽만 과다 |
| 계산 | 쉬움 | 쉬움 | 쉬움 |
| 권장 | **기본** | 비권장 | **z-score 대신** |

**세 방법 모두 "치우친 분포"에서 약합니다. → 로그 변환 후 적용하세요.**

### 탐지 방법 ③ 다변량 이상치

**각 특성만 보면 정상인데, 조합이 이상한 경우입니다.**

```
방 개수 3개       →  정상
가격 500만 원     →  정상 (대저택도 있으니)
방 3개 + 500만 원 →  ★ 이상 (조합이 말이 안 됨)
```

```
      가격
       │        ●  ← 다변량 이상치
       │     ····
       │   ······
       │  ········
       │ ·········
       └────────────── 방 개수
```

| 방법 | 원리 | 특징 |
|---|---|---|
| **Isolation Forest** | 무작위 분할로 빨리 고립되면 이상치 | **가장 실용적.** 빠름 |
| Local Outlier Factor | 이웃 대비 밀도가 낮으면 이상치 | 국소 이상치에 강함 |
| Elliptic Envelope | 다변량 정규분포 가정 | 분포 가정이 필요 |
| Mahalanobis 거리 | 공분산을 고려한 거리 | 해석이 명확 |

```python
from sklearn.ensemble import IsolationForest

iso = IsolationForest(contamination=0.05, random_state=42)
labels = iso.fit_predict(X)        # -1이 이상치, 1이 정상
```

| 파라미터 | 의미 |
|---|---|
| `contamination` | **이상치 비율 가정.** 0.01~0.1 |
| `n_estimators` | 트리 개수 (기본 100) |

> ⚠️ **`contamination` 을 정해 줘야 한다는 것이 함정입니다.**
> "이상치가 몇 %인지"를 미리 알아야 하는데, 그걸 알면 탐지가 왜 필요합니까?
> **실무에서는 여러 값으로 돌려 보고 눈으로 확인합니다.**

### ★ 네 가지 처리 옵션

| 옵션 | 코드 | 언제 | 위험 |
|---|---|---|---|
| **① 제거** | `df = df[~mask]` | 명백한 **입력 오류** | 정보 손실. 편향 |
| **② 절단 (clipping)** | `df[c].clip(lo, hi)` | 극단값이 실재하지만 영향을 줄이고 싶을 때 | 값을 왜곡 |
| **③ 플래그 추가** | `df["is_outlier"] = mask` | **모델이 스스로 판단하게** | 특성 증가 |
| **④ 그대로 두기** | (아무것도 안 함) | 극단값이 예측 대상에 포함 | 모델이 끌려감 |

**추가 옵션**

| 옵션 | 설명 |
|---|---|
| **⑤ 변환** | 로그 변환으로 극단값의 영향을 자연스럽게 축소 |
| **⑥ 강건한 모델** | MAE 손실, Huber, 트리 계열 사용 ([Day 106](day-106.md)) |
| **⑦ 별도 모델** | 극단값 집단을 따로 모델링 |

> **⑤와 ⑥이 실무에서 가장 자주 쓰입니다.**
> 데이터를 건드리지 않고 문제를 해결하기 때문입니다.

### 처리 대상: 타깃인가 특성인가

**전혀 다른 문제입니다.**

| | 특성(X)의 이상치 | 타깃(y)의 이상치 |
|---|---|---|
| 영향 | 그 샘플의 예측만 이상 | **손실 함수 전체를 지배** |
| 제거 시 | 그 행이 사라짐 | 그 행이 사라짐 |
| 절단 시 | 입력만 조정 | **★ 정답을 바꾸는 것** — 매우 위험 |
| 권장 | 절단 또는 플래그 | **로그 변환 또는 강건한 손실** |

> ⚠️ **타깃을 절단(clip)하는 것은 신중해야 합니다.**
> "50만 원짜리 게임의 가격을 10만 원으로 바꿔서 학습"하는 것입니다.
> **모델은 50만 원을 영원히 예측하지 못합니다.**

### 정보 손실량 확인

**제거를 결정하기 전에 반드시 계산하세요.**

```python
removed = mask.sum()
print(f"제거 건수: {removed}건 ({removed/len(df)*100:.2f}%)")
print(f"제거된 행의 타깃 평균: {y[mask].mean():.2f} (전체 {y.mean():.2f})")
```

**확인할 것 3가지**

| 확인 | 위험 신호 |
|---|---|
| 제거 비율 | **5% 넘으면 재검토.** 10% 넘으면 방법이 잘못됨 |
| **제거된 행의 타깃 분포** | 특정 구간만 사라지면 **편향** |
| 제거된 행의 특성 | 특정 범주만 사라지면 **그 범주를 못 배움** |

```
[위험한 사례]
IQR로 가격 이상치 제거 → 고가 게임 800건이 전부 사라짐
→ 모델이 "비싼 게임"이라는 개념을 아예 학습 못 함
→ 테스트셋의 고가 게임에서 전부 틀림
```

### 이상치 처리는 학습셋에만?

**중요한 구분이 있습니다.**

| 작업 | 학습셋만 | 전체 |
|---|---|---|
| **행 제거** | **학습셋만** ★ | ✗ |
| 절단 경계 계산 | **학습셋으로 fit** ★ | ✗ |
| 절단 적용 | — | **전체에 transform** |
| 플래그 생성 | 규칙을 학습셋에서 | 전체에 적용 |

```python
# ✓ 올바름
lo, hi = X_train[col].quantile([0.01, 0.99])     # 학습셋으로 경계 계산
X_train[col] = X_train[col].clip(lo, hi)
X_val[col] = X_val[col].clip(lo, hi)             # 같은 경계 적용
X_test[col] = X_test[col].clip(lo, hi)
```

> ⚠️ **검증·테스트셋의 행을 제거하면 안 됩니다.**
> 실제 서비스에서는 이상한 입력도 들어옵니다. **그것도 예측해야 합니다.**
> 평가에서 어려운 샘플을 빼면 **성능이 부풀려집니다.** ([Day 109](day-109.md) 누수)

## ④ 단계별 실습

### Step 1. 이상치 탐지 3종 비교

```python
import numpy as np
import pandas as pd
import matplotlib.pyplot as plt
from sklearn.datasets import fetch_california_housing

SEED = 42
np.random.seed(SEED)
plt.rcParams["figure.figsize"] = (10, 5)
plt.rcParams["axes.grid"] = True
plt.rcParams["grid.alpha"] = 0.3

raw = fetch_california_housing(as_frame=True)
df = raw.frame.copy()
TARGET = "MedHouseVal"
feat_cols = [c for c in df.columns if c != TARGET]


def detect_iqr(s, k=1.5):
    q1, q3 = s.quantile([0.25, 0.75])
    iqr = q3 - q1
    lo, hi = q1 - k * iqr, q3 + k * iqr
    return (s < lo) | (s > hi), lo, hi


def detect_zscore(s, thr=3.0):
    z = (s - s.mean()) / s.std()
    return z.abs() > thr, s.mean() - thr * s.std(), s.mean() + thr * s.std()


def detect_modified_z(s, thr=3.5):
    med = s.median()
    mad = (s - med).abs().median()
    if mad == 0:
        mad = 1e-9
    mz = 0.6745 * (s - med) / mad
    return mz.abs() > thr, med - thr * mad / 0.6745, med + thr * mad / 0.6745


rows = []
for c in feat_cols:
    s = df[c]
    m_iqr, lo_i, hi_i = detect_iqr(s)
    m_z, lo_z, hi_z = detect_zscore(s)
    m_mz, lo_m, hi_m = detect_modified_z(s)
    rows.append({
        "특성": c,
        "중앙값": round(s.median(), 3),
        "최대": round(s.max(), 2),
        "최대/중앙": round(s.max() / s.median(), 1) if s.median() != 0 else np.inf,
        "IQR": f"{m_iqr.sum():,} ({m_iqr.mean()*100:.2f}%)",
        "z-score": f"{m_z.sum():,} ({m_z.mean()*100:.2f}%)",
```

```python
def apply_treatment(Xtr, ytr, Xva, yva, method):
    """★ 경계는 학습셋으로 계산, 행 제거는 학습셋만"""
    Xtr, Xva = Xtr.copy(), Xva.copy()

    if method == "① 보존":
        return Xtr, ytr, Xva, yva

    if method == "② 제거":
        mask = pd.Series(False, index=Xtr.index)
        for c in TREAT:
            m, _, _ = detect_iqr(Xtr[c], k=3.0)      # k=3 (보수적)
            mask |= m
        return Xtr[~mask], ytr[~mask], Xva, yva      # ★ 검증셋은 그대로

    if method == "③ 절단":
        for c in TREAT:
            lo, hi = Xtr[c].quantile([0.005, 0.995])  # ★ 학습셋 기준
            Xtr[c] = Xtr[c].clip(lo, hi)
            Xva[c] = Xva[c].clip(lo, hi)              # 같은 경계
        return Xtr, ytr, Xva, yva

    if method == "④ 플래그":
        for c in TREAT:
            _, lo, hi = detect_iqr(Xtr[c], k=3.0)
            Xtr[f"{c}_out"] = ((Xtr[c] < lo) | (Xtr[c] > hi)).astype(int)
            Xva[f"{c}_out"] = ((Xva[c] < lo) | (Xva[c] > hi)).astype(int)
        return Xtr, ytr, Xva, yva

    if method == "⑤ 로그변환":
        for c in TREAT:
            Xtr[c] = np.log1p(Xtr[c])
            Xva[c] = np.log1p(Xva[c])
        return Xtr, ytr, Xva, yva

    if method == "⑥ 절단+플래그":
        for c in TREAT:
            _, lo3, hi3 = detect_iqr(Xtr[c], k=3.0)
            Xtr[f"{c}_out"] = ((Xtr[c] < lo3) | (Xtr[c] > hi3)).astype(int)
            Xva[f"{c}_out"] = ((Xva[c] < lo3) | (Xva[c] > hi3)).astype(int)
            lo, hi = Xtr[c].quantile([0.005, 0.995])
            Xtr[c] = Xtr[c].clip(lo, hi)
            Xva[c] = Xva[c].clip(lo, hi)
        return Xtr, ytr, Xva, yva

    raise ValueError(method)


def score(yt, p):
    return {"MAE": round(mean_absolute_error(yt, p), 4),
            "RMSE": round(float(np.sqrt(mean_squared_error(yt, p))), 4),
            "R²": round(r2_score(yt, p), 4)}


def train_nn(Xtr, ytr, Xva, yva):
    sc = StandardScaler().fit(Xtr)
    tf.random.set_seed(SEED)
    m = keras.Sequential([
        layers.Input(shape=(Xtr.shape[1],)),
        layers.Dense(128, activation="relu"),
        layers.Dense(64, activation="relu"),
        layers.Dense(1),
    ])
    m.compile(optimizer=keras.optimizers.Adam(1e-3), loss="mse", metrics=["mae"])
    es = keras.callbacks.EarlyStopping(monitor="val_loss", patience=20,
                                       restore_best_weights=True)
    m.fit(sc.transform(Xtr), ytr, validation_data=(sc.transform(Xva), yva),
          epochs=300, batch_size=64, callbacks=[es], verbose=0)
    return m.predict(sc.transform(Xva), verbose=0).ravel()


methods = ["① 보존", "② 제거", "③ 절단", "④ 플래그", "⑤ 로그변환", "⑥ 절단+플래그"]
rows = []

for method in methods:
    Xtr, ytr, Xva, yva = apply_treatment(X_train0, y_train0, X_val, y_val, method)

    # 릿지
    ridge = make_pipeline(StandardScaler(), RidgeCV(alphas=np.logspace(-3, 3, 30)))
    ridge.fit(Xtr, ytr)
    r1 = {"처리": method, "모델": "릿지", "학습행수": len(Xtr), "특성수": Xtr.shape[1]}
    r1.update(score(yva, ridge.predict(Xva)))
    rows.append(r1)

    # HistGB
    hgb = HistGradientBoostingRegressor(max_iter=300, random_state=SEED)
    hgb.fit(Xtr, ytr)
    r2 = {"처리": method, "모델": "HistGB", "학습행수": len(Xtr), "특성수": Xtr.shape[1]}
    r2.update(score(yva, hgb.predict(Xva)))
    rows.append(r2)

    # 신경망
    r3 = {"처리": method, "모델": "신경망", "학습행수": len(Xtr), "특성수": Xtr.shape[1]}
    r3.update(score(yva, train_nn(Xtr, ytr, Xva, yva)))
    rows.append(r3)

res = pd.DataFrame(rows)

print("\n" + "=" * 92)
print("이상치 처리 방식 × 모델 — 검증셋 성능")
print("=" * 92)
pivot = res.pivot(index="처리", columns="모델", values="MAE").reindex(methods)
pivot = pivot[["릿지", "HistGB", "신경망"]]
info = res.drop_duplicates("처리").set_index("처리")[["학습행수", "특성수"]].reindex(methods)
combined = pd.concat([info, pivot], axis=1)
print(combined.to_string())
print("=" * 92)

base_row = combined.loc["① 보존"]
print("\n[① 보존 대비 개선율]")
for m in ["릿지", "HistGB", "신경망"]:
    print(f"  {m:<8}", end="")
    for method in methods[1:]:
        imp = (base_row[m] - combined.loc[method, m]) / base_row[m] * 100
        print(f"  {method[:4]} {imp:+5.1f}%", end="")
    print()
```

```python
import numpy as np
import pandas as pd
from sklearn.ensemble import HistGradientBoostingRegressor
from sklearn.metrics import mean_absolute_error, r2_score
from sklearn.model_selection import train_test_split

SEED = 42
TARGET = "할인가"

df = pd.read_csv("games.csv")
print(f"원본: {len(df):,}행 × {df.shape[1]}열")

# ═══════════════════════════════════════════════════════════
# ★ 수정 1: 처리 대상 열을 명시적으로 선정 (도메인 판단)
# ═══════════════════════════════════════════════════════════
NUMERIC = df.select_dtypes(include=[np.number]).columns.tolist()
EXCLUDE = [TARGET, "게임id", "출시연도"]        # ID·연도·타깃 제외
TREAT = [c for c in NUMERIC if c not in EXCLUDE]

print(f"\n처리 대상 {len(TREAT)}개: {TREAT}")
print(f"제외 {len(EXCLUDE)}개: {EXCLUDE}")

# ═══════════════════════════════════════════════════════════
# ★ 수정 8: 실제 행을 눈으로 확인
# ═══════════════════════════════════════════════════════════
print("\n[극단값 실제 행 확인]")
for c in TREAT[:3]:
    print(f"\n  {c} 상위 3건:")
    print(df.nlargest(3, c)[[c, TARGET]].to_string(index=False))

# ═══════════════════════════════════════════════════════════
# ★ 수정 5: 분할이 먼저
# ★ 수정 7: 3분할
# ═══════════════════════════════════════════════════════════
X_all, y_all = df.drop(columns=[TARGET]), df[TARGET]
y_bins = pd.qcut(y_all, q=10, labels=False, duplicates="drop")

X_dev, X_test, y_dev, y_test, b_dev, _ = train_test_split(
    X_all, y_all, y_bins, test_size=0.2, random_state=SEED, stratify=y_bins)
X_train, X_val, y_train, y_val = train_test_split(
    X_dev, y_dev, test_size=0.25, random_state=SEED, stratify=b_dev)

# ═══════════════════════════════════════════════════════════
# ★ 수정 2: Modified z-score
# ★ 수정 3: 마스크를 한 번에 계산 (누적 제거 방지)
# ═══════════════════════════════════════════════════════════
def modified_z_mask(s, thr=3.5):
    med = s.median()
    mad = (s - med).abs().median()
    if mad == 0:
        return pd.Series(False, index=s.index)
    return (0.6745 * (s - med) / mad).abs() > thr

masks = {c: modified_z_mask(X_train[c]) for c in TREAT}      # ★ 원본 기준으로 한 번에
combined = pd.DataFrame(masks).any(axis=1)

print("\n[특성별 탐지 건수 — 학습셋 기준]")
for c, m in masks.items():
    print(f"  {c:<20}{m.sum():>6,}건 ({m.mean()*100:>5.2f}%)")
print(f"  {'합집합':<20}{combined.sum():>6,}건 ({combined.mean()*100:>5.2f}%)")

# ═══════════════════════════════════════════════════════════
# ★ 수정 6: 정보 손실량 확인 — 제거 전에
# ═══════════════════════════════════════════════════════════
print("\n[정보 손실량 점검]")
print(f"  제거 비율: {combined.mean()*100:.2f}%  "
      f"{'★ 5% 초과 — 재검토' if combined.mean() > 0.05 else 'OK'}")

rate_by_bin = combined.groupby(pd.qcut(y_train, q=10, duplicates="drop"),
                               observed=True).mean() * 100
skew_ratio = rate_by_bin.max() / max(rate_by_bin.min(), 0.01)
print(f"  타깃 구간별 제거율 편차: {skew_ratio:.1f}배  "
      f"{'★ 3배 초과 — 편향 위험' if skew_ratio > 3 else 'OK'}")
print(rate_by_bin.round(2).to_string())

# ═══════════════════════════════════════════════════════════
# ★ 수정 4: 타깃은 절단하지 않음 — 대신 로그 변환
# ★ 수정 9: 트리 모델이므로 절단만 (제거하지 않음)
# ═══════════════════════════════════════════════════════════
X_train_t, X_val_t, X_test_t = X_train.copy(), X_val.copy(), X_test.copy()
for c in TREAT:
    lo, hi = X_train[c].quantile([0.005, 0.995])      # ★ 학습셋 기준
    for Xd in (X_train_t, X_val_t, X_test_t):
        Xd[c] = Xd[c].clip(lo, hi)

# ── 타깃은 로그 변환 (절단 대신) ──
y_train_log = np.log1p(y_train)

# ═══════════════════════════════════════════════════════════
# 비교: 처리 전후
# ═══════════════════════════════════════════════════════════
def evaluate(Xtr, ytr, Xva, yva, use_log, tag):
    m = HistGradientBoostingRegressor(random_state=SEED)
    m.fit(Xtr, np.log1p(ytr) if use_log else ytr)
    p = m.predict(Xva)
    if use_log:
        p = np.expm1(p)
    return {"처리": tag,
            "MAE": round(mean_absolute_error(yva, p), 2),
            "R²": round(r2_score(yva, p), 4)}

rows = [
    evaluate(X_train, y_train, X_val, y_val, False, "① 처리 없음"),
    evaluate(X_train_t, y_train, X_val_t, y_val, False, "② 특성 절단"),
    evaluate(X_train, y_train, X_val, y_val, True, "③ 타깃 로그"),
    evaluate(X_train_t, y_train, X_val_t, y_val, True, "④ 절단 + 로그"),
]
print("\n" + "=" * 56)
print("처리 방식 비교 (검증셋)")
print("=" * 56)
print(pd.DataFrame(rows).to_string(index=False))
print("=" * 56)
print("★ 테스트셋은 아직 열지 않았습니다.")
```

## 오늘의 정리

| 개념 | 핵심 |
|---|---|
| 이상치의 두 얼굴 | **입력 오류** vs **실제 극단값**. 처리가 완전히 다름 |
| 판별 질문 | ①물리적으로 가능한가 ②도메인에서 발생하나 ③**예측 대상에 포함되나** |
| IQR | Q1-1.5×IQR ~ Q3+1.5×IQR. **기본 방법** |
| z-score | **masking effect로 이상치가 자기를 숨김.** 쓰지 말 것 |
| Modified z-score | 중앙값·MAD 기반. **z-score 대신 이것을** |
| 치우친 분포 | 세 방법 모두 약함 → **로그 변환 후 적용** |
| 다변량 이상치 | 각 특성은 정상인데 **조합이 이상.** IsolationForest |
| 처리 4옵션 | ①제거 ②절단 ③플래그 ④보존 (+⑤변환 ⑥강건한 모델) |
| 타깃 절단 | **정답을 바꾸는 것.** 매우 위험 |
| 검증·테스트셋 | **행을 제거하면 안 됨.** 성능이 부풀려짐 |
| 경계 계산 | **학습셋으로만.** 전체로 하면 누수 |
| 정보 손실 점검 | 제거 비율 5% · **타깃 구간별 편차 3배** |
| 모델별 민감도 | **트리는 거의 불변** · 신경망/선형은 크게 개선 |
| 최선의 처리 | **대개 로그 변환.** 데이터를 안 버리고 효과가 큼 |
| 제거하면 안 되는 것 | 오존층 · 블랙프라이데이 · **예측이 가장 중요한 날** |
| 산출물 | **이상치 처리 결정서** (특성/판정/근거/결정/성능영향) |

**오늘 반드시 기억할 세 가지**
> ① **통계는 후보를 주고, 판정은 도메인이 합니다.** 실제 행을 열어 보세요.
> ② **제거는 마지막 수단입니다.** 로그 변환·플래그·강건한 손실이 먼저입니다.
> ③ **"제거했습니다" 대신 결정서를 보여 주세요.** 특성별 판정과 근거가 있어야 합니다.

**과제** — 이상치 처리 결정 근거 문서를 작성하세요.

**필수 포함 항목**

| 항목 | 내용 |
|---|---|
| 1 | 데이터 선택과 수치형 특성 목록 |
| 2 | **탐지 3종 비교표** — IQR / z-score / Modified z-score의 특성별 탐지 건수 |
| 3 | **극단값 실제 행 확인** — 각 특성의 상위 5건을 표로 붙이고 **무엇인지 서술** |
| 4 | **다변량 이상치** — IsolationForest 적용 + 단변량만/다변량만 잡힌 건수 교차표 |
| 5 | **처리 방식 4종 이상 성능 비교** — 모델 2개 이상 × 처리 방식 4개 이상 |
| 6 | **정보 손실량 분석** — 제거 비율 + **타깃 구간별 제거율 표와 편차 비율** |
| 7 | **처리 후 상관 변화** — 피어슨이 스피어만에 얼마나 근접했는가 |
| 8 | **이상치 처리 결정서** — 특성별로 `최대/중앙값 배수 / 탐지건수 / 판정 / 근거 / 결정 / 성능영향` |
| 9 | **보존하기로 한 특성 3개 이상**과 그 근거 (전부 처리하면 감점) |
| 10 | "제거하면 안 되는 이상치" 관점에서 **본인 데이터의 위험 특성 2개** 이상 식별 |

**주의**
- 3번이 이 과제의 핵심입니다. **숫자만 보고 판정하면 감점**입니다.
- 5번에서 **트리 모델을 반드시 포함**하세요. 이상치 처리 효과가 모델마다 다르다는 것을 보여야 합니다.
- 6번에서 편차 비율이 3배를 넘는데도 제거를 선택했다면, **그 근거를 반드시 쓰세요.**
- 9번을 빠뜨리지 마세요. **"모든 이상치를 처리했다"는 답은 틀린 답입니다.**
- 검증·테스트셋에서 행을 제거했다면 감점입니다.
