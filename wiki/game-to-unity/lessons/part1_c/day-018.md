## 1. 오늘 만드는 것

**정산 함수가 소지금을 실제로 바꾼다.** 그리고 한 번의 함수 호출로 여러 값을 동시에 바꾼다.

```
╔═══════════════════════════════════╗
║      럭키 다이스   Round 4        ║
╚═══════════════════════════════════╝

  소지금    1420 G

  [ 정산 전 ]  money = 1420  (주소 0x00AFF8C4)

  Settle(&game) 호출...
    함수 안에서 g->money  1420 -> 1780
    함수 안에서 g->wins      2 -> 3

  [ 정산 후 ]  money = 1780   ★ 실제로 바뀌었다!
               wins  = 3      ★ 두 값이 동시에!
```

```

```

## 2. 막히는 상황

Day 4에서 이런 코드를 만났다.

```c
void Heal(int hp)
{
    hp = hp + 20;
    printf("함수 안: %d\n", hp);      // 120
}

int main(void)
{
    int heroHp = 100;
    Heal(heroHp);
    printf("함수 밖: %d\n", heroHp);  // 100 — 안 바뀐다!
}
```

그때는 **`return`으로 받아서** 우회했다.

```c
int Heal(int hp) { return hp + 20; }
heroHp = Heal(heroHp);                // ✔ 동작은 한다
```

**그런데 이게 안 통하는 경우가 있다.**

```c
// 정산: 소지금도 바꾸고, 승수도 바꾸고, 라운드도 올려야 한다
??? Settle(int money, int wins, int round)
{
    money += 180;
    wins++;
    round++;
    return ???;              // 세 개를 어떻게 돌려주지?
}
```

**`return`은 값을 하나만 돌려준다.** 세 개를 바꿔야 하는데 방법이 없다.

```
   지금 할 수 있는 우회책들

   ① 함수를 세 개로 쪼갠다        →  하나의 일이 세 군데로 흩어진다
   ② 전역 변수를 쓴다             →  누가 언제 바꿨는지 추적 불가
   ③ 구조체를 통째로 반환한다      →  큰 구조체를 매번 복사. 느리다

   전부 불편하다.
```

그리고 Day 2부터 계속 나온 이 `&`는 도대체 무엇인가?

```c
scanf_s("%d", &damage);         // 왜 & 를 붙이지?
InitGame(&game);                // Day 17에서도 나왔다
```

> **함수가 원본을 직접 건드릴 수 있게 하는 방법이 필요하다.** → **포인터**

## 3. 개념

### 3-1. 메모리와 주소 — 모든 변수에는 번지수가 있다

**왜 필요한가** — 포인터를 이해하려면 "변수가 메모리 어딘가에 산다"는 그림이 먼저 있어야 한다.

```
   메모리는 번호가 매겨진 칸들의 나열이다.

   주소:  0x1000  0x1004  0x1008  0x100C  0x1010
        ┌───────┬───────┬───────┬───────┬───────┐
        │  100  │   30  │   20  │       │       │
        └───────┴───────┴───────┴───────┴───────┘
          heroHp  slimeHp  damage

   ★ 변수 이름은 사람이 쓰기 위한 것이고,
     컴퓨터는 주소로 찾아간다.
```

**주소 연산자 `&`** — "이 변수는 어디에 사는가?"

```c
int hp = 100;

printf("값:   %d\n", hp);          // 100
printf("주소: %p\n", &hp);         // 0x00AFF8C4 (실행할 때마다 다름)
```

```
   hp   →  변수에 담긴 "값"      (100)
   &hp  →  변수가 있는 "주소"    (0x00AFF8C4)
```

> **`scanf_s("%d", &damage)`의 `&`가 바로 이것이다.**
> "damage라는 변수가 **어디 있는지** 알려줄 테니, 거기에 입력값을 써 넣어라"는 뜻이다.
> 주소를 안 주면 `scanf`는 값을 어디에 넣을지 모른다.

### 3-2. 포인터 변수 — 주소를 담는 그릇

**왜 필요한가** — 주소를 저장해 두고 나중에 그 자리를 찾아가기 위해서.

```c
int  hp = 100;
int* p  = &hp;          // p는 hp의 주소를 담는다
```

```
   변수 hp                   포인터 p
   ┌──────────┐            ┌──────────────┐
   │   100    │            │  0x00AFF8C4  │
   └──────────┘            └──────────────┘
    주소 0x00AFF8C4               │
        ▲                         │
        └─────────────────────────┘
              p가 hp를 "가리킨다"
```

**선언 방법**

```c
int*  p;          // int를 가리키는 포인터
char* c;          // char를 가리키는 포인터
GameState* g;     // GameState 구조체를 가리키는 포인터
```

> `int* p`와 `int *p`는 완전히 같다. 어디에 `*`를 붙이든 상관없다.
> **다만 이럴 때 주의:**
>
> ```c
> int* a, b;        // a는 포인터, b는 그냥 int!  (함정)
> int *a, *b;       // 둘 다 포인터
> ```
>
> 한 줄에 하나씩 선언하는 게 안전하다.

### 3-3. 역참조 `*` — 그 주소로 찾아가기

**왜 필요한가** — 주소만 알아서는 소용없다. 그 자리의 값을 읽고 쓸 수 있어야 한다.

```c
int  hp = 100;
int* p  = &hp;

printf("%d\n", *p);        // 100    — p가 가리키는 곳의 값을 읽는다
*p = 50;                   //         — p가 가리키는 곳에 50을 쓴다
printf("%d\n", hp);        // 50     ★ hp가 바뀌었다!
```

```
   *p = 50;  이 하는 일

   ① p에 담긴 주소를 본다        0x00AFF8C4
   ② 그 주소로 찾아간다          ─────────────▶ ┌──────────┐
   ③ 거기에 50을 쓴다                            │   50     │  ← hp
                                                 └──────────┘
                                                주소 0x00AFF8C4
```

> ### ⚠️ `*`가 두 가지 뜻으로 쓰인다 — 가장 헷갈리는 지점
>
> | 위치 | 뜻 | 예 |
> |---|---|---|
> | **선언할 때** | "이건 포인터다" | `int* p;` |
> | **사용할 때** | "가리키는 곳으로 가라" | `*p = 50;` |
>
> ```c
> int* p = &hp;     // 선언: p는 포인터다
> *p = 50;          // 사용: p가 가리키는 곳에 50을 쓴다
> p  = &mp;         // 사용: p 자체를 바꾼다 (다른 곳을 가리키게)
> ```

**세 가지를 정확히 구분한다**

```c
int  hp = 100;
int* p  = &hp;
```

| 표기 | 뜻 | 값 |
|---|---|---|
| `hp` | 변수의 값 | `100` |
| `&hp` | 변수의 주소 | `0x00AFF8C4` |
| `p` | 포인터에 담긴 주소 | `0x00AFF8C4` |
| `*p` | 그 주소에 있는 값 | `100` |
| `&p` | 포인터 자신의 주소 | `0x00AFF8B0` (다른 곳) |

### 3-4. 함수에 주소 넘기기 — 오늘의 핵심

**왜 필요한가** — Day 4부터 막혀 있던 문제가 여기서 풀린다.

```c
// ✘ 값 전달 (call by value)
void Heal(int hp)
{
    hp += 20;                    // 사본만 바뀐다
}

// ✔ 주소 전달 (call by reference)
void Heal(int* hp)
{
    *hp += 20;                   // 원본이 바뀐다
}

int main(void)
{
    int heroHp = 100;

    Heal(heroHp);                // ✘ 값을 넘김 → 100 그대로
    Heal(&heroHp);               // ✔ 주소를 넘김 → 120
}
```

```
   [ 값 전달 ]                          [ 주소 전달 ]

   main:  heroHp = 100                 main:  heroHp = 100
          (주소 0x1000)                       (주소 0x1000)
            │                                   │
            │ 값 100을 복사                     │ 주소 0x1000을 복사
            ▼                                   ▼
   Heal:  hp = 100                      Heal:  hp = 0x1000
          hp += 20                             *hp += 20
          → 사본이 120                          → 0x1000 자리의 값이 120
            │                                   │
            │ 함수 끝 → 사본 소멸                │ 함수 끝 → 주소 사본만 소멸
            ▼                                   ▼
   main:  heroHp = 100  ✘               main:  heroHp = 120  ✔
```

> **핵심 문장**
> 값 전달이든 주소 전달이든 **매개변수는 항상 사본이다.**
> 다만 **주소의 사본**을 가지면, 그 주소로 찾아가서 **원본을 건드릴 수 있다.**

**호출하는 쪽과 받는 쪽의 짝**

```c
void Func(int* p)          // 받는 쪽: * 를 붙여 포인터로 받는다
Func(&value);              // 넘기는 쪽: & 를 붙여 주소를 넘긴다
```

### 3-5. 여러 값을 동시에 바꾸기

**왜 필요한가** — 2절의 문제였다. `return`은 하나뿐이지만 포인터는 개수 제한이 없다.

```c
void Settle(int* money, int* wins, int* round, int profit)
{
    *money += profit;
    (*wins)++;                   // ★ 괄호 주의
    (*round)++;
}

// 호출
Settle(&game.money, &game.wins, &game.round, 180);
```

> ### ⚠️ `*p++` 와 `(*p)++` 는 다르다
>
> ```
>   (*p)++     →  p가 가리키는 곳의 값을 1 증가        ✔ 우리가 원하는 것
>   *p++       →  p(주소)를 1 증가시키고 그 값을 참조   ✘ 엉뚱한 곳을 가리키게 됨
>   ++*p       →  (*p)++ 와 같은 결과
> ```
>
> **`(*p)++` 처럼 괄호를 명시한다.** 헷갈릴 여지를 없애는 게 낫다.

**출력 매개변수 패턴** — Day 12에서 미리 썼던 그것

```c
// 찾으면 1을 반환하고, 좌표를 outX/outY에 넣는다
int FindTile(char map[][MAP_W+1], char target, int* outX, int* outY)
{
    for (int y = 0; y < MAP_H; y++)
        for (int x = 0; x < MAP_W; x++)
            if (map[y][x] == target)
            {
                *outX = x;
                *outY = y;
                return 1;
            }
    return 0;
}

// 사용
int px, py;
if (FindTile(g_map, 'P', &px, &py))
    printf("찾았다: (%d, %d)\n", px, py);
```

```
   반환값     →  성공/실패 여부
   출력 매개변수 →  실제 결과값들

   ★ C에서 아주 흔한 패턴이다. Windows API가 전부 이렇게 생겼다.
```

### 3-6. 구조체 포인터와 `->`

**왜 필요한가** — Day 17에서 계속 쓴 `g->money`의 정체.

```c
GameState game;
GameState* g = &game;

// 이 두 줄은 완전히 같다
(*g).money = 1000;
g->money   = 1000;          // ★ 이게 훨씬 읽기 쉽다
```

```
   (*g).money

   ①  *g      g가 가리키는 구조체로 간다
   ②  .money  그 구조체의 money 멤버

   너무 자주 쓰이는 조합이라 전용 연산자가 생겼다  →  g->money
```

| 상황 | 연산자 |
|---|---|
| 구조체 **변수** | `game.money` (점) |
| 구조체 **포인터** | `g->money` (화살표) |

**구조체를 포인터로 넘기는 두 가지 이유**

```c
void PrintStatus(GameState g);      // ✘ 구조체 전체(약 40바이트)를 복사
void PrintStatus(GameState* g);     // ✔ 주소(4 또는 8바이트)만 복사
```

| 이유 | 설명 |
|---|---|
| **① 원본을 바꿀 수 있다** | 오늘의 핵심 |
| **② 빠르다** | 큰 구조체를 복사하지 않는다 |

**읽기만 할 때는 `const`를 붙인다**

```c
void PrintStatus(const GameState* g)      // 읽기 전용임을 명시
{
    printf("%d\n", g->money);
    // g->money = 0;      ← 컴파일 오류. 실수를 컴파일러가 막아준다
}
```

> `const`는 **자신과 동료를 위한 안전장치**다. "이 함수는 상태를 안 바꾼다"가 시그니처에 드러난다.

### 3-7. 배열과 포인터 — Day 11의 수수께끼

**왜 필요한가** — "배열은 왜 함수에서 원본이 바뀌지?"의 답.

```c
int arr[5] = { 10, 20, 30, 40, 50 };

printf("%p\n", arr);        // 0x1000
printf("%p\n", &arr[0]);    // 0x1000   ← 같다!
```

> **배열 이름은 첫 요소의 주소다.**

```
   int arr[5];

   arr[0]  arr[1]  arr[2]  arr[3]  arr[4]
   ┌──────┬──────┬──────┬──────┬──────┐
   │  10  │  20  │  30  │  40  │  50  │
   └──────┴──────┴──────┴──────┴──────┘
   0x1000 0x1004 0x1008 0x100C 0x1010
     ▲
     └── arr 이 곧 이 주소
```

**그래서 배열을 함수에 넘기면 자동으로 주소가 넘어간다.**

```c
void Fill(int arr[], int size)      // 사실은 int* arr 과 같다
{
    for (int i = 0; i < size; i++)
        arr[i] = 0;                 // 원본이 바뀐다
}

int items[5];
Fill(items, 5);                     // & 없이도 주소가 넘어간다
```

```
   ★ Day 11의 수수께끼가 풀렸다.
     배열은 "특별해서" 원본이 바뀌는 게 아니라,
     애초에 주소가 넘어가기 때문이다.
```

**그리고 함수 안에서 `sizeof(arr)`가 안 되는 이유도 같다.**

```c
void Func(int arr[])
{
    printf("%zu\n", sizeof(arr));   // 4 또는 8 (포인터 크기)
}                                    // 배열 크기가 아니다!
```

```
   함수가 받은 것은 배열이 아니라 "첫 요소의 주소" 하나뿐이다.
   몇 개짜리인지는 애초에 안 넘어왔다.  →  크기를 따로 넘겨야 한다
```

**포인터 산술** (참고)

```c
int arr[5] = { 10, 20, 30, 40, 50 };
int* p = arr;

printf("%d\n", *p);          // 10  (arr[0])
printf("%d\n", *(p + 1));    // 20  (arr[1])
printf("%d\n", p[2]);        // 30  ← 포인터에도 [] 를 쓸 수 있다
```

```
   p + 1  은 "주소 + 1바이트"가 아니라 "주소 + int 하나 크기(4바이트)"다.
   자료형을 알기 때문에 컴파일러가 알아서 계산한다.

   p     →  0x1000
   p + 1 →  0x1004      (4바이트 뒤)
   p + 2 →  0x1008
```

> `arr[i]` 는 사실 `*(arr + i)` 의 다른 표기법이다.

### 3-8. ⚠️ 포인터의 위험 — 반드시 알아야 할 세 가지

**왜 필요한가** — 포인터 관련 버그는 크래시하거나, 더 나쁘게는 **조용히 데이터를 망가뜨린다.**

**① 초기화하지 않은 포인터**

```c
int* p;                  // ✘ 어디를 가리키는지 모른다 (쓰레기 주소)
*p = 100;                // ✘ 어딘가 모를 곳에 100을 쓴다 → 크래시 또는 데이터 파괴

int* p = NULL;           // ✔ 명시적으로 "아무 데도 안 가리킴"
```

**② `NULL` 역참조**

```c
int* p = NULL;
*p = 100;                // ✘ 크래시 (액세스 위반)

if (p != NULL)           // ✔ 쓰기 전에 확인
    *p = 100;
```

```c
// 함수에서 받은 포인터는 항상 검사한다
void Settle(GameState* g)
{
    if (g == NULL) return;          // ★ 방어

    g->money += 100;
}
```

**③ 사라진 지역 변수를 가리키기 (dangling pointer)**

```c
int* MakeNumber(void)
{
    int n = 42;
    return &n;               // ✘ n은 함수가 끝나면 사라진다!
}

int* p = MakeNumber();
printf("%d\n", *p);          // 무슨 값이 나올지 모른다
```

```
   함수 안의 지역 변수는 함수가 끝나면 사라진다 (Day 4)
   그 주소를 들고 나와 봐야 빈 자리를 가리킬 뿐이다

   ★ 해결책은 내일 배울 "동적 할당"이다
```

### Step 3 — 값 전달 vs 주소 전달 (직접 비교)

```c
void HealByValue(int hp)
{
    hp += 20;
    printf("  [값 전달]   함수 안: %d\n", hp);
}

void HealByPointer(int* hp)
{
    *hp += 20;
    printf("  [주소 전달] 함수 안: %d\n", *hp);
}

int main(void)
{
    int a = 100;
    printf("호출 전: %d\n", a);
    HealByValue(a);
    printf("호출 후: %d\n\n", a);      // 100 — 안 바뀜

    int b = 100;
    printf("호출 전: %d\n", b);
    HealByPointer(&b);
    printf("호출 후: %d\n", b);        // 120 — 바뀜!
}
```

**✅ 여기까지 실행하면** — 두 방식의 차이가 명확하게 보인다.

```
호출 전: 100
  [값 전달]   함수 안: 120
호출 후: 100        ← 안 바뀜

호출 전: 100
  [주소 전달] 함수 안: 120
호출 후: 120        ← 바뀜!
```

### Step 4 — 값 교환 (Swap) — 포인터의 고전

```c
void Swap(int* a, int* b)
{
    int temp = *a;
    *a = *b;
    *b = temp;
}

int x = 10, y = 20;
printf("교환 전: x=%d y=%d\n", x, y);
Swap(&x, &y);
printf("교환 후: x=%d y=%d\n", x, y);      // x=20 y=10
```

```
   Swap(&x, &y)

   초기      a→[10]  b→[20]   temp = ?
   ①        temp = *a = 10
   ②        *a = *b     →  a→[20]  b→[20]
   ③        *b = temp   →  a→[20]  b→[10]
```

> `Swap`이 포인터 없이는 **절대 불가능**하다는 것을 확인한다.
> 값 전달로 만들면 함수 안에서만 바뀌고 끝난다.
>
> 이 `Swap`은 **Day 16의 카드 셔플**, 정렬 알고리즘 등에서 계속 쓴다.

**✅ 여기까지 실행하면** — 두 값이 실제로 교환된다.

**정상이라면 이렇게 보인다.**

```

&hp = 00AFF8C4

*p  = 50

=== 값 전달 vs 주소 전달 ===
호출 전: 100

  [주소 전달] 함수 안: 120

[정산 전] money=1420 wins=2 round=4

=== 전투 ===

용사 HP 100 → 97
```

- [ ] `&변수`로 주소를 출력할 수 있다
- [ ] `*p = 값;` 으로 원본을 바꿀 수 있다
- [ ] 값 전달과 주소 전달의 차이를 실행 결과로 확인했다
- [ ] `Swap`이 실제로 두 값을 교환한다
- [ ] 한 번의 함수 호출로 여러 값이 동시에 바뀐다
- [ ] `g->money` 와 `(*g).money` 가 같다는 것을 확인했다
- [ ] `arr` 과 `&arr[0]` 의 주소가 같다
- [ ] `const GameState*` 에 값을 쓰려 하면 컴파일 오류가 난다
- [ ] RPG 전투가 한 함수 호출로 양쪽 HP를 바꾼다

## 6. 자주 막히는 곳

| 증상 | 원인 | 해결 |
|---|---|---|
| 크래시 (액세스 위반) | 초기화 안 한 포인터 역참조 | `int* p = NULL;` 로 초기화 |
| 크래시 | `NULL` 역참조 | 쓰기 전에 `if (p != NULL)` |
| 값이 안 바뀜 | `&` 없이 값을 넘김 | `Func(&value)` |
| `error C2440: 형식 변환 불가` | `int`를 `int*`에 대입 | `&`를 붙였는지 확인 |
| 이상한 값이 나옴 | 지역 변수 주소를 반환 | 동적 할당(Day 19) 또는 매개변수로 받기 |
| `(*p)++` 가 이상하게 동작 | `*p++` 로 씀 | **괄호를 명시**한다 |
| 구조체 멤버 접근 오류 | 포인터에 `.` 사용 | `->` 로 |
| `int* a, b;` 에서 b가 포인터가 아님 | `*`는 변수 하나에만 적용 | 한 줄에 하나씩 선언 |
| 함수 안 `sizeof(arr)`가 4/8 | 배열은 포인터로 넘어감 | 크기를 따로 매개변수로 |
| `%p` 출력 경고 | 형변환 필요할 수 있음 | `(void*)` 캐스팅 |

## 7. 정리

### 오늘 배운 것

| 개념 | 한 줄 요약 |
|---|---|
| 주소 `&` | 변수가 메모리 어디에 있는지 |
| 포인터 `int*` | 주소를 담는 변수 |
| 역참조 `*p` | 그 주소로 찾아가 값을 읽고 쓴다 |
| **주소 전달** | 함수에 `&`로 주소를 넘기면 **원본을 바꿀 수 있다** |
| 여러 값 변경 | `return`은 하나지만 포인터는 개수 제한 없음 |
| `->` | `(*p).member` 의 줄임. 구조체 포인터 전용 |
| `const T*` | 읽기 전용. 실수를 컴파일러가 막는다 |
| **배열 = 첫 요소 주소** | Day 11의 수수께끼가 풀렸다 |
| 3대 위험 | 미초기화 / NULL / 사라진 변수 |
