### Day 3 · 조건문 — 승패를 판단하기

| | |
|---|---|
| **연결 문서** | 01 영웅은 절차적 — Step 2 |

**🔧 막히면**

- `else if` 순서 오류 → 넓은 조건이 앞에 오면 뒤가 절대 실행되지 않음
- `switch`에서 모든 case가 다 실행됨 → **`break` 누락**

### Day 6 · 반복문 3종 — 게임 루프의 조상

| | |
|---|---|
| **연결 문서** | 02 탈출 루프 — Step 0~1 |
| **오늘의 목표** | 메뉴가 사라지지 않고 계속 다시 뜬다 |

**오전 (4h)**
- **막히는 상황**: 한 번 고르면 프로그램이 끝난다. 게임은 끝날 때까지 계속 물어봐야 한다
- `while` / `for` / `do-while` — 세 형태와 각각이 자연스러운 상황
- 무한 루프 `while(1)` 과 종료 조건
- 반복 횟수 제어 변수 / 누적 변수
- 메뉴 출력 → 선택 입력 → 결과 출력 → **다시 메뉴** 구조 구현

**오후 (4h)**
- 중첩 반복문 — 구구단, 별 찍기로 감각 익히기
- Week 1의 RPG 전투를 `while` 루프로 감싸 **턴제 전투**로 개조
- 반복 안에서의 변수 수명 확인
- 실습: 3판 2선승 구조 만들기

**✅ 실행 결과** — 메뉴를 고르고 결과를 본 뒤 다시 메뉴 화면으로 돌아온다. 프로그램이 스스로 끝나지 않는다.

**🔧 막히면**
- 무한 루프에서 못 빠져나옴 → **Ctrl+C** 로 강제 종료하는 법 먼저 안내
- 조건식에 세미콜론 (`while(...);`) → 본문이 실행되지 않음
- `for` 안에서 증감 누락 → 무한 루프

### Day 7 · break / continue — 루프에서 빠져나가기

| | |
|---|---|
| **연결 문서** | 02 탈출 루프 — Step 2 |
| **오늘의 목표** | 0번을 고르면 프로그램이 정상 종료되고, 잘못된 번호는 건너뛴다 |

**오전 (4h)**
- `break` — 루프 즉시 탈출 / `continue` — 이번 회차만 건너뛰기
- `switch` 안의 `break`와 루프의 `break` 구분 (자주 헷갈리는 지점)
- 중첩 루프에서의 `break`는 **한 겹만** 벗어난다 → 플래그 변수 패턴
- 종료 메뉴(0번) 구현

**오후 (4h)**
- 게임 루프의 3단계 정리 — 입력 / 처리 / 출력 (도해)
- 여러 종료 경로 정리 (탈출 성공 / 사망 / 사용자 종료)
- 실습: 남은 시도 횟수를 두고 소진되면 자동 종료
- 리팩터링 — 루프 본문을 함수로 분리

**✅ 실행 결과** — 메뉴에서 0을 입력하면 "게임을 종료합니다"가 출력되고 프로세스가 정상 종료된다. 9를 입력하면 "없는 메뉴입니다"가 뜨고 다시 메뉴로 돌아온다.

**🔧 막히면**
- `break`가 `switch`만 빠져나감 → 루프 종료용 플래그 변수 사용
- `continue` 후 무한 루프 → `for`가 아닌 `while`에서 증감을 건너뛴 경우

### Day 8 · 입력 검증 — 프로그램을 죽지 않게 하기

**오후 (4h)**

- 실습: Week 1의 RPG에도 `ReadInt`를 적용

**✅ 실행 결과** — 아래처럼 어떤 입력을 넣어도 프로그램이 죽거나 폭주하지 않는다.
```
메뉴 선택 (0~3): abc
숫자를 입력해 주세요.
메뉴 선택 (0~3): 99
0~3 사이로 입력해 주세요.
메뉴 선택 (0~3): 2
```

### Day 18 · 포인터 — 함수 밖의 값을 바꾸기 ★

| | |
|---|---|
| **연결 문서** | 04 갬블 게임 — Step 3 |
| **오늘의 목표** | 함수 안에서 정산한 소지금이 `main`에도 반영된다 |

**오전 (4h)**
- **막히는 상황**: `Settle(money)` 로 정산했는데 `main`의 `money`가 그대로다 (Day 4에서 미뤄둔 문제)
- 원인 — **값 복사(call by value)**. 함수는 사본을 받는다 (도해)
- 주소 연산자 `&` 와 포인터 변수, 역참조 `*`
- `Settle(int* money)` 로 고치기 → 값이 반영된다
- 포인터가 가리키는 메모리 도해

**모노스페이스 도해**
```
   [값 전달]                        [주소 전달]
   main:  money = 1000              main:  money = 1000  (주소 0x1000)
            │ 복사                           │ 주소만 전달
            ▼                                ▼
   Settle: money = 1000            Settle: pMoney = 0x1000
           money -= 100                     *pMoney -= 100
           → 사본만 900                     → 원본이 900  ✔
   main:  money = 1000  ✘          main:  money = 900
```

**오후 (4h)**
- 배열과 포인터의 관계 — 배열 이름은 첫 요소의 주소
- 포인터로 배열 순회
- 구조체 포인터와 `->` 연산자

### Day 22 · 공의 좌표와 벽 반사

| | |
|---|---|
| **연결 문서** | 05 알카노이드 — Step 2 |
| **오늘의 목표** | 공이 화면 안에서 벽에 튕기며 계속 날아다닌다 |

**오전 (4h)**
- 위치와 **속도 벡터** — `x += vx; y += vy;`
- 반사의 원리 — 좌우 벽은 `vx = -vx`, 상하 벽은 `vy = -vy`
- 벽에 박히는 문제 — 반사 후 위치 보정
- 공 구조체 설계 (`Ball { x, y, vx, vy }`)

**모노스페이스 도해**
```
   ┌─────────────────────────┐
   │        ●                │   vx=+1, vy=+1  → 오른쪽 아래로
   │          ╲              │
   │            ╲            │   오른쪽 벽 충돌 → vx = -vx
   │              ● ──▶ │    │
   │            ╱            │   아래 벽 충돌  → vy = -vy
   │          ●              │
   └─────────────────────────┘
```

**오후 (4h)**
- 속도 조절과 체감 난이도
- 공 여러 개 (배열)로 확장
- 잔상 제거 — 이전 위치 지우기
- 실습: 공이 벽에 닿을 때마다 색/문자 바꾸기

**✅ 실행 결과** — 공(`●`)이 화면 안에서 대각선으로 날아가다 벽에 닿으면 방향을 바꿔 계속 튕긴다. 벽을 뚫고 나가지 않는다.

**🔧 막히면**
- 공이 벽에 붙어 진동 → 반사 시 위치를 벽 안쪽으로 밀어주지 않음
- 공이 사라짐 → 경계 검사 순서 오류

### Day 23 · 비동기 입력과 패들

| | |
|---|---|
| **연결 문서** | 05 알카노이드 — Step 3 |
| **오늘의 목표** | 공이 움직이는 중에도 패들이 좌우로 조작된다 |

**오전 (4h)**
- **막히는 상황**: `_getch()`를 쓰면 키를 누를 때까지 공이 멈춘다

- `if (_kbhit()) { key = _getch(); ... }` 패턴
- 패들 구조체와 이동 처리 / 화면 경계 제한

**오후 (4h)**
- 패들과 공의 충돌 — 패들 위에서 `vy = -vy`
- 패들의 어느 지점에 맞았는지에 따라 반사각 변화 (게임성의 핵심)
- 공을 놓쳤을 때 처리 (라이프 감소, 재시작)

**✅ 실행 결과** — 공이 계속 날아다니는 상태에서 좌우 키로 패들이 즉시 움직이고, 공이 패들에 닿으면 위로 튕긴다.

**🔧 막히면**
- 여전히 멈춤 → `_kbhit()` 없이 `_getch()`를 직접 호출
- 키가 눌린 채로 유지되지 않음 → `_kbhit`은 눌린 순간만 잡음. 연속 이동은 상태 플래그로 처리
- 공이 패들을 뚫음 → 이동량이 패들 두께보다 커서 한 프레임에 지나침

### Day 24 · 블록과 AABB 충돌 판정

| | |
|---|---|
| **연결 문서** | 05 알카노이드 — Step 4 |
| **오늘의 목표** | 공이 블록에 닿으면 블록이 사라지고 반사된다 |

**오전 (4h)**
- **막히는 상황**: 공이 블록을 그냥 통과한다 → **겹침을 판단할 방법이 필요하다**
- **AABB (Axis-Aligned Bounding Box)** 충돌 판정 원리
- 겹침 조건 — `a.left < b.right && a.right > b.left && a.top < b.bottom && a.bottom > b.top`
- 블록 배열 (2차원) 설계와 활성/비활성 플래그
- 충돌 시 블록 비활성화 + 공 반사

**모노스페이스 도해 — AABB**
```
   겹침 O                        겹침 X
   ┌───────┐                     ┌───────┐
   │  A    │                     │  A    │
   │    ┌──┼────┐                └───────┘   ┌───────┐
   └────┼──┘    │                            │   B   │
        │   B   │                            └───────┘
        └───────┘
   A.right > B.left  이고                A.right < B.left
   A.left  < B.right 이고                → 한 축만 어긋나도 겹치지 않음
   (y축도 동일)
```

**오후 (4h)**
- 충돌 방향 판별 — 위/아래에서 맞았나, 옆에서 맞았나 (반사 축 결정)
- 한 프레임에 여러 블록과 충돌하는 경우 처리
- 블록 배치 패턴 (배열 데이터로 스테이지 구성)
- 실습: 2번 맞아야 깨지는 블록(내구도) 추가

**✅ 실행 결과** — 공이 블록에 부딪히면 그 블록이 화면에서 사라지고 공이 튕겨 나간다. 옆에서 맞으면 좌우로, 위아래에서 맞으면 상하로 반사된다.

**🔧 막히면**
- 블록 하나 치면 여러 개가 사라짐 → 충돌 후 `break` 로 그 프레임 판정 종료
- 반사 방향이 이상함 → 충돌 방향 판별 없이 `vy`만 뒤집는 경우
- 공이 블록 사이에 끼임 → 충돌 후 위치 보정 누락

- 접근 지정자 `public` `private` — 왜 감추는가
- 생성자와 소멸자 — 초기화와 정리를 강제하기

**오후 (4h)**
- `Ball`, `Paddle`, `Block` 클래스로 알카노이드 재작성
- 헤더(`.h`)와 구현(`.cpp`) 분리
- 참조자 `&` — 포인터보다 안전하고 편한 전달
- `new` / `delete` (C++의 동적 할당)

**✅ 실행 결과** — Day 25와 **화면과 조작이 완전히 동일**한 알카노이드가 클래스 구조로 돌아간다.

**🔧 막히면**
- 링크 오류 (`unresolved external`) → 헤더에 선언만 하고 `.cpp`에 정의 누락
- 멤버 초기화 안 됨 → 생성자 초기화 리스트 사용 안내
- `private` 접근 오류 → getter/setter 또는 설계 재검토

### Day 28 · 상속과 가상 함수 — 다르게 행동하는 같은 것들 ★

| | |
|---|---|
| **연결 문서** | (C++ 전환) |
| **오늘의 목표** | 오브젝트 배열 하나를 순회하면 공·블록·패들이 각자 알아서 그려진다 |

**오전 (4h)**
- **막히는 상황**: `UpdateBall`, `UpdatePaddle`, `UpdateBlock`을 각각 호출하는 코드가 길다. 오브젝트가 늘면 계속 늘어난다
- 공통점 찾기 — 전부 "좌표를 갖고, 갱신되고, 그려진다"
- 기반 클래스 `GameObject { x, y; virtual Update(); virtual Render(); }`
- 상속 (`class Ball : public GameObject`)
- **`virtual` 과 다형성** — 부모 포인터로 자식의 동작을 부른다

**모노스페이스 도해**
```
                  GameObject
                  x, y
                  virtual Update()
                  virtual Render()
                       ▲
        ┌──────────────┼──────────────┐
      Ball           Paddle          Block
      Update()       Update()        Update()
      Render()       Render()        Render()

   GameObject* objects[100];
   for (auto* o : objects) { o->Update(); o->Render(); }
       └─▶ 같은 코드인데 각자 다르게 동작한다   ← 이게 다형성
```

**오후 (4h)**
- `virtual`을 뺐을 때 무슨 일이 나는지 **직접 실행해서 확인** (부모 함수만 불린다)
- 가상 소멸자가 필요한 이유 — 자식 소멸자가 안 불리는 사고 시연
- 순수 가상 함수와 추상 클래스
- 알카노이드를 `GameObject` 배열 하나로 관리하도록 재구성 — **Week 8 프레임워크의 원형**

**✅ 실행 결과** — `objects` 배열 하나만 순회하는데 공은 날아가고, 패들은 입력을 받고, 블록은 자리를 지킨다. `virtual`을 지우면 전부 아무것도 안 한다.

**🔧 막히면**
- 자식 동작이 안 불림 → `virtual` 누락 (오늘의 핵심)
- 메모리 누수 → 가상 소멸자 미선언
- 슬라이싱 → 포인터/참조가 아닌 **값**으로 담아서 자식 정보가 잘림
