## 3. 개념

### 3-1. 발표의 목적

**왜 필요한가** — 자랑이 아니라 검증.

```
   ★ 오늘 발표의 목적

   ① 팀이 같은 것을 상상하는지 확인
   ② 4주에 가능한지 외부 시선으로 검증
   ③ **범위를 깎는다**  ★
```

```
   ⚠️ 발표에서 흔한 실수

   ✗ 만들 기능을 나열한다
   ✗ 화려한 계획을 보여준다
   ✗ 제외 목록을 생략한다

   ✔ 핵심 루프 하나를 명확히
   ✔ 안 만드는 것을 당당히 말한다
```

```
   ★ 좋은 발표의 신호

   듣는 사람이
   "아, 그 게임 해보고 싶다"
   "그건 4주에 되겠네요"
   라고 말한다
```

### 3-2. 발표 구성 (7분)

**왜 필요한가** — 시간을 지킨다.

| 시간 | 내용 | 슬라이드 |
|:--:|---|:--:|
| 0:00~1:00 | 한 줄 소개 + 첫 30초 | 1 |
| 1:00~3:00 | **핵심 루프** (그림) | 1~2 |
| 3:00~4:00 | 조작 + 승패 | 1 |
| 4:00~5:00 | 콘텐츠 범위 + **제외 목록** ★ | 1 |
| 5:00~6:00 | 기술 + 재사용 코드 | 1 |
| 6:00~7:00 | 일정 + 리스크 | 1 |

```
   ★ 슬라이드 6~8장

   ① 표지 (한 줄 소개)
   ② 첫 30초
   ③ 핵심 루프
   ④ 조작·승패
   ⑤ 범위 (Must/Should/Won't)
   ⑥ 기술·재사용
   ⑦ 일정
   ⑧ 리스크
```

```
   ⚠️ 7분을 넘기지 않는다

   → 리허설 필수
   → 넘기면 가장 중요한 "제외 목록"을 못 말한다
```
