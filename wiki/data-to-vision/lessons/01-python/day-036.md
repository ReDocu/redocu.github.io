## ② 왜 필요한가

**코드부터 치면 이렇게 됩니다.**

> 월요일: "일단 플레이어부터 만들자"
> 화요일: "아 보스도 넣고 싶다"
> 수요일: "멀티플레이도 되면 좋겠는데"
> 목요일: "아무것도 완성 안 됐다"
> 금요일: 발표할 것이 없음

**기획의 목적은 아이디어를 늘리는 것이 아니라 줄이는 것**입니다.

| 기획 없이 | 기획 후 |
|---|---|
| "재미있는 게임" | "5스테이지를 클리어하는 종스크롤 슈팅" |
| 계속 기능 추가 | 목록에 없으면 안 만듦 |
| 진행률 모름 | "8개 중 5개 완료" |
| 발표 직전 미완성 | 목요일에 완성 |

오늘 만든 문서가 **남은 4일의 지도**가 됩니다.

**MoSCoW — 우선순위 나누기**

| 등급 | 뜻 | 배정 |
|---|---|---|
| **Must** | 없으면 게임이 아님 | Day 037 |
| **Should** | 있어야 게임답다 | Day 038 |
| **Could** | 있으면 좋다 | Day 039 (시간 남으면) |
| **Won't** | **이번엔 안 한다** | 명시적으로 제외 |

**`main.py` — 오늘의 목표: 이것이 실행되어야 함**

```python
"""슈팅게임 진입점."""

import pygame

from game.settings import SCREEN_WIDTH, SCREEN_HEIGHT, FPS, TITLE
from game.scenes.manager import GameManager


def main():
    pygame.init()
    pygame.mixer.init()

    screen = pygame.display.set_mode((SCREEN_WIDTH, SCREEN_HEIGHT))
    pygame.display.set_caption(TITLE)
    clock = pygame.time.Clock()

    manager = GameManager(screen)

    running = True
    while running:
        for event in pygame.event.get():
            if event.type == pygame.QUIT:
                running = False
            else:
                running = manager.handle_event(event)

        manager.update()
        manager.draw()

        pygame.display.flip()
        clock.tick(FPS)

    manager.quit()
    pygame.quit()


if __name__ == "__main__":
    main()
```

**`game/scenes/manager.py` — 최소 버전**

```python
"""게임 상태 관리 (Day 036 뼈대)."""

import pygame

from ..settings import (SCREEN_WIDTH, SCREEN_HEIGHT, COLOR_BG,
                        COLOR_TEXT, COLOR_TEXT_DIM, COLOR_BULLET)
from ..utils import make_font, draw_text

TITLE_STATE = "TITLE"
PLAYING = "PLAYING"
GAME_OVER = "GAME_OVER"


class GameManager:
    """상태 전환과 화면 그리기를 담당합니다."""

    def __init__(self, screen):
        self.screen = screen
        self.state = TITLE_STATE

        self.fonts = {
            "big": make_font(44),
            "normal": make_font(22),
            "small": make_font(15),
        }

    def handle_event(self, event):
        """이벤트를 처리합니다. 계속 실행하면 True."""
        if event.type != pygame.KEYDOWN:
            return True

        if event.key == pygame.K_ESCAPE:
            return False

        if self.state == TITLE_STATE and event.key == pygame.K_RETURN:
            self.state = PLAYING
        elif self.state == PLAYING and event.key == pygame.K_g:
            self.state = GAME_OVER          # 임시: G 로 게임오버 테스트
        elif self.state == GAME_OVER and event.key == pygame.K_RETURN:
            self.state = TITLE_STATE

        return True

    def update(self):
        """상태를 갱신합니다."""
        pass                                 # Day 037 에서 구현

    def draw(self):
        """화면을 그립니다."""
        screen = self.screen
        cx = SCREEN_WIDTH // 2

        screen.fill(COLOR_BG)

        if self.state == TITLE_STATE:
            draw_text(screen, "SPACE SHOOTER", self.fonts["big"],
                      COLOR_BULLET, (cx, 160), center=True)
            draw_text(screen, "ENTER = 시작    ESC = 종료", self.fonts["normal"],
                      COLOR_TEXT, (cx, 300), center=True)

        elif self.state == PLAYING:
            draw_text(screen, "(게임 화면 — Day 037 에서 구현)",
                      self.fonts["normal"], COLOR_TEXT_DIM, (cx, 280), center=True)
            draw_text(screen, "G = 게임오버 테스트", self.fonts["small"],
                      COLOR_TEXT_DIM, (cx, 330), center=True)

        elif self.state == GAME_OVER:
            draw_text(screen, "GAME OVER", self.fonts["big"],
                      (231, 76, 60), (cx, 240), center=True)
            draw_text(screen, "ENTER = 타이틀로", self.fonts["small"],
                      COLOR_TEXT_DIM, (cx, 330), center=True)

        # 개발 중 상태 표시
        draw_text(screen, f"[{self.state}]", self.fonts["small"],
                  COLOR_TEXT_DIM, (12, SCREEN_HEIGHT - 26))

    def quit(self):
        """종료 처리."""
        pass
```

### Step 3. 클래스 설계도 작성

`docs/design.md`

```markdown
# 클래스 설계도

## 1. 상속 구조

pygame.sprite.Sprite
 └── Entity                      float 위치, rect 동기화, 경계 처리
      ├── Player                 이동, 발사, 체력, 무적
      ├── Bullet                 직진, 화면 밖 제거
      │    └── EnemyBullet       아래로
      ├── Enemy                  이동, 체력, 점수
      │    ├── FastEnemy         빠름 · 약함
      │    ├── TankEnemy         느림 · 튼튼
      │    └── Boss              대형 · 패턴 공격
      └── Item                   아래로 이동
           ├── HealItem          HP +30
           └── PowerItem         무기 강화

## 2. 관리 클래스 (Sprite 아님)

| 클래스 | 책임 | 주요 메서드 |
|---|---|---|
| GameManager | 상태 전환·이벤트 분배·그리기 | handle_event, update, draw |
| GameStats | 점수·목숨·콤보·통계 | add_kill, lose_life, accuracy |
| SpawnManager | 적 생성 타이밍·종류 선택 | update → Enemy 또는 None |
| ScreenShake | 흔들림 | shake, update, offset |

## 3. 스프라이트 그룹

| 그룹 | 용도 | 담기는 것 |
|---|---|---|
| all_sprites | 갱신·그리기 | 전부 |
| bullets | 충돌 (플레이어 총알) | Bullet |
| enemy_bullets | 충돌 (적 총알) | EnemyBullet |
| enemies | 충돌 | Enemy 계열 |
| items | 충돌 | Item 계열 |
| particles | 이펙트 | Particle |

## 4. Entity 인터페이스 (부모가 제공)

class Entity(pygame.sprite.Sprite):
    pos_x, pos_y        float 위치
    sync_rect()         float → rect 반영
    sync_pos()          rect → float 되돌림
    clamp_to_screen()   화면 안으로 제한
    is_out_of_screen()  화면 밖 판정
    kill_if_out()       화면 밖이면 제거

## 5. 각 클래스가 반드시 구현할 것

| 클래스 | update() 에서 하는 일 |
|---|---|
| Player | 타이머 감소 → 이미지 교체 → 위치 반영 → 경계 제한 |
| Bullet | 이동 → 위치 반영 → 화면 밖 제거 |
| Enemy | move() → 위치 반영 → 화면 밖 제거 |
| Item | 이동 → 위치 반영 → 화면 밖 제거 |
| Particle | 수명 감소 → 이동 → 크기·투명도 갱신 |

## 6. 충돌 처리 순서 (중요)

1. bullets ↔ enemies      공격이 먼저
2. enemy_bullets ↔ player
3. enemies ↔ player
4. items ↔ player

## 7. 의존 방향

main.py
  └→ scenes/manager.py
        └→ entities/*  effects/*  stats.py  db.py
              └→ surfaces.py  utils.py
                    └→ settings.py   (아무것도 import 안 함)

⚠️ 역방향 import 금지. entities 가 scenes 를 부르면 순환 참조.
```

## ⑤ 자주 하는 실수

### 기획 없이 코드부터 침

**증상** — 목요일까지 아무것도 완성되지 않습니다.
**해결** — 오늘 하루는 문서에 씁니다. **남은 4일이 훨씬 빨라집니다.**

### `Won't` 를 안 적음

**증상** — "이것도 넣으면 좋겠는데" 가 반복되며 Must 가 미완성으로 남습니다.
**해결** — 안 할 것을 **명시적으로 문서에** 적습니다.

### 완료 기준이 모호함

```
❌ "적 생성 기능"
✅ "3초마다 화면 위 무작위 위치에서 적이 생성된다"
```

**해결** — **"무엇을 보면 완료인가"** 를 적습니다.

### 수평으로 개발

**증상** — 클래스는 다 만들었는데 실행이 안 됩니다.
**해결** — **매일 실행 가능한 상태**를 유지합니다. 오늘도 창이 떠야 합니다.

### 일정을 낙관적으로 잡음

**증상** — "하루면 되겠지" 가 3일이 됩니다.
**해결** — **예상 시간의 2배**로 잡습니다. 남으면 Could 를 하면 됩니다.

### 리소스(이미지·사운드) 의존

**증상** — 이미지를 못 구해서 진도가 멈춥니다.
**해결** — [Day 020](day-020.md)처럼 **코드로 Surface 를 만듭니다.** 이미지는 나중에 교체합니다.

### 커밋을 안 함

**증상** — 목요일에 코드를 망가뜨렸는데 되돌릴 수 없습니다.
**해결** — **매일 저녁 반드시 커밋**합니다. 작동하는 상태에서만.

### 다른 PC 테스트를 마지막에

**증상** — 발표 당일 "제 컴퓨터에서는 됐는데요" 가 됩니다.
**해결** — **Day 039 에 반드시** 다른 PC 또는 새 가상환경에서 테스트합니다.

<details>
<summary>답 보기</summary>

| # | 기능 | 등급 | 이유 |
|---|---|---|---|
| ① | 플레이어 이동 | **Must** | 없으면 게임이 성립하지 않음 |
| ⑥ | 충돌 시 체력 감소 | **Must** | 실패 조건이 없으면 게임이 아님 |

**판단 기준 세 가지**

```
Must   — 이게 없으면 "게임"이라 부를 수 없는가?
Should — 없으면 완성도가 크게 떨어지는가?
Could  — 있으면 좋지만 없어도 발표할 수 있는가?
Won't  — 5일 안에 물리적으로 불가능한가?
```

> 하지만 **문서에 `Won't` 로 적어 두면** 수요일에 흔들리지 않습니다.
> "이건 다음 프로젝트에서" 라고 적어 두세요.
</details>
