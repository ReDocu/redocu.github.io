## ② 왜 필요한가

이번 주에 우리는 이미지 분류기를 만들었습니다(0.954). 그런데 그 모델을 "쓰는" 코드는
아직 학습 스크립트 안에 얽혀 있습니다 — 데이터로더, 학습 루프, 평가 함수 사이 어딘가에.
서빙하려면 질문 하나에 답하는 코드가 따로 필요합니다:

> **"이미지 파일 하나를 주면, 라벨과 확신도를 다오."**

이 단순한 질문에 숨은 함정이 이번 주 내내 하나씩 등장했습니다: 전처리가 다르면 조용히
틀리고([Day 083](day-083.md) ⑤), eval()을 잊으면 예측이 흔들리고([Day 081](day-081.md) ⑤),
no_grad()가 없으면 느려지고([Day 078](day-078.md) ⑤), 배치 차원을 잊으면 shape 에러
([Day 076](day-076.md)). 오늘 이 함정들을 전부 피해 간 **표준 추론 스크립트**를 완성합니다.

그리고 구조 하나를 미리 심습니다 — **로드와 예측의 분리.** 다음 주 FastAPI 서버는
"시작할 때 load_model() 한 번, 요청마다 predict() 여러 번"으로 정확히 이 두 함수를
가져다 씁니다 ([Day 096](day-096.md)). 오늘의 predict.py가 곧 MP3의 심장입니다.

## ③ 개념 설명

### 학습 코드와 추론 코드는 다른 물건

| | 학습 스크립트 (train) | 추론 스크립트 (predict) |
|---|---|---|
| 입력 | 데이터셋 전체 + 라벨 | **한 건** (라벨 없음) |
| 필요한 것 | 손실·optimizer·루프·체크포인트 | 모델 로드 + 전처리 + 순전파 |
| 실행 주기 | 가끔 (몇 시간짜리) | **항상** (요청마다, ms 단위) |
| 의존성 | 무거움 (데이터·MLflow…) | 가볍게 유지해야 (서버에 들어감) |

한 파일에 섞여 있으면 서빙 서버가 학습 의존성까지 짊어지고, 학습 코드 수정이 서빙을
깨뜨립니다. [Day 013](../01-python-data/day-013.md)의 관심사 분리가 모델 세계에 적용된 것입니다.

### 추론 경로의 4대 의무

```python
PREPROCESS = (학습과 같은 transform)      # ① 같은 전처리 — 다르면 조용히 틀림
model.eval()                              # ② 드롭아웃·BN을 추론 모드로 — 안 하면 출렁임
with torch.no_grad():                     # ③ 미분 기록 끔 — 안 하면 느리고 메모리 셈
x = PREPROCESS(img).unsqueeze(0)          # ④ 배치 차원 — 모델은 언제나 배치를 받음
```

이 넷은 체크리스트가 아니라 **구조로 박아 둘 것**들입니다 — predict.py 안에 있으면
쓰는 사람이 잊을 방법이 없습니다.

### 로드 1회 / 예측 N회

모델 로드(디스크 → 메모리, 가중치 복원)는 수백 ms~수 초짜리 작업이고, 예측은 수십 ms입니다.
로드를 예측 함수 안에 넣으면 매 요청이 로드 비용을 냅니다 — 커리큘럼 FAQ의
"요청마다 모델을 로드하면 왜 안 되나요?"가 이것이며, [Day 096](day-096.md)에서 실측합니다.
오늘은 함수 경계로만 분리해 둡니다: `load_model()` 과 `predict()`.

## ④ 단계별 실습

### Step 1. predict.py 작성 (1~3교시)

```python
# predict.py — 추론 전용 스크립트: 이미지 한 장 → 라벨과 확신도
# 사용법: python predict.py <이미지 경로>
import argparse
import sys
import torch
import torch.nn as nn
from PIL import Image
from torchvision import models, transforms

CKPT = "models/antbee_resnet18.pt"

# 학습(Day 083)과 반드시 같은 전처리 — 다르면 조용히 틀린다 (Day 097의 주제)
PREPROCESS = transforms.Compose([
    transforms.Resize(256), transforms.CenterCrop(224),
    transforms.ToTensor(),
    transforms.Normalize([0.485, 0.456, 0.406], [0.229, 0.224, 0.225]),
])


def load_model():
    """서버라면 시작 시 1회만 호출될 함수 (Day 096의 복선)."""
    ckpt = torch.load(CKPT, map_location="cpu")
    model = models.resnet18(weights=None)                 # 구조만 만들고
    model.fc = nn.Linear(model.fc.in_features, len(ckpt["classes"]))
    model.load_state_dict(ckpt["state_dict"])             # 가중치는 체크포인트에서
    model.eval()                                          # 추론 모드 고정!
    return model, ckpt["classes"]


def predict(model, classes, image_path):
    try:
        img = Image.open(image_path).convert("RGB")
    except Exception as e:
        sys.exit(f"이미지를 열 수 없습니다: {image_path} ({type(e).__name__})")
    x = PREPROCESS(img).unsqueeze(0)                      # (3,224,224) → (1,3,224,224) 배치 차원
    with torch.no_grad():
        probs = torch.softmax(model(x), dim=1)[0]
    top = probs.argmax().item()
    return {"label": classes[top], "confidence": round(probs[top].item(), 4),
            "probs": {c: round(p.item(), 4) for c, p in zip(classes, probs)}}


if __name__ == "__main__":
    ap = argparse.ArgumentParser(description="개미/벌 이미지 분류")
    ap.add_argument("image", help="이미지 파일 경로")
    args = ap.parse_args()
    model, classes = load_model()
    result = predict(model, classes, args.image)
    print(f"판정: {result['label']} (확신도 {result['confidence']:.1%})")
    print(f"전체 확률: {result['probs']}")
```

구조를 훑어보세요 — 4대 의무가 전부 코드 안에 있고([① PREPROCESS 상수, ② load_model의
eval(), ③ predict의 no_grad(), ④ unsqueeze(0)]), 학습 관련 import는 하나도 없습니다.
`load_model` 이 반환하는 `classes` — [Day 083](day-083.md)에서 체크포인트에 같이 저장해 둔
라벨 사전이 여기서 빛을 봅니다.

### 오늘 새로 나오는 실수

**추론 스크립트가 학습 코드를 import함** — `from day083_transfer import *` 식으로 가져오면
서버가 학습 의존성(데이터셋 다운로드 코드까지!)을 짊어집니다. predict.py는 **자급자족**이어야
합니다 — 필요한 것은 체크포인트 파일과 전처리 정의뿐.

**전처리를 predict.py에 복붙으로 두 벌 유지** — 오늘은 교육상 한 파일에 썼지만, 학습과 추론이
같은 PREPROCESS를 **한 모듈에서 import** 하는 것이 완성형입니다 ([Day 074](../03-machine-learning/day-074.md)의
src/ 구조 — MP3에서 그렇게 갑니다). 두 벌이 존재하는 순간 언젠가 한쪽만 수정됩니다.

**확신도를 확률로 과신** — 76.9%는 "이 모델의 소프트맥스 출력"이지 보정된 확률이 아닙니다.
특히 학습 분포 밖 입력(개미도 벌도 아닌 사진)에도 높은 확신도가 나올 수 있습니다 —
[Day 088](day-088.md) ⑤에서 이 문제를 다시 만납니다.

## 주간 퀴즈 15 — W17 (신경망 학습 실전)

<details>
<summary>1. 학습 곡선에서 과적합의 신호는?</summary>

train 지표는 계속 오르는데 valid 지표가 정점을 찍고 내려가기 시작하는 것 — 그 간격의 확대가 암기의 진행률입니다.

</details>

<details>
<summary>2. 검증 손실이 오르기 시작할 때의 대응 3가지는?</summary>

조기 종료(최고 시점 복원), 드롭아웃/가중치 감쇠(규제), 데이터 증강 또는 모델 축소. (주간 체크포인트!)

</details>

<details>
<summary>3. 드롭아웃이 학습 때만 켜져야 하는 이유와 그 스위치는?</summary>

추론에서 뉴런을 끄면 같은 입력에도 예측이 무작위로 달라집니다. 스위치는 model.train()/model.eval().

</details>

<details>
<summary>4. CNN이 MLP보다 적은 파라미터로 이미지를 잘 다루는 두 원리는?</summary>

가중치 공유(한 필터를 전 위치가 재사용 — 위치 불변)와 지역성(3×3 이웃만 봐 공간 구조 보존).

</details>

<details>
<summary>5. "공간은 절반, 채널은 배로"에서 풀링의 역할은?</summary>

구역 최댓값만 남겨 공간 해상도를 줄이고("어디쯤"만 유지), 뒤 층이 더 넓은 맥락을 보게 하며 계산량을 줄입니다.

</details>

<details>
<summary>6. 특징 추출과 파인튜닝의 차이와 선택 기준은?</summary>

특징 추출은 몸통 동결 + 머리만 학습(데이터 적음·도메인 유사), 파인튜닝은 전체를 작은 학습률로(데이터 있음·도메인 멂). 관례는 특징 추출부터.

</details>

<details>
<summary>7. 사전학습 모델에 ImageNet 통계 Normalize를 쓰는 이유는?</summary>

몸통이 그 자(전처리)로 잰 입력에 맞춰 학습됐기 때문 — 내 데이터 통계로 재면 에러 없이 성능만 떨어지는 조용한 실패가 납니다.

</details>

<details>
<summary>8. 체크포인트에 모델 외에 꼭 들어가야 할 것과 이유는?</summary>

optimizer의 state_dict(모멘텀 등)와 epoch — 없으면 재개 직후 학습이 출렁이고 어디서부터인지도 모릅니다. last(재개용)/best(배포용) 분리도 관례.

</details>

<details>
<summary>9. GPU 학습이 시드를 고정해도 완전 재현이 안 되는 이유와 보고 관례는?</summary>

수천 코어의 병렬 덧셈 순서가 실행마다 달라 부동소수점 결과가 미세하게 변합니다. 여러 시드의 평균±표준편차로 보고합니다.

</details>

<details>
<summary>10. 추론 스크립트의 4대 의무는?</summary>

학습과 같은 전처리 · model.eval() · torch.no_grad() · 배치 차원(unsqueeze(0)).

</details>
