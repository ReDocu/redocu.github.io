## ① 학습 목표

이 레슨을 마치면 이렇게 할 수 있습니다.

- 결함을 **우선순위 순으로 하나씩** 고치고, 수정마다 **스모크 테스트**로 검증할 수 있다.
- 결함 ID 를 **커밋 메시지·재현 절차·회귀 확인**에 연결해 수정 이력을 관리할 수 있다.

- **오탐을 유형화**해 유형별로 대응하고, 미검출과의 **균형점**을 지표로 판단할 수 있다.
- **1시간 이상 무중단 테스트**를 계측·판정하고, **24시간으로 외삽**해 위험을 예측할 수 있다.

### 1시간이 왜 기준인가

시연 15분 + 심사·질의 10분 + 세팅·대기 20분 — **발표장에서 켜 두는 시간은
약 45분**입니다. 1시간은 "발표를 무사히 마칠 수 있는가" 의 최소 기준입니다.

```
★ 그러나 1시간 통과 ≠ 24시간 통과
  · 메모리 +6MB/h  → 일주일 +1GB
  · 디스크 +84MB/h → 9일이면 가득
  · 발열 68℃       → 여름엔 76℃ → 스로틀링
→ 그래서 오늘 마지막에 "24시간 외삽" 을 합니다
```

## ③ 개념 설명

### 기능 동결(feature freeze) 이란

```
기능 동결 = ★ 이 시점부터 "무엇을 만들지" 를 더 이상 바꾸지 않는다

  동결 전                        동결 후
  ────────────────────          ────────────────────
  기능을 추가한다          →     있는 기능을 고친다
  "되게 만든다"            →     "안 깨지게 만든다"
  진척 = 기능 수           →     진척 = 결함 수 감소
```

동결은 개발을 멈추는 것이 아니라 **"무엇을 만들지" 를 멈추는 것**입니다.

| 단계 | 허용되는 변경 | 우리 일정 |
|---|---|---|
| 기능 동결 (Feature Freeze) | 결함 수정 · 문구 · 설정 | ★ **Day 177 09:00** |
| 코드 동결 (Code Freeze) | Critical 결함만 | Day 178 12:00 |
| 릴리스 동결 (Release Freeze) | **아무것도** | Day 179 18:00 |

### ★ 왜 동결이 지켜지기 어려운가

```
동결을 깨는 유혹은 항상 ★ "좋은 아이디어" 의 얼굴로 옵니다

  ① "이거 30분이면 되는데"    → 30분 코딩 + ★ 2시간 디버깅 + 재검증 1시간
  ② "지금 안 하면 아쉬워서"    → 아쉬움은 발표를 망치는 것보다 낫습니다
  ③ "심사위원이 물어볼 것 같아" → "다음 개선 항목입니다" 가 오히려 좋은 답입니다
  ④ "옆 조는 그것도 있던데"    → 옆 조는 그것 때문에 지금 밤을 새고 있습니다
```

| | 동결 없음 | 동결 |
|---|---|---|
| 남은 3일의 변경 건수 | 40~60건 | **10~15건** |
| 각 변경의 검증 시간 | 0~5분 | **20분 이상** |
| 발표 전날 밤 · 당일 첫 실행 | 미검증 코드 다수 · ★ **도박** | **전부 검증됨** |

### 결함 우선순위 — 심각도 × 빈도

```
        빈도 →   항상        가끔        드물게
      ┌──────────┬──────────┬──────────┐
Critical │  ★ P0   │   ★ P0   │    P1    │
 Major   │     P1   │    P1    │    P2    │
 Minor   │    P2    │    P2    │    P3    │
Trivial  │    P3    │    P3    │     안 함 │
      └──────────┴──────────┴──────────┘
```

| 심각도 | 정의 | 예 |
|---|---|---|
| **Critical** | ★ 시스템이 목적을 달성하지 못함 | 알림이 안 감 · 프로세스 죽음 |
| **Major** | 목적은 달성하나 기준 미달 | 오탐 다발 · 지연 초과 |
| **Minor** / **Trivial** | 우회 가능 / 알아채기 어려움 | 표 넘침 · 시각 표기 / 오타 |

| 순위 | ID | P | 예상 시간 |
|---|---|---|---|
| 1~3 | **D-01** 알림 지연 · **D-02** 카메라 · **D-03** 재시작 유실 | ★ **P0** | 40 / 50 / 40분 |
| 4~5 | **D-07** 알림 중복 · **D-09** 메모리 증가 | **P1** | 30 / 45분 |
| 6~8 | D-04 · D-06 · D-08 | P1 | 오후 |
| 9 | **D-05** 원거리 helmet | P2 | 재학습 필요 → 보류 |
| 10~13 | D-12 · D-10 · D-11 · D-13 | P2~P3 | 각 3~12분 |
| 14 | D-14 README | P3 | Day 178 |

**D-05 를 보류한 이유.** 원인은 학습 데이터에 6m 이상 helmet 샘플이 12장뿐인
것인데, 데이터 추가 → 재학습 → 재평가 → 재배포에 **최소 6시간**이 듭니다.
오늘 안에는 불가능하므로 **"한계" 로 문서화**하고(Day 178), 대신 운영

### 예외 ① 카메라 끊김

| 증상 | `isOpened()` | `read()` | 원인 | 대응 |
|---|---|---|---|---|
| **A. 열기 실패** | `False` | — | 장치 없음 · 권한 | 재시도 + 백오프 |
| **B. ★ 좀비 캡처** | `True` | `(False, None)` | USB 재열거 | **release 후 재생성** |
| **C. 멈춤(hang)** | `True` | **블록** | 드라이버 · CSI | 워치독 + 재시작 |

**B 가 D-02 의 정체입니다.** USB 를 뽑으면 커널이 장치 노드를 지우고, 다시
꽂으면 `/dev/video0` → `/dev/video2` 로 **번호가 바뀔 수 있습니다.** 그런데
`cap` 객체는 계속 "열려 있다" 고 보고합니다 — `isOpened() == True` 라 재연결
조건에 걸리지 않고 **`read()` 만 영원히 `False`** 를 돌려줍니다.

```bash
# ★ 장치 번호가 바뀌어도 같은 경로를 유지하는 방법
$ ls -l /dev/v4l/by-id/
usb-046d_HD_Pro_Webcam_C920_A1B2C3-video-index0 -> ../../video0
# ★ 이 경로를 쓰면 인덱스가 바뀌어도 동일합니다
```

CSI 카메라(파이 카메라 모듈)라면 로그 문구로 원인을 가릅니다.
`Unable to request buffers` 는 다른 프로세스가 점유한 것(중복 실행 확인),
`Camera frontend timeout` 은 **리본 케이블 접촉**, `Failed to queue buffer` 는
메모리 부족(`gpu_mem` 조정), `pipeline handler in use` 는 libcamera 충돌입니다.

> ⚠️ **CSI 리본 케이블은 발표장 이동 중에 가장 잘 빠집니다.**
> 파이를 가방에 넣고 옮기면 커넥터가 미세하게 들립니다.
> **발표 전 반드시 물리 점검 → 스모크 테스트** 를 하세요.

**★ 재연결 루프와 지수 백오프**

```
✗ 즉시 재시도  → ★ CPU 100% · 로그 폭발 · 디스크 고갈
✓ 지수 백오프 + 상한
  시도 1 실패 → 1초 → 2초 → 4초 → 8초 → 16초 → 30초 (상한)
  상한이 없으면 1024초(17분) 뒤에나 시도 → 복구가 늦습니다
```

| 대기 전략 | CPU | 복구 지연 | 로그량 | 평가 |
|---|---|---|---|---|
| 즉시 재시도 | ★ 100% | 즉시 | 폭발 | ✗ |
| 고정 1초 / 고정 30초 | 3% / 0.1% | 1초 / 최대 30초 | 많음 / 적음 | △ |
| **지수 + 상한 30초** | 0.2% | 1~30초 | 적음 | ✅ |

**연속 실패 시 알림 단계** — 5회(약 30초) 로그 WARNING, 20회(약 8분) 텔레그램
"카메라 연결 끊김", 이후 10분마다 재알림하되 **최대 3회까지만**.
재알림 상한이 없으면 밤새 500통이 옵니다.

### 예외 ② 네트워크 단절

[Day 169](day-169.md) 에서 만든 **아웃박스 큐(`EventSync`)가 이미 있습니다.**
전송에 실패하면 `queue.db` 에 보관하고 30초마다 재시도합니다. 오늘 할 일은
"만드는 것" 이 아니라 **"정말 되는지 검증하고 상한을 추가하는 것"** 입니다.

| 실패 | `requests` 예외 | 재시도 | 비고 |
|---|---|---|---|
| Wi-Fi 끊김 · 서버 다운 | `ConnectionError` | ✅ | 즉시 실패 · 연결 거부 |
| **DNS 실패** | `ConnectionError` | ✅ | 최대 5초 소모 |
| 서버 5xx | 없음 (응답 옴) | ✅ | 백오프 |
| **서버 4xx** | 없음 | ★ **금지** | 100번 보내도 400 |
| 응답 지연 | `ReadTimeout` | ✅ | 타임아웃 설정값 |
| TLS 오류 | `SSLError` | ❌ | 인증서 |

**4xx 를 재시도하면 큐에 영원히 남아 큐 전체를 막습니다.** 로그를 남기고
큐에서 제거하세요 (Day 159 코드에 이미 반영돼 있습니다).

```
★ DNS 를 조심하세요

  SERVER_URL = "http://cctv-server.local:5000"    ← mDNS 이름
  · 공유기가 재시작되면 이름 해석 실패
  · 발표장 Wi-Fi 는 mDNS 가 막힌 경우가 많음 · DNS 조회에만 5초 소모

  대응 ① 시연용은 IP 직접 지정  http://192.168.0.42:5000
       ② /etc/hosts 고정 매핑   ③ 두 주소 폴백
```

| 값 | 너무 짧으면 | 너무 길면 | ★ 권장 |
|---|---|---|---|
| 연결 timeout | 정상인데 실패 처리 | 끊긴 걸 오래 못 앎 | **3초** |
| 읽기 timeout | 큰 스냅샷 전송 실패 | 스레드가 오래 묶임 | **10초** |
| 재시도 간격 | 트래픽 폭증 | 복구 늦음 | **30초** |

근거는 실측입니다. 스냅샷 평균 180KB · 업로드 평균 0.4초 · p95 1.9초 —
읽기 10초는 **p95 의 5배 여유**입니다.

> ⚠️ **`timeout` 을 지정하지 않으면 무한 대기입니다.**
> `requests` 의 기본값은 **`None`(영원히)** 입니다.
> 서버가 응답하지 않으면 **전송 스레드가 영구히 묶이고 큐가 멈춥니다.**

**★ 큐가 무한정 커지지 않게 — 오늘 반드시 추가할 것**

```
네트워크가 3일 끊겼다고 가정
  이벤트 200건/일 × 3일 = 600건 · 스냅샷 180KB × 600 = ★ 108MB
  → 큐가 디스크를 잡아먹고 → ★ 로컬 기록도 실패 → 시스템 전체 정지
```

| 정책 | 값 | 근거 |
|---|---|---|
| 큐 최대 건수 / 용량 | **2,000건 / 500MB** | 200건/일 × 10일 · 스냅샷 포함 |
| 최대 보관 기간 / 재시도 | **7일 / 100회** | 이후는 가치 낮음 · 30초 × 100 ≈ 50분 |
| ★ 초과 시 | **가장 오래된 것부터 폐기** | 최신이 더 중요 |
| 폐기 시 | **로그 ERROR + 카운터** | 조용히 버리면 안 됨 |

```
★ 왜 "오래된 것부터" 인가
  방금 전 침입 → 지금 대응해야 함 / 3일 전 침입 → 기록으로만 의미
  → 도메인에 따라 다릅니다 (은행 거래라면 반대입니다)
```

**단, 로컬 `events.db` 는 절대 버리지 않습니다.** 아웃박스 큐는 "서버로 보낼 것"
이라 폐기할 수 있지만, 로컬 DB 는 "우리가 본 것" 이라 폐기하면 안 됩니다.
Day 154 의 결정 — **"서버가 죽어도 1단계는 계속 동작"** 이 그 근거입니다.

### 예외 ④~⑧ — 나머지 다섯 가지

**④ 메모리 부족과 스왑**

| 증상 | 원인 후보 | 확인 |
|---|---|---|
| RSS 계속 증가 | ★ 프레임 큐 무한 | `queue.qsize()` |
| RSS 계단식 증가 | 리스트에 결과 누적 | 전역 리스트 검색 |
| 스왑 사용 시작 | 전체 메모리 압박 | `free -m` |
| **OOM Killer** | 커널이 종료 | `dmesg \| grep -i oom` |

```
★ 스왑이 시작되면 FPS 가 무너집니다
  microSD 스왑 40MB/s vs RAM 6,000MB/s → 150배
  → 스왑에 들어간 순간 12 FPS → 0.8 FPS (멈춘 것처럼 보임)
$ dmesg | grep -i "killed process"
[86412.339] Out of memory: Killed process 1834 (python3) anon-rss:1893220kB
```

대응은 한 줄입니다. `queue.Queue()` 를 **`queue.Queue(maxsize=2)`** 로 바꾸고,
가득 차면 `get_nowait()` 로 **가장 오래된 프레임을 버린 뒤** 최신을 넣습니다.
CCTV 에서 밀린 프레임은 쓸모가 없습니다. 3초 전 프레임을 지금 분석하면
알림이 3초 늦습니다 — Day 153 의 `LatestFrameCapture` 가 바로 이 원리입니다.

**⑤ DB 잠김 (`database is locked`)**

| 대책 | 방법 | 효과 |
|---|---|---|
| ★ **WAL 모드** | `PRAGMA journal_mode=WAL` | 읽기·쓰기 동시 |
| busy timeout | `connect(..., timeout=5)` | 5초까지 대기 |
| 짧은 트랜잭션 | 즉시 commit · close | 잠금 최소화 |
| 연결 재사용 금지 | 스레드마다 새 연결 | 스레드 안전 |

연결을 여는 함수 하나에 `timeout=5.0` · `journal_mode=WAL` ·
`synchronous=NORMAL`(SD 카드 수명) · `busy_timeout=5000` 을 **모아 두고**
프로젝트 전체가 그 함수만 쓰게 하면 됩니다.

> ⚠️ **`check_same_thread=False` 로 연결을 공유하지 마세요.**
> 편해 보이지만 **동시 쓰기에서 DB 파일이 손상**될 수 있습니다.

**⑥ 시각 동기 실패**

라즈베리파이에는 **RTC 가 없습니다.** 전원을 끄면 시간을 잊고, 부팅하면
**1970-01-01 부터** 시작해 NTP 동기까지 10~30초가 걸립니다. 그 사이에
이벤트가 나면 `ts = "1970-01-01T00:00:14"` 로 **목록 맨 아래에 처박힙니다.**

| 대응 | 방법 |
|---|---|
| ★ 시각 동기 대기 | `timedatectl show -p NTPSynchronized --value` == `yes` |
| 최대 대기 | 60초. 이후엔 그냥 시작하되 `"clock_synced": false` 를 남긴다 |
| systemd 의존 | `After=time-sync.target` |

**⑦ 알림 API 장애**

| 상태 | 재시도 | 대응 |
|---|---|---|
| ★ **429** | ✅ | `Retry-After` 초만큼 대기 |
| 5xx | ✅ | 지수 백오프 |
| **401 · 403** | ❌ | 토큰 문제. 로그 ERROR + 폴백 |
| ConnectionError | ✅ | 백오프. 5회 실패 시 폴백 |

**폴백 경로를 하나 더 두세요.** 1순위 텔레그램 · 2순위 웹 `/status` 배지 ·
3순위 GPIO 부저·LED. 발표장에서 텔레그램이 막히는 일은 흔하므로 시연
시나리오는 **2순위(웹 화면)까지** 준비해야 안전합니다.

**⑧ 전원 순단**

| 대책 | 방법 | 비용 |
|---|---|---|
| ★ **WAL + synchronous=NORMAL** | 쓰기 중 손상 확률 급감 | 0 |
| 자동 재시작 · 무결성 검사 | `Restart=always` · `PRAGMA integrity_check` | 0 |
| UPS · 보조배터리 | 파이용 5V PD 배터리 | 2~4만원 |

**발표 당일 대책** — 파이를 보조배터리로 구동하면 콘센트를 옮기는 동안에도
꺼지지 않습니다. 시연 중 케이블에 발이 걸려도 살아남습니다.

### 워치독과 자가 치유

죽는 것보다 무서운 것은 **"살아 있는데 아무것도 안 하는 것"** 입니다.
프로세스는 살아 있으니 systemd 는 정상으로 보는데, `read()` 에서 영원히
블록돼 있으면 **아무도 모릅니다.**

```
       [검출 루프]                    [워치독]
      매 프레임 hb 기록  ────→   매 10초 mtime 확인
                                        │
                                 ★ 15/30/60초 경과 시
                                 ① WARNING ② 알림 ③ ★ 재시작
```

| 방식 | 구현 | 장점 | 단점 |
|---|---|---|---|
| 파일 mtime / 별도 스레드 | `Path.touch()` / 같은 프로세스 | 간단 · 즉시 | SD 쓰기 · 같이 멈춤 |
| ★ **systemd Watchdog** | `sd_notify WATCHDOG=1` | OS 가 감시 | 라이브러리 필요 |

```ini
[Service]
Type=notify
WatchdogSec=30          # ★ 30초 안에 하트비트가 없으면 SIGABRT + 재시작
```

**★ 재시작이 근본 해결이 아님을 반드시 남기세요**

워치독이 하루 40번 재시작하면 겉으로는 "잘 돌아감" 이지만 **아무도 원인을
모르는 상태**이고, 하필 발표 중에 재시작이 일어나 15초가 빕니다.
판정 기준은 **하루 0회 정상 / 1~2회 관찰 / 3회 이상 근본 원인 조사**이며,
**1시간 테스트 중 1회라도 있으면 안정화 실패**로 봅니다.

> ⚠️ **워치독은 "증상 완화" 이지 "치료" 가 아닙니다.**
> 재시작으로 넘어가면 **원인은 그대로 남아 발표 당일에 다시 나옵니다.**

### ★ 오탐 줄이기 — 임계값 최종 조정

심사위원 앞에서 아무도 없는데 "사람 감지!" 알림이 세 번 울리면
**시스템 신뢰도가 0 이 됩니다.** 그렇다고 추측으로 임계값을 올리면 안 됩니다.

```
★ 오탐 대응 4단계
  ① 1시간 돌리며 모든 이벤트 스냅샷을 남긴다
  ② 사람이 눈으로 정탐/오탐을 판정한다
  ③ 오탐을 유형으로 묶는다   ④ 유형별로 다른 대응을 한다
```

| 수단 | 무엇을 막나 | 미검출 영향 |
|---|---|---|
| **conf 상향** / **클래스별 conf** | 전반적 약한 검출 / 특정 클래스만 | 큼 / 작음 |
| **ROI 축소** / **정적 마스크** | 관심 밖 영역 / 항상 같은 자리 | 없음 |
| **최소 박스 크기 · 종횡비** | 그림자 · 아주 작은 오검출 | 원거리 손실 |
| **N-of-M 강화** | ★ 순간적 오탐 | 지연 증가 |

**N-of-M** 은 M 프레임 중 N 프레임 이상 검출되어야 인정하는 방식입니다.
`3/5` → `4/6` 으로 올리면 한두 프레임 튀는 오탐이 사라지고, 진짜 사람은
연속으로 검출되므로 그대로 통과합니다. 대가는 판정이 **0.18초 늦어지는 것**
뿐이라 목표 5초에 비하면 무시할 수 있습니다.

```
★ 오탐을 줄이면 미검출이 늘어납니다

       conf 낮음 ←───────────────→ conf 높음
       오탐 많음                     미검출 많음
       Recall 0.95 / Precision 0.52  Recall 0.72 / Precision 0.97

  ★ 어디를 고를 것인가?  →  Day 171 성공 기준이 정합니다
    mAP@0.5 ≥ 0.75 · 8 FPS 이상 · 알림 지연 5초 이내
    (Day 176 추가) 오탐 3건/시간 이하 · 미검출률 15% 이하

```

**안전 감시 도메인의 판단.** helmet 미착용을 놓치면 사고 위험이 있으므로
원래는 Recall 우선입니다(Day 148). 그런데 **오탐이 시간당 47건이면 아무도
보지 않습니다.** "무시되는 알림" 은 없는 알림과 같습니다. 그래서 균형점은
**오탐을 줄이되 Recall 0.85 이상 유지**입니다 (상세 지표표는 Step 5).

> ⚠️ **임계값 조정은 "더 좋게" 가 아니라 "어느 쪽 실수를 감당할 것인가" 의 선택입니다.**
> 완벽한 값은 없습니다. **선택했다는 사실과 근거를 문서로 남기는 것**이 안정화입니다.

### ★ 1시간 이상 무중단 테스트 (soak test)

기능 테스트는 1회 실행해 성공/실패를 봅니다. soak test 는 **1시간 방치하고
시간에 따른 변화**를 봅니다.

```
★ 측정 항목 16가지 (기준은 Step 7 판정표)
  가동시간 · 프레임 수 · FPS · 이벤트 수 · 오탐 · 미검출
  CPU · RSS 추이 · 온도 · 스로틀 플래그 · 디스크 증가량
  알림 성공률 · 알림 지연 p95 · 재시작 횟수 · 아웃박스 잔량 · ERROR 수
```

**8번(RSS)과 14번(재시작)이 가장 중요합니다.** 나머지가 다 좋아도 RSS 가
계속 오르면 24시간 뒤에 죽고, 재시작이 1회라도 있으면 발표 중에 일어납니다.

**★ 1시간에 문제없다고 24시간이 괜찮은 것은 아닙니다**

```
① 디스크  84MB/h × 24 = 2.0GB/일 → 남은 18.4GB → ★ 9.2일 후 가득
② 메모리  +6MB/h × 24 = +144MB/일 → 7일이면 ★ MemoryMax 도달
③ 온도    1시간 68.2℃ (실내 24℃) → 한여름 32℃ → 76℃ → 스로틀 4℃ 전
④ 로그    2.1MB/h × 24 = 50MB/일 → 회전 10MB×3 이면 14시간분만 보존
```

선형으로 늘어나지 않는 것도 있습니다 (온도는 포화하고, 오탐은 야간에 줄어듭니다).
그래서 **주간 1시간 수치를 곱한 "최악 가정 상한"** 으로 봅니다.

**★ 비밀값 점검 — 발표 화면에 토큰이 뜨면**

| 위험 | 확인 방법 | 조치 |
|---|---|---|
| 코드에 하드코딩 | `grep -rn "bot[0-9]\{8,\}"` | 환경변수 |
| ★ 로그에 출력 | `grep -rn "TOKEN\|SECRET" *.log` | 마스킹 |
| git 히스토리 | `git log -S "bot" --oneline` | 토큰 재발급 |
| 설정 파일 커밋 | `git ls-files \| grep env` | `.gitignore` |

```python
class SecretFilter(logging.Filter):
    """★ 로그에서 토큰을 가린다"""
    PATTERNS = [
        (re.compile(r"bot\d{8,}:[A-Za-z0-9_-]{30,}"), "bot***:***"),
        (re.compile(r"(chat_id=)\d+"), r"\1***"),
    ]

    def filter(self, record):
        msg = record.getMessage()
        for pat, rep in self.PATTERNS:
            msg = pat.sub(rep, msg)
        record.msg = msg
        record.args = ()
        return True
```

> ⚠️ **git 에 한 번 올라간 토큰은 지워도 히스토리에 남습니다.**
> `git rm` 으로는 부족합니다. **토큰을 즉시 재발급**하는 것이 유일한 해결입니다.

```python
    sys.exit(0 if passed == total else 1)


if __name__ == "__main__":
```

```python
"""pi/resilience.py — 카메라 · 네트워크 · 디스크 예외 대응 (Day 177)

새 기능이 아니라 ★ 있는 기능이 안 죽게 하는 코드입니다.
카메라를 열고 읽고 다시 붙는 본문은 Day 164 그대로이므로 여기서는 생략합니다.
"""
from __future__ import annotations

import logging
import shutil
import sqlite3
import subprocess
import time
from dataclasses import dataclass, field
from pathlib import Path

from web.resilience import ResilientCamera as BaseCamera    # Day 164

logger = logging.getLogger(__name__)


# ═══════════ ① 카메라 — 재열거 확인과 알림 억제만 추가 (D-02) ═══════════

class ResilientCamera(BaseCamera):
    """재연결 로직은 Day 164 것을 그대로 쓰고, 두 가지만 더합니다.

    · 5회 연속 실패  → 장치 목록을 찍어 번호가 바뀌었는지 확인
    · 20회 연속 실패 → 알림. 단 최대 3회까지만 (밤새 500통 방지)
    """

    warn_after, notify_after, notify_repeat = 5, 20, 3

    def _list_devices(self):
        """USB 재열거로 장치 번호가 바뀌었는지 확인"""
        try:
            out = subprocess.run(["v4l2-ctl", "--list-devices"],
                                 capture_output=True, text=True, timeout=5)
            logger.warning("현재 비디오 장치:\n%s", out.stdout.strip())
        except Exception:
            logger.warning("현재 비디오 장치: %s",
                           [str(d) for d in sorted(Path("/dev").glob("video*"))])

    def on_reconnect_failed(self, streak: int):
        """Day 164 재연결 루프가 실패할 때마다 부르는 훅"""
        if streak == self.warn_after:
            logger.warning("카메라 재연결 %d회 연속 실패", streak)
            self._list_devices()
        if streak >= self.notify_after and self.notify_sent < self.notify_repeat:
            self.notify_sent += 1
            msg = (f"⚠ 카메라 연결 끊김\n연속 실패 {streak}회\n"
                   f"마지막 정상 {time.time() - self.last_ok_ts:.0f}초 전")
            if self.notifier:
                self.notifier.put(f"camera_down_{self.notify_sent}", msg)
            logger.error("%s", msg.replace("\n", " / "))


# ═══════════ ② 네트워크 — 아웃박스 큐에 상한을 둔다 ═══════════

@dataclass
class QueuePolicy:
    max_items: int = 2000
    max_bytes: int = 500 * 1024 * 1024
    max_age_days: int = 7
    max_attempts: int = 100
    drop_oldest_first: bool = True            # ★ 최신을 살린다


class OutboxGuard:
    """★ Day 169 EventSync 의 큐를 옆에서 감시·정리한다

    기존 코드를 고치지 않습니다 (동결 원칙 — 변경 최소화).
    """

    def __init__(self, queue_db, policy: QueuePolicy | None = None,
                 notifier=None):
        self.db_path = str(queue_db)
        self.policy = policy or QueuePolicy()
        self.notifier = notifier
        self.dropped_total = 0
        self.last_warn = 0.0

    def enforce(self) -> dict:
        """정책을 적용해 초과분을 폐기한다 (조용히 버리지 않는다)"""
        if not Path(self.db_path).exists():
            return {"dropped": 0}
        dropped, reasons = 0, []
        order = "ASC" if self.policy.drop_oldest_first else "DESC"
        db = self._open()                        # WAL · timeout=5.0 로 연다
        try:
            for name, sql, params in [
                ("age", "DELETE FROM queue WHERE created < ?",
                 (time.time() - self.policy.max_age_days * 86400,)),
                ("attempts", "DELETE FROM queue WHERE attempts >= ?",
                 (self.policy.max_attempts,))]:
                cur = db.execute(sql, params)
                if cur.rowcount > 0:
                    dropped += cur.rowcount
                    reasons.append(f"{name}:{cur.rowcount}")

            # 건수 초과 — 오래된 것부터
            n = db.execute("SELECT COUNT(*) c FROM queue").fetchone()["c"]
            excess = n - self.policy.max_items
            if excess > 0:
                cur = db.execute(
                    f"DELETE FROM queue WHERE event_id IN (SELECT event_id "
                    f"FROM queue ORDER BY created {order} LIMIT ?)", (excess,))
                dropped += cur.rowcount
                reasons.append(f"max_items:{cur.rowcount}")
            db.commit()

            dropped += self._enforce_bytes(db, order, reasons)   # 용량 초과
        except sqlite3.OperationalError as e:
            logger.warning("아웃박스 정리 실패: %s", e)
            return {"dropped": 0}
        finally:
            db.close()

        if dropped:
            self.dropped_total += dropped
            logger.error("아웃박스 폐기 %d건 (%s) — 누적 %d건",
                         dropped, ",".join(reasons), self.dropped_total)
            if self.notifier and time.time() - self.last_warn > 3600:
                self.last_warn = time.time()
                self.notifier.put(f"outbox_drop_{int(time.time())}",
                                  f"⚠ 서버 전송 큐 초과 — {dropped}건 폐기\n"
                                  f"누적 {self.dropped_total}건")
        return {"dropped": dropped, "reasons": reasons}


# ═══════════ ③ 디스크 — 차기 전에 줄이고, 안 되면 축소 운전 ═══════════

@dataclass
class DiskThresholds:
    warn_pct: float = 20.0
    alert_pct: float = 10.0
    critical_pct: float = 5.0        # 여기서 스냅샷 중단
    fatal_pct: float = 2.0
    retain_days: list = field(default_factory=lambda: [30, 14, 7, 3])


class DiskGuard:
    """디스크가 차기 전에 스스로 줄인다 (D-06)

    normal → warn(14일 정리) → alert(7일+알림)
           → critical(스냅샷 중단, 기록·알림은 계속) → fatal(로그 회전)
    """

    def __init__(self, snapshot_dir, log_dir=None,
                 thresholds: DiskThresholds | None = None,
                 notifier=None, check_interval=60.0):
        self.snap_dir, self.log_dir = Path(snapshot_dir), log_dir
        self.th = thresholds or DiskThresholds()
        self.notifier, self.check_interval = notifier, check_interval
        self.state, self.snapshot_enabled = "normal", True
        self.last_check = self.last_notify = 0.0
        self.cleanups, self.freed_mb_total = 0, 0.0

    def usage(self) -> dict:
        total, used, free = shutil.disk_usage("/")
        return {"total_gb": round(total / 1024**3, 2),
                "used_gb": round(used / 1024**3, 2),
                "free_gb": round(free / 1024**3, 2),
                "free_pct": round(free / total * 100, 2)}

    def _cleanup(self, days: int) -> float:
        """days 일 이전 스냅샷을 지우고 확보한 용량(MB)을 돌려준다"""
        cutoff, freed, removed = time.time() - days * 86400, 0, 0
        for p in self.snap_dir.rglob("*.jpg"):
            try:
                if p.stat().st_mtime < cutoff:
                    freed += p.stat().st_size
                    p.unlink()
                    removed += 1
            except OSError:
                continue
        mb = freed / 1024 / 1024
        if removed:
            self.cleanups += 1
            self.freed_mb_total += mb
            logger.warning("디스크 정리 — %d일 이전 %d개 (%.1fMB)",
                           days, removed, mb)
        return mb

    def _notify(self, text, key):
        if self.notifier and time.time() - self.last_notify > 1800:
            self.last_notify = time.time()
            self.notifier.put(key, text)

    def check(self, force=False) -> dict:
        now = time.time()
        if not force and now - self.last_check < self.check_interval:
            return {"state": self.state,
                    "snapshot_enabled": self.snapshot_enabled}
        self.last_check = now
        u = self.usage()
        free, prev = u["free_pct"], self.state

        if free > self.th.warn_pct:
            self.state, self.snapshot_enabled = "normal", True
        elif free > self.th.alert_pct:
            self.state, self.snapshot_enabled = "warn", True
            self._cleanup(self.th.retain_days[1])
        elif free > self.th.critical_pct:
            self.state, self.snapshot_enabled = "alert", True
            self._cleanup(self.th.retain_days[2])
            self._notify(f"⚠ 디스크 여유 {free:.1f}%\n7일 이전 스냅샷 정리",
                         f"disk_alert_{int(now)}")
        elif free > self.th.fatal_pct:
            self.state = "critical"
            self._cleanup(self.th.retain_days[3])
            u2 = self.usage()
            if u2["free_pct"] <= self.th.critical_pct:
                self.snapshot_enabled = False   # 정리해도 부족 → 사진만 중단
                logger.error("디스크 %.1f%% — 스냅샷 저장 중단 "
                             "(이벤트 기록·알림은 계속)", u2["free_pct"])
                self._notify(f"🚨 디스크 여유 {u2['free_pct']:.1f}%\n"
                             f"스냅샷 저장을 중단했습니다\n"
                             f"이벤트 기록과 알림은 계속됩니다",
                             f"disk_critical_{int(now)}")
            else:
                self.snapshot_enabled = True
        else:
            self.state, self.snapshot_enabled = "fatal", False
            self._cleanup(1)
            self._rotate_logs()             # 최후 수단 — 오래된 로그 삭제
            logger.critical("디스크 %.1f%% — 축소 운전", free)

        if prev != self.state:
            logger.warning("디스크 상태 전이 %s → %s (여유 %.1f%%)",
                           prev, self.state, free)
        return {"state": self.state,
                "snapshot_enabled": self.snapshot_enabled, **u}

    def can_save_snapshot(self) -> bool:
        """검출 루프가 스냅샷을 저장하기 전에 매번 물어본다"""
        self.check()
        return self.snapshot_enabled
```

```python
"""pi/state.py — ★ 재시작 복구용 상태 체크포인트 (D-03)"""
from __future__ import annotations

import json
import logging
import time
from pathlib import Path

logger = logging.getLogger(__name__)
STATE_PATH = Path("/var/lib/cctv/state.json")
MAX_AGE_SEC = 30.0            # ★ 이보다 오래된 상태는 버린다


def save_state(state: dict, path: Path = STATE_PATH) -> None:
    """★ 원자적 쓰기 — 쓰는 도중 죽어도 파일이 깨지지 않는다"""
    path.parent.mkdir(parents=True, exist_ok=True)
    payload = dict(state, _saved_at=time.time())
    tmp = path.with_suffix(".tmp")
    try:
        tmp.write_text(json.dumps(payload, ensure_ascii=False), "utf-8")
        tmp.replace(path)                    # rename 은 원자적
    except OSError:
        logger.warning("상태 저장 실패", exc_info=True)


def load_state(path: Path = STATE_PATH) -> dict:
    """시작 시 복원. 손상됐거나 너무 오래된 것은 버린다."""
    try:
        data = json.loads(path.read_text(encoding="utf-8"))
    except (OSError, json.JSONDecodeError):
        return {}
    age = time.time() - data.pop("_saved_at", 0)
    if age > MAX_AGE_SEC:
        logger.info("상태가 %.0f초 지남 — 폐기", age)
        return {}
    logger.info("상태 복원 (%.1f초 전): %s", age, data)
    return data


class DwellTracker:
    """체류 시간 판정 — 재시작 내성"""

    def __init__(self, dwell_sec=3.0):
        self.dwell_sec, self.last_save = dwell_sec, 0.0
        self.first_seen = load_state().get("first_seen")     # 복원

    def update(self, person_present: bool, now: float) -> bool:
        if not person_present:
            if self.first_seen is not None:
                self.first_seen = None
                save_state({})
            return False
        if self.first_seen is None:
            self.first_seen = now
        if now - self.last_save >= 2.0:      # 2초마다 (매 프레임은 SD 낭비)
            save_state({"first_seen": self.first_seen})
            self.last_save = now
        if now - self.first_seen >= self.dwell_sec:
            self.first_seen = None
            save_state({})
            return True
        return False
```

```python
"""pi/watchdog.py — ★ 멈춤 감지와 자가 치유

원칙 · 재시작은 최후 수단이다
     · ★ 재시작했다는 사실을 반드시 기록한다
     · 무한 재시작은 systemd StartLimitBurst 가 막는다
"""
from __future__ import annotations

import json
import logging
import os
import signal
import sqlite3
import threading
import time
from datetime import datetime
from pathlib import Path

logger = logging.getLogger(__name__)
HEARTBEAT = Path("/run/cctv/heartbeat")
RESTART_LOG = Path("/var/lib/cctv/restarts.jsonl")


class Heartbeat:
    """★ 검출 루프가 살아 있음을 알린다"""

    def __init__(self, path: Path = HEARTBEAT, min_interval=1.0):
        self.path, self.min_interval, self.last = path, min_interval, 0.0
        self.path.parent.mkdir(parents=True, exist_ok=True)
        self.path.touch(exist_ok=True)
        try:
            import sdnotify                  # systemd Type=notify 연동
            self._sd = sdnotify.SystemdNotifier()
            self._sd.notify("READY=1")
        except Exception:
            self._sd = None

    def beat(self):
        """매 프레임 호출 (내부에서 빈도 제한)"""
        now = time.time()
        if now - self.last < self.min_interval:
            return
        self.last = now
        try:
            self.path.touch()
        except OSError:
            pass
        if self._sd:
            self._sd.notify("WATCHDOG=1")


class Watchdog(threading.Thread):
    """하트비트가 멈추면 ① 로그 ② 알림 ③ 프로세스 종료"""

    def __init__(self, path: Path = HEARTBEAT, stale_warn=15.0,
                 stale_alert=30.0, stale_kill=60.0, interval=5.0,
                 notifier=None):
        super().__init__(daemon=True, name="watchdog")
        self.path, self.interval, self.notifier = path, interval, notifier
        self.stale_warn, self.stale_alert = stale_warn, stale_alert
        self.stale_kill = stale_kill
        self._stop = threading.Event()
        self.warned = self.alerted = False

    def age(self) -> float:
        try:
            return time.time() - self.path.stat().st_mtime
        except OSError:
            return 0.0

    def run(self):
        logger.info("워치독 시작 (warn %.0fs · alert %.0fs · kill %.0fs)",
                    self.stale_warn, self.stale_alert, self.stale_kill)
        while not self._stop.wait(self.interval):
            a = self.age()
            if a < self.stale_warn:
                self.warned = self.alerted = False
                continue
            if not self.warned:
                self.warned = True
                logger.warning("하트비트 %.0f초 정지 — 관찰 중", a)
            if a >= self.stale_alert and not self.alerted:
                self.alerted = True
                logger.error("하트비트 %.0f초 정지 — 멈춤 의심", a)
                if self.notifier:
                    self.notifier.put(f"hang_{int(time.time())}",
                                      f"⚠ 검출 루프 멈춤 의심\n정지 {a:.0f}초")
            if a >= self.stale_kill:
                record_restart(f"watchdog_hang_{a:.0f}s")
                logger.critical("하트비트 %.0f초 정지 — 프로세스 종료 "
                                "(systemd 가 재시작)", a)
                os.kill(os.getpid(), signal.SIGTERM)   # 정리 기회를 준다
                time.sleep(15)
                os.kill(os.getpid(), signal.SIGKILL)

    def stop(self):
        self._stop.set()


def record_restart(reason: str):
    """재시작이 근본 해결이 아님을 남긴다"""
    RESTART_LOG.parent.mkdir(parents=True, exist_ok=True)
    try:
        with RESTART_LOG.open("a", encoding="utf-8") as f:
            f.write(json.dumps(
                {"ts": datetime.now().isoformat(timespec="seconds"),
                 "reason": reason}, ensure_ascii=False) + "\n")
    except OSError:
        pass
    logger.error("재시작 기록: %s", reason)


def startup_recovery(db_path) -> dict:
    """시작할 때 한 번 — 이전 종료가 비정상이었는지 확인"""
    report = {"unclean_shutdown": False, "db_ok": True}
    marker = Path("/run/cctv/clean_exit")
    if not marker.exists():
        report["unclean_shutdown"] = True
        record_restart("unclean_shutdown")
        logger.warning("이전 종료가 비정상이었습니다")
    marker.parent.mkdir(parents=True, exist_ok=True)
    marker.unlink(missing_ok=True)

    try:                                   # 전원 순단 대비 무결성 검사
        db = sqlite3.connect(db_path, timeout=5.0)
        r = db.execute("PRAGMA integrity_check").fetchone()[0]
        db.close()
        report["db_ok"] = (r == "ok")
        if r != "ok":
            logger.critical("DB 무결성 오류: %s", r)
    except Exception as e:
        report["db_ok"] = False
        logger.critical("DB 열기 실패: %s", e)

    logger.info("시작 복구 점검: %s", report)
    return report
```

같은 파일에 두 함수가 더 있습니다. `mark_clean_exit()` 는 SIGTERM 핸들러에서
`/run/cctv/clean_exit` 를 만들어 **정상 종료였음을 표시**하고,
`restart_summary(hours=24)` 는 `restarts.jsonl` 을 읽어 최근 24시간 재시작을
사유별로 셉니다. 판정은 **0회 정상 · 1~2회 관찰 · 3회 이상 근본 원인 조사**.

### Step 4. 성능 튜닝 — 측정 → 조정 → 재측정

```python
"""pi/profiler.py — ★ 구간별 지연 측정 (추측 금지)"""
from __future__ import annotations

import statistics
import threading
import time
from collections import defaultdict, deque
from contextlib import contextmanager


class StageProfiler:
    """with prof("inference"): ... 로 구간 시간을 잰다"""

    def __init__(self, window=500):
        self._data: dict[str, deque] = defaultdict(lambda: deque(maxlen=window))
        self._counts: dict[str, int] = defaultdict(int)
        self._lock = threading.Lock()

    @contextmanager
    def __call__(self, stage: str):
        t0 = time.perf_counter()
        try:
            yield
        finally:
            dt = (time.perf_counter() - t0) * 1000.0
            with self._lock:
                self._data[stage].append(dt)
                self._counts[stage] += 1

    def summary(self) -> dict:
        with self._lock:
            snap = {k: sorted(v) for k, v in self._data.items()}
            counts = dict(self._counts)
        out = {}
        for stage, s in snap.items():
            if not s:
                continue
            out[stage] = {"n": counts[stage],
                          "avg": round(statistics.fmean(s), 2),
                          "p95": round(s[min(int(len(s) * .95), len(s)-1)], 2),
                          "max": round(s[-1], 2)}
        return out
```

```python
# ★ 조정 1·2 — 검출 루프에서 동기 호출 제거
```

```python
"""pi/filters.py — ★ 유형별 오탐 억제 (Day 177)

각 필터에 ★ 왜 넣었는지를 주석으로 남깁니다 → Day 178 문서화 재료.
"""
from __future__ import annotations


class DetectionFilter:
    def __init__(self, cfg: dict):
        self.conf_by_class = cfg.get("conf_by_class", {})   # ★ reflection·pallet
        self.conf_default = cfg.get("conf", 0.55)
        self.min_box_h_pct = cfg.get("min_box_h_pct", 4.0)  # shadow
        self.min_box_area_pct = cfg.get("min_box_area_pct", 0.35)
        self.ar_range = tuple(cfg.get("aspect_ratio", [0.20, 1.30]))  # shadow
        self.roi = cfg.get("roi")                           # branch
        self.masks = cfg.get("static_masks", [])            # poster
        self.stats = {"in": 0, "conf": 0, "size": 0, "ar": 0,
                      "roi": 0, "mask": 0, "out": 0}

    def apply(self, detections: list[dict], w: int, h: int) -> list[dict]:
        self.stats["in"] += len(detections)
        roi_px = ([self.roi[0]*w, self.roi[1]*h, self.roi[2]*w, self.roi[3]*h]
                  if self.roi else None)
        out = []
        for d in detections:
            box, bw, bh = d["box"], d["box"][2]-d["box"][0], d["box"][3]-d["box"][1]

            # ① 클래스별 conf (reflection · pallet)
            if d["conf"] < self.conf_by_class.get(d["class_name"],
                                                  self.conf_default):
                self.stats["conf"] += 1
                continue
            # ② 최소 크기 (shadow · 원거리 오검출)
            if (bh / h * 100 < self.min_box_h_pct
                    or bw * bh / (w * h) * 100 < self.min_box_area_pct):
                self.stats["size"] += 1
                continue
            # ③ 종횡비 (shadow 는 0.12 근처)
            ar = bw / bh if bh > 0 else 99.0
            if not (self.ar_range[0] <= ar <= self.ar_range[1]):
                self.stats["ar"] += 1
                continue
            # ④ ROI (branch)
            if roi_px:
                cx, cy = (box[0]+box[2])/2, (box[1]+box[3])/2
                if not (roi_px[0] <= cx <= roi_px[2]
                        and roi_px[1] <= cy <= roi_px[3]):
                    self.stats["roi"] += 1
                    continue
            # ⑤ 정적 마스크 (poster — 항상 같은 자리)
            if any(self._overlap(box, [m[0]*w, m[1]*h, m[2]*w, m[3]*h]) > 0.55
                   for m in self.masks):
                self.stats["mask"] += 1
                continue
            out.append(d)
        self.stats["out"] += len(out)
        return out

    def report(self) -> str:
        s = self.stats
        return (f"필터 — 입력 {s['in']} → 출력 {s['out']} "
                f"(conf {s['conf']} · size {s['size']} · ar {s['ar']} · "
                f"roi {s['roi']} · mask {s['mask']})")
```

`stats` 를 세는 이유는 **어느 필터가 몇 건을 걸렀는지**를 나중에 설명하기
위해서입니다. 박스와 마스크의 겹침 비율을 돌려주는 `_overlap()`, 그리고
클래스별 최근 M 프레임 판정을 들고 있다가 `sum(h) >= n` 인지만 보는
`NofMConfirmer` 는 각각 열 줄 이내라 지면에서 생략했습니다.

```python
def ascii_series(values, height=8, width=56, title=""):
    """★ 시계열 ASCII 그래프"""
    if not values:
        return ""
    lo, hi = min(values), max(values)
    hi = hi if hi - lo > 1e-9 else lo + 1.0
    pts = values[::max(1, len(values) // width)][:width]
    rows = [f"  {title}"] if title else []
    for r in range(height, 0, -1):
        thr = lo + (hi - lo) * (r - 0.5) / height
        rows.append(f"{thr:8.1f} │" + "".join("█" if v >= thr else " "
                                              for v in pts))
    rows.append(f"{'':8} └" + "─" * len(pts))
    return "\n".join(rows)


def verdict(s: dict) -> tuple[bool, list[str]]:

        (s["restarts"] == 0, f"재시작 {s['restarts']}회 (목표 0)"),
        (s["fps_avg"] >= 8.0, f"평균 FPS {s['fps_avg']:.1f} < 8.0"),
        (s["rss_growth_mb_per_h"] <= 20,
         f"메모리 증가 {s['rss_growth_mb_per_h']:.1f}MB/h > 20"),
        (s["temp_max"] <= 75, f"최고 온도 {s['temp_max']:.1f}℃ > 75"),
        (s["throttled_seen"] == "0x0", f"스로틀 {s['throttled_seen']}"),
        (s["cpu_avg"] <= 75, f"CPU 평균 {s['cpu_avg']:.1f}% > 75"),
        (s["alerts_fail"] == 0, f"알림 실패 {s['alerts_fail']}건"),
        (s["outbox_end"] == 0, f"아웃박스 잔량 {s['outbox_end']}건"),
        (s["errors"] == 0, f"ERROR 로그 {s['errors']}건"),
    ]
    fails = [msg for ok, msg in checks if not ok]
    return (not fails), fails

        "notify_p95": last["notify_p95"],
        "cpu_avg": round(statistics.fmean(s["cpu_pct"] for s in samples), 1),
        "cpu_max": round(max(s["cpu_pct"] for s in samples), 1),
        "rss_start": first["rss_mb"], "rss_end": last["rss_mb"],
        "rss_growth_mb_per_h": round((last["rss_mb"] - first["rss_mb"]) / dur_h, 1),
        "temp_avg": round(statistics.fmean(s["temp_c"] for s in samples), 1),
        "temp_max": round(max(s["temp_c"] for s in samples), 1),
        "throttled_seen": next((s["throttled"] for s in samples
                                if s["throttled"] not in ("0x0", "n/a")), "0x0"),
        "snap_growth_mb": round(last["snap_mb"] - first["snap_mb"], 1),
        "disk_growth_mb_per_h": round(
            (last["snap_mb"] - first["snap_mb"]) / dur_h, 1),
        "disk_free_pct_end": last["disk_free_pct"],
        "outbox_end": last["outbox"], "restarts": last["restarts"],
        "errors": last["errors"],
    }


def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("--minutes", type=float, default=60)
    ap.add_argument("--interval", type=float, default=30)
    ap.add_argument("--out", default=None)
    args = ap.parse_args()

    proc = find_proc()
    if proc is None:
        print("검출 프로세스를 찾지 못했습니다 (pi.main)")
        sys.exit(2)
    proc.cpu_percent(interval=None)        # 첫 호출은 0 이므로 버린다

    base = {"restarts": line_count(RESTART_LOG),
            "errors": line_count(LOG, (" ERROR ", " CRITICAL "))}
    t0, samples = time.time(), []
    print(f"★ soak test 시작 — {args.minutes:.0f}분 / {args.interval:.0f}초 간격\n")
    print(f"{'경과':>6}{'FPS':>7}{'RSS MB':>9}{'CPU%':>7}{'온도':>7}"
          f"{'이벤트':>7}{'알림':>6}{'큐':>5}{'디스크%':>8}")
    print("─" * 62)

    deadline = t0 + args.minutes * 60
    try:
        while time.time() < deadline:
            s = sample(proc, t0, base)
            samples.append(s)
            print(f"{s['t']/60:>5.0f}m{s['fps']:>7.1f}{s['rss_mb']:>9.1f}"
                  f"{s['cpu_pct']:>7.1f}{s['temp_c']:>7.1f}{s['events']:>7}"
                  f"{s['alerts_ok']:>6}{s['outbox']:>5}"
                  f"{s['disk_free_pct']:>8.1f}")
            if not s["active"]:
                print("서비스가 inactive 입니다 — 테스트 중단")
                break
            time.sleep(args.interval)
    except KeyboardInterrupt:
        print("\n사용자 중단")

    if len(samples) < 2:
        sys.exit(2)

    summary = summarize(samples, args.minutes)
    ok, fails = verdict(summary)
    summary["verdict"] = "PASS" if ok else "FAIL"
    summary["fail_reasons"] = fails

    print("\n" + "═" * 62)
    print(f"★ SOAK TEST {summary['verdict']}   "
          f"{summary['uptime_min']:.0f}분 / 표본 {summary['samples']}개")
    print("═" * 62)
    for k, v in summary.items():
        if k not in ("fail_reasons", "verdict"):
            print(f"  {k:<22} {v}")
    for f in fails:
        print(f"  불합격 — {f}")

    print("\n" + ascii_series([s["rss_mb"] for s in samples], title="RSS (MB)"))
    print("\n" + ascii_series([s["temp_c"] for s in samples], title="온도 (℃)"))

    out = Path(args.out or ROOT / "docs" /
               f"soak_{datetime.now():%Y%m%d_%H%M}.json")
    out.parent.mkdir(parents=True, exist_ok=True)
    out.write_text(json.dumps({"summary": summary, "samples": samples},
                              indent=2, ensure_ascii=False), encoding="utf-8")
    print(f"\n저장: {out}")
    sys.exit(0 if ok else 1)


if __name__ == "__main__":
    main()
```

### Step 8. 24시간 외삽 위험 분석

```python
"""tools/extrapolate.py — ★ 1시간 결과로 24시간·7일을 예측한다

from __future__ import annotations

from pathlib import Path


def analyze(s: dict, fp_per_h: int = 6) -> list[dict]:
    risks = []

    per_h = s["disk_growth_mb_per_h"]                       # ① 디스크
    free_mb = shutil.disk_usage("/").free / 1024 / 1024
    per_day = per_h * 24
    days = free_mb / per_day if per_day > 0 else 9999
    risks.append({"항목": "디스크", "시간당": f"{per_h:.1f} MB",

                  "대응": "보관 기간 단축 · 품질 하향" if days < 14 else "현행"})

    g, end, limit = s["rss_growth_mb_per_h"], s["rss_end"], 1500.0  # ② 메모리
    hrs = (limit - end) / g if g > 0 else 9999
    risks.append({"항목": "메모리", "시간당": f"{g:+.1f} MB",
                  "24시간": f"{g*24:+.0f} MB", "7일": f"{g*24*7/1024:+.2f} GB",
                  "소진": f"{hrs/24:.1f}일",
                  "위험": "높음" if hrs < 72 else "중간" if hrs < 336 else "낮음",
                  "대응": ("누수 재조사" if hrs < 72 else
                          "주 1회 계획 재시작" if hrs < 336 else "현행")})

    tmax = s["temp_max"]                                    # ③ 발열
    summer = tmax + 8.0                     # ★ 하절기 실내 +8℃ 가정
    risks.append({"항목": "발열", "시간당": "포화", "24시간": f"{tmax:.1f} ℃",
                  "7일": f"{summer:.1f} ℃ (하절기)",

                  "대응": "액티브 쿨러" if summer > 72 else "현행"})

    risks += log_risk(s) + db_risk(s) + fp_risk(fp_per_h)   # ④⑤⑥
```

| # | 문제 | 결과 |
|---|---|---|
| ★ 1 | 이전 캡처를 `release()` 하지 않음 | FD 누수 → "Too many open files" |

| 4 | `isOpened()` 확인 없음 | 열리지 않은 캡처로 `read()` |
| 5 | 고정 인덱스 `0` | USB 재열거로 `video2` 가 되면 영원히 실패 |
| 6 | `print` 로 로그 | 타임스탬프·레벨 없음 · 파일에 안 남음 |
| 7 | `process()` 예외 미처리 | 루프 전체가 죽음 |

| 9 | 실패가 길어져도 알림 없음 | 밤새 죽어 있어도 모름 |
| 10 | `BUFFERSIZE` 미설정 | 프레임이 밀림 |

### 수정본

```python
"""안정화된 캡처 루프"""
import logging
import signal
import sys
import time

import cv2

logger = logging.getLogger(__name__)
SRC = "/dev/v4l/by-id/usb-046d_HD_Pro_Webcam_C920_A1B2C3-video-index0"  # ★ 5
FAIL_THRESHOLD, BACKOFF_MAX, NOTIFY_AFTER = 15, 30.0, 20
running = True


def shutdown(signum, frame):                     # ★ 8
    global running
    logger.info("종료 신호 %s 수신", signum)
    running = False


signal.signal(signal.SIGTERM, shutdown)
signal.signal(signal.SIGINT, shutdown)


def open_camera(src):
    cap = cv2.VideoCapture(src, cv2.CAP_V4L2)
    cap.set(cv2.CAP_PROP_BUFFERSIZE, 1)          # ★ 10
    ok, _ = cap.read()                           # 4 · 실제로 읽어 본다
    if not cap.isOpened() or not ok:
        cap.release()
        return None
    return cap


def main(notifier=None):
    cap = open_camera(SRC)
    fails = streak = notified = 0
    backoff = 1.0

    while running:
        if cap is None:
            streak += 1
            logger.warning("카메라 재연결 시도 #%d", streak)      # 6
            cap = open_camera(SRC)
            if cap is None:
                if streak >= NOTIFY_AFTER and notified < 3 and notifier:
                    notified += 1                                # 9
                    notifier.put(f"cam_down_{notified}",
                                 f"⚠ 카메라 연결 실패 {streak}회")
                time.sleep(backoff)                              # 2
                backoff = min(backoff * 2, BACKOFF_MAX)
                continue
            logger.info("카메라 복구")
            fails = streak = notified = 0
            backoff = 1.0

        ok, frame = cap.read()
        if not ok or frame is None:
            fails += 1
            if fails >= FAIL_THRESHOLD:          # 3
                logger.warning("연속 실패 %d회 — 재연결", fails)
                cap.release()                    # 1
                cap = None
                fails = 0
            continue

        fails = 0
        try:
            process(frame)                       # 7
        except Exception:
            logger.exception("프레임 처리 실패 — 계속 진행")

    if cap is not None:
        cap.release()
    logger.info("정상 종료")
    sys.exit(0)
```

**검증 방법** — ① USB 를 뽑으면 15프레임(약 1.3초) 뒤 재연결이 시작되고,
② 30초 방치하면 백오프가 1→2→4→8→16→30 으로 늘고, ③ 다시 꽂으면 최대
30초 안에 복구됩니다. ④ `ls /proc/$(pgrep -f pi.main)/fd | wc -l` 로
**재연결 전후 FD 개수가 같은지** 확인합니다.

메모리로 죽고 3.6일이면 디스크가 찹니다. 조치 순서는 ① 메모리 누수(P0)
② ERROR 4건(P0) ③ 알림 실패(P1) ④ 디스크 증가율(P1) ⑤ 냉각(P2), 그리고
**다시 1시간 soak** 입니다.

**4.** 오탐 47건을 유형화했습니다. 유형별 **최적 대응**을 고르고, **conf 만 올려 해결하면 안 되는 이유**를 지표로 설명하세요.

```
그림자 14 · 금속 반사 9 · 팔레트→box 8 · 포스터 속 사람 7 · 나뭇가지 5 · 조명 점멸 4
```

<details>
<summary>답 보기</summary>

| 유형 | 대응 | 이유 | 미검출 영향 |
|---|---|---|---|
| **그림자 14** | **종횡비 + 최소 크기** | 그림자는 w/h ≈ 0.12 로 극단적 | 거의 없음 |
| **금속 반사 9** | conf 0.45→0.55 | 반사는 conf 평균 0.51 | 소폭 |
| **팔레트 8** | ★ **클래스별 conf** (box 0.60) | person·helmet 은 안 건드림 | box 만 |
| **포스터 7** | **정적 마스크** | 항상 같은 좌표 | 없음 |
| **나뭇가지 5** | **ROI 축소** | 관심 영역 밖 | 없음 |
| **조명 점멸 4** | **N-of-M 4/6** | 순간적 튐은 연속성이 없음 | 지연 0.18초 |

**적용 순서가 중요합니다.** ① 공짜인 것부터(미검출 영향 0) — 정적 마스크 ·
ROI · 종횡비, ② 대상이 좁은 것 — 클래스별 conf, ③ 지연을 대가로 하는 것 —
N-of-M, ④ **마지막에 전역 conf** (가장 광범위한 부작용).

### ★ conf 만 올리면 안 되는 이유

| 설정 | TP | FP | FN | Precision | Recall | F1 |
|---|---|---|---|---|---|---|
| conf 0.35 | 31 | 82 | 1 | 0.274 | 0.969 | 0.427 |
| conf 0.45 (기준) | 29 | 47 | 3 | 0.382 | 0.906 | 0.538 |
| conf 0.55 | 27 | 21 | 5 | 0.563 | 0.844 | 0.675 |
| conf 0.65 만 | 21 | 8 | 11 | 0.724 | 0.656 | 0.688 |
| conf 0.75 | 14 | 3 | 18 | 0.824 | 0.438 | 0.572 |
| ★ **유형별 대응** | **29** | **6** | **5** | **0.829** | **0.853** | **0.841** |

conf 만으로 오탐을 8건까지 줄이려면 **0.65 가 필요합니다.** 대가는 미검출
3 → **11**, Recall 0.906 → **0.656** — 안전모 미착용자 3명 중 1명을 놓칩니다.
**안전 감시로서 실격**입니다.

```
★ 왜 이런 차이가 나는가
  conf 상향 = "모든 검출에 똑같이 엄격해진다"
    그림자 0.52 → 걸러짐 ✅ / 원거리 사람 0.58 → 함께 걸러짐 ❌
    포스터 0.71 → 안 걸러짐 ❌

  유형별 대응 = "각 오탐의 고유한 성질을 이용한다"
    그림자 → 종횡비가 다름 → conf 와 무관하게 제거
    포스터 → 좌표가 고정   → conf 0.9 여도 제거
    원거리 사람 → 종횡비 정상 · 좌표 가변 → 살아남음
```

같은 오탐 감소를 얻으면서 conf 만 올리면 TP 29 → 21 로 **8건을 잃지만**
(F1 0.688), 유형별 대응은 TP 29 → 29 로 **하나도 잃지 않습니다**(F1 0.841).
**"오탐을 줄인다" 는 하나의 손잡이가 아닙니다.** 오탐마다 다른 손잡이가
있고, 그래서 먼저 모으고 유형화합니다.

**남은 6건**(reflection 3 · light 2 · pallet 1)은 더 줄이면 FN 이 5 → 11 이
되므로 **중단하고 `docs/LIMITATIONS.md` 에 기록**합니다 — "정오 무렵 셔터
금속면 반사로 시간당 약 3건의 오탐이 발생합니다. conf 를 더 올리면 원거리
검출이 함께 손실되므로 편광 필터 장착 또는 카메라 각도 변경이 근본 대책입니다."

</details>

**5.** 1시간 soak 는 PASS 지만 24시간 외삽에서 디스크가 9.4일 뒤 가득 찹니다. 아래 세 의견을 평가하고 **우선순위**를 정하세요.

```
A: "9일이면 발표까지는 충분한데 그냥 두죠"
B: "지금 전체 저장 구조를 바꿔서 S3 에 올립시다"
C: "conf 를 더 올려서 이벤트 자체를 줄이면 되잖아요"
```

<details>
<summary>답 보기</summary>

| 의견 | 장점 | 단점 | 판정 |
|---|---|---|---|
| **A** 그냥 두기 | ★ 변경 위험 0 | 결함을 알면서 방치 · 주말에 켜 두면 확인 불가 | **부분적으로 옳음** |
| **B** S3 이관 | 근본 해결 | 새 의존성·인증·실패 모드 · 검증 4시간 · 발표장 인터넷 차단 시 더 나빠짐 | **기각** |
| **C** conf 상향 | 설정 1줄 | 디스크 26% 개선에 Recall 0.853 → 0.656 | **기각** |

**A 가 놓친 것** — ① 심사에서 "24시간 운영하면?" 을 물으면 "9일 뒤 멈춥니다"
라고 답해야 합니다. ② 금~월 켜 두면 확인이 안 됩니다(실제로 계속 켜 두는
팀이 많습니다). **C 는 방향이 틀렸습니다** — "저장 공간을 아끼려고 사람을
놓친다" 는 것은 요구사항(Day 171) 위반입니다.

### ★ 올바른 우선순위

| 순위 | 조치 | 시간 | 되돌리기 |
|---|---|---|---|
| **1** | JPEG 품질 92 → 82 (용량 −38%) | 5분 | 설정 1줄 |
| **2** | 보관 30일 → 7일 | 5분 | 설정 1줄 |

| ❌ | S3 이관 (★ 동결 위반) · conf 추가 상향 (목적 훼손) | — | — |

조치 후에는 시간당 증가가 83.6MB → **52.0MB**, 무한 증가하던 사용량이
**8.5GB 에서 평형**, 디스크 소진 9.4일 → **없음**이 됩니다. 스냅샷 화질은
92 → 82 지만 **육안 차이는 거의 없습니다.**

### ★ 그리고 반드시 할 것

① 변경 후 다시 스모크(스냅샷 저장 · 웹 표시 확인), ② `docs/FREEZE_EXCEPTION.md`

검토했으나 발표 3일 전 신규 의존성 추가는 검증 시간이 부족해 기각하고, 설정

**"판단해서 안 한 것"** 은 다릅니다.

- [ ] 재시작해도 ★ **중복 알림이 없다**

- [ ] ★ **구간별로 측정한 뒤** 튜닝했고 FPS · 지연 · CPU · 온도가 목표를 만족한다
- [ ] ★ **RSS 증가가 20MB/h 미만**이다
- [ ] 오탐을 ★ **유형화**하고 조정 전후 **Precision · Recall · F1** 을 기록했다
