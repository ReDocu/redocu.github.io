## ① 학습 목표

이 강을 마치면 다음을 할 수 있습니다.

- INNER JOIN 질의를 표준 문법(JOIN ON)으로 **직접 작성할 수 있다**
- LEFT/RIGHT/FULL OUTER JOIN에서 **짝 없는 행이 어떻게 나오는지 예측할 수 있다**
- 카티션 곱의 행 수를 **계산할 수 있다**
- 단일행·다중행 서브쿼리(IN·EXISTS 포함)의 결과를 **예측하고 작성할 수 있다**
- UNION과 UNION ALL의 결과 행 수 차이를 **판정할 수 있다**

---

## ② 왜 필요한가

**현실의 질문은 언제나 두 테이블에 걸쳐 있습니다.** "학생 이름과 학과 이름을 나란히" — 이름은 STUDENT에, 학과명은 DEPT에 있습니다. 나눠 저장하는 것이 정규화(10강)의 결과라면, **다시 잇는 도구가 JOIN**입니다. 그래서 SQL 작성형 문제의 상당수가 JOIN 또는 서브쿼리를 요구합니다(기출 복원 기반 비공식 경향).

시험이 노리는 곳은 **짝이 없는 행**입니다. 우리 스키마의 정유진(학과 NULL)과 색채학 C4(수강생 없음)는 INNER JOIN에서 조용히 사라집니다. "몇 행이 나오는가"를 묻는 문제의 답이 여기서 갈리고, 이들을 살리는 도구가 OUTER JOIN입니다.

**시험에서의 중요도와 출제 형태** — SQL 작성형(JOIN·서브쿼리 질의 쓰기), 결과 예측형(행 수·행 내용), 빈칸형(ON·IN·EXISTS 채우기). 08강의 실행 순서 감각(FROM이 먼저)이 "서브쿼리부터 계산한다"는 해석 순서로 이어집니다.

## ③ 개념 설명

### 3-1. JOIN의 원리 — 곱한 뒤 거른다

두 테이블을 잇는 논리적 원리는 ①모든 행 조합을 만들고(**카티션 곱**) ②조건(ON)에 맞는 조합만 남기는 것입니다.

📌 **반드시 암기 — 카티션 곱(CROSS JOIN)의 행 수 = m × n.** STUDENT(5행) × DEPT(3행) = 15행. ON 조건을 빠뜨린 JOIN이 바로 이 상태이며, "조건 없이 조인하면 몇 행인가"가 계산 문제로 나옵니다.

**INNER JOIN** — 조건에 맞는 짝이 **있는 행만** 남깁니다.

```sql
-- 표준 문법 (권장)
SELECT S.이름, D.학과명
FROM   STUDENT S
JOIN   DEPT D ON S.학과코드 = D.학과코드;

-- WHERE 방식 (구식·암시적 조인 — 기출 지문에 등장하므로 읽을 줄 알아야 함)
SELECT S.이름, D.학과명
FROM   STUDENT S, DEPT D
WHERE  S.학과코드 = D.학과코드;
```

두 질의는 같은 결과입니다. `STUDENT S`의 S는 **테이블 별칭** — 양쪽에 같은 이름의 열(학과코드)이 있을 때 `S.학과코드`처럼 소속을 밝히는 데 필수입니다(⑤ 참고).

### 3-2. OUTER JOIN — 짝이 없어도 살린다

| 종류 | 남기는 것 | 짝 없는 자리 |
|---|---|---|
| `LEFT JOIN` (LEFT OUTER JOIN) | 왼쪽 테이블의 **모든 행** | 오른쪽 열들이 **NULL** |
| `RIGHT JOIN` | 오른쪽 테이블의 모든 행 | 왼쪽 열들이 NULL |
| `FULL OUTER JOIN` | 양쪽 모든 행 | 없는 쪽이 NULL |

📌 **판정 요령**: "어느 테이블의 행이 전부 나와야 하는가"를 먼저 정하고 그 테이블을 LEFT(기준)로 둡니다. RIGHT JOIN은 좌우를 바꾼 LEFT JOIN과 같아서, 실무·답안 모두 LEFT로 통일하는 것이 안전합니다.

⚖️ **DBMS 차이** — Oracle에는 `WHERE S.학과코드 = D.학과코드(+)`라는 고유 표기가 있습니다((+)가 붙은 쪽이 NULL을 허용하는 쪽). 기출 지문에서 읽을 수 있으면 충분하고, **답안은 표준 LEFT JOIN**으로 작성합니다. FULL OUTER JOIN은 MySQL이 미지원(UNION으로 대체)·SQLite는 3.39부터 지원 — 개념 판정 문제로만 대비하면 됩니다.

**셀프 조인** — 같은 테이블을 별칭 두 개로 두 번 사용하는 조인입니다(예: 직원 테이블에서 `E.상사번호 = M.사원번호`로 직원-상사 짝 만들기). 우리 스키마에는 자기 참조 열이 없어 정의만 알아 두면 됩니다.

### 3-3. 서브쿼리 — 괄호 안 질의가 먼저

**서브쿼리(subquery)** 는 질의 안에 괄호로 들어간 또 하나의 질의입니다. **해석 순서는 항상 안쪽(서브쿼리) → 바깥쪽**입니다.

📌 **반드시 암기 — 반환 행 수에 따른 연산자 선택**

| 서브쿼리 반환 | 쓸 수 있는 연산자 | 예 |
|---|---|---|
| **단일 행** (값 1개) | `= <> < >` 등 비교 연산자 | `성적 = (SELECT MAX(성적) ...)` |
| **다중 행** (값 여러 개) | `IN`, `ANY`, `ALL`, `EXISTS` | `학번 IN (SELECT 학번 ...)` |

| 다중 행 연산자 | 뜻 |
|---|---|
| `IN` | 목록 중 하나와 일치 |
| `ANY` (=SOME) | 목록 중 **하나라도** 만족하면 참 (`> ANY` = 최솟값보다 크면) |
| `ALL` | 목록 **전부**에 대해 만족해야 참 (`> ALL` = 최댓값보다 크면) |
| `EXISTS` | 서브쿼리 결과가 **한 행이라도 있으면** 참 (값 비교가 아니라 존재 검사) |

⚖️ **혼동 비교 — IN vs EXISTS**: IN은 "값이 목록에 있는가", EXISTS는 "조건에 맞는 행이 존재하는가"입니다. 결과가 같아지는 경우가 많지만, EXISTS의 서브쿼리에는 바깥 행을 참조하는 조건(`E.학번 = S.학번`, 상관 서브쿼리)이 들어간다는 형태 차이로 구분합니다.

### 3-4. 집합 연산 — 결과끼리 위아래로 합치기

| 연산 | 뜻 | 중복 |
|---|---|---|
| `UNION` | 합집합 | **제거** |
| `UNION ALL` | 합집합 | **유지** 📌 (행 수 = 두 결과의 합) |
| `INTERSECT` | 교집합 | 제거 |
| `EXCEPT` | 차집합 (⚖️ Oracle은 `MINUS`) | 제거 |

전제 조건: 두 SELECT의 **열 개수와 자료형이 같아야** 합니다. "UNION과 UNION ALL의 행 수 차이"가 결과 예측 단골입니다.

### Step 2. INNER JOIN — 학생과 학과명 잇기

**사용 테이블: STUDENT, DEPT · 난이도: 🟡 기본 · 학습 개념: JOIN ON, 테이블 별칭**

> 문제: 학생 이름과 소속 학과명을 조회하시오.

```sql
SELECT S.이름, D.학과명
FROM   STUDENT S
JOIN   DEPT D ON S.학과코드 = D.학과코드;
```

**예상 결과 (4행)**

| 이름 | 학과명 |
|---|---|
| 김하늘 | 컴퓨터공학 |
| 이준호 | 컴퓨터공학 |
| 박서연 | 경영학 |
| 최민수 | 경영학 |

실행 원리: 학과코드가 같은 짝만 남습니다. **정유진(학과코드 NULL)은 NULL이 어떤 값과도 짝이 되지 못해 탈락**, 학생이 없는 D3 디자인도 짝이 없어 안 나옵니다. "STUDENT는 5행인데 왜 4행인가"가 이 유형의 출제 포인트입니다.

### Step 3. LEFT JOIN — 사라진 행 살리기

**사용 테이블: STUDENT, DEPT · 난이도: 🟡 기본 · 학습 개념: 기준 테이블, NULL 채움**

```sql
SELECT S.이름, D.학과명
FROM   STUDENT S
LEFT JOIN DEPT D ON S.학과코드 = D.학과코드;
```

**예상 결과 (5행)**

| 이름 | 학과명 |
|---|---|
| 김하늘 | 컴퓨터공학 |
| 이준호 | 컴퓨터공학 |
| 박서연 | 경영학 |
| 최민수 | 경영학 |
| 정유진 | **NULL** |

왼쪽(STUDENT)의 모든 행이 기준이므로 정유진이 살아나고, 짝 없는 학과명 자리는 NULL로 채워집니다.

**사용 테이블: COURSE, ENROLL · 난이도: 🔴 심화(빈출 함정) · 학습 개념: LEFT JOIN + 집계, COUNT의 대상**

> 문제: 수강생이 없는 과목까지 포함해 과목별 수강 인원을 조회하시오.

```sql
SELECT C.과목명, COUNT(E.학번) AS 수강인원
FROM   COURSE C
LEFT JOIN ENROLL E ON C.과목코드 = E.과목코드
GROUP BY C.과목코드, C.과목명;
```

**예상 결과**

| 과목명 | 수강인원 |
|---|---|
| 데이터베이스 | 3 |
| 자료구조 | 1 |
| 회계원리 | 2 |
| 색채학 | **0** |

- **대표 오답 쿼리**: `COUNT(*)`로 세면 색채학이 **1**로 나옵니다. LEFT JOIN이 만든 "색채학 + NULL" 행도 행은 행이라 COUNT(*)가 세어 버리기 때문입니다. 짝의 개수를 세려면 **오른쪽 테이블의 열**을 세어(`COUNT(E.학번)`) NULL이 제외되게 해야 합니다 — 08강 NULL 규칙이 JOIN과 만나는 지점입니다.

### Step 4. 3개 테이블 JOIN

**사용 테이블: ENROLL, STUDENT, COURSE · 난이도: 🟡 기본 · 학습 개념: 다중 JOIN**

> 문제: 성적이 85점 이상인 수강 기록의 학생 이름, 과목명, 성적을 조회하시오.

```sql
SELECT S.이름, C.과목명, E.성적
FROM   ENROLL E
JOIN   STUDENT S ON E.학번 = S.학번
JOIN   COURSE C ON E.과목코드 = C.과목코드
WHERE  E.성적 >= 85;
```

**예상 결과 (3행)**

| 이름 | 과목명 | 성적 |
|---|---|---|
| 김하늘 | 데이터베이스 | 90 |
| 김하늘 | 자료구조 | 85 |
| 박서연 | 데이터베이스 | 95 |

실행 원리: 다리 역할인 ENROLL을 가운데 두고 양쪽으로 JOIN을 한 번씩 — "N개 테이블을 이으려면 JOIN(ON)이 N−1개"입니다. 성적 NULL인 최민수 행은 `>= 85` 비교를 통과하지 못합니다.

### Step 5. 서브쿼리 — 단일행과 다중행

**사용 테이블: ENROLL · 난이도: 🟡 기본 · 학습 개념: 단일행 서브쿼리**

> 문제: 최고 성적을 받은 수강 기록의 학번과 성적을 조회하시오.

```sql
SELECT 학번, 성적
FROM   ENROLL
WHERE  성적 = (SELECT MAX(성적) FROM ENROLL);
```

| 학번 | 성적 |
|---|---|
| 1003 | 95 |

해석 순서: 안쪽 먼저 — `(SELECT MAX(성적)...)` = 95 → 바깥은 `WHERE 성적 = 95`가 됩니다. MAX는 값 하나(단일 행)라 `=`를 쓸 수 있습니다.

**사용 테이블: STUDENT, ENROLL · 난이도: 🟡 기본 · 학습 개념: 다중행 서브쿼리 IN**

> 문제: 'C1' 과목을 수강한 학생의 이름을 조회하시오.

```sql
SELECT 이름
FROM   STUDENT
WHERE  학번 IN (SELECT 학번 FROM ENROLL WHERE 과목코드 = 'C1');
```

| 이름 |
|---|
| 김하늘 |
| 이준호 |
| 박서연 |

안쪽 결과가 (1001, 1002, 1003)의 **여러 행**이므로 `=`가 아니라 `IN`. 같은 문제를 JOIN으로도 풀 수 있습니다(`JOIN ENROLL ON ... WHERE 과목코드='C1'`) — 시험은 두 방식 모두 정답으로 인정되는 것이 보통이지만, 지문이 방식을 지정하면 따릅니다.

**사용 테이블: STUDENT, ENROLL · 난이도: 🔴 심화 · 학습 개념: NOT EXISTS (상관 서브쿼리)**

> 문제: 아무 과목도 수강하지 않은 학생의 이름을 조회하시오.

```sql
SELECT 이름
FROM   STUDENT S
WHERE  NOT EXISTS (SELECT * FROM ENROLL E WHERE E.학번 = S.학번);
```

| 이름 |
|---|
| 정유진 |

실행 원리: 학생 한 행마다 "이 학생의 수강 행이 존재하는가"를 검사(안쪽이 바깥의 `S.학번`을 참조 — 상관 서브쿼리)해, 존재하지 **않는** 학생만 남깁니다. `WHERE 학번 NOT IN (SELECT 학번 FROM ENROLL)`도 같은 결과지만, **서브쿼리 결과에 NULL이 섞이면 NOT IN은 0행이 되는 함정**이 있어(NULL 비교 규칙) EXISTS 형태가 더 안전합니다.

### Step 6. UNION vs UNION ALL

**사용 테이블: STUDENT, DEPT · 난이도: 🟡 기본 · 학습 개념: 중복 제거 여부**

```sql
SELECT 학과코드 FROM STUDENT WHERE 학과코드 IS NOT NULL
UNION
SELECT 학과코드 FROM DEPT;
```

결과: **3행** (D1, D2, D3 — 중복 제거)

```sql
SELECT 학과코드 FROM STUDENT WHERE 학과코드 IS NOT NULL
UNION ALL
SELECT 학과코드 FROM DEPT;
```

결과: **7행** (위 4행 D1,D1,D2,D2 + 아래 3행 D1,D2,D3 그대로)

"UNION이면 몇 행, UNION ALL이면 몇 행?"이 결과 예측의 전형입니다. ALL = 전부 그대로(합), 무표시 = 중복 정리.

## ⑤ 자주 하는 실수

| 에러/증상 원문 | 원인 | 해결 |
|---|---|---|
| `Parse error: ambiguous column name: 학과코드` | 양쪽 테이블에 같은 이름의 열이 있는데 소속 미표기 | 별칭 접두사 필수: `S.학과코드` — JOIN 답안 작성의 기본기 |
| 결과가 수십 행으로 폭발 | ON(또는 WHERE 조인 조건) 누락 → 카티션 곱 (5×3=15행처럼 m×n) | JOIN마다 ON이 있는지 확인 — "JOIN N−1개 = ON N−1개" |
| INNER JOIN 결과에 특정 행이 없음 (에러 아님) | NULL 외래키(정유진)·짝 없는 행(C4)은 INNER에서 탈락 | 전부 나와야 하는 쪽을 기준으로 LEFT JOIN |
| LEFT JOIN + `COUNT(*)`가 0 대신 1 | 짝 없는 행도 행으로 세어짐 | 오른쪽 테이블 열로 카운트: `COUNT(E.학번)` (Step 3 함정) |
| `ORA-01427: single-row subquery returns more than one row` | 다중 행 서브쿼리에 `=` 사용 | `IN`으로 교체. ⚖️ SQLite는 에러 없이 첫 행만 사용하므로 자습 시 발견이 늦음 — 손 검산 필수 |
| NOT IN 결과가 예상 밖 0행 | 서브쿼리 결과에 NULL 포함 → 전체 비교가 '알 수 없음' | `NOT EXISTS` 사용 또는 서브쿼리에 `IS NOT NULL` 추가 |
| `Parse error: SELECTs to the left and right of UNION do not have the same number of result columns` | UNION 양쪽 열 개수 불일치 | 두 SELECT의 열 개수·순서·자료형을 맞춘다 |
| WHERE에 바깥 행 조건을 쓸지 ON에 쓸지 혼란 | LEFT JOIN에서 ON과 WHERE는 결과가 다름 (WHERE는 조인 후 필터라 NULL 행이 걸러질 수 있음) | 기준 행을 남기려면 조건을 ON 쪽에 — 🔴 심화 판정 포인트 |

## ⑥ 확인 문제

1. [결과 예측] 다음 SQL의 결과 행 수와, 정유진 행의 학과명 값을 쓰시오.
   ```sql
   SELECT S.이름, D.학과명
   FROM   STUDENT S
   LEFT JOIN DEPT D ON S.학과코드 = D.학과코드;
   ```
2. [SQL 작성] '데이터베이스' 과목을 수강한 학생의 이름을 조회하는 SQL을 서브쿼리 방식으로 쓰시오. (과목명은 COURSE에만 있음)
3. [결과 예측] STUDENT가 5행, DEPT가 3행일 때 다음 두 질의의 결과 행 수를 각각 쓰시오.
   ```sql
   SELECT * FROM STUDENT, DEPT;                          -- (ㄱ)
   SELECT 학년 FROM STUDENT UNION SELECT 학년 FROM STUDENT; -- (ㄴ)
   ```

<details>
<summary>정답과 해설</summary>

1. **5행, NULL** — LEFT JOIN은 왼쪽(STUDENT) 전 행을 유지하고, 짝 없는 정유진의 학과명 자리를 NULL로 채웁니다.
   - 대표 오답: 4행 — INNER JOIN과 혼동. "LEFT = 왼쪽은 무조건 전원 출석"입니다.
2. 정답 쿼리 (2단 서브쿼리):
   ```sql
   SELECT 이름
   FROM   STUDENT
   WHERE  학번 IN (SELECT 학번 FROM ENROLL
                   WHERE 과목코드 = (SELECT 과목코드 FROM COURSE
                                     WHERE 과목명 = '데이터베이스'));
   ```
   결과: 김하늘, 이준호, 박서연. 해석은 가장 안쪽부터: 과목명→C1 (단일행이라 `=`) → C1 수강 학번들 (다중행이라 `IN`) → 이름.
   - 대표 오답: 두 번째 연산자까지 `=`로 쓰기 — 안쪽이 3행을 반환하므로 단일행 연산자는 표준·Oracle에서 에러(ORA-01427)입니다.
3. **(ㄱ) 15행, (ㄴ) 3행** — (ㄱ) 조인 조건 없는 카티션 곱 5×3. (ㄴ) 학년 열은 (1,2,2,3,3)이고 UNION이 자기 자신과의 합집합에서 중복을 제거해 1,2,3.
   - 대표 오답: (ㄴ)을 10행으로 — 그건 UNION **ALL**의 답입니다.

</details>

## 마무리

**오늘의 요약** — JOIN의 원리는 "곱해서(카티션 곱 m×n) 조건으로 거른다"이며, INNER는 짝 있는 행만, LEFT는 왼쪽 전원 + 빈자리 NULL입니다. LEFT JOIN에서 개수를 셀 때는 COUNT(*)가 아니라 오른쪽 열로 세어야 0이 나옵니다. 서브쿼리는 안쪽부터 해석하고, 반환이 단일행이면 비교 연산자·다중행이면 IN/ANY/ALL/EXISTS이며, NOT IN + NULL 조합은 0행 함정이 있어 NOT EXISTS가 안전합니다. UNION은 중복 제거, UNION ALL은 그대로 합칩니다.

**복습 체크리스트**

- [ ] Step 2가 4행이고 정유진·D3이 빠지는 이유를 설명할 수 있다
- [ ] Step 3 함정(COUNT(*) → 색채학 1)을 남에게 설명할 수 있다
- [ ] 단일행/다중행 서브쿼리 연산자 표를 안 보고 재현할 수 있다
- [ ] NOT IN이 위험한 이유와 대안을 말할 수 있다
- [ ] UNION vs UNION ALL의 행 수를 즉답할 수 있다

**과제** — ① Step 4를 "2학년 학생의 수강 기록(이름·과목명·성적)"으로 바꿔 작성하고 SQLite로 검증(예상: 이준호·데이터베이스·70, 박서연·데이터베이스·95, 박서연·회계원리·80), ② ⑥ 2번을 JOIN 방식으로 다시 작성해 두 방식 비교, ③ `> ANY`와 `> ALL`의 차이를 (70, 80, 95) 목록 예시로 한 줄씩 정리. (형성평가는 10강 과제에 통합)

**다음 강 예고** — 10강은 3단원의 마지막입니다. SQL 4분류(DDL·DML·DCL·TCL)를 완성하고, 트랜잭션 ACID·인덱스·뷰, 그리고 이론 단답의 단골 **정규화(도부이결)와 관계대수 기호**(σ·π·⋈·÷)까지 정리합니다. 5주차 형성평가가 과제로 나갑니다.
