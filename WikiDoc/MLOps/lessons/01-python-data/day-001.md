## ③ 개념 설명

### MLOps 엔지니어는 무슨 일을 하는가

**MLOps**는 Machine Learning(머신러닝) + Operations(운영)의 합성어입니다.
"모델을 만드는 사람"이 아니라 **"모델이 서비스로 계속 돌아가게 만드는 사람"** 입니다.

데이터 과학자가 만든 모델은 대개 노트북 파일(`.ipynb`) 하나입니다. 그것이 실제 서비스가 되려면 이런 일이 필요합니다.

| 단계 | 하는 일 | 이 과정에서 배우는 시점 |
|---|---|---|
| 수집 | 외부 데이터를 자동으로 가져온다 | W04 |
| 저장 | DB에 넣고, 두 번 돌려도 안 망가지게 한다 | W07–W09 |
| 학습 | 모델을 만들고 실험 기록을 남긴다 | W11–W14 |
| 서빙 | 다른 개발자가 HTTP로 부를 수 있게 만든다 | W19–W20 |
| 배포 | 컨테이너로 묶어 서버에 올린다 | W24–W25 |
| 자동화 | 커밋하면 알아서 테스트·배포된다 | W26 |
| 감시 | 모델이 언제 낡았는지 알아챈다 | W27 |

이 7단계를 혼자 관통하는 것이 32주 뒤의 여러분입니다.

### 파이썬과 인터프리터

**파이썬(Python)** 은 프로그래밍 언어입니다. 우리가 `.py` 파일에 쓴 글자를 컴퓨터가 바로 이해하지는 못합니다.
중간에서 통역해 주는 프로그램이 필요한데, 그게 **인터프리터(interpreter)** 입니다.

```
[내가 쓴 hello.py]  →  [파이썬 인터프리터]  →  [컴퓨터가 실행]
```

파이썬을 "설치한다"는 건 이 통역사를 내 컴퓨터에 들여놓는다는 뜻입니다.

> **왜 3.12인가** — 너무 최신 버전은 PyTorch·Pandas 같은 라이브러리가 아직 지원하지 않는 경우가 있습니다.
> 실무에서는 "라이브러리들이 모두 지원하는 가장 높은 버전"을 고릅니다. 2026년 기준 3.12가 그 자리입니다.

### 가상환경 (virtual environment)

프로젝트마다 필요한 도구(패키지)가 다릅니다. 그리고 **버전까지** 다릅니다.

이걸 전부 한 곳에 설치하면 **버전 충돌**이 납니다.
A 프로젝트는 `numpy 1.26`이 필요한데 B 프로젝트가 `numpy 2.1`을 깔아 버리면, A가 갑자기 안 돌아갑니다.

**가상환경 = 프로젝트 전용 도구상자**입니다.

```
내 컴퓨터
├── mlops-day01/
│   └── venv/          ← 여기엔 requests만
└── mlops-project/
    └── venv/          ← 여기엔 pandas, torch만
```

서로 간섭하지 않으니 마음 놓고 설치할 수 있습니다.

### pip와 requirements.txt

| 용어 | 뜻 |
|---|---|
| **pip** | 파이썬 패키지를 설치해 주는 도구. 앱스토어라고 생각하면 됩니다 |
| **패키지(package)** | 남이 만들어 둔 코드 묶음. `pandas`, `requests` 같은 것 |
| **requirements.txt** | "이 프로젝트에 필요한 패키지 목록" 파일 |

`requirements.txt`가 왜 중요하냐면, 이 파일 한 장이 있으면 다른 사람이 `pip install -r requirements.txt` 한 줄로 내 환경을 재현할 수 있기 때문입니다.
**재현 가능성(reproducibility)** — 이 과정 전체를 관통하는 단어입니다.

### Git과 GitHub

| 용어 | 뜻 |
|---|---|
| **Git** | 내 컴퓨터에서 코드 변경 이력을 기록하는 프로그램 |
| **GitHub** | 그 기록을 인터넷에 올려 두는 웹사이트 |
| **커밋(commit)** | "여기까지의 상태를 저장" 하는 행위. 게임의 세이브 포인트 |
| **푸시(push)** | 내 컴퓨터의 커밋을 GitHub로 올리는 것 |
| **`.gitignore`** | "이 파일들은 올리지 마라"고 적는 목록 |

원리는 W22([Day 106](../05-infra-mlops/day-106.md))에서 제대로 다룹니다.
그때까지는 **add → commit → push 세 줄만 매일 반복**하면 충분합니다.

## ④ 단계별 실습

### Step 1. 파이썬 설치와 확인

1. <https://www.python.org/downloads/> 에서 **Python 3.12.x** 를 내려받습니다.
2. 설치 화면 맨 아래 **`Add python.exe to PATH`** 를 반드시 체크합니다. (이걸 놓치면 ⑤번 첫 번째 에러가 납니다)
3. `Install Now` 를 누릅니다.

설치가 끝나면 터미널(PowerShell)을 열어 확인합니다.

```powershell
$ python --version
Python 3.12.7
```

버전 숫자가 보이면 성공입니다.

pip도 같이 확인합니다.

```powershell
$ pip --version
pip 24.2 from C:\Users\사용자\AppData\Local\Programs\Python\Python312\Lib\site-packages\pip (python 3.12)
```

### Step 2. VS Code 설치와 설정

1. <https://code.visualstudio.com/> 에서 내려받아 설치합니다.
2. 왼쪽 확장(Extensions, `Ctrl+Shift+X`) 아이콘을 누르고 아래를 설치합니다.
   - **Python** (Microsoft 제작) — 필수
   - **Pylance** (Python 설치 시 함께 딸려옴) — 자동완성·타입 확인
   - **Korean Language Pack** (선택) — 메뉴 한글화

### Step 3. 작업 폴더와 첫 프로그램

작업 폴더를 하나 만듭니다. 예: `C:\workspace\mlops`

VS Code에서 `파일 > 폴더 열기`로 그 폴더를 엽니다. `hello.py` 파일을 만들어 아래를 입력합니다.

```python
# 화면에 글자를 출력합니다
print("안녕하세요, MLOps 과정입니다.")
print("오늘은 Day 001, 앞으로 159일 남았습니다.")
```

`Ctrl + F5` 또는 오른쪽 위 ▶ 버튼으로 실행합니다.

실행 결과:

```
안녕하세요, MLOps 과정입니다.
오늘은 Day 001, 앞으로 159일 남았습니다.
```

> `print()` 는 괄호 안의 내용을 화면에 보여 주는 명령입니다. 앞으로 가장 많이 쓰게 될 함수입니다.

### Step 4. 가상환경 만들기

VS Code 터미널(`Ctrl + Shift + ~`)에서 아래를 순서대로 실행합니다.

```powershell
# 1. venv 라는 이름의 가상환경을 만듭니다
$ python -m venv venv

# 2. 가상환경을 켭니다 (활성화)
$ .\venv\Scripts\Activate.ps1
```

실행 결과 — 프롬프트 앞에 `(venv)` 가 붙으면 성공입니다.

```
(venv) PS C:\workspace\mlops>
```

> **활성화(activate)** 는 "지금부터 이 도구상자를 쓰겠다"는 선언입니다.
> 터미널을 새로 열 때마다 다시 활성화해야 합니다. 끌 때는 `deactivate` 를 입력합니다.

macOS·Linux(WSL2 포함)라면 활성화 명령이 다릅니다.

```bash
$ source venv/bin/activate
```

VS Code가 이 가상환경을 쓰도록 지정합니다. `Ctrl+Shift+P` → `Python: Select Interpreter` → 경로에 `venv`가 들어간 항목을 고릅니다.

가상환경이 켜진 상태에서 실행합니다. `requests`는 W04에서 데이터를 수집할 때 쓸 패키지입니다.

## ⑤ 자주 하는 실수

### `'python'은(는) 내부 또는 외부 명령... 이 아닙니다`

```
'python'은(는) 내부 또는 외부 명령, 실행할 수 있는 프로그램, 또는
배치 파일이 아닙니다.
```

**원인** — 설치할 때 `Add python.exe to PATH` 를 체크하지 않았습니다. 컴퓨터가 파이썬이 어디 있는지 모릅니다.
**해결** — 파이썬 설치 파일을 다시 실행 → `Modify` → `Next` → **`Add Python to environment variables`** 체크 → `Install`.
그 후 터미널을 **새로 열어서** 확인합니다. (기존 터미널은 옛 설정을 들고 있습니다.)

### `이 시스템에서 스크립트를 실행할 수 없으므로...`

```
.\venv\Scripts\Activate.ps1 : 이 시스템에서 스크립트를 실행할 수 없으므로
C:\workspace\mlops\venv\Scripts\Activate.ps1 파일을 로드할 수 없습니다.
```

**원인** — Windows PowerShell의 보안 정책이 스크립트 실행을 막고 있습니다.
**해결** — PowerShell에서 아래를 한 번 실행하고 `Y` 로 승인합니다.

```powershell
$ Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
```

### `ModuleNotFoundError: No module named 'requests'`

```
Traceback (most recent call last):
  File "check_env.py", line 2, in <module>
    import requests
ModuleNotFoundError: No module named 'requests'
```

**원인** — 가상환경을 활성화하지 않은 상태에서 실행했거나, VS Code가 다른 파이썬을 쓰고 있습니다.
**해결** — ① 터미널 프롬프트에 `(venv)` 가 있는지 확인 ② `Ctrl+Shift+P` → `Python: Select Interpreter` → `venv` 가 붙은 항목 선택.
이 에러는 앞으로 160일 동안 가장 자주 보게 될 에러입니다. **먼저 `(venv)`부터 확인**하는 습관을 들이세요.

### `fatal: not a git repository`

```
fatal: not a git repository (or any of the parent directories): .git
```

**원인** — `git init` 을 하지 않은 폴더에서 git 명령을 실행했습니다. 또는 다른 폴더에 있습니다.
**해결** — `pwd`(PowerShell은 `Get-Location`)로 현재 위치를 확인하고, 프로젝트 폴더로 이동한 뒤 `git init`.

### GitHub에 `venv` 폴더가 올라갔습니다

**원인** — `.gitignore` 를 만들기 전에 `git add .` 을 했습니다. 한 번 추적되기 시작한 파일은 `.gitignore`를 나중에 추가해도 계속 추적됩니다.
**해결** — 추적 목록에서만 빼냅니다. (파일은 안 지워집니다.)

```powershell
$ git rm -r --cached venv
$ git commit -m "venv 추적 제외"
$ git push
```

## ⑥ 확인 문제

**1.** 가상환경을 쓰지 않고 모든 패키지를 한 곳에 설치하면 어떤 문제가 생길 수 있나요?

<details>
<summary>답 보기</summary>

프로젝트마다 필요한 패키지 **버전**이 다를 때 충돌이 납니다.
예를 들어 W05에서 쓰던 프로젝트가 `numpy 1.26`을 쓰는데, W16에서 PyTorch를 설치하며 `numpy 2.1`로 덮어쓰면 앞 프로젝트의 코드가 갑자기 에러를 냅니다.

또 하나의 문제는 **재현 불가능**입니다. 전역에 100개가 깔려 있으면 이 프로젝트에 실제로 필요한 것이 무엇인지 알 수 없어서, W24에서 Docker 이미지를 만들 때 무엇을 설치해야 할지 정할 수 없습니다.
</details>

**2.** `requirements.txt` 파일은 왜 만드나요? 이 파일이 없으면 나중에 어떤 일이 생기나요?

<details>
<summary>답 보기</summary>

이 프로젝트를 돌리는 데 필요한 패키지와 **버전**을 기록한 파일입니다.
받는 사람이 `pip install -r requirements.txt` 한 줄로 똑같은 환경을 재현할 수 있습니다.

없으면 ① 팀원이 내 코드를 받아도 실행하지 못하고 ② W24에서 Dockerfile을 쓸 때 설치 목록을 손으로 추측해야 하며 ③ 몇 달 뒤 내가 다시 열었을 때 어떤 버전에서 돌아가던 코드인지 알 수 없습니다.
</details>

**3.** `.gitignore` 파일에 `venv/` 와 `.env` 를 적는 이유는 각각 무엇인가요?

<details>
<summary>답 보기</summary>

**`venv/`** — 용량이 수백 MB로 크고, 운영체제·파이썬 버전마다 내용이 달라 다른 컴퓨터에서 그대로 쓸 수 없습니다.
대신 `requirements.txt` 만 올려 두면 받는 사람이 자기 환경에 맞게 재생성할 수 있습니다.

**`.env`** — 여기에는 API 인증키·DB 비밀번호 같은 **비밀 정보**가 들어갑니다 (W04부터 사용).
GitHub 공개 저장소에 키가 올라가면 자동 스캔 봇이 몇 분 안에 찾아내 악용합니다. 실무에서 실제로 벌어지는 사고입니다.
</details>

## 오늘의 정리

| 명령 | 하는 일 |
|---|---|
| `python --version` | 파이썬 설치 확인 |
| `python -m venv venv` | 가상환경 생성 |
| `.\venv\Scripts\Activate.ps1` | 가상환경 활성화 (Windows) |
| `source venv/bin/activate` | 가상환경 활성화 (macOS/Linux) |
| `pip install 패키지명` | 패키지 설치 |
| `pip freeze > requirements.txt` | 설치 목록 저장 |
