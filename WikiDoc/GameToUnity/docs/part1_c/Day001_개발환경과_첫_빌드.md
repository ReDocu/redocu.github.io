## 3. 개념

### 3-1. 소스코드는 어떻게 실행 파일이 되나

**왜 필요한가** — 빌드가 실패했을 때 어느 단계에서 실패했는지 알아야 고칠 수 있다.

```
   main.c            컴파일          main.obj          링크         main.exe
   (내가 쓴 글)  ──────────────▶  (기계어 조각)  ──────────────▶  (실행 파일)
                      │                                │
                      │                                │
              문법이 틀리면 여기서 실패        함수를 못 찾으면 여기서 실패
              "구문 오류", "선언되지 않은..."   "확인할 수 없는 외부 기호"
```

| 단계 | 하는 일 | 대표 오류 메시지 |
|---|---|---|
| **컴파일** | 문법 검사 → 기계어 조각(`.obj`) 생성 | `error C2143: 구문 오류`, `error C2065: 선언되지 않은 식별자` |
| **링크** | 조각들 + 라이브러리를 하나로 묶음 | `error LNK2019: 확인할 수 없는 외부 기호` |
| **실행** | OS가 `.exe`를 메모리에 올려 돌림 | 크래시, 잘못된 결과 |

> 오류 메시지 앞의 `C`는 컴파일 오류, `LNK`는 링크 오류다. **이 글자 하나로 원인의 절반이 좁혀진다.**

### 3-2. `main` 함수 — 프로그램의 입구

**왜 필요한가** — OS는 어디서부터 실행할지 알아야 한다. 그 약속된 이름이 `main`이다.

```c
#include <stdio.h>      // printf를 쓰기 위한 선언들을 가져온다

int main(void)          // 프로그램은 여기서 시작한다
{
    printf("전투 시작!\n");

    return 0;           // 0 = 정상 종료. OS에게 보고하는 값
}
```

| 조각 | 뜻 |
|---|---|
| `#include <stdio.h>` | `printf` 같은 표준 입출력 기능을 쓰겠다는 선언 |
| `int main(void)` | 정수를 반환하고, 인자를 받지 않는 시작 함수 |
| `{ }` | 함수의 몸통. 이 안이 실행된다 |
| `return 0;` | 정상 종료 신호 |

### 3-3. `printf` — 화면에 찍기

**왜 필요한가** — 게임의 세 칸 중 **출력**을 담당한다. 지금은 이게 우리의 유일한 화면이다.

```c
printf("문자열 그대로\n");           // \n = 줄바꿈
printf("HP: %d\n", 100);             // %d 자리에 100이 들어간다
printf("%s의 HP는 %d\n", "용사", 100);
```

**서식 지정자** — `%` 뒤에 오는 글자가 "여기에 무엇이 들어올지"를 정한다.

| 지정자 | 자료형 | 예시 | 출력 |
|:--:|---|---|---|
| `%d` | 정수 | `printf("%d", 42)` | `42` |
| `%f` | 실수 | `printf("%f", 3.14)` | `3.140000` |
| `%.2f` | 실수(소수 2자리) | `printf("%.2f", 3.14159)` | `3.14` |
| `%c` | 문자 하나 | `printf("%c", 'A')` | `A` |
| `%s` | 문자열 | `printf("%s", "용사")` | `용사` |
| `%%` | `%` 기호 자체 | `printf("100%%")` | `100%` |

**정렬 — 게임 화면을 만들 때 아주 유용하다.**

| 표기 | 뜻 | `printf("[%5d]", 42)` 결과 |
|---|---|---|
| `%5d` | 폭 5칸, 오른쪽 정렬 | `[   42]` |
| `%-5d` | 폭 5칸, 왼쪽 정렬 | `[42   ]` |

**이스케이프 문자**

| 표기 | 뜻 |
|:--:|---|
| `\n` | 줄바꿈 |
| `\t` | 탭 |
| `\\` | 역슬래시 `\` |
| `\"` | 큰따옴표 `"` |

### 3-4. 콘솔 한글 출력

**왜 필요한가** — 한글이 `???`로 나오면 오늘 화면이 성립하지 않는다.

Windows 콘솔의 기본 코드 페이지와 소스 파일의 인코딩이 어긋나면 글자가 깨진다. 둘 중 하나로 맞춘다.

**방법 A — 소스 파일을 "UTF-8(BOM 포함)"으로 저장 (권장)**

```
Visual Studio 메뉴 → 파일 → 다른 이름으로 저장 → 저장 버튼 옆 ▼ → 인코딩하여 저장
→ "유니코드(UTF-8 서명 있음) - 코드 페이지 65001" 선택
```

**방법 B — 코드에서 콘솔 출력 코드 페이지를 바꾸기**

```c
#include <stdio.h>
#include <windows.h>

int main(void)
{
    SetConsoleOutputCP(65001);   // 콘솔 출력을 UTF-8로
    printf("전투 시작!\n");
    return 0;
}
```

> 둘 다 해도 된다. **먼저 A를 시도하고, 그래도 깨지면 B를 추가**한다.

## 4. 따라 만들기

### Step 0 — 프로젝트 만들기

1. Visual Studio 2022 실행 → **새 프로젝트 만들기**
2. **빈 프로젝트** 선택 (C++) → 이름 `01_rpg_battle` → 위치 `KY/src/`
3. 솔루션 탐색기 → **소스 파일** 우클릭 → 추가 → 새 항목 → **C++ 파일(.cpp)**
4. 파일 이름을 **`main.c`** 로 (확장자 `.c`를 직접 입력)

> `.cpp`가 아니라 `.c`로 만드는 이유 — 6주차까지는 C 문법으로 간다. 확장자가 컴파일 방식을 결정한다.

**✅ 여기까지 하면** — 솔루션 탐색기에 `main.c`가 보이고 편집기가 열린다. (아직 빌드 안 됨)

### Step 1 — 첫 출력

```c
#include <stdio.h>

int main(void)
{
    printf("전투 시작!\n");

    return 0;
}
```

**빌드하고 실행** — `Ctrl + F5` (디버깅 없이 시작)

**✅ 여기까지 실행하면** — 검은 창에 `전투 시작!` 한 줄이 나오고, "계속하려면 아무 키나 누르십시오"가 뜬다.

> `F5`(디버깅 시작)로 실행하면 창이 순식간에 닫힌다. **`Ctrl + F5`를 쓴다.**

### Step 2 — 구분선 그리기

```c
#include <stdio.h>

int main(void)
{
    printf("===============================\n");   // ← 추가
    printf("      전투 시작!\n");
    printf("-------------------------------\n");   // ← 추가
    printf("===============================\n");   // ← 추가

    return 0;
}
```

**✅ 여기까지 실행하면** — 제목이 선 사이에 끼워진 형태로 보인다.

### Step 3 — 캐릭터 상태 넣기

```c
#include <stdio.h>

int main(void)
{
    printf("===============================\n");
    printf("      전투 시작!\n");
    printf("-------------------------------\n");
    printf("  용사    HP %3d / %3d\n", 100, 100);   // ← 추가
    printf("  슬라임  HP %3d / %3d\n",  30,  30);   // ← 추가
    printf("===============================\n");

    return 0;
}
```

`%3d`로 폭을 3칸 잡았기 때문에 `100`과 `30`의 자릿수가 달라도 세로줄이 맞는다.

**✅ 여기까지 실행하면** — 1절의 완성 화면과 동일한 결과가 나온다.

## 6. 자주 막히는 곳

| 증상 | 원인 | 해결 |
|---|---|---|
| 창이 뜨자마자 닫힘 | `F5`로 실행 | **`Ctrl + F5`** 로 실행 |
| 한글이 `???` | 인코딩 불일치 | UTF-8(BOM 포함)로 저장, 안 되면 `SetConsoleOutputCP(65001)` |
| `error C2143: 구문 오류` | 세미콜론 `;` 누락 | 오류 줄 **바로 위 줄** 끝을 확인 |
| `error C2065: 선언되지 않은 식별자 'printf'` | `#include <stdio.h>` 누락 | 맨 위에 추가 |
| `"` 짝이 안 맞는다는 오류 | 따옴표 하나만 씀 | 문자열은 `"..."` 로 감싼다 |
| 자릿수가 안 맞음 | `%d`만 씀 | `%3d`처럼 폭 지정 |
| 빌드는 되는데 옛날 결과가 나옴 | 실행 파일이 갱신 안 됨 | 빌드 → **솔루션 다시 빌드** |
| C++ 관련 오류가 남 | 파일이 `.cpp` | 파일명을 `.c`로 변경 |

> **오류를 읽는 순서** — Console(출력) 창에서 **가장 위의 오류 하나**만 본다.
> 아래 오류들은 대부분 위 오류의 부작용이라, 첫 번째를 고치면 우수수 사라진다.

## 7. 정리

### 오늘 배운 것

| 개념 | 한 줄 요약 |
|---|---|
| 게임의 구조 | 게임 = 입력 → 상태 → 출력의 반복 |
| 빌드 과정 | 소스 → (컴파일) → obj → (링크) → exe |
| `main` 함수 | 프로그램의 시작 지점 |
| `printf` 서식 | `%d %f %c %s` + 폭 지정 `%5d` |
| 오류 읽기 | `C`=컴파일, `LNK`=링크. 첫 오류부터 고친다 |
