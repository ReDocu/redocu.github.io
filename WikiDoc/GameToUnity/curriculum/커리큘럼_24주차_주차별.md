## 4. 구간별 목표

### Part 1 · C언어 기초 (Week 1~6, Day 1~30, 240h)

> **"프로그램은 위에서 아래로 흐르고, 게임은 그 흐름을 반복시킨 것이다"**

콘솔이라는 가장 단순한 화면에서 프로그램의 뼈대를 잡는다. 문법을 나열하지 않고,
게임을 만들다 막히는 지점에서 필요한 문법을 꺼낸다.

| 막히는 상황 | 그래서 배우는 것 | 위치 |
|---|---|---|
| 몬스터가 여러 마리인데 변수를 계속 늘려야 한다 | 구조체 | Day 5 |
| 잘못 입력하면 프로그램이 미쳐 날뛴다 | 입력 검증 | Day 8 |
| 미로 맵을 변수 100개로 못 만든다 | 2차원 배열 | Day 12 |
| 함수 안에서 바꾼 소지금이 밖에서 안 바뀐다 | 포인터 | Day 18 |
| 키를 눌러야 화면이 갱신된다 | 게임 루프, 비동기 입력 | Day 21·23 |
| 오브젝트마다 코드가 복붙된다 | 클래스, 상속, 가상 함수 | Day 27~28 |

**Part 1 종료 시 확보**: 콘솔 게임 5편 + C++ 객체지향 기본기 (Part 2의 전제)

### Part 2 · WINAPI (Week 7~14, Day 31~70, 320h)

> **"엔진을 쓰기 전에 엔진이 무엇을 대신 해주는지 안다"**

과정 전체에서 가장 무거운 구간이자, 이 커리큘럼의 정체성이다.
Week 8에서 만든 프레임워크를 Week 9~14가 **전부 재사용**한다.

```
                      ┌─────────────────────────────────┐
   Week 7  별 애니 ──▶│  Week 8  프레임워크 (더블버퍼링) │
                      │  Core / Timer / Scene / Object   │
                      └───┬────┬────┬────┬────┬─────────┘
                          │    │    │    │    │
              Week 9 격투 ┘    │    │    │    └ Week 14 포트리스
                  Week 11 슈팅 ┘    │    └ Week 13 택틱스
                          Week 12 맵툴
```

**Part 2 종료 시 확보**: 자작 2D 게임 프레임워크 1식 + 그 위에 얹은 게임 5편

### Part 3 · Unity (Week 15~20, Day 71~100, 240h)

> **"직접 만든 것이 엔진 안에서는 무엇으로 불리는지 확인한다"**

Part 2에서 손으로 만든 개념이 Unity에서 어떤 이름을 갖는지 대응시키며 진행한다.
이 대응표가 이 구간의 학습 효율을 만든다.

| 직접 만든 것 (Part 2) | Unity에서의 이름 |
|---|---|
| 더블버퍼링 백버퍼 | 렌더 파이프라인 (URP) |
| `Update()` / `Render()` 분리 | `MonoBehaviour.Update()` / `LateUpdate()` |
| 오브젝트 풀 배열 | `ObjectPool<T>` / 프리팹 인스턴싱 |
| 스프라이트 애니메이션 상태 머신 | Animator Controller (메카님) |
| A* 길 찾기 | NavMesh / NavMeshAgent |
| 아이소메트릭 좌표 변환 | Tilemap / 카메라 투영 |

**Part 3 종료 시 확보**: Unity 게임 5편 + 빌드·버전관리 역량

### Part 4 · 파이널 프로젝트 (Week 21~24, Day 101~120, 160h)

> **"포트폴리오가 되는 결과물 하나를 끝까지 민다"**

기술 스택은 학습자가 선택한다 (WINAPI 자작 엔진 / Unity).
4주를 프로토 → 알파 → 베타 → 릴리즈의 실제 개발 사이클로 운영한다.

### Week 1 · 텍스트 RPG 전투 — 프로그램의 뼈대

- **연결 문서**: `01 영웅은 절차적`
- **목표**: 콘솔에 글자를 찍는 것에서 시작해, 주인공과 몬스터가 턴을 주고받는 전투를 완성한다.
- **선수**: 없음 (과정 시작점)

**이번 주 배우는 기능**

| 기능 | 왜 필요한가 |
|---|---|
| 변수·자료형 | 체력과 공격력을 기억해 둘 곳이 필요하다 |
| 조건문 | "체력이 0 이하면 패배"를 판단해야 한다 |
| 함수 분리 | 공격 코드가 세 군데 복붙되기 시작한다 |
| 구조체 | 몬스터가 두 마리가 되는 순간 변수 이름이 감당 안 된다 |

**일차 요약**

| Day | 내용 | 실행 결과 |

| 2 | 변수·연산자·입력 | 입력한 공격력만큼 몬스터 체력이 깎여 출력된다 |

### Week 2 · 탈출 루프 — 게임 루프의 원형

- **연결 문서**: `02 탈출 루프`
- **목표**: 메뉴를 고르고 결과를 보고 다시 메뉴로 돌아오는 구조를 만든다. 게임 루프의 조상이다.
- **선수**: Week 1 (구조체, 함수)

**이번 주 배우는 기능**

| 기능 | 왜 필요한가 |
|---|---|
| 반복문 (while/for/do-while) | 게임은 끝날 때까지 같은 일을 반복한다 |
| break / continue | "탈출 성공"이면 루프를 빠져나가야 한다 |
| 입력 검증 | 숫자를 물었는데 문자를 넣으면 프로그램이 무한루프에 빠진다 |
| 상태 변수 | 지금 몇 번 방에 있는지 기억해야 한다 |

**일차 요약**

| Day | 내용 | 실행 결과 |
|:--:|---|---|
| 6 | 반복문 3종 · 게임 루프의 형태 | 메뉴가 계속 다시 뜬다 |
| 7 | 메뉴 선택 · break / continue | 0번을 고르면 프로그램이 정상 종료된다 |
| 8 | **입력 검증** (버퍼 비우기) | 문자를 넣어도 무한루프에 빠지지 않고 재입력을 요구한다 |
| 9 | 상태 변수 · 방 이동 | 선택에 따라 다른 방 설명이 출력된다 |
| 10 | 탈출 조건 · 엔딩 분기 · 문서 02 완성 | 조건을 만족하면 "탈출 성공" 엔딩이 뜬다 |

- **다음 주 연결**: 방을 배열로 관리하면 방이 100개여도 코드는 그대로다 → **배열**

### Week 3 · 미로 탈출 — 좌표와 맵

- **연결 문서**: `03 미로 탈출`
- **목표**: 2차원 배열로 미로를 표현하고, 키 입력으로 캐릭터를 움직여 출구까지 간다.
- **선수**: Week 2 (반복문, 입력 검증)

**이번 주 배우는 기능**

| 기능 | 왜 필요한가 |
|---|---|
| 배열 (1차원) | 아이템 5개를 변수 5개로 만들 수는 없다 |
| **2차원 배열** | 미로는 가로 × 세로다 |
| 좌표 이동 (dx, dy) | 방향키를 좌표 변화로 바꿔야 한다 |
| 벽 판정 · 경계 검사 | 벽을 통과하고 화면 밖으로 나가버린다 |

**모노스페이스 도해 — 배열 인덱스와 화면 좌표**

```
   map[y][x]  ← 행이 y(세로), 열이 x(가로). 순서 주의

        x→ 0 1 2 3 4
   y=0     # # # # #        '#' 벽
   y=1     # P . . #        '.' 길
   y=2     # . # . #        'P' 플레이어 (x=2, y=1) → map[1][2]
   y=3     # . . . E        'E' 출구
   y=4     # # # # #

   ←(-1,0)  →(+1,0)  ↑(0,-1)  ↓(0,+1)
```

**일차 요약**

| Day | 내용 | 실행 결과 |
|:--:|---|---|
| 11 | 1차원 배열 · 인덱스와 메모리 | 인벤토리 5칸이 순서대로 출력된다 |
| 12 | 2차원 배열 · 맵 출력 | 콘솔에 `#`과 `.`로 미로가 그려진다 |

### Week 14 · 포트리스 — 각도, 포물선, 알파 렌더

- **연결 문서**: `12 포트리스`
- **목표**: 각도와 힘으로 포탄을 쏘고, 포물선을 그리며 날아가 지형을 파괴하게 만든다. WINAPI 구간을 닫는다.

**모노스페이스 도해 — 발사 벡터와 포물선**

```
   각도 θ, 힘 P 일 때 (라디안 = θ * π / 180)

     vx = cos(θ) * P
     vy = -sin(θ) * P        ← 화면 y는 아래가 +이므로 부호 반전

   매 프레임:
     vy += GRAVITY * dt      ← 중력이 vy를 계속 아래로 민다
     x  += vx * dt
     y  += vy * dt

        ·   ·  ·
     ·           ·  ·
   ▲                    · ·
  포대                       ▼ 착탄 → 지형 파괴
```

### Week 19 · 레이싱 게임 — 셰이더와 주행 경로

- **연결 문서**: `17 레이싱 게임`
- **목표**: 차량을 조종하고, AI가 트랙을 따라 달리게 하고, 셰이더로 화면을 손본다.

| 기능 | 왜 필요한가 |
|---|---|

| 웨이포인트 / 스플라인 경로 | 트랙은 격자가 아니다 |
| **Point Cloud (경로 점군) 분석** | 코너 앞에서 감속하려면 앞 지점을 미리 봐야 한다 |
| AI 경로 추종 · 랩 판정 | 상대가 있어야 레이싱이다 |
| **셰이더 (Shader Graph) · URP** | 재질과 화면 효과를 직접 만든다 |
| 포스트 프로세싱 | 속도감은 연출로 만든다 |

**모노스페이스 도해 — 웨이포인트 추종과 선행 지점**

```
   트랙 위 경로 점군 (Point Cloud)

     P0 ── P1 ── P2 ── P3
                        ╲
                         P4      ← 선행 지점(lookahead) = 현재 위치 기준 N개 앞
                          ╲         P4까지의 각도차가 크다 → 코너 → 감속
                           P5

   조향 = (선행 지점 방향 - 현재 진행 방향)
   목표 속도 = 최대속도 × (1 - 각도차 / 180)
```
