## ② 왜 필요한가

지난주 CNN은 이미지의 전용 부품이었습니다. 텍스트에도 전용 부품이 필요합니다 — 그런데
텍스트는 이미지보다 성질이 고약합니다.

```
"미세먼지가 심해서 창문을 닫았다. 그것이 걱정이다."
```

여기서 "그것"이 무엇인지 사람은 즉시 압니다. 모델 입장에서 이건 어려운 문제입니다 —
**단서가 멀리 떨어져** 있고(장거리 의존), 문장마다 길이가 다르며, 순서를 바꾸면 뜻이
변합니다. 2017년 이전의 표준(RNN)은 문장을 왼쪽부터 한 단어씩 읽어 기억을 이어 갔는데,
멀수록 기억이 흐려지고 순차 계산이라 GPU를 놀렸습니다.

**Attention은 이 문제를 "모든 단어 쌍을 동시에 비교"로 뒤집었고**, 이 부품 하나로 조립된
Transformer가 오늘날 언어 모델 전부(BERT, GPT, 번역기, ChatGPT)의 뼈대입니다.
MLOps 엔지니어가 이 구조를 수식 없이라도 설명할 수 있어야 하는 이유는 단순합니다 —
**앞으로 서빙하게 될 모델의 태반이 이것**이기 때문입니다.

## ③ 개념 설명

### Self-Attention — 세 단계 계산

각 단어가 문장 안의 **모든 단어에게 "주목 점수"를 배분**하고, 그 비율로 정보를 섞습니다.

```
① 유사도:   모든 단어 쌍의 벡터 내적            (나와 관련 있는 단어는?)
② softmax:  각 단어의 주목 배분을 합 1로 정규화   (관심의 예산 배분)
③ 가중 평균: 배분 비율만큼 다른 단어의 벡터를 섞음  (문맥이 반영된 새 표현)
```

전부 행렬곱입니다 — [Day 076](day-076.md)의 `@` 로 다 됩니다. 그래서 GPU에서 병렬로 빠릅니다.

실제 Transformer는 여기에 세 가지를 더합니다 (이름만 알아 두세요):

| 장치 | 역할 |
|---|---|
| **Q/K/V 투영** | 내적 전에 단어 벡터를 세 갈래(질문/열쇠/값)로 변환 — 이 변환이 **학습되는** 부분 |
| **멀티 헤드** | 위 계산을 여러 벌(예: 12개) 병렬로 — 헤드마다 다른 관계(지시·수식·인접)를 봄 |
| 위치 인코딩 | 순서 정보를 벡터에 주입 (어텐션 자체는 순서를 모르므로) |

### Encoder / Decoder — 이해와 생성

```
Encoder: 문장 전체를 양방향으로 읽고 각 토큰의 문맥 표현을 만든다   → "이해"
Decoder: 지금까지 생성된 것만 보고 다음 토큰을 하나씩 만든다        → "생성"
```

| 계열 | 구조 | 대표 | 잘하는 것 |
|---|---|---|---|
| Encoder만 | 양방향 | **BERT** (내일 씀) | 분류·임베딩·검색 |
| Decoder만 | 한 방향(왼→오) | **GPT** | 생성 ([Day 090](day-090.md)에서 개관) |
| 둘 다 | 번역기 원형 | T5, 번역 모델 | 입력→출력 변환 |

### 스케일 감각

오늘 손계산은 4단어×4차원입니다. 실제 klue/bert-base는 **토큰 512개 × 768차원 × 12층 ×
12헤드**로 같은 계산을 합니다. 원리는 오늘 것과 동일하고, 크기만 다릅니다.

### Step 1. 장난감 셀프 어텐션 — 손으로 검산 가능한 크기 (1~3교시)

```python
# day086_attention.py — Attention: "어디를 볼지"를 배운다
import torch
import torch.nn.functional as F

torch.manual_seed(42)

print("== B. 셀프 어텐션을 장난감 숫자로 ==")
# 단어 4개짜리 문장, 각 단어를 4차원 벡터로 (실제로는 수백 차원)
words = ["미세먼지가", "심해서", "그것이", "해롭다"]
E = torch.tensor([
    [1.0, 0.9, 0.0, 0.1],    # 미세먼지가 (대기 오염 주제)
    [0.2, 0.3, 0.8, 0.0],    # 심해서     (정도 표현)
    [0.9, 0.8, 0.1, 0.2],    # 그것이     (미세먼지를 가리키므로 비슷한 방향)
    [0.1, 0.2, 0.9, 0.7],    # 해롭다     (평가 표현)
])

# 유사도 점수: 모든 단어 쌍의 내적 (Q=K=V=E 로 단순화한 셀프 어텐션)
scores = E @ E.T
weights = F.softmax(scores, dim=1)       # 행마다 합이 1인 '주목 배분'
print("어텐션 가중치 (행 = 이 단어가, 열 = 저 단어를 얼마나 보나):")
print("            " + "  ".join(f"{w:>8}" for w in words))
for i, w in enumerate(words):
    print(f"{w:>8}  " + "  ".join(f"{v:8.2f}" for v in weights[i]))

print(f"\n'그것이'의 주목 배분: {dict(zip(words, [round(v, 2) for v in weights[2].tolist()]))}")
```

실행 결과:

```
== B. 셀프 어텐션을 장난감 숫자로 ==
어텐션 가중치 (행 = 이 단어가, 열 = 저 단어를 얼마나 보나):
               미세먼지가       심해서       그것이       해롭다
   미세먼지가      0.43      0.11      0.36      0.10
     심해서      0.21      0.28      0.22      0.29
     그것이      0.40      0.13      0.35      0.13
     해롭다      0.16      0.24      0.18      0.42
```

'그것이' 행을 읽으세요 — 자기 자신(0.35)보다 **'미세먼지가'(0.40)를 더 크게** 봅니다.
두 단어의 벡터가 비슷한 방향(같은 주제)이라 내적이 컸기 때문입니다. **대명사 해소가
내적 + softmax만으로** 일어났습니다. 우리가 규칙을 쓴 게 아니라, 벡터의 기하가 해낸 것입니다.

### Step 2. 주목한 만큼 섞기 (4교시)

```python
print("\n== C. 주목한 만큼 섞는다 — 새 표현 만들기 ==")
new_E = weights @ E                       # 각 단어의 새 벡터 = 주목 가중 평균
print(f"'그것이'의 원래 벡터: {[round(v, 2) for v in E[2].tolist()]}")
print(f"'그것이'의 새 벡터  : {[round(v, 2) for v in new_E[2].tolist()]}")
```

실행 결과:

```
== C. 주목한 만큼 섞는다 — 새 표현 만들기 ==
'그것이'의 원래 벡터: [0.9, 0.8, 0.1, 0.2]
'그것이'의 새 벡터  : [0.75, 0.7, 0.25, 0.2]
```

'그것이'의 새 벡터에는 주목 비율만큼 다른 단어들의 정보가 섞였습니다 — 이제 이 벡터는
"그것"이 아니라 **"(미세먼지를 가리키는) 그것"** 을 표현합니다. 이 섞기를 12층 반복하면
층이 올라갈수록 점점 풍부한 문맥 표현이 됩니다. Transformer 한 층의 본질이 이 두 Step입니다.

### Step 3. 진짜 모델의 어텐션 열어 보기 (5~6교시)

장난감이 아니라 klue/bert-base(내일 정식 소개)의 어텐션을 직접 꺼냅니다.

```python
print("\n== E. 실제 BERT의 어텐션 — '그것'은 누구를 보는가 ==")
from transformers import AutoModel, AutoTokenizer
tok = AutoTokenizer.from_pretrained("klue/bert-base")
model = AutoModel.from_pretrained("klue/bert-base", attn_implementation="eager")
sent = "미세먼지가 심해서 그것이 걱정이다"
b = tok(sent, return_tensors="pt")
tokens = tok.convert_ids_to_tokens(b["input_ids"][0])
with torch.no_grad():
    out = model(**b, output_attentions=True)
att = out.attentions
print("토큰:", tokens)
print("어텐션 텐서: 층", len(att), "개 · 각", tuple(att[0].shape), "(배치, 헤드, 토큰, 토큰)")

i = tokens.index("그것")
j = tokens.index("미세먼지")
best = max(((att[L][0, h, i, j].item(), L, h) for L in range(12) for h in range(12)))
val, L, h = best
print(f"'그것' 토큰이 '미세먼지'를 가장 크게 보는 헤드: {L+1}층 {h+1}번 (가중치 {val:.2f})")
for t, v in zip(tokens, att[L][0, h, i].tolist()):
    print(f"  {t:>8} {v:.2f}")
```

실행 결과:

```

토큰: ['[CLS]', '미세먼지', '##가', '심해', '##서', '그것', '##이', '걱정', '##이다', '[SEP]']
어텐션 텐서: 층 12 개 · 각 (1, 12, 10, 10) (배치, 헤드, 토큰, 토큰)
'그것' 토큰이 '미세먼지'를 가장 크게 보는 헤드: 5층 2번 (가중치 0.36)
     [CLS] 0.08
      미세먼지 0.36
       ##가 0.09
        심해 0.07
       ##서 0.03
        그것 0.02
       ##이 0.07
        걱정 0.10
      ##이다 0.04
     [SEP] 0.14
```

144개 헤드(12층×12헤드) 중에 **'그것'→'미세먼지'에 0.36을 배분하는 헤드**가 실제로
있습니다. 아무도 이 헤드에게 "대명사를 처리하라"고 시키지 않았습니다 — 대량의 한국어를
학습하는 과정에서 저절로 분화된 역할입니다. 다른 헤드들은 인접 토큰, 조사, 문장 경계 등
저마다 다른 관계를 봅니다 (144개를 다 볼 필요는 없습니다 — "여러 관점의 앙상블"이라는
그림만 가져가세요).

참고 — 모델 로드 시 `cls.predictions.*` 가중치가 UNEXPECTED라는 안내가 뜹니다.
klue/bert-base의 원래 용도(빈칸 맞히기 헤드)에 딸린 부분인데 `AutoModel`(몸통만)에는
자리가 없어 버려진다는 뜻으로, 정상입니다 — 내일 이 "헤드 갈아 끼우기"가 핵심 주제가 됩니다.

## ⑤ 자주 하는 실수

### 어텐션 가중치를 "정답 해석"으로 믿음

**증상** — "5층 2번 헤드가 대명사 담당"이라고 보고서에 단정.
**원인** — 헤드의 역할 분화는 경향이지 계약이 아닙니다. 문장이 바뀌면 다른 헤드가 그 일을 하기도 합니다.
**해결** — 어텐션 시각화는 직관을 얻는 도구로 쓰되, 모델 해석의 근거로는 [Day 064](../03-machine-learning/day-064.md)에서 배운 것처럼 입력을 바꿔 보는 실험(ablation)을 함께 쓰세요.

### softmax의 dim을 틀림

**증상** — 가중치 행렬의 **열** 합이 1 (행 합이 아니라) — 주목 배분이 뒤집힌 해석이 됨.
**원인** — `F.softmax(scores, dim=1)` 의 dim은 "어느 축을 따라 합이 1인가"입니다. dim=0이면 열 기준.
**해결** — "행 = 주목하는 쪽"이 되도록 dim=1(마지막 축). 계산 후 `weights.sum(dim=1)` 이 전부 1인지 확인하는 습관.

### output_attentions에서 에러 또는 빈 값

**증상** — `out.attentions` 가 None이거나, 최신 버전에서 어텐션 구현 관련 경고/에러.
**원인** — 기본 어텐션 구현(sdpa 등 고속 커널)은 가중치를 밖으로 내주지 않는 경우가 있습니다.
**해결** — 관찰이 목적일 때는 Step 3처럼 `attn_implementation="eager"` 로 로드합니다 (느리지만 속이 보임). 서빙에서는 기본 구현으로 되돌립니다.

### 어텐션 = Transformer 전부라고 착각

**증상** — "Transformer는 어텐션이다"라고만 알고, 층 하나에 함께 있는 나머지(FFN·잔차·정규화)를 모름.
**원인** — 오늘 수업이 어텐션에 집중했기 때문 — 의도된 단순화입니다.
**해결** — 층 하나 = 어텐션(섞기) + FFN(가공) + 잔차·LayerNorm(안정화)라는 구도만 기억하세요. 우리 과정 깊이에선 이 한 줄이면 충분하고, 더는 LLM 과정의 몫입니다.

### 토큰 = 단어라고 가정

**증상** — Step 3에서 '미세먼지가'를 찾는데 토큰 목록에 없음 ('미세먼지'와 '##가'로 쪼개져 있음).
**원인** — 모델은 단어가 아니라 **서브워드 토큰** 단위로 봅니다.
**해결** — 내일(Day 087)의 주제가 정확히 이것입니다. 오늘은 `convert_ids_to_tokens` 로 실제 토큰을 확인하고 그 안에서 찾는 것으로 충분합니다.

언어로)을 답하세요.

<details>
<summary>답 보기</summary>

① 유사도 — 모든 쌍의 내적 (`E @ E.T`, 행렬곱), ② 주목 배분 — softmax (행 기준 정규화),
③ 섞기 — 가중 평균 (`weights @ E`, 행렬곱). 전부 행렬 연산이라 GPU 병렬화에 최적이고,
이것이 RNN 대비 Transformer의 속도 우위의 근원입니다.

**Q2.** RNN이 "그것 → 미세먼지" 같은 장거리 의존에 약한 이유와, 어텐션이 그 문제를 어떻게
구조적으로 없앴는지 비교하세요.

<details>
<summary>답 보기</summary>

RNN은 왼쪽부터 순서대로 읽으며 기억(은닉 상태)을 이어 가므로, 두 단어 사이 거리만큼 정보가
여러 단계를 거치며 희석됩니다. 어텐션은 모든 단어 쌍을 **직접, 같은 한 번의 계산**으로 비교하므로
거리 1이든 100이든 연결 비용이 동일합니다 — 장거리 의존이 "먼 길"이 아니라 "옆자리"가 됩니다.

</details>

**Q3.** BERT(Encoder)와 GPT(Decoder)의 구조적 차이 한 가지와, 그로 인해 각각 잘하게 된 일을 쓰세요.

<details>
<summary>답 보기</summary>

BERT는 문장 **전체를 양방향**으로 보고 각 토큰의 표현을 만들므로 이해 계열(분류·임베딩)에 강하고,
GPT는 **왼쪽만 보며 다음 토큰을 생성**하도록 제약되어 있어 생성에 강합니다. 그래서 내일 분류기의
재료로는 BERT 계열(klue/bert-base)을 쓰고, 생성형의 동작 원리는 [Day 090](day-090.md)에서 개관합니다.

</details>
