## 2. 막히는 상황

어제 확인한 사실을 정리한다.

```
   ① 그릴 것이 많을수록 깜빡임이 심하다
   ② 매 프레임 "배경만 있는 빈 화면"이 잠깐 보인다
   ③ 배경을 안 지우면 깜빡임이 사라진다 (대신 잔상이 남는다)
   ④ 그리기를 최적화해도 깜빡임 자체는 안 없어진다
```

그런데 이상한 점이 있다.

```
   ★ 우리는 배경을 지우는 코드를 쓴 적이 없다

   WM_PAINT 안에는 이것뿐이다:

   RenderStars(hdc);
   RenderUI(hdc);

   FillRect도, 배경 칠하기도 없다.
   그런데 왜 화면이 지워지는가?
```

```
   지금:   누가, 언제, 왜 배경을 지우는지 모른다

   필요:   ① 배경을 지우는 주체를 찾는다
           ② 그 시점을 정확히 안다
           ③ 막아 보고, 그때 무슨 일이 생기는지 확인한다
```

> **범인을 찾아야 한다.**

## 3. 개념

### 3-1. `WM_ERASEBKGND` — 범인

**왜 필요한가** — 우리가 쓴 적 없는 배경 지우기의 정체.

```
   WM_PAINT 가 오기 직전에, Windows는 WM_ERASEBKGND 를 먼저 보낸다

   ┌───────────────────────────────────────────────────────┐
   │  InvalidateRect(hWnd, NULL, TRUE)                      │
   │        ↓                                               │
   │  Windows: "이 영역이 더러워졌다. 배경도 지워야 한다"     │
   │        ↓                                               │
   │  ★ WM_ERASEBKGND  ──▶  DefWindowProc                  │
   │                          ↓                             │
   │                     WNDCLASS의 hbrBackground 로        │
   │                     클라이언트 영역 전체를 칠한다        │
   │        ↓                                               │
   │  WM_PAINT  ──▶  우리 코드가 그린다                      │
   └───────────────────────────────────────────────────────┘
```

```cpp
    // Day 31에서 이렇게 썼다
    wc.hbrBackground = (HBRUSH)GetStockObject(BLACK_BRUSH);
    //                  ▲
    //                  └── 이 브러시로 Windows가 배경을 칠한다
```

> **범인은 `DefWindowProc`의 `WM_ERASEBKGND` 기본 처리였다.**
> 우리가 코드를 안 썼을 뿐, Windows가 대신 하고 있었다.

### 3-2. 깜빡임의 정확한 메커니즘

**왜 필요한가** — 시간축으로 보면 명확해진다.

```
   한 프레임의 시간축 (별 500개, 그리기 8ms 기준)

   시각(ms)   화면 상태                       무슨 일
   ────────────────────────────────────────────────────────────
     0.0      [별들이 있는 완성 화면]          이전 프레임 결과
     0.1      [████ 전부 검정 ████]           ← WM_ERASEBKGND: 배경 칠
     1.0      [· 별 조금 그려짐]              WM_PAINT 진행 중
     3.0      [· · · 별 절반]                 진행 중
     6.0      [· · · · · 별 대부분]           진행 중
     8.0      [완성 화면]                     WM_PAINT 끝
    16.7      [████ 전부 검정 ████]           ← 다음 프레임의 지우기
    ...

   ★ 0.1ms ~ 8.0ms 구간이 "불완전한 화면"이다
     이 구간이 초당 60번 반복되면 → 깜빡임
```

```
   ┌──────────────────────────────────────────────────────┐
   │  깜빡임의 정의                                        │
   │                                                       │
   │  "그리는 중간 과정이 사용자 눈에 보이는 현상"           │
   │                                                       │
   │  중간 과정이 길수록 (=그릴 게 많을수록) 심해진다        │
   │  ✔ 어제 관찰 ①과 정확히 일치                          │
   └──────────────────────────────────────────────────────┘
```

**모니터 관점에서 보면**

```
   모니터는 초당 60번 화면을 읽어 표시한다 (60Hz)

   읽는 순간에 우리 화면이 "지워진 상태"면  →  검은 화면이 표시된다
   읽는 순간에 "완성된 상태"면              →  정상 화면이 표시된다

   ★ 우리가 그리는 타이밍과 모니터가 읽는 타이밍이 안 맞아서
     둘이 섞여 보이는 것이다
```

### 3-3. `WM_ERASEBKGND` 가로채기

**왜 필요한가** — 범인을 확인했으니 막아 본다.

```cpp
    case WM_ERASEBKGND:
        return 1;                // ★ "내가 지웠다" (실제로는 안 지움)
```

```
   반환값의 의미

   0  →  "안 지웠다"  →  Windows가 계속 진행 (사실상 의미 없음)
   1  →  "지웠다"     →  Windows가 기본 지우기를 건너뛴다  ★

   ★ 다른 메시지와 달리 return 0 이 아니다. 주의!
```

**막으면 무슨 일이 생기나**

```
   ✔ 깜빡임이 사라진다
   ✘ 이전 프레임의 그림이 안 지워져서 잔상이 남는다

   별이 지나간 자리에 별이 계속 쌓인다
   → 화면이 하얗게 뒤덮인다
```

> **어제 `bErase=FALSE`로 했을 때와 같은 결과다.**
> 지우는 방법이 두 가지였을 뿐, 결국 같은 이야기다.

### 3-4. 배경 지우기의 세 가지 경로

**왜 필요한가** — 어디를 건드려야 하는지 정리한다.

```
   ┌─────────────────────────────────────────────────────────┐
   │  경로 ①  InvalidateRect 의 bErase 인자                  │
   │           TRUE  →  WM_ERASEBKGND 발생                   │
   │           FALSE →  발생 안 함                            │
   ├─────────────────────────────────────────────────────────┤
   │  경로 ②  WM_ERASEBKGND 처리                             │
   │           DefWindowProc  →  hbrBackground 로 칠함        │
   │           return 1        →  안 칠함                     │
   ├─────────────────────────────────────────────────────────┤
   │  경로 ③  WNDCLASS.hbrBackground                         │
   │           브러시 지정  →  그 색으로 칠함                  │
   │           NULL        →  아무것도 안 칠함                 │
   └─────────────────────────────────────────────────────────┘

   ★ 셋 중 하나만 막아도 배경 지우기가 멈춘다
   ★ 게임에서는 보통 ②와 ③을 모두 처리한다
```

| 조합 | 결과 |
|---|---|
| bErase=TRUE + DefWindowProc + 브러시 있음 | 깜빡임 (기본 상태) |
| bErase=FALSE | 깜빡임 없음, 잔상 |
| `WM_ERASEBKGND` return 1 | 깜빡임 없음, 잔상 |
| `hbrBackground = NULL` | 깜빡임 없음, 잔상 |

### 3-5. 해결의 방향 — 화가의 비유

**왜 필요한가** — 답은 이미 나와 있다. 관점만 바꾸면 된다.

```
   문제:  "그리는 중간 과정이 보인다"

   → 지우지 말자?    ✘  잔상이 남는다
   → 빨리 그리자?    ✘  아무리 빨라도 0은 아니다 (어제 관찰 ④)

   → 중간 과정을 안 보이는 곳에서 하자!  ✔
```

```
   ┌─────────────────────────────────────────────────────────┐
   │  화가는 어떻게 하는가                                     │
   │                                                          │
   │  ✘  관객 앞의 캔버스를 지우고 처음부터 그린다             │
   │      → 관객이 빈 캔버스와 미완성 그림을 본다              │
   │                                                          │
   │  ✔  무대 뒤에서 완성하고, 완성본만 무대에 올린다          │
   │      → 관객은 완성된 그림만 본다                          │
   └─────────────────────────────────────────────────────────┘
```

```
   [ 지금 방식 — 단일 버퍼 ]

   화면 ─────────────────────────────────────────▶
        지움    별1   별2   ...   별500   완성
        ▲       ▲     ▲            ▲
        └───────┴─────┴────────────┘
              이 전부가 사용자에게 보인다


   [ 해결 방식 — 더블 버퍼 ]

   백버퍼 ───────────────────────────────┐
        지움    별1   별2  ...  별500   완성
        ▲                                │
        └── 아무도 못 본다                │ 한 번에 복사
                                          ▼
   화면 ─────────────────────────────────●───────▶
                                     완성본만 보인다
```

> **이것이 더블버퍼링(double buffering)이다.**
> 그리고 **Day 15에서 콘솔로 이미 해 본 것**이다.
>
> ```
>   Day 15:  char buffer[4096] 에 다 그리고  →  printf 한 번
>   Day 37:  메모리 비트맵에 다 그리고       →  BitBlt 한 번
> ```

### 3-6. 메모리 DC — 안 보이는 도화지

**왜 필요한가** — 내일 쓸 도구를 미리 소개한다.

```
   HDC 는 "그릴 대상"이라고 했다 (Day 33)

   그 대상이 반드시 화면일 필요는 없다
```

| 함수 | 만드는 것 |
|---|---|
| `GetDC(hWnd)` | **화면**에 그리는 HDC |
| `CreateCompatibleDC(hdc)` | **메모리**에 그리는 HDC ← 내일 쓴다 |
| `CreateDC("WINSPOOL",...)` | 프린터에 그리는 HDC |

```
   ┌───────────────────────────────────────────────────┐
   │  화면 DC                    메모리 DC              │
   │  ┌──────────────┐          ┌──────────────┐       │
   │  │              │          │              │       │
   │  │   보인다      │          │  안 보인다    │       │
   │  │              │          │              │       │
   │  └──────────────┘          └──────────────┘       │
   │                                    │               │
   │        ◀───────── BitBlt ─────────┘               │
   │              (픽셀 복사)                            │
   └───────────────────────────────────────────────────┘
```

> **오늘은 개념만.** 구현은 내일 한다.

### Step 4 — 진단 패널 만들기

세 가지 경로를 각각 토글할 수 있게 한다.

```cpp
bool g_handleErase   = false;      // [1] WM_ERASEBKGND 를 가로챌 것인가
bool g_bErase        = true;       // [2] InvalidateRect 의 bErase
bool g_clearInPaint  = false;      // [3] WM_PAINT 에서 직접 배경 칠

    case WM_KEYDOWN:
        switch (wParam)
        {
        case '1': g_handleErase  = !g_handleErase;  break;
        case '2': g_bErase       = !g_bErase;       break;
        case '3': g_clearInPaint = !g_clearInPaint; break;
        }
        return 0;

    case WM_ERASEBKGND:
        g_eraseCount++;
        if (g_handleErase)
            return 1;                                    // 안 지움
        return DefWindowProc(hWnd, message, wParam, lParam);   // 지움

    case WM_TIMER:
        // ...
        InvalidateRect(hWnd, NULL, g_bErase ? TRUE : FALSE);
        return 0;

    case WM_PAINT:
        {
            PAINTSTRUCT ps;
            HDC hdc = BeginPaint(hWnd, &ps);

            if (g_clearInPaint)                          // ★ 직접 칠하기
            {
                RECT rc;
                GetClientRect(hWnd, &rc);
                HBRUSH bg = CreateSolidBrush(RGB(10, 10, 25));
                FillRect(hdc, &rc, bg);
                DeleteObject(bg);
            }

            RenderStars(hdc);
            RenderDiagnostics(hdc);

            EndPaint(hWnd, &ps);
        }
        return 0;
```

**✅ 여기까지 실행하면** — 조합을 바꿔 가며 실험할 수 있다.

### Step 5 — 조합 실험 (핵심)

**아래 표를 직접 채운다.**

| [1] Erase 가로채기 | [2] bErase | [3] Paint에서 칠 | 깜빡임 | 잔상 | 비고 |
|:--:|:--:|:--:|---|---|---|
| X | TRUE | X | ? | ? | 기본 상태 |
| **O** | TRUE | X | ? | ? | |
| X | **FALSE** | X | ? | ? | |
| **O** | **FALSE** | X | ? | ? | |
| **O** | **FALSE** | **O** | ? | ? | ★ 주목 |

**예상 결과**

```
   ① X / TRUE  / X   →  깜빡임 O, 잔상 X    (기본. 지금 상태)
   ② O / TRUE  / X   →  깜빡임 X, 잔상 O
   ③ X / FALSE / X   →  깜빡임 X, 잔상 O
   ④ O / FALSE / X   →  깜빡임 X, 잔상 O
   ⑤ O / FALSE / O   →  깜빡임 O, 잔상 X    ← ★ 다시 깜빡인다!
```

**✅ 여기까지 실험하면** — ⑤번 결과가 결정적이다.

```
   ┌──────────────────────────────────────────────────────────┐
   │  ⑤ 실험이 알려주는 것                                     │
   │                                                           │
   │  Windows의 배경 지우기를 완전히 막았는데도,                │

## 6. 자주 막히는 곳

| 증상 | 원인 | 해결 |
|---|---|---|
| `WM_ERASEBKGND`가 안 옴 | `bErase=FALSE` | `TRUE`로 |
| `return 1`인데 계속 지워짐 | `DefWindowProc`도 호출 중 | `return 1;`로 끝낸다 |
| `return 0`으로 썼는데 안 됨 | `WM_ERASEBKGND`는 **1이 "지웠다"** | `return 1` |
| 배경을 막아도 검게 보임 | 클래스 브러시가 아니라 이전 프레임 잔상 | 정상 |
| 잔상이 안 생김 | 별이 너무 적거나 창을 계속 움직임 | 별 200개 이상으로 |
| 진단 패널이 잔상에 묻힘 | 배경 안 지움 상태 | 정상. 토글로 확인 |
| F6가 너무 느림 | `Sleep(1)` × 별 개수 | 별 개수를 줄여서 |
| 창을 옮기면 정상으로 보임 | 강제 전체 갱신 | 정상 |

## 7. 정리

### 오늘 배운 것

| 개념 | 한 줄 요약 |
|---|---|
| **`WM_ERASEBKGND`** | `WM_PAINT` 직전에 오는 배경 지우기 메시지 |
| `DefWindowProc` | `WNDCLASS.hbrBackground`로 클라이언트 전체를 칠한다 |
| `return 1` | "내가 지웠다" → 기본 지우기를 건너뛴다 (0이 아니다!) |
| 배경 지우기 3경로 | `bErase` / `WM_ERASEBKGND` / `hbrBackground` |
| **깜빡임의 정의** | **그리는 중간 과정이 사용자 눈에 보이는 현상** |
| **핵심 결론** | 화면에서 직접 그리는 한, 무엇을 해도 깜빡인다 |
| 메모리 DC | 화면이 아닌 곳에 그리는 HDC (내일 사용) |

### 실험으로 확인한 것

```
   ① WM_ERASEBKGND 가 매 프레임 배경을 지운다
   ② 막으면 깜빡임은 사라지지만 잔상이 남는다
   ③ 직접 칠해도 똑같이 깜빡인다        ← ★ 결정적
   ④ 그러므로 문제는 "지우기"가 아니라 "화면에서 그리는 것"이다
```
