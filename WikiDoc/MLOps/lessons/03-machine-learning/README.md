## 이 문서들을 읽는 법

각 일차 문서는 **6개 블록의 고정 구조**를 갖습니다. 어느 날짜를 펴도 같은 자리에 같은 종류의 내용이 있습니다.

| 블록 | 내용 | 이렇게 쓰세요 |
|---|---|---|
| ① 학습 목표 | 오늘을 마치면 할 수 있게 되는 것 | 수업 전에 읽고, 수업 후에 다시 읽어 체크 |
| ② 왜 필요한가 | 이 개념이 없으면 무엇이 안 되는지 | 이해가 안 갈 때 여기로 돌아오세요 |
| ③ 개념 설명 | 용어와 원리 | 표와 그림 위주. 용어는 처음 나올 때 풀어 씀 |
| ④ 단계별 실습 | Step 1 → N, 코드 + 실행 결과 | **직접 타이핑**하세요. 복사만 하면 안 늡니다 |
| ⑤ 자주 하는 실수 | 에러 메시지 원문 + 원인 + 해결 | 에러가 났을 때 Ctrl+F로 검색 |
| ⑥ 확인 문제 | 3문항, 답은 접혀 있음 | 답을 보기 전에 반드시 먼저 풀어 보세요 |

**코드 블록 규칙** — 실습 코드는 전부 **복사해서 붙여넣으면 그대로 실행되는 완성본**입니다.
터미널 블록은 `$` 로 시작하는 줄이 입력, 그 아래가 실제 출력입니다. `실행 결과:` 아래 블록은 그 코드를 실행했을 때 실제로 나오는 출력입니다.

> **이 단원의 숫자는 전부 진짜입니다.** 모든 문서가 [Day 051](day-051.md)에서 만드는 **하나의 공통 데이터셋(`air_daily.csv`, 시드 고정)** 을 사용하므로,
> 여러분이 실행한 결과와 문서의 실행 결과가 소수점까지 같아야 정상입니다. 다르면 [Day 051](day-051.md)의 환경 구축부터 다시 확인하세요.

## 이 단원을 마치면

- [ ] 문제에 맞는 모델과 **평가 지표를 선택하고 그 이유를 설명**할 수 있다
- [ ] **데이터 누수 없이** 학습/검증/평가를 분리하고 교차검증으로 성능을 신뢰할 수 있게 만든다
- [ ] 전처리부터 모델까지 **sklearn Pipeline 하나로 직렬화**해 재현 가능하게 만든다
- [ ] MLflow로 **실험을 기록·비교**하고, 학습을 CLI 스크립트로 실행할 수 있다

**단원 완료 조건 (MP2 제출 기준)**

- [ ] 베이스라인 대비 개선 폭을 CV 기준으로 제시한다
- [ ] 전처리가 Pipeline 안에 있어 누수가 없다
- [ ] MLflow에서 실험 이력을 비교해 보여줄 수 있다
- [ ] 모델 카드에 용도·한계·데이터 출처가 적혀 있다

**단원 산출물** ML 예측 모델 + 실험 기록 + 모델 카드 → 포트폴리오 저장소 3번

## 자주 나오는 질문

| 질문 | 답 |
|---|---|
| 딥러닝이 항상 더 좋지 않나요? | 테이블 데이터에서는 아닙니다. 이 단원의 데이터에서는 부스팅조차 선형 회귀를 못 이기며, 그 격차도 특성 구성에 따라 완전히 달라집니다 ([Day 059](day-059.md)·[064](day-064.md)). 문제·데이터·운영 비용에 맞게 고르는 것이 엔지니어링입니다. |
| 점수가 문서와 다르게 나옵니다 | 데이터셋·라이브러리 버전·랜덤 시드 셋 중 하나가 다른 것입니다. [Day 051](day-051.md)의 버전 고정 설치와 [Day 066](day-066.md)의 재현성 체크리스트를 확인하세요. |
| 테스트 점수가 검증 점수보다 많이 낮아요 | 검증 점수에 맞춰 튜닝을 반복해 **검증 세트에 과적합**된 것입니다. 최종 평가는 한 번만 씁니다 ([Day 061](day-061.md)). |
| 정확도만 보고하면 안 되나요? | 불균형 데이터에서 정확도는 착시를 만듭니다. 아무것도 안 하는 모델이 정확도 86%인 사례를 [Day 060](day-060.md)에서 직접 만듭니다. |
