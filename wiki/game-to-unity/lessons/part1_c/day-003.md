## 1. 오늘 만드는 것

행동을 고르고, 공격을 반복하다가, 슬라임을 쓰러뜨리면 **승리 메시지가 뜨고 게임이 끝난다.**

## 2. 막히는 상황

어제 코드에는 두 가지 문제가 있다.

```c
int realDamage = damage - SLIME_DEF;   // 공격력 1 → 데미지 -2
slimeHp -= realDamage;                 // HP가 오히려 올라간다!

// ... 그리고 HP가 -20이 되어도 프로그램은 아무 말 없이 끝난다
```

```
   지금:   무슨 값이 들어와도  →  그냥 계산하고  →  끝
                                    ▲
                                    └── 판단이 없다

   필요:   값을 보고  →  "이러면 이렇게, 저러면 저렇게"  →  다르게 행동
```

> **값을 보고 갈림길을 만드는 방법이 필요하다.** → **조건문**

## 3. 개념

### 3-1. `if` — 갈림길 만들기

**왜 필요한가** — "체력이 0 이하면 죽었다"를 프로그램이 판단해야 한다.

```c
if (조건)
{
    // 조건이 참일 때 실행
}
```

```
              ┌─────────────┐
              │  slimeHp    │
              │   <= 0 ?    │
              └──┬───────┬──┘
             참  │       │  거짓
                 ▼       ▼
         "쓰러뜨렸다"   그냥 통과
                 │       │
                 └───┬───┘
                     ▼
                  다음 코드
```

```c
if (slimeHp <= 0)
{
    slimeHp = 0;
    printf("슬라임을 쓰러뜨렸다!\n");
}
```

### 3-2. `if - else` / `else if` — 여러 갈래

**왜 필요한가** — "죽었으면 A, 아니면 B" 처럼 반대편도 처리해야 한다.

```c
if (slimeHp <= 0)
{
    printf("승리!\n");
}
else if (heroHp <= 0)
{
    printf("패배...\n");
}
else
{
    printf("전투 계속\n");
}
```

```
   if (A)          A가 참 → 실행하고 끝. 아래는 검사조차 안 한다
   else if (B)     A가 거짓이고 B가 참 → 실행
   else if (C)     A,B가 거짓이고 C가 참 → 실행
   else            전부 거짓 → 실행

   ★ 위에서부터 순서대로 검사하고, 하나 걸리면 나머지는 건너뛴다
```

> **순서가 결과를 바꾼다.** 넓은 조건을 먼저 쓰면 뒤가 절대 실행되지 않는다.
>
> ```c
> // ✘ 잘못된 순서 — "위험"이 절대 안 나온다
> if (ratio <= 100) printf("여유");     // 30%도 100 이하라서 여기서 걸림
> else if (ratio <= 30) printf("위험");
>
> // ✔ 좁은 조건부터
> if (ratio <= 30) printf("위험");
> else if (ratio <= 60) printf("주의");
> else printf("여유");
> ```

### 3-3. 비교 연산자와 논리 연산자

**왜 필요한가** — 조건을 만드는 재료다.

**비교 연산자** — 결과는 항상 참(1) 또는 거짓(0)

| 연산자 | 뜻 | 예 |
|:--:|---|---|
| `==` | 같다 | `hp == 0` |
| `!=` | 다르다 | `choice != 3` |
| `<` `>` | 작다 / 크다 | `hp < 10` |
| `<=` `>=` | 작거나 같다 / 크거나 같다 | `hp <= 0` |

> ### ⚠️ `==` 와 `=` 를 혼동하면 조용히 망가진다
>
> ```c
> if (hp = 0)     // ✘ hp에 0을 "대입"하고, 그 결과 0(거짓)을 조건으로 씀
> if (hp == 0)    // ✔ hp가 0과 "같은지" 비교
> ```
>
> `if (hp = 0)`은 **문법 오류가 아니다.** 컴파일도 되고 실행도 된다.
> 다만 HP를 0으로 만들어 버리고 조건은 항상 거짓이 된다. 찾기 매우 어려운 버그다.
>
> ```
>  hp = 0   →  대입 → 결과값 0  →  0은 거짓  →  if 블록 실행 안 됨 + hp 파괴
>  hp = 5   →  대입 → 결과값 5  →  0이 아니면 참 → if 블록 항상 실행 + hp 파괴
> ```

**논리 연산자** — 조건을 조합한다

| 연산자 | 뜻 | 예 | 결과 |
|:--:|---|---|---|
| `&&` | 그리고 (AND) | `hp > 0 && mp >= 10` | 둘 다 참일 때만 참 |
| `\|\|` | 또는 (OR) | `hp <= 0 \|\| turn > 30` | 하나라도 참이면 참 |
| `!` | 아니다 (NOT) | `!isDead` | 참↔거짓 뒤집기 |

**진리표**

| A | B | `A && B` | `A \|\| B` | `!A` |
|:--:|:--:|:--:|:--:|:--:|
| 참 | 참 | 참 | 참 | 거짓 |
| 참 | 거짓 | 거짓 | 참 | 거짓 |
| 거짓 | 참 | 거짓 | 참 | 참 |
| 거짓 | 거짓 | 거짓 | 거짓 | 참 |

**C에서의 참과 거짓**

```
   0        →  거짓
   0이 아닌 모든 값  →  참    (1도 참, -5도 참, 100도 참)
```

### 3-4. `switch` — 값에 따른 분기

**왜 필요한가** — 메뉴 선택처럼 "값이 1이면 A, 2면 B, 3이면 C"를 깔끔하게 쓴다.

```c
switch (choice)
{
case 1:
    printf("공격\n");
    break;              // ★ 없으면 아래로 줄줄 흘러내린다
case 2:
    printf("방어\n");
    break;
case 3:
    printf("도망\n");
    break;
default:
    printf("잘못된 선택\n");
    break;
}
```

> ### ⚠️ `break`를 빼먹으면 아래 case까지 다 실행된다 (fall-through)
>
> ```
>   break 있음                     break 없음
>   case 1: 공격  ─ break ─▶ 끝    case 1: 공격
>   case 2: 방어                   case 2: 방어   ← 여기까지 실행!
>   case 3: 도망                   case 3: 도망   ← 여기까지 실행!!
> ```
>
> 의도한 fall-through라면 주석으로 명시한다. 대부분은 실수다.

**`if`와 `switch` 중 무엇을 쓸까**

| 상황 | 선택 |
|---|---|
| 값이 딱 떨어지는 몇 가지 (메뉴, 키 코드, 상태) | `switch` |
| 범위 비교 (`hp < 30`), 복합 조건 (`&&`, `\|\|`) | `if` |

`switch`는 정수형(`int`, `char`, `enum`)만 쓸 수 있다. 실수나 범위 비교는 불가.

### 3-5. 값 보정 — 하한과 상한

**왜 필요한가** — HP가 음수가 되거나 최대치를 넘으면 표시도 계산도 다 망가진다.

```c
if (slimeHp < 0)  slimeHp = 0;                    // 하한
if (heroHp > MAX_HERO_HP) heroHp = MAX_HERO_HP;   // 상한 (회복 시)

if (realDamage < 1) realDamage = 1;               // 최소 데미지 보장
```

```
   보정 없음:  HP  6 - 9 = -3   →  "HP -3"  화면이 이상해진다
   보정 있음:  HP  6 - 9 = -3   →  0으로 보정  →  "HP 0"  ✔
```

> 이 패턴을 **클램프(clamp)** 라고 한다. 24주 내내 쓴다.
> 좌표를 화면 안에 가두기(Day 14), 체력바 길이 계산(오늘), 볼륨 조절, 파워 게이지…

## 4. 따라 만들기

### Step 1 — 최소 데미지 보장

```c
    int realDamage = damage - SLIME_DEF;

    if (realDamage < 1)        // ← 추가
    {
        realDamage = 1;
    }
```

**✅ 여기까지 실행하면** — 공격력 1을 넣어도 데미지가 `-2`가 아니라 `1`이 된다. HP가 올라가지 않는다.

### Step 2 — HP 하한 보정과 승리 판정

```c
    slimeHp -= realDamage;

    if (slimeHp < 0)               // ← 추가
    {
        slimeHp = 0;
    }

    printf("슬라임 HP %3d → %3d\n", beforeHp, slimeHp);

    if (slimeHp <= 0)                              // ← 추가
    {
        printf("\n슬라임을 쓰러뜨렸다!\n");
        printf("\n        *** 승  리 ***\n");
    }
```

**✅ 여기까지 실행하면** — 공격력 40을 넣으면 HP가 `0`으로 표시되고 승리 메시지가 나온다.

### Step 3 — 체력 비율에 따른 상태 표시

```c
    int ratio = slimeHp * 100 / MAX_SLIME_HP;   // ← 추가 (% 계산)

    printf("슬라임 HP %3d → %3d   ", beforeHp, slimeHp);

    if (ratio <= 0)                              // ← 추가
        printf("전투불능\n");
    else if (ratio <= 30)                        // ← 좁은 조건부터!
        printf("빈사\n");
    else if (ratio <= 60)
        printf("위험\n");
    else
        printf("여유\n");
```

> `slimeHp * 100 / MAX_SLIME_HP` — **곱하기를 먼저** 한다.
> `slimeHp / MAX_SLIME_HP * 100`으로 쓰면 정수 나눗셈 때문에 항상 `0`이 된다. (Day 2)

**✅ 여기까지 실행하면** — HP를 깎을 때마다 `여유` → `위험` → `빈사` 로 상태 표시가 바뀐다.

### Step 4 — 행동 선택 메뉴 (`switch`)

```c
    printf("\n무엇을 하시겠습니까?\n");
    printf("  1. 공격   2. 방어   3. 도망\n");
    printf("선택: ");

    int choice = 0;
    scanf_s("%d", &choice);

    switch (choice)
    {
    case 1:
        printf("\n용사의 공격!\n");
        // (Step 1~3의 공격 처리 코드를 여기로)
        break;

    case 2:
        printf("\n용사는 방어 태세를 취했다. (받는 데미지 절반)\n");
        break;

    case 3:
        printf("\n용사는 도망쳤다!\n");
        break;

    default:
        printf("\n그런 행동은 할 수 없다.\n");
        break;
    }
```

**✅ 여기까지 실행하면** — 1/2/3을 고르면 각각 다른 메시지가 나오고, 9를 넣으면 "그런 행동은 할 수 없다"가 뜬다.

### Step 5 — 반격과 패배 판정

```c
    // 공격 처리 후, 슬라임이 살아 있으면 반격
    if (slimeHp > 0)                              // ← 추가
    {
        int counterDamage = SLIME_ATK;

        if (choice == 2)                          // 방어 중이면 절반
        {
            counterDamage /= 2;
            if (counterDamage < 1) counterDamage = 1;
        }

        int heroBefore = heroHp;
        heroHp -= counterDamage;
        if (heroHp < 0) heroHp = 0;

        printf("\n슬라임의 반격!  용사에게 %d 데미지\n", counterDamage);
        printf("용사   HP %3d → %3d\n", heroBefore, heroHp);

        if (heroHp <= 0)
        {
            printf("\n용사는 쓰러졌다...\n");
            printf("\n        *** 패  배 ***\n");
        }
    }
```

**✅ 여기까지 실행하면** — 1절의 완성 화면이 나온다. 공격하면 반격이 오고, 방어를 고르면 반격 데미지가 절반이 된다.

## 6. 자주 막히는 곳

| 증상 | 원인 | 해결 |
|---|---|---|
| 조건문이 항상 실행되거나 항상 안 됨 | `if (hp = 0)` — **`=`와 `==` 혼동** | `==` 로 수정 |
| `else if` 뒤쪽이 절대 실행 안 됨 | 넓은 조건이 앞에 있음 | **좁은 조건부터** 배치 |
| `switch`에서 모든 case가 실행됨 | **`break` 누락** | 각 case 끝에 `break;` |
| 비율이 항상 0 | `hp / max * 100` — 정수 나눗셈 | `hp * 100 / max` |
| `switch`에 실수를 넣으면 오류 | `switch`는 정수형만 | `if`로 바꾸기 |
| 조건이 복잡해서 뭐가 뭔지 모름 | 괄호 부족 | `(a > 0) && (b > 0)` 처럼 명시적으로 |
| `default`가 안 걸림 | `default`도 `break` 필요 | 추가 |
| 승리했는데 반격이 옴 | 판정 순서 문제 | 반격 전에 `if (slimeHp > 0)` 검사 |

## 7. 정리

### 오늘 배운 것

| 개념 | 한 줄 요약 |
|---|---|
| `if` / `else if` / `else` | 값을 보고 갈림길을 만든다. **좁은 조건부터** |
| `==` vs `=` | 비교는 `==`. `=`는 대입이라 조용히 망가진다 |
| 논리 연산자 | `&&`(둘 다) `\|\|`(하나라도) `!`(뒤집기) |
| `switch` | 값이 딱 떨어질 때. **`break` 필수** |
| 참/거짓 | C에서 0은 거짓, 0이 아니면 전부 참 |
| 클램프 | 값을 범위 안으로 가두기. 앞으로 계속 쓴다 |

### 직접 해보기

| 난이도 | 과제 | 힌트 |
|:--:|---|---|
| ★ | 도망(3)을 고르면 30% 확률로만 성공하게 (지금은 항상 성공) | 확률은 Day 16. 지금은 "공격력이 짝수면 성공" 같은 규칙으로 대체 |
| ★★ | 크리티컬 — 특정 조건에서 데미지 2배 | `if (조건) realDamage *= 2;` |
| ★★★ | 슬라임이 빈사(30% 이하)가 되면 반격 데미지가 1.5배로 오르게 | `counterDamage = counterDamage * 3 / 2;` |
