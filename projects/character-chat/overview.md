![인트로 화면 — 대표 캐릭터 민소양](/projects/character-chat/img/intro.webp)

## 1. 한 줄 요약

**CharacterChat**은 브라우저에서 여는 비주얼 노벨 화면 위에서, 사용자의 PC에서 돌아가는 LLM과 캐릭터 대화를 나누는 게임이다. 캐릭터가 말할 때마다 LLM이 대사와 함께 **포즈·배경·옷차림·호감도 변화**를 직접 골라 화면에 반영하고, 대화가 쌓이면 관계 단계가 "어색함"에서 "연인"까지 올라간다.

| 항목 | 내용 |
|---|---|
| 장르 | 연애 시뮬레이션 · 비주얼 노벨형 AI 캐릭터 대화 |
| 플랫폼 | 데스크톱 브라우저 (최신 Chrome / Edge) |
| 실행 방식 | 정적 웹앱 + 사용자 PC의 로컬 LLM 서버 (OpenAI 호환 API) |
| 캐릭터 | 3명 — 민소양(대표, 그림 260장), 윤하나·서지안(대사 전용) |
| 상태 | 개발 중 (개인 프로젝트) |

## 2. 왜 만들었나

기존 클라우드형 캐릭터 채팅에는 세 가지 아쉬움이 있었다.

1. **대화가 외부 서버로 간다.** 사적인 이야기를 나눌수록 부담이 커진다. 요금·검열·서비스 종료 위험도 따라온다.
2. **텍스트만 오간다.** 글자만 주고받는 채팅은 몰입이 약하다. 비주얼 노벨처럼 캐릭터의 모습이 대사에 맞춰 바뀌면 훨씬 생생해진다.
3. **관계가 쌓이지 않는다.** 대화를 닫으면 캐릭터가 나를 잊거나, 몇 마디 만에 친밀도가 끝까지 올라가 버린다.

그래서 목표를 이렇게 잡았다.

| 목표 | 기준 |
|---|---|
| 로컬에서만 동작 | LLM이 로컬이면 대화 데이터가 PC 밖으로 나가지 않는다 |
| 대사에 맞는 연출 | 감정·행동에 맞는 포즈가 자동으로 바뀐다 |
| 관계가 쌓이는 느낌 | 새로고침·재시작 뒤에도 대화·호감도·기억이 이어진다 |
| 체감 속도 | 스트리밍으로 첫 글자가 바로 타이핑되기 시작한다 |

## 3. 누구를 위해

- **주 사용자**: 자기 PC에 LM Studio·KoboldCpp·Ollama 같은 로컬 LLM 런타임을 띄워 본 캐릭터 채팅 애호가.
- **부 사용자**: 자기 캐릭터(설정 + 그림)를 넣어 보고 싶은 창작자. 캐릭터 하나는 폴더 하나(`card.json`·`poses.json`·`backgrounds.json`)이고, 그림이 없어도 대사만으로 동작한다.

## 4. 핵심 기능

| 기능 | 설명 |
|---|---|
| 비주얼 노벨 화면 | 배경 위에 캐릭터 전신 그림, 아래에 이름과 대사 박스. 대사는 타이핑 효과로 나오고 클릭·Space로 건너뛴다 |
| LLM이 연출까지 고른다 | 응답은 JSON 하나 — 대사, 포즈 ID, 배경 ID, 옷차림, 호감도 변화(-2~+2), 사건, 속마음 메모 |
| 포즈·배경·옷차림 | 포즈 260장(평상복·머리 푼 차림·운동복), 배경 60장. 두 장을 번갈아 쓰는 크로스페이드로 전환 |
| 호감도 5단계 | 어색함 → 친구 → 호감 → 설렘 → 연인. 단계마다 말투 지시가 바뀌고, 고호감 포즈·배경이 해금된다 |
| 기억 | 의미 있는 사건은 "이야기 로그", 사용자에 대해 알게 된 것은 캐릭터 1인칭 "메모"로 쌓여 다음 대화에 들어간다 |
| 공략 완료 | 처음 연인 단계에 오르면 그동안의 사건·메모를 캐릭터 회상 한 단락으로 정리해 장기 기억으로 쓴다 |
| 현실 시간 연동 | 지금 시각·요일·실제 날씨·캐릭터 일정을 안다. 오랜만에 돌아오면 캐릭터가 먼저 말을 건다 |
| 음성 (선택) | 로컬 Whisper 서버로 음성 입력, GPT-SoVITS 서버로 캐릭터 음성 출력 |

## 5. 화면 흐름

```text
인트로(대표 캐릭터) → 캐릭터 선택 → 이름 입력(첫 방문만)
  → 대화 화면 ─┬─ 입력 → 스트리밍 대사 + 포즈·배경 전환 + 호감도
               ├─ ▶ 혼잣말: 사용자 없이 캐릭터가 혼자 다음 장면을 잇는다
               ├─ ↻ 재생성: 마지막 응답과 그 호감도 변화를 되돌리고 다시 생성
               └─ 상단 바: 설정 · 내 정보 · 대화 로그 · 이야기 로그 · 캐릭터의 메모 · 저장 관리
```

## 6. 대표 캐릭터 — 민소양

동네 댄스 스튜디오의 걸스힙합·코레오 강사(26세). 사용자는 한 달 전 저녁 초급반에 등록한 수강생이다.

- 겉으로는 장난기 많은 누나지만, 진심 어린 칭찬을 들으면 말이 꼬인다.
- 배우 출신이고 수학과 수석 졸업생이라는 과거가 있지만 쉽게 털어놓지 않는다. 이 과거는 호감도 단계에 따라 단계적으로 열리는 `lore` 14개로 나뉘어 있다.
- 요일·시간별 일정(새벽 연습, 수업, 휴식)이 있어, 수업 중에 말을 걸면 짧게 답하고 늦은 밤에는 일찍 자라고 잔소리한다.

![한강 노을 — 운동복으로 갈아입은 장면, 설렘 단계](/projects/character-chat/img/play-hangang.webp)

## 7. 눈여겨볼 점

- **분류 모델 없이 LLM이 직접 연출을 고른다.** 프롬프트에 "포즈 ID: 설명" 목록을 주고, JSON 스키마의 `enum`으로 지금 고를 수 있는 ID만 허용한다. 존재하지 않는 ID가 와도 직전 포즈를 유지한다.
- **옷이 대사마다 바뀌지 않는다.** 지금 입은 옷의 포즈만 후보로 주고, LLM이 `outfit`을 적은 턴에만 갈아입는다.
- **관계는 되돌릴 수 없다.** 수동 저장 슬롯과 대화 되감기를 일부러 뺐다. 되돌릴 수 있으면 관계의 무게가 사라지기 때문이다. 대신 "처음부터"는 있고, 공략 기록은 초기화해도 남는다.
- **빌드도, 패키지도 없다.** 바닐라 HTML·CSS와 JS 모듈 5개(약 680줄)로 돌아간다. `index.html`을 정적 서버로 열면 끝이다.

> 스크린샷의 대화 장면은 화면 구성을 보여 주기 위해 예시 저장 데이터를 넣어 찍었다. 실제 대사는 연결한 LLM이 그때그때 만든다.
