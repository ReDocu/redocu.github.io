## ② 왜 필요한가

**SQL은 실기에서 매회 출제되는, 준비한 만큼 그대로 점수가 되는 영역입니다.** 그리고 모든 SQL의 8할은 결국 SELECT입니다 — JOIN도 서브쿼리도 집계도 SELECT라는 뼈대 위에 얹히는 살입니다. 오늘 WHERE의 조건 연산자들을 어설프게 넘기면, 9강의 JOIN 문제에서 "조인은 맞았는데 조건에서 틀리는" 일이 반복됩니다.

키와 무결성은 코드 없이도 나오는 **이론 단답 빈출 지점**입니다. "각 행을 유일하게 식별하며 NULL이 될 수 없는 키는?" 같은 문제는 용어를 정확한 철자로 쓰기만 하면 되는 공짜 점수입니다.

오늘 만드는 **공용 예제 스키마는 이후 모든 SQL 수업·중간평가·모의고사에서 재사용**됩니다. 학교(학과-학생-과목-수강)라는 익숙한 구조라, 문제를 읽는 시간이 갈수록 줄어드는 투자입니다.

**시험에서의 중요도와 출제 형태** — SQL 작성형(질의를 직접 쓰기), 결과 예측형(질의를 주고 결과 행 쓰기), 빈칸형(키워드 채우기), 이론 단답(키·무결성·용어). 내일이 아니라 **다음 강(08강) 중간평가에 오늘 범위가 바로 포함**됩니다.

## ③ 개념 설명

### 3-1. 관계형 데이터베이스의 용어

관계형 데이터베이스는 데이터를 **표(릴레이션)** 로 관리합니다. 같은 대상을 부르는 이름이 세 벌이라 표로 정리합니다.

📌 **반드시 암기 (단답 빈출)**

| 일상 용어 | 관계형 모델 용어 | 파일 시스템 용어 |
|---|---|---|
| 표 | **릴레이션(relation)** | 파일 |
| 행 | **튜플(tuple)** | 레코드 |
| 열 | **속성(attribute)** | 필드 |

| 용어 | 뜻 | 아래 STUDENT의 값 |
|---|---|---|
| **차수(degree)** | 속성(열)의 개수 | 4 |
| **카디널리티(cardinality)** | 튜플(행)의 개수 | 5 |
| **도메인(domain)** | 한 속성이 가질 수 있는 값의 범위 | 학년의 도메인 = 1~4의 정수 |

### 3-2. 키(Key) 5종

📌 **반드시 암기 (표째)** — "유일성 = 서로 구별됨, 최소성 = 꼭 필요한 속성만"

| 키 | 정의 | STUDENT에서의 예 |
|---|---|---|
| 슈퍼키 | **유일성**만 만족하는 속성 집합 | (학번), (학번, 이름) 등 학번이 끼면 전부 |
| 후보키 | 유일성 + **최소성** 만족 | 학번 |
| **기본키** | 후보키 중 대표로 **선정**한 키 — NULL 불가·중복 불가 | 학번 |
| 대체키 | 기본키로 뽑히지 못한 나머지 후보키 | (주민등록번호 속성이 있다면 그것) |
| **외래키** | 다른 릴레이션의 기본키를 **참조**하는 속성 | STUDENT.학과코드 → DEPT.학과코드 |

⚖️ **혼동 주의** — 슈퍼키 ⊇ 후보키 ⊇ 기본키의 포함 관계입니다. "(학번, 이름)"은 유일하지만 이름이 군더더기라 **최소성 위반 → 후보키가 아니라 슈퍼키**. 이 판정이 단골 문제입니다.

### 3-3. 무결성 제약조건 3종

📌 **반드시 암기**

| 무결성 | 내용 | 예 |
|---|---|---|
| **개체 무결성** | 기본키는 NULL·중복 불가 | 학번 없는 학생 행은 못 넣음 |
| **참조 무결성** | 외래키는 참조하는 기본키에 실제로 있는 값이거나 **NULL** | 학과코드에 'D9'(없는 학과)는 불가, NULL은 가능 |
| 도메인 무결성 | 속성 값은 정의된 도메인(자료형·범위) 안의 값 | 학년에 '가'는 불가 |

"외래키는 NULL이 될 수 **있다**"는 것이 함정 포인트 — 아래 스키마의 정유진(학과 미정)이 바로 그 사례입니다.

### 3-4. 과정 공용 예제 스키마 — 이후 모든 SQL 문제의 무대

화살표는 외래키 → 기본키 참조입니다. **이 4개 표는 안 보고 그릴 수 있을 때까지 암기합니다.**

```
DEPT(학과)                    STUDENT(학생)
┌────────┬──────────┬──────┐  ┌──────┬────────┬─────┬──────────┐
│학과코드*│ 학과명    │ 위치 │  │학번* │ 이름   │학년 │학과코드FK│──▶ DEPT
├────────┼──────────┼──────┤  ├──────┼────────┼─────┼──────────┤
│ D1     │컴퓨터공학 │공학관│  │ 1001 │ 김하늘 │  1  │ D1       │
│ D2     │경영학    │상경관│  │ 1002 │ 이준호 │  2  │ D1       │
│ D3     │디자인    │예술관│  │ 1003 │ 박서연 │  2  │ D2       │
└────────┴──────────┴──────┘  │ 1004 │ 최민수 │  3  │ D2       │
                              │ 1005 │ 정유진 │  3  │ NULL     │
                              └──────┴────────┴─────┴──────────┘
COURSE(과목)                  ENROLL(수강)  * 기본키 = (학번, 과목코드) 복합키
┌────────┬────────────┬────┐  ┌──────┬────────┬──────┐
│과목코드*│ 과목명      │학점│  │학번FK│과목코드FK│ 성적 │
├────────┼────────────┼────┤  ├──────┼────────┼──────┤
│ C1     │데이터베이스 │ 3  │  │ 1001 │ C1     │  90  │

                              └──────┴────────┴──────┘
```

일부러 심어 둔 **함정 데이터** 3곳 — ①정유진의 학과코드 NULL(참조 무결성·IS NULL·OUTER JOIN용) ②최민수의 성적 NULL(미채점 — 집계 함수의 NULL 무시용) ③수강생이 없는 C4 색채학(OUTER JOIN·서브쿼리용). 앞으로 이 세 곳에서 문제가 계속 나옵니다.

### 3-5. SELECT의 조건 도구들

| 도구 | 문법 | 뜻 |
|---|---|---|
| 비교 | `= <> < <= > >=` | ⚖️ "같지 않다"는 표준 SQL로 **`<>`** (`!=`는 다수 DBMS가 허용하는 비표준) |
| 논리 | `AND OR NOT` | 코드의 `&& \|\| !`에 대응 |
| `LIKE` | `이름 LIKE '김%'` | 패턴 일치 — **`%` = 0글자 이상 아무거나, `_` = 정확히 1글자** 📌 |
| `BETWEEN a AND b` | `학번 BETWEEN 1002 AND 1004` | a 이상 b 이하 — **양 끝 포함** 📌 |
| `IN (목록)` | `학년 IN (1, 3)` | 목록 중 하나와 일치 (= OR의 줄임) |
| `IS NULL` | `학과코드 IS NULL` | NULL 판정 — **`= NULL`은 항상 실패** 📌 (⑤ 참고) |
| `ORDER BY` | `ORDER BY 학년 DESC, 이름` | 정렬 — 기본은 오름차순(**ASC**), 내림차순은 DESC |
| `DISTINCT` | `SELECT DISTINCT 학년` | 결과의 중복 행 제거 |

### Step 3. SELECT와 WHERE — 열 고르기, 행 거르기

**사용 테이블: STUDENT · 난이도: 🟢 입문 · 학습 개념: SELECT-FROM-WHERE, AND**

> 문제: 2학년 이상이면서 경영학과(D2)인 학생의 이름과 학년을 조회하시오.

```sql
SELECT 이름, 학년
FROM   STUDENT
WHERE  학년 >= 2 AND 학과코드 = 'D2';
```

**예상 결과**

| 이름 | 학년 |
|---|---|
| 박서연 | 2 |
| 최민수 | 3 |

실행 원리: FROM(STUDENT를 편다) → WHERE(두 조건을 **모두** 만족하는 행만 — AND) → SELECT(이름·학년 열만). 정유진은 학년은 3이지만 학과코드가 NULL이라 `= 'D2'` 판정을 통과하지 못합니다.

### Step 4. ORDER BY와 DISTINCT

**사용 테이블: STUDENT · 난이도: 🟡 기본 · 학습 개념: 다중 정렬 기준**

> 문제: 전체 학생을 학년 내림차순, 같은 학년끼리는 이름 오름차순으로 조회하시오.

```sql
SELECT 이름, 학년
FROM   STUDENT
ORDER BY 학년 DESC, 이름 ASC;
```

**예상 결과**

| 이름 | 학년 |
|---|---|
| 정유진 | 3 |
| 최민수 | 3 |
| 박서연 | 2 |
| 이준호 | 2 |
| 김하늘 | 1 |

실행 원리: 첫 기준(학년 DESC)으로 큰 줄을 세우고, **동점자만** 둘째 기준(이름 ASC — 가나다순)으로 세웁니다. ASC는 기본값이라 생략 가능하지만, 시험 답안에서는 써 주는 편이 안전합니다.

**사용 테이블: STUDENT · 난이도: 🟢 입문 · 학습 개념: DISTINCT**

```sql
SELECT DISTINCT 학년 FROM STUDENT;
```

| 학년 |
|---|
| 1 |
| 2 |
| 3 |

5행이 아니라 **3행** — 중복(2학년 2명, 3학년 2명)이 제거됩니다. 문제 지문에 "중복 없이"가 보이면 DISTINCT가 정답 키워드입니다(누락 시 오답 처리 기준 — [로드맵 7절](../../curriculum/README.md)).

### Step 5. LIKE·BETWEEN·IN — 패턴과 범위

**사용 테이블: STUDENT · 난이도: 🟡 기본 · 학습 개념: 와일드카드 `%`와 `_`**

> 문제: 성이 '김'인 학생을 조회하시오.

```sql
SELECT * FROM STUDENT WHERE 이름 LIKE '김%';
```

| 학번 | 이름 | 학년 | 학과코드 |
|---|---|---|---|
| 1001 | 김하늘 | 1 | D1 |

- `'김%'` = 김으로 시작(뒤는 0글자 이상 아무거나), `'%수'` = 수로 끝남(→ 최민수), `'_준%'` = **둘째 글자**가 준(→ 이준호).
- **대표 오답**: `WHERE 이름 = '김%'` — `=`는 문자 그대로 "김%"라는 이름을 찾으므로 0행. 패턴 일치는 반드시 LIKE.

**사용 테이블: STUDENT · 난이도: 🟡 기본 · 학습 개념: BETWEEN 양 끝 포함, IN**

```sql
SELECT 이름 FROM STUDENT WHERE 학번 BETWEEN 1002 AND 1004;
```

| 이름 |
|---|
| 이준호 |
| 박서연 |
| 최민수 |

**1002와 1004도 포함**(이상~이하)입니다. "미만"이라고 착각하면 행 수가 달라집니다.

```sql
SELECT 이름 FROM STUDENT WHERE 학년 IN (1, 3);
```

| 이름 |
|---|
| 김하늘 |
| 최민수 |
| 정유진 |

`IN (1, 3)`은 `학년 = 1 OR 학년 = 3`의 줄임입니다. 빈칸 문제에서 OR 나열 ↔ IN 상호 변환이 출제됩니다.

### Step 6. NULL 함정 — `=`가 통하지 않는 값

**사용 테이블: STUDENT · 난이도: 🟡 기본 · 학습 개념: IS NULL**

> 문제: 학과가 아직 정해지지 않은 학생을 조회하시오.

```sql
-- 대표 오답 (0행 반환 — 에러도 안 남)
SELECT 이름 FROM STUDENT WHERE 학과코드 = NULL;

-- 정답
SELECT 이름 FROM STUDENT WHERE 학과코드 IS NULL;
```

| 이름 |
|---|
| 정유진 |

실행 원리: NULL은 '값이 없음(알 수 없음)'이라는 **상태**라서 `= NULL`, `<> NULL` 같은 비교의 결과도 '알 수 없음'이 되어 어떤 행도 참이 되지 못합니다. NULL 판정은 오직 **IS NULL / IS NOT NULL**. 에러가 나지 않고 조용히 0행이 나오기 때문에 오류 찾기 유형의 단골입니다.

## ⑤ 자주 하는 실수

| 에러/증상 원문 | 원인 | 해결 |
|---|---|---|
| `Parse error: near "SELCET": syntax error` | 키워드 오타 (SELCET·FORM·WHRE 등) | 필답형에서는 **철자 자체가 채점 대상** — SELECT·FROM·WHERE를 손으로 반복해서 써 볼 것 |
| `Parse error: no such column: 김하늘` | `WHERE 이름 = 김하늘` — 따옴표 누락으로 열 이름 취급 | 문자값은 작은따옴표 `'김하늘'` ([02강](../../lessons/01-foundation/lesson-02.md)의 재등장 — 반복되는 실수) |
| `Parse error: no such table: STUDNET` | 테이블 이름 오타 | 스키마 그림을 먼저 그리고 시작하는 습관 |
| `= NULL`이 0행 (에러 없음) | NULL은 비교 연산 불가 상태 | `IS NULL` / `IS NOT NULL` — 최빈출 함정 |
| BETWEEN 결과가 예상보다 많음/적음 | 양 끝 포함(이상~이하)을 미만으로 착각 | "BETWEEN은 경계 포함"을 소리 내어 암기 |
| `LIKE '김_'`가 김하늘을 못 찾음 | `_`는 **정확히 1글자** — 김하늘은 김+2글자 | 글자 수 미정이면 `%`, 한 글자 고정이면 `_` |
| ORDER BY 결과가 반대 | 기본 정렬이 ASC(오름차순)임을 잊고 DESC 누락 | 내림차순 요구 지문("높은 순", "최근 순")에 DESC 확인 |
| `<>`와 `!=` 중 무엇을 쓸지 혼란 | 표준 SQL은 `<>` (`!=`는 비표준 허용 문법) | ⚖️ 시험 답안은 표준 `<>` 권장 |

## ⑥ 확인 문제

1. [이론 단답] STUDENT 릴레이션(3-4절 기준)의 차수와 카디널리티를 각각 쓰시오.
2. [SQL 작성] ENROLL 테이블에서 성적이 80 이상 90 이하인 행의 학번과 성적을, 성적 내림차순으로 조회하는 SQL을 쓰시오. (BETWEEN 사용)
3. [결과 예측] 다음 SQL의 결과 행 수와 그 이유를 쓰시오.
   ```sql
   SELECT 이름 FROM STUDENT WHERE 학과코드 <> 'D1';
   ```

<details>
<summary>정답과 해설</summary>

1. **차수 4, 카디널리티 5** — 차수 = 속성(열) 수(학번·이름·학년·학과코드), 카디널리티 = 튜플(행) 수.
   - 대표 오답: 반대로 쓰기. "차수는 열, **카**디널리티는 **행**(카·행 둘 다 거센소리)"처럼 자기만의 고리를 만들어 두세요.
2. 정답 쿼리:
   ```sql
   SELECT 학번, 성적
   FROM   ENROLL
   WHERE  성적 BETWEEN 80 AND 90
   ORDER BY 성적 DESC;
   ```
   결과: (1001, 90) → (1001, 85) → (1003, 80). 성적 NULL인 최민수 행은 BETWEEN 비교 자체가 '알 수 없음'이라 제외됩니다.
   - 대표 오답: `WHERE 성적 >= 80 AND 성적 <= 90` — 결과는 같지만 지문이 BETWEEN을 지정했으므로 요구 키워드 누락으로 감점 대상(채점 기준 참고).
3. **2행 (박서연, 최민수).** D1인 김하늘·이준호는 조건에서 제외되고, **정유진(NULL)은 `<> 'D1'` 비교 결과가 '알 수 없음'이라 역시 제외**됩니다.
   - 오답 원인: "D1이 아니니까 NULL도 포함해서 3행"— NULL은 `=`에도 `<>`에도 걸리지 않습니다. NULL까지 포함하려면 `WHERE 학과코드 <> 'D1' OR 학과코드 IS NULL`.

</details>

## 마무리

**오늘의 요약** — 표=릴레이션·행=튜플·열=속성, 열 수=차수·행 수=카디널리티입니다. 키는 슈퍼(유일성)⊇후보(+최소성)⊇기본(선정, NULL·중복 불가)이고 탈락자가 대체키, 남의 기본키를 참조하면 외래키(NULL 가능)입니다. WHERE의 도구는 LIKE(`%`/`_`)·BETWEEN(양 끝 포함)·IN(OR의 줄임)·IS NULL(`= NULL` 금지)이며, 공용 스키마의 함정 3곳(정유진 NULL 학과·최민수 NULL 성적·수강생 없는 C4)을 기억하세요.

- [ ] 키 5종 표를 안 보고 재현할 수 있다
