## ② 왜 필요한가

여러분의 MP3 API는 지금 어디에 있습니까 — 노트북 안입니다. 노트북은 덮으면 꺼지고, 집 밖에선
접속이 안 되고, 발표 때만 잠깐 켜지는 서비스입니다. 서비스가 **남의 컴퓨터(서버)에서 24시간**
돌아야 비로소 서비스인데, 그 서버들의 세계는 사실상 하나의 OS입니다 — 상용 서버·클라우드의
절대다수가 Linux이고, 여러분이 W07부터 쓴 Docker 컨테이너([Day 031](../02-sql-pipeline/day-031.md)의
PostgreSQL)의 속도 전부 Linux였습니다.

그리고 서버에는 마우스가 없습니다. 원격 서버에 접속하면 만나는 것은 커서 하나 깜빡이는
텍스트 화면 — **셸(shell)**이 유일한 대화 수단입니다:

```
접속 직후 여러분이 보는 전부:
deploy@mlops-server:~$ █

여기서 해야 하는 일:
코드 배포 · 로그 확인 · 서비스 재시작 · 디스크 점검 · 장애 조사
```

이번 주의 목표는 이 깜빡이는 커서 앞에서 **불안하지 않은 사람**이 되는 것입니다. 다행히
여러분은 맨손이 아닙니다 — PowerShell에서 3개월간 쓴 파이프와 명령 감각이 그대로 이식됩니다.
문법만 리눅스식으로 갈아 끼우면 됩니다.

## ③ 개념 설명

### WSL2 — 노트북 안의 진짜 리눅스 서버

WSL2(Windows Subsystem for Linux 2)는 Windows 안에서 **진짜 Linux 커널**을 경량 가상 머신으로
돌립니다. 흉내(호환 계층)가 아니라 실물이라서, 여기서 익힌 모든 것이 클라우드 서버에서 동일하게
동작합니다.

> **이번 주의 관점 전환** — 오늘부터 WSL2 Ubuntu를 "내 PC의 부속"이 아니라 **"원격 서버"**로
> 취급합니다. 파일을 GUI로 끌어다 놓고 싶은 유혹이 올 때마다 상기하세요: 진짜 서버였다면
> 그 방법은 없습니다. 서버에서 통하는 방법(명령)만 씁니다 — 그래야 W29의 진짜 클라우드
> 인스턴스 앞에서 몸이 기억합니다.

### 디렉터리 구조 — 모든 리눅스 서버의 공통 지도

Windows의 `C:\Program Files`, `C:\Users` 처럼 리눅스에도 표준 배치가 있습니다.
운영에서 실제로 드나드는 곳은 여섯 군데면 충분합니다:

| 경로 | 무엇이 사는가 | 이 과정에서 |
|---|---|---|
| `/home/<사용자>` | 사용자의 집 (`~`) | 작업·실험 공간 |
| `/etc` | **설정 파일** 전부 | ssh 설정(Day 114) · nginx 설정(Day 124) |
| `/var/log` | **로그** | 오늘 오후의 사냥터 · 장애 조사의 출발점 |
| `/opt` | 직접 설치한 서비스 | **MP3 API가 살 집** (Day 113) |
| `/tmp` | 임시 파일 (재부팅 시 소멸) | 실험용 |
| `/usr/bin` 등 | 설치된 프로그램 본체 | `which python3` 의 답 |

이 지도의 힘은 **모든 리눅스 서버에서 같다**는 데 있습니다. 처음 접속한 서버에서도
"설정은 /etc, 로그는 /var/log"부터 뒤지면 됩니다.

### 필수 명령 12 — PowerShell 대응표와 함께

| 하는 일 | Linux | PowerShell에서 쓰던 것 |
|---|---|---|
| 현재 위치 / 이동 | `pwd` / `cd` | 동일 |
| 목록 (상세·숨김) | `ls -al` | `ls` (Get-ChildItem) |
| 복사 / 이동·이름변경 / 삭제 | `cp` / `mv` / `rm` | cp / mv / rm (별칭 동일!) |
| 폴더 생성 | `mkdir -p a/b/c` | mkdir |
| 파일 내용 (전체/앞/뒤) | `cat` / `head` / `tail` | cat / `-TotalCount` / `-Tail` |
| 긴 파일 넘겨 보기 | `less` (q로 종료) | more |
| **줄 검색** | `grep "패턴" 파일` | Select-String |
| **파일 찾기** | `find 경로 -name "*.log"` | Get-ChildItem -Recurse |

PowerShell 별칭 덕분에 절반은 손이 이미 압니다. 결정적 차이 두 가지만 새로 새기면 됩니다:
**① 리눅스는 대소문자를 구분한다** (`Data.csv` ≠ `data.csv`) **② 경로 구분자는 `/`**.

### 파이프와 리다이렉션 — 작은 명령을 이어 큰 일을

PowerShell에서 석 달 내내 써 온 그 파이프의 원조가 여기입니다. 리눅스 명령은
전부 "텍스트 입력 → 텍스트 출력"이라서 레고처럼 이어집니다:

| 기호 | 뜻 | 예 |
|---|---|---|
| `\|` | 왼쪽의 출력을 오른쪽의 입력으로 | `cat api.log \| grep ERROR \| wc -l` |
| `>` | 출력을 파일로 (덮어쓰기) | `ls -al > snapshot.txt` |
| `>>` | 출력을 파일 **끝에 추가** | `echo "완료" >> run.log` |
| `2>` | **에러** 출력만 파일로 | `python3 app.py 2> error.log` |
| `2>&1` | 에러를 표준 출력에 합류 | `python3 app.py > all.log 2>&1` |

`2>` 가 낯설다면 — 리눅스 프로세스의 출력 통로는 표준 출력(1)과 표준 에러(2) 두 개입니다.
[Day 098](../04-deep-learning-serving/day-098.md)에서 로그를 stderr로 보낸 이유가 바로 이 분리
때문이었고, W25의 컨테이너 로그 수집도 이 두 통로를 그대로 씁니다.

## ④ 단계별 실습

### Step 1. 서버 개통 — WSL2 + Ubuntu 22.04 (1~2교시)

PowerShell(관리자)에서:

```powershell
wsl --install -d Ubuntu-22.04
```

재부팅 후 Ubuntu 창이 열리며 **서버의 첫 사용자**를 만듭니다 (사용자명은 소문자 —
문서는 `student` 기준). 설치가 끝나면 신원 확인:

```bash
lsb_release -d && uname -r
```

```
$ lsb_release -d && uname -r
Description:    Ubuntu 22.04.4 LTS
5.15.167.4-microsoft-standard-WSL2
```

커널 이름에 WSL2가 박혀 있지만 Ubuntu 22.04 LTS 실물입니다. 패키지 목록부터 최신화합니다
(새 서버 개통 후 1번 의식 — 내일 sudo를 배우며 뜻을 정확히 알게 됩니다):

```bash
sudo apt update && sudo apt upgrade -y
```

> 프롬프트 읽는 법 — `student@DESKTOP:~$` 는 "student 사용자가 DESKTOP 머신의 `~`(홈)에서
> 대기 중"입니다. **이 문서의 `$` 줄은 입력, 그 아래는 출력**이라는 규칙은 리눅스에서도 같습니다.

### Step 2. 지도 들고 탐험 (3교시)

③의 지도를 직접 밟습니다:

```bash
cd /
ls
ls /var/log
ls -al ~
```

```
$ ls
```


Windows의 C 드라이브가 `/mnt/c` 에 그대로 보입니다 — 파일을 가져올 때 편리하지만, **이 통로는
WSL2 특전이지 진짜 서버엔 없습니다.** 서버식 이동(scp)은 Day 114에서 배웁니다.

```bash
mkdir -p ~/lab/logs
```

사라집니다 (⑤ 참고). 이 감각이 리눅스 조심성의 절반입니다.

### Step 4. 로그 사냥 — 오늘 배운 전부의 조합 (6~7교시)

실전 재료를 만듭니다. MP3 API의 예측 로그([Day 098](../04-deep-learning-serving/day-098.md)의
JSON 형식)를 흉내 낸 5,000줄짜리 파일을 생성:

```bash
cd ~/lab/logs
python3 - <<'EOF'
import json, random
random.seed(42)
with open("api.log", "w") as f:
    for i in range(5000):
        level = random.choices(["INFO","WARNING","ERROR"], weights=[94,4,2])[0]
        rec = {"level": level, "path": random.choice(["/predict","/health","/model/info"]),
               "status": 500 if level=="ERROR" else 200,
               "latency_ms": round(random.lognormvariate(3.0, 0.4), 1)}
        f.write(json.dumps(rec) + "\n")
print("생성 완료")
EOF
wc -l api.log
```

```
$ wc -l api.log
5000 api.log
```

이제 운영자의 질문에 명령 조합으로 답합니다:

```bash
grep -c ERROR api.log                        # Q1. 에러가 몇 건인가
grep ERROR api.log | head -3                 # Q2. 에러 샘플을 보여 달라
grep ERROR api.log | grep -c "/predict"      # Q3. 그중 /predict 에서 난 것은
grep -v "/health" api.log | wc -l            # Q4. 헬스체크 소음을 빼면 몇 줄인가
tail -5 api.log                              # Q5. 방금 무슨 일 있었나 (최근 5건)
grep ERROR api.log > errors_today.log        # Q6. 에러만 추려 보고용 파일로
```

```
$ grep -c ERROR api.log
94
$ grep ERROR api.log | grep -c "/predict"
38
$ grep -v "/health" api.log | wc -l
3341
```

마지막으로 실시간 감시 — 두 번째 터미널을 열고(`wsl` 입력이면 새 접속) 한쪽에서
`tail -f api.log`, 다른 쪽에서 `echo '{"level":"ERROR","path":"/predict"}' >> api.log` —
추가하는 순간 감시 창에 나타납니다. **`tail -f` 는 장애 조사의 기본 자세**입니다
(Ctrl+C로 종료).

### Step 5. 과제 — 명령 조합 10문제 (8교시)

`api.log` 를 대상으로, 다음 질문에 답하는 **명령 한 줄씩**을 만들어 명령과 출력을 함께 제출하세요.

1. WARNING은 총 몇 건인가
2. ERROR 중 `/model/info` 에서 난 것은 몇 건인가
3. 마지막 20줄 중 ERROR만 보여라
4. ERROR와 WARNING을 **한 번에** 세라 (힌트: `grep -E "ERROR|WARNING"`)
5. `/predict` 요청만 추려 `predict.log` 로 저장하라
6. `predict.log` 의 줄 수를 확인하라
7. ERROR가 **없는** 줄만으로 `clean.log` 를 만들어라
8. `~/lab` 아래의 모든 `.log` 파일을 찾아라
9. 그 로그 파일들의 크기를 사람이 읽는 단위로 보여라 (힌트: `ls -alh`)
10. api.log의 8행~12행만 출력하라 (힌트: head와 tail의 파이프 조합)

각 문제에 한 줄 메모: **어느 명령이 어느 출력을 어느 입력으로 받았는가.**

## ⑤ 자주 하는 실수

### rm에 휴지통이 있을 거라는 믿음

**증상** — `rm -rf ~/lab` 후 "복구 어떻게 해요?" — 복구는 없습니다.
**원인** — Windows 탐색기의 휴지통 감각. `rm` 은 즉시 영구 삭제이고 `-rf` 는 "묻지도 말고
폴더째"입니다.
**해결** — 몸에 붙일 순서: 지우기 전 `ls` 로 대상 확인 → 와일드카드(`*`)와 `-rf` 조합은 경로를
**절대 경로로** 쓰고 한 박자 쉬고 Enter. 서버에서 `rm -rf` 오타는 경력이 끝나는 사고 유형입니다.

### Permission denied — 아직 배우지 않은 벽

**증상** —
```
$ echo "test" > /var/log/mine.log
-bash: /var/log/mine.log: Permission denied
```
**원인** — `/var/log` 는 시스템 영역이라 일반 사용자에게 쓰기 권한이 없습니다.
**해결** — 오늘은 홈(`~`) 아래에서만 작업하면 안 만납니다. 이 벽의 정체(소유자·권한·sudo)가
정확히 **내일 수업 전체**입니다 — 에러 문구를 기억해 두세요.

### Windows에서 만든 파일이 리눅스에서 이상하게 동작

**증상** — `/mnt/c` 로 가져온 스크립트 실행 시:
```
-bash: ./run.sh: /bin/bash^M: bad interpreter: No such file or directory
```
**원인** — Windows의 줄바꿈(CRLF)과 리눅스(LF)의 차이. `^M` 이 그 흔적입니다.
**해결** — `sudo apt install dos2unix` 후 `dos2unix run.sh`. 근본 대책은 Day 115에서 스크립트를
**처음부터 리눅스 안에서** 작성하는 것 — VS Code의 WSL 연동을 그때 세팅합니다.

### 대소문자 무시 습관

**증상** — `cat Api.log` → `No such file or directory` (파일은 `api.log`).
**원인** — Windows 파일 시스템은 대소문자를 구분하지 않아 생긴 습관.
**해결** — 리눅스에서 `Api.log` 와 `api.log` 는 **서로 다른 두 파일**입니다. Tab 자동완성을
쓰면(파일명 두세 글자 + Tab) 오타와 대소문자 사고가 동시에 사라집니다 — 자동완성은 편의가 아니라
정확성 도구입니다.

### grep 패턴을 따옴표 없이

**증상** — `grep {"level": "ERROR"} api.log` 가 이상한 에러를 내거나 아무거나 매칭.
**원인** — 공백·특수문자가 든 패턴을 따옴표 없이 쓰면 셸이 먼저 해석해 버립니다.
**해결** — 패턴은 습관적으로 따옴표로: `grep '"level": "ERROR"' api.log`. 셸이 해석하는
특수문자(`* $ " { }` 등)를 grep에게 온전히 전달하는 유일한 방법입니다.

(`grep ERROR 로그파일 | tail`). ② `/etc` (또는 서비스가 사는 `/opt`) — 설정이 최근 바뀌었는지,
서비스 설정 파일이 정상인지 확인합니다. "로그부터, 그다음 설정" — 모든 리눅스 서버에서 통하는
조사 순서이고, 표준 배치 덕분에 처음 보는 서버에서도 가능한 것입니다.

</details>

**Q2.** `cat api.log | grep ERROR | wc -l` 과 `grep -c ERROR api.log` 는 같은 답을 냅니다.
파이프 관점에서 두 명령의 데이터 흐름을 각각 설명하세요.

<details>
<summary>답 보기</summary>

전자: cat이 파일 전체를 표준 출력으로 → 파이프가 그것을 grep의 표준 입력으로 → grep이 ERROR 줄만
통과 → 파이프 → wc가 줄 수를 셈. 세 프로세스가 텍스트 스트림으로 연결된 조립 라인입니다.
후자: grep 혼자 파일을 직접 읽으며 매칭 줄을 세는(-c) 단일 프로세스. 결과는 같지만 후자가
프로세스 두 개만큼 가볍습니다 — 다만 파이프 조립(전자)은 중간 단계를 자유로 갈아 끼울 수 있어
탐색 단계에서 강력합니다.

</details>

**Q3.** `python3 train.py > train.log 2>&1` 에서 각 기호가 하는 일을 분해하고, 왜 학습
스크립트를 서버에서 돌릴 때 이 형태가 표준인지 설명하세요.

<details>
<summary>답 보기</summary>

`> train.log` 는 표준 출력(1)을 파일로 보내고, `2>&1` 은 표준 에러(2)를 "1이 가는 곳"에 합류시킵니다
— 결과적으로 정상 출력과 에러가 **한 파일에 시간 순으로** 남습니다. 서버 학습은 지켜보는 사람이
없으므로 출력을 파일로 남겨야 하고, 에러만 다른 곳에 가면 "왜 죽었는지"가 로그에서 빠집니다.
Day 115의 cron 정기 작업에서 이 형태가 그대로 필수가 됩니다.

</details>
