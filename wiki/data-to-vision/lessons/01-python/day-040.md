```
① 무엇을 만들었나      한 문장 + 스크린샷 + 기능 목록
② 어떻게 만들었나      구조도 + 핵심 기술 + 코드 일부
③ 막힌 지점과 해결     문제 → 원인 → 해결 (3개 이상)
④ 배운 것             기술적 배움 + 태도의 배움
⑤ 한계와 개선 방향     지금 부족한 것 + 다음에 할 것
```

> **③번이 가장 중요합니다.** 성공한 이야기보다 **막혔다가 해결한 이야기**가 실력을 보여 줍니다.

### 회고를 쓰는 요령

**❌ 추상적**

> "클래스가 어려웠지만 열심히 해서 이해했다."

**✅ 구체적**

> "총알 20개를 리스트로 관리하다가, 화면 밖 총알을 `for` 문 안에서 `remove()` 했더니
> 일부가 안 지워지는 버그가 났다. 순회 중 삭제 시 인덱스가 밀리는 문제였고,
> `pygame.sprite.Group` 과 `kill()` 로 바꿔 해결했다.
> 이후 "순회 중인 컨테이너를 수정하지 않는다"는 원칙을 갖게 됐다."

**차이 4가지**

| 항목 | 설명 |
|---|---|
| 상황이 구체적 | "총알 20개", "화면 밖" |
| 증상이 명확 | "일부가 안 지워지는" |
| 원인을 이해함 | "인덱스가 밀리는 문제" |
| 일반화된 교훈 | "순회 중 수정하지 않는다" |

## 4. 막힌 점과 해결 (1분)

### 문제: 3분쯤 플레이하면 FPS 가 20으로 떨어짐

- **증상** — 시간이 지날수록 게임이 느려짐
- **진단** — HUD 에 스프라이트 개수를 띄웠더니 2000개가 넘어감
- **원인** — 화면 밖으로 나간 총알이 제거되지 않고 계속 `update()` 됨
- **해결** — `update()` 안에서 화면 밖 판정 후 `self.kill()`

def update(self):
    self.pos_y += self.vel_y
    self.sync_rect()
    self.kill_if_out()          # ← 이 한 줄

- **교훈** — 만든 것은 반드시 지운다. 그리고 **문제는 추측하지 말고 측정한다.**

### 핵심 설계 ① — 상속으로 적 확장

부모 `Enemy` 가 `update()` 흐름(이동 → 위치 반영 → 화면 밖 제거)을 정하고,
자식은 `move()` 만 오버라이딩한다.

class Enemy(Entity):
    def update(self):
        self.move()              # 자식마다 다름
        self.sync_rect()         # 공통
        self.kill_if_out()       # 공통

    def move(self):
        self.pos_y += self.speed

class ZigzagEnemy(Enemy):
    def move(self):
        self.pos_y += self.speed
        self.pos_x += self.vel_x
        # 벽 반사...

덕분에 적을 4종류로 늘려도 게임 루프는 `self.all_sprites.update()` 한 줄 그대로다.
5번째 적을 추가할 때 게임 루프를 **한 글자도 고치지 않았다.**

### 핵심 설계 ② — DB 접근 계층 분리

게임 코드는 SQL 을 전혀 모른다. `db.py` 의 함수만 호출한다.

# scenes/manager.py
record_id, rank = db.save_score(name, score, kills=..., shots=...)

# db.py 안에서만 SQL 사용
with session() as conn:
    conn.execute("INSERT INTO scores (...) VALUES (?, ?, ...)", params)

테이블 구조를 두 번 바꿨는데, 그때마다 `db.py` 만 고치면 됐다.

## ③ 막힌 지점과 해결

### 문제 1 — 3분쯤 지나면 FPS 가 20으로 떨어짐

**증상**
시간이 지날수록 게임이 눈에 띄게 느려졌다. 처음엔 컴퓨터 성능 문제라고 생각했다.

**진단 과정**
HUD 에 디버그 정보를 띄웠다.

debug = [f"FPS {clock.get_fps():.0f}",
         f"스프라이트 {len(self.all_sprites)}"]

3분 뒤 스프라이트가 **2,400개**였다. 화면에는 20개도 안 보이는데.

**원인**
화면 위로 나간 총알이 제거되지 않고 계속 `update()` 되고 `draw()` 대상에 남아 있었다.
1초에 10발씩 나가는데 하나도 안 지워지니 당연했다.

**해결**

def update(self):
    self.pos_x += self.vel_x
    self.pos_y += self.vel_y
    self.sync_rect()
    self.kill_if_out()          # ← 이 한 줄

그리고 `kill_if_out()` 을 처음엔 위쪽만 검사하게 만들었다가,
확산탄이 좌우로 나가면서 또 쌓이는 것을 발견해 **네 방향을 모두** 검사하도록 고쳤다.

**교훈**
- 만든 것은 반드시 지운다.
- **성능 문제는 추측하지 말고 측정한다.** 화면에 숫자를 띄우니 5초 만에 원인을 찾았다.

### 문제 2 — 적에 스치면 목숨 3개가 순식간에 사라짐

**증상**
적과 겹치는 순간 게임 오버가 됐다. 처음엔 데미지 값이 너무 큰 줄 알았다.

**진단**
피해를 입을 때 로그를 찍었더니 **1초에 60번** 찍혔다.

**원인**
`spritecollide` 는 매 프레임 호출된다. 적과 겹쳐 있는 동안 계속 참이라
0.2초 만에 체력 100이 0이 되고, 부활하자마자 또 맞았다.

**해결**
무적 시간을 도입했다.

def take_damage(self, amount):
    if self.is_invincible:
        return False                     # 무적 중엔 무시
    self.hp -= amount
    self.invincible_timer = INVINCIBLE_FRAMES
    return True

부활 시에는 무적을 2배로 줬다. 부활 지점에 적이 있으면 즉사가 반복됐기 때문이다.

**교훈**
**매 프레임 실행되는 코드에서 상태를 바꿀 때는 "얼마나 자주 일어나야 하는가"를 먼저 생각한다.**
총알 발사(쿨타임), 적 스폰(간격), 피격(무적) — 전부 같은 문제였고 같은 해법(타이머)이었다.

### 문제 3 — 벽에 붙으면 반대 방향 키가 한동안 안 먹음

**증상**
왼쪽 벽에 대고 왼쪽 키를 3초간 누른 뒤 오른쪽을 누르면, 3초쯤 지나야 움직였다.

**원인**
`clamp_ip()` 는 `rect` 만 화면 안으로 되돌리는데, `float` 위치인 `pos_x` 는 그대로 -1000 같은 값이었다.
오른쪽 키를 눌러도 `pos_x` 가 -1000에서 6씩 늘어나 화면에 들어오기까지 시간이 걸렸다.

**해결**

def clamp_to_screen(self):
    self.rect.clamp_ip(screen_rect)
    self.pos_x = float(self.rect.centerx)     # ← 되돌린 값을 반영
    self.pos_y = float(self.rect.centery)

**교훈**
**같은 정보를 두 곳에 저장하면 반드시 어긋난다.**
`pos_x` 와 `rect.centerx` 는 같은 것을 나타내므로, 한쪽을 고치면 다른 쪽도 맞춰야 한다.
가능하면 계산할 수 있는 값은 저장하지 않는 편이 낫다.

### 문제 4 — 총알이 안 보이는데 움직이고는 있음

**증상**
발사는 되는데 화면에 아무것도 안 나왔다. 로그를 찍으면 총알 개수는 늘고 있었다.

**원인**
`self.bullets.add(bullet)` 만 하고 `self.all_sprites.add(bullet)` 을 빠뜨렸다.
`all_sprites.draw()` 대상이 아니라 그려지지 않았던 것.

**해결**

**교훈**
하나의 스프라이트가 여러 그룹에 속할 수 있고, **각 그룹의 목적이 다르다.**

`settings.py` 에 상수를 전부 모아서, 밸런스 조정은 이 파일 하나만 고치면 됩니다.

핵심은 두 가지입니다.

첫째, 적을 상속으로 만들었습니다.
부모가 `update()` 흐름을 정하고 자식은 `move()` 만 오버라이딩합니다.
그래서 적을 4종류로 늘렸는데 게임 루프는 `enemies.update()` 한 줄 그대로입니다.
5번째 적을 추가할 때 게임 루프를 한 글자도 안 고쳤습니다.

둘째, DB 접근을 `db.py` 하나로 모았습니다.
게임 코드는 SQL 을 전혀 모르고 `db.save_score()` 만 부릅니다.
개발 중에 테이블 구조를 두 번 바꿨는데, 그때마다 `db.py` 만 고치면 됐습니다."

## [4:00–4:50] 막힌 점

"가장 오래 붙잡았던 문제를 하나 말씀드리면,
3분쯤 플레이하면 FPS 가 60에서 20으로 떨어졌습니다.

처음엔 제 컴퓨터가 느린 줄 알았는데,
화면에 스프라이트 개수를 띄워 보니 2,400개였습니다.
화면에는 20개도 안 보이는데요.

원인은 화면 밖으로 나간 총알이 제거되지 않고
계속 갱신되고 그려지고 있었던 것이었습니다.
`update()` 안에 화면 밖 판정과 `kill()` 을 넣어서 해결했습니다.

여기서 배운 건 **성능 문제는 추측하지 말고 측정하자**는 것입니다.
숫자를 띄우니까 5초 만에 원인을 찾았습니다."

SELECT player_name, score, kills, stage, created_at FROM scores;

**이 데이터로 무엇을 알 수 있을까요?**

```python
import pandas as pd
import sqlite3

conn = sqlite3.connect("data/game.db")
df = pd.read_sql("SELECT * FROM scores", conn)

df.groupby("stage")["score"].mean().plot(kind="bar")
```
