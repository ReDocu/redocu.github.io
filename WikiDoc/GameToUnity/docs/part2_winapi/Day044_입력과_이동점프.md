## 1. 오늘 만드는 것

**캐릭터가 걷고, 점프하고, 착지한다.** 동작에 맞는 애니메이션이 자동으로 바뀐다.

```
   ┌──────────────────────────────────────────────────────────┐
   │  Movement                                        ─    ✕ │
   ├──────────────────────────────────────────────────────────┤
   │                                                          │
   │                       ██████                              │
   │                      ████████    ← 점프 중                │
   │                      ██    ██                             │
   │                     ███    ███                            │
   │                                                          │
   │                                                          │
   │  ──────────────────────────────────────────────────────  │
   │  ▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓ 바닥 ▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓  │
   │                                                          │
   │  pos (412.3, 380.0)   vel (180.0, -420.0)                │
   │  애니메이션  "jump"    바닥접촉  X    방향  →              │
   │  입력  ←□ →■ ↑■  점프잔여 1/2                             │
   │                                                          │
   │  [← →] 이동  [↑/SPACE] 점프  [Shift] 달리기               │
   └──────────────────────────────────────────────────────────┘
```

**조작** — 좌우 이동, 점프(이단 점프), Shift로 달리기.

## 2. 막히는 상황

어제까지 캐릭터는 제자리에서 애니메이션만 재생했다.

```cpp
    if (input.IsKeyDown('1')) m_animator.Play("idle");
    if (input.IsKeyDown('2')) m_animator.Play("walk");
```

**숫자 키로 애니메이션만 바꿀 뿐, 캐릭터가 움직이지 않는다.**

이동을 붙여 보면 문제가 줄줄이 나온다.

```cpp
    if (input.IsKeyPress(VK_RIGHT))
    {
        m_x += 200 * dt;
        m_animator.Play("walk");
    }
```

```
   ① 키를 떼도 걷기 애니메이션이 계속 나온다
   ② 왼쪽으로 가도 캐릭터가 오른쪽을 본다
   ③ 점프를 어떻게 만들지 모르겠다
   ④ 좌우 키를 동시에 누르면 이상하게 동작한다
   ⑤ 화면 밖으로 나간다
   ⑥ 다른 창을 쓰는데도 캐릭터가 움직인다
```

```
   지금:   입력과 이동과 애니메이션이 따로 논다

   필요:   입력  →  속도  →  위치  →  애니메이션
           이 흐름을 한 방향으로 정리한다
```

> **입력·물리·애니메이션을 연결하는 구조가 필요하다.**

## 3. 개념

### 3-1. 입력 → 속도 → 위치

**왜 필요한가** — 순서를 정하면 코드가 정리된다.

```
   ┌──────────────────────────────────────────────────────────┐
   │  ① 입력 읽기      "오른쪽 키가 눌려 있나?"                │
   │        ▼                                                  │
   │  ② 속도 결정      m_vx = +walkSpeed                       │
   │        ▼                                                  │
   │  ③ 물리 적용      m_vy += gravity * dt                    │
   │        ▼                                                  │
   │  ④ 위치 갱신      m_x += m_vx * dt                        │
   │        ▼                                                  │
   │  ⑤ 충돌 처리      바닥 판정, 화면 경계                     │
   │        ▼                                                  │
   │  ⑥ 애니메이션     상태를 보고 클립 선택                    │
   └──────────────────────────────────────────────────────────┘

   ★ 애니메이션은 마지막이다
     "무엇을 하고 있는가"가 정해진 뒤에 그에 맞는 그림을 고른다
```

> **애니메이션을 입력에서 바로 결정하면 안 된다.**
> 공중에서 오른쪽 키를 눌러도 걷기 모션이 나오면 안 되기 때문이다.

### 3-2. 입력 3상태 활용 (Day 23 복습)

**왜 필요한가** — 어떤 동작에 어떤 상태를 쓰는지 명확히 한다.

| 동작 | 사용할 상태 | 이유 |
|---|---|---|
| **이동** | `IsKeyPress` | 누르는 동안 계속 |
| **점프** | `IsKeyDown` | 누른 순간 한 번만 |
| **공격** | `IsKeyDown` | 한 번만 |
| 달리기 | `IsKeyPress` | 누르는 동안 |
| 차지 공격 | `IsKeyDown` + `IsKeyUp` | 누른 순간 시작, 뗀 순간 발사 |

```cpp
    // ✘ 점프에 Press를 쓰면
    if (input.IsKeyPress(VK_SPACE)) Jump();
    // → 누르고 있는 동안 매 프레임 점프 → 하늘로 날아간다

    // ✔ Down을 쓴다
    if (input.IsKeyDown(VK_SPACE)) Jump();
```

### 3-3. 좌우 동시 입력 처리

**왜 필요한가** — 양쪽 키를 동시에 누르면 어떻게 되어야 하나.

```cpp
    // ✘ 순서대로 처리하면 뒤의 것이 이긴다
    if (input.IsKeyPress(VK_LEFT))  m_vx = -speed;
    if (input.IsKeyPress(VK_RIGHT)) m_vx = +speed;      // 항상 오른쪽 승

    // ✔ 축(axis)으로 합산한다
    double axis = 0.0;
    if (input.IsKeyPress(VK_LEFT))  axis -= 1.0;
    if (input.IsKeyPress(VK_RIGHT)) axis += 1.0;

    m_vx = axis * speed;
```

```
   왼쪽만    →  axis = -1  →  왼쪽 이동
   오른쪽만  →  axis = +1  →  오른쪽 이동
   둘 다     →  axis =  0  →  정지        ★ 자연스럽다
   아무것도  →  axis =  0  →  정지
```

> **이것을 "입력 축(input axis)"이라고 한다.**
> Unity의 `Input.GetAxis("Horizontal")`이 정확히 같은 것이다 (Day 73).

### 3-4. 중력과 점프

**왜 필요한가** — Day 22의 속도 벡터에 중력을 더하면 점프가 된다.

```cpp
const double GRAVITY     = 1800.0;      // 픽셀/초²
const double JUMP_POWER  =  620.0;      // 픽셀/초

void Character::Update(double dt)
{
    // 중력
    m_vy += GRAVITY * dt;

    // 위치
    m_x += m_vx * dt;
    m_y += m_vy * dt;

    // 바닥 판정
    if (m_y >= GROUND_Y)
    {
        m_y = GROUND_Y;
        m_vy = 0.0;
        m_onGround = true;
    }
    else
    {
        m_onGround = false;
    }
}

void Character::Jump()
{
    if (!m_onGround) return;

    m_vy = -JUMP_POWER;                 // ★ 위로 = 음수 (화면 y는 아래로 증가)
    m_onGround = false;
}
```

```
   점프의 속도 변화 (GRAVITY = 1800, JUMP_POWER = 620)

   시간(초)  vy       y 변화        상태
   ─────────────────────────────────────────
   0.00     -620     빠르게 위로    점프 시작
   0.10     -440     위로
   0.20     -260     위로
   0.34        0     정점          ← 최고점
   0.45     +200     아래로
   0.60     +460     빠르게 아래로
   0.69     +620     착지

   ★ 체공 시간 ≈ 2 × JUMP_POWER / GRAVITY = 0.69초
   ★ 최고 높이 ≈ JUMP_POWER² / (2 × GRAVITY) = 107픽셀
```

**점프 파라미터 역산**

```
   원하는 것:  최고 높이 h, 체공 시간 t

   GRAVITY    = 8h / t²
   JUMP_POWER = 4h / t

   예)  h = 120픽셀, t = 0.7초
        GRAVITY    = 8 × 120 / 0.49 = 1959
        JUMP_POWER = 4 × 120 / 0.7  = 686
```

> **감으로 조절하지 말고 원하는 결과에서 역산한다.**
> Day 20의 밸런싱 사고방식과 같다.

### 3-5. 이단 점프

**왜 필요한가** — 게임성을 위해 흔히 쓰는 기능.

```cpp
    int m_maxJumpCount = 2;

void Character::Jump()
{
    if (m_jumpCount >= m_maxJumpCount) return;

    m_vy = -JUMP_POWER;
    m_onGround = false;
    m_jumpCount++;
}

    // 착지 시
    if (m_y >= GROUND_Y)
    {
        m_y = GROUND_Y;
        m_vy = 0;
        m_onGround = true;
        m_jumpCount = 0;                // ★ 초기화

```

```
   ★ 흔한 버그: 착지해도 jumpCount 를 초기화 안 하면

```

### 3-6. 방향 전환

**왜 필요한가** — 왼쪽으로 가는데 오른쪽을 보면 안 된다.

```cpp

    if (axis > 0) m_facingLeft = false;
    // axis == 0 이면 마지막 방향 유지
```


### 3-7. 애니메이션 선택 — 상태에서 결정

**왜 필요한가** — 입력이 아니라 **현재 상태**를 보고 고른다.

```cpp
void Character::UpdateAnimation()
{
    if (!m_onGround)
    {
        if (m_vy < 0) m_animator.Play("jump");        // 올라가는 중
        else          m_animator.Play("fall");        // 떨어지는 중
    }
    else if (fabs(m_vx) > 0.1)
    {
        if (m_isRunning) m_animator.Play("run");
        else             m_animator.Play("walk");
    }
    else
    {
        m_animator.Play("idle");
    }
}
```

```
   ┌───────────────────────────────────────────────┐
   │  판정 순서가 중요하다                           │
   │                                                │
   │  ① 공중인가?     →  jump / fall               │
   │  ② 움직이는가?   →  walk / run                │
   │  ③ 그 외         →  idle                      │
   │                                                │
   │  ★ 우선순위가 높은 것부터 검사한다             │
   │    공중에서 이동 키를 눌러도 걷기가 나오면 안 됨│
   └───────────────────────────────────────────────┘
```

> **이 `if` 사슬이 길어지면 관리가 안 된다.**
> **Day 46에서 유한 상태 머신(FSM)으로 정리한다.** 오늘은 이 한계를 느끼는 것도 목적이다.

## 4. 따라 만들기

### Step 1 — `Character` 클래스

```cpp
class Character : public GameObject
{
public:
    bool Init(Core* core) override;
    void Update(double dt) override;
    void Render(Renderer& r) const override;

    void Jump();

    bool IsOnGround() const { return m_onGround; }
    double GetVx() const { return m_vx; }
    double GetVy() const { return m_vy; }

private:
    void ProcessInput(double dt);
    void ApplyPhysics(double dt);
    void CheckBounds();
    void UpdateAnimation();

private:
    Sprite   m_sprite;
    Animator m_animator;

    double m_vx = 0.0, m_vy = 0.0;

    bool m_onGround   = true;
    bool m_facingLeft = false;
    bool m_isRunning  = false;

    int m_jumpCount    = 0;
    int m_maxJumpCount = 2;

    double m_walkSpeed = 200.0;
    double m_runSpeed  = 360.0;
};
```

**✅ 여기까지 하면** — 클래스 골격이 잡힌다.

### Step 2 — 좌우 이동 (입력 축)

```cpp
void Character::ProcessInput(double dt)
{
    Input& in = m_core->GetInput();

    // 이동 축
    double axis = 0.0;
    if (in.IsKeyPress(VK_LEFT)  || in.IsKeyPress('A')) axis -= 1.0;
    if (in.IsKeyPress(VK_RIGHT) || in.IsKeyPress('D')) axis += 1.0;

    // 달리기
    m_isRunning = in.IsKeyPress(VK_SHIFT);
    double speed = m_isRunning ? m_runSpeed : m_walkSpeed;

    m_vx = axis * speed;

    // 방향
    if (axis < 0) m_facingLeft = true;
    if (axis > 0) m_facingLeft = false;

    // 점프
    if (in.IsKeyDown(VK_SPACE) || in.IsKeyDown(VK_UP) || in.IsKeyDown('W'))
        Jump();
}
```

**✅ 여기까지 실행하면** — 좌우 키로 캐릭터가 움직인다. **양쪽을 동시에 누르면 멈춘다.**

### Step 3 — 중력과 점프

```cpp
const double GRAVITY    = 1800.0;
const double JUMP_POWER =  620.0;
const double GROUND_Y   =  480.0;

void Character::ApplyPhysics(double dt)
{
    m_vy += GRAVITY * dt;

    m_x += m_vx * dt;
    m_y += m_vy * dt;

    if (m_y >= GROUND_Y)
    {
        m_y = GROUND_Y;
        m_vy = 0.0;

        if (!m_onGround)
            DebugLog("[착지]\n");

        m_onGround  = true;
        m_jumpCount = 0;                 // ★ 초기화
    }
    else
    {
        m_onGround = false;
    }
}

void Character::Jump()
{
    if (m_jumpCount >= m_maxJumpCount) return;

    m_vy = -JUMP_POWER;
    m_onGround = false;
    m_jumpCount++;
}
```

**✅ 여기까지 실행하면** — SPACE로 점프하고 중력으로 착지한다. **이단 점프까지 된다.**

### Step 4 — 점프 파라미터 조정

```cpp
    // 화면에 표시
    double airTime = 2.0 * JUMP_POWER / GRAVITY;
    double maxH    = JUMP_POWER * JUMP_POWER / (2.0 * GRAVITY);

    r.DrawTextF(20, 40, RGB(200,200,255),
                "체공 %.2f초   최고높이 %.0fpx", airTime, maxH);
```

**여러 조합을 시험해 본다.**

| GRAVITY | JUMP_POWER | 체공 | 최고 높이 | 느낌 |
|:--:|:--:|:--:|:--:|---|
| 1200 | 500 | 0.83초 | 104px | 둥실둥실 |
| 1800 | 620 | 0.69초 | 107px | **적당** |
| 2600 | 750 | 0.58초 | 108px | 묵직·경쾌 |
| 3500 | 620 | 0.35초 | 55px | 짧고 답답 |

**✅ 여기까지 실행하면** — 같은 높이라도 중력에 따라 느낌이 완전히 다르다.

> **점프감은 게임의 인상을 좌우한다.** 시간을 들여 조정할 가치가 있다.

### Step 5 — 화면 경계

```cpp
void Character::CheckBounds()
{
    double halfW = m_sprite.GetFrameWidth() / 2.0;
    int screenW = m_core->GetWidth();

    if (m_x < halfW)            m_x = halfW;
    if (m_x > screenW - halfW)  m_x = screenW - halfW;
}
```

**✅ 여기까지 실행하면** — 캐릭터가 화면 밖으로 안 나간다.

### Step 6 — 애니메이션 연결

```cpp
void Character::UpdateAnimation()
{
    if (!m_onGround)
    {
        if (m_vy < 0) m_animator.Play("jump");
        else          m_animator.Play("fall");
    }
    else if (fabs(m_vx) > 0.1)
    {
        m_animator.Play(m_isRunning ? "run" : "walk");
    }
    else
    {
        m_animator.Play("idle");
    }
}

void Character::Update(double dt)
{
    ProcessInput(dt);
    ApplyPhysics(dt);
    CheckBounds();
    UpdateAnimation();                    // ★ 마지막

    m_animator.Update(dt);
}
```

**✅ 여기까지 실행하면** — 걸으면 걷기, 뛰면 달리기, 점프하면 점프 모션이 나온다.
**키를 떼면 대기로 돌아온다.**

> `Play`가 `restart=false`이므로 매 프레임 호출해도 문제없다 (Day 43).

### Step 7 — 좌우 반전 적용

```cpp
void Character::Render(Renderer& r) const
{
    int drawX = (int)m_x - m_sprite.GetFrameWidth() / 2;
    int drawY = (int)m_y - m_sprite.GetFrameHeight();

    m_animator.Render(r.GetDC(), drawX, drawY, m_facingLeft);
}
```

**✅ 여기까지 실행하면** — 왼쪽으로 가면 왼쪽을 본다. **키를 떼도 방향이 유지된다.**


**✅ 여기까지 실행하면** — 달릴 때 애니메이션도 빨라져 발 미끄러짐이 줄어든다.

### Step 9 — 포커스 처리

```cpp
    // Core::ProcessInput
void Core::ProcessInput()
{
    if (!m_hasFocus)
    {
        m_input.Clear();
        return;
    }
    m_input.Update();
}
```

**✅ 여기까지 실행하면** — 알트탭으로 다른 창을 쓰면 캐릭터가 멈춘다.

> **다른 창에서 방향키를 눌러도 게임 캐릭터가 안 움직이는지 확인한다.**

### Step 10 — 관성 추가 (선택)

지금은 키를 떼면 즉시 멈춘다. 관성을 넣으면 감각이 달라진다.

```cpp
    double targetVx = axis * speed;

    const double ACCEL   = 2400.0;      // 가속도
    const double FRICTION = 1800.0;     // 마찰

    if (fabs(targetVx) > 0.1)
    {
        // 가속
        if (m_vx < targetVx) { m_vx += ACCEL * dt; if (m_vx > targetVx) m_vx = targetVx; }
        if (m_vx > targetVx) { m_vx -= ACCEL * dt; if (m_vx < targetVx) m_vx = targetVx; }
    }
    else
    {
        // 감속
        if (m_vx > 0) { m_vx -= FRICTION * dt; if (m_vx < 0) m_vx = 0; }
        if (m_vx < 0) { m_vx += FRICTION * dt; if (m_vx > 0) m_vx = 0; }
    }
```

**✅ 여기까지 실행하면** — 키를 떼도 약간 미끄러진다.

```
   ★ 장르에 따라 선택한다

   격투게임    →  즉시 정지 (정확한 조작이 중요)
   플랫포머    →  관성 있음 (마리오)
   레이싱      →  관성 큼
```

> **격투게임이므로 관성은 넣지 않거나 아주 작게 한다.** 확인 후 판단한다.

## 6. 자주 막히는 곳

| 증상 | 원인 | 해결 |
|---|---|---|
| 하늘로 날아감 | 점프에 `IsKeyPress` | `IsKeyDown` |
| 한 번 점프하면 다시 안 됨 | `m_jumpCount` 초기화 누락 | 착지 시 0으로 |
| 오른쪽만 우선됨 | `if` 순서대로 대입 | 입력 축(axis) 방식 |
| 키를 떼면 정면을 봄 | `axis == 0`에서도 방향 변경 | 0일 때는 유지 |
| 걷기 애니메이션이 안 멈춤 | 입력으로 애니메이션 결정 | **상태**로 결정 |
| 공중에서 걷기 모션 | 판정 순서 | 공중 검사를 먼저 |
| 걷기가 0프레임에서 멈춤 | `Play(..., true)` | `restart=false` |
| 바닥을 뚫음 | 이동량이 큼 | 위치 보정 순서 확인 |
| 다른 창에서도 움직임 | 포커스 미처리 | `Input::Clear()` |
| 점프가 너무 낮음/높음 | 파라미터 | 역산 공식으로 계산 |
| 발이 미끄러짐 | 애니메이션 속도 불일치 | 이동 속도에 연동 |

## 7. 정리

### 오늘 배운 것

| 개념 | 한 줄 요약 |
|---|---|
| **처리 순서** | 입력 → 속도 → 물리 → 위치 → 충돌 → **애니메이션** |
| 입력 3상태 | 이동은 `Press`, 점프·공격은 `Down` |
| **입력 축** | `axis = (오른쪽?1:0) - (왼쪽?1:0)`. 동시 입력 자연스럽게 |
| 중력 | `vy += GRAVITY * dt`. 위는 음수 |
| 점프 역산 | `GRAVITY = 8h/t²`, `JUMP_POWER = 4h/t` |
| 이단 점프 | 카운트 관리. **착지 시 초기화 필수** |
| 방향 유지 | `axis == 0`이면 안 바꾼다 |
| **애니메이션 선택** | 입력이 아니라 **상태**를 보고 결정 |
| 포커스 처리 | 비활성 시 입력 차단 |
