### 문제 1. W13 최종 후보 확정 (1~2교시)

이번 주의 모든 결론을 코드 하나에 담습니다: 전 특성 + Pipeline + TSS CV, test는 마지막 한 번.

```python
# day065_final.py — W13 통합: 최종 후보 모델
import numpy as np
import pandas as pd
from sklearn.compose import ColumnTransformer
from sklearn.impute import SimpleImputer
from sklearn.linear_model import LinearRegression
from sklearn.metrics import mean_absolute_error, r2_score
from sklearn.model_selection import TimeSeriesSplit, cross_val_score
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import OneHotEncoder, StandardScaler

pd.set_option("display.width", 140)
NUM = ["pm10", "pm25", "o3", "no2", "co", "so2", "temp", "humidity", "wind_speed", "precip"]
TIME = ["pm25_lag1", "pm25_ma3", "seoul_pm25", "month"]
FC = ["wind_fc", "humidity_fc", "precip_fc"]

def load():
    df = pd.read_csv("data/air_daily.csv", parse_dates=["date"]).sort_values(["station", "date"])
    g = df.groupby("station")
    df["pm25_lag1"] = g["pm25"].shift(1)
    df["pm25_ma3"] = g["pm25"].transform(lambda s: s.rolling(3).mean())
    df["seoul_pm25"] = df.groupby("date")["pm25"].transform("mean")
    df["month"] = df.date.dt.month
    df["wind_fc"] = g["wind_speed"].shift(-1)
    df["humidity_fc"] = g["humidity"].shift(-1)
    df["precip_fc"] = g["precip"].shift(-1)
    return df

def build(feats):
    prep = ColumnTransformer([
        ("num", Pipeline([("i", SimpleImputer(strategy="median")), ("s", StandardScaler())]), feats),
        ("cat", OneHotEncoder(handle_unknown="ignore"), ["station"]),
    ])
    return Pipeline([("prep", prep), ("m", LinearRegression())])

print("== A. W13 최종 후보 확정 (TSS CV + test 1회) ==")
df = load()
d = df[df.pm25_next.notna() & df[FC].notna().all(axis=1)].sort_values("date")
tr = d[d.date < "2026-01-01"]; te = d[d.date >= "2026-01-01"]
feats = NUM + TIME + FC
pipe = build(feats)
cv = cross_val_score(pipe, tr[feats + ["station"]], tr.pm25_next, cv=TimeSeriesSplit(5), scoring="r2")
print(f"TSS 5-fold CV R²: {cv.mean():.3f} ± {cv.std():.3f}")
pipe.fit(tr[feats + ["station"]], tr.pm25_next)
p = pipe.predict(te[feats + ["station"]])
print(f"test: R² {r2_score(te.pm25_next, p):.3f}  MAE {mean_absolute_error(te.pm25_next, p):.2f}")
```

실행 결과:

```
== A. W13 최종 후보 확정 (TSS CV + test 1회) ==
TSS 5-fold CV R²: 0.355 ± 0.127
test: R² 0.519  MAE 4.26
```

CV(0.355)와 test(0.519)의 큰 간격에 놀라지 마세요 — TSS 초반 폴드는 train이 400여 행뿐이고
예보 특성 없던 시절의 어려운 겨울을 검증하기 때문에 박합니다. **CV는 후보끼리의 비교 자,
test는 최종 성능 보고** — 역할이 다릅니다 ([Day 061](day-061.md)·[063](day-063.md)에서 반복된 교훈).

### 문제 3. 재현 게임 — 세 사람, 세 숫자 (5~6교시)

동료의 기록 노트에 이렇게만 적혀 있다고 합시다 (흔한 수준의 기록입니다):

> **"선형 파이프라인 + 예보 특성, test R² 0.519"**

세 사람이 각자 이 기록만 보고 재현을 시도합니다.

```python
print("\n== B. '기록 노트'만 보고 재현 시도 — 세 사람, 세 숫자 ==")

# 재현자 1: '예보 특성'이라니 예보만 추가 (시간 파생을 뺌)
d1 = df[df.pm25_next.notna() & df[FC].notna().all(axis=1)]
tr1 = d1[d1.date < "2026-01-01"]; te1 = d1[d1.date >= "2026-01-01"]
f1 = NUM + FC
m1 = build(f1).fit(tr1[f1 + ["station"]], tr1.pm25_next)
print(f"재현자 1 (시간 파생 없이): R² {r2_score(te1.pm25_next, m1.predict(te1[f1 + ['station']])):.3f}")

# 재현자 2: 특성은 다 넣었지만 결측 처리를 dropna로 (기록에 대치 방식이 없어서)
d2 = df.dropna(subset=NUM + TIME + FC + ["pm25_next"])
tr2 = d2[d2.date < "2026-01-01"]; te2 = d2[d2.date >= "2026-01-01"]
f2 = NUM + TIME + FC
m2 = build(f2).fit(tr2[f2 + ["station"]], tr2.pm25_next)
print(f"재현자 2 (dropna 방식):   R² {r2_score(te2.pm25_next, m2.predict(te2[f2 + ['station']])):.3f}")

# 재현자 3: 우리가 실제로 한 것
print(f"재현자 3 (원래 방식):     R² {r2_score(te.pm25_next, p):.3f}")
```

실행 결과:

```
== B. '기록 노트'만 보고 재현 시도 — 세 사람, 세 숫자 ==
재현자 1 (시간 파생 없이): R² 0.503
재현자 2 (dropna 방식):   R² 0.513
재현자 3 (원래 방식):     R² 0.519
```

**0.503, 0.513, 0.519.** 셋 다 "선형 파이프라인 + 예보 특성"이라는 기록에 부합하고,
셋 다 자신이 원본을 재현했다고 믿을 것입니다. 기록의 빈칸(②특성의 정확한 목록, ①행의 정의)이
0.016의 유령 차이를 만들었습니다 — 이 크기는 [Day 062](day-062.md) 튜닝 이득(+0.015)과 같은
급입니다. **기록이 부실하면 개선과 노이즈를 구분할 수 없게 됩니다.**

## ⑥ 확인 문제

**Q1.** 문제 1에서 CV R²(0.355)와 test R²(0.519)가 크게 다른데도 우리가 당황하지 않은 이유를
두 가지 쓰세요.

<details>
<summary>답 보기</summary>

① TSS의 초반 폴드는 train이 수백 행뿐이라 절대값이 박하게 나오는 구조입니다 (폴드가 진행될수록 점수 상승).
② CV의 역할은 **후보 간 비교**이고 최종 성능 보고는 test의 역할이므로, 두 숫자는 애초에 같은 것을
재는 자가 아닙니다. 당황해야 할 것은 반대 상황(CV ≫ test)입니다 — 그건 누수나 승자의 저주 신호입니다.

</details>

**Q2.** 재현 게임에서 세 사람의 차이(최대 0.016)가 [Day 062](day-062.md)의 튜닝 이득(+0.015)과 비슷한
크기라는 사실이 왜 심각한가요?

<details>
<summary>답 보기</summary>

기록 부실로 인한 재현 오차가 실제 개선 폭과 같은 크기라면, 누군가 "튜닝으로 0.015 올렸다"고 보고해도
그것이 진짜 개선인지 재현 방식의 차이(유령 개선)인지 **구분할 방법이 없기 때문**입니다. 기록의 정밀도는
측정하려는 효과의 크기보다 좋아야 합니다.

</details>

**Q3.** 여덟 칸 중 "⑧ 왜(가설과 결론)"가 자동화 도구(MLflow)로도 대체하기 어려운 칸인 이유를 쓰세요.

<details>
<summary>답 보기</summary>

파라미터·지표·버전은 코드에서 자동 수집할 수 있지만, "왜 이 실험을 했고 결과에서 무엇을 결론지었나"는
사람의 판단이라 자동 기록될 수 없습니다. 그래서 MLflow를 써도 기각/채택의 이유는 사람이 남겨야 하며
(태그·노트), 이것이 없는 실험 이력은 숫자 무덤이 됩니다.

</details>

## 주간 퀴즈 12 — W13 (모델 개선과 파이프라인)

<details>
<summary>1. 검증 세트 하나로 잰 점수의 근본 문제는?</summary>

어느 표본이 검증에 뽑혔느냐는 **운**에 점수가 좌우됩니다 (seed만 바꿔도 0.929~0.954). 교차검증으로 평균±표준편차를 만들어야 합니다.

</details>

<details>
<summary>2. 시계열 데이터에 무작위 K-Fold를 쓰면 안 되는 이유는?</summary>

검증 조각의 앞뒤 시점이 학습 조각에 들어가는 **시점 누수**가 폴드마다 반복되어, 정밀하지만 부풀려진 점수(0.944 vs 진짜 0.818)가 나옵니다.

</details>

<details>
<summary>3. "정밀하게 틀렸다"는 말의 뜻은?</summary>

반복 측정끼리는 잘 일치(작은 분산)하지만 과녁 자체가 잘못 걸려(체계적 편향) 참값에서 먼 상태. 측정 반복으로는 교정되지 않습니다.

</details>

<details>
<summary>4. Grid 대신 Random Search가 유리해지는 조건은?</summary>

탐색 축이 많고(4+) 그중 일부만 중요한 경우 — Random은 같은 예산으로 중요한 축에서 훨씬 다양한 값을 시험합니다.

</details>

<details>
<summary>5. 승자의 저주란?</summary>

수십 후보 중 CV 1등의 점수는 실력+운(CV 노이즈의 좋은 쪽)의 합이라 낙관 편향을 갖는 것. Optuna CV 1위(0.809)가 test 꼴찌(0.794)였던 실측 사례.

</details>

<details>
<summary>6. Pipeline이 전처리 누수를 "구조적으로" 막는다는 것의 의미는?</summary>

predict/CV 경로에서 전처리 단계는 자동으로 transform만 호출되므로, test 통계로 fit하는 실수가 코드상 불가능해집니다.

</details>

<details>
<summary>7. `prep__num__imputer__strategy` 같은 이름의 규칙과 용도는?</summary>

`단계이름__파라미터`(밑줄 2개)로 파이프라인 내부 파라미터를 지정하는 주소 체계. GridSearch가 전처리 선택지까지 함께 탐색할 수 있게 합니다.

</details>

<details>
<summary>8. OneHotEncoder(handle_unknown="ignore")가 필요한 이유는?</summary>

서빙에서 학습에 없던 범주(새 측정소)가 오면 기본값은 에러로 죽습니다. ignore는 전부 0으로 인코딩해 "평균적인 범주"로 안전하게 처리합니다.

</details>

<details>
<summary>9. 이번 주 개선 수단 3종의 이득 순위는?</summary>

특성(예보 +0.093) > 파이프라인(대치·원핫 +0.032) > 튜닝(+0.015). 모델은 입력에 없는 정보를 만들 수 없기 때문입니다.

</details>

<details>
<summary>10. "내일의 풍속 예보"가 누수가 아닌 이유와, 실습에서 그것을 흉내 낸 방식의 한계는?</summary>

예보는 **예측 시점에 입수 가능한** 정보라 합법입니다. 실습은 내일 실측값을 예보 대용으로 써 "완벽한 예보" 가정이므로, 예보 오차 노이즈 민감도 실험으로 한계를 보정해 보고해야 합니다.

</details>
