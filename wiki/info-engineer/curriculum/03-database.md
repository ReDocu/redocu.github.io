## 1. 단원 개요

**이 단원을 마치면**

- [ ] 예제 스키마에서 SELECT(조건·정렬·집계·GROUP BY·HAVING)를 **직접 작성할 수 있다**
- [ ] JOIN(INNER·OUTER)과 서브쿼리(IN·EXISTS 포함)의 결과를 **예측하고 작성할 수 있다**
- [ ] DDL·DML·DCL·TCL을 구분하고 각 대표 문법을 **손으로 쓸 수 있다**
- [ ] 트랜잭션 성질(ACID)과 COMMIT·ROLLBACK 동작을 **설명할 수 있다**
- [ ] 이상현상과 정규화 단계(1NF~BCNF), 관계대수 기호를 **판정할 수 있다**
- [ ] NULL·집계·GROUP BY에서 발생하는 함정 문제를 **피할 수 있다**

**왜 2주인가** — SQL은 매회 출제되는 확실한 득점 영역이면서, DB 이론(정규화·트랜잭션·키·무결성)도 단답 빈출 영역입니다. 4단원 이론 주차가 1주뿐인 것은 DB 이론을 이 단원에서 실습과 함께 소화하기 때문입니다. 07강에서 정의하는 예제 스키마는 이후 모든 SQL 문제(중간평가·통합 세트·모의고사)에서 재사용되어 문제 읽는 부담을 줄입니다.

**주차 구성**

| 주차 | 강 | 주제 |
|---|---|---|
| W04 | 07–08강 | DB 개념·SELECT 기본 / 집계·GROUP BY·HAVING + 🏁 중간평가 |
| W05 | 09–10강 | JOIN·서브쿼리 / DDL·DML·DCL·TCL·트랜잭션·인덱스·뷰·정규화·관계대수 |

**선행 지식** — [01단원](01-foundation.md) 02강: DB·DBMS·SQL 개념, SELECT-FROM-WHERE 구조. [02단원](02-programming.md): 자료형 감각(숫자 vs 문자열).

> **주차 목표**
> 1. 두 테이블 이상을 연결하는 질의를 자유롭게 작성한다
> 2. DDL·DML·DCL·TCL 대표 문법을 손으로 재현한다
> 3. 트랜잭션·인덱스·뷰·정규화·관계대수를 시험 표현으로 정리한다

| 강 | 제목 | 핵심 내용 | 문서 |

| 10 | SQL 분류 완성과 DB 이론 | CREATE·ALTER·DROP·제약조건, INSERT·UPDATE·DELETE, GRANT·REVOKE, COMMIT·ROLLBACK·SAVEPOINT, 트랜잭션 ACID, 인덱스, 뷰, 이상현상·정규화(1NF~BCNF), 관계대수 기호(σ·π·⋈·÷) | [lesson-10](../lessons/03-database/lesson-10.md) |

- 10강의 정규화·관계대수는 **판정 문제를 풀 수 있는 수준까지만** 다룹니다. 함수 종속 이론의 수학적 증명은 출제 빈도 대비 학습 부담이 커서 축소합니다(사유 표기 — [로드맵 8절](README.md) 운영 원칙 6).

## 5. 이 단원에서 자주 나오는 질문

| 질문 | 답 |
|---|---|
| SQL은 어떤 DBMS 기준으로 배우나요? | 표준 SQL 기준입니다. Oracle·MySQL 등에서 문법이 갈리는 부분(문자열 연결, 날짜 등)은 본문에서 '표준/DBMS별'로 구분 표기하며, 시험 답안은 표준 문법으로 쓰는 것을 원칙으로 합니다. |
| SQL 답안은 대소문자를 구분하나요? | 키워드는 대소문자 구분이 없지만, 본 과정에서는 가독성을 위해 키워드 대문자 표기를 권장 스타일로 통일합니다. |
| 정규화가 이론인데 왜 이 단원에 있나요? | 정규화·트랜잭션은 SQL 실습 맥락에서 배워야 이해가 빠르고, 실제로도 DB 영역 단답으로 출제됩니다. 이론 주차(6주차)의 부담을 줄이는 배치입니다. |
