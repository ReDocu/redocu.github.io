## ② 왜 필요한가

지금까지 다룬 데이터는 **여러분이 직접 입력한 것**이었습니다.
실무의 데이터는 밖에 있습니다. 그리고 대부분 **HTTP로 옵니다.**

```
공공데이터포털 API   →  HTTP GET  →  JSON
서울열린데이터광장   →  HTTP GET  →  JSON / XML
뉴스 사이트          →  HTTP GET  →  HTML   (Day 017)
사내 시스템          →  HTTP POST →  JSON
```

그리고 **HTTP는 이 과정이 끝날 때까지 계속 나옵니다.**

| HTTP 지식이 쓰이는 곳 | 시점 |
|---|---|
| 공공데이터 수집기 | W04 |

| Hugging Face 모델 다운로드 | W18 |
| **FastAPI로 API를 만드는 쪽** | W19–W21 |

**W19부터는 입장이 바뀝니다.** 지금은 요청을 보내는 쪽(클라이언트)이지만,
그때는 요청을 받는 쪽(서버)이 됩니다. **오늘 배우는 것이 그때의 사양서**가 됩니다.

"왜 404가 아니라 400을 보내야 하는가", "왜 이 헤더가 필요한가"에 답하려면 오늘이 필요합니다.

## ③ 개념 설명

### HTTP란

**HyperText Transfer Protocol** — 웹에서 데이터를 주고받는 규칙입니다.

```
[클라이언트]  ──── 요청(Request) ────▶  [서버]
              ◀─── 응답(Response) ───
```

**요청과 응답은 둘 다 "헤더 + 바디" 구조**입니다.

```
요청                              응답
┌──────────────────────┐         ┌──────────────────────┐
│ GET /api/data?page=1 │         │ 200 OK               │
│ Host: api.example.com│         │ Content-Type: json   │
│ User-Agent: python   │  ────▶  │ Content-Length: 1234 │
├──────────────────────┤         ├──────────────────────┤
│ (바디 — GET은 보통 없음)│        │ {"items": [...]}     │
└──────────────────────┘         └──────────────────────┘
```

### URL 구조

```
https://api.example.com:443/v1/stations?city=seoul&page=2#section
└─┬─┘   └──────┬──────┘└┬┘└───┬────┘ └────────┬────────┘└──┬──┘
scheme      host      port  path         query          fragment
```

| 부분 | 뜻 |
|---|---|
| scheme | `http` / `https` (암호화) |
| host | 서버 주소 |
| port | 포트 (http=80, https=443, 생략 가능) |
| path | 자원의 경로 |
| **query** | `?key=value&key2=value2` — 조건 전달 |
| fragment | `#이후` — 브라우저 내부용, 서버로 안 감 |

### HTTP 메서드

| 메서드 | 뜻 | 바디 | 예 |
|---|---|---|---|
| **GET** | 조회 | 없음 | 데이터 읽기 |
| **POST** | 생성 | 있음 | 새 글 작성 |
| PUT | 전체 수정 | 있음 | 정보 통째로 교체 |
| PATCH | 부분 수정 | 있음 | 이름만 변경 |
| DELETE | 삭제 | 없음 | 글 삭제 |

**수집에서는 GET이 99%** 입니다. POST는 로그인이나 복잡한 검색 조건을 보낼 때 씁니다.

> **GET은 "안전(safe)"해야 합니다.** 여러 번 호출해도 서버 상태가 안 바뀌어야 합니다.
> W19에서 API를 설계할 때 이 원칙을 지켜야 합니다.

### 상태 코드 (status code)

**첫 자리가 의미를 결정합니다.**

| 범위 | 뜻 | 대응 |
|---|---|---|
| **2xx** | 성공 | 계속 진행 |
| **3xx** | 리다이렉트 | requests가 자동 처리 |
| **4xx** | **클라이언트 잘못** | 재시도해도 소용없음 → 코드·요청을 고쳐야 |
| **5xx** | **서버 잘못** | 재시도할 가치 있음 |

**꼭 외워야 하는 것**

| 코드 | 이름 | 상황 |
|---|---|---|
| `200` | OK | 정상 |
| `201` | Created | POST로 생성 성공 |
| `204` | No Content | 성공했지만 돌려줄 내용 없음 |
| `400` | Bad Request | 요청 형식이 잘못됨 |
| `401` | Unauthorized | 인증 안 됨 (키 없음) |
| `403` | Forbidden | 인증은 됐지만 권한 없음 |
| `404` | Not Found | 없는 주소 |
| `429` | Too Many Requests | **너무 자주 호출함** |
| `500` | Internal Server Error | 서버 코드가 터짐 |
| `502` / `503` | Bad Gateway / Service Unavailable | 서버가 일시적으로 못 받음 |
| `504` | Gateway Timeout | 서버가 늦음 |

> **4xx와 5xx의 구분이 재시도 전략을 결정합니다.**
> `404` 는 100번 다시 보내도 `404` 입니다. `503` 은 1초 뒤에 성공할 수 있습니다.
> `429` 는 **"쉬었다 오라"** 는 뜻이니 반드시 간격을 늘려야 합니다.

### requests 기본

```python
import requests

response = requests.get("https://api.example.com/data")

response.status_code      # 200
response.text             # 응답 본문 (문자열)
response.json()           # JSON을 딕셔너리로 파싱
response.headers          # 응답 헤더 (딕셔너리 비슷)
response.ok               # 2xx 면 True
response.encoding         # 'utf-8'
response.elapsed          # 걸린 시간 (timedelta)
```

```python
params = {"q": "서울 지하철"}
```

이걸 **URL 인코딩**이라고 합니다. `requests` 가 알아서 해 줍니다.

### 헤더

```python
headers = {
    "User-Agent": "MLOps-Study/1.0 (hong@example.com)",
    "Accept": "application/json",
    "Authorization": "Bearer 토큰값",
}
response = requests.get(url, headers=headers)
```

| 헤더 | 뜻 |
|---|---|
| `User-Agent` | 누가 요청하는지. **밝히는 것이 예의** |
| `Accept` | 어떤 형식으로 받고 싶은지 |
| `Authorization` | 인증 정보 |
| `Content-Type` | 보내는 바디의 형식 (POST) |

> **`User-Agent` 를 밝히세요.** 기본값은 `python-requests/2.32.3` 인데,
> 많은 사이트가 이걸 보고 차단합니다. 연락처를 넣으면 문제가 생겼을 때 사이트가 연락할 수 있습니다.
> **속이라는 뜻이 아닙니다.** 브라우저인 척하는 것은 [Day 018](day-018.md)에서 다룰 윤리 문제입니다.

### POST 요청

```python
# JSON 바디
requests.post(url, json={"name": "홍길동", "age": 25})

# 폼 데이터 (HTML form과 같은 형식)
requests.post(url, data={"username": "hong", "password": "***"})
```

| 인자 | Content-Type | 언제 |
|---|---|---|
| `json=` | `application/json` | 대부분의 최신 API |
| `data=딕셔너리` | `application/x-www-form-urlencoded` | HTML 폼 |
| `data=문자열` | 지정한 대로 | 직접 제어 |
| `files=` | `multipart/form-data` | 파일 업로드 |

### 타임아웃 — **반드시 지정하세요**

```python
requests.get(url, timeout=10)              # 전체 10초
requests.get(url, timeout=(3, 10))         # (연결 3초, 읽기 10초)
```

**타임아웃이 없으면 영원히 기다립니다.** 서버가 응답을 안 주면 프로그램이 멈춥니다.
1만 건을 수집하는 중에 하나가 멈추면 나머지 9999건도 못 받습니다.

> **`requests` 의 기본 타임아웃은 없음(무한)입니다.** 이건 라이브러리의 유명한 함정입니다.
> **모든 요청에 `timeout` 을 붙이세요.** 예외 없습니다.

### 예외 처리

```python
import requests

try:
    r = requests.get(url, timeout=10)
    r.raise_for_status()          # 4xx·5xx 면 예외 발생
    data = r.json()
except requests.Timeout:
    print("시간 초과")
except requests.ConnectionError:
    print("연결 실패 (네트워크·DNS)")
except requests.HTTPError as e:
    print(f"HTTP 오류: {e.response.status_code}")
except ValueError:                 # json() 파싱 실패
    print("JSON이 아닙니다")
except requests.RequestException as e:
    print(f"요청 실패: {e}")
```

**예외 계층**

```
RequestException           ← 전부 잡으려면 이것
├── ConnectionError        ← 네트워크·DNS 문제
│   └── ConnectTimeout
├── Timeout
│   ├── ConnectTimeout
│   └── ReadTimeout
├── HTTPError              ← raise_for_status() 가 던짐
└── TooManyRedirects
```

### `raise_for_status()`

```python
r = requests.get(url)
r.raise_for_status()       # 200이 아니면 HTTPError
```

**이걸 안 쓰면 404 응답의 HTML을 JSON으로 파싱하려다 엉뚱한 에러가 납니다.**

```python
# ❌ 상태 확인 없이
data = requests.get(url).json()
# json.decoder.JSONDecodeError: Expecting value: line 1 column 1
# → 사실은 404 였는데 원인을 모름
```

### Session — 연결 재사용

```python
session = requests.Session()
session.headers.update({"User-Agent": "MLOps-Study/1.0"})

for page in range(1, 100):
    r = session.get(url, params={"page": page}, timeout=10)
```

| | 매번 `requests.get()` | `Session` |
|---|---|---|
| TCP 연결 | 매번 새로 맺음 | **재사용** |
| 헤더 | 매번 지정 | 한 번 설정 |
| 쿠키 | 유지 안 됨 | 자동 유지 |
| 속도 | 느림 | **빠름** |

**100번 이상 요청하면 반드시 Session을 쓰세요.** 체감 속도가 다릅니다.

### 응답 인코딩 문제

```python
r = requests.get(url)
print(r.encoding)          # 'ISO-8859-1'  ← 한글이 깨짐
r.encoding = "utf-8"       # 명시적으로 지정
print(r.text)
```

**국내 사이트에서 자주 겪습니다.** 서버가 인코딩을 안 알려 주면 `requests` 가 추측하는데 틀릴 때가 있습니다.

```python
r.encoding = r.apparent_encoding      # 본문을 보고 추측 (느리지만 정확)
```

### Step 3. 상태 코드별 대응

`status_demo.py` 를 만듭니다.

```python
import requests

CODES = [200, 201, 204, 301, 400, 401, 403, 404, 429, 500, 503]

MEANING = {
    2: "성공 — 계속 진행",
    3: "리다이렉트 — requests가 자동 처리",
    4: "클라이언트 잘못 — 재시도 무의미, 요청을 고쳐야 함",
    5: "서버 잘못 — 재시도할 가치 있음",
}


def should_retry(status: int) -> bool:
    """재시도할 가치가 있는 상태인가."""
    if status == 429:
        return True                   # 간격을 늘려서
    return 500 <= status < 600


print(f"{'코드':<6}{'분류':<40}{'재시도?':<8}{'ok'}")
print("-" * 62)

for code in CODES:
    r = requests.get(f"https://httpbin.org/status/{code}",
                     timeout=10, allow_redirects=False)
    category = MEANING[r.status_code // 100]
    retry = "예" if should_retry(r.status_code) else "아니오"
    print(f"{r.status_code:<6}{category:<40}{retry:<8}{r.ok}")

print("\n--- raise_for_status() 동작 ---")
for code in (200, 404, 503):
    r = requests.get(f"https://httpbin.org/status/{code}", timeout=10)
    try:
        r.raise_for_status()
        print(f"  {code}: 예외 없음")
    except requests.HTTPError as e:
        print(f"  {code}: HTTPError — {e}")
```

```
403   클라이언트 잘못 — 재시도 무의미, 요청을 고쳐야 함        아니오    False
404   클라이언트 잘못 — 재시도 무의미, 요청을 고쳐야 함        아니오    False
429   클라이언트 잘못 — 재시도 무의미, 요청을 고쳐야 함        예       False
500   서버 잘못 — 재시도할 가치 있음                     예       False
503   서버 잘못 — 재시도할 가치 있음                     예       False

--- raise_for_status() 동작 ---
  200: 예외 없음
  404: HTTPError — 404 Client Error: NOT FOUND for url: https://httpbin.org/status/404
  503: HTTPError — 503 Server Error: SERVICE UNAVAILABLE for url: https://httpbin.org/status/503
```

> **`429` 만 4xx인데 재시도 대상**입니다. "너무 자주 왔으니 쉬었다 오라"는 뜻이기 때문입니다.

```python
import requests


def fetch(url: str, timeout: float = 5.0) -> tuple[dict | None, str | None]:
    """URL에서 JSON을 가져옵니다.

    Returns:
        (데이터, 에러 메시지) — 성공하면 에러는 None
    """
    try:
        r = requests.get(url, timeout=timeout)
        r.raise_for_status()
        return r.json(), None

    except requests.Timeout:
        return None, f"시간 초과 ({timeout}초)"

    except requests.ConnectionError:
        return None, "연결 실패 — 네트워크 또는 주소를 확인하세요"

    except requests.HTTPError as e:
        code = e.response.status_code
        kind = "서버 오류" if code >= 500 else "요청 오류"
        return None, f"{kind} HTTP {code}"

    except ValueError:
        return None, "응답이 JSON 형식이 아닙니다"

    except requests.RequestException as e:
        return None, f"요청 실패: {type(e).__name__}"


CASES = [
    ("정상", "https://httpbin.org/json"),
    ("느린 응답 (5초 지연)", "https://httpbin.org/delay/5"),
    ("404", "https://httpbin.org/status/404"),
    ("503", "https://httpbin.org/status/503"),
    ("JSON 아님 (HTML)", "https://httpbin.org/html"),
    ("없는 도메인", "https://this-domain-does-not-exist-12345.com"),
]

for label, url in CASES:
    data, error = fetch(url, timeout=3.0)
    if error:
        print(f"  ✗ {label:<24} {error}")
    else:
        preview = str(data)[:40]
        print(f"  ✓ {label:<24} {preview}...")
```

```
  ✗ 404                     요청 오류 HTTP 404
  ✗ 503                     서버 오류 HTTP 503
  ✗ JSON 아님 (HTML)          응답이 JSON 형식이 아닙니다
```

```python
import time

import requests

URL = "https://httpbin.org/get"
N = 10

HEADERS = {
    "User-Agent": "MLOps-Study/1.0 (교육용 실습, hong@example.com)",
    "Accept": "application/json",
}

# --- 1) 매번 새 연결 ---
start = time.perf_counter()
for i in range(N):
    requests.get(URL, headers=HEADERS, timeout=10)
without_session = time.perf_counter() - start

# --- 2) Session 재사용 ---
start = time.perf_counter()
with requests.Session() as s:
    s.headers.update(HEADERS)
    for i in range(N):
        s.get(URL, timeout=10)
with_session = time.perf_counter() - start

print(f"{N}회 요청")
print(f"  Session 없음 : {without_session:.2f}초")
print(f"  Session 사용 : {with_session:.2f}초")
print(f"  약 {without_session / with_session:.1f}배 빠름")

print("\n--- 서버가 받은 헤더 확인 ---")
with requests.Session() as s:
    s.headers.update(HEADERS)
    received = s.get(URL, timeout=10).json()["headers"]
    for key in ("User-Agent", "Accept"):
        print(f"  {key:<14}: {received.get(key)}")
```

```python
"""API로 수집한 데이터를 CSV·JSON으로 저장합니다."""

from pathlib import Path

import requests

OUT.mkdir(exist_ok=True)


def fetch_posts(session: requests.Session, user_id: int) -> list[dict]:
    r = session.get(f"{BASE}/posts", params={"userId": user_id}, timeout=10)
    r.raise_for_status()
    return r.json()


def to_record(post: dict, fetched_at: str) -> dict:
    """수집 결과를 저장용 레코드로 정규화합니다."""
    return {
        "id": post["id"],
        "user_id": post["userId"],

        "body_length": len(post.get("body", "")),
        "fetched_at": fetched_at,

# --- 실패 기록 ---
if failed:
    fail_path = OUT / "failed.json"

    print(f"실패 : {fail_path}")
```

### Step 8. 오프라인 연습용 로컬 서버 (선택)

인터넷이 불안정하거나 외부 API 접속이 막혀 있다면, 로컬에 연습용 서버를 띄울 수 있습니다.

```python
"""연습용 로컬 HTTP 서버. python mock_server.py 로 실행하고 다른 터미널에서 요청하세요."""

import json
import random
from http.server import BaseHTTPRequestHandler, HTTPServer
from urllib.parse import urlparse, parse_qs

STATIONS = ["강남", "홍대입구", "잠실", "신촌", "건대입구", "서울역", "구로디지털단지"]


class Handler(BaseHTTPRequestHandler):
    def log_message(self, fmt, *args):
        print(f"  [server] {self.address_string()} {fmt % args}")

    def _send(self, code, payload):
        body = json.dumps(payload, ensure_ascii=False, indent=2).encode("utf-8")
        self.send_response(code)
        self.send_header("Content-Type", "application/json; charset=utf-8")
        self.send_header("Content-Length", str(len(body)))
        self.end_headers()
        self.wfile.write(body)

    def do_GET(self):
        parsed = urlparse(self.path)
        query = parse_qs(parsed.query)

        if parsed.path == "/api/stations":
            page = int(query.get("page", ["1"])[0])
            size = int(query.get("size", ["3"])[0])

            # 10% 확률로 503 — 재시도 연습용
            if random.random() < 0.1:
                self._send(503, {"error": "Service Unavailable"})
                return

            start = (page - 1) * size
            items = [
                {"stationName": s, "line": "2호선", "boarding": random.randint(10000, 60000)}
                for s in STATIONS[start:start + size]
            ]
            self._send(200, {
                "response": {
                    "header": {"resultCode": "00", "resultMsg": "NORMAL SERVICE"},
                    "body": {"totalCount": len(STATIONS), "pageNo": page,
                             "numOfRows": size, "items": items},
                }
            })

        elif parsed.path == "/api/error":
            self._send(int(query.get("code", ["500"])[0]), {"error": "requested error"})

        else:
            self._send(404, {"error": "Not Found"})


if __name__ == "__main__":
    print("http://127.0.0.1:8000/api/stations?page=1&size=3")
    print("종료하려면 Ctrl+C\n")
    HTTPServer(("127.0.0.1", 8000), Handler).serve_forever()
```

```python
url = f"https://api.example.com/search?q={keyword}"    # keyword = "a&b=c"
# → ?q=a&b=c  ← 파라미터가 두 개로 쪼개짐!
```

**해결** — `params` 를 쓰세요.

```python
requests.get("https://api.example.com/search", params={"q": keyword})
# → ?q=a%26b%3Dc
```

### 상태 코드가 200인데 사실은 에러

```python
{"response": {"header": {"resultCode": "30", "resultMsg": "SERVICE KEY IS NOT REGISTERED"}}}
```

**원인** — **일부 API는 에러도 HTTP 200으로 보냅니다.** 공공데이터포털이 대표적입니다.
**해결** — 응답 **본문의 결과 코드도** 확인하세요.

```python
r.raise_for_status()                  # HTTP 레벨
data = r.json()
code = data.get("response", {}).get("header", {}).get("resultCode")
if code != "00":                      # 애플리케이션 레벨
    raise ValueError(f"API 오류: {code}")
```

**두 겹의 검사가 필요합니다.** [Day 019](day-019.md)에서 이걸 수집기에 넣습니다.

### 응답이 리스트인지 딕셔너리인지 확인 안 함

```python
data = r.json()
for item in data["items"]:      # TypeError: list indices must be str
```

**원인** — API가 최상위에 리스트를 돌려줬습니다.
**해결** — 타입을 확인하세요.

```python
data = r.json()
items = data if isinstance(data, list) else data.get("items", [])
```

### 요청을 너무 빨리 반복해 차단됨

```
429 Too Many Requests
```

**원인** — 간격 없이 연속 호출했습니다.
**해결** — 요청 사이에 `time.sleep()` 을 넣으세요. [Day 018](day-018.md)에서 자세히 다룹니다.
**이건 기술 문제가 아니라 예의와 규정의 문제**입니다.

```python
API_KEY = "abc123def456..."          # ❌ 커밋되면 유출
```

## ⑥ 확인 문제

**1.** HTTP 상태 코드 `404` 와 `503` 을 받았을 때 각각 어떻게 대응해야 하나요? 재시도 전략의 관점에서 설명하세요.

<details>
<summary>답 보기</summary>

| | `404 Not Found` | `503 Service Unavailable` |
|---|---|---|
| 분류 | **4xx — 클라이언트 잘못** | **5xx — 서버 잘못** |
| 뜻 | 요청한 자원이 없음 | 서버가 지금 처리 못 함 |
| 재시도 | **무의미** | **가치 있음** |
| 대응 | 로그 남기고 다음으로 | 잠시 후 재시도 |

**404를 재시도하면 안 되는 이유**

주소가 틀렸거나 자원이 삭제된 것입니다. **100번 다시 보내도 100번 404입니다.**
서버에 불필요한 부하만 주고, 수집 시간만 늘어납니다.

대신 **기록**해야 합니다.

```python
failed.append({"url": url, "status": 404, "reason": "자원 없음"})
```

수집 후 404가 많다면 **URL 생성 로직에 버그**가 있다는 신호입니다.

**503을 재시도해야 하는 이유**

서버가 일시적으로 과부하이거나 재시작 중입니다. **1초 뒤에는 성공할 수 있습니다.**

```python
def should_retry(status: int) -> bool:
    if status == 429:
        return True                    # 간격을 늘려서
    return 500 <= status < 600
```

**지수 백오프**를 씁니다. 간격을 점점 늘리는 것입니다.

```python
for attempt in range(1, 4):
    r = session.get(url, timeout=10)
    if r.ok:
        break
    if not should_retry(r.status_code):
        break                          # 4xx 면 즉시 포기
    time.sleep(1.5 ** attempt)         # 1.5초 → 2.25초 → 3.4초
```

**왜 간격을 늘리나** — 서버가 과부하라면, 모든 클라이언트가 1초마다 다시 오면
**부하가 더 심해집니다.** 점점 물러나 주는 것이 서버가 회복할 시간을 줍니다.

**429는 특별합니다.**

4xx인데도 재시도 대상입니다. "너무 자주 왔다"는 뜻이라 **쉬면 해결됩니다.**
많은 API가 `Retry-After` 헤더로 얼마나 기다릴지 알려 줍니다.

```python
if r.status_code == 429:
    wait = int(r.headers.get("Retry-After", 60))
    time.sleep(wait)
```

이 판단 로직이 [Day 019](day-019.md) 수집기의 핵심이 됩니다.
</details>

**2.** 아래 코드는 세 가지 문제가 있습니다. 각각 무엇이고 어떻게 고치나요?

```python
import requests

keyword = "서울 지하철"
url = f"https://api.example.com/search?q={keyword}&page=1"
data = requests.get(url).json()

for item in data["items"]:
    print(item["name"])
```

<details>
<summary>답 보기</summary>

**문제 ① URL을 f-string으로 조합**

```python
url = f"...?q={keyword}&page=1"
```

`keyword` 에 공백·한글·`&`·`=` 가 들어가면 URL이 깨집니다.
`keyword = "a&page=999"` 라면 **의도하지 않은 파라미터가 주입**됩니다.

```python
requests.get("https://api.example.com/search",
             params={"q": keyword, "page": 1})
```

**문제 ② 타임아웃이 없음**

서버가 응답을 안 주면 **영원히 기다립니다.** `requests` 의 기본값은 무한입니다.
1만 건 수집 중 하나가 멈추면 나머지도 전부 못 받습니다.

```python
requests.get(..., timeout=10)
```

**문제 ③ 상태 코드 확인 없이 `.json()`**

404·500이면 HTML 에러 페이지가 오고, `.json()` 이 `JSONDecodeError` 를 냅니다.
**진짜 원인(404)이 가려집니다.**

```python
r = requests.get(...)
r.raise_for_status()           # HTTP 오류를 명확히 드러냄
data = r.json()
```

**추가로 있는 문제**

④ `data["items"]` — 응답 구조가 다르면 `KeyError`. `data.get("items", [])` 를 쓰세요.
⑤ 예외 처리 없음 — 하나 실패하면 프로그램 전체가 중단됩니다.
⑥ `User-Agent` 미지정 — 차단당할 수 있습니다.

**전부 고친 코드**

```python
import requests

def search(keyword: str, page: int = 1) -> list[dict]:
    try:
        r = requests.get(
            "https://api.example.com/search",
            params={"q": keyword, "page": page},
            headers={"User-Agent": "MLOps-Study/1.0 (hong@example.com)"},
            timeout=10,
        )
        r.raise_for_status()
        data = r.json()
    except requests.RequestException as e:
        print(f"요청 실패: {e}")
        return []
    except ValueError:
        print("JSON 파싱 실패")
        return []

    return data.get("items", [])


for item in search("서울 지하철"):
    print(item.get("name", "(이름 없음)"))
```
</details>

**3.** 100페이지를 수집할 때 `requests.get()` 을 100번 부르는 것과 `Session` 을 쓰는 것의 차이는 무엇인가요?

<details>
<summary>답 보기</summary>

**핵심 차이: TCP 연결과 TLS 핸드셰이크를 재사용하느냐**

HTTPS 요청 하나에는 이 과정이 들어갑니다.

```
1. DNS 조회          (도메인 → IP)
2. TCP 연결 수립      (3-way handshake)
3. TLS 핸드셰이크     (암호화 협상 — 가장 비쌈)
4. 실제 요청/응답
5. 연결 종료
```

`requests.get()` 을 100번 부르면 **1~5를 100번** 합니다.
`Session` 은 연결을 **살려 두고 재사용**하므로 4번만 반복합니다.

| 항목 | 개별 요청 | Session |
|---|---|---|
| 연결 수립 | 100회 | 1회 (풀에서 재사용) |
| TLS 핸드셰이크 | 100회 | 1회 |
| 속도 | 기준 | **2~5배 빠름** |
| 서버 부하 | 높음 | 낮음 |

**부가 이점**

```python
with requests.Session() as s:
    s.headers.update({"User-Agent": "MLOps-Study/1.0"})   # 한 번만 설정
    s.params = {"serviceKey": API_KEY}                     # 공통 파라미터
    
    for page in range(1, 101):
        r = s.get(url, params={"page": page}, timeout=10)
```

| 이점 | 설명 |
|---|---|
| 헤더 공유 | 매번 안 써도 됨 |
| **쿠키 유지** | 로그인 세션이 필요한 사이트에 필수 |
| 재시도 어댑터 | `HTTPAdapter` 로 자동 재시도 설정 가능 |
| 연결 수 제한 | 서버에 과부하를 안 주도록 조절 |

**`with` 를 쓰는 이유**

```python
with requests.Session() as s:
    ...
# 여기서 열린 연결이 정리됨
```

파일과 같습니다. 안 닫으면 연결이 남아 **리소스 누수**가 됩니다.
장시간 도는 수집기에서는 열린 소켓이 쌓여 `Too many open files` 에러가 납니다.

**언제 Session을 안 써도 되나**

요청이 몇 번뿐이라면 차이가 없습니다. 하지만 **수집기를 만드는 순간부터는 항상 Session** 입니다.
[Day 019](day-019.md)의 `Collector` 클래스는 `self.session` 을 인스턴스 속성으로 들고 다닙니다.
W20에서 만들 추론 API도 외부 호출 시 같은 원리를 씁니다.
</details>

## 오늘의 정리

| 항목 | 내용 |
|---|---|
| 요청 | `requests.get(url, params=, headers=, timeout=)` |
| 쿼리 | **`params=` 딕셔너리** — 직접 f-string 조합 금지 |
| 상태 확인 | `r.status_code` · `r.ok` · `r.raise_for_status()` |
| 파싱 | `r.json()` · `r.text` · `r.headers` |
| 타임아웃 | **모든 요청에 필수** — 기본값은 무한 |
| 상태 코드 | 2xx 성공 · 4xx 내 잘못(재시도 X) · 5xx 서버(재시도 O) · **429는 예외** |
| 예외 | `Timeout` `ConnectionError` `HTTPError` `RequestException` |
| POST | `json=` (JSON) · `data=` (폼) |
| Session | 연결 재사용 · 헤더 공유 · **100회 이상이면 필수** |
| 헤더 | `User-Agent` 에 **정체와 연락처**를 밝히기 |
| 인코딩 | `r.encoding = "utf-8"` · `r.apparent_encoding` |
| 함정 | 200인데 본문에 에러 코드가 있는 API |
| 인증키 | **환경 변수** — 코드에 절대 금지 |

**과제** — 공개 API 하나를 골라 수집 스크립트를 만드세요.
① `Session` 과 `timeout` 을 쓰고 `User-Agent` 를 지정
② 상태 코드별로 다르게 대응 (4xx는 기록 후 진행, 5xx는 3회 재시도)
③ 수집 결과를 CSV와 JSON으로 저장하고 `fetched_at` 컬럼 포함
④ 실패한 요청은 `failed.json` 에 원인과 함께 격리
⑤ 총 수집 건수·실패 건수·소요 시간을 마지막에 출력
