## 2. 막히는 상황

어제 만든 HandArea에 카드를 넣어 보자.

```csharp
    // 카드 3장을 손패에 배치
    card1.anchoredPosition = new Vector2(-200, 0);
    card2.anchoredPosition = new Vector2(   0, 0);
    card3.anchoredPosition = new Vector2( 200, 0);
```

```
   ★ 카드를 한 장 뽑으면?

   card4의 위치는?
   → 전부 다시 계산해야 한다

   ┌─────────────┐        ┌─────────────┐
   │  ▣  ▣  ▣   │   →    │ ▣ ▣ ▣ ▣    │
   └─────────────┘        └─────────────┘
   -200, 0, 200           -300,-100,100,300
```

```
   ★ 카드를 한 장 내면?

   중간 카드를 냈다면 양쪽이 모여야 한다
```

**직접 계산해 보면**

```csharp
    void RearrangeHand()
    {
        int n = hand.Count;
        float spacing = 200f;

        if (n * spacing > areaWidth)           // 넘치면 겹치기
            spacing = areaWidth / n;

        float startX = -(n - 1) * spacing * 0.5f;

        for (int i = 0; i < n; i++)
            hand[i].anchoredPosition = new Vector2(startX + i * spacing, 0);
    }
```

```
   ★ 이건 그래도 할 만하다

   그런데
   × 카드 크기가 다르면?
   × 세로 목록이면?
   × 격자 배치면?
   × 스크롤이 필요하면?
   × 여백·정렬 옵션이 바뀌면?

   → 매번 새로 짜야 한다
```

> **레이아웃 그룹이 이 일을 대신한다.**

## 3. 개념

### 3-1. Layout Group — 자식을 자동 배치

**왜 필요한가** — 오늘의 핵심.

| 컴포넌트 | 배치 |
|---|---|
| **Horizontal Layout Group** | 가로 한 줄 |
| **Vertical Layout Group** | 세로 한 줄 |
| **Grid Layout Group** | 격자 |

```
   Horizontal Layout Group

   ┌─────────────────────────────┐
   │ ▣  ▣  ▣  ▣  ▣            │
   └─────────────────────────────┘
     ↑  ↑
   Padding  Spacing
```

```
   Vertical Layout Group          Grid Layout Group

   ┌────────┐                     ┌─────────────┐
   │  ▣     │                     │ ▣ ▣ ▣      │
   │  ▣     │                     │ ▣ ▣ ▣      │
   │  ▣     │                     │ ▣ ▣        │
   └────────┘                     └─────────────┘
```

```
   ★ 자식의 RectTransform은 그룹이 통제한다

   자식의 anchoredPosition을 직접 바꿔도
   → 다음 레이아웃 갱신에서 덮어써진다
```

### 3-2. Horizontal/Vertical Layout Group 설정

**왜 필요한가** — 옵션이 결과를 크게 바꾼다.

| 필드 | 의미 |
|---|---|
| **Padding** | 그룹 안쪽 여백 (Left/Right/Top/Bottom) |
| **Spacing** | 자식 사이 간격 |
| **Child Alignment** | 정렬 (좌/중앙/우 × 상/중앙/하) |
| **Control Child Size** | 자식 크기를 그룹이 정할지 |
| **Use Child Scale** | 자식 Scale을 계산에 포함 |
| **Child Force Expand** | 남는 공간을 자식에게 나눠줄지 |

```
   ★ Control Child Size vs Child Force Expand

   Control Child Size (Width ✔)
   → 자식의 Width를 그룹이 결정한다
   → Layout Element로 선호 크기를 지정

   Child Force Expand (Width ✔)
   → 남는 공간을 자식들이 균등하게 나눠 가진다
```

```
   Force Expand ✗                 Force Expand ✔

   ┌─────────────────────────┐    ┌─────────────────────────┐
   │ ▣ ▣ ▣                  │    │  ▣    ▣    ▣           │
   └─────────────────────────┘    └─────────────────────────┘
   왼쪽부터 채움                   간격이 벌어져 꽉 참
```

```
   ⚠️ 조합이 헷갈릴 때

   ① 자식 크기 고정 + 왼쪽 정렬
      Control Child Size ✗, Force Expand ✗, Alignment Left

   ② 자식 크기 고정 + 중앙 정렬  ★ 손패에 적합
      Control Child Size ✗, Force Expand ✗, Alignment Center

   ③ 자식이 공간을 균등 분할  ★ 툴바에 적합
      Control Child Size ✔, Force Expand ✔
```

### 3-3. ⚠️ 손패에는 Layout Group이 부족하다

**왜 필요한가** — 실전에서 만나는 한계.

```
   카드가 많아지면

   Layout Group:  간격만 줄인다 → 영역을 넘칠 수 있다
   실제 카드 게임: 겹치고, 부채꼴로 펼친다
```

```
   Layout Group만                실제 원하는 것

   ┌──────────────┐              ┌──────────────┐
   │▣▣▣▣▣▣▣▣▣│              │  ╱▣▣▣▣╲   │
   └──────────────┘              │ ▣      ▣  │
   빽빽하게 나열                  └──────────────┘
                                  부채꼴로 겹침
```

```
   ★ 해결

   ① 단순한 목록·격자 → Layout Group
   ② 손패처럼 특수한 배치 → 직접 계산 (오늘 둘 다 만든다)
```

### 3-4. Layout Element

**왜 필요한가** — 개별 자식의 크기를 제어한다.

| 필드 | 의미 | 우선순위 |
|---|---|:--:|
| **Min Width/Height** | 최소 크기. 반드시 확보 | 1 |
| **Preferred Width/Height** | 선호 크기 | 2 |
| **Flexible Width/Height** | 남는 공간 배분 비율 | 3 |
| Ignore Layout | 이 요소는 레이아웃에서 제외 | — |

```
   ★ 배분 순서

   ① 모든 자식의 Min 을 먼저 확보
   ② 남으면 Preferred 까지 채운다
   ③ 그래도 남으면 Flexible 비율로 나눈다
```

```
   예)  폭 600, 자식 3개

   A: Min 100, Preferred 200, Flexible 0
   B: Min 100, Preferred 200, Flexible 1
   C: Min 100, Preferred 200, Flexible 2

   ① Min 확보: 100+100+100 = 300  (남음 300)
   ② Preferred까지: 200+200+200 = 600  (남음 0)
   → A=200, B=200, C=200
```

```
   예)  폭 900, 같은 자식

   ① Min 300  ② Preferred 600  (남음 300)
   ③ Flexible 0:1:2 → A+0, B+100, C+200
   → A=200, B=300, C=400
```

```
   ⚠️ Ignore Layout

   드래그 중인 카드처럼
   "잠시 레이아웃에서 빠져야 하는" 요소에 사용
```

### 3-5. Content Size Fitter

**왜 필요한가** — 내용에 맞춰 크기를 자동 조절한다.

| 모드 | 동작 |
|---|---|
| Unconstrained | 자동 조절 안 함 |
| **Preferred Size** | 자식들의 선호 크기 합만큼 |
| Min Size | 최소 크기만큼 |

```
   ★ 스크롤 뷰의 Content에 필수

   Content Size Fitter가 없으면
   → Content 높이가 0
   → 스크롤할 게 없다고 판단
   → 스크롤이 안 된다
```

```
   Vertical Layout Group + Content Size Fitter (Vertical: Preferred)

   ┌──────────┐  자식 5개 → 높이 500
   │ ▣        │
   │ ▣        │  자식 10개 → 높이 1000  ★ 자동
   │ ▣        │
   └──────────┘
```

```
   ⚠️ 순환 참조 주의

   부모: Content Size Fitter (자식에 맞춤)
   자식: 앵커 stretch (부모에 맞춤)
   → 서로를 참조 → 크기가 0이 되거나 진동

   ★ Content Size Fitter를 쓰는 오브젝트의 자식은
     stretch 앵커를 쓰지 않는다
```

### 3-6. ⚠️ 레이아웃 갱신 타이밍

**왜 필요한가** — "추가했는데 위치가 안 맞는" 문제.

```
   ★ Unity의 레이아웃 갱신은 프레임 끝에 일어난다

   Instantiate(cardPrefab, handArea);
   float x = card.anchoredPosition.x;         // ★ 아직 0
```

```
   갱신 순서

   Update()
     ↓
   코루틴
     ↓
   ★ Canvas.willRenderCanvases
     → 레이아웃 계산 (LayoutRebuilder)
     ↓
   렌더링
```

**해결 1 — 강제 리빌드**

```csharp
using UnityEngine.UI;

    LayoutRebuilder.ForceRebuildLayoutImmediate(handAreaRect);

    float x = card.anchoredPosition.x;         // ★ 이제 정확
```

**해결 2 — 한 프레임 대기**

```csharp
    IEnumerator AddCardAndAnimate(GameObject card)
    {
        card.transform.SetParent(handArea, false);

        yield return null;                     // ★ 한 프레임 대기

        Vector2 target = card.GetComponent<RectTransform>().anchoredPosition;
        // 이제 정확한 목표 위치를 안다
    }
```

**해결 3 — 끝 프레임 대기**

```csharp
    yield return new WaitForEndOfFrame();
```

```
   ⚠️ ForceRebuildLayoutImmediate는 비싸다

   매 프레임 호출하면 안 된다
   → 카드 추가/제거 같은 이벤트에서만
```

```
   ★ SetParent의 두 번째 인자

   card.transform.SetParent(parent);         // worldPositionStays = true (기본)
   card.transform.SetParent(parent, false);  // ★ 로컬 값 유지

   UI에서는 대부분 false 를 쓴다
   true면 스케일·위치가 튄다
```

### 3-7. 레이아웃 그룹의 성능

**왜 필요한가** — 매 프레임 갱신되면 느리다.

```
   ★ 레이아웃이 다시 계산되는 조건

   ① 자식 추가/제거
   ② 자식 크기 변경
   ③ 그룹 설정 변경
   ④ 부모 크기 변경
```

```
   ⚠️ 흔한 실수

   Update에서 자식의 sizeDelta를 매 프레임 바꾼다
   → 매 프레임 전체 레이아웃 재계산
   → 자식이 50개면 눈에 띄게 느려진다
```

```
   ★ 대안

   ① 애니메이션 중에는 Layout Element의 Ignore Layout 켜기
   ② 레이아웃 그룹 대신 직접 계산 (좌표만 lerp)
   ③ 자주 바뀌는 목록은 그룹을 쓰지 않는다
```

| 상황 | 권장 |
|---|---|
| 정적 목록 (설정 화면) | Layout Group ✔ |
| 가끔 바뀌는 목록 (인벤토리) | Layout Group ✔ |
| 매 프레임 움직임 (손패 애니메이션) | **직접 계산** |
| 수백 개 항목 | **가상화 스크롤** |

### 3-8. Scroll View 구조

**왜 필요한가** — 목록이 화면보다 길 때.

```
   ScrollView                    (Scroll Rect, Image)
   └─ Viewport                   (Mask 또는 RectMask2D, Image)
       └─ Content                (Layout Group + Content Size Fitter)
           ├─ Item0
           ├─ Item1
           └─ ...
   └─ Scrollbar Vertical         (선택)
   └─ Scrollbar Horizontal       (선택)
```

```
   ★ 각 부분의 역할

   ScrollView:  Scroll Rect가 붙어 스크롤 처리
   Viewport:    보이는 창. Mask로 밖을 잘라낸다
   Content:     실제 내용. Viewport보다 크다
```

```
        Viewport (보이는 범위)
        ┌──────────────┐
   ┌────┼──────────────┼────┐
   │    │  Item 3      │    │
   │    │  Item 4      │    │  Content (전체)
   │    │  Item 5      │    │
   └────┼──────────────┼────┘
        └──────────────┘
```

**Scroll Rect 설정**

| 필드 | 의미 |
|---|---|
| Content | 스크롤할 대상 |
| **Horizontal / Vertical** | 스크롤 방향 |
| **Movement Type** | Unrestricted / Elastic / Clamped |
| Elasticity | 튕김 정도 |
| **Inertia** | 관성 (놓아도 계속 미끄러짐) |
| Deceleration Rate | 감속률 |
| Scroll Sensitivity | 휠 감도 |
| Viewport | 마스크 영역 |

```
   ★ Movement Type

   Unrestricted:  끝없이 스크롤 (거의 안 씀)
   Elastic:       끝에서 튕겨 돌아옴  ★ 모바일 느낌
   Clamped:       끝에서 딱 멈춤     ★ PC 느낌
```

### 3-9. Mask vs RectMask2D

**왜 필요한가** — 둘 다 잘라내지만 성능이 다르다.

| | Mask | RectMask2D |
|---|---|---|
| 모양 | 스프라이트 모양 | **사각형만** |
| 원리 | 스텐실 버퍼 | 셰이더 클리핑 |
| 성능 | 무거움 (드로우 콜 +2) | **가벼움** |
| 배칭 | 깨짐 | 유지 |
| 용도 | 원형·특수 모양 | **일반 스크롤** ★ |

```
   ★ 스크롤 뷰에는 RectMask2D를 쓴다

   기본 Scroll View 템플릿은 Mask를 쓴다
   → 바꿔 주는 것이 좋다
```

```
   ⚠️ RectMask2D는 회전한 UI를 제대로 못 자른다

   회전이 필요하면 Mask
```

### 3-11. 손패 직접 배치 (부채꼴)

**왜 필요한가** — Layout Group으로 안 되는 것.

```csharp
public class HandLayout : MonoBehaviour
{
    [Header("배치")]
    [SerializeField] private float maxWidth = 900f;
    [SerializeField] private float cardSpacing = 180f;
    [SerializeField] private float arcHeight = 40f;
    [SerializeField] private float maxAngle = 12f;

    [Header("애니메이션")]
    [SerializeField] private float moveSpeed = 12f;

    private readonly List<RectTransform> cards = new List<RectTransform>();

    public void Add(RectTransform card)
    {
        card.SetParent(transform, false);      // ★ false
        cards.Add(card);
    }

    public void Remove(RectTransform card)
    {
        cards.Remove(card);
    }

    void Update()
    {
        int n = cards.Count;
        if (n == 0) return;

        // ★ 넘치면 간격을 줄인다
        float spacing = cardSpacing;
        float total = (n - 1) * spacing;

        if (total > maxWidth) spacing = maxWidth / (n - 1);

        float startX = -(n - 1) * spacing * 0.5f;

        for (int i = 0; i < n; i++)
        {
            RectTransform c = cards[i];
            if (c == null) continue;

            // ★ 중앙에서의 거리 비율 (-1 ~ 1)
            float t = (n == 1) ? 0f : (i / (float)(n - 1)) * 2f - 1f;

            Vector2 target = new Vector2(
                startX + i * spacing,
                -Mathf.Abs(t) * arcHeight);    // ★ 양 끝이 아래로

            float angle = -t * maxAngle;       // ★ 부채꼴 회전

            // 부드럽게 이동
            c.anchoredPosition = Vector2.Lerp(
                c.anchoredPosition, target, moveSpeed * Time.deltaTime);

            c.localRotation = Quaternion.Lerp(
                c.localRotation, Quaternion.Euler(0, 0, angle),
                moveSpeed * Time.deltaTime);

            c.SetSiblingIndex(i);              // ★ 그리기 순서
        }
    }
}
```

```
   부채꼴 배치

        ▣▣▣▣▣
      ▣         ▣
     ↑ t=-1    t=+1 ↑
     아래로     아래로

   t = 중앙에서의 거리 (-1 ~ 1)
   y = -|t| × arcHeight
   각도 = -t × maxAngle
```

```
   ★ Vector2.Lerp로 부드럽게

   Day 64·72에서 쓴 선형 보간
```

### 3-12. 정렬 순서 (Sibling Index)

**왜 필요한가** — 카드가 겹칠 때 순서가 중요하다.

```csharp
    card.transform.SetSiblingIndex(i);         // 위치 지정
    card.transform.SetAsFirstSibling();        // 맨 뒤로
    card.transform.SetAsLastSibling();         // 맨 앞으로
```

```
   ★ UI 그리기 순서 = Hierarchy 순서

   [0] 먼저 그림  = 아래
   [1]
   [2] 나중에 그림 = 위
```


### Step 7 — 마우스 오버 강조

```csharp
using UnityEngine;
using UnityEngine.EventSystems;

public class CardHover : MonoBehaviour,
    IPointerEnterHandler, IPointerExitHandler
{
    [SerializeField] private float hoverScale = 1.15f;
    [SerializeField] private float hoverLift = 40f;
    [SerializeField] private float speed = 14f;

    private RectTransform rt;
    private int originalIndex;
    private bool hovering;

    private Vector2 extraOffset;
    private float extraScale = 1f;

    void Awake() { rt = GetComponent<RectTransform>(); }

    public void OnPointerEnter(PointerEventData e)
    {
        hovering = true;
        originalIndex = rt.GetSiblingIndex();
        rt.SetAsLastSibling();                 // ★ 맨 앞으로
    }

    public void OnPointerExit(PointerEventData e)
    {
        hovering = false;
        rt.SetSiblingIndex(originalIndex);
    }

    void Update()
    {
        float targetScale = hovering ? hoverScale : 1f;
        float targetLift  = hovering ? hoverLift : 0f;

        extraScale = Mathf.Lerp(extraScale, targetScale, speed * Time.deltaTime);
        extraOffset = Vector2.Lerp(extraOffset, new Vector2(0, targetLift),
                                   speed * Time.deltaTime);

        rt.localScale = Vector3.one * extraScale;
    }

    public Vector2 ExtraOffset => extraOffset;
}
```

## 6. 자주 막히는 곳

| 증상 | 원인 | 해결 |
|---|---|---|
| 카드가 겹침 | Spacing 0 또는 영역 초과 | Spacing 조절, 직접 배치 |
| 카드가 영역을 넘침 | Layout Group 한계 | Control Child Size 또는 직접 계산 |
| **추가 직후 위치가 0** | 레이아웃 갱신 지연 | `ForceRebuildLayoutImmediate` |
| **스크롤이 안 됨** | Content 높이 0 | Content Size Fitter |
| 스크롤이 반대로 | Content Pivot | (0.5, 1) |
| 목록이 아래에서 쌓임 | Pivot / Start Corner | 상단 기준으로 |
| SetParent 후 크기 튐 | `worldPositionStays` | `SetParent(p, false)` |
| Grid에서 크기 설정 무시 | Cell Size 강제 | Grid는 Cell Size로만 |
| 자식 위치를 코드로 못 바꿈 | 그룹이 통제 | Ignore Layout 또는 그룹 제거 |
| 크기가 0이 되거나 진동 | 순환 참조 | Fitter 자식에 stretch 금지 |
| 매우 느림 | 매 프레임 레이아웃 갱신 | 직접 계산으로 전환 |
| 배치가 많음 | Mask 사용 | RectMask2D |
| 호버가 순서를 못 바꿈 | 그룹이 매 프레임 재정렬 | 예외 처리 |

## 7. 정리

### 오늘 배운 것

| 개념 | 한 줄 요약 |
|---|---|
| **Horizontal/Vertical LG** | 자식을 한 줄로 자동 배치 |
| **Grid Layout Group** | 격자. Cell Size 강제 |
| Control Child Size | 자식 크기를 그룹이 결정 |
| Child Force Expand | 남는 공간 균등 분배 |
| **Layout Element** | Min → Preferred → Flexible 순 배분 |
| Ignore Layout | 레이아웃에서 제외 |
| **Content Size Fitter** | 내용에 맞춰 크기 자동. 스크롤에 필수 |
| **갱신 타이밍** | 프레임 끝. `ForceRebuildLayoutImmediate` |
