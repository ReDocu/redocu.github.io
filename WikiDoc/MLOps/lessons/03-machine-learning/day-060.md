## ② 왜 필요한가

이번 주 내내 우리 발밑에 있던 문제를 정면으로 다룹니다. 우리 데이터의 나쁨은 15%,
그래서 **"아무것도 안 하는 모델"의 정확도가 86.1%** 였습니다. 실무의 불균형은 더 심합니다.

| 문제 | 양성 비율 |
|---|---|
| 카드 사기 탐지 | 0.1~0.5% |
| 제조 불량 검출 | 1% 미만 |
| 희귀 질환 스크리닝 | 1% 미만 |
| 이탈 예측 | 2~10% |
| **우리: 내일 나쁨** | **15%** |

사기 탐지에서 "전부 정상" 모델의 정확도는 **99.9%** 입니다. 실무 분류 문제의 태반이 불균형이고,
불균형을 다루지 못하면 "높은 정확도의 쓸모없는 모델"을 만들게 됩니다. 금요일 종합 실습으로
이만한 주제가 없습니다 — 이번 주에 배운 지표(057)·모델(058-059)·임계값(056)이 전부 동원됩니다.

## ③ 개념 설명

### 불균형이 망가뜨리는 세 가지

| 무엇이 | 어떻게 | 우리가 본 증거 |
|---|---|---|
| **정확도** | 다수 클래스만 맞혀도 고득점 | 전부-아님 = 0.861 ([Day 056](day-056.md)) |
| **기본 임계값 0.5** | 소수 클래스 확률은 원래 낮게 형성 → 0.5를 잘 못 넘음 | 로지스틱@0.5 재현율 0.339 |
| **학습의 무게** | 손실에서 다수 클래스 오차가 지배 → 경계가 다수 쪽에 유리하게 그어짐 | 고농도 과소예측 경향 |

### 대응 도구 상자

| 도구 | 하는 일 | 코드 |
|---|---|---|
| ① 지표 교체 | 정확도 대신 P/R/F1/PR-AUC로 채점 | [Day 057](day-057.md) |
| ② 임계값 조정 | 결정 단계에서 소수 클래스에 유리하게 | `proba >= 0.2` ([Day 056](day-056.md)) |
| ③ 클래스 가중치 | **손실 함수**에서 소수 클래스 오차를 크게 벌점 | `class_weight="balanced"` |
| ④ 리샘플링 | **데이터**에서 비율을 맞춤 (소수 복제=오버 / 다수 삭제=언더) | `resample(...)` |

미리 말해 두면 — 오늘 실험의 결론은 "④가 최신 기법이니 최고" 같은 것이 아닙니다.
**②③④는 사실상 같은 일(오류 비용의 재배분)을 다른 자리에서 하는 것**임을 보게 됩니다.

### ROC-AUC와 PR-AUC

불균형이 심할수록 ROC-AUC는 후해 보입니다 — 가로축(헛경보율)의 분모가 거대한 다수 클래스라,
헛경보가 수백 건 늘어도 곡선이 거의 안 움직이기 때문입니다. **PR-AUC**(평균 정밀도)는
두 축이 모두 양성 기준이라 소수 클래스 성능을 정직하게 반영합니다.
불균형 문제의 보고서에는 둘을 나란히 적는 것이 안전합니다.

## ④ 단계별 실습 — 불균형 분류 미니 리포트

산출물은 `day060_imbalance.py` 와 `imbalance_report.md` 입니다.

### 문제 1. 네 가지 대응을 같은 조건에서 재기 (1~3교시)

임계값을 0.5로 고정하고, ①그대로 ②가중치 ③오버샘플링 ④언더샘플링을 비교합니다.

```python
# day060_imbalance.py — 클래스 불균형 대응 비교
import numpy as np
import pandas as pd
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import (average_precision_score, f1_score, precision_score,
                             recall_score, roc_auc_score)
from sklearn.preprocessing import StandardScaler
from sklearn.utils import resample

pd.set_option("display.width", 140)
df = pd.read_csv("data/air_daily.csv", parse_dates=["date"])
F10 = ["pm10", "pm25", "o3", "no2", "co", "so2", "temp", "humidity", "wind_speed", "precip"]
d = df.dropna(subset=F10).copy()
d["bad_next"] = (d.pm25_next >= 36).astype(int)
tr = d[d.date < "2026-01-01"]; te = d[d.date >= "2026-01-01"]
ytr, yte = tr.bad_next, te.bad_next
sc = StandardScaler().fit(tr[F10])
Xtr, Xte = sc.transform(tr[F10]), sc.transform(te[F10])

def row(name, clf, X_train, y_train):
    m = clf.fit(X_train, y_train)
    pr = m.predict_proba(Xte)[:, 1]
    p05 = (pr >= 0.5).astype(int)
    print(f"| {name:<20} | {precision_score(yte, p05):.3f} | {recall_score(yte, p05):.3f} | "
          f"{f1_score(yte, p05):.3f} | {roc_auc_score(yte, pr):.3f} | {average_precision_score(yte, pr):.3f} |")

print("== A. 네 가지 대응 비교 (임계값 0.5 고정) ==")
print("| 방법 | 정밀도 | 재현율 | F1 | ROC-AUC | PR-AUC |")
print("|---|---|---|---|---|---|")
row("① 그대로", LogisticRegression(max_iter=5000), Xtr, ytr)
row("② class_weight", LogisticRegression(max_iter=5000, class_weight="balanced"), Xtr, ytr)

# ③ 오버샘플링: 소수 클래스를 복제해 수를 맞춤
tr_maj = tr[tr.bad_next == 0]; tr_min = tr[tr.bad_next == 1]
tr_over = pd.concat([tr_maj, resample(tr_min, n_samples=len(tr_maj), random_state=42)])
row("③ 오버샘플링", LogisticRegression(max_iter=5000), sc.transform(tr_over[F10]), tr_over.bad_next)

# ④ 언더샘플링: 다수 클래스를 버려서 수를 맞춤
tr_under = pd.concat([resample(tr_maj, n_samples=len(tr_min), random_state=42), tr_min])
row("④ 언더샘플링", LogisticRegression(max_iter=5000), sc.transform(tr_under[F10]), tr_under.bad_next)

print(f"\n(train 구성: 아님 {len(tr_maj)} / 나쁨 {len(tr_min)} → 오버샘플링 후 {len(tr_over)}행, 언더샘플링 후 {len(tr_under)}행)")
```

실행 결과:

```
== A. 네 가지 대응 비교 (임계값 0.5 고정) ==
| 방법 | 정밀도 | 재현율 | F1 | ROC-AUC | PR-AUC |
|---|---|---|---|---|---|
| ① 그대로                | 0.446 | 0.339 | 0.385 | 0.818 | 0.428 |
| ② class_weight       | 0.319 | 0.736 | 0.445 | 0.819 | 0.424 |
| ③ 오버샘플링              | 0.313 | 0.736 | 0.440 | 0.819 | 0.422 |
| ④ 언더샘플링              | 0.313 | 0.636 | 0.420 | 0.809 | 0.404 |

(train 구성: 아님 2227 / 나쁨 402 → 오버샘플링 후 4454행, 언더샘플링 후 804행)
```

표를 뜯어 읽습니다.

| 관찰 | 해석 |
|---|---|
| ②③이 거의 동일 (재현율 0.736) | 가중치 = "복제하는 대신 벌점을 키움". **수학적으로 같은 일**이라 결과도 같음 |
| ④만 뒤처짐 (0.636, AUC도 하락) | 다수 클래스 1,825행을 **버렸기 때문** — 정보 손실. 언더샘플링은 데이터가 넘칠 때의 절약술 |
| **ROC-AUC가 넷 다 0.81~0.82** | 가중치·리샘플링이 **확률의 순서는 거의 안 바꿈** — 바뀐 건 확률의 **눈금**뿐 |

마지막 줄이 오늘의 복선입니다. 순서가 안 바뀌었는데 재현율이 두 배가 됐다? 그럼 이건 사실…

### 문제 2. 정체 폭로 — 가중치 ≈ 임계값 이동 (4교시)

②(가중치)와 같은 재현율을, ①(그대로)의 **임계값 조정만으로** 만들 수 있는지 봅니다.

```python
print("\n== B. 같은 재현율에서 비교: 그대로 + 임계값 조정 ==")
m1 = LogisticRegression(max_iter=5000).fit(Xtr, ytr)
pr1 = m1.predict_proba(Xte)[:, 1]
m2 = LogisticRegression(max_iter=5000, class_weight="balanced").fit(Xtr, ytr)
r_target = recall_score(yte, (m2.predict_proba(Xte)[:, 1] >= 0.5).astype(int))
for t in np.arange(0.5, 0.0, -0.01):
    p_t = (pr1 >= t).astype(int)
    if recall_score(yte, p_t) >= r_target:
        print(f"weighted@0.5 재현율 {r_target:.3f} ≈ 그대로@{t:.2f} → 정밀도 {precision_score(yte, p_t):.3f} (weighted 정밀도 {precision_score(yte, (m2.predict_proba(Xte)[:,1]>=0.5).astype(int)):.3f})")
        break
```

실행 결과:

```
== B. 같은 재현율에서 비교: 그대로 + 임계값 조정 ==
weighted@0.5 재현율 0.736 ≈ 그대로@0.15 → 정밀도 0.302 (weighted 정밀도 0.319)
```

그대로 모델의 임계값을 0.15로 내리니 재현율 0.736에 정밀도 0.302 — 가중치 모델(0.319)과
**사실상 같은 지점**입니다. 정리하면:

> **임계값 조정 · 클래스 가중치 · 오버샘플링은 "오류 비용의 재배분"이라는 같은 일을
> 결정 단계 · 손실 함수 · 데이터에서 각각 수행하는 것**입니다. 로지스틱처럼 매끈한 모델에서는
> 결과도 거의 같습니다. 그러니 유행하는 리샘플링 기법을 좇기 전에, 훨씬 싸고 투명한
> 임계값부터 조정해 보세요. (단, 트리 계열은 학습 중 분할 자체가 바뀌므로 가중치·리샘플링이
> 임계값과 다른 결과를 낼 수 있습니다 — 그래서 "실험으로 비교"가 항상 정답입니다.)

### 문제 3. 표본 2개짜리 클래스 — 모델링을 거부할 용기 (5교시)

'매우나쁨'(pm25 ≥ 76) 경보 모델을 만들어 달라는 요청이 왔다고 합시다.

```python
print("\n== C. '매우나쁨'(>=76) — 표본 2개짜리 클래스 ==")
d["vbad_next"] = (d.pm25_next >= 76).astype(int)
print(f"전체 {len(d)}행 중 매우나쁨 {d.vbad_next.sum()}건")
print(d[d.vbad_next == 1][["date", "station", "pm25", "pm25_next"]].to_string(index=False))
tr2 = d[d.date < "2026-01-01"]; te2 = d[d.date >= "2026-01-01"]
print(f"train에 {tr2.vbad_next.sum()}건 / test에 {te2.vbad_next.sum()}건")
```

실행 결과:

```
== C. '매우나쁨'(>=76) — 표본 2개짜리 클래스 ==
전체 3497행 중 매우나쁨 2건
      date station  pm25  pm25_next
2024-11-08     강남구  70.7       80.3
2024-11-08     서초구  66.2       77.8
train에 2건 / test에 0건
```

2년치 데이터에 **양성이 2건**, 그마저 **같은 날**(2024-11-08 에피소드)의 두 측정소입니다.
사실상 사건 1개. test에는 0건이라 **평가 자체가 불가능**합니다. 여기서 가중치를 만 배로 주든
2건을 천 번 복제하든, 사건 1개를 외운 모델이 나올 뿐입니다.

이럴 때 엔지니어의 정답은 모델링이 아니라 **문제 재정의**입니다.

| 선택지 | 내용 |
|---|---|
| 문턱 완화 | "매우나쁨 예보" 대신 **나쁨 예보(15%)를 잘 만들고**, 그 확률이 극단일 때 강한 경보 |
| 연속값 활용 | 회귀 예측값(pm25_next)이 60을 넘으면 운영 경보 — 분류 클래스가 필요 없음 |
| 이상 탐지 관점 | "정상 분포에서 얼마나 벗어났나"로 접근 (별도 과정의 주제) |
| 데이터 축적 | 몇 년 더 모을 때까지 이 클래스의 자동 예보를 **하지 않겠다고 문서화** |

"안 됩니다"를 근거와 대안과 함께 말하는 것 — 이것도 MP2 평가 항목(방법론 적절성)입니다.

### 오늘 새로 나오는 실수

**리샘플링을 분리 전에 함** — 전체 데이터를 오버샘플링한 뒤 train/test를 나누면, **복제된 같은 행이
train과 test 양쪽에** 들어갑니다. 소수 클래스 점수가 거의 만점으로 뻥튀기되는 유명한 누수입니다.
순서는 언제나: 분리 먼저, 리샘플링은 train만.

**test까지 리샘플링함** — test는 실제 세상의 비율(15%)이어야 합니다. 비율을 조작한 test 점수는
아무 운영 상황도 대변하지 않습니다.

**가중치와 리샘플링을 중복 적용** — `class_weight="balanced"` + 오버샘플링을 같이 걸면 보정이
이중으로 들어가 소수 클래스로 과하게 쏠립니다. 하나만 고르세요.

**희귀 클래스에 무조건 SMOTE류 기법부터 검색** — 문제 3에서 봤듯 표본 자체가 사건 1~2개면
어떤 생성 기법도 정보를 만들어내지 못합니다. 기법 검색 전에 **표본 수를 세어 보세요.**

## ⑥ 확인 문제

**Q1.** 문제 1에서 class_weight와 오버샘플링의 결과가 거의 같았던 이유와, 언더샘플링만 뒤처진 이유를
각각 한 문장으로 쓰세요.

<details>
<summary>답 보기</summary>

가중치는 "소수 표본의 오차 벌점을 키우는 것", 오버샘플링은 "소수 표본을 복제해 벌점 횟수를 늘리는 것"이라
손실 함수 입장에서 수학적으로 같은 조작이기 때문입니다. 언더샘플링은 다수 클래스 1,825행의 정보를
실제로 버리므로 확률 품질 자체(AUC 0.809)가 떨어집니다.

</details>

**Q2.** 네 방법 모두 ROC-AUC가 0.81~0.82로 거의 같았습니다. 이 사실에서 "불균형 대응"의 본질에 대해
무엇을 알 수 있나요?

<details>
<summary>답 보기</summary>

가중치·리샘플링이 **확률의 순서(모델의 분별력)는 거의 바꾸지 못하고**, 확률의 눈금을 밀어 임계값 0.5에서의
결정만 바꾼다는 것입니다. 즉 이 도구들의 본질은 분별력 향상이 아니라 **오류 비용의 재배분**이고,
같은 효과는 임계값 조정으로도 얻을 수 있습니다(문제 2). 분별력 자체를 올리려면 특성과 모델을 개선해야 합니다.

</details>

**Q3.** 동료가 전체 데이터를 SMOTE로 증강한 뒤 train/test를 나눠 "재현율 0.98"을 보고했습니다.
무엇이 잘못됐고, 올바른 순서는 무엇인가요?

<details>
<summary>답 보기</summary>

증강(복제·합성)을 분리 **전에** 해서, 같은 원본에서 나온 표본이 train과 test에 동시에 들어갔습니다 —
[Day 052](day-052.md)의 시점 누수와 같은 부류의 누수라 점수가 뻥튀기된 것입니다.
올바른 순서: ① train/test 분리(시계열이면 시간 기준) → ② train에만 리샘플링 → ③ 원본 그대로의 test로 평가.

</details>

## 주간 퀴즈 11 — W12 (분류와 트리 계열)

<details>
<summary>1. predict와 predict_proba의 관계는?</summary>

`predict` = `predict_proba` 의 양성 확률에 **임계값 0.5를 적용한 것**. 0.5는 비용 중립 가정의 기본값일 뿐입니다.

</details>

<details>
<summary>2. 정밀도와 재현율의 분모는 각각 무엇인가?</summary>

정밀도의 분모는 **양성이라 예측한 것**(TP+FP), 재현율의 분모는 **실제 양성**(TP+FN)입니다.

</details>

<details>
<summary>3. F1이 산술평균이 아니라 조화평균인 이유는?</summary>

조화평균은 작은 쪽에 끌려가므로, 정밀도나 재현율 한쪽을 포기한 극단 전략("전부 경보" 등)에 높은 점수를 주지 않기 때문입니다.

</details>

<details>
<summary>4. AUC 0.8의 확률적 해석은?</summary>

무작위로 뽑은 (양성, 음성) 쌍에서 양성 쪽에 더 높은 확률을 부여할 확률이 80%라는 뜻입니다. 임계값과 무관한 순서 품질 점수입니다.

</details>

<details>
<summary>5. 결정 트리 분할의 선택 기준은?</summary>

모든 (특성, 문턱) 후보 중 **분할 후 불순도(지니 등)를 가장 크게 줄이는** 것을 고릅니다.

</details>

<details>
<summary>6. 트리에 스케일링이 필요 없는 이유는?</summary>

분할은 "값이 문턱보다 큰가?"라는 **순서 비교**만 쓰므로, 단조 변환(스케일링)에 결과가 불변입니다.

</details>

<details>
<summary>7. 배깅이 과적합을 줄이는 원리는?</summary>

부트스트랩 표본과 특성 무작위화로 서로 다르게 과적합한 트리들을 만들어 평균 내면, 제각각인 노이즈(분산)는 상쇄되고 공통 구조만 남기 때문입니다.

</details>

<details>
<summary>8. 배깅과 부스팅에서 "나무 수 증가"의 효과 차이는?</summary>

배깅은 손해 없음(수확 체감), 부스팅은 **과적합 가능**(오답 보정이 노이즈 학습으로 변질) — 그래서 부스팅엔 조기 종료를 씁니다.

</details>

<details>
<summary>9. 불균형 문제에서 ROC-AUC 대신/과 함께 봐야 할 곡선 지표와 이유는?</summary>

**PR-AUC(평균 정밀도).** ROC의 헛경보율은 거대한 음성 클래스가 분모라 불균형에서 후해 보이지만, PR은 두 축이 모두 양성 기준이라 소수 클래스 성능을 정직하게 보여줍니다.

</details>

<details>
<summary>10. 클래스 가중치·오버샘플링·임계값 조정의 공통 본질은?</summary>

**오류 비용의 재배분** — 각각 손실 함수·데이터·결정 단계에서 같은 일을 합니다. 모델의 분별력(확률 순서)은 거의 바꾸지 않습니다.

</details>

## 오늘의 정리

- 불균형에서 정확도는 버리고, **양성 클래스 기준 지표**(P/R/F1/PR-AUC)로 채점합니다.
- 가중치·리샘플링·임계값은 **같은 손잡이의 세 위치** — 싸고 투명한 임계값부터.
- 언더샘플링은 정보를 버리고, 리샘플링은 반드시 **분리 후 train에만**.
- 표본 2개짜리 클래스는 모델이 아니라 **문제 정의를 바꿔야** 합니다.
- 다음 주: 점수의 신뢰도(교차검증)와 자동 튜닝, 그리고 이 모든 것을 담는 Pipeline.
