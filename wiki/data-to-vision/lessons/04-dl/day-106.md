## ② 왜 필요한가

### 어제까지 만든 모델은 이 질문에 답할 수 없습니다

[Day 105](../03-ml/day-105.md)에서 여러분은 늑대와 허스키를 88% 정확도로 구분하는 모델을 만들었습니다.

이제 이런 요청이 들어왔다고 합시다.

> **"이 게임, 다음 세일 때 얼마에 팔릴 것 같아?"**

CNN 모델로 답할 수 있습니까? 없습니다. 구조 자체가 다릅니다.

```python
# 분류 모델의 출력
model.predict(x)      # → [0.12, 0.88]     "88% 확률로 허스키"

# 우리에게 필요한 출력
model.predict(x)      # → 12347.8          "12,347원"
```

분류 모델은 **정해진 선택지 중 하나를 고릅니다.** 선택지가 2개면 출력 노드도 2개입니다.
그런데 가격은 선택지가 없습니다. 12,347원일 수도, 12,348원일 수도 있습니다.

**출력이 "고르는 것"에서 "재는 것"으로 바뀝니다.** 이것이 회귀입니다.

### 채점표가 사라집니다

분류에서는 채점이 간단했습니다.

```
정답: 허스키    예측: 허스키    →  ○
정답: 허스키    예측: 늑대      →  ✗
                                   100장 중 88장 맞음 → 88%
```

회귀에서는 이 채점이 불가능합니다.

```
정답: 12,000원   예측: 12,347원   →  ?
정답: 12,000원   예측: 11,980원   →  ?
정답:  3,000원   예측:  9,400원   →  ?
```

**세 번째는 확실히 틀렸습니다. 앞의 둘은 뭐라고 해야 합니까?**

"정확도"라는 개념이 성립하지 않습니다. 대신 이렇게 말해야 합니다.

```
평균적으로 347원씩 빗나갑니다.       ← MAE
가끔 크게 빗나가는 경우가 있습니다.   ← RMSE가 MAE보다 훨씬 큼
```

> **오늘 배우는 손실 함수가 바로 이 "빗나감을 재는 자"입니다.**
> 그리고 **어떤 자를 쓰느냐에 따라 모델이 다르게 학습됩니다.** 이것을 눈으로 확인하는 것이 오늘의 실습입니다.

### 손실 함수 하나로 결과가 뒤집히는 사례

같은 데이터, 같은 모델 구조, 손실 함수만 다르게 학습시킨 결과입니다.

```
데이터: 정상 데이터 100건 + 극단적 이상치 5건

MSE로 학습    → 예측선이 이상치 쪽으로 끌려감.  정상 구간 오차 커짐
MAE로 학습    → 이상치를 무시하고 정상 구간에 맞음
Huber로 학습  → 그 중간
```

**"어떤 손실 함수를 쓸까"는 취향 문제가 아닙니다.**
데이터에 이상치가 있는지, 그 이상치가 진짜 값인지 오류인지에 따라 답이 정해집니다.

스팀 가격 예측 프로젝트([Day 126](day-126.md))에서 이 판단을 직접 해야 합니다.
**무료 게임(0원)과 초고가 번들(50만 원)이 같은 데이터에 섞여 있기 때문입니다.**

### 오늘의 목표를 한 줄로

> **"이 문제의 출력층은 노드 1개 · 활성화 없음이고, 손실 함수는 ○○를 쓰겠다. 왜냐하면 ○○이기 때문이다."**
> 이 문장을 근거를 대며 말할 수 있게 되는 것.

## ③ 개념 설명

### 분류 vs 회귀 — 판단 기준

| | 분류 (Classification) | 회귀 (Regression) |
|---|---|---|
| 출력 | **범주** (고양이/개, 스팸/정상) | **연속된 수** (가격, 온도, 시간) |
| 출력층 노드 수 | 클래스 수 (이진은 1개도 가능) | **1개** |
| 출력층 활성화 | Softmax (다중) / Sigmoid (이진) | **없음 (linear)** |
| 손실 함수 | 크로스엔트로피 | **MSE / MAE / Huber** |
| 평가 지표 | 정확도, F1, AUC | **MAE, RMSE, R²** |
| "정답에 가깝다" | 개념 없음 (맞거나 틀림) | **있음** (오차의 크기) |

**판단이 애매한 경우들**

| 문제 | 답 | 이유 |
|---|---|---|
| 별점 예측 (1~5) | **둘 다 가능** | 1과 5의 "거리"가 의미 있으면 회귀, 아니면 분류 |
| 나이 예측 | 보통 **회귀** | 25살을 24로 예측한 것과 60으로 예측한 것은 다름 |
| 티셔츠 사이즈 (S/M/L) | **분류** (순서형) | S와 L 사이에 "1.5배" 같은 관계가 없음 |
| 내일 비가 올 확률 | **분류** (출력이 확률) | 0~1 범위의 확률. Sigmoid |
| 내일 강수량(mm) | **회귀** | 연속값. 0 이상 제약 필요 |
| 고장까지 남은 시간 | **회귀** | 생존 분석이라는 전용 분야도 있음 |

> **핵심 질문 하나** — **"예측값과 정답의 차이를 뺄셈으로 계산하는 것이 의미가 있는가?"**
> 의미가 있으면 회귀입니다. "고양이 - 개 = ?"는 말이 안 되므로 분류입니다.

### 회귀 문제 4가지 유형

| 유형 | 예시 | 특징 |
|---|---|---|
| **가격 예측** | 집값, 중고차, **게임 세일가** | 타깃 분포가 오른쪽으로 치우침(왜도) → 로그 변환 필요 |
| **수요 예측** | 판매량, 방문자 수, 전력 사용량 | 음수 불가. 시계열인 경우가 많음 |
| **물리량 예측** | 기온, 습도, 농도 | 범위가 정해짐. 단위가 명확 |
| **잔여 수명** | 기계 고장까지 남은 시간 | 0 이상. 검열(censoring) 데이터 문제 |

> **우리 프로젝트는 첫 번째 유형입니다.** 그래서 [Day 111](day-111.md)의 **로그 변환**이 중요해집니다.

### 출력층 설계 — 이 단원에서 가장 자주 틀리는 곳

```python
# 분류 (3클래스)
Dense(3, activation="softmax")

# 이진 분류
Dense(1, activation="sigmoid")

# ★ 회귀
Dense(1)                       # 활성화 함수를 아예 안 씁니다
```

**왜 활성화 함수가 없는가**

| 활성화 함수 | 출력 범위 | 회귀에 쓰면 |
|---|---|---|
| Sigmoid | 0 ~ 1 | **12,000원을 절대 출력 못 함** |
| Softmax | 합이 1 | 확률용. 의미 없음 |
| ReLU | 0 ~ ∞ | 음수를 못 냄 (기온 예측 불가) |
| **없음 (linear)** | **-∞ ~ ∞** | ✓ 어떤 값이든 출력 가능 |

```python
model = Sequential([
    Dense(64, activation="relu", input_shape=(n_features,)),   # 은닉층엔 ReLU
    Dense(32, activation="relu"),                              # 은닉층엔 ReLU
    Dense(1),                                                  # ★ 출력층엔 없음
])
```

> **은닉층의 ReLU와 출력층의 활성화는 역할이 다릅니다.**
> 은닉층 ReLU는 **비선형성**을 넣기 위한 것이고, 출력층 활성화는 **출력 범위를 제한**하는 것입니다.
> 회귀는 범위를 제한할 이유가 없으므로 안 씁니다.

### 예측값에 제약이 필요한 경우

가끔은 범위를 제한해야 합니다.

| 상황 | 문제 | 대응 |
|---|---|---|
| 가격 · 판매량 | 음수가 나오면 안 됨 | ① `ReLU` 출력 ② **로그 변환 후 학습** ③ 사후 `clip` |
| 확률 · 비율 (0~1) | 범위 초과 | Sigmoid 출력 |
| 점수 (0~100) | 범위 초과 | Sigmoid × 100 또는 사후 clip |

**권장 순서**

```
1순위: 타깃을 로그 변환해서 학습  →  expm1로 되돌리면 자동으로 양수
2순위: 사후 clip                 →  np.clip(pred, 0, None)
3순위: ReLU 출력층               →  기울기가 0이 되는 구간이 생겨 학습이 불안정
```

> ⚠️ **ReLU를 출력층에 쓰면 "죽은 예측" 문제가 생깁니다.**
> 예측이 한번 음수 영역으로 가면 기울기가 0이 되어 영영 못 돌아옵니다.
> **로그 변환이 훨씬 안전합니다.** ([Day 111](day-111.md)에서 자세히)

### 손실 함수 ① MSE — 평균 제곱 오차

```
MSE = (1/n) × Σ (실제 - 예측)²
```

| 오차 | 제곱 | 기여도 |
|---|---|---|
| 1 | 1 | 1배 |
| 2 | 4 | 4배 |
| 10 | 100 | **100배** |
| 100 | 10,000 | **10,000배** |

**오차가 10배 커지면 벌점은 100배가 됩니다.** 큰 오차를 극도로 싫어하는 손실 함수입니다.

| 장점 | 단점 |
|---|---|
| 미분이 매끄러움 → 학습이 안정적 | **이상치 하나가 전체를 지배** |
| 수학적으로 다루기 좋음 (최소제곱법) | 단위가 제곱이라 해석이 어려움 (원²) |
| 큰 실수를 확실히 줄여 줌 | |

### 손실 함수 ② MAE — 평균 절대 오차

```
MAE = (1/n) × Σ |실제 - 예측|
```

| 오차 | 절댓값 | 기여도 |
|---|---|---|
| 1 | 1 | 1배 |
| 10 | 10 | 10배 |
| 100 | 100 | 100배 |

**오차가 10배 커지면 벌점도 10배입니다.** 공평합니다.

| 장점 | 단점 |
|---|---|
| **이상치에 강함(robust)** | 0에서 미분 불가 → 학습이 덜 매끄러움 |
| **단위가 원래 값과 같음** (원, ℃) | 큰 오차를 방치할 수 있음 |
| 해석이 쉬움 — "평균 3,200원 빗나감" | 수렴이 느릴 수 있음 |

### 최적 예측값이 다릅니다 — 이것이 본질입니다

**데이터가 [10, 12, 14, 16, 200] 일 때, 하나의 값으로 예측한다면?**

| 손실 함수 | 최적값 | 이유 |
|---|---|---|
| **MSE** | **50.4 (평균)** | 제곱 오차 합을 최소화하는 값은 **평균** |
| **MAE** | **14 (중앙값)** | 절대 오차 합을 최소화하는 값은 **중앙값** |

```
MSE 선택 → 50.4    실제 데이터 대부분(10~16)에서 크게 빗나감
MAE 선택 → 14      200 하나는 크게 틀리지만 나머지 4개는 잘 맞음
```

> **"MSE는 평균을 쫓고, MAE는 중앙값을 쫓는다."**
> 이 한 문장이 오늘의 핵심입니다. 이상치가 있으면 평균이 끌려가고, 중앙값은 안 끌려갑니다.
> [Day 111](day-111.md)에서 "평균 > 중앙값이면 오른쪽 꼬리"를 배울 때 다시 나옵니다.

### 손실 함수 ③ Huber — 둘의 절충

```
        ⎧ ½(실제-예측)²                      |오차| ≤ δ 일 때   (MSE처럼)
Huber = ⎨
        ⎩ δ·|실제-예측| - ½δ²                |오차| > δ 일 때   (MAE처럼)
```

**작은 오차는 MSE처럼, 큰 오차는 MAE처럼 다룹니다.**

```
벌점
  │        MSE ╱
  │          ╱
  │        ╱
  │      ╱ ┄┄┄ Huber (δ 이후 직선)
  │    ╱ ┄┄
  │  ╱┄┄       ─── MAE
  │╱┄
  └──────┼──────────── 오차
         δ
```

| 파라미터 | 의미 | 정하는 법 |
|---|---|---|
| `delta` (δ) | MSE↔MAE 전환점 | **"이 크기부터는 이상치로 본다"는 오차 크기** |

```python
from tensorflow.keras.losses import Huber

model.compile(optimizer="adam", loss=Huber(delta=1.0))
```

> ⚠️ **`delta` 는 타깃의 스케일에 의존합니다.**
> 타깃이 원 단위(수만)인데 `delta=1.0` 이면 거의 모든 오차가 MAE 구간이 됩니다. 사실상 MAE입니다.
> **타깃을 표준화했거나 로그 변환했다면 `delta=1.0` 이 적당합니다.**

### 정리 — 어떤 것을 쓸까

```
① 이상치가 있는가?
      아니오 →  MSE (기본)
      예    →  ②

② 그 이상치가 "오류"인가 "진짜 값"인가?
      오류(측정 실수, 입력 오류)  →  MAE 또는 이상치 제거
      진짜 값(초고가 상품 등)     →  Huber (무시하지도, 지배당하지도 않게)

③ 큰 오차가 특히 치명적인 문제인가? (의료, 안전)
      예 →  MSE (큰 실수를 확실히 줄여야 함)
```

| 상황 | 권장 |
|---|---|
| 깨끗한 데이터, 일반적인 회귀 | **MSE** |
| 이상치가 섞인 실무 데이터 | **Huber** 또는 **MAE** |
| **평가 지표가 MAE인 대회/과제** | **MAE로 학습** (지표와 손실을 맞춤) |
| 큰 오차가 치명적 | **MSE** |

> **"평가 지표와 손실 함수를 맞추라"** 는 실무 원칙이 있습니다.
> MAE로 평가받을 건데 MSE로 학습시키면, 모델은 평가받지 않는 것을 최적화하는 셈입니다.

### metrics는 손실과 별개입니다

```python
model.compile(
    optimizer="adam",
    loss="mse",              # ← 학습에 쓰는 것 (역전파 대상)
    metrics=["mae"],         # ← 사람이 보려고 찍는 것 (학습에 영향 없음)
)
```

| | loss | metrics |
|---|---|---|
| 역할 | **가중치를 갱신하는 기준** | 사람이 읽는 참고 숫자 |
| 미분 가능해야 하나 | **예** | 아니오 |
| 여러 개 가능 | 아니오 (1개) | **예** (리스트) |

> **회귀에서 `metrics=['accuracy']` 를 넣으면 0.0000이 나옵니다.**
> 예측값 12347.8과 정답 12000.0이 **정확히 같지 않기** 때문입니다. 당연히 0입니다.
> 이것이 [README](README.md)의 FAQ 1번 질문입니다. **`metrics=['mae']` 로 바꾸세요.**

| 지표 | 수식 | 단위 | 읽는 법 |
|---|---|---|---|
| **MAE** | 평균 \|오차\| | 원래 단위 | "평균 3,200원 빗나감" |
| **RMSE** | √MSE | 원래 단위 | "제곱평균 4,100원. MAE보다 크면 큰 오차 존재" |
| **R²** | 1 - SSE/SST | 없음 | "1.0이 완벽, 0.0이 평균 예측 수준, 음수면 그보다 못함" |

**오늘은 이것만 기억하세요.**

```
RMSE > MAE 이면 → 큰 오차가 섞여 있다   (항상 RMSE ≥ MAE)
RMSE ≈ MAE 이면 → 오차가 고르게 퍼져 있다
```

```
전체 데이터의 4.8%인 이상치 10건이
나머지 95.2%의 예측 오차를 3.5배로 만들었습니다.
```

> **왜 MSE가 이렇게 되는지 계산으로 확인해 보세요.**
> 이상치 하나의 오차는 약 120 - 5 = 115입니다. 제곱하면 **13,225**입니다.
> 정상 데이터 하나의 오차는 약 2, 제곱하면 4입니다.
> **이상치 1건이 정상 데이터 3,300건과 맞먹는 발언권을 갖습니다.** 10건이면 33,000건입니다.
>
> **모델 입장에서는 이상치를 맞추는 것이 압도적으로 이득입니다.** 그래서 선이 위로 올라갑니다.

> ⚠️ **여기서 "그럼 항상 MAE를 쓰면 되겠네"라고 결론 내리면 안 됩니다.**
> 저 120이라는 값이 **입력 오류**라면 MAE가 맞습니다. 무시해야 할 값이니까요.
> 그런데 저 값이 **진짜 발생하는 사건**이라면? (예: 한정판 게임의 실제 가격)
> **MAE 모델은 그 사건을 영원히 예측하지 못합니다.** 그것도 실패입니다.
>
> **판단은 도메인 지식에서 나옵니다.** [Day 112](day-112.md)에서 이 판단을 정식으로 훈련합니다.

```python
    layers.Dense(1),                              # ★ 회귀 출력층

model.compile(optimizer=keras.optimizers.Adam(learning_rate=1e-3),
              loss="mse",

    X_train_s, y_train,
```

### Step 6. 오늘의 종합 — 손실 함수 비교 실험표

```python
from pathlib import Path

import numpy as np
import pandas as pd
import matplotlib.pyplot as plt
import tensorflow as tf
from tensorflow import keras
from tensorflow.keras import layers
from sklearn.datasets import fetch_california_housing
from sklearn.model_selection import train_test_split
from sklearn.preprocessing import StandardScaler

SEED = 42
np.random.seed(SEED)

housing = fetch_california_housing()
X, y = housing.data, housing.target

X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.2, random_state=SEED)
X_train, X_val, y_train, y_val = train_test_split(X_train, y_train, test_size=0.2, random_state=SEED)

scaler = StandardScaler()
X_train_s = scaler.fit_transform(X_train)
X_val_s = scaler.transform(X_val)


def train_one(loss_name, loss_obj, epochs=60):
    tf.random.set_seed(SEED)
    m = keras.Sequential([
        layers.Input(shape=(X_train_s.shape[1],)),
        layers.Dense(64, activation="relu"),
        layers.Dense(32, activation="relu"),
        layers.Dense(1),
    ])
    m.compile(optimizer=keras.optimizers.Adam(1e-3), loss=loss_obj, metrics=["mae"])
    h = m.fit(X_train_s, y_train, validation_data=(X_val_s, y_val),
              epochs=epochs, batch_size=64, verbose=0)
    pred = m.predict(X_val_s, verbose=0).ravel()
    err = y_val - pred
    return m, h, {
        "손실함수": loss_name,
        "val_MAE": round(float(np.abs(err).mean()), 4),
        "val_RMSE": round(float(np.sqrt((err ** 2).mean())), 4),
        "val_중앙오차": round(float(np.median(np.abs(err))), 4),
        "오차>1.0 건수": int((np.abs(err) > 1.0).sum()),
    }


configs = [
    ("MSE", "mse"),
    ("MAE", "mae"),
    ("Huber(δ=0.5)", keras.losses.Huber(delta=0.5)),
    ("Huber(δ=1.0)", keras.losses.Huber(delta=1.0)),
]

results, histories = [], {}
for name, obj in configs:
    m, h, row = train_one(name, obj)
    results.append(row)
    histories[name] = h

df = pd.DataFrame(results)
df["RMSE-MAE"] = (df["val_RMSE"] - df["val_MAE"]).round(4)

print("=" * 86)
print("손실 함수 비교 — California Housing, 동일 구조·동일 seed")
print("=" * 86)
print(df.to_string(index=False))
print("=" * 86)

best_mae = df.loc[df["val_MAE"].idxmin()]
best_rmse = df.loc[df["val_RMSE"].idxmin()]
print(f"MAE 기준 최고  : {best_mae['손실함수']}  ({best_mae['val_MAE']})")
print(f"RMSE 기준 최고 : {best_rmse['손실함수']}  ({best_rmse['val_RMSE']})")
print("→ 기준을 바꾸면 승자가 바뀝니다. 어떤 지표로 평가할지 먼저 정해야 합니다.")

# ── 실험 기록표 저장 ──
df["관찰"] = [
    "RMSE 최소. 큰 오차를 억제하는 데 유리",

    "MAE에 가까움. δ가 작아 대부분 선형 구간",

]
df["다음_시도"] = [

    "이상치(5.0 상한) 제거 후 비교",
    "delta를 타깃 스케일에 맞춰 재조정",
    "이 설정을 기본으로 채택하고 구조 실험",
]

OUT = Path("dl_course/experiments")
OUT.mkdir(parents=True, exist_ok=True)
df.to_csv(OUT / "day106_loss_comparison.csv", index=False, encoding="utf-8-sig")
print(f"\n저장: {OUT / 'day106_loss_comparison.csv'}")
```

**증상** — 손실이 전혀 줄지 않거나, 예측값이 전부 같은 값(0.5나 1.0)으로 나옵니다.

### `loss` 가 `nan` 이 됨

```

Epoch 2/50  loss: nan

```

**원인 4가지와 확인 순서**

| 순서 | 원인 | 확인 코드 |
|---|---|---|
| 1 | 타깃/입력에 `NaN`·`inf` | `np.isnan(X).sum()`, `np.isinf(X).sum()` |
| 2 | **스케일링 누락** | `X.max()` 가 수만 이상인가 |
| 3 | 학습률 과다 | `1e-3` → `1e-4` 로 낮춰 보기 |
| 4 | 타깃 스케일이 너무 큼 | 타깃도 표준화하거나 로그 변환 |

```python
# 진단 코드
print("X NaN:", np.isnan(X).sum(), " X inf:", np.isinf(X).sum())
print("y NaN:", np.isnan(y).sum(), " y inf:", np.isinf(y).sum())
print("X 범위:", X.min(), "~", X.max())
print("y 범위:", y.min(), "~", y.max())
```

### Huber의 `delta` 를 타깃 스케일과 무관하게 설정

**해결** — `delta` 는 **"이 크기부터 이상치"** 로 보는 오차 크기입니다. 타깃을 표준화했다면 1.0이 적당합니다.

| 로그 변환됨 | **0.5 ~ 1.0** |
| 원 단위 (수만) | **타깃 표준편차의 0.5~1배** |

**3.** 이상치가 손실 함수 선택에 미치는 영향을 **직접 재현**하고 결론을 쓰세요.

① `y = 2x + 3` 관계의 데이터 150건 생성 (노이즈 표준편차 1.5)
② 이상치 비율을 0%, 2%, 5%, 10%, 20%로 바꿔가며 (이상치 y값 = 100)
③ 각 조건에서 MSE·MAE·Huber(δ=1)로 학습
④ **정상 데이터에서의 MAE**를 측정해 표와 그래프로 비교
⑤ "이상치가 몇 %부터 MSE를 쓰면 안 되는가"에 대한 결론

<details>

```python
import numpy as np
import pandas as pd
import matplotlib.pyplot as plt
import tensorflow as tf
from tensorflow import keras
from tensorflow.keras import layers

SEED = 42


def make_data(n_normal=150, outlier_ratio=0.0, seed=SEED):
    """정상 데이터 + 이상치를 섞은 데이터 생성"""
    rng = np.random.default_rng(seed)
    X = rng.uniform(-5, 5, size=(n_normal, 1)).astype("float32")
    y = (2 * X.ravel() + 3 + rng.normal(0, 1.5, size=n_normal)).astype("float32")

    n_out = int(round(n_normal * outlier_ratio))
    if n_out == 0:
        return X, y, X, y, 0

    X_out = rng.uniform(-5, 5, size=(n_out, 1)).astype("float32")
    y_out = np.full(n_out, 100.0, dtype="float32")
    return np.vstack([X, X_out]), np.concatenate([y, y_out]), X, y, n_out


def train(X, y, loss, epochs=300, seed=SEED):
    tf.random.set_seed(seed)
    m = keras.Sequential([layers.Input(shape=(1,)), layers.Dense(1)])
    m.compile(optimizer=keras.optimizers.Adam(0.1), loss=loss)
    m.fit(X, y, epochs=epochs, verbose=0)
    w, b = m.layers[0].get_weights()
    return m, float(w[0][0]), float(b[0])


ratios = [0.0, 0.02, 0.05, 0.10, 0.20]
loss_defs = [("MSE", "mse"), ("MAE", "mae"),
             ("Huber(δ=1)", keras.losses.Huber(delta=1.0))]

rows = []
for r in ratios:
    X_all, y_all, X_clean, y_clean, n_out = make_data(outlier_ratio=r)
    for lname, lobj in loss_defs:
        m, w, b = train(X_all, y_all, lobj)
        pred_clean = m.predict(X_clean, verbose=0).ravel()
        rows.append({
            "이상치비율": f"{r*100:.0f}%",
            "이상치수": n_out,
            "손실함수": lname,
            "w": round(w, 3),
            "b": round(b, 3),
            "정상MAE": round(float(np.abs(y_clean - pred_clean).mean()), 3),
        })

df = pd.DataFrame(rows)

print("=" * 78)
print("이상치 비율 × 손실 함수 — 정상 데이터에서의 MAE (정답 w=2, b=3)")
print("=" * 78)
pivot = df.pivot(index="이상치비율", columns="손실함수", values="정상MAE")
pivot = pivot.reindex([f"{r*100:.0f}%" for r in ratios])
pivot = pivot[["MSE", "MAE", "Huber(δ=1)"]]
print(pivot.to_string())
print("=" * 78)

print("\n[학습된 절편 b의 변화] — 정답은 3.0")
pivot_b = df.pivot(index="이상치비율", columns="손실함수", values="b")
pivot_b = pivot_b.reindex([f"{r*100:.0f}%" for r in ratios])[["MSE", "MAE", "Huber(δ=1)"]]
print(pivot_b.to_string())

print("\n[MSE의 성능 저하 배수] — 이상치 0% 대비")
base = pivot.loc["0%", "MSE"]
for r in ratios:
    key = f"{r*100:.0f}%"
    print(f"  {key:>4} : {pivot.loc[key, 'MSE'] / base:>5.2f}배   "
          f"(MAE는 {pivot.loc[key, 'MAE'] / pivot.loc['0%', 'MAE']:.2f}배)")

# ── 그래프 ──
fig, axes = plt.subplots(1, 2, figsize=(15, 5))

ax = axes[0]
xs = [r * 100 for r in ratios]
for lname in ["MSE", "MAE", "Huber(δ=1)"]:
    ax.plot(xs, pivot[lname].values, "o-", linewidth=2.2, markersize=7, label=lname)
ax.set_xlabel("outlier ratio (%)")
ax.set_ylabel("MAE on normal data")
ax.set_title("MSE degrades fast; MAE barely moves")
ax.legend()

ax = axes[1]
for lname in ["MSE", "MAE", "Huber(δ=1)"]:
    ax.plot(xs, pivot_b[lname].values, "o-", linewidth=2.2, markersize=7, label=lname)
ax.axhline(3.0, color="black", linestyle="--", alpha=0.7, label="true b=3")
ax.set_xlabel("outlier ratio (%)")
ax.set_ylabel("learned intercept b")
ax.set_title("Intercept gets dragged upward under MSE")
ax.legend()

fig.tight_layout()
plt.show()
```

```
   10% :  7.92배   (MAE는 1.03배)
   20% : 12.84배   (MAE는 1.07배)
```

**⑤ 결론**

| 이상치 비율 | MSE 상태 | 권장 |
|---|---|---|
| 0% | 정상 (MAE와 동일) | **MSE** — 학습이 매끄러움 |
| **~2%** | 이미 2.5배 나빠짐 | **Huber** |
| 5% | 4.8배 | **Huber 또는 MAE** |
| 10% 이상 | 8배 이상. 사실상 사용 불가 | **MAE** + 이상치 처리 |

**결론 문장** — **이상치가 2%만 있어도 MSE는 쓰면 안 됩니다.**
"5% 정도는 괜찮겠지"라는 직관이 틀렸다는 것이 이 실험의 핵심입니다.

**추가로 읽어야 할 3가지**

- **MAE는 20%에서도 거의 흔들리지 않습니다 (1.07배).**
  이상치가 20%면 5건 중 1건인데도 중앙값은 잘 버팁니다. **중앙값의 강건성**입니다.

- **Huber는 10%까지는 MAE와 비슷하다가 20%에서 무너집니다 (2.89).**
  이상치가 너무 많으면 δ 안쪽으로 들어오는 오차가 늘어나 MSE처럼 동작하기 시작합니다.
  **Huber는 "이상치가 소수일 때"의 도구입니다.**

- **절편 b만 올라가고 기울기 w는 거의 안 변합니다.**
  (MSE 20%에서 b=17.2인데 w는 2.0 근처)
  이상치의 x가 전 구간에 고르게 퍼져 있기 때문입니다.
  **만약 이상치가 특정 x 구간에만 몰려 있었다면 기울기까지 망가집니다.** 훨씬 나쁜 상황입니다.

**실무 판단 순서**

```
① 타깃 히스토그램을 그린다              ← 이걸 안 하고 학습부터 하지 말 것
② 이상치가 보이는가?
      아니오 → MSE
      예    → ③
③ 이상치가 오류인가 진짜 값인가?
      오류    → 제거 후 MSE  (Day 112)
      진짜 값 → Huber, 또는 로그 변환 후 MSE  (Day 111)
④ 이상치가 20% 넘는가?
      예 → 그건 이상치가 아니라 "두 개의 다른 집단"입니다.
           문제 정의를 다시 하세요.
```

> **④가 실무에서 자주 나옵니다.** 스팀 데이터에서 "무료 게임"이 20%라면,
> 그건 이상치가 아니라 **별도로 다뤄야 할 집단**입니다.
> 무료 게임을 제외하고 모델을 만들거나, "무료 여부"를 특성으로 넣어야 합니다. ([Day 127](day-127.md))
</details>

## 오늘의 정리

| 개념 | 핵심 |
|---|---|
| 분류 vs 회귀 | **"예측값 - 정답"의 뺄셈이 의미 있으면 회귀** |
| 회귀 출력층 | **`Dense(1)`** — 노드 1개, **활성화 함수 없음** |
| sigmoid 출력층 | 출력이 0~1에 갇힘. 회귀에 쓰면 학습 자체가 불가능 |
| softmax(1노드) | **항상 1.0** 출력. 에러 없이 조용히 망함 |
| MSE | 오차의 **제곱**. 큰 오차에 극단적 벌점. **평균을 쫓음** |
| MAE | 오차의 **절댓값**. 이상치에 강함. **중앙값을 쫓음** |
| Huber | 작은 오차는 MSE, 큰 오차는 MAE. `delta` 가 전환점 |
| 손실 함수 선택 | **이상치 2%만 있어도 MSE는 위험** |
| loss vs metrics | loss는 **학습 기준**, metrics는 **사람이 보는 숫자** |
| `metrics=['accuracy']` | 회귀에서 항상 0. `['mae']` 로 |
| `loss: nan` | ① NaN/inf ② **스케일링 누락** ③ 학습률 과다 |
| 예측 vs 실제 산점도 | 회귀의 기본 진단 그래프. **y=x 선 주변에 모여야 정상** |
| RMSE > MAE | **큰 오차가 존재한다**는 신호 (항상 RMSE ≥ MAE) |
| `.ravel()` | 예측 shape (n,1)을 (n,)으로. 안 하면 브로드캐스팅 사고 |

**오늘 반드시 기억할 세 가지**
> ① **회귀 출력층은 `Dense(1)`.** 활성화 함수를 넣는 순간 그 모델은 못 씁니다.
> ② **MSE는 평균을, MAE는 중앙값을 쫓습니다.** 이상치가 있으면 평균이 끌려갑니다.
> ③ **학습 전에 타깃 히스토그램부터 그리세요.** 손실 함수 선택의 근거가 거기 있습니다.

**과제** — 회귀 문제 3개를 직접 정의하고 설계 문서를 작성하세요.

**필수 포함 항목**

| 항목 | 내용 |
|---|---|
| 1 | 문제 3개 — **각각 다른 도메인**에서 (가격 / 수요 / 물리량 / 잔여수명 중 3개) |
| 2 | 각 문제의 **입력 특성 목록** (최소 5개, 실제로 구할 수 있는 것만) |
| 3 | **타깃 정의** — 정확히 무엇을 예측하는가. 단위 포함 |
| 4 | **출력층 설계** — 노드 수, 활성화, 범위 제약이 필요한가와 그 처리 방법 |
| 5 | **손실 함수 선택과 근거** — 이상치가 있을 것으로 예상되는가, 어떤 종류인가 |
| 6 | **평가 지표 선택과 근거** — MAE/RMSE/R² 중 무엇을 주 지표로 볼 것인가 |
| 7 | **"성능이 좋다"의 기준** — 숫자로. (예: "MAE가 평균가의 10% 이내") |
| 8 | 그 문제를 **분류로 바꾼다면** 어떻게 되는가와, 왜 회귀가 더 나은가 |

**주의**
- "데이터를 구할 수 있는가"를 반드시 확인하세요. 상상 속 특성은 감점입니다.
- 5번에서 "MSE를 쓰겠다"고 쓸 거라면, **왜 이상치가 없다고 보는지** 근거를 대세요.
