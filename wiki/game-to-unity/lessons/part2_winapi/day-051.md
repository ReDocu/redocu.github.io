## 2. 막히는 상황

격투게임은 캐릭터가 두 명이었다. 슈팅게임은 다르다.

```
   화면에 동시에 존재하는 것

   플레이어 총알   초당 20발 × 화면 체류 1.5초  =  약 30발
   적             10~30기
   적 총알         약 100~300발
   폭발 이펙트     10~20개
   배경 별         100~200개
   ──────────────────────────────────────
   합계           약 250~550개
```

이걸 격투게임처럼 만들면?

```cpp
    // 발사
    Bullet* b = new Bullet();
    b->SetPos(m_x, m_y);
    scene->Add(b);

    // 화면 밖
    if (m_y < -20) Destroy();       // → RemoveInactive에서 delete
```

```
   초당 20발 발사  →  초당 20번 new
   초당 20발 소멸  →  초당 20번 delete

   적 총알까지 합치면 초당 수백 번
```

**실제로 만들어 보면 프레임이 떨어진다.**

```
   지금:   왜 느린지 "느낌"으로만 안다

   필요:   ① 얼마나 느린지 수치로 측정
           ② 어디에 시간이 쓰이는지 분해
           ③ 원인을 정확히 짚는다
```

> **오늘은 문제를 정확히 측정한다.**

## 3. 개념

### 3-1. 종스크롤 슈팅의 구조

**왜 필요한가** — 오늘 만들 게임의 골격.

```
   ┌───────────────────────┐
   │  ·   ·     ·      ·   │  ← 배경 (아래로 스크롤)
   │     ▼  ▼      ▼       │  ← 적 (아래로 이동)
   │                       │
   │        ▲  ▲  ▲        │  ← 플레이어 총알 (위로)
   │                       │
   │          ██           │  ← 플레이어 (좌우/상하 이동)
   │         ████          │
   └───────────────────────┘

   ★ 격투게임과 다른 점
     - 중력이 없다 (좌표 그대로 이동)
     - 오브젝트가 계속 생기고 사라진다
     - 화면 밖으로 나가면 소멸
```

**오브젝트 종류와 태그**

```cpp
enum Tag
{
    TAG_NONE = 0,
    TAG_PLAYER,
    TAG_ENEMY,
    TAG_PLAYER_BULLET,
    TAG_ENEMY_BULLET,
    TAG_ITEM,
    TAG_EFFECT
};
```

### 3-2. `new` / `delete`의 비용

**왜 필요한가** — "느리다"의 정체를 안다.

```
   new Bullet() 이 실제로 하는 일

   ① 힙 관리자에게 요청           "48바이트 주세요"
   ② 빈 블록 탐색                 자유 목록에서 맞는 크기 찾기
   ③ 블록 분할·메타데이터 기록     "여기부터 48바이트 사용 중"
   ④ 메모리 반환
   ⑤ 생성자 호출                  멤버 초기화
   ⑥ (멀티스레드면) 락 획득/해제

   ★ 단순 계산 몇 개가 아니라 "관리 작업"이다
```

| 작업 | 대략적 비용 |
|---|---|
| 지역 변수 생성 | 거의 0 (스택 포인터 이동) |
| `new` 한 번 | 50~200 나노초 |
| `delete` 한 번 | 50~200 나노초 |
| 배열 인덱스 접근 | 1~2 나노초 |

```
   초당 1000번 new + delete
   = 1000 × 300ns
   = 0.3 ms/초

   ★ 이것만 보면 별것 아니다
```

**그런데 왜 느려지나?**

### 3-3. 진짜 원인 — 메모리 단편화와 캐시

**왜 필요한가** — 숫자만으로 설명이 안 되는 부분.

**① 메모리 단편화**

```
   힙 상태 변화

   초기:     [                                    ]
   할당 100: [AAAA][BBBB][CCCC][DDDD] ...
   일부 해제:[AAAA][    ][CCCC][    ] ...          ← 구멍
   재할당:   [AAAA][EEEE][CCCC][FFFF] ...

   시간이 지나면:
             [A][ ][C][ ][E][ ][G][ ][I][ ] ...
                ▲ 작은 구멍이 많아진다

   → 새 할당 시 맞는 구멍을 찾는 데 오래 걸린다
   → 못 찾으면 힙을 확장한다 (더 느리다)
```

**② 캐시 미스 — 이게 더 크다**

```
   [ 흩어진 메모리 ]

   총알들이 힙 여기저기에 흩어져 있다

   주소:  0x1000  0x8420  0x3F10  0xA800  0x2200 ...
          bullet0 bullet1 bullet2 bullet3 bullet4

   for (모든 총알) bullet->Update(dt);

   → 매번 다른 캐시 라인을 읽는다  →  캐시 미스
   → CPU가 메모리를 기다린다


   [ 연속된 메모리 ]

   주소:  0x1000  0x1030  0x1060  0x1090  0x10C0 ...
          bullet0 bullet1 bullet2 bullet3 bullet4

   → 한 번 읽으면 여러 개가 캐시에 들어온다  →  캐시 히트
   → 훨씬 빠르다
```

```
   ★ 캐시 미스 비용

   L1 캐시 히트   약 1 나노초
   L2 캐시 히트   약 4 나노초
   메인 메모리    약 100 나노초      ← 100배 차이

   총알 1000개를 흩어진 메모리에서 순회하면
   → 1000 × 100ns = 0.1ms

   연속 메모리면
   → 1000 × 2ns = 0.002ms          (50배 빠름)
```

> **`new`/`delete` 자체보다 "흩어진 메모리를 순회하는 비용"이 더 크다.**
> 이것이 오브젝트 풀링의 진짜 이유다.

### 3-4. 성능 측정 방법

**왜 필요한가** — 추측이 아니라 수치로 판단한다.

```cpp
class Profiler
{
public:
    void Begin(const char* name)
    {
        m_currentName = name;
        QueryPerformanceCounter(&m_start);
    }

    void End()
    {
        LARGE_INTEGER now;
        QueryPerformanceCounter(&now);

        double ms = (now.QuadPart - m_start.QuadPart) * 1000.0 / m_freq.QuadPart;

        // 누적
        for (int i = 0; i < m_count; i++)
        {
            if (strcmp(m_entries[i].name, m_currentName) == 0)
            {
                m_entries[i].totalMs += ms;
                m_entries[i].calls++;
                return;
            }
        }

        // 새 항목
        strcpy_s(m_entries[m_count].name, 32, m_currentName);
        m_entries[m_count].totalMs = ms;
        m_entries[m_count].calls = 1;
        m_count++;
    }

    void Reset() { for (int i = 0; i < m_count; i++) { m_entries[i].totalMs = 0; m_entries[i].calls = 0; } }

private:
    struct Entry { char name[32]; double totalMs; int calls; };
    Entry m_entries[16];
    int   m_count = 0;
    LARGE_INTEGER m_freq, m_start;
    const char* m_currentName = nullptr;
};
```

```cpp
    g_profiler.Begin("Update");
    UpdateAll(dt);
    g_profiler.End();

    g_profiler.Begin("Alloc");
    SpawnBullets();
    g_profiler.End();

    g_profiler.Begin("Render");
    RenderAll(r);
    g_profiler.End();
```

**측정할 항목**

| 항목 | 무엇을 아는가 |
|---|---|
| 프레임 시간 | 전체 성능 |
| Update 시간 | 로직 비용 |
| Render 시간 | 그리기 비용 |
| **할당 시간** | `new`/`delete` 비용 |
| 오브젝트 수 | 규모 |
| `new` 호출 횟수 | 얼마나 자주 |

### 3-5. 측정 시 주의점

**왜 필요한가** — 잘못 측정하면 엉뚱한 결론을 낸다.

```
   ★ Debug 빌드로 측정하면 안 된다

   Debug:    최적화 없음 + 런타임 검사 → 5~20배 느리다
   Release:  실제 성능

   반드시 Release 빌드로 측정한다
```

```
   ★ 첫 몇 초는 버린다

   프로그램 시작 직후는
   - 힙이 아직 안정되지 않았다
   - 캐시가 비어 있다
   - JIT/로딩이 남아 있다

   → 5초 이상 돌린 뒤의 값을 본다
```

```
   ★ 한 프레임 값이 아니라 평균을 본다

   프레임마다 값이 크게 흔들린다
   → 60프레임 평균 또는 1초 평균
```

### 3-6. 문제를 재현하는 조건

**왜 필요한가** — 문제가 안 보이면 해결의 필요성도 안 보인다.

```
   ★ 오늘의 목표는 "느려지게 만드는 것"이다

   조건
   ① 총알을 초당 30발 이상 발사
   ② 적 총알을 대량으로 (초당 100발+)
   ③ 폭발 이펙트를 아끼지 않고 생성
   ④ 총알 하나가 화면에 1~2초 체류
   ⑤ Release 빌드로 실행

   → 동시 오브젝트 500~1000개
   → FPS 20~30대로 떨어진다
```

```
   ★ 그래도 안 느려지면?

   요즘 CPU는 빠르다. 더 극단적으로 만든다
   - 오브젝트를 5000개까지
   - 총알마다 이펙트 생성
   - Update에서 약간의 계산 추가
```

## 4. 따라 만들기

### Step 1 — 플레이어

```cpp
class Player : public GameObject
{
public:
    bool Init(Core* core) override
    {
        GameObject::Init(core);

        m_x = core->GetWidth() / 2.0;
        m_y = core->GetHeight() - 100.0;

        SetLayer(2);
        SetTag(TAG_PLAYER);
        return true;
    }

    void Update(double dt) override
    {
        Input& in = m_core->GetInput();

        double ax = 0, ay = 0;
        if (in.IsKeyPress(VK_LEFT))  ax -= 1;
        if (in.IsKeyPress(VK_RIGHT)) ax += 1;
        if (in.IsKeyPress(VK_UP))    ay -= 1;
        if (in.IsKeyPress(VK_DOWN))  ay += 1;

        m_x += ax * SPEED * dt;
        m_y += ay * SPEED * dt;

        ClampToScreen();

        // 발사
        m_fireTimer -= dt;

        if (in.IsKeyPress('Z') && m_fireTimer <= 0.0)
        {
            Fire();
            m_fireTimer = m_fireInterval;
        }
    }

    void Render(Renderer& r) const override
    {
        r.DrawRect((int)m_x - 12, (int)m_y - 16, 24, 32, RGB(80, 200, 255));
        r.DrawRect((int)m_x - 4,  (int)m_y - 24, 8,  16, RGB(200, 240, 255));
    }

private:
    void Fire();
    void ClampToScreen();

    static constexpr double SPEED = 320.0;
    double m_fireTimer    = 0.0;
    double m_fireInterval = 0.05;             // 초당 20발
};
```

**✅ 여기까지 실행하면** — 플레이어가 화면 안에서 움직인다.

### Step 2 — 총알 (`new`/`delete` 방식)

```cpp
class Bullet : public GameObject
{
public:
    static int s_newCount;                    // ★ 통계
    static int s_deleteCount;

    Bullet() { s_newCount++; }
    ~Bullet() { s_deleteCount++; }

    bool Init(Core* core) override
    {
        GameObject::Init(core);
        SetLayer(3);
        return true;
    }

    void Setup(double x, double y, double vx, double vy, int tag)
    {
        m_x = x; m_y = y;
        m_vx = vx; m_vy = vy;
        SetTag(tag);
    }

    void Update(double dt) override
    {
        m_x += m_vx * dt;
        m_y += m_vy * dt;

        if (m_y < -20 || m_y > m_core->GetHeight() + 20 ||
            m_x < -20 || m_x > m_core->GetWidth() + 20)
        {
            Destroy();                        // → RemoveInactive 에서 delete
        }
    }

    void Render(Renderer& r) const override
    {
        COLORREF c = (GetTag() == TAG_PLAYER_BULLET)
                   ? RGB(255, 240, 120) : RGB(255, 120, 120);

        r.DrawRect((int)m_x - 2, (int)m_y - 6, 4, 12, c);
    }

    RectF GetBounds() const override
    {
        return RectF{ (float)m_x - 2, (float)m_y - 6, 4, 12 };
    }

private:
    double m_vx = 0, m_vy = 0;
};

int Bullet::s_newCount = 0;
int Bullet::s_deleteCount = 0;
```

```cpp
void Player::Fire()
{

}
```

### Step 3 — 적과 적 총알

```cpp
class Enemy : public GameObject
{
public:
    bool Init(Core* core) override
    {
        GameObject::Init(core);

        m_x = 60 + rand() % (core->GetWidth() - 120);
        m_y = -30;
        m_vy = 60.0 + rand() % 80;
        m_hp = 3;

        SetLayer(2);
        SetTag(TAG_ENEMY);
        return true;
    }

    void Update(double dt) override
    {
        m_y += m_vy * dt;

        // 주기적 발사
        m_fireTimer -= dt;
        if (m_fireTimer <= 0.0)
        {
            FireSpread(8);                    // ★ 한 번에 8발
            m_fireTimer = 0.6;
        }

        if (m_y > m_core->GetHeight() + 40) Destroy();
    }

    void OnCollide(GameObject* other) override
    {
        if (other->GetTag() != TAG_PLAYER_BULLET) return;

        other->Destroy();

        if (--m_hp <= 0)
        {
            SpawnExplosion();
            Destroy();
        }
    }

private:
    void FireSpread(int count);
    void SpawnExplosion();

    double m_vy = 80.0;
    double m_fireTimer = 0.8;
    int    m_hp = 3;
};
```

```cpp
void Enemy::FireSpread(int count)
{
    for (int i = 0; i < count; i++)
    {
        double angle = -3.14159 / 2 + (i - count / 2.0) * 0.22;

        Bullet* b = new Bullet();             // ★ 8개씩 new
        b->Setup(m_x, m_y + 16,
                 cos(angle) * 220.0, -sin(angle) * 220.0,
                 TAG_ENEMY_BULLET);
        m_scene->Add(b);
    }
}
```

**✅ 여기까지 실행하면** — 적이 내려오며 탄막을 뿌린다.

### Step 4 — 폭발 이펙트

```cpp
class Explosion : public GameObject
{
public:
    static int s_newCount, s_deleteCount;

    Explosion()  { s_newCount++; }
    ~Explosion() { s_deleteCount++; }

    bool Init(Core* core) override
    {
        GameObject::Init(core);
        SetLayer(4);
        m_life = 0.4;
        return true;
    }

    void Update(double dt) override
    {
        m_life -= dt;
        m_radius += 60.0 * dt;
        if (m_life <= 0) Destroy();
    }

    void Render(Renderer& r) const override
    {
        r.DrawCircle((int)m_x, (int)m_y, (int)m_radius, RGB(255, 180, 60), false);
        r.DrawCircle((int)m_x, (int)m_y, (int)(m_radius * 0.6), RGB(255, 240, 160), false);
    }

private:
    double m_life = 0.4;
    double m_radius = 4.0;
};
```

### Step 5 — 스폰 매니저

```cpp
class ShootScene : public Scene
{
    void Update(double dt) override
    {
        m_spawnTimer -= dt;

        if (m_spawnTimer <= 0.0)
        {
            int count = 1 + (int)(m_elapsed / 10.0);      // 시간이 갈수록 증가
            if (count > 5) count = 5;

            for (int i = 0; i < count; i++)
                Add(new Enemy());

            m_spawnTimer = 0.8;
        }

        m_elapsed += dt;

        UpdateAll(dt);
        CheckCollision(TAG_PLAYER_BULLET, TAG_ENEMY);
        CheckCollision(TAG_ENEMY_BULLET, TAG_PLAYER);
        RemoveInactive();
    }
};
```

**✅ 여기까지 실행하면** — 시간이 갈수록 적이 많아진다.

## 6. 자주 막히는 곳

| 증상 | 원인 | 해결 |
|---|---|---|
| 안 느려짐 | 오브젝트가 적음 | 발사 속도·탄막·스폰을 극단적으로 |
| 안 느려짐 | Debug 빌드 | **Release**로 (Debug는 원래 느려서 비교 불가) |
| 측정값이 들쭉날쭉 | 한 프레임 값 | 1초 평균 |

| 크래시 | 순회 중 삭제 | `RemoveInactive`는 순회 밖에서 |
| 총알이 안 사라짐 | 화면 밖 판정 오류 | 범위 확인 |
| 메모리 계속 증가 | `delete` 누락 | `new`/`delete` 카운트 비교 |
| `psapi` 링크 오류 | 라이브러리 누락 | `#pragma comment(lib, "psapi.lib")` |

## 7. 정리

### 오늘 배운 것

| 개념 | 한 줄 요약 |
|---|---|
| 슈팅게임 구조 | 오브젝트가 계속 생기고 사라진다 |
