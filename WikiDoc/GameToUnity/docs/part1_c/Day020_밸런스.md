```
   홀짝:  승률 50%   →  50번 이기고 50번 진다
          100 G씩 걸었다면?

          이길 때:  100 × 1.9 = 190  →  순이익 +90
          질 때:    -100

          50번 × (+90) + 50번 × (-100) = +4500 - 5000 = -500

          100판에 500 G 손해  →  판당 -5 G  →  베팅액의 5%
```

**계산해 보면 하우스가 이긴다.** 그런데 이게 맞나? `숫자 지정`은?

```
   숫자 지정:  승률 1/6 ≈ 16.67%,  배당 5.5배

   100판 × 100 G:
     16.67번 × (+450) + 83.33번 × (-100) = +7500 - 8333 = -833

   판당 -8.33 G  →  8.33%
```

**세 베팅의 손해율이 제각각이다.** 5.25% / 8.33% / ? — 이러면 플레이어는 **가장 손해가 적은 홀짝만** 하게 된다.

```
   지금:   숫자를 감으로 정했다
           맞는지 확인할 방법이 없다
           베팅 종류 간 유불리가 다르다

   필요:   ① 기대값을 계산한다        (이론)
           ② 시뮬레이션으로 검증한다   (실측)
           ③ 조정한다                 (밸런싱)
```

> **게임이 성립하는지 숫자로 확인하는 방법이 필요하다.**

## 3. 개념

### 3-1. 기대값 — 평균적으로 얼마를 얻는가

**왜 필요한가** — 게임 밸런스의 가장 기본이 되는 계산.

```
   기대값(EV) = Σ (각 결과의 확률 × 그 결과의 수익)
```

**홀짝 예시 (1 G 베팅 기준)**

| 결과 | 확률 | 수익 | 확률 × 수익 |
|---|:--:|:--:|:--:|
| 적중 | 0.5 | +0.9 | +0.45 |
| 빗나감 | 0.5 | -1.0 | -0.50 |
| | | **기대값** | **-0.05** |

```
   1 G를 걸면 평균 0.05 G를 잃는다  →  -5%
```

**일반 공식**

```
   승률 p, 배당 m 일 때 (1 G 베팅)

   이길 확률   p    →  수익 (m - 1)      ← 배당에서 원금을 뺀 순이익
   질 확률  (1-p)   →  수익  -1

   EV = p × (m - 1) + (1 - p) × (-1)
      = p × m - p - 1 + p
      = p × m - 1
```

```
   ★ EV = (승률 × 배당) - 1
```

| 베팅 | 승률 p | 배당 m | p × m | EV |
|---|:--:|:--:|:--:|:--:|
| 홀짝 | 0.5000 | 1.9 | 0.950 | **-0.0500** |
| 숫자 지정 | 0.1667 | 5.5 | 0.917 | **-0.0833** |
| 하이/로우 | 0.3333 | 2.8 | 0.933 | **-0.0667** |

### 3-2. 하우스 엣지 — 게임이 성립하는 조건

**왜 필요한가** — 도박 게임의 존재 이유이자, 밸런스의 기준선.

```
   하우스 엣지 = -EV × 100 %

   EV = -0.05  →  하우스 엣지 5%
```

| EV | 의미 | 게임으로 |
|:--:|---|---|
| EV > 0 | 플레이어가 유리 | ✘ 무한히 벌 수 있다. 성립 불가 |
| EV = 0 | 공정 | △ 아무도 손해를 안 본다. 하우스가 운영할 이유 없음 |
| **EV < 0** | 하우스가 유리 | ✔ **성립** |

**현실 참고값**

| 게임 | 하우스 엣지 |
|---|:--:|
| 블랙잭 (최적 플레이) | 0.5% |
| 바카라 | 1.1% |
| 룰렛 (유럽식) | 2.7% |
| 룰렛 (미국식) | 5.3% |
| 슬롯머신 | 5~15% |

> **너무 크면** 플레이어가 금방 파산해서 재미없다.
> **너무 작으면** 게임 진행이 늘어지고 긴장감이 없다.
> **5~8%가 이 게임에 적당하다.**

### 3-3. 배당 역산 — 원하는 엣지에 맞추기

**왜 필요한가** — 감으로 정하지 말고 목표에서 거꾸로 계산한다.

```
   EV = p × m - 1

   목표 EV가 -0.06 (엣지 6%) 이라면

   -0.06 = p × m - 1
   p × m = 0.94
   m = 0.94 / p
```

| 베팅 | 승률 p | 목표 배당 (엣지 6%) | 반올림 |
|---|:--:|:--:|:--:|
| 홀짝 | 0.5000 | 0.94 / 0.5000 = 1.880 | **1.9** |
| 숫자 지정 | 0.1667 | 0.94 / 0.1667 = 5.639 | **5.6** |
| 하이/로우 | 0.3333 | 0.94 / 0.3333 = 2.820 | **2.8** |

```
   Day 17의 값과 비교

   홀짝       1.9  →  1.9    (그대로)
   숫자 지정  5.5  →  5.6    ★ 수정 필요 (엣지가 8.3%로 너무 높았다)
   하이/로우  2.8  →  2.8    (그대로)
```

**조정 후 재계산**

| 베팅 | p | m | EV | 엣지 |
|---|:--:|:--:|:--:|:--:|
| 홀짝 | 0.5000 | 1.9 | -0.0500 | 5.00% |
| 숫자 지정 | 0.1667 | 5.6 | -0.0667 | 6.67% |
| 하이/로우 | 0.3333 | 2.8 | -0.0667 | 6.67% |

> 완벽히 같게 만들 필요는 없다. **오히려 약간의 차이가 선택의 재미를 만든다.**
> 다만 **한쪽이 명백히 유리하면 안 된다.** 그러면 아무도 다른 걸 안 고른다.

### 3-5. 파산 시뮬레이션 — 체감 난이도

**왜 필요한가** — 기대값이 -5%라고 해서 플레이어가 항상 5%씩 잃는 건 아니다.

```
   실제 플레이는 이렇게 흘러간다

   자금
   3000 ┤                    ╱╲        ← 목표 달성 (승리!)
        │              ╱╲  ╱   ╲
   2000 ┤        ╱╲  ╱  ╲╱
        │      ╱   ╲╱
   1000 ┼────╱                          ← 시작
        │ ╲╱
      0 ┴──────────────────────────▶ 라운드
        ▲ 파산

   ★ 기대값은 "평균"일 뿐. 개별 플레이는 크게 요동친다
```

**측정할 것**

| 지표 | 의미 |
|---|---|
| 목표 달성률 | 몇 %가 이기는가 |
| 평균 생존 라운드 | 얼마나 오래 즐기는가 |
| 최대 잔액의 평균 | 한 번쯤 "될 뻔한" 경험을 하는가 |

**목표 수치의 감각**

| 달성률 | 체감 |
|:--:|---|
| 50% 이상 | 너무 쉽다. 도전 의욕 없음 |
| **15~25%** | **적당.** "운이 좋으면 된다"는 감각 |
| 5% 미만 | 절망적. 금방 그만둔다 |

> **기댓값(수학)과 체감(심리)은 다르다.** 둘 다 봐야 밸런싱이 된다.
> 이 감각이 **Day 89의 타워 디펜스 밸런싱**, 파이널 프로젝트까지 이어진다.

## 4. 따라 만들기

### Step 1 — 기대값 계산 함수

```c
// 기대값 × 10000 (정수로 유지)
int CalcEV_x10000(int winPercent, int payoutX10)
{
    // EV = p × m - 1
    // p = winPercent / 100,  m = payoutX10 / 10
    // EV × 10000 = winPercent × payoutX10 × 10 - 10000

    return winPercent * payoutX10 * 10 - 10000;
}
```

```c
void PrintTheory(void)
{
    printf("\n  베팅 종류    승률    배당    기대값    하우스엣지\n");
    printf("  ────────────────────────────────────────────────\n");

    for (int i = 0; i < BET_COUNT; i++)
    {
        int ev = CalcEV_x10000(g_betTable[i].winPercent, g_betTable[i].payoutX10);

        printf("  %-10s  %2d%%   %d.%d배  %+7.4f    %5.2f%%\n",
               g_betTable[i].name,
               g_betTable[i].winPercent,
               g_betTable[i].payoutX10 / 10,
               g_betTable[i].payoutX10 % 10,
               ev / 10000.0,
               -ev / 100.0);
    }
}
```

> ⚠️ **승률을 정수 %로 저장하면 정확도가 떨어진다.**
> 숫자 지정의 실제 승률은 16.6667%인데 테이블에는 17로 저장돼 있다.
> **정밀도가 필요하면 `winPercentX100`(1667)으로 저장한다.**

**개선한 테이블**

```c
typedef struct
{
    const char* name;
    int         payoutX10;       // 배당 × 10
    int         winRateX10000;   // 승률 × 10000 (50% → 5000)
} BetInfo;

const BetInfo g_betTable[BET_COUNT] = {
    { "홀짝",      19, 5000 },      // 3/6 = 50.00%
    { "숫자 지정", 56, 1667 },      // 1/6 = 16.67%
    { "하이/로우", 28, 3333 }       // 2/6 = 33.33%
};
```

**✅ 여기까지 실행하면** — 이론 기대값 표가 출력된다.

### Step 2 — 배당 역산으로 조정

```c
// 목표 엣지에 맞는 배당 × 10 을 계산
int CalcTargetPayoutX10(int winRateX10000, int targetEdgePercent)
{
    // m = (1 - edge) / p
    // m × 10 = (10000 - edge×100) × 10 / winRateX10000 × ... 

    // 정수 연산으로: (10000 - edge*100) * 10000 / winRateX10000 / 1000
    long long numerator = (long long)(10000 - targetEdgePercent * 100) * 10;
    return (int)(numerator * 1000 / winRateX10000 / 10);
}
```

```c
void SuggestPayouts(int targetEdge)
```

### Step 3 — 무인 시뮬레이션

```c
typedef struct
{
    int trials;
    int wins;
    int totalBet;
    int totalReturn;
} SimResult;

SimResult SimulateBetType(BetType type, int trials, int betAmount)
{
    SimResult r = { trials, 0, 0, 0 };

    for (int i = 0; i < trials; i++)
    {
        GameState g;
        g.betType    = type;
        g.betAmount  = betAmount;
        g.diceResult = RandRange(1, 6);

        // 무작위 예측 (플레이어가 아무렇게나 고른다고 가정)
        switch (type)
        {
        case BET_ODDEVEN: g.prediction = RandRange(1, 2); break;
        case BET_NUMBER:  g.prediction = RandRange(1, 6); break;
        case BET_HIGHLOW: g.prediction = RandRange(1, 3); break;
        default: g.prediction = 1; break;
        }

        r.totalBet += betAmount;

        if (IsWin(&g))                                  // Day 17의 함수 재사용
        {
            r.wins++;
            r.totalReturn += betAmount * g_betTable[type].payoutX10 / 10;
        }
    }

    return r;
}
```

**✅ 여기까지 실행하면** — 시뮬레이션이 돌아간다. (아직 출력 없음)

### Step 4 — 이론 vs 실측 비교표

```c
void VerifyBalance(int trials)
{
    printf("\n╔═══════════════════════════════════════════════╗\n");
    printf("║           밸런스 검증  —  %6d 라운드        ║\n", trials);
    printf("╚═══════════════════════════════════════════════╝\n\n");

    printf("  베팅 종류    이론승률  실제승률   배당   기대값   하우스엣지\n");
    printf("  ─────────────────────────────────────────────────────────\n");

    int grandBet = 0, grandReturn = 0;

    for (int i = 0; i < BET_COUNT; i++)
    {
        SimResult r = SimulateBetType((BetType)i, trials, 100);

        double theoryRate = g_betTable[i].winRateX10000 / 100.0;
        double actualRate = r.wins * 100.0 / r.trials;
        double actualEV   = (r.totalReturn - r.totalBet) * 1.0 / r.totalBet;

        printf("  %-10s   %6.2f%%  %6.2f%%  %d.%d배  %+7.4f  %6.2f%%\n",
               g_betTable[i].name,
               theoryRate, actualRate,
               g_betTable[i].payoutX10 / 10, g_betTable[i].payoutX10 % 10,
               actualEV, -actualEV * 100);

        grandBet    += r.totalBet;
        grandReturn += r.totalReturn;
    }

    printf("\n  ─────────────────────────────────────────────────────────\n");
    printf("  플레이어 총 베팅   %,d G\n", grandBet);
    printf("  플레이어 총 수익   %+d G   (%+.2f%%)\n",
           grandReturn - grandBet,
           (grandReturn - grandBet) * 100.0 / grandBet);

    if (grandReturn < grandBet)
        printf("\n  >> 하우스 우위 확인.  게임이 성립한다.\n");
    else
        printf("\n  >> 경고: 플레이어가 유리하다!  배당을 낮춰야 한다.\n");
}
```

**✅ 여기까지 실행하면** — 1절 상단의 검증표가 나온다.
**이론 승률과 실제 승률이 0.5%p 이내로 일치해야 정상이다.**

### Step 6 — 파산 시뮬레이션

```c
typedef struct
{
    int reachedGoal;        // 목표 달성 횟수
    int wentBankrupt;       // 파산 횟수
    int totalRounds;        // 총 라운드 (평균 계산용)
    int maxPeakSum;         // 최고 잔액 합 (평균 계산용)
} RuinResult;

RuinResult SimulateRuin(int runs, int startMoney, int goal, int betAmount)
{
    RuinResult res = { 0, 0, 0, 0 };

    for (int i = 0; i < runs; i++)
    {
        int money = startMoney;
        int rounds = 0;
        int peak = money;

        while (money >= betAmount && money < goal && rounds < 10000)
        {
            GameState g;
            g.betType    = BET_ODDEVEN;              // 홀짝만 한다고 가정
            g.betAmount  = betAmount;
            g.prediction = RandRange(1, 2);
            g.diceResult = RandRange(1, 6);

            if (IsWin(&g))
                money += betAmount * g_betTable[BET_ODDEVEN].payoutX10 / 10 - betAmount;
            else
                money -= betAmount;

            if (money > peak) peak = money;
            rounds++;
        }

        if (money >= goal) res.reachedGoal++;
        else               res.wentBankrupt++;

        res.totalRounds += rounds;
        res.maxPeakSum  += peak;
    }

    return res;
}
```

```c
void PrintRuinSimulation(int runs)
{
    printf("\n───────────────────── [ 파산 시뮬레이션 ]\n\n");
    printf("  시작 자금 %d G / 매 라운드 %d G 베팅 / %d회 시행\n\n",
           START_MONEY, 100, runs);

    RuinResult r = SimulateRuin(runs, START_MONEY, GOAL_MONEY, 100);

    printf("  목표(%dG) 달성    %4d회  (%.1f%%)\n",
           GOAL_MONEY, r.reachedGoal, r.reachedGoal * 100.0 / runs);
    printf("  파산              %4d회  (%.1f%%)\n",
           r.wentBankrupt, r.wentBankrupt * 100.0 / runs);
    printf("  평균 생존 라운드   %.1f\n", r.totalRounds * 1.0 / runs);
    printf("  평균 최고 잔액     %d G\n", r.maxPeakSum / runs);

    double rate = r.reachedGoal * 100.0 / runs;

    printf("\n  >> ");
    if (rate > 40)      printf("너무 쉽다. 목표 금액을 올리거나 배당을 낮춘다.\n");
    else if (rate < 5)  printf("너무 어렵다. 목표를 낮추거나 시작 자금을 늘린다.\n");
    else                printf("플레이어는 대체로 진다. 하지만 %.0f%%는 이긴다.\n", rate);
}
```

**✅ 여기까지 실행하면** — 1절 하단의 파산 시뮬레이션이 나온다.

### Step 7 — 밸런스 조정 실습

```c

```

| 조정 | 달성률 변화 |
|---|---|
| 목표 금액 3000 → 2000 | 올라간다 |
| 시작 자금 1000 → 1500 | 올라간다 |
| 베팅 단위 100 → 200 | **올라간다** (변동성 증가) |
| 배당 1.9 → 1.95 | 올라간다 |

> **베팅 단위를 키우면 달성률이 올라가는 것**이 흥미롭다.
> 기대값은 그대로인데 **변동성이 커져서** 목표에 닿을 확률이 높아진다.
> 대신 빨리 끝난다(생존 라운드 감소).
>
> 이것이 도박의 유명한 결론이다 — **불리한 게임에서는 크게 걸어야 한다.**

**✅ 여기까지 실행하면** — 수치를 바꿔 가며 달성률이 15~25%가 되는 조합을 찾을 수 있다.

### Step 9 — 다른 게임에도 적용 (확장)

**RPG의 크리티컬 밸런스**

```
   크리티컬 확률 20%, 배수 2배

   평균 데미지 배율 = 0.8 × 1.0 + 0.2 × 2.0 = 1.2배

   → 크리티컬을 넣으면 전체 데미지가 20% 오른다
   → 몬스터 체력을 20% 올려야 난이도가 유지된다
```

**미로의 아이템 배치**

```
   맵 100칸 중 길이 50칸, 아이템 5개

   → 이동 중 아이템을 만날 확률: 5/50 = 10%
   → 평균 30칸 이동하면 3개를 얻는다
```

**✅ 여기까지 하면** — 밸런싱이 게임 전반에 적용되는 사고 방식임을 이해한다.

## 6. 자주 막히는 곳

| 증상 | 원인 | 해결 |
|---|---|---|
| 실제 승률이 이론과 크게 다름 | 판정 로직 버그 | `IsWin`의 조건 재검토 |
| 시뮬레이션 결과가 매번 크게 다름 | 시행 횟수 부족 | 10,000회 이상 |
| 기대값이 항상 0 | 정수 나눗셈 | `1.0 *` 또는 `(double)` 캐스팅 |
| 총합이 음수로 오버플로 | `int` 범위 초과 | `long long` 사용 |
| 승률이 정확히 이론값 | 난수 시드 고정 상태 | `srand` 확인 |
| `%,d` 서식이 안 먹힘 | 표준 C에 없음 | 직접 자릿수 구분 함수 작성 |
| 파산 시뮬레이션이 안 끝남 | 종료 조건 누락 | `rounds < 10000` 안전장치 |
| 배당 조정이 반영 안 됨 | 코드에 값이 박혀 있음 | **테이블만 고쳐서 되어야 정상** |

## 7. 정리

### 오늘 배운 것

| 개념 | 한 줄 요약 |
|---|---|
| **기대값 (EV)** | `EV = 승률 × 배당 - 1`. 게임 밸런스의 기본 계산 |
| 하우스 엣지 | `-EV × 100%`. 게임이 성립하려면 EV < 0 |
| 배당 역산 | `배당 = (1 - 목표엣지) / 승률` |
| 시뮬레이션 검증 | 이론과 실측을 대조. **확률 버그를 잡는 유일한 방법** |
| 파산 시뮬레이션 | 기대값과 체감은 다르다. 달성률 15~25%가 적당 |
| 변동성 | 크게 걸면 불리한 게임에서 이길 확률이 올라간다 |
| 데이터 기반 밸런싱 | 수치는 테이블에. **코드를 고쳐야 하면 설계 문제** |
