## 3. 전체 16주 한눈에 보기

### 3-1. 학습 흐름 — 주차가 어떻게 이어지는가

이 과정은 매주 새 서비스를 나열하는 방식이 아니라, **앞 주차에서 만든 것을 다음 주차가 그대로 물려받아 키우는** 방식입니다.

```
W1-2  계정·IAM 기준선 ──────────────────────────────┐ (모든 주차의 권한 기반)
W3    CLI·리눅스·첫 EC2                              │
W4    VPC 골격 ①  ───────────┐                       │
W5    그 VPC 안에 ASG ②      │                       │
W6    ASG 앞에 ALB + HTTPS ③ │  같은 VPC가            │
W7    S3/CloudFront 정적 계층 │  16주 내내 자란다      │
W8    프라이빗 서브넷에 RDS ④ ┘  → 중간 프로젝트        │
W9-10 같은 데이터에 Lambda·API·큐 붙이기               │
W11   같은 앱을 컨테이너로 재포장 + 관측성 부착          │
W12   여기까지 만든 것을 코드(IaC)로 재현 + CI/CD ⑤     │
W13-16 팀 요구사항으로 처음부터 다시, 단 전부 코드로 ────┘
```

**통제 수단 8가지**

1. **첫 수업(02강)에서 AWS Budgets 알림 3단계 설정** — $5 / $10 / $20 도달 시 메일. 이 설정 스크린샷 제출이 02강 과제.
2. **모든 리소스에 태그 3종 강제** — `Project=aws-course`, `Owner=<학번>`, `Week=W04`. Cost Explorer에서 주차별 비용을 스스로 확인.
3. **NAT Gateway는 "만들고 그 시간 안에 지운다"** — 시간당 $0.059(월 $42)로 이 과정 최대 위험. 상시 필요 시 **VPC 엔드포인트(S3/SSM)** 로 대체하는 법을 07강에서 함께 학습.
4. **퍼블릭 IPv4 주소도 과금**(시간당 $0.005, 월 약 $3.6/개)임을 03강에서 명시 — 프리 티어 종료 계정은 EIP 미사용분까지 과금.
5. **주말·야간 자동 정지** — 최종 프로젝트 스택은 EventBridge 스케줄 + Lambda로 야간 ASG 0대/RDS 중지(최대 7일). 30강 실습에 포함.
6. **삭제는 스택 단위로** — 12주차 이후 모든 리소스를 CloudFormation 스택으로 만들어 `delete-stack` 한 번에 정리.
7. **매주 과제에 "비용 확인 스크린샷" 포함** — Cost Explorer 일별 그래프. 이상 비용을 다음 수업 첫 10분에 공유.
8. **강사용 점검 리스트** — 매주 수업 종료 24시간 후 학습자 계정의 NAT/ALB/RDS 잔존 여부 확인(자가 점검 CLI 스크립트 배포).

> **프리 티어 주의** — AWS 프리 티어는 계정 생성 시점에 따라 정책이 다릅니다.
> 2025년 7월 이전 개설 계정은 **12개월 무료 사용량 + 상시 무료**, 이후 개설 계정은 **크레딧 기반 무료 플랜(6개월)** 이 적용될 수 있습니다.
> 첫 수업에서 각자 **Billing 콘솔 → 프리 티어** 화면으로 본인 계정에 적용된 방식을 직접 확인합니다. 정책은 변경될 수 있으므로 문서 값이 아니라 **콘솔 화면을 근거로** 삼습니다.

## 8. 운영 원칙

1. **실습은 반드시 본인 계정, 반드시 서울 리전.** 리전이 섞이면 리소스를 잃어버리고 그대로 과금됩니다. 매 실습 시작 전 우측 상단 리전 표시를 확인합니다.
2. **루트 계정으로는 아무 작업도 하지 않습니다.** 02강 이후 모든 실습은 IAM 사용자 또는 역할로 수행하며, 루트는 결제 정보 변경 등 불가피한 경우에만 사용합니다.
3. **정리(cleanup)는 실습의 일부입니다.** 강마다 정리 체크리스트를 두고, 정리 완료 증빙(콘솔 화면 또는 `aws ... describe` 빈 결과)까지 제출해야 실습을 마친 것으로 봅니다.
4. **버튼 위치가 아니라 작업 흐름을 익힙니다.** AWS 콘솔 UI는 수시로 바뀌므로, 문서는 "무엇을 왜 만드는가 → 어떤 값을 넣는가 → 어떻게 검증하는가" 순서로 서술하고 CLI 명령을 정답으로 함께 둡니다.
5. **서비스를 나열하지 않고 항상 대안과 비교합니다.** "왜 NLB가 아니라 ALB인가", "왜 RDS가 아니라 DynamoDB인가"를 답하지 못하면 그 서비스는 배운 것이 아닙니다.
6. **보안·비용·모니터링은 매 강에 들어갑니다.** 특정 주차에 몰아넣지 않으며, 모든 실습 절차에 최소 권한 · 예상 비용 · 동작 확인 지표가 포함됩니다.
7. **진도가 밀리면 이론을 줄이지 말고 실습 범위를 줄입니다.** 단, 프로젝트 주차(04·08·12·16주)는 새 개념을 넣지 않고 배운 것만으로 완주시킵니다.
8. **실패를 정상 절차로 취급합니다.** 접속이 안 되는 보안 그룹, 라우팅이 빠진 서브넷은 훌륭한 교보재입니다. 각 강 ⑤블록에 에러 원문을 그대로 실어 검색 가능하게 합니다.
