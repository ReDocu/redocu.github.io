## ② 왜 필요한가

### 어제까지의 모델은 이 질문에 답할 수 없습니다

[Day 105](../03-ml/day-105.md)에서 만든 CNN은 사진 한 장에 답 하나를 냈습니다.

```python
model.predict(사진)      # → "허스키"
```

이제 이런 요청이 들어왔다고 합시다.

> **"현관 카메라 화면에 사람이 몇 명 있고, 각각 어디에 서 있는지 알려 줘."**

분류 모델로 답할 수 있습니까? 없습니다.

```python
# 분류 모델의 출력
model.predict(현관사진)   # → "person"

# 필요한 출력
model.predict(현관사진)
# → [{"class": "person", "conf": 0.94, "box": [ 34,  88, 210, 340]},
#     {"class": "person", "conf": 0.87, "box": [280, 110, 430, 360]}]
```

**"사람이 있다"와 "사람이 두 명, 여기와 저기에 있다"는 완전히 다른 정보입니다.**

CCTV가 필요한 것은 후자입니다. 앞의 정보로는 아무것도 못 합니다.
문 앞에 서 있는 사람과 길 건너 지나가는 사람을 구분할 수 없기 때문입니다.

### 답의 개수가 정해져 있지 않습니다

이것이 분류와 검출의 가장 큰 구조적 차이입니다.

```
분류 : 출력 노드 3개 → 항상 3개 확률이 나옴 → argmax로 하나 고름
검출 : 출력 개수가 이미지마다 다름 → 0개일 수도, 30개일 수도 있음
```

출력이 가변 길이가 되면 따라오는 것들이 있습니다.

| | 분류 | 검출 |
|---|---|---|
| 정답 라벨 | 폴더 이름 (`dogs/`) | **좌표가 적힌 파일** |
| 채점 | 맞음/틀림 | **박스가 얼마나 겹치는가** |
| 틀리는 방식 | 오분류 1가지 | **미검출 · 오검출 · 박스 어긋남 · 중복** 4가지 |
| 사람이 정할 것 | 없음 | **`conf` · `iou` 두 개의 임계값** |

오늘은 이 중 **"좌표가 적힌 파일"** 을 다룹니다. 나머지는 [Day 148](day-148.md)에서 이어집니다.

### 좌표 형식이 세 개나 되는 이유

이 단원에서 처음 만나는 짜증나는 사실이 있습니다.
**같은 박스 하나를 표현하는 방법이 최소 세 가지입니다.**

```
같은 박스 (개 한 마리)

  Pascal VOC : (34, 88, 210, 340)
  COCO       : (34, 88, 176, 252)
  YOLO       : (0.2383, 0.4458, 0.2750, 0.5250)
```

**세 줄 다 정확히 같은 박스입니다.** 숫자만 보면 전혀 달라 보입니다.

왜 통일이 안 됐냐면, 각자 다른 곳에서 태어났기 때문입니다.

| 형식 | 태어난 곳 | 지금 쓰이는 곳 |
|---|---|---|
| **Pascal VOC** | 2005년 VOC 챌린지 | **labelImg 저장 포맷** · 많은 라벨링 도구 |
| **COCO** | 2014년 Microsoft COCO | **공개 데이터셋 배포 포맷** · 평가 도구 |
| **YOLO** | 2015년 YOLO 논문 | **Ultralytics 학습 입력 포맷** |

그래서 실제 작업 흐름은 이렇게 됩니다.

```
labelImg로 라벨링  →  VOC .xml 로 저장
                          ↓  ★ 변환해야 함
Ultralytics로 학습  →  YOLO .txt 가 필요
```

**변환을 못 하면 학습을 시작조차 못 합니다.**

### 형식 하나 틀리면 mAP가 0이 됩니다

이 단원에서 가장 자주 나오는 사고가 이것입니다.

```
학습은 정상적으로 돌아감 (에러 없음)
loss 도 잘 떨어짐
그런데 mAP 가 0.00

원인: 라벨 좌표를 정규화하지 않고 픽셀값 그대로 넣음
```

에러가 안 납니다. YOLO 포맷은 그냥 숫자 5개를 읽을 뿐이니까요.
`0.238` 이 와야 할 자리에 `34` 가 들어가면 모델은 **이미지 밖 34배 지점에 박스가 있다**고 배웁니다.

> ⚠️ **좌표 형식 오류는 에러 메시지 없이 실패합니다.**
> 그래서 오늘 배우는 마지막 것이 가장 중요합니다 — **라벨을 이미지에 그려서 눈으로 확인하기.**
> 이 습관 하나로 이 단원의 사고 절반이 사라집니다.

## ③ 개념 설명

### 컴퓨터 비전 4대 과제

같은 사진 한 장에 대해 네 가지 다른 질문을 할 수 있습니다.

```
사진: 강아지 두 마리가 잔디밭에 있음

  ① 분류        "이 사진은 무엇인가?"           → "dog"
  ② 검출        "무엇이 어디에 몇 개 있는가?"    → dog(34,88,210,340), dog(280,110,430,360)
  ③ 의미 분할   "각 픽셀은 무엇에 속하는가?"     → 픽셀마다 dog/grass/sky
  ④ 인스턴스    "각 픽셀은 몇 번째 개에 속하는가?" → 픽셀마다 dog#1/dog#2/배경
```

| | 분류 | **검출** | 의미 분할 | 인스턴스 분할 |
|---|---|---|---|---|
| 영어 | Classification | **Object Detection** | Semantic Segmentation | Instance Segmentation |
| 출력 | 클래스 1개 | **클래스 + 박스 N개** | 픽셀별 클래스 맵 | 픽셀별 클래스 + 개체 ID |
| 개체 구분 | ✗ | **✓** | ✗ (개 두 마리가 한 덩어리) | ✓ |
| 위치 정밀도 | 없음 | **사각형** | 픽셀 단위 | 픽셀 단위 |
| 라벨 만드는 비용 | 1× (폴더 분류) | **8× (박스 치기)** | 40× (외곽선 따기) | 50× |
| 학습·추론 속도 | 빠름 | **중간** | 느림 | 가장 느림 |
| 대표 모델 | ResNet · EfficientNet | **YOLO · Faster R-CNN** | U-Net · DeepLab | Mask R-CNN · YOLO-seg |

**왜 우리는 검출을 고르는가**

```
CCTV 요구사항
  "사람이 지나가면 알림"        → 검출로 충분
  "사람의 정확한 실루엣이 필요"  → 분할 필요 (우리는 불필요)

라벨링 비용
  박스 500장   →  6~10시간   ← 우리가 감당 가능
  외곽선 500장 →  40시간     ← 불가능

라즈베리파이 속도
  검출(yolo11n) →  실용 가능
  분할          →  1~2 FPS
```

> **검출은 "충분히 정확하면서 감당 가능한" 지점입니다.**
> 이것이 실무에서 검출이 가장 널리 쓰이는 이유입니다.

### 바운딩 박스 — 사각형 하나로 표현하기

**바운딩 박스(bounding box)** 는 객체를 감싸는 **축에 정렬된 최소 직사각형**입니다.

```
"축에 정렬된(axis-aligned)" = 기울어지지 않은 사각형

   ┌──────────┐        ╱‾‾‾‾‾╲
   │  🐕      │       ╱  🐕   ╲
   └──────────┘       ╲       ╱
   ✓ 우리가 쓰는 것      ╲_____╱
                       ✗ 회전 박스(OBB) — 다른 주제
```

**최소 직사각형**이라는 말이 중요합니다.

```
✓ 대상에 딱 맞게      ✗ 여유를 두고        ✗ 일부만
┌────────┐          ┌──────────────┐    ┌─────┐
│ ██████ │          │              │    │ ███ │████
│ ██████ │          │   ██████     │    └─────┘
└────────┘          │   ██████     │
                    └──────────────┘
```

박스를 여유 있게 치면 모델은 **배경도 객체의 일부**라고 배웁니다.
[Day 138](day-138.md)에서 이 원칙을 손으로 훈련합니다.

### ★ 이미지 좌표계 — 수학 시간과 다릅니다

여기서 처음 헷갈립니다.

```
수학 좌표계                   이미지 좌표계
                              (0,0) ───────→ x
    y                           │
    ↑                           │
    │                           │
 ───┼───→ x                     ↓
 (0,0)                          y

  y가 위로 증가                y가 아래로 증가
                              원점이 좌측 상단
```

**이미지에서 `y=0` 은 맨 위입니다.** 아래로 갈수록 y가 커집니다.

```python
import cv2

img = cv2.imread("dog.jpg")
print(img.shape)        # (450, 800, 3)
#                          ↑    ↑   ↑
#                          H    W   채널(BGR)
```

> ⚠️ **`img.shape` 는 `(높이, 너비, 채널)` 순서입니다.**
> 우리가 말할 때는 "800×450 이미지"라고 하는데, 코드에서는 `(450, 800, 3)` 입니다.
> **이 순서를 바꿔 쓰는 것이 이 단원 초반 실수 1위입니다.**

```python
h, w = img.shape[:2]        # ✓ 이렇게 받는 습관
w, h = img.shape[:2]        # ✗ 세로가 w에 들어감
```

### 좌표 형식 ① Pascal VOC — 두 모서리

```
(x_min, y_min, x_max, y_max)     단위: 픽셀 (절대값)
```

```
(0,0)
  ┌─────────────────────────────┐
  │                             │
  │   (34,88)                   │
  │      ┌───────────┐          │
  │      │    🐕     │          │
  │      │           │          │
  │      └───────────┘          │
  │              (210,340)      │
  └─────────────────────────────┘
                          (800,450)

  VOC = (34, 88, 210, 340)
        좌측상단 x, y      우측하단 x, y
```

| 장점 | 단점 |
|---|---|
| 사람이 읽기 쉬움 (구석 두 점) | 해상도가 바뀌면 값이 전부 바뀜 |
| 잘라내기·겹침 계산이 편함 | 파일이 XML이라 무거움 |
| **labelImg 기본 저장 포맷** | |

**XML 파일 모양**

```xml
<annotation>
  <filename>dog.jpg</filename>
  <size>
    <width>800</width>
    <height>450</height>
    <depth>3</depth>
  </size>
  <object>
    <name>dog</name>
    <bndbox>
      <xmin>34</xmin>
      <ymin>88</ymin>
      <xmax>210</xmax>
      <ymax>340</ymax>
    </bndbox>
  </object>
</annotation>
```

> **참고 — 1픽셀 논쟁**
> 원본 Pascal VOC는 좌표가 **1부터 시작**하고 `x_max` 가 **포함(inclusive)** 이었습니다.
> 그래서 엄밀히는 `너비 = x_max - x_min + 1` 입니다.
> 현대 도구들은 대부분 0부터 시작하고 `x_max` 를 제외로 다뤄 `너비 = x_max - x_min` 을 씁니다.
> **박스 크기가 200픽셀일 때 1픽셀 차이는 0.5%입니다. 무시해도 됩니다.**
> 단, 아주 작은 객체(10픽셀)를 다룰 땐 10% 차이가 되므로 도구의 규칙을 확인하세요.

### 좌표 형식 ② COCO — 한 모서리 + 크기

```
(x_min, y_min, width, height)     단위: 픽셀 (절대값)
```

```
  (34,88)
     ┌───────────┐
     │           │  height = 252
     │    🐕     │
     └───────────┘
       width = 176

  COCO = (34, 88, 176, 252)
```

VOC와 **앞의 두 숫자는 같고 뒤의 두 숫자만 다릅니다.** 이것이 함정입니다.

```
VOC  = (34, 88, 210, 340)
COCO = (34, 88, 176, 252)
        ↑   ↑    ↑    ↑
        같음      다름 — 그런데 둘 다 "그럴듯한" 숫자
```

**형식을 잘못 알고 그리면 박스가 이상하게 나오는데, 에러는 안 납니다.**

| 장점 | 단점 |
|---|---|
| 면적 계산이 즉시 (`w × h`) | 우측 하단을 알려면 덧셈 필요 |
| 이동/크기 변경이 직관적 | 해상도 의존 |
| **공개 데이터셋 표준** | |

**JSON 파일 모양**

```json
{
  "images": [
    {"id": 1, "file_name": "dog.jpg", "width": 800, "height": 450}
  ],
  "annotations": [
    {"id": 1, "image_id": 1, "category_id": 18,
     "bbox": [34, 88, 176, 252], "area": 44352, "iscrowd": 0}
  ],
  "categories": [
    {"id": 18, "name": "dog"}
  ]
}
```

### 좌표 형식 ③ YOLO — 중심 + 크기, 그리고 정규화

```
(class_id, x_center, y_center, width, height)     단위: 0~1 (정규화)
```

```
             cx = 122/800 = 0.1525
  ┌─────────────────────────────┐
  │      ┌─────·─────┐          │  cy = 214/450 = 0.4756
  │      │     ●     │          │       ●  = 박스 중심 (122, 214)
  │      └───────────┘          │
  └─────────────────────────────┘

  YOLO = 0  0.1525  0.4756  0.2200  0.5600
         ↑    cx      cy      w       h
      class
```

**두 가지가 동시에 다릅니다.**

```
① 기준점이 다름     : 모서리 → 중심
② 단위가 다름       : 픽셀 → 0~1 정규화
```

`.txt` 파일 모양 — **이미지 한 장에 텍스트 파일 한 개**입니다.

```
dog.jpg  ↔  dog.txt

# dog.txt (객체 3개)
0 0.152500 0.475556 0.220000 0.560000
0 0.443750 0.522222 0.187500 0.555556
2 0.812500 0.311111 0.075000 0.155556
```

| 장점 | 단점 |
|---|---|
| **해상도에 독립적** — 이미지를 리사이즈해도 값 그대로 | 사람이 눈으로 위치를 가늠하기 어려움 |
| 파일이 가볍고 읽기 빠름 | 이미지 크기를 모르면 픽셀로 못 되돌림 |
| **Ultralytics 학습 입력 포맷** | 클래스가 이름이 아니라 번호 |

### ★ 왜 정규화하는가

이것이 YOLO 포맷의 핵심 아이디어입니다.

```
원본 이미지 800×450 에서 라벨링
       ↓
학습할 때 640×640 으로 리사이즈
       ↓
VOC 좌표라면?  (34,88,210,340) → 전부 다시 계산해야 함
YOLO 좌표라면? (0.1525, 0.4756, 0.22, 0.56) → ★ 그대로 유효
```

**검출 학습은 이미지를 반드시 리사이즈합니다.** 사진마다 크기가 다르면 배치로 묶을 수 없기 때문입니다.
정규화 좌표는 이 리사이즈에 영향을 받지 않습니다.

> **"비율로 적어두면 크기가 변해도 그대로다."**
> 이 한 문장이 YOLO 포맷이 정규화를 쓰는 이유의 전부입니다.

### 세 형식 한눈에 비교

같은 박스 하나 (이미지 800×450, 클래스 `dog` = 0)

| | 형식 | 값 | 단위 |
|---|---|---|---|
| **VOC** | `x_min, y_min, x_max, y_max` | `34, 88, 210, 340` | 픽셀 |
| **COCO** | `x_min, y_min, w, h` | `34, 88, 176, 252` | 픽셀 |
| **YOLO** | `cx, cy, w, h` | `0.152500, 0.475556, 0.220000, 0.560000` | 0~1 |

**구분하는 법 — 숫자만 보고 판단하기**

```
값이 전부 0~1 사이     →  YOLO (정규화)
값이 정수이고 4개       →  VOC 또는 COCO
  세 번째 > 첫 번째이고
  네 번째 > 두 번째     →  VOC 일 가능성
  세 번째가 작음         →  COCO 일 가능성

★ 확실한 방법: 그려 본다
```

### 변환 공식 — 6방향 전부

**VOC ↔ COCO** (픽셀끼리, 정규화 없음)

```
VOC → COCO
    x = x_min
    y = y_min
    w = x_max - x_min
    h = y_max - y_min

COCO → VOC
    x_min = x
    y_min = y
    x_max = x + w
    y_max = y + h
```

**VOC ↔ YOLO** (이미지 크기 W, H 필요)

```
VOC → YOLO
    cx = (x_min + x_max) / 2 / W
    cy = (y_min + y_max) / 2 / H
    w  = (x_max - x_min)     / W
    h  = (y_max - y_min)     / H

YOLO → VOC
    x_min = (cx - w/2) * W
    y_min = (cy - h/2) * H
    x_max = (cx + w/2) * W
    y_max = (cy + h/2) * H
```

**COCO ↔ YOLO**

```
COCO → YOLO
    cx = (x + w/2) / W
    cy = (y + h/2) / H
    w  = w / W
    h  = h / H

YOLO → COCO
    w_px = w * W
    h_px = h * H
    x = cx * W - w_px/2
    y = cy * H - h_px/2
```

> **외우지 마세요.** 세 가지만 기억하면 전부 유도됩니다.
> ① VOC는 **두 점**, COCO는 **점 + 크기**, YOLO는 **중심 + 크기**
> ② YOLO만 **W, H로 나눔**
> ③ 중심 = (min + max) / 2, min = 중심 − 크기/2

### 신뢰도(confidence)와 클래스 점수

검출 결과에는 좌표 말고 숫자가 하나 더 붙습니다.

```python
{"class": "person", "conf": 0.87, "box": [280, 110, 430, 360]}
#                     ↑
#                 이게 뭔가?
```

**`conf` = 이 박스에 이 클래스의 객체가 있을 것이라는 모델의 확신 정도 (0~1)**

역사적으로 두 가지가 곱해진 값이었습니다.

```
YOLOv3~v7 방식

  objectness  : 이 박스에 "뭔가" 있는가        0.92
  class prob  : 그것이 person 일 확률          0.95
  ────────────────────────────────────────────
  conf        = 0.92 × 0.95 = 0.874
```

```
YOLOv8 / YOLO11 방식 (앵커프리 · 분리 헤드)

  objectness 분기가 없어짐
  conf = 클래스 점수 자체
```

**우리가 쓰는 YOLO11에서는 `conf` 가 곧 클래스 점수입니다.** 계산 방식은 달라도 **읽는 법은 같습니다.**

| conf | 해석 | 실무 판단 |
|---|---|---|
| 0.90 ~ 1.00 | 거의 확실 | 그대로 신뢰 |
| 0.60 ~ 0.90 | 대체로 맞음 | 일반적인 사용 구간 |
| 0.30 ~ 0.60 | 애매 | 용도에 따라 채택/기각 |
| 0.00 ~ 0.30 | 대부분 오검출 | 보통 버림 |

> ⚠️ **`conf` 는 확률이 아닙니다.**
> "0.87이면 87% 확률로 맞다"는 뜻이 아닙니다. 모델이 학습 중에 만들어낸 **점수**일 뿐입니다.
> 잘 보정되지 않은 모델은 틀린 것에도 0.95를 줍니다.
> **그래서 임계값을 데이터로 정해야 합니다** — [Day 149](day-149.md).

### Step 2. ★ 변환 함수 구현

`day136/bbox_utils.py` 로 저장합니다. **이 파일은 W28 내내 씁니다.**

```python
"""bbox_utils.py — 바운딩 박스 좌표 형식 변환

형식 정의
  voc  : (x_min, y_min, x_max, y_max)   픽셀
  coco : (x_min, y_min, w, h)           픽셀
  yolo : (cx, cy, w, h)                 0~1 정규화
"""


# ────────────────────────── VOC ↔ COCO ──────────────────────────
def voc_to_coco(box):
    """(x1, y1, x2, y2) → (x, y, w, h)"""
    x1, y1, x2, y2 = box
    return (x1, y1, x2 - x1, y2 - y1)


def coco_to_voc(box):
    """(x, y, w, h) → (x1, y1, x2, y2)"""
    x, y, w, h = box
    return (x, y, x + w, y + h)


# ────────────────────────── VOC ↔ YOLO ──────────────────────────
def voc_to_yolo(box, img_w, img_h):
    """(x1, y1, x2, y2) 픽셀 → (cx, cy, w, h) 정규화"""
    x1, y1, x2, y2 = box
    cx = (x1 + x2) / 2 / img_w
    cy = (y1 + y2) / 2 / img_h
    w = (x2 - x1) / img_w
    h = (y2 - y1) / img_h
    return (cx, cy, w, h)


def yolo_to_voc(box, img_w, img_h):
    """(cx, cy, w, h) 정규화 → (x1, y1, x2, y2) 픽셀"""
    cx, cy, w, h = box
    bw = w * img_w
    bh = h * img_h
    x1 = cx * img_w - bw / 2
    y1 = cy * img_h - bh / 2
    return (x1, y1, x1 + bw, y1 + bh)


# ────────────────────────── COCO ↔ YOLO ─────────────────────────
def coco_to_yolo(box, img_w, img_h):
    """(x, y, w, h) 픽셀 → (cx, cy, w, h) 정규화"""
    return voc_to_yolo(coco_to_voc(box), img_w, img_h)


def yolo_to_coco(box, img_w, img_h):
    """(cx, cy, w, h) 정규화 → (x, y, w, h) 픽셀"""
    return voc_to_coco(yolo_to_voc(box, img_w, img_h))


# ────────────────────────── 보조 함수 ──────────────────────────
def clip_voc(box, img_w, img_h):
    """이미지 밖으로 나간 좌표를 경계로 자름"""
    x1, y1, x2, y2 = box
    x1 = max(0, min(x1, img_w))
    y1 = max(0, min(y1, img_h))
    x2 = max(0, min(x2, img_w))
    y2 = max(0, min(y2, img_h))
    return (x1, y1, x2, y2)


def to_int(box):
    """OpenCV 그리기용 — 반올림 후 정수화"""
    return tuple(int(round(v)) for v in box)


def is_valid_yolo(box, eps=1e-9):
    """YOLO 좌표가 0~1 범위이고 박스가 이미지를 벗어나지 않는가"""
    cx, cy, w, h = box
    if not all(0 - eps <= v <= 1 + eps for v in (cx, cy, w, h)):
        return False, "0~1 범위를 벗어남"
    if w <= 0 or h <= 0:
        return False, "너비/높이가 0 이하"
    if cx - w / 2 < -eps or cx + w / 2 > 1 + eps:
        return False, "박스가 이미지 좌우를 벗어남"
    if cy - h / 2 < -eps or cy + h / 2 > 1 + eps:
        return False, "박스가 이미지 상하를 벗어남"
    return True, "OK"
```

**★ `coco_to_yolo` 를 처음부터 다시 짜지 않았습니다.**

```python
def coco_to_yolo(box, img_w, img_h):
    return voc_to_yolo(coco_to_voc(box), img_w, img_h)
```

VOC를 **중간 허브**로 두면 6개 함수 중 4개만 실제로 계산하면 됩니다.

### Step 5. OpenCV로 박스 그리기

```python
from pathlib import Path

import cv2

import bbox_utils as B

WORK = Path("day136")

# 클래스별 색상 — ★ OpenCV는 BGR 순서
COLORS = {
    "dog":    ( 60, 200,  60),   # 초록
    "person": (255, 120,  60),   # 파랑 계열
    "cat":    ( 60, 120, 255),   # 빨강 계열
}


def draw_box(img, voc_box, label, color=(0, 255, 0), conf=None, thickness=2):
    """이미지에 VOC 좌표 박스 + 라벨을 그린다 (원본을 수정)"""
    x1, y1, x2, y2 = B.to_int(voc_box)

    # ① 박스
    cv2.rectangle(img, (x1, y1), (x2, y2), color, thickness)

    # ② 라벨 문자열
    text = label if conf is None else f"{label} {conf:.2f}"

    # ③ 글자 크기를 먼저 재서 배경 사각형을 그린다
    font = cv2.FONT_HERSHEY_SIMPLEX
    scale, tk = 0.5, 1
    (tw, th), baseline = cv2.getTextSize(text, font, scale, tk)

    # 박스 위에 공간이 없으면 박스 안쪽에 그린다
    ty = y1 - 4 if y1 - th - 6 >= 0 else y1 + th + 6
    bg_y1 = ty - th - 4
    bg_y2 = ty + baseline

    cv2.rectangle(img, (x1, bg_y1), (x1 + tw + 6, bg_y2), color, -1)
    cv2.putText(img, text, (x1 + 3, ty), font, scale, (255, 255, 255), tk,
                lineType=cv2.LINE_AA)
    return img


# ── 실행 ──

h, w = img.shape[:2]

detections = [
    ("dog",    ( 34,  88, 210, 340), 0.94),

    ("person", (620,  60, 680, 210), 0.51),
]

    draw_box(img, box, name, COLORS[name], conf)

print("=" * 78)

print(f"  이미지: {w}×{h}")
print(f"  박스 {len(detections)}개\n")

    cw, ch = box[2] - box[0], box[3] - box[1]
    print(f"  {name:<8}{conf:.2f}  {str(box):<26}크기 {cw}×{ch}  면적 {cw*ch:,}px²")

### Step 6. ★ YOLO 라벨 파일 → 이미지에 그려서 검증

**이 Step이 오늘의 핵심입니다.** 라벨이 맞는지 확인하는 유일하게 확실한 방법입니다.

```python
from pathlib import Path

import cv2

import bbox_utils as B

WORK = Path("day136")
CLASS_NAMES = ["dog", "person", "cat"]
COLORS = [(60, 200, 60), (255, 120, 60), (60, 120, 255)]


def write_yolo_label(txt_path, items, img_w, img_h):
    """items: [(class_id, voc_box), ...] → YOLO txt 저장"""
    lines = []
    for cls_id, voc in items:
        cx, cy, bw, bh = B.voc_to_yolo(voc, img_w, img_h)
        lines.append(f"{cls_id} {cx:.6f} {cy:.6f} {bw:.6f} {bh:.6f}")
    txt_path.write_text("\n".join(lines) + "\n", encoding="utf-8")
    return len(lines)


def read_yolo_label(txt_path):
    """YOLO txt → [(class_id, (cx, cy, w, h)), ...]"""
    out = []
    if not txt_path.exists():
        return out                      # ★ 빈 라벨 = 객체 없음. 정상입니다
    for ln, line in enumerate(txt_path.read_text(encoding="utf-8").splitlines(), 1):
        line = line.strip()
        if not line:
            continue
        parts = line.split()
        if len(parts) != 5:
            raise ValueError(f"{txt_path.name} {ln}행: 값이 5개가 아님 → {line!r}")
        cls_id = int(parts[0])
        box = tuple(float(v) for v in parts[1:])
        out.append((cls_id, box))
    return out


def visualize_label(img_path, txt_path, out_path):
    """라벨 파일을 이미지에 그려서 저장 — ★ 눈으로 검증"""
    img = cv2.imread(str(img_path))
    if img is None:
        raise FileNotFoundError(img_path)
    h, w = img.shape[:2]

    items = read_yolo_label(txt_path)
    report = []
    for cls_id, yolo in items:
        ok, msg = B.is_valid_yolo(yolo)
        voc = B.yolo_to_voc(yolo, w, h)
        name = CLASS_NAMES[cls_id] if cls_id < len(CLASS_NAMES) else f"id{cls_id}"
        color = COLORS[cls_id % len(COLORS)]

        x1, y1, x2, y2 = B.to_int(voc)
        cv2.rectangle(img, (x1, y1), (x2, y2), color, 2)
        cv2.circle(img, ((x1 + x2) // 2, (y1 + y2) // 2), 4, color, -1)   # 중심점
        cv2.putText(img, name, (x1 + 3, max(y1 - 5, 14)),
                    cv2.FONT_HERSHEY_SIMPLEX, 0.5, color, 2, cv2.LINE_AA)
        report.append((name, yolo, B.to_int(voc), ok, msg))

    cv2.imwrite(str(out_path), img)
    return report, (w, h)


# ── 라벨 저장 → 다시 읽어서 그리기 ──
img_path = WORK / "images" / "sample.jpg"
txt_path = WORK / "labels" / "sample.txt"
out_path = WORK / "output" / "step6_verify.jpg"

    (0, ( 34,  88, 210, 340)),
    (0, (280, 110, 430, 360)),
    (1, (620,  60, 680, 210)),
], 800, 450)

print("=" * 92)
print(f"라벨 저장: {txt_path}  ({n}줄)")
print("-" * 92)
print(txt_path.read_text(encoding="utf-8").rstrip())
print("=" * 92)

print(f"\n라벨 검증 — {img_path.name} ({w}×{h})")
print("-" * 92)
print(f"{'클래스':<9}{'YOLO (cx, cy, w, h)':<42}{'복원 VOC':<28}{'판정'}")
print("-" * 92)
for name, yolo, voc, ok, msg in report:
    ystr = " ".join(f"{v:.4f}" for v in yolo)
    print(f"{name:<9}{ystr:<42}{str(voc):<28}{'✓' if ok else '✗ ' + msg}")
print("-" * 92)
print(f"  결과 이미지: {out_path}")
print("  ★ 이 이미지를 열어서 박스가 물체에 맞는지 눈으로 확인하세요")
print("=" * 92)

```python
from pathlib import Path

import cv2

import bbox_utils as B

CLASS_NAMES = ["dog", "person", "cat"]


def verify_dataset(img_dir, lbl_dir, out_dir, class_names=CLASS_NAMES, limit=None):
    """이미지 폴더 전체의 라벨을 검증하고 시각화 이미지를 저장한다"""
    img_dir, lbl_dir, out_dir = Path(img_dir), Path(lbl_dir), Path(out_dir)
    out_dir.mkdir(parents=True, exist_ok=True)

    exts = {".jpg", ".jpeg", ".png", ".bmp"}
    images = sorted(p for p in img_dir.iterdir() if p.suffix.lower() in exts)
    if limit:
        images = images[:limit]

    stats = {"이미지": 0, "박스": 0, "라벨없음": 0, "이상": 0}
    problems = []

    for p in images:
        stats["이미지"] += 1
        img = cv2.imread(str(p))
        if img is None:
            problems.append((p.name, "이미지를 읽을 수 없음"))
            continue
        h, w = img.shape[:2]

        txt = lbl_dir / (p.stem + ".txt")
        if not txt.exists():
            stats["라벨없음"] += 1
            problems.append((p.name, "라벨 파일 없음 (배경 이미지라면 정상)"))
            continue

        for ln, line in enumerate(txt.read_text(encoding="utf-8").splitlines(), 1):
            if not line.strip():
                continue
            parts = line.split()
            if len(parts) != 5:
                stats["이상"] += 1
                problems.append((p.name, f"{ln}행 값 개수 {len(parts)}"))
                continue
            cid = int(parts[0])
            yolo = tuple(float(v) for v in parts[1:])
            stats["박스"] += 1

            ok, msg = B.is_valid_yolo(yolo)
            if not ok:
                stats["이상"] += 1
                problems.append((p.name, f"{ln}행 {msg}"))
            if cid >= len(class_names):
                stats["이상"] += 1
                problems.append((p.name, f"{ln}행 클래스 id {cid} 정의 없음"))

            voc = B.to_int(B.clip_voc(B.yolo_to_voc(yolo, w, h), w, h))
            color = (0, 0, 255) if not ok else (60, 200, 60)
            cv2.rectangle(img, voc[:2], voc[2:], color, 2)
            name = class_names[cid] if cid < len(class_names) else f"id{cid}"
            cv2.putText(img, name, (voc[0] + 3, max(voc[1] - 5, 14)),
                        cv2.FONT_HERSHEY_SIMPLEX, 0.5, color, 2, cv2.LINE_AA)

        cv2.imwrite(str(out_dir / p.name), img)

    return stats, problems


stats, problems = verify_dataset("day136/images", "day136/labels",
                                 "day136/output/verify")

print("=" * 80)
print("데이터셋 라벨 검증")

    for name, msg in problems[:10]:
        print(f"    · {name:<24}{msg}")
else:
    print("  ✓ 문제 없음")
print("=" * 80)

**3.** 아래는 어떤 CCTV 프로젝트의 검출 결과입니다.

```
person 0.94 (120,  80, 260, 430)
person 0.91 (118,  76, 265, 435)
person 0.42 (600, 200, 640, 260)
dog    0.31 (400, 300, 470, 360)
```

① 이 결과에서 **눈에 띄는 문제 두 가지**를 지적하세요.
② "현관에 사람이 오면 알림"이라는 목적에서 `conf` 임계값을 얼마로 잡을지, 근거와 함께 답하세요.
③ 임계값을 잘못 잡았을 때 각각 어떤 일이 벌어지는지 쓰세요.

<details>
<summary>답 보기</summary>

### ① 문제 두 가지

**문제 A — 같은 사람에 박스가 2개 (중복 검출)**

```
person 0.94 (120, 80, 260, 430)
person 0.91 (118, 76, 265, 435)
       ↑ 좌표가 거의 같음. 겹침이 95% 이상
```

**원인**: NMS(비최대 억제)가 제대로 동작하지 않았습니다.
**대응**: `iou` 임계값을 낮춥니다 (0.7 → 0.45). → [Day 149](day-149.md)

**문제 B — 신뢰도가 낮은 검출이 섞여 있음**

```
person 0.42 (600, 200, 640, 260)   ← 40×60 픽셀. 아주 작음
dog    0.31 (400, 300, 470, 360)   ← 개를 키우지 않는다면 오검출
```

작은 박스 + 낮은 신뢰도는 **오검출의 전형적인 조합**입니다.

### ② 임계값 판단 — 목적이 정합니다

```
목적: "현관에 사람이 오면 알림"

놓치면(FN)  → 침입자를 못 잡음        ← 치명적
헛알림(FP)  → 휴대폰이 한 번 울림     ← 성가심

★ 놓치는 비용 > 헛알림 비용   →  재현율(recall) 우선
                              →  conf 를 낮게
```

**권장: `conf = 0.35 ~ 0.40`**

```
0.35 로 잡으면
  ✓ person 0.94, 0.91 채택 (중복은 NMS가 처리)
  ✓ person 0.42 채택      ← 진짜 사람일 수 있으므로 살림
  ✗ dog    0.31 기각

추가로 클래스 필터를 겁니다
  classes=[0]  (person만)  →  dog 는 아예 안 나옴
```

> **더 나은 방법 — 임계값 하나로 다 해결하려 하지 않기**
> ```
> ① conf 0.35 로 낮게 잡아 놓치지 않게 한다
> ② 대신 "3프레임 연속 검출" 조건을 건다  →  헛알림 감소
> ③ ROI(현관 영역) 밖은 무시한다          →  헛알림 감소
> ```
> [Day 170](day-170.md)에서 이 세 가지를 전부 구현합니다.

### ③ 잘못 잡았을 때

| 설정 | 결과 | 실제로 겪는 일 |
|---|---|---|
| `conf = 0.8` (너무 높음) | **미검출 증가** | 밤에 어두워 신뢰도가 0.6으로 떨어지는 순간 침입자를 놓침 |
| `conf = 0.1` (너무 낮음) | **오검출 폭증** | 나뭇가지 그림자에 알림. 하루 200번 울리면 **알림을 꺼 버립니다** |

**후자가 더 위험합니다.**

```
알림이 너무 잦음 → 사용자가 알림을 끔 → 시스템이 없는 것과 같음
```

> **"CCTV 침입 감지는 재현율 우선"이 원칙이지만,
> 재현율만 올리면 시스템이 사용되지 않게 됩니다.**
> 그래서 임계값 하나가 아니라 **연속 프레임 · ROI · 쿨다운**을 함께 씁니다.
> 이것이 [Day 149](day-149.md)와 [Day 170](day-170.md)를 나눠 배우는 이유입니다.

</details>

## 오늘의 정리

| 항목 | 핵심 |
|---|---|
| 검출 = ? | **무엇이 · 어디에 · 몇 개** — 출력 개수가 가변 |
| 4대 과제 | 분류 → **검출** → 의미 분할 → 인스턴스 분할 |
| 검출을 고르는 이유 | 라벨 비용 8× · 실시간 가능 · CCTV에 충분 |
| 이미지 좌표계 | **원점 좌상단 · y는 아래로** |
| `img.shape` | **(H, W, C)** — 순서 주의 |
| **VOC** | `x1, y1, x2, y2` 픽셀 — labelImg 저장 |
| **COCO** | `x, y, w, h` 픽셀 — 공개 데이터셋 |
| **YOLO** | `cx, cy, w, h` **0~1 정규화** — 학습 입력 |
| 정규화 이유 | **리사이즈해도 값이 유효** |
| 변환 허브 | VOC를 중간에 두면 함수 4개면 충분 |
| 검증 방법 | **왕복 변환** + ★ **그려 보기** |
| `conf` | 클래스 점수. **확률 아님** |
| 최다 사고 | 정규화 누락 · **W/H 교체** · 형식 착각 |
| 사고의 특징 | **에러가 안 남.** mAP만 0 |
| OpenCV 주의 | **BGR** · 정수 좌표 · 한글 불가 · 한글 경로 불가 |

> ③ **라벨은 반드시 그려서 확인하세요.** 검사 스크립트가 통과해도 틀릴 수 있습니다.
