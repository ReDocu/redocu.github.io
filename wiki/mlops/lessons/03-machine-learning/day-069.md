## ① 학습 목표

이 레슨을 마치면 이렇게 할 수 있습니다.

- 전체 평균 지표가 감추는 **집단별 성능 격차**를 분리 평가로 드러낼 수 있다.
- 격차가 "누구에게 어떤 불이익"이 되는지 서비스 언어로 번역할 수 있다.
- **모델 카드**의 표준 항목(용도 · 비대상 · 데이터 출처 · 성능 · 한계)을 채울 수 있다.
- 성능 격차 앞에서 가능한 대응(문서화 · 임계값 분리 · 데이터 보강)을 비교할 수 있다.

## ② 왜 필요한가

우리 모델의 성적표는 한 줄이었습니다: **test R² 0.519, MAE 4.26.** 오늘 이 평균을 쪼개 보면
이런 사실이 나옵니다 (실습에서 직접 확인합니다).

> 같은 모델이 강남구의 나쁨은 58%를 잡고, **노원구의 나쁨은 27%만** 잡습니다.

이 모델로 경보 서비스를 열면, 노원 주민은 강남 주민의 절반 수준의 보호를 받습니다.
누구도 의도하지 않았지만 결과는 **지역 간 서비스 격차**입니다. 실무의 유명 사례들 —
특정 성별에 불리한 채용 필터, 특정 인종에서 오류율이 높은 안면 인식, 재범 예측의 인종 편향 —
전부 "전체 평균은 좋았던" 모델들입니다.

그리고 석 달 뒤, 다른 팀이 이 모델을 "공기질 관련 예측이 필요하다"며 가져다 씁니다.
학습 범위(서울 5개 구, 2024-26년)를 모른 채 부산 데이터에 꽂으면 어떻게 될까요?
모델은 경고문 없이 아무 숫자나 뱉습니다. **모델 카드**는 이 두 사고(감춰진 격차, 범위 밖 사용)를
막는 문서입니다 — 약병의 성분표·효능·부작용 라벨과 같은 역할입니다.

## ③ 개념 설명

### 평균은 격차를 감춘다 — 분리 평가

편향 점검의 방법론은 단순합니다: **의미 있는 집단으로 쪼개서 같은 지표를 다시 잰다.**

| 축 | 우리 문제 | 실무 예 |
|---|---|---|
| 공간·집단 | 측정소(구)별 | 지역·성별·연령대·언어 |
| 시간 | 월별·계절별 | 요일, 프로모션 기간 |
| 값의 구간 | 좋음/보통/나쁨 | 소액/고액 거래 |

주의 두 가지: ① 집단이 작으면 지표가 흔들립니다 — **표본 수를 함께** 보고하세요.
② 격차 발견은 시작이지 결론이 아닙니다 — 원인(데이터 부족? 기저율 차이? 특성 누락?)을
추적해야 대응을 고를 수 있습니다.

### 모델 카드 — 표준 항목

모델 카드(Model Card)는 구글이 제안해 업계 표준이 된 **모델 문서 양식**입니다.

| 항목 | 답해야 할 질문 |
|---|---|
| 개요 | 무엇을 예측하나, 버전, 만든 사람, 날짜 |
| **용도** | 어디에 쓰라고 만들었나 |
| **비대상 (out of scope)** | 어디에 쓰면 **안 되나** ← 가장 자주 빠지고 가장 중요한 칸 |
| 데이터 | 출처 · 기간 · 규모 · **지문**([Day 066](day-066.md)) · 알려진 한계 |
| 성능 | 전체 + **집단별** 지표, 평가 방법 |
| 한계·편향 | 오늘 발견한 것들 — 숨기지 않고 |
| 윤리·주의 | 오용 시 피해, 재학습 주기 |

### 격차에 대한 세 가지 대응

| 대응 | 내용 | 우리 사례라면 |
|---|---|---|
| **문서화** (최소한) | 격차를 카드에 명시, 사용자에게 고지 | "노원 재현율 27% — 저농도 지역 경보는 보수적으로 해석" |
| 운영 보정 | 집단별 임계값·후처리 분리 | 노원의 경보 문턱을 33으로 낮춤 (헛경보 증가와 흥정) |
| 근본 개선 | 데이터·특성 보강, 재학습 | 저농도 지역의 나쁨 사례 축적, 구별 특성 추가 |

### Step 1. 측정소별 분리 평가 (1~2교시)

```python
# day069_card.py — 집단별 성능 분리와 모델 카드 (특성 생성부는 Day 065와 동일)
import joblib
import pandas as pd
from sklearn.metrics import mean_absolute_error, r2_score
# … (Day 065의 load()로 d, tr, te 준비)

pipe = joblib.load("models/pm25_pipeline.joblib")
te["pred"] = pipe.predict(te[COLS])
te["err"] = te.pred - te.pm25_next
print(f"전체 test: R² {r2_score(te.pm25_next, te.pred):.3f}  MAE {mean_absolute_error(te.pm25_next, te.pred):.2f}")

print("\n== A. 측정소별 성능 ==")
print("| 측정소 | 표본 | MAE | R² | 나쁨재현* |")
print("|---|---|---|---|---|")
for st, grp in te.groupby("station"):
    bad = grp.pm25_next >= 36
    rec = ((grp.pred >= 36) & bad).sum() / bad.sum() if bad.sum() else float("nan")
    print(f"| {st} | {len(grp)} | {mean_absolute_error(grp.pm25_next, grp.pred):.2f} | "
          f"{r2_score(grp.pm25_next, grp.pred):.3f} | {rec:.0%} ({bad.sum()}일) |")
print("* 나쁨재현: 실제 나쁨(>=36)인 날 중 예측도 36 이상이었던 비율")
```

실행 결과:

MAE·R²만 보면 다섯 구가 고만고만합니다(4.08~4.49). 그런데 **나쁨재현 열**을 보세요 —
강남 58% vs 노원 27%, **두 배가 넘는 격차**입니다. 원인 가설을 세워 봅시다:
노원은 기저 농도가 가장 낮은 지역이라([Day 051](day-051.md) 측정소별 평균 23.0), 나쁨(36)을
넘는 날이 대부분 문턱을 **살짝** 넘는 날들입니다. 평균 오차 4의 모델에게 "39를 39로" 맞히는
것은 "48을 44로" 맞히기(강남·문턱은 넘김)보다 훨씬 어렵습니다. 즉 격차의 뿌리는
**기저율 차이 + 평균으로의 회귀**([Day 053](day-053.md)) — 모델이 노원을 미워한 게 아니라,
수학이 저농도 지역에 구조적으로 불리하게 작동한 것입니다. 의도 없는 격차, 이것이 편향의 전형입니다.

### Step 2. 시기별·구간별 분리 평가 (3교시)

```python
print("\n== B. 월별 성능 ==")
for m, grp in te.groupby(te.date.dt.month):
    print(f"  {m}월: MAE {mean_absolute_error(grp.pm25_next, grp.pred):5.2f}  "
          f"평균오차(편향) {grp.err.mean():+5.2f}  표본 {len(grp)}")

print("\n== C. 농도 구간별 성능 ==")
bins = [(0, 16, "좋음"), (16, 36, "보통"), (36, 200, "나쁨")]
for lo, hi, name in bins:
    grp = te[(te.pm25_next >= lo) & (te.pm25_next < hi)]
    print(f"  {name}({lo}~{hi}): MAE {mean_absolute_error(grp.pm25_next, grp.pred):5.2f}  "
          f"평균오차 {grp.err.mean():+5.2f}  표본 {len(grp)}")
```

## ⑤ 자주 하는 실수

### 전체 지표 하나로 공정성을 판정함

**증상** — "MAE 차이가 0.4밖에 안 나니 지역 편향 없음"이라 결론.
**원인** — 회귀 지표(MAE)는 비슷해도 **문턱을 걸친 서비스 지표**(나쁨재현)는 두 배 차이였습니다.
**해결** — 분리 평가는 반드시 **서비스가 실제로 쓰는 지표**로. 지표 선택([Day 057](day-057.md))이 여기서도 결정적입니다.

### 작은 집단의 격차를 과잉 해석함

**증상** — "노원 27%(15일 중 4일)" → "모델이 노원을 차별한다!"고 단정.
**원인** — 표본 15일이면 하루 차이로 7%p가 움직입니다.
**해결** — 표본 수를 지표 옆에 병기하고(오늘 표의 괄호), 가능하면 기간을 늘리거나 여러 시드/기간으로 격차의 안정성을 확인한 뒤 결론을 냅니다. 다만 "표본이 작아 불확실"도 카드에 적을 정보입니다.

### 격차를 발견하고 조용히 임계값만 만져서 감춤

**증상** — 노원 임계값을 몰래 33으로 낮춰 재현율 표를 맞춰 놓음. 문서 없음.
**원인** — 보정 자체는 정당한 선택지지만, **기록 없는 보정**은 다음 담당자가 알 수 없는 지뢰입니다.
**해결** — 집단별 보정은 모델 카드와 운영 문서에 근거·날짜와 함께 명시합니다. 보정의 부작용(노원 헛경보 증가)도 같이.

### 모델 카드를 홍보문으로 씀

**증상** — 카드에 최고 지표와 장점만. "한계" 칸이 "특별한 한계 없음".
**원인** — 카드의 독자는 잠재 고객이 아니라 **미래의 사용자와 운영자**입니다.
**해결** — [Day 050](../02-sql-pipeline/day-050.md)의 교훈 그대로 — 한계를 아는 것이 신뢰의 근거입니다. 비대상·한계 칸이 빈약한 카드는 반려하세요.

### 카드를 만들고 갱신하지 않음

**증상** — 모델은 v3인데 카드는 v1 시절 숫자.
**원인** — 카드가 학습 프로세스 밖의 수작업으로 남아 있기 때문입니다.
**해결** — 내일([Day 070](day-070.md)) 만들 학습 CLI가 카드의 성능 숫자를 자동 갱신하도록 묶습니다. 문서도 파이프라인의 산출물입니다.

**Q2.** 모델 카드에서 "비대상(out of scope)" 칸이 성능 칸보다 중요한 이유를, 오늘 우리 카드의
