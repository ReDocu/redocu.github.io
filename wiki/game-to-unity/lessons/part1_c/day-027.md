## 2. 막히는 상황

Day 25의 알카노이드 코드를 다시 보자.

```c
// ─── Ball 관련 ───
typedef struct { double x, y, vx, vy; } Ball;

void  UpdateBall(Ball* b, double dt);
void  RenderBall(const Ball* b, char screen[][SCREEN_W+1]);
void  ResetBall(Ball* b);

// ─── Paddle 관련 ───

```

**세 가지 문제가 보인다.**

**① 데이터와 함수가 떨어져 있다**

```c
   Ball 구조체와 UpdateBall 함수는 사실 한 덩어리인데
   소스 파일에서는 수백 줄 떨어져 있을 수 있다
```

**② 이름이 계속 길어진다**

```c
   UpdateBall, UpdatePaddle, UpdateBlock, UpdateGame...
   RenderBall, RenderPaddle, RenderBlock, RenderGame...
   ★ 함수 이름에 "무엇에 대한 것인지"를 계속 붙여야 한다
```

**③ 실수를 막아주지 않는다**

```c
   Paddle p;
   UpdateBall((Ball*)&p, dt);      // 컴파일된다! 그리고 메모리가 망가진다

   Ball b;
   b.vx = 999999;                  // 아무나 아무 값이나 넣을 수 있다
```

```
   지금:   데이터(구조체)  +  기능(함수)  가 따로

   필요:   데이터와 기능을 하나로 묶고,
           밖에서 함부로 못 건드리게 감춘다
```

> **데이터와 그것을 다루는 함수를 하나로 묶는 방법이 필요하다.** → **클래스**

## 3. 개념

### 3-1. C에서 C++로 — 프로젝트 전환

**왜 필요한가** — 파일 확장자 하나가 컴파일 방식을 결정한다.

```
   main.c    →  C 컴파일러      (클래스 사용 불가)
   main.cpp  →  C++ 컴파일러    (클래스 사용 가능)
```

**전환 절차**

1. 솔루션 탐색기에서 `main.c` 우클릭 → 이름 바꾸기 → `main.cpp`
2. 빌드 → 오류가 나면 아래 표대로 수정

| C에서는 되는데 C++에서 오류 | 수정 |
|---|---|
| `void* p = malloc(...)` 을 `int*`에 대입 | `(int*)malloc(...)` — **캐스팅 필수** |
| `struct Ball b;` | `Ball b;` (C++는 `struct` 생략 가능) |
| 변수 이름이 `class`, `new`, `this` 등 | 이름 변경 (예약어) |
| 함수 원형 없이 호출 | 원형 선언 추가 (C++가 더 엄격) |

> **대부분은 캐스팅 문제다.** C는 `void*`를 자동 변환하지만 C++는 명시를 요구한다.

**입출력은 그대로 써도 된다**

```cpp
#include <cstdio>          // C++ 스타일 (stdio.h 도 그대로 동작)

printf("점수: %d\n", score);           // ✔ C++에서도 잘 된다
std::cout << "점수: " << score << "\n"; // C++ 스타일

// 이 과정에서는 printf 를 계속 쓴다. 서식 제어가 편하기 때문이다.
```

### 3-2. 클래스 — 구조체 + 함수

**왜 필요한가** — 관련된 데이터와 함수를 한 곳에 모은다.

```cpp
class Ball
{
public:
    void Update(double dt);
    void Render(char screen[][SCREEN_W + 1]) const;
    void Reset(double px, double py);

    double GetSpeed() const;
    void   SetSpeed(double s);

private:
    double m_x, m_y;
    double m_vx, m_vy;
    char   m_symbol;
};
```

```
   struct Ball { double x, y, vx, vy; };      class Ball {
   void UpdateBall(Ball* b, double dt);           double m_x, m_y, m_vx, m_vy;
   void RenderBall(const Ball* b, ...);       public:
                                                  void Update(double dt);
   ★ 두 덩어리                                    void Render(...) const;
                                              };
                                              ★ 한 덩어리
```

**멤버 함수 정의**

```cpp
// 클래스 밖에서 정의할 때는 클래스 이름 :: 을 붙인다
void Ball::Update(double dt)
{
    m_x += m_vx * dt;                    // ★ b-> 가 사라졌다
    m_y += m_vy * dt;

    if (m_x < 0)              { m_x = 0;              m_vx = -m_vx; }
    if (m_x > SCREEN_W - 1)   { m_x = SCREEN_W - 1;   m_vx = -m_vx; }
    if (m_y < 0)              { m_y = 0;              m_vy = -m_vy; }
}
```

**사용**

```cpp
Ball ball;

ball.Reset(20.0, 10.0);
ball.Update(dt);                         // UpdateBall(&ball, dt) 대신
ball.Render(screen);
```

> **`b->` 가 전부 사라진다.** 멤버 함수 안에서는 자기 멤버에 바로 접근할 수 있다.

### 3-3. `this` — 자기 자신을 가리키는 포인터

**왜 필요한가** — 멤버 함수는 사실 숨겨진 매개변수를 하나 더 받는다.

```cpp
class Ball
{
    double m_x;
public:
    void SetX(double x)
    {
        m_x = x;                // 사실은 this->m_x = x;
        this->m_x = x;          // 명시적으로 써도 된다 (같은 뜻)
    }
};
```

```
   컴파일러가 하는 일

   ball.Update(dt);
        ↓ 실제로는
   Ball::Update(&ball, dt);        ← &ball 이 this 로 들어간다

   ★ C에서 우리가 손으로 하던 "포인터 전달"을
     컴파일러가 대신 해주는 것뿐이다
```

> **클래스는 마법이 아니다.** Day 18에서 배운 포인터 전달을 문법으로 정리한 것이다.

### 3-4. 접근 지정자 — `public` / `private`

**왜 필요한가** — 밖에서 함부로 건드리면 안 되는 것을 감춘다.

```cpp
class Ball
{
public:                     // 밖에서 접근 가능
    void Update(double dt);
    double GetX() const { return m_x; }

private:                    // 클래스 안에서만 접근 가능
    double m_x, m_y;
    double m_vx, m_vy;
};
```

```cpp
Ball ball;

ball.Update(0.016);         // ✔ public
ball.m_x = 999;             // ✘ 컴파일 오류 — private
```

```
   ┌─────────────────── Ball ───────────────────┐
   │                                             │
   │  private:  m_x, m_y, m_vx, m_vy             │  ← 밖에서 안 보인다
   │  ─────────────────────────────────────────  │
   │  public:   Update(), Render(), GetSpeed()   │  ← 밖에서 쓸 수 있다
   │                                             │
   └─────────────────────────────────────────────┘
              ▲
              └── 이 경계를 "인터페이스"라고 한다
```

**왜 감추는가**

| 감추면 | 얻는 것 |
|---|---|
| 잘못된 값 대입을 막는다 | `ball.m_vx = 99999` 같은 사고 방지 |
| 내부 구현을 바꿀 수 있다 | `m_x, m_y` 를 `Vector2 m_pos` 로 바꿔도 밖은 영향 없음 |
| 무엇을 쓸 수 있는지 명확 | `public` 목록만 보면 사용법을 안다 |

**getter / setter**

```cpp
public:
    double GetX() const { return m_x; }              // 읽기

    void SetSpeed(double s)                          // 쓰기 (검증 포함)
    {
        if (s > MAX_SPEED) s = MAX_SPEED;            // ★ 검증을 여기서 한다
        if (s < 1.0)       s = 1.0;
        // ... 적용 ...
    }
```

> **모든 멤버에 getter/setter를 만드는 것은 의미가 없다.**
> 그럴 거면 `public`으로 두는 것과 같다.
> **정말 밖에서 필요한 것만** 노출한다.

### 3-5. `const` 멤버 함수

**왜 필요한가** — "이 함수는 상태를 안 바꾼다"를 컴파일러가 보증하게 한다.

```cpp
double GetSpeed() const                  // ★ 뒤에 const
{
    return sqrt(m_vx * m_vx + m_vy * m_vy);
    // m_x = 0;      ← 컴파일 오류. const 함수는 멤버를 못 바꾼다
}
```

```
   void Render(...) const;      "그리기만 한다. 상태는 안 바꾼다"
                                  ▲
                                  └── Day 25의 Update/Render 분리를
                                      컴파일러가 강제해 준다
```

> Day 18의 `const GameState*` 와 같은 발상이다.
> **읽기 전용 함수에는 반드시 `const`를 붙인다.**

### 3-6. 생성자와 소멸자

**왜 필요한가** — 초기화를 잊는 사고를 원천 차단한다.

```cpp
class Ball
{
public:
    Ball();                              // 생성자 — 만들어질 때 자동 호출
    ~Ball();                             // 소멸자 — 사라질 때 자동 호출

private:
    double m_x, m_y, m_vx, m_vy;
};

Ball::Ball()
    : m_x(0), m_y(0), m_vx(0), m_vy(0)   // ★ 초기화 리스트
{
}

Ball::~Ball()
{
    // 정리할 것이 있으면 여기서
}
```

```cpp
Ball ball;              // 여기서 생성자가 자동 호출된다
                        // → 초기화를 잊을 수가 없다

{
    Ball temp;          // 생성자 호출
    // ...
}                       // 블록을 벗어나면 소멸자 자동 호출
```

```
   C:                              C++:

   Ball b;                         Ball b;          ← 생성자가 알아서
   InitBall(&b);   ← 잊으면 버그
   // ...
   ReleaseBall(&b); ← 잊으면 누수   }                ← 소멸자가 알아서
```

**초기화 리스트를 쓰는 이유**

```cpp
Ball::Ball() { m_x = 0; }                // 기본값으로 만든 뒤 대입 (2단계)
Ball::Ball() : m_x(0) { }                // 처음부터 0으로 생성 (1단계, 더 효율적)
```

> `const` 멤버나 참조 멤버는 **초기화 리스트로만** 초기화할 수 있다.
> 습관적으로 초기화 리스트를 쓴다.

### 3-7. 참조자 `&` — 포인터보다 편한 전달

**왜 필요한가** — C++가 포인터의 불편함을 줄이기 위해 추가한 것.

```cpp
// 포인터 (Day 18)
void AddScore(int* score, int amount) { *score += amount; }
AddScore(&myScore, 100);

// 참조자
void AddScore(int& score, int amount) { score += amount; }      // * 불필요
AddScore(myScore, 100);                                          // & 불필요
```

| | 포인터 `T*` | 참조자 `T&` |
|---|---|---|
| `NULL` 가능 | O | **X** (항상 유효) |
| 나중에 다른 것 가리키기 | O | X (한 번 정하면 끝) |
| 문법 | `*p`, `p->` | 그냥 변수처럼 |
| `&` 붙여 호출 | 필요 | 불필요 |

```cpp
void Render(Screen& screen) const;       // 큰 객체를 복사 없이 전달
void Render(const Screen& screen) const; // 읽기만 할 때
```

> **규칙**
> - 값이 없을 수 있다 → **포인터** (`nullptr` 검사)
> - 항상 있다 → **참조자** (검사 불필요)
>
> 참조자를 쓰면 `nullptr` 검사가 필요 없어 코드가 짧아진다.

### 3-8. `new` / `delete`

**왜 필요한가** — C++의 동적 할당. `malloc`/`free`와 다르다.

```cpp
Ball* p = new Ball();            // 할당 + 생성자 호출
delete p;                        // 소멸자 호출 + 해제
p = nullptr;

Ball* arr = new Ball[10];        // 배열
delete[] arr;                    // ★ 배열은 delete[]
arr = nullptr;
```

| | `malloc`/`free` | `new`/`delete` |
|---|---|---|
| 생성자·소멸자 | 호출 안 함 | **호출함** |
| 크기 계산 | `sizeof` 직접 | 자동 |
| 반환형 | `void*` (캐스팅 필요) | 정확한 타입 |
| 실패 시 | `NULL` 반환 | 예외 발생 |

> ### ⚠️ 짝을 맞춘다
>
> ```
>   malloc  ↔  free
>   new     ↔  delete
>   new[]   ↔  delete[]
>
>   ★ 섞으면 안 된다. malloc으로 만든 걸 delete 하면 크래시.
> ```

`nullptr` — C++11부터의 널 포인터. `NULL`보다 안전하다.

```cpp
Ball* p = nullptr;               // ✔ C++ 방식
Ball* p = NULL;                  // 동작하지만 구식
```

### Step 2 — 첫 클래스: `Ball`

```cpp
class Ball
{
public:
    Ball();

    void Reset(double x, double y);
    void Launch(double vx, double vy);
    void Update(double dt);
    void Render(char screen[][SCREEN_W + 1]) const;

    double GetX() const { return m_x; }
    double GetY() const { return m_y; }
    double GetSpeed() const;
    void   SetSpeed(double s);

    bool IsLaunched() const { return m_launched; }
    bool IsOutOfBottom() const { return m_y > SCREEN_H - 1; }

    void BounceX() { m_vx = -m_vx; }
    void BounceY() { m_vy = -m_vy; }

    void SetPos(double x, double y) { m_x = x; m_y = y; }
    double GetVx() const { return m_vx; }
    double GetVy() const { return m_vy; }
    void   SetVel(double vx, double vy) { m_vx = vx; m_vy = vy; }

private:
    double m_x, m_y;
    double m_vx, m_vy;
    char   m_symbol;
    bool   m_launched;
};
```

```cpp
Ball::Ball()
    : m_x(0), m_y(0), m_vx(0), m_vy(0), m_symbol('@'), m_launched(false)
{
}

void Ball::Reset(double x, double y)
{
    m_x = x;
    m_y = y;
    m_vx = 0;
    m_vy = 0;
    m_launched = false;
}

void Ball::Launch(double vx, double vy)
{
    if (m_launched) return;

    m_vx = vx;
    m_vy = vy;
    m_launched = true;
}

void Ball::Update(double dt)
{
    if (!m_launched) return;

    m_x += m_vx * dt;
    m_y += m_vy * dt;

    if (m_x < 0)            { m_x = 0;            m_vx = -m_vx; }
    if (m_x > SCREEN_W - 1) { m_x = SCREEN_W - 1; m_vx = -m_vx; }
    if (m_y < 0)            { m_y = 0;            m_vy = -m_vy; }
}

void Ball::Render(char screen[][SCREEN_W + 1]) const
{
    int sx = (int)m_x;
    int sy = (int)m_y;

    if (sx >= 0 && sx < SCREEN_W && sy >= 0 && sy < SCREEN_H)
        screen[sy][sx] = m_symbol;
}

double Ball::GetSpeed() const
{
    return sqrt(m_vx * m_vx + m_vy * m_vy);
}

void Ball::SetSpeed(double s)
{
    if (s > MAX_SPEED) s = MAX_SPEED;
    if (s < 1.0)       s = 1.0;

    double cur = GetSpeed();
    if (cur < 0.0001) return;

    m_vx = m_vx / cur * s;
    m_vy = m_vy / cur * s;
}
```

```cpp
// 사용
Ball g_ball;

g_ball.Reset(SCREEN_W / 2.0, SCREEN_H - 3);
g_ball.Update(dt);
g_ball.Render(screen);
```

**✅ 여기까지 실행하면** — 공의 동작이 **Day 26과 완전히 동일**하다. 코드 구조만 바뀌었다.

### Step 5 — `Block` / `BlockField` 클래스

```cpp
class Block
{
public:
    Block() : m_hp(0), m_score(0) {}

    void Set(int hp, int score) { m_hp = hp; m_score = score; }

    bool IsAlive() const   { return m_hp > 0; }
    bool IsBreakable() const { return m_hp > 0; }

    // 맞았을 때 — 파괴되면 true
    bool Hit()
    {
        if (m_hp <= 0) return false;
        m_hp--;
        return m_hp == 0;
    }

    int  GetScore() const { return m_score; }
    int  GetHp() const    { return m_hp; }

private:
    int m_hp;
    int m_score;
};
```

```cpp
void Game::Run()
{
    clock_t prevTime = clock();

    while (m_running)
    {
        clock_t frameStart = clock();

        double dt = (double)(frameStart - prevTime) / CLOCKS_PER_SEC;
        prevTime = frameStart;
        if (dt > 0.1) dt = 0.1;

        UpdateInput();
        Update(dt);
        Render();

        LimitFrameRate(frameStart);
    }
}
```

## 6. 자주 막히는 곳

| 증상 | 원인 | 해결 |
|---|---|---|
| `error C2440: void*에서 변환 불가` | C++는 `malloc` 결과 캐스팅 필요 | `(T*)malloc(...)` |
| `error LNK2019: 확인할 수 없는 외부 기호` | 멤버 함수 선언만 하고 정의 안 함 | `.cpp`에 `클래스::함수` 정의 |
| `error C2248: private 액세스 불가` | 밖에서 `private` 멤버 접근 | getter 추가 또는 설계 재검토 |
| `error C2011: 클래스 재정의` | 헤더 중복 포함 | `#pragma once` |
| `const` 함수에서 멤버 수정 오류 | `const` 함수는 수정 불가 | 수정이 필요하면 `const` 제거 |
| 초기화 안 된 멤버 | 생성자 누락 | 생성자 + 초기화 리스트 |
| 크래시 (종료 시) | `delete` 누락 또는 이중 해제 | 짝 확인, `nullptr` 대입 |
| `delete[]` 대신 `delete` | 배열 해제 오류 | 배열은 `delete[]` |
| 참조자 초기화 오류 | 참조자는 선언 시 반드시 초기화 | 선언과 동시에 대입 |
| 헤더 순환 참조 | A.h가 B.h를, B.h가 A.h를 포함 | 전방 선언 `class B;` 사용 |

## 7. 정리

### 오늘 배운 것

| 개념 | 한 줄 요약 |
|---|---|
| **클래스** | 데이터 + 그 데이터를 다루는 함수를 한 덩어리로 |
| `this` | 멤버 함수에 숨겨진 자기 자신 포인터. C의 포인터 전달을 문법화 |
| `public` / `private` | 밖에 보일 것과 감출 것. **컴파일러가 실수를 막아준다** |
| `const` 멤버 함수 | 상태를 안 바꾼다는 보증. Update/Render 분리를 강제 |
| 생성자 / 소멸자 | 초기화와 정리를 **자동으로**. 잊을 수가 없다 |
| 초기화 리스트 | `: m_x(0), m_y(0)` — 더 효율적 |
| 참조자 `&` | 포인터보다 편한 전달. `nullptr` 검사 불필요 |
| `new` / `delete` | 생성자·소멸자를 호출하는 동적 할당. **짝을 맞춘다** |
| 헤더 분리 | `.h` 선언 / `.cpp` 정의. `#pragma once` 필수 |
