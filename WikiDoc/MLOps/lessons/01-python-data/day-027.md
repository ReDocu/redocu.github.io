## ③ 개념 설명

### 행 지향 vs 컬럼 지향

**CSV는 행 지향입니다.** 한 행의 모든 값이 붙어 있습니다.

```
CSV (행 지향)
2026-08-01,강남구,41,25,0.03
2026-08-01,서초구,38,22,0.04
2026-08-02,강남구,45,28,0.02
```

**Parquet은 컬럼 지향입니다.** 같은 컬럼의 값이 모여 있습니다.

```
Parquet (컬럼 지향)
[2026-08-01, 2026-08-01, 2026-08-02]     ← date 컬럼
[강남구, 서초구, 강남구]                    ← station 컬럼
[41, 38, 45]                              ← pm10 컬럼
[25, 22, 28]                              ← pm25 컬럼
```

**이 차이가 세 가지 이점을 만듭니다.**

| 이점 | 이유 |
|---|---|
| **압축이 잘 됨** | 같은 타입·비슷한 값이 모여 있어 압축률이 높음 |
| **필요한 컬럼만 읽음** | 컬럼이 따로 저장돼 있어 나머지를 안 읽어도 됨 |
| **타입 보존** | 컬럼마다 타입이 메타데이터에 기록됨 |

**행 지향이 유리한 경우도 있습니다.**

```
"이 한 행 전체를 읽어라"       → 행 지향 유리 (트랜잭션 DB)
"이 컬럼의 평균을 구해라"       → 컬럼 지향 유리 (분석)
```

**분석 작업은 거의 항상 컬럼 지향이 유리합니다.**

### 주요 포맷 비교

| 포맷 | 크기 | 읽기 | 타입 | 사람이 읽기 | 용도 |
|---|---|---|---|---|---|
| **CSV** | 100% | 느림 | ❌ | ✅ | 교환·확인 |
| CSV.gz | ~25% | 더 느림 | ❌ | ❌ | 보관 |
| JSON | ~250% | 느림 | 부분 | ✅ | API·중첩 |
| **Parquet** | ~15% | **빠름** | ✅ | ❌ | **분석·저장** ⭐ |
| Feather | ~30% | **가장 빠름** | ✅ | ❌ | 임시 캐시 |
| Pickle | ~40% | 빠름 | ✅ | ❌ | ⚠ 보안 위험 |
| HDF5 | ~30% | 빠름 | ✅ | ❌ | 과학 계산 |

> **Pickle을 주의하세요.** 임의 코드를 실행할 수 있어 **신뢰할 수 없는 파일을 열면 안 됩니다.**
> 그리고 파이썬·Pandas 버전이 바뀌면 못 읽을 수 있습니다. **장기 보관에 쓰지 마세요.**

### Parquet 사용

```python
pip install pyarrow
```

```python
df.to_parquet("data.parquet")
df.to_parquet("data.parquet", compression="snappy")     # 기본, 빠름
df.to_parquet("data.parquet", compression="zstd")       # 압축률 좋음
df.to_parquet("data.parquet", compression="gzip")       # 가장 작음, 느림
df.to_parquet("data.parquet", index=False)              # 인덱스 제외

df = pd.read_parquet("data.parquet")
df = pd.read_parquet("data.parquet", columns=["date", "pm10"])   # 컬럼 선택 ⭐
df = pd.read_parquet("data.parquet", filters=[("region", "==", "동남")])  # 필터 푸시다운
```

**압축 방식 선택**

| 압축 | 크기 | 쓰기 | 읽기 | 언제 |
|---|---|---|---|---|
| `snappy` (기본) | 보통 | 빠름 | 빠름 | 일반적 ⭐ |
| `zstd` | 작음 | 보통 | 빠름 | 저장 공간이 중요할 때 ⭐ |
| `gzip` | 가장 작음 | 느림 | 보통 | 장기 보관 |
| `None` | 큼 | 가장 빠름 | 가장 빠름 | 임시 파일 |

### 파티셔닝

**폴더 구조로 데이터를 나눠 저장합니다.**

```python
df.to_parquet("data/measurements", partition_cols=["year", "month"])
```

```
data/measurements/
├── year=2025/
│   ├── month=1/
│   │   └── part-0.parquet
│   ├── month=2/
│   │   └── part-0.parquet
│   └── ...
└── year=2026/
    └── ...
```

**읽을 때 필요한 파티션만 읽습니다.**

```python
# 2026년 8월만 — 다른 폴더는 열지도 않음
df = pd.read_parquet("data/measurements",
                     filters=[("year", "==", 2026), ("month", "==", 8)])
```

**파티션 키 고르는 기준**

| 좋은 파티션 키 | 나쁜 파티션 키 |
|---|---|
| 날짜(년·월) — 대부분 기간으로 조회 | 고유값이 수천 개 (ID) |
| 지역·카테고리 — 자주 필터하는 값 | 거의 필터하지 않는 컬럼 |
| 고유값 수십~수백 | 고유값 1~2개 (의미 없음) |

> **파티션이 너무 많으면 오히려 느려집니다.** 작은 파일이 수천 개가 되면
> 파일 열기 오버헤드가 커집니다. **파티션당 최소 수십 MB**를 목표로 하세요.

### 스키마 진화

**Parquet은 컬럼 추가에 유연합니다.**

```python
# 1월 데이터 (컬럼 5개)
df_jan.to_parquet("data/part/year=2026/month=1/data.parquet")

# 2월부터 컬럼이 하나 늘어남 (컬럼 6개)
df_feb.to_parquet("data/part/year=2026/month=2/data.parquet")

# 함께 읽으면 1월 행의 새 컬럼은 NaN
df = pd.read_parquet("data/part")
```

**CSV로는 이게 안 됩니다.** 컬럼 수가 다르면 파싱이 깨집니다.

### Polars — 더 빠른 DataFrame

```python
pip install polars
```

```python
import polars as pl

df = pl.read_csv("data.csv")
df = pl.read_parquet("data.parquet")

result = (df
    .filter(pl.col("pm10") > 100)
    .group_by("station")
    .agg(pl.col("pm10").mean().alias("avg"))
    .sort("avg", descending=True))
```

| | Pandas | Polars |
|---|---|---|
| 구현 | Python + C | **Rust** |
| 병렬 | 단일 코어 | **멀티코어 자동** |
| 메모리 | 많이 씀 | 적게 씀 |
| 지연 실행 | ❌ | ✅ (`scan_csv`) |
| 생태계 | **매우 큼** | 성장 중 |
| 학습 곡선 | — | 문법이 다름 |

**지연 실행(lazy)이 강력합니다.**

```python
result = (pl.scan_parquet("data/*.parquet")     # 아직 안 읽음
    .filter(pl.col("year") == 2026)
    .select(["station", "pm10"])
    .group_by("station")
    .agg(pl.col("pm10").mean())
    .collect())                                  # 여기서 실행 — 최적화된 계획으로
```

Polars가 **"어차피 station·pm10만 필요하니 나머지는 안 읽자"** 를 스스로 판단합니다.

> **이 과정에서는 Pandas를 씁니다.** sklearn·PyTorch 생태계가 Pandas 기준이기 때문입니다.
> Polars는 **"이런 것도 있다"** 정도로 알아 두고, 대용량 전처리에서 병목이 생기면 고려하세요.

### 포맷 선택 기준

```
사람이 열어 봐야 하는가?
  예 → CSV (utf-8-sig)
  아니오 ↓

중첩 구조인가?
  예 → JSON / JSONL
  아니오 ↓

다른 시스템(엑셀·다른 언어)과 교환하는가?
  예 → CSV
  아니오 ↓

→ Parquet ⭐
```

**실무 패턴 — 둘 다 저장**

```
data/
├── raw/          원본 (CSV·JSON 그대로)
├── processed/    정제 결과 (Parquet)  ← 프로그램이 쓰는 것
└── reports/      사람이 볼 것 (CSV·xlsx)
```

### Step 2. 크기와 속도 벤치마크

`format_benchmark.py` 를 만듭니다.

```python
"""저장 포맷 벤치마크 — 크기·쓰기·읽기 속도."""

import gc
import time
from pathlib import Path

import pandas as pd

OUT = Path("data/bench")
OUT.mkdir(parents=True, exist_ok=True)

SOURCE = Path("data/large.csv")
ROWS = 1_000_000

DTYPES = {
    "station": "category", "region": "category", "grade": "category",
    "pm10": "uint8", "pm25": "uint8",
    "o3": "float32", "no2": "float32", "temperature": "float32",
    "humidity": "uint8", "device_id": "uint16", "is_valid": "bool",
}

print(f"{ROWS:,}행 로딩 중...")
df = pd.read_csv(SOURCE, nrows=ROWS, dtype=DTYPES, parse_dates=["measured_at"])
print(f"  메모리: {df.memory_usage(deep=True).sum() / 1024**2:,.1f} MB\n")


def timed(func):
    gc.collect()
    start = time.perf_counter()
    result = func()
    return time.perf_counter() - start, result


FORMATS = {
    "csv": (
        lambda p: df.to_csv(p, index=False),
        lambda p: pd.read_csv(p),
    ),
    "csv (dtype 지정 읽기)": (
        lambda p: df.to_csv(p, index=False),
        lambda p: pd.read_csv(p, dtype=DTYPES, parse_dates=["measured_at"]),
    ),
    "csv.gz": (
        lambda p: df.to_csv(p, index=False, compression="gzip"),
        lambda p: pd.read_csv(p, compression="gzip"),
    ),
    "json": (
        lambda p: df.to_json(p, orient="records", date_format="iso"),
        lambda p: pd.read_json(p),
    ),
    "parquet (snappy)": (
        lambda p: df.to_parquet(p, index=False, compression="snappy"),
        lambda p: pd.read_parquet(p),
    ),
    "parquet (zstd)": (
        lambda p: df.to_parquet(p, index=False, compression="zstd"),
        lambda p: pd.read_parquet(p),
    ),
    "parquet (gzip)": (
        lambda p: df.to_parquet(p, index=False, compression="gzip"),
        lambda p: pd.read_parquet(p),
    ),
    "parquet (무압축)": (
        lambda p: df.to_parquet(p, index=False, compression=None),
        lambda p: pd.read_parquet(p),
    ),
    "feather": (
        lambda p: df.to_feather(p),
        lambda p: pd.read_feather(p),
    ),
    "pickle": (
        lambda p: df.to_pickle(p),
        lambda p: pd.read_pickle(p),
    ),
}

EXTENSIONS = {
    "csv": ".csv", "csv (dtype 지정 읽기)": ".csv", "csv.gz": ".csv.gz",
    "json": ".json", "parquet (snappy)": ".snappy.parquet",
    "parquet (zstd)": ".zstd.parquet", "parquet (gzip)": ".gzip.parquet",
    "parquet (무압축)": ".raw.parquet", "feather": ".feather", "pickle": ".pkl",
}

results = []

print("=" * 92)
print(f"{'포맷':<24}{'크기(MB)':>11}{'쓰기(초)':>11}{'읽기(초)':>11}"
      f"{'타입보존':>10}{'메모리(MB)':>12}")
print("=" * 92)

for name, (writer, reader) in FORMATS.items():
    path = OUT / f"bench{EXTENSIONS[name]}"

    write_time, _ = timed(lambda: writer(path))
    size_mb = path.stat().st_size / 1024**2
    read_time, loaded = timed(lambda: reader(path))

    preserved = "✅" if loaded.dtypes.equals(df.dtypes) else "❌"
    mem = loaded.memory_usage(deep=True).sum() / 1024**2

    results.append({
        "포맷": name, "크기": size_mb, "쓰기": write_time,
        "읽기": read_time, "타입": preserved, "메모리": mem,
    })
```

```python
"""필요한 컬럼만 읽기 — 컬럼 지향의 이점."""

import gc
import time
from pathlib import Path

import pandas as pd

CSV = Path("data/large.csv")
PQ = Path("data/bench/bench.zstd.parquet")

NEEDED = ["measured_at", "station", "pm10"]

print("=" * 76)
print("측정소별 평균 미세먼지 — 12개 컬럼 중 3개만 필요")
print("=" * 76)


def timed(label, func):
    gc.collect()
    start = time.perf_counter()
    result = func()
    elapsed = time.perf_counter() - start
    print(f"  {label:<38}{elapsed:>8.2f}초")
    return result


r1 = timed("CSV 전체 읽기", lambda: pd.read_csv(CSV, nrows=1_000_000))
r2 = timed("CSV usecols", lambda: pd.read_csv(CSV, nrows=1_000_000, usecols=NEEDED))
r3 = timed("Parquet 전체 읽기", lambda: pd.read_parquet(PQ))
r4 = timed("Parquet columns 지정", lambda: pd.read_parquet(PQ, columns=NEEDED))

print(f"""
  CSV 는 usecols 를 써도 **파일 전체를 파싱**합니다.
    → 행 지향이라 필요 없는 컬럼도 읽고 나서 버립니다.

  Parquet 은 컬럼이 따로 저장돼 있어 **해당 부분만 디스크에서 읽습니다.**
    → 컬럼 3/12 만 읽으면 I/O 도 1/4
""")

print("=" * 76)
print("메모리 비교")
print("=" * 76)
for label, df in [("CSV 전체", r1), ("CSV usecols", r2),
                  ("Parquet 전체", r3), ("Parquet columns", r4)]:
    mb = df.memory_usage(deep=True).sum() / 1024**2
    print(f"  {label:<24}{mb:>10,.1f} MB   컬럼 {len(df.columns)}개")

print("\n" + "=" * 76)
print("컬럼 수에 따른 읽기 시간")
print("=" * 76)
all_columns = pd.read_parquet(PQ).columns.tolist()

for n in [1, 3, 6, 9, len(all_columns)]:
    cols = all_columns[:n]
    start = time.perf_counter()
    df = pd.read_parquet(PQ, columns=cols)
    elapsed = time.perf_counter() - start
    mb = df.memory_usage(deep=True).sum() / 1024**2
    bar = "■" * int(elapsed * 40)
    print(f"  컬럼 {n:>2}개 — {elapsed:>5.2f}초  {mb:>7,.1f} MB  {bar}")
    del df
    gc.collect()

print("\n" + "=" * 76)
print("행 필터 푸시다운")
print("=" * 76)

start = time.perf_counter()
filtered = pd.read_parquet(PQ, filters=[("region", "==", "동남")])
t1 = time.perf_counter() - start
print(f"  filters 사용        : {t1:.2f}초, {len(filtered):,}행")

start = time.perf_counter()
full = pd.read_parquet(PQ)
manual = full[full["region"] == "동남"]
t2 = time.perf_counter() - start
print(f"  전체 읽고 필터      : {t2:.2f}초, {len(manual):,}행")
print(f"  → {t2 / t1:.1f}배 빠름")

print("""
  filters 는 Parquet 의 통계 정보(각 블록의 min/max)를 보고
  조건에 맞을 수 없는 블록을 아예 읽지 않습니다.
  이것을 **프레디케이트 푸시다운**이라고 합니다.
""")
```

```python
"""Polars 맛보기 — Pandas 와 비교."""

import time
from pathlib import Path

import pandas as pd
import polars as pl

CSV = Path("data/large.csv")
PQ = Path("data/bench/bench.zstd.parquet")

print(f"Polars {pl.__version__} / Pandas {pd.__version__}\n")


def timed(label, func):
    start = time.perf_counter()
    result = func()
    elapsed = time.perf_counter() - start
    print(f"  {label:<40}{elapsed:>8.2f}초")
    return result


print("=" * 74)
print("1) CSV 읽기")
print("=" * 74)
pdf = timed("Pandas read_csv", lambda: pd.read_csv(CSV, nrows=1_000_000))
pldf = timed("Polars read_csv", lambda: pl.read_csv(CSV, n_rows=1_000_000))

print("\n" + "=" * 74)
print("2) 그룹 집계 — 측정소별 평균")
print("=" * 74)

r_pd = timed("Pandas groupby",
             lambda: pdf[pdf["is_valid"]].groupby("station")["pm10"].mean())

r_pl = timed("Polars group_by", lambda: (
    pldf.filter(pl.col("is_valid"))
        .group_by("station")
        .agg(pl.col("pm10").mean().alias("avg"))
        .sort("avg", descending=True)
))

print(f"\n  Polars 결과 (상위 5):")
print(r_pl.head(5))

print("\n" + "=" * 74)
print("3) 지연 실행 (lazy) — Polars 의 강점")
print("=" * 74)

result = timed("Polars scan_parquet (lazy)", lambda: (
    pl.scan_parquet(PQ)                       # 아직 안 읽음
      .filter(pl.col("pm10") > 100)
      .group_by("region")
      .agg([
          pl.col("pm10").mean().alias("avg_pm10"),
          pl.col("pm10").count().alias("n"),
      ])
      .sort("avg_pm10", descending=True)
      .collect()                              # 여기서 실행
))
print(result)

print("""
  scan_parquet 은 계획만 세우고 collect() 에서 실행합니다.
  Polars 가 "region·pm10 만 필요하다"를 스스로 판단해
  다른 컬럼은 디스크에서 읽지도 않습니다.
""")

print("=" * 74)
print("4) 문법 비교")
print("=" * 74)
print("""
  Pandas:
    df[df["pm10"] > 100].groupby("region")["pm10"].agg(["mean", "count"])

  Polars:
    df.filter(pl.col("pm10") > 100)
      .group_by("region")
      .agg([pl.col("pm10").mean(), pl.col("pm10").count()])

  → Polars 는 메서드 체이닝이 강제되어 흐름이 명확합니다.
     대신 문법을 새로 배워야 합니다.
""")

print("=" * 74)
print("5) 상호 변환")
print("=" * 74)
converted_pd = pldf.to_pandas()
converted_pl = pl.from_pandas(pdf)
print(f"  Polars → Pandas: {type(converted_pd).__name__}, {converted_pd.shape}")
print(f"  Pandas → Polars: {type(converted_pl).__name__}, {converted_pl.shape}")
print(f"""
  변환이 자유로우므로 **필요한 부분만 Polars 로** 처리하고
  sklearn·PyTorch 에 넘길 때는 Pandas 로 바꾸면 됩니다.
""")

print("=" * 74)
print("이 과정에서의 선택")
print("=" * 74)
print("""
  Pandas 를 기본으로 씁니다:
    - sklearn, PyTorch, matplotlib 이 전부 Pandas 기준
    - 자료·예제가 압도적으로 많음
    - 이 과정 이후 실무에서도 여전히 표준

  Polars 를 고려할 때:
    - 전처리가 병목이고 데이터가 수천만 행 이상
    - 멀티코어를 자동으로 쓰고 싶을 때
    - 메모리가 부족할 때 (lazy + streaming)

  → "Pandas 로 하다가 느리면 그 부분만 Polars" 가 현실적입니다.
""")
```

### Step 6. 포맷 선택 유틸리티

`storage.py` 를 만듭니다. [Day 029](day-029.md)에서 씁니다.

```python
"""저장 포맷 유틸리티."""

from __future__ import annotations

import logging
from pathlib import Path
from typing import Any, Literal

import pandas as pd

logger = logging.getLogger(__name__)

Format = Literal["csv", "parquet", "json", "feather"]

EXTENSIONS: dict[Format, str] = {
    "csv": ".csv",
    "parquet": ".parquet",
    "json": ".json",
    "feather": ".feather",
}


def save(df: pd.DataFrame, path: Path | str, fmt: Format | None = None,
         compression: str = "zstd", **kwargs) -> Path:
    """DataFrame 을 저장합니다. 확장자로 포맷을 판단합니다."""
    path = Path(path)
    path.parent.mkdir(parents=True, exist_ok=True)

    if fmt is None:
        fmt = _infer_format(path)

    if fmt == "parquet":
        df.to_parquet(path, index=False, compression=compression, **kwargs)
    elif fmt == "csv":
        kwargs.setdefault("encoding", "utf-8-sig")
        df.to_csv(path, index=False, **kwargs)
    elif fmt == "json":
        kwargs.setdefault("force_ascii", False)
        kwargs.setdefault("orient", "records")
        kwargs.setdefault("date_format", "iso")
        df.to_json(path, indent=2, **kwargs)
    elif fmt == "feather":
        df.to_feather(path, **kwargs)
    else:
        raise ValueError(f"지원하지 않는 포맷: {fmt}")

    size_mb = path.stat().st_size / 1024**2
    logger.info("저장: %s (%s, %d행, %.1f MB)", path, fmt, len(df), size_mb)
    return path


def load(path: Path | str, fmt: Format | None = None,
         columns: list[str] | None = None, **kwargs) -> pd.DataFrame:
    """DataFrame 을 읽습니다."""
    path = Path(path)
    if not path.exists():
        raise FileNotFoundError(f"파일이 없습니다: {path}")

    if fmt is None:
        fmt = _infer_format(path)

    if fmt == "parquet":
        df = pd.read_parquet(path, columns=columns, **kwargs)
    elif fmt == "csv":
        kwargs.setdefault("encoding", "utf-8-sig")
        df = pd.read_csv(path, usecols=columns, **kwargs)
    elif fmt == "json":
        df = pd.read_json(path, **kwargs)
        if columns:
            df = df[columns]
    elif fmt == "feather":
        df = pd.read_feather(path, columns=columns, **kwargs)
    else:
        raise ValueError(f"지원하지 않는 포맷: {fmt}")

    logger.info("로드: %s (%d행 × %d열)", path, len(df), len(df.columns))
    return df


def _infer_format(path: Path) -> Format:
    """확장자로 포맷을 판단합니다."""
    suffixes = "".join(path.suffixes).lower()
    if ".parquet" in suffixes or ".pq" in suffixes:
        return "parquet"
    if ".feather" in suffixes or ".arrow" in suffixes:
        return "feather"
    if ".json" in suffixes or ".jsonl" in suffixes:
        return "json"
    if ".csv" in suffixes:
        return "csv"
    if path.is_dir():
        return "parquet"          # 파티션 폴더
    raise ValueError(f"확장자로 포맷을 알 수 없습니다: {path}")


def save_partitioned(df: pd.DataFrame, path: Path | str,
                     partition_cols: list[str],
                     compression: str = "zstd") -> Path:
    """파티션 구조로 저장합니다."""
    path = Path(path)
    path.mkdir(parents=True, exist_ok=True)

    for col in partition_cols:
        if col not in df.columns:
            raise ValueError(f"파티션 컬럼이 없습니다: {col}")
        n = df[col].nunique()
        if n > 1000:
            logger.warning("파티션 컬럼 %s 의 고유값이 %d개입니다. "
                           "작은 파일이 많아질 수 있습니다.", col, n)

    df.to_parquet(path, index=False, partition_cols=partition_cols,
                  compression=compression)

    files = list(path.rglob("*.parquet"))
    total_mb = sum(f.stat().st_size for f in files) / 1024**2
    logger.info("파티션 저장: %s (%d 파일, %.1f MB)", path, len(files), total_mb)
    return path


def load_partitioned(path: Path | str,
                     filters: list[tuple] | None = None,
                     columns: list[str] | None = None) -> pd.DataFrame:
    """파티션에서 필요한 부분만 읽습니다.

    Example:
        load_partitioned("data/measurements",
                         filters=[("year", "==", 2026), ("month", ">=", 6)],
                         columns=["station", "pm10"])
    """
    df = pd.read_parquet(path, filters=filters, columns=columns)
    logger.info("파티션 로드: %s (%d행, filters=%s)", path, len(df), filters)
    return df


def compare_formats(df: pd.DataFrame, out_dir: Path | str = "data/_compare"
                    ) -> pd.DataFrame:
    """여러 포맷으로 저장해 크기·속도를 비교합니다."""
    import time

    out_dir = Path(out_dir)
    out_dir.mkdir(parents=True, exist_ok=True)

    candidates = [
        ("csv", "csv", {}),
        ("parquet-snappy", "parquet", {"compression": "snappy"}),
        ("parquet-zstd", "parquet", {"compression": "zstd"}),
        ("feather", "feather", {}),
    ]

    rows = []
    for name, fmt, kwargs in candidates:
        path = out_dir / f"cmp_{name}{EXTENSIONS[fmt]}"

        start = time.perf_counter()
        save(df, path, fmt, **kwargs)
        write_time = time.perf_counter() - start

        start = time.perf_counter()
        loaded = load(path, fmt)
        read_time = time.perf_counter() - start

        rows.append({
            "포맷": name,
            "크기(MB)": round(path.stat().st_size / 1024**2, 2),
            "쓰기(초)": round(write_time, 3),
            "읽기(초)": round(read_time, 3),
            "타입보존": loaded.dtypes.equals(df.dtypes),
        })

    return pd.DataFrame(rows).sort_values("크기(MB)")
```

## ⑥ 확인 문제

**1.** 같은 데이터를 CSV로 저장했다 읽으면 dtype이 달라지는데 Parquet은 유지됩니다. 왜 그런가요?

<details>
<summary>답 보기</summary>

**CSV는 텍스트 파일이고 타입 개념이 없습니다.**

```csv
date,station,pm10,code
2026-08-01,강남구,41,001
```

이 파일만 보고는 알 수 없습니다.
- `2026-08-01` 이 날짜인가 문자열인가?
- `41` 이 `int8` 인가 `int64` 인가 `float` 인가?
- `001` 이 문자열인가 숫자 1인가?

Pandas는 **값을 보고 추측**합니다. 그리고 안전한 쪽으로 정합니다.

| 실제 | CSV 저장 | 읽으면 |
|---|---|---|
| `datetime64` | `2026-08-01` | `object` |
| `category` | `강남구` | `object` |
| `uint8` | `41` | `int64` (8배 메모리) |
| `float32` | `0.031` | `float64` |
| `'001'` | `001` | **`1`** ← 손상 |

**마지막이 진짜 문제입니다.** 우편번호·사업자번호·지역코드에서 실제로 벌어집니다.

**Parquet은 스키마를 함께 저장합니다.**

```
파일 구조
├── 메타데이터
│   ├── 스키마: date=timestamp[ns], station=dictionary<string>,
│   │           pm10=uint8, code=string
│   ├── 행 수, 컬럼별 통계(min/max/null 수)
│   └── 각 블록의 위치
└── 데이터 (컬럼별로 압축 저장)
```

**읽을 때 추측할 필요가 없습니다.** 스키마 그대로 복원됩니다.

**추가 이점 — 컬럼별 통계**

메타데이터의 min/max 덕분에 **필터 푸시다운**이 가능합니다.

```python
pd.read_parquet(path, filters=[("pm10", ">", 150)])
```

각 블록의 max가 150 이하면 **그 블록은 읽지도 않습니다.**

**언제 CSV를 쓰나**

| 상황 | 포맷 |
|---|---|
| 사람이 열어서 확인 | CSV |
| Excel로 전달 | CSV (utf-8-sig) |
| 다른 언어·시스템과 교환 | CSV |
| **프로그램이 다시 읽을 중간 결과** | **Parquet** ⭐ |
| 대용량 저장 | Parquet |
| 학습 데이터셋 | Parquet |

**실무 패턴 — 둘 다 저장**

```
data/
├── raw/          원본 그대로 (CSV·JSON)
├── processed/    정제 결과 (Parquet) ← 파이프라인이 쓰는 것
└── reports/      사람이 볼 것 (CSV)
```

**CSV를 꼭 써야 한다면** dtype을 설정 파일에 기록하고 읽을 때마다 지정하세요.

```python
DTYPES = {"code": str, "station": "category", "pm10": "uint8"}
pd.read_csv(path, dtype=DTYPES, parse_dates=["date"])
```

**하지만 지정을 빠뜨리면 조용히 데이터가 손상됩니다.**
Parquet은 그럴 여지가 없습니다.
</details>

**2.** Parquet에서 `columns=` 로 컬럼을 지정하면 CSV의 `usecols=` 보다 훨씬 빠릅니다. 왜인가요?

<details>
<summary>답 보기</summary>

**저장 방식이 근본적으로 다르기 때문입니다.**

**CSV (행 지향)**

```
2026-08-01,강남구,41,25,0.031,0.021,28.4,65,보통,1234,True
2026-08-02,서초구,38,22,0.042,0.019,30.1,72,좋음,5678,True
```

한 행의 모든 값이 **한 줄에 붙어** 있습니다.

`usecols=["station", "pm10"]` 를 줘도:
1. 파일 전체를 **디스크에서 읽어야** 합니다
2. 각 줄을 **전부 파싱**해서 쉼표로 나눠야 합니다
3. 그중 2개만 남기고 **나머지를 버립니다**

**I/O와 파싱 비용은 그대로**이고 메모리만 절약됩니다.

**Parquet (컬럼 지향)**

```
파일 안에서
[블록1: date 컬럼 데이터]        ← 위치 정보가 메타데이터에
[블록2: station 컬럼 데이터]
[블록3: pm10 컬럼 데이터]
[블록4: pm25 컬럼 데이터]
...
```

`columns=["station", "pm10"]` 를 주면:
1. 메타데이터에서 **두 컬럼의 위치**를 확인
2. 그 부분만 **디스크에서 읽음**
3. 나머지 블록은 **열지도 않음**

**I/O 자체가 줄어듭니다.**

**측정 결과**

```
                           시간      메모리
CSV 전체 읽기              2.94초   339.5 MB
CSV usecols (3/12)        1.31초    87.4 MB    ← 시간은 절반만 줄어듦
Parquet 전체 읽기          0.39초    27.0 MB
Parquet columns (3/12)    0.11초     9.1 MB    ← 시간이 1/4
```

**컬럼 수에 비례해 시간이 줄어드는 것**을 확인할 수 있습니다.

```
컬럼  1개 — 0.04초
컬럼  3개 — 0.11초
컬럼  6개 — 0.19초
컬럼 12개 — 0.39초
```

**추가 이점 — 압축률**

같은 컬럼의 값은 **비슷합니다.**

```
station 컬럼: [강남구, 강남구, 서초구, 강남구, 서초구, ...]
             → 사전 인코딩 + RLE 로 극도로 잘 압축됨

pm10 컬럼: [41, 38, 45, 42, 39, ...]
          → 값의 범위가 좁아 비트 패킹 가능
```

CSV는 **다른 타입의 값이 섞여** 있어 압축이 잘 안 됩니다.

```
크기 비교 (100만 행)
  CSV            117.3 MB
  CSV.gz          31.4 MB
  Parquet(zstd)   13.2 MB      ← CSV의 11%
```

**세 번째 이점 — 필터 푸시다운**

컬럼별 통계(min/max)가 메타데이터에 있어, 조건에 맞을 수 없는 블록을 건너뜁니다.

```python
pd.read_parquet(path, filters=[("region", "==", "동남")])
# 3.4배 빠름
```

**정리**

| 최적화 | CSV | Parquet |
|---|---|---|
| 컬럼 선택 | 메모리만 절약 | **I/O 자체 감소** ⭐ |
| 압축 | 전체 압축(해제 필요) | 컬럼별 최적 압축 |
| 필터 | 읽고 나서 필터 | **블록 건너뛰기** ⭐ |
| 파티션 | 폴더를 직접 관리 | **자동 지원** ⭐ |

**"컬럼 100개 중 3개만 쓰는 분석"** 이 흔한데, 이때 차이가 30배 이상 납니다.
</details>

**3.** 파티셔닝을 할 때 파티션 키를 어떻게 골라야 하나요? 잘못 고르면 어떻게 되나요?

<details>
<summary>답 보기</summary>

**좋은 파티션 키의 조건 세 가지**

**① 자주 필터하는 컬럼**

```python
# 실제 조회 패턴이
df[df["year"] == 2026]                    # 자주
df[df["region"] == "동남"]                 # 가끔
df[df["device_id"] == 1234]               # 거의 안 함

# → year 로 파티션
```

**조회하지 않는 컬럼으로 나누면 아무 이득이 없습니다.**

**② 파티션당 충분한 크기 (수십 MB 이상)**

```python
rows_per_partition = len(df) / df.groupby(keys).ngroups
```

| 파티션당 행 수 | 평가 |
|---|---|
| < 1만 | ❌ 너무 잘음 |
| 10만 ~ 1000만 | ✅ 적절 |
| > 1억 | 더 나눌 여지 |

**③ 고유값이 적당함 (수십~수백)**

```
year        : 2~5개      ✅
year/month  : 12~60개    ✅
region      : 5개        ✅
station     : 25개       △ (다른 키와 조합하면 폭증)
device_id   : 9,000개    ❌
user_id     : 100만개    ❌❌
```

**잘못 고르면 벌어지는 일**

**문제 ① 작은 파일 폭증 (small files problem)**

```python
df.to_parquet(path, partition_cols=["station", "date"])
# 25 × 365 = 9,125개 폴더
# 파일 하나가 20 KB
```

| 증상 | 원인 |
|---|---|
| 읽기가 **더 느려짐** | 파일 9,125개를 여는 오버헤드 |
| 저장 공간이 더 큼 | 파일마다 메타데이터 중복 |
| 압축률 하락 | 파일이 작아 압축 이득이 적음 |
| 파일 시스템 부담 | inode 소진 |

**실측**

```
파티션 없음      : 22.4 MB, 파일 1개,   읽기 0.71초
year/month      : 23.1 MB, 파일 12개,  읽기 0.09초    ✅
station         : 28.9 MB, 파일 25개,  읽기 0.31초    △
station/date    : 61.2 MB, 파일 9125개, 읽기 4.82초   ❌
```

**문제 ② 데이터 편향(skew)**

```python
df.to_parquet(path, partition_cols=["grade"])
```

```
grade=보통      : 42% (126만 행, 12 MB)
grade=좋음      : 35% (105만 행, 10 MB)
grade=약간나쁨  : 18% (54만 행, 5 MB)
grade=나쁨      : 5%  (15만 행, 1.4 MB)
```

**크기가 10배 차이납니다.** 병렬 처리 시 한 워커만 오래 걸립니다.

**문제 ③ 조회 패턴과 불일치**

```python
# 파티션은 region 으로 나눴는데
df.to_parquet(path, partition_cols=["region"])

# 실제 조회는 날짜로
pd.read_parquet(path, filters=[("date", ">=", "2026-08-01")])
# → 모든 파티션을 다 읽어야 함. 파티션의 의미가 없음
```

**실무 권장 패턴**

```python
# 시계열 데이터 — 가장 흔함
partition_cols=["year", "month"]

# 데이터가 매우 많으면
partition_cols=["year", "month", "day"]

# 지역별 조회가 많으면
partition_cols=["year", "month", "region"]     # 순서 중요! 큰 단위부터

# ❌ 피할 것
partition_cols=["user_id"]           # 고유값 폭증
partition_cols=["timestamp"]         # 초 단위면 행마다 폴더
partition_cols=["is_valid"]          # 고유값 2개, 의미 없음
```

**순서가 중요합니다.**

```
year=2026/month=8/region=동남/     ✅ 큰 단위 → 작은 단위
region=동남/month=8/year=2026/     ❌ 날짜만으로 필터할 때 비효율
```

**계층 구조에서는 왼쪽부터 필터해야 폴더를 건너뛸 수 있습니다.**

**결정 절차**

```
1. 실제 조회 패턴을 확인한다 (로그·요구사항)
2. 가장 자주 쓰는 필터 컬럼 1~2개를 고른다
3. 파티션당 행 수를 계산한다
     len(df) / df.groupby(keys).ngroups
4. 10만~1000만 행이면 적절, 아니면 조정
5. 실제로 저장해 보고 파일 수와 크기를 확인한다
6. 조회 속도를 측정해 비교한다
```

**검증 코드**

```python
def check_partition(df, keys):
    groups = df.groupby(keys).size()
    print(f"파티션 수      : {len(groups)}")
    print(f"파티션당 평균  : {groups.mean():,.0f}행")
    print(f"최소/최대      : {groups.min():,} / {groups.max():,}")
    print(f"편차 비율      : {groups.max() / groups.min():.1f}배")

    if len(groups) > 1000:
        print("⚠ 파티션이 너무 많습니다")
    if groups.mean() < 10_000:
        print("⚠ 파티션당 행 수가 적습니다")
    if groups.max() / groups.min() > 10:
        print("⚠ 파티션 크기 편차가 큽니다")
```

이 원리가 W07 [Day 038](../02-sql-pipeline/day-038.md)의 **인덱스 설계**와
W27 [Day 131](../05-infra-mlops/day-131.md)의 **DVC 데이터 버전 관리**에도 이어집니다.
</details>

## 오늘의 정리

| 항목 | 내용 |
|---|---|
| 행 vs 컬럼 지향 | CSV=행 · **Parquet=컬럼** (분석에 유리) |
| Parquet 이점 | **타입 보존** · 압축 · 컬럼 선택 읽기 · 필터 푸시다운 |
| 설치 | `pip install pyarrow` |
| 저장 | `df.to_parquet(path, index=False, compression="zstd")` |
| 읽기 | `pd.read_parquet(path, columns=[...], filters=[(...)])` |
| 압축 | `snappy`(기본) · **`zstd`**(권장) · `gzip`(가장 작음) |
| 파티션 | `partition_cols=["year", "month"]` |
| 파티션 키 | 자주 필터 · 파티션당 수십 MB · 고유값 수십~수백 |
| 크기 비교 | CSV 100% · Parquet **11~16%** · JSON 250% |
| 속도 비교 | Parquet이 CSV보다 **7배 이상** 빠름 |
| Polars | Rust 기반 · 멀티코어 · lazy — **병목일 때 고려** |
| 포맷 선택 | 사람→CSV · 중첩→JSON · **그 외 전부 Parquet** |
| 금기 | Pickle 신뢰 없이 열기 · 작은 데이터에 Parquet · 파티션 과다 |
