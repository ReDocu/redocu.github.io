## ① 학습 목표

이 레슨을 마치면 이렇게 할 수 있습니다.

- `try` / `except` / `else` / `finally` 로 에러가 나도 죽지 않는 프로그램을 만들 수 있다.
- `raise` 로 의도적인 에러를 발생시켜 잘못된 데이터를 걸러낼 수 있다.
- `with open()` 으로 파일을 안전하게 읽고 쓸 수 있고, 인코딩 문제를 해결할 수 있다.
- `csv` · `json` 모듈로 표 데이터와 구조 데이터를 저장하고 복원할 수 있다.

## ② 왜 필요한가

지금까지 만든 프로그램에는 치명적인 문제가 둘 있습니다.

**1) 껐다 켜면 데이터가 사라집니다.**
가계부에 100건을 입력하고 프로그램을 종료하면 전부 없어집니다. 쓸 수 없는 프로그램입니다.

**2) 예상 못 한 값 하나에 전체가 멈춥니다.**

```
1만 건 수집 중... 9,847번째 응답에 필드가 하나 빠짐
→ KeyError
→ 프로그램 종료
→ 앞의 9,846건도 저장 안 됨
```

**이건 실제로 벌어지는 일입니다.** 그리고 MLOps에서 가장 중요한 방어입니다.

| 예외 처리가 없으면 | 시점 |
|---|---|
| 응답 하나가 이상해서 수집 전체가 중단 | W04 |
| 결측값 한 개 때문에 전처리가 멈춤 | W05 |
| 1000만 행 중 3행이 불량이라 적재가 롤백 | W09 |
| 잘못된 입력에 API가 500 에러를 뱉음 | W20 |
| 컨테이너가 죽고 서비스가 내려감 | W25 |

**"실패해도 계속 돌고, 무엇이 실패했는지 기록을 남긴다."** 이것이 운영 가능한 코드의 조건입니다.

## ③ 개념 설명

### 예외(exception)란

프로그램 실행 중에 발생하는 **정상적이지 않은 상황**입니다.
파이썬은 이걸 만나면 즉시 실행을 멈추고 Traceback을 출력합니다 ([Day 005](day-005.md)).

**예외 처리는 그 멈춤을 가로채는 것**입니다.

### try / except 기본

```python
try:
    위험한 코드
except 예외종류:
    문제가 생겼을 때 할 일
```

```python
try:
    age = int(input("나이: "))
    print(f"내년엔 {age + 1}살")
except ValueError:
    print("숫자를 입력하세요.")
```

```
나이: 스물다섯
숫자를 입력하세요.
```

**프로그램이 죽지 않고 계속됩니다.**

### 여러 예외 처리

```python
try:
    ...
except ValueError:
    print("값이 잘못됨")
except ZeroDivisionError:
    print("0으로 나눔")
except (KeyError, IndexError):        # 여러 개를 한 번에
    print("데이터를 못 찾음")
except Exception as e:                # 나머지 전부
    print(f"예상 못 한 오류: {type(e).__name__}: {e}")
```

**위에서부터 순서대로 검사**하고 처음 맞는 것 하나만 실행합니다. `if`/`elif` 와 같습니다.
그래서 **구체적인 예외를 위에, 포괄적인 것을 아래에** 씁니다.

### `as e` — 예외 객체 받기

```python
try:
    int("abc")
except ValueError as e:
    print(f"에러 내용: {e}")
    print(f"에러 종류: {type(e).__name__}")
```

```
에러 내용: invalid literal for int() with base 10: 'abc'
에러 종류: ValueError
```

**로그에 남길 때 반드시 필요합니다.** "실패했다"보다 "무엇이 왜 실패했다"가 중요합니다.

### else 와 finally

```python
try:
    f = open("data.txt")
except FileNotFoundError:
    print("파일이 없습니다")
else:
    print("성공했을 때만 실행")        # 예외가 안 났을 때
finally:
    print("성공하든 실패하든 항상 실행")   # 정리 작업
```

| 블록 | 언제 실행되나 | 주 용도 |
|---|---|---|
| `try` | 항상 (시도) | 위험한 코드 |
| `except` | 예외가 났을 때 | 복구·기록 |
| `else` | 예외가 **안** 났을 때 | 성공 후속 처리 |
| `finally` | **항상** | 파일 닫기·연결 해제 |

> `finally` 는 `return` 이 있어도 실행됩니다. **자원 정리의 보증**입니다.
> 다만 파일은 `with` 를 쓰면 `finally` 가 필요 없습니다 (뒤에 설명).

### raise — 직접 예외 일으키기

```python
def set_age(age):
    if age < 0:
        raise ValueError(f"나이는 0 이상이어야 합니다: {age}")
    if age > 150:
        raise ValueError(f"나이가 비현실적입니다: {age}")
    return age
```

**왜 `return False` 가 아니라 `raise` 인가?**

| 방식 | 문제 |
|---|---|
| `return None` | 호출한 쪽이 확인을 안 하면 조용히 지나감 |
| `return False` | "실패"만 알 뿐 **이유**를 못 전달 |
| `raise` | 무시할 수 없음 + 이유가 메시지에 담김 |

**데이터 검증에서는 `raise` 를 씁니다.** 잘못된 데이터가 조용히 흘러가는 것이 가장 위험하기 때문입니다.

### 사용자 정의 예외

```python
class ValidationError(Exception):
    """데이터 검증 실패."""
    pass


class CollectorError(Exception):
    """수집 실패."""
    pass
```

이렇게 만들어 두면 **내 코드의 에러**와 **라이브러리 에러**를 구분해서 잡을 수 있습니다.

```python
try:
    process(row)
except ValidationError as e:
    log_bad_row(row, str(e))      # 불량 행만 격리하고 계속
except Exception as e:
    raise                          # 예상 못 한 것은 다시 던짐
```

> W09 [Day 044](../02-sql-pipeline/day-044.md)의 데이터 품질 검증에서 그대로 씁니다.

### 나쁜 예외 처리

```python
# ❌ 절대 하지 마세요
try:
    do_something()
except:
    pass
```

**무엇이 왜 실패했는지 영원히 알 수 없습니다.** 심지어 `Ctrl+C` 도 잡아먹습니다.
운영 중인 서비스에서 이런 코드는 **몇 주 동안 데이터를 조용히 망가뜨립니다.**

```python
# ✅ 최소한 이렇게
try:
    do_something()
except Exception as e:
    logger.warning(f"실패: {type(e).__name__}: {e}")
```

**원칙 세 가지**

1. `except:` 만 쓰지 않는다 — 최소 `except Exception as e:`
2. 잡았으면 **반드시 기록**한다 (지금은 `print`, [Day 014](day-014.md)부터 `logging`)
3. 처리할 수 없는 예외는 **다시 던진다** (`raise`)

### 파일 열기 — `with open()`

```python
with open("data.txt", "r", encoding="utf-8") as f:
    content = f.read()
```

`with` 블록을 벗어나면 **파일이 자동으로 닫힙니다.** 예외가 나도 닫힙니다.

```python
# ❌ 옛날 방식 — 예외가 나면 파일이 안 닫힘
f = open("data.txt")
content = f.read()
f.close()
```

**항상 `with` 를 쓰세요.**

### 파일 모드

| 모드 | 뜻 | 파일이 없으면 | 기존 내용 |
|---|---|---|---|
| `"r"` | 읽기 (기본) | `FileNotFoundError` | — |
| `"w"` | 쓰기 | 새로 만듦 | **전부 지움** ⚠ |
| `"a"` | 이어쓰기 | 새로 만듦 | 유지 |
| `"x"` | 새로 쓰기 | 새로 만듦 | 있으면 에러 |
| `"rb"` / `"wb"` | 바이너리 | | 이미지·모델 파일 |

> **`"w"` 는 파일을 통째로 비웁니다.** 실수로 로그 파일을 `"w"` 로 열면 그동안의 기록이 사라집니다.
> 로그는 항상 `"a"` 입니다.

### 인코딩 — `encoding="utf-8"`

**한글이 들어가면 반드시 지정하세요.**

```python
with open("data.csv", "r", encoding="utf-8") as f:
```

지정하지 않으면 운영체제 기본값을 씁니다. Windows는 `cp949`, Linux는 `utf-8` 입니다.
같은 코드가 **내 PC에서는 되고 W23의 Linux 서버에서는 깨집니다.**

| 인코딩 | 언제 |
|---|---|
| `utf-8` | 기본. 항상 이것을 쓰세요 |
| `cp949` / `euc-kr` | 국내 공공기관 CSV에서 가끔 필요 |
| `utf-8-sig` | Excel로 저장한 CSV (BOM 제거) |

### 읽기 방법

```python
with open("data.txt", encoding="utf-8") as f:
    content = f.read()            # 전체를 문자열 하나로 — 큰 파일엔 위험
    lines = f.readlines()         # 줄 리스트로 — 큰 파일엔 위험
    for line in f:                # 한 줄씩 — ✅ 메모리 안전
        print(line.rstrip())
```

> **`for line in f:` 가 기본입니다.** 1GB 파일도 메모리 걱정 없이 처리됩니다.
> W06 [Day 026](day-026.md)의 대용량 처리가 이 원리의 확장입니다.
>
> `line` 끝에는 줄바꿈 `\n` 이 붙어 있습니다. `.rstrip()` 으로 제거하세요.

### CSV 모듈

CSV는 쉼표로 구분된 표 데이터입니다. **직접 `split(",")` 하면 안 됩니다.**

```
이름,메모,금액
홍길동,"점심, 커피",12000        ← 값 안에 쉼표가 있음
```

`csv` 모듈이 따옴표 규칙을 처리해 줍니다.

```python
import csv

# 쓰기
with open("data.csv", "w", encoding="utf-8", newline="") as f:
    writer = csv.writer(f)
    writer.writerow(["이름", "나이"])
    writer.writerows([["홍길동", 25], ["김철수", 31]])

# 읽기
with open("data.csv", "r", encoding="utf-8") as f:
    reader = csv.reader(f)
    header = next(reader)          # 첫 줄은 헤더
    for row in reader:
        print(row)                 # ['홍길동', '25']  ← 전부 문자열!
```

**딕셔너리로 다루면 훨씬 편합니다.**

```python
with open("data.csv", "r", encoding="utf-8") as f:
    for row in csv.DictReader(f):
        print(row["이름"], row["나이"])
```

> **`newline=""` 를 꼭 넣으세요.** 없으면 Windows에서 빈 줄이 하나씩 끼어듭니다.
> **CSV에서 읽은 값은 전부 문자열입니다.** 숫자로 쓰려면 형변환해야 합니다 ([Day 002](day-002.md)).

### JSON 모듈

중첩 구조를 그대로 저장할 수 있습니다.

```python
import json

data = {"name": "홍길동", "scores": [88, 92], "active": True}

# 쓰기
with open("data.json", "w", encoding="utf-8") as f:
    json.dump(data, f, ensure_ascii=False, indent=2)

# 읽기
with open("data.json", "r", encoding="utf-8") as f:
    loaded = json.load(f)
```

| 옵션 | 뜻 |
|---|---|
| `ensure_ascii=False` | **한글을 그대로 저장** (없으면 `안녕` 로 저장됨) |
| `indent=2` | 보기 좋게 들여쓰기 |
| `default=str` | 날짜 등 변환 못 하는 타입을 문자열로 |

**문자열로 주고받을 때**는 `dumps` / `loads` 입니다 (`s` = string).

```python
text = json.dumps(data, ensure_ascii=False)     # 딕셔너리 → 문자열
data = json.loads(text)                          # 문자열 → 딕셔너리
```

W04에서 API 응답을 파싱할 때 `response.json()` 이 내부적으로 `loads` 를 부릅니다.

### CSV vs JSON

| | CSV | JSON |
|---|---|---|
| 구조 | 평평한 표 | 중첩 가능 |
| 타입 | 전부 문자열 | 타입 보존 |
| 크기 | 작음 | 큼 (키가 반복됨) |
| Excel | 바로 열림 | 안 열림 |
| 용도 | 표 데이터·대용량 | 설정·API 응답·중첩 데이터 |

### Step 1. 예외 처리 기본

`exception_basics.py` 를 만듭니다.

```python
def safe_divide(a, b):
    """나눗셈. 실패하면 None과 이유를 돌려줍니다."""
    try:
        result = a / b
    except ZeroDivisionError:
        return None, "0으로 나눌 수 없습니다"
    except TypeError as e:
        return None, f"타입 오류: {e}"
    else:
        return result, None


tests = [(10, 2), (10, 0), (10, "2"), (7, 3)]

for a, b in tests:
    value, error = safe_divide(a, b)
    if error:
        print(f"{a} / {b!r:<4} → 실패: {error}")
    else:
        print(f"{a} / {b!r:<4} → {value:.4f}")
```

실행 결과:

```
10 / 2    → 2.5000
10 / 0    → 실패: 0으로 나눌 수 없습니다
10 / '2'  → 실패: 타입 오류: unsupported operand type(s) for /: 'int' and 'str'
7 / 3     → 2.3333
```

> `return 값, 에러` 형태로 둘 다 돌려주는 패턴입니다. Go 언어에서 흔히 쓰는 방식이고,
> 파이썬에서도 "실패가 정상 흐름의 일부"일 때 유용합니다.

### Step 2. 안전한 입력 함수

`safe_input.py` 를 만듭니다. [Day 004](day-004.md)의 `.isdigit()` 방식보다 강력합니다.

```python
def input_int(prompt, min_value=None, max_value=None):
    """정수를 안전하게 입력받습니다."""
    while True:
        raw = input(prompt).strip().replace(",", "")
        try:
            value = int(raw)
        except ValueError:
            print(f"  → '{raw}' 는 정수가 아닙니다.")
            continue

        if min_value is not None and value < min_value:
            print(f"  → {min_value} 이상이어야 합니다.")
            continue
        if max_value is not None and value > max_value:
            print(f"  → {max_value} 이하여야 합니다.")
            continue

        return value


def input_float(prompt):
    """실수를 안전하게 입력받습니다."""
    while True:
        try:
            return float(input(prompt).strip().replace(",", ""))
        except ValueError as e:
            print(f"  → 실수를 입력하세요. ({e})")


age = input_int("나이(0-120): ", min_value=0, max_value=120)
height = input_float("키(cm): ")
print(f"\n입력 완료: {age}세, {height}cm")
```

실행 결과:

```
나이(0-120): 스물다섯
  → '스물다섯' 는 정수가 아닙니다.
나이(0-120): -5
  → 0 이상이어야 합니다.
나이(0-120): 25
키(cm): 175.5

입력 완료: 25세, 175.5cm
```

> `.isdigit()` 은 `-5` 나 `1,000` 을 처리 못 합니다. `try/except` 가 더 정확합니다.
> **"허락보다 용서가 쉽다(EAFP)"** — 미리 확인하기보다 일단 해보고 실패를 잡는 것이 파이썬 스타일입니다.

### Step 3. 파일 읽고 쓰기

`file_basics.py` 를 만듭니다.

```python
# 1) 쓰기 — 기존 내용을 지웁니다
with open("notes.txt", "w", encoding="utf-8") as f:
    f.write("첫 번째 줄\n")
    f.write("두 번째 줄\n")

# 2) 이어쓰기
with open("notes.txt", "a", encoding="utf-8") as f:

# 3) 전체 읽기
with open("notes.txt", "r", encoding="utf-8") as f:
    print("--- read() ---")
    print(f.read())

# 4) 한 줄씩 읽기 — 큰 파일에도 안전
print("--- 한 줄씩 ---")
with open("notes.txt", "r", encoding="utf-8") as f:
    for i, line in enumerate(f, start=1):
        print(f"{i}: {line.rstrip()}")

# 5) 없는 파일 읽기
print("\n--- 없는 파일 ---")
try:
    with open("nothing.txt", "r", encoding="utf-8") as f:
        f.read()
except FileNotFoundError as e:
    print(f"FileNotFoundError: {e}")
```

실행 결과:

```
--- read() ---
첫 번째 줄
두 번째 줄
세 번째 줄 (이어쓰기)

--- 한 줄씩 ---
1: 첫 번째 줄
2: 두 번째 줄
3: 세 번째 줄 (이어쓰기)

--- 없는 파일 ---
FileNotFoundError: [Errno 2] No such file or directory: 'nothing.txt'
```

```python
import csv
```

```python
import json
import os

DATA_FILE = "budget_data.json"


def save_records(records, path=DATA_FILE):
    """내역을 JSON 파일로 저장합니다."""
    try:
        with open(path, "w", encoding="utf-8") as f:
            json.dump(records, f, ensure_ascii=False, indent=2)
        return True, None
    except OSError as e:
        return False, f"저장 실패: {e}"


def load_records(path=DATA_FILE):
    """저장된 내역을 불러옵니다. 없으면 빈 목록."""
    if not os.path.exists(path):
        return [], None

    try:
        with open(path, "r", encoding="utf-8") as f:
            data = json.load(f)
    except json.JSONDecodeError as e:
        return [], f"파일이 손상되었습니다 ({e}). 새로 시작합니다."
    except OSError as e:
        return [], f"읽기 실패: {e}"

    if not isinstance(data, list):
        return [], "파일 형식이 올바르지 않습니다. 새로 시작합니다."

    # 각 레코드의 필수 키 확인 — 불량 행은 버리고 계속
    valid = []
    dropped = 0
    for rec in data:
        if isinstance(rec, dict) and {"kind", "category", "memo", "amount"} <= rec.keys():
            valid.append(rec)
        else:
            dropped += 1

    warning = f"불량 레코드 {dropped}건을 건너뛰었습니다." if dropped else None
    return valid, warning


def main():
    records, warning = load_records()
    if warning:
        print(f"⚠ {warning}")
    print(f"저장된 내역 {len(records)}건을 불러왔습니다.")

    while True:
        # ... 메뉴 처리 (Day 008과 동일) ...
        choice = input("선택 > ").strip()

        if choice == "0":
            ok, error = save_records(records)
            if ok:
                print(f"{len(records)}건을 {DATA_FILE} 에 저장했습니다.")
            else:
                print(f"⚠ {error}")
            break

        elif choice == "1":
            memo = input("  내용: ").strip()
            amount = input_int("  금액(원): ", min_value=1)
            records.append({"kind": "수입", "category": "수입", "memo": memo, "amount": amount})
            save_records(records)          # 매번 저장 — 갑자기 종료돼도 안전
            print("  ✓ 등록·저장됨")

        # ... 나머지 메뉴 ...


main()
```

### Step 7. 로그 파일 분석기

`log_analyzer.py` 를 만듭니다. 오늘 배운 것을 종합합니다.

```python
import json
from collections import Counter      # 딕셔너리 집계를 대신해 주는 표준 도구


def parse_line(line):
    """로그 한 줄을 딕셔너리로 파싱합니다. 실패하면 ValueError."""
    line = line.strip()
    if not line:
        raise ValueError("빈 줄")

    if "[" not in line or "]" not in line:
        raise ValueError("레벨 표기 없음")

    try:
        date = line[0:10]
        time = line[11:19]
        level = line[line.index("[") + 1:line.index("]")]
        rest = line[line.index("]") + 2:]
        module, message = rest.split(" - ", 1)
    except (ValueError, IndexError) as e:
        raise ValueError(f"형식 불일치: {e}")

    return {"date": date, "time": time, "level": level,
            "module": module.strip(), "message": message.strip()}


# 샘플 로그 파일 만들기 (일부러 불량 줄을 섞음)
sample = """2026-08-12 14:23:05 [ERROR] api.collector - 요청 실패 status=503
2026-08-12 14:23:06 [INFO] api.collector - 재시도 1/3
이건 형식이 완전히 다른 줄입니다

2026-08-12 14:23:08 [INFO] api.collector - 성공
2026-08-12 14:25:11 [WARN] db.loader - 느린 쿼리 3.2s
2026-08-12 14:31:02 [ERROR] db.loader - 연결 끊김
2026-08-12 14:31:05 [INFO] db.loader - 재연결 성공
"""

with open("app.log", "w", encoding="utf-8") as f:
    f.write(sample)


# --- 분석 ---
parsed = []
bad_lines = []

with open("app.log", "r", encoding="utf-8") as f:
    for lineno, line in enumerate(f, start=1):
        try:
            parsed.append(parse_line(line))
        except ValueError as e:
            bad_lines.append({"line": lineno, "reason": str(e), "raw": line.rstrip()})
            continue                    # ★ 죽지 않고 다음 줄로

print(f"파싱 성공 {len(parsed)}줄 / 실패 {len(bad_lines)}줄\n")

# 레벨별 집계
levels = Counter(p["level"] for p in parsed)
print("[레벨별]")
for level, count in levels.most_common():
    print(f"  {level:<6}{count:>3}줄  {'■' * count}")

# 모듈별 에러
print("\n[모듈별 ERROR]")
errors = Counter(p["module"] for p in parsed if p["level"] == "ERROR")
for module, count in errors.most_common():
    print(f"  {module:<16}{count}건")

# 불량 줄 리포트
if bad_lines:
    print("\n[파싱 실패한 줄]")
    for b in bad_lines:
        print(f"  {b['line']:>3}행: {b['reason']:<20} {b['raw']!r}")

# 결과를 JSON으로 저장
report = {
    "total_lines": len(parsed) + len(bad_lines),
    "parsed": len(parsed),
    "failed": len(bad_lines),
    "by_level": dict(levels),
    "errors_by_module": dict(errors),
}
with open("log_report.json", "w", encoding="utf-8") as f:
    json.dump(report, f, ensure_ascii=False, indent=2)

print(f"\n리포트를 log_report.json 에 저장했습니다.")
```

실행 결과:

```
파싱 성공 6줄 / 실패 2줄

[레벨별]
  INFO     3줄  ■■■
  ERROR    2줄  ■■
  WARN     1줄  ■

[모듈별 ERROR]
  api.collector   1건
  db.loader       1건

[파싱 실패한 줄]
    3행: 레벨 표기 없음           '이건 형식이 완전히 다른 줄입니다'
    4행: 빈 줄                   ''

리포트를 log_report.json 에 저장했습니다.
```

> **이것이 오늘 배운 것의 완성형입니다.**
> 불량 데이터 2줄이 있어도 6줄은 정상 처리되고, **무엇이 왜 실패했는지 기록**이 남습니다.
> W09 [Day 044](../02-sql-pipeline/day-044.md)의 "불량 행 격리 테이블"이 정확히 이 구조입니다.
>
> `Counter` 는 `collections` 표준 모듈의 도구로, `d[k] = d.get(k, 0) + 1` 을 대신해 줍니다.
> `.most_common()` 은 빈도순으로 정렬해 돌려줍니다.

## ⑥ 확인 문제

**1.** 아래 코드의 출력 순서를 예측하세요.

```python
def test(x):
    try:
        result = 10 / x
        print("A")
        return result
    except ZeroDivisionError:
        print("B")
        return None
    else:
        print("C")
    finally:
        print("D")

print("결과:", test(2))
print("---")
print("결과:", test(0))
```

<details>
<summary>답 보기</summary>

```
A
D
결과: 5.0
---
B
D
결과: None
```

**설명**

- `test(2)` — 예외가 안 나므로 `try` 안의 `print("A")` 실행 → `return` 을 만남.
  하지만 **`finally` 는 `return` 이 있어도 반드시 실행**되므로 `D` 가 출력된 뒤 값이 돌아갑니다.
- `test(0)` — `ZeroDivisionError` 발생 → `except` 의 `B` 실행 → `finally` 의 `D` → `None` 반환.
- **`C` 는 절대 출력되지 않습니다.** `else` 는 `try` 가 예외 없이 끝났을 때 실행되는데,
  여기서는 `try` 안에서 `return` 을 해 버려 도달하지 못합니다.

**핵심** — `finally` 는 정리 작업의 보증입니다. 파일 닫기·DB 연결 해제·락 해제에 씁니다.
(파일은 `with` 를 쓰면 `finally` 가 필요 없습니다.)
</details>

**2.** 아래 수집 코드는 응답 1만 건 중 한 건만 이상해도 전부 중단됩니다. 나머지는 살리면서 실패를 기록하도록 고치세요.

```python
results = []
for item in items:
    record = {
        "id": item["id"],
        "name": item["stationName"],
        "count": int(item["boarding"]),
    }
    results.append(record)
```

<details>
<summary>답 보기</summary>

```python
results = []
failed = []

for i, item in enumerate(items):
    try:
        record = {
            "id": item["id"],
            "name": item["stationName"],
            "count": int(item["boarding"]),
        }
    except KeyError as e:
        failed.append({"index": i, "reason": f"필수 필드 없음: {e}", "raw": item})
        continue
    except (ValueError, TypeError) as e:
        failed.append({"index": i, "reason": f"값 변환 실패: {e}", "raw": item})
        continue

    results.append(record)

print(f"성공 {len(results)}건 / 실패 {len(failed)}건")

if failed:
    with open("failed_items.json", "w", encoding="utf-8") as f:
        json.dump(failed, f, ensure_ascii=False, indent=2)
    print(f"실패 {len(failed)}건을 failed_items.json 에 격리했습니다.")
```

**핵심 세 가지**

1. **`continue`** — 실패한 건만 건너뛰고 나머지는 계속 처리합니다.
2. **실패를 버리지 않고 기록** — 무엇이 왜 실패했는지, 원본 데이터까지 남깁니다.
   나중에 원인을 고쳐 그 건만 다시 처리할 수 있습니다.
3. **구체적인 예외를 각각 잡음** — `KeyError`(필드 없음)와 `ValueError`(변환 실패)는
   원인이 다르므로 리포트에서 구분됩니다.

`except Exception: pass` 였다면 1만 건 중 3천 건이 조용히 사라져도 아무도 모릅니다.

이 구조가 W09 [Day 044](../02-sql-pipeline/day-044.md)의 **불량 행 격리 테이블(quarantine table)** 입니다.
</details>

## 오늘의 정리

| 항목 | 문법 |
|---|---|
| 기본 | `try:` / `except 예외종류 as e:` / `else:` / `finally:` |
| 여러 예외 | `except (KeyError, IndexError):` · 구체적인 것부터 위에 |
| 직접 발생 | `raise ValueError("메시지")` |
| 사용자 정의 | `class MyError(Exception): pass` |
| 금기 | `except: pass` — 최소 `except Exception as e:` + 기록 |
| 파일 열기 | `with open(path, mode, encoding="utf-8") as f:` |
| 모드 | `r` 읽기 · `w` **덮어씀** · `a` 이어쓰기 |
| 큰 파일 | `for line in f:` — 메모리 안전 |
| CSV | `csv.DictReader` / `csv.DictWriter` · `newline=""` · **값은 전부 문자열** |
| JSON | `json.dump/load` · `ensure_ascii=False` · `indent=2` · **타입 보존** |
| 인코딩 | 항상 `utf-8` · Excel CSV는 `utf-8-sig` · 국내 공공 CSV는 `cp949` 가능 |
