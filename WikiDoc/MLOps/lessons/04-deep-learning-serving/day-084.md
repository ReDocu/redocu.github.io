## ② 왜 필요한가

지금까지의 학습은 길어야 몇 분이었습니다. 실전 DL 학습은 **몇 시간~며칠**입니다.
그 시간 규모에서는 새로운 종류의 사고가 일상이 됩니다:

```

```

체크포인트 없는 장시간 학습은 저장 없이 밤새 게임하는 것과 같습니다. 그리고 학습이
길어질수록 실험 관리도 절실해집니다 — 에폭 40개짜리 곡선을 print 로그로 스크롤하며 비교할
수는 없으니, [Day 067](../03-machine-learning/day-067.md)의 MLflow가 DL에서는 **곡선 기록계**로
승격됩니다.

마지막으로 정직해질 문제가 하나 있습니다. [Day 066](../03-machine-learning/day-066.md)에서
우리는 "같은 실험은 같은 결과"를 신조로 삼았는데, GPU 딥러닝에서는 그 신조가 **조건부**가
됩니다. 오늘 어디까지 재현되고 어디부터 흔들리는지 선을 긋습니다 — 이 단원 README의
"숫자 재현성 주의"가 바로 이 이야기였습니다.

## ③ 개념 설명

### 체크포인트 — 무엇을 담나

`model.state_dict()` 만으로는 **재개가 안 됩니다.** Adam은 파라미터마다 이동 평균(모멘텀 등)
상태를 들고 있는데, 이걸 잃으면 재개 직후 학습이 출렁입니다.

```python
torch.save({
    "epoch": epoch,                      # 어디까지 했나
    "model": model.state_dict(),         # 모델 파라미터
    "optimizer": opt.state_dict(),       # ★ optimizer 내부 상태 (모멘텀·적응 학습률)
    "valid_acc": va,                     # 이 시점의 성적 (best 판단용)
}, "checkpoints/last.pt")
```

관례상 두 슬롯을 유지합니다: `last.pt`(재개용 — 매 에폭 덮어씀)와 `best.pt`(배포용 —
최고 valid 갱신 때만, [Day 079](day-079.md) 과제의 그것).

### MLflow의 step — 점수가 아니라 곡선

```python
mlflow.log_metric("valid_acc", va, step=epoch)
```

대단원 03에서는 실험 하나 = 숫자 하나였지만, DL에서는 실험 하나 = **곡선 하나**입니다.
`step=` 을 주면 MLflow UI가 에폭별 추이를 그래프로 그려 주고, 여러 run의 곡선을 겹쳐
비교할 수 있습니다 — 과적합 진단([Day 081](day-081.md))이 클릭 두 번이 됩니다.

### DL 재현성의 현실

| 층위 | 재현되나 | 조건 |
|---|---|---|
| CPU + 시드 고정 | **완전 재현** (오늘 확인) | 모델·데이터·셔플의 시드 모두 고정 |
| GPU + 시드 고정 | **근사 재현** | 병렬 덧셈 순서가 실행마다 달라 소수점 아래가 흔들림 |
| GPU + 결정적 모드 | 완전 재현에 근접 | `torch.use_deterministic_algorithms(True)` — 대신 느려지고 일부 연산은 미지원 |

부동소수점 덧셈은 순서에 따라 결과가 미세하게 다른데(a+b+c ≠ c+a+b의 세계), GPU는 수천
코어가 임의 순서로 더합니다. 그래서 GPU 실험 보고의 관례는 "시드 고정 + **여러 시드의
평균±표준편차**"입니다 — 재현성의 단위를 "숫자"에서 "분포"로 넓히는 것입니다.

### GPU 없이 배우는 선택지 (이 과정의 설계이기도 합니다)

| 선택지 | 예 |
|---|---|
| 무료 GPU | Colab (세션 만료가 있으니 **체크포인트 필수** — 오늘 기술이 생존 기술) |
| 작게 줄여 CPU로 | 이번 주 내내 한 것 (서브셋·작은 모델·낮은 해상도) |
| 전이학습·특징 추출 | [Day 083](day-083.md) — 큰 학습은 남이 GPU로 해 둠 |
| 추론만 CPU로 | 사전학습 모델 활용([Day 088](day-088.md)~)과 서빙(W19~)은 CPU로 충분 |

## ④ 단계별 실습

`day084_ops.py` 에 이어 붙입니다. (모델·데이터 준비는 [Day 082](day-082.md)의 CNN과
CIFAR 2,000장 — 코드는 저장소의 스크립트 참고)

### Step 1. 체크포인트 저장 — 그리고 정전 (1~2교시)

```python
print("== A. 체크포인트: 학습의 저장 슬롯 ==")
torch.manual_seed(42)
model = make_model()
opt = torch.optim.Adam(model.parameters(), lr=0.001)
os.makedirs("checkpoints", exist_ok=True)
for epoch in range(1, 4):                      # 3에폭까지 학습하고 '사고로 중단'됐다고 가정
    train_one_epoch(model, opt)
    va = accuracy(model)
    torch.save({"epoch": epoch,
                "model": model.state_dict(),
                "optimizer": opt.state_dict(),
                "valid_acc": va},
               "checkpoints/last.pt")
    print(f"  epoch {epoch}: valid {va:.3f} → checkpoints/last.pt 저장")
print("  (여기서 정전! 프로세스 사망)")
```

실행 결과:

```
== A. 체크포인트: 학습의 저장 슬롯 ==
  epoch 1: valid 0.271 → checkpoints/last.pt 저장
  epoch 2: valid 0.338 → checkpoints/last.pt 저장
  epoch 3: valid 0.376 → checkpoints/last.pt 저장
  (여기서 정전! 프로세스 사망)
```

### Step 2. 재개 — 새 프로세스에서 이어 하기 (3교시)

```python
print("\n== B. 재개(resume): 저장 슬롯에서 이어 하기 ==")
model2 = make_model()                          # 새 프로세스라고 가정 — 전부 새로 만든 뒤
opt2 = torch.optim.Adam(model2.parameters(), lr=0.001)
ckpt = torch.load("checkpoints/last.pt")
model2.load_state_dict(ckpt["model"])
opt2.load_state_dict(ckpt["optimizer"])        # optimizer 상태(모멘텀 등)까지 복원!
start = ckpt["epoch"] + 1
print(f"  epoch {ckpt['epoch']}(valid {ckpt['valid_acc']:.3f})에서 복원 → {start}부터 재개")
for epoch in range(start, 6):
    train_one_epoch(model2, opt2)
    print(f"  epoch {epoch}: valid {accuracy(model2):.3f}")
```

실행 결과:

```
== B. 재개(resume): 저장 슬롯에서 이어 하기 ==
  epoch 3(valid 0.376)에서 복원 → 4부터 재개
  epoch 4: valid 0.414
  epoch 5: valid 0.425
```

**0.376 → 0.414 → 0.425** — 곡선이 끊긴 자리에서 자연스럽게 이어집니다. optimizer 상태까지
복원했기 때문입니다 (모델만 복원했다면 재개 직후 모멘텀이 초기화되어 한동안 출렁였을 겁니다).
"학습 = 언제든 죽고 되살아날 수 있는 장기 프로세스"라는 이 감각은 W27의 자동 재학습
파이프라인에서 그대로 요구됩니다.

### Step 3. MLflow에 곡선 기록 (4~5교시)

```python
print("\n== C. MLflow로 DL 학습 곡선 기록 ==")
mlflow.set_experiment("cifar-cnn")
torch.manual_seed(42)
model = make_model()
opt = torch.optim.Adam(model.parameters(), lr=0.001)
with mlflow.start_run(run_name="smallcnn-2k"):
    mlflow.log_params({"arch": "conv32-conv64-fc128", "lr": 0.001, "batch": 128,
                       "train_size": 2000, "seed": 42, "device": "cpu"})
    for epoch in range(1, 6):
        train_one_epoch(model, opt)
        va = accuracy(model)
        mlflow.log_metric("valid_acc", va, step=epoch)     # step= 이 학습 곡선을 만든다
        print(f"  epoch {epoch}: valid {va:.3f} (MLflow에 step={epoch}로 기록)")
```

실행 결과:

```
== C. MLflow로 DL 학습 곡선 기록 ==
  epoch 1: valid 0.271 (MLflow에 step=1로 기록)
  epoch 2: valid 0.338 (MLflow에 step=2로 기록)
  epoch 3: valid 0.376 (MLflow에 step=3로 기록)
  epoch 4: valid 0.411 (MLflow에 step=4로 기록)
  epoch 5: valid 0.429 (MLflow에 step=5로 기록)
```

`mlflow ui` 를 열어 run의 valid_acc를 클릭해 보세요 — 다섯 점이 **곡선**으로 그려져 있습니다.
[Day 065](../03-machine-learning/day-065.md)의 여덟 칸 규율은 그대로 유효합니다 (arch·seed·
train_size·device까지 params에). 체크포인트 파일을 `mlflow.log_artifact` 로 run에 첨부하면
"이 곡선의 그 시점 모델"까지 한 몸이 됩니다 — [Day 068](../03-machine-learning/day-068.md) Q3의
족보가 DL에서도 완성됩니다.

### Step 4. 재현성 점검 — 선 긋기 (6교시)

```python
print("\n== D. 재현성 점검: 같은 시드로 두 번 (CPU) ==")
accs = []
for run in (1, 2):
    torch.manual_seed(42)
    m = make_model()
    o = torch.optim.Adam(m.parameters(), lr=0.001)
    dl = DataLoader(Subset(full, range(0, 2000)), batch_size=128, shuffle=True,
                    generator=torch.Generator().manual_seed(0))   # 셔플 난수도 고정
    for xb, yb in dl:
        loss = loss_fn(m(xb), yb)
        loss.backward(); o.step(); o.zero_grad()
    accs.append(accuracy(m))
    print(f"  실행 {run}: 1에폭 후 valid {accs[-1]:.6f}")
print(f"  완전히 같은가? {accs[0] == accs[1]}  (CPU는 재현 — GPU는 근사 재현이 현실)")
```

실행 결과:

```
== D. 재현성 점검: 같은 시드로 두 번 (CPU) ==
  실행 1: 1에폭 후 valid 0.280000
  실행 2: 1에폭 후 valid 0.280000
  완전히 같은가? True  (CPU는 재현 — GPU는 근사 재현이 현실)
```

시드를 **두 군데**(모델 초기화, DataLoader 셔플) 고정하니 CPU에서는 소수점 여섯 자리까지
같습니다. 같은 코드를 Colab GPU에서 두 번 돌리면 대개 소수점 서너 자리부터 어긋납니다 —
버그가 아니라 병렬 덧셈 순서의 문제입니다. 그래서 이 단원의 문서 숫자도 "CPU 기준,
경향이 같으면 정상"이라 했던 것입니다. **재현성의 정신([Day 066](../03-machine-learning/day-066.md))은
그대로, 눈금만 현실에 맞게** — GPU 실험은 시드별 평균±표준편차로 보고합니다.

## ⑤ 자주 하는 실수

### 모델만 저장하고 optimizer를 빼먹음

**증상** — 재개는 되는데 직후 몇 에폭 동안 valid가 뚝 떨어졌다 회복함.
**원인** — Adam의 파라미터별 상태(모멘텀·2차 모멘트)가 초기화되어 첫 걸음들이 과격해집니다.
**해결** — 체크포인트에는 model + **optimizer** + epoch. 학습률 스케줄러를 쓰면 그것도 함께.

### best와 last를 한 파일에 겸용

**증상** — 최고였던 epoch 10 모델을 배포하려는데 파일에는 (과적합된) epoch 40이 들어 있음.
**원인** — 매 에폭 덮어쓰는 last 슬롯 하나만 운영했습니다.
**해결** — last.pt(재개용, 항상 덮어씀)와 best.pt(valid 갱신 시만)를 분리. 배포는 언제나 best에서.

### torch.load를 아무 파일에나 씀

**증상** — 출처 불명의 .pt 파일을 로드 — 보안 사고 가능성.
**원인** — 체크포인트도 pickle 계열이라 로드 시 코드가 실행될 수 있습니다 ([Day 068](../03-machine-learning/day-068.md)의 그 경고).
**해결** — 신뢰할 수 있는 출처만. 최신 PyTorch의 기본값(`weights_only=True`)이 임의 객체 실행을 막아 주지만, 원칙은 동일합니다 — 모델 파일은 코드처럼 취급하세요.

### 시드를 한 군데만 고정하고 재현을 기대

**증상** — `torch.manual_seed(42)` 를 했는데 실행마다 결과가 다름.
**원인** — DataLoader 셔플이 별도 난수를 씁니다 (+ GPU면 병렬 비결정성, num_workers>0이면 워커 시드까지).
**해결** — Step 4처럼 DataLoader에 `generator=` 지정. 그래도 GPU에서는 "근사 재현"이 기대치 — 완전 일치가 필요하면 결정적 모드(느림)를 검토합니다.

### Colab에서 체크포인트를 세션 안에만 둠

**증상** — 세션 만료와 함께 checkpoints/ 폴더 증발 — 재개할 대상이 없음.
**원인** — Colab의 로컬 디스크는 세션 수명과 같습니다.
**해결** — 체크포인트를 Google Drive 마운트 경로나 외부 저장소에 저장하세요. "저장 슬롯은 죽지 않는 곳에" — 이것까지가 학습 운영입니다.
