## 3. 개념

### 3-1. 블렌드 트리 — 클립을 섞는다

**왜 필요한가** — 전환이 아니라 혼합.

```
   전이(Transition)          블렌드 트리

   Walk ──0.2초──▶ Run       Speed = 3.5
   순간적으로 섞임            → Walk 60% + Run 40%
   그 뒤엔 Run만              → 계속 섞인 상태 유지
```

```
   Speed:  0 ──────── 2 ──────── 5.5

   Idle:   ████████░░░░░░░░░░░░░░░░
   Walk:   ░░░░░░░░████████░░░░░░░░
   Run:    ░░░░░░░░░░░░░░░░████████

   Speed = 3.5 일 때
   Walk 가중치 0.57, Run 가중치 0.43
   → 두 애니의 뼈 회전을 그 비율로 섞는다
```

```
   ★ 상태 하나로 이동 전체를 표현한다

   Idle / Walk / Run 3개 상태 → Locomotion 1개 상태
   → 전이 화살표가 사라진다
```

### 3-2. 1D 블렌드 트리

**왜 필요한가** — 파라미터 하나로 섞는다.

```
   State 우클릭 → Create State → From New Blend Tree
   → 더블클릭해서 들어간다
```

| 필드 | 의미 |
|---|---|
| **Blend Type** | 1D / 2D Simple Directional / 2D Freeform 등 |
| **Parameter** | 섞는 기준 (예: Speed) |
| Motion 목록 | 클립 + Threshold |
| **Automate Thresholds** | 자동 균등 배분 |
| **Compute Thresholds** | 클립의 실제 속도로 계산 ★ |

```
   Motion          Threshold
   Idle            0
   Walk            2
   Run             5.5
```

```
   ★ Compute Thresholds → Velocity Z

   각 클립의 루트 모션 속도를 읽어 Threshold를 자동 설정
   → 발 미끄러짐이 크게 줄어든다
```

```
   ⚠️ Threshold 단위를 이동 속도와 맞춘다

   Walk 클립의 실제 속도가 2 m/s 인데
   Threshold를 0.5로 두면
   → 코드 속도 2일 때 Run이 재생된다
   → 발이 미끄러진다
```

### 3-4. 발 미끄러짐 (Foot Sliding)

**왜 필요한가** — 3D 캐릭터 애니메이션의 대표 문제.

```
   ★ 원인

   애니메이션의 보폭 속도  ≠  실제 이동 속도

   애니: 발이 2 m/s 로 움직인다
   코드: 캐릭터가 5 m/s 로 나간다
   → 발이 땅에서 미끄러진다
```

**해결 1 — 이동 속도를 애니에 맞춘다**

```
   Walk 클립의 실제 속도를 측정해 walkSpeed로 사용
   → Compute Thresholds가 이 값을 알려준다
```

**해결 2 — 애니 재생 속도를 이동에 맞춘다**

```
   State의 Speed에 Multiplier 파라미터 연결

   Speed: 1
   Multiplier: SpeedMultiplier (Float)
```

```csharp
    // 실제 속도 / 클립 기준 속도
    animator.SetFloat(HashSpeedMult, currentSpeed / baseClipSpeed);
```

```
   ⚠️ 너무 크게 조절하면 부자연스럽다

   0.7 ~ 1.4 범위를 넘지 않게 clamp
```

**해결 3 — 루트 모션 사용**

```
   애니메이션이 이동을 담당
   → 원리적으로 미끄러지지 않는다
   → 대신 제어가 어렵다 (3-5)
```

**해결 4 — Foot IK**

```
   State Inspector → Foot IK ✔

   발이 지면에 맞게 보정된다 (경사면에서 특히)
   ⚠️ Humanoid만 가능
```

### 3-5. 루트 모션

**왜 필요한가** — 이동의 주체를 정한다.

```
   Root Motion 사용                  코드 이동

   애니메이션이 캐릭터를 민다         코드가 위치를 정한다
   ┌──────────────────┐              ┌──────────────────┐
   │ 애니 → Transform │              │ 입력 → Transform │
   └──────────────────┘              └──────────────────┘
```

| | Root Motion | 코드 이동 |
|---|---|---|
| 발 미끄러짐 | **적음** | 발생하기 쉬움 |
| 제어 정밀도 | 낮음 | **높음** |
| 물리 연동 | 어려움 | 쉬움 |
| 네트워크 동기화 | 어려움 | 쉬움 |
| 적합 | 공격·회피 등 **정해진 이동** | **자유 이동** |

```
   ★ 실무에서는 섞어 쓴다

   이동(Locomotion):  코드
   공격·회피·구르기:   루트 모션
```

```csharp
public class RootMotionController : MonoBehaviour
{
    [SerializeField] private Animator animator;
    private Rigidbody rb;

    // ★ 애니메이터가 루트 모션을 적용하기 직전에 호출
    void OnAnimatorMove()
    {
        if (!useRootMotion)
        {
            // 루트 모션 무시 (코드 이동)
            return;
        }

        Vector3 delta = animator.deltaPosition;
        delta.y = 0;                           // ★ 수직은 물리에 맡긴다

        rb.MovePosition(rb.position + delta);
        rb.MoveRotation(rb.rotation * animator.deltaRotation);
    }
}
```

```
   ★ OnAnimatorMove

   Apply Root Motion이 켜져 있을 때
   Unity가 자동 적용하는 대신 이 함수를 호출한다
   → 우리가 원하는 방식으로 적용할 수 있다
```

```
   ⚠️ Apply Root Motion ✔ 인데 코드로도 이동하면

   두 배로 움직이거나, 서로 싸워서 떨린다
```

**상태별로 전환하기**

```csharp
    // 공격 상태 진입 시 루트 모션 켜기
    public class RootMotionState : StateMachineBehaviour
    {
        [SerializeField] private bool useRootMotion = true;

        public override void OnStateEnter(Animator a, AnimatorStateInfo s, int l)
        {
            a.applyRootMotion = useRootMotion;
        }
    }
```

### 3-7. ⚠️ 애니메이션 이벤트의 함정

**왜 필요한가** — 실전에서 반드시 만난다.

```
   ⚠️ ① 마지막 프레임의 이벤트가 안 불릴 수 있다

   전이가 그 전에 시작되면 건너뛴다
   → 마지막에서 1~2프레임 앞에 둔다
```

```
   ⚠️ ② 재생 속도가 빠르면 건너뛸 수 있다

   Speed 3배로 재생하면 프레임을 뛰어넘는다
   → 중요한 이벤트는 여유를 둔다
```

```
   ⚠️ ③ Culling Mode: Cull Completely 면 안 불린다

   화면 밖 캐릭터의 이벤트가 실행되지 않는다
   → Cull Update Transforms 사용
```

```
   ⚠️ ④ 함수가 없으면 매번 경고

   "'OnAttackStart' AnimationEvent has no receiver!"

```


### 3-8. 판정 박스 (Day 47의 재현)

**왜 필요한가** — 무엇이 때리고 무엇이 맞는지.

```
   ★ Day 47에서 배운 구분

   히트박스(Hitbox)   = 때리는 영역 (공격자)
   허트박스(Hurtbox)  = 맞는 영역 (피격자)
```

```
        공격자                      피격자

        ●                            ●
       ╱│╲    ┌ ─ ─ ┐               ╱│╲
      ─┤ ├────╎히트 ╎              ┌┤ ├┐  ← 허트박스
       ╱ ╲    └ ─ ─ ┘              └╱ ╲┘
```

```csharp
using System.Collections.Generic;
using UnityEngine;

public class HitboxController : MonoBehaviour
{
    [Header("판정")]
    [SerializeField] private Vector3 offset = new Vector3(0, 1f, 0.8f);
    [SerializeField] private Vector3 size = new Vector3(1.2f, 1.2f, 1.4f);
    [SerializeField] private LayerMask targetLayer;

    [Header("데미지")]
    [SerializeField] private int damage = 10;
    [SerializeField] private float knockback = 4f;

    private readonly HashSet<Collider> alreadyHit = new HashSet<Collider>();
    private readonly Collider[] buffer = new Collider[16];    // ★ 재사용

    public bool IsActive { get; private set; }

    public void Activate()
    {
        alreadyHit.Clear();                    // ★ Day 47의 히트 기록 초기화
        IsActive = true;
    }

    public void Deactivate() => IsActive = false;

    void FixedUpdate()
    {
        if (!IsActive) return;

        Vector3 center = transform.TransformPoint(offset);

        // ★ NonAlloc — GC 할당 없음 (Day 74)
        int count = Physics.OverlapBoxNonAlloc(
            center, size * 0.5f, buffer, transform.rotation, targetLayer);

        for (int i = 0; i < count; i++)
        {
            Collider c = buffer[i];

            if (alreadyHit.Contains(c)) continue;   // ★ 중복 타격 방지
            alreadyHit.Add(c);

            IDamageable d = c.GetComponentInParent<IDamageable>();
            if (d == null) continue;

            Vector3 dir = (c.transform.position - transform.position);
            dir.y = 0;
            dir.Normalize();

            d.TakeDamage(new DamageInfo
            {
                amount = damage,
                knockback = knockback,
                direction = dir,
                source = transform,
            });
        }
    }

    void OnDrawGizmos()
    {
        Gizmos.color = IsActive
            ? new Color(1f, 0.2f, 0.2f, 0.5f)
            : new Color(0.5f, 0.5f, 0.5f, 0.15f);

        Matrix4x4 old = Gizmos.matrix;
        Gizmos.matrix = Matrix4x4.TRS(
            transform.TransformPoint(offset), transform.rotation, Vector3.one);

        Gizmos.DrawCube(Vector3.zero, size);
        Gizmos.DrawWireCube(Vector3.zero, size);

        Gizmos.matrix = old;
    }
}
```

```
   ★ HashSet으로 중복 타격 방지

   Day 47에서 배열로 했던 그것
   Part 2:  bool hitRecord[MAX_TARGETS];
   Unity:   HashSet<Collider>
```

```
   ★ OverlapBoxNonAlloc

   OverlapBox는 배열을 새로 만든다 → GC
   NonAlloc은 미리 만든 배열을 채운다 → GC 없음

   ⚠️ 버퍼 크기를 넘으면 잘린다
```

```csharp

{

}

[System.Serializable]
public struct DamageInfo
{
    public int amount;
    public float knockback;
    public Vector3 direction;
    public Transform source;
}
```


### 3-10. 프레임 데이터 (격투 게임 개념)

**왜 필요한가** — 액션의 밸런스를 수치로 관리한다.

```
   ★ Day 47에서 배운 구조

   시작(Startup) → 활성(Active) → 후딜(Recovery)

   프레임  0 ─────── 12 ──── 18 ──────── 30
           준비        판정      후딜

   Startup   12 프레임   빠를수록 강하다
   Active     6 프레임   길수록 맞히기 쉽다
   Recovery  12 프레임   짧을수록 안전하다
```

```csharp
[System.Serializable]
public class AttackData
{
    public string name = "Attack1";
    public int startupFrames = 12;
    public int activeFrames = 6;
    public int recoveryFrames = 12;

    public int damage = 10;
    public float knockback = 4f;

    public int TotalFrames => startupFrames + activeFrames + recoveryFrames;

    // ★ 30fps 기준 정규화 시간
    public float StartNormalized => startupFrames / (float)TotalFrames;
    public float EndNormalized => (startupFrames + activeFrames) / (float)TotalFrames;
}
```

```
   ★ 이벤트 대신 시간 기반으로 할 수도 있다

   장점:  데이터로 관리. 밸런싱이 쉽다
   단점:  클립 길이가 바뀌면 다시 계산
```

```
   ★ 어느 쪽을 쓰나

   애니메이션 이벤트:  애니메이터가 타이밍을 조절 (협업)
   프레임 데이터:      기획자가 수치로 조절 (밸런싱)

   → 격투 게임은 후자, 일반 액션은 전자가 많다
```

```csharp
using UnityEngine;

public class SimpleEnemy : MonoBehaviour, IDamageable
{
    [SerializeField] private int maxHp = 50;
    [SerializeField] private Renderer rend;

    private int hp;
    private Color originalColor;
    private float flashTimer;

    public bool IsAlive => hp > 0;

    void Awake()
    {
        hp = maxHp;
        if (rend == null) rend = GetComponentInChildren<Renderer>();
        originalColor = rend.material.color;
    }

    public void TakeDamage(DamageInfo info)
    {
        if (!IsAlive) return;

        hp -= info.amount;
        flashTimer = 0.12f;

        // 넉백
        transform.position += info.direction * info.knockback * 0.15f;

        Debug.Log($"[적] 피해 {info.amount}, 남은 HP {hp}");

        if (hp <= 0)
        {
            Debug.Log("[적] 사망");
            Destroy(gameObject, 0.3f);
        }
    }

    void Update()
    {
        if (flashTimer > 0)
        {
            flashTimer -= Time.deltaTime;
            rend.material.color = Color.red;
            if (flashTimer <= 0) rend.material.color = originalColor;
        }
    }
}
```

- [ ] 안전장치(`ForceEndAttack`)가 동작한다
- [ ] 중복 타격 방지(`HashSet`)를 확인했다
- [ ] 수신자 없음 경고를 봤다
- [ ] 루트 모션을 상태별로 제어했다
- [ ] (선택) 3단 콤보가 동작한다
- [ ] (선택) 발소리 이벤트가 불린다

## 6. 자주 막히는 곳

| 증상 | 원인 | 해결 |
|---|---|---|
| **이벤트가 안 불림** | 함수가 private | `public`으로 |
| 이벤트가 안 불림 | 다른 GameObject | Animator와 **같은 오브젝트** |
| 이벤트가 안 불림 | Culling Mode | Cull Update Transforms |
| 마지막 이벤트 누락 | 전이가 먼저 시작 | 1~2프레임 앞으로 |
| "no receiver" 경고 | 함수 없음 | 함수 추가 또는 이벤트 삭제 |
| **판정이 안 꺼짐** | End 이벤트 누락 | 안전장치 + 이벤트 확인 |
| 한 번에 여러 번 맞음 | 히트 기록 없음 | `HashSet` |
| 두 번째 공격이 안 맞음 | 기록 초기화 누락 | `Activate`에서 `Clear` |
| **발이 미끄러짐** | 속도 불일치 | Compute Thresholds / Multiplier |
| 블렌드가 이상함 | Threshold 단위 | 실제 속도로 |
| 애니가 튐 | 파라미터 급변 | dampTime |
| 두 배로 이동 | 루트 모션 중복 | 상태별 제어 |
| 공격이 제자리 | XZ Bake ✔ | 해제 |
| 콤보가 끊김 | Exit Time 범위 | 0.4~0.8 구간에 조건 |
| 콤보 후 재공격 | Trigger 잔류 | `ResetTrigger` |
| GC 발생 | `OverlapBox` | `OverlapBoxNonAlloc` |
