## 왜 만들었나

1인 개발 스튜디오는 한 사람이 메이커·프리랜서·운영자·사업자·학습자를 하루 안에 오간다. 기록 도구가 역할마다 따로 있으면 입력 자체가 귀찮아 아무것도 남지 않고, 그 결과는 돈으로 돌아온다.

- 외주는 납품 후 조용해져 **미수금이 묻힌다.**
- 개인 프로젝트는 시작만 하고 **진척·회고가 남지 않는다.**
- 배포한 사이트·게임의 **도메인·SSL·구독 만료를 놓친다.**
- 매출·비용이 프로젝트와 연결되지 않아 **무엇이 돈이 되는지 모른다.**
- 수집한 자료가 **읽히지 않고 쌓인다.**

PA_는 이 다섯 가지를 한 앱, 한 입력창으로 해결한다.

## 누가, 언제 쓰나

| 역할 | 하는 일 | 앱에서 관리하는 것 |
|---|---|---|
| 메이커 | 개인 프로젝트(웹·게임·툴) 기획·개발·출시 | 프로젝트, 태스크, 시간 |
| 프리랜서 | 문의 → 견적 → 계약 → 납품 → 정산 | 외주 건, 발주처, 미수금 |
| 운영자 | 출시한 것을 살려 두기 | 배포물, 도메인·SSL, 장애, 서버 비용 |
| 사업자 | 회사 돈 흐름과 세금 | 매출·비용, 고정비, 부가세·종소세 |
| 학습자 | 자료를 모아 내 지식으로 | 자료, 위키, 사용 툴 |

| 시점 | 앱에서 하는 일 | 목표 시간 |
|---|---|---|
| 아침 | 홈 한 화면에서 일정·마감·미수금·장애·만료 확인 | 30초 |
| 작업 중 | Ctrl+K 캡처, 분류는 나중에 | 5초 |
| 작업 끝 | 타임라인 블록 하나 (`2h #프로젝트`) | 15초 |
| 입금·결제 | 외주 입금 입력 → 장부 매출 자동 / 폰에서 금액 캡처 → 장부 비용 | 10~15초 |
| 저녁 | 인박스를 1~2탭으로 비우기 | 2분 |
| 월말 | 손익·고정비·프로젝트 시간 배분 열람 | 5분 |

## 설계 원칙

1. **기록 하나만 의무, 나머지는 선택.** 빈칸을 채우라고 재촉하지 않는다.
2. **입력은 한 곳(캡처), 분류는 나중에.** 확인 단계가 없다.
3. **돈은 묻히지 않게.** 미수금·만료·장애는 해결될 때까지 홈에서 사라지지 않는다.
4. **삭제는 묻지 않고 5초 되돌리기.**
5. **연결은 자동, 끊김은 안전.** 외주 → 장부, 구독 → 고정비 → 거래는 자동. 상위를 지워도 하위 기록은 남는다.
6. **목표·달성률 없음.** 통계는 조용한 열람처.
7. **같은 돈은 한 번만.** 하나의 결제는 장부에 한 행. 자동 생성된 행이 있으면 병합한다.

## 눈여겨볼 구현

**같은 돈은 한 번만.** 고정비는 결제일에 비용 거래를 자동 생성한다. 이후 캡처·수동 입력·CSV로 같은 결제가 들어오면 새 행을 만들지 않고 자동 행에 병합한다. 조건은 결제일 ±3일, 메모에 매칭 키워드 포함, 같은 통화면 금액 ±5%. USD 구독을 KRW 카드로 결제한 경우는 금액을 무시하고 원화 청구액만 채운다. 병합도 5초 되돌리기 대상이다.

**세금 방식이 미수금을 결정한다.** 발주처가 세금계산서 방식이면 청구 총액은 공급가 × 1.1이고 입금을 공급가·부가세로 자동 분리한다. 3.3% 원천징수면 공제액을 입금으로 간주해야 미수금이 0이 된다. 이 규칙은 사용성 테스트에서 "정산완료 버튼이 영원히 비활성"이 되는 시나리오를 잡아내며 추가됐다.

**첨부 포함 ZIP을 메모리 없이 스트리밍.** 워커 메모리 한계 안에서 수백 MB 첨부를 내보내기 위해 무압축 ZIP 라이터를 직접 작성했다. data descriptor 방식으로 크기·CRC를 뒤에 쓰고 R2 객체를 그대로 파이프한다. 백업은 앱 키로 지울 수 없는 별도 버킷에 매일 쌓이고, 보관 기간은 R2 수명 주기 규칙이 담당한다.

**트러스트 바운더리 한 곳.** 범용 CRUD는 테이블 허용 목록과 `PRAGMA table_info` 컬럼 캐시로 알 수 없는 컬럼을 조용히 버린다. 도메인 규칙이 필요한 곳만 모듈 라우트가 맡아 코드가 짧다.

## 만든 과정

| 단계 | 산출물 |
|---|---|
| 1. PRD v0.5 | 사용자 맥락(5역할·하루의 흐름) → 목표 지표 → 기능 명세 ID 110여 개 → 데이터 모델 → 결정 사항 |
| 2. 사용성 테스트 | 시나리오 9개 인지적 워크스루. P0 누락 7건(돈 중복, 세금 규칙, 할 일·태스크 통합, 홈 900px, 보안, 백업 범위) 발견 → PRD 반영 |
| 3. 디자인 | 브루탈리즘 토큰(테두리 2 · 구분선 4 · 그림자 5×5 · 라운드 없음) 기준 화면 48장, 입력 상태 별도 |
| 4. 구현 | 모듈별 파일 소유권을 정해 Claude Code 세션 4개가 병렬 구현. 모듈 간 계약(미수금·월 요약·비용 추가·태그 해석)을 함수 export로 고정, 리드 세션만 커밋 |
| 5. 배포 | Workers + D1 + R2 두 버킷 + Cron. 무료 한도 안에서 운영 |
