## ① 학습 목표

이 레슨을 마치면 이렇게 할 수 있습니다.

- API를 **3계층**(router / service / repository)으로 나누고 각 층의 책임을 말할 수 있다.
- **"service는 HTTP를 모른다"** 를 코드로 증명할 수 있다 (서버 없이 직접 호출).
- `Depends` 로 의존성을 주입하고, 그것이 왜 테스트·교체를 쉽게 만드는지 안다.
- 설정을 환경 변수로 분리하고, DB 연결(대단원 02의 SQLAlchemy)을 저장 계층에 격리할 수 있다.

---

## ② 왜 필요한가

어제까지의 main.py는 한 파일에 전부 있었습니다 — 검증, 등급 계산 규칙, 저장, HTTP 응답까지.
파일이 200줄일 땐 문제가 없습니다. MP3와 실무의 API는 다릅니다:

```
"등급 기준이 바뀌었대요. 어디 고치죠?"          → 규칙이 핸들러 여기저기에
"저장을 dict에서 PostgreSQL로 바꿔 주세요"      → 저장 코드가 20군데에
"이 규칙, 배치 작업에서도 써야 하는데요"         → HTTP 없이는 호출 불가능한 구조
"테스트 좀 짜 주세요"                           → 서버를 띄워야만 뭐든 테스트 가능
```

답은 [Day 010](../01-python-data/day-010.md)과 [Day 013](../01-python-data/day-013.md)에서 이미
배웠습니다 — **관심사를 계층으로 나누고, 화살표를 한 방향으로.** 그때 "W19에서 이 구조가
API의 표준이 된다"고 예고했던 그 날이 오늘입니다. datapipe 패키지에서 수집/정제/저장을
나눴듯, API에서는 HTTP/규칙/저장을 나눕니다.

## ③ 개념 설명

### 3계층 — 각 층은 하나만 안다

```
router (HTTP 계층)        요청 검증(pydantic) · 도메인 예외 → 상태 코드 번역
   ↓ 호출
service (비즈니스 계층)    규칙(중복 금지 · 등급 계산) — HTTP도 SQL도 모름
   ↓ 호출
repository (저장 계층)     SQL — 규칙을 모름. "찾아라/저장하라"만
```

| 층 | 아는 것 | 모르는 것 | 이 층이 바뀌는 이유 |
|---|---|---|---|
| router | HTTP (상태 코드·JSON) | 규칙의 내용, SQL | API 스펙 변경 |
| **service** | 도메인 규칙 | **HTTP, SQL** | 업무 규칙 변경 |
| repository | SQL·저장소 | 규칙, HTTP | DB 교체·스키마 변경 |

바뀌는 이유가 다른 것들을 한 파일에 두지 않는다 — [Day 013](../01-python-data/day-013.md)의
원칙 그대로입니다. 화살표는 위에서 아래로만 흐릅니다 (service가 router를 import하면 반칙).

### 도메인 예외 — 계층 사이의 언어

service는 실패를 HTTP 코드가 아니라 **자기 언어**로 말합니다: `DuplicateReport`,
`ReportNotFound`. 그것을 409·404로 번역하는 것은 router의 일입니다. 이 분리 덕에
같은 service를 배치 작업·CLI·다른 프로토콜에서도 그대로 씁니다 — 오늘 실습 마지막에
**서버 없이** service를 호출해 이를 증명합니다.

### Depends — 부품을 꽂아 주는 소켓

```python
def get_service() -> ReportService:
    return ReportService(ReportRepository())

@router.post("")
def create_report(r: ReportIn, svc: ReportService = Depends(get_service)):
```

핸들러가 "서비스를 **어떻게 만드는지**"를 모르게 하는 장치입니다. 효과 두 가지:
① 만드는 방법이 한 곳(get_service)에 모임 — DB 연결·설정이 바뀌어도 핸들러는 무변,
② 테스트에서 **가짜 부품으로 교체** 가능 (`app.dependency_overrides` — 내일 사용).
[Day 070](../03-machine-learning/day-070.md)에서 설정과 코드를 분리했듯, 여기서는 **조립과
사용**을 분리합니다.

### 설정과 DB — 대단원 02의 재사용

설정(환경·DB URL)은 코드 밖(환경 변수)에서 옵니다. DB 연결은
[Day 041](../02-sql-pipeline/day-041.md)의 SQLAlchemy `create_engine` 그대로 —
수업은 파일 하나짜리 SQLite로 하되, **URL만 바꾸면 PostgreSQL**입니다
(`postgresql+psycopg://...` — MP1에서 쓰던 그 엔진). 저장 기술의 교체가 URL 한 줄인 것도
repository 계층에 SQL을 격리한 덕입니다.

## ④ 단계별 실습

### Step 1. 패키지 구조로 리팩터링 (1~4교시)

어제의 main.py를 다섯 파일로 나눕니다.

```
api/app/
├── __init__.py
├── config.py        설정 (환경 변수)
├── repository.py    저장 계층 (SQL은 여기에만)
├── service.py       비즈니스 계층 (HTTP도 SQL도 모름)
├── router.py        HTTP 계층 (번역만)
└── main.py          조립
```

`app/config.py`:

```python

class Settings:
    def __init__(self):
        self.app_env = os.getenv("APP_ENV", "dev")
        # 수업은 SQLite. PostgreSQL이면 URL만 교체:
        #   postgresql+psycopg://postgres:pw@localhost:5432/air   (Day 041의 그 엔진)
        self.db_url = os.getenv("DB_URL", "sqlite:///reports_dev.db")
```

`app/repository.py`:

```python
# app/repository.py — 저장 계층: "어떻게 저장하나"만 안다 (SQL은 여기에만 존재)
from sqlalchemy import create_engine, text

from .config import settings

engine = create_engine(settings.db_url)

with engine.begin() as conn:
    conn.execute(text("""
        CREATE TABLE IF NOT EXISTS report (
            station TEXT NOT NULL,
            measured_on TEXT NOT NULL,
            pm25 REAL NOT NULL,
            grade TEXT NOT NULL,
            PRIMARY KEY (station, measured_on)
        )"""))


class ReportRepository:
    def find(self, station: str, measured_on: str) -> dict | None:
        with engine.begin() as conn:
            row = conn.execute(
                text("SELECT * FROM report WHERE station=:s AND measured_on=:d"),
                {"s": station, "d": measured_on}).mappings().first()
        return dict(row) if row else None

    def save(self, row: dict) -> None:
        with engine.begin() as conn:
            conn.execute(text("""
                INSERT INTO report (station, measured_on, pm25, grade)
                VALUES (:station, :measured_on, :pm25, :grade)"""), row)
```

`app/service.py`:

```python
# app/service.py — 비즈니스 계층: 규칙만 안다. HTTP도, SQL도 모른다.
from .repository import ReportRepository


class DuplicateReport(Exception):
    """같은 (측정소, 날짜) 리포트가 이미 있음."""


class ReportNotFound(Exception):
    """조회 대상 없음."""


def to_grade(pm25: float) -> str:
    return "좋음" if pm25 < 16 else "보통" if pm25 < 36 else "나쁨" if pm25 < 76 else "매우나쁨"


class ReportService:
    def __init__(self, repo: ReportRepository):
        self.repo = repo

    def create(self, station: str, measured_on: str, pm25: float) -> dict:
        if self.repo.find(station, measured_on):
            raise DuplicateReport(f"{station} {measured_on}")
        row = {"station": station, "measured_on": measured_on,
               "pm25": pm25, "grade": to_grade(pm25)}
        self.repo.save(row)
        return row

    def get(self, station: str, measured_on: str) -> dict:
        row = self.repo.find(station, measured_on)
        if row is None:
            raise ReportNotFound(f"{station} {measured_on}")
        return row
```

`app/router.py`:

```python
# app/router.py — HTTP 계층: 요청/응답 번역만 한다. 규칙은 service에 위임.
from datetime import date
from fastapi import APIRouter, Depends, HTTPException
from pydantic import BaseModel, Field

from .repository import ReportRepository
from .service import DuplicateReport, ReportNotFound, ReportService

router = APIRouter(prefix="/reports", tags=["reports"])


class ReportIn(BaseModel):
    model_config = {"extra": "forbid"}
    station: str
    measured_on: date
    pm25: float = Field(ge=0, le=300)


def get_service() -> ReportService:          # 의존성: "서비스가 필요하면 이렇게 만든다"
    return ReportService(ReportRepository())


@router.post("", status_code=201)
def create_report(r: ReportIn, svc: ReportService = Depends(get_service)):
    try:
        return svc.create(r.station, str(r.measured_on), r.pm25)
    except DuplicateReport as e:             # 도메인 예외 → HTTP 언어로 번역
        raise HTTPException(status_code=409, detail=f"이미 있습니다: {e}")


@router.get("/{station}/{measured_on}")
def get_report(station: str, measured_on: date, svc: ReportService = Depends(get_service)):
    try:
        return svc.get(station, str(measured_on))
    except ReportNotFound:
        raise HTTPException(status_code=404, detail="리포트가 없습니다")
```

`app/main.py`:

```python
# app/main.py — 조립: 라우터를 앱에 꽂기만 한다
from fastapi import FastAPI

from .config import settings
from .router import router

app = FastAPI(title="대기질 리포트 API", version="0.3.0")
app.include_router(router)


@app.get("/health")
def health():
    return {"status": "ok", "env": settings.app_env}
```

### Step 3. 증명 — service는 HTTP를 모른다 (6교시)

서버를 **끄고**, 파이썬에서 service를 직접 호출합니다:

```powershell
python -c "
from app.repository import ReportRepository
from app.service import ReportService, DuplicateReport
svc = ReportService(ReportRepository())
print('직접 호출:', svc.get('강남구', '2026-08-13'))
try:
    svc.create('강남구', '2026-08-13', 30.0)
except DuplicateReport as e:
    print('도메인 예외:', type(e).__name__, e)
"
```

```
직접 호출: {'station': '강남구', 'measured_on': '2026-08-13', 'pm25': 41.5, 'grade': '나쁨'}
도메인 예외: DuplicateReport 강남구 2026-08-13
```

**서버도, HTTP도, 포트도 없이** 업무 규칙이 완전하게 동작합니다. 실패도 409가 아니라
`DuplicateReport` — 도메인의 언어입니다. 이 성질 덕에: 배치 작업이 이 service를 그대로
import해 쓸 수 있고, 내일의 테스트가 서버 없이 규칙을 검증할 수 있고, W27의 Airflow
태스크도 HTTP를 거치지 않고 규칙을 재사용합니다. **"service는 HTTP를 모른다"는 격리가
아니라 재사용의 선언**입니다.

## ⑤ 자주 하는 실수

### service가 HTTPException을 던짐

**증상** — service.py에 `from fastapi import HTTPException` 이 등장.
**원인** — 편해서. 하지만 그 순간 service는 FastAPI 없이는 못 쓰는 코드가 됩니다 (배치·CLI 재사용 불가, 테스트에 서버 필요).
**해결** — service는 도메인 예외를, router가 번역을. import 문에 fastapi가 보이면 계층이 샌 것입니다 — **"import가 곧 의존성 감사"** ([Day 013](../01-python-data/day-013.md)의 화살표 검사).

### SQL이 계층을 넘어 흩어짐

**증상** — 급한 조회 하나를 router에서 바로 engine.execute — "한 번인데 뭐".
**원인** — 그 한 번이 두 번이 되고, DB 교체 때 전 파일 수색이 됩니다.
**해결** — SQL은 repository에만. 다른 층에서 `text(` 가 보이면 리뷰에서 반려합니다.

### 순환 import

```
ImportError: cannot import name 'router' from partially initialized module 'app.router' (most likely due to a circular import)
```

**원인** — 아래층(service)이 위층(router)을 import하는 역방향 화살표.
**해결** — 화살표는 main → router → service → repository → config 한 방향으로만. 역방향이 필요해 보이면 설계를 다시 봅니다 (대개 공용 타입을 별도 모듈로 빼면 풀립니다).

### Depends를 쓰지 않고 전역 인스턴스를 직접 참조

**증상** — 핸들러가 모듈 전역의 `svc = ReportService(...)` 를 직접 씀 — 동작은 함.
**원인** — Depends의 가치(교체 가능성)를 아직 체감 못 해서.
**해결** — 내일 테스트에서 `dependency_overrides` 로 가짜 저장소를 꽂는 순간 가치가 보입니다. 오늘은 규약으로: **핸들러의 부품은 Depends로 받는다.**

### 상대 import 에러로 실행이 안 됨

```
ImportError: attempted relative import with no known parent package
```

**원인** — `python app/main.py` 처럼 파일을 직접 실행 — 패키지 문맥이 없어 `.config` 를 못 찾습니다.
**해결** — 패키지 루트(api/)에서 `uvicorn app.main:app` 으로 실행합니다. [Day 013](../01-python-data/day-013.md) ⑤에서 겪은 그 문제의 재방문입니다.
