## ② 왜 필요한가

**위험한 명령을 배웁니다.**

```sql
DELETE FROM scores;          -- WHERE 를 빠뜨리면 전체 삭제!
UPDATE scores SET score = 0; -- WHERE 를 빠뜨리면 전체 수정!
```

**`WHERE` 하나를 빠뜨리면 데이터가 전부 사라집니다.** 되돌릴 수 없습니다.
오늘은 그 방어법도 함께 배웁니다.

그리고 **모듈화**가 오늘의 진짜 주제입니다.

```python
# ❌ 게임 코드 여기저기에 SQL 이 흩어짐
conn = sqlite3.connect("game.db")
conn.execute("INSERT INTO scores ...")
conn.commit()
conn.close()
```

DB 파일 이름이 바뀌면? 테이블 구조가 바뀌면? **모든 곳을 고쳐야 합니다.**

```python
# ✅ db 모듈만 알면 됨
import db
db.save_score(name, score, kills)
```

게임 코드는 **SQL 이 무엇인지도 모릅니다.** 나중에 SQLite 를 MySQL 로 바꿔도 `db.py` 만 고치면 됩니다.

## ③ 개념 설명

### UPDATE — 수정

```sql
UPDATE scores SET score = 20000 WHERE id = 1;
UPDATE scores SET score = 20000, kills = 200 WHERE id = 1;
UPDATE scores SET score = score + 1000 WHERE player_name = '홍길동';
```

```python
cursor.execute(
    "UPDATE scores SET score = ?, kills = ? WHERE id = ?",
    (20000, 200, 1),
)
print(f"{cursor.rowcount}건 수정됨")
```

> **`cursor.rowcount`** 는 영향받은 행 수입니다. **0이면 조건에 맞는 행이 없었다는 뜻**입니다.
> 수정·삭제 후에는 항상 확인하는 습관을 들이세요.

### DELETE — 삭제

```sql
DELETE FROM scores WHERE id = 1;
DELETE FROM scores WHERE score < 1000;
DELETE FROM scores WHERE created_at < datetime('now', '-30 days');
DELETE FROM scores;                       -- ⚠️ 전체 삭제!
```

**안전 장치 — 삭제 전에 조회로 확인**

```python
# ① 먼저 몇 건이 지워질지 확인
count = conn.execute(
    "SELECT COUNT(*) AS c FROM scores WHERE score < ?", (1000,)
).fetchone()["c"]

print(f"{count}건이 삭제됩니다.")

# ② 사용자 확인
if input("계속할까요? (yes 입력): ").strip() == "yes":
    conn.execute("DELETE FROM scores WHERE score < ?", (1000,))
    conn.commit()
```

> **`DELETE` 는 되돌릴 수 없습니다.** 실무에서는 아예 지우지 않고 **`deleted_at` 열로 표시**하기도 합니다.
> 이를 **논리 삭제(soft delete)** 라고 합니다.

```sql
-- 논리 삭제
UPDATE scores SET deleted_at = datetime('now','localtime') WHERE id = ?;

-- 조회할 때 제외
SELECT * FROM scores WHERE deleted_at IS NULL;
```

### 트랜잭션 — 전부 성공 아니면 전부 취소

```python
conn = sqlite3.connect("game.db")

try:
    conn.execute("UPDATE accounts SET balance = balance - 1000 WHERE id = 1")
    conn.execute("UPDATE accounts SET balance = balance + 1000 WHERE id = 2")
    conn.commit()               # 둘 다 성공 → 확정
except Exception:
    conn.rollback()             # 하나라도 실패 → 전부 취소
    raise
finally:
    conn.close()
```

**트랜잭션이 없으면**

```
① 1번 계좌에서 1000원 차감  ✅
② 2번 계좌에 1000원 입금    ❌ (프로그램 종료)
→ 1000원이 사라졌습니다!
```

**트랜잭션이 있으면** ②가 실패하면 ①도 취소됩니다.

| 명령 | 하는 일 |
|---|---|
| `commit()` | 지금까지의 변경을 확정 |
| `rollback()` | 마지막 커밋 이후 변경을 전부 취소 |

**`with conn:` 이 이것을 자동으로 합니다.**

```python
with conn:                      # 블록 끝: commit / 예외: rollback
    conn.execute("UPDATE ...")
    conn.execute("UPDATE ...")
```

### ACID — 트랜잭션의 4가지 보장

| 속성 | 뜻 |
|---|---|
| **A**tomicity (원자성) | 전부 되거나 전부 안 되거나 |
| **C**onsistency (일관성) | 제약 조건이 항상 지켜짐 |
| **I**solation (격리성) | 동시 작업이 서로 간섭하지 않음 |
| **D**urability (지속성) | 커밋되면 전원이 나가도 남음 |

> [Day 031](day-031.md)에서 본 JSON 의 문제(중단 시 파일 손상, Lost Update)가 A와 I로 해결됩니다.

### UPSERT — 있으면 수정, 없으면 삽입

```sql
INSERT INTO settings (key, value) VALUES ('volume', '0.8')
ON CONFLICT(key) DO UPDATE SET value = excluded.value;
```

**또는 간단하게**

```sql
INSERT OR REPLACE INTO settings (key, value) VALUES ('volume', '0.8');
```

| 구문 | 동작 |
|---|---|
| `INSERT OR IGNORE` | 충돌하면 **건너뜀** |
| `INSERT OR REPLACE` | 충돌하면 **행을 지우고 새로 삽입** |
| `ON CONFLICT ... DO UPDATE` | 충돌하면 **지정한 열만 수정** (권장) |

> ⚠️ `INSERT OR REPLACE` 는 행을 **삭제 후 재삽입**하므로, 지정하지 않은 열이 기본값으로 초기화됩니다.
> 일부만 수정하려면 `ON CONFLICT ... DO UPDATE` 를 쓰세요.

### DB 접근 계층 분리

```
┌──────────────────────────┐
│  게임 코드 (scenes, main) │   SQL 을 전혀 모름
└───────────┬──────────────┘
            │ db.save_score(name, score)
┌───────────▼──────────────┐
│  db.py  (접근 계층)       │   SQL 을 여기에만
└───────────┬──────────────┘
            │ sqlite3
┌───────────▼──────────────┐
│  game.db                 │
└──────────────────────────┘
```

**얻는 것 4가지**

| 이점 | 설명 |
|---|---|
| **한곳에서 관리** | 테이블 구조가 바뀌면 `db.py` 만 수정 |
| **테스트 쉬움** | `db.py` 만 따로 검증 |
| **교체 가능** | SQLite → MySQL 전환 시 `db.py` 만 |
| **안전** | 파라미터 바인딩을 여기서 강제 |

### 연결 관리 전략

**① 매번 열고 닫기 (단순, 소규모에 적합)**

```python
def save_score(name, score):
    conn = get_connection()
    try:
        with conn:
            conn.execute("INSERT INTO scores ...", (name, score))
    finally:
        conn.close()
```

**② 연결을 재사용 (빠름, 관리 필요)**

```python
_connection = None

def get_connection():
    global _connection
    if _connection is None:
        _connection = sqlite3.connect(DB_PATH)
        _connection.row_factory = sqlite3.Row
    return _connection

def close():
    global _connection
    if _connection:
        _connection.close()
        _connection = None
```

> 게임처럼 **한 프로그램이 계속 도는 경우**는 ②가 효율적입니다.
> 다만 프로그램 종료 시 `close()` 를 반드시 호출해야 합니다.

**③ 컨텍스트 매니저 (가장 깔끔)**

```python
from contextlib import contextmanager

@contextmanager
def db_session():
    """with db_session() as conn: 형태로 사용합니다."""
    conn = sqlite3.connect(DB_PATH)
    conn.row_factory = sqlite3.Row
    try:
        yield conn
        conn.commit()
    except Exception:
        conn.rollback()
        raise
    finally:
        conn.close()


# 사용
with db_session() as conn:
    conn.execute("INSERT INTO scores ...", params)
```

### Step 1. UPDATE 와 DELETE 안전하게 쓰기

`db_modify.py`

```python
"""데이터 수정과 삭제 — 안전 장치 포함."""

import sqlite3
from pathlib import Path

DB_PATH = Path(__file__).resolve().parent / "game.db"


def get_connection():
    conn = sqlite3.connect(DB_PATH)
    conn.row_factory = sqlite3.Row
    return conn


def update_player_name(old_name, new_name):
    """플레이어 이름을 일괄 변경합니다. 변경된 건수를 반환합니다."""
    if not new_name.strip():
        print("[오류] 새 이름이 비어 있습니다.")
        return 0

    conn = get_connection()
    try:
        # ① 몇 건이 바뀔지 먼저 확인
        count = conn.execute(
            "SELECT COUNT(*) AS c FROM scores WHERE player_name = ?",
            (old_name,),
        ).fetchone()["c"]

        if count == 0:
            print(f"[안내] '{old_name}' 기록이 없습니다.")
            return 0

        # ② 실행
        with conn:
            cursor = conn.execute(
                "UPDATE scores SET player_name = ? WHERE player_name = ?",
                (new_name.strip(), old_name),
            )
            changed = cursor.rowcount

        print(f"[완료] '{old_name}' → '{new_name}' ({changed}건 변경)")
        return changed

    finally:
        conn.close()


def delete_low_scores(threshold, confirm=False):
    """기준 미만 기록을 삭제합니다. confirm=True 여야 실행됩니다."""
    conn = get_connection()
    try:
        # ① 삭제 대상 확인
        rows = conn.execute(
            "SELECT id, player_name, score FROM scores WHERE score < ? "
            "ORDER BY score LIMIT 5",
            (threshold,),
        ).fetchall()

        count = conn.execute(
            "SELECT COUNT(*) AS c FROM scores WHERE score < ?", (threshold,)
        ).fetchone()["c"]

        if count == 0:
            print(f"[안내] {threshold:,}점 미만 기록이 없습니다.")
            return 0

        print(f"\n[확인] {threshold:,}점 미만 {count}건이 삭제됩니다.")
        for r in rows:
            print(f"    #{r['id']:<5}{r['player_name']:<10}{r['score']:>8,}점")
        if count > 5:
            print(f"    ... 외 {count - 5}건")

        # ② 확인 없으면 중단
        if not confirm:
            print("  → confirm=True 로 호출해야 실제로 삭제됩니다.")
            return 0

        # ③ 실행
        with conn:
            cursor = conn.execute(
                "DELETE FROM scores WHERE score < ?", (threshold,)
            )
            deleted = cursor.rowcount

        print(f"[완료] {deleted}건 삭제")
        return deleted

    finally:
        conn.close()


def delete_by_id(record_id):
    """기록 하나를 삭제합니다."""
    conn = get_connection()
    try:
        row = conn.execute(
            "SELECT player_name, score FROM scores WHERE id = ?", (record_id,)
        ).fetchone()

        if row is None:
            print(f"[안내] #{record_id} 기록이 없습니다.")
            return False

        with conn:
            conn.execute("DELETE FROM scores WHERE id = ?", (record_id,))

        print(f"[완료] #{record_id} ({row['player_name']}, "
              f"{row['score']:,}점) 삭제")
        return True

    finally:
        conn.close()


def cleanup_old_records(days=30, keep_top=10, confirm=False):
    """오래된 기록을 삭제하되, 상위 기록은 보존합니다."""
    conn = get_connection()
    try:
        # 상위 keep_top 개의 id 는 보존
        sql_count = """
            SELECT COUNT(*) AS c FROM scores
            WHERE created_at < datetime('now', ?, 'localtime')
              AND id NOT IN (SELECT id FROM scores ORDER BY score DESC LIMIT ?)
        """
        count = conn.execute(sql_count, (f"-{days} days", keep_top)).fetchone()["c"]

        print(f"\n[정리] {days}일 이전 기록 중 상위 {keep_top}건을 제외한 "
              f"{count}건이 대상입니다.")

        if count == 0 or not confirm:
            if not confirm and count > 0:
                print("  → confirm=True 로 호출해야 실제로 삭제됩니다.")
            return 0

        with conn:
            cursor = conn.execute("""
                DELETE FROM scores
                WHERE created_at < datetime('now', ?, 'localtime')
                  AND id NOT IN (SELECT id FROM scores ORDER BY score DESC LIMIT ?)
            """, (f"-{days} days", keep_top))
            deleted = cursor.rowcount

        print(f"[완료] {deleted}건 정리")
        return deleted

    finally:
        conn.close()


if __name__ == "__main__":
    print("=" * 56)
    print("            수정·삭제 실습")
    print("=" * 56)

    update_player_name("홍길동", "홍길동(수정)")
    update_player_name("없는사람", "테스트")

    delete_low_scores(3000)                    # 확인만
    delete_low_scores(3000, confirm=True)      # 실제 삭제

    cleanup_old_records(days=30, keep_top=10)

    print("\n" + "=" * 56)
```

> **눈여겨볼 점 4가지**
> - **삭제 전에 항상 몇 건이 대상인지 조회**합니다. 예상과 다르면 멈출 수 있습니다.
> - `confirm=False` 기본값 — **실수로 호출해도 삭제되지 않습니다.**
> - `cursor.rowcount` 로 실제 영향받은 건수를 확인합니다.
> - `id NOT IN (SELECT ...)` — 서브쿼리로 "상위 10건은 제외" 를 표현했습니다.

### Step 2. 트랜잭션 실습

`transaction_demo.py`

```python
"""트랜잭션이 데이터를 어떻게 지키는지 확인합니다."""

import sqlite3

conn = sqlite3.connect(":memory:")
conn.row_factory = sqlite3.Row

with conn:
    conn.execute("""
        CREATE TABLE accounts (
            id      INTEGER PRIMARY KEY,
            name    TEXT NOT NULL,
            balance INTEGER NOT NULL CHECK (balance >= 0)
        )
    """)
    conn.executemany(
        "INSERT INTO accounts (id, name, balance) VALUES (?, ?, ?)",
        [(1, "홍길동", 100000), (2, "김철수", 50000)],
    )


def show_balances(label):
    print(f"\n  [{label}]")
    for r in conn.execute("SELECT name, balance FROM accounts ORDER BY id"):
        print(f"    {r['name']:<10}{r['balance']:>10,}원")


def transfer_unsafe(from_id, to_id, amount):
    """❌ 트랜잭션 없이 — 중간에 실패하면 돈이 사라집니다."""
    conn.execute("UPDATE accounts SET balance = balance - ? WHERE id = ?",
                 (amount, from_id))
    conn.commit()                          # ← 여기서 이미 확정!

    # 여기서 프로그램이 종료된다면?
    conn.execute("UPDATE accounts SET balance = balance + ? WHERE id = ?",
                 (amount, to_id))
    conn.commit()


def transfer_safe(from_id, to_id, amount):
    """✅ 트랜잭션 — 전부 성공하거나 전부 취소됩니다."""
    try:
        with conn:                         # 자동 커밋/롤백
            conn.execute("UPDATE accounts SET balance = balance - ? WHERE id = ?",
                         (amount, from_id))
            conn.execute("UPDATE accounts SET balance = balance + ? WHERE id = ?",
                         (amount, to_id))
        return True
    except sqlite3.IntegrityError as e:
        print(f"    → 실패 (자동 롤백): {e}")
        return False


print("=" * 56)
print("               트랜잭션 실험")
print("=" * 56)

show_balances("초기 상태")

# ── 정상 이체 ──
print("\n[① 정상 이체 30,000원]")
transfer_safe(1, 2, 30000)
show_balances("이체 후")

# ── 잔액 부족 이체 ──
print("\n[② 잔액 부족 이체 999,999원]")
transfer_safe(1, 2, 999999)
show_balances("실패 후 (변화 없어야 함)")

# ── 수동 롤백 ──
print("\n[③ 수동 롤백]")
conn.execute("UPDATE accounts SET balance = 0 WHERE id = 1")
show_balances("UPDATE 직후 (아직 커밋 안 함)")

conn.rollback()
show_balances("rollback() 후")

print("\n" + "=" * 56)
print("결론: CHECK 제약 위반으로 두 번째 UPDATE 가 실패하자")
print("      첫 번째 UPDATE 도 자동으로 취소되었습니다.")
print("=" * 56)

conn.close()
```

### Step 3. db.py 모듈 (오늘의 종합 예제)

`game/db.py` — 게임 코드가 쓸 유일한 DB 인터페이스

```python
"""게임 데이터베이스 접근 계층.

게임 코드는 이 모듈의 함수만 호출하며, SQL 을 직접 다루지 않습니다.
"""

import sqlite3
from contextlib import contextmanager
from pathlib import Path

# ══════════ 설정 ══════════
BASE_DIR = Path(__file__).resolve().parent.parent
DATA_DIR = BASE_DIR / "data"
DB_PATH = DATA_DIR / "game.db"

MAX_RANKING = 10
ALLOWED_SORT = {"score": "score", "kills": "kills", "date": "created_at"}


# ══════════ 연결 관리 ══════════

@contextmanager
def session():
    """
    DB 세션을 엽니다.

    with session() as conn:
        conn.execute(...)

    블록이 끝나면 자동 커밋, 예외가 나면 자동 롤백 후 연결을 닫습니다.
    """
    DATA_DIR.mkdir(parents=True, exist_ok=True)

    conn = sqlite3.connect(DB_PATH)
    conn.row_factory = sqlite3.Row
    conn.execute("PRAGMA foreign_keys = ON")

    try:
        yield conn
        conn.commit()
    except Exception:
        conn.rollback()
        raise
    finally:
        conn.close()

def init():
    """테이블과 인덱스를 만듭니다. 프로그램 시작 시 한 번 호출합니다."""
    with session() as conn:
        conn.execute("""
            CREATE TABLE IF NOT EXISTS scores (
                id            INTEGER PRIMARY KEY AUTOINCREMENT,
                player_name   TEXT    NOT NULL,
                score         INTEGER NOT NULL DEFAULT 0 CHECK (score >= 0),
                kills         INTEGER NOT NULL DEFAULT 0 CHECK (kills >= 0),
                max_combo     INTEGER NOT NULL DEFAULT 0,
                shots         INTEGER NOT NULL DEFAULT 0,
                hits          INTEGER NOT NULL DEFAULT 0,
                play_seconds  INTEGER NOT NULL DEFAULT 0,
                stage         INTEGER NOT NULL DEFAULT 1,
                created_at    TEXT    NOT NULL
                              DEFAULT (datetime('now','localtime'))
            )
        """)
        conn.execute("""
            CREATE TABLE IF NOT EXISTS settings (
                key    TEXT PRIMARY KEY,
                value  TEXT NOT NULL
            )
        """)
        conn.execute("CREATE INDEX IF NOT EXISTS idx_scores_score "
                     "ON scores(score DESC)")
        conn.execute("CREATE INDEX IF NOT EXISTS idx_scores_name "
                     "ON scores(player_name)")

def save_score(player_name, score, kills=0, max_combo=0,
               shots=0, hits=0, play_seconds=0, stage=1):
    """게임 기록을 저장하고 (id, 순위)를 반환합니다."""
    name = (player_name or "이름없음").strip()[:20]

    with session() as conn:
        cursor = conn.execute("""
            INSERT INTO scores
                (player_name, score, kills, max_combo,
                 shots, hits, play_seconds, stage)
            VALUES (?, ?, ?, ?, ?, ?, ?, ?)
        """, (name, max(score, 0), max(kills, 0), max(max_combo, 0),
              max(shots, 0), max(hits, 0), max(play_seconds, 0), max(stage, 1)))

        new_id = cursor.lastrowid

        rank = conn.execute(
            "SELECT COUNT(*) + 1 AS r FROM scores WHERE score > ?", (score,)
        ).fetchone()["r"]

    return new_id, rank


def get_ranking(limit=MAX_RANKING):
    """상위 기록을 딕셔너리 리스트로 반환합니다."""
    with session() as conn:
        rows = conn.execute("""
            SELECT id, player_name, score, kills, stage, created_at,
                   CASE WHEN shots > 0 THEN hits * 100.0 / shots ELSE 0 END
                   AS accuracy
            FROM scores
            ORDER BY score DESC, kills DESC
            LIMIT ?
        """, (limit,)).fetchall()

    return [dict(r) for r in rows]


def is_new_record(score, top_n=MAX_RANKING):
    """랭킹에 들어갈 점수인지 확인합니다."""
    with session() as conn:
        count = conn.execute("SELECT COUNT(*) AS c FROM scores").fetchone()["c"]
        if count < top_n:
            return True

        row = conn.execute(
            "SELECT score FROM scores ORDER BY score DESC LIMIT 1 OFFSET ?",
            (top_n - 1,),
        ).fetchone()

    return row is None or score > row["score"]


def get_player_best(player_name):
    """플레이어의 최고 기록을 반환합니다. 없으면 None."""
    with session() as conn:
        row = conn.execute("""
            SELECT * FROM scores WHERE player_name = ?
            ORDER BY score DESC LIMIT 1
        """, (player_name,)).fetchone()

    return dict(row) if row else None


def get_stats():
    """전체 통계를 반환합니다."""
    with session() as conn:
        row = conn.execute("""
            SELECT COUNT(*)                    AS games,
                   COUNT(DISTINCT player_name) AS players,
                   COALESCE(SUM(kills), 0)     AS total_kills,
                   COALESCE(MAX(score), 0)     AS best_score,
                   COALESCE(ROUND(AVG(score)), 0) AS avg_score
            FROM scores
        """).fetchone()

    return dict(row)

def rename_player(old_name, new_name):
    """플레이어 이름을 일괄 변경합니다. 변경 건수를 반환합니다."""
    new_name = (new_name or "").strip()[:20]
    if not new_name:
        return 0

    with session() as conn:
        cursor = conn.execute(
            "UPDATE scores SET player_name = ? WHERE player_name = ?",
            (new_name, old_name),
        )
        return cursor.rowcount


def delete_score(record_id):
    """기록 하나를 삭제합니다. 성공하면 True."""
    with session() as conn:
        cursor = conn.execute("DELETE FROM scores WHERE id = ?", (record_id,))
        return cursor.rowcount > 0


def clear_all(confirm=False):
    """⚠️ 모든 기록을 삭제합니다. confirm=True 필수."""
    if not confirm:
        raise ValueError("clear_all(confirm=True) 로 호출해야 합니다")

    with session() as conn:
        cursor = conn.execute("DELETE FROM scores")
        return cursor.rowcount

def get_setting(key, default=None):
    """설정값을 문자열로 반환합니다."""
    with session() as conn:
        row = conn.execute(
            "SELECT value FROM settings WHERE key = ?", (key,)
        ).fetchone()

    return row["value"] if row else default


def set_setting(key, value):
    """설정값을 저장합니다. 있으면 수정, 없으면 삽입합니다."""
    with session() as conn:
        conn.execute("""
            INSERT INTO settings (key, value) VALUES (?, ?)
            ON CONFLICT(key) DO UPDATE SET value = excluded.value
        """, (key, str(value)))


def get_setting_float(key, default=0.0):
    """설정값을 실수로 반환합니다."""
    try:
        return float(get_setting(key, default))
    except (TypeError, ValueError):
        return default
```

> **눈여겨볼 점 6가지**

> - **모든 함수가 딕셔너리를 반환**합니다. `sqlite3.Row` 를 그대로 반환하면 게임 코드가 sqlite3 에 의존하게 됩니다.

> - `ON CONFLICT DO UPDATE` 로 UPSERT 를 구현했습니다.

## ⑤ 자주 하는 실수

### `WHERE` 를 빠뜨림

```python
conn.execute("DELETE FROM scores")           # 전체 삭제!
conn.execute("UPDATE scores SET score = 0")  # 전체 초기화!
```

**해결** — 습관을 만드세요.

```
1. WHERE 를 먼저 쓴다:  DELETE FROM scores WHERE
2. 조건을 채운다:       DELETE FROM scores WHERE id = ?
3. SELECT 로 확인한다:  SELECT * FROM scores WHERE id = ?
4. 그다음 실행한다
```

### 삭제 전에 확인하지 않음

**해결** — 항상 `SELECT COUNT(*)` 로 대상 건수를 먼저 봅니다.

### `commit()` 없이 `close()`

```python
conn.execute("UPDATE ...")
conn.close()                 # 변경이 사라짐
```

**해결** — `with conn:` 을 쓰세요.

### 트랜잭션 중간에 `commit()`

```python
conn.execute("UPDATE accounts SET balance = balance - 1000 WHERE id = 1")
conn.commit()                # ← 여기서 확정되어 롤백 불가
conn.execute("UPDATE accounts SET balance = balance + 1000 WHERE id = 2")
conn.commit()
```

**해결** — 한 덩어리로 처리할 작업은 **마지막에 한 번만** 커밋합니다.

### `rowcount` 를 확인하지 않음

```python
conn.execute("UPDATE scores SET score = ? WHERE id = ?", (100, 9999))
# 9999번이 없어도 조용히 넘어감
```

**해결** — `cursor.rowcount == 0` 이면 대상이 없었다는 뜻입니다.

### `INSERT OR REPLACE` 로 일부만 수정하려 함

```sql
INSERT OR REPLACE INTO settings (key, value) VALUES ('volume', '0.8');
-- updated_at 등 다른 열이 기본값으로 초기화됨
```

**해결** — `ON CONFLICT(key) DO UPDATE SET value = excluded.value`

### 게임 코드에 SQL 을 직접 씀

```python
# scenes/gameover.py
conn = sqlite3.connect("game.db")
conn.execute("INSERT INTO scores ...")
```

**해결** — `db.save_score(...)` 를 호출합니다. SQL 은 `db.py` 에만.

### 예외 처리 없이 DB 함수를 호출

```python
db.save_score(name, score)     # 디스크가 가득 차면?
```

**해결** — 중요한 지점에서는 예외를 처리합니다.

**문제 ① SQL 인젝션**

`name` 이 f-string 으로 삽입됩니다. `' OR '1'='1` 을 넣으면 전체가 초기화됩니다.

**문제 ② 의도치 않은 대량 삭제**

`DELETE FROM scores WHERE score = 0` 은 **원래부터 0점이던 다른 사람의 기록도 삭제**합니다.
이 함수는 특정 플레이어만 처리해야 하는데, 전체를 건드립니다.

**문제 ③ 트랜잭션이 부적절**

두 작업이 한 덩어리여야 하는데, 중간에 예외가 나면 첫 번째만 적용된 상태가 됩니다.
(여기서는 `commit()` 이 마지막에 한 번이라 어느 정도 보호되지만, 예외 시 롤백이 없습니다)

**개선**

```python
import sqlite3


def reset_player(conn, name, confirm=False):
    """
    특정 플레이어의 기록을 전부 삭제합니다.

    반환: 삭제된 건수
    """
    if not name or not name.strip():
        raise ValueError("이름이 비어 있습니다")

    name = name.strip()

    # ① 대상 확인
    count = conn.execute(
        "SELECT COUNT(*) AS c FROM scores WHERE player_name = ?", (name,)
    ).fetchone()[0]

    if count == 0:
        print(f"[안내] '{name}' 기록이 없습니다.")
        return 0

    print(f"[확인] '{name}' 의 기록 {count}건이 삭제됩니다.")

    if not confirm:
        print("  → confirm=True 로 호출해야 실제로 삭제됩니다.")
        return 0

    # ② 트랜잭션으로 한 번에
    try:
        with conn:
            cursor = conn.execute(
                "DELETE FROM scores WHERE player_name = ?", (name,)
            )
            deleted = cursor.rowcount

        print(f"[완료] {deleted}건 삭제")
        return deleted

    except sqlite3.Error as e:
        print(f"[오류] 삭제 실패 (롤백됨): {e}")
        return 0
```

**개선한 것 5가지**
- 파라미터 바인딩 `?` 사용
- **두 단계 작업을 한 단계로** 정리 (0으로 만들고 지울 이유가 없음)
- 삭제 전 대상 건수 확인 + `confirm` 안전장치
- `with conn:` 으로 자동 커밋/롤백
- `rowcount` 로 실제 삭제 건수 반환

> **원래 코드의 진짜 문제** — "점수를 0으로 만든 뒤 0점을 지운다" 는 **우회적인 방법**입니다.
> 직접 `DELETE ... WHERE player_name = ?` 하면 됩니다.
> **의도를 그대로 표현하는 코드**가 안전하고 읽기도 좋습니다.

```python
"""도서 대출 — 트랜잭션으로 안전하게 처리."""

import sqlite3
from contextlib import contextmanager
from pathlib import Path

DB_PATH = Path(__file__).resolve().parent / "library.db"
MAX_LOANS_PER_MEMBER = 3
LOAN_DAYS = 14


class LoanError(Exception):
    """대출 실패를 나타내는 예외."""
    pass


@contextmanager
def session():
    conn = sqlite3.connect(DB_PATH)
    conn.row_factory = sqlite3.Row
    conn.execute("PRAGMA foreign_keys = ON")
    try:
        yield conn
        conn.commit()
    except Exception:
        conn.rollback()
        raise
    finally:
        conn.close()


def borrow_book(book_id, member_id):
    """
    책을 대출합니다.

    반환: 대출 id
    예외: LoanError (사유를 메시지에 담음)
    """
    with session() as conn:
        # ── ① 책이 존재하는가 ──
        book = conn.execute(
            "SELECT id, title FROM books WHERE id = ?", (book_id,)
        ).fetchone()

        if book is None:
            raise LoanError(f"#{book_id} 도서를 찾을 수 없습니다")

        # ── ② 회원이 존재하는가 ──
        member = conn.execute(
            "SELECT id, name FROM members WHERE id = ?", (member_id,)
        ).fetchone()

        if member is None:
            raise LoanError(f"#{member_id} 회원을 찾을 수 없습니다")

        # ── ③ 이미 대출 중인가 ──
        active = conn.execute("""
            SELECT l.id, m.name
            FROM loans l JOIN members m ON l.member_id = m.id
            WHERE l.book_id = ? AND l.returned_at IS NULL
        """, (book_id,)).fetchone()

        if active is not None:
            raise LoanError(
                f"'{book['title']}' 은(는) {active['name']}님이 대출 중입니다"
            )

        # ── ④ 대출 한도 확인 ──
        current = conn.execute("""
            SELECT COUNT(*) AS c FROM loans
            WHERE member_id = ? AND returned_at IS NULL
        """, (member_id,)).fetchone()["c"]

        if current >= MAX_LOANS_PER_MEMBER:
            raise LoanError(
                f"{member['name']}님은 이미 {current}권을 대출 중입니다 "
                f"(최대 {MAX_LOANS_PER_MEMBER}권)"
            )

        # ── ⑤ 대출 기록 생성 ──
        cursor = conn.execute("""
            INSERT INTO loans (book_id, member_id, due_at)
            VALUES (?, ?, datetime('now', ?, 'localtime'))
        """, (book_id, member_id, f"+{LOAN_DAYS} days"))

        loan_id = cursor.lastrowid

    print(f"[대출] '{book['title']}' → {member['name']}님 "
          f"(#{loan_id}, {LOAN_DAYS}일)")
    return loan_id


def return_book(loan_id):
    """책을 반납합니다."""
    with session() as conn:
        loan = conn.execute("""
            SELECT l.id, l.returned_at, b.title, m.name
            FROM loans l
            JOIN books b   ON l.book_id = b.id
            JOIN members m ON l.member_id = m.id
            WHERE l.id = ?
        """, (loan_id,)).fetchone()

        if loan is None:
            raise LoanError(f"#{loan_id} 대출 기록이 없습니다")

        if loan["returned_at"] is not None:
            raise LoanError(f"이미 {loan['returned_at']} 에 반납되었습니다")

        conn.execute("""
            UPDATE loans SET returned_at = datetime('now','localtime')
            WHERE id = ?
        """, (loan_id,))

    print(f"[반납] '{loan['title']}' ← {loan['name']}님")
    return True


if __name__ == "__main__":
    tests = [
        ("정상 대출", 1, 1),
        ("같은 책 중복 대출", 1, 2),
        ("없는 책", 999, 1),
        ("없는 회원", 2, 999),
    ]

    for label, book_id, member_id in tests:
        print(f"\n[{label}] 도서 #{book_id} → 회원 #{member_id}")
        try:
            borrow_book(book_id, member_id)
        except LoanError as e:
            print(f"  ✗ {e}")
```

**포인트 6가지**
- **모든 검증이 하나의 트랜잭션 안**에 있습니다. 검증과 삽입 사이에 다른 사람이 끼어들 수 없습니다.
- 검증 실패 시 `raise LoanError(...)` — **예외로 사유를 전달**합니다. `False` 만 반환하면 왜 실패했는지 모릅니다.
- **가드 절 구조**입니다. 잘못된 경우를 하나씩 걸러 내고, 통과하면 마지막에 실행합니다. ([Day 030](day-030.md))
- `returned_at IS NULL` 로 "대출 중"을 판정합니다. 별도 플래그 열이 필요 없습니다.
- 예외가 나면 `session()` 이 자동으로 롤백합니다.
- 사용자 정의 예외(`LoanError`)로 **DB 에러와 업무 규칙 위반을 구분**합니다.

**문제 5가지**

| # | 문제 | 위험 |
|---|---|---|
| 1 | SQL 인젝션 (f-string) | 이름에 `'` 가 있으면 에러, 악의적 입력 시 데이터 손상 |
| 2 | `conn.close()` 없음 | 연결 누수. 반복 호출 시 파일 잠김 |
| 3 | 예외 처리 없음 | 실패하면 게임이 그대로 죽음 |
| 4 | 예외 시 롤백 없음 | 점수만 저장되고 설정은 안 되는 상태 |
| 5 | 상대 경로 `"game.db"` | 실행 위치에 따라 다른 파일을 봄 |

**추가 문제**
- 값 검증이 없음 (음수 점수, 빈 이름)
- `INSERT OR REPLACE` 로 설정의 다른 열이 초기화될 수 있음

**개선**

```python
"""게임 결과 저장."""

import logging
import sqlite3
from contextlib import contextmanager
from pathlib import Path

DB_PATH = Path(__file__).resolve().parent / "data" / "game.db"

logger = logging.getLogger(__name__)


@contextmanager
def session():
    """자동 커밋/롤백/닫기를 처리하는 DB 세션."""
    DB_PATH.parent.mkdir(parents=True, exist_ok=True)

    conn = sqlite3.connect(DB_PATH)
    conn.row_factory = sqlite3.Row
    try:
        yield conn
        conn.commit()
    except Exception:
        conn.rollback()
        raise
    finally:
        conn.close()


def save_game_result(name, score, kills, settings=None):
    """
    게임 결과와 설정을 한 트랜잭션으로 저장합니다.

    반환: (성공 여부, 기록 id 또는 None)
    """
    # ── 입력 검증 ──
    name = (name or "이름없음").strip()[:20] or "이름없음"
    score = max(int(score), 0)
    kills = max(int(kills), 0)
    settings = settings or {}

    try:
        with session() as conn:                      # 하나의 트랜잭션
            cursor = conn.execute(
                "INSERT INTO scores (player_name, score, kills) "
                "VALUES (?, ?, ?)",
                (name, score, kills),                # ← 파라미터 바인딩
            )
            record_id = cursor.lastrowid

            for key, value in settings.items():
                conn.execute("""
                    INSERT INTO settings (key, value) VALUES (?, ?)
                    ON CONFLICT(key) DO UPDATE SET value = excluded.value
                """, (str(key), str(value)))

        logger.info(f"기록 저장 완료: #{record_id} {name} {score:,}점")
        return True, record_id

    except sqlite3.Error as e:
        logger.error(f"기록 저장 실패 (롤백됨): {e}")
        return False, None

    except Exception as e:
        logger.exception(f"예상치 못한 오류: {e}")
        return False, None


# ── 호출하는 쪽 ──
if __name__ == "__main__":
    logging.basicConfig(level=logging.INFO,
                        format="%(levelname)s: %(message)s")

    ok, record_id = save_game_result(
        name="홍길동' OR '1'='1",          # 공격 시도 — 그냥 이름으로 저장됨
        score=15000,
        kills=152,
        settings={"volume": 0.7, "difficulty": "hard"},
    )

    if ok:
        print(f"저장 성공 (#{record_id})")
    else:
        print("저장에 실패했지만 게임은 정상 종료됩니다.")
```

**개선 효과 6가지**
- **파라미터 바인딩**으로 인젝션 차단. 위험한 이름도 그냥 문자열로 저장됩니다.
- `@contextmanager` 로 **연결·커밋·롤백·닫기**를 자동 처리.
- **점수와 설정이 한 트랜잭션** — 설정 저장이 실패하면 점수도 롤백됩니다.
- 예외를 잡아 **게임이 죽지 않습니다.** 저장 실패는 로그로 남기고 게임은 정상 종료.
- 절대경로로 **어디서 실행해도 같은 DB** 를 봅니다.
- `(성공 여부, id)` 를 반환해 호출하는 쪽이 결과를 알 수 있습니다.

> **핵심 판단** — 게임 종료 시 저장 실패는 **치명적이지 않습니다.**
> 예외를 위로 던져 게임을 죽이는 것보다, 로그를 남기고 사용자에게 알린 뒤 정상 종료하는 편이 낫습니다.
>
> 반대로 **은행 이체 실패**는 반드시 예외를 던져야 합니다. 조용히 넘어가면 돈이 사라집니다.
> **"실패했을 때 무엇이 더 나쁜가"** 를 기준으로 판단하세요.

## 오늘의 정리

| 개념 | 핵심 |
|---|---|
| `UPDATE` | **`WHERE` 필수** · `rowcount` 로 확인 |
| `DELETE` | **`WHERE` 필수** · 삭제 전 `SELECT COUNT` |
| 안전장치 | `confirm=False` 기본값 · 대상 건수 먼저 확인 |
| 트랜잭션 | 전부 성공 아니면 전부 취소 |
| `with conn:` | 자동 커밋 / 예외 시 롤백 |
| UPSERT | `ON CONFLICT(key) DO UPDATE SET ...` |
| `@contextmanager` | 연결·커밋·롤백·닫기를 한 번에 |
| 접근 계층 | 게임 코드는 SQL 을 모름 · `db.py` 에만 |
| 반환 형태 | `sqlite3.Row` → `dict` 로 변환해 반환 |

**오늘 반드시 기억할 세 가지**
> ① `DELETE` / `UPDATE` 는 **`WHERE` 를 먼저 쓰고** 조건을 채우세요.
> ② 삭제 전에 **`SELECT COUNT(*)` 로 대상 건수를 확인**하세요.
> ③ 게임 코드에 SQL 을 쓰지 마세요. **`db.py` 함수만 호출**합니다.

**과제** — `db.py` 에 아래를 추가하세요.
① `soft_delete(record_id)` — 논리 삭제 (`deleted_at` 열 추가)
② `restore(record_id)` — 복구 ③ `export_csv(path)` — 전체 기록을 CSV 로 내보내기
