## 3. 개념

### 3-1. 구조체 배열로 다수 관리

**왜 필요한가** — Day 5, Day 11에서 배운 그대로. 도구만 바뀌었다.

```cpp
#define MAX_STARS 1000

struct Star
{
    double x, y;
    double speed;              // 초당 픽셀
    int    size;               // 반지름
    COLORREF color;
};

Star g_stars[MAX_STARS];
int  g_starCount = 200;
```

```cpp
void InitStars(int clientW, int clientH)
{
    for (int i = 0; i < MAX_STARS; i++)
    {
        g_stars[i].x     = rand() % clientW;
        g_stars[i].y     = rand() % clientH;
        g_stars[i].speed = 20.0 + rand() % 180;      // 20~200 px/s

        // 빠를수록 크고 밝게 (깊이감)
        double t = (g_stars[i].speed - 20.0) / 180.0;   // 0.0 ~ 1.0

        g_stars[i].size  = 1 + (int)(t * 3);            // 1~4
        int bright = 100 + (int)(t * 155);              // 100~255
        g_stars[i].color = RGB(bright, bright, bright);
    }
}
```

```
   깊이감(parallax)의 원리

   가까운 별  →  빠르게, 크게, 밝게
   먼 별      →  느리게, 작게, 어둡게

   ★ 실제로는 평면인데 입체적으로 보인다
   ★ Day 54(슈팅 배경), Day 92(레이싱)에서 다시 쓴다
```

### 3-2. 갱신과 그리기 분리

**왜 필요한가** — Day 21에서 배운 원칙. WINAPI에서도 똑같이 지킨다.

```cpp
// ── Update: 상태만 바꾼다 ──
void UpdateStars(double dt, int clientW, int clientH)
{
    for (int i = 0; i < g_starCount; i++)
    {
        g_stars[i].x += g_stars[i].speed * dt;

        if (g_stars[i].x > clientW + 5)
        {
            g_stars[i].x = -5;
            g_stars[i].y = rand() % clientH;
        }
    }
    // ★ 여기에 그리기 코드가 없다
}

// ── Render: 그리기만 한다 ──
void RenderStars(HDC hdc)
{
    for (int i = 0; i < g_starCount; i++)
    {
        const Star& s = g_stars[i];
        int x = (int)s.x;
        int y = (int)s.y;

        if (s.size <= 1)
        {
            SetPixel(hdc, x, y, s.color);
        }
        else
        {
            HBRUSH b  = CreateSolidBrush(s.color);
            HBRUSH ob = (HBRUSH)SelectObject(hdc, b);
            HPEN   op = (HPEN)SelectObject(hdc, GetStockObject(NULL_PEN));

            Ellipse(hdc, x - s.size, y - s.size, x + s.size, y + s.size);

            SelectObject(hdc, op);
            SelectObject(hdc, ob);
            DeleteObject(b);
        }
    }
    // ★ 여기서 상태를 안 바꾼다
}
```

> ### ⚠️ 위 `RenderStars`에는 성능 문제가 있다
>
> **별 하나마다 브러시를 만들고 지운다.** 200개면 프레임당 200번이다.
>
> ```cpp
> // ✔ 색이 같은 것끼리 묶거나, 브러시를 미리 만들어 둔다
> HBRUSH g_starBrush[8];              // 밝기 8단계
>
> void CreateStarBrushes()
> {
>     for (int i = 0; i < 8; i++)
>     {
>         int b = 100 + i * 22;
>         g_starBrush[i] = CreateSolidBrush(RGB(b, b, b));
>     }
> }
> ```
>
> **GDI 오브젝트 생성은 비싸다.** 미리 만들어 두고 재사용한다.
> 이 발상이 **Day 41의 이미지 매니저**, **Day 52의 오브젝트 풀링**으로 이어진다.

### 3-3. FPS 측정 (WINAPI 버전)

**왜 필요한가** — 깜빡임 정도와 성능을 수치로 기록해야 비교할 수 있다.

```cpp
int    g_frameCount = 0;
double g_fpsTimer   = 0.0;
double g_fps        = 0.0;

    // WM_TIMER 안 (갱신 후)
    g_frameCount++;
    g_fpsTimer += dt;

    if (g_fpsTimer >= 1.0)
    {
        g_fps = g_frameCount / g_fpsTimer;
        g_frameCount = 0;
        g_fpsTimer = 0.0;
    }
```

> **`WM_TIMER` 방식에서는 FPS가 60을 넘지 못한다.** 타이머 해상도 때문이다.
> **Day 38의 게임 루프로 바꾸면 수백 FPS가 나온다.**

### 3-4. 깜빡임(flickering)의 관찰

**왜 필요한가** — 내일 원인을 규명하기 전에, 현상을 정확히 기술한다.

**언제 심해지는가**

| 조건 | 깜빡임 |
|---|---|
| 별 10개 | 거의 안 보임 |
| 별 100개 | 눈에 띔 |
| **별 500개** | **심각** |
| 배경을 어둡게 | 심해 보임 (대비가 커서) |
| 창을 크게 | 심해짐 |
| 그리는 시간이 길어짐 | 심해짐 |

**무엇이 보이는가**

```
   프레임을 아주 느리게(타이머 500ms) 하면 정체가 보인다

   시각 0ms     화면:  [별들이 그려진 상태]
   시각 1ms     화면:  [전부 흰색/배경색]      ← ★ 이 순간
   시각 5ms     화면:  [별들이 그려진 상태]
   시각 500ms   화면:  [전부 흰색]             ← 다시
   ...

   ★ "배경만 있는 빈 화면"이 매 프레임 잠깐씩 보인다
     그것이 깜빡임의 정체다
```

**의도적으로 느리게 만들어 확인하기**

```cpp
    SetTimer(hWnd, TIMER_MAIN, 500, NULL);      // 0.5초 간격
```

```
   →  화면이 "빈 화면 → 별 화면 → 빈 화면 → 별 화면" 으로
      느리게 번갈아 보인다

   ★ 60fps에서는 이게 너무 빨라서 "깜빡임"으로 느껴지는 것이다
```

### 3-5. 원인 가설 세우기

**왜 필요한가** — 내일 답을 배우기 전에 스스로 추론해 본다.

```
   관찰 사실

   ① 그릴 것이 많을수록 심하다
   ② 매 프레임 "빈 화면"이 잠깐 보인다
   ③ bErase=FALSE 로 하면 깜빡임은 없지만 잔상이 남는다
```

```
   ★ ③이 결정적인 단서다

     bErase=TRUE   →  누군가 배경을 지운다  →  깜빡인다
     bErase=FALSE  →  아무도 안 지운다      →  깜빡임 없음, 잔상

     → "배경을 지우는 행위"가 깜빡임의 원인이다
```

```
   그럼 왜 지우는 게 문제인가?

   지움  ──▶  (빈 화면)  ──▶  그림 완성
              ▲
              └── 이 상태가 사용자 눈에 "보인다"

   그리는 시간이 길수록 (=별이 많을수록) 이 구간이 길어진다
   → 더 심하게 깜빡인다  ✔ 관찰 ①과 일치
```

> **여기까지 스스로 추론했다면 내일의 절반은 이미 이해한 것이다.**
> 남은 질문은 하나다. **"그럼 어떻게 해야 하나?"**

**힌트 — 화가는 어떻게 하는가**

```
   ✘ 관객 앞에서 캔버스를 지우고 처음부터 그린다
      → 관객이 빈 캔버스를 본다

   ✔ 무대 뒤에서 다 그리고, 완성된 것만 무대에 올린다
      → 관객은 완성본만 본다
```

**✅ 여기까지 실행하면** — F2로 0.5초 간격으로 바꾸면 **깜빡임의 정체가 눈으로 보인다.**

```
   빈 화면  →  별 화면  →  빈 화면  →  별 화면  →  ...
     ▲
     └── 60fps에서는 이게 너무 빨라 "깜빡임"으로 느껴진다
```

### Step 8 — 그리기 시간 측정

```cpp
double g_renderTimeMs = 0.0;

    case WM_PAINT:
        {
            LARGE_INTEGER freq, t1, t2;
            QueryPerformanceFrequency(&freq);
            QueryPerformanceCounter(&t1);

            PAINTSTRUCT ps;
            HDC hdc = BeginPaint(hWnd, &ps);

            RenderStars(hdc);
            RenderUI(hdc);

            EndPaint(hWnd, &ps);

            QueryPerformanceCounter(&t2);
            g_renderTimeMs = (t2.QuadPart - t1.QuadPart) * 1000.0 / freq.QuadPart;
        }
        return 0;
```

UI에 추가:

```cpp
    sprintf_s(buf, "그리기 시간 %.2f ms", g_renderTimeMs);
```

**✅ 여기까지 실행하면** — 별 개수에 따른 그리기 시간이 보인다.

```
   별   50개  →  약 0.8 ms
   별  200개  →  약 3.2 ms
   별  500개  →  약 8.5 ms
   별 1000개  →  약 17 ms       ← 16.7ms(60fps)를 넘어섰다
```

> **"빈 화면 구간"의 길이가 곧 이 그리기 시간이다.**
> 관찰 ①(많을수록 심하다)의 수치적 근거를 확보했다.

> `QueryPerformanceCounter` — **Day 38에서 게임 루프의 정밀 타이머로 쓴다.**

### Step 9 — 브러시 재사용 (성능 개선)

```cpp
#define BRUSH_LEVELS 8

HBRUSH g_starBrush[BRUSH_LEVELS];

void CreateStarBrushes()
{
    for (int i = 0; i < BRUSH_LEVELS; i++)
    {
        int b = 100 + i * 22;
        g_starBrush[i] = CreateSolidBrush(RGB(b, b, b));
    }
}

void DestroyStarBrushes()
{
    for (int i = 0; i < BRUSH_LEVELS; i++)
        DeleteObject(g_starBrush[i]);
}
```

```cpp
void RenderStars(HDC hdc)
{
    HPEN oldPen = (HPEN)SelectObject(hdc, GetStockObject(NULL_PEN));

    for (int i = 0; i < g_starCount; i++)
    {
        const Star& s = g_stars[i];
        int x = (int)s.x, y = (int)s.y;

        if (s.size <= 1)
        {
            SetPixel(hdc, x, y, s.color);
        }
        else
        {
            int level = (s.color & 0xFF) / 32;                  // 0~7
            if (level >= BRUSH_LEVELS) level = BRUSH_LEVELS - 1;

            HBRUSH ob = (HBRUSH)SelectObject(hdc, g_starBrush[level]);
            Ellipse(hdc, x - s.size, y - s.size, x + s.size, y + s.size);
            SelectObject(hdc, ob);
        }
    }

    SelectObject(hdc, oldPen);
}
```

**✅ 여기까지 실행하면** — 그리기 시간이 눈에 띄게 줄어든다.

```
   별 500개:  8.5 ms  →  3.1 ms      (약 3배)
```

> **하지만 깜빡임은 여전하다.** 줄어들 뿐 사라지지 않는다.
> **최적화로는 해결되지 않는 문제**임을 확인한다.

## 6. 자주 막히는 곳

| 증상 | 원인 | 해결 |
|---|---|---|
| 별이 안 보임 | 배경색과 별색이 같음 | 배경을 검정으로 |
| 별이 한 줄로 뭉침 | 초기 y가 전부 같음 | `rand() % clientH` |
| 별이 안 움직임 | `InvalidateRect` 누락 | 추가 |
| 별 개수를 늘려도 안 늘어남 | `g_starCount`만 늘리고 초기화 안 함 | `MAX_STARS`만큼 미리 초기화 |
| 심하게 느림 | 별마다 브러시 생성 | 브러시 재사용 (Step 9) |
| GDI 개체 증가 | `DeleteObject` 누락 | 확인 |
| 창 크기 변경 후 별이 화면 밖 | `g_clientW/H` 미갱신 | `WM_SIZE`에서 갱신 |
| **깜빡임** | 정상 | **Day 37에서 해결** |
| 잔상 | `bErase=FALSE`의 정상 결과 | **Day 37에서 해결** |
| `QueryPerformanceCounter` 오류 | `LARGE_INTEGER` 선언 | `<windows.h>` 포함 확인 |

## 7. 정리

### 오늘 배운 것

| 개념 | 한 줄 요약 |
|---|---|
| 구조체 배열 | 다수 오브젝트 관리. Day 5·11과 같은 방식 |
| 깊이감(parallax) | 빠를수록 크고 밝게 → 입체감 |
| Update/Render 분리 | WINAPI에서도 같은 원칙 |
| GDI 오브젝트 재사용 | 매번 만들지 말고 미리 만들어 둔다 |
| 그리기 시간 측정 | `QueryPerformanceCounter` |
| **깜빡임 관찰** | 그릴 것이 많을수록 심하다 |
| **`bErase` 딜레마** | `TRUE`=깜빡임, `FALSE`=잔상. **둘 다 못 쓴다** |
| **원인 가설** | "배경을 지우는 과정이 사용자에게 보인다" |

### 오늘 확보한 관찰 사실 (내일의 근거)

```
   ① 그릴 것이 많을수록 깜빡임이 심하다
   ② 매 프레임 "배경만 있는 빈 화면"이 잠깐 보인다
   ③ 배경을 안 지우면 깜빡임이 사라진다 (대신 잔상)
   ④ 그리기를 최적화해도 깜빡임 자체는 안 없어진다
```
