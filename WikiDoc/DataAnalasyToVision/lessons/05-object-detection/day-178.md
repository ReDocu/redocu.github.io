```

  [1] 작성자를 정한다        (예: C 가 README 작성)
  [2] 검증자를 정한다        (예: A — README 를 안 본 사람)
```

````markdown
## 문제 · 주요 기능 · 시스템 구성 · 기술 스택

**문제** — 창고 출입구는 안전모 착용이 의무이지만 관리자가 상주할 수 없고,
기존 CCTV 는 **녹화만** 합니다. 사고가 난 **뒤에야** 봅니다. 필요한 것은
**"사고 전 알림"** 이고 영상이 **외부로 나가지 않아야** 합니다.

**기능** — 🎥 실시간 검출 9.2 FPS · 🚨 3초 체류 판정 · 📸 스냅샷(30일 자동 삭제) ·
📨 텔레그램 알림(60초 쿨다운) · 🌐 웹 대시보드 · 📤 업로드 검출 ·
🔌 오프라인 내성(아웃박스 큐) · 🔁 자동 복구

```
[현장 2.8m·하향 20°] Pi Camera v3 → 라즈베리파이 5 (8GB)
   ① NCNN 640 검출 9.2 FPS  ② 이벤트 판정 3초 체류·60초 쿨다운
   ③ 로컬 SQLite(서버 없이도 동작)  ④ 텔레그램 알림 3.4초  ⑤ 아웃박스 큐
                    │  event(JSON) + snapshot(JPEG)
                    │  HTTP POST multipart · ★ 멱등 · 지수 백오프
                    ▼
[서버 · 같은 LAN] Flask 3.0 + waitress  POST /api/events

**아웃박스 큐** = 전송에 실패한 이벤트를 파이의 SQLite 에 쌓아 두고 나중에
````

````markdown
   → 완화: 야간에는 `dwell` 3 → 5초 (오탐 절반) / 개선: 야간 60장 추가(4시간)
2. ★ **"손에 든 안전모"를 착용으로 오판정** — 22건 중 6건.
   모델이 아니라 **이벤트 규칙의 한계**입니다.
   → helmet 중심이 person 박스 **상단 25%** 안에 있을 때만 착용으로 (1시간)
3. **원거리에서 helmet 을 놓칩니다** — 5~7m Recall **0.612**, 640 에서 20px 이하.
   → ROI 를 출입구 3m 이내로 제한 / `imgsz` 960 은 mAP +0.04 지만 ★ FPS 9.2→4.1
4. **단일 장소 학습** — 창고 1곳. 다른 장소·각도는 **미측정**입니다.
   유사 사례상 장소가 바뀌면 mAP 0.3~0.5 하락합니다.
5. ★ **모델 자체는 "미착용"을 모릅니다.** `helmet` 이 검출되지 않은 것과
   "안전모를 안 썼다"는 다릅니다. 검출 실패와 실제 미착용을 모델은 구분하지 못하며
   `dwell 3초` 조건이 이를 **통계적으로 완화할 뿐**입니다.
6. **가림에 약합니다** — 2명 이상 mAP **0.774**. 라벨링 규칙상 60% 이상 가려진
   객체를 제외해 모델도 학습하지 못했습니다.
7. **안전모 색상 2종만 학습** — 흰·노랑. 파랑·빨강 성능은 **모릅니다.**
8. **box 클래스가 약합니다** — AP 0.762. 크기·형태·적재 상태가 다양했습니다.
   이벤트 판정에 쓰이지 않아 우선순위를 낮췄습니다.
9. **소형 person 미검출** — 20m 이상은 검증하지 않았습니다(화각 밖).
````

#### 6-3. 주석 — 좋은 주석과 나쁜 주석

주석의 기준은 한 줄입니다. 코드는 **"무엇을 하는가"** 를 이미 말하고 있으니,
주석은 **"왜 그렇게 했는가"** 만 말해야 합니다.

| 유형 | 예 | 판정 |
|---|---|---|
| 코드 반복 · 자명한 설명 | `i += 1  # i 를 1 증가` | ✗ 삭제 |
| 죽은 코드 · 이력 | `# conf = 0.45` · `# 2026-02-05 B 수정` | ✗ 삭제 (git 이 합니다) |
| 거짓말 | `# 기본 0.45` 인데 코드는 `0.35` | ✗✗ **가장 나쁨** |
| **왜** | `# NCNN 은 BGR 입력 · cvtColor 하면 mAP 0.13 하락` | ✓ |
| **근거** | `# 3초 — Day 176 실측 오탐 12건→2건` | ✓ |
| **함정 경고** | `# seek(0) 없으면 빈 파일이 저장됩니다` | ✓ |
| **의도적 예외** | `# noqa: E501 — 로그 포맷을 한 줄로 유지` | ✓ |

**★ 실제로 고친 예 2개**

```python
# ✗ 이전 — 주석 3개가 전부 코드를 그대로 옮긴 것
def parse(det):
    x1, y1, x2, y2 = det[:4]      # 좌표를 꺼낸다
    cx = (x1 + x2) / 2            # 중심 x
    cy = (y1 + y2) / 2            # 중심 y
    return cx, cy

# ✓ 이후 — 주석이 1개로 줄고, 그 1개가 코드에 없는 정보를 말합니다
def parse(det):
    x1, y1, x2, y2 = det[:4]
    # 중심점으로 비교하는 이유: IoU 는 helmet 이 person 안에 있을 때 늘 낮게 나옵니다
    # (helmet 면적이 person 의 3% 수준) → 포함 판정은 중심점으로 합니다
    return (x1 + x2) / 2, (y1 + y2) / 2
```

````markdown
### 3.1 사람이 지나갔는데 "box 감지" 라고 표시됨

```
파이 로그   det: class_id=0 conf=0.87 xyxy=(412,198,566,690)
웹 화면     [box 0.87]          ← ★ 이름만 틀림
텔레그램    "상자 감지 1건"      ← 여기도

**② 가설** ① 모델이 잘못 학습됐다(person 을 box 로 배움) ② 파이와 웹이 서로 다른

**③ 확인**

# 가설 1 배제 — 같은 이미지를 PC 에서 직접 추론
$ python -c "from ultralytics import YOLO; m=YOLO('models/best.pt'); print(m.names)"
{0: 'person', 1: 'helmet', 2: 'box'}          # 모델은 정상

# 가설 2 배제 — 체크섬 대조
$ sha256sum models/best.pt        # 9f2c41ab...
$ ssh pi 'sha256sum ~/safegate/models/best.pt'   # 9f2c41ab...  동일

# 가설 3 — 웹 코드를 grep
$ grep -rn "CLASS_LABELS" web/
web/routes/detect.py:22:CLASS_LABELS = ['box', 'helmet', 'person']
```

**④ 원인**

웹 담당이 [Day 174](day-174.md) 에 **클래스 목록을 알파벳 순으로 정렬해서** 하드코딩했습니다.

```
data.yaml   {0: person, 1: helmet, 2: box}
웹 코드     ['box',   'helmet', 'person']      ★ 0번이 서로 다름

모델이 class_id=0(person) → 웹은 CLASS_LABELS[0] = 'box'
인덱스가 유효하므로 예외가 안 납니다. 이름만 조용히 틀립니다.
```

**⑤ 해결** — 이름의 출처를 **하나로** 만들었습니다.

```python
# ✗ 각자 목록을 들고 있음
CLASS_LABELS = ['box', 'helmet', 'person']
name = CLASS_LABELS[det["class_id"]]

# ✓ 검출기가 이름까지 넣어서 반환 · 소비자는 이름만 사용
det = {"name": model.names[cls_id], "conf": conf, "xyxy": xyxy}
name = det["name"]
```

**가중치의 `names` 와 `data_v2.yaml` 의 `names` 가 같은지**를 CI 에서 확인합니다.

**⑥ 배운 것**

★ **예외가 안 나는 버그가 가장 늦게 발견됩니다.** 이 버그는 발표장에서 심사위원이
발견했을 수도 있는 종류입니다. 그래서 규칙으로 만들었습니다 —
**"class_id 는 경계를 넘지 않는다."** 검출기 밖으로는 이름만 나가고, ID→이름 변환은

### 3.4 화면이 3초 늦게 움직임

**① 증상**

[Day 163](day-163.md) 스트리밍을 붙이자 화면 앞에서 손을 흔들면
**3초 뒤에 화면에서 손이 흔들립니다.** 손을 멈춰도 **3초 동안 계속 흔듭니다.**

```
지연 실측 (스톱워치를 카메라에 비추고 화면과 차이를 측정)
  평균 2.8 s · 최대 5.9 s · ★ 시간이 갈수록 커짐
```

**② 가설** ① 추론이 느리다(68ms → 이 정도로 밀릴 리 없음) ② 네트워크가 느리다
③ 시간이 갈수록 커진다 = 어딘가에 쌓이고 있다

**③ 확인** — 각 구간에 시각을 찍어 봤습니다
(`cap.read()` / `detect()` / `cv2.imencode()` 앞뒤로 `time.time()`).

```
read()     3ms      ← 빠릅니다. 이미 준비된 프레임을 꺼내니까요
detect   68ms
encode    9ms
        ────────
합계     80ms = 12.5 FPS   ★ 코드는 빠릅니다. 그런데 화면은 3초 늦습니다
```

★ **처리 속도가 아니라 "언제 찍힌 프레임인가" 가 문제였습니다.**

**④ 원인**

카메라는 30 FPS 로 계속 찍어 **드라이버 버퍼에 넣습니다.**
우리는 80ms 마다 = **12.5 FPS 로 꺼냅니다.** 초당 17.5장씩 **쌓입니다.**

```
카메라 30 FPS ──┐
                ▼
        ┌───────────────────┐
        │ 드라이버 내부 버퍼 │  ← ★ 여기가 계속 찹니다
        └───────┬───────────┘
                ▼
          read() 12.5 FPS      ← 꺼내는 것은 항상 "가장 오래된" 프레임
```

**⑤ 해결** — 버퍼를 줄이는 것으로는 부족했습니다.
`cap.set(CAP_PROP_BUFFERSIZE, 1)` 은 **DSHOW·MSMF 백엔드가 무시**합니다.
그래서 **읽기 전용 스레드를 따로 두는 쪽**을 택했습니다.

```python
class LatestFrameCapture:
    """카메라 속도로 계속 read() 하고, 최신 1장만 들고 있습니다."""
    def __init__(self, src):
        self.cap = cv2.VideoCapture(src)
        self.lock, self.frame = threading.Lock(), None
        threading.Thread(target=self._loop, daemon=True).start()

    def _loop(self):
        while True:
            ok, f = self.cap.read()          # 30 FPS 로 계속 비웁니다
            if ok:
                with self.lock:
                    self.frame = f           # 오래된 것은 버립니다

    def read(self):
        with self.lock:
            return None if self.frame is None else self.frame.copy()
```

```
방식                        평균 지연   최대     안정성
cap.read() 그대로            2.8 s      5.9 s   요동
BUFFERSIZE=1 만              1.9 s      3.4 s   백엔드 의존
★ LatestFrameCapture         0.11 s     0.14 s   ✓ 일정
```

**⑥ 배운 것**

★ **"느리다" 와 "밀린다" 는 다른 문제입니다.** 느리면 처리 시간을 줄이고,
밀리면 쌓이는 곳을 찾습니다. **시간이 갈수록 나빠지면 거의 항상 큐가 범인입니다.**
그리고 **실시간 시스템에서는 오래된 데이터를 버리는 것이 맞습니다** — CCTV 에서
3초 전 프레임은 가치가 없습니다. 이 원칙이 그대로 `Queue(maxsize=2)` 로 이어졌습니다.

def check_power():
    """기동 시 전원 상태를 확인하고 로그에 남깁니다."""

### 3.6 알림이 28초 늦게 옴

**① 증상**

D-01  이벤트 발생 → 텔레그램 도착   중앙값 ★ 28.4초 (목표 5초)
      그리고 알림이 밀리는 동안 검출도 멈춥니다 (FPS 11.2 → 0.4)

**② 가설** ① 추론이 느리다 → "모델을 더 작게 하자" 는 의견이 나왔습니다
② 네트워크가 느리다 ③ 어느 구간인지 모른다 = 재야 한다

**③ 확인** — ★ **추측을 멈추고 구간별로 쟀습니다.**
`contextlib.contextmanager` 로 구간별 소요를 `defaultdict(float)` 에 누적하는
`Stage` 클래스를 만들어 100프레임을 돌렸습니다.

```
구간별 1프레임 평균 (100프레임)
  1위    알림 전송(동기)   5,912 ms   68%
  2위    추론              96 ms     16%
  3위    스냅샷 저장        41 ms      7%
  4위    DB 기록           23 ms      4%
  5위    전처리·후처리      18 ms      3%
```

★ **가설 1대로 모델을 줄였다면 6시간을 쓰고 16% 중 일부만 줄였을 것입니다.**

**④ 원인**

텔레그램 API 호출을 **검출 루프 안에서 동기로** 부르고 있었습니다.
API 가 느리거나 재시도가 걸리면 **그 시간 동안 카메라를 읽지 않습니다.**

```
[✗ 이전]  캡처 → 추론 → 판정 → requests.post(텔레그램) ─ 최대 30초 대기 ─→ 다음 프레임
[✓ 이후]  캡처 → 추론 → 판정 → 큐에 넣고 즉시 다음 프레임
                                   └→ [워커 스레드] 전송 · 재시도 · 실패 기록
```

**⑤ 해결**

```python
alert_q = queue.Queue(maxsize=100)          # 상한 필수 (없으면 메모리가 샙니다)

def alert_worker():
    while True:
        payload = alert_q.get()
        try:
            send_telegram(payload, timeout=10)
        except Exception as e:
            logging.warning("알림 실패 %s — %s", payload["event_id"], e)
        finally:
            alert_q.task_done()

threading.Thread(target=alert_worker, daemon=True).start()

def on_event(payload):
    try:
        alert_q.put_nowait(payload)         # 즉시 반환
    except queue.Full:
        logging.error("알림 큐 포화 — 폐기 %s", payload["event_id"])
```

```
결과
  알림 지연   28.4 s → ★ 3.4 s
  유효 FPS    알림 중 0.4 → 11.2 유지
  부작용 하나 — 종료 시 큐에 남은 알림이 유실됩니다
     → 종료 훅에서 alert_q.join() 으로 flush 하도록 추가했습니다
```

**⑥ 배운 것**

★ **추측으로 최적화하면 엉뚱한 곳을 6시간 고칩니다.** "느린 것 같다" 는 의견이
3개 나왔는데 **셋 다 틀렸습니다.** **외부 API 호출은 절대 주 루프 안에 두지 않습니다** —
````

```python
"""tools/check_docs.py — 문서 완성도 자동 점검"""
import re
import subprocess
from pathlib import Path

ROOT = Path(__file__).resolve().parents[1]
README = (ROOT / "README.md").read_text("utf-8")
fail = []

def chk(cond, msg):
    print(f"  {'✓' if cond else '✗'}  {msg}")
    if not cond:
        fail.append(msg)

for f in ["README.md", "requirements.txt", "requirements-lock.txt", ".env.example",
          ".gitignore", "docs/MODEL_CARD.md", "docs/LABELING_GUIDE.md",
          "docs/RETROSPECTIVE.md", "docs/ARCHITECTURE.md"]:      # 1. 필수 파일
    chk((ROOT / f).exists(), f"파일 {f}")

for sec in ["문제", "주요 기능", "시스템 구성", "성능", "설치", "실행",
            "사용법", "프로젝트 구조", "한계", "팀"]:              # 2. README 필수 절
    chk(bool(re.search(rf"^##\s*.*{sec}", README, re.M)), f"README 절 '{sec}'")

head = "\n".join(README.splitlines()[:60])                        # 3. 첫 화면 이미지
chk("![" in head, "README 첫 화면에 이미지")
chk(bool(re.search(r"mAP.*0\.\d{3}", README)), "성능 숫자(mAP)")   # 4. 성능 숫자
chk(bool(re.search(r"FPS", README)), "성능 숫자(FPS)")

# 5. 비밀 노출
SECRET = [(r"\b\d{8,10}:[A-Za-z0-9_-]{30,}", "텔레그램 토큰"),
          (r"(?i)(password|passwd|pw)\s*[:=]\s*\S{4,}", "비밀번호"),
          (r"\b192\.168\.\d+\.\d+\b", "사설 IP"),
          (r"\bsk-[A-Za-z0-9]{20,}", "API 키"),
          (r"(?i)\b[A-Za-z0-9._%+-]+@(gmail|naver|daum)\.", "개인 이메일")]
docs = list(ROOT.glob("*.md")) + list((ROOT / "docs").glob("*.md"))
for pat, name in SECRET:
    hits = [f"{p.name}:{i}" for p in docs
            for i, ln in enumerate(p.read_text('utf-8').splitlines(), 1)
            if re.search(pat, ln) and "예시" not in ln and "example" not in ln.lower()]
    chk(not hits, f"비밀 미노출 — {name} {hits if hits else ''}")

# 6. 깨진 내부 링크
links = re.findall(r"\]\((?!https?:|#|mailto:)([^)#]+)", README)
broken = [l for l in links if not (ROOT / l).exists()]
chk(not broken, f"내부 링크 {broken if broken else ''}")

# 7. 이미지 용량
big = [p.name for p in (ROOT / "docs/img").glob("*")
       if p.is_file() and p.stat().st_size > 1_000_000]
chk(not big, f"이미지 1MB 이하 {big if big else ''}")

# 8. 버전 고정
req = (ROOT / "requirements.txt").read_text("utf-8").splitlines()
loose = [l for l in req if l.strip() and not l.startswith("#") and "==" not in l]
chk(not loose, f"버전 고정 {loose if loose else ''}")

# 9. 저장소 용량
size = int(subprocess.check_output(["git", "count-objects", "-v"], cwd=ROOT)
           .decode().split("size-pack:")[1].split()[0])
chk(size < 100_000, f"저장소 {size/1024:.0f} MB (100MB 미만)")

print(f"\n  {'★ 전부 통과' if not fail else f'실패 {len(fail)}건'}")
```

````markdown
### 3.4 화면이 3초 늦게 움직임

**① 증상**
스트리밍을 붙이자 카메라 앞에서 손을 흔들면 화면에서는 3초 뒤에 흔들립니다.
손을 멈춰도 3초 동안 계속 흔듭니다. 스톱워치를 비춰 재니
**평균 2.8초 · 최대 5.9초**, 그리고 **시간이 갈수록 커집니다.**

**② 가설** ① 추론이 느리다 ② 네트워크가 느리다
③ **시간이 갈수록 커진다 = 어딘가에 쌓이고 있다**

**③ 확인** 구간별로 시각을 찍으니 `read()` 3ms · `detect` 68ms · `encode` 9ms
= 합계 80ms(12.5 FPS). 코드는 빠른데 화면은 3초 늦습니다.
→ **처리 속도가 아니라 "언제 찍힌 프레임인가" 의 문제**입니다. (①② 배제)

**④ 원인** 카메라는 30 FPS 로 드라이버 버퍼에 넣고 우리는 12.5 FPS 로 꺼냅니다.
초당 17.5장씩 쌓이고, `read()` 는 **항상 가장 오래된 프레임**을 줍니다.

**⑤ 해결** `CAP_PROP_BUFFERSIZE=1` 은 DSHOW·MSMF 백엔드가 무시했습니다(1.9초).
읽기 전용 스레드가 카메라 속도로 계속 비우고 **최신 1장만** 들고 있게 바꿨습니다.
평균 지연 2.8초(최대 5.9) → 1.9초(3.4) → **0.11초(0.14).**

**⑥ 배운 것** "느리다" 와 "밀린다" 는 다른 문제입니다. 느리면 처리 시간을 줄이고,
**밀리면 쌓이는 곳을 찾습니다. 시간이 갈수록 나빠지면 거의 항상 큐가 범인입니다.**
실시간 시스템에서는 **오래된 데이터를 버리는 것이 맞습니다.**
````

| ⑨ | ✗ 금지 | 제3자 사업장 정보 · 동의 범위 밖 | 상호 가림 · 카메라 각도만 보이게 |
| ⑩ | △ 지양 | 스팸 수집 대상 | GitHub 프로필 · 팀 대표 메일 |

### 판정 기준 3가지

```
① ★ 그것으로 무언가를 할 수 있는가   → 토큰 · 비밀번호 · 키 → 금지
② 남의 것인가                        → 얼굴 · 상호 · 서명 → 동의 범위 확인
③ 우리 환경만의 값인가               → 사설 IP · 개인 폴더 경로 → 플레이스홀더
✓ 반대로 넣어야 하는 것 — 측정 조건이 붙은 숫자 · 체크섬 · 설정 파일 · 실패 기록 · 한계
```

### 이미 커밋해 버렸다면 — 순서가 중요합니다

```
1. ★ 즉시 무효화        토큰 재발급(BotFather /revoke) · 비밀번호 변경
2. 영향 범위 확인       봇 로그 · ssh 접속 기록
3. 코드에서 제거        .env 로 이동 · .gitignore 추가 · git rm --cached
4. 히스토리 정리        git filter-repo (팀 전원 재클론 필요)
5. 기록                 무엇이 언제 노출됐고 무엇을 했는지

⚠️ 3·4 를 먼저 하고 1 을 안 하면 ★ 아무것도 한 것이 없습니다
   공개 저장소는 ★ 미러·캐시·포크가 이미 존재할 수 있습니다
```
