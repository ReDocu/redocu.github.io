|---|---|---|
| **개요** | 얼마나 · 언제부터 · 얼마나 온전한가 | `COUNT` · `MIN/MAX` · 결측률 |

### 인사이트 쓰는 법 — 질문 → 근거 → 결론

```markdown
### Q4. 대기질이 나쁜 측정소는 어디인가?

**질문** — '나쁨'의 정의를 평균과 빈도 두 가지로 나누어 순위를 비교한다.

**쿼리** (sql/analysis/04_ranking.sql)

**결과**
| 측정소 | 평균 PM10 | 순위 | '나쁨' 이상 비율 | 순위 |
|---|---|---|---|---|
| 강북구 | 41.2 | 1 | 12.4% | 3 |
| 도로변A | 39.8 | 2 | 18.1% | 1 |

**결론** — 두 순위가 다르다. 강북구는 **늘 조금씩** 나쁘고,
도로변A는 **가끔 매우** 나쁘다. 고농도 노출이 건강에 더 영향이 크다면
도로변A가 우선 관리 대상이다.

**한계** — 도로변 측정소는 교통량 영향이 커 주거지역과 직접 비교하기 어렵다.
```

**"한계"를 쓰는 것이 신뢰도를 만듭니다.** 한계를 모르는 분석은 과신을 부릅니다.

### 차트는 색이 아니라 형태부터

**색을 먼저 고르는 것이 나쁜 차트의 1순위 원인입니다.** 순서가 있습니다.

```
① 형태를 고른다     이 데이터의 일은 무엇인가?
② 색을 역할에 배정   정체성? 크기? 극성? 상태?
③ 마크를 다듬는다   선 굵기·격자·레이블
④ 접근성 확인       범례 · 색맹 · 표 병기
```

**① 형태 고르기**

| 데이터의 일 | 형태 |
|---|---|
| **시간에 따른 변화** | 꺾은선 |
| **항목 간 크기 비교 · 순위** | 가로 막대 (**세로 막대는 이름이 길면 못 읽습니다**) |
| **두 축의 격자별 크기** | 히트맵 |
| 구성비 | 누적 막대 (원 그래프는 3조각 넘으면 읽기 어려움) |
| 두 변수의 관계 | 산점도 |
| **숫자 하나가 결론** | **차트가 아니라 큰 숫자 한 줄** |

**② 색의 네 가지 역할**

| 역할 | 언제 | 규칙 |
|---|---|---|
| **범주형** | 계열 구분 (측정소 A·B·C) | 정해진 순서대로 배정. **순환시키지 않음** |
| **연속형** | 크기 (농도가 높을수록 진하게) | **한 색상, 밝음→어둠.** 무지개 금지 |
| **발산형** | 기준선 기준 양/음 (평년 대비) | 두 색 + **중간은 회색** |
| **상태** | 좋음/나쁨 경보 | 예약된 색. 계열 색으로 재사용 금지 |

**절대 하지 말 것**

| 금지 | 이유 |
|---|---|
| **이중 축 (y축 2개)** | 두 축의 눈금을 조작하면 **어떤 상관관계도 만들어 낼 수 있습니다.** 차트 실수 1위 |
| 무지개 연속형 | 색상 순서에 크기 감각이 없어 값을 못 읽음 |
| 순위에 따라 색이 바뀜 | 필터를 바꿨을 때 같은 대상의 색이 달라져 혼란 |
| 모든 점에 숫자 표기 | 읽을 게 너무 많아 아무것도 안 읽힘 |

> **이중 축을 쓰고 싶어지면** 차트를 두 개로 나누거나, 두 값을 **같은 기준으로 지수화**(첫날=100)하세요.

**③ 마크 다듬기**

```
선          2px, 계열별 색
점          8px 이상 (있으면)
막대 끝     모서리 4px 둥글게, 기준선에 붙임
격자        아주 옅게, 가로선만
축 선       없애거나 아주 옅게
레이블      계열 4개 이하면 선 끝에 직접 표기 (범례와 병행)
```

**④ 접근성**

| 항목 | 규칙 |
|---|---|
| 계열 2개 이상 | **범례 필수** (계열 1개면 제목이 그 역할) |
| 계열 4개 이하 | 범례 + **직접 레이블** 병행 — 색만으로 구분하지 않게 |
| 색맹 | 색상 조합을 검증된 순서로. **모양·레이블을 함께** |
| 대비가 낮은 색 | **레이블을 반드시 표기**하거나 표를 함께 제공 |

### Step 3. 추이 (Q2~Q3) — 윈도우 함수 (3교시)

```sql
-- sql/analysis/02_trend.sql
-- 질문: 일별 PM10 평균의 추세와 변동 폭은?

WITH daily AS (
    SELECT m.measured_at::date        AS day,
           ROUND(AVG(m.pm10), 1)      AS avg_pm10,
           MAX(m.pm10)                AS max_pm10,
           COUNT(*)                   AS n
    FROM measurement m
    WHERE m.pm10 IS NOT NULL
    GROUP BY 1
)
SELECT day, avg_pm10, max_pm10, n,
       LAG(avg_pm10) OVER (ORDER BY day)                     AS 전일,
       ROUND(avg_pm10 - LAG(avg_pm10) OVER (ORDER BY day), 1) AS 증감,
       ROUND(AVG(avg_pm10) OVER (ORDER BY day
             ROWS BETWEEN 6 PRECEDING AND CURRENT ROW), 1)    AS 이동평균7일
FROM daily
ORDER BY day;
```

**변동이 큰 날 찾기**

```sql
-- 질문: 급변한 날은 언제이며, 전국적 현상인가 국지적 현상인가?
WITH daily AS (
    SELECT m.station_id, m.measured_at::date AS day, AVG(m.pm10) AS avg_pm10
    FROM measurement m WHERE m.pm10 IS NOT NULL
    GROUP BY 1, 2
),
changed AS (
    SELECT day,
           ROUND(AVG(avg_pm10), 1)                                   AS 전체평균,
           COUNT(*) FILTER (WHERE avg_pm10 >= 80)                    AS 나쁨측정소수,
           COUNT(*)                                                  AS 측정소수
    FROM daily GROUP BY day
)
SELECT day, 전체평균, 나쁨측정소수, 측정소수,
       ROUND(나쁨측정소수 * 100.0 / 측정소수, 1) AS 나쁨비율
FROM changed
WHERE 나쁨측정소수 > 0
ORDER BY 나쁨비율 DESC
LIMIT 5;
```

### Step 4. 구성·세그먼트 (Q4~Q6) (4교시)

```sql
-- sql/analysis/03_composition.sql
-- 질문: 대기질 등급의 분포는? 시간대·요일에 따라 다른가?

SELECT CASE WHEN pm10 <=  30 THEN '좋음'
            WHEN pm10 <=  80 THEN '보통'
            WHEN pm10 <= 150 THEN '나쁨'
            ELSE                  '매우나쁨'
       END                                                    AS 등급,
       COUNT(*)                                               AS 건수,
       ROUND(COUNT(*) * 100.0 / SUM(COUNT(*)) OVER (), 2)     AS 비율
FROM measurement
WHERE pm10 IS NOT NULL
GROUP BY 1
ORDER BY MIN(pm10);
```

```
   등급   | 건수  | 비율
----------+-------+-------
 좋음     | 14382 | 52.47
 보통     | 11284 | 41.16
 나쁨     |  1601 |  5.84
 매우나쁨 |   145 |  0.53
(4 rows)
```

**`SUM(COUNT(*)) OVER ()`** — [Day 037](day-037.md)에서 배운 이중 구조입니다.
`GROUP BY` 결과 위에 윈도우 함수를 얹어 전체 대비 비율을 냅니다.

**검산** — 건수 합 27,412 = `COUNT(pm10)` ✅ · 비율 합 100.00 ✅

**시간대 × 요일 (히트맵용 데이터)**

```sql
-- sql/analysis/05_segment.sql
SELECT EXTRACT(DOW  FROM measured_at)::int AS 요일,   -- 0=일요일
       EXTRACT(HOUR FROM measured_at)::int AS 시각,
       ROUND(AVG(pm10), 1)                 AS 평균,
       COUNT(*)                            AS n
FROM measurement
WHERE pm10 IS NOT NULL
GROUP BY 1, 2
ORDER BY 1, 2;
```

168행(7×24)이 나옵니다. 이 표를 사람이 읽기는 어렵습니다. **히트맵이 필요한 이유입니다.**

### Step 5. 순위 (Q7~Q8) — `RANK` (5교시)

```sql
-- sql/analysis/04_ranking.sql
-- 질문: '나쁨'의 정의를 바꾸면 측정소 순위가 달라지는가?

WITH stat AS (
    SELECT s.station_id, s.name,
           COUNT(*)                                              AS n,
           ROUND(AVG(m.pm10), 1)                                 AS 평균,
           ROUND(COUNT(*) FILTER (WHERE m.pm10 > 80) * 100.0
                 / COUNT(*), 2)                                  AS 나쁨비율
    FROM measurement m
    JOIN station s ON m.station_id = s.station_id
    WHERE m.pm10 IS NOT NULL
    GROUP BY s.station_id, s.name
    HAVING COUNT(*) >= 500                    -- 표본이 적은 측정소 제외 (Day 047)
)
SELECT name AS 측정소, n AS 관측수, 평균,
       RANK() OVER (ORDER BY 평균 DESC)       AS 평균순위,
       나쁨비율,
       RANK() OVER (ORDER BY 나쁨비율 DESC)   AS 빈도순위,
       RANK() OVER (ORDER BY 평균 DESC)
       - RANK() OVER (ORDER BY 나쁨비율 DESC) AS 순위차
FROM stat
ORDER BY 평균 DESC
LIMIT 10;
```

```
  측정소  | 관측수 | 평균 | 평균순위 | 나쁨비율 | 빈도순위 | 순위차
----------+--------+------+----------+----------+----------+--------
```

**같은 데이터, 다른 정의, 다른 1등입니다.**
`RANK()` 를 두 번 써서 순위를 나란히 놓은 것이 이 표의 핵심입니다.

**시·도 안에서의 순위** (`PARTITION BY`)

```sql
SELECT s.sido, s.name, ROUND(AVG(m.pm10), 1) AS 평균,
       RANK() OVER (PARTITION BY s.sido ORDER BY AVG(m.pm10) DESC) AS 지역내순위
FROM measurement m JOIN station s ON m.station_id = s.station_id
WHERE m.pm10 IS NOT NULL
GROUP BY s.sido, s.station_id, s.name;
```

### Step 6. 이상 탐지 (Q9~Q10) (6교시)

```sql
-- sql/analysis/06_anomaly.sql
-- 질문: 다른 측정소와 유독 다르게 움직이는 측정소가 있는가?

WITH daily AS (
    SELECT station_id, measured_at::date AS day, AVG(pm10) AS v
    FROM measurement WHERE pm10 IS NOT NULL
    GROUP BY 1, 2
),
citywide AS (
    SELECT day, AVG(v) AS city_avg, STDDEV(v) AS city_sd
    FROM daily GROUP BY day
)
SELECT s.name                                     AS 측정소,
       COUNT(*) FILTER (WHERE ABS(d.v - c.city_avg) > 2 * c.city_sd) AS 이탈일수,
       COUNT(*)                                   AS 관측일수,
       ROUND(AVG(d.v - c.city_avg), 1)            AS 평균편차
FROM daily d
JOIN citywide c ON d.day = c.day
JOIN station  s ON d.station_id = s.station_id
WHERE c.city_sd > 0
GROUP BY s.station_id, s.name
HAVING COUNT(*) >= 20
ORDER BY 이탈일수 DESC
LIMIT 5;
```

## ⑥ 확인 문제

**1.** "측정소별 평균 PM10"과 "측정소별 '나쁨' 이상 비율"의 순위가 다릅니다. 어느 쪽을 보고서의 결론으로 삼아야 하나요?

<details>
<summary>답 보기</summary>

**둘 다 싣고, 다르다는 사실 자체를 결론으로 삼습니다.**

```
평균이 높은 곳     =  늘 조금씩 나쁜 곳     (만성 노출)
나쁨 비율이 높은 곳 =  가끔 매우 나쁜 곳     (급성 고농도 노출)
```

**하나를 골라야 한다면 목적이 정합니다.**

| 목적 | 지표 |
|---|---|
| 연간 건강 영향 추정 | **평균** (누적 노출량) |
| 경보 발령·마스크 배포 | **'나쁨' 비율** (고농도 빈도) |
| 저감 정책 효과 측정 | 평균 (변화를 보기 쉬움) |
| 취약계층 보호 | '나쁨' 비율 (극단값이 위험) |

**보고서 문장 예시**

```markdown
평균 기준 1위는 강북구(41.2), '나쁨' 이상 빈도 기준 1위는 도로변A(12.06%)로 서로 다릅니다.
```

`RANK()` 를 두 번 써서 **순위차 열**까지 만들면, 이 차이가 표 하나에 드러납니다.

**2.** 아래 차트 코드의 문제점을 3개 이상 찾고 고치세요.

```python
fig, ax = plt.subplots()
ax2 = ax.twinx()
ax.bar(df["측정소"], df["평균"], color=plt.cm.rainbow(range(len(df))))
ax2.plot(df["측정소"], df["관측수"], color="red")
ax.set_ylim(30, 45)
for i, v in enumerate(df["평균"]):
    ax.text(i, v, str(v))
```

<details>
<summary>답 보기</summary>

| # | 문제 | 왜 나쁜가 | 고침 |
|---|---|---|---|
| 1 | **`twinx()` 이중 축** | 두 축의 눈금 조절로 **없는 상관관계를 만들어 냄.** 차트 실수 1위 | 차트를 두 개로 분리 |
| 2 | **무지개 색** | 순위에 따라 색이 바뀌어 **정체성이 없음.** 색맹에게 판독 불가 | 단일 색 (`#2a78d6`) |
| 3 | **`set_ylim(30, 45)`** | 막대는 **길이로 크기를 읽음.** 축을 자르면 차이가 과장됨 | `set_ylim(0, ...)` |
| 4 | **모든 값에 숫자** | 40개면 전부 겹쳐 아무것도 안 읽힘 | 상위 몇 개만 또는 가로 막대 + 끝 레이블 |
| 5 | 세로 막대에 측정소 이름 | 이름이 길면 겹치거나 회전해야 함 | **가로 막대** |
| 6 | 제목·축 레이블 없음 | 그림만 봐서는 무슨 데이터인지 모름 | `set_title` · `set_xlabel` |
| 7 | 정렬 없음 | 순위 차트인데 순서가 없음 | `sort_values` |

**고친 코드**

```python
df = df.sort_values("평균")                    # 가로 막대는 아래가 작은 값

fig, ax = plt.subplots(figsize=(8, 5))
ax.barh(df["측정소"], df["평균"], color="#2a78d6", height=0.62)

for y, v in zip(df["측정소"], df["평균"]):     # 값은 막대 끝에만
    ax.annotate(f"{v}", xy=(v, y), xytext=(5, 0), textcoords="offset points",
                va="center", fontsize=9, color="#52514e")

ax.set_title("측정소별 평균 PM10 상위 10 (관측 500건 이상)")
ax.set_xlabel("PM10 (㎍/㎥)")
ax.set_xlim(0, df["평균"].max() * 1.12)        # 0부터
ax.grid(axis="y", visible=False)
```

**관측수는 어떻게 하나요?** 세 가지 선택지가 있습니다.

1. **별도 차트로** — 가장 정직합니다
2. **제목이나 부제로** — "관측 500건 이상 측정소 대상"
3. **표로 병기** — 보고서에서는 이게 가장 흔합니다

**3.** 히트맵에 무지개(`jet`) 컬러맵을 쓰면 왜 안 되나요? 대신 무엇을 써야 하며, 값의 부호가 양·음으로 나뉠 때는 어떻게 하나요?

<details>
<summary>답 보기</summary>

**무지개가 나쁜 이유**

| 문제 | 설명 |
|---|---|
| **순서 감각이 없다** | 빨강과 파랑 중 뭐가 큰지 **약속을 외워야** 알 수 있음. 밝기는 그냥 보임 |
| **가짜 경계를 만든다** | 청록↔노랑 구간에서 색이 급변해, 값이 완만한데도 **경계선이 있는 것처럼** 보임 |
| **색맹에게 무너진다** | 빨강-초록 구분이 안 되면 양 끝이 같아 보임 |
| **흑백 인쇄 불가** | 밝기가 단조롭게 변하지 않아 회색조로 바꾸면 순서가 뒤섞임 |

**대신 쓸 것 — 연속형(한 색상, 밝음→어둠)**

```python
cmap = LinearSegmentedColormap.from_list(
    "seq_blue",
    ["#cde2fb", "#9ec5f4", "#5598e7", "#2a78d6", "#1c5cab", "#0d366b"],
)
# 또는 matplotlib 내장: cmap="Blues"
```

**밝기가 단조롭게 변하므로** 흑백으로 인쇄해도, 색맹이 봐도 **순서가 유지**됩니다.

**부호가 나뉠 때 — 발산형(두 색 + 회색 중간)**

"평년 대비 편차"처럼 **0이 의미 있는 기준**일 때 씁니다.

```python
from matplotlib.colors import TwoSlopeNorm

cmap = LinearSegmentedColormap.from_list(
    "div_blue_red",
    ["#0d366b", "#5598e7", "#f0efec", "#e87a79", "#a01f1e"],   # 파랑 ← 회색 → 빨강
)
norm = TwoSlopeNorm(vmin=df.min().min(), vcenter=0, vmax=df.max().max())
im = ax.imshow(values, cmap=cmap, norm=norm, aspect="auto")
```

| 규칙 | 이유 |
|---|---|
| **중간은 회색** | "차이 없음"이 눈에 안 띄어야 함. 중간에 색상을 두면 그게 강조됨 |
| **양쪽 팔의 단계 수를 같게** | 안 그러면 한쪽이 과장됨 |
| **`vcenter=0` 을 명시** | 데이터 범위가 비대칭이어도 0이 항상 회색 |

**`TwoSlopeNorm` 없이 그리면** 데이터가 `-5 ~ +40` 일 때 회색이 `+17.5` 에 오게 되어
**+10 인 칸이 파랑(음수처럼)으로 보입니다.** 조용히 틀리는 종류의 오류입니다.

**정리**

| 데이터의 성격 | 색 |
|---|---|
| 크기 (0 ~ 최대) | **연속형** — 한 색상 밝음→어둠 |
| 기준선 대비 양/음 | **발산형** — 두 색상 + 회색 중간, `vcenter` 명시 |
| 서로 다른 항목 | **범주형** — 정해진 순서, 순환 금지 |
| 좋음/나쁨 경보 | **상태색** — 예약된 색 + 아이콘/레이블 병기 |
</details>
