## ② 왜 필요한가

### 발표가 프로젝트의 절반입니다

```
아무리 좋은 분석도 전달되지 않으면 없는 것과 같습니다
```

**그리고 이 프로젝트는 특히 그렇습니다.**

| 보여 주기 쉬운 것 | 보여 주기 어려운 것 |
|---|---|
| 정확도 0.8842 | **왜 그 숫자를 믿을 수 있는가** |
| 학습 곡선 | **배경을 보지 않는다는 증거** |
| 예쁜 혼동행렬 | **정확도 0.9053짜리를 왜 버렸는가** |

**오른쪽 열이 이번 주에 한 일의 전부입니다.**
그런데 그냥 발표하면 왼쪽 열만 전달됩니다.

### 심사자가 물어볼 단 하나의 질문

```
"그 모델, 눈밭 보고 맞힌 거 아닌가요?"
```

**이 질문에 5초 안에 답할 수 있어야 합니다.**

```
✅ "마스킹 실험을 했습니다. 동물을 가리면 0.88 → 0.61로 무너지고,
    배경을 가리면 0.85로 유지됩니다. 동물을 보고 있습니다."
```

**슬라이드 한 장으로 답이 끝나야 합니다.** 그 슬라이드가 오늘 만들 핵심입니다.

### 회고문서는 다음 프로젝트의 시작입니다

```
대단원 03 → 04 딥러닝 → 05 객체 탐지
```

## ③ 개념 설명

## 1부 · 발표 구성

### 10분 배분 — 이 프로젝트 전용

| 시간 | 내용 | 비중 |
|---|---|---|
| 0:00~0:40 | **결론 먼저** — 숫자 3개 + 한 문장 | 7% |
| 0:40~1:40 | 왜 이 문제인가 — 배경 편향 사례 | 10% |
| 1:40~2:40 | 데이터 — 수집·층화·counter 셋 | 10% |
| 2:40~4:00 | 실험 과정 — 기록표 요약 | 13% |
| 4:00~5:00 | 결과 — 정확도 + **신뢰구간** | 10% |
| **5:00~7:00** | **★ 편향 검증 — 마스킹 실험** | **20%** |
| 7:00~8:00 | 오분류 분석 + 시연 | 10% |
| 8:00~9:00 | 한계와 개선 | 10% |
| 9:00~10:00 | 질의응답 | 10% |

**일반 프로젝트와 다른 점** — 5:00~7:00이 클라이맥스입니다.
보통은 "결과"가 클라이맥스지만, 이 프로젝트는 **"결과를 믿을 수 있는 이유"** 가 주제입니다.

### 결론 먼저 (BLUF)

```
❌ "저희는 늑대와 허스키를 분류하는 모델을 만들었습니다.
    먼저 데이터를 수집했고요, 크롤링을 해서..."
    → 3분 뒤에도 결론이 안 나옴

✅ "정확도 88.4%, 배경을 반대로 바꾼 테스트에서도 82.0%입니다.
    동물을 가리면 61%로 무너지고 배경을 가려도 85%를 유지합니다.
    즉, 이 모델은 배경이 아니라 동물을 보고 판단합니다."
    → 40초에 전부 전달
```

### 슬라이드 원칙

| 원칙 | 이유 |
|---|---|
| 한 장에 메시지 하나 | 두 개면 둘 다 안 남음 |
| **제목이 결론** | "마스킹 실험 결과" ❌ → "동물을 가리면 무너진다" ✅ |
| 숫자는 3개 이하 | 표는 강조 표시로 시선 유도 |
| **그림 > 표 > 글** | 마스킹 실험은 이미지로 보여 주면 즉시 이해됨 |
| 코드는 안 넣음 | 필요하면 부록 |

### 시연이 가장 강력합니다

```
① 새 이미지 5장을 그 자리에서 넣어 예측
② 그중 1장은 '눈밭 허스키' 또는 '실내 늑대'  ← ★
③ 맞히면 그것으로 증명 끝
④ 틀리면? → "이런 경우에 취약합니다"로 한계 설명
```

> **틀려도 됩니다.** 준비된 한계 설명으로 이어지면 오히려 신뢰가 올라갑니다.
> **미리 돌려 보지 않은 이미지로 시연하세요.** 그게 진짜 시연입니다.

### 반드시 나오는 질문 10개

| # | 질문 | 답의 근거 |
|---|---|---|
| 1 | **배경 보고 맞힌 거 아닌가요** | **마스킹 실험** ([Day 104](day-104.md) Step 5) |
| 2 | 데이터 몇 장인가요 | 데이터 카드 |

| 4 | **테스트셋을 몇 번 봤나요** | **1회** — 개봉 체크리스트 |
| 5 | 왜 정확도 높은 모델을 안 골랐나요 | 성공 기준 B, 마스킹 대조군 |
| 6 | 88%와 90%는 차이가 있나요 | **신뢰구간 ±0.066** |
| 7 | 어떤 이미지에서 틀리나요 | 오분류 전수표 |
| 8 | 실무에 쓸 수 있나요 | 임계값 설계 + 한계 |
| 9 | 데이터 저작권은요 | 수집 대장 |
| 10 | 다시 한다면 뭘 바꾸겠나요 | 개선안 8절 |

### 답변 3원칙

```
① 결론 먼저 → 근거 → (필요시) 부연
② 슬라이드/문서의 어디를 보라고 지목
③ 모르면 "확인하지 않았습니다"
```

**예시**

```
Q. "다른 개 품종을 넣으면 어떻게 되나요?"

❌ "음... 아마 잘 안 될 것 같은데요, 해보지는 않았고..."
✅ "확인하지 않았습니다. 학습에 두 클래스만 넣었으므로
    말라뮤트는 둘 중 하나로 강제 분류될 것입니다.
    보고서 7절에 이 한계를 명시했습니다."
```

> **"모릅니다"는 감점이 아닙니다.**
> **모르는데 아는 척하는 것**이 감점입니다.

### 곤란한 질문 대응

| 질문 유형 | 대응 |
|---|---|
| "이거 틀린 거 아닌가요" | 근거를 요청 → 맞으면 인정하고 메모 |
| "그건 의미 없는 실험 아닌가요" | 왜 했는지 목적을 다시 설명 |
| "데이터가 너무 적은데요" | **동의합니다.** CI로 한계를 이미 명시했음을 지목 |
| 답이 없는 질문 | "확인하지 않았습니다. 개선안에 추가하겠습니다" |

## 3부 · 상호 평가

### 평가 5축

| 축 | 배점 | 무엇을 보는가 |
|---|---|---|
| 문제 정의 | 20 | 한 문장 정의 · **성공 기준이 사전에 있었는가** |
| 데이터 | 20 | 수집 계획 · 층화 · **counter 셋** · 라이선스 |
| 방법 | 20 | 실험 기록 · **한 번에 하나** · 선정 근거 |
| **편향 검증** | **25** | **counter · Grad-CAM · 마스킹** ★ |
| 정직성 | 15 | 한계 서술 · 테스트 1회 · **실패 실험 기록** |

**정확도 점수가 없습니다.** 의도한 것입니다.

> **정확도 0.94인데 마스킹 실험이 없는 팀 < 정확도 0.81인데 편향을 정확히 진단한 팀**

### 평가 시 주의

```
① 결과가 아니라 과정을 본다
② "우리보다 정확도 낮네"는 평가가 아니다
③ 근거 없는 칭찬도 피드백이 아니다
④ 좋았던 점 1개 + 궁금한 점 1개를 반드시 쓴다
```

**형식** — `[무엇이 문제였나] + [왜 그랬나] + [다음엔 어떻게]`

## ④ 단계별 실습

### Step 1. 발표 대본 — 10분

```markdown
# 발표 대본 — 늑대 vs 허스키 CNN 이미지 분류 (10분)

## [0:00~0:40] 결론 먼저

"저희 모델의 테스트 정확도는 88.4%입니다.
 배경을 학습 데이터와 반대로 구성한 테스트에서도 82.0%입니다.

 그리고 이 숫자보다 중요한 것 하나.
 동물을 가리면 88% → 61%로 무너지고,
 배경을 가려도 85%를 유지합니다.

 즉, 이 모델은 **배경이 아니라 동물을 보고 판단합니다.**
 오늘 발표의 절반은 이 문장을 증명하는 데 씁니다."

  [슬라이드 1] 숫자 3개 + 마스킹 실험 그림 1장

## [0:40~1:40] 왜 이 문제인가

"늑대와 허스키는 사람도 헷갈립니다. 그런데 진짜 어려움은 다른 데 있습니다.

 늑대 사진은 대부분 눈밭에서 찍혔고, 허스키 사진은 대부분 실내나 공원입니다.
 아무도 의도하지 않았는데 **배경이 정답과 상관관계**를 갖습니다.

 이러면 모델은 '눈이면 늑대'만 배우고도 85%를 맞힐 수 있습니다.
 동물을 볼 이유가 없습니다.

 2016년 LIME 논문의 유명한 실험이 정확히 이것이었습니다.
 정확도 90%인 모델이 사실은 눈을 보고 있었습니다.

 저희 목표는 이 함정을 재현하고, 그다음 깨는 것이었습니다."

  [슬라이드 2] 늑대(눈밭) / 허스키(실내) 대표 이미지 + Clever Hans

## [1:40~2:40] 데이터

"719장을 직접 수집했고, 정제 후 696장을 썼습니다.
 전 건 출처와 라이선스를 기록했습니다.

 핵심은 수량이 아니라 **구성**입니다.

 처음 모았을 때 눈 배경 비율이 늑대 58%, 허스키 35%였습니다.
 이대로면 배경만으로 정확도 85%가 나옵니다.
 그래서 **눈밭 허스키**와 **눈 없는 늑대**를 집중적으로 더 모아
 양쪽 모두 48%로 맞췄습니다.

 그리고 처음부터 따로 만든 것이 하나 더 있습니다.
 **배경 교차 테스트셋 61장** — 늑대는 전부 눈 없는 배경,
 허스키는 전부 눈 배경입니다. 학습 데이터와 정반대입니다.
 이건 목요일까지 한 번도 열지 않았습니다."

  [슬라이드 3] 층화 격자 그림 + counter 셋 예시 이미지

## [2:40~4:00] 실험 과정

"실험은 14회 했고 전부 기록했습니다. 한 번에 하나씩만 바꿨습니다.

 베이스라인은 밑바닥 CNN으로 val 70.5%였습니다.
 여기서 세 번의 도약이 있었습니다.

 첫째, 전이학습. 70.5% → 88.4%. 가장 큰 변화였습니다.
 파라미터는 오히려 1/6로 줄었습니다.

 둘째, 미세조정. 88.4% → 91.6%.
 그런데 여기서 이상한 일이 생겼습니다.
 정확도는 올랐는데 **배경 교차 테스트는 68.9%로 거의 그대로**였습니다.
 하락폭이 오히려 커졌습니다.

 모델이 강해질수록 지름길을 더 잘 찾는다는 것을 여기서 봤습니다.

 셋째, CutOut. 이미지의 랜덤 영역을 지우는 증강입니다.
 배경 교차가 68.9% → 80.3%로 올랐습니다.
 여기에 색 증강을 더해 83.6%까지 갔습니다.
 대신 val은 91.6% → 89.5%로 2%p 내줬습니다."

  [슬라이드 4] 실험 기록표 요약 + 두 선(val/counter) 그래프

## [4:00~5:00] 결과

"최종 모델은 전이학습 + CutOut + 색 증강입니다.

 val 정확도가 91.6%인 모델도 있었지만 그걸 고르지 않았습니다.
 월요일에 정한 성공 기준이 세 개였기 때문입니다.

   A. 정확도 85% 이상          → 88.4%  ✅
   B. 배경 교차 75% 이상       → 82.0%  ✅
   C. 하락폭 10%p 이하         → 6.4%p  ✅

 91.6% 모델은 배경 교차가 68.9%라 B와 C에서 탈락했습니다.

 그리고 88.4%라는 숫자에 대해 하나 말씀드리면,
 테스트셋이 95장이라 **95% 신뢰구간이 80.3%~93.5%** 입니다.
 88%라고 단정하기보다 '80~94% 사이'가 정확한 표현입니다."
```

| 문제 정의 | 20 | **8** | 분류 문제는 명확하나 성공 기준이 사전에 없음. 0.9421이 좋은지 판단할 기준 부재 |
| 데이터 | 20 | **6** | 1200장은 충분하나 **출처·라이선스 미기록**. 배경 층화 없음. counter 셋 없음 |
| 방법 | 20 | **4** | **"여러 가지 해봤다"는 기록이 아님.** 무엇이 효과였는지 말할 수 없음 |
| 편향 검증 | 25 | **0** | 없음 |
| 정직성 | 15 | **5** | 한계가 "시간 부족"뿐. 테스트셋 사용 횟수 불명 |
| **합계** | 100 | **23** | |

**좋았던 점 (반드시 1개)**

> "테스트셋을 200장으로 잡은 것이 좋았습니다.
> 저희는 95장이라 신뢰구간이 ±0.066인데, 200장이면 ±0.032로 절반입니다."

**궁금한 점 (반드시 1개)**

> "0.9421이 배경 덕분인지 확인해 보셨나요?
> 눈밭 허스키나 실내 늑대 사진 몇 장만 넣어 봐도 바로 알 수 있습니다."

**이 평가에서 배울 것**

```
정확도 0.9421 > 저희 0.8842
그러나 그 0.9421이 무엇을 보고 나온 숫자인지 아무도 모릅니다

1200장을 크롤링하면 배경 편향은 원본 그대로 들어갑니다
→ "눈이면 늑대" 규칙만으로도 0.85가 나오는 데이터일 가능성이 높습니다
→ 0.9421의 상당 부분이 배경일 수 있습니다
```

> **평가에서 조심할 것** — "정확도가 높으니까 잘했다"도,
> "편향 검증을 안 했으니 나쁘다"도 근거를 붙여야 피드백입니다.
> **"확인해 볼 방법이 있다"** 를 알려 주는 것이 가장 좋은 피드백입니다.
