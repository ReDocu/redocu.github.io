### ★ 손실 3종의 의미

**검출은 세 가지를 동시에 학습합니다.**

| 손실 | 무엇을 재는가 | 크면 무슨 뜻인가 |
|---|---|---|
| **`box_loss`** | 예측 박스와 정답 박스의 **위치·크기 차이** (CIoU 기반) | 박스가 어긋남 |
| **`cls_loss`** | 각 위치의 **클래스 예측 오차** (BCE) | 무엇인지 못 맞힘 |
| **`dfl_loss`** | 박스 **경계의 확률 분포** 학습 오차 | 경계가 애매함 |

**`dfl_loss` 가 생소할 텐데**

```
전통적 방식: 박스 경계를 숫자 하나로 예측
    x1 = 34.2

DFL (Distribution Focal Loss): 경계를 ★ 확률 분포로 예측
    x1 이 32일 확률 0.1
    x1 이 33일 확률 0.2
    x1 이 34일 확률 0.4      → 기댓값 34.2
    x1 이 35일 확률 0.2
    x1 이 36일 확률 0.1

왜?
  · 실제 경계는 애매한 경우가 많음 (머리카락 끝, 흐릿한 가장자리)
  · 분포로 표현하면 ★ 불확실성까지 학습
  · 결과적으로 박스가 더 정확해짐
```

**세 손실의 전형적 범위**

| 손실 | 학습 초기 | 정상 수렴 | 이상 |
|---|---|---|---|
| `box_loss` | 2.0~3.0 | **0.7~1.2** | 2.0 이상 유지 |
| `cls_loss` | 3.0~6.0 | **0.4~1.0** | 2.0 이상 유지 |
| `dfl_loss` | 1.4~2.0 | **0.9~1.2** | 1.5 이상 유지 |

> ⚠️ **절대값보다 추세와 조합이 중요합니다.**
> 데이터셋마다 값의 범위가 다릅니다. **줄고 있는가, 어느 것이 안 줄고 있는가**를 보세요.

### ★ 손실 조합으로 진단하기

| box | cls | dfl | 진단 | 조치 |
|---|---|---|---|---|
| ↓ | ↓ | ↓ | ✓ 정상 | 계속 |
| → | ↓ | → | **박스 위치 학습 실패** | 라벨 좌표 점검 · imgsz↑ |
| ↓ | → | ↓ | **클래스 구분 실패** | 클래스 정의 · 데이터 불균형 |
| ↓ | ↓ | → | 경계 애매 | 라벨 타이트함 점검 |
| → | → | → | **학습 자체가 안 됨** | `.pt` 확인 · 학습률 · 라벨 |
| ↓ | ↓ | ↓ (val mAP →) | **과적합** | 증강↑ · 데이터↑ · 조기 종료 |

### `results.png` 읽는 법

```
Ultralytics가 그려 주는 10개 그래프

  1행: train/box_loss   train/cls_loss   train/dfl_loss   metrics/precision   metrics/recall
  2행: val/box_loss     val/cls_loss     val/dfl_loss     metrics/mAP50       metrics/mAP50-95
```

**★ 4가지 확인 포인트**

```
[1] train 손실 3개가 모두 내려가는가
      → 안 내려가면 학습 설정 문제

[2] ★ val 손실이 train 손실을 따라 내려가는가
      → val 이 올라가기 시작하면 과적합 시작점

[3] mAP50 이 상승하는가, 언제 평평해지는가
      → 끝까지 오르고 있으면 ★ 에폭을 더 늘릴 여지

[4] mAP50-95 가 mAP50 을 따라 오르는가
      → mAP50 만 오르고 50-95 가 정체 = 박스 정밀도 문제
```

### 혼동행렬 (Confusion Matrix)

```
                    Predicted
                person   box   background
        person  [ 183     4        44    ]
True    box     [   6    48        15    ]
        backgr  [  31    19         0    ]
```

**읽는 법**

| 위치 | 의미 |
|---|---|
| **대각선** | 맞게 검출 (TP) |
| **행 방향 (background 열)** | ★ **미검출 (FN)** — 있는데 못 찾음 |
| **열 방향 (background 행)** | ★ **오검출 (FP)** — 없는데 찾음 |
| 대각선 밖 (클래스 간) | 클래스 혼동 |

**위 예시 해석**

```
person
  · 183개 정확히 검출
  · 44개 놓침 (background 로)      ★ 미검출률 44/231 = 19%
  · 4개를 box 로 착각
  · 31개를 없는데 person 이라고 함  ★ 오검출

box
  · 48개 정확
  · 15개 놓침                       ★ 미검출률 15/69 = 22%
  · 6개를 person 으로 착각
  · 19개 오검출

★ 가장 큰 문제: 미검출 (44 + 15 = 59개)
  클래스 혼동(4 + 6 = 10개)은 상대적으로 적음
  → 클래스 정의는 괜찮은데 "찾는 것" 자체가 약함
  → conf 를 낮추거나 (Day 149), 데이터를 늘려야 함 (Day 150)
```

**정규화 버전 (`confusion_matrix_normalized.png`)**

```
행 방향으로 정규화 → 각 실제 클래스가 어디로 갔는지 비율

        person   box   background
person  [ 0.79  0.02      0.19   ]
box     [ 0.09  0.70      0.22   ]

★ 클래스별 재현율이 대각선에 바로 보입니다
```

### `val_batch*_pred.jpg` — 가장 많은 정보

```
val_batch0_labels.jpg   정답 (사람이 친 라벨)
val_batch0_pred.jpg     예측 (모델의 답, conf 포함)
```

**★ 실패 4유형 분류**

```
① 미검출 (FN)
     labels 에는 박스가 있는데 pred 에는 없음
     → Recall 하락

② 오검출 (FP)
     pred 에 박스가 있는데 labels 에는 없음
     → Precision 하락

③ 박스 어긋남 (Localization)
     둘 다 있는데 위치·크기가 다름
     → mAP50-95 하락 (mAP50 은 통과할 수도)

④ 중복 검출
     한 객체에 pred 박스가 여러 개
     → NMS 문제 (Day 149)
```

**이 분류가 왜 중요한가 — 조치가 다릅니다**

| 유형 | 주 원인 | 조치 |
|---|---|---|
| **미검출** | 데이터 부족 · conf 높음 | 데이터↑ · conf↓ |
| **오검출** | 배경 이미지 부족 · conf 낮음 | 하드 네거티브↑ · conf↑ |
| **박스 어긋남** | 라벨 타이트함 · 해상도 | 라벨 점검 · imgsz↑ |
| **중복** | NMS iou 높음 | iou↓ |

### `best.pt` vs `last.pt`

```
best.pt   val fitness 가 가장 높았던 에폭의 가중치
last.pt   마지막 에폭의 가중치 (+ 옵티마이저 상태)
```

**`fitness` 는 무엇인가**

```
fitness = 0.1 × mAP50 + 0.9 × mAP50-95

★ mAP50-95 에 훨씬 큰 가중치
  → 박스 정확도를 중시하는 기준
```

**어느 것을 쓸 것인가**

| 상황 | 선택 |
|---|---|
| 일반적인 사용 | **`best.pt`** |
| 학습 재개 | **`last.pt`** (필수) |
| 과적합이 있었음 | **`best.pt`** (정점에서 저장됨) |
| 정상 수렴, 마지막이 최고 | 둘이 같음 |
| ★ 추가 fine-tune 시작점 | `best.pt` |

> ⚠️ **`best.pt` 가 항상 좋은 건 아닙니다.**
> `fitness` 는 mAP50-95 중심이라, **재현율이 중요한 CCTV**에는 다른 에폭이 나을 수 있습니다.

## ④ 단계별 실습

### Step 1. `results.csv` 로 직접 그리기

```python
"""plot_results.py — 학습 결과 곡선 (Ultralytics 기본보다 목적에 맞게)"""
from pathlib import Path

import matplotlib.pyplot as plt
import pandas as pd

plt.rcParams["font.family"] = "Malgun Gothic"      # Windows 한글
plt.rcParams["axes.unicode_minus"] = False

RUN = Path("C:/vision/runs/exp01_n_640_50ep")


def load_results(run_dir):
    df = pd.read_csv(Path(run_dir) / "results.csv")
    df.columns = [c.strip() for c in df.columns]
    return df


def plot_training(run_dir, out_path=None):
    df = load_results(run_dir)
    fig, axes = plt.subplots(2, 3, figsize=(16, 8))

    # ── 1행: 손실 3종 (train vs val) ──
    losses = [("box_loss", "박스 위치"), ("cls_loss", "클래스"), ("dfl_loss", "경계 분포")]
    for ax, (key, title) in zip(axes[0], losses):
        tr = f"train/{key}"
        va = f"val/{key}"
        if tr in df:
            ax.plot(df["epoch"], df[tr], label="train", lw=2)
        if va in df:
            ax.plot(df["epoch"], df[va], label="val", lw=2, ls="--")
        ax.set_title(f"{title}  ({key})")
        ax.set_xlabel("epoch")
        ax.grid(alpha=0.3)
        ax.legend()

    # ── 2행 좌: P / R ──
    ax = axes[1][0]
    ax.plot(df["epoch"], df["metrics/precision(B)"], label="Precision", lw=2)
    ax.plot(df["epoch"], df["metrics/recall(B)"], label="Recall", lw=2)
    ax.set_title("정밀도 / 재현율")
    ax.set_xlabel("epoch"); ax.grid(alpha=0.3); ax.legend(); ax.set_ylim(0, 1)

    # ── 2행 중: mAP ──
    ax = axes[1][1]
    m50 = df["metrics/mAP50(B)"]
    m5095 = df["metrics/mAP50-95(B)"]
    ax.plot(df["epoch"], m50, label="mAP50", lw=2)
    ax.plot(df["epoch"], m5095, label="mAP50-95", lw=2)
    best_i = m50.idxmax()
    ax.axvline(df["epoch"][best_i], color="r", ls=":", alpha=0.7)
    ax.annotate(f"최고 {m50.max():.3f}\n@ep{int(df['epoch'][best_i])}",
                xy=(df["epoch"][best_i], m50.max()),
                xytext=(10, -30), textcoords="offset points",

```python
"""failure_analysis.py — 예측을 정답과 대조해 실패를 분류"""
from collections import Counter
from pathlib import Path

import cv2
import numpy as np
import yaml
from ultralytics import YOLO

import bbox_utils as B

RUN = Path("C:/vision/runs/exp01_n_640_50ep")
ROOT = Path("C:/vision/datasets/cctv_v1")
OUT = Path("C:/vision/day147/failures")

IOU_MATCH = 0.5
IOU_LOOSE = 0.2          # ★ 박스 어긋남 판정용


def iou(a, b):
    ax1, ay1, ax2, ay2 = a
    bx1, by1, bx2, by2 = b
    ix1, iy1 = max(ax1, bx1), max(ay1, by1)
    ix2, iy2 = min(ax2, bx2), min(ay2, by2)
    iw, ih = max(0.0, ix2-ix1), max(0.0, iy2-iy1)
    inter = iw * ih
    ua = (ax2-ax1)*(ay2-ay1) + (bx2-bx1)*(by2-by1) - inter
    return inter / ua if ua > 0 else 0.0


def load_gt(txt, w, h):
    if not Path(txt).exists():
        return []
    out = []
    for line in Path(txt).read_text(encoding="utf-8").splitlines():
        if not line.strip():
            continue
        p = line.split()
        out.append((int(p[0]),
                    B.yolo_to_voc(tuple(float(v) for v in p[1:5]), w, h)))
    return out


def analyze(model, split="val", conf=0.25, save_n=20):
    img_dir = ROOT / "images" / split
    lbl_dir = ROOT / "labels" / split
    OUT.mkdir(parents=True, exist_ok=True)

    kinds = Counter()
    records = []

    for p in sorted(img_dir.glob("*.jpg")):
        img = cv2.imread(str(p))
        if img is None:
            continue
        h, w = img.shape[:2]
        gt = load_gt(lbl_dir / (p.stem + ".txt"), w, h)

        r = model(str(p), conf=conf, verbose=False)[0]
        pred = [(int(b.cls), tuple(b.xyxy[0].tolist()), float(b.conf))
                for b in r.boxes]

        matched_gt, matched_pd = set(), set()
        # ① 정상 매칭
        for i, (gc, gb) in enumerate(gt):
            best, bj = 0.0, -1
            for j, (pc, pb, _) in enumerate(pred):
                if j in matched_pd or pc != gc:
                    continue
                v = iou(gb, pb)
                if v > best:
                    best, bj = v, j
            if best >= IOU_MATCH:
                matched_gt.add(i); matched_pd.add(bj)
                kinds["정상"] += 1
            elif best >= IOU_LOOSE:
                matched_gt.add(i); matched_pd.add(bj)
                kinds["박스 어긋남"] += 1
                records.append((p, "박스 어긋남", gt[i], pred[bj], best))

        # ② 미검출
        for i, (gc, gb) in enumerate(gt):
            if i not in matched_gt:
                kinds["미검출"] += 1
                records.append((p, "미검출", gt[i], None, 0.0))

        # ③ 오검출 · 중복
        for j, (pc, pb, pconf) in enumerate(pred):
            if j in matched_pd:
                continue
            # 다른 예측과 크게 겹치면 중복
            dup = any(k != j and k in matched_pd and iou(pb, pred[k][1]) > 0.6
                      for k in range(len(pred)))
            kind = "중복 검출" if dup else "오검출"
            kinds[kind] += 1
            records.append((p, kind, None, (pc, pb, pconf), 0.0))

    return kinds, records

}

print("=" * 88)

all_rows = []
for p in sorted((ROOT / "images/val").glob("*.jpg")):

    for cid, (x1, y1, x2, y2) in load_gt(ROOT / "labels/val" / (p.stem + ".txt"), w, h):

for lb in labels:

    miss = (fn["bin"] == lb).sum()

### ② `conf` 조정 예측

> ⚠️ **중요한 사실 — mAP 는 conf 임계값과 무관합니다.**

> 자세한 것은 [Day 148](day-148.md)에서 다룹니다.

**따라서**

min_visibility 0.35 → 0.25
→ 재학습 후 비교
```

**★ 조치 순서의 원칙**

```
① 재학습이 필요 없는 것부터 (NMS iou)      ← 즉시 효과 확인
② 원인 규명이 필요한 것 (박스 크기)          ← 가장 큰 효과
③ 데이터 작업 (하드 네거티브, 가장자리)      ← 시간 소요
④ 증강 조정                                ← 한 번에 하나만

★ 그리고 한 번에 하나씩 바꾸고 기록합니다 (대단원 04 원칙)
```

> **★ 이 문제의 교훈**
>
> **`val_batch0_pred.jpg` 한 장에서 4가지 문제를 찾았습니다.**
> mAP 숫자로는 하나도 알 수 없는 것들입니다.
>
> ```
> "mAP 0.789"      → 조치를 정할 수 없음
> "예측 박스가 크다" → ★ 즉시 조치 가능
> ```
>
> **눈으로 보는 것이 가장 강력한 진단 도구입니다.**

</details>
