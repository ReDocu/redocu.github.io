## ② 왜 필요한가

[Day 030](../01-python-data/day-030.md)에서 `datapipe` 패키지를 완성했습니다. 이 패키지는 데이터를 **Parquet 파일**에 저장합니다.
잘 돌아갑니다. 지금까지는요.

그런데 이 파이프라인이 실제 서비스로 들어가는 순간, 아래 네 가지가 한꺼번에 터집니다.

### 한계 ① — 조건 하나 걸려면 전부 읽어야 한다

"서울에서 PM10이 100을 넘은 측정소"를 구하려면 파일 전체를 읽어 메모리에 올려야 합니다.
1년치 1억 행이면, 답이 3줄이어도 1억 행을 읽습니다.

```python
# 답은 3줄인데, 읽는 건 1억 행
df = pd.read_parquet("data/air/")        # 메모리 8GB
result = df[(df.city == "서울") & (df.pm10 > 100)]   # 3 rows
```

### 한계 ② — 두 사람이 동시에 쓰면 한 명의 작업이 사라진다

파일에 데이터를 추가하는 흔한 방식은 **읽기 → 합치기 → 통째로 다시 쓰기** 입니다.
두 프로세스가 겹치면 이런 일이 벌어집니다.

```
시각   프로세스 A (수집기)              프로세스 B (보정 스크립트)
────────────────────────────────────────────────────────────────
10:00  df = read_parquet()  (1000행)
10:01                                   df = read_parquet()  (1000행)
10:02  df + 신규 50행 → to_parquet()    ← 파일 1050행
10:03                                   df + 보정 20행 → to_parquet()
                                        ← 파일 1020행  ★ A의 50행 증발
```

이것을 **갱신 손실(lost update)** 이라고 합니다. 에러도 안 나고, 로그도 안 남습니다.
**조용히 데이터가 사라집니다.** 실무에서 가장 무서운 종류의 사고입니다.

### 한계 ③ — 중복 방지를 매번 직접 짜야 한다

[Day 029](../01-python-data/day-029.md)에서 파이프라인을 두 번 돌려도 안전하게 만드느라 상태 파일을 따로 관리했습니다.
DB에서는 컬럼에 `UNIQUE` 한 단어를 붙이면 끝입니다.

### 한계 ④ — 데이터를 결합하려면 전부 메모리에 올려야 한다

측정소 정보와 측정값을 합치려면 두 파일을 다 읽어서 `merge` 해야 합니다.
DB는 필요한 부분만 골라 결합합니다. 이것이 `JOIN` ([Day 034](day-034.md))입니다.

## ③ 개념 설명

### 데이터베이스와 DBMS

| 용어 | 뜻 | 비유 |
|---|---|---|
| **데이터베이스(DB)** | 체계적으로 정리해 둔 데이터 모음 | 서류 창고 |
| **DBMS** | 그 창고를 관리해 주는 **프로그램** | 창고 관리인 |
| **PostgreSQL** | DBMS 제품 이름 중 하나 | 관리인 회사 |
| **SQL** | 관리인에게 일을 시키는 **언어** | 창고에 보내는 요청서 |

우리가 배우는 건 **SQL**(요청서 쓰는 법)이고, 오늘 설치하는 건 **PostgreSQL**(관리인)입니다.
흔히 "DB에 넣었다"고 말하지만, 정확히는 "DBMS에게 넣어 달라고 SQL로 요청했다"입니다.

### 관계형 모델 — 표가 전부입니다

**관계형 데이터베이스(RDB, Relational Database)** 는 데이터를 **표(table)** 로 저장합니다.
Pandas의 `DataFrame`을 이미 다뤄 봤다면 절반은 아는 셈입니다.

```
        ┌─── 열(column) = 필드. 이름과 타입이 정해져 있음
        ▼
 customer_id │ name   │ city │ grade
─────────────┼────────┼──────┼────────
      1      │ 김민수 │ 서울 │ gold     ◀── 행(row) = 레코드. 데이터 한 건
      2      │ 이서연 │ 서울 │ silver
      3      │ 박지훈 │ 부산 │ bronze
```

| 용어 | 뜻 | Pandas로 치면 |
|---|---|---|
| **테이블(table)** | 같은 구조의 데이터를 모아 둔 표 | `DataFrame` |
| **행(row) · 레코드** | 데이터 한 건 | 한 줄 |
| **열(column) · 필드** | 항목 하나. **타입이 고정** | `Series` |
| **스키마(schema)** | 테이블의 설계도 (열 이름 · 타입 · 제약) | `dtypes` + 약속 |

가장 큰 차이는 **타입이 고정**이라는 점입니다.
`price` 열을 `integer`로 정하면, 거기에 `"이만오천원"` 은 아예 들어가지 못하고 **에러가 납니다.**
[Day 023](../01-python-data/day-023.md)에서 정제 코드로 잡아내던 문제를, DB는 **애초에 못 들어오게** 막습니다.

### 키(key) — 행을 가리키는 이름표

| 종류 | 영문 | 역할 |
|---|---|---|
| **기본키** | PRIMARY KEY (PK) | 이 테이블에서 **행 하나를 유일하게 가리키는** 열. 중복·NULL 불가 |
| **외래키** | FOREIGN KEY (FK) | 다른 테이블의 기본키를 가리키는 열. **관계를 만드는 장치** |

외래키가 관계형 DB의 핵심입니다. 주문 테이블에 고객 이름·주소·전화번호를 전부 적어 두는 대신,
**고객 번호 하나만** 적어 두고 필요할 때 고객 테이블을 찾아갑니다.

```
customers                orders                    order_items              products
┌───────────────┐        ┌───────────────┐         ┌───────────────┐        ┌──────────────┐
│ customer_id PK│◀───┐   │ order_id    PK│◀────┐   │order_item_id PK│   ┌──▶│ product_id PK│
│ name          │    └───│ customer_id FK│     └───│ order_id    FK │   │   │ name         │
│ email         │        │ ordered_at    │         │ product_id  FK │───┘   │ category     │
│ city          │        │ status        │         │ quantity       │       │ price        │
│ grade         │        └───────────────┘         │ unit_price     │       │ stock        │
│ joined_at     │                                  └────────────────┘       └──────────────┘
└───────────────┘
   고객 1명이  ──▶  주문 여러 건  ──▶  주문 상세 여러 줄  ◀──  상품
      (1 : N)            (1 : N)                              (N : 1)
```

이렇게 관계를 그린 그림을 **ERD(Entity–Relationship Diagram)** 라고 합니다. 직접 그리는 건 [Day 039](day-039.md)입니다.

> **왜 주문 테이블과 주문 상세 테이블이 따로인가요?**
> 주문 한 건에 상품이 여러 개 담기기 때문입니다. 한 행에 다 넣으려면 `product1, product2, product3...` 처럼
> 열을 늘려야 하는데, 상품 4개를 사는 순간 무너집니다. **"여러 개"는 열이 아니라 행으로 표현합니다.**
> 이 원칙을 정리한 것이 **정규화**이고, [Day 039](day-039.md)에서 다룹니다.

### SQL의 갈래

SQL 명령은 하는 일에 따라 이름이 나뉩니다. 지금 다 외울 필요는 없고, **"이런 분류가 있구나"** 만 알면 됩니다.

| 갈래 | 풀이 | 대표 명령 | 이 과정에서 |
|---|---|---|---|
| **DQL** | 조회 | `SELECT` | Day 032–037 (**대부분 여기**) |
| **DML** | 데이터 조작 | `INSERT` `UPDATE` `DELETE` | Day 038 · 041–042 |
| **DDL** | 구조 정의 | `CREATE` `ALTER` `DROP` | Day 038–039 |
| **TCL** | 트랜잭션 | `COMMIT` `ROLLBACK` | Day 039 |
| **DCL** | 권한 | `GRANT` `REVOKE` | W22 (인프라) |

### 왜 PostgreSQL인가

| DBMS | 특징 | 이 과정에서 안 쓰는 이유 |
|---|---|---|
| **SQLite** | 파일 하나 = DB. 설치 불필요 | 동시 쓰기가 약해 서비스 DB로 부적합 |
| **MySQL / MariaDB** | 웹 서비스에서 가장 흔함 | 분석 함수·타입이 PostgreSQL보다 빈약 |
| **PostgreSQL** ★ | 표준 SQL 충실 · 윈도우 함수 · JSON · 확장(pgvector) | — |
| **BigQuery · Snowflake** | 대규모 분석 전용 | 유료 · 클라우드 종속 |

MLOps에서 PostgreSQL을 고르는 실질적인 이유는 **하나로 여러 역할을 다 하기 때문**입니다.
서비스 DB, 실험 기록 저장소(MLflow 백엔드, W13), 피처 저장, 임베딩 검색(pgvector)까지 같은 DB로 처리됩니다.

### 클라이언트–서버 구조

PostgreSQL은 **항상 켜져 있는 서버 프로그램**입니다. 우리가 쓰는 도구(psql, DBeaver, Python)는 전부 **클라이언트**입니다.

```
 [psql]      ┐
 [DBeaver]   ├── TCP 5432번 포트 ──▶ [PostgreSQL 서버] ──▶ 디스크
 [Python]    ┘
```

그래서 접속하려면 항상 **다섯 가지**가 필요합니다. 앞으로 지겹도록 보게 될 조합입니다.

| 항목 | 오늘 우리가 쓸 값 | 설명 |
|---|---|---|
| host | `localhost` | 서버 주소 |
| port | `5432` | PostgreSQL 기본 포트 |
| database | `shop` | 접속할 데이터베이스 이름 |
| user | `postgres` | 사용자 |
| password | `mlops1234` | 비밀번호 (실습용) |

[Day 041](day-041.md)에서 Python으로 붙을 때 이 다섯 개를 `.env` 에 넣습니다.
**비밀번호는 코드에 절대 쓰지 않습니다** — [Day 019](../01-python-data/day-019.md)에서 API 키에 대해 배운 것과 같은 원칙입니다.

### 데이터베이스 · 스키마 · 테이블의 계층

같은 서버 안에 데이터베이스가 여러 개 있을 수 있고, 그 안에 다시 스키마가 있습니다.

```
PostgreSQL 서버 (컨테이너 mlops-pg)
├── postgres          ← 관리용 기본 DB. 여기엔 아무것도 안 만듭니다
├── shop              ← 오늘 만들 실습용 DB
│   └── public        ← 기본 스키마 (별도로 안 만들면 여기 들어감)
│       ├── customers
│       ├── products
│       ├── orders
│       └── order_items
└── airquality        ← W09에서 만들 ETL 대상 DB
```

`\dt` 를 쳤는데 아무것도 없다면, **십중팔구 다른 데이터베이스에 접속해 있는 것**입니다. (⑤번 참고)

### Docker는 왜 쓰나요

PostgreSQL을 직접 설치하면 OS마다 절차가 다르고, 지우기도 번거롭고, 버전을 바꾸기도 어렵습니다.
**Docker**를 쓰면 명령 한 줄로 띄우고 한 줄로 지웁니다.

> **오늘은 Docker를 "명령 한 줄로 DB를 띄우는 도구"로만 씁니다.**
> 이미지가 무엇이고 컨테이너가 어떻게 격리되는지는 W24([Day 116](../05-infra-mlops/day-116.md)–[120](../05-infra-mlops/day-120.md))에서 제대로 배웁니다.
> 지금은 아래 네 개만 외우면 충분합니다.

| 명령 | 하는 일 |
|---|---|
| `docker run ...` | 컨테이너를 만들고 실행 (**처음 한 번만**) |
| `docker ps` | 실행 중인 컨테이너 목록 |
| `docker stop 이름` / `docker start 이름` | 껐다 켜기 (**매일 이것만**) |
| `docker exec -it 이름 명령` | 컨테이너 안에서 명령 실행 |

### Step 2. PostgreSQL 16 컨테이너 실행

**딱 한 번만** 실행하는 명령입니다. (긴 한 줄입니다. 그대로 복사하세요.)

```powershell
$ docker run --name mlops-pg -e POSTGRES_PASSWORD=mlops1234 -e TZ=Asia/Seoul -p 5432:5432 -v mlops-pgdata:/var/lib/postgresql/data -d postgres:16
Unable to find image 'postgres:16' locally
16: Pulling from library/postgres
a2318d6c47ec: Pull complete
...
Status: Downloaded newer image for postgres:16
c3f1a9b27d84e5f6a1b0c9d8e7f6a5b4c3d2e1f0a9b8c7d6e5f4a3b2c1d0e9f8
```

마지막에 64자리 문자열이 나오면 성공입니다. 옵션의 뜻은 이렇습니다.

| 옵션 | 뜻 |
|---|---|
| `--name mlops-pg` | 컨테이너 이름. 앞으로 이 이름으로 부릅니다 |
| `-e POSTGRES_PASSWORD=mlops1234` | `postgres` 사용자의 비밀번호 지정 (**실습용**) |
| `-e TZ=Asia/Seoul` | 시간대를 한국으로 |
| `-p 5432:5432` | 내 컴퓨터의 5432 포트를 컨테이너의 5432에 연결 |
| `-v mlops-pgdata:/var/lib/postgresql/data` | **데이터를 컨테이너 밖에 저장** — 컨테이너를 지워도 데이터가 남습니다 |
| `-d` | 백그라운드로 실행 |
| `postgres:16` | 쓸 이미지와 버전 |

`-v` 옵션이 오늘 가장 중요합니다. 이게 없으면 `docker rm` 한 번에 그동안 만든 데이터가 전부 사라집니다.

실행 중인지 확인합니다.

```powershell
$ docker ps
CONTAINER ID   IMAGE         COMMAND                  CREATED          STATUS          PORTS                    NAMES
c3f1a9b27d84   postgres:16   "docker-entrypoint.s…"   12 seconds ago   Up 11 seconds   0.0.0.0:5432->5432/tcp   mlops-pg
```

`STATUS` 가 `Up` 이면 서버가 살아 있는 것입니다.

### Step 3. psql로 접속하기

**psql**은 PostgreSQL 공식 명령행 클라이언트입니다. 컨테이너 안에 이미 들어 있으니 따로 설치하지 않습니다.

```powershell
$ docker exec -it mlops-pg psql -U postgres
psql (16.4 (Debian 16.4-1.pgdg120+1))
Type "help" for help.

postgres=#
```

`postgres=#` 프롬프트가 뜨면 접속 성공입니다. 앞의 `postgres` 는 **지금 접속한 데이터베이스 이름**입니다.

psql에는 SQL이 아닌 **메타 명령**이 있습니다. 전부 백슬래시(`\`)로 시작하고 **세미콜론이 필요 없습니다.**

| 메타 명령 | 하는 일 |
|---|---|
| `\l` | 데이터베이스 목록 |
| `\c 이름` | 다른 데이터베이스로 이동 |
| `\dt` | 현재 DB의 테이블 목록 |
| `\d 테이블명` | 테이블 구조 보기 |
| `\du` | 사용자 목록 |
| `\x` | 세로 출력 켜기/끄기 (열이 많을 때) |
| `\?` | 메타 명령 도움말 |
| `\q` | 종료 |

데이터베이스 목록부터 봅니다.

```
postgres=# \l

`Encoding` 이 `UTF8` 인지 확인하세요. 한글 데이터를 넣으려면 반드시 UTF8이어야 합니다.
`template0` · `template1` 은 **새 DB를 만들 때 쓰는 원본 틀**입니다. 건드리지 않습니다.

```

**② 테이블 구조 — 오늘의 핵심 명령**

```
shop=# \d customers
                              Table "public.customers"
   Column    |  Type   | Collation | Nullable |             Default
-------------+---------+-----------+----------+----------------------------------
 customer_id | integer |           | not null | generated always as identity
 name        | text    |           | not null |
 email       | text    |           | not null |
 city        | text    |           |          |
 grade       | text    |           |          |
 phone       | text    |           |          |
 joined_at   | date    |           | not null |
Indexes:
    "customers_pkey" PRIMARY KEY, btree (customer_id)
    "customers_email_key" UNIQUE CONSTRAINT, btree (email)
Referenced by:
    TABLE "orders" CONSTRAINT "orders_customer_id_fkey" FOREIGN KEY (customer_id) REFERENCES customers(customer_id)
```

이 출력에서 읽어야 할 정보입니다.

| 줄 | 읽는 법 |
|---|---|
| `Nullable: not null` | 이 열은 **비워 둘 수 없다** — `name` · `email` · `joined_at` |
| `city` · `grade` · `phone` 이 비어 있음 | **NULL 허용** — 값이 없을 수 있다 ([Day 032](day-032.md)의 주제) |
| `Indexes: customers_pkey PRIMARY KEY` | `customer_id` 가 기본키 |
| `UNIQUE CONSTRAINT (email)` | 같은 이메일로 두 명 등록 불가 |
| `Referenced by: TABLE "orders"` | **orders가 이 테이블을 가리키고 있다** — 자식 테이블 |

자식 쪽에서도 봅니다.

```
shop=# \d orders
                              Table "public.orders"
   Column    |  Type   | Collation | Nullable |             Default
-------------+---------+-----------+----------+----------------------------------
 order_id    | integer |           | not null | generated always as identity
 customer_id | integer |           | not null |
 ordered_at  | date    |           | not null |
 status      | text    |           | not null |
Indexes:
    "orders_pkey" PRIMARY KEY, btree (order_id)
Foreign-key constraints:
    "orders_customer_id_fkey" FOREIGN KEY (customer_id) REFERENCES customers(customer_id)
Referenced by:
    TABLE "order_items" CONSTRAINT "order_items_order_id_fkey" FOREIGN KEY (order_id) REFERENCES orders(order_id)
```

`Foreign-key constraints` 는 **내가 남을 가리키는 것**, `Referenced by` 는 **남이 나를 가리키는 것**입니다.
이 두 줄만 따라가면 처음 보는 DB에서도 테이블 관계를 그릴 수 있습니다.

**③ 행 수 확인**

## ⑤ 자주 하는 실수

### `Ports are not available: ... 0.0.0.0:5432`

```
docker: Error response from daemon: Ports are not available: exposing port TCP 0.0.0.0:5432 -> 0.0.0.0:0:
listen tcp 0.0.0.0:5432: bind: Only one usage of each socket address ... is normally permitted.
```

**원인** — 5432 포트를 이미 다른 프로그램이 쓰고 있습니다. 대개 **예전에 설치한 PostgreSQL**이 서비스로 떠 있는 경우입니다.
**해결** — 두 가지 중 하나를 고릅니다.

```powershell
# (a) 무엇이 쓰고 있는지 확인하고 그 서비스를 중지
$ netstat -ano | findstr :5432
  TCP    0.0.0.0:5432    0.0.0.0:0    LISTENING    7412

# (b) 그냥 다른 포트를 쓴다 — 내 컴퓨터 쪽만 5433으로
$ docker run --name mlops-pg -e POSTGRES_PASSWORD=mlops1234 -e TZ=Asia/Seoul -p 5433:5432 -v mlops-pgdata:/var/lib/postgresql/data -d postgres:16
```

(b)를 골랐다면 **DBeaver·Python에서 포트를 `5433`으로** 적어야 합니다. `docker exec` 접속은 영향받지 않습니다.

### `error during connect: ... The system cannot find the file specified`

```
error during connect: Get "http://%2F%2F.%2Fpipe%2FdockerDesktopLinuxEngine/v1.47/containers/json":
open //./pipe/dockerDesktopLinuxEngine: The system cannot find the file specified.
```

**원인** — **Docker Desktop 앱이 실행돼 있지 않습니다.** `docker` 명령은 앱이 떠 있어야 동작합니다.
**해결** — 시작 메뉴에서 Docker Desktop 실행 → 고래 아이콘이 초록색이 될 때까지(1~2분) 기다린 뒤 다시 시도.

### `password authentication failed for user "postgres"`

```
psql: error: connection to server at "localhost" (::1), port 5432 failed:
FATAL:  password authentication failed for user "postgres"
```

**원인** — 비밀번호가 틀렸거나, **다른 PostgreSQL 서버**에 붙었습니다. (포트 충돌 상태에서 자주 발생)
**해결** — ① `docker exec -it mlops-pg psql -U postgres` 로 접속되는지 확인 (이건 비밀번호 없이 됩니다)
② 그게 되는데 DBeaver만 안 된다면, 붙은 대상이 컨테이너가 아닙니다. 위 포트 충돌 항목을 먼저 해결하세요.

### `database "shop" does not exist`

```
psql: error: connection to server at "localhost" (::1), port 5432 failed:
FATAL:  database "shop" does not exist
```

**원인** — Step 4의 `CREATE DATABASE shop;` 을 건너뛰었습니다.
**해결** — `docker exec -it mlops-pg psql -U postgres` 로 붙어서 `CREATE DATABASE shop;` 을 실행합니다.

### `\dt` 를 쳤는데 `Did not find any relations.`

```
shop=# \dt
Did not find any relations.
```

**원인** — ① 다른 데이터베이스에 접속해 있거나 ② 데이터 적재(Step 6)가 실패했습니다.
**해결** — 먼저 **지금 어디에 있는지** 확인합니다.

```
postgres=# SELECT current_database();
 current_database
------------------
 postgres
(1 row)
```

`shop` 이 아니라면 `\c shop` 으로 이동합니다. 프롬프트 왼쪽 글자가 곧 현재 DB 이름입니다.

### 프롬프트가 `shop-#` 나 `shop'#` 에서 안 돌아옵니다

```
shop=# SELECT * FROM products
shop-#
```

**원인** — `-#` 은 세미콜론이 없어서, `'#` 은 **작은따옴표가 안 닫혀서** 문장이 안 끝난 상태입니다.
**해결** — `;` 을 치고 엔터. 그래도 이상하면 `Ctrl + C` 로 입력 중인 문장을 통째로 취소합니다.

### 한글이 `?????` 나 깨진 글자로 보입니다

```
 product_id |   name   | category
------------+----------+----------
          1 | ?????    | ?????
```

**원인** — 터미널 코드페이지가 UTF-8이 아닙니다. (Windows 기본은 949)
**해결** — psql을 켜기 **전에** 터미널에서 실행합니다.

```powershell
$ chcp 65001
Active code page: 65001
```

매번 치기 싫다면 **Windows Terminal**을 쓰고 글꼴을 `D2Coding` 이나 `맑은 고딕` 계열로 바꾸세요.
저장된 데이터 자체는 UTF8이라 **화면만의 문제**입니다. DBeaver에서는 정상으로 보입니다.

### 컨테이너를 지웠더니 데이터가 사라졌습니다

**원인** — `docker run` 할 때 `-v mlops-pgdata:/var/lib/postgresql/data` 를 빠뜨렸습니다.
컨테이너는 지우면 안이 통째로 사라집니다. `-v` 는 데이터를 **바깥 저장소(볼륨)** 에 두는 옵션입니다.
**해결** — 볼륨이 살아 있는지 확인하고, `-v` 를 붙여 컨테이너만 다시 만듭니다.

```powershell
$ docker volume ls
DRIVER    VOLUME NAME
local     mlops-pgdata

$ docker rm -f mlops-pg
$ docker run --name mlops-pg -e POSTGRES_PASSWORD=mlops1234 -e TZ=Asia/Seoul -p 5432:5432 -v mlops-pgdata:/var/lib/postgresql/data -d postgres:16
```

볼륨 목록에 `mlops-pgdata` 가 없다면 데이터는 복구할 수 없습니다. Step 6을 다시 실행하세요.
**이 실습은 다시 하면 되지만, MP1부터는 그렇지 않습니다.** 오늘 `-v` 의 의미를 확실히 익혀 두세요.

### `syntax error at or near "..."`

```
ERROR:  syntax error at or near "FORM"
LINE 1: SELECT * FORM products;
                 ^
```

**원인** — 오타입니다. `FROM` 을 `FORM` 으로 쓰는 건 통과의례입니다.
**해결** — `^` 표시가 **문제 지점을 정확히 가리킵니다.** 에러 메시지에서 이 화살표부터 보세요.
[Day 032](day-032.md)부터 하루에 몇 번씩 보게 됩니다.

## ⑥ 확인 문제

**1.** 수집한 데이터를 Parquet 파일에 계속 쌓아 두면 어떤 문제가 생기나요? 세 가지 이상 들고, 각각을 DB가 어떻게 해결하는지 쓰세요.

<details>
<summary>답 보기</summary>

| 파일의 문제 | DB의 해결 |
|---|---|
| **조건 조회에 전체 읽기** — "PM10 > 100" 한 줄을 찾으려고 1억 행을 메모리에 올림 | **인덱스**로 해당 부분만 찾아감 ([Day 038](day-038.md)) |
| **갱신 손실** — 두 프로세스가 읽기·쓰기를 겹치면 한쪽 결과가 조용히 사라짐 | **트랜잭션·동시성 제어**로 순서를 보장 ([Day 039](day-039.md)) |
| **중복 방지를 직접 구현** — 상태 파일을 따로 관리해야 함 | `UNIQUE` 제약 · `ON CONFLICT` 한 줄 ([Day 042](day-042.md)) |
| **결합에 전체 메모리** — 두 파일을 다 읽어야 `merge` 가능 | `JOIN` 으로 필요한 부분만 결합 ([Day 034](day-034.md)) |
| **타입이 안 지켜짐** — 숫자 열에 문자열이 섞여 들어옴 | 열마다 **타입 고정**, 위반하면 `INSERT` 자체가 실패 |

에러 없이 조용히 잘못되는 **갱신 손실**을 답에 넣었다면 특히 좋습니다. 로그에도 안 남는 사고이기 때문입니다.
</details>

**2.** `orders` 테이블에 고객 이름·이메일·전화번호를 직접 넣지 않고 `customer_id` 하나만 넣는 이유는 무엇인가요?

<details>
<summary>답 보기</summary>

**① 중복 저장을 없애기 위해서.** 김민수 님이 주문을 100번 하면 이름·이메일·전화번호가 100번 저장됩니다. 용량 낭비입니다.

**② 값을 고칠 때 한 곳만 고치기 위해서.** 김민수 님이 전화번호를 바꾸면, 이름을 직접 넣는 방식에서는 주문 100건을 전부 찾아 고쳐야 합니다.
한 건이라도 놓치면 **같은 사람인데 정보가 다른** 데이터가 생깁니다. `customer_id` 만 있으면 `customers` 테이블 한 줄만 고치면 끝입니다.

**③ 무결성을 지키기 위해서.** `REFERENCES customers(customer_id)` 덕분에 **존재하지 않는 고객 번호로는 주문을 넣을 수 없습니다.**
DB가 막아 줍니다.

이 원칙을 체계화한 것이 **정규화**이고 [Day 039](day-039.md)에서 다룹니다.
반대로 `unit_price` 는 `products.price` 와 겹치는데도 일부러 따로 저장했습니다.
"주문 당시의 가격"은 **그 시점에 박제돼야 하는 값**이라, 상품 가격이 나중에 바뀌어도 따라 변하면 안 되기 때문입니다.
</details>

**3.** `docker run` 명령에서 `-p 5432:5432` 와 `-v mlops-pgdata:/var/lib/postgresql/data` 는 각각 무슨 일을 하나요? 빠뜨리면 어떻게 되나요?

<details>
<summary>답 보기</summary>

**`-p 5432:5432`** — 내 컴퓨터의 5432 포트를 컨테이너의 5432 포트에 연결합니다(포트 포워딩).
빠뜨리면 `docker exec` 로 컨테이너 **안에서는** 접속되지만, DBeaver나 Python([Day 041](day-041.md))처럼
**바깥에서 `localhost:5432` 로 붙는 클라이언트는 연결에 실패**합니다.

**`-v mlops-pgdata:/var/lib/postgresql/data`** — 컨테이너 안의 데이터 폴더를 `mlops-pgdata` 라는 **볼륨**(컨테이너 바깥 저장소)에 연결합니다.
빠뜨리면 데이터가 컨테이너 안에만 있어서, `docker rm` 으로 컨테이너를 지우는 순간 **DB 내용이 전부 사라집니다.**
컨테이너는 언제든 지웠다 다시 만드는 물건이라, 데이터는 반드시 바깥에 둬야 합니다.

`docker start` / `docker stop` 은 컨테이너를 지우지 않으므로 데이터에 영향이 없습니다. 위험한 건 `docker rm` 입니다.
</details>

## 부록 · Docker 없이 하기

회사·학교 정책으로 Docker를 설치할 수 없다면 PostgreSQL을 직접 설치해도 됩니다. **이후 실습은 전부 동일합니다.**

1. <https://www.postgresql.org/download/windows/> 에서 **PostgreSQL 16** 설치 프로그램 실행
2. 설치 중 `postgres` 비밀번호를 `mlops1234` 로, 포트는 `5432` 로 지정
3. 설치 옵션에서 **Command Line Tools** 를 반드시 포함
4. 설치 후 접속

```powershell
$ psql -U postgres
Password for user postgres:
psql (16.4)
Type "help" for help.

postgres=#
```

명령 대응표입니다.

| 이 문서의 명령 (Docker) | 직접 설치했을 때 |
|---|---|
| `docker exec -it mlops-pg psql -U postgres` | `psql -U postgres` |
| `docker exec -it mlops-pg psql -U postgres -d shop` | `psql -U postgres -d shop` |
| `docker cp` + `psql -f /tmp/shop_sample.sql` | `psql -U postgres -d shop -f shop_sample.sql` |
| `docker start mlops-pg` | (서비스로 자동 실행됨) |

> 다만 **W24부터는 Docker가 필수**입니다. 그때까지 설치 방법을 확보해 두세요.

## 오늘의 정리

| 명령 | 하는 일 |
|---|---|
| `docker run --name mlops-pg ... -d postgres:16` | PostgreSQL 컨테이너 생성 (**한 번만**) |
| `docker start mlops-pg` / `docker stop mlops-pg` | 껐다 켜기 (**매일 이것만**) |
| `docker exec -it mlops-pg psql -U postgres -d shop` | psql 접속 |
| `docker cp 파일 mlops-pg:/tmp/` | 컨테이너로 파일 복사 |
| `\l` · `\c 이름` | DB 목록 · DB 이동 |
| `\dt` · `\d 테이블` | 테이블 목록 · **테이블 구조** |
| `\x` · `\q` | 세로 출력 토글 · 종료 |

| 개념 | 한 줄 정의 |
|---|---|
| 테이블 · 행 · 열 | 표 · 데이터 한 건 · 타입이 고정된 항목 |
| 기본키(PK) | 행 하나를 유일하게 가리키는 열 |
| 외래키(FK) | 다른 테이블의 기본키를 가리켜 **관계를 만드는** 열 |
| 접속 정보 5요소 | host · port · database · user · password |

**오늘의 습관** — 실습을 시작할 때 `docker start mlops-pg`, 접속하면 제일 먼저 `\dt`.
"지금 어느 DB에 붙어 있는가"를 항상 프롬프트로 확인하는 버릇을 들이세요. 사고의 절반은 여기서 납니다.

**과제 — 테이블 구조 탐색 리포트**

`docs/db_exploration.md` 를 만들어 아래를 채우고 커밋하세요.

1. `\dt` 결과 — 테이블 4개 목록
2. 테이블별 `\d` 결과를 보고 정리한 표 — 열 이름 · 타입 · NULL 허용 여부 · PK/FK 표시
3. 테이블별 행 수 (`COUNT(*)`)
4. `Foreign-key constraints` · `Referenced by` 를 따라가며 그린 **관계도** (③번의 ASCII 그림 형태로 직접)
5. **이 데이터로 답하고 싶은 질문 3개** — 한국어 문장으로 (예: "가장 많이 팔린 상품은?")

5번은 [Day 035](day-035.md)에서 SQL로 직접 옮기게 됩니다. 지금 쓴 질문을 그날 다시 꺼내세요.
