## ① 학습 목표

이 레슨을 마치면 이렇게 할 수 있습니다.

- 사전학습(pretraining)이 무엇이고 왜 **적은 데이터의 구원**인지 설명할 수 있다.
- **특징 추출**(동결) 방식의 전이학습을 구현할 수 있다 (`requires_grad=False` + 머리 교체).
- 특징 추출 vs **파인튜닝**의 선택 기준과 학습률 전략을 안다.
- 사전학습 모델의 **전처리 통계를 그대로 따라야 하는 이유**를 안다.

---

## ② 왜 필요한가

현실의 이미지 과제는 CIFAR처럼 5만 장을 주지 않습니다.

```
"불량 부품 사진으로 분류기를" — 라벨된 사진: 300장
"측정소 CCTV로 시정 흐림 판정" — 라벨된 프레임: 수백 장
```

어제의 결론대로면 절망입니다 — CNN도 결국 데이터가 필요한데, 245장으로 무엇을 배우겠습니까.
실제로 오늘 첫 실험에서 어제의 CNN은 245장 앞에서 무너집니다(0.68에서 오락가락).

탈출구는 [Day 088](day-088.md)에서 텍스트로 먼저 본 그 발상입니다 — **남이 대형 데이터로
배운 것을 빌린다.** ImageNet(120만 장, 1000종)으로 학습된 ResNet의 몸통은 모서리·질감·
부위 같은 **범용 시각 특징**을 이미 압니다. 우리는 그 위에 "개미냐 벌이냐"라는 머리만
얹으면 됩니다. 오늘 그 효과를 숫자로 봅니다: **학습 파라미터 1,026개로 정확도 0.954.**

(순서에 대한 안내 — 이 문서 묶음에서는 이미지의 전이학습을 먼저 배우고, W18에서 같은 구도가
텍스트에서 반복됩니다. 개념은 한 번 잡으면 양쪽에서 통합니다.)

## ③ 개념 설명

### 사전학습 모델 — 시각의 공통 밑천

ImageNet급 학습이 만들어 내는 것은 "1000개 클래스 분류기"가 아니라 그 과정에서 생긴
**특징 추출기**입니다 — 어제 본 계층(모서리→질감→부위)이 크고 좋게 완성된 것.
이 밑천은 개미/벌에도, 불량 부품에도, CCTV 프레임에도 대부분 통합니다.

### 두 가지 전이 전략

| | **특징 추출** (오늘) | 파인튜닝 |
|---|---|---|
| 몸통 | **동결** (`requires_grad=False`) | 아주 작은 학습률로 함께 학습 |
| 학습 대상 | 새 머리만 (수백~수천 개) | 전체 (수백만 개) |
| 데이터 요구 | 수백 장이면 충분 | 수천 장 이상 권장 |
| 비용·위험 | 싸고 안전 (과적합 어려움) | 비싸고 망각·과적합 위험 |
| 선택 기준 | 데이터가 적다 / 도메인이 ImageNet과 비슷 | 데이터가 있다 / 도메인이 많이 다름 (X-ray 등) |

관례: **특징 추출부터 시작**해 베이스라인을 잡고, 아쉬우면 뒷부분 층부터 조금씩 풀어
파인튜닝합니다 (학습률은 1/10 이하로 — W18에서 텍스트 파인튜닝을 할 때 그 감각을 씁니다).

### 전처리도 빌려 온 계약의 일부

사전학습 모델은 **자기가 학습할 때 본 형식**의 입력을 기대합니다. ResNet이면:
224×224 크기, ImageNet의 채널 통계(평균 [0.485, 0.456, 0.406] / 표준편차 [0.229, 0.224, 0.225])로
표준화된 텐서. 우리 데이터 통계가 아니라 **그 모델의 통계**를 쓰는 것 —
[Day 097](day-097.md) "학습 전처리 = 서빙 전처리"의 변주로, "**사전학습 전처리 = 내 전처리**"입니다.

## ④ 단계별 실습

`day083_transfer.py` 에 이어 붙입니다.

### Step 1. 데이터 — 개미 vs 벌 245장 (1~2교시)

PyTorch 공식 튜토리얼의 유명한 미니 데이터셋입니다. 폴더 구조가 곧 라벨입니다:

```
data/hymenoptera_data/
├── train/ants/*.jpg   train/bees/*.jpg      (총 244장)
└── val/ants/*.jpg     val/bees/*.jpg        (153장)
```

```python
# day083_transfer.py — 전이학습: 245장으로 분류기
import time
import torch
import torch.nn as nn
from torch.utils.data import DataLoader
from torchvision import datasets, models, transforms

torch.manual_seed(42)

print("== A. 데이터: 개미 vs 벌, 고작 245장 ==")
tf = transforms.Compose([
    transforms.Resize(256), transforms.CenterCrop(224),       # ResNet의 표준 입력 224×224
    transforms.ToTensor(),
    transforms.Normalize([0.485, 0.456, 0.406], [0.229, 0.224, 0.225]),  # ImageNet 통계 — 사전학습과 같은 자!
])
train_ds = datasets.ImageFolder("data/hymenoptera_data/train", transform=tf)
valid_ds = datasets.ImageFolder("data/hymenoptera_data/val", transform=tf)
print(f"train {len(train_ds)}장 / valid {len(valid_ds)}장 · 클래스 {train_ds.classes}")
train_dl = DataLoader(train_ds, batch_size=32, shuffle=True)
valid_dl = DataLoader(valid_ds, batch_size=64)
```

실행 결과:

```
== A. 데이터: 개미 vs 벌, 고작 245장 ==
train 244장 / valid 153장 · 클래스 ['ants', 'bees']
```

`ImageFolder` — "폴더명 = 클래스"라는 관례만 지키면 어떤 이미지 뭉치든
Dataset([Day 079](day-079.md)의 두 약속을 대신 구현해 줌)이 됩니다. 여러분의 커스텀 데이터도
이 구조로 폴더만 정리하면 오늘 코드가 그대로 돕니다 — MP3 재료의 규격입니다.

### Step 2. 도전자 1 — 바닥부터 CNN (3교시)

```python
def accuracy(model, dl):
    model.eval()
    hit = n = 0
    with torch.no_grad():
        for xb, yb in dl:
            hit += (model(xb).argmax(dim=1) == yb).sum().item()
            n += len(yb)
    return hit / n


print("\n== B. 도전자 1: 어제의 CNN을 바닥부터 ==")
scratch = nn.Sequential(
    nn.Conv2d(3, 32, 3, padding=1), nn.ReLU(), nn.MaxPool2d(4),   # 224→56
    nn.Conv2d(32, 64, 3, padding=1), nn.ReLU(), nn.MaxPool2d(4),  # 56→14
    nn.Flatten(), nn.Linear(64 * 14 * 14, 64), nn.ReLU(), nn.Dropout(0.5),
    nn.Linear(64, 2),
)
opt = torch.optim.Adam(scratch.parameters(), lr=0.001, weight_decay=1e-4)
loss_fn = nn.CrossEntropyLoss()
t0 = time.perf_counter()
for epoch in range(1, 6):
    scratch.train()
    for xb, yb in train_dl:
        loss = loss_fn(scratch(xb), yb)
        loss.backward(); opt.step(); opt.zero_grad()
    print(f"  epoch {epoch}: valid acc {accuracy(scratch, valid_dl):.3f}")
print(f"  (5에폭 {time.perf_counter()-t0:.0f}초)")
```

실행 결과:

```
== B. 도전자 1: 어제의 CNN을 바닥부터 ==
  epoch 1: valid acc 0.608
  epoch 2: valid acc 0.654
  epoch 3: valid acc 0.647
  epoch 4: valid acc 0.680
  epoch 5: valid acc 0.562
  (5에폭 37초)
```

0.6대에서 오르내리다 마지막엔 0.562 — 동전(0.5)보다 조금 나은 수준에서 **불안정**합니다.
어제 4,000장에서 통하던 구조가 244장에서는 특징을 만들 재료 자체가 부족합니다.
이것이 "적은 데이터 + 바닥부터"의 현실입니다.

### Step 3. 도전자 2 — ResNet18 특징 추출 (4~6교시)

```python
print("\n== C. 도전자 2: ResNet18 특징 추출 (backbone 동결) ==")
model = models.resnet18(weights=models.ResNet18_Weights.DEFAULT)   # ImageNet 사전학습
for p in model.parameters():
    p.requires_grad = False                                        # 몸통 동결
model.fc = nn.Linear(model.fc.in_features, 2)                      # 머리만 교체 (이건 학습됨)
trainable = sum(p.numel() for p in model.parameters() if p.requires_grad)
total = sum(p.numel() for p in model.parameters())
print(f"전체 {total:,}개 중 학습하는 파라미터: {trainable:,}개 ({trainable/total:.2%})")

opt = torch.optim.Adam(model.fc.parameters(), lr=0.001)
t0 = time.perf_counter()
for epoch in range(1, 6):
    model.train()
    for xb, yb in train_dl:
        loss = loss_fn(model(xb), yb)
        loss.backward(); opt.step(); opt.zero_grad()
    print(f"  epoch {epoch}: valid acc {accuracy(model, valid_dl):.3f}")
print(f"  (5에폭 {time.perf_counter()-t0:.0f}초)")

torch.save({"state_dict": model.state_dict(), "classes": train_ds.classes}, "models/antbee_resnet18.pt")
print("저장: models/antbee_resnet18.pt")
```

실행 결과:

```
== C. 도전자 2: ResNet18 특징 추출 (backbone 동결) ==
전체 11,177,538개 중 학습하는 파라미터: 1,026개 (0.01%)
  epoch 1: valid acc 0.765
  epoch 2: valid acc 0.902
  epoch 3: valid acc 0.928
  epoch 4: valid acc 0.954
  epoch 5: valid acc 0.954
  (5에폭 52초)
저장: models/antbee_resnet18.pt
```

숫자를 천천히 음미하세요.

| | 바닥부터 CNN | ResNet18 특징 추출 |
|---|---|---|
| 학습하는 파라미터 | 811,970개 전부 | **1,026개 (전체의 0.01%)** |
| 최고 valid | 0.680 (불안정) | **0.954 (안정)** |
| 시간 (CPU) | 37초 | 52초 |

1,117만 개 파라미터 중 우리가 학습한 것은 새로 단 머리(512×2+2 = 1,026개)뿐인데
**0.954**입니다. ImageNet 120만 장이 만들어 둔 특징 추출기가 개미와 벌의 차이를 이미
"볼 줄" 알았던 것입니다. 저장 시 `classes` 를 함께 담은 것도 봐 두세요 — 로짓 인덱스를
사람 말로 바꿀 계약([Day 068](../03-machine-learning/day-068.md)의 스키마 정신)이며, 이 파일이
[Day 085](day-085.md) predict.py와 MP3 서빙의 재료가 됩니다.

무너지는지 관찰하세요 — "데이터가 적을수록 덜 푸는" 관례의 근거를 스스로 확인하는 실험입니다.

## ⑤ 자주 하는 실수

### ImageNet 통계 대신 내 데이터 통계로 정규화

**증상** — 에러 없이 학습되는데 정확도가 몇 %p 낮게 나옴 (조용한 손해).
**원인** — 몸통의 필터들은 ImageNet 통계로 표준화된 입력에 맞춰져 있습니다. 다른 자로 잰 입력은 미묘하게 어긋난 세계입니다.
**해결** — 사전학습 모델을 쓸 때는 **그 모델의 전처리**를 그대로 (torchvision은 `ResNet18_Weights.DEFAULT.transforms()` 로 공식 전처리를 제공합니다). 서빙까지 이 계약이 따라갑니다 ([Day 097](day-097.md)·[100](day-100.md)).

### 동결을 잊고 전체를 큰 학습률로 학습

**증상** — 1에폭 만에 valid가 요동치고 사전학습 이점이 사라짐.
**원인** — lr 1e-3이 몸통의 좋은 가중치를 뭉갰습니다 (파괴적 망각 — [Day 089](day-089.md)에서 재회).
**해결** — 특징 추출이면 동결 + 머리만 optimizer에 등록. 파인튜닝이면 lr을 1/10 이하로.

### 머리를 교체했는데 optimizer에 옛 파라미터를 등록

**증상** — loss가 꿈쩍 안 함 — [Day 078](day-078.md) ⑤의 그 사고의 전이학습판.
**원인** — `model.fc` 를 새로 갈아 끼운 **뒤에** optimizer를 만들어야 새 머리가 등록됩니다.
**해결** — 순서 고정: 로드 → 동결 → 머리 교체 → optimizer 생성. 학습 전 `trainable` 개수 출력(오늘 코드)이 좋은 자가 진단입니다.

### 클래스 수를 안 바꾸고 그대로 씀

**증상** — 출력이 1000차원이라 loss 계산에서 라벨 범위 에러, 또는 이상한 학습.
**원인** — ResNet의 기본 머리는 ImageNet 1000클래스용입니다.
**해결** — `model.fc = nn.Linear(model.fc.in_features, 내_클래스_수)`. HF에서 `num_labels=2` 를 주는 것과 같은 행위입니다.

### 사전학습 가중치의 라이선스·출처를 안 남김

**증상** — MP3 문서에서 "이 모델 어디서 왔죠?"에 답 못 함.
**원인** — torchvision 가중치도 조달입니다 ([Day 088](day-088.md)의 규율은 이미지에도 적용).
**해결** — model_sourcing.md에 한 줄: ResNet18 / ImageNet 사전학습 / torchvision 제공 / 라이선스 확인일. 모델 카드([Day 069](../03-machine-learning/day-069.md))의 "데이터 출처" 칸에도 들어갑니다.

## ⑥ 확인 문제

**Q1.** 오늘 학습된 파라미터는 1,026개뿐인데 0.954가 나온 이유를 "특징 추출기"라는 단어로
설명하고, 1,026이라는 숫자의 출처를 계산해 보세요.

<details>
<summary>답 보기</summary>

ImageNet 사전학습이 만든 몸통이 이미 범용 시각 특징(모서리→질감→부위)을 추출해 주므로, 우리는
그 512차원 특징 위에 선형 경계 하나만 그으면 됐습니다. 1,026 = 512(특징)×2(클래스) + 2(편향).
사실상 "ResNet 특징 위의 로지스틱 회귀"를 학습한 것과 같습니다 — [Day 057](../03-machine-learning/day-057.md)의
그 모델이 좋은 특성만 있으면 얼마나 강한지의 재확인이기도 합니다.

</details>

다음을 판정하세요: ① 폐 X-ray 3만 장 ② 일상 물건 사진 200장 ③ 위성 사진 800장.
