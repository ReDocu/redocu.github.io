1프로그램 개요 · 현황

소규모 팀의 운영 허브 — 메뉴얼·프로젝트 일정(간트)·게시판/채팅·참조 자료·사내 서재를 한 주소에서 제공하는 Next.js 단일 웹앱. PC·모바일 브라우저와, 같은 주소를 원격 로드하는 Android 껍데기 앱이 동일한 화면을 쓴다.

항목내용
저장소 루트ops/ — 프로젝트 폴더(CompanySystem/)가 아니라 ops가 git 저장소다. 모든 npm 명령·커밋·배포 기준.
두 갈래 데이터운영 데이터(프로젝트·일정·글·메시지) = Supabase 16테이블 / 읽기용 콘텐츠(메뉴얼·학습·소설) = content/**.md 파일
상태 소유클라이언트 단일 컨텍스트 WorkspaceProvider가 전 화면 상태를 소유 — 화면은 update(fn)만 호출하고 저장 경로를 모른다
접근 통제미들웨어 기반 팀 공용 비밀번호 게이트(HttpOnly 쿠키). 앱 내부 로그인(초대코드)은 기능 플래그로 꺼져 있음
전제 환경Node 20+ · npm · 브라우저. DB 키가 없으면 localStorage 폴백으로 그대로 동작

현황 (2026-07-28 실측)

  • 데이터 층 이전 완료 — store.tsx + sync.ts가 16테이블 로드/저장을 담당. 컴포넌트는 수정 없이 그대로 쓴다.
  • 콘텐츠는 파일 기반 — content/manual · study · novel의 md를 서버가 읽어 API로 내려준다. 앱 내 업로드 UI는 없다(커밋으로 반영).
  • 인증 단계 비활성 — flags.ts의 AUTH_STEPS_ENABLED = false. 게이트를 통과하면 BYPASS_SESSION(admin)이 자동 부여된다. true로 되돌리면 로그인·초대코드 흐름이 되살아난다.
  • 빈 템플릿 상태 — seed.ts는 빈 구조를 반환한다. 예시 데이터가 든 스냅샷은 git template 브랜치에 보존.
  • 실시간 없음 — Supabase Realtime 미적용. 다른 사람의 변경은 새로고침(재로드) 시 반영된다.

2시스템 아키텍처 — UML 컴포넌트 다이어그램

요청은 예외 없이 middleware.ts를 먼저 지난다. 통과한 뒤에야 화면·API가 열리고, 화면 상태는 store.tsx 하나가 소유한다. 저장 경로(Supabase / localStorage)의 분기는 store에서 끝나며, 콘텐츠 읽기는 서버 전용 content.ts에서만 일어난다.

component diagram — 실행 컴포넌트와 주요 호출 경로

핵심 계약은 두 개다. ① 화면 ↔ 상태: useWorkspace() → { data, update } — 화면은 저장소를 모른다. ② 서버 ↔ 콘텐츠: GET /api/docs = { docs: ContentDoc[] } · GET /api/novels = { novels: ContentNovel[] } — 파일이 곧 화면이다.

6상태 전이 — UML 상태머신

왼쪽: 화면에서 다루는 도메인 상태(프로젝트 · 아이디어). 오른쪽: 접속·세션 상태. 접속 상태는 쿠키(서버 판정)와 세션(클라이언트 판정)이 분리돼 있고, 둘 다 통과해야 화면이 보인다.

state machine — 프로젝트 status · 아이디어 · 접속/세션

가드는 두 겹이지만 성격이 다르다 — 게이트(미들웨어·쿠키)는 서버가 강제하는 실제 차단이고, 세션 가드(레이아웃)는 화면 전환용이다. 현재 AUTH_STEPS_ENABLED = false라 세션 가드는 사실상 통과되므로, 실효 보호선은 게이트 하나다.

배열 14 + 맵 2 = 16 테이블. 배열 항목은 전부 id: string을 가지며, 이 id가 동기화·백업·복원의 유일한 키다.

7.2 스키마 설계 규칙

  • 컬럼명 = 앱 필드명(camelCase) — 매핑 코드를 없애기 위한 선택. Postgres는 기본이 소문자라 "joinedAt"처럼 큰따옴표로 인용한다. "end"는 예약어라 반드시 인용.
  • 날짜·시간은 text — 앱이 쓰는 문자열(ISO 또는 yyyy-mm-dd)을 왕복 변환 없이 그대로 보존한다.
  • 항상 함께 편집되는 중첩 배열은 jsonb — segments · logs · comments · chapters · tags. 개별 행으로 쪼개지 않는다.
  • id는 text — 앱이 만든 문자열 id(uid() 기반)를 그대로 PK로 쓴다. DB 생성 id를 쓰지 않으므로 오프라인 폴백과 동일한 데이터 형태가 유지된다.
  • project_roles → projects만 FK(on delete cascade). 나머지는 느슨한 참조라 고아 행이 화면을 깨지 않는다.

9상태 관리 · 동기화 설계

9.1 단일 상태 · 낙관적 갱신

  • 상태 소유자는 하나 — WorkspaceProvider. 화면은 useWorkspace()로 읽고 update(fn)으로 쓴다. 저장 대상(DB냐 로컬이냐)은 화면이 알지 못한다.
  • 로드는 마운트 1회 — 이후 폴링이나 구독이 없다. ready가 될 때까지 Provider가 null을 렌더해 미완성 화면이 깜빡이지 않는다.
  • 쓰기는 낙관적 — setData(next)로 화면을 먼저 갱신하고, DB 반영은 void syncWorkspace(...)로 흘려보낸다. 실패해도 화면은 멈추지 않고 콘솔에 기록만 남는다(= 새로고침하면 되돌아갈 수 있음).
  • 최신값은 dataRef — diff 계산에 렌더 사이의 낡은 클로저 값이 섞이지 않도록 ref로 병행 보관한다.

9.2 동기화 규칙 (sync.ts)

대상판정동작
배열 테이블 14종참조가 같으면 즉시 건너뜀 (불변 갱신 전제)—
변경·신규 행prev에 없거나 JSON.stringify 결과가 다름upsert(rows)
사라진 행prev에 있고 next의 id 집합에 없음delete().in("id", ids)
맵 테이블 2종값이 달라진 key만 추림upsert({key, val})
맵에서 사라진 keyprev에만 존재delete().in(keyCol, keys)
전체Promise.allSettled일부 실패해도 나머지는 반영 · 실패는 console.error
동시 편집은 last-write-wins다. 같은 행을 두 사람이 동시에 고치면 나중 저장이 이긴다. 버전 컬럼·충돌 감지·Realtime 구독은 현재 없다 — 필요해지면 이 지점(§9.2)이 확장 대상이다.

9.3 폴백 경로

  • supabase.ts가 env 부재 시 null + isSupabaseConfigured=false를 내보내고, store가 이를 보고 localStorage("tw.data.v2") 전량 저장 방식으로 전환한다.
  • 로컬 데이터가 깨졌거나 구버전 형태(roles·novels 누락)면 createSeed()로 되돌린다.
  • DB 로드가 예외로 실패하면 빈 상태로 시작한다(화면은 뜬다). 세션·테마는 어느 모드에서든 항상 로컬 저장이다.

10콘텐츠 파이프라인 (파일 → 화면)

폴더가 곧 화면이다. content/에 md를 넣고 새로고침하면 반영되고, 라이브에는 커밋·푸시로 배포된다. 파서는 content.ts 하나뿐이며 변환 프롬프트(docs/prompts/)가 이 파서의 입력 형식에 1:1로 맞춰져 있다.

폴더화면규칙
content/manual/*.md필수 메뉴얼 (홈) · /manual/<slug>파일명 = 슬러그 · frontmatter(title·category·summary·updated·tags)
content/study/*.md학습 문서 · /docs/<slug>동일 + field(분야) · purpose(목적) · related
content/novel/<작품>/NN_*.md서재 · /novels/<slug>파일 하나 = 한 화 · 파일명 순 정렬 · 첫 # 줄이 화 제목
content/novel/<작품>/_index.md작품 정보title·author·status·note·featured (없으면 폴더명에서 유추)
content/study/html/표시 안 됨변환 전 HTML 원본 보관처 — 앱은 .md만 읽는다

파서 세부 (실측)

  • frontmatter는 미니 파서다 — --- 블록의 key: value를 읽어 [a, b]는 배열, 숫자만 있으면 number, 나머지는 따옴표를 벗긴 문자열로 만든다. 중첩 YAML은 지원하지 않는다.
  • 문서 정렬은 updated 내림차순, 소설 정렬은 제목 한국어 로케일 기준이다.
  • 소설 폴더는 재귀 탐색한다 — 하위 폴더도 독립 작품이 되고, slug는 경로를 --로 이어 만든다(예: 작품--생애).
  • 화 본문은 빈 줄 기준으로 문단을 나누고, 각 문단 안의 줄바꿈은 공백으로 합친다. ## 이상 소제목은 기호만 벗겨 문단으로 넣고, --- 구분선은 버린다.
  • 실패 내성 — 읽기·파싱이 실패한 파일/폴더는 조용히 건너뛰고 나머지를 반환한다. 한 파일이 목록 전체를 깨뜨리지 않는다.
배포 시 주의 — 이 경로는 런타임 fs 읽기라 서버리스 번들 추적이 자동으로 되지 않는다. next.config.ts의 outputFileTracingIncludes에서 ./content/**/*를 함수에 포함시키고 있으며, 이 설정을 빼면 배포 환경에서만 문서·소설이 빈 채로 뜬다(로컬은 정상이라 놓치기 쉽다).

11보안 · 불변 규칙

11.1 보안 설계

  • 비밀번호는 서버에만 — 원문은 process.env.APP_PASSWORD로만 존재하고 클라이언트 번들·응답에 실리지 않는다. 쿠키에는 SHA-256("companyos::gate::" + 비밀번호) 파생 토큰만 담긴다.
  • 쿠키 속성 — httpOnly · sameSite=lax · 프로덕션에서 secure · path=/ · 30일.
  • 타이밍 둔감 비교 — safeEqual()은 길이가 달라도 조기 반환하지 않고 XOR 누적으로 판정한다.
  • 오픈 리다이렉트 차단 — /gate의 next는 safeNext()로 /로 시작하고 //가 아닌 내부 경로만 허용한다.
  • Edge/Node 토큰 일치 — 미들웨어(Edge)와 API(Node)가 같은 lib/gate.ts를 쓰고 Web Crypto만 사용해, 런타임이 달라도 판정이 갈리지 않는다.
  • 시크릿은 미추적 — .env*(단 .env.example 제외) · /backup/ · /docs/*.txt가 .gitignore로 선제 차단된다.

11.2 알려진 보안 한계 (설계상 수용)

  • DB는 공개 anon 키로 접근한다. 로그인이 Supabase Auth가 아니라서 RLS 정책은 anon/authenticated 전체 허용이며, 실제 통제는 앱 게이트에 의존한다. NEXT_PUBLIC_* 값은 브라우저 번들에 포함되므로 공개 전제로만 써야 한다.
  • 사용자별 데이터 보호가 필요해지면 순서는 정해져 있다 — ① Supabase Auth 도입 → ② 정책을 auth.uid() 기준으로 좁히기 → ③ flags.ts의 인증 단계 복구.
  • 게이트는 팀 단위 공유 비밀이라 개인 식별·감사 기능이 없다. 관리자 화면의 로그인 이력은 앱이 기록한 값이지 인증 로그가 아니다.

11.3 불변 규칙 (어기면 재발하는 문제)

  1. 상태 변경은 반드시 update(fn)로 — 불변 갱신(새 배열/객체)을 지켜야 sync의 참조 비교가 성립한다. 배열을 제자리 수정하면 저장이 조용히 누락된다.
  2. lib/content.ts는 서버 전용 — 클라이언트 컴포넌트에서 import하면 node:fs 때문에 빌드가 깨진다. 화면은 useDocs 훅만 쓴다.
  3. 미들웨어는 Edge 런타임 — Node API·supabase-js를 들이지 않는다. 공유 로직은 Web Crypto만 쓰는 gate.ts에 둔다.
  4. 새 화면·정적 자산을 게이트 밖에 두려면 PUBLIC_PREFIXES/PUBLIC_EXACT에 명시한다(현재 예외: gate·api/gate·icons·downloads·manifest·favicon).
  5. 새 컬렉션을 추가할 때는 세 곳을 함께 고친다 — types.ts(WorkspaceData) · sync.ts(ARRAY_TABLES) · schema.sql. 백업 대상이면 backup.ts의 키 목록도.
  6. DB 컬럼은 앱 필드명 그대로 — 예약어(end)와 대문자는 큰따옴표로 인용한다.
  7. content/**는 outputFileTracingIncludes에 유지 — 라우트를 새로 만들어 파일을 읽으면 그 라우트도 목록에 추가한다.
  8. 실제 비밀값은 .env.local과 호스팅 환경변수에만 — 문서·스크린샷·커밋에 남기지 않는다.

12.3 알려진 경계 · 현재 비목표

  • 실시간 동기화 없음 — Realtime 구독 미적용. 다른 사람의 변경은 재로드 시점에 보인다. 채팅도 같은 조건.
  • 충돌 처리 없음 — 같은 행 동시 편집은 마지막 저장이 이긴다(§9.2).
  • 파일 업로드 UI 없음 — 메뉴얼·학습·소설은 저장소 커밋으로만 추가된다. 첨부파일·Storage 미사용.

  • 검색은 클라이언트 필터 — 전체 텍스트 검색·인덱스 없음. 데이터가 커지면 이 지점이 먼저 한계에 닿는다.
  • 테스트 없음 — 자동화된 테스트 스위트가 없다. 검증은 npm run build(타입 검사 포함)와 수동 확인에 의존한다.
