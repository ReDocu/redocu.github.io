## 2. 왜 발표를 하는가

**코드가 돌아가는 것과 설명할 수 있는 것은 다르다.**

```
   "돌아갑니다"만 아는 상태

   → 다른 게임에 응용을 못 한다
   → 버그가 나면 어디를 봐야 할지 모른다
   → 면접에서 설명하지 못한다


   "왜 이렇게 만들었는지" 아는 상태

   → 다음 프로젝트에 그대로 가져다 쓴다
   → 문제가 생기면 원인을 좁힐 수 있다
   → 포트폴리오가 된다
```

그리고 오늘은 **6주간 배운 것이 실제로 남았는지 확인하는 날**이기도 하다.

```
   Part 2(WINAPI)는 Part 1 위에 그대로 얹힌다

   포인터를 모르면        →  프레임워크 설계를 못 따라온다 (Day 39)
   다형성을 모르면        →  오브젝트 구조를 못 만든다 (Day 40)
   게임 루프를 모르면     →  PeekMessage 루프를 이해 못 한다 (Day 38)
   AABB를 모르면          →  판정 박스를 못 만든다 (Day 47)

   ★ 오늘 구멍을 찾아 메우고 넘어간다
```

## 3. 발표

### 3-1. 발표 구성 (3분)

```
   ┌───────────────────────────────────────────────────┐
   │  ① 무엇을 만들었나        30초   실행하며 시연     │
   │  ② 어떻게 만들었나        60초   클래스 구조       │
   │  ③ 무엇이 어려웠나        60초   ★ 가장 중요       │
   │  ④ 다음에 한다면          30초   개선 아이디어     │
   └───────────────────────────────────────────────────┘
```

**① 무엇을 만들었나 (30초)**

```
   ✔ "쫓아오는 몬스터를 피해 열쇠를 찾아 탈출하는 미로 게임입니다."
     (실행하며 30초 플레이 시연)

   ✘ "미로 탈출을 확장했고요, 몬스터도 넣었고, 스테이지도 3개 만들었고,
      원래는 시야 제한도 하려고 했는데 시간이..."
```

> **한 문장으로 시작한다.** 나머지는 뒤에서 설명한다.

**② 어떻게 만들었나 (60초)**

```
   클래스 구조를 그림으로 준비한다 (종이나 화면)

                GameObject
                     ▲
        ┌────────┬───┴────┬────────┐
     Player   Monster   Item     Exit

   "GameObject를 상속받아 네 종류를 만들었고,
    ObjectManager가 배열 하나로 전부 Update/Render 합니다."
```

**③ 무엇이 어려웠나 (60초) — 가장 중요**

```
   구조:  문제 → 왜 그랬는지 → 어떻게 풀었는지 → 배운 것

   예)
   "몬스터가 벽에 막히면 제자리에서 부들부들 떨었습니다.
    x 방향으로 가려는데 벽이라 못 가고, 다음 프레임에 또 같은 판단을 해서였습니다.
    '더 먼 축부터 시도하고, 막히면 다른 축으로' 규칙을 넣어 완화했는데
    완전한 해결은 아니었습니다. 길찾기 알고리즘이 필요하다는 걸 알게 됐습니다."
```

> **해결하지 못한 것도 좋은 발표 소재다.**
> "무엇이 문제인지 정확히 안다"는 것 자체가 실력이다.

**④ 다음에 한다면 (30초)**

```
   "다시 만든다면 몬스터 이동을 BFS로 바꿔 보고 싶습니다."
   "구조는 만족스러운데 충돌 처리가 Game 클래스에 몰려 있어서 나눠야 할 것 같습니다."
```

### 5-3. 자가 점검표

**전부 체크되어야 Part 2로 넘어갈 준비가 된 것이다.**

**기초 (Week 1~3)**

- [ ] 변수·조건·반복·함수·구조체를 게임 코드 안에서 설명할 수 있다
- [ ] 어떤 입력을 넣어도 죽지 않는 입력 처리를 짤 수 있다
- [ ] `map[y][x]`의 순서를 설명할 수 있다
- [ ] 2차원 배열로 맵을 표현하고 좌표 이동·경계 검사를 구현할 수 있다
- [ ] 경계 검사를 벽 판정보다 먼저 해야 하는 이유를 안다

**포인터와 메모리 (Week 4)**

- [ ] `&`와 `*`의 차이를 설명할 수 있다
- [ ] 포인터로 함수 밖 값을 바꿀 수 있고, 그 원리를 설명할 수 있다
- [ ] `malloc`/`free`, `new`/`delete`를 짝 맞춰 쓸 수 있다
- [ ] 배열 이름이 왜 주소인지 안다
- [ ] 메모리 누수가 무엇인지 알고 확인할 수 있다

**게임 루프 (Week 5)**

- [ ] 게임 루프 3단계를 그림으로 그릴 수 있다
- [ ] `_kbhit`이 왜 필요한지 설명할 수 있다
- [ ] 델타 타임이 없으면 무엇이 깨지는지 시연할 수 있다
- [ ] AABB 겹침 조건을 외우지 않고 유도할 수 있다
- [ ] 충돌 후 위치 보정이 왜 필요한지 안다

**C++ (Week 6)**

- [ ] 파일로 데이터를 저장하고 다시 읽을 수 있다
- [ ] 클래스와 구조체의 차이를 설명할 수 있다
- [ ] `private`으로 감추는 이유를 설명할 수 있다
- [ ] `virtual`을 빼면 무엇이 깨지는지 직접 보여줄 수 있다
- [ ] 가상 소멸자가 없으면 무엇이 문제인지 안다
- [ ] 다형성이 왜 포인터로만 되는지 안다

> **체크 안 된 항목이 있으면 오늘 밤에 해당 Day 문서를 다시 읽는다.**
