## 3. 개념

### 3-1. 메모리 DC와 비트맵 — 안 보이는 도화지

**왜 필요한가** — 화면이 아닌 곳에 그리려면 두 가지가 필요하다.

```cpp
    HDC     memDC  = CreateCompatibleDC(hdc);              // ① 도화지 받침대
    HBITMAP bitmap = CreateCompatibleBitmap(hdc, w, h);    // ② 실제 종이
    HBITMAP oldBmp = (HBITMAP)SelectObject(memDC, bitmap); // ③ 받침대에 종이 끼우기
```

```
   ┌──────────────────────────────────────────────────────────┐
   │  왜 두 개가 필요한가?                                      │
   │                                                           │
   │  HDC     = "그리는 도구 세트" (펜, 브러시, 폰트, 대상)     │
   │  HBITMAP = "실제 픽셀이 저장되는 곳"                       │
   │                                                           │
   │  CreateCompatibleDC 로 만든 DC는                          │
   │  기본적으로 1×1 흑백 비트맵을 갖고 있다                    │
   │  → 쓸모없다. 제대로 된 비트맵을 만들어 끼워야 한다         │
   └──────────────────────────────────────────────────────────┘
```

### 3-2. ⚠️ `CreateCompatibleBitmap`의 첫 인자

**왜 필요한가** — 여기서 틀리면 화면이 흑백으로 나온다.

```cpp
    HBITMAP bmp = CreateCompatibleBitmap(hdc, w, h);       // ✔ 화면 DC
    HBITMAP bmp = CreateCompatibleBitmap(memDC, w, h);     // ✘ 메모리 DC
```

```
   CreateCompatibleBitmap(hdc, ...)  →  hdc와 "호환되는" 비트맵을 만든다
                                        = 색 깊이(비트 수)를 hdc에서 가져온다

   화면 DC 기준     →  32비트 컬러 비트맵  ✔
   메모리 DC 기준   →  1비트 흑백 비트맵   ✘  (기본 상태가 흑백이라)
```

```
   ★ CreateCompatibleDC 는 memDC 기준으로 만들어도 되지만,
     CreateCompatibleBitmap 은 반드시 화면 DC 기준으로 만든다
```

### 3-3. `BitBlt` — 픽셀 복사

**왜 필요한가** — 백버퍼의 내용을 화면으로 옮긴다.

```cpp
    BitBlt(hdc,   0, 0, w, h,        // 대상: 어디에, 어느 위치, 얼마나
           memDC, 0, 0,              // 원본: 어디서, 어느 위치부터
           SRCCOPY);                 // 방식: 그대로 복사
```

```
   BitBlt(dstDC, dstX, dstY, width, height,
          srcDC, srcX, srcY, rop)

   ┌────────────────────┐        ┌────────────────────┐
   │  srcDC (백버퍼)     │        │  dstDC (화면)       │
   │                    │        │                    │
   │  (srcX,srcY)       │        │  (dstX,dstY)       │
   │      ┌─────────┐   │  ───▶  │      ┌─────────┐   │
   │      │ w × h   │   │        │      │ w × h   │   │
   │      └─────────┘   │        │      └─────────┘   │
   └────────────────────┘        └────────────────────┘
```

**주요 래스터 연산(ROP) 코드**

| 코드 | 동작 |
|---|---|
| **`SRCCOPY`** | 원본을 그대로 복사 ← **거의 항상 이것** |
| `SRCAND` | 원본 AND 대상 (마스크 합성, Day 41) |
| `SRCPAINT` | 원본 OR 대상 |
| `SRCINVERT` | XOR |
| `BLACKNESS` / `WHITENESS` | 전부 검정/흰색으로 |

> `BitBlt`은 **매우 빠르다.** 그래픽 드라이버가 하드웨어 가속을 쓴다.
> 800×600 전체 복사가 보통 0.1ms 이하다.

### 3-4. 전체 흐름

**왜 필요한가** — 순서를 정확히 지켜야 한다.

```
   ┌──────────────────────────────────────────────────────────────┐
   │  WM_PAINT                                                     │
   │                                                               │
   │  ① HDC hdc = BeginPaint(...)         화면 DC 획득             │
   │           ▼                                                   │
   │  ② 백버퍼 준비 (없으면 생성)          memDC + bitmap          │
   │           ▼                                                   │
   │  ③ 백버퍼를 배경색으로 채운다          FillRect(memDC, ...)    │
   │           ▼                                                   │
   │  ④ 백버퍼에 전부 그린다               RenderStars(memDC)      │
   │           ▼                    ★ 여기까지 화면에 아무 변화 없음 │
   │  ⑤ BitBlt(hdc ← memDC)               한 번에 옮긴다           │
   │           ▼                                                   │
   │  ⑥ EndPaint(...)                                              │
   └──────────────────────────────────────────────────────────────┘
```

```cpp
    case WM_PAINT:
        {
            PAINTSTRUCT ps;
            HDC hdc = BeginPaint(hWnd, &ps);

            // ③ 백버퍼 지우기
            RECT rc = { 0, 0, g_clientW, g_clientH };
            FillRect(g_backDC, &rc, g_bgBrush);

            // ④ 백버퍼에 그리기
            RenderStars(g_backDC);
            RenderUI(g_backDC);

            // ⑤ 화면으로 전송
            BitBlt(hdc, 0, 0, g_clientW, g_clientH,
                   g_backDC, 0, 0, SRCCOPY);

            EndPaint(hWnd, &ps);
        }
        return 0;
```

> **`RenderStars(hdc)` → `RenderStars(g_backDC)`** 로 인자만 바꾸면 된다.
> **Day 33에서 `Render(HDC, w, h)` 형태로 분리해 둔 것이 여기서 값을 한다.**

### 3-5. ⚠️ 백버퍼는 한 번만 만든다

**왜 필요한가** — 매 프레임 만들면 게임이 점점 느려지다 멈춘다.

```cpp
    // ✘ 나쁜 방식 — 매 프레임 생성/해제
    case WM_PAINT:
        {
            HDC memDC = CreateCompatibleDC(hdc);                    // 매번!
            HBITMAP bmp = CreateCompatibleBitmap(hdc, w, h);        // 매번!
            // ...
            DeleteObject(bmp);
            DeleteDC(memDC);
        }
```

```
   800×600 비트맵 = 약 1.9MB

   매 프레임 1.9MB를 할당하고 해제한다
   → 초당 60번 × 1.9MB = 114MB/초의 메모리 트래픽
   → 프레임이 뚝뚝 떨어진다
```

```cpp
    // ✔ 좋은 방식 — 한 번 만들고 재사용
    HDC     g_backDC  = NULL;
    HBITMAP g_backBmp = NULL;
    HBITMAP g_oldBmp  = NULL;

    case WM_CREATE:
        CreateBackBuffer(hWnd);
        return 0;

    case WM_DESTROY:
        DestroyBackBuffer();
        PostQuitMessage(0);
        return 0;
```

### 3-6. `WM_SIZE` — 크기가 바뀌면 다시 만든다

**왜 필요한가** — 백버퍼 크기가 창보다 작으면 오른쪽·아래가 안 그려진다.

```cpp
    case WM_SIZE:
        g_clientW = LOWORD(lParam);
        g_clientH = HIWORD(lParam);

        if (g_clientW > 0 && g_clientH > 0)
        {
            DestroyBackBuffer();
            CreateBackBuffer(hWnd);         // ★ 새 크기로 다시 생성
        }
        return 0;
```

```
   창 크기  800×600  →  백버퍼 800×600   ✔ 딱 맞음

   창을 1200×900 으로 늘림
   백버퍼는 여전히 800×600
   → BitBlt 로 800×600 만 복사됨
   → 오른쪽 400px, 아래 300px 이 안 그려진다 (쓰레기 표시)
```

> 창 크기를 고정했다면(Day 31 Step 6) 이 처리가 필요 없지만,
> **넣어 두는 것이 안전하다.** 최소화/복원 시에도 `WM_SIZE`가 온다.

### 3-7. 리소스 해제 — 역순 원칙

**왜 필요한가** — 순서를 틀리면 해제가 안 되거나 크래시한다.

```cpp
void DestroyBackBuffer()
{
    if (g_backDC)
    {
        SelectObject(g_backDC, g_oldBmp);      // ① 원래 비트맵으로 복구
        DeleteObject(g_backBmp);               // ② 우리 비트맵 삭제
        DeleteDC(g_backDC);                    // ③ DC 삭제

        g_backDC  = NULL;
        g_backBmp = NULL;
        g_oldBmp  = NULL;
    }
}
```

```
   생성 순서            해제 순서 (역순)

   CreateCompatibleDC       SelectObject(원래 것)
        ↓                        ↓
   CreateCompatibleBitmap   DeleteObject(비트맵)
        ↓                        ↓
   SelectObject             DeleteDC

   ★ DC가 비트맵을 쓰고 있는 상태에서 비트맵을 지우면 안 된다
     먼저 원래 비트맵으로 되돌려 놓고 지운다
```

| 함수 | 짝 |
|---|---|
| `CreateCompatibleDC` | **`DeleteDC`** (`ReleaseDC` 아님!) |
| `GetDC` | `ReleaseDC` |
| `BeginPaint` | `EndPaint` |
| `CreateCompatibleBitmap` | `DeleteObject` |

### 3-8. `WM_ERASEBKGND`는 여전히 막는다

**왜 필요한가** — 백버퍼를 써도 Windows가 화면을 지우면 깜빡인다.

```cpp
    case WM_ERASEBKGND:
        return 1;                    // 화면 배경 지우기 차단
```

```
   ┌────────────────────────────────────────────────────────┐
   │  더블버퍼링을 해도 WM_ERASEBKGND를 막아야 하는 이유     │
   │                                                         │
   │  ① Windows가 화면 배경을 검게 칠함    ← 여기서 깜빡임   │
   │  ② 우리가 BitBlt로 완성본을 덮어씀                      │
   │                                                         │
   │  ①이 필요 없다. 어차피 ②가 전체를 덮어쓴다.            │
   │  → 막는다                                               │
   └────────────────────────────────────────────────────────┘
```

```
   ★ 세 가지를 모두 한다

   1. WM_ERASEBKGND  →  return 1        (화면 지우기 차단)
   2. 백버퍼에 FillRect                  (백버퍼는 우리가 지운다)
   3. BitBlt 로 전체 덮어쓰기
```

### 3-9. 왜 완전히 사라지는가

**왜 필요한가** — 원리를 확실히 이해하고 넘어간다.

```
   [ 단일 버퍼 ]  한 프레임 = 8ms

   시각    화면 상태
   ────────────────────────────────────
   0.0    완성 화면 (이전 프레임)
   0.1    ████ 전부 검정 ████     ← 불완전
   2.0    · 별 조금               ← 불완전
   5.0    · · · 별 절반           ← 불완전
   8.0    완성 화면
          ▲ 8ms 동안 불완전한 화면이 보인다


   [ 더블 버퍼 ]  한 프레임 = 8ms + 0.1ms

   시각    백버퍼(안 보임)         화면(보임)
   ────────────────────────────────────────────
   0.0    (이전 내용)             완성 화면 A
   0.1    ████ 검정 ████          완성 화면 A    ← 여전히 A
   2.0    · 별 조금               완성 화면 A    ← 여전히 A
   5.0    · · · 별 절반           완성 화면 A    ← 여전히 A
   8.0    완성 화면 B             완성 화면 A
   8.1    완성 화면 B             완성 화면 B    ← 한 번에 교체!

   ★ 화면은 항상 "어떤 완성된 화면"을 보여준다
     불완전한 순간이 0이다  →  깜빡임 0
```

> **`BitBlt` 자체가 0.1ms 정도 걸리지만, 그동안에도 화면은 "이전 완성본 → 새 완성본"으로 바뀔 뿐이다.**
> 사람 눈에는 순간 교체로 보인다.

## 4. 따라 만들기

### Step 1 — 전역 변수와 생성 함수

```cpp
HDC     g_backDC   = NULL;
HBITMAP g_backBmp  = NULL;
HBITMAP g_oldBmp   = NULL;
HBRUSH  g_bgBrush  = NULL;

int g_clientW = 800;
int g_clientH = 600;

bool CreateBackBuffer(HWND hWnd)
{
    HDC hdc = GetDC(hWnd);

    g_backDC  = CreateCompatibleDC(hdc);
    g_backBmp = CreateCompatibleBitmap(hdc, g_clientW, g_clientH);   // ★ hdc 기준

    if (g_backDC == NULL || g_backBmp == NULL)
    {
        ReleaseDC(hWnd, hdc);
        return false;
    }

    g_oldBmp = (HBITMAP)SelectObject(g_backDC, g_backBmp);

    ReleaseDC(hWnd, hdc);

    if (g_bgBrush == NULL)
        g_bgBrush = CreateSolidBrush(RGB(8, 8, 20));

    return true;
}

void DestroyBackBuffer()
{
    if (g_backDC)
    {
        SelectObject(g_backDC, g_oldBmp);
        DeleteObject(g_backBmp);
        DeleteDC(g_backDC);

        g_backDC  = NULL;
        g_backBmp = NULL;
        g_oldBmp  = NULL;
    }
}
```

**✅ 여기까지 하면** — 백버퍼 생성/해제 함수가 준비된다.

### Step 2 — 생명주기에 연결

```cpp
    case WM_CREATE:
        {
            RECT rc;
            GetClientRect(hWnd, &rc);
            g_clientW = rc.right - rc.left;
            g_clientH = rc.bottom - rc.top;

            if (!CreateBackBuffer(hWnd))
            {
                MessageBox(hWnd, "백버퍼 생성 실패", "오류", MB_OK);
                return -1;                        // 창 생성 실패
            }
        }
        return 0;

    case WM_DESTROY:
        DestroyBackBuffer();
        if (g_bgBrush) { DeleteObject(g_bgBrush); g_bgBrush = NULL; }
        KillTimer(hWnd, TIMER_MAIN);
        PostQuitMessage(0);
        return 0;
```

**✅ 여기까지 하면** — 백버퍼가 창과 함께 생성/해제된다.

### Step 3 — `WM_PAINT`를 더블버퍼링으로 ★

```cpp
    case WM_ERASEBKGND:
        return 1;                                 // ★ 화면 지우기 차단

    case WM_PAINT:
        {
            PAINTSTRUCT ps;
            HDC hdc = BeginPaint(hWnd, &ps);

            if (g_backDC)
            {
                // ① 백버퍼 지우기
                RECT rc = { 0, 0, g_clientW, g_clientH };
                FillRect(g_backDC, &rc, g_bgBrush);

                // ② 백버퍼에 전부 그리기
                RenderStars(g_backDC);
                RenderUI(g_backDC);

                // ③ 화면으로 한 번에 전송
                BitBlt(hdc, 0, 0, g_clientW, g_clientH,
                       g_backDC, 0, 0, SRCCOPY);
            }

            EndPaint(hWnd, &ps);
        }
        return 0;
```

   별 200개를 흘려도 화면이 유리처럼 매끄럽다
```

### Step 4 — 토글로 비교하기 (필수)

```cpp

### Step 10 — 백버퍼 렌더 함수로 정리

```cpp
void RenderFrame(HDC targetDC)
{
    // 배경
    RECT rc = { 0, 0, g_clientW, g_clientH };
    FillRect(targetDC, &rc, g_bgBrush);

    // 내용
    RenderStars(targetDC);
    RenderUI(targetDC);
}

void Present(HWND hWnd, HDC hdc)
{
    BitBlt(hdc, 0, 0, g_clientW, g_clientH, g_backDC, 0, 0, SRCCOPY);
}

    case WM_PAINT:
        {
            PAINTSTRUCT ps;
            HDC hdc = BeginPaint(hWnd, &ps);

            if (g_useDoubleBuffer && g_backDC)
            {
                RenderFrame(g_backDC);       // 백버퍼에 그리고
                Present(hWnd, hdc);          // 화면으로 전송
            }
            else
            {
                RenderFrame(hdc);            // 화면에 직접
            }

            EndPaint(hWnd, &ps);
        }
        return 0;
```

**✅ 여기까지 하면** — 렌더 코드가 대상 DC에 무관해진다.

> ### ★ 이 구조를 기억해 둔다
>
> ```
>   RenderFrame(targetDC)   →  "어디에 그릴지"만 받는다
>   Present()               →  "화면으로 옮긴다"
>
>   Day 39:  Core::Render() 와 Core::Present()
>   Unity:   렌더 파이프라인의 마지막 단계가 Present
>   DirectX: IDXGISwapChain::Present()
>
>   ★ 이름까지 거의 같다
> ```

## 6. 자주 막히는 곳

| 증상 | 원인 | 해결 |
|---|---|---|
| **화면이 검게만 나옴** | 백버퍼를 안 지우고 그림 | `FillRect`로 백버퍼 초기화 |
| **화면이 검게만 나옴** | `BitBlt` 인자 순서 | `BitBlt(dst, ..., src, ...)` |
| **화면이 흑백** | `CreateCompatibleBitmap(memDC, ...)` | **`hdc` 기준**으로 생성 |
| 시간이 갈수록 느려짐 | 매 프레임 백버퍼 생성 | 한 번 만들고 재사용 |
| 여전히 깜빡임 | `WM_ERASEBKGND` 미차단 | `return 1` |
| 창 크기 조절 시 깨짐 | `WM_SIZE`에서 재생성 안 함 | 추가 |
| 종료 시 크래시 | 해제 순서 오류 | `SelectObject(원래)` → `DeleteObject` → `DeleteDC` |
| GDI 누수 | `DeleteDC` 대신 `ReleaseDC` | `CreateCompatibleDC`의 짝은 **`DeleteDC`** |
| 백버퍼 생성 실패 | 창 크기가 0 | `WM_SIZE`에서 `w>0 && h>0` 확인 |
| 일부만 그려짐 | 백버퍼 크기 < 창 크기 | 크기 동기화 |
| 최소화 후 복원 시 오류 | 크기 0으로 재생성 시도 | 크기 검사 |

## 7. 정리

### 오늘 배운 것

| 개념 | 한 줄 요약 |
|---|---|
| **더블버퍼링** | 안 보이는 곳에 다 그리고, 완성본만 화면에 옮긴다 |
| `CreateCompatibleDC` | 메모리 DC 생성. 짝은 **`DeleteDC`** |
| `CreateCompatibleBitmap` | **화면 DC 기준**으로 생성해야 컬러 |
| **`BitBlt`** | 픽셀 블록 복사. `SRCCOPY`. **매우 빠르다** |
| 한 번만 생성 | 매 프레임 만들면 느려진다 |
| `WM_SIZE` | 크기가 바뀌면 백버퍼 재생성 |
| `WM_ERASEBKGND` | 여전히 `return 1`로 차단 |
| 해제 역순 | `SelectObject(원래)` → `DeleteObject` → `DeleteDC` |
| `RenderFrame(HDC)` | 대상을 인자로 받으면 화면/백버퍼 전환이 자유롭다 |
