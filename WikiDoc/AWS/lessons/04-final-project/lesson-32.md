## ② 왜 필요한가

16주가 이 순간을 위한 것이었습니다. 그런데 마지막 관문이 가장 어렵습니다 — **만든 것을 남에게 설명하는 것.**

```
 [만들기만 한 팀]
  "열심히 만들었습니다" → "왜 이렇게 만들었죠?" → "그게... 그렇게 배워서요"

 [설명할 수 있는 팀]
  "요구 X 때문에 Y를 택했고, 대안 Z는 이래서 제외했으며,
   이 위험은 이렇게 관리합니다" → 신뢰
```

현장에서 아키텍트의 가치는 **만드는 능력만큼 설명하는 능력**입니다. 팀장에게, 고객에게, 다른 팀에게 "왜 이 구조인가"를 설득하지 못하면 좋은 설계도 채택되지 않습니다.

그리고 이 과정 내내 강조한 **정리** — 오늘이 마지막이자 가장 위험한 순간입니다. 발표가 끝나면 긴장이 풀려 리소스를 남기기 쉽습니다. **과정이 끝난 뒤의 청구서**가 가장 흔한 사고입니다.

M4를 완성하고, 16주를 닫고, 다음 학습 경로([A2](../../curriculum/A2-next-steps.md))로 넘어갑니다.

## ③ 워크숍 가이드 — 발표와 시연

### 발표 10분 구성

| 시간 | 내용 | 핵심 |
|---|---|---|
| 1분 | 서비스 소개 + 핵심 요구 3개 | 무엇을 왜 만드나 |
| 2분 | 아키텍처 다이어그램(요청 흐름 따라) | 그림으로 |
| 3분 | **선택 근거** — 대안 비교 의사결정 3개 | 가장 중요 ⭐ |
| 2분 | 검증 결과 — 고가용성·확장·복구 수치 | 그래프로 |
| 1분 | 비용 + 절감안 | |
| 1분 | 회고 — 다시 만든다면 | 성숙도 |

> 🔑 **3분(선택 근거)이 발표의 심장**입니다. "EC2를 썼습니다"가 아니라 "상시 트래픽이라 Fargate, 이벤트성이 아니라 Lambda 제외, 밀도 최적화가 불필요해 EC2 기반 제외." 이것이 아키텍트의 발표입니다.

### 시연 5분 — 말이 아니라 실물

3가지 중 **2개 이상** 라이브(또는 녹화):

| 시연 | 보여 주는 것 |
|---|---|
| ① 정상 동작 | 신청 → DB 기록 → HTTPS 자물쇠 |
| ② 장애 복구 | 태스크 죽이기 → 자동 복구 → 200 유지 |
| ③ 자동 배포 | 코드 push → 파이프라인 → 무중단 반영 |

> ⚠️ **시연 실패는 큰 감점이 아닙니다.** 원인을 즉시 진단·설명하는 능력이 오히려 가점. 하지만 **백업 녹화**를 준비하세요 — 라이브가 막히면 녹화로.

### 발표 자세

| 하라 | 하지 마라 |
|---|---|
| 근거로 말하기 | "그냥 그렇게 했어요" |
| 모르면 "모른다, 접근법은 이렇다" | 아는 척하다 무너지기 |
| 위험을 인정하고 관리 계획 제시 | 완벽하다고 우기기 |
| 민감 정보 마스킹 | 계정 ID·시크릿 노출 |

### 자주 나오는 질문 대비

- "왜 X 대신 Y인가?" → 결정표의 근거
- "트래픽이 10배면?" → 부하 테스트 + 확장 정책
- "가장 먼저 죽는 곳은?" → 게임데이 + 위험 목록
- "비용을 절반으로?" → 절감안 + trade-off
- "이 데이터는 어떻게 보호되나?" → 암호화·시크릿·비공개 경로

### 정리의 위험 — 발표 후가 가장 위험

```
 발표 끝 → 긴장 풀림 → "나중에 지우지" → 잊음 → 다음 달 청구서
```

**32강 Step 5는 강사 확인까지 포함**하고, 종료 1주일 후 비용을 재확인합니다.

- [ ] 시연 환경 재배포(app 스택 `deploy` 또는 push) + 데이터 준비

- [ ] 시연 3가지 중 2개 사전 리허설
- [ ] 백업 녹화 준비

### Step 2. 🏁 최종 발표 + 시연 + 질의 (전체, 90분)

팀당 발표 10분 + 시연 5분 + 질의 5분.

**발표 팀 체크리스트** — 발표에서 아래를 증명:

- [ ] 핵심 요구 3개와 그것을 충족하는 설계

- [ ] 위험 목록과 관리 계획
- [ ] 시연 2건 이상

### Step 3. 동료 평가 (개인, 15분)

팀원 각자가 나머지 팀원에게 100점 + 근거 2줄.

| 평가 항목 | 내용 |
|---|---|
| 기여도 | 실제 작업량 |
| 협업 | 소통·도움 |
| 지식 공유 | 배운 것을 나눴나 |

> 최고·최저 제외 평균. 팀 내 편차 30점↑이면 강사 면담.

### Step 4. 🧹 완전 정리 ⭐ (전체, 30분)

**삭제 순서** — 앱 → 데이터 → 네트워크. IaC라서 스택 삭제가 대부분.

```bash
# 1) app 스택 (ALB·Fargate)
$ aws cloudformation delete-stack --stack-name course-app
$ aws cloudformation wait stack-delete-complete --stack-name course-app

# 2) data 스택 (RDS — DeletionPolicy:Snapshot이 스냅샷 뜸)
$ aws cloudformation delete-stack --stack-name course-data
$ aws cloudformation wait stack-delete-complete --stack-name course-data
# 남은 스냅샷도 실습 데이터면 삭제
$ aws rds describe-db-snapshots --snapshot-type manual \
    --query 'DBSnapshots[?contains(DBSnapshotIdentifier,`course`)].DBSnapshotIdentifier' --output text
# → 삭제

# 3) network 스택 (엔드포인트·SG·서브넷·VPC)
$ aws cloudformation delete-stack --stack-name course-network
$ aws cloudformation wait stack-delete-complete --stack-name course-network

# 4) 스택 밖 리소스
$ aws secretsmanager delete-secret --secret-id course/final/db --force-delete-without-recovery
$ aws kms schedule-key-deletion --key-id $(aws kms describe-key --key-id alias/course-final --query 'KeyMetadata.KeyId' --output text) --pending-window-in-days 7
$ aws kms delete-alias --alias-name alias/course-final
# WAF, EventBridge 규칙(야간 축소), Lambda, 대시보드·알람, 로그 그룹
# ECR 리포지토리, OIDC 공급자·배포 역할(포트폴리오 유지 원하면 남김)
# Route 53 호스팅 영역(과정 종료 시)
```

**태그로 잔존 확인 — 이 명령이 0건이어야 완료**

```bash
$ aws resourcegroupstaggingapi get-resources \
    --tag-filters Key=Project,Values=aws-course \
    --query 'ResourceTagMappingList[*].ResourceARN' --output table
```

**비용 나는 리소스 전수 확인**

```bash
$ aws ecs list-clusters --query 'clusterArns' --output text
$ aws elbv2 describe-load-balancers --query 'LoadBalancers[*].LoadBalancerName' --output text
$ aws rds describe-db-instances --query 'DBInstances[*].DBInstanceIdentifier' --output text
$ aws ec2 describe-nat-gateways --filter "Name=state,Values=available,pending" --query 'NatGateways[*].NatGatewayId' --output text
$ aws ec2 describe-addresses --query 'Addresses[*].PublicIp' --output text
```

**전부 빈 출력 + 강사 확인**이면 정리 완료.

## ⑤ 자주 하는 실수

### 시연이 막히자 당황해 무너진다

**해결** — 시연 실패는 감점이 작습니다. **원인을 즉시 진단**("헬스 체크 유예가 짧아서 아직 준비 중, 30초 뒤 다시")하고 백업 녹화로 넘어갑니다. 침착한 진단이 오히려 가점입니다.

### "왜 X인가"에 "배운 대로"라고 답한다

**증상** — 근거를 못 대고 습관을 말합니다.
**해결** — 발표 전 **결정표를 다시 봅니다.** 각 선택의 대안과 근거를 입으로 말해 봅니다. "상시 트래픽이라 Fargate" 수준이면 됩니다. 3분 파트는 이걸 증명하는 시간입니다.

### 발표 자료에 계정 ID·시크릿을 노출한다

**증상** — 스크린샷에 계정 ID·엔드포인트·시크릿이 그대로.
**해결** — 마스킹. 공개 발표 자료에 민감 정보를 넣지 않는 것은 [13·25강](lesson-25.md) 보안 원칙의 연장입니다.

### 발표 후 정리를 미룬다

**증상** — "집에 가서 지우지" → 안 지움 → 청구서.
**해결** — Step 4를 **발표 직후 그 자리에서**. 강사 확인까지. 이 과정 16주의 마지막 교훈이 "정리는 실습의 일부"입니다.

### 스택 삭제가 실패한다

**원인** — S3 객체 잔존, ENI 점유, 삭제 순서 위반([23강](../03-serverless-automation/lesson-23.md)).
**해결** — 순서(app→data→network), S3 비우기, 잔존 ENI 확인. 태그 조회로 남은 것 특정.

### RDS 최종 스냅샷을 만들어 계속 과금된다

**원인** — data 스택의 `DeletionPolicy: Snapshot`이 스냅샷을 남깁니다 — 실습 데이터엔 불필요.
**해결** — 스냅샷도 실습 데이터면 삭제. 운영이면 유지가 맞지만 이건 실습입니다.

### 종료했는데 며칠 뒤 비용이 찍힌다

**원인** — Route 53 호스팅 영역($0.50/월), 미삭제 스냅샷, KMS 키, Secrets Manager 복구 대기.
**해결** — 종료 3일·7일 후 재확인 습관. Budgets 알림이 잡아 줍니다(그래서 남깁니다).

<details>
<summary>1. 발표의 3분(선택 근거)에서 무엇을 말할 건가요?</summary>

</details>

<details>
<summary>2. 리소스를 언제, 어떻게 정리할 건가요?</summary>

**발표 직후 그 자리에서, IaC 스택 삭제로.** 순서는 app→data→network, 그다음 스택 밖 리소스(시크릿·KMS·WAF·이벤트·로그). 검증은 **태그 조회 0건 + 비용 리소스 전수 확인 빈 출력 + 강사 확인**. 그리고 종료 3일·7일 후 재확인. Budgets 알림은 남겨 잊은 리소스를 잡습니다. "나중에"가 이 과정 최대 사고 원인입니다.
</details>

<details>
<summary>3. 이 16주에서 가장 크게 바뀐 생각 하나는 무엇인가요?</summary>

개인마다 다르지만, 답이 있어야 합니다. 흔한 것: "서버는 애완동물이 아니라 가축"([09강](../02-compute-data/lesson-09.md)), "보안은 특정 단계가 아니라 매 단계"([전 과정]), "정리는 뒷정리가 아니라 실습의 일부", "고가용성은 겪어 봐야 안다"([30강](lesson-30.md)), "아키텍처는 만드는 것이 아니라 설명하는 것"(오늘). 이 전환이 "AWS를 쓸 줄 안다"에서 "AWS로 설계·운영할 줄 안다"로 넘어간 증거입니다.
</details>

## 오늘의 정리

| 개념 | 핵심 |
|---|---|
| 발표 10분 | 소개·다이어그램·**근거(3분)**·검증·비용·회고 |
| 근거 | 대안 비교 의사결정 — "배운 대로" 금지 |
| 시연 | 2건 이상 · 실패는 진단으로 · 백업 녹화 |
| 질의 | 근거로 · 모르면 접근법 제시 · 마스킹 |
| **정리** | 발표 직후 그 자리에서 · 태그 0건 · 강사 확인 |
| 종료 후 | Budgets 유지 · 3일·7일 재확인 · 포트폴리오 |

**한 장 요약**

```
  발표(근거 3분이 심장) + 시연 2건 + 질의(근거로)
    → 동료 평가
    → 🧹 완전 정리(app→data→network, 태그 0건, 강사 확인)
    → 회고 + 다음 경로(A2, SAA-C03)
    = M4 완성 = 16주 수료
```

**오늘 반드시 기억할 한 가지**
> **아키텍처는 만드는 것이 아니라 설명하고 지키고 정리하는 것입니다.**
> 그리고 이 과정의 마지막 교훈 — 정리는 실습의 일부입니다.
