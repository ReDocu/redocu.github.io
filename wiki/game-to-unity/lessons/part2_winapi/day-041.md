### 3-2. BMP 파일 형식

**왜 필요한가** — WINAPI가 기본으로 지원하는 유일한 형식이다.

| 형식 | WINAPI 기본 지원 | 투명도 | 크기 |
|---|:--:|:--:|---|
| **BMP** | **O** | X (컬러 키로 대체) | 큼 |
| PNG | X (GDI+ 필요) | O (알파 채널) | 작음 |
| JPG | X (GDI+ 필요) | X | 작음 |

```
   ★ 이 과정에서는 BMP를 쓴다

   이유:  ① LoadImage 하나로 로드된다 (외부 라이브러리 불필요)
          ② 원리를 이해하기 좋다
          ③ 투명 처리를 직접 구현하게 된다

   실무에서는 PNG + GDI+ 또는 DirectX 텍스처를 쓴다
```

**PNG를 BMP로 변환**

```
   그림판, GIMP, Photoshop 등에서
   "다른 이름으로 저장" → 24비트 비트맵(.bmp)

   ★ 투명 영역은 마젠타 RGB(255, 0, 255) 로 칠한다
```

### 3-4. ⚠️ 파일 경로 문제

**왜 필요한가** — "F5로는 되는데 exe로는 안 된다"의 원인. Day 26에서 겪은 그 문제다.

```
   상대 경로 "assets/player.bmp" 의 기준

   Visual Studio F5 실행    →  프로젝트 폴더 (.vcxproj 있는 곳)
   exe 더블클릭             →  exe 가 있는 폴더

   ★ 둘이 다르다!
```

**해결 — 실행 파일 기준 경로**

```cpp
void GetAssetPath(const char* relativePath, char* out, int outSize)
{
    char exePath[MAX_PATH];
    GetModuleFileNameA(NULL, exePath, MAX_PATH);

    char* lastSlash = strrchr(exePath, '\\');
    if (lastSlash) *(lastSlash + 1) = '\0';

    sprintf_s(out, outSize, "%s%s", exePath, relativePath);
}
```

```cpp
    char path[MAX_PATH];
    GetAssetPath("assets/player.bmp", path, sizeof(path));

    HBITMAP bmp = (HBITMAP)LoadImage(NULL, path, IMAGE_BITMAP, 0, 0, LR_LOADFROMFILE);
```

> **또는 프로젝트 설정에서 "작업 디렉터리"를 출력 폴더로 맞춘다.**
> 속성 → 디버깅 → 작업 디렉터리 → `$(OutDir)`
>
> **가장 확실한 방법은 위 함수를 쓰는 것이다.**

### 3-5. 이미지 그리기 — `BitBlt`

**왜 필요한가** — Day 37에서 배운 그것. 이번엔 이미지가 원본이다.

```cpp
    // 이미지를 담을 임시 DC
    HDC imageDC = CreateCompatibleDC(m_backDC);
    HBITMAP oldBmp = (HBITMAP)SelectObject(imageDC, bitmap);

    // 백버퍼로 복사
    BitBlt(m_backDC, x, y, width, height,
           imageDC, 0, 0, SRCCOPY);

    SelectObject(imageDC, oldBmp);
    DeleteDC(imageDC);
```

```
   ┌──────────────────────────────────────────────────────────┐
   │  HBITMAP (이미지 데이터)                                  │
   │        │                                                  │
   │        │ SelectObject                                     │
   │        ▼                                                  │
   │  HDC imageDC  ──── BitBlt ────▶  HDC backDC ──▶ 화면      │
   │  (이미지를 담은 DC)               (백버퍼)                 │
   └──────────────────────────────────────────────────────────┘

   ★ HBITMAP 은 직접 그릴 수 없다
     DC에 SelectObject 로 끼워야 BitBlt의 원본이 될 수 있다
```

### 3-6. 투명 처리 — 컬러 키

**왜 필요한가** — 그냥 `BitBlt`하면 캐릭터 뒤에 사각형이 따라다닌다.

```
   원본 이미지 (BMP는 투명도가 없다)

   ┌────────────┐
   │████████████│      █ = 마젠타 RGB(255,0,255)  ← "여기는 투명"
   │███  ██  ███│      ▓ = 캐릭터 픽셀
   │██ ▓▓▓▓▓▓ ██│
   │█ ▓▓▓▓▓▓▓▓ █│
   │████████████│
   └────────────┘

   BitBlt 그대로:  마젠타 사각형이 그대로 그려진다  ✘
   TransparentBlt: 마젠타 픽셀을 건너뛴다           ✔
```

```cpp
#pragma comment(lib, "msimg32.lib")      // ★ 링크 필요

    TransparentBlt(
        m_backDC, x, y, w, h,            // 대상
        imageDC, 0, 0, w, h,             // 원본
        RGB(255, 0, 255));               // ★ 이 색을 투명으로 취급
```

**왜 마젠타인가**

```
   RGB(255, 0, 255) = 형광 분홍

   ① 자연물에 거의 없는 색  →  실수로 캐릭터에 쓸 일이 없다
   ② 눈에 확 띈다           →  덜 지운 부분이 바로 보인다
   ③ 업계 관행              →  많은 도구가 기본값으로 쓴다
```

> ### ⚠️ `TransparentBlt`의 인자가 `BitBlt`보다 많다
>
> ```cpp
>   BitBlt        (dst, dx, dy, w,  h,  src, sx, sy, rop)
>   TransparentBlt(dst, dx, dy, dw, dh, src, sx, sy, sw, sh, color)
>                                            ▲          ▲
>                                    원본 크기를 따로 지정  →  확대/축소 가능
> ```

### 3-8. 키-값 저장 — 간단한 맵

**왜 필요한가** — `"player"` 라는 이름으로 이미지를 찾을 수 있어야 한다.

```cpp
struct ImageEntry
{
    char    key[32];
    Image*  image;
};

class ImageManager
{
public:
    Image* Get(const char* key)
    {
        for (int i = 0; i < m_count; i++)
            if (strcmp(m_entries[i].key, key) == 0)
                return m_entries[i].image;

        return nullptr;
    }

private:
    static const int MAX_IMAGES = 128;
    ImageEntry m_entries[MAX_IMAGES];
    int        m_count = 0;
};
```

> **선형 탐색이라 O(n)이지만 이미지가 수십 개면 문제없다.**
> C++ 표준 라이브러리를 쓴다면 `std::unordered_map<std::string, Image*>`가 더 낫다.
> **이 과정에서는 원리를 보기 위해 직접 만든다.**

### 3-9. `Image` 클래스 설계

```cpp
class Image
{
public:
    ~Image() { Release(); }

    bool Load(const char* path, COLORREF colorKey = RGB(255, 0, 255));
    void Release();

    void Draw(HDC destDC, int x, int y) const;                       // 전체
    void DrawPart(HDC destDC, int dx, int dy,
                  int sx, int sy, int sw, int sh) const;             // 일부 (Day 42)
    void DrawScaled(HDC destDC, int dx, int dy, int dw, int dh) const;
    void DrawFlipped(HDC destDC, int x, int y, bool flipX) const;    // 좌우 반전

    int  GetWidth()  const { return m_width; }
    int  GetHeight() const { return m_height; }
    bool IsValid()   const { return m_bitmap != nullptr; }

    void SetUseColorKey(bool use) { m_useColorKey = use; }

private:
    HBITMAP  m_bitmap     = nullptr;
    HDC      m_imageDC    = nullptr;         // ★ 미리 만들어 둔다
    HBITMAP  m_oldBmp     = nullptr;
    int      m_width      = 0;
    int      m_height     = 0;
    COLORREF m_colorKey   = RGB(255, 0, 255);
    bool     m_useColorKey = true;
};
```

> ### ★ `m_imageDC`를 미리 만들어 두는 이유
>
> ```cpp
>   // ✘ 그릴 때마다 DC 생성
>   void Draw(HDC dst, int x, int y)
>   {
>       HDC dc = CreateCompatibleDC(dst);     // 매번!
>       SelectObject(dc, m_bitmap);
>       BitBlt(...);

>   }
> ```
>
> 캐릭터 100개를 그리면 프레임당 100번 DC를 만들고 지운다.
> **한 번 만들어 두고 재사용한다.** (Day 37의 백버퍼와 같은 이유)

### Step 3 — `Image` 클래스 — 로드

```cpp
// Engine/Image.cpp
bool Image::Load(const char* path, COLORREF colorKey)
{
    Release();

    char fullPath[MAX_PATH];
    GetAssetPath(path, fullPath, sizeof(fullPath));

    m_bitmap = (HBITMAP)LoadImage(nullptr, fullPath, IMAGE_BITMAP,
                                  0, 0, LR_LOADFROMFILE);

    if (m_bitmap == nullptr)
    {
        DebugLog("[Image] 로드 실패: %s\n", fullPath);
        return false;
    }

    BITMAP info;
    GetObject(m_bitmap, sizeof(BITMAP), &info);
    m_width  = info.bmWidth;
    m_height = info.bmHeight;

    // 이미지 DC 미리 생성
    HDC screenDC = GetDC(nullptr);
    m_imageDC = CreateCompatibleDC(screenDC);
    ReleaseDC(nullptr, screenDC);

    m_oldBmp = (HBITMAP)SelectObject(m_imageDC, m_bitmap);

    m_colorKey = colorKey;

    DebugLog("[Image] 로드 성공: %s (%d x %d)\n", path, m_width, m_height);
    return true;
}

void Image::Release()
{
    if (m_imageDC)
    {
        if (m_oldBmp) SelectObject(m_imageDC, m_oldBmp);
        DeleteDC(m_imageDC);
        m_imageDC = nullptr;
        m_oldBmp  = nullptr;
    }

    if (m_bitmap)
    {
        DeleteObject(m_bitmap);
        m_bitmap = nullptr;
    }

    m_width = m_height = 0;
}
```

**✅ 여기까지 실행하면** — 출력 창에 로드 성공/실패가 찍힌다.

```
[Image] 로드 성공: assets/player.bmp (64 x 96)
[Image] 로드 성공: assets/bg_stage1.bmp (800 x 600)
```

// Engine/ImageManager.h
class ImageManager
{
public:
    static ImageManager& Get()
    {
        static ImageManager instance;
        return instance;
    }

    bool Load(const char* key, const char* path,
              COLORREF colorKey = RGB(255, 0, 255));

    Image* Find(const char* key);

    void ReleaseAll();

    int  GetCount() const { return m_count; }
    size_t GetMemoryUsage() const;

private:
    ImageManager() = default;
    ~ImageManager() { ReleaseAll(); }

    struct Entry { char key[32]; Image* image; };

    static const int MAX_IMAGES = 128;
    Entry m_entries[MAX_IMAGES] = {};
    int   m_count = 0;
};
```

```cpp
// Engine/ImageManager.cpp
bool ImageManager::Load(const char* key, const char* path, COLORREF colorKey)
{
    if (Find(key))
    {
        DebugLog("[ImageManager] 이미 로드됨: %s\n", key);
        return true;
    }

    if (m_count >= MAX_IMAGES)
    {
        DebugLog("[ImageManager] 한계 초과\n");
        return false;
    }

    Image* img = new Image();

    if (!img->Load(path, colorKey))
    {
        delete img;
        return false;
    }

    strcpy_s(m_entries[m_count].key, sizeof(m_entries[m_count].key), key);
    m_entries[m_count].image = img;
    m_count++;

    return true;
}

Image* ImageManager::Find(const char* key)
{
    for (int i = 0; i < m_count; i++)
        if (strcmp(m_entries[i].key, key) == 0)
            return m_entries[i].image;

    return nullptr;
}

void ImageManager::ReleaseAll()
{
    for (int i = 0; i < m_count; i++)
    {
        delete m_entries[i].image;
        m_entries[i].image = nullptr;
    }
    m_count = 0;
}
```

### Step 9 — 좌우 반전

```cpp
void Image::DrawFlipped(HDC destDC, int x, int y, bool flipX) const
{
    if (!m_bitmap || !m_imageDC) return;

    if (!flipX)
    {
        Draw(destDC, x, y);
        return;
    }

    // 폭을 음수로 주면 좌우 반전된다
    if (m_useColorKey)
    {
        // TransparentBlt은 음수 폭을 지원하지 않는다
        // → 임시 DC에 반전해서 그린 뒤 전송
        HDC tempDC = CreateCompatibleDC(destDC);
        HBITMAP tempBmp = CreateCompatibleBitmap(destDC, m_width, m_height);
        HBITMAP oldTemp = (HBITMAP)SelectObject(tempDC, tempBmp);

        StretchBlt(tempDC, m_width - 1, 0, -m_width, m_height,
                   m_imageDC, 0, 0, m_width, m_height, SRCCOPY);

        TransparentBlt(destDC, x, y, m_width, m_height,
                       tempDC, 0, 0, m_width, m_height, m_colorKey);

        SelectObject(tempDC, oldTemp);
        DeleteObject(tempBmp);
        DeleteDC(tempDC);
    }
    else
    {
        StretchBlt(destDC, x + m_width - 1, y, -m_width, m_height,
                   m_imageDC, 0, 0, m_width, m_height, SRCCOPY);
    }
}
```

```
   StretchBlt 의 폭을 음수로 주면 좌우 반전

   원본:  ▶            반전:  ◀

   ★ 시작 x 좌표도 조정해야 한다 (x + width - 1)
```

> **매 프레임 임시 DC를 만드는 것은 비효율적이다.**
> 실무에서는 **반전된 이미지를 미리 만들어 캐시**한다.
> Day 42에서 개선한다.

**✅ 여기까지 실행하면** — 캐릭터가 좌우로 뒤집힌다.

## 6. 자주 막히는 곳

| 증상 | 원인 | 해결 |
|---|---|---|
| `TransparentBlt` 링크 오류 | 라이브러리 누락 | `#pragma comment(lib, "msimg32.lib")` |
| 이미지가 안 뜸 | 경로 문제 | `GetAssetPath` 사용, 출력 창 로그 확인 |
| 이미지가 안 뜸 | BMP가 아님 | 확장자만 bmp인 PNG일 수 있다. 다시 저장 |
| 마젠타가 안 빠짐 | 실제 배경색이 다름 | 그림판 스포이드로 정확한 RGB 확인 |
| 마젠타 테두리가 남음 | JPG 압축 등으로 색이 번짐 | 무손실 형식으로 다시 저장 |
| 시간이 갈수록 느려짐 | 매 프레임 로드 또는 DC 생성 | `ImageManager` + `m_imageDC` 재사용 |
| GDI 개체 증가 | `DeleteObject`/`DeleteDC` 누락 | `Image::Release` 확인 |
| 이미지가 뒤집혀 나옴 | BMP는 아래→위 저장 | `LoadImage`가 처리해 준다. 다른 원인 확인 |
| 반전 시 위치가 어긋남 | 시작 좌표 미보정 | `x + width - 1` |
| exe로는 안 됨 | 작업 디렉터리 | `GetAssetPath` 또는 빌드 후 복사 |

## 7. 정리

### 오늘 배운 것

| 개념 | 한 줄 요약 |
|---|---|
| BMP | WINAPI가 기본 지원하는 형식. 투명도가 없다 |
| `LoadImage` | 파일에서 `HBITMAP` 로드. `LR_LOADFROMFILE` |
| **경로 문제** | 실행 파일 기준 경로를 직접 계산한다 |
| `BitBlt` + 이미지 DC | `HBITMAP`을 DC에 끼워야 그릴 수 있다 |
| **`TransparentBlt`** | 컬러 키(마젠타)를 투명 처리. `msimg32.lib` |
| **`ImageManager`** | 한 번 로드해서 재사용. 매 프레임 로드 금지 |
| DC 미리 생성 | 그릴 때마다 만들지 않는다 |
| 대체 이미지 | 애셋이 없어도 개발을 계속한다 |
