## 3. 개념

### 3-1. 스프라이트 시트 — 격자로 배치된 프레임들

**왜 필요한가** — 파일 하나에 프레임 전부를 담는다.

```
   player_sheet.bmp  (384 × 288, 프레임 64×96, 6열 × 3행)

    열:   0     1     2     3     4     5
        ┌─────┬─────┬─────┬─────┬─────┬─────┐
   행0  │  0  │  1  │  2  │  3  │  4  │  5  │   ← 대기 (0~3), 걷기 시작
        ├─────┼─────┼─────┼─────┼─────┼─────┤
   행1  │  6  │  7  │  8  │  9  │ 10  │ 11  │   ← 걷기
        ├─────┼─────┼─────┼─────┼─────┼─────┤
   행2  │ 12  │ 13  │ 14  │ 15  │ 16  │ 17  │   ← 공격
        └─────┴─────┴─────┴─────┴─────┴─────┘

   ★ 프레임 번호는 왼쪽 위부터 오른쪽으로, 그다음 줄로
```

| 용어 | 뜻 |
|---|---|
| 스프라이트 시트 | 여러 프레임을 격자로 담은 이미지 |
| 프레임 | 한 컷 |
| 프레임 인덱스 | 0부터 시작하는 번호 |
| 열 수 (cols) | 가로 프레임 개수 |
| 행 수 (rows) | 세로 프레임 개수 |

### 3-2. 인덱스 → 좌표 변환 ★

**왜 필요한가** — 오늘의 핵심 계산.

```
   프레임 인덱스가 주어지면, 시트 안의 좌표를 구한다

   col = index % cols          ← 나머지 = 몇 번째 열
   row = index / cols          ← 몫   = 몇 번째 행

   srcX = col * frameWidth
   srcY = row * frameHeight
```

```
   예)  index = 14,  cols = 6,  frameW = 64,  frameH = 96

   col = 14 % 6 = 2
   row = 14 / 6 = 2

   srcX = 2 * 64 = 128
   srcY = 2 * 96 = 192

        열0   열1   열2
        ┌────┬────┬────┐
   행0  │ 0  │ 1  │ 2  │
        ├────┼────┼────┤
   행1  │ 6  │ 7  │ 8  │
        ├────┼────┼────┤
   행2  │ 12 │ 13 │▓14▓│  ← (128, 192)
        └────┴────┴────┘
```

> ### ★ Day 2에서 배운 `%`와 `/`가 여기서 쓰인다
>
> ```
>   나머지(%)  →  "한 줄에서 몇 번째"
>   몫(/)      →  "몇 번째 줄"
>
>   ★ 이 조합은 격자 좌표 계산의 표준 공식이다
>
>   Day 56  맵툴의 타일 좌표
>   Day 78  Unity의 스프라이트 슬라이싱
> ```

**역변환 (좌표 → 인덱스)**

```
   col = x / frameWidth
   row = y / frameHeight

   index = row * cols + col
```

### 3-3. `DrawPart` — 일부만 그리기

**왜 필요한가** — `BitBlt`/`TransparentBlt`의 원본 좌표를 지정한다.

```cpp
void Image::DrawPart(HDC destDC, int dx, int dy,
                     int sx, int sy, int sw, int sh) const
{
    if (!m_bitmap || !m_imageDC) return;

    if (m_useColorKey)
    {
        TransparentBlt(destDC, dx, dy, sw, sh,       // 대상: 위치, 크기
                       m_imageDC, sx, sy, sw, sh,    // 원본: 위치, 크기
                       m_colorKey);
    }
    else
    {
        BitBlt(destDC, dx, dy, sw, sh,
               m_imageDC, sx, sy, SRCCOPY);
    }
}
```

   │        (sx,sy)=(128,192)        │        │  (dx,dy)     │

   │           │ 64×96│              │        │    │ 64×96│  │

### 3-4. `Sprite` 클래스 — 시트 정보를 묶는다

**왜 필요한가** — 프레임 크기와 열 수를 매번 계산에 넘기지 않는다.

```cpp
class Sprite
{
public:
    bool Init(const char* imageKey, int frameWidth, int frameHeight);

    void Draw(HDC destDC, int index, int x, int y,
              bool flipX = false) const;

    void DrawScaled(HDC destDC, int index, int x, int y,
                    float scale, bool flipX = false) const;

    int GetFrameCount()  const { return m_cols * m_rows; }
    int GetCols()        const { return m_cols; }
    int GetRows()        const { return m_rows; }
    int GetFrameWidth()  const { return m_frameW; }
    int GetFrameHeight() const { return m_frameH; }

    void GetFrameRect(int index, int* outX, int* outY) const;

private:
    Image* m_image  = nullptr;
    int    m_frameW = 0;
    int    m_frameH = 0;
    int    m_cols   = 0;
    int    m_rows   = 0;
};
```

```cpp
bool Sprite::Init(const char* imageKey, int frameWidth, int frameHeight)
{
    m_image = ImageManager::Get().Find(imageKey);

    if (!m_image || !m_image->IsValid()) return false;
    if (frameWidth <= 0 || frameHeight <= 0) return false;

    m_frameW = frameWidth;
    m_frameH = frameHeight;

    m_cols = m_image->GetWidth()  / frameWidth;
    m_rows = m_image->GetHeight() / frameHeight;

    if (m_cols <= 0 || m_rows <= 0) return false;

    DebugLog("[Sprite] %s: %dx%d 프레임, %d열 %d행 (총 %d프레임)\n",
             imageKey, m_frameW, m_frameH, m_cols, m_rows, GetFrameCount());

    return true;
}

void Sprite::GetFrameRect(int index, int* outX, int* outY) const
{
    if (index < 0) index = 0;
    if (index >= GetFrameCount()) index = GetFrameCount() - 1;

    int col = index % m_cols;
    int row = index / m_cols;

    *outX = col * m_frameW;
    *outY = row * m_frameH;
}

void Sprite::Draw(HDC destDC, int index, int x, int y, bool flipX) const
{
    if (!m_image) return;

    int sx, sy;
    GetFrameRect(index, &sx, &sy);

    if (flipX)
        m_image->DrawPartFlipped(destDC, x, y, sx, sy, m_frameW, m_frameH);
    else
        m_image->DrawPart(destDC, x, y, sx, sy, m_frameW, m_frameH);
}
```

### 3-5. 정렬 기준 — 좌상단 vs 발밑

**왜 필요한가** — 캐릭터의 "위치"를 어디로 볼 것인가. 게임 로직 전체에 영향을 준다.

```
   [ 좌상단 기준 ]              [ 발밑 중앙 기준 ]

   (x,y)                              머리
     ┌──────┐                      ┌──────┐
     │  머리 │                      │      │
     │  몸   │                      │      │
     │  발   │                      │      │
     └──────┘                      └───●──┘
                                     (x,y)
   그리기:  Draw(x, y)            그리기:  Draw(x - w/2, y - h)
```

| 기준 | 장점 | 단점 |
|---|---|---|
| 좌상단 | 그리기가 단순 | 크기가 바뀌면 위치가 흔들린다 |
| **발밑 중앙** | 바닥 판정·크기 변경에 자연스럽다 | 그릴 때 보정 필요 |

```
   ★ 격투게임·플랫포머는 "발밑 중앙"이 표준이다

   이유:
     ① 바닥 y 좌표와 캐릭터 y가 바로 비교된다
     ② 캐릭터가 커지거나 웅크려도 발 위치가 고정된다
     ③ 좌우 반전 시 중심이 안 흔들린다
```

```cpp
class Character
{
    // m_x, m_y 는 "발밑 중앙"
    void Render(Renderer& r) const
    {
        int drawX = (int)m_x - m_sprite->GetFrameWidth() / 2;
        int drawY = (int)m_y - m_sprite->GetFrameHeight();

        m_sprite->Draw(r.GetDC(), m_frameIndex, drawX, drawY, m_facingLeft);
    }
};
```

### 3-6. 좌우 반전 — 캐시 방식

**왜 필요한가** — Day 41의 방식은 매 프레임 임시 DC를 만들어 느리다.

```cpp
class Image
{
public:
    bool Load(const char* path, COLORREF colorKey, bool createFlipped = false);

private:
    HDC     m_imageDC        = nullptr;
    HDC     m_flippedDC      = nullptr;      // ★ 반전본을 미리 만들어 둔다
    HBITMAP m_flippedBmp     = nullptr;
};
```

```cpp
bool Image::CreateFlippedCache()
{
    HDC screenDC = GetDC(nullptr);

    m_flippedDC  = CreateCompatibleDC(screenDC);
    m_flippedBmp = CreateCompatibleBitmap(screenDC, m_width, m_height);

    ReleaseDC(nullptr, screenDC);

    if (!m_flippedDC || !m_flippedBmp) return false;

    m_oldFlipped = (HBITMAP)SelectObject(m_flippedDC, m_flippedBmp);

    // 좌우 반전해서 복사 (한 번만)
    StretchBlt(m_flippedDC, m_width - 1, 0, -m_width, m_height,
               m_imageDC, 0, 0, m_width, m_height, SRCCOPY);

    return true;
}
```

```cpp
void Image::DrawPartFlipped(HDC destDC, int dx, int dy,
                            int sx, int sy, int sw, int sh) const
{
    if (!m_flippedDC) { DrawPart(destDC, dx, dy, sx, sy, sw, sh); return; }

    // ★ 반전본에서의 x 좌표를 다시 계산해야 한다
    int flippedSx = m_width - sx - sw;

    if (m_useColorKey)
        TransparentBlt(destDC, dx, dy, sw, sh,
                       m_flippedDC, flippedSx, sy, sw, sh, m_colorKey);
    else
        BitBlt(destDC, dx, dy, sw, sh, m_flippedDC, flippedSx, sy, SRCCOPY);
}
```

```
   ★ 반전본에서의 좌표 계산

   원본 시트 (폭 384)
   ┌────┬────┬────┬────┬────┬────┐
   │ 0  │ 1  │ 2  │ 3  │ 4  │ 5  │
   └────┴────┴────┴────┴────┴────┘
   sx=128 (프레임 2)

   반전본
   ┌────┬────┬────┬────┬────┬────┐
   │ 5' │ 4' │ 3' │ 2' │ 1' │ 0' │      ' = 좌우 뒤집힌 것
   └────┴────┴────┴────┴────┴────┘
                  ▲
        flippedSx = 384 - 128 - 64 = 192
```

**메모리 대가**

```
   반전본을 만들면 이미지 메모리가 2배가 된다

   384×288×4바이트 = 442KB  →  884KB

   ★ 트레이드오프
     메모리 2배  vs  매 프레임 반전 연산

   캐릭터처럼 자주 반전되는 것만 캐시한다
```

### Step 5 — 시트 전체를 축소해서 보여주기

void RenderSheetPreview(Renderer& r, const Sprite& sprite, int x, int y, float scale)
{
    Image* img = sprite.GetImage();
    if (!img) return;

    int w = (int)(img->GetWidth()  * scale);
    int h = (int)(img->GetHeight() * scale);

    img->DrawScaled(r.GetDC(), x, y, w, h);

    // 격자선
    for (int c = 0; c <= sprite.GetCols(); c++)
    {
        int lx = x + (int)(c * sprite.GetFrameWidth() * scale);
        r.DrawLine(lx, y, lx, y + h, RGB(80, 80, 100));
    }
    for (int rr = 0; rr <= sprite.GetRows(); rr++)
    {
        int ly = y + (int)(rr * sprite.GetFrameHeight() * scale);
        r.DrawLine(x, ly, x + w, ly, RGB(80, 80, 100));
    }
}

void Sprite::DrawScaled(HDC destDC, int index, int x, int y,
                        float scale, bool flipX) const

    int dh = (int)(m_frameH * scale);

}

## 5. 실행 결과

**정상이라면 이렇게 보인다.**

```
   ┌──────────────────────────────────────────────────────────┐
   │  Sprite Sheet                                    ─    ✕ │
   ├──────────────────────────────────────────────────────────┤
   │  ┌──── 시트 원본 ────┐                                    │
   │  │  │  │  │  │  │  │ │                                    │
   │  │  │  │  │  │  │  │ │   현재 프레임 14 (빨간 테두리)      │
   │  │  │  │▓▓│  │  │  │ │                                    │
   │  └───────────────────┘                                    │
   │                                                          │
   │             ██████                                        │
   │            ████████                                       │
   │            ██    ██          ← 확대 표시                   │
   │           ███    ███                                      │
   │  ─────────────●───────────── ← 발밑 기준점 + 바닥선        │
   │                                                          │
   │  프레임 14 / 18    시트 384x288    프레임 64x96           │
   │  col = 14 % 6 = 2    row = 14 / 6 = 2                    │
   │  srcX = 128    srcY = 192    반전 OFF    배율 2.0x        │
   │                                                          │
   │  [←→] 프레임  [F] 반전  [+/-] 배율  [1~4] 구간            │
   └──────────────────────────────────────────────────────────┘
```

- [ ] 시트에서 원하는 프레임 하나만 그려진다
- [ ] 좌우 키로 모든 프레임을 확인할 수 있다
- [ ] 인덱스 → 좌표 계산식이 화면에 표시된다
- [ ] 시트 미리보기에서 현재 프레임이 강조된다
- [ ] `F`로 좌우 반전되고 **성능 저하가 없다**
- [ ] 반전해도 프레임이 어긋나지 않는다
- [ ] 발밑 기준으로 그리면 프레임이 바뀌어도 발 위치가 고정된다
- [ ] 확대해도 프레임 경계가 정확하다
- [ ] 프레임 크기를 잘못 넣으면 경고가 뜬다

## 6. 자주 막히는 곳

| 증상 | 원인 | 해결 |
|---|---|---|
| 엉뚱한 부분이 잘려 나옴 | 프레임 크기 오류 | 시트 크기 ÷ 프레임 수로 검산 |
| 옆 프레임 조각이 붙어 보임 | 시트 크기가 나누어떨어지지 않음 | 애셋 수정 또는 크기 재확인 |
| 마지막 프레임에서 깨짐 | 인덱스 범위 초과 | `GetFrameRect`에서 클램프 |
| 반전 시 다른 프레임이 나옴 | `flippedSx` 계산 오류 | `m_width - sx - sw` |
| 반전 시 느려짐 | 매 프레임 반전 연산 | 캐시 방식 사용 |
| 프레임마다 캐릭터가 흔들림 | 좌상단 기준 | **발밑 중앙 기준**으로 |
| 확대 시 흐릿함 | 보간 모드 | `SetStretchBltMode(hdc, COLORONCOLOR)` |
| 시트 미리보기가 안 나옴 | `DrawScaled` 미구현 | `StretchBlt` 사용 |
| 반전본 때문에 메모리 2배 | 정상 | 필요한 이미지만 캐시 |
| `%`/`/` 결과가 이상 | 열 수가 0 | `Init`에서 검증 |

## 7. 정리

### 오늘 배운 것

| 개념 | 한 줄 요약 |
|---|---|
| 스프라이트 시트 | 프레임 여러 개를 격자로 담은 이미지 한 장 |
| **인덱스 → 좌표** | `col = i % cols`, `row = i / cols` |
| `DrawPart` | `BitBlt`/`TransparentBlt`의 원본 좌표를 지정 |
| `Sprite` 클래스 | 시트 정보(프레임 크기, 열/행)를 묶는다 |
| **발밑 중앙 기준** | 격투게임·플랫포머의 표준. 바닥 판정이 자연스럽다 |
| 반전 캐시 | 미리 만들어 두면 빠르다. 메모리는 2배 |
| 반전 좌표 | `flippedSx = width - sx - sw` |
| 규격 검증 | 나누어떨어지지 않으면 경고 |
