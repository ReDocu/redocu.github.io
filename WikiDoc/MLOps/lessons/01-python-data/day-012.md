공통 부분을 두 번 쓰면, 재시도 로직을 고칠 때 **두 곳을 고쳐야 합니다.** 하나를 빠뜨리면 버그입니다.

**상속은 "공통은 부모에, 다른 것만 자식에"** 를 코드로 표현하는 도구입니다.

그리고 `@dataclass` 는 반대 방향의 도구입니다.

```python
def __init__(self, todo_id, title, priority, tags):
    self.id = todo_id
    self.title = title            # 이름을 그대로 옮겨 적기만 함
    self.priority = priority
    self.tags = tags
```

## ③ 개념 설명

### 상속 기본

```python
class Animal:                          # 부모(super/base) 클래스
    def __init__(self, name):
        self.name = name

    def speak(self):
        return "..."


class Dog(Animal):                     # 자식(sub/derived) 클래스
    def speak(self):                   # 오버라이딩 — 부모 것을 덮어씀
        return "멍멍"
```

```python
d = Dog("바둑이")
d.name         # '바둑이'   ← 부모의 __init__ 을 물려받음
d.speak()      # '멍멍'     ← 자식 것이 우선
```

**자식은 부모의 모든 것을 물려받고, 필요한 것만 바꿉니다.**

### `super()` — 부모 기능 재사용

자식에서 `__init__` 을 새로 쓰면 **부모 것이 실행되지 않습니다.**

```python
class Dog(Animal):
    def __init__(self, name, breed):
        self.breed = breed             # name 이 설정 안 됨!
```

`super()` 로 부모를 호출해야 합니다.

```python
class Dog(Animal):
    def __init__(self, name, breed):
        super().__init__(name)         # 부모의 __init__ 실행
        self.breed = breed             # 자식만의 추가
```

**메서드에서도 씁니다.**

```python
class LoudDog(Dog):
    def speak(self):
        return super().speak().upper() + "!!!"     # 부모 결과를 가공
```

### 메서드 탐색 순서

```python
d = Dog("바둑이")
d.speak()
```

파이썬은 이 순서로 찾습니다.

```
Dog 에 speak 가 있는가?  →  있으면 그것 사용
없으면 Animal 에 있는가?  →  있으면 그것 사용
없으면 object 에 있는가?  →  없으면 AttributeError
```

이 순서를 **MRO(Method Resolution Order)** 라고 하며, `Dog.__mro__` 로 확인할 수 있습니다.

### `isinstance` 로 관계 확인

```python
d = Dog("바둑이")
isinstance(d, Dog)         # True
isinstance(d, Animal)      # True   ← 자식은 부모이기도 함
isinstance(d, Cat)         # False
```

> **`type(d) == Dog` 보다 `isinstance(d, Dog)` 를 쓰세요.**
> `isinstance` 는 상속 관계를 인정하지만 `type ==` 은 정확히 그 클래스만 봅니다.

### 추상 부모 — "이건 자식이 반드시 구현해라"

```python
from abc import ABC, abstractmethod


class Collector(ABC):
    """수집기 공통 부모. 직접 인스턴스로 만들 수 없습니다."""

    def __init__(self, name, retries=3):
        self.name = name
        self.retries = retries

    @abstractmethod
    def fetch(self, target):
        """자식이 반드시 구현해야 합니다."""
        ...

    def run(self, targets):
        """공통 실행 로직 — 자식이 만든 fetch 를 사용합니다."""
        results = []
        for t in targets:
            for attempt in range(1, self.retries + 1):
                try:
                    results.append(self.fetch(t))
                    break
                except Exception as e:
                    print(f"  [{self.name}] {t} 실패 {attempt}/{self.retries}: {e}")
        return results
```

```python
Collector("x")      # TypeError: Can't instantiate abstract class
```

**`fetch` 를 구현하지 않은 자식도 만들 수 없습니다.**
"이 인터페이스를 지켜라"를 코드로 강제하는 것입니다.

이 구조를 **템플릿 메서드 패턴**이라고 합니다.
`run()` 이 큰 흐름을 정하고, 바뀌는 부분(`fetch`)만 자식에게 맡깁니다.

### 상속 vs 컴포지션

상속은 강력하지만 **남용하면 위험합니다.**

| 관계 | 표현 | 예 |
|---|---|---|
| **is-a** (~이다) | 상속 | `APICollector` **는** `Collector` **이다** ✅ |
| **has-a** (~를 가진다) | 컴포지션 | `TodoList` **는** `Todo` 들**을 가진다** ✅ |

```python
# ❌ 잘못된 상속 — TodoList 는 Todo 가 아님
class TodoList(Todo): ...

# ✅ 컴포지션 — 안에 담는다
class TodoList:
    def __init__(self):
        self.items = []
```

> **실무 조언: 상속보다 컴포지션을 우선하세요.**
> 상속은 부모가 바뀌면 모든 자식이 영향을 받습니다. 깊은 상속(3단 이상)은 추적이 어렵습니다.
> **공통 코드가 정말 같고, "~이다" 관계가 자연스러울 때만** 씁니다.

### 매직 메서드 정리

| 메서드 | 지원 문법 | 언제 정의 |
|---|---|---|
| `__init__` | `Todo(...)` | 항상 |
| `__str__` | `print(x)`, `f"{x}"` | 사람이 읽을 때 |
| `__repr__` | 목록 안 표시, 디버깅 | **개발자가 볼 때** |
| `__eq__` | `x == y` | 내용 비교가 필요할 때 |
| `__lt__` | `x < y`, `sorted()` | 정렬 기준이 있을 때 |
| `__len__` | `len(x)` | 개수 개념이 있을 때 |
| `__iter__` | `for i in x` | 순회 가능할 때 |
| `__contains__` | `y in x` | 포함 검사 |
| `__getitem__` | `x[0]` | 인덱싱 |

### `__str__` vs `__repr__`

```python
class Todo:
    def __str__(self):
        return f"[{'✔' if self.done else ' '}] {self.title}"

    def __repr__(self):
        return f"Todo(id={self.id}, title={self.title!r}, done={self.done})"
```

| | `__str__` | `__repr__` |
|---|---|---|
| 대상 | 최종 사용자 | 개발자 |
| 목적 | 보기 좋게 | **정확하게** |
| 호출 | `print(x)`, `str(x)` | 리스트 안, `repr(x)`, 디버거 |
| 관례 | 자유 | `ClassName(인자=값)` 형태 |

**`__repr__` 만 정의하면 `__str__` 도 그것을 씁니다.** 하나만 만든다면 `__repr__` 을 만드세요.

```python
todos = [Todo(1, "a"), Todo(2, "b")]
print(todos)      # [Todo(id=1, title='a', done=False), Todo(id=2, ...)]
```

`print(리스트)` 는 **각 요소의 `__repr__`** 을 씁니다. `__str__` 이 아닙니다.

### `__eq__` 와 정렬

```python
class Todo:
    def __eq__(self, other):
        if not isinstance(other, Todo):
            return NotImplemented
        return self.id == other.id

    def __lt__(self, other):
        return self.id < other.id
```

`__lt__` 만 정의해도 `sorted()` 가 동작합니다.

> **`__eq__` 를 정의하면 세트·딕셔너리 키로 못 씁니다.**
> `__hash__` 가 자동으로 `None` 이 되기 때문입니다. 필요하면 함께 정의하세요.
> ```python
> def __hash__(self):
>     return hash(self.id)
> ```

### `@dataclass` — 반복을 없애기

```python
from dataclasses import dataclass, field


@dataclass
class Todo:
    id: int
    title: str
    priority: str = "보통"
    tags: list = field(default_factory=list)
    done: bool = False
```

**이 한 덩어리가 아래를 전부 자동 생성합니다.**

- `__init__` — `Todo(1, "장보기")`
- `__repr__` — `Todo(id=1, title='장보기', priority='보통', tags=[], done=False)`
- `__eq__` — 모든 필드를 비교

```python
t1 = Todo(1, "장보기")
t2 = Todo(1, "장보기")
t1 == t2          # True   ← 자동으로 내용 비교
```

**핵심 규칙**

| 항목 | 설명 |
|---|---|
| 타입 힌트 필수 | `id: int` 처럼 써야 필드로 인식됨 |
| 기본값은 뒤로 | 기본값 있는 필드가 앞에 오면 에러 |
| **가변 기본값** | `tags: list = []` ❌ → `field(default_factory=list)` ✅ |
| 검증 | `__post_init__` 에서 |
| 불변 | `@dataclass(frozen=True)` |
| 정렬 지원 | `@dataclass(order=True)` — `<`, `sorted()` 자동 |

### `__post_init__` — 생성 직후 검증

```python
@dataclass
class Todo:
    id: int
    title: str
    priority: str = "보통"

    def __post_init__(self):
        self.title = self.title.strip()
        if not self.title:
            raise ValueError("제목은 비워 둘 수 없습니다.")
        if self.priority not in ("높음", "보통", "낮음"):
            raise ValueError(f"우선순위가 잘못되었습니다: {self.priority!r}")
```

`__init__` 이 끝난 직후 자동으로 호출됩니다. **검증과 정규화를 여기에 씁니다.**

### 언제 dataclass를 쓰나

| dataclass가 적합 | 일반 클래스가 적합 |
|---|---|
| 데이터를 담는 것이 주 목적 | 동작(메서드)이 주 목적 |
| 필드가 많고 `__init__` 이 지루함 | 복잡한 초기화 로직이 있음 |
| 내용 비교(`==`)가 필요 | 상태 관리가 복잡함 |
| 레코드·설정·DTO | 서비스·수집기·매니저 |

> `Todo`(데이터) → dataclass, `TodoList`(관리) → 일반 클래스. 이렇게 섞어 쓰는 것이 자연스럽습니다.

### Step 1. 상속 기본

`inherit_basics.py` 를 만듭니다.

```python
class Animal:
    def __init__(self, name, sound="..."):
        self.name = name
        self.sound = sound

    def speak(self):
        return f"{self.name}: {self.sound}"

    def info(self):
        return f"{type(self).__name__}({self.name})"


class Dog(Animal):
    def __init__(self, name, breed="믹스"):
        super().__init__(name, "멍멍")      # 부모 __init__ 호출
        self.breed = breed

    def info(self):
        return f"{super().info()} - {self.breed}"      # 부모 결과를 확장

    def fetch(self):
        return f"{self.name}가 공을 물어 옵니다."


class Cat(Animal):
    def __init__(self, name):
        super().__init__(name, "야옹")

    def speak(self):
        return f"{super().speak()} (관심 없음)"          # 오버라이딩 + 부모 재사용


animals = [Dog("바둑이", "진돗개"), Cat("나비"), Animal("정체불명")]

for a in animals:
    print(f"{a.info():<28} {a.speak()}")

print("\n--- isinstance ---")
d = animals[0]
print(f"  Dog     : {isinstance(d, Dog)}")
print(f"  Animal  : {isinstance(d, Animal)}   ← 자식은 부모이기도 함")
print(f"  Cat     : {isinstance(d, Cat)}")

print("\n--- 자식만의 메서드 ---")
for a in animals:
    if isinstance(a, Dog):
        print(f"  {a.fetch()}")

print("\n--- MRO (메서드 탐색 순서) ---")
for cls in Dog.__mro__:
    print(f"  {cls.__name__}")
```

### Step 2. 수집기 계층 — W04 예고편

`collector_base.py` 를 만듭니다. **오늘의 핵심 실습**입니다.

```python
import random
import time
from abc import ABC, abstractmethod


class CollectorError(Exception):
    """수집 실패."""


class Collector(ABC):
    """수집기 공통 부모.

    자식은 fetch() 하나만 구현하면 됩니다.
    재시도·간격 제어·로그·집계는 부모가 처리합니다.
    """

    def __init__(self, name, retries=3, delay=0.2):
        self.name = name
        self.retries = retries
        self.delay = delay
        self.success_count = 0
        self.fail_count = 0
        self.errors = []

    @abstractmethod
    def fetch(self, target):
        """대상 하나를 수집합니다. 실패하면 CollectorError를 던집니다."""
        ...

    def run(self, targets):
        """공통 실행 흐름 — 이 코드는 자식마다 다시 쓸 필요가 없습니다."""
        results = []
        print(f"\n[{self.name}] {len(targets)}개 대상 수집 시작")

        for target in targets:
            data = self._fetch_with_retry(target)
            if data is not None:
                results.append(data)

            time.sleep(self.delay)

        print(f"[{self.name}] 완료 — 성공 {self.success_count} / 실패 {self.fail_count}")
        return results

    def _fetch_with_retry(self, target):
        """재시도를 포함한 수집. 내부용이므로 _ 로 시작."""
        for attempt in range(1, self.retries + 1):
            try:
                data = self.fetch(target)
            except CollectorError as e:
                if attempt < self.retries:
                    print(f"  {target} 실패 ({attempt}/{self.retries}): {e} — 재시도")
                    time.sleep(self.delay)
                    continue
                print(f"  {target} 최종 실패: {e}")
                self.fail_count += 1
                self.errors.append({"target": target, "reason": str(e)})
                return None
            else:
                self.success_count += 1
                return data

    def report(self):
        total = self.success_count + self.fail_count
        rate = self.success_count / total if total else 0
        return {
            "collector": self.name,
            "total": total,
            "success": self.success_count,
            "failed": self.fail_count,
            "success_rate": rate,
            "errors": self.errors,
        }

    def __repr__(self):
        return f"{type(self).__name__}(name={self.name!r}, retries={self.retries})"


class APICollector(Collector):
    """JSON API에서 수집합니다."""

    def __init__(self, base_url, retries=3, delay=0.2):
        super().__init__("API", retries, delay)
        self.base_url = base_url

    def fetch(self, target):
        status = random.choice([200, 200, 200, 503])
        if status != 200:
            raise CollectorError(f"HTTP {status}")
        return {"source": "api", "url": f"{self.base_url}/{target}", "id": target}


class CrawlerCollector(Collector):
    """웹 페이지를 파싱해 수집합니다."""

    def __init__(self, base_url, retries=3, delay=0.2):
        super().__init__("Crawler", retries, delay)
        self.base_url = base_url

    def fetch(self, target):
        if random.random() < 0.25:
            raise CollectorError("셀렉터를 찾을 수 없음")
        return {"source": "crawler", "url": f"{self.base_url}/page/{target}", "id": target}


# ---------- 실행 ----------

random.seed(42)      # 결과 재현을 위해 고정

collectors = [
    APICollector("https://api.example.com"),
    CrawlerCollector("https://news.example.com", retries=2),
]

all_results = []
for c in collectors:
    print(f"\n{c!r}")
    all_results.extend(c.run([1, 2, 3, 4, 5]))

print("\n" + "=" * 52)
print(f"전체 수집 {len(all_results)}건\n")

for c in collectors:
    r = c.report()
    print(f"  {r['collector']:<10} 성공 {r['success']}/{r['total']}  "
          f"({r['success_rate']:.0%})")
    for e in r["errors"]:
        print(f"    ✗ {e['target']}: {e['reason']}")
```

실행 결과:

```python
class Money:
    """금액. 원 단위 정수로 관리합니다."""

    def __init__(self, won):
        if not isinstance(won, int):
            raise TypeError(f"금액은 정수여야 합니다: {won!r}")
        self.won = won

    # --- 표현 ---
    def __str__(self):
        return f"{self.won:,}원"

    def __repr__(self):
        return f"Money({self.won})"

    # --- 비교 ---
    def __eq__(self, other):
        if not isinstance(other, Money):
            return NotImplemented
        return self.won == other.won

    def __lt__(self, other):
        if not isinstance(other, Money):
            return NotImplemented
        return self.won < other.won

    def __hash__(self):
        return hash(self.won)

    # --- 연산 ---
    def __add__(self, other):
        return Money(self.won + other.won)

    def __sub__(self, other):
        return Money(self.won - other.won)

    def __mul__(self, n):
        return Money(self.won * n)

    def __bool__(self):
        return self.won != 0


a = Money(89_000)
b = Money(12_500)

print("--- 표현 ---")
print(f"  str  : {a}")
print(f"  repr : {a!r}")
print(f"  목록  : {[a, b]}    ← 목록 안에서는 __repr__")

print("\n--- 연산 ---")
print(f"  {a} + {b} = {a + b}")
print(f"  {a} - {b} = {a - b}")
print(f"  {b} × 3  = {b * 3}")

print("\n--- 비교와 정렬 ---")
print(f"  {a} == {Money(89000)} : {a == Money(89000)}")
print(f"  {a} > {b}  : {a > b}   ← __lt__ 만 정의해도 > 가 동작")

prices = [Money(89_000), Money(12_500), Money(3_000), Money(45_900)]
print(f"  정렬: {[str(m) for m in sorted(prices)]}")
print(f"  최대: {max(prices)}")
print(f"  합계: {sum(prices, Money(0))}")

print("\n--- bool ---")
print(f"  Money(0)   → {bool(Money(0))}")
print(f"  Money(100) → {bool(Money(100))}")
if not Money(0):
    print("  0원은 falsy 로 취급됩니다.")

print("\n--- 세트·딕셔너리 키 (__hash__ 덕분) ---")
unique = {Money(1000), Money(1000), Money(2000)}
print(f"  {sorted(unique, key=lambda m: m.won)}")
```

### Step 4. dataclass로 다시 쓰기

`todo_dataclass.py` 를 만듭니다. [Day 011](day-011.md)의 `Todo` 와 비교하세요.

```python
from dataclasses import dataclass, field, asdict
from datetime import datetime


@dataclass(order=True)
class Todo:
    """할 일 하나 (dataclass 버전)."""

    id: int
    title: str
    priority: str = "보통"
    tags: list = field(default_factory=list)
    done: bool = False
    created_at: str = field(default_factory=lambda: datetime.now().strftime("%Y-%m-%d %H:%M"))
    completed_at: str | None = None

    PRIORITIES = ("높음", "보통", "낮음")      # 타입 힌트가 없으므로 필드가 아님 = 클래스 상수

    def __post_init__(self):
        """생성 직후 검증과 정규화."""
        self.title = self.title.strip()
        if not self.title:
            raise ValueError("제목은 비워 둘 수 없습니다.")
        if self.priority not in self.PRIORITIES:
            raise ValueError(f"우선순위가 잘못되었습니다: {self.priority!r}")
        self.tags = sorted(set(self.tags))

    def complete(self):
        if not self.done:
            self.done = True
            self.completed_at = datetime.now().strftime("%Y-%m-%d %H:%M")
        return self

    def reopen(self):
        self.done = False
        self.completed_at = None
        return self

    def matches(self, keyword):
        keyword = keyword.strip().lower()
        if not keyword:
            return False
        return keyword in self.title.lower() or any(keyword in t.lower() for t in self.tags)

    def to_dict(self):
        return asdict(self)          # dataclass 전용 — 자동 변환

    @classmethod
    def from_dict(cls, data):
        return cls(**data)           # 딕셔너리를 키워드 인자로 펼침


t1 = Todo(1, "  MP1 데이터 선정  ", "높음", ["프로젝트", "급함", "프로젝트"])
t2 = Todo(2, "Day 012 과제")

print("--- 자동 생성된 __repr__ ---")
print(f"  {t1!r}")
print(f"  {t2!r}")

print("\n--- __post_init__ 이 정규화함 ---")
print(f"  제목 공백 제거: {t1.title!r}")
print(f"  태그 중복 제거·정렬: {t1.tags}")

print("\n--- 자동 생성된 __eq__ ---")
a = Todo(1, "같은 것")
b = Todo(1, "같은 것")
print(f"  내용이 같으면 == : {a == b}")
print(f"  하나만 바꾸면    : {a == Todo(1, '다른 것')}")

print("\n--- order=True 덕분에 정렬 ---")
todos = [Todo(3, "C"), Todo(1, "A"), Todo(2, "B")]
print(f"  {[t.title for t in sorted(todos)]}")

print("\n--- 변환 ---")
d = t1.to_dict()
print(f"  to_dict  : {d}")
restored = Todo.from_dict(d)
print(f"  복원 후 == : {restored == t1}")

print("\n--- 검증 ---")
for label, args in [("빈 제목", (9, "   ")), ("잘못된 우선순위", (9, "정상", "매우높음"))]:
    try:
        Todo(*args)
        print(f"  {label:<14} → 통과됨 (문제!)")
    except ValueError as e:
        print(f"  {label:<14} → {e}")

print("\n--- 가변 기본값 함정 확인 ---")
x = Todo(10, "X")
y = Todo(11, "Y")
x.tags.append("업무")
print(f"  x.tags = {x.tags}")
print(f"  y.tags = {y.tags}   ← field(default_factory=list) 덕분에 분리됨")
```

실행 결과:

### Step 5. frozen dataclass — 설정에 적합

`config_dataclass.py` 를 만듭니다.

```python
from dataclasses import dataclass, field, replace


@dataclass(frozen=True)
class RetryConfig:
    """재시도 설정. 만들어진 뒤 바뀌지 않습니다."""
    max_attempts: int = 3
    backoff: float = 1.5
    timeout: float = 10.0

    def __post_init__(self):
        if self.max_attempts < 1:
            raise ValueError(f"max_attempts는 1 이상이어야 합니다: {self.max_attempts}")
        if self.backoff <= 1.0:
            raise ValueError(f"backoff는 1보다 커야 합니다: {self.backoff}")

    def delay_for(self, attempt):
        """n번째 시도 전 대기 시간 (지수 백오프)."""
        return self.backoff ** (attempt - 1)


@dataclass(frozen=True)
class CollectorConfig:
    name: str
    url: str
    interval: int = 3600
    enabled: bool = True
    retry: RetryConfig = field(default_factory=RetryConfig)


cfg = CollectorConfig("api", "https://api.example.com")
print(f"{cfg!r}\n")

print("--- 지수 백오프 대기 시간 ---")
for attempt in range(1, cfg.retry.max_attempts + 1):
    print(f"  {attempt}회차: {cfg.retry.delay_for(attempt):.2f}초 대기")

print("\n--- 수정 시도 (frozen) ---")
try:
    cfg.interval = 60
except Exception as e:
    print(f"  {type(e).__name__}: {e}")

print("\n--- 일부만 바꾼 새 설정 만들기 ---")
fast = replace(cfg, interval=60, name="api-fast")
print(f"  원본: {cfg.name}, interval={cfg.interval}")
print(f"  사본: {fast.name}, interval={fast.interval}")
print(f"  retry 설정은 그대로: {fast.retry == cfg.retry}")

print("\n--- 잘못된 설정은 생성 시점에 거부 ---")
for label, kwargs in [("시도 0회", {"max_attempts": 0}), ("backoff 1.0", {"backoff": 1.0})]:
    try:
        RetryConfig(**kwargs)
        print(f"  {label:<14} → 통과됨 (문제!)")
    except ValueError as e:
        print(f"  {label:<14} → {e}")
```

실행 결과:

```

  1회차: 1.00초 대기
  2회차: 1.50초 대기
  3회차: 2.25초 대기

--- 수정 시도 (frozen) ---

--- 일부만 바꾼 새 설정 만들기 ---

--- 잘못된 설정은 생성 시점에 거부 ---
```

## ⑥ 확인 문제

**1.** 아래 코드의 출력을 예측하고, `super()` 가 하는 일을 설명하세요.

```python

    def greet(self):
        return "A"

class B(A):
    def greet(self):
        return super().greet() + "B"

class C(B):
    def greet(self):
        return super().greet() + "C"

print(C().greet())
```

<details>
<summary>답 보기</summary>

```
ABC
```

**호출 흐름**

```
C().greet()
  └─ super().greet()  →  B.greet()
        └─ super().greet()  →  A.greet()
              └─ "A" 반환
        └─ "A" + "B" = "AB" 반환
  └─ "AB" + "C" = "ABC"
```

`super()` 는 **MRO에서 자기 바로 다음 클래스**를 가리킵니다. 부모를 이름으로 직접 부르지 않는 이유는:

1. 부모 이름이 바뀌어도 코드를 안 고쳐도 됩니다.
2. 다중 상속에서 MRO를 올바르게 따라갑니다.
3. 중간에 클래스를 끼워 넣어도 자동으로 연결됩니다.

`C.__mro__` 는 `(C, B, A, object)` 입니다.

**실무 활용** — "부모의 동작 + 내 동작"을 표현할 때 씁니다.

```python
class TimedCollector(APICollector):
    def fetch(self, target):
        start = time.perf_counter()
        result = super().fetch(target)        # 부모의 수집을 그대로 쓰고
        result["elapsed"] = time.perf_counter() - start   # 시간만 추가
        return result
```

W20 [Day 098](../04-deep-learning-serving/day-098.md)의 처리시간 측정 미들웨어가 같은 발상입니다.
</details>

**2.** `@dataclass` 를 쓰면 자동으로 생성되는 것 세 가지는 무엇이고, 각각 어떤 상황에서 필요한가요?

<details>
<summary>답 보기</summary>

| 자동 생성 | 지원 문법 | 필요한 상황 |
|---|---|---|
| `__init__` | `Todo(1, "장보기")` | **항상** — 필드를 그대로 옮겨 적는 반복 제거 |
| `__repr__` | `print(obj)`, 목록 안 표시, 디버깅 | 로그·에러 메시지·디버깅에서 값을 확인할 때 |
| `__eq__` | `a == b`, `in` 검사 | **테스트** — 기대값과 실제값을 통째로 비교 |

**`__eq__` 가 특히 중요한 이유**

```python
def test_from_dict():
    original = Todo(1, "장보기", "높음", ["업무"])
    restored = Todo.from_dict(original.to_dict())
    assert restored == original            # ← 한 줄로 모든 필드 검증
```

`__eq__` 가 없으면 필드를 하나씩 비교해야 합니다.

```python
assert restored.id == original.id
assert restored.title == original.title
assert restored.priority == original.priority
# ... 필드를 추가할 때마다 여기도 추가해야 함
```

[Day 014](day-014.md)에서 pytest를 배우면 이 차이가 크게 느껴집니다.

**옵션으로 더 얻을 수 있는 것**

| 옵션 | 추가로 생성 |
|---|---|
| `order=True` | `__lt__` `__le__` `__gt__` `__ge__` → `sorted()` 가능 |
| `frozen=True` | 수정 차단 + `__hash__` → 세트·딕셔너리 키 가능 |
| `slots=True` | 메모리 절약 (수십만 개 객체를 만들 때) |

**안 만들어 주는 것**은 `__str__` 입니다. `__repr__` 만 만들어 주므로,
사용자에게 보여 줄 형식이 따로 필요하면 직접 정의하세요.
</details>

**3.** W04에서 API 수집기와 크롤러를 만들 예정입니다. 아래 두 설계 중 어느 쪽이 좋고, 왜인가요?

```python
# A) 상속
class Collector(ABC):
    def run(self, targets): ...       # 공통: 재시도·간격·로그
    @abstractmethod
    def fetch(self, target): ...      # 다름: 실제 수집

class APICollector(Collector):
    def fetch(self, target): ...


# B) 각각 독립 클래스
class APICollector:
    def run(self, targets): ...       # 재시도·간격·로그 (복붙)
    def fetch(self, target): ...

class CrawlerCollector:
    def run(self, targets): ...       # 재시도·간격·로그 (복붙)
    def fetch(self, target): ...
```

<details>
<summary>답 보기</summary>

**A(상속)가 맞습니다.** 이 상황이 상속의 교과서적 사례이기 때문입니다.

**조건 세 가지가 모두 충족됩니다.**

1. **"~이다" 관계가 자연스럽다** — `APICollector 는 Collector 이다` ✅
2. **공통 코드가 정말 같다** — 재시도 3회, 1초 간격, 실패 로그. 우연히 비슷한 게 아니라 **본질적으로 같은 절차**
3. **다른 부분이 명확히 하나다** — `fetch()` 만 다름

**B의 구체적 문제**

| 상황 | 결과 |
|---|---|
| 재시도를 3회 → 5회로 변경 | **두 파일**을 고쳐야 함. 하나를 빠뜨리면 동작이 갈림 |
| 지수 백오프 추가 | 두 곳에 같은 코드 복붙 |
| 세 번째 수집기 추가 | `run()` 을 또 복붙 |
| 실패 리포트 형식 변경 | 두 곳 수정 |
| 테스트 | `run()` 을 두 번 테스트해야 함 |

복붙된 코드는 시간이 지나면서 **조금씩 달라집니다.** 그러면 "API는 되는데 크롤러만 이상하다" 같은 버그가 생깁니다.

**A로 얻는 것**

```python
# 새 수집기 추가 = fetch 하나만 구현
class DBCollector(Collector):
    def fetch(self, target):
        return self.conn.execute(...).fetchone()
```

3줄로 재시도·간격·로그·리포트를 전부 얻습니다.

**다만 상속이 항상 답은 아닙니다.**

만약 크롤러가 "재시도 대신 프록시 교체", API가 "재시도 후 백오프"처럼 **공통 흐름 자체가 다르다면**
억지로 상속하지 말고 각자 만들거나, 재시도 로직만 별도 클래스로 분리해 **주입**하는 편이 낫습니다.

```python
class Collector:
    def __init__(self, retry_policy):     # 컴포지션
        self.retry_policy = retry_policy
```

**판단 순서**: ① "~이다"가 성립하는가 → ② 공통이 본질적으로 같은가 → ③ 상속 깊이가 2단 이내인가.
셋 다 예일 때만 상속을 쓰고, 아니면 컴포지션을 씁니다.
</details>

## 오늘의 정리

| 항목 | 문법 |
|---|---|
| 상속 | `class Dog(Animal):` |
| 부모 호출 | `super().__init__(...)` · `super().메서드()` |
| 오버라이딩 | 자식에 같은 이름 메서드를 정의 |
| 추상 메서드 | `from abc import ABC, abstractmethod` · `@abstractmethod` |
| 관계 확인 | `isinstance(x, Animal)` (`type ==` 보다 권장) |
| 상속 vs 컴포지션 | **is-a** → 상속 · **has-a** → 안에 담기 |
| 표현 | `__str__` 사용자용 · `__repr__` **개발자용(목록·디버깅)** |
| 비교 | `__eq__` · `__lt__` 하나로 정렬 전부 지원 · `__hash__` 함께 |
| dataclass | `@dataclass` → `__init__` `__repr__` `__eq__` 자동 |
| 가변 기본값 | `field(default_factory=list)` |
| 검증 | `__post_init__` |
| 옵션 | `order=True` 정렬 · `frozen=True` 불변+해시 |
| 변환 | `asdict(obj)` · `replace(obj, 필드=값)` |
