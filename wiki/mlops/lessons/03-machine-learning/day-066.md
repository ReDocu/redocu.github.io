## ② 왜 필요한가

이 대화는 ML 팀에서 매주 일어납니다.

```
후임:  "선배 노트북에선 0.519라면서요. 제 컴퓨터에선 0.503인데요."
선배:  "이상하네, 같은 코드인데?"
       (반나절 뒤)
선배:  "……제가 데이터 정제를 다시 한 버전을 쓰고 있었네요. 코드는 같은데 데이터가 달랐어요."
```

어제의 재현 게임은 **기록**의 문제였습니다. 오늘은 한 층 아래 — 기록이 완벽해도
**실행 환경 자체가 흔들리면** 같은 결과가 안 나옵니다. 그리고 재현성은 학문적 결벽이 아니라
MLOps의 생존 조건입니다.

| 재현이 안 되면 | 결과 |
|---|---|
| 버그 수정 후 성능 비교 불가 | "고쳤더니 0.003 올랐다" — 수정 효과인가 난수인가? |
| 장애 시 롤백 불가 | "지난달 모델로 돌려라" — 그 모델을 다시 만들 수 없음 |
| 협업 불가 | 어제의 재현 게임 |
| 감사(audit) 불가 | "이 대출 거절 판정의 근거 모델을 제출하라" — 금융·의료의 법적 요구 |

MP2 평가 기준의 "재현성 20점", 그리고 대단원 05에서 배울 Docker·DVC가 전부 오늘의 연장선입니다.

## ③ 개념 설명

### 재현성의 4요소

"같은 실험"이려면 네 가지가 같아야 합니다. 하나라도 다르면 다른 실험입니다.

| 요소 | 흔들리는 예 | 고정 수단 |
|---|---|---|
| **코드** | "그 사이 전처리를 살짝 고침" | git 커밋 해시 |
| **데이터** | 파이프라인이 새 데이터를 적재함, 정제 재실행 | **파일 해시** · 버전 관리(DVC, W27) |
| **환경** | sklearn 1.6 → 1.7에서 기본값 변경 | `requirements.txt` 버전 고정, Docker(W24) |
| **난수** | 부트스트랩·초기화·셔플 | `random_state` / `np.random.default_rng(시드)` |

### 난수는 어디에 숨어 있나

우리가 쓴 것들만 해도: 랜덤포레스트의 부트스트랩·특성 선택, train_test_split의 셔플,
KFold(shuffle=True), Optuna의 샘플러, LightGBM의 서브샘플링. **`random_state` 인자가 있는
모든 곳**이 난수 소비처이고, 그 인자를 비우면 실행마다 다른 우주가 됩니다.

> 시드를 고정하는 이유는 "그 시드가 좋아서"가 아닙니다. **차이의 원인을 하나로 좁히기
> 위해서**입니다. 시드까지 같은데 결과가 다르면 → 코드·데이터·환경 중 무언가가 다른 것.
> 이 소거법이 재현성의 실용적 가치입니다.

### 데이터의 지문 — 해시

파일 내용을 한 줄 문자열로 요약한 것이 해시입니다. **내용이 1바이트만 달라도 완전히 다른
값**이 나오므로, "우리 둘이 같은 데이터를 쓰고 있나?"를 눈 비비고 diff 할 필요 없이
지문 한 줄 비교로 끝냅니다.

### 환경의 지문 — requirements.txt

```powershell
pip freeze > requirements.txt      # 지금 환경의 전체 버전 목록을 기록
pip install -r requirements.txt    # 그 목록 그대로 복원
```

라이브러리 버전이 다르면 **에러가 나는 게 차라리 행운**입니다. 무서운 것은 기본값·알고리즘이
조용히 바뀌어 숫자만 달라지는 경우입니다 (Day 051에서 버전을 못 박은 이유).

## ④ 단계별 실습

### Step 1. 시드 없는 코드의 배신 (1~2교시)

```python
# day066_repro.py — 재현성: 시드·해시·환경
import hashlib
import numpy as np
import pandas as pd
from sklearn.ensemble import RandomForestClassifier
from sklearn.metrics import roc_auc_score

pd.set_option("display.width", 140)
df = pd.read_csv("data/air_daily.csv", parse_dates=["date"])
F10 = ["pm10", "pm25", "o3", "no2", "co", "so2", "temp", "humidity", "wind_speed", "precip"]
d = df.dropna(subset=F10).copy()
d["bad_next"] = (d.pm25_next >= 36).astype(int)
tr = d[d.date < "2026-01-01"]; te = d[d.date >= "2026-01-01"]
Xtr, ytr, Xte, yte = tr[F10], tr.bad_next, te[F10], te.bad_next

print("== A. 시드 없는 같은 코드, 두 번 실행 ==")
for i in [1, 2]:
    rf = RandomForestClassifier(n_estimators=100, n_jobs=-1).fit(Xtr, ytr)   # random_state 없음!
    print(f"  실행 {i}: test AUC {roc_auc_score(yte, rf.predict_proba(Xte)[:, 1]):.4f}")

print("\n== B. 시드 고정, 두 번 실행 ==")
for i in [1, 2]:
    rf = RandomForestClassifier(n_estimators=100, random_state=42, n_jobs=-1).fit(Xtr, ytr)
    print(f"  실행 {i}: test AUC {roc_auc_score(yte, rf.predict_proba(Xte)[:, 1]):.4f}")
```

실행 결과:

```
== A. 시드 없는 같은 코드, 두 번 실행 ==
  실행 1: test AUC 0.7807
  실행 2: test AUC 0.7847

== B. 시드 고정, 두 번 실행 ==
  실행 1: test AUC 0.7828
  실행 2: test AUC 0.7828
```

*(A의 두 값은 실행할 때마다 다르게 나옵니다 — 여러분의 값이 문서와 다른 것이 정상이며, 그게 바로 요점입니다.)*

시드 없는 A는 실행마다 0.004씩 출렁입니다. 사소해 보이나요? [Day 062](day-062.md)의 튜닝 이득이
+0.015였습니다 — **개선 폭의 1/4이 난수 소음**이면, "고쳐서 좋아졌다"는 주장의 상당수가
소음 위에 지어집니다. B처럼 시드를 고정하면 소수점 넷째 자리까지 동일합니다.

## ⑤ 자주 하는 실수

### 시드를 한 군데만 고정함

**증상** — 모델엔 `random_state=42`를 줬는데 여전히 실행마다 결과가 다름.
**원인** — `train_test_split`, KFold(shuffle), Optuna 샘플러 등 **다른 난수 소비처**가 남아 있습니다.
**해결** — `random_state` / `seed` 인자를 받는 모든 호출을 검색해 고정하세요. 병렬 처리(n_jobs) 자체는 이 데이터 규모에선 결과를 바꾸지 않지만, 시드 없는 병렬 학습은 실행 순서까지 뒤섞여 더 크게 출렁입니다.

### "시드 쇼핑"

**증상** — 시드를 1~50까지 돌려 보고 점수가 제일 좋은 시드로 보고.
**원인** — 시드는 고정용이지 튜닝 대상이 아닙니다. 시드로 오른 점수는 난수 소음의 좋은 쪽 끝일 뿐입니다([Day 062](day-062.md)의 승자의 저주와 같은 구조).
**해결** — 시드는 처음에 하나 정해 계속 씁니다(관례상 42). 시드 민감도가 궁금하면 여러 시드의 평균±표준편차로 **불확실성을 보고**하는 용도로만.

### 데이터를 덮어쓰며 작업함

**증상** — `air_daily.csv` 를 정제해서 같은 이름으로 저장 — 지난주 실험들의 데이터가 소멸.
**원인** — 원본을 덮어쓰면 그 파일로 잰 과거 결과는 전부 재현 불능이 됩니다.
**해결** — 원본은 불변으로 두고, 가공본은 새 이름(`_v2`)이나 파생 폴더로. 데이터 버전 관리의 정식 도구(DVC)는 W27에서 배웁니다.

### pip freeze를 프로젝트 막판에 한 번만 함

**증상** — requirements.txt는 있는데 석 달 전 것 — 그 사이 `pip install` 한 것들이 누락.
**원인** — 환경은 실험 중에 계속 자랍니다. 지문은 바뀔 때마다 갱신해야 지문입니다.
**해결** — 새 패키지를 설치한 커밋에는 반드시 requirements.txt 갱신을 포함하는 습관을 들이세요.

### "내 컴퓨터에선 되는데요"로 방어함

**증상** — 재현 실패 보고에 환경 탓·컴퓨터 탓으로 응수.
**원인** — 재현 실패는 4요소 중 무언가가 다르다는 **정보**이지 인격의 문제가 아닙니다.
**해결** — 소거법으로 답합시다: 커밋 해시 같은가 → 데이터 지문 같은가 → requirements 같은가 → 시드 같은가. 넷 다 같은데 다르면 그때가 진짜 흥미로운 버그입니다.
