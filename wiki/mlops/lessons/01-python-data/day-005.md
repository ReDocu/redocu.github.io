그리고 안 되는 코드를 고치는 능력의 90%는 **에러 메시지를 읽는 능력**입니다.

| 태도 | 결과 |

이 차이가 160일 누적되면 어마어마합니다.
그리고 W26에서 CI가 깨졌을 때, W25에서 컨테이너가 안 뜰 때, 여러분이 볼 수 있는 유일한 단서도 **로그와 에러 메시지**입니다.

오늘은 **새 문법을 배우지 않습니다.** 이번 주 내용만으로 하나를 끝까지 완성합니다.
이것이 이 과정의 금요일 운영 원칙입니다.

## ③ 개념 설명

### Traceback 읽는 법

파이썬 에러는 이렇게 생겼습니다.

```
Traceback (most recent call last):
  File "C:\workspace\mlops\budget.py", line 14, in <module>
    amount = int(raw_amount)
             ^^^^^^^^^^^^^^^
ValueError: invalid literal for int() with base 10: '오만원'
```

**읽는 순서는 아래에서 위로입니다.**

| 위치 | 읽어야 할 것 | 이 예시에서 |
|---|---|---|
| **마지막 줄** | 에러 종류와 이유 | `ValueError` — `'오만원'` 을 int로 못 바꿈 |
| **그 위** | 문제가 난 코드 | `amount = int(raw_amount)` |
| **File ... line N** | 파일과 줄 번호 | `budget.py` 14번 줄 |
| **맨 위 문장** | "가장 최근 호출이 마지막" | 여러 줄일 때 **맨 아래가 진짜 원인** |

> **`Traceback (most recent call last)`** 는 "함수 호출 경로를 보여 주는데, 가장 최근 것이 마지막"이라는 뜻입니다.
> 함수를 쓰기 시작하는 Day 006부터는 이 목록이 여러 줄이 됩니다. **항상 맨 아래부터 보세요.**

### 자주 만나는 에러 5종

| 에러 | 뜻 | 대표 원인 |
|---|---|---|
| `SyntaxError` | 문법이 틀림 | 콜론 누락, 괄호 안 닫음, 오타 |
| `NameError` | 이름을 모름 | 변수 오타, 정의 전에 사용 |
| `TypeError` | 타입이 안 맞음 | `"10" + 5` |
| `ValueError` | 타입은 맞는데 값이 이상 | `int("오만원")` |
| `IndentationError` | 들여쓰기가 어긋남 | Tab/Space 혼용 |

> **`SyntaxError` 는 특별합니다.** 코드가 아예 실행되지 않습니다. 나머지는 실행 중에 납니다.
> 그래서 `SyntaxError` 는 줄 번호가 실제 문제 위치보다 **한 줄 뒤**를 가리키는 경우가 많습니다.
> (예: 3번 줄에서 괄호를 안 닫으면 4번 줄에서 에러가 뜹니다.) 이럴 땐 **한 줄 위**를 보세요.

### print 디버깅

가장 원시적이고, 가장 많이 쓰이는 방법입니다.

```python
print(f"[DEBUG] i={i}, total={total}, type(total)={type(total)}")
```

**세 가지를 같이 찍는 것**이 요령입니다.
① 어디인지 표시(`[DEBUG]`) ② 변수 이름과 값 ③ 필요하면 타입

> 나중에 이 `print` 들은 전부 `logging` 으로 바뀝니다 ([Day 014](day-014.md)).
> `print` 는 지우면 사라지지만 로그는 서버에 남습니다. 그게 W23 이후의 세계입니다.

### VS Code 중단점(breakpoint)

값이 언제 어떻게 변하는지 **한 줄씩** 보고 싶을 때 씁니다.

| 조작 | 단축키 | 하는 일 |
|---|---|---|
| 중단점 찍기 | 줄 번호 왼쪽 클릭 (빨간 점) | 여기서 멈춤 |
| 디버깅 시작 | `F5` | 실행하다 중단점에서 정지 |
| 한 줄 실행 | `F10` | 다음 줄로 |
| 함수 안으로 | `F11` | 함수 내부까지 따라 들어감 |
| 계속 | `F5` | 다음 중단점까지 |
| 중지 | `Shift+F5` | 디버깅 종료 |

멈춘 상태에서 왼쪽 `변수` 패널을 보면 **그 시점의 모든 변수 값**이 보입니다.
`print` 를 10개 찍는 것보다 빠릅니다.

### Step 5. 가계부 — 입력과 검증

`budget.py` 에 입력 기능을 채웁니다.

```python
records = []

CATEGORIES = ("식비", "교통", "주거", "여가", "기타")


def show_menu():
    print()
    print("=" * 41)
    print("            콘솔 가계부 v0")
    print("=" * 41)
    print("1. 수입 추가")
    print("2. 지출 추가")
    print("3. 내역 보기")
    print("4. 요약 보기")
    print("0. 종료")
    print("-" * 41)


def input_amount():
    """올바른 금액이 들어올 때까지 반복해서 묻습니다."""
    while True:
        raw = input("  금액(원): ").strip().replace(",", "")
        if raw == "":
            print("  → 금액을 입력하세요.")
            continue
        if not raw.isdigit():
            print(f"  → '{raw}' 는 숫자가 아닙니다. 예: 12000")
            continue
        amount = int(raw)
        if amount <= 0:
            print("  → 0보다 큰 금액을 입력하세요.")
            continue
        return amount


def input_category():
    """지출 분류를 고릅니다."""
    print("  분류:", " / ".join(CATEGORIES))
    while True:
        cat = input("  분류 선택: ").strip()
        if cat in CATEGORIES:
            return cat
        print(f"  → '{cat}' 는 목록에 없습니다.")


while True:
    show_menu()
    choice = input("선택 > ").strip()

    if choice == "0":
        print("가계부를 종료합니다.")
        break

    elif choice == "1":
        print("\n[수입 추가]")
        memo = input("  내용: ").strip()
        amount = input_amount()
        records.append(("수입", "수입", memo, amount))
        print(f"  ✓ 수입 {amount:,}원 등록됨")

    elif choice == "2":
        print("\n[지출 추가]")
        memo = input("  내용: ").strip()
        category = input_category()
        amount = input_amount()
        records.append(("지출", category, memo, amount))
        print(f"  ✓ 지출 {amount:,}원 ({category}) 등록됨")

    elif choice == "3":
        print("\n[내역 보기] — 아직 구현 전")

    elif choice == "4":
        print("\n[요약 보기] — 아직 구현 전")

    else:
        print("0에서 4 사이의 숫자를 입력하세요.")
```

> `records.append(("지출", category, memo, amount))` 에서 괄호가 두 겹인 것에 주의하세요.
> 안쪽은 **튜플**(값 4개 묶음), 바깥은 `append()` 의 괄호입니다. 튜플은 Day 007에서 배웁니다.

실행 결과:

```
선택 > 2

[지출 추가]
  내용: 점심 김치찌개
  분류: 식비 / 교통 / 주거 / 여가 / 기타
  분류 선택: 식사
  → '식사' 는 목록에 없습니다.
  분류 선택: 식비
  금액(원): 9,000
  ✓ 지출 9,000원 (식비) 등록됨
```

> 사용자가 `9,000` 처럼 쉼표를 넣어도 `.replace(",", "")` 덕분에 처리됩니다.
> **입력을 받는 곳에서 정규화하는 것**이 원칙입니다. W09의 데이터 검증도 같은 철학입니다.

```python
    elif choice == "3":
        print("\n[내역 보기]")
        if len(records) == 0:
            print("  등록된 내역이 없습니다.")

                if kind == "수입":

                else:
                    expense += amount
                    if category == "식비":
                        food += amount
                    elif category == "교통":
                        transport += amount
                    elif category == "주거":
                        housing += amount
                    elif category == "여가":
                        leisure += amount
                    else:
                        etc += amount

            balance = income - expense

            print(f"  총 수입 : {income:>12,} 원")
            print(f"  총 지출 : {expense:>12,} 원")
            print("  " + "-" * 27)
            print(f"  잔액    : {balance:>12,} 원")

            if expense > 0:
                print("\n  [지출 분류별]")
                print(f"    식비  {food:>10,} 원  ({food / expense:>5.1%})")
                print(f"    교통  {transport:>10,} 원  ({transport / expense:>5.1%})")
                print(f"    주거  {housing:>10,} 원  ({housing / expense:>5.1%})")
                print(f"    여가  {leisure:>10,} 원  ({leisure / expense:>5.1%})")
                print(f"    기타  {etc:>10,} 원  ({etc / expense:>5.1%})")

            if balance < 0:
                print(f"\n  ⚠ 적자입니다. {-balance:,}원 초과 지출했습니다.")
            elif balance == 0:
                print("\n  수입과 지출이 정확히 같습니다.")
            else:
                rate = balance / income
                print(f"\n  저축률 {rate:.1%} 입니다.")
```

```
    여가      14,000 원  ( 17.9%)
    기타           0 원  (  0.0%)

  저축률 97.2% 입니다.
```

> **`kind, category, memo, amount = rec`** 는 튜플을 4개 변수로 한 번에 푸는 문법입니다.
> **언패킹(unpacking)** 이라고 하며 Day 007에서 다룹니다.

### `TypeError: unsupported operand type(s) for +=: 'int' and 'str'`

```
Traceback (most recent call last):
  File "debug_practice.py", line 5, in <module>
    total += s
TypeError: unsupported operand type(s) for +=: 'int' and 'str'
```

**원인** — 리스트의 요소가 문자열인데 정수에 더하려 했습니다. CSV·JSON에서 읽은 값에서 매일 납니다.
**해결** — `total += int(s)`. 그리고 **의심되면 `type()` 부터 찍으세요.**

### `ZeroDivisionError: division by zero`

```
ZeroDivisionError: division by zero
```

**원인** — 0으로 나눴습니다. 가계부에서 지출이 하나도 없을 때 `food / expense` 를 하면 납니다.
**해결** — 나누기 전에 분모를 확인합니다.

```python
if expense > 0:
    print(f"{food / expense:.1%}")
```

이 방어는 W05의 비율 계산, W12의 정밀도·재현율 계산에서 그대로 반복됩니다.

### `ValueError: too many values to unpack (expected 3)`

```python
kind, category, amount = rec     # rec는 값이 4개
```

```
ValueError: too many values to unpack (expected 3)
```

**원인** — 언패킹할 변수 개수와 튜플의 길이가 다릅니다.
**해결** — 개수를 맞춥니다. 일부만 필요하면 관례적으로 `_` 를 씁니다.

```python
kind, category, _, amount = rec      # memo는 안 쓸 때
```

### 무한 루프에서 빠져나오지 못함

가계부 메뉴에서 `0` 을 눌러도 안 끝난다면:

```python
if choice == 0:        # ← 틀림. choice는 문자열
```

**원인** — `input()` 은 문자열을 돌려주므로 `"0"` 과 비교해야 합니다.
**해결** — `if choice == "0":`. 에러가 안 나고 조건이 늘 거짓이 되는 **조용한 버그**입니다.

### 들여쓰기 때문에 `elif` 가 `if` 와 연결되지 않음

```
SyntaxError: invalid syntax
```

**원인** — `if` 와 `elif` 의 들여쓰기 깊이가 다릅니다. 둘은 **정확히 같은 깊이**여야 합니다.
**해결** — VS Code에서 코드를 블록 선택 후 `Shift+Tab` 으로 정렬하거나, `Alt+Shift+F` 로 자동 서식을 적용합니다.

### 실행했는데 아무 일도 안 일어남

**원인** — 메뉴 루프까지 도달하지 못했습니다. 대개 위쪽에 `SyntaxError` 가 있는데
터미널을 스크롤하지 않아 못 본 경우입니다.
**해결** — 터미널을 **맨 위로 스크롤**해서 에러가 있는지 확인하세요. 에러는 실행 결과보다 먼저 나옵니다.

## ⑥ 확인 문제

**1.** 아래 Traceback에서 ① 에러 종류 ② 문제가 난 파일과 줄 번호 ③ 원인 ④ 고치는 방법을 각각 답하세요.

```
Traceback (most recent call last):
  File "C:\workspace\mlops\budget.py", line 22, in <module>
    amount = int(raw)
             ^^^^^^^^
ValueError: invalid literal for int() with base 10: '12,000'
```

<details>
<summary>답 보기</summary>

| 항목 | 답 |
|---|---|
| ① 에러 종류 | `ValueError` — 타입은 문자열로 맞지만 **값**이 int로 바뀔 수 없음 |
| ② 위치 | `budget.py` 의 **22번 줄**, `amount = int(raw)` |
| ③ 원인 | 입력값에 **쉼표**가 들어 있음 (`'12,000'`). `int()` 는 순수 숫자 문자열만 받음 |
| ④ 해결 | 변환 전에 쉼표를 제거 — `amount = int(raw.replace(",", ""))` |

`TypeError` 와 `ValueError` 의 차이를 정리해 두세요.
- `TypeError` : **타입 자체**가 잘못됨 (`int("a") + [1]`)
- `ValueError` : 타입은 맞는데 **값**이 부적절 (`int("십이")`)
</details>

**2.** 아래 코드는 에러 없이 실행되지만 항상 `"메뉴를 다시 선택하세요"` 만 출력합니다. 왜인가요?

```python
choice = input("선택 > ")
if choice == 1:
    print("수입 추가")
elif choice == 2:
    print("지출 추가")
else:
    print("메뉴를 다시 선택하세요")
```

<details>
<summary>답 보기</summary>

`input()` 은 **항상 문자열**을 돌려줍니다. 사용자가 `1` 을 쳐도 `choice` 에는 `"1"` (문자열)이 들어갑니다.

`"1" == 1` 은 **타입이 달라서 항상 `False`** 입니다. 에러가 나지 않고 조용히 거짓이 되므로,
모든 조건이 거짓이 되어 `else` 로 떨어집니다.

**두 가지 해법**이 있습니다.

```python
# A) 문자열끼리 비교
if choice == "1":

# B) 입력을 정수로 변환 (단, 숫자가 아니면 ValueError)
choice = int(input("선택 > "))
if choice == 1:
```

메뉴 선택에서는 **A가 더 안전합니다.** 사용자가 `abc` 를 쳐도 프로그램이 죽지 않기 때문입니다.
B를 쓰려면 Day 009의 `try/except` 가 필요합니다.
</details>

**3.** 가계부 요약 기능에서 분류별 합계를 변수 5개(`food`, `transport`, `housing`, `leisure`, `etc`)로 관리했습니다. 분류가 20개로 늘어난다면 어떤 문제가 생기고, 무엇으로 해결해야 할까요?

<details>
<summary>답 보기</summary>

**생기는 문제**

1. 변수를 20개 선언해야 합니다.
2. `if`/`elif` 가 20단으로 늘어납니다.
3. 출력 `print` 도 20줄이 됩니다.
4. 분류를 하나 추가할 때마다 **세 곳(선언·분기·출력)을 모두** 고쳐야 하고, 하나라도 빠뜨리면 조용히 틀립니다.

**해결 — 딕셔너리 ([Day 008](day-008.md))**

```python
totals = {}                       # 빈 딕셔너리

for rec in records:
    kind, category, memo, amount = rec
    if kind == "지출":
        totals[category] = totals.get(category, 0) + amount

for category, amount in totals.items():
    print(f"  {category}  {amount:>10,} 원  ({amount / expense:>5.1%})")
```

분류가 5개든 200개든 **코드는 그대로**입니다. 새 분류가 들어오면 자동으로 항목이 생깁니다.

이것이 **자료구조를 배우는 이유**입니다. 문법을 늘리는 게 아니라, **바뀌는 부분을 데이터로 옮겨** 코드가 안 바뀌게 만드는 것입니다.
같은 원리가 W04의 수집 설정(yaml), W09의 검증 규칙, W13의 하이퍼파라미터 탐색 공간에 그대로 적용됩니다.
</details>
