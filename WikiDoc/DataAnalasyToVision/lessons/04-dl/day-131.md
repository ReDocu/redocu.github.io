## 2부 · 개발 데이터 전체 재학습

### 왜 다시 학습하는가

```
Day 130까지: 학습 1,807건으로만 학습
지금:        학습 1,807 + 검증 603 = 2,410건

★ 데이터가 33% 늘어납니다
```

**작은 데이터셋일수록 이 효과가 큽니다.**

### 재학습 시 주의할 점

```
① 하이퍼파라미터는 그대로 (다시 튜닝 금지)
② 조기 종료용 내부 검증은 파이프라인이 알아서 분할
③ 전처리기도 개발 전체로 다시 적합
④ seed 고정
```

### 재학습 효과를 검증할 수 없습니다

```
검증셋을 학습에 썼으므로 검증 성능을 잴 수 없습니다
→ 테스트셋으로만 확인 가능
→ 그래서 "학습셋만 학습" 버전도 함께 테스트 평가해 비교합니다
```

**이것은 테스트셋을 2번 보는 것이 아닙니다. 같은 회차에 두 모델을 함께 평가하는 것입니다.**

## 3부 · 테스트 평가와 신뢰구간

### 점 추정은 위험합니다

```
"MAE 7.62"
→ 마치 정확한 값처럼 들립니다

실제로는 테스트셋 603건을 뽑은 운에 따라 달라집니다
```

### 부트스트랩 신뢰구간

```python
boots = [mean_absolute_error(y_te[idx], pred[idx])
         for idx in resample_indices(2000)]
lo, hi = np.percentile(boots, [2.5, 97.5])
```

**"MAE 7.62 (95% CI 7.31 ~ 7.94)"** 로 보고합니다.

### 규칙 베이스라인 대비도 구간으로

```
개선율의 신뢰구간이 0을 포함하면
→ "개선했다"고 말할 수 없습니다
```

**쌍체 부트스트랩으로 계산합니다.**

### Step 2. 개발 데이터 전체로 재학습

def full_metrics(y_true, y_pred):
    y_true = np.asarray(y_true, float)
    y_pred = np.asarray(y_pred, float)
    err = y_pred - y_true
    nz = y_true != 0
    slope = np.polyfit(y_pred, y_true, 1)[0]

def group_report(frame, col, min_n=15, bins=None, labels=None):
    f = frame.copy()
    key = col
    if bins is not None:
        key = f"{col}_bin"
        f[key] = pd.cut(f[col], bins=bins, labels=labels)
    g = f.groupby(key, observed=True).agg(
        n=("절대오차", "size"),
        MAE=("절대오차", "mean"),
        편향=("오차", "mean"),
        실제평균=("실제", "mean"),

## ⑤ 자주 하는 실수

### 테스트셋으로 후보 3개를 다 평가한 뒤 선택

```
✗ 3개 평가 → 최고 선택 → "MAE 7.61 달성!"
```

**그 순간 테스트셋은 검증셋입니다.**
**Step 1에서 선택을 먼저 확정하고 파일로 남겼습니다.**

### 테스트 결과가 나빠서 되돌아감

```
"어? 8.4가 나왔네. 다시 튜닝해야겠다"
```

**되돌아가면 그 다음 테스트 평가는 무의미합니다.**
**나쁜 결과도 그대로 보고합니다.**

### 재학습을 안 함

```
학습 1,807건 → 테스트 7.9214
개발 2,410건 → 테스트 7.6841

3% 손해를 그냥 버리는 것입니다
```

### 재학습하면서 하이퍼파라미터도 다시 튜닝

```
데이터가 늘었으니 튜닝도 다시... ✗
```

**튜닝은 [Day 130](day-130.md)에서 끝났습니다.**

### 점추정만 보고

```
"MAE 7.68"          ← 불완전
"MAE 7.68 (7.12~8.24)"  ← 완전
```

### 개선율의 신뢰구간을 빠뜨림

```
"36.2% 개선" 은 점추정입니다
구간 하한 32.4%가 목표 35%에 미달한다는 사실을 보고해야 합니다
```

### 오차 top 20을 숫자로만 봄

```
"인덱스 284가 오차 58"
```

**게임 이름·장르·가격을 봐야 원인이 보입니다.**

### 집단별 표에 n을 안 씀

```
"Casual 장르 MAE 5.84 — 가장 정확!"
n = 16 입니다. 신뢰할 수 없습니다
```

### 전체 MAE만 보고하고 취약 구간을 숨김

```
"MAE 7.68"

실제로는
  16~30% 구간: 4.2
  76~90% 구간: 38.4
```

**평균 하나로 뭉뚱그리면 위험한 곳에 모델을 쓰게 됩니다.**

### 취약 구간을 발견하고도 사용 제한을 안 씀

```
발견만 하고 "개선하겠습니다"로 끝 ✗
"할인 75% 이상에는 사용 금지" 로 명시 ✓
```
