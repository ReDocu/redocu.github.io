## ② 왜 필요한가

[Day 051](day-051.md)에서 손으로 짜다 실패한 규칙을 기억하나요?

```
규칙 v1: 오늘 pm25 > 35 이면 → 내일도 나쁨
```

오늘 배우는 결정 트리는 정확히 **이런 규칙을 데이터에서 자동으로 찾아내는 모델**입니다.
실제로 오늘 첫 실습에서 트리가 스스로 찾아낸 첫 규칙을 보면 소름이 돋을 겁니다.

트리 계열을 배워야 하는 실용적인 이유는 분명합니다.

| 이유 | 설명 |
|---|---|
| **테이블 데이터의 주력** | 실무 정형 데이터 대회·현업에서 가장 많이 쓰이는 계열 (내일 배울 부스팅 포함) |
| **문턱과 상호작용** | "pm25가 36을 넘고 **그리고** 바람이 약하면" — 선형 모델이 못 그리는 꺾인 경계를 그림 |
| 전처리 관대함 | 스케일링 불필요 (분할은 값의 **순서**만 봄) |
| 읽을 수 있음 | if-else로 펼쳐 보여줄 수 있는 몇 안 되는 모델 |

그리고 트리 하나의 치명적 약점(과적합)과 그 극복(앙상블)의 이야기가 곧 **현대 ML의 중심 서사**입니다.
오늘 그 서사를 처음부터 끝까지 걷습니다.

## ③ 개념 설명

### 결정 트리 — 스무고개 기계

트리는 데이터를 가장 잘 가르는 질문을 반복해서 던집니다.

```
                 [pm25 <= 36.9 ?]
                  예 ↙        ↘ 아니오
          (내일 아님이 다수)   [pm10 <= 68.9 ?]
                              예 ↙       ↘ 아니오
                        (나쁨 우세)      (나쁨 확실)
```

**"가장 잘 가른다"의 기준 = 불순도(impurity) 감소.** 어떤 노드에 나쁨과 아님이 반반 섞여 있으면
불순(지니 불순도 최대), 한쪽뿐이면 순수(0)입니다. 트리는 가능한 모든 (특성, 문턱값) 조합을 훑어
**쪼갠 뒤 두 조각의 불순도가 가장 낮아지는 질문**을 고릅니다. 그게 전부입니다 —
경사하강도, 계수도 없습니다.

| 성질 | 결과 |
|---|---|
| 값의 순서만 봄 | 스케일링 불필요 · 이상치에 강함 |
| 축에 수직인 경계만 그림 | "pm25>36 그리고 wind<2" 같은 **사각형 규칙**의 조합 |
| 멈추게 하지 않으면 끝까지 쪼갬 | 잎마다 표본 1개 = **완벽한 암기** = 과적합 |

### 과적합 제어 — 가지치기 손잡이

| 파라미터 | 뜻 | 키우면/줄이면 |
|---|---|---|
| `max_depth` | 질문을 몇 단까지 | 얕을수록 단순 (기본 None = 무제한!) |
| `min_samples_leaf` | 잎에 남아야 할 최소 표본 | 클수록 "소수 표본으로 규칙 만들기" 금지 |
| `min_samples_split` | 쪼개려면 필요한 최소 표본 | 위와 유사 |

**기본값이 "무제한 성장"** 임을 기억하세요. `DecisionTreeClassifier()` 를 그냥 쓰면
train 100점짜리 암기 기계가 나옵니다 (오늘 실습에서 확인).

### 배깅과 랜덤포레스트 — 떨리는 손 여러 개의 평균

트리 하나는 데이터가 조금만 바뀌어도 완전히 다른 모양이 됩니다(분산이 큼).
**배깅**(bagging)은 이 불안정성을 역이용합니다.

```
원본 train (2,629행)
├─ 복원추출 표본 ① → 트리 ①  ┐
├─ 복원추출 표본 ② → 트리 ②  ├─ 투표(분류) / 평균(회귀)
├─ …                          │
└─ 복원추출 표본 ⑳⓪ → 트리 ⑳⓪ ┘
```

각 트리는 **서로 다른 표본**으로 배우고(부트스트랩), **랜덤포레스트**는 여기에 하나를 더합니다 —
각 분할에서 **특성도 일부만 무작위로** 후보에 올립니다. 트리들이 서로 닮지 않게(상관을 낮게) 만들수록
평균의 잡음 제거 효과가 커지기 때문입니다.

> 직관: 한 명의 암기왕은 시험마다 성적이 널뜁니다. **서로 다른 문제집으로 공부한 300명의 다수결**은
> 개개인보다 훨씬 안정적입니다. 개별 트리의 과적합(높은 분산)이 평균에서 상쇄됩니다.

### 특성 중요도 — 편리하지만 조심

`feature_importances_` 는 "그 특성이 분할에 쓰여 불순도를 얼마나 줄였나"의 합계입니다. 두 가지 주의:

1. **상관된 특성끼리 중요도를 나눠 가집니다** — pm10과 no2가 비슷한 정보면 합쳐서 봐야 합니다.
2. 고유값이 많은 특성이 과대평가되는 편향이 있습니다. 더 공정한 방법(순열 중요도)은 [Day 064](day-064.md)에서.

## ④ 단계별 실습

`day058_tree.py` 에 이어 붙입니다. 타깃은 이번 주 계속 쓰는 `bad_next`(내일 나쁨)입니다.

### Step 1. 깊이 2 트리 — 모델이 찾아낸 규칙 읽기 (1~2교시)

```python
# day058_tree.py — 결정 트리와 랜덤포레스트
import numpy as np
import pandas as pd
from sklearn.ensemble import RandomForestClassifier
from sklearn.metrics import accuracy_score, recall_score, roc_auc_score
from sklearn.tree import DecisionTreeClassifier, export_text

pd.set_option("display.width", 140)
df = pd.read_csv("data/air_daily.csv", parse_dates=["date"])
F10 = ["pm10", "pm25", "o3", "no2", "co", "so2", "temp", "humidity", "wind_speed", "precip"]
d = df.dropna(subset=F10).copy()
d["bad_next"] = (d.pm25_next >= 36).astype(int)
tr = d[d.date < "2026-01-01"]; te = d[d.date >= "2026-01-01"]
Xtr, ytr, Xte, yte = tr[F10], tr.bad_next, te[F10], te.bad_next

print("== A. 깊이 2 트리의 규칙 읽기 ==")
tree2 = DecisionTreeClassifier(max_depth=2, random_state=42).fit(Xtr, ytr)
print(export_text(tree2, feature_names=F10, decimals=1))
print(f"AUC: {roc_auc_score(yte, tree2.predict_proba(Xte)[:, 1]):.3f}")
```

실행 결과:

```
== A. 깊이 2 트리의 규칙 읽기 ==
|--- pm25 <= 36.9
|   |--- pm25 <= 29.8
|   |   |--- class: 0
|   |--- pm25 >  29.8
|   |   |--- class: 0
|--- pm25 >  36.9
|   |--- pm10 <= 68.9
|   |   |--- class: 1
|   |--- pm10 >  68.9
|   |   |--- class: 1

AUC: 0.727
```

첫 질문을 보세요: **`pm25 <= 36.9`**. 우리가 아무것도 알려주지 않았는데, 트리가 데이터만 보고
[Day 051](day-051.md)의 규칙 v1("오늘 나쁘면 내일도 나쁨")과 **'나쁨' 등급 기준(36)** 을
스스로 재발견했습니다. 이것이 "데이터에서 규칙을 뽑는다"의 가장 생생한 모습입니다.

한 가지 눈여겨볼 것 — 아래층 분할(pm25 29.8, pm10 68.9)은 잎의 class 표기(0/0, 1/1)를 바꾸지
못했습니다. 그래도 무의미하지 않습니다: 각 잎의 **나쁨 비율(확률)** 은 서로 달라서,
`predict_proba` 의 눈금을 4단계로 만들어 줍니다. 규칙 4줄짜리 모델이 AUC 0.727 — 나쁘지 않은 출발입니다.

### Step 2. 무제한 성장 = 암기 — 깊이별 과적합 게이지 (3교시)

```python
print("== B. 깊이별 과적합 게이지 ==")
print("max_depth | train AUC | test AUC")
for depth in [2, 3, 5, 8, None]:
    t = DecisionTreeClassifier(max_depth=depth, random_state=42).fit(Xtr, ytr)
    a_tr = roc_auc_score(ytr, t.predict_proba(Xtr)[:, 1])
    a_te = roc_auc_score(yte, t.predict_proba(Xte)[:, 1])
    print(f"  {str(depth):>5}   |   {a_tr:.3f}   |  {a_te:.3f}")
```

실행 결과:

```
== B. 깊이별 과적합 게이지 ==
max_depth | train AUC | test AUC
      2   |   0.914   |  0.727
      3   |   0.923   |  0.658
      5   |   0.954   |  0.664
      8   |   0.981   |  0.649
   None   |   1.000   |  0.596
```

[Day 054](day-054.md)의 과적합 게이지(간격)가 트리에서 극적으로 나타납니다. 깊이 무제한이면
**train 1.000 — 완벽한 암기** — 인데 test는 0.596으로 최악입니다. 심지어 깊이 3부터 이미
test가 나빠집니다. 트리는 우리 데이터의 노이즈까지 규칙으로 만드는 데 천재적입니다.

```python
print("\n== C. 잎사귀 최소 표본으로 제어 ==")
for msl in [1, 20, 50]:
    t = DecisionTreeClassifier(min_samples_leaf=msl, random_state=42).fit(Xtr, ytr)
    print(f"  min_samples_leaf={msl:<3} train {roc_auc_score(ytr, t.predict_proba(Xtr)[:, 1]):.3f}  "
          f"test {roc_auc_score(yte, t.predict_proba(Xte)[:, 1]):.3f}")
```

실행 결과:

```
== C. 잎사귀 최소 표본으로 제어 ==
  min_samples_leaf=1   train 1.000  test 0.596
  min_samples_leaf=20  train 0.969  test 0.729
  min_samples_leaf=50  train 0.955  test 0.767
```

"잎 하나에 최소 50일은 있어야 규칙으로 인정"이라는 제약만으로 0.596 → **0.767**.
[Day 055](day-055.md) 문제 3에서 본 것과 같은 원리입니다 — **소수 표본으로 만든 규칙은 우연**입니다.

### Step 3. 랜덤포레스트 — 나무 수의 마법 (5교시)

```python
print("\n== D. 랜덤포레스트 — 나무 수의 효과 ==")
for n in [1, 10, 100, 300]:
    rf = RandomForestClassifier(n_estimators=n, random_state=42, n_jobs=-1).fit(Xtr, ytr)
    print(f"  나무 {n:>3}그루: test AUC {roc_auc_score(yte, rf.predict_proba(Xte)[:, 1]):.3f}")
```

실행 결과:

```
== D. 랜덤포레스트 — 나무 수의 효과 ==
  나무   1그루: test AUC 0.599
  나무  10그루: test AUC 0.729
  나무 100그루: test AUC 0.783
  나무 300그루: test AUC 0.790
```

개별 트리는 여전히 무제한 성장(암기 기계, 1그루 = 0.599)입니다. 그런데 **300그루의 평균은 0.790.**
가지치기를 하나도 안 했는데 앙상블만으로 과적합이 씻겨 나갑니다 — 각 나무의 암기(노이즈)는
서로 다르지만 진짜 구조(pm25 문턱, 계절)는 공유하므로, 평균에서 노이즈만 상쇄됩니다.
나무 수는 100 → 300에서 수확 체감이 보입니다. **나무 수는 많을수록 좋되(과적합 안 함) 시간과의 흥정**입니다.

### Step 4. 3파전 정리 — 그리고 미묘한 결과 (6교시)

```python
print("\n== E. 최종 비교 (test) ==")
from sklearn.linear_model import LogisticRegression
from sklearn.preprocessing import StandardScaler
rf = RandomForestClassifier(n_estimators=300, random_state=42, n_jobs=-1).fit(Xtr, ytr)
sc = StandardScaler().fit(Xtr)
lo = LogisticRegression(max_iter=5000).fit(sc.transform(Xtr), ytr)
tree3 = DecisionTreeClassifier(max_depth=3, random_state=42).fit(Xtr, ytr)
for name, pr in [("로지스틱(어제)", lo.predict_proba(sc.transform(Xte))[:, 1]),
                 ("트리 depth3", tree3.predict_proba(Xte)[:, 1]),
                 ("랜덤포레스트 300", rf.predict_proba(Xte)[:, 1])]:
    p05 = (pr >= 0.5).astype(int)
    print(f"  {name:<12} AUC {roc_auc_score(yte, pr):.3f}  acc {accuracy_score(yte, p05):.3f}  recall@0.5 {recall_score(yte, p05):.3f}")
```

실행 결과:

```
== E. 최종 비교 (test) ==
  로지스틱(어제)     AUC 0.818  acc 0.849  recall@0.5 0.339
  트리 depth3    AUC 0.658  acc 0.839  recall@0.5 0.380
  랜덤포레스트 300   AUC 0.790  acc 0.849  recall@0.5 0.413
```

포레스트(0.790)가 단일 트리를 크게 이겼지만 **로지스틱(0.818)에는 못 미칩니다.**
"트리 계열이 테이블 데이터 최강 아니었나?" — 좋은 질문이고, 내일([Day 059](day-059.md))
부스팅까지 보고 나서 정면으로 다룹니다. 힌트: 우리 데이터의 주 신호가 **여러 특성에 퍼진
매끈한(선형에 가까운) 구조**라서, 직선을 잘 긋는 모델이 유리한 판입니다. 대신 재현율(0.413 vs
0.339)은 포레스트가 앞선다는 점도 눈여겨보세요 — 지표에 따라 순위가 갈립니다([Day 057](day-057.md)).

## ⑤ 자주 하는 실수

### 기본값 트리를 그대로 씀

**증상** — `DecisionTreeClassifier()` 로 train 점수 1.000이 나와 "완벽!"이라 보고.
**원인** — 기본 `max_depth=None` 은 잎이 순수해질 때까지(= 표본 암기까지) 자랍니다. train 1.000은 성공이 아니라 **경보**입니다.
**해결** — 단일 트리는 반드시 `max_depth` 나 `min_samples_leaf` 로 제한하고, train/test 간격을 같이 봅니다.

### 트리에도 스케일링부터 함

**증상** — StandardScaler를 걸었는데 점수가 소수점까지 그대로라 어리둥절.
**원인** — 트리의 분할은 "36.9보다 큰가?"처럼 값의 **순서**만 보므로 단조 변환에 불변입니다.
**해결** — 트리 계열에는 스케일링이 불필요합니다(해롭지도 않음). 파이프라인 설계 시 모델별로 전처리를 다르게 — [Day 063](day-063.md).

### 중요도를 인과·제거효과로 해석

**증상** — "no2 중요도 0.14니까 no2 센서를 늘리면 예보가 14% 좋아진다"는 식의 보고.
**원인** — 불순도 중요도는 상관 특성끼리 나눠 갖는 **상대적 사용량**이지, 제거 시 성능 하락도, 인과도 아닙니다.
**해결** — 제거 효과가 궁금하면 실제로 빼고 재학습하거나 순열 중요도([Day 064](day-064.md))를 쓰세요.

### random_state를 안 박고 결과가 바뀐다고 당황

**증상** — 같은 코드를 두 번 돌렸는데 포레스트 AUC가 0.790 → 0.786으로 다름.
**원인** — 부트스트랩·특성 선택이 난수 기반입니다. 시드를 고정하지 않으면 실행마다 다른 숲이 자랍니다.
**해결** — 실험에는 `random_state=42` 를 고정. 시드가 재현성의 3요소 중 하나라는 것은 [Day 066](day-066.md)의 주제입니다.

### 나무 수를 과적합 손잡이로 착각

**증상** — "과적합 같으니 n_estimators를 300에서 50으로 줄이자."
**원인** — 나무 수는 많을수록 분산이 줄어들 뿐 과적합을 **일으키지 않습니다** (Step 3에서 단조 개선 확인). 줄이면 그냥 손해입니다.
**해결** — 과적합 제어는 개별 트리의 깊이·잎 크기로, 나무 수는 시간이 허락하는 만큼 크게.

## ⑥ 확인 문제

**Q1.** Step 1의 깊이 2 트리에서 네 잎의 class가 0, 0, 1, 1이라 두 번째 층 분할이 무의미해 보입니다.
그런데 AUC는 왜 이 분할의 덕을 볼 수 있나요?

<details>
<summary>답 보기</summary>

AUC는 0/1 판정이 아니라 **확률의 순서**로 계산됩니다([Day 057](day-057.md)). 두 번째 층 분할은 잎마다
나쁨 **비율**(확률)을 다르게 만들어 확률 눈금을 2단계에서 4단계로 늘리므로, 판정(class)은 같아도
순위 매기기 성능(AUC)은 좋아질 수 있습니다.

</details>

**Q2.** 단일 트리(무제한)는 test AUC 0.596인데, 같은 무제한 트리 300그루의 포레스트는 0.790입니다.
가지치기를 안 했는데 왜 좋아졌는지 "분산"과 "상쇄"라는 단어로 설명하세요.

<details>
<summary>답 보기</summary>

무제한 트리의 오류는 대부분 **분산**(표본의 노이즈까지 암기한, 트리마다 제각각인 오류)입니다.
부트스트랩과 특성 무작위화로 서로 다르게 틀리는 트리들을 만들고 평균 내면, 제각각인 노이즈 부분은
**상쇄**되고 모든 트리가 공유하는 진짜 구조만 남습니다. 그래서 개별 트리의 과적합이 앙상블에서 사라집니다.

</details>

**Q3.** 팀 회의에서 "포레스트(AUC 0.790)가 로지스틱(0.818)보다 낮으니 트리 계열은 버리자"는 의견이
나왔습니다. 오늘 결과에서 반박 근거를 두 가지 찾아 제시하세요.

<details>
<summary>답 보기</summary>

① 재현율@0.5는 포레스트가 앞섭니다(0.413 vs 0.339) — 경보 서비스의 주 지표가 재현율이라면 순위가 뒤집힙니다.
② 아직 트리 계열의 대표 주자(그래디언트 부스팅, [Day 059](day-059.md))와 튜닝([Day 062](day-062.md)),
특성 개선([Day 064](day-064.md))을 시도하지 않았습니다. 지표 하나·설정 하나로 계열 전체를 버리는 것은 성급합니다.

</details>
