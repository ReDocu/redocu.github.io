## 2. 막히는 상황

플레이어에게 라운드 수를 물어보고, 그만큼 기록을 남기려고 한다.

```c
int rounds = ReadInt("몇 라운드?", 1, 1000);

int record[rounds];              // ✘ error: 상수 식이 필요합니다
```

**배열 크기는 컴파일할 때 결정된다.** 실행 중에 정할 수 없다.

우회책을 생각해 보자.

```c
int record[1000];                // 최대치로 잡아 두기
```

| 문제 | 설명 |
|---|---|
| 낭비 | 10라운드만 해도 1000칸을 차지한다 |
| 부족 | 1001라운드를 원하면? 다시 빌드해야 한다 |
| 스택 한계 | 1,000,000칸을 잡으면 **스택 오버플로**로 죽는다 |

그리고 어제 3-8절에서 본 이 문제도 아직 해결되지 않았다.

```c
int* MakeNumber(void)
{
    int n = 42;
    return &n;               // ✘ 함수가 끝나면 n이 사라진다
}
```

```
   지금:   크기가 미리 정해진 공간만 쓸 수 있다
           함수가 끝나면 그 안의 변수는 사라진다

   필요:   실행 중에 원하는 만큼 빌리고,
           내가 반납할 때까지 유지되는 공간
```

> **실행 중에 메모리를 직접 빌리는 방법이 필요하다.** → **동적 할당**

## 3. 개념

### 3-1. 스택과 힙 — 메모리의 두 구역

**왜 필요한가** — 지금까지 쓴 변수들이 어디에 있었는지, 그리고 어디가 다른지 알아야 한다.

```
   프로그램의 메모리 구조

   ┌─────────────────────────────────────┐  높은 주소
   │           스택 (Stack)               │
   │  지역 변수, 매개변수, 함수 호출 정보  │
   │            ↓ 자라는 방향              │
   ├─────────────────────────────────────┤
   │                                      │
   │            (빈 공간)                  │
   │                                      │
   ├─────────────────────────────────────┤
   │            ↑ 자라는 방향              │
   │            힙 (Heap)                 │
   │      malloc으로 빌리는 공간           │
   ├─────────────────────────────────────┤
   │       전역 변수 / 정적 변수           │
   ├─────────────────────────────────────┤
   │            코드 (실행 명령)           │
   └─────────────────────────────────────┘  낮은 주소
```

| | 스택 | 힙 |
|---|---|---|
| 무엇이 | 지역 변수, 매개변수 | `malloc`으로 빌린 것 |
| 크기 결정 | **컴파일 시점** | **실행 시점** |
| 정리 | **자동** (함수 끝나면) | **직접** (`free` 호출) |
| 크기 한계 | 작다 (보통 1MB 내외) | 크다 (수 GB) |
| 속도 | 빠르다 | 상대적으로 느리다 |
| 수명 | 함수 끝날 때까지 | `free`할 때까지 |

> **"함수가 끝나면 지역 변수가 사라진다"(Day 4)는 것은 스택의 성질**이다.
> 힙에 빌린 것은 함수가 끝나도 남아 있다. 그래서 2절의 문제가 해결된다.

### 3-2. `malloc` — 메모리 빌리기

**왜 필요한가** — 실행 중에 원하는 크기만큼 힙에서 공간을 얻는다.

```c
#include <stdlib.h>

int* p = (int*)malloc(sizeof(int) * 100);       // int 100개 분량
```

```
   malloc(크기)  →  힙에서 "크기" 바이트를 확보하고 그 시작 주소를 반환

   malloc(400)
        │
        ▼
   힙:  ┌────────────────────────────────────┐
        │  400바이트 확보                     │
        └────────────────────────────────────┘
        ▲
        └── 이 주소를 반환한다  (실패하면 NULL)
```

**크기 계산은 항상 `sizeof`로**

```c
int* p = (int*)malloc(100);                  // ✘ 100바이트 = int 25개뿐
int* p = (int*)malloc(sizeof(int) * 100);    // ✔ int 100개
```

| 원하는 것 | 코드 |
|---|---|
| `int` 100개 | `malloc(sizeof(int) * 100)` |
| `char` 50개 | `malloc(sizeof(char) * 50)` |
| `GameState` 1개 | `malloc(sizeof(GameState))` |
| `Record` n개 | `malloc(sizeof(Record) * n)` |

> **더 안전한 표기** — 자료형이 바뀌어도 안전하다.
>
> ```c
> Record* p = malloc(sizeof(*p) * n);      // p가 가리키는 것의 크기
> ```

### 3-3. ⚠️ 할당 실패 검사 — 반드시 한다

**왜 필요한가** — 메모리가 부족하면 `malloc`은 `NULL`을 반환한다. 검사 없이 쓰면 크래시한다.

```c
int* p = (int*)malloc(sizeof(int) * count);

if (p == NULL)                          // ★ 반드시
{
    printf("메모리 할당 실패\n");
    return 1;                           // 또는 다른 대응
}

// 여기부터는 p를 안심하고 쓸 수 있다
```

```
   malloc 실패 시나리오

   ① 메모리 부족                 →  NULL
   ② 요청 크기가 너무 큼          →  NULL
   ③ 크기 계산에서 오버플로 발생  →  NULL 또는 작은 크기 할당(위험)
```

### 3-4. `free` — 반납하기

**왜 필요한가** — 빌린 것은 돌려줘야 한다. 안 돌려주면 **메모리 누수**가 된다.

```c
free(p);
p = NULL;                    // ★ 해제 후 NULL 대입 (습관)
```

```
   malloc  ──▶  사용  ──▶  free      반드시 짝을 맞춘다

   ┌─────────────────────────────────────────┐
   │  int* p = malloc(...);                   │
   │  if (p == NULL) return;                  │
   │                                          │
   │  ... 사용 ...                             │
   │                                          │
   │  free(p);                                │
   │  p = NULL;                               │
   └─────────────────────────────────────────┘
```

**해제 후 `NULL`을 대입하는 이유**

```c
free(p);
// p = NULL;  을 안 하면

*p = 100;          // ✘ 이미 반납한 곳에 쓴다 (dangling pointer)
free(p);           // ✘ 이중 해제 → 크래시
```

```c
free(p);
p = NULL;

if (p != NULL) *p = 100;      // ✔ 안전하게 걸러진다
free(p);                       // ✔ free(NULL)은 아무 일도 안 한다 (안전)
```

> `free(NULL)`은 **아무 일도 하지 않는다.** 표준이 보장한다. 그래서 안전하다.

### 3-5. 메모리 누수 — 안 돌려주면 생기는 일

**왜 필요한가** — 게임처럼 오래 도는 프로그램에서 치명적이다.

```c
void Leak(void)
{
    int* p = (int*)malloc(sizeof(int) * 1000);
    // free(p);     ← 없다
}                    // p는 사라지지만 힙의 4000바이트는 그대로 남는다

for (int i = 0; i < 100000; i++)
    Leak();          // 4000 × 100000 = 400MB 누수
```

```
   호출 1회:  힙  [4KB 사용중]
   호출 2회:  힙  [4KB][4KB]
   호출 3회:  힙  [4KB][4KB][4KB]
              ...
   호출 n회:  힙  [.....................] ← 계속 늘어난다
                     ▲
                     아무도 이 주소를 모른다. 반납할 방법이 없다
```

**확인 방법**

```
   작업 관리자 → 세부 정보 → 프로그램의 "메모리" 열을 관찰

   정상:   실행 후 일정하게 유지
   누수:   시간이 갈수록 계속 증가
```

> 게임은 몇 시간씩 돌아간다. 프레임마다 조금씩 새면 결국 죽는다.
> **Day 51~52의 오브젝트 풀링**이 이 문제를 근본적으로 피하는 방법이다.

### 3-6. `calloc`과 `realloc`

**왜 필요한가** — `malloc`으로 안 되는 상황이 있다.

**`calloc` — 0으로 초기화된 메모리**

```c
int* p1 = (int*)malloc(sizeof(int) * 10);     // 내용은 쓰레기 값
int* p2 = (int*)calloc(10, sizeof(int));      // 전부 0으로 채워짐
```

| | `malloc` | `calloc` |
|---|---|---|
| 인자 | `malloc(총 바이트)` | `calloc(개수, 크기)` |
| 초기값 | 쓰레기 값 | **0** |
| 속도 | 빠름 | 약간 느림 (0으로 채우는 시간) |

> 배열을 0으로 시작해야 하면 `calloc`이 편하다.
> 어차피 전부 덮어쓸 거면 `malloc`이 빠르다.

**`realloc` — 크기 바꾸기**

```c
int* p = (int*)malloc(sizeof(int) * 10);

// 20개로 늘리고 싶다
int* tmp = (int*)realloc(p, sizeof(int) * 20);

if (tmp == NULL)
{
    free(p);                 // ★ 실패해도 원본은 살아 있다
    return;
}
p = tmp;                     // 성공했으면 교체
```

> ### ⚠️ `realloc`의 결과를 원래 포인터에 바로 대입하지 않는다
>
> ```c
> p = realloc(p, size);       // ✘ 실패하면 NULL이 되어 원본 주소를 잃는다
>                              //   → 반납할 방법이 없어져 누수 발생
> ```
>
> **반드시 임시 포인터로 받아서 확인 후 교체한다.**

```
   realloc 이 하는 일

   ① 뒤에 여유 공간이 있으면  →  그 자리에서 늘린다 (주소 유지)
   ② 없으면                   →  새 공간을 잡고, 내용을 복사하고, 옛 공간을 반납
                                  → 주소가 바뀐다!

   ★ 그래서 반환값을 반드시 받아 써야 한다
```

### 3-7. 동적 배열 사용법

**왜 필요한가** — 할당한 메모리는 일반 배열처럼 쓸 수 있다. (Day 18의 "배열 = 주소")

```c
int count = 200;
int* record = (int*)malloc(sizeof(int) * count);

if (record == NULL) return 1;

for (int i = 0; i < count; i++)
    record[i] = 0;                     // ★ 일반 배열처럼 [] 사용

record[5] = 100;
printf("%d\n", record[5]);

free(record);
record = NULL;
```

```
   int arr[200];                    int* p = malloc(sizeof(int)*200);
   ┌───┬───┬───┬─── ... ───┐        ┌───┬───┬───┬─── ... ───┐
   │   │   │   │            │        │   │   │   │            │
   └───┴───┴───┴────────────┘        └───┴───┴───┴────────────┘
    스택에 있다                        힙에 있다
    자동 정리                          free 필요
    arr[i] 로 접근                     p[i] 로 접근   ← 사용법은 똑같다
```

> ⚠️ **동적 배열도 범위 검사는 없다.** `record[999]`에 쓰면 힙이 망가진다.
> 스택 오버플로보다 증상이 더 이상하게 나타난다. (Day 11의 그 문제가 더 나빠진 버전)

### 3-8. 구조체 동적 할당

**왜 필요한가** — 게임 기록처럼 여러 정보를 묶어 저장할 때.

```c
typedef struct
{
    int betType;
    int betAmount;
    int diceResult;
    int isWin;
    int moneyAfter;
} Record;

int count = 200;
Record* records = (Record*)malloc(sizeof(Record) * count);

if (records == NULL) return 1;

records[0].betType    = BET_ODDEVEN;
records[0].betAmount  = 100;
records[0].isWin      = 1;

free(records);
records = NULL;
```

> `records[i].member` — 배열 요소는 구조체 **변수**이므로 `.`을 쓴다.
> `records->member`는 `records[0].member`와 같다 (첫 요소).

### 3-9. 2절의 문제 해결 — 함수에서 메모리 돌려주기

**왜 필요한가** — 어제 못 했던 것이 오늘 된다.

```c
// ✘ Day 18에서 실패했던 방식
int* MakeArrayBad(int size)
{
    int arr[100];                // 스택 — 함수 끝나면 사라진다
    return arr;                  // 사라진 곳의 주소
}

// ✔ 오늘의 방식
int* MakeArray(int size)
{
    int* arr = (int*)malloc(sizeof(int) * size);   // 힙 — 남아 있다

    if (arr == NULL) return NULL;

    for (int i = 0; i < size; i++)
        arr[i] = 0;

    return arr;                  // ★ 안전하다
}

// 사용
int* data = MakeArray(100);
if (data != NULL)
{
    // ... 사용 ...
    free(data);                  // ★ 받은 쪽이 반납할 책임을 진다
    data = NULL;
}
```

> ### 소유권 규칙
> **"누가 `malloc`했는가"보다 "누가 `free`할 책임을 지는가"를 명확히 한다.**
>
> 함수 이름과 주석으로 밝힌다.
> ```c
> // 반환된 포인터는 호출자가 free 해야 한다
> int* CreateRecordArray(int count);
> ```
>
> 이 규칙이 흐릿하면 누수 아니면 이중 해제가 난다.
> C++에서는 이 문제를 해결하려고 **스마트 포인터**가 나왔다.

## 4. 따라 만들기

### Step 1 — 스택 배열의 한계 확인

```c
#include <stdio.h>

int main(void)
{
    int n = 10;
    // int arr[n];              // ← 주석을 풀면 C에서는 오류
                                //   (C99 VLA는 MSVC에서 지원 안 함)

    int big[100000];            // 400KB — 아슬아슬
    // int huge[10000000];      // ← 주석 풀면 스택 오버플로로 크래시

    printf("big 배열 크기: %zu 바이트\n", sizeof(big));

    return 0;
}
```

**✅ 여기까지 하면** — 스택 배열의 두 가지 한계를 확인한다.
① 크기를 변수로 못 정한다 ② 너무 크면 죽는다

> 확인 후 주석은 다시 닫는다.

### Step 2 — 첫 `malloc`

```c
#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    int count = 10;

    int* p = (int*)malloc(sizeof(int) * count);

    if (p == NULL)
    {
        printf("메모리 할당 실패\n");
        return 1;
    }

    printf("할당 성공!\n");
    printf("  크기: %zu 바이트\n", sizeof(int) * count);
    printf("  주소: %p\n\n", p);

    for (int i = 0; i < count; i++)
        p[i] = i * 10;

    for (int i = 0; i < count; i++)
        printf("  p[%d] = %d\n", i, p[i]);

    free(p);
    p = NULL;

    printf("\n해제 완료.\n");

    return 0;
}
```

**✅ 여기까지 실행하면** — 힙에 10칸을 빌려 값을 넣고 출력하고 반납한다.

```
할당 성공!
  크기: 40 바이트
  주소: 00C3A8F0

  p[0] = 0
  p[1] = 10
  ...
```

### Step 3 — 크기를 입력으로 결정

```c
    int count = ReadInt("몇 개의 공간이 필요합니까", 1, 1000000);

    int* p = (int*)malloc(sizeof(int) * count);

    if (p == NULL) { printf("할당 실패\n"); return 1; }

    printf("%d칸 확보 (%zu 바이트)\n", count, sizeof(int) * count);
```

**✅ 여기까지 실행하면** — **2절의 문제가 해결된다.** 실행 중에 입력받은 크기로 배열이 만들어진다.
`1000000`을 넣어도 스택 배열과 달리 죽지 않는다.

### Step 4 — `malloc` vs `calloc` 비교

```c
    int n = 10;

    int* a = (int*)malloc(sizeof(int) * n);
    int* b = (int*)calloc(n, sizeof(int));

    printf("malloc 결과 (초기화 안 함):\n  ");
    for (int i = 0; i < n; i++) printf("%d ", a[i]);

    printf("\n\ncalloc 결과 (0으로 초기화):\n  ");
    for (int i = 0; i < n; i++) printf("%d ", b[i]);
    printf("\n");

    free(a); a = NULL;
    free(b); b = NULL;
```

**✅ 여기까지 실행하면** — `malloc`은 쓰레기 값, `calloc`은 전부 0이 나온다.

> `malloc` 결과가 우연히 0으로 보일 수도 있다. **그래도 보장되지 않는다.**
> 초기화가 필요하면 `calloc`을 쓰거나 직접 채운다.

### Step 8 — 기록 분석 (배열 순회 패턴 재사용)

```c
void AnalyzeRecords(const Record* r, int count)
{
    if (r == NULL || count == 0) return;

    int maxWinStreak = 0, maxLoseStreak = 0;
    int curWin = 0, curLose = 0;
    int maxMoney = r[0].moneyAfter;
    int minMoney = r[0].moneyAfter;

    for (int i = 0; i < count; i++)
    {
        // 연승/연패
        if (r[i].isWin)
        {
            curWin++;
            curLose = 0;
            if (curWin > maxWinStreak) maxWinStreak = curWin;
        }
        else
        {
            curLose++;
            curWin = 0;
            if (curLose > maxLoseStreak) maxLoseStreak = curLose;
        }

        // 최대/최소 (Day 11 패턴 ③)
        if (r[i].moneyAfter > maxMoney) maxMoney = r[i].moneyAfter;
        if (r[i].moneyAfter < minMoney) minMoney = r[i].moneyAfter;
    }

    printf("\n  최대 연승  %d        최대 연패  %d\n", maxWinStreak, maxLoseStreak);
    printf("  최고 잔액  %d G      최저 잔액  %d G\n", maxMoney, minMoney);
}
```

**✅ 여기까지 실행하면** — 1절의 통계가 나온다.

### Step 10 — `realloc`으로 확장 (도전)

```c
    // 라운드가 예상보다 길어지면 기록 공간을 늘린다
    if (game.round > capacity)
    {
        int newCapacity = capacity * 2;

        Record* tmp = (Record*)realloc(records, sizeof(Record) * newCapacity);

        if (tmp == NULL)
        {
            printf("확장 실패. 기록을 중단합니다.\n");
            // records는 여전히 유효하다
        }
        else
        {
            records  = tmp;
            capacity = newCapacity;
            printf("  기록 공간 확장: %d칸\n", capacity);
        }
    }
```

> **2배씩 늘리는 이유** — 1칸씩 늘리면 매번 복사가 일어나 느리다.
> 2배씩 늘리면 확장 횟수가 로그 수준으로 줄어든다.
> (C++의 `std::vector`, C#의 `List<T>`가 정확히 이 방식이다)

**✅ 여기까지 실행하면** — 기록이 가득 차면 자동으로 공간이 늘어난다.

## 6. 자주 막히는 곳

| 증상 | 원인 | 해결 |
|---|---|---|
| 크래시 | `malloc` 결과 `NULL` 검사 안 함 | `if (p == NULL)` 추가 |
| 크기가 예상보다 작음 | `malloc(100)` 처럼 개수만 씀 | `malloc(sizeof(int) * 100)` |
| 이상한 초기값 | `malloc`은 초기화 안 함 | `calloc` 사용 또는 직접 채우기 |
| 이중 해제 크래시 | `free` 두 번 | `free` 후 `p = NULL` |
| 해제 후에도 사용 | dangling pointer | `free` 후 `NULL`, 사용 전 검사 |
| 메모리 계속 증가 | `free` 누락 | `malloc`마다 짝이 되는 `free` 확인 |
| `realloc` 후 누수 | `p = realloc(p, ...)` 로 대입 | 임시 포인터로 받아 검사 후 교체 |
| 힙 손상 오류 | 범위 초과 쓰기 | 인덱스 검사 |
| `free` 시 크래시 | 반환받은 주소가 아닌 것을 `free` | `malloc`이 준 원래 주소만 `free` |
| `malloc` 관련 오류 | `<stdlib.h>` 누락 | 포함 |

> **디버그 팁 — Visual Studio의 메모리 누수 감지**
>
> ```c
> #define _CRTDBG_MAP_ALLOC
> #include <stdlib.h>
> #include <crtdbg.h>
>
> int main(void)
> {
>     _CrtSetDbgFlag(_CRTDBG_ALLOC_MEM_DF | _CRTDBG_LEAK_CHECK_DF);
>     // ... 프로그램 ...
> }
> ```
>
> 디버그 실행(F5) 종료 시 **출력 창**에 누수 목록이 뜬다.

## 7. 정리

### 오늘 배운 것

| 개념 | 한 줄 요약 |
|---|---|
| 스택 vs 힙 | 스택=자동/작음/컴파일 시점, 힙=수동/큼/실행 시점 |
| `malloc` | 힙에서 빌리기. **크기는 `sizeof`로 계산** |
| `NULL` 검사 | 할당 실패 시 `NULL`. **반드시 검사** |
| `free` | 반납. **`malloc`과 1:1 짝** |
| `free` 후 `NULL` | 이중 해제·dangling pointer 방지 |
| `calloc` | 0으로 초기화된 할당 |
| `realloc` | 크기 변경. **임시 포인터로 받는다** |
| 메모리 누수 | 반납 안 하면 프로그램이 점점 커진다 |
| 소유권 | **누가 `free`할 책임인지** 명확히 한다 |
