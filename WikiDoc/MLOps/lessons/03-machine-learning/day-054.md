## ① 학습 목표

이 레슨을 마치면 이렇게 할 수 있습니다.

- MAE · RMSE · R²가 **각각 무엇을 다르게 보는지** 설명하고, 문제 상황에 맞게 고를 수 있다.
- **지표에 따라 모델의 순위가 달라질 수 있음**을 실험으로 보일 수 있다.
- R²를 직접 계산하고, **음수 R²** 가 무슨 뜻인지 설명할 수 있다.
- 과적합을 일부러 만든 뒤 **Ridge/Lasso 규제**로 눌러 볼 수 있고, Lasso의 특성 선택 효과를 안다.

---

## ② 왜 필요한가

어제까지 R² · MAE를 계속 봤지만, 사실 아직 이 질문에 답하지 못합니다.

> "모델 A는 MAE가 좋고 모델 B는 RMSE가 좋습니다. **어느 걸 배포하죠?**"

지표를 모르면 이 질문 앞에서 동전을 던지게 됩니다. 그런데 이건 동전 던지기가 아니라
**서비스의 성격을 정하는 결정**입니다.

```
MAE가 좋은 모델  = 평소에 두루 잘 맞히지만, 가끔 크게 틀릴 수 있음
RMSE가 좋은 모델 = 평소엔 조금 둔해도, 대형 사고(큰 오차)가 적음
```

미세먼지 예보가 **평소에 1~2 더 정확한 것**과 **황사 날 20씩 틀리지 않는 것** 중
무엇이 중요한가 — 이건 수학이 아니라 **제품 결정**이고, 지표 선택이 그 결정을 코드에 새깁니다.
MP2 기획서의 "모델 평가: 주 지표 1개 + 보조 지표 2개, **선택 근거**"가 바로 이것입니다.

## ③ 개념 설명

### 회귀 지표 3종

실제값 y, 예측값 ŷ, 오차 e = y − ŷ 라고 할 때:

| 지표 | 계산 | 단위 | 성격 |
|---|---|---|---|
| **MAE** | \|e\| 의 평균 | 타깃과 동일 (㎍/㎥) | 모든 오차를 공평하게. **이상치에 둔감** |
| **RMSE** | e² 의 평균에 √ | 타깃과 동일 (㎍/㎥) | 제곱 때문에 **큰 오차에 벌점 집중** |
| **R²** | 1 − (모델 MSE / 평균모델 MSE) | 없음 (비율) | "평균으로 찍기 대비 얼마나 나은가" |

세 가지 기억할 점:

1. **RMSE ≥ MAE 항상 성립.** 둘의 차이가 클수록 "가끔 크게 틀리는" 모델입니다.
2. **MAE·RMSE는 단위가 있어 설명하기 좋습니다.** "평균 4.9㎍/㎥ 어긋납니다"는 비전공자도 압니다.
3. **R²는 단위가 없어 문제끼리 비교할 때** 좋지만, 홀로 쓰면 오해를 만듭니다 (아래 참고).

### R²의 눈금 읽기

```
R² = 1.0   완벽한 예측
R² = 0.5   평균으로 찍기보다 오차(제곱)를 절반으로 줄임
R² = 0.0   평균으로 찍기와 같은 수준
R² < 0     평균으로 찍기보다 못함  ← 실제로 자주 봅니다!
```

R²는 정확도가 아닙니다. "R² 0.39 = 39% 맞힘"이 아니라 **"평균 모델의 제곱 오차를 39% 줄였다"** 입니다.
그리고 시간 분리 평가에서는 음수가 잘 나옵니다 — train 평균으로 찍는 모델은 test 구간의
평균이 조금만 달라도 밑지기 때문입니다 (실습 Step 3).

### 손실 함수와 평가 지표는 다른 것

| | 손실 함수 | 평가 지표 |
|---|---|---|
| 누가 쓰나 | **모델이** 학습 중 최적화 | **사람이** 보고·비교 |
| 예 | 제곱 오차, 절대 오차 | MAE, RMSE, R² |

둘을 **정렬**하는 것이 좋습니다. MAE로 평가할 거면서 제곱 오차로 학습시키면, 모델은
"큰 오차 회피"를 배우는데 성적표는 "평균 오차"로 받는 엇박자가 생깁니다.
오늘 실습 Step 2에서 손실 함수만 바꿔 모델의 성격이 바뀌는 것을 확인합니다.

### 규제(regularization) — 계수에 벌점을 매긴다

과적합의 전형적인 모습은 **계수가 비정상적으로 커지는 것**입니다 (몇몇 특성에 극단적으로
기대어 학습 데이터를 외움). 규제는 손실 함수에 **계수 크기에 대한 벌점**을 더해 이를 막습니다.

```
Ridge: 손실 = MSE + α · Σ(계수²)      ← 큰 계수를 고르게 줄임 (L2)
Lasso: 손실 = MSE + α · Σ|계수|       ← 덜 중요한 계수를 정확히 0으로 (L1)
```

| | Ridge | Lasso |
|---|---|---|
| 계수가 | 작아짐 (0은 안 됨) | **0이 됨** → 특성 선택 효과 |
| 어울리는 상황 | 상관된 특성이 많을 때 | 특성이 많고 일부만 유효할 때 |
| α (알파) | 벌점 강도. 클수록 단순한 모델 | 동일 |

**규제 전 표준화는 필수입니다.** 벌점이 계수 크기에 매겨지는데, 어제 봤듯 계수 크기는
특성의 스케일에 종속됩니다. 스케일링 없이 규제하면 단위가 작은 특성(so2)만 억울하게 벌 받습니다.

### Step 1. 손 계산 — 두 예보관 문제 (1교시)

5일간 실제 pm25가 `20, 25, 30, 35, 60`이었습니다. 두 예보관의 예보:

- **김 예보관**: `24, 29, 26, 39, 56` — 매일 꼬박꼬박 4씩 틀림
- **이 예보관**: `20, 25, 30, 35, 40` — 4일은 완벽, **황사 날(60) 하루만 20 틀림**

```python
# day054_metrics.py — 회귀 지표와 규제
import numpy as np
import pandas as pd
from sklearn.metrics import mean_absolute_error, r2_score

def rmse(y, p):
    return float(np.sqrt(((y - p) ** 2).mean()))

print("== A. 손 계산: 두 예보관 ==")
actual = np.array([20, 25, 30, 35, 60])
kim    = np.array([24, 29, 26, 39, 56])   # 모든 날 4 오차
lee    = np.array([20, 25, 30, 35, 40])   # 4일 완벽, 고농도 날 20 오차
for name, p in [("김 예보관", kim), ("이 예보관", lee)]:
    print(f"  {name}: MAE {mean_absolute_error(actual, p):.1f}  RMSE {rmse(actual, p):.2f}")
```

실행 결과:

```
== A. 손 계산: 두 예보관 ==
  김 예보관: MAE 4.0  RMSE 4.00
  이 예보관: MAE 4.0  RMSE 8.94
```

**MAE로는 동률(4.0), RMSE로는 2배 이상 차이.** 지표가 순위를 가릅니다.
누가 더 나은 예보관인지는 지표가 아니라 **서비스가** 정합니다 — "황사 날 놓치면 안 되는
경보 서비스"라면 김, "매일 문자로 보내는 생활 예보 평균 품질"이라면 둘은 동급입니다.

### Step 2. 손실 함수 교체 실험 — 모델의 성격이 바뀐다 (2~3교시)

같은 모델(그래디언트 부스팅, [Day 059](day-059.md)에서 자세히)의 **손실 함수만** 바꿔 봅니다.

```python
print("\n== B. 같은 모델, 손실 함수만 교체 ==")
from sklearn.ensemble import HistGradientBoostingRegressor
from sklearn.linear_model import LinearRegression

df = pd.read_csv("data/air_daily.csv", parse_dates=["date"])
F10 = ["pm10", "pm25", "o3", "no2", "co", "so2", "temp", "humidity", "wind_speed", "precip"]
d = df.dropna(subset=F10)
tr = d[d.date < "2026-01-01"]; te = d[d.date >= "2026-01-01"]
Xtr, ytr, Xte, yte = tr[F10], tr.pm25_next, te[F10], te.pm25_next

models = {
    "선형 회귀": LinearRegression().fit(Xtr, ytr),
    "HGB(제곱 손실)": HistGradientBoostingRegressor(random_state=42, loss="squared_error").fit(Xtr, ytr),
    "HGB(절대 손실)": HistGradientBoostingRegressor(random_state=42, loss="absolute_error").fit(Xtr, ytr),
}
for name, m in models.items():
    p = m.predict(Xte)
    print(f"  {name:<12} MAE {mean_absolute_error(yte, p):5.2f}  RMSE {rmse(yte, p):5.2f}  R² {r2_score(yte, p):6.3f}")
```

실행 결과:

```
== B. 같은 모델, 손실 함수만 교체 ==
  선형 회귀        MAE  4.87  RMSE  6.09  R²  0.390
  HGB(제곱 손실)   MAE  5.43  RMSE  6.88  R²  0.221
  HGB(절대 손실)   MAE  5.12  RMSE  6.43  R²  0.321
```

손실 함수 한 줄로 MAE가 5.43 → 5.12. **모델이 무엇을 무서워하는지가 바뀐 것**입니다.
그럼 제곱 손실은 뭘 얻었을까요? **최악의 한 방**을 봅니다.

```python
print("\n  오차 분포의 꼬리:")
for name in ["HGB(제곱 손실)", "HGB(절대 손실)"]:
    e = (yte - models[name].predict(Xte)).abs()
    print(f"  {name}: 최대 오차 {e.max():.1f} · 상위 5% 오차 {e.quantile(0.95):.2f} · 10 이상 비율 {(e >= 10).mean() * 100:.1f}%")
```

실행 결과:

```
  오차 분포의 꼬리:
  HGB(제곱 손실): 최대 오차 21.3 · 상위 5% 오차 14.02 · 10 이상 비율 14.5%
  HGB(절대 손실): 최대 오차 23.0 · 상위 5% 오차 12.68 · 10 이상 비율 12.6%
```

절대 손실이 평균 성적(MAE·상위 5%)은 좋지만 **최대 오차는 제곱 손실이 작습니다**(21.3 vs 23.0).
제곱 손실은 "크게 틀리느니 평소에 조금씩 손해 보겠다"는 성격 — 김 예보관입니다.
(참고로 세 모델 모두 선형 회귀를 못 이깁니다. 이 데이터에서 부스팅이 왜 고전하는지는 [Day 059](day-059.md)의 주제입니다.)

### Step 3. R² 직접 계산 — 그리고 음수 R² (5교시)

```python
print("\n== C. R² 직접 계산 ==")
p = models["선형 회귀"].predict(Xte)
mse_model = ((yte - p) ** 2).mean()
mse_mean = ((yte - ytr.mean()) ** 2).mean()      # 비교 대상: train 평균으로 찍기
print(f"  모델 MSE {mse_model:.2f} · 평균모델 MSE {mse_mean:.2f} · R² = 1 - {mse_model:.2f}/{mse_mean:.2f} = {1 - mse_model / mse_mean:.3f}")
print(f"  sklearn r2_score = {r2_score(yte, p):.3f}  (sklearn은 test 평균 기준: 약간 다를 수 있음)")

p_mean = np.full(len(yte), ytr.mean())
print(f"  평균 예측의 R² = {r2_score(yte, p_mean):.3f}  ← 음수!")
```

실행 결과:

```
== C. R² 직접 계산 ==
  모델 MSE 37.14 · 평균모델 MSE 63.51 · R² = 1 - 37.14/63.51 = 0.415
  sklearn r2_score = 0.390  (sklearn은 test 평균 기준: 약간 다를 수 있음)
  평균 예측의 R² = -0.043  ← 음수!
```

두 가지 발견:

1. **기준 평균을 무엇으로 잡느냐로 R²가 달라집니다** (0.415 vs 0.390). sklearn은 "test
   구간의 평균으로 찍기"와 비교합니다 — 우리가 할 수 없는 예측(미래의 평균)과 비교하므로 더 짠 채점입니다.
2. **"train 평균으로 찍기"의 R²는 -0.043, 음수입니다.** test 구간(2026년 상반기 — 겨울·봄 포함)의
   평균 농도가 train 전체 평균과 달라서, 과거 평균으로 찍기는 미래에서 밑집니다.
   **음수 R² = "그 데이터의 평균으로 찍느니만 못함"** 이지 버그가 아닙니다.

### Step 4. 과적합을 만들고 규제로 눌러 보기 (6~7교시)

지금까지 우리 선형 회귀는 과적합할 재료(특성 10개 vs 행 2,629개)가 부족했습니다.
**다항 특성**으로 재료를 늘려 일부러 과적합을 만든 뒤 규제로 눌러 봅니다.

```python
print("\n== D. 과적합 만들기: 다항 특성 + 규제 ==")
from sklearn.linear_model import Ridge, Lasso
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import PolynomialFeatures, StandardScaler

for name, model in [
    ("선형 (10특성)", LinearRegression()),
    ("선형 (2차 다항 65특성)", make_pipeline(StandardScaler(), PolynomialFeatures(2, include_bias=False), LinearRegression())),
    ("선형 (3차 다항 285특성)", make_pipeline(StandardScaler(), PolynomialFeatures(3, include_bias=False), LinearRegression())),
    ("Ridge(α=10) 3차 다항", make_pipeline(StandardScaler(), PolynomialFeatures(3, include_bias=False), Ridge(alpha=10.0))),
    ("Lasso(α=0.1) 2차 다항", make_pipeline(StandardScaler(), PolynomialFeatures(2, include_bias=False), Lasso(alpha=0.1, max_iter=50000))),
]:
    m = model.fit(Xtr, ytr)
    print(f"  {name:<20} train R² {r2_score(ytr, m.predict(Xtr)):.3f}   test R² {r2_score(yte, m.predict(Xte)):.3f}")
```

실행 결과:

```
== D. 과적합 만들기: 다항 특성 + 규제 ==
  선형 (10특성)          train R² 0.648   test R² 0.390
  선형 (2차 다항 65특성)   train R² 0.673   test R² 0.397
  선형 (3차 다항 285특성)  train R² 0.719   test R² 0.312
  Ridge(α=10) 3차 다항   train R² 0.715   test R² 0.333
  Lasso(α=0.1) 2차 다항  train R² 0.665   test R² 0.409
```

이 표 하나에 이번 주 전체가 들어 있습니다.

| 행 | 읽는 법 |
|---|---|
| 10특성 → 2차 다항 | train·test 모두 소폭 상승 — 상호작용 항(pm10×풍속 같은)에 **진짜 정보**가 조금 있음 |
| → 3차 다항 | train은 계속 오르는데(0.719) **test는 무너짐**(0.312) — 전형적 과적합. train 점수는 늘 웃는 얼굴 |
| Ridge α=10 | 3차의 폭주를 **완화**(0.312→0.333)하지만 회복 불능 — 규제는 만병통치가 아님 |
| **Lasso 2차** | **0.409 — 오늘의 최고점.** 적당한 재료(2차) + 규제의 조합이 순정 선형(0.390)을 넘음 |

> train R²와 test R²의 **간격**이 과적합 게이지입니다. 간격이 벌어지는데 test가 안 오르면
> 모델을 키우는 게 아니라 줄여야(규제) 할 때입니다.

### Step 5. Lasso의 특성 선택 (7교시)

```python
print("\n== E. Lasso의 특성 선택 (원 10특성 기준) ==")
sc = StandardScaler().fit(Xtr)
for a in [0.01, 0.1, 0.5, 1.0]:
    las = Lasso(alpha=a, max_iter=50000).fit(sc.transform(Xtr), ytr)
    alive = [f for f, c in zip(F10, las.coef_) if abs(c) > 1e-6]
    p = las.predict(sc.transform(Xte))
    print(f"  α={a:<5} 살아남은 특성 {len(alive)}개 {alive}  test R² {r2_score(yte, p):.3f}")
```

실행 결과:

```
== E. Lasso의 특성 선택 (원 10특성 기준) ==
  α=0.01  살아남은 특성 10개 ['pm10', 'pm25', 'o3', 'no2', 'co', 'so2', 'temp', 'humidity', 'wind_speed', 'precip']  test R² 0.391
  α=0.1   살아남은 특성 6개 ['pm10', 'pm25', 'no2', 'so2', 'temp', 'precip']  test R² 0.394
  α=0.5   살아남은 특성 5개 ['pm10', 'pm25', 'no2', 'temp', 'precip']  test R² 0.390
  α=1.0   살아남은 특성 5개 ['pm10', 'pm25', 'no2', 'temp', 'precip']  test R² 0.365
```

α를 키울수록 Lasso가 특성을 **정확히 0으로** 잘라냅니다. α=0.5에서 **특성 5개로 10개와
같은 성능**(0.390) — "절반을 버려도 성능이 같다"는 것은 어제 Step 3(특성 2배, 이득 0.001)과
같은 이야기를 규제의 언어로 다시 들려주는 것입니다. 입력이 절반이면 수집·검증·서빙 비용도 절반입니다.

> α를 어떻게 고르냐고요? 지금은 test 점수를 보며 골랐는데 — **이거, Day 052에서 하지 말라던
> 그 행동입니다** (test를 여러 번 열었음). 제대로 고르는 방법이 [Day 061](day-061.md) 교차검증입니다.

## ⑤ 자주 하는 실수

### MSE와 RMSE를 섞어 씀

**증상** — "오차가 37이나 된다"고 보고 (실제 RMSE는 6.09).
**원인** — MSE(37.14)는 **제곱된 단위**(㎍/㎥)²라 크기가 직관과 다릅니다.
**해결** — 보고에는 √를 씌운 RMSE를 씁니다. `mean_squared_error(y, p)` 에 √를 직접 씌우거나
`root_mean_squared_error` 를 쓰세요.

### R²를 "몇 % 맞혔다"로 해석함

**증상** — "R² 0.39니까 39%밖에 못 맞히는 모델"이라고 폐기 판정.
**원인** — R²는 정답률이 아니라 **평균 모델 대비 제곱 오차 감소율**입니다.
**해결** — "평균으로 찍기보다 오차(제곱)를 39% 줄였다"로 읽습니다. 체감 성능은 MAE("평균 4.9 어긋남")로 말하세요.

### 스케일링 없이 Lasso/Ridge를 돌림

**증상** — 에러는 없는데, 스케일이 작은 특성(so2 등)의 계수만 먼저 0이 됨.
**원인** — 벌점은 계수 크기에 붙고, 계수 크기는 스케일에 종속입니다([Day 053](day-053.md)). 단위가 작은 특성이 부당하게 큰 벌을 받습니다.
**해결** — 규제 모델 앞에는 반드시 StandardScaler. `make_pipeline(StandardScaler(), Lasso(...))` 처럼 묶으세요.

### Lasso가 수렴 경고를 냄

```
ConvergenceWarning: Objective did not converge. You might want to increase the number of iterations.
```

**원인** — Lasso는 반복 최적화를 쓰는데 기본 반복 횟수(1,000)가 부족했습니다. 특히 다항 특성처럼 특성이 많고 상관될 때 잘 납니다.
**해결** — `Lasso(alpha=..., max_iter=50000)` 처럼 반복을 늘리거나, 스케일링이 빠지지 않았는지 확인합니다(스케일링 없으면 수렴이 훨씬 느립니다).

### α를 test 점수로 고름

**증상** — Step 5처럼 α별 test R²를 보고 "0.1이 최고네" 하고 채택.
**원인** — test를 튜닝에 썼으므로 그 순간부터 test는 더 이상 공정한 시험이 아닙니다 ([Day 052](day-052.md) 원칙 위반 — 오늘 수업에서는 교육 목적으로 일부러 보였습니다).
**해결** — 하이퍼파라미터 선택은 train 내부의 교차검증으로 ([Day 061](day-061.md)·[062](day-062.md)). test는 최종 확인 1회.
