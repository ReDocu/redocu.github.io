## ② 왜 필요한가

### 어제의 질문 — 모델은 이 답을 어떻게 만드는가

어제 우리는 **정답을 표현하는 법**을 배웠습니다.

```
person 0.87 (280, 110, 430, 360)
```

그런데 모델은 이 네 개의 숫자를 **어디서 가져오는 걸까요?**

분류 모델은 이해하기 쉬웠습니다. 마지막 층에 노드 3개를 두면 확률 3개가 나옵니다.
그런데 검출은 **몇 개가 나올지 모릅니다.** 노드를 몇 개 둬야 합니까?

```
사진 A: 사람 1명   → 답 1개
사진 B: 사람 12명  → 답 12개
사진 C: 아무도 없음 → 답 0개

★ 출력 노드 개수를 어떻게 정하는가?
```

**이 문제를 푸는 방식이 곧 검출 모델의 역사입니다.**
오늘 배우는 계보는 전부 이 한 가지 질문에 대한 서로 다른 답입니다.

### 가장 단순한 답 — 다 해 보면 되지 않나

분류 모델이 이미 있다면, 이렇게 하면 될 것 같습니다.

```
① 작은 사각형 창을 만든다
② 이미지 위를 조금씩 옮기면서
③ 매번 분류 모델을 돌린다
④ "개"라고 나온 위치를 답으로 삼는다
```

**이것을 슬라이딩 윈도우(sliding window)라고 합니다.** 논리적으로는 완벽합니다.
문제는 횟수입니다.

```
이미지 640 × 640
창 크기 64 × 64, 8픽셀씩 이동

가로 이동 횟수 = (640 - 64) / 8 + 1 = 73
세로 이동 횟수 = 73
                              → 5,329 번

그런데 물체 크기가 다양하므로 창 크기도 여러 개 필요
창 크기 5종 (32, 64, 128, 192, 256)   → 약 12,000 번
가로세로 비율 3종 (1:1, 1:2, 2:1)      → 약 36,000 번
```

**사진 한 장에 분류를 36,000번 돌려야 합니다.**

```
분류 1회 = 3ms  (가벼운 CNN 기준)
36,000 × 3ms = 108초

★ 사진 한 장에 1분 48초
★ 영상 30 FPS 라면? 계산 불가
```

> **검출 모델의 역사는 "이 36,000번을 어떻게 줄일 것인가"의 역사입니다.**
> 오늘 배우는 모든 구조는 이 숫자를 줄이는 서로 다른 전략입니다.

### 우리가 이 계보를 알아야 하는 실무적 이유

"어차피 YOLO 쓸 건데 R-CNN을 왜 배우나요?"

**세 가지 판단을 해야 하기 때문입니다.**

| 판단 | 계보를 모르면 |
|---|---|
| 모델 크기 선택 (n/s/m/l/x) | 왜 큰 게 느린지 감이 없음 |
| **속도가 안 나올 때 무엇을 바꿀지** | 해상도인지 모델인지 판단 불가 |
| 정확도가 안 나올 때 원인 추정 | "작은 물체를 못 찾는다"의 구조적 이유를 모름 |

그리고 실무에서 이런 대화를 하게 됩니다.

```
"Faster R-CNN 쓰면 안 되나요?"
→ "라즈베리파이에서 0.4 FPS 나옵니다. 1-stage 아니면 못 씁니다."
```

**이 대답을 하려면 왜 그런지 알아야 합니다.**

### 오늘 하는 일

```
1~4교시 (개념)
  ① 슬라이딩 윈도우 — 왜 안 되는가
  ② 2-stage 계보 — R-CNN → Fast → Faster
  ③ 1-stage 계보 — YOLO의 아이디어
  ④ YOLO 버전 변화 · FPS 요구사항 · Ultralytics

  ⑥ COCO 80개 클래스 확인
  ⑦ 결과 객체 구조 파헤치기 — boxes / conf / cls
  ⑧ 이미지 · 폴더 · 동영상 · 웹캠 추론
```

### 오늘의 목표를 한 줄로

> **"YOLO가 왜 빠른지 한 문장으로 말하고, 사전학습 모델로 지금 당장 검출을 돌린다."**

## ③ 개념 설명

### 슬라이딩 윈도우 — 왜 안 되는가

```
     이미지                    창을 옮기며 분류
  ┌──────────────┐        ┌──┐
  │              │        │  │→ "배경"
  │      🐕      │          ┌──┐
  │              │          │  │→ "배경"
  └──────────────┘             ┌──┐
                               │🐕│→ "개!" ✓
```

**낭비되는 지점 두 곳**

| 낭비 | 설명 |
|---|---|
| **중복 계산** | 8픽셀 옮기면 창의 87%가 이전과 같은 픽셀인데 처음부터 다시 계산 |
| **대부분이 배경** | 36,000번 중 99.9%가 "배경". 의미 없는 계산 |

**두 낭비를 없애는 것이 각각의 계보가 됩니다.**

```
중복 계산 제거      →  특징맵을 한 번만 계산 (Fast R-CNN · YOLO 공통)
배경 후보 줄이기    →  ① 영역 제안으로 후보 2,000개만    (2-stage)
                     ② 격자로 나눠 셀마다 고정 개수만    (1-stage)
```

### 2-stage 계보 — 후보를 먼저 고르고, 그다음 분류

**핵심 아이디어**: 36,000군데를 다 볼 필요 없다. **"뭔가 있어 보이는 곳"만 2,000군데 고르자.**

```
[1단계] 영역 제안(Region Proposal)     → 후보 박스 ~2,000개
                ↓
[2단계] 각 후보를 분류 + 박스 미세조정  → 최종 결과
```

| 모델 | 연도 | 핵심 개선 | 속도 |
|---|---|---|---|
| **R-CNN** | 2014 | Selective Search로 후보 2,000개 → **각각 CNN 통과** | 47초/장 |
| **Fast R-CNN** | 2015 | **CNN을 한 번만** 돌리고 특징맵에서 후보 영역만 잘라 씀(RoI Pooling) | 2초/장 |
| **Faster R-CNN** | 2015 | 영역 제안도 **신경망(RPN)** 으로 → 전 과정 학습 가능 | 0.2초/장 |
| Mask R-CNN | 2017 | + 픽셀 마스크 분기 (인스턴스 분할) | 0.2초/장 |

**R-CNN → Fast R-CNN 이 23배 빨라진 이유**

```
R-CNN       후보 2,000개 × CNN 1번씩  =  CNN 2,000번
Fast R-CNN  CNN 1번 → 특징맵에서 2,000개 영역을 잘라 씀  =  CNN 1번
```

> **"특징 추출을 공유한다"** — 이 아이디어는 이후 모든 검출 모델의 기본이 됩니다.
> YOLO도 마찬가지로 CNN을 딱 한 번만 돌립니다.

### 1-stage 계보 — 후보를 고르지 말고 한 번에 예측

**핵심 아이디어**: 후보를 고르는 단계 자체를 없애자. **격자로 나누고 각 칸이 책임지게 하자.**

```
[한 단계] 이미지 → CNN → 격자의 각 칸마다 "여기 뭐 있어?" 를 동시에 예측
```

| 모델 | 연도 | 특징 |
|---|---|---|
| **YOLO v1** | 2015 | 7×7 격자. "You Only Look Once". 45 FPS |
| **SSD** | 2016 | 여러 크기의 특징맵에서 동시 예측 → 작은 물체 개선 |
| **RetinaNet** | 2017 | Focal Loss로 배경 불균형 해결 → 1-stage 정확도 향상 |
| **YOLOv3~v8, YOLO11** | 2018~ | 지속 개선. 현재 실무 표준 |

### ★ YOLO의 아이디어 — 그림으로

**① 이미지를 격자로 나눕니다**

```
   ┌───┬───┬───┬───┬───┬───┐
   │   │   │   │   │   │   │      예: 20 × 20 격자
   ├───┼───┼───┼───┼───┼───┤      (실제로는 3가지 크기의 격자를 함께 씀)
   │   │ ● │   │   │   │   │
   ├───┼───┼───┼───┼───┼───┤      ● = 객체의 중심이 들어간 칸
   │   │🐕 │   │   │   │   │
   ├───┼───┼───┼───┼───┼───┤
   │   │   │   │   │ ● │   │
   ├───┼───┼───┼───┼───┼───┤
   │   │   │   │   │🐈 │   │
   └───┴───┴───┴───┴───┴───┘
```

**② 객체의 중심이 들어간 칸이 그 객체를 책임집니다**

```
각 칸이 내놓는 답
   · 박스 좌표 (cx, cy, w, h)     ← 어제 배운 그 형식
   · 클래스별 점수                 ← 80개 클래스면 80개 숫자
```

**③ 모든 칸의 답을 한 번에 뽑고, 겹치는 것을 정리합니다**

```
20×20 격자 = 400칸 → 후보 400개 (실제로는 8,400개 수준)
       ↓
conf 임계값으로 거르기        → 12개
       ↓
NMS 로 중복 제거              → 3개  ★ 최종 결과
```

> **"You Only Look Once"** — 이미지를 딱 한 번 통과시킨다는 뜻입니다.
> 2-stage는 두 번 봅니다(후보 뽑고, 다시 분류). 이 차이가 속도 차이의 전부입니다.

### 앵커(anchor)와 앵커프리(anchor-free)

**앵커**는 "미리 정해 둔 표준 박스 모양"입니다.

```
칸 하나가 아무 크기나 예측하려면 어렵습니다.
→ "이 정도 크기·비율"을 미리 3개 정해 두고, 거기서 얼마나 다른지만 예측

  앵커 1: 세로로 긴 것  (사람)
  앵커 2: 정사각형      (공, 얼굴)
  앵커 3: 가로로 긴 것  (자동차, 버스)
```

| | 앵커 기반 (v3~v7) | **앵커프리 (v8, YOLO11)** |
|---|---|---|
| 방식 | 표준 박스 대비 차이를 예측 | **중심점에서 네 방향 거리를 직접 예측** |
| 사전 설정 | 앵커 크기를 데이터에 맞춰 정해야 함 | **불필요** |
| 하이퍼파라미터 | 많음 | 적음 |
| 우리 수업 | 개념만 | **실제로 쓰는 방식** |

> **좋은 소식** — YOLO11은 앵커프리라서 **앵커를 신경 쓸 필요가 없습니다.**
> 예전 자료에서 "앵커 클러스터링(k-means)"을 하라는 내용을 보면, **v7 이하 이야기**입니다.

### 2-stage vs 1-stage — 무엇을 고를 것인가

| | 2-stage (Faster R-CNN) | **1-stage (YOLO)** |
|---|---|---|
| 속도 | 느림 (5~10 FPS) | **빠름 (30~200 FPS)** |
| 정확도 | 전통적으로 우위 | **현재는 거의 동등하거나 우위** |
| 작은 물체 | 유리 | 개선됨 (다중 스케일) |
| 학습 난이도 | 복잡 | **간단** |
| 엣지 디바이스 | 사실상 불가 | **가능** |
| 생태계 | 연구용 프레임워크 | **Ultralytics 한 줄 설치** |

**우리가 YOLO를 쓰는 이유 세 가지**

```
① 라즈베리파이에서 돌아가야 한다        → 1-stage 필수
② 실시간 스트리밍을 해야 한다           → 1-stage 필수
③ 수업 시간에 학습·배포를 끝내야 한다    → Ultralytics 생태계
```

> **"정확도는 2-stage가 좋다"는 말은 2019년까지의 상식입니다.**
> 지금은 YOLO11이 COCO에서 Faster R-CNN보다 정확하면서 20배 빠릅니다.
> 오래된 블로그를 읽을 때 **연도를 먼저 보세요.**

### YOLO 버전 계보 — 알아야 할 것만

| 버전 | 연도 | 만든 곳 | 기억할 점 |
|---|---|---|---|
| v1~v3 | 2016~18 | Joseph Redmon | 원저자. v3까지 만들고 연구 중단 선언 |
| v4 | 2020 | Alexey Bochkovskiy | Darknet 계열 마지막 정통 후계 |
| **v5** | 2020 | **Ultralytics** | PyTorch 재구현. **쓰기 쉬워서 폭발적으로 퍼짐** |
| v6 · v7 | 2022 | Meituan · 원 v4팀 | 산업용 최적화 |
| **v8** | 2023 | Ultralytics | **앵커프리** · 분류/분할/자세추정 통합 |
| v9 · v10 | 2024 | 학계 | NMS 제거 시도 등 |
| **YOLO11** | 2024 | **Ultralytics** | **우리가 쓸 버전.** v8 대비 파라미터 ↓ 정확도 ↑ |

> ⚠️ **버전 번호가 성능 순서가 아닙니다.**
> v10이 YOLO11보다 최신도 아니고, 만든 팀이 다 다릅니다.
> **"Ultralytics 패키지에서 지원하는 최신 안정 버전"** 을 쓰면 됩니다. 지금은 **YOLO11**입니다.

### 모델 크기 — n / s / m / l / x

같은 YOLO11이라도 크기가 5종입니다.

| 모델 | 파라미터 | COCO mAP50-95 | CPU 속도 | 용도 |
|---|---|---|---|---|
| **yolo11n** | 2.6 M | 39.5 | 가장 빠름 | **라즈베리파이 · 실시간** |
| yolo11s | 9.4 M | 47.0 | 빠름 | **노트북 실시간 · 우리 기본값** |
| yolo11m | 20.1 M | 51.5 | 보통 | 서버 |
| yolo11l | 25.3 M | 53.4 | 느림 | 정확도 우선 |
| yolo11x | 56.9 M | 54.7 | 가장 느림 | 정확도 최우선 |

```
n → x 로 갈수록
  파라미터 22배 ↑
  mAP        +15 (39.5 → 54.7)
  속도        10배 이상 ↓
```

> **"큰 모델을 쓰면 좋아진다"는 함정입니다.**
> 데이터가 500장뿐이면 큰 모델은 **과적합**만 심해집니다.
> [Day 150](day-150.md)에서 실제로 비교해 보면, 우리 데이터셋에서는 **n과 s의 차이가 거의 없습니다.**

### 실시간이란 몇 FPS인가

**"실시간"은 용도가 정합니다.** 절대 기준은 없습니다.

| 용도 | 필요 FPS | 이유 |
|---|---|---|
| 자율주행 | 30~60 | 시속 60km = 초당 16m 이동 |
| 사람 추적 (붐비는 곳) | 15~30 | 사람이 빠르게 교차 |
| **CCTV 침입 감지** | **5~10** | 사람 걸음 속도. 이 정도면 놓치지 않음 |
| 주차장 차량 카운팅 | 2~5 | 차가 천천히 진입 |
| 이미지 업로드 검출 | **0.3 (3초)** | 사용자가 기다려 줌 |

```
사람이 걷는 속도 = 1.4 m/s
카메라 화각 안에 머무는 시간 ≈ 3~5초

5 FPS 라면 그동안 15~25 프레임 → 충분히 잡힘
```

> **우리 프로젝트 목표는 라즈베리파이에서 5 FPS 이상입니다.**
> "30 FPS 못 나오면 실패"라고 생각하지 마세요. **요구사항을 먼저 정하세요.** ([Day 154](day-154.md))

### Ultralytics — 왜 이걸 쓰는가

```python
from ultralytics import YOLO

model = YOLO("yolo11n.pt")
results = model("사진.jpg")
```

| 기능 | 명령 |
|---|---|
| 추론 | `model(source)` 또는 `model.predict(...)` |

|---|---|

```python
def detect_to_dicts(model, source, conf=0.25):
    """추론 결과를 표준 dict 리스트로 — ★ Day 152 detector.py 의 원형"""
    r = model(source, conf=conf, verbose=False)[0]

        voc = tuple(round(v, 1) for v in b.xyxy[0].tolist())
        out.append({
            "class_id": cls_id,
            "class": model.names[cls_id],
            "conf": round(float(b.conf), 4),
            "voc": voc,
            "coco": tuple(round(v, 1) for v in B.voc_to_coco(voc)),
            "yolo": tuple(round(v, 6) for v in B.voc_to_yolo(voc, w, h)),

    return out, (w, h)
```

### Step 8. 동영상과 웹캠

```python
import time
from pathlib import Path

import cv2
from ultralytics import YOLO

OUT = Path("day137/output")
OUT.mkdir(parents=True, exist_ok=True)
model = YOLO("yolo11n.pt")


def detect_video(src, out_path=None, max_frames=None, show=False):
    """동영상/웹캠 추론 + FPS 측정"""
    cap = cv2.VideoCapture(src)
    if not cap.isOpened():
        raise RuntimeError(f"열 수 없음: {src}")

    w = int(cap.get(cv2.CAP_PROP_FRAME_WIDTH))
    h = int(cap.get(cv2.CAP_PROP_FRAME_HEIGHT))
    src_fps = cap.get(cv2.CAP_PROP_FPS) or 30

    writer = None
    if out_path:
        fourcc = cv2.VideoWriter_fourcc(*"mp4v")
        writer = cv2.VideoWriter(str(out_path), fourcc, src_fps, (w, h))

    n, t0, total_det = 0, time.time(), 0
    try:
        while True:
            ok, frame = cap.read()
            if not ok:
                break
            r = model(frame, verbose=False)[0]
            total_det += len(r.boxes)
            vis = r.plot()

            elapsed = time.time() - t0
            fps = (n + 1) / elapsed if elapsed > 0 else 0
            cv2.putText(vis, f"FPS {fps:.1f}  det {len(r.boxes)}",
                        (12, 30), cv2.FONT_HERSHEY_SIMPLEX, 0.8,
                        (0, 255, 0), 2, cv2.LINE_AA)

            if writer:
                writer.write(vis)
            if show:
                cv2.imshow("detect", vis)
                if cv2.waitKey(1) & 0xFF == ord("q"):   # ★ q 로 종료
                    break

            n += 1
            if max_frames and n >= max_frames:
                break
    finally:
        cap.release()
        if writer:
            writer.release()
        cv2.destroyAllWindows()

    dt = time.time() - t0
    return {"frames": n, "seconds": round(dt, 2),
            "fps": round(n / dt, 2) if dt else 0,
            "avg_det": round(total_det / n, 2) if n else 0,
            "size": f"{w}×{h}"}


stat = detect_video("day137/videos/street.mp4",
                    out_path=OUT / "street_det.mp4", max_frames=150)

print("=" * 72)
print("동영상 추론 결과")
print("=" * 72)
for k, v in stat.items():
    print(f"  {k:<10}{v}")
print("-" * 72)
print(f"""
  ★ CPU에서 {stat['fps']} FPS 입니다.
    CCTV 목표(5 FPS)에는 미치지만 실시간 30 FPS 는 안 됩니다.

    대응 방법 (Day 153 · 168에서 전부 다룹니다)
      · imgsz 를 640 → 416 으로            속도 약 2배
      · 프레임 스킵 (2프레임에 1번만 추론)   속도 2배
      · ONNX/NCNN 으로 내보내기            속도 1.5~3배
      · GPU 사용                          속도 10배 이상
""")
print("=" * 72)

# ── 웹캠 (주석 해제해서 실행) ──
```

## ⑥ 확인 문제

**1.** 아래 상황에서 **슬라이딩 윈도우 방식의 총 분류 횟수**를 계산하고,
YOLO(20×20 격자 기준)와 비교해 몇 배 차이인지 답하세요.

```
이미지        1280 × 720
창 크기       96 × 96
이동 간격     16 픽셀
창 크기 종류   4종
가로세로 비율  3종
```

또한 이 계산이 **왜 실제 속도 차이를 과소평가하는지** 한 가지 이유를 쓰세요.

<details>
<summary>답 보기</summary>

### 슬라이딩 윈도우 횟수

```
가로 이동 = (1280 - 96) / 16 + 1 = 1184 / 16 + 1 = 74 + 1 = 75
세로 이동 = ( 720 - 96) / 16 + 1 =  624 / 16 + 1 = 39 + 1 = 40

한 조합당 = 75 × 40 = 3,000

창 크기 4종 × 비율 3종 = 12 조합
총 = 3,000 × 12 = 36,000 회
```

### YOLO 쪽

```
20 × 20 격자 = 400 칸
CNN 통과는 ★ 단 1회

(실제 YOLO11은 80×80, 40×40, 20×20 세 단계 특징맵을 써서
 8,400개 후보를 내지만, 그것도 CNN 1회 안에서 나옵니다)
```

### 비교

```
분류 횟수 기준:  36,000 : 1  →  ★ 36,000배

실제 측정으로는
  슬라이딩 윈도우 (3ms 분류기) = 108 초
  YOLO11n (CPU)              = 0.062 초
                             → 약 1,740배
```

### ★ 이 계산이 과소평가하는 이유

**① 각 창을 잘라내고 리사이즈하는 비용이 빠졌습니다**

```
36,000번의 crop + resize + 정규화
분류 자체보다 이 전처리가 더 오래 걸릴 수 있습니다
```

**② 배치 처리 효율이 반영 안 됐습니다**

```
YOLO는 이미지 1장을 한 번에 처리 → GPU/CPU 캐시 효율 최적
슬라이딩 윈도우는 작은 입력 36,000번 → 오버헤드가 지배적
```

**③ 겹치는 영역의 중복 계산**

```
16픽셀 이동 = 창의 83%가 이전 창과 같은 픽셀
→ 같은 픽셀을 6번 이상 반복 계산
```

**④ 슬라이딩 윈도우는 이후에도 NMS가 필요합니다**

```
36,000개 후보 중 "개"로 나온 것이 수십 개
→ 중복 제거 비용이 추가로 듭니다
```

> **핵심은 배수가 아니라 방향입니다.**
> "특징 추출을 한 번만 하고, 그 결과를 공유한다" — 이 아이디어가 검출을 실용화했습니다.

### ② 최소 FPS

```
요구사항: 사람이 오면 3초 이내 알림

알림 조건 (오탐 방지)
  "3프레임 연속 person 검출" 로 잡는다고 하면

  필요 시간 = 3프레임 / FPS + 알림 전송 시간(≈0.5초) < 3초
           → 3 / FPS < 2.5
           → FPS > 1.2
```

**이론상 2 FPS면 충분합니다.** 그런데 여유를 둡니다.

| 고려 | 여유 |
|---|---|
| 사람이 빠르게 지나갈 수 있음 | ×2 |
| 야간에 검출 실패가 섞임 | ×1.5 |
| 다른 처리(저장·DB·전송) 시간 | ×1.3 |

```
★ 목표: 5 FPS  (최소 3 FPS)
```

**택배 상자는 움직이지 않으므로 1 FPS로 충분합니다.**

> **★ 좋은 설계 — 두 대상에 다른 주기를 씁니다.**
> ```
> 사람  : 매 프레임 검출        (5 FPS)
> 택배  : 10초에 한 번만 검출   (0.1 FPS)
> ```
> [Day 170](day-170.md)에서 이런 이벤트 설계를 다룹니다.

### ③ 오늘 만들 수 있는 프로토타입

**오늘 배운 것만으로 이만큼 됩니다.**

```python
import time
from datetime import datetime
from pathlib import Path

import cv2
from ultralytics import YOLO

SNAP = Path("snapshots")
SNAP.mkdir(exist_ok=True)

model = YOLO("yolo11n.pt")
CONF = 0.35
PERSON = 0
CONSECUTIVE = 3        # 3프레임 연속이면 이벤트
COOLDOWN = 30          # 30초 안에 재알림 안 함

cap = cv2.VideoCapture(0)
streak, last_alert = 0, 0.0

while True:
    ok, frame = cap.read()
    if not ok:
        break

    r = model(frame, conf=CONF, classes=[PERSON], verbose=False)[0]
    found = len(r.boxes) > 0
    streak = streak + 1 if found else 0

    now = time.time()
    if streak >= CONSECUTIVE and now - last_alert > COOLDOWN:
        last_alert = now
        stamp = datetime.now().strftime("%Y%m%d_%H%M%S")
        path = SNAP / f"person_{stamp}.jpg"
        cv2.imwrite(str(path), r.plot())
        print(f"[알림] {stamp}  사람 {len(r.boxes)}명 감지 → {path.name}")
        # TODO: 텔레그램 전송 (Day 170)

    cv2.imshow("cctv", r.plot())
    if cv2.waitKey(1) & 0xFF == ord("q"):
        break

cap.release()
cv2.destroyAllWindows()
```

| 연속 프레임 조건 | `streak >= 3` | [Day 170](day-170.md) |

## 오늘의 정리

| 항목 | 핵심 |
|---|---|
| 검출의 근본 문제 | **출력 개수가 가변** |
| 슬라이딩 윈도우 | 사진 1장에 분류 **36,000번** → 불가능 |
| 해결 아이디어 | **특징 추출을 한 번만** 하고 공유 |
| **2-stage** | 후보 제안 → 분류. 느리지만 정확 (R-CNN 계열) |
| **1-stage** | 격자로 나눠 한 번에 예측. **빠름** (YOLO·SSD) |
| YOLO 한 문장 | **"You Only Look Once"** — 이미지를 한 번만 통과 |
| 그리드 셀 | 객체 **중심이 든 칸**이 그 객체를 책임짐 |
| 앵커 | v5 이하 개념. **YOLO11은 앵커프리** |
| 버전 | 번호가 성능 순 아님. **YOLO11 사용** |
| 모델 크기 | n(2.6M) ~ x(56.9M). **데이터 적으면 작은 게 낫다** |
| 실시간 | 절대 기준 없음. **CCTV는 5~10 FPS면 충분** |
| Ultralytics | 설치 1줄, 추론 3줄. **라이선스 AGPL-3.0 주의** |
| `results` | **리스트.** `[0]` 으로 꺼냄 |
| `boxes.xyxy` | VOC · `xywhn` = YOLO · **`xywh` ≠ COCO** |
| 의사 라벨 | 사전학습 예측을 **라벨링 초안**으로 활용 |
| 속도 측정 | **워밍업 1회 필수** |
| 긴 영상 | **`stream=True`** 로 제너레이터 |

**오늘 반드시 기억할 세 가지**
> ① **YOLO가 빠른 이유는 CNN을 한 번만 돌리기 때문입니다.** 후보를 뽑는 단계가 없습니다.
> ② **큰 모델이 항상 좋은 게 아닙니다.** 데이터 500장에 yolo11x는 과적합만 늘립니다.
> ③ **"COCO에 있는가"를 먼저 확인하세요.** 있으면 라벨링 없이 오늘 당장 씁니다.

**오늘의 산출물**

**과제 — 사전학습 모델로 검출 결과 10장 만들기**

```
1. 이미지 10장을 준비합니다. 아래를 반드시 포함하세요.
     · 사람이 여러 명 (5명 이상)      2장
     · 차량이 있는 실외              2장
     · ★ 야간 또는 저조도            2장
     · ★ 검출 대상이 없는 사진        1장
     · 우리 팀 프로젝트 후보 장면      3장

2. 각 사진에 대해 기록합니다.
     · 검출된 객체 수와 클래스별 개수
     · 가장 낮은 conf 와 가장 높은 conf
     · ★ 사람 눈으로 봤을 때 놓친 것(FN)이 몇 개인가
     · ★ 잘못 잡은 것(FP)이 몇 개인가

3. conf 를 0.25 / 0.5 / 0.75 로 바꿔 각각 다시 돌리고
   검출 개수가 어떻게 변하는지 표로 정리합니다.
```
