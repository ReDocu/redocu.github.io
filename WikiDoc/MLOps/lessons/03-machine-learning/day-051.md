그러자 이런 질문이 돌아왔습니다.

> "그래서, **내일은 나쁜가요?**"

SQL은 이 질문에 답하지 못합니다. `WHERE date = '내일'` 인 행은 DB에 없기 때문입니다.
**과거를 설명하는 것**(분석)과 **미래를 맞히는 것**(예측)은 다른 기술입니다. 오늘부터 5주간 후자를 배웁니다.

### 규칙으로 만들어 보면 안 되나?

만들어 봅시다. MP1 분석에서 "바람이 약하면 나쁘더라"를 알아냈으니까요.

```
규칙 v1: 오늘 pm25 > 35 이면          → 내일도 나쁨
  ...오늘 나빠도 비 오면 내일 깨끗하던데?
규칙 v2: + 오늘 비가 왔으면           → 내일 좋음
  ...비가 왔어도 바람이 없으면 그대로던데?
규칙 v3: + 풍속 < 2.0 이면            → 내일도 나쁨
  ...겨울이랑 여름이 다르던데?
규칙 v4: + 월이 11~3월이면 기준 완화  → ???
  ...강남구랑 노원구가 다르게 움직이던데?
규칙 v5: + 측정소별 보정치            → ?????
```

규칙이 5개를 넘어가면서 **서로 충돌하기 시작**합니다. 예외의 예외를 적다 보면 아무도 못 읽는
if 문 더미가 되고, 새 데이터가 들어오면 처음부터 다시 손봐야 합니다.

**머신러닝은 이 방향을 뒤집습니다.** 사람이 규칙을 쓰는 대신, **데이터에서 규칙을 찾아내게** 합니다.

| | 규칙 기반 | 학습 기반 (ML) |
|---|---|---|
| 규칙을 만드는 주체 | 사람이 직접 작성 | **데이터에서 자동으로 추출** |
| 잘 맞는 문제 | 규칙이 명확·소수 (세금 계산, 검증 규칙) | 규칙이 복잡·암묵적 (예측, 인식, 추천) |
| 데이터가 바뀌면 | 코드를 고쳐야 함 | **다시 학습시키면 됨** |
| 근거 설명 | 쉬움 (if 문을 보면 됨) | 어려울 수 있음 (Day 064에서 다룸) |
| 유지 비용 | 규칙 수에 비례해 폭증 | 데이터·재학습 파이프라인 관리 |

> **규칙 기반이 열등한 것이 아닙니다.** [Day 044](../02-sql-pipeline/day-044.md)의 검증 규칙(범위·형식 체크)은
> 규칙 기반이 정답입니다. **규칙을 사람이 다 적을 수 없을 때** 머신러닝을 씁니다.

### MLOps 엔지니어에게 이 단원이 필요한 이유

여러분의 최종 목표는 모델을 **서빙하고 운영하는 것**(대단원 04·05)입니다. 그런데 모델이
어떻게 만들어지고 무엇이 잘못될 수 있는지 모르면, 운영 중인 모델이 이상해졌을 때
**무엇을 감시해야 하는지조차 알 수 없습니다.** 이 단원에서 겪을 누수·과적합·불균형이
그대로 대단원 05의 모니터링 항목이 됩니다.

## ③ 개념 설명

### 머신러닝의 세 종류

| 종류 | 데이터에 정답이 | 하는 일 | 예 |
|---|---|---|---|
| **지도학습** (supervised) | **있음** | 입력 → 정답 대응 관계를 학습 | 내일 pm25 예측, 스팸 분류 |
| 비지도학습 (unsupervised) | 없음 | 데이터 안의 구조를 발견 | 고객 군집화, 이상 탐지 |
| 강화학습 (reinforcement) | 보상만 있음 | 시행착오로 행동 전략을 학습 | 게임, 로봇 제어 |

이 단원은 **지도학습**만 다룹니다. 실무 테이블 데이터 문제의 대부분이 지도학습이기 때문입니다.

### 지도학습의 두 얼굴 — 회귀와 분류

정답(출력)의 형태가 무엇이냐로 갈립니다.

| | 회귀 (regression) | 분류 (classification) |
|---|---|---|
| 출력 | **연속된 숫자** | **범주(클래스)** |
| 예 | 내일 pm25는 **41.2** | 내일은 **나쁨/좋음** |
| 주간 | **W11 (이번 주)** | W12 (다음 주) |
| 대표 지표 | MAE · RMSE · R² ([Day 054](day-054.md)) | 정밀도 · 재현율 · F1 ([Day 057](day-057.md)) |

같은 현상도 문제를 어떻게 정의하느냐에 따라 둘 다 될 수 있습니다.
"내일 pm25 값"을 맞히면 회귀, "내일 나쁨 여부"를 맞히면 분류입니다.

### 문제 정의의 3요소 — 입력 · 출력 · 지표

**ML 프로젝트는 코드가 아니라 문제 정의에서 시작합니다.** 다음 3개가 문장으로 적히기 전에는
`import sklearn` 을 하지 마세요.

| 요소 | 질문 | 우리 문제의 답 |
|---|---|---|
| **입력 X** | 예측 시점에 **알 수 있는** 정보는? | 오늘의 측정값 (pm10, pm25, 풍속, 습도, 강수 …) |
| **출력 y** | 무엇을 맞히면 문제가 풀리나? | **내일의 pm25** (측정소별) |
| **지표** | 얼마나 잘 맞혀야 쓸모 있나? | 오차(MAE) — 단위가 ㎍/㎥ 그대로라 설명하기 쉬움 |

> **"예측 시점에 알 수 있는"** — 이 한 구절이 이 단원에서 가장 중요한 문장입니다.
> 내일의 풍속을 입력에 넣으면 점수는 오르지만, 내일이 되기 전엔 그 값을 모르므로
> 실제로는 쓸 수 없는 모델이 됩니다. 이 함정(누수)은 [Day 052](day-052.md)에서 파고듭니다.

### 우리의 예제 문제 — "내일 초미세먼지 예보"

이 단원의 25일 전체가 **하나의 문제**를 풉니다.

```
MP1에서 만든 것                          이 단원에서 만들 것
─────────────────────                   ─────────────────────────
서울 대기질 DB                           내일 pm25 예측 모델
(measurement, 시간별)          ───▶     (오늘 관측 → 내일 농도)
"어제까지 어땠는가"                      "내일은 어떨 것인가"
```

학습 데이터는 MP1의 DB에서 **일 평균으로 집계**해 꺼냅니다. 타깃(내일 값)을 만드는 것은
[Day 037](../02-sql-pipeline/day-037.md)에서 배운 윈도우 함수 `LEAD` 그 자체입니다.

```sql
WITH daily AS (
    SELECT s.name AS station, m.measured_at::date AS date,
           ROUND(AVG(m.pm25)::numeric, 1) AS pm25, ...
    FROM measurement m JOIN station s USING (station_id)
    GROUP BY s.name, m.measured_at::date
)
SELECT *, LEAD(pm25) OVER (PARTITION BY station ORDER BY date) AS pm25_next
FROM daily ORDER BY station, date;
```

| 컬럼 | 뜻 | 비고 |
|---|---|---|
| `date`, `station` | 날짜 · 측정소(5곳) | 식별자 — 모델 입력이 아님 |
| `pm10`, `pm25` | 미세 · 초미세먼지 (㎍/㎥) | |
| `o3`, `no2`, `co`, `so2` | 오존 · 이산화질소 · 일산화탄소 · 아황산가스 (ppm) | |
| `temp`, `humidity` | 기온(℃) · 습도(%) | |
| `wind_speed`, `precip` | 풍속(m/s) · 강수량(mm) | |
| **`pm25_next`** | **내일의 pm25 = 타깃 y** | `LEAD` 로 생성 |

### 모델 · 학습 · 예측 — 용어 정리

| 용어 | 뜻 | scikit-learn에서 |
|---|---|---|
| 모델 (model) | 입력→출력 대응 규칙의 담는 그릇 | `KNeighborsRegressor()` 같은 객체 |
| 학습 (fit/train) | 데이터를 보고 그 규칙을 채우는 과정 | `model.fit(X, y)` |
| 예측 (predict) | 새 입력에 대해 규칙을 적용 | `model.predict(X_new)` |
| 특성 (feature) | 입력 X의 각 컬럼 | `X` 의 열 |
| 타깃/레이블 (target) | 맞혀야 할 정답 y | `y` |

**scikit-learn의 위대함은 인터페이스 통일에 있습니다.** 어떤 모델이든:

```python
model = 모델이름(옵션)     # ① 만들고
model.fit(X, y)            # ② 학습시키고
model.predict(X_new)       # ③ 예측한다
```

이 세 줄이 전부입니다. 모델을 바꿔도 이 세 줄은 그대로입니다 — 오늘 실습 Step 5에서 직접 확인합니다.

### Step 2. 공통 데이터셋 만들기 (2교시)

`make_dataset.py` 를 만듭니다. **이 스크립트의 내용은 오늘 이해하지 않아도 됩니다.**
실제 수업이라면 각자 MP1 DB에서 추출하겠지만, 사람마다 수집 기간·측정소가 달라 숫자가
제각각이 되므로, 이 단원에서는 모두가 같은 숫자를 보도록 **시드 고정 생성기**를 씁니다.

재미있는 점: 이 스크립트 안의 수식이 곧 **이 데이터의 "정답 구조"** 입니다.
단원 내내 우리는 모델이 이 구조를 얼마나 스스로 알아내는지 보게 됩니다.

```python
# make_dataset.py — 대단원 03 공통 데이터셋 생성기
#
# 실제 수업이라면 MP1에서 구축한 DB에서 이렇게 추출합니다 (Day 033 집계 + Day 037 LEAD):
#
#   WITH daily AS (
#       SELECT s.name AS station, m.measured_at::date AS date,
#              ROUND(AVG(m.pm10)::numeric, 1) AS pm10, ROUND(AVG(m.pm25)::numeric, 1) AS pm25, ...
#       FROM measurement m JOIN station s USING (station_id)
#       GROUP BY s.name, m.measured_at::date)
#   SELECT *, LEAD(pm25) OVER (PARTITION BY station ORDER BY date) AS pm25_next
#   FROM daily ORDER BY station, date;
#
# 다만 사람마다 수집 기간·측정소가 달라 숫자가 제각각이 되므로,
# 이 단원에서는 모두가 같은 숫자를 보도록 시드 고정 생성기를 씁니다.
# ★ 이 스크립트의 내용은 지금 이해하지 않아도 됩니다. 실행만 하세요.
#    (안의 수식이 곧 "정답의 구조"인데, 단원 내내 모델이 이걸 얼마나 알아내는지 보게 됩니다.)
import numpy as np
import pandas as pd

rng = np.random.default_rng(42)

STATIONS = {
    # 이름: (pm10 오프셋, pm25 오프셋, 에피소드 민감도)
    "강남구": (+4.0, +1.8, 1.10),
    "노원구": (-3.5, -1.5, 0.90),
    "마포구": (+1.0, +0.5, 1.00),
    "서초구": (+2.0, +0.8, 1.05),
    "종로구": (-1.0, -0.3, 0.95),
}

dates = pd.date_range("2024-07-01", "2026-06-30", freq="D")
n = len(dates)
doy = dates.dayofyear.to_numpy()
season = np.cos(2 * np.pi * (doy - 15) / 365.25)      # 겨울 +1 · 여름 -1

def ar1(phi, sigma):
    x = np.zeros(n)
    e = rng.normal(0, sigma, n)
    for t in range(1, n):
        x[t] = phi * x[t - 1] + e[t]
    return x

# ── 날씨 (서울 일 평균 수준 — 날씨는 하루 단위로 이어진다) ──
temp = 13.0 - 11.5 * season + ar1(0.70, 1.8) + rng.normal(0, 0.8, n)
rain = rng.random(n) < np.where(season < -0.3, 0.42, 0.22)
precip = np.where(rain, np.round(rng.gamma(1.6, 7.0, n), 1), 0.0)
wind = np.round(np.clip(2.3 + 0.9 * ar1(0.72, 0.85), 0.4, 8.0), 1)
humidity = np.clip(58 - 9 * season + 8 * rain + 6 * ar1(0.65, 0.9), 20, 98)

# ── 지역 공통 요인: 대기 정체(AR) + 겨울·봄 고농도 에피소드(황사·장거리 이동) ──
# 고농도 정체 국면은 오래가고, 깨끗한 날은 빨리 평소로 돌아온다
f = np.zeros(n)
fe = rng.normal(0, 4.5, n)
for t in range(1, n):
    phi = 0.88 if f[t - 1] > 4 else (0.58 if f[t - 1] < -2 else 0.74)
    f[t] = phi * f[t - 1] + fe[t]

ep = np.zeros(n)
active, mag = False, 0.0
for t in range(n):
    if not active and season[t] > -0.2 and rng.random() < 0.070:
        active, mag = True, rng.gamma(2.2, 13.0)      # 에피소드 시작
    elif active:
        cont = 0.85 if wind[t] < 2.2 else 0.30        # 바람이 약하면 잘 안 끝난다
        if rng.random() > cont:
            active = False
    level = mag * (0.90 + 0.2 * rng.random()) if active else 0.0
    yf = {2024: 1.00, 2025: 1.20, 2026: 0.85}[dates[t].year]    # 연도별 황사 편차
    ep[t] = 0.5 * ep[t - 1] + 0.5 * level * yf if t > 0 else level * yf

rows = []
for name, (off10, off25, sens) in STATIONS.items():
    raw10 = 34.5 + off10 + 8.5 * season + 1.7 * f + sens * ep
    vent = np.clip(1.0 - 0.055 * (wind - 2.3), 0.60, 1.15)     # 바람 환기(곱셈)
    wash = 1.0 - 0.38 * (1.0 - np.exp(-np.maximum(precip - 0.5, 0) / 8.0))   # 강수 세정
    pm10 = raw10 * vent * wash + rng.normal(0, 3.2, n)
    pm10 = np.clip(pm10, 4, None)
    stagnant = ((wind < 1.8) & (humidity > 72)).astype(float)  # 정체 조건(비선형)
    pm25 = (4.0 + off25 + 0.50 * pm10 + 0.05 * humidity - 0.6 * wind
            + 6.0 * stagnant + rng.normal(0, 1.7, n))
    pm25 = np.clip(pm25, 3, None)
    o3 = np.clip(0.012 + 0.014 * (temp / 25) + 0.004 * wind + rng.normal(0, 0.006, n), 0.002, 0.12)
    no2 = np.clip(0.016 + 0.0005 * pm10 + 0.004 * (off10 > 1.5) - 0.0018 * wind
                  + rng.normal(0, 0.004, n), 0.003, 0.09)
    co = np.clip(0.35 + 0.007 * pm25 + rng.normal(0, 0.06, n), 0.1, 1.8)
    so2 = np.clip(0.0035 + 0.00004 * pm10 + rng.normal(0, 0.0009, n), 0.001, 0.012)
    rows.append(pd.DataFrame({
        "date": dates, "station": name,
        "pm10": np.round(pm10, 1), "pm25": np.round(pm25, 1),
        "o3": np.round(o3, 4), "no2": np.round(no2, 4),
        "co": np.round(co, 2), "so2": np.round(so2, 4),
        "temp": np.round(temp + rng.normal(0, 0.4, n), 1),
        "humidity": np.round(humidity + rng.normal(0, 1.5, n), 0),
        "wind_speed": wind, "precip": precip,
    }))

df = pd.concat(rows, ignore_index=True).sort_values(["station", "date"])

# ── 결측 주입 (장비 점검·통신 두절 — MP1에서 겪은 그대로) ──
def poke(col, frac):
    idx = rng.choice(df.index, size=int(len(df) * frac), replace=False)
    df.loc[idx, col] = np.nan

poke("pm10", 0.012)
poke("humidity", 0.008)
poke("o3", 0.020)
mask = (df["station"] == "서초구") & df["date"].between("2025-11-03", "2025-11-05")
df.loc[mask, ["pm10", "pm25", "o3", "no2", "co", "so2"]] = np.nan   # 서초구 점검 3일

# ── 타깃: 다음날 pm25 (SQL의 LEAD와 동일) ──
df["pm25_next"] = df.groupby("station")["pm25"].shift(-1)
df = df[df["pm25_next"].notna()].reset_index(drop=True)   # 마지막 날·점검 직전일 제거

import os
os.makedirs("data", exist_ok=True)
df.to_csv("data/air_daily.csv", index=False)
print(f"저장: data/air_daily.csv  ({df.shape[0]}행 × {df.shape[1]}열)")
print(f"기간: {df['date'].min().date()} ~ {df['date'].max().date()} · 측정소 {df['station'].nunique()}곳")
print()
print(df.head(3).to_string(index=False))
```

### Step 4. 첫 모델 — 규칙 없이 예측하기 (5~6교시)

`first_model.py` 를 만듭니다. 모델은 **k-최근접 이웃(KNN)**: "예측하고 싶은 날과
**가장 비슷한 과거의 날 5일**을 찾아, 그 날들의 '다음 날 pm25' 평균을 답으로 낸다"는,
머신러닝 중 가장 정직한 알고리즘입니다. ②에서 손으로 짜다 실패한 규칙들이
"비슷한 날 찾기" 하나로 대체됩니다.

```python
# first_model.py — Day 051 Step 4: 첫 모델. 규칙을 쓰지 않고 "비슷한 날"을 찾게 한다
import pandas as pd
from sklearn.neighbors import KNeighborsRegressor

df = pd.read_csv("data/air_daily.csv", parse_dates=["date"])

# 오늘 관측한 값(입력 X) → 내일 pm25(출력 y)
FEATURES = ["pm10", "pm25", "wind_speed", "humidity", "precip"]
d = df.dropna(subset=FEATURES)           # 결측 행은 일단 버린다 (제대로 된 처리는 Day 063)
X = d[FEATURES]
y = d["pm25_next"]
print(f"학습에 쓰는 데이터: {len(d):,}행")

# ① 모델을 만들고 → ② 데이터를 보여주고(fit) → ③ 물어본다(predict)
model = KNeighborsRegressor(n_neighbors=5)   # "가장 비슷한 날 5일을 찾아 그 다음날들의 평균"
model.fit(X, y)

# 2024-11-08 종로구: pm25 63.8, 이 데이터에서 손꼽히는 고농도 날. 규칙 없이 내일을 물어보면?
today = d[(d["station"] == "종로구") & (d["date"] == "2024-11-08")]
print()
print("오늘의 관측값:")
print(today[["date", "station"] + FEATURES + ["pm25_next"]].to_string(index=False))

pred = model.predict(today[FEATURES])
print(f"\n모델의 예측(내일 pm25): {pred[0]:.1f}")
print(f"실제 내일 pm25       : {today['pm25_next'].iloc[0]:.1f}")

# 규칙을 하나도 쓰지 않았다. 룰북 대신 "과거의 비슷한 날 5일"이 답을 만들었다.
score = model.score(X, y)                # R² (1에 가까울수록 좋음 — 자세한 뜻은 Day 054)
print(f"\n전체 데이터에 대한 점수 R²: {score:.3f}")
print("…그럴듯해 보이지만, 이 점수에는 심각한 함정이 있습니다. 내일(Day 052) 확인합니다.")
```
