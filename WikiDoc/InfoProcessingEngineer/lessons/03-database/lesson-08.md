## ② 왜 필요한가

**"과목별 평균", "학년별 인원수" — 시험의 SQL 작성형이 가장 좋아하는 문장 구조입니다.** "~별"이라는 두 글자가 보이면 GROUP BY이고, 묶은 결과에 다시 조건("평균이 85 이상인 과목만")이 붙으면 HAVING입니다. 이 두 키워드를 빈칸으로 뚫는 문제가 반복 출제됩니다(기출 복원 기반 비공식 경향).

여기에 시험이 심는 함정이 **NULL**입니다. 07강 스키마의 최민수(성적 NULL)가 있는 상태에서 `AVG(성적)`은 얼마인가 — NULL을 0으로 치고 나누면 틀리고, 아예 빼고 나누면 맞습니다. 집계 함수의 NULL 규칙을 모르면 계산을 다 하고도 분모에서 틀립니다.

**시험에서의 중요도와 출제 형태** — SQL 작성형(GROUP BY·HAVING 질의 쓰기), 결과 예측형(집계 결과 값 쓰기), 빈칸형(HAVING 채우기). 그리고 오늘 후반부의 **중간평가**는 배점 절반 이상을 차지하는 코드 영역 전체 + SQL 기초의 첫 실전 점검입니다.

## ③ 개념 설명

### 3-1. 집계 함수 5종 — 여러 행을 하나의 값으로

**집계 함수(aggregate function)** 는 여러 행을 받아 **하나의 값**으로 요약합니다.

| 함수 | 뜻 | ENROLL.성적 기준 결과 |
|---|---|---|
| `COUNT(*)` | **행의 개수** (NULL 포함) | 6 |
| `COUNT(성적)` | 그 열이 **NULL이 아닌** 행의 개수 | 5 |
| `SUM(성적)` | 합계 (NULL 제외) | 420 |
| `AVG(성적)` | 평균 (NULL 제외) | 84 |
| `MAX(성적)` / `MIN(성적)` | 최대 / 최소 (NULL 제외) | 95 / 70 |

📌 **반드시 암기 — NULL 규칙**: 집계 함수는 NULL을 **계산에서 제외**합니다. 단 하나의 예외가 `COUNT(*)` — 행 자체를 세므로 NULL이 있어도 셉니다. 그래서 `AVG(성적)`은 420÷**5**=84이지, 420÷6=70이 아닙니다. "AVG의 분모는 COUNT(열)"로 기억하세요.

### 3-2. GROUP BY — "~별"을 만드는 키워드

GROUP BY는 지정한 열의 **값이 같은 행끼리 묶고, 그룹마다 한 행**을 출력합니다.

```
ENROLL을 과목코드로 묶으면:
C1 그룹 { (1001,90) (1002,70) (1003,95) }  → 한 행으로 요약
C2 그룹 { (1001,85) }                      → 한 행으로 요약
C3 그룹 { (1003,80) (1004,NULL) }          → 한 행으로 요약
```

📌 **반드시 암기 — SELECT 절 규칙**: GROUP BY를 쓰면 SELECT 절에는 **①그룹화 기준 열 ②집계 함수** 두 종류만 올 수 있습니다. `SELECT 이름, COUNT(*) ... GROUP BY 학년`처럼 기준이 아닌 일반 열을 섞으면 표준 SQL에서는 에러입니다. ⚖️ SQLite·MySQL 일부 설정은 이를 허용하고 임의 값을 돌려주지만(**DBMS 차이**), 시험 답안은 표준 규칙을 따릅니다.

### 3-3. WHERE vs HAVING — 거르는 시점이 다르다

⚖️ **혼동 비교 (최빈출)**

| 구분 | WHERE | HAVING |
|---|---|---|
| 거르는 대상 | 개별 **행** | 묶인 **그룹** |
| 실행 시점 | 그룹화 **전** | 그룹화 **후** |
| 집계 함수 사용 | **불가** | **가능** (오히려 주 용도) |
| 예 | `WHERE 성적 >= 80` (행 필터) | `HAVING AVG(성적) >= 85` (그룹 필터) |

📌 **반드시 암기 — 논리적 실행 순서** (단답·순서 나열 출제)

```
FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY
(편다) (행 거름) (묶는다)  (그룹 거름) (고른다)  (정렬)
```

"WHERE에는 집계 함수를 못 쓴다"는 이 순서의 결과입니다 — WHERE가 실행되는 시점에는 아직 그룹이 없어 평균을 낼 수 없기 때문입니다.

### 3-4. 별칭(alias) — AS

```sql
SELECT 과목코드, AVG(성적) AS 평균
FROM ENROLL GROUP BY 과목코드;
```

결과 열의 머리글이 `AVG(성적)` 대신 `평균`이 됩니다. `AS`는 생략 가능(`AVG(성적) 평균`)하지만, [02강 ⑥ 3번](../01-foundation/lesson-02.md)에서 본 "쉼표 누락이 별칭으로 해석되는" 함정의 원인이기도 합니다. ⚖️ 테이블 별칭(`FROM ENROLL E`)은 9강 JOIN에서 본격 사용합니다.

### Step 2. COUNT의 두 얼굴과 AVG의 분모

**사용 테이블: ENROLL · 난이도: 🟡 기본 · 학습 개념: COUNT(*) vs COUNT(열), NULL 제외**

```sql
SELECT COUNT(*), COUNT(성적), SUM(성적), AVG(성적)
FROM   ENROLL;
```

**예상 결과**

| COUNT(*) | COUNT(성적) | SUM(성적) | AVG(성적) |
|---|---|---|---|
| 6 | 5 | 420 | 84 |

실행 원리: ENROLL은 6행이지만 최민수의 성적이 NULL → `COUNT(*)`는 행을 세서 6, `COUNT(성적)`은 NULL을 빼고 5. SUM은 90+85+70+95+80=420, AVG는 420÷5=**84**. (⚖️ SQLite 화면에는 `84.0`처럼 소수점으로 표시됩니다 — 표시 형식은 DBMS 차이이며, 답안은 값이 맞으면 84·84.0 모두 인정)

- **대표 오답**: AVG를 70(=420÷6)으로 계산 — NULL을 분모에 넣은 경우. "집계는 NULL을 없는 셈 친다, COUNT(*)만 예외"를 다시 확인하세요.

### Step 3. GROUP BY — 과목별 요약표 만들기

**사용 테이블: ENROLL · 난이도: 🟡 기본 · 학습 개념: 그룹당 한 행, 그룹 안의 NULL**

> 문제: 과목별 수강 인원과 평균 성적을 조회하시오.

```sql
SELECT 과목코드, COUNT(*) AS 인원, AVG(성적) AS 평균
FROM   ENROLL
GROUP BY 과목코드;
```

**예상 결과**

| 과목코드 | 인원 | 평균 |
|---|---|---|
| C1 | 3 | 85 |
| C2 | 1 | 85 |
| C3 | 2 | 80 |

실행 원리: 3-2절의 묶음 그림대로 그룹당 한 행. C1 평균 = (90+70+95)÷3 = 85. **C3이 핵심 함정** — 인원(COUNT(*))은 2인데 평균은 80÷**1**=80. 한 그룹 안에서도 COUNT(*)와 AVG의 분모가 다를 수 있습니다. 수강생이 없는 C4는 ENROLL에 행이 없으므로 **그룹 자체가 없습니다**(0으로 나오지 않음 — 9강 OUTER JOIN에서 해결).

### Step 4. HAVING — 그룹에 조건 걸기

**사용 테이블: ENROLL · 난이도: 🟡 기본 · 학습 개념: HAVING, WHERE와의 역할 분담**

> 문제: 평균 성적이 85 이상인 과목의 과목코드와 평균을 조회하시오.

```sql
SELECT 과목코드, AVG(성적) AS 평균
FROM   ENROLL
GROUP BY 과목코드
HAVING AVG(성적) >= 85;
```

**예상 결과**

| 과목코드 | 평균 |
|---|---|
| C1 | 85 |
| C2 | 85 |

실행 원리: FROM → (WHERE 없음) → GROUP BY로 3그룹 → **HAVING이 그룹을 심사**해 평균 80인 C3 탈락 → SELECT.

- **대표 오답 쿼리**: `... WHERE AVG(성적) >= 85 GROUP BY 과목코드;` → `misuse of aggregate: AVG()` 에러. WHERE 시점에는 그룹이 없어 평균이 존재하지 않습니다(3-3절 실행 순서).
- 구분 연습: "**성적이 85 이상인 행만으로** 과목별 평균"이라면 `WHERE 성적 >= 85 ... GROUP BY ...` — 행 조건은 WHERE, 그룹 조건은 HAVING. 지문의 조건이 **행에 붙는지 그룹에 붙는지**를 먼저 판정하는 것이 실전 요령입니다.

## ⑤ 자주 하는 실수

| 에러/증상 원문 | 원인 | 해결 |
|---|---|---|
| `Parse error: misuse of aggregate: AVG()` | WHERE 절에 집계 함수 (`WHERE AVG(성적) >= 85`) | 그룹 조건은 **HAVING** — 실행 순서상 WHERE 시점엔 그룹이 없음 |
| AVG 결과가 예상보다 큼 | NULL을 분모에 넣어 암산 (420÷6=70을 기대) | 집계는 NULL 제외 — AVG의 분모는 COUNT(열)=5 |
| `COUNT(*)`와 `COUNT(성적)`이 다른 값 | 오류가 아니라 정상 — NULL 포함 여부 차이 | 문제로 나오면 "성적에 NULL이 있다"는 신호로 읽을 것 |
| 표준 SQL 에러: GROUP BY에 없는 일반 열을 SELECT | `SELECT 이름, COUNT(*) ... GROUP BY 학년` | SELECT에는 기준 열 + 집계 함수만 ⚖️ (SQLite는 조용히 임의 값 반환 — DBMS 차이로 오히려 위험) |
| HAVING만 있고 GROUP BY가 없어 혼란 | 전체를 한 그룹으로 취급(문법상 가능)하나 시험 답안으론 비권장 | GROUP BY와 짝으로 쓰는 형태로 답안 작성 |
| `Parse error: near "GROUP": syntax error` | 절 순서 바꿔 씀 (`GROUP BY`를 WHERE 앞에) | 작성 순서 고정: SELECT–FROM–WHERE–GROUP BY–HAVING–ORDER BY |
| 별칭에 예약어·공백 사용 | `AS 평균 성적` (공백 포함) | 한 단어로 쓰거나 큰따옴표 `"평균 성적"` — 답안에서는 한 단어 권장 |

## ⑥ 확인 문제

1. [결과 예측] `SELECT COUNT(*), COUNT(성적) FROM ENROLL WHERE 과목코드 = 'C3';` 의 결과를 쓰시오.
2. [빈칸] 수강 인원이 2명 이상인 과목코드를 조회한다. 빈칸 두 개를 채우시오.
   ```sql
   SELECT 과목코드
   FROM   ENROLL
   _____ 과목코드
   _____ COUNT(*) >= 2;
   ```
3. [오류 찾기 + 작성] "성적이 80 이상인 수강 기록만으로 과목별 평균을 구하되, 그 평균이 90 이상인 과목만" 조회하려 한다. 행 조건과 그룹 조건을 올바른 절에 배치한 SQL을 쓰시오.

<details>
<summary>정답과 해설</summary>

1. **`2 | 1`** — C3 그룹은 (1003, 80)과 (1004, NULL)의 2행. COUNT(*)=2, COUNT(성적)은 NULL 제외 1.
   - 대표 오답: `2 | 2` — WHERE로 행을 걸렀어도 NULL 제외 규칙은 그대로 적용됩니다.
2. **`GROUP BY`, `HAVING`** — "~별"(과목별 묶음) + "묶음에 대한 조건"(인원 2 이상). 결과: C1(3명), C3(2명).
3. 정답 쿼리:
   ```sql
   SELECT 과목코드, AVG(성적) AS 평균
   FROM   ENROLL
   WHERE  성적 >= 80
   GROUP BY 과목코드
   HAVING AVG(성적) >= 90;
   ```
   "성적 80 이상"은 개별 **행** 조건 → WHERE. "평균 90 이상"은 **그룹** 조건 → HAVING. (이 데이터에서는 C1이 (90+95)÷2=92.5로 유일하게 통과)
   - 대표 오답: 두 조건을 모두 HAVING에 넣기 — 결과가 달라집니다. WHERE로 70을 먼저 빼고 평균을 내는 것과, 70을 포함해 평균 낸 뒤 그룹을 거르는 것은 **다른 계산**입니다.

</details>

## 마무리

**오늘의 요약** — 집계 함수는 NULL을 제외하며 유일한 예외가 COUNT(*)입니다(그래서 AVG(성적)=420÷5=84). "~별"은 GROUP BY, 그룹 조건은 HAVING, 행 조건은 WHERE이고, 근거는 실행 순서 FROM→WHERE→GROUP BY→HAVING→SELECT→ORDER BY입니다. 중간평가로 전반부(코드 전체 + SQL 기초)의 현재 위치가 확인되었습니다 — 점수보다 **어느 영역에서 잃었는지**가 5주차 계획의 재료입니다.

**복습 체크리스트**

- [ ] 집계 함수 표(3-1)를 예제 값까지 안 보고 재현할 수 있다
- [ ] Step 3의 과목별 요약표에서 C3 평균이 80인 이유를 설명할 수 있다
- [ ] WHERE와 HAVING의 차이를 실행 순서로 설명할 수 있다
- [ ] 실행 순서 6단계를 안 보고 나열할 수 있다
- [ ] 중간평가 오답을 전부 오답노트에 기록했다

**과제 — 4주차 형성평가 (10문항, 09강 첫 복습 퀴즈와 연동)**

1. `SELECT SUM(성적) FROM ENROLL;` 의 결과값은?
2. `SELECT MAX(성적), MIN(성적) FROM ENROLL;` 의 결과는?
3. `SELECT AVG(성적) FROM ENROLL;` 이 84가 되는 계산 과정을 쓰시오. (분모 명시)
4. `SELECT COUNT(*) FROM ENROLL WHERE 과목코드 = 'C1';` 의 결과값은?
5. `SELECT 학년, COUNT(*) FROM STUDENT GROUP BY 학년;` 의 결과 행 수는?
6. WHERE와 HAVING의 차이를 한 문장으로 쓰시오.
7. SELECT 문의 논리적 실행 순서 6단계를 나열하시오.
8. C: `printf("%d", 6 & 3);` 의 출력은? (03강 누적)
9. Python: `print("ABCDEF"[::2])` 의 출력은? (06강 누적)
10. Java: 예외 발생 여부와 무관하게 항상 실행되는 블록은? (06강 누적)

<details>
<summary>형성평가 정답</summary>

| 번호 | 정답 | 측정 개념 |

| 1 | `420` | SUM (NULL 제외) |
