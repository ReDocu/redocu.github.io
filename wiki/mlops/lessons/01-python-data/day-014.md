## ② 왜 필요한가

**이 세 가지는 이 과정 모든 제출물의 필수 요건입니다.**

| 제출 요건 | 오늘 배우는 것 |
|---|---|
| "테스트 코드 (`pytest`, 핵심 로직 + API 통합 테스트)" | pytest |
| "실패해도 죽지 않고 기록을 남긴다" | logging |
| "다른 사람이 읽고 쓸 수 있는 코드" | 타입 힌트 |

그리고 각각의 실질적 이유가 있습니다.

**타입 힌트** — 어제 만든 `storage.load()` 는 무엇을 돌려주나요?

```python
def load(path=DEFAULT_PATH):
    ...
    return todos, warning
```

코드를 다 읽어야 압니다. 타입 힌트가 있으면 한 줄로 압니다.

```python
def load(path: Path | str = DEFAULT_PATH) -> tuple[list[Todo], str | None]:
```

**로깅** — `print` 는 터미널을 닫으면 사라집니다.
W23에서 서버에 배포하면 터미널이 없습니다. W25에서 컨테이너로 돌리면 더더욱 없습니다.
**"어제 새벽 3시에 왜 실패했는가"** 에 답하려면 로그가 남아 있어야 합니다.

**테스트** — 지금은 `todo.py` 를 고치고 직접 실행해 눈으로 확인합니다.
파일이 20개가 되면 무엇이 깨졌는지 알 수 없습니다.

| 테스트가 없으면 | 시점 |
|---|---|
| 전처리를 고쳤더니 수집이 깨진 걸 3일 뒤에 발견 | W06 |
| 서빙 전처리가 학습과 달라진 걸 배포 후 발견 | W20 |
| PR을 머지했더니 운영이 멈춤 | W26 |

W26의 CI(GitHub Actions)는 **여러분이 작성한 pytest를 자동으로 돌립니다.**
테스트가 없으면 CI는 아무것도 지켜 주지 못합니다.

## ③ 개념 설명

### 타입 힌트 기본

```python
def add(a: int, b: int) -> int:
    return a + b

name: str = "홍길동"
scores: list[int] = [88, 92]
```

| 위치 | 문법 |
|---|---|
| 매개변수 | `a: int` |
| 반환값 | `-> int` |
| 변수 | `name: str = "홍길동"` |

**파이썬은 타입 힌트를 강제하지 않습니다.**

```python
add("a", "b")      # 실행됩니다. 결과는 "ab"
```

**그럼 왜 쓰나요?**

| 이유 | 설명 |
|---|---|
| **VS Code 자동완성** | `todo.` 를 치면 메서드 목록이 뜸 |
| **실행 전 오류 발견** | Pylance가 빨간 줄로 표시 |
| **문서 역할** | 주석보다 정확하고 안 낡음 |
| **리팩터링 안전** | 타입이 바뀌면 영향 범위를 알려 줌 |

### 자주 쓰는 타입

| 타입 | 표기 | 예 |
|---|---|---|
| 기본 | `int` `float` `str` `bool` | `age: int` |
| 리스트 | `list[str]` | `names: list[str]` |
| 딕셔너리 | `dict[str, int]` | `counts: dict[str, int]` |
| 튜플 | `tuple[str, int]` | `pair: tuple[str, int]` |
| 세트 | `set[str]` | `tags: set[str]` |
| 없을 수 있음 | `str \| None` | `memo: str \| None = None` |
| 여러 타입 | `int \| str` | `key: int \| str` |
| 아무거나 | `Any` | 최후의 수단 |
| 반환 없음 | `-> None` | `def show() -> None:` |

> **`X | None` 표기는 파이썬 3.10부터** 씁니다. 이전에는 `Optional[X]` 였습니다.
> 이 과정은 3.12를 쓰므로 `|` 를 씁니다.

**경로는 `Path` 를 쓰세요.**

```python
from pathlib import Path

def load(path: Path | str) -> list[dict]:
    path = Path(path)          # 문자열도 받고 내부에서 변환
```

### 커스텀 타입과 별칭

```python
from todoapp.models import Todo

def filter_done(todos: list[Todo]) -> list[Todo]:
    return [t for t in todos if t.done]
```

**타입 별칭**으로 복잡한 타입에 이름을 붙일 수 있습니다.

```python
LoadResult = tuple[list[Todo], str | None]

def load(path: Path) -> LoadResult:
    ...
```

### logging 기본

```python
import logging

logger = logging.getLogger(__name__)      # 모듈마다 하나

logger.debug("상세한 디버깅 정보")
logger.info("정상 진행 상황")
logger.warning("이상하지만 계속 진행 가능")
logger.error("실패했음")
logger.critical("프로그램을 계속할 수 없음")
```

### 로그 레벨

| 레벨 | 값 | 언제 |
|---|---|---|
| `DEBUG` | 10 | 개발 중 상세 정보. 변수 값, 흐름 추적 |
| `INFO` | 20 | 정상 동작 기록. "3건 수집 완료" |
| `WARNING` | 30 | 문제지만 계속 가능. "재시도 1/3" |
| `ERROR` | 40 | 실패. "이 항목은 처리 못 함" |
| `CRITICAL` | 50 | 치명적. "DB 연결 불가, 종료" |

**설정한 레벨 이상만 출력됩니다.**

```python
logging.basicConfig(level=logging.INFO)
logger.debug("안 보임")        # INFO보다 낮으므로 무시
logger.info("보임")
```

> **개발 중에는 `DEBUG`, 운영에서는 `INFO`** 로 설정합니다.
> 코드를 고칠 필요 없이 **설정 한 줄로 로그 양을 조절**할 수 있다는 것이 `print` 와의 결정적 차이입니다.

### print vs logging

| | `print` | `logging` |
|---|---|---|
| 레벨 구분 | 없음 | 5단계 |
| 출력 위치 | 화면만 | 화면 · **파일** · 서버 · 여러 곳 동시 |
| 시각·모듈명 | 직접 써야 함 | 자동 |
| 운영에서 끄기 | 코드를 지워야 함 | **설정만 변경** |
| 컨테이너 로그 수집 | 어려움 | 표준 (W25) |

### 핸들러와 포맷

```python
import logging
from pathlib import Path

def setup_logging(level=logging.INFO, log_file=None):
    """로깅을 설정합니다."""
    fmt = "%(asctime)s [%(levelname)-8s] %(name)s - %(message)s"
    datefmt = "%Y-%m-%d %H:%M:%S"

    handlers = [logging.StreamHandler()]                 # 화면
    if log_file:
        handlers.append(logging.FileHandler(log_file, encoding="utf-8"))   # 파일

    logging.basicConfig(level=level, format=fmt, datefmt=datefmt, handlers=handlers)
```

| 핸들러 | 어디로 |
|---|---|
| `StreamHandler` | 화면(stderr) |
| `FileHandler` | 파일 |
| `RotatingFileHandler` | 파일 (크기 초과 시 회전) |
| `TimedRotatingFileHandler` | 파일 (날짜별 회전) |

**포맷 항목**

| 항목 | 뜻 |
|---|---|
| `%(asctime)s` | 시각 |
| `%(levelname)s` | 레벨 |
| `%(name)s` | 로거 이름 (모듈명) |
| `%(message)s` | 메시지 |
| `%(filename)s:%(lineno)d` | 파일:줄번호 |

### 예외를 로그에 남기기

```python
try:
    risky()
except Exception:
    logger.exception("처리 실패")       # Traceback 전체가 함께 기록됨
```

`logger.exception()` 은 **`except` 블록 안에서만** 씁니다. `ERROR` 레벨 + Traceback입니다.

```python
except Exception as e:
    logger.error("처리 실패: %s", e)     # 메시지만
    logger.exception("처리 실패")         # 메시지 + Traceback  ← 원인 추적에 유리
```

> **`logger.error(f"실패: {e}")` 대신 `logger.error("실패: %s", e)` 를 쓰세요.**
> 레벨이 낮아 출력되지 않을 때 **문자열을 만드는 비용 자체를 아낍니다.**
> 반복문 안에서 초당 수천 번 호출되면 차이가 납니다.

### 라이브러리는 핸들러를 설정하지 않는다

**중요한 관례입니다.**

```python
# 라이브러리 코드 (models.py, service.py)
logger = logging.getLogger(__name__)
logger.info("...")                # 로거를 얻어 쓰기만 함

# 실행 진입점 (cli.py, __main__.py)
logging.basicConfig(...)          # 설정은 여기서만
```

`basicConfig` 를 라이브러리에서 호출하면, 이 패키지를 쓰는 사람의 로깅 설정을 덮어씁니다.
**설정은 프로그램을 실행하는 쪽이 결정합니다.**

### 예외 테스트

import pytest


def test_empty_title_raises():

def test_error_message():

### 픽스처(fixture) — 준비 코드 재사용

```python
import pytest


@pytest.fixture
def sample_todos():
    """테스트용 할 일 목록."""
    todos = TodoList()
    todos.add("첫 번째", "높음", ["업무"])
    todos.add("두 번째", "보통")
    return todos


def test_length(sample_todos):          # 이름을 인자로 쓰면 자동 주입
    assert len(sample_todos) == 2


def test_search(sample_todos):          # 각 테스트마다 새로 만들어짐
    assert len(sample_todos.search("업무")) == 1
```

**각 테스트마다 새로 실행됩니다.** 한 테스트가 데이터를 바꿔도 다른 테스트에 영향을 주지 않습니다.

**`tmp_path` 는 pytest가 기본 제공하는 픽스처**입니다. 임시 폴더를 만들어 줍니다.

```python
def test_save_and_load(tmp_path):
    path = tmp_path / "todos.json"      # 테스트마다 다른 임시 폴더
    storage.save(todos, path)
    loaded, warning = storage.load(path)
    assert warning is None
```

**실제 파일을 건드리지 않습니다.** 테스트가 끝나면 자동으로 정리됩니다.

### 파라미터화 — 같은 테스트를 여러 값으로

```python
@pytest.mark.parametrize("title", ["", "   ", "\t", "\n"])
def test_blank_title_rejected(title):
    with pytest.raises(ValidationError):
        Todo(1, title)
```

**4개의 테스트가 만들어집니다.** 실패하면 어떤 값에서 실패했는지 보여 줍니다.

여러 인자도 됩니다.

```python
@pytest.mark.parametrize("raw,expected", [
    ("12,000", 12000),
    (" 5000 ", 5000),
    ("89,000원", 89000),
])
def test_parse_amount(raw, expected):
    assert parse_amount(raw) == expected
```

### 좋은 테스트의 조건

| 조건 | 설명 |
|---|---|
| **독립적** | 실행 순서가 바뀌어도 통과 |
| **빠름** | 밀리초 단위. 느리면 아무도 안 돌림 |
| **하나의 것만** | 이름이 곧 실패 원인이 되게 |
| **경계값 포함** | 0, 빈 목록, 최대값, 없는 ID |
| **실패 시 원인이 보임** | `assert` 메시지가 충분한가 |

**AAA 패턴**으로 구조를 잡으면 읽기 좋습니다.

```python
def test_toggle():
    todos = TodoList()              # Arrange (준비)
    todo = todos.add("테스트")

    todos.toggle(todo.id)           # Act (실행)

    assert todo.done is True        # Assert (검증)
```

### Step 1. 타입 힌트 붙이기

`src/todoapp/models.py` 를 수정합니다.

```python
"""할 일 데이터 모델."""

from dataclasses import dataclass, field, asdict
from datetime import datetime
from typing import Any

PRIORITIES: tuple[str, ...] = ("높음", "보통", "낮음")


class TodoError(Exception):
    """이 패키지의 기본 예외."""


class ValidationError(TodoError):
    """데이터 검증 실패."""


class NotFoundError(TodoError):
    """항목을 찾지 못함."""


def _now() -> str:
    return datetime.now().strftime("%Y-%m-%d %H:%M")


@dataclass(order=True)
class Todo:
    """할 일 하나."""

    id: int
    title: str
    priority: str = "보통"
    tags: list[str] = field(default_factory=list)
    done: bool = False
    created_at: str = field(default_factory=_now)
    completed_at: str | None = None

    def __post_init__(self) -> None:
        self.title = self.title.strip()
        if not self.title:
            raise ValidationError("제목은 비워 둘 수 없습니다.")
        if self.priority not in PRIORITIES:
            raise ValidationError(
                f"우선순위는 {' / '.join(PRIORITIES)} 중 하나여야 합니다: {self.priority!r}"
            )
        self.tags = sorted({t.strip() for t in self.tags if t.strip()})

    def complete(self) -> "Todo":
        if not self.done:
            self.done = True
            self.completed_at = _now()
        return self

    def reopen(self) -> "Todo":
        self.done = False
        self.completed_at = None
        return self

    def toggle(self) -> "Todo":
        return self.reopen() if self.done else self.complete()

    def matches(self, keyword: str) -> bool:
        keyword = keyword.strip().lower()
        if not keyword:
            return False
        return keyword in self.title.lower() or any(keyword in t.lower() for t in self.tags)

    def to_dict(self) -> dict[str, Any]:
        return asdict(self)

    @classmethod
    def from_dict(cls, data: dict[str, Any]) -> "Todo":
        return cls(**data)
```

> **`-> "Todo"`** 처럼 따옴표를 쓴 것에 주목하세요.
> 클래스 정의가 아직 끝나지 않아 `Todo` 라는 이름을 쓸 수 없기 때문입니다.
> (파일 맨 위에 `from __future__ import annotations` 를 넣으면 따옴표가 필요 없어집니다.)

### Step 2. service.py에 타입 힌트

`src/todoapp/service.py` 를 수정합니다.

```python
"""할 일 목록 관리 로직."""

import logging
from collections.abc import Iterable, Iterator
from typing import Any, Literal

from todoapp.models import Todo, NotFoundError

logger = logging.getLogger(__name__)

Status = Literal["all", "todo", "done"]


class TodoList:
    """할 일 목록. 파일 입출력과 화면 출력을 하지 않습니다."""

    def __init__(self, items: Iterable[Todo] | None = None) -> None:
        self.items: list[Todo] = list(items or [])
        logger.debug("TodoList 생성: %d건", len(self.items))

    def __len__(self) -> int:
        return len(self.items)

    def __iter__(self) -> Iterator[Todo]:
        return iter(self.items)

    def next_id(self) -> int:
        return max((t.id for t in self.items), default=0) + 1

    def find(self, todo_id: int) -> Todo | None:
        for t in self.items:
            if t.id == todo_id:
                return t
        return None

    def get(self, todo_id: int) -> Todo:
        """찾지 못하면 NotFoundError."""
        todo = self.find(todo_id)
        if todo is None:
            logger.warning("존재하지 않는 ID 요청: %s", todo_id)
            raise NotFoundError(f"{todo_id}번 할 일이 없습니다.")
        return todo

    def add(self, title: str, priority: str = "보통", tags: list[str] | None = None) -> Todo:
        todo = Todo(self.next_id(), title, priority, tags or [])
        self.items.append(todo)
        logger.info("추가: id=%d title=%r priority=%s", todo.id, todo.title, todo.priority)
        return todo

    def remove(self, todo_id: int) -> Todo:
        todo = self.get(todo_id)
        self.items.remove(todo)
        logger.info("삭제: id=%d title=%r", todo.id, todo.title)
        return todo

    def toggle(self, todo_id: int) -> Todo:
        todo = self.get(todo_id).toggle()
        logger.info("토글: id=%d done=%s", todo.id, todo.done)
        return todo

    def filter(self, status: Status = "all") -> list[Todo]:
        if status == "todo":
            return [t for t in self.items if not t.done]
        if status == "done":
            return [t for t in self.items if t.done]
        return list(self.items)

    def search(self, keyword: str) -> list[Todo]:
        result = [t for t in self.items if t.matches(keyword)]
        logger.debug("검색 %r → %d건", keyword, len(result))
        return result

    def all_tags(self) -> set[str]:
        tags: set[str] = set()
        for t in self.items:
            tags.update(t.tags)
        return tags

    def stats(self) -> dict[str, Any]:
        total = len(self.items)
        done = sum(1 for t in self.items if t.done)
        by_priority: dict[str, int] = {}
        by_tag: dict[str, int] = {}
        for t in self.items:
            by_priority[t.priority] = by_priority.get(t.priority, 0) + 1
            for tag in t.tags:
                by_tag[tag] = by_tag.get(tag, 0) + 1
        return {
            "total": total,
            "done": done,
            "todo": total - done,
            "rate": done / total if total else 0.0,
            "by_priority": by_priority,
            "by_tag": by_tag,
        }

    def __repr__(self) -> str:
        s = self.stats()
        return f"TodoList(total={s['total']}, done={s['done']})"
```

"""로깅 설정. 진입점(cli)에서만 호출합니다."""

import logging
import sys
from pathlib import Path

FORMAT = "%(asctime)s [%(levelname)-8s] %(name)-18s %(message)s"
DATE_FORMAT = "%Y-%m-%d %H:%M:%S"


def setup_logging(
    level: int | str = logging.INFO,
    log_file: Path | str | None = None,
    console: bool = True,
) -> None:
    """로깅을 설정합니다.

    Args:
        level: 로그 레벨 (logging.DEBUG, "INFO" 등)
        log_file: 파일로도 남기려면 경로 지정
        console: 화면에도 출력할지
    """
    handlers: list[logging.Handler] = []

    if console:
        handlers.append(logging.StreamHandler(sys.stderr))

    if log_file:
        path = Path(log_file)
        path.parent.mkdir(parents=True, exist_ok=True)
        handlers.append(logging.FileHandler(path, encoding="utf-8"))

    logging.basicConfig(
        level=level,
        format=FORMAT,
        datefmt=DATE_FORMAT,
        handlers=handlers,
        force=True,          # 이미 설정돼 있어도 덮어씀
    )
```

### 로그가 하나도 안 보임

**해결** — `force=True` 를 주세요. (파이썬 3.8+)

logging.basicConfig(level=logging.DEBUG, force=True)
```

**① 레벨로 출력량을 조절할 수 있다 — 코드를 안 고치고**

logger.debug("응답 원문: %s", response.text)      # 개발 중엔 필요, 운영에선 방해

# 개발

```

`print` 였다면 **운영 배포 전에 디버깅용 print를 전부 찾아 지워야** 합니다.
그러다 하나를 놓치면 운영 로그에 응답 원문이 통째로 찍혀 **개인정보 유출**이 됩니다

```

`print("저장 실패")` 만 있으면 **새벽 3시에 무슨 일이 있었는지 알 수 없습니다.**

**③ 출력 대상을 바꿀 수 있다**

| 운영 (W27) | 로그 수집 시스템 → 대시보드·알림 |

**코드는 한 줄도 안 바뀝니다.** 핸들러 설정만 바뀝니다.

W23에서 서버에 배포하면 터미널이 없고, W25에서 컨테이너로 돌리면 프로세스만 있습니다.
**"어제 왜 실패했는가"에 답할 수 있는 유일한 수단이 로그입니다.**

**2.** 아래 테스트에는 문제가 있습니다. 무엇이고 어떻게 고치나요?

```python
todos = TodoList()

def test_add():
    todos.add("첫 번째")
    assert len(todos) == 1

def test_search():
    todos.add("두 번째")
    assert len(todos.search("두")) == 1
    assert len(todos) == 1
```

<details>
<summary>답 보기</summary>

**문제: 테스트끼리 상태를 공유합니다.**

`todos` 가 모듈 수준에 있어서 **모든 테스트가 같은 객체**를 씁니다.

| 실행 순서 | `test_search` 의 `len(todos)` | 결과 |
|---|---|---|
| `test_add` → `test_search` | 2 (첫 번째 + 두 번째) | **실패** |
| `test_search` 만 단독 실행 | 1 | 통과 |

**실행 순서에 따라 결과가 달라집니다.** 이런 테스트는 신뢰할 수 없습니다.

특히 `pytest -k "search"` 로 하나만 돌리면 통과하고, 전체를 돌리면 실패합니다.
CI에서만 깨지는 유령 같은 실패가 됩니다.

**해결 — 픽스처를 쓰세요.**

```python
import pytest


@pytest.fixture
def todos():
    """각 테스트마다 새로 만들어집니다."""
    return TodoList()


def test_add(todos):
    todos.add("첫 번째")
    assert len(todos) == 1


def test_search(todos):
    todos.add("두 번째")
    assert len(todos.search("두")) == 1
    assert len(todos) == 1        # 이제 통과
```

**픽스처는 각 테스트 함수마다 다시 실행됩니다.** 그래서 항상 깨끗한 상태에서 시작합니다.

**좋은 테스트의 첫 번째 조건이 "독립성"** 인 이유입니다.
- 어떤 순서로 돌려도 결과가 같다
- 하나만 돌려도 전부 돌려도 같다
- 병렬로 돌려도 안전하다 (`pytest -n auto`)

**같은 원리가 파일에도 적용됩니다.**

```python
def test_save():
    storage.save(todos, "todos.json")      # ❌ 실제 파일 + 다른 테스트에 영향

def test_save(tmp_path):
    storage.save(todos, tmp_path / "todos.json")   # ✅ 테스트마다 다른 임시 폴더
```

**3.** 아래 함수에 대한 테스트를 설계하세요. 어떤 경우를 반드시 포함해야 하나요?

```python
def parse_amount(raw: str) -> int | None:
    """'12,000원' 같은 문자열을 정수로 변환합니다. 실패하면 None."""
    cleaned = raw.strip().replace(",", "").replace("원", "").strip()
    if cleaned == "" or not cleaned.isdigit():
        return None
    return int(cleaned)
```

<details>
<summary>답 보기</summary>

**테스트는 세 부류로 나눠 설계합니다.**

```python
import pytest


class TestParseAmount:
    # ① 정상 경로 — 되어야 하는 것
    @pytest.mark.parametrize("raw,expected", [
        ("12000", 12000),
        ("12,000", 12000),
        ("12,000원", 12000),
        (" 12,000 원 ", 12000),
        ("1,234,567", 1234567),
        ("0", 0),
    ])
    def test_정상_변환(self, raw, expected):
        assert parse_amount(raw) == expected

    # ② 경계값 — 가장자리
    @pytest.mark.parametrize("raw,expected", [
        ("0", 0),                    # 최솟값
        ("1", 1),
        ("원", None),                 # 단위만
        (",", None),                 # 구분자만
    ])
    def test_경계값(self, raw, expected):
        assert parse_amount(raw) == expected

    # ③ 실패 경로 — 안 되어야 하는 것
    @pytest.mark.parametrize("raw", [
        "",           # 빈 문자열
        "   ",        # 공백만
        "오만원",       # 한글 숫자
        "12.5",       # 소수점 — isdigit()이 False
        "-5000",      # 음수 — isdigit()이 False
        "12a00",      # 숫자와 문자 혼합
        "１２０００",    # 전각 숫자 (실제로는 isdigit()이 True!)
    ])
    def test_실패시_None(self, raw):
        assert parse_amount(raw) is None
```

**반드시 포함해야 할 것**

| 종류 | 왜 |
|---|---|
| **빈 문자열 / 공백** | 사용자가 그냥 엔터를 침. 가장 흔한 입력 |
| **0** | 0은 falsy라 `if not amount` 같은 코드에서 사고를 냄 |
| **음수·소수점** | 사양상 허용인지 아닌지 테스트가 문서 역할을 함 |
| **예상치 못한 형식** | 한글, 혼합 문자 |
| **경계** | 최소·최대·바로 아래·바로 위 |

**테스트를 쓰면서 사양의 구멍을 발견합니다.**

위 테스트를 실제로 돌리면 마지막 항목이 **실패**합니다.

```
FAILED test_실패시_None[１２０００] - assert 12000 is None
```

전각 숫자 `１２０００` 은 `.isdigit()` 이 `True` 를 돌려주기 때문입니다!
`int()` 도 이걸 변환합니다.

**이건 버그일까요, 사양일까요?**

이 질문에 답하는 것이 테스트의 진짜 가치입니다.
- 허용한다면 → 테스트를 `assert parse_amount("１２０００") == 12000` 으로 고치고 docstring에 명시
- 막는다면 → `.isascii()` 검사를 추가

어느 쪽이든 **다음 사람이 이 동작을 알 수 있게 됩니다.**

W05 [Day 023](day-023.md)의 데이터 정제, W09 [Day 044](../02-sql-pipeline/day-044.md)의 품질 검증에서
정확히 이런 케이스들과 매일 마주치게 됩니다.
</details>

## 오늘의 정리

| 항목 | 문법 |
|---|---|
| 타입 힌트 | `def f(a: int, b: str = "") -> list[int]:` |
| 없을 수 있음 | `str \| None` |
| 컨테이너 | `list[str]` `dict[str, int]` `tuple[str, int]` |
| 제한된 값 | `Literal["all", "todo", "done"]` |
| 자기 클래스 | `-> "Todo"` 또는 `from __future__ import annotations` |
| 로거 얻기 | `logger = logging.getLogger(__name__)` (모듈 맨 위) |
| 레벨 | `DEBUG` < `INFO` < `WARNING` < `ERROR` < `CRITICAL` |
| 설정 | `logging.basicConfig(...)` — **진입점에서만 한 번** |
| 예외 로그 | `logger.exception("메시지")` — Traceback 포함 |
| 포매팅 | `logger.info("%s건", n)` — f-string 금지 |
| 테스트 파일 | `tests/test_*.py` · 함수는 `test_` 로 시작 |
| 검증 | `assert 조건` |
| 예외 검증 | `with pytest.raises(ValueError, match="메시지"):` |
| 준비 재사용 | `@pytest.fixture` — 테스트마다 새로 실행 |
| 임시 파일 | `tmp_path` 픽스처 |
| 반복 | `@pytest.mark.parametrize("a,b", [(1,2), (3,4)])` |
| 실수 비교 | `pytest.approx(1/3)` |

**과제** — 도서 대여 시스템에 오늘 배운 것을 전부 적용하세요.
① 모든 공개 함수·메서드에 타입 힌트 추가
② `print` 를 전부 `logging` 으로 교체하고, 진입점에서만 `setup_logging()` 호출
③ `tests/` 에 **20개 이상**의 pytest 테스트 작성 — 경계값(빈 목록·없는 ISBN·이미 대여된 책)을 반드시 포함
④ `tmp_path` 를 써서 저장·복원 테스트 작성
⑤ 일부러 코드를 하나 망가뜨려 **테스트가 그것을 잡아내는지** 확인하고, 실패 메시지를 README에 기록
