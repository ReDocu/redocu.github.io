## 2. 막히는 상황

어제 깜빡임은 해결했다. 그런데 실행해서 이것들을 해 보자.

**② 타이머 간격을 5ms로 바꿔 본다**

**③ 메뉴를 열거나 창 크기를 조절한다**

```

```

   ③ 제어권이 Windows에 있다

```
   지금:   Windows가 "이제 갱신해라"라고 알려줄 때만 돈다

```

## 3. 개념

### 3-1. `PeekMessage` — 기다리지 않는 메시지 확인

**왜 필요한가** — Day 23의 `_kbhit()`과 정확히 같은 발상이다.

```cpp
    MSG msg;

    if (PeekMessage(&msg, NULL, 0, 0, PM_REMOVE))
    {
        // 메시지가 있었다
    }
    else
    {
        // 메시지가 없다 → 게임을 돌린다
    }
```

| 함수 | 메시지가 없으면 |
|---|---|
| `GetMessage` | **기다린다** (블로킹) |
| **`PeekMessage`** | **바로 반환** (0) |

```
   ┌──────────────────────────────────────────────────────┐
   │  Day 23 (콘솔)              Day 38 (WINAPI)          │
   │                                                       │
   │  _getch()      기다림       GetMessage()   기다림     │
   │  _kbhit()      안 기다림    PeekMessage()  안 기다림  │
   │                                                       │
   │  ★ 완전히 같은 구조다                                 │
   └──────────────────────────────────────────────────────┘
```

**마지막 인자**

| 값 | 동작 |
|---|---|
| `PM_REMOVE` | 메시지를 큐에서 **꺼낸다** ← 보통 이것 |
| `PM_NOREMOVE` | 확인만 하고 큐에 남긴다 |

### 3-2. 게임 루프의 표준 형태

**왜 필요한가** — 앞으로 6주간 쓸 루프의 완성형.

```cpp
int APIENTRY WinMain(HINSTANCE hInstance, HINSTANCE, LPSTR, int nCmdShow)
{
    HWND hWnd = CreateGameWindow(...);
    if (!hWnd) return 0;

    InitGame();

    MSG msg = { 0 };
    bool running = true;

    while (running)
    {
        // ── 메시지 처리 (있는 만큼 전부) ──
        while (PeekMessage(&msg, NULL, 0, 0, PM_REMOVE))
        {
            if (msg.message == WM_QUIT)
            {
                running = false;
                break;
            }

            TranslateMessage(&msg);
            DispatchMessage(&msg);
        }

        if (!running) break;

        // ── 게임 ──
        double dt = CalcDeltaTime();

        ProcessInput();
        Update(dt);
        Render(hWnd);
    }

    ReleaseGame();
    return (int)msg.wParam;
}
```

```
   ┌───────────────────────────────────────────────────────────┐
   │  while (running)                                           │
   │                                                            │
   │    ┌─ while (PeekMessage(...))   메시지가 있는 만큼 전부   │
   │    │     DispatchMessage         → WndProc 호출            │
   │    └─                                                      │
   │                                                            │
   │    dt = CalcDeltaTime()          시간 재기                 │
   │    ProcessInput()                입력 상태 갱신             │
   │    Update(dt)                    게임 상태 갱신             │
   │    Render()                      백버퍼에 그리고 Present    │
   │                                                            │
   └───────────────────────────────────────────────────────────┘
```

> ### ⚠️ 안쪽 `while`이 중요하다
>
> ```cpp
>   if (PeekMessage(...))       // ✘ 프레임당 메시지 1개만 처리
>   while (PeekMessage(...))    // ✔ 쌓인 메시지를 전부 처리
> ```
>
> `if`로 쓰면 마우스를 빠르게 움직일 때 메시지가 쌓여 입력이 지연된다.

### 3-3. `WM_QUIT` 처리

**왜 필요한가** — `PeekMessage`는 `GetMessage`와 달리 `WM_QUIT`을 알아서 처리하지 않는다.

```
   GetMessage :  WM_QUIT 을 만나면 0 을 반환 → while 조건이 거짓 → 자동 종료

   PeekMessage:  WM_QUIT 도 그냥 하나의 메시지로 반환 (1)
                 → 우리가 직접 검사해야 한다
```

```cpp
        while (PeekMessage(&msg, NULL, 0, 0, PM_REMOVE))
        {
            if (msg.message == WM_QUIT)      // ★ 직접 검사
            {
                running = false;
                break;
            }
            TranslateMessage(&msg);
            DispatchMessage(&msg);
        }
```

> **이 검사를 빼면 X를 눌러도 프로그램이 안 끝난다.**

### 3-4. 고정밀 타이머 — `QueryPerformanceCounter`

**왜 필요한가** — `GetTickCount`의 15.6ms 해상도로는 프레임 시간을 못 잰다.

```cpp
LARGE_INTEGER g_freq;          // 초당 카운트 수
LARGE_INTEGER g_prevCount;

void InitTimer()
{
    QueryPerformanceFrequency(&g_freq);        // 한 번만
    QueryPerformanceCounter(&g_prevCount);
}

double CalcDeltaTime()
{
    LARGE_INTEGER now;
    QueryPerformanceCounter(&now);

    double dt = (double)(now.QuadPart - g_prevCount.QuadPart) / g_freq.QuadPart;
    g_prevCount = now;

    if (dt > 0.1) dt = 0.1;                    // 클램프 (Day 21)

    return dt;
}
```

```
   QueryPerformanceFrequency(&freq)  →  freq.QuadPart = 초당 카운트
                                        예: 10,000,000 (10MHz)

   QueryPerformanceCounter(&now)     →  현재 카운트 값

   경과 시간(초) = (now - prev) / freq
```

| 함수 | 해상도 | 비고 |
|---|---|---|
| `GetTickCount()` | 약 15.6ms | 부족 |
| `timeGetTime()` | 1ms | `winmm.lib` 필요 |
| **`QueryPerformanceCounter`** | **마이크로초 이하** | **이걸 쓴다** |
| `std::chrono::steady_clock` | 나노초 | C++11. 이식성 좋음 |

> `LARGE_INTEGER`는 64비트 정수 구조체다. `.QuadPart`로 값에 접근한다.

### 3-5. 델타 타임 — 다시 확인

**왜 필요한가** — Day 21에서 배운 것이지만, 오늘 진짜로 필요해진다.

```
   프레임 제한을 안 걸면 FPS가 수백~수천이 나온다
   → 고정값 이동은 완전히 통제 불능이 된다

   ballX += 1;                    // 500fps에서는 초당 500칸!
   ballX += speed * dt;           // 몇 fps든 초당 speed 칸  ✔
```

**클램프가 오늘 특히 중요하다**

```cpp
    if (dt > 0.1) dt = 0.1;
```

```
   ★ 클램프가 필요한 순간들

   ① 창을 드래그하다 놓았을 때        →  dt = 3.0초
   ② 디버거에서 중단점에 멈췄다 재개   →  dt = 30초
   ③ 최소화했다가 복원                →  dt = 60초
   ④ 다른 무거운 프로그램이 CPU 점유   →  dt = 0.5초

   클램프가 없으면 그 순간 별이 화면 밖으로 순간이동한다
```

### 3-6. 프레임 제한 — 걸 것인가 말 것인가

**왜 필요한가** — 제한 없이 돌리면 CPU를 100% 먹는다.

```cpp
const double TARGET_FPS = 60.0;
const double TARGET_FRAME_TIME = 1.0 / TARGET_FPS;

    // 루프 끝에서
    double elapsed = GetElapsedSinceFrameStart();

    if (elapsed < TARGET_FRAME_TIME)
    {
        DWORD sleepMs = (DWORD)((TARGET_FRAME_TIME - elapsed) * 1000.0);
        if (sleepMs > 0)
            Sleep(sleepMs);
    }
```

| 방식 | CPU | 부드러움 | 배터리 |
|---|---|---|---|
| 제한 없음 | **100%** | 최고 | 최악 |
| `Sleep` 기반 제한 | 낮음 | 좋음 | 좋음 ← **이걸 쓴다** |
| 스핀 대기 (`while` 돌기) | 100% | 최고 | 최악 |

```
   ★ Sleep 은 정확하지 않다 (요청보다 조금 더 잘 수 있다)
     하지만 게임 루프에서는 충분하다.
     정밀함이 필요하면 Sleep(대부분) + 스핀(나머지) 조합을 쓴다
```

> **모니터 주사율(보통 60Hz)보다 빨리 그려도 사람 눈에 차이가 없다.**
> 60fps 제한이 합리적이다.

### 3-7. `WM_PAINT` 없이 그리기

**왜 필요한가** — 게임 루프에서는 `InvalidateRect` → `WM_PAINT`를 거치지 않고 직접 그린다.

```cpp
void Render(HWND hWnd)
{
    // 백버퍼에 그리기
    RECT rc = { 0, 0, g_clientW, g_clientH };
    FillRect(g_backDC, &rc, g_bgBrush);

    RenderStars(g_backDC);
    RenderUI(g_backDC);

    // 화면으로 전송
    HDC hdc = GetDC(hWnd);                 // ★ BeginPaint 가 아니라 GetDC
    BitBlt(hdc, 0, 0, g_clientW, g_clientH, g_backDC, 0, 0, SRCCOPY);
    ReleaseDC(hWnd, hdc);
}
```

```
   [ 타이머 방식 (어제까지) ]

   WM_TIMER  →  Update  →  InvalidateRect  →  (나중에) WM_PAINT  →  그리기
                              ▲
                              └── 언제 그려질지 Windows가 정한다


   [ 게임 루프 방식 (오늘) ]

   루프  →  Update  →  Render  →  GetDC + BitBlt  →  ReleaseDC
                                     ▲
                                     └── 지금 당장 그린다
```

**`WM_PAINT`는 어떻게 하나**

```cpp
    case WM_PAINT:
        {
            PAINTSTRUCT ps;
            HDC hdc = BeginPaint(hWnd, &ps);

            // 백버퍼 내용을 그대로 전송 (게임 루프가 이미 그려 놨다)
            if (g_backDC)
                BitBlt(hdc, 0, 0, g_clientW, g_clientH, g_backDC, 0, 0, SRCCOPY);

            EndPaint(hWnd, &ps);
        }
        return 0;
```

> **`WM_PAINT`는 여전히 처리해야 한다.**
> 창이 가려졌다 드러날 때 Windows가 보내는데, 처리하지 않으면 계속 보낸다.
> 백버퍼를 그대로 전송하면 된다.

### 3-8. 창 드래그 문제 — 모달 루프

**왜 필요한가** — `PeekMessage`로 바꿔도 이 문제는 남는다.

```
   창 제목 표시줄을 드래그하면

   Windows가 자체 루프(모달 루프)에 들어간다
   → DefWindowProc 안에서 안 나온다
   → 우리 while 루프가 아예 안 돈다
```

**대응 방법**

```cpp
    case WM_ENTERSIZEMOVE:
        // 드래그/크기조절 시작 — 타이머로 대신 돌린다
        SetTimer(hWnd, TIMER_MODAL, 16, NULL);
        return 0;

    case WM_EXITSIZEMOVE:
        KillTimer(hWnd, TIMER_MODAL);
        g_prevCount = GetNow();          // ★ dt 리셋
        return 0;

    case WM_TIMER:
        if (wParam == TIMER_MODAL)
        {
            double dt = CalcDeltaTime();
            Update(dt);
            Render(hWnd);
        }
        return 0;
```

```
   ★ 모달 루프 중에도 WM_TIMER 는 온다
     그때만 타이머로 게임을 돌린다
```

> **게임에서는 창 크기 조절을 막는 것이 더 흔한 해결책이다** (Day 31 Step 6).
> 그래도 이 처리를 알아 두면 좋다.

### Step 4 — 델타 타임 검증 (핵심 실험)

```cpp
double g_fixedX = 0.0;      // 프레임마다 고정값

void Update(double dt)
{
    g_fixedX += 1.0;                // 1프레임에 1픽셀
    g_deltaX += 100.0 * dt;         // 초당 100픽셀

    UpdateStars(dt);
}
```

**5초 동안 실행하고 값을 비교한다.**

|:--:|:--:|:--:|
| 60 (제한) | 약 300 | **약 500** |
| 500 | 약 2500 | **약 500** |
| 2000 | 약 10000 | **약 500** |

**✅ 여기까지 실행하면** — `deltaX`는 FPS와 무관하게 항상 500 근처다.

### Step 5 — FPS 제한

```cpp
bool g_limitFps = true;
const double TARGET_FPS = 60.0;

    while (running)
    {
        LARGE_INTEGER frameStart;
        QueryPerformanceCounter(&frameStart);

        // ... 메시지 처리, Update, Render ...

        if (g_limitFps)
        {
            LARGE_INTEGER now;
            QueryPerformanceCounter(&now);

            double elapsed = (double)(now.QuadPart - frameStart.QuadPart)
                           / (double)g_freq.QuadPart;

            double target = 1.0 / TARGET_FPS;

            if (elapsed < target)
            {
                DWORD sleepMs = (DWORD)((target - elapsed) * 1000.0);
                if (sleepMs > 0) Sleep(sleepMs);
            }
        }
    }
```

```cpp
    case WM_KEYDOWN:
        if (wParam == 'V') g_limitFps = !g_limitFps;
        return 0;
```

**✅ 여기까지 실행하면** — `V`로 토글한다.

```
   제한 ON   →  FPS 60,  CPU 3%
   제한 OFF  →  FPS 800, CPU 100%

   ★ 별의 이동 속도는 둘 다 같다  ✔
```

### Step 6 — `Render`를 `GetDC` 방식으로

```cpp
void Render(HWND hWnd)
{
    if (!g_backDC) return;

    // 백버퍼에 그리기
    RECT rc = { 0, 0, g_clientW, g_clientH };

### Step 10 — 루프 골격 정리

```cpp
// ─────────────────────────────────────────────
//  게임 루프 골격 (Day 39에서 클래스가 된다)
// ─────────────────────────────────────────────

bool Init(HWND hWnd);
void ProcessInput();
void Update(double dt);
void Render(HWND hWnd);
void Release();

int APIENTRY WinMain(HINSTANCE hInstance, HINSTANCE, LPSTR, int nCmdShow)
{
    HWND hWnd = CreateGameWindow(hInstance, "Game Loop", 800, 600, nCmdShow);
    if (!hWnd) return 0;

    if (!Init(hWnd))
    {
        MessageBox(NULL, "초기화 실패", "오류", MB_OK);
        return 0;
    }

    MSG msg = { 0 };
    bool running = true;

    while (running)
    {
        LARGE_INTEGER frameStart;
        QueryPerformanceCounter(&frameStart);

        while (PeekMessage(&msg, NULL, 0, 0, PM_REMOVE))
        {
            if (msg.message == WM_QUIT) { running = false; break; }
            TranslateMessage(&msg);
            DispatchMessage(&msg);
        }
        if (!running) break;

        double dt = CalcDeltaTime();

        ProcessInput();
        Update(dt);
        Render(hWnd);

        LimitFrameRate(frameStart);
    }

    Release();
    return (int)msg.wParam;
}
```

**✅ 여기까지 하면** — `WinMain`이 게임 루프 형태로 정리된다.

> ### ★ 이 골격을 잘 봐 둔다
>
> | 오늘 | 내일 (Day 39) |
> |---|---|
> | `Init()` | `Core::Init()` |
> | `while (running) {...}` | `Core::Run()` |
> | `ProcessInput()` | `Core::ProcessInput()` |
> | `Update(dt)` | `Core::Update(dt)` |
> | `Render(hWnd)` | `Core::Render()` |
> | `Release()` | `Core::Release()` |
>
> **함수를 클래스 멤버로 옮기기만 하면 된다.**

## 6. 자주 막히는 곳

| 증상 | 원인 | 해결 |
|---|---|---|
| **X를 눌러도 안 끝남** | `WM_QUIT` 검사 누락 | `if (msg.message == WM_QUIT)` |
| CPU 100% | 프레임 제한 없음 | `Sleep` 기반 제한 |
| 입력이 지연됨 | `if (PeekMessage)` 사용 | **`while (PeekMessage)`** |
| 창 드래그 시 멈춤 | 모달 루프 | `WM_ENTERSIZEMOVE` + 타이머 |
| 드래그 후 순간이동 | `dt` 폭증 | 클램프 + `WM_EXITSIZEMOVE`에서 리셋 |
| `dt`가 0 | 프레임이 너무 빨라 카운트 차이 없음 | 정상. 다음 프레임에 누적된다 |
| FPS가 여전히 60 | 수직 동기(V-Sync) 또는 `Sleep` | 제한 코드 확인 |
| 화면이 안 그려짐 | `GetDC`/`ReleaseDC` 누락 | 짝 확인 |
| 종료 시 크래시 | 루프 밖에서 리소스 사용 | `Release()` 위치 확인 |
| `QueryPerformanceFrequency` 매 프레임 호출 | 불필요 | 초기화 시 한 번만 |

## 7. 정리

### 오늘 배운 것

| 개념 | 한 줄 요약 |
|---|---|
| **`PeekMessage`** | 메시지가 없으면 바로 반환. `_kbhit()`의 WINAPI 버전 |
| `while (PeekMessage)` | 쌓인 메시지를 **전부** 처리한다 |
| `WM_QUIT` 검사 | `PeekMessage`는 자동 종료를 안 해준다 |
| **`QueryPerformanceCounter`** | 마이크로초 단위 고정밀 타이머 |
| 델타 타임 | FPS와 무관한 이동. **클램프 필수** |
| 프레임 제한 | `Sleep`으로 CPU를 아낀다 |
| `GetDC` + `BitBlt` | `WM_PAINT` 없이 직접 화면 갱신 |
| 모달 루프 | 창 드래그 중에는 `WM_TIMER`로 대신 돌린다 |

### 콘솔에서의 대응

| Day 21 (콘솔) | Day 38 (WINAPI) |
|---|---|
| `_kbhit()` | `PeekMessage(..., PM_REMOVE)` |

| `clock()` | `QueryPerformanceCounter` |
| `Sleep(16)` | `Sleep(남은 시간)` |
| `printf` 한 번 | `BitBlt` 한 번 |
