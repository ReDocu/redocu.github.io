### 학습 루프 표준 골격 — 오늘 이후의 템플릿

```
[준비]  분할(시간!) → 표준화(train 통계로) → Dataset/DataLoader
[조립]  model = nn.Module 조립 · optimizer = Adam(model.parameters()) · loss_fn
[학습]  for epoch:
            for xb, yb in train_dl:      ① model(xb) ② loss ③ backward ④ step ⑤ zero_grad
            valid 지표 계산 → 최고면 state_dict 저장         ← 감시와 체크포인트
[마감]  최고 시점 복원 → test 1회 → 저장                     ← 금고 원칙 그대로
```

sklearn과 비교하면: `fit()` 한 줄이 [학습] 블록 전체로 풀어헤쳐진 대신, 그 안의 **모든 단계에
손을 넣을 수 있게** 됐습니다 — 손실을 바꾸고, 멈출 곳을 고르고, 구조를 조립하는 자유입니다.

### 언제 sklearn, 언제 PyTorch

| 상황 | 선택 | 근거 |
|---|---|---|
| 테이블 데이터, 수천~수십만 행 | **sklearn/부스팅 먼저** | 오늘 실험이 근거. 빠르고 강하고 운영이 쌈 |
| 이미지·텍스트·음성 | **PyTorch** | 특성 자체를 학습해야 함 — 선형/트리로는 표현 불가 |
| 커스텀 손실·구조가 필요 | PyTorch | fit() 안에 손을 넣어야 하므로 |
| 사전학습 모델 활용 | PyTorch (+HF) | W17–18의 세계 |

## ④ 단계별 실습 — MP2 재구현 대결

산출물: `day080_rematch.py`. MP2와 조건을 정확히 맞추는 것이 오늘의 기술입니다 —
**같은 특성(17개 + station 원-핫), 같은 시간 분할, 같은 test.**

### 문제 1. MP2의 특성 그대로 (1~2교시)

```python
# day080_rematch.py — 주간 종합: MP2 문제를 PyTorch로 재구현
import numpy as np
import pandas as pd
import torch
import torch.nn as nn
from sklearn.metrics import mean_absolute_error, r2_score
from torch.utils.data import DataLoader, TensorDataset

torch.manual_seed(42)

NUM = ["pm10", "pm25", "o3", "no2", "co", "so2", "temp", "humidity", "wind_speed", "precip"]
TIME = ["pm25_lag1", "pm25_ma3", "seoul_pm25", "month"]
FC = ["wind_fc", "humidity_fc", "precip_fc"]
FEATS = NUM + TIME + FC

print("== A. MP2의 특성 그대로 (Day 065의 make_features) ==")
df = pd.read_csv("data/air_daily.csv", parse_dates=["date"]).sort_values(["station", "date"])
g = df.groupby("station")
df["pm25_lag1"] = g["pm25"].shift(1)
df["pm25_ma3"] = g["pm25"].transform(lambda s: s.rolling(3).mean())
df["seoul_pm25"] = df.groupby("date")["pm25"].transform("mean")
df["month"] = df.date.dt.month
df["wind_fc"] = g["wind_speed"].shift(-1)
df["humidity_fc"] = g["humidity"].shift(-1)
df["precip_fc"] = g["precip"].shift(-1)
d = df[df.pm25_next.notna() & df[FC].notna().all(axis=1)].copy()

# station 원-핫 (범주 5개 고정이라 get_dummies로 충분 — 서빙까지 갈 모델이면 Day 063 방식)
onehot = pd.get_dummies(d.station, prefix="st")
d = pd.concat([d, onehot], axis=1)
COLS = FEATS + list(onehot.columns)

tr = d[d.date < "2025-10-01"]
va = d[(d.date >= "2025-10-01") & (d.date < "2026-01-01")]
te = d[d.date >= "2026-01-01"]
print(f"특성 {len(COLS)}개 · train {len(tr)} / valid {len(va)} / test {len(te)}")

mu = tr[COLS].mean(); sigma = tr[COLS].std().replace(0, 1)
def to_tensor(frame):
    X = torch.tensor(((frame[COLS] - mu) / sigma).to_numpy(dtype=np.float32))
    X = torch.nan_to_num(X, nan=0.0)          # 표준화 후 결측은 0(=평균) 대치
    y = torch.tensor(frame.pm25_next.to_numpy(dtype=np.float32))
    return X, y

Xtr, ytr = to_tensor(tr); Xva, yva = to_tensor(va); Xte, yte = to_tensor(te)
train_dl = DataLoader(TensorDataset(Xtr, ytr), batch_size=64, shuffle=True)
```

실행 결과:

```
== A. MP2의 특성 그대로 (Day 065의 make_features) ==
특성 22개 · train 2268 / valid 452 / test 888
```

디테일: `torch.nan_to_num(X, nan=0.0)` — 표준화된 좌표에서 0은 곧 평균이므로, sklearn
파이프라인의 평균 대치와 같은 일을 텐서 세계에서 한 것입니다. sigma의 `replace(0, 1)` 은
상수 열(분산 0)에서 0으로 나누는 사고 방지입니다.

### 문제 2. 학습 — 표준 골격 그대로 (3~5교시)

```python
print("\n== B. 회귀 MLP 학습 (검증 감시 + 최고 시점 저장) ==")
model = nn.Sequential(
    nn.Linear(len(COLS), 64), nn.ReLU(),
    nn.Linear(64, 32), nn.ReLU(),
    nn.Linear(32, 1),
)
optimizer = torch.optim.Adam(model.parameters(), lr=0.001)
loss_fn = nn.MSELoss()

def valid_r2():
    model.eval()
    with torch.no_grad():
        p = model(Xva).squeeze(1)
    model.train()
    return r2_score(yva.numpy(), p.numpy())

best_r2, best_state, best_epoch = -9, None, 0
for epoch in range(1, 81):
    for xb, yb in train_dl:
        loss = loss_fn(model(xb).squeeze(1), yb)
        loss.backward()
        optimizer.step()
        optimizer.zero_grad()
    r2 = valid_r2()
    if r2 > best_r2:
        best_r2, best_epoch = r2, epoch
        best_state = {k: v.clone() for k, v in model.state_dict().items()}
    if epoch in (1, 5, 10, 20, 40, 80):
        print(f"  epoch {epoch:>2}: valid R² {r2:.3f}{'  ★ 최고 갱신' if epoch == best_epoch else ''}")

print(f"\n최고 시점: epoch {best_epoch} (valid R² {best_r2:.3f}) → 그 시점으로 복원")
model.load_state_dict(best_state)
```

실행 결과:

```
== B. 회귀 MLP 학습 (검증 감시 + 최고 시점 저장) ==
  epoch  1: valid R² -14.406
  epoch  5: valid R² -0.368  ★ 최고 갱신
  epoch 10: valid R² 0.192  ★ 최고 갱신
  epoch 20: valid R² 0.369  ★ 최고 갱신
  epoch 40: valid R² 0.369
  epoch 80: valid R² 0.373

최고 시점: epoch 50 (valid R² 0.433) → 그 시점으로 복원
```

로그를 읽어 봅시다. ① epoch 1의 R² **-14.4** — 무작위 초기화 모델은 평균 찍기보다 열네 배
나쁩니다([Day 054](../03-machine-learning/day-054.md)의 음수 R², 여기서 재회). ② 40~80 구간은
0.37 언저리 정체지만 **최고점은 epoch 50(0.433)** 에 숨어 있었습니다 — 우리가 로그를 찍은
에폭(40, 80) 사이에서요. 에폭마다 감시하고 최고를 저장하는 어제 과제의 패턴이 아니었다면
그냥 지나쳤을 지점입니다.

### 문제 3. 금고 개봉 — 최종 비교표 (6교시)

```python
print("\n== C. 금고 개봉 — sklearn 챔피언과 최종 비교 ==")
model.eval()
with torch.no_grad():
    p = model(Xte).squeeze(1).numpy()
print(f"| PyTorch MLP ({sum(p_.numel() for p_ in model.parameters())}개 파라미터) | R² {r2_score(yte.numpy(), p):.3f} | MAE {mean_absolute_error(yte.numpy(), p):.2f} |")
print(f"| sklearn 선형 파이프라인 (MP2 최종, Day 073)   | R² 0.519 | MAE 4.26 |")
print(f"| 내일=오늘 베이스라인 (Day 055)                | R² 0.207 | MAE 5.58 |")
```

실행 결과:

```
== C. 금고 개봉 — sklearn 챔피언과 최종 비교 ==
| PyTorch MLP (3585개 파라미터) | R² 0.509 | MAE 4.30 |
| sklearn 선형 파이프라인 (MP2 최종, Day 073)   | R² 0.519 | MAE 4.26 |
| 내일=오늘 베이스라인 (Day 055)                | R² 0.207 | MAE 5.58 |
```

**3,585개 파라미터의 신경망이 23개짜리 선형 회귀와 사실상 동률**(0.509 vs 0.519)입니다.
이 결과의 독법:

1. 신경망이 "안 되는" 게 아닙니다 — 베이스라인(0.207)은 가뿐히 넘었고, 선형이 뽑을 수 있는
   정보를 거의 다 뽑았습니다. **이 데이터의 신호 총량이 거기까지**라는 뜻입니다
   ([Day 064](../03-machine-learning/day-064.md): 성능은 정보가 정한다).
2. 그런데 비용은 다릅니다: 학습 시간, 튜닝 민감도(학습률·에폭·구조), 운영 복잡도 전부
   신경망이 비쌉니다. **같은 성능이면 싼 쪽** — MP2의 결론이 도구를 바꿔도 유효합니다.
3. 그럼에도 이번 주가 헛되지 않은 이유: 다음 주부터의 데이터(이미지)에서는 선형·트리가
   **아예 출전 불가**입니다. 오늘 만든 골격이 그 유일한 선수의 훈련 장비입니다.

## 주간 퀴즈 14 — W16 (PyTorch 기초)

<details>
<summary>1. 텐서의 세 속성과 각각의 대표 사고는?</summary>

shape(행렬곱 불일치·배치 차원), dtype(정수로 평균·미분 불가), device(CPU/GPU 혼용 에러).

</details>

<details>
<summary>2. 학습 루프의 5단계는?</summary>

① 순전파 model(x) → ② 손실 → ③ 역전파 backward() → ④ 갱신 optimizer.step() → ⑤ 초기화 zero_grad().

</details>

<details>
<summary>3. grad를 매 걸음 지워야 하는 이유는?</summary>

backward()는 기울기를 **누적**(+=)하므로, 안 지우면 이전 걸음들이 합산되어 보폭이 폭주합니다.

</details>

<details>
<summary>4. 학습률이 너무 클 때와 너무 작을 때의 증상은?</summary>

너무 크면 골짜기를 뛰어넘으며 발산(loss가 inf/nan), 너무 작으면 수렴이 하세월. 발산 직전보다 한두 단계 작은 값이 보통 효율적입니다.

</details>

<details>
<summary>5. 선형 회귀는 스케일링 없이도 같은 답인데(Day 053), 왜 경사하강에서는 표준화가 필수인가?</summary>

답(골짜기 바닥)은 같지만 **골짜기의 모양**이 달라집니다. 미정규화 입력은 협곡을 만들어 지그재그·발산을 유발하고, 표준화는 골짜기를 둥글게 해 큰 보폭으로 곧장 수렴하게 합니다.

</details>

<details>
<summary>6. 활성화 함수가 없으면 깊은 신경망은 무엇과 같아지나?</summary>

선형 변환의 합성은 선형이므로, 층수와 무관하게 선형 모델 하나와 같아집니다.

</details>

<details>
<summary>7. Dataset의 두 약속과 DataLoader의 역할 분담은?</summary>

Dataset: `__len__`(몇 건)·`__getitem__`(i번째 한 건). DataLoader: 인덱스를 섞고(shuffle) 묶어서(batch) 실어 나름.

</details>

<details>
<summary>8. "분할은 시간으로, 배치는 섞어서"의 뜻은?</summary>

train/valid/test 분할은 시간 기준이어야 누수가 없고(Day 052), 확정된 train 안에서 배치 순서를 섞는 것은 정보 유입이 아니며 오히려 기울기 쏠림을 막습니다.

</details>

<details>
<summary>9. model.eval()과 torch.no_grad()의 역할 차이는?</summary>

eval()은 드롭아웃·배치정규화 같은 **레이어의 동작 모드**를 평가용으로 전환, no_grad()는 **연산 기록(미분 준비)을 중단**해 메모리·속도를 아낌. 평가·추론에서는 둘 다 씁니다.

</details>

<details>
<summary>10. BCEWithLogitsLoss를 쓸 때 모델 출력에 시그모이드를 씌우면 안 되는 이유는?</summary>

이 손실 안에 시그모이드가 내장되어 있어 이중 적용이 됩니다. 모델은 로짓을 내고, 확률이 필요한 평가·서빙에서만 sigmoid를 씌웁니다.

</details>
