## 단원 개요

### 이 단원을 마치면

- 분류가 아닌 **회귀 문제**를 딥러닝으로 풀 수 있다.
- 정형 데이터를 대상으로 EDA → 이상치 제거 → 인코딩 → 분리 → 정규화의 전처리 전 과정을 수행할 수 있다.
- 학습 결과 그래프를 보고 **모델의 문제를 진단하고 다음 조치를 결정할 수 있다.**
- 회귀 지표(MAE/RMSE/R²)를 근거로 모델을 비교하고 하이퍼파라미터를 튜닝할 수 있다.

### 대단원 03과 무엇이 다른가

| | 대단원 03 머신러닝 | 대단원 04 딥러닝 |
|---|---|---|
| 데이터 | 이미지 (비정형) | 표 (정형) |
| 문제 | 분류 — "무엇인가?" | 회귀 — "얼마인가?" |
| 출력층 | Softmax / Sigmoid | 활성화 없음 (선형) |
| 손실 함수 | 크로스엔트로피 | MSE / MAE |
| 평가 | 정확도·F1·혼동행렬 | MAE·RMSE·R² |
| 이 단원의 초점 | 모델 구조 이해 | **전처리와 검증·튜닝 절차** |

이 단원의 핵심은 새 모델이 아니라 **"믿을 수 있는 결과를 만드는 절차"** 입니다.
전처리 순서 하나만 틀려도(예: 분할 전에 스케일링) 결과 전체가 무효가 되기 때문에, 절차의 정확성을 반복 훈련합니다.

> - 회귀 지표의 의미를 알고 상황에 맞게 고를 수 있다.
> - 교차검증으로 성능을 안정적으로 추정할 수 있다.
> - 하이퍼파라미터를 체계적으로 탐색할 수 있다.

| Day | 주제 | 1–4교시 (개념) | 5–8교시 (실습) | 과제 |
|---|---|---|---|---|
| **121** (월) | 회귀 평가 지표 | **MAE** — 평균 절대 오차, 단위가 원래 값과 같아 설명하기 쉬움 · **MSE / RMSE** — 큰 오차에 더 큰 벌점 · **R²** — 설명력, 음수가 나오는 경우 · **MAPE** — 비율 오차, 0 근처에서 폭발 · 지표별 장단점과 **문제에 맞는 선택**(가격 예측은 왜 MAE·MAPE를 함께 보는가) · 로그 변환한 타깃의 지표 해석 주의 | 실습: 네 지표 직접 구현 후 sklearn 결과와 대조 · 이상치를 넣었을 때 지표별 변화 관찰 · 동일 모델을 지표별로 다르게 평가해 순위 뒤바뀜 확인 | 지표 선택 가이드 작성 |
| **122** (화) | 교차검증 | 홀드아웃의 한계(운에 좌우됨) · KFold 원리 · `cross_val_score` / `cross_validate` · 반복 교차검증 · 평균과 표준편차를 함께 보고하기 · **교차검증 안에서 전처리하기**(Pipeline과 함께 써야 누수가 없다) · 계산 비용과 딥러닝에서의 현실적 타협 | 실습: 5-fold 교차검증으로 모델 3종 비교(평균±표준편차 보고) · Pipeline 없이 스케일링했을 때의 낙관 편향 재현 | 교차검증 비교표 |
| **123** (수) | 튜닝 대상 정리 | 하이퍼파라미터 vs 파라미터 · **튜닝 대상 목록과 영향도** — 학습률(가장 큼) / 층 수·노드 수 / 배치 크기 / 에폭(EarlyStopping으로 대체) / 드롭아웃 비율 / 옵티마이저 / 가중치 초기화 / 규제 강도 · 탐색 범위 정하기(로그 스케일) · **한 번에 하나씩 vs 동시 탐색** | 실습: 학습률만 5수준으로 바꿔 영향도 측정 → 배치 크기 → 구조 순으로 단계 탐색 · 영향도 순위 도출 | 튜닝 우선순위 정리 |
| **124** (목) | 탐색 방법 | 수동 탐색의 한계 · **그리드 서치** — 전수 조사, 조합 수 폭발 · **랜덤 서치** — 왜 랜덤이 그리드보다 효율적인가 · 베이지안 최적화 개념 · KerasTuner 사용법(`RandomSearch` / `Hyperband`) · 탐색 예산 관리(시간·조합 수 제한) · **탐색은 검증셋으로만** | 실습: KerasTuner로 자동 탐색 실행 → 상위 5개 조합 확인 → 수동 탐색 결과와 비교 · 랜덤 서치 vs 그리드 서치 효율 비교 | 자동 탐색 결과 리포트 |
| **125** (금) | 최종 모델 확정 | 확정 절차 — ① 검증셋으로 후보 선정 ② 전체 학습 데이터로 재학습 ③ **테스트셋 1회 평가** ④ 결과 보고 · 성능 보고 양식(지표 + 신뢰 범위 + 조건) · 과대 보고를 피하는 법 · 모델 카드 개념(용도·한계·데이터 출처) | **종합 실습**: W23~W25 전 과정을 하나의 데이터셋에 적용해 최종 모델 확정 · 모델 카드 작성 · **단원 실기 평가** | **주간 퀴즈 22** · 최종 모델 + 모델 카드 |

**주차 체크포인트** — "RMSE 3200원"이라는 결과에 어떤 조건을 함께 밝혀야 하는지 말할 수 있는가.

## 이 단원에서 자주 나오는 질문

| 질문 | 답 |
|---|---|
| 회귀인데 정확도(accuracy)가 0으로 나옵니다 | 회귀에는 정확도 지표가 없습니다. `metrics=['mae']` 등으로 바꾸세요. |
| loss가 `nan`이 됩니다 | 학습률 과다, 타깃에 결측/무한값, 정규화 누락이 주 원인입니다. 데이터에 `inf`가 없는지 먼저 확인하세요. |
| R²가 음수입니다 | 평균으로 예측한 것보다 못하다는 뜻입니다. 전처리 오류나 학습 실패를 의심하세요. |
| 검증 성능이 실행할 때마다 크게 달라집니다 | 검증셋이 작거나 seed가 고정되지 않았습니다. 교차검증으로 평균±표준편차를 보고하세요. |
| 원-핫 인코딩 후 열이 수천 개가 됐습니다 | 고카디널리티 범주입니다. 빈도 낮은 값을 '기타'로 묶거나 임베딩·타깃 인코딩을 검토하세요. |
| 테스트 성능이 검증 성능보다 훨씬 나쁩니다 | 검증셋을 보며 너무 많이 튜닝했거나(검증셋 과적합), 분할이 편향됐습니다. |
