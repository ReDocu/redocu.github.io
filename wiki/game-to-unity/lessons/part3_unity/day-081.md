## 3. 개념

### 3-1. 3D 애셋의 구성

**왜 필요한가** — 무엇이 들어 있는지 알아야 설정을 이해한다.

```
   FBX 파일 하나 안에

   ┌─────────────────────────────────────┐
   │  Mesh          모양 (정점, 삼각형)   │
   │  Material      표면 정보 참조        │
   │  Texture       이미지 (보통 별도)    │
   │  Skeleton      뼈대 (Rig)            │
   │  Skin Weight   각 정점이 어느 뼈를   │
   │                얼마나 따를지          │
   │  Animation     클립 (뼈의 시간별 변화)│
   └─────────────────────────────────────┘
```

```
   ★ 스키닝 (Skinning)

   뼈가 움직이면 → 웨이트에 따라 정점이 따라간다

   팔꿈치 근처 정점
   ├─ 상완골 0.6
   └─ 전완골 0.4
   → 두 뼈의 중간쯤 움직인다 (부드럽게 접힌다)
```

```
   ★ Part 2와의 차이

   2D 스프라이트:  그려진 그림을 순서대로 보여준다
   3D 스키닝:      뼈를 움직이면 메시가 실시간으로 변형된다

   → 3D는 모션을 "공유"할 수 있다 (뼈 구조가 같다면)
```

### 3-2. 임포트 탭 4개

**왜 필요한가** — 각 탭이 다른 것을 설정한다.

| 탭 | 설정 대상 |
|---|---|
| **Model** | 메시, 스케일, 법선, 최적화 |
| **Rig** | 뼈대 타입, 아바타 |
| **Animation** | 클립 자르기, 루프, 루트 모션 |
| **Materials** | 머티리얼 추출·연결 |

```
   ⚠️ 설정을 바꾸면 반드시 Apply

   누르지 않으면 반영 안 된다
   → 다른 애셋을 선택하면 "변경사항을 적용할까요?" 팝업
```

### 3-3. Model 탭 — 스케일

**왜 필요한가** — 크기가 이상한 이유.

```
   ★ 단위 불일치

   Unity:      1 유닛 = 1 미터
   Blender:    1 유닛 = 1 미터  (보통)
   3ds Max:    1 유닛 = 1 인치 또는 cm
   Maya:       1 유닛 = 1 cm
```

| 필드 | 의미 |
|---|---|
| **Scale Factor** | 임포트 시 곱할 배율 |
| **Convert Units** | 원본 단위를 자동 변환 |
| Bake Axis Conversion | 축 방향 변환을 메시에 굽기 |

```
   ★ 확인 방법

   캐릭터를 씬에 놓고 1×1×1 큐브 옆에 세운다

   사람 = 약 1.7~1.8 유닛이면 정상

        ┌─┐
        │●│  1.75
        │ │      ┌─┐
        │ │      │ │ 1.0
   ▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓
```

```
   ⚠️ Transform Scale로 조절하지 않는다

   캐릭터의 Scale을 0.01로 두면
   → 물리, NavMesh, 파티클이 전부 어긋난다

   ★ Scale Factor(임포트 설정)로 맞춘다
```

**Model 탭 주요 옵션**

| 필드 | 권장 |
|---|---|
| Mesh Compression | Off (품질 우선) |
| **Read/Write** | ✗ (메모리 절약. 런타임 메시 수정 시만 ✔) |
| Optimize Mesh | ✔ |
| **Import BlendShapes** | 표정이 있으면 ✔ |
| Import Visibility | 보통 ✗ |
| **Import Cameras/Lights** | ✗ |
| Normals | Import (없으면 Calculate) |
| Tangents | Calculate Mikktspace |

```
   ★ Read/Write Enabled

   켜면 메시가 CPU 메모리에도 올라간다 → 2배
   → 런타임에 메시를 코드로 수정할 때만 켠다
```

### 3-4. Rig 탭 — Animation Type

**왜 필요한가** — 오늘 가장 중요한 설정.

| 타입 | 설명 | 용도 |
|---|---|---|
| **None** | 뼈 없음 | 배경 소품 |
| **Legacy** | 구식 애니메이션 | 사용 안 함 |
| **Generic** | 뼈대가 있지만 인간형 아님 | 동물, 기계, 문 |
| **Humanoid** | **인간형 표준 뼈대** | **캐릭터** ★ |

```
   ★ Humanoid의 핵심 — 리타게팅

   서로 다른 캐릭터가 같은 모션을 쓸 수 있다

   [모델 A]        [Humanoid 아바타]        [모델 B]
   Bip01_Spine  ──▶   Spine       ◀──   spine_01
   Bip01_L_Arm  ──▶   LeftArm     ◀──   arm_l
   Bip01_Head   ──▶   Head        ◀──   head_jnt

   → 뼈 이름이 달라도 "표준 이름"으로 매핑
   → Mixamo 모션을 아무 캐릭터에나 적용 가능
```

```
   ★ 아바타 (Avatar)

   "이 모델의 뼈 ↔ 표준 인간형 뼈"의 매핑표
```

| Avatar Definition | 의미 |
|---|---|
| **Create From This Model** | 이 모델로 새 아바타 생성 |
| **Copy From Other Avatar** | 다른 모델의 아바타 재사용 |

```
   ★ 실무 패턴

   Hero.fbx          → Create From This Model  (아바타 생성)
   Hero@Idle.fbx     → Copy From Other Avatar (Hero_Avatar)
   Hero@Walk.fbx     → Copy From Other Avatar
   Hero@Attack.fbx   → Copy From Other Avatar

   → 모션 파일은 아바타를 공유한다
```

```
   ⚠️ 각 모션 파일이 자기 아바타를 만들면

   → 미묘하게 다른 매핑
   → 모션이 어긋난다
```

### 3-5. Configure — 뼈 매핑 확인

**왜 필요한가** — 자동 매핑이 실패할 때.

```
   Rig 탭 → Configure... 클릭
   → 아바타 편집 모드로 들어간다
```

```
   ┌─────────────────────────────┐
   │        [Head]               │
   │           ●                 │
   │    ●──────┼──────●          │  ● = 필수 뼈 (초록)
   │  Left    Spine   Right      │  ○ = 선택 뼈 (회색)
   │  Arm             Arm        │  ✗ = 매핑 실패 (빨강)
   │           ●                 │
   │      ●────┴────●            │
   │   Left       Right          │
   │   Leg         Leg           │
   └─────────────────────────────┘
```

```
   ★ 필수 뼈 15개

   Hips, Spine, Head
   Left/Right Upper Arm, Lower Arm, Hand
   Left/Right Upper Leg, Lower Leg, Foot
```

```
   ⚠️ 매핑 실패 시

   ① 빨간 항목 클릭
   ② Hierarchy에서 해당 뼈를 드래그
   ③ Apply

   또는 Mapping → Automap 재시도
```

```
   ★ Muscles & Settings 탭

   각 관절의 회전 한계를 조절
   → 팔이 이상하게 꺾이는 것을 방지
```

### 3-6. Animation 탭 — 클립 설정

**왜 필요한가** — 반복·이동 처리.

| 필드 | 의미 |
|---|---|
| **Loop Time** | 반복 재생 |
| Loop Pose | 시작·끝 포즈를 자연스럽게 연결 |
| Cycle Offset | 루프 시작 지점 |
| **Root Transform Rotation** | 회전을 애니가 담당할지 |
| **Root Transform Position (Y)** | 상하 이동 |
| **Root Transform Position (XZ)** | 전후좌우 이동 ★ |
| Start / End | 클립 자르기 (프레임) |

```
   ★ Bake Into Pose

   체크 = 애니메이션이 그 축을 담당하지 않는다
        = 루트가 그 축으로 안 움직인다

   보통
   Rotation      Bake ✔  (코드가 회전 담당)
   Position Y    Bake ✔  (점프가 아니면)
   Position XZ   Bake ✗  (루트 모션 사용 시)
                 Bake ✔  (코드 이동 시)
```

```
   ⚠️ 제자리 걷기 애니메이션인데 캐릭터가 앞으로 나간다

   → Position XZ의 Bake Into Pose를 체크
```

```
   ⚠️ 반대로 제자리에서 미끄러진다

   → 이동 속도와 애니 속도가 안 맞는다 (Day 83에서 다룸)
```

**클립 자르기**

```
   ★ 한 FBX에 여러 모션이 들어 있는 경우

   Clips 목록에서 +
   Name: Idle,   Start 0,   End 60
   Name: Walk,   Start 61,  End 120
   Name: Attack, Start 121, End 165
```

### 3-7. Materials 탭 — URP 변환

**왜 필요한가** — 분홍색 해결.

```
   ★ 분홍색 = 셰이더를 못 찾음

   FBX의 머티리얼은 Standard 셰이더를 참조한다
   URP 프로젝트에는 Standard가 없다
```

| Material Creation Mode | 의미 |
|---|---|
| None | 머티리얼 안 만듦 |
| **Standard** | 기본 |
| Import via MaterialDescription | FBX 정보 최대한 반영 |

| Location | 의미 |
|---|---|
| Use Embedded Materials | FBX 안에 포함 (수정 불가) |
| **Use External Materials** | 별도 애셋으로 추출 ★ |

```
   ★ 해결 절차

   ① Materials 탭 → Extract Materials... → 폴더 지정
   ② 추출된 머티리얼 선택
   ③ Shader → Universal Render Pipeline/Lit

   또는

   Edit → Rendering → Materials
   → Convert Selected Built-in Materials to URP
```

```
   ⚠️ 텍스처 연결 확인

   추출 후에도 Base Map이 비어 있으면
   → 텍스처를 수동으로 드래그
```

### 3-8. 텍스처 임포트

**왜 필요한가** — 색이 이상한 이유.

| 텍스처 종류 | sRGB | 설명 |
|---|:--:|---|
| **Base/Albedo** | ✔ | 기본 색 |
| **Normal Map** | ✗ | Texture Type을 **Normal map**으로 |
| Metallic/Smoothness | ✗ | 선형 데이터 |
| Occlusion | ✗ | |
| Emission | ✔ | |

```
   ⚠️ Normal Map을 Default로 두면

   "This texture is not marked as a normal map" 경고
   → 표면이 이상하게 보인다
   → Texture Type: Normal map 으로 변경
```

```
   ⚠️ Metallic 맵에 sRGB가 켜져 있으면

   금속감이 과하거나 부족해진다
   → sRGB (Color Texture) 체크 해제
```

### 3-9. Mixamo 워크플로

**왜 필요한가** — 무료로 캐릭터와 모션을 구한다.

```
   mixamo.com  (Adobe 계정 필요, 무료)

   ① Characters 탭에서 캐릭터 선택
   ② Animations 탭에서 모션 검색
   ③ Download
      Format: FBX for Unity(.fbx)
      Skin:   With Skin (캐릭터) / Without Skin (모션만)
      Frames per Second: 30
      Keyframe Reduction: none
```

```
   ★ 다운로드 전략

   ① 캐릭터 1개를 "With Skin"으로 (T포즈)
   ② 모션들을 "Without Skin"으로

   → 파일 크기가 훨씬 작다
```

```
   ⚠️ Mixamo 임포트 시 흔한 문제

   ① 크기: Scale Factor 0.01 필요할 수 있다 → 확인
   ② 머티리얼: 분홍색 → URP 변환
   ③ 텍스처: 별도 폴더에 압축돼 있다 → 추출
   ④ Rig: Humanoid로 설정 (기본은 보통 Generic)
```

```
   ★ 파일 이름 규칙

   Hero.fbx           캐릭터 (With Skin)
   Hero@Idle.fbx      모션
   Hero@Walk.fbx

   @ 앞이 같으면 Unity가 자동으로 연결해 준다 (Legacy 방식의 흔적)
   → 필수는 아니지만 정리에 좋다
```

### 3-10. 다른 무료 애셋 출처

**왜 필요한가** — 선택지를 안다.

| 출처 | 특징 |
|---|---|
| **Mixamo** | 인간형 캐릭터 + 모션. 무료 |
| **Kenney.nl** | 로우폴리, CC0 (완전 무료) |
| Unity Asset Store | 무료 섹션 다수 |
| Quaternius | 로우폴리 CC0 |
| Sketchfab | CC 라이선스 확인 필요 |

```
   ⚠️ 라이선스를 반드시 확인한다

   CC0        완전 자유
   CC-BY      출처 표기 필요
   CC-BY-NC   상업적 사용 금지
   Asset Store EULA  Unity 프로젝트 내 사용
```

```
   ★ 포트폴리오에도 애셋 출처를 적는다

   "3D 모델: Kenney (CC0), 애니메이션: Mixamo"
   → 정직함이 신뢰를 만든다
```

```
   ① 재생 버튼으로 확인
   ② 미리보기 창에 캐릭터 모델을 드래그하면
      그 모델로 재생된다  ★ 리타게팅 확인
```

```
   ★ 리타게팅 확인 방법

   Walk.fbx (Without Skin, 뼈만) 선택

```

```
   ⚠️ 미리보기에서 이상하면

   ① 아바타가 다르다 (Copy From Other Avatar 확인)
   ② 뼈 매핑이 잘못됐다 (Configure)
   ③ 스케일이 안 맞는다
```

## 4. 따라 만들기

### Step 1 — 새 씬과 폴더

```
   File → New Scene → Basic (URP)
   Scenes/Action.unity 로 저장
   Build Settings에 추가
```

```
   Assets/Art/
   ├─ Characters/
   ├─ Animations/
   ├─ Materials/
   └─ Textures/
```

### Step 2 — 캐릭터 받기

```
   mixamo.com 접속

   ① Characters → 아무 캐릭터 선택 (예: "Y Bot" 또는 "X Bot")
   ② Download
      Format: FBX for Unity(.fbx)
      Pose:   T-pose
   ③ Assets/Art/Characters/ 에 넣는다
```

```
   ★ Y Bot / X Bot 을 추천하는 이유

   ① 텍스처가 없어 머티리얼 문제가 적다
   ② 파일이 작다
   ③ Mixamo 표준 리그라 매핑이 확실하다
```

**✅ 여기까지 하면** — Project에 FBX가 보인다.

### Step 3 — 씬에 놓기 (문제 확인)

**FBX를 Hierarchy로 드래그한다.**

**✅ 여기까지 하면**

```
   ★ 이 중 하나 이상이 발생한다

   ① 분홍색
   ② 크기가 이상함
   ③ T포즈로 굳어 있음 (정상 — 아직 애니메이션이 없다)
```

### Step 14 — 클립 설정 (Walk / Run)

```
   Loop Time: ✔
   Root Transform Rotation: Bake ✔
   Root Transform Position (Y): Bake ✔
   Root Transform Position (XZ): Bake ✔     ← 코드로 이동할 것이므로
   → Apply
```

```
   ★ XZ를 Bake 하는 이유

   Bake ✔ = 애니메이션이 앞으로 밀지 않는다 (제자리 걷기)
          = 코드가 이동을 담당한다

   Bake ✗ = 애니메이션이 캐릭터를 앞으로 민다 (루트 모션)
          → Day 83에서 다룬다
```

**Bake를 해제하고 미리보기를 본다.**

```
   → 캐릭터가 미리보기 밖으로 걸어 나간다
```

> **다시 체크한다.**

```
   Root Transform Rotation:  Bake ✔
   Root Transform Position (Y): Bake ✔
   Root Transform Position (XZ): Bake ✗       ★ 앞으로 나가는 동작 유지
   → Apply
```

```
   ★ 공격 시 살짝 전진하는 것은 자연스럽다
     루트 모션을 쓰는 대표적인 경우
```

### Step 16 — 클립 자르기

```
   Attack 클립의 Start/End 를 조절한다

   미리보기를 보며
   → 준비 동작이 너무 길면 Start를 늘린다
   → 마무리가 늘어지면 End를 줄인다
```

```
   ★ 액션 게임의 공격 클립 구성

   준비(Anticipation) → 타격(Impact) → 마무리(Recovery)

   프레임 0        10        20        40
        │─────────│─────────│─────────│
        준비        타격      마무리

   ⚠️ 준비가 길면 답답하다
     → 앞부분을 자르거나 재생 속도를 올린다
```

**✅ 여기까지 하면** — 4개 클립이 준비된다.
