# 학습문서(Study Note) 생성 프롬프트

MBC아카데미 학습문서 5종과 같은 "데이터 리포트 / 노트북 스타일" 문서를 뽑아내는 재사용 프롬프트.
결과물은 사이트 셸(layout `academy-doc`) 안에 들어가는 **본문 조각 HTML**이다.

**사용법**
1. 아래 `[입력 정보]`의 빈칸을 채운다. (모르는 항목은 비워두면 AI가 임의로 채우고 `[확인 필요]`로 표시한다)
2. `──── 여기서부터 복사 ────` 아래 전체를 복사해서 Claude에게 붙여넣는다.
3. 결과를 `academy/<학원>/<slug>-notes.html`로 저장하고, 같은 폴더의 `index.md`에서 링크한다.
   스타일은 `assets/css/academy-doc.css`(공통) + `assets/css/adoc-<학원>.css`(학원별)가 레이아웃에서 자동으로 붙는다. 다른 학원에 쓸 때는 해당 `adoc-<학원>.css`에 같은 클래스가 있는지 확인한다.

---

──── 여기서부터 복사 ────

너는 개발 포트폴리오용 학습문서(기술문서)를 만드는 퍼블리셔다.
아래 [출력 형식]과 [문서 골격]을 **정확히** 따라, Jekyll front matter + 본문 HTML로 된 `.html` 파일 **하나**를 생성하라.

## 입력 정보

- 학원(family): 예) mbc
- 문서 제목(h1, 2줄 분리 지점 포함):
- 짧은 문서명(브레드크럼용): 예) 늑대 vs 허스키
- 프로젝트 한 줄 소개(description):
- 기관·과정명(아이브로우, 영문 대문자 병기): 예) MBC컴퓨터아카데미 · MACHINE LEARNING
- 문서 번호 / 전체 수: 예) 03 / 05
- 문서 보조색(--ch): 예) #a78bfa
- 요약 타일 4개(기간/스택/방법론 등): 예) 4일 · TensorFlow · CNN · 2 classes
- 관련 PDF(또는 다운로드) 경로(사이트 절대경로): 없으면 "없음"
- 프로젝트에서 실제 한 일(개조식 메모, 상세할수록 좋다):
- 배운 점·회고(있으면):
- 코드 스니펫으로 보여줄 핵심 기술 2~3개:

## 출력 형식

- 파일 맨 위 front matter (순서 그대로):
  ```yaml
  ---
  layout: academy-doc
  title: "<짧은 문서명> — 학습문서"
  description: "<한 줄 소개>"
  family: <학원>
  css: [adoc-<학원>]
  crumb: [[MBC, /academy/mbc/], ["<짧은 문서명>"]]
  render_with_liquid: false
  ---
  ```
- 그 아래는 **본문 조각만**. `<!DOCTYPE>`·`<html>`·`<head>`·`<body>`·`<main>`은 쓰지 않는다(사이트 레이아웃이 감싼다).
- 자체 topbar·돌아가기 링크·테마 토글·진행 바·`<script>`·`<style>`·`<link>`를 넣지 않는다. 내비게이션·다크모드는 사이트가 맡는다.
- 색은 하드코딩하지 않고 사이트 토큰(`--bg` `--surface` `--line` `--text` `--muted` `--accent` 등)을 따르는 기존 클래스만 쓴다. 문서별 색은 루트 `.mdoc`의 `style="--ch:<보조색>"` 하나뿐이다.
- 외부 CDN·웹폰트·이미지 없이 자급자족할 것. 링크는 사이트 절대경로(`/academy/...`)로 쓴다.

## 문서 골격 (순서 고정)

전체를 `<div class="mdoc" style="--ch:<보조색>">` … `</div>` 하나로 감싼다.

1. **문서 번호** — `<p class="doc-id">STUDY NOTE · NN / NN</p>`
2. **hero** — `<header class="hero">`:
   - `.eyebrow`: 기관·과정명 (영문 대문자)
   - `h1`: 2줄 제목(`<br>`), 핵심 키워드 줄은 `<span class="grad">`
   - `.lead`: 3~4문장 요약 (무엇을·왜·어떻게)
   - `.chips`: 팀 형태 칩(`<span class="chip"><span class="dot"></span><b>…</b></span>`) + 주제 칩 + PDF 링크 칩(`a.chip`, 📄 아이콘, `target="_blank" rel="noopener"`)
   - `.stats`: `.stat` 타일 4개 — `.v`(값, 단위는 `<small>`) + `.k`(라벨)
3. **섹션 01 · 개요** — `<section id="…">` 안에 `.sec-head`(`<span class="n">01</span><h2>…</h2>`), `.sec-desc` 서술, `<div class="tbl"><table>…</table></div>`로 항목(목표/역할/데이터/기능 등) 정리. 학습 목표가 있으면 `.goal-box`(h4 + ul)를 표 앞에 둔다
4. **섹션 02 · 진행 과정** — `.pipeline` 안에 `.pipe` 카드 4개: `.t`(`<span class="idx">P1</span>` + 제목) + `<p>` 1문장. 프로젝트 흐름(수집→전처리→분석→도출 / 설계→구현→검증→폴리싱 등)에 맞게
5. **섹션 03 · 핵심 개념** — `.grid2` 안에 `.concept` 카드 4개. 각 카드: h3 제목 + `<ul>`의 li 3개(각 li에 `<b>` 강조 1개 내외, 필요시 `<code>`)
6. **섹션 04 · 구현/분석/실험 노트** — `.cell` 2~3개. 각 셀: `.cell-head`(`<span class="in">In [n]</span>` + `<span class="cap">무엇을 — 왜</span>`) + `<pre>` 코드
7. **섹션 05 · 배운 점 & 회고** — `ul.klist` 3~4개 + 마지막에 `.callout`(`<span class="ico">💡</span><p><span class="tt">한 줄 정리</span>…</p>`). 함정·실패담이 있으면 ⚠️ 콜아웃(`.tt`는 "함정")을 klist 앞에 추가
8. **footer** — `.mdoc` 직속 `<footer>`: 왼쪽 `<span>기관명 · 학습문서 NN</span>` / 오른쪽 `<span><a>프로젝트 PDF ↗</a></span>`(PDF 없으면 생략)

섹션 하위 제목이 필요하면 `<h3 class="sub"><span class="m">01-A</span>제목</h3>`, 표·카드 밖 서술 문단은 `<p class="prose">`를 쓴다.

## 콘텐츠 작성 규칙

- 문체는 개조식이 아닌 **짧은 완결형 "~했다" 체**. 과장·수식어 금지.
- 배운 점은 **"교훈 한 문장(볼드) + 부연 한 문장"** 구조. 예) `<b>모델보다 데이터가 먼저다.</b> 크롤링한 데이터의 품질·편향이 정확도에 그대로 반영됐다.`
- "한 줄 정리" 콜아웃은 이 프로젝트가 **전체 성장 서사에서 어떤 계단이었는지** 한 문장으로 연결한다.
- 코드는 실제 코드의 **핵심 아이디어만 남긴 요약본**(셀당 15줄 이내). 하이라이트는 `<span class="kw">`(키워드) `<span class="fn">`(함수/클래스명) `<span class="st">`(문자열) `<span class="nm">`(숫자/데코레이터) `<span class="cm">`(주석)으로 수동 마크업. `<` `>` `&`는 반드시 `&lt;` `&gt;` `&amp;`로 이스케이프.
- 입력 정보에 없는 내용은 그럴듯하게 채우되, 창작한 사실은 답변 끝에 **"[확인 필요] 목록"**으로 정리해 사용자가 검토하게 한다.
- 보조색은 문서당 하나만 쓴다. 시리즈로 만들 때는 문서마다 다른 색(예: #38bdf8 / #10b981 / #a78bfa / #818cf8 / #f59e0b)을 배정한다.

## 참고
