## ① 학습 목표

이 레슨을 마치면 이렇게 할 수 있습니다.

- `COUNT` · `SUM` · `AVG` · `MIN` · `MAX` 로 여러 행을 **한 줄로 요약**할 수 있다.
- `GROUP BY` 로 그룹별 집계를 만들고, `HAVING` 으로 **그룹을 걸러낼** 수 있다.
- `WHERE` 와 `HAVING` 의 차이를 실행 순서로 설명할 수 있다.
- `CASE` 표현식으로 값을 **구간화·분류**해 집계 축을 직접 만들 수 있다.

## ② 왜 필요한가

어제까지는 **행을 골라내는** 일만 했습니다. 그런데 실무에서 오는 질문은 이런 모양입니다.

| 질문 | 어제까지의 도구로는 |
|---|---|
| "이번 달 매출이 얼마죠?" | 행을 다 뽑아서 사람이 더해야 함 |
| "카테고리별로 몇 개씩 팔렸나요?" | 카테고리마다 쿼리를 따로 실행 |
| "주문 3건 이상 한 단골이 몇 명인가요?" | 불가능 |

**질문에 대한 답은 대부분 "행"이 아니라 "숫자 하나" 또는 "그룹별 숫자"입니다.**
그걸 만드는 것이 오늘의 집계(aggregate)입니다.

그리고 이것은 **DB에서 해야** 합니다.

```
❌ 3천만 행을 Python으로 가져와서 sum()      →  8GB 전송, 3분
✅ SELECT SUM(...) — DB가 계산해 숫자 1개만 →  8바이트 전송, 0.2초
```

[Day 024](../01-python-data/day-024.md)의 `df.groupby("category")["price"].sum()` 과 하는 일이 똑같습니다.
다만 **데이터를 옮기지 않고 계산**한다는 점이 다릅니다. MLOps에서 이 차이가 곧 비용입니다.

> **오늘은 테이블 하나 안에서만 집계합니다.**
> "카테고리별 매출"처럼 `products` 와 `order_items` 를 같이 봐야 하는 질문은 내일([Day 034](day-034.md)) `JOIN` 을 배운 뒤에 풉니다.

## ③ 개념 설명

### 집계 함수 5총사

| 함수 | 하는 일 | NULL 처리 |
|---|---|---|
| `COUNT(*)` | **행 개수** | NULL이든 뭐든 무조건 셈 |
| `COUNT(열)` | 그 열이 **NULL이 아닌** 행 개수 | **NULL은 안 셈** ★ |
| `COUNT(DISTINCT 열)` | 서로 다른 값의 개수 | NULL은 안 셈 |
| `SUM(열)` · `AVG(열)` | 합계 · 평균 | **NULL은 무시하고 계산** |
| `MIN(열)` · `MAX(열)` | 최솟값 · 최댓값 | NULL 무시 |

`COUNT(*)` 와 `COUNT(열)` 의 차이가 오늘의 첫 함정입니다.

```
customers 12명 중 phone이 NULL인 사람 3명

COUNT(*)      →  12   (행을 셈)
COUNT(phone)  →   9   (값이 있는 것만 셈)
```

**"전화번호를 등록한 고객 수"** 를 구하려면 `COUNT(phone)` 이 맞습니다.
`COUNT(*)` 로 세고 "고객의 100%가 전화번호를 등록했다"고 보고하는 사고가 여기서 납니다.

`AVG` 도 마찬가지입니다. **NULL은 0이 아니라 "없는 것"으로 취급**되어 분모에서도 빠집니다.

```
값이 [10, 20, NULL] 일 때
  AVG  →  (10+20) / 2 = 15      ← 분모가 2
  0으로 채웠다면  (10+20+0) / 3 = 10
```

어느 쪽이 맞는지는 **데이터의 의미**가 정합니다. "미응답"이면 15가, "0점"이면 10이 맞습니다.
헷갈리면 `AVG(COALESCE(열, 0))` 처럼 **의도를 코드에 드러내세요.**

### `GROUP BY` — 묶어서 세기

```sql
SELECT category, COUNT(*), AVG(price)
FROM products
GROUP BY category;
```

```
products 12행                      결과 3행
┌──────────────────┐
│ 전자기기 ...  5개│  ──┐
│ 사무용품 ...  4개│  ──┼──▶  전자기기 | 5 | 94200
│ 생활용품 ...  3개│  ──┘      사무용품 | 4 | 16425
└──────────────────┘           생활용품 | 3 | 21666.67
```

**`GROUP BY` 를 쓰면 결과 한 줄이 그룹 하나가 됩니다.** 그래서 규칙이 하나 생깁니다.

> **`SELECT` 에는 ① `GROUP BY` 에 적은 열 또는 ② 집계 함수만 올 수 있습니다.**

```sql
-- ❌ name 은 그룹마다 5개씩 있는데 한 줄에 뭘 써야 하나?
SELECT category, name, COUNT(*) FROM products GROUP BY category;
--     ERROR: column "products.name" must appear in the GROUP BY clause
--            or be used in an aggregate function
```

이 에러는 **문법 실수가 아니라 논리 질문**입니다. DB가 "그 열은 대표값이 뭐냐"고 묻는 것입니다.
답이 "아무거나"라면 `MIN(name)`, "전부 보고 싶다"면 `STRING_AGG(name, ', ')` 를 씁니다.

```sql
SELECT category, COUNT(*), STRING_AGG(name, ', ' ORDER BY name) AS 상품들
FROM products GROUP BY category;
```

`GROUP BY` 는 **NULL도 하나의 그룹**으로 만듭니다. `WHERE` 와 정반대라 헷갈리기 쉽습니다.

### `HAVING` — 그룹을 거르기

| 구문 | 무엇을 거르나 | 언제 실행되나 |
|---|---|---|
| `WHERE` | **행**을 거른다 | 그룹 만들기 **전** |
| `HAVING` | **그룹**을 거른다 | 그룹 만든 **후** |

```
FROM  →  WHERE  →  GROUP BY  →  HAVING  →  SELECT  →  ORDER BY  →  LIMIT
 ①        ②          ③           ④         ⑤          ⑥           ⑦
```

그래서 이렇게 나뉩니다.

```sql
SELECT customer_id, COUNT(*) AS 주문수
FROM orders
WHERE  status <> 'cancelled'   -- ② 취소 건은 세기 전에 제외 (행 조건)
GROUP BY customer_id           -- ③
HAVING COUNT(*) >= 3           -- ④ 3건 이상인 고객만 (그룹 조건)
ORDER BY 주문수 DESC;          -- ⑥
```

**집계 결과에 조건을 걸고 싶으면 `HAVING`, 원본 행에 조건을 걸고 싶으면 `WHERE`.**
`WHERE COUNT(*) >= 3` 은 에러입니다. `WHERE`(②) 시점엔 아직 세지도 않았기 때문입니다.

> **성능 요령** — 같은 결과를 낼 수 있다면 `WHERE` 로 먼저 줄이는 쪽이 항상 빠릅니다.
> `HAVING` 은 이미 다 세어 놓은 뒤에 버리는 것이라 낭비가 생깁니다.

### `CASE` — 내가 만드는 집계 축

원본 테이블에 없는 기준으로 묶고 싶을 때 씁니다. **`if / elif / else` 의 SQL 버전**입니다.

```sql
CASE
    WHEN price <  10000 THEN '저가'
    WHEN price < 50000 THEN '중가'
    ELSE                     '고가'
END
```

| 규칙 | 설명 |
|---|---|
| **위에서부터** 먼저 맞는 `WHEN` 하나만 실행 | 조건이 겹쳐도 앞의 것이 이깁니다 |
| `ELSE` 가 없고 아무 것도 안 맞으면 | 결과는 `NULL` (**빠뜨리기 쉬운 함정**) |
| `SELECT` · `GROUP BY` · `ORDER BY` 어디든 올 수 있다 | 하나의 값이므로 |

집계와 섞으면 **가로 방향 집계**가 됩니다. Pandas의 `pivot_table` 과 같은 일입니다.

```sql
SUM(CASE WHEN status = 'cancelled' THEN 1 ELSE 0 END)   -- 취소 건수
COUNT(*) FILTER (WHERE status = 'cancelled')            -- 같은 뜻, PostgreSQL 전용 (더 읽기 쉬움)
```

### 정수 나눗셈 함정

```sql
SELECT SUM(price) / COUNT(*) FROM products;   -- 50141   ← 소수점이 잘림
SELECT AVG(price)            FROM products;   -- 50141.666...
```

`integer / integer` 는 **정수 나눗셈**이라 소수점 아래가 버려집니다.
"결제 성공률"을 이렇게 계산하면 **항상 0** 이 나옵니다. `* 1.0` 을 곱하거나 `::numeric` 으로 바꾸세요.

```sql
SELECT COUNT(*) FILTER (WHERE status = 'delivered') * 100.0 / COUNT(*) AS 배송완료율
FROM orders;
```

### Step 6. `HAVING` — 그룹 거르기

**주문 3건 이상 한 단골 고객**입니다.

```
shop=# SELECT customer_id, COUNT(*) AS 주문수
shop-# FROM orders
shop-# GROUP BY customer_id
shop-# HAVING COUNT(*) >= 3
shop-# ORDER BY 주문수 DESC, customer_id;
 customer_id | 주문수
-------------+--------
           1 |      5
           2 |      5
           4 |      4
           5 |      3
           8 |      3
(5 rows)
```

`WHERE` 와 `HAVING` 을 함께 씁니다. **취소 건은 세기 전에 빼고** 다시 구합니다.

```
shop=# SELECT customer_id, COUNT(*) AS 유효주문수
shop-# FROM orders
shop-# WHERE status <> 'cancelled'
shop-# GROUP BY customer_id
shop-# HAVING COUNT(*) >= 3
shop-# ORDER BY 유효주문수 DESC, customer_id;
 customer_id | 유효주문수
-------------+------------
           1 |          5
           2 |          5
           4 |          3
           5 |          3
           8 |          3
(5 rows)
```

앞 쿼리에서 4건이던 최수아(4)님이 **3건으로 줄었습니다.** 원본 행을 열어 확인해 봅니다.

```
shop=# SELECT order_id, ordered_at, status FROM orders
shop-# WHERE customer_id = 4 ORDER BY order_id;
 order_id | ordered_at |  status
----------+------------+-----------
        5 | 2025-02-02 | delivered
       12 | 2025-03-12 | cancelled
       21 | 2025-05-06 | delivered
       29 | 2025-06-20 | shipped
(4 rows)
```

12번 주문이 취소라 `WHERE` 단계에서 빠졌고, 남은 3건이 세어졌습니다. 숫자가 설명됩니다.

> **집계 쿼리를 디버깅하는 방법은 하나뿐입니다 — 묶기 전 원본 행으로 돌아가는 것.**
> 결과가 예상과 다르면 `GROUP BY` 를 지우고 `WHERE 그룹키 = 값` 으로 해당 그룹의 행을 직접 보세요. 10초면 됩니다.

### Step 7. `CASE` — 가격 구간화

```
shop=# SELECT name, price,
shop-#        CASE WHEN price <  10000 THEN '저가'
shop-#             WHEN price <  50000 THEN '중가'
shop-#             ELSE                     '고가'
shop-#        END AS 가격대
shop-# FROM products
shop-# ORDER BY price;
      name      | price  | 가격대
----------------+--------+--------
```

## ⑤ 자주 하는 실수

### `column "products.name" must appear in the GROUP BY clause`

```
shop=# SELECT category, name, COUNT(*) FROM products GROUP BY category;
ERROR:  column "products.name" must appear in the GROUP BY clause or be used in an aggregate function
LINE 1: SELECT category, name, COUNT(*) FROM products GROUP BY categ...
                         ^
```

**원인** — 결과 한 줄이 그룹 하나인데, `name` 은 그룹마다 여러 개입니다. DB가 "뭘 보여줄까?"를 못 정합니다.
**해결** — 의도에 따라 셋 중 하나를 고릅니다.

```sql
SELECT category, COUNT(*) FROM products GROUP BY category;                    -- name 을 뺀다
SELECT category, MAX(name), COUNT(*) FROM products GROUP BY category;         -- 대표값 하나
SELECT category, STRING_AGG(name, ', '), COUNT(*) FROM products GROUP BY category;  -- 전부
```

### `aggregate functions are not allowed in WHERE`

```
shop=# SELECT customer_id FROM orders WHERE COUNT(*) >= 3 GROUP BY customer_id;
ERROR:  aggregate functions are not allowed in WHERE
LINE 1: SELECT customer_id FROM orders WHERE COUNT(*) >= 3 GROUP BY ...
                                             ^
```

**원인** — `WHERE`(②)는 `GROUP BY`(③)보다 **먼저** 실행됩니다. 그 시점엔 셀 그룹 자체가 없습니다.
**해결** — 집계 결과에 거는 조건은 `HAVING` 으로.

```sql
SELECT customer_id, COUNT(*) FROM orders GROUP BY customer_id HAVING COUNT(*) >= 3;
```

### 비율이 항상 `0` 으로 나옵니다

```
shop=# SELECT COUNT(*) FILTER (WHERE status = 'cancelled') * 100 / COUNT(*) AS 취소율 FROM orders;
 취소율
--------
      6
(1 row)
```

**원인** — 정수 ÷ 정수는 **정수 나눗셈**입니다. `6.67` 의 소수점이 잘려 `6` 이 됩니다.
비율이 1%도 안 되는 경우엔 아예 **`0`** 이 나와 "문제 없음"으로 오해합니다.
**해결** — `100.0` 을 쓰거나 `::numeric` 으로 캐스팅하고, `ROUND(..., 2)` 로 자릿수를 지정합니다.

### `COUNT(*)` 로 셌더니 결측이 안 보입니다

```sql
SELECT COUNT(*) FROM customers WHERE phone IS NOT NULL;  -- 9  ✅
SELECT COUNT(phone) FROM customers;                      -- 9  ✅
SELECT COUNT(*) FROM customers;                          -- 12 ← "전화번호 등록 고객"이 아님
```

**원인** — `COUNT(*)` 는 행을, `COUNT(열)` 은 그 열의 **값**을 셉니다.
**해결** — "N명이 ○○을 했다"를 셀 때는 **`COUNT(그 열)`** 또는 `COUNT(*) FILTER (WHERE ...)`.

### 그룹이 예상보다 적게 나옵니다

`GROUP BY customer_id` 를 했는데 고객 12명 중 10그룹만 나오는 경우입니다.

**원인** — `orders` 테이블에 **행이 아예 없는** 고객은 그룹도 안 생깁니다. `GROUP BY` 는 없는 것을 만들지 못합니다.
**해결** — `customers LEFT JOIN orders` 로 기준 테이블을 바꿉니다 ([Day 034](day-034.md)).

**"0건인 대상"이 결과에서 사라지는 것**은 이탈 분석·재고 분석에서 늘 나오는 문제입니다. 오늘 기억해 두세요.

### `CASE` 에 `ELSE` 를 안 써서 NULL이 생김

```sql
CASE WHEN price < 10000 THEN '저가'
     WHEN price < 50000 THEN '중가'
END      -- 5만 원 이상 → NULL
```

**원인** — 아무 `WHEN` 에도 안 걸리면 결과가 `NULL` 입니다. 그리고 그 NULL은 `GROUP BY` 에서 **빈칸 그룹**으로 나타납니다.
**해결** — `ELSE` 를 항상 씁니다. 값이 없어야 정상인 경우라도 `ELSE '기타'` 로 **의도를 드러내세요.**

### `CASE` 조건 순서를 거꾸로 씀

```sql
-- ❌ 모든 상품이 '고가'가 됨
CASE WHEN price > 10000 THEN '고가'
     WHEN price > 50000 THEN '초고가'   -- 여기 도달하지 못함
     ELSE '저가' END
```

**원인** — `CASE` 는 **위에서부터 처음 맞는 것 하나만** 실행합니다. 259000원도 `> 10000` 에서 먼저 걸립니다.
**해결** — 좁은 조건(큰 값)부터 위에 씁니다. 또는 `<` 로 통일해 **작은 값부터** 순서대로 씁니다.

### 구간 정렬이 가나다순으로 나옵니다

```
 가격대 | 상품수
--------+--------
 고가   |      3
 저가   |      2
 중가   |      7
```

**원인** — `ORDER BY 가격대` 는 문자열 정렬입니다.
**해결** — `ORDER BY MIN(price)` 처럼 **원본 값 기준**으로 정렬하거나, `CASE ... THEN 1/2/3` 으로 정렬용 숫자를 따로 만듭니다.

**1.** `customers` 12행에 대해 아래 세 쿼리는 각각 몇을 반환하나요? 왜 다른가요?

```sql
SELECT COUNT(*)     FROM customers;
SELECT COUNT(phone) FROM customers;
SELECT COUNT(DISTINCT city) FROM customers;
```

<details>
<summary>답 보기</summary>

| 쿼리 | 결과 | 이유 |
|---|---|---|
| `COUNT(*)` | **12** | **행**의 개수. 값이 있든 없든 셉니다 |
| `COUNT(phone)` | **9** | `phone` 이 **NULL이 아닌 행**만. 박지훈·강하은·한지민 3명이 빠집니다 |
| `COUNT(DISTINCT city)` | **6** | 서로 다른 도시. 서울·부산·대구·인천·광주·대전 |

**실무에서 왜 중요한가** — "전화번호 인증률"을 보고할 때 `COUNT(*)` 를 분자로 쓰면 항상 100%가 나옵니다.
지표 쿼리를 리뷰할 때 **분자와 분모가 각각 무엇을 세고 있는지** 확인하는 것이 첫 번째 점검 항목입니다.

`COUNT(DISTINCT ...)` 도 NULL을 세지 않습니다. `grade` 로 하면 gold·silver·bronze 3이 나오고, NULL은 빠집니다.
</details>

**2.** "취소되지 않은 주문이 3건 이상인 고객"을 구하려 합니다. 아래 두 쿼리의 차이를 실행 순서로 설명하고, 어느 쪽이 맞는지 답하세요.

```sql
-- A
SELECT customer_id, COUNT(*) FROM orders
GROUP BY customer_id
HAVING COUNT(*) >= 3 AND status <> 'cancelled';

-- B
SELECT customer_id, COUNT(*) FROM orders
WHERE status <> 'cancelled'
GROUP BY customer_id
HAVING COUNT(*) >= 3;
```

<details>
<summary>답 보기</summary>

**B가 맞습니다. A는 아예 에러가 납니다.**

```
ERROR:  column "orders.status" must appear in the GROUP BY clause or be used in an aggregate function
```

**A가 틀린 이유** — `HAVING` 은 `GROUP BY`(③) **다음**(④)에 실행됩니다. 그 시점에는 이미 행이 그룹으로 뭉쳐져
개별 행의 `status` 는 존재하지 않습니다. 그룹 안에 `delivered` 와 `cancelled` 가 섞여 있는데 "이 그룹의 status"가 뭐냐고 물으면 답이 없습니다.

**B가 맞는 이유** — `WHERE`(②)가 `GROUP BY`(③)보다 먼저이므로, **취소 건을 먼저 버린 다음** 남은 행만 셉니다.

```
FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT
        ↑개별 행 조건        ↑그룹(집계) 조건
```

**정리** — `status` 처럼 **행 하나하나의 속성**은 `WHERE`, `COUNT(*)` 처럼 **그룹 전체의 속성**은 `HAVING`.

참고로 "그룹 안에 취소가 하나라도 있는 고객"을 찾고 싶다면 `HAVING` 에 집계로 써야 합니다.

```sql
HAVING COUNT(*) FILTER (WHERE status = 'cancelled') > 0
```
</details>

**3.** 아래 쿼리로 "주문 한 건의 평균 금액"을 구하려 했지만 틀렸습니다. 무엇이 문제이고 어떻게 고쳐야 하나요?

```sql
SELECT AVG(quantity * unit_price) FROM order_items;
```

<details>
<summary>답 보기</summary>

**문제** — 이 쿼리의 분모는 **주문 건수(30)가 아니라 주문 상세 줄 수(47)** 입니다.
계산되는 값은 "주문 상세 한 줄의 평균 금액" = 3,073,500 / 47 ≈ **65,393원** 입니다.

"주문 한 건의 평균 금액"은 3,073,500 / 30 = **102,450원** 이어야 합니다.

**고치는 방법 ① 분모를 명시**

```sql
SELECT ROUND(SUM(quantity * unit_price)::numeric / COUNT(DISTINCT order_id)) AS 평균주문금액
FROM order_items;
--  102450
```

**고치는 방법 ② 먼저 주문별로 묶은 뒤 평균** ([Day 036](day-036.md)의 서브쿼리)

```sql
SELECT ROUND(AVG(주문금액)) AS 평균주문금액
FROM (
    SELECT order_id, SUM(quantity * unit_price) AS 주문금액
    FROM order_items
    GROUP BY order_id
) t;
--  102450
```

**핵심 교훈** — 집계 쿼리를 볼 때는 항상 **"이 숫자의 분모가 몇 행인가"** 를 먼저 확인하세요.
[Day 034](day-034.md)에서 `JOIN` 을 배우면 행이 더 늘어나기 때문에, 이 습관이 없으면 매출이 몇 배로 부풀어도 알아채지 못합니다.
</details>

## 오늘의 정리

| 구문 | 하는 일 |
|---|---|
| `COUNT(*)` / `COUNT(열)` | 행 수 / **NULL 아닌 값** 수 |
| `COUNT(DISTINCT 열)` | 서로 다른 값의 수 |
| `SUM` · `AVG` · `MIN` · `MAX` | 합·평균·최소·최대 (**NULL 무시**) |
| `GROUP BY 열` | 그룹별 집계 (**NULL도 한 그룹**) |
| `HAVING 집계조건` | **그룹**을 거름 |
| `CASE WHEN ... THEN ... ELSE ... END` | 분류·구간화 |
| `COUNT(*) FILTER (WHERE ...)` | 조건부 집계 (가로 피벗) |
| `DATE_TRUNC('month', 날짜)` · `TO_CHAR(날짜,'YYYY-MM')` | 기간 단위로 묶기 |
| `STRING_AGG(열, ', ')` | 그룹 안 값들을 이어 붙이기 |

| 함정 | 방어 |
|---|---|
| `COUNT(*)` 로 결측을 못 봄 | `COUNT(열)` 과 비교해 결측률 계산 |
| 정수 나눗셈으로 비율이 0 | `* 100.0` 또는 `::numeric` |
| `WHERE` 에 집계 조건 | `HAVING` 으로 |
| 0건인 대상이 결과에서 사라짐 | `LEFT JOIN` ([Day 034](day-034.md)) |
| `CASE` 에 `ELSE` 없음 → NULL 그룹 | `ELSE '기타'` 항상 |
| 분모가 몇 행인지 모름 | `COUNT(DISTINCT ...)` 로 명시 |
