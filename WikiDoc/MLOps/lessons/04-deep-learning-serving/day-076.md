## ② 왜 필요한가

sklearn으로 잘 살고 있었는데 왜 PyTorch를 배울까요? 대단원 03의 마지막 질문으로 돌아갑시다 —
우리 모델은 **테이블 데이터**만 다룰 수 있습니다. 다음 요구가 오는 순간 막힙니다.

이미지와 텍스트에는 sklearn의 `fit(X, y)` 에 넣을 "특성 컬럼"이 없습니다. 픽셀과 단어에서

| | sklearn | PyTorch |
|---|---|---|
| 무엇을 주나 | 완성된 알고리즘 (`LinearRegression()`) | **부품** (텐서·미분·레이어) — 모델을 조립 |
| 잘 맞는 데이터 | 테이블 | 이미지·텍스트·음성 + 테이블도 가능 |
| 우리의 용도 | MP2 (완료) | W17 이미지 · W18 텍스트 → **MP3 서빙 대상** |

그리고 모든 부품의 밑바닥에 **텐서**가 있습니다. 오늘 이 기본 자료형을 손에 익히지 않으면,
이번 주 내내 에러 메시지의 절반(shape 불일치)과 싸우게 됩니다.

## ③ 개념 설명

### 텐서 — 차원이 자유로운 숫자 상자

텐서(tensor)는 NumPy 배열의 사촌입니다. 숫자를 0차원(스칼라)부터 n차원까지 담습니다.

```
0차원  스칼라        loss 값 하나
1차원  벡터          한 행의 특성들 (5,)
2차원  행렬          테이블 데이터 (3570, 5) = (행, 특성)
3차원               흑백 이미지 배치 (32, 28, 28) = (배치, 높이, 너비)
4차원               컬러 이미지 배치 (32, 3, 224, 224) = (배치, 채널, 높이, 너비)
```

NumPy와 다른 점이 정확히 두 가지이고, 그게 딥러닝의 전부입니다:

1. **autograd** — 연산을 기억했다가 미분을 자동으로 해 줌 (내일의 주제)
2. **device** — 같은 코드가 CPU에서도 GPU에서도 돎 (오늘 마지막 Step)

### 세 가지 속성 — 디버깅의 90%

텐서 문제의 90%는 이 셋을 출력해 보면 풀립니다.

| 속성 | 뜻 | 대표 사고 |
|---|---|---|
| `shape` | 각 차원의 크기 | 행렬곱 불일치, 배치 차원 누락 |
| `dtype` | 숫자 타입 (float32가 기본) | 정수 텐서로 평균·미분 시도 |
| `device` | 어느 장치의 메모리에 있나 | CPU 텐서와 GPU 텐서를 섞어 연산 |

### 연산 — `*` 와 `@` 는 다른 세계

| 연산 | 기호 | 규칙 |
|---|---|---|
| 요소별 곱 | `a * b` | 같은 위치끼리. shape가 같거나 브로드캐스팅 가능해야 |
| **행렬곱** | `a @ b` | `(n, k) @ (k, m) → (n, m)` — **안쪽 k가 맞아야** |

**브로드캐스팅**: shape가 달라도 한쪽이 1이거나 차원이 부족하면 자동으로 "늘려서" 맞춥니다.
`(2,2) + (2,)` 는 벡터가 각 행에 더해집니다 — 신경망에서 편향(bias)이 더해지는 방식 그대로입니다.

### 형태 변환 — 배치 차원이라는 관문

| 함수 | 하는 일 |
|---|---|
| `reshape(3, 4)` | 12개 원소를 3×4로 재배열. `-1` 은 "알아서 계산" |
| `unsqueeze(0)` | 맨 앞에 크기 1 차원 추가: `(3,4) → (1,3,4)` |
| `squeeze()` | 크기 1 차원 제거 |
| `.T` / `transpose` | 차원 순서 교환 |

`unsqueeze(0)` 를 기억해 두세요 — 딥러닝 모델은 언제나 **배치**(여러 건 묶음)를 받도록
만들어져서, 한 건만 예측할 때도 `(특성,) → (1, 특성)` 으로 포장해야 합니다.
서빙(W20)에서 요청 한 건을 처리할 때마다 만나게 됩니다.

## ⑤ 자주 하는 실수

### 행렬곱 shape 불일치

```
RuntimeError: mat1 and mat2 shapes cannot be multiplied (2x3 and 2x3)
```

**원인** — `(2,3) @ (2,3)` — 안쪽 차원(3과 2)이 다릅니다. `@` 는 `(n,k) @ (k,m)` 이어야 합니다.
**해결** — 에러가 shape를 그대로 알려줍니다. 한쪽을 전치(`b.T`)하거나 설계를 다시 보세요. 이 에러는 이번 주 내내 가장 자주 만날 친구입니다 — **shape를 종이에 적으며 따라가는 습관**이 약입니다.

### 정수 텐서로 평균·미분을 시도

```
RuntimeError: mean(): could not infer output dtype. Input dtype must be either a floating point or complex dtype. Got: Long
```

**원인** — `torch.arange(6)` 같은 정수(Long) 텐서에 `mean()` 을 불렀습니다. 통계·미분은 실수 전용입니다.
**해결** — 만들 때 `1.0` 처럼 소수점을 쓰거나 `dtype=torch.float32` 를 명시, 또는 `.float()` 로 변환.

### requires_grad 텐서를 numpy로 직행

```
RuntimeError: Can't call numpy() on Tensor that requires grad. Use tensor.detach().numpy() instead.
```

**원인** — 미분 추적 중인 텐서(내일 배울 requires_grad)는 numpy로 바로 못 나갑니다.
**해결** — 에러가 시키는 대로 `t.detach().numpy()`. "추적을 끊고 값만 꺼낸다"는 뜻입니다.

### from_numpy 공유를 모른 채 원본을 수정

**증상** — 에러 없음. 어느 날 numpy 배열 값이 "저절로" 바뀌어 있음 (Step 4에서 일부러 재현한 그것).
**원인** — `torch.from_numpy` 는 메모리 공유입니다.
**해결** — 원본을 보존해야 하면 `torch.tensor(arr)` (복사). 공유를 쓸 때는 주석으로 명시해 두세요.

### shape (n,)과 (n,1)을 같은 것으로 취급

**증상** — 계산은 되는데 결과 shape가 이상하게 커짐 (예: `(3570,) - (3570,1)` → `(3570, 3570)`!).
**원인** — 브로드캐스팅이 두 텐서를 "친절하게" 서로 늘려 버립니다. 조용히 3,570×3,570 행렬이 만들어집니다.
**해결** — 뺄셈·손실 계산 전에 두 텐서의 shape를 print로 확인. 이 함정은 [Day 077](day-077.md)–[080](day-080.md)의 손실 계산에서 실제로 밟게 되니 오늘 기억해 두세요.

## ⑥ 확인 문제

**Q1.** 텐서의 세 속성(shape·dtype·device)이 각각 어긋났을 때 나는 대표 에러를 하나씩 연결해 보세요.

<details>
<summary>답 보기</summary>

shape → `mat1 and mat2 shapes cannot be multiplied` (행렬곱 불일치).
dtype → `Input dtype must be either a floating point ... Got: Long` (정수로 평균·미분).
device → `Expected all tensors to be on the same device` (CPU 텐서와 GPU 텐서 혼용 — W17에서 GPU를 쓰는 순간 만나게 됩니다).

</details>

**Q2.** `(32, 3, 224, 224)` shape의 텐서는 무엇을 담고 있을 가능성이 높고, 각 차원은 무슨 뜻인가요?

<details>
<summary>답 보기</summary>

컬러 이미지 **배치**입니다: (배치 32장, 채널 3 = RGB, 높이 224, 너비 224).
W17의 CNN이 받는 표준 입력 형태이며, 이미지 한 장만 예측할 때도 `unsqueeze(0)` 으로 `(1, 3, 224, 224)` 를 만들어 넣습니다.

</details>

**Q3.** `torch.from_numpy(arr)` 와 `torch.tensor(arr)` 의 차이를 쓰고, 각각 언제 고르는 게 맞는지 답하세요.

<details>
<summary>답 보기</summary>

`from_numpy` 는 **메모리 공유**(복사 없음 — 빠르지만 한쪽을 고치면 둘 다 바뀜), `torch.tensor()` 는 **복사**
(안전하지만 메모리·시간 비용). 대용량 데이터를 읽기 전용으로 올릴 때는 from_numpy, 원본을 보존하며
텐서를 수정할 일이 있으면 tensor()를 고릅니다.

</details>
