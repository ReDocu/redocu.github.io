## 2. 막히는 상황

어제까지 만든 것을 냉정하게 보자.

```
   ✔ 공이 튕긴다
   ✔ 패들로 받아친다
   ✔ 블록이 깨진다

   ✘ 실행하면 바로 게임이 시작된다 (타이틀이 없다)
   ✘ 블록을 다 깨면 그냥 끝난다 (다음 스테이지가 없다)
   ✘ 점수는 있는데 잘한 건지 모른다 (기록이 없다)
   ✘ 잘 치나 대충 치나 똑같다 (보상이 없다)
   ✘ 중간에 멈출 수 없다
```

**돌아가는 프로그램**과 **게임**의 차이가 여기에 있다.

```
   지금:   기능은 다 있다.  하지만 "한 판"이 없다.

   필요:   ① 씬 흐름       타이틀 → 게임 → 결과 → 타이틀
           ② 진행           스테이지 1 → 2 → 3
           ③ 보상 구조      콤보, 점수 배율
           ④ 기록           최고 점수 유지
           ⑤ 편의           일시정지
```

> **게임으로 완성하는 방법이 필요하다.**

### 3-1. 씬(Scene) — 화면 상태 관리

**왜 필요한가** — 타이틀과 인게임은 입력도, 갱신도, 그리기도 전부 다르다.

### 3-2. 스테이지 데이터 — 코드가 아닌 데이터로

**왜 필요한가** — 스테이지를 코드로 만들면 추가할 때마다 코드를 고쳐야 한다. (Day 15의 원칙)

```c
#define STAGE_COUNT   3
#define BLOCK_ROWS    5
#define BLOCK_COLS   11

const char g_stageData[STAGE_COUNT][BLOCK_ROWS][BLOCK_COLS + 1] = {
    {   // Stage 1 — 기본
        "11111111111",
        "11111111111",
        "11111111111",
        "...........",
        "..........."
    },
    {   // Stage 2 — 피라미드
        "22222222222",
        "11111111111",
        "11111111111",
        "...1111....",
        "..........."
    },
    {   // Stage 3 — 요새
        "33333333333",
        "22222222222",
        "2.........2",
        "2..11111..2",
        "22222222222"
    }
};
```

| 문자 | 의미 | HP | 점수 |
|:--:|---|:--:|:--:|
| `.` | 빈칸 | — | — |
| `1` | 약한 블록 `[--]` | 1 | 10 |
| `2` | 보통 블록 `[==]` | 2 | 20 |
| `3` | 단단한 블록 `[##]` | 3 | 30 |
| `X` | 파괴 불가 | -1 | 0 |

```c
void LoadStage(int index)
{
    g_remainBlocks = 0;

    for (int row = 0; row < BLOCK_ROWS; row++)
    {
        for (int col = 0; col < BLOCK_COLS; col++)
        {
            char c = g_stageData[index][row][col];

            switch (c)
            {
            case '1': g_blocks[row][col].hp = 1; g_blocks[row][col].score = 10; break;
            case '2': g_blocks[row][col].hp = 2; g_blocks[row][col].score = 20; break;
            case '3': g_blocks[row][col].hp = 3; g_blocks[row][col].score = 30; break;
            case 'X': g_blocks[row][col].hp = -1; g_blocks[row][col].score = 0; break;
            default:  g_blocks[row][col].hp = 0; g_blocks[row][col].score = 0; break;
            }

            if (g_blocks[row][col].hp > 0)
                g_remainBlocks++;
        }
    }
}
```

> ⚠️ **파괴 불가 블록(`hp == -1`)은 남은 블록 수에 넣지 않는다.**
> 넣으면 영원히 클리어할 수 없다.

### 3-3. 콤보 — 잘하면 더 주는 구조

**왜 필요한가** — "잘 칠 이유"를 만든다. 점수만 있으면 대충 쳐도 똑같다.

```
   콤보 = 패들에 닿기 전까지 연속으로 깬 블록 수

   블록 깸 → 콤보 +1 → 배율 상승
   패들에 닿음 → 콤보 초기화

   점수 = 블록 점수 × 콤보 배율
```

| 콤보 | 배율 |
|:--:|:--:|
| 1 | ×1.0 |
| 2~3 | ×1.5 |
| 4~5 | ×2.0 |
| 6+ | ×3.0 |

```c
int g_combo = 0;

int GetComboMultiplierX10(int combo)
{
    if (combo >= 6) return 30;
    if (combo >= 4) return 20;
    if (combo >= 2) return 15;
    return 10;
}

// 블록 파괴 시
g_combo++;
int mult = GetComboMultiplierX10(g_combo);
g_score += g_blocks[row][col].score * mult / 10;      // 고정소수점 (Day 17)

// 패들 충돌 시
g_combo = 0;
```

> **콤보는 "위험을 감수하면 보상"의 구조를 만든다.**
> 이 발상은 Day 89(타워 디펜스 밸런싱)와 파이널 프로젝트까지 이어진다.

### 3-5. 일시정지 — 시간을 멈추기

**왜 필요한가** — 게임 루프는 계속 도는데 게임만 멈춰야 한다.

```c
case SCENE_PAUSED:
    // Update를 호출하지 않는다 → 공도, 패들도 멈춘다
    if (KeyDown('P'))     g_scene = SCENE_PLAYING;
    if (KeyDown(VK_ESCAPE)) g_scene = SCENE_TITLE;
    RenderPaused();
    break;
```

```
   ★ 게임 루프 자체는 계속 돈다 (입력을 받아야 하니까)
     다만 Update(dt)를 호출하지 않을 뿐이다
```

> ### ⚠️ 일시정지를 풀 때 `dt`가 튄다
>
> 10초간 멈췄다가 재개하면 `dt = 10.0`이 되어 공이 화면 밖으로 순간이동한다.
> Day 21에서 넣은 클램프가 여기서 일한다.
>
> ```c
> if (dt > 0.1) dt = 0.1;
> ```
>
> 또는 일시정지 해제 시 `prevTime`을 갱신한다.

### 3-6. 게임 루프에서 Update와 Render의 완전한 분리

**왜 필요한가** — 오늘로 Part 1 콘솔 구간이 끝난다. 다음 단계로 넘어가기 전 정리.

```
   ┌────────────────────────────────────────────────────┐
   │  UpdateInput()        입력 상태 갱신                │
   ├────────────────────────────────────────────────────┤
   │  Update(dt)                                        │
   │    ├─ 패들 이동                                     │
   │    ├─ 공 이동                                       │
   │    ├─ 충돌 판정 (벽 / 패들 / 블록)                   │
   │    ├─ 점수·콤보·라이프 갱신                          │
   │    └─ 씬 전환 조건 확인                              │
   │    ★ printf 를 한 번도 호출하지 않는다               │
   ├────────────────────────────────────────────────────┤
   │  Render()                                          │
   │    ├─ 화면 배열 지우기                               │
   │    ├─ 블록 / 공 / 패들 그리기                        │
   │    ├─ HUD 그리기                                    │
   │    └─ 한 번에 출력                                   │
   │    ★ 상태를 한 번도 바꾸지 않는다                     │
   └────────────────────────────────────────────────────┘
```

> **이 분리가 지켜지면 Day 39의 프레임워크 이식이 쉽다.**
> `Update`에 `printf`가 섞여 있으면 WINAPI로 옮길 때 전부 뜯어고쳐야 한다.

### 3-7. 콘솔의 한계 — 다음 단계로 가는 이유

**왜 필요한가** — 오늘로 콘솔 게임이 끝나는 이유를 이해한다.

| 한계 | 왜 |
|---|---|
| **깜빡임** | 커서 이동으로 줄였지만 완전히 못 없앤다 (Day 15) |
| **해상도** | 최소 단위가 글자 한 칸. 부드러운 곡선이 불가능 |
| **색상** | 기본 16색. 그라데이션·투명도 없음 |
| **도형** | 원을 그릴 수 없다. `●` 문자로 흉내낼 뿐 |
| **이미지** | 스프라이트를 표시할 방법이 없다 |
| **입력** | 마우스 처리가 번거롭다 |

```
   콘솔에서 배운 것들 (전부 다음 단계로 이어진다)

   게임 루프          →  Day 38 PeekMessage 루프
   델타 타임          →  Day 38 QueryPerformanceCounter
   화면 배열 + 일괄 출력 →  Day 37 더블버퍼링
   AABB 충돌          →  Day 47 판정 박스
   상태 관리          →  Day 46 FSM
   Update/Render 분리 →  Day 39 Core 클래스

   ★ 도구만 바뀐다. 원리는 그대로다.
```

### Step 4 — 게임 초기화

```c
void StartNewGame(void)
{
    g_score        = 0;
    g_life         = MAX_LIFE;
    g_combo        = 0;
    g_currentStage = 0;
    g_totalTime    = 0.0;
    g_isNewRecord  = 0;

    LoadStage(g_currentStage);
    ResetBallAndPaddle();
}

void ResetBallAndPaddle(void)
{
    g_paddle.x     = SCREEN_W / 2.0 - PADDLE_WIDTH / 2.0;
    g_paddle.y     = SCREEN_H - 2;
    g_paddle.width = PADDLE_WIDTH;
    g_paddle.speed = PADDLE_SPEED;

    g_ballLaunched = 0;
    g_combo        = 0;
}
```

### Step 6 — 스테이지 클리어와 전환

```c
void UpdatePlaying(double dt)
{
    // ... 기존 갱신 ...

    if (g_remainBlocks <= 0)
    {
        g_clearBonus = (int)(1000 - g_totalTime * 5);       // 빠를수록 보너스
        if (g_clearBonus < 0) g_clearBonus = 0;

        g_score += g_clearBonus;
        g_scene = SCENE_STAGE_CLEAR;
    }

    if (g_life <= 0)
        g_scene = SCENE_GAME_OVER;
}

void UpdateStageClear(void)
{
    if (KeyDown(VK_SPACE))
    {
        g_currentStage++;

        if (g_currentStage >= STAGE_COUNT)
        {
            g_allClear = 1;
            g_scene = SCENE_RESULT;
        }
        else
        {
            LoadStage(g_currentStage);
            ResetBallAndPaddle();
            g_scene = SCENE_PLAYING;
        }
    }
}
```

## 6. 자주 막히는 곳

| 증상 | 원인 | 해결 |
|---|---|---|
| 씬이 안 바뀜 | `g_scene` 대입 누락 | 각 전이 지점 확인 |
| 씬 전환 시 이전 화면이 남음 | 화면 지우기 누락 | 씬 전환 시 `system("cls")` 한 번 |
| 일시정지 해제 후 공 순간이동 | `dt` 폭증 | 클램프 확인, 또는 `prevTime` 갱신 |
| 클리어가 안 됨 | 파괴 불가 블록을 카운트 | `hp > 0`만 셈 |
| 스테이지 2에서 이전 블록이 남음 | `LoadStage` 미호출 | 전환 시 반드시 호출 |
| 콤보가 안 오름 | 파괴 시점이 아닌 충돌 시점에 증가 | `hp == 0`이 된 순간에만 |
| 라이프 잃고 점수가 초기화 | `StartNewGame`을 호출 | `ResetBallAndPaddle`만 호출 |
| 최고 점수가 갱신 안 됨 | 비교 시점 문제 | 게임 종료 시점에 비교 |
| 스테이지 데이터 오류 | 행마다 글자 수가 다름 | 모든 줄을 `BLOCK_COLS`로 맞춤 |
