## 1. 오늘 만드는 것

방이 **여러 개**가 되고, 이동할 수 있고, 방마다 다른 일이 일어난다.

```
---------------------------------
[ 남은 시간 18 ]   현재 위치: 창고
[ 소지품 ]  (없음)

     ┌────────┐
     │  창고   │ ← 지금 여기
     └───┬────┘
         │
     ┌───┴────┐      ┌────────┐
     │  복도   │──────│  서재   │
     └───┬────┘      └────────┘
         │
     ┌───┴────┐
     │  현관   │  ← 출구
     └────────┘

무엇을 하시겠습니까?
  1. 주변을 살펴본다
  2. 복도로 이동한다
  0. 포기한다

선택 (0~2): 1

낡은 상자를 열었다.  녹슨 열쇠를 손에 넣었다!
```

**조작** — 방마다 메뉴가 달라진다. 이동하며 열쇠를 찾아 현관으로 간다.

## 2. 막히는 상황

어제 코드에 방을 3개로 늘려 보자.

```c
    if (currentRoom == 0)          // 창고
    {
        if (choice == 1) printf("낡은 상자가 있다\n");
        else if (choice == 2) printf("복도로 간다\n");
        else if (choice == 3) printf("...\n");
    }
    else if (currentRoom == 1)     // 복도
    {
        if (choice == 1) printf("긴 복도다\n");
        else if (choice == 2) printf("창고로 간다\n");
        else if (choice == 3) printf("서재로 간다\n");
        else if (choice == 4) printf("현관으로 간다\n");
    }
    else if (currentRoom == 2)     // 서재
    {
        // ... 또 5개 ...
    }
```

`if`가 **15개**가 됐다. 방을 하나 더 추가하면 5개가 더 늘어난다.
그리고 3일 뒤에 이 코드를 보면 `currentRoom == 2`가 어느 방인지 모른다.

```
   지금:   방마다 if 덩어리를 통째로 복사
           ┌──────────┐ ┌──────────┐ ┌──────────┐
           │ 방0 처리  │ │ 방1 처리  │ │ 방2 처리  │   ← 방이 늘면
           └──────────┘ └──────────┘ └──────────┘      코드도 비례해서 늘어난다

   필요:   상태를 데이터로 두고, 처리는 한 벌만
           ┌───────────────────────────────┐
           │  currentRoom (지금 어디)        │
           │  hasKey      (열쇠 있나)        │  ← 데이터
           │  doorOpen    (문 열렸나)        │
           └───────────────────────────────┘
                        ▼
           ┌───────────────────────────────┐
           │  처리 코드 한 벌                │  ← 데이터를 보고 동작만 달라진다
           └───────────────────────────────┘
```

> **"지금 어떤 상황인가"를 값으로 들고 다니는 방법이 필요하다.** → **상태 변수**

## 3. 개념

### 3-1. 상태 변수 — 지금 상황을 값으로 기억

**왜 필요한가** — 프로그램이 "지금 어디에 있고, 무엇을 가졌는지"를 알아야 다르게 행동한다.

```c
int currentRoom = 0;        // 지금 있는 방 번호
int hasKey      = 0;        // 열쇠 소지 여부 (0=없음, 1=있음)
int doorOpen    = 0;        // 현관문 개방 여부
```

**상태 전이 = 상태 변수에 대입하는 것뿐이다.**

```c
currentRoom = 1;            // 복도로 "이동했다"
hasKey      = 1;            // 열쇠를 "얻었다"
```

```
   currentRoom = 0          currentRoom = 1
   ┌────────┐   이동         ┌────────┐
   │  창고   │ ────────────▶ │  복도   │
   └────────┘                └────────┘

   화면에 보이는 "이동"의 실체는 변수에 1을 대입한 것뿐이다.
```

> 이 감각이 앞으로 계속 쓰인다.
> Day 17의 `enum`, Day 46의 **유한 상태 머신(FSM)**, Day 82의 Unity **Animator**까지
> 전부 "지금 상태를 값 하나로 들고, 그 값을 바꾸는 것"이다.

### 3-2. `switch`로 상태별 분기

**왜 필요한가** — `if` 15개를 구조로 정리한다.

```c
switch (currentRoom)
{
case ROOM_STORAGE:
    // 창고에서 할 수 있는 일
    break;
case ROOM_HALL:
    // 복도에서 할 수 있는 일
    break;
case ROOM_STUDY:
    // 서재에서 할 수 있는 일
    break;
}
```

**방 번호에 이름 붙이기** — 숫자만 있으면 읽을 수 없다.

```c
#define ROOM_STORAGE  0
#define ROOM_HALL     1
#define ROOM_STUDY    2
#define ROOM_ENTRANCE 3

// 나쁨:  if (currentRoom == 2)
// 좋음:  if (currentRoom == ROOM_STUDY)
```

> 내일모레(Day 17) `enum`을 배우면 이 `#define` 뭉치가 더 깔끔해진다. 오늘은 `#define`으로 충분하다.

### 3-3. 플래그 변수 — 예/아니오를 기억

**왜 필요한가** — "열쇠를 가졌는가"처럼 두 가지 상태만 있는 것.

```c
int hasKey = 0;             // 0 = 거짓, 1 = 참

// 획득
hasKey = 1;

// 확인
if (hasKey)                 // 0이 아니면 참 (Day 3)
    printf("열쇠를 가지고 있다.\n");

if (!hasKey)                // 부정
    printf("열쇠가 없다.\n");
```

**플래그 이름은 `is~`, `has~`, `can~`으로 시작한다.**

| 좋은 이름 | 나쁜 이름 |
|---|---|
| `hasKey` | `key` (개수인지 여부인지 모름) |
| `isDoorOpen` | `door` |
| `canEscape` | `escape` |

### 3-4. 상태 조합 — 여러 조건이 함께 걸릴 때

**왜 필요한가** — 게임 규칙은 대부분 조합이다. "열쇠가 있고 + 현관에 있어야 + 탈출 가능".

```c
if (currentRoom == ROOM_ENTRANCE && hasKey)
{
    printf("열쇠로 문을 열었다!\n");
    doorOpen = 1;
}
else if (currentRoom == ROOM_ENTRANCE && !hasKey)
{
    printf("문이 잠겨 있다. 열쇠가 필요하다.\n");
}
```

**조합을 표로 정리하면 빠뜨리지 않는다.**

| 위치 | 열쇠 | 결과 |
|---|:--:|---|
| 현관 | O | 탈출 성공 |
| 현관 | X | "열쇠가 필요하다" |
| 그 외 | O | 문이 여기 없다 |
| 그 외 | X | 문이 여기 없다 |

> **표를 먼저 만들고 코드를 쓴다.** 이 습관이 Day 46의 상태 전이표로 이어진다.

### 3-5. 상태 전이표 — 어디서 어디로 갈 수 있는가

**왜 필요한가** — 이동 규칙을 코드에 흩뿌리지 말고 한눈에 보이게 정리한다.

```
        ┌────────┐
        │  창고   │  0
        └───┬────┘
            │
        ┌───┴────┐        ┌────────┐
        │  복도   │  1 ────│  서재   │  2
        └───┬────┘        └────────┘
            │
        ┌───┴────┐
        │  현관   │  3   ← 출구
        └────────┘
```

| 현재 위치 \ 이동 대상 | 창고 | 복도 | 서재 | 현관 |
|---|:--:|:--:|:--:|:--:|
| **창고** | — | O | X | X |
| **복도** | O | — | O | O |
| **서재** | X | O | — | X |
| **현관** | X | O | — | — |

> 이 표를 배열로 옮기면 이동 검사 코드가 한 줄이 된다. (Day 11 배열에서 다룬다)
> 오늘은 `switch`로 방마다 갈 수 있는 곳을 나열한다.

### 3-6. 상태 출력 — 지금 상황을 항상 보여주기

**왜 필요한가** — 플레이어가 "내가 어디 있고 뭘 가졌는지" 모르면 게임을 할 수 없다.
그리고 **개발자에게는 이게 가장 좋은 디버그 도구**다.

```c
void PrintHeader(int room, int timeLeft, int hasKey)
{
    const char* roomNames[] = { "창고", "복도", "서재", "현관" };

    printf("\n---------------------------------\n");
    printf("[ 남은 시간 %2d ]   현재 위치: %s\n", timeLeft, roomNames[room]);
    printf("[ 소지품 ]  %s\n", hasKey ? "녹슨 열쇠" : "(없음)");
}
```

> `roomNames[room]` — 배열로 숫자를 이름으로 바꾸는 이 기법을 **룩업 테이블**이라고 한다.
> `if`로 이름을 고르는 것보다 훨씬 짧다. 내일(Day 11) 배열을 배우면 더 적극적으로 쓴다.

## 4. 따라 만들기

### Step 1 — 방 번호에 이름 붙이기

```c
#define ROOM_STORAGE   0        // ← 추가
#define ROOM_HALL      1
#define ROOM_STUDY     2
#define ROOM_ENTRANCE  3
#define ROOM_COUNT     4
```

```c
    int currentRoom = ROOM_STORAGE;      // ← 추가
```

**✅ 여기까지 실행하면** — 아직 화면 변화는 없다. 이름 준비만 했다.

### Step 2 — 상태 헤더 출력

```c
void PrintHeader(int room, int timeLeft, int hasKey)
{
    const char* roomNames[ROOM_COUNT] = { "창고", "복도", "서재", "현관" };

    printf("\n---------------------------------\n");
    printf("[ 남은 시간 %2d ]   현재 위치: %s\n", timeLeft, roomNames[room]);
    printf("[ 소지품 ]  %s\n", hasKey ? "녹슨 열쇠" : "(없음)");
}
```

```c
    while (running)
    {
        PrintHeader(currentRoom, timeLeft, hasKey);     // ← 추가
        // ...
    }
```

**✅ 여기까지 실행하면** — 매 턴 현재 위치와 소지품이 표시된다.

### Step 3 — 방마다 다른 메뉴

```c
// 방마다 메뉴를 출력하고, 선택 가능한 최대 번호를 돌려준다
int PrintMenu(int room)
{
    printf("\n무엇을 하시겠습니까?\n");

    switch (room)
    {
    case ROOM_STORAGE:
        printf("  1. 주변을 살펴본다\n");
        printf("  2. 복도로 이동한다\n");
        printf("  0. 포기한다\n");
        return 2;

    case ROOM_HALL:
        printf("  1. 주변을 살펴본다\n");
        printf("  2. 창고로 이동한다\n");
        printf("  3. 서재로 이동한다\n");
        printf("  4. 현관으로 이동한다\n");
        printf("  0. 포기한다\n");
        return 4;

    case ROOM_STUDY:
        printf("  1. 책장을 뒤진다\n");
        printf("  2. 복도로 이동한다\n");
        printf("  0. 포기한다\n");
        return 2;

    case ROOM_ENTRANCE:
        printf("  1. 문을 열어 본다\n");
        printf("  2. 복도로 이동한다\n");
        printf("  0. 포기한다\n");
        return 2;
    }

    return 0;
}
```

```c
        int maxChoice = PrintMenu(currentRoom);            // ← 추가
        int choice = ReadInt("선택", 0, maxChoice);        // ← 범위를 방마다 다르게
```

**✅ 여기까지 실행하면** — 방마다 다른 메뉴가 뜨고, 그 방의 선택지 개수만큼만 입력을 받는다.

### Step 4 — 이동 처리 (상태 전이)

```c
        switch (currentRoom)
        {
        case ROOM_STORAGE:
            if (choice == 2) currentRoom = ROOM_HALL;      // ★ 상태 전이
            break;

        case ROOM_HALL:
            if      (choice == 2) currentRoom = ROOM_STORAGE;
            else if (choice == 3) currentRoom = ROOM_STUDY;
            else if (choice == 4) currentRoom = ROOM_ENTRANCE;
            break;

        case ROOM_STUDY:
            if (choice == 2) currentRoom = ROOM_HALL;
            break;

        case ROOM_ENTRANCE:
            if (choice == 2) currentRoom = ROOM_HALL;
            break;
        }
```

**✅ 여기까지 실행하면** — 이동을 선택하면 다음 턴 헤더의 `현재 위치`가 바뀐다.

### Step 5 — 열쇠 획득 (플래그)

```c
        case ROOM_STORAGE:
            if (choice == 1)
            {
                if (!hasKey)                                  // ← 추가
                {
                    printf("\n낡은 상자를 열었다.  녹슨 열쇠를 손에 넣었다!\n");
                    hasKey = 1;                               // ★ 플래그 세우기
                }
                else
                {
                    printf("\n이미 다 뒤졌다. 남은 건 먼지뿐이다.\n");
```

**✅ 여기까지 실행하면** — 창고에서 살펴보면 열쇠를 얻고, 헤더의 소지품이 `녹슨 열쇠`로 바뀐다.
두 번째로 살펴보면 다른 메시지가 나온다.

### Step 6 — 상태 조합으로 탈출 판정

```c
        case ROOM_ENTRANCE:
            if (choice == 1)
            {
                if (hasKey)                                   // ★ 조합 조건
                {
                    printf("\n녹슨 열쇠가 딱 맞는다.  문이 열렸다!\n");

                else
                {
                    printf("\n문은 굳게 잠겨 있다.  열쇠가 필요하다.\n");
```

**✅ 여기까지 실행하면** — 열쇠 없이 현관에서 문을 열면 실패하고, 열쇠를 가지고 가면 탈출 성공한다.

```c
void PrintMap(int room)
```

```
---------------------------------
[ 남은 시간 19 ]   현재 위치: 창고
[ 소지품 ]  녹슨 열쇠

선택 (0~2): 2

---------------------------------
[ 남은 시간 18 ]   현재 위치: 복도
[ 소지품 ]  녹슨 열쇠

무엇을 하시겠습니까?
  1. 주변을 살펴본다
  2. 창고로 이동한다
  3. 서재로 이동한다
  4. 현관으로 이동한다
  0. 포기한다
```

- [ ] 이동하면 헤더의 `현재 위치`가 바뀐다
- [ ] 방마다 메뉴 항목 수가 다르고, 입력 범위도 그에 맞게 제한된다
- [ ] 창고에서 열쇠를 얻으면 소지품 표시가 바뀐다
- [ ] 같은 곳을 두 번 살펴보면 다른 메시지가 나온다
- [ ] 열쇠 없이 현관 문을 열면 실패한다
- [ ] 열쇠를 가지고 현관 문을 열면 탈출 성공한다

## 6. 자주 막히는 곳

| 증상 | 원인 | 해결 |
|---|---|---|
| 이동해도 이전 방 설명이 나옴 | `currentRoom` 갱신 누락 | 이동 선택지에서 대입 확인 |
| 어디로도 못 감 | `switch`의 `case` 값과 실제 방 번호 불일치 | `#define` 값 확인 |
| 열쇠를 계속 얻음 | `hasKey` 검사 없이 메시지만 출력 | `if (!hasKey)` 로 감싸기 |
| 다른 방 메뉴가 나옴 | `PrintMenu`와 처리 `switch`의 번호가 어긋남 | 메뉴와 처리를 나란히 두고 대조 |
| 입력 범위가 안 맞음 | `maxChoice`를 고정값으로 씀 | `PrintMenu`의 반환값을 사용 |
| `roomNames[room]`에서 크래시 | `room`이 배열 범위 밖 | 방 번호 상수 값과 배열 크기 확인 |
| 조건이 복잡해서 뭐가 뭔지 모름 | 상태 조합을 코드로만 관리 | **표를 먼저 그린다** |
| 시간이 안 줄어듦 | `continue`로 건너뛰는 경로에서 감소 누락 | 감소 위치 재확인 |

| 상태 전이 | 화면의 "이동"은 사실 **변수에 대입하는 것**뿐 |
| 상수로 이름 붙이기 | `currentRoom == 2` → `currentRoom == ROOM_STUDY` |
| 플래그 변수 | 예/아니오를 기억. `has~`, `is~`, `can~` |
| 상태 조합 | 여러 조건이 함께 걸릴 때. **표로 먼저 정리** |
| 룩업 테이블 | `roomNames[room]` — 숫자를 이름으로 |
| 상태 출력 | 플레이어에게도, 개발자에게도 필수 |
