# Week 21 · 프로토타입 — "재미있나?"

> 목표: 재미의 핵심이 되는 조작 루프 하나를 플레이 가능한 상태로 만든다
> 산출물: 플레이어블 프로토타입

---

### Day 101 · 프로젝트 세팅

| | |
|---|---|
| **오늘의 목표** | 팀 전원의 PC에서 같은 프로젝트가 빌드된다 |

**오전 (4h)**
- 프로젝트 생성 및 저장소 초기 커밋 (Day 97 규칙 적용)
- 폴더 구조 확정 — `Scenes/` `Scripts/` `Prefabs/` `Art/` `Data/` `Docs/`
- 코드 컨벤션 합의 (네이밍, 폴더별 네임스페이스, 주석 규칙)
- `.gitignore` / Force Text / Visible Meta Files 확인
- 재사용할 자기 코드 이식 (Part 2 프레임워크 또는 Part 3 공통 모듈)

**오후 (4h)**
- 브랜치 전략 확정 (`main` / `develop` / `feature/*`)
- 이슈 또는 작업 목록 등록 (Day 99 일정표를 이슈로 옮긴다)
- 빈 씬 + 카메라 + 기본 오브젝트로 **첫 빌드**
- 전원이 클론 → 빌드 → 실행 확인

**✅ 실행 결과** — 팀원 전원이 저장소를 클론해 프로젝트를 열고, 빌드한 실행 파일이 실행된다. 첫 커밋 이력이 남는다.

**🔧 막히면**
- 다른 PC에서 참조가 깨짐 → `.meta` 미커밋
- Unity 버전 불일치로 프로젝트가 강제 업그레이드됨 → 버전 통일 재확인
- 자작 프레임워크 이식 시 빌드 오류 → 경로·라이브러리 링크 설정 확인

### Day 102 · 핵심 조작 구현 ①

| | |
|---|---|
| **오늘의 목표** | 플레이어가 의도대로 움직인다 |

**오전 (4h)**
- 플레이어 캐릭터/유닛 배치 및 기본 이동
- 입력 매핑 (GDD의 조작 표대로)
- 카메라 세팅

**오후 (4h)**
- 이동 감각 조정 — 속도, 가속, 관성, 반응성
- 애니메이션 또는 시각적 피드백 최소 연결
- **감각 튜닝을 오늘 끝낸다** (나중으로 미루면 전체가 어색한 채로 굳는다)
- 커밋 및 빌드 확인

**✅ 실행 결과** — 조작해서 캐릭터를 원하는 곳으로 움직일 수 있고, 조작 감각이 "답답하지 않다".

**🔧 막히면**
- 감각이 이상한데 원인을 모름 → 속도/가속/입력 데드존을 하나씩 극단값으로 바꿔 확인
- 시간이 오래 걸림 → Part 2·3에서 만든 이동 코드를 그대로 가져온다. 새로 짜지 않는다

### Day 103 · 핵심 조작 구현 ②

| | |
|---|---|
| **오늘의 목표** | 플레이어의 행동이 세계에 영향을 준다 |

**오전 (4h)**
- 상호작용 구현 — 공격 / 획득 / 설치 / 선택 등 게임의 핵심 동사
- 충돌·판정 처리
- 대상(적, 오브젝트, 타일 등) 최소 1종 구현

**오후 (4h)**
- 피드백 — 반응이 있는가 (소리, 색 변화, 수치 변화 중 최소 하나)
- 상태 관리 (체력, 자원 등 핵심 수치 1~2개)
- 디버그 표시 (현재 상태를 화면에 텍스트로)
- 커밋 및 빌드 확인

**✅ 실행 결과** — 플레이어의 행동에 대상이 반응한다(적이 죽거나, 아이템이 사라지거나, 타워가 놓이거나). 화면의 수치가 그에 맞게 변한다.

**🔧 막히면**
- 판정이 안 됨 → Part 2 AABB / Part 3 Collider 설정 재확인
- 반응이 밋밋함 → 수치 변화만 있고 시각·청각 피드백이 없음. 하나라도 붙인다

### Day 104 · 핵심 루프 연결

| | |
|---|---|
| **오늘의 목표** | 시작부터 종료까지 한 판이 진행된다 |

**오전 (4h)**
- 게임 시작 조건 / 진행 / 종료 조건 연결
- 승리·패배 판정 구현
- 최소한의 결과 표시 (텍스트라도)

**오후 (4h)**
- 한 판 반복 가능하게 (재시작)
- 난이도·수치 1차 조정 — 너무 쉽거나 어려워서 판단이 안 되지 않게
- **내부 플레이 테스트** — 팀원끼리 서로 플레이
- 커밋 및 빌드 확인

**✅ 실행 결과** — 실행하면 게임이 시작되고, 플레이해서 이기거나 지고, 다시 시작할 수 있다. 한 판이 1~3분 안에 끝난다.

**🔧 막히면**
- 종료가 안 됨 → 판정 조건이 실제로 도달 가능한지 확인
- 한 판이 너무 김 → 프로토 단계에서는 짧게. 검증이 목적이다

### Day 105 · 프로토 리뷰 — 재미 판정 ★

| | |
|---|---|
| **오늘의 목표** | 이 게임을 계속 만들지, 깎을지, 바꿀지 결정한다 |

**오전 (4h)**
- 빌드 배포 및 **교차 플레이 테스트** — 다른 팀이 설명 없이 플레이
- 관찰 기록 — 어디서 막히는가, 무엇을 오해하는가, 언제 웃는가
- 피드백 수집 (구조화된 질문지)

**표 — 프로토 리뷰 질문지**

| 질문 | 응답 |
|---|---|
| 무엇을 하는 게임이라고 생각했나요? | |
| 목표가 무엇인지 알았나요? (설명 없이) | 예 / 아니오 |
| 가장 재미있던 순간은? | |
| 가장 답답했던 순간은? | |
| 한 번 더 하고 싶었나요? | 예 / 아니오 |
| 이 게임에 무엇이 하나 추가되면 좋을까요? | |

**오후 (4h)**
- 팀별 판정 회의 및 **강사 리뷰**

**표 — 판정과 대응**

| 판정 | 신호 | 대응 |
|---|---|---|
| **통과** | "한 번 더" 응답이 과반 | 그대로 W22 진행 |
| **범위 축소** | 재미는 있으나 구현량 과다 | 콘텐츠·기능을 깎고 진행 |
| **피벗** | 무엇을 하는 게임인지 전달 안 됨 | **오늘 안에** 핵심 루프를 바꾼다 |

- 판정 결과에 따라 **일정표 갱신** (Day 106~120 재작성)
- **범위 확정** — 오늘 이후 늘리지 않는다
- W22 작업 분해 및 담당 배정

**✅ 실행 결과** — 다른 팀 3명 이상의 플레이 테스트 기록이 남고, 판정 결과와 그에 따라 수정된 일정표가 저장소에 커밋된다.

**🔧 막히면**
- 피드백이 "재밌어요"뿐 → 질문지대로 구체적으로 묻는다. 관찰이 응답보다 정확하다
- 피벗해야 하는데 아까움 → **지금 바꾸는 비용이 가장 싸다.** 3주 뒤에는 못 바꾼다

# Week 22 · 알파 — "다 되나?"

> 목표: 게임을 구성하는 주요 시스템을 모두 붙인다. "기능은 다 있으나 거칠다" 상태
> 산출물: 알파 빌드

---

### Day 106 · 시스템 구현 ①

| | |
|---|---|
| **오늘의 목표** | 게임의 진행 구조가 동작한다 |

**오전 (4h)**
- 진행 시스템 구현 — 스테이지 / 웨이브 / 라운드 / 레벨 등 GDD에 정의한 구조
- 진행 데이터를 코드 밖으로 (ScriptableObject / JSON / 파일) — 밸런싱을 위해 필수
- 진행에 따른 난이도 변화

**오후 (4h)**
- 구현 계속 / 강사 순회 코칭
- 디버그 기능 추가 — **스테이지 스킵, 무적, 자원 치트** (테스트 효율에 직결한다)
- 커밋 및 빌드 확인

**✅ 실행 결과** — 스테이지 1을 클리어하면 스테이지 2가 시작되고, 진행 데이터 파일을 수정하면 구성이 바뀐다.

**🔧 막히면**
- 진행이 꼬임 → 진행 상태를 단일 변수(FSM)로 관리. Part 2 Day 46 재사용
- 테스트가 느림 → 디버그 치트를 먼저 만든다. 남는 시간이 아니라 투자다

### Day 107 · 시스템 구현 ②

| | |
|---|---|
| **오늘의 목표** | 서브 시스템이 동작한다 |

**오전 (4h)**
- 두 번째 시스템 구현 — 성장 / 자원 / 인벤토리 / 스킬 / 업그레이드 등
- 핵심 루프와의 연결 (이 시스템이 왜 재미에 기여하는가 확인)

**오후 (4h)**
- 구현 계속
- 시스템 간 상호작용 검증 (자원 → 업그레이드 → 전투력 → 자원)
- 커밋 및 빌드 확인

**✅ 실행 결과** — 플레이 중 획득한 자원으로 무언가를 강화·구매할 수 있고, 그 효과가 실제 플레이에 반영된다.

**🔧 막히면**
- 시스템이 겉돎 → 핵심 루프와 연결되지 않은 시스템은 **과감히 제외 목록으로**
- 시간이 부족 → Day 105에서 정한 우선순위대로. 낮은 것은 버린다

### Day 108 · UI 전체 연결

| | |
|---|---|
| **오늘의 목표** | 타이틀부터 결과까지 화면 흐름이 끊기지 않는다 |

**오전 (4h)**
- 씬/화면 흐름 구성 — 타이틀 → (선택) → 인게임 → 일시정지 → 결과 → 타이틀
- 인게임 HUD — 핵심 수치가 전부 보이는가
- 일시정지 / 설정 (사운드, 조작 안내)

**오후 (4h)**
- 화면 전환 처리 (페이드, 로딩)
- 해상도 대응 확인 (Day 76의 앵커·Canvas Scaler)
- UI 조작만으로 게임을 처음부터 끝까지 진행 가능한지 확인
- 커밋 및 빌드 확인

**✅ 실행 결과** — 키보드 조작 없이 마우스만으로 타이틀에서 시작해 한 판을 마치고 타이틀로 돌아올 수 있다. 창 크기를 바꿔도 UI가 어긋나지 않는다.

**🔧 막히면**
- 씬 전환 시 데이터 소실 → 게임 매니저를 `DontDestroyOnLoad` 또는 단일 씬 구조로
- 결과 화면에 값이 안 넘어감 → 씬 간 데이터 전달 방식 정리 (정적 클래스 / 매니저)

### Day 109 · 데이터 외부화와 저장

| | |
|---|---|
| **오늘의 목표** | 밸런스 수치를 코드 수정 없이 조정할 수 있다 |

**오전 (4h)**
- 남은 하드코딩 수치를 데이터로 이관 (적 체력, 데미지, 비용, 속도, 드랍률…)
- 밸런스 표 작성 (스프레드시트 또는 문서) — Day 89의 형식 활용

**오후 (4h)**

- 데이터만 바꿔 가며 밸런스 1차 조정
- 커밋 및 빌드 확인

**✅ 실행 결과** — 데이터 파일의 적 체력을 2배로 바꾸고 게임을 실행하면 실제로 2배가 된다. 빌드된 실행 파일에서도 동작한다.

**🔧 막히면**
- 빌드에서 데이터를 못 찾음 → `StreamingAssets` 또는 리소스 폴더 경로 정책 확인
- 세이브가 깨짐 → 포맷 버전 필드로 방어 (Part 2 Day 59)

**✅ 실행 결과** — 알파 빌드 실행 파일로 게임을 완주할 수 있고, 체크리스트 6항목이 모두 체크된다.

**🔧 막히면**

- 미구현 기능이 남음 → 제외 목록으로 옮기고 GDD를 갱신 (숨기지 않고 문서에 남긴다)
