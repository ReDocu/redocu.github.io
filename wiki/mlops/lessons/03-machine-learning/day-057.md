## ③ 개념 설명

### 혼동행렬 — 네 가지 결말

이진 분류의 예측은 정확히 네 가지로 끝납니다. 우리 문제(나쁨=양성=1)의 언어로:

```
                      예측: 나쁨(경보)         예측: 아님(안심)
실제: 나쁨(1)      TP 경보 적중 ✓           FN 놓침 ✗ (조용한 재난)
실제: 아님(0)      FP 헛경보 ✗ (양치기)      TN 조용히 맞음 ✓
```

- **T/F** = 맞았나 틀렸나, **P/N** = 뭐라고 예측했나. "FP = 양성이라고 **예측**했는데 틀림"으로 읽습니다.
- sklearn의 `confusion_matrix` 는 **행=실제, 열=예측**, 그리고 클래스 순서가 `[0, 1]` 이라
  왼쪽 위가 TN입니다. 교과서 그림과 배치가 다르니 주의하세요.

### 정밀도와 재현율 — 두 개의 다른 질문

| 지표 | 식 | 묻는 질문 | 낮으면 생기는 일 |
|---|---|---|---|
| **정밀도** (precision) | TP / (TP+FP) | **경보를 울렸을 때**, 얼마나 믿을 만한가 | 양치기 소년 — 아무도 경보를 안 믿음 |
| **재현율** (recall) | TP / (TP+FN) | **실제 나쁨 중**, 얼마나 잡았나 | 조용한 재난 — 위험한 날 안심 문자 |

분모가 다릅니다 — 정밀도는 **예측 기준**, 재현율은 **실제 기준**. 그리고 이 둘은 임계값을 사이에
둔 시소입니다: 임계값을 내리면 재현율↑ 정밀도↓, 올리면 그 반대. **둘 다 최고인 지점은 없습니다.**

### F1 — 시소의 절충점

F1은 정밀도와 재현율의 **조화평균**입니다: `F1 = 2·P·R / (P+R)`.

왜 산술평균이 아니라 조화평균? 산술평균은 한쪽이 0이어도 다른 쪽이 1이면 0.5가 나옵니다
("전부 경보"의 P 0.14, R 1.0 → 산술 0.57로 그럴듯해 보임). 조화평균은 **작은 쪽에 끌려가므로**
(같은 경우 F1 0.24) 한쪽을 포기한 모델에 후한 점수를 주지 않습니다.

### ROC 곡선과 AUC — 임계값 없는 성적표

정밀도/재현율/F1은 전부 **임계값 하나를 정한 뒤의** 점수입니다. "모델 자체"의 등급을 매기려면
임계값 전체를 훑어야 합니다. ROC 곡선은 임계값을 1→0으로 내리며 (헛경보율, 재현율)을 찍은
곡선이고, **AUC**는 그 아래 면적입니다.

| AUC | 뜻 |
|---|---|
| 1.0 | 완벽 — 어떤 임계값에서든 양/음성을 완전히 가름 |
| 0.8 | 무작위로 뽑은 (나쁨 날, 아닌 날) 쌍에서 나쁨 날에 더 높은 확률을 줄 확률 80% |
| 0.5 | 동전 던지기 — 확률 순서에 정보가 없음 |

**용도 구분** — 모델끼리 비교·선택은 AUC로(임계값 독립), 운영 성적 보고는 그 임계값의
정밀도/재현율로. 하나 더: 양성이 아주 드물면 ROC가 후해 보이는 함정이 있어 PR 곡선을 함께 봅니다
(이 이야기는 [Day 060](day-060.md) 불균형에서).

### Step 0. 어제 모델 재구성 (1교시)

```python
# day057_metrics.py — 분류 지표: 혼동행렬부터 AUC까지
import numpy as np
import pandas as pd
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import (classification_report, confusion_matrix, f1_score,
                             precision_score, recall_score, roc_auc_score)
from sklearn.preprocessing import StandardScaler

pd.set_option("display.width", 140)
df = pd.read_csv("data/air_daily.csv", parse_dates=["date"])
F10 = ["pm10", "pm25", "o3", "no2", "co", "so2", "temp", "humidity", "wind_speed", "precip"]
d = df.dropna(subset=F10).copy()
d["bad_next"] = (d.pm25_next >= 36).astype(int)
tr = d[d.date < "2026-01-01"]; te = d[d.date >= "2026-01-01"]
ytr, yte = tr.bad_next, te.bad_next

sc = StandardScaler().fit(tr[F10])
clf = LogisticRegression(max_iter=5000).fit(sc.transform(tr[F10]), ytr)
proba = clf.predict_proba(sc.transform(te[F10]))[:, 1]
pred = (proba >= 0.5).astype(int)
```

### Step 1. 혼동행렬을 손으로 검산 (2교시)

```python
print("== A. 혼동행렬 (임계값 0.5) ==")
cm = confusion_matrix(yte, pred)
print(cm)
tn, fp, fn, tp = cm.ravel()
print(f"TN {tn} · FP {fp} · FN {fn} · TP {tp}")
print(f"정밀도 = {tp}/{tp}+{fp} = {precision_score(yte, pred):.3f}")
print(f"재현율 = {tp}/{tp}+{fn} = {recall_score(yte, pred):.3f}")
print(f"F1     = {f1_score(yte, pred):.3f}")
```

실행 결과:

```

 [ 80  41]]
TN 696 · FP 51 · FN 80 · TP 41
정밀도 = 41/41+51 = 0.446
재현율 = 41/41+80 = 0.339

```

읽어 봅시다. test 868일 중:

| FP 51 | **헛경보 51일** | "또 틀렸네" 51번 |
| **FN 80** | **놓친 나쁨 80일** | 위험한 날 안심 문자 80번 — 최악 |
| TP 41 | 적중 41일 | 서비스의 존재 이유 |

정확도 0.849의 실체가 이것입니다 — **나쁨 121일 중 80일을 놓치고도** 0.849가 나옵니다
(TN 696이 점수를 다 벌어 줌). 어제 "정확도는 나침반이 아니다"의 해부도입니다.

### Step 3. 임계값 곡선 — 시소를 숫자로 (4~5교시)

```python
print("== C. 임계값별 정밀도-재현율-F1 ==")
print("임계값 | 정밀도 | 재현율 |  F1")
best_t, best_f1 = 0, 0
for t in np.arange(0.05, 0.95, 0.05):
    p_t = (proba >= t).astype(int)
    if p_t.sum() == 0:
        continue
    f1 = f1_score(yte, p_t)
    if f1 > best_f1:
        best_t, best_f1 = t, f1
    if round(t * 100) % 10 == 0 or abs(t - 0.25) < 0.01 or abs(t - 0.35) < 0.01:
        print(f"  {t:.2f} | {precision_score(yte, p_t):5.3f} | {recall_score(yte, p_t):5.3f} | {f1:5.3f}")
print(f"F1 최대: 임계값 {best_t:.2f} → F1 {best_f1:.3f}")
```

### Step 5. 지표 선택 토론을 숫자로 — 암 진단 vs 스팸 필터 (7교시)

고전 토론: "암 진단은 재현율, 스팸 필터는 정밀도"라고 외우지 말고, **비용을 넣어 계산**해 봅니다.
우리 확률 출력에 두 가지 비용 구조를 대 봅니다.

```python
print("\n== E. 비용 시나리오별 최적 임계값 ==")
for name, c_fn, c_fp in [("경보 서비스(놓침이 10배 비쌈)", 10, 1), ("광고 발송(헛발송이 5배 비쌈)", 1, 5)]:
    best = min(((c_fn * ((proba < t) & (yte == 1)).sum() + c_fp * ((proba >= t) & (yte == 0)).sum(), t)
                for t in np.arange(0.05, 0.95, 0.05)))
    print(f"  {name}: 최적 임계값 {best[1]:.2f} (총비용 {best[0]})")
```

실행 결과:

```
== E. 비용 시나리오별 최적 임계값 ==
  경보 서비스(놓침이 10배 비쌈): 최적 임계값 0.05 (총비용 454)
  광고 발송(헛발송이 5배 비쌈): 최적 임계값 0.90 (총비용 127)
```

**같은 모델, 같은 확률인데 최적 임계값이 0.05와 0.90.** "암 진단 vs 스팸"의 정체는 모델 문제가
아니라 **비용 구조 문제**입니다. FN이 비싸면(암, 경보) 임계값을 바닥까지 내려 재현율을 사고,
FP가 비싸면(스팸 차단, 광고) 천장까지 올려 정밀도를 삽니다. 지표 선택 근거를 물으면
이 비용 표에서 시작하세요 — MP2 보고서의 "지표 선택 근거"가 이것입니다.

## ⑤ 자주 하는 실수

### 혼동행렬의 방향을 착각함

**증상** — TP와 TN을 바꿔 읽거나, 행·열을 뒤집어 해석.
**원인** — sklearn은 **행=실제, 열=예측**, 클래스 순서 `[0, 1]` 이라 **왼쪽 위가 TN**입니다. 교과서 그림(왼쪽 위 TP)과 다릅니다.
**해결** — `tn, fp, fn, tp = confusion_matrix(y, pred).ravel()` 로 이름 붙여 받는 습관을 들이세요.

### AUC를 predict 결과(0/1)로 계산함

**증상** — 같은 모델의 AUC가 문서(0.818)보다 한참 낮은 0.635.
**원인** — `roc_auc_score(y, clf.predict(X))` — 0/1로 뭉갠 뒤에는 확률 순서 정보가 사라져 임계값 하나짜리 점수가 됩니다.
**해결** — AUC에는 반드시 확률을: `roc_auc_score(y, clf.predict_proba(X)[:, 1])`.

### 높은 임계값에서 정밀도 경고

```
UndefinedMetricWarning: Precision is ill-defined and being set to 0.0 due to no predicted
samples. Use `zero_division` parameter to control this behavior.
```

**원인** — 임계값이 너무 높아 양성 예측이 0건이면 정밀도의 분모(TP+FP)가 0입니다.
**해결** — 그 임계값은 "경보를 아예 안 울리는 설정"이라는 뜻입니다. 곡선에서 제외하거나 `zero_division=0` 을 명시하고, 값이 0으로 찍힌 게 버그가 아님을 이해하세요.

### 재현율 100%를 자랑함

**증상** — "재현율 1.0 달성!" — 임계값 0.0으로 전 날짜 경보.
**원인** — 재현율은 "전부 양성"이라 하면 공짜로 1.0이 됩니다. 정밀도(0.139)를 같이 봐야 합니다.
**해결** — 재현율·정밀도는 **반드시 쌍으로** 보고합니다. 절충 한 줄 요약이 필요하면 F1.

### 지표를 정하지 않고 실험부터 시작함

**증상** — 실험 10개를 돌린 뒤 "어느 게 좋은 거지?" — 표마다 이기는 모델이 다름.
**원인** — 주 지표를 먼저 안 정하면 실험 후에 유리한 지표를 고르게 됩니다(체리피킹).
**해결** — [Day 051](day-051.md) 문제 정의의 3요소에 지표가 있는 이유입니다. **실험 전에** 주 지표 1 + 보조 2를 문서로 박아 두세요 (MP2 기획서 양식 그대로).

## ⑥ 확인 문제

**Q1.** 혼동행렬이 `TN 696, FP 51, FN 80, TP 41` 일 때, 정밀도와 재현율을 계산하고
각각을 "경보 서비스" 언어로 한 문장씩 번역하세요.

<details>
<summary>답 보기</summary>

정밀도 = 41/(41+51) = **0.446** — "경보를 울린 날 중 45%만 실제로 나빴다 (둘 중 하나는 헛경보)".
재현율 = 41/(41+80) = **0.339** — "실제 나쁜 날의 34%만 잡아냈다 (셋 중 둘은 놓침)".

</details>

**Q2.** 모델 A는 AUC 0.82, 모델 B는 AUC 0.74입니다. 그런데 임계값 0.5의 F1은 B가 더 높습니다.
어느 모델을 채택해야 하나요?

<details>
<summary>답 보기</summary>

일반적으로 **A**입니다. F1은 임계값 0.5 하나에서의 점수일 뿐이고, 임계값은 우리가 자유롭게 옮길 수
있습니다(어제 Step 3). AUC가 높다는 것은 확률의 순서가 더 좋다는 뜻이라, A의 임계값을 조정하면
B의 최적 F1 이상을 얻을 가능성이 높습니다. 채택 후 서비스 비용 구조에 맞춰 A의 임계값을 정합니다.

</details>

**Q3.** Step 5에서 같은 모델의 최적 임계값이 0.05(경보)와 0.90(광고)으로 갈렸습니다.
이 사실이 "모델 개발"과 "서비스 운영"의 분업에 시사하는 바를 두 문장으로 쓰세요.

<details>
<summary>답 보기</summary>

모델(확률 출력)은 서비스 정책과 독립적으로 개발·평가(AUC)할 수 있고, 임계값은 비용 구조를 아는
운영·기획이 정하는 **정책 파라미터**입니다. 따라서 서빙 API는 0/1이 아니라 확률을 반환하도록 설계하고
(대단원 04), 임계값은 코드 밖 설정으로 두는 것이 옳습니다.

</details>
