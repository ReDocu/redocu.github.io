## ① 학습 목표

이 레슨을 마치면 이렇게 할 수 있습니다.

- 모델이 **이해한 것**과 **외운 것**을 점수로 구분할 수 있다 (과적합).
- train/test를 분리하고, **test 세트를 단 한 번만** 쓰는 원칙을 지킬 수 있다.
- 데이터 누수 3유형(타깃 누수 · 시점 누수 · 전처리 누수)을 식별하고 만들지 않을 수 있다.
- 시계열 데이터에서 **무작위 분할이 왜 반칙인지** 실험으로 보이고, 시간 기준으로 나눌 수 있다.

## ② 왜 필요한가

어제의 마지막 출력을 다시 봅시다.

```
전체 데이터에 대한 점수 R²: 0.732
…그럴듯해 보이지만, 이 점수에는 심각한 함정이 있습니다.
```

오늘 이 함정을 직접 엽니다. 결론부터 말하면 **저 모델의 진짜 실력은 R² 0.258입니다.**
0.732는 모델이 답을 외웠기 때문에 나온 숫자입니다.

이것이 왜 심각한가? 실무 시나리오로 바꿔 보겠습니다.

```
당신:   "예보 모델 R² 0.73입니다. 배포하시죠."
팀장:   "좋네요. 배포합시다."
(2주 뒤)
운영팀: "예보가 계속 빗나갑니다. 측정해 보니 R² 0.26인데요?"
당신:   "…제 컴퓨터에서는 0.73이었는데…"
```

**모델 성능을 잘못 재는 것은 ML에서 가장 비싼 실수입니다.** 코드가 죽는 버그는 배포 전에 들키지만,
점수를 부풀리는 버그(누수)는 **배포 후에, 고객 앞에서** 들킵니다. 에러 메시지도 없습니다.
점수가 오히려 **좋아 보이기 때문에** 아무도 의심하지 않습니다.

오늘은 이 조용한 버그를 **일부러 네 가지 방법으로 만들어 보고**, 각각을 교정합니다.

## ③ 개념 설명

### 암기와 이해 — 과적합

| 학생 | 공부 방법 | 문제집 점수 | 새 문제(수능) 점수 |
|---|---|---|---|
| A | 원리를 이해 | 85점 | **82점** |
| B | 답을 통암기 | **100점** | 40점 |

모델도 똑같습니다. **학습 데이터를 과하게 따라가 새 데이터에서 무너지는 것**을
**과적합**(overfitting)이라 합니다. 어제의 KNN이 학생 B입니다 — KNN은 극단적인 경우
"자기 자신"을 가장 비슷한 이웃으로 찾습니다. 답안지를 들고 시험장에 들어간 셈입니다.

```
                 학습 데이터 점수     새 데이터 점수
과소적합(모자람)      낮음                낮음         → 모델이 너무 단순
적정                 높음                높음         → 목표
과적합(외움)         매우 높음            낮음         → 모델이 학습 데이터를 외움
```

**중요한 것은 두 점수의 관계입니다.** 학습 점수만 보면 과적합일수록 좋아 보입니다.
그래서 반드시 **모델이 본 적 없는 데이터**로 점수를 재야 합니다.

### train / test 분리 — 시험지는 미리 보여주지 않는다

```
전체 데이터
├── train (학습용)  ── model.fit() 에 들어감. 모델이 마음껏 봄
└── test  (평가용)  ── 금고에 넣어 둠. 마지막에 딱 한 번 엶
```

두 가지 규칙만 기억하면 됩니다.

| 규칙 | 이유 |
|---|---|
| test는 학습의 **어떤 단계에도** 관여하지 않는다 | 전처리 통계·특성 선택·튜닝까지 전부 포함입니다 |
| test 점수는 **한 번만** 잰다 | test 점수를 보고 모델을 고치기 시작하면, 그 순간부터 test에 과적합이 시작됩니다 (튜닝용 데이터는 따로 — [Day 061](day-061.md)) |

### 데이터 누수 — 시험 정보가 새는 세 가지 경로

**데이터 누수**(data leakage)란 **예측 시점에 알 수 없는 정보**가 학습 과정에 흘러드는 모든 상황입니다.
판별 질문은 어제 배운 그 문장 하나입니다 — **"이 값을 예측 시점에 알 수 있는가?"**

| 유형 | 무엇이 새나 | 오늘의 재현 실험 | 실무 예 |
|---|---|---|---|
| **① 타깃 누수** | 정답(미래)이 특성에 섞임 | 중심 이동평균 (실험 3) | "이번 달 해지 여부" 예측에 "다음 달 청구액 0원" 특성 |
| **② 시점 누수** | 미래의 행이 train에 섞임 | 무작위 분할 (실험 2) | 시계열을 `train_test_split` 으로 나눔 |
| **③ 전처리 누수** | test의 통계량이 전처리에 섞임 | 전체 데이터로 스케일러 fit (실험 4) | 평균·표준편차·결측 대치값을 전체로 계산 |

### 시계열은 시간으로 나눈다

우리 데이터는 시계열입니다. 어제와 오늘의 pm25는 강하게 이어져 있습니다(상관 0.745).
무작위로 나누면 이런 일이 벌어집니다.

```
무작위 분할:   3/12(train)  3/13(test)  3/14(train)  3/15(test) …
                              ↑ 3/12와 3/14를 다 본 모델에게 3/13을 묻는다
                                — 앞뒤 답을 보여주고 가운데를 맞히게 하는 꼴

시간 분할:     |──────── train (2024-07 ~ 2025-12) ────────|── test (2026-01~) ──|
                              ↑ 실제 운영과 같은 상황: 과거로 배워 미래를 맞힌다
```

모델이 배포되면 **반드시 미래를 예측하게 됩니다.** 평가도 같은 방향이어야 정직한 리허설입니다.

## ④ 단계별 실습

오늘 실습은 실험 4개입니다. `day052_leak.py` 하나에 이어 붙이며 진행합니다.

### Step 1. 실험 1 — 어제 점수의 정체 (1~2교시)

```python
# day052_leak.py — 누수를 일부러 만들고, 교정한다
import pandas as pd
from sklearn.linear_model import LinearRegression
from sklearn.metrics import mean_absolute_error
from sklearn.model_selection import train_test_split
from sklearn.neighbors import KNeighborsRegressor

df = pd.read_csv("data/air_daily.csv", parse_dates=["date"])
FEATURES = ["pm10", "pm25", "wind_speed", "humidity", "precip"]
d = df.dropna(subset=FEATURES).copy()
X, y = d[FEATURES], d["pm25_next"]

print("== 실험 1: 문제집으로 시험 보기 vs 새 문제로 시험 보기 ==")
knn = KNeighborsRegressor(5).fit(X, y)
print(f"전체로 학습, 전체로 평가(어제 점수): R² {knn.score(X, y):.3f}")

# 시간 기준 분리: 2026년부터는 모델이 본 적 없는 '미래'
train = d[d.date < "2026-01-01"]
test = d[d.date >= "2026-01-01"]
print(f"train {len(train)}행 (2024-07~2025-12) / test {len(test)}행 (2026-01~06)")

knn2 = KNeighborsRegressor(5).fit(train[FEATURES], train.pm25_next)
r2_time = knn2.score(test[FEATURES], test.pm25_next)
mae_time = mean_absolute_error(test.pm25_next, knn2.predict(test[FEATURES]))
print(f"시간 분리 test: R² {r2_time:.3f}  MAE {mae_time:.2f}")
```

실행 결과:

```
== 실험 1: 문제집으로 시험 보기 vs 새 문제로 시험 보기 ==
전체로 학습, 전체로 평가(어제 점수): R² 0.732
train 2686행 (2024-07~2025-12) / test 884행 (2026-01~06)
시간 분리 test: R² 0.258  MAE 5.44
```

**0.732 → 0.258.** 어제 점수의 65%가 암기였습니다. 진짜 실력(본 적 없는 미래에 대한 예측력)은
R² 0.258, 평균 5.44㎍/㎥ 어긋나는 수준입니다. 이 0.258이 이번 주의 출발선입니다 —
W11~W13 내내 이 숫자를 정직한 방법으로만 끌어올립니다.

### Step 2. 실험 2 — 무작위 분할이라는 반칙 (3교시)

"분리는 했는데 **무작위로** 했다면?" 많은 튜토리얼이 이렇게 합니다.

```python
print("\n== 실험 2: 무작위 분리 vs 시간 분리 ==")
Xtr, Xte, ytr, yte = train_test_split(X, y, test_size=0.25, random_state=42)
knn3 = KNeighborsRegressor(5).fit(Xtr, ytr)
print(f"KNN   무작위: R² {knn3.score(Xte, yte):.3f}   시간: R² {r2_time:.3f}")

lr_r = LinearRegression().fit(Xtr, ytr)
lr_t = LinearRegression().fit(train[FEATURES], train.pm25_next)
print(f"선형  무작위: R² {lr_r.score(Xte, yte):.3f}   시간: R² {lr_t.score(test[FEATURES], test.pm25_next):.3f}")
```

실행 결과:

```
== 실험 2: 무작위 분리 vs 시간 분리 ==
KNN   무작위: R² 0.607   시간: R² 0.258
선형  무작위: R² 0.621   시간: R² 0.400
```

| 모델 | 무작위 분할 | 시간 분할 | 부풀려진 정도 |
|---|---|---|---|
| KNN | 0.607 | **0.258** | 2.4배 |
| 선형 회귀 | 0.621 | **0.400** | 1.6배 |

분리를 "하긴 했는데" 무작위로 하면 여전히 크게 부풀려집니다. test에 있는 3월 13일의
**앞날(3/12)과 뒷날(3/14)을 train에서 이미 봤기 때문**입니다. 고농도 에피소드는 며칠씩
이어지므로, 에피소드의 가운데 날을 빼서 물어보면 못 맞히는 게 이상합니다.

> 주목 — **누수는 모델을 차별하지 않지만 균등하지도 않습니다.** 암기력이 좋은 KNN이
> (0.607) 시간 분할에서 가장 크게 무너집니다(0.258). **누수 환경에서는 "많이 외우는 모델"이
> 유리해 보이기 때문에, 누수는 점수만이 아니라 모델 선택까지 왜곡합니다.**

### Step 3. 실험 3 — 실무에서 가장 흔한 타깃 누수 사고 재현 (5교시)

파생 특성을 만들다 나는 진짜 사고를 재현합니다. "최근 3일 평균 pm25"를 특성으로 추가하는데,
pandas `rolling` 의 옵션 하나가 운명을 가릅니다.

```python
print("\n== 실험 3: 타깃 누수 — 중심 이동평균 ==")
d2 = df.sort_values(["station", "date"]).copy()
g = d2.groupby("station")["pm25"]
d2["ma3_center"] = g.transform(lambda s: s.rolling(3, center=True).mean())  # (어제+오늘+내일)/3 ← 내일!
d2["ma3_trail"] = g.transform(lambda s: s.rolling(3).mean())                # (그제+어제+오늘)/3

for col in ["ma3_center", "ma3_trail"]:
    dd = d2.dropna(subset=FEATURES + [col])
    tr = dd[dd.date < "2026-01-01"]; te = dd[dd.date >= "2026-01-01"]
    m = LinearRegression().fit(tr[FEATURES + [col]], tr.pm25_next)
    print(f"선형 + {col:<10}: 시간 분리 test R² {m.score(te[FEATURES + [col]], te.pm25_next):.3f}")
```

실행 결과:

```
== 실험 3: 타깃 누수 — 중심 이동평균 ==
선형 + ma3_center: 시간 분리 test R² 0.738
선형 + ma3_trail : 시간 분리 test R² 0.413
```

**train/test를 시간으로 완벽하게 나눴는데도** 0.738이 나왔습니다. `center=True` 는
(어제+오늘+**내일**)/3 을 계산합니다 — 내일 pm25가 곧 정답인데, 정답의 3분의 1이
특성 안에 들어앉은 것입니다. 분리를 아무리 잘해도 **특성 자체에 미래가 들어 있으면** 끝입니다.

| | `rolling(3, center=True)` | `rolling(3)` |
|---|---|---|
| 계산 범위 | 어제 + 오늘 + **내일** | 그제 + 어제 + 오늘 |
| 예측 시점에 계산 가능? | ❌ 내일 값이 필요 | ✅ |
| test R² | 0.738 (가짜) | 0.413 (진짜) |

> **점수가 갑자기 확 오르면 기뻐하지 말고 의심하세요.** 특히 특성 하나 추가에 R²가
> 0.1 이상 뛰면, 그 특성의 계산식에 미래나 정답이 들어 있지 않은지부터 봅니다.
> 이번 주 출발선이 0.4 언저리임을 아는 것 — 그것이 **베이스라인을 아는 사람의 후각**입니다.

### Step 4. 실험 4 — 전처리 누수: 작아도 원칙 (6교시)

마지막 유형입니다. 전처리(스케일링)의 **통계량을 어느 데이터로 계산하느냐**의 문제입니다.

```python
print("\n== 실험 4: 스케일링과 전처리 누수 ==")
from sklearn.preprocessing import StandardScaler
from sklearn.metrics import r2_score

# 올바른 방법: train으로만 fit, test는 transform만
sc = StandardScaler().fit(train[FEATURES])
knn_s = KNeighborsRegressor(5).fit(sc.transform(train[FEATURES]), train.pm25_next)
r2_s = r2_score(test.pm25_next, knn_s.predict(sc.transform(test[FEATURES])))
print(f"KNN 스케일 없이     : R² {r2_time:.3f}")
print(f"KNN + 스케일(train만 fit): R² {r2_s:.3f}")

# 누수: test까지 포함해 fit — 평균·표준편차에 미래 정보가 스며든다
sc_all = StandardScaler().fit(d[FEATURES])
knn_l = KNeighborsRegressor(5).fit(sc_all.transform(train[FEATURES]), train.pm25_next)
r2_l = r2_score(test.pm25_next, knn_l.predict(sc_all.transform(test[FEATURES])))
print(f"KNN + 스케일(전체로 fit — 누수): R² {r2_l:.3f}")
```

실행 결과:

```
== 실험 4: 스케일링과 전처리 누수 ==
KNN 스케일 없이     : R² 0.258
KNN + 스케일(train만 fit): R² 0.243
KNN + 스케일(전체로 fit — 누수): R² 0.242
```

여기서 배울 것이 두 가지입니다.

1. **이번에는 누수 티가 안 났습니다** (0.243 vs 0.242). 평균·표준편차는 train과 test가
   비슷해서입니다. 그럼 대충 해도 되나? **안 됩니다.** 언제 티가 나는지는 데이터에 달렸고
   (분포가 변하는 순간 티가 납니다), 원칙은 공짜입니다: **fit은 train에만.**
2. 스케일링이 점수를 올려 주지도 않았습니다(0.258 → 0.243). "KNN엔 스케일링" 같은
   격언도 **실험으로 확인하기 전엔 참이 아닙니다.** (이 데이터에선 값이 큰 pm10·pm25가
   마침 가장 중요한 특성이라, 거리 계산이 그쪽으로 쏠린 것이 오히려 유리했습니다.)

> 규칙을 코드 한 줄로: **`fit_transform` 은 train에만, test에는 `transform` 만.**
> 이 원칙을 사람이 아니라 구조가 지키게 만드는 도구가 sklearn Pipeline이며 [Day 063](day-063.md)에서 배웁니다.

## ⑤ 자주 하는 실수

### X만 dropna 하고 y는 원본에서 가져옴

```
ValueError: Found input variables with inconsistent numbers of samples: [3570, 3642]
```

**원인** — `X = df.dropna(...)[FEATURES]` 로 행을 지웠는데 `y = df["pm25_next"]` 는 안 지운
원본이라 길이가 다릅니다.
**해결** — 걸러낸 DataFrame 하나(`d = df.dropna(subset=FEATURES)`)에서 X와 y를 **함께** 꺼냅니다.

### DataFrame으로 fit 하고 ndarray로 transform (또는 그 반대)

```
UserWarning: X does not have valid feature names, but StandardScaler was fitted with feature names
```

**원인** — fit할 때와 transform할 때 입력 형태(컬럼 이름 유무)가 다릅니다. 경고로 끝날 때도
있지만, **컬럼 순서가 다르면 조용히 틀린 값**이 나옵니다.
**해결** — 전 과정에서 같은 형태(가급적 같은 컬럼 순서의 DataFrame)를 유지합니다.

### test 점수를 보며 모델을 반복 수정함

**증상** — 에러는 없습니다. test 점수가 회를 거듭할수록 좋아지는데, 배포하면 그보다 나쁩니다.
**원인** — test를 수십 번 열어 보며 고르는 순간, **여러분 자신이 test에 과적합**됩니다.
test는 더 이상 "본 적 없는 데이터"가 아닙니다.
**해결** — 모델 선택·튜닝은 train 내부에서(검증 세트/교차검증, [Day 061](day-061.md)), test는 최종 1회.

### `train_test_split` 이 기본으로 섞는다는 걸 모름

**증상** — "시계열인데 나눴으니 됐지"라고 생각했는데 점수가 이상하게 높습니다.
**원인** — `train_test_split` 의 기본값은 `shuffle=True` 입니다. 시계열에 그대로 쓰면 실험 2의 반칙이 됩니다.
**해결** — 시계열은 날짜 조건(`d[d.date < "2026-01-01"]`)으로 직접 나누거나 `TimeSeriesSplit`([Day 061](day-061.md))을 씁니다.

### 점수가 좋아지면 원인을 안 찾음

**증상** — 특성 하나 넣었더니 R²가 0.41 → 0.74. "오늘 컨디션이 좋네"라며 커밋.
**원인** — 실험 3이 정확히 이 사고입니다. 좋아진 이유를 설명 못 하는 개선은 대부분 누수입니다.
**해결** — 개선 폭이 크면 **특성의 계산식**을 소리 내어 읽어 보세요. "어제+오늘+내일의 평균" —
'내일'이 들리는 순간 누수입니다.

## ⑥ 확인 문제

**Q1.** 다음 특성 중 "내일 pm25 예측" 모델에 넣으면 안 되는 것을 모두 고르고, 각각 누수 3유형 중
무엇인지 답하세요.

- (a) 오늘까지의 7일 이동평균 pm25
- (b) 이번 주(월~일) 평균 pm25 — 오늘은 수요일
- (c) 오늘의 풍속
- (d) 내일의 풍속 (기상청 예보값이 아니라 실측값)

<details>
<summary>답 보기</summary>

**(b)와 (d)** 가 누수입니다. (b)는 목·금·토·일의 미래 값이 평균에 들어가므로 **타깃 누수**(미래 정보 유입),
(d)는 내일의 실측값이므로 예측 시점에 알 수 없는 **타깃 누수**입니다. (a)·(c)는 과거·현재 정보만 쓰므로 안전합니다.
단, (d)를 "기상청 **예보값**"으로 바꾸면 예측 시점에 알 수 있는 정보가 되어 합법입니다 — 이 아이디어는 [Day 064](day-064.md)에서 씁니다.

</details>

**Q2.** 실험 2에서 무작위 분할(0.607)과 시간 분할(0.258)의 KNN 점수 차이가 선형 회귀(0.621 vs 0.400)보다
훨씬 큰 이유를 "암기"라는 단어를 써서 설명하세요.

<details>
<summary>답 보기</summary>

KNN은 학습 데이터를 통째로 **암기**해 두고 가장 비슷한 사례를 찾는 모델입니다. 무작위 분할에서는 test 날짜의
바로 앞뒤 날이 train에 있어 "거의 같은 날"을 암기에서 꺼내 쓸 수 있지만, 시간 분할에서는 미래 근처의 사례가
전혀 없어 암기가 무용지물이 됩니다. 규칙(계수)만 배우는 선형 회귀는 암기 의존도가 낮아 낙차가 작습니다.

</details>

**Q3.** 동료가 "결측치를 전체 데이터의 평균으로 채운 뒤 train/test를 나눴다"고 합니다.
어떤 유형의 누수이고, 올바른 순서는 무엇인가요?

<details>
<summary>답 보기</summary>

**전처리 누수**입니다. 대치에 쓴 평균에 test 구간의 값이 섞여 있습니다. 올바른 순서는
① train/test 분리 → ② train의 평균 계산 → ③ 그 값으로 train과 test를 각각 채움.
즉 "fit(통계량 계산)은 train에만"입니다. 이 순서를 코드 구조로 강제하는 것이 [Day 063](day-063.md)의 Pipeline입니다.

</details>
