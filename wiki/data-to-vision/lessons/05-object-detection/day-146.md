### 두 가지 실행 방식

**① CLI (명령줄)**

```bash
yolo detect train \
  data=C:/vision/datasets/cctv_v1/data.yaml \
  model=yolo11n.pt \
  epochs=50 imgsz=640 batch=16 device=0
```

```
장점: 짧다 · 서버에서 돌리기 좋다 · 로그가 깔끔
단점: 결과 객체를 코드로 못 받는다
```

**② Python API**

```python
from ultralytics import YOLO

model = YOLO("yolo11n.pt")
results = model.train(
    data="C:/vision/datasets/cctv_v1/data.yaml",
    epochs=50, imgsz=640, batch=16, device=0,
)
print(results.box.map50)          # ★ 결과를 바로 쓸 수 있음
```

```
장점: 결과를 변수로 받음 · 실험 자동화 가능
단점: 노트북에서 끊기면 커널이 죽음
```

> **★ 우리는 Python API를 씁니다.**

| **`workers`** | 데이터 로딩 프로세스 | **0 (Windows)** / 8 (Linux) | ★ Windows 주의 |

| `pretrained` | 사전학습 사용 | `True` (기본) |
| `optimizer` | 최적화기 | `auto` |
| `lr0` | 초기 학습률 | 0.01 (auto가 알아서) |

| `val` | 매 에폭 검증 | `True` |
| `plots` | 그래프 생성 | `True` |

### `model` — `.pt` vs `.yaml`

```python
YOLO("yolo11n.pt")        # ★ 사전학습 가중치에서 시작 (전이학습)
YOLO("yolo11n.yaml")      # 구조만 가져오고 ★ 밑바닥부터 학습
```

**차이가 극적입니다.**

| | `.pt` (전이학습) | `.yaml` (처음부터) |
|---|---|---|
| 데이터 500장 · 50에폭 | **mAP50 0.76** | mAP50 0.12 |
| 수렴까지 필요 에폭 | 50~100 | 300~500 |
| 필요 데이터 | 수백 장 | 수만 장 |

**왜 이렇게 다른가**

```
COCO 12만 장으로 학습된 가중치는 이미
  · 모서리 · 질감 · 색 대비를 감지하는 필터
  · 사람·차량 같은 일반적 형태
  · 박스를 회귀하는 방법
을 알고 있습니다

우리는 "이 필터들을 우리 데이터에 맞게 조금 조정"만 하면 됩니다
```

> **★ 밑바닥 학습은 연구용입니다.** 실무에서는 항상 사전학습에서 시작합니다.
> 대단원 03의 전이학습([Day 100](../03-ml/day-100.md))과 정확히 같은 원리입니다.

### `imgsz` — 학습 해상도

```
imgsz=640  →  이미지의 긴 변을 640으로 리사이즈 (비율 유지 + 패딩)
```

| imgsz | 속도 | 작은 객체 | 메모리 |
|---|---|---|---|
| 416 | 빠름 | ✗ 약함 | 적음 |
| **640** | 보통 | 보통 | 보통 |
| 960 | 느림 | ✓ 강함 | 많음 |
| 1280 | 매우 느림 | ✓✓ | 매우 많음 |

```
★ 32의 배수여야 합니다 (416, 640, 960, 1280)
  아니면 자동으로 올림 조정됩니다
```

> **★ [Day 142](day-142.md)의 최소 크기 기준과 직결됩니다.**
> `imgsz` 를 640 → 960으로 올리면 최소 크기 기준이 24px → 16px 로 내려갑니다.
> **작은 객체가 중요하면 모델을 키우기 전에 해상도를 올리세요.** ([Day 150](day-150.md)에서 실험)

### `batch` — 배치 크기와 GPU 메모리

```
batch=16  →  이미지 16장을 한 번에 GPU에 올려 처리
```

**메모리 사용량 목안 (yolo11n, imgsz 640)**

| batch | VRAM | 권장 GPU |
|---|---|---|
| 4 | ~1.5 GB | 노트북 GTX |
| 8 | ~2.5 GB | GTX 1660 |
| **16** | **~4 GB** | **RTX 3060 · Colab T4** |
| 32 | ~7 GB | RTX 3080 |
| 64 | ~13 GB | A100 |

```
batch=-1  →  ★ 자동 (GPU 메모리의 60%를 쓰도록 계산)
             편하지만 값이 매번 달라져 실험 비교가 어려움
             → 우리는 고정값을 씁니다
```

**배치 크기가 성능에 미치는 영향**

```
작은 배치 (4~8)
  ✓ 메모리 적게 씀
  ✗ 배치 정규화가 불안정
  ✗ 학습이 느리고 흔들림

큰 배치 (32~64)
  ✓ 안정적 · 빠름
  ✗ 메모리 많이 씀
  ✗ 일반화가 약간 나빠질 수 있음

★ 16이 대부분의 경우 무난합니다
```

### ★ OOM (Out Of Memory) 대처

```
torch.cuda.OutOfMemoryError: CUDA out of memory.
Tried to allocate 2.00 GiB (GPU 0; 15.00 GiB total capacity;
13.21 GiB already allocated)
```

**대처 순서**

```
① batch 를 절반으로          16 → 8 → 4        ★ 1순위
② imgsz 를 낮춤              640 → 512 → 416
③ 더 작은 모델               yolo11s → yolo11n
④ workers 를 줄임            8 → 4 → 0
⑤ cache 끄기                 cache=False
⑥ 다른 프로세스 종료          nvidia-smi 로 확인
⑦ amp=True 확인              (기본 켜짐 — 혼합정밀도)
```

```python
# 메모리 상태 확인
import torch
print(f"할당됨 {torch.cuda.memory_allocated()/1024**3:.2f} GB")
print(f"예약됨 {torch.cuda.memory_reserved()/1024**3:.2f} GB")
torch.cuda.empty_cache()          # ★ 캐시 비우기
```

> 이전 학습이 메모리를 잡고 있는 경우가 많습니다.

### ★ `workers` — Windows의 함정

```python
workers=8          # Linux/Colab 기본
workers=0          # ★ Windows 권장
```

**Windows에서 `workers > 0` 이면 생기는 문제**

```
· 데이터 로더가 프로세스를 fork 하지 못함 (spawn 방식)
· 학습 시작 시 무한 대기하거나
· BrokenPipeError / RuntimeError 발생
· 학습이 오히려 느려짐
```

```python
# ★ 안전한 코드
import platform
WORKERS = 0 if platform.system() == "Windows" else 8
```

**또는 스크립트를 이렇게 감싸면 `workers>0` 도 동작합니다.**

```python
if __name__ == "__main__":          # ★ Windows 멀티프로세싱 필수
    model.train(..., workers=4)
```

## ④ 단계별 실습

### Step 1. 조별 GPU 시간표 작성

```python
from datetime import datetime, timedelta
from pathlib import Path

import pandas as pd

WORK = Path("C:/vision/day146")
WORK.mkdir(parents=True, exist_ok=True)

TEAMS = ["1조", "2조", "3조", "4조", "5조", "6조", "7조", "8조"]
DEVICES = ["GPU서버-A", "GPU서버-B", "Colab(개인)"]
SLOT_MIN = 45

start = datetime(2026, 1, 1, 13, 0)          # 5교시 시작
rows = []
for i, team in enumerate(TEAMS):
    dev = DEVICES[i % 2]                      # 서버 2대를 번갈아
    slot = i // 2
    t0 = start + timedelta(minutes=SLOT_MIN * slot)
    t1 = t0 + timedelta(minutes=SLOT_MIN)
    rows.append({
        "조": team, "장비": dev,
        "시작": t0.strftime("%H:%M"), "종료": t1.strftime("%H:%M"),
        "용도": "1차 학습 (yolo11n, 50ep)",
        "예상 소요": "25~35분",
        "백업": "Colab",
    })

sched = pd.DataFrame(rows)

print("=" * 96)
print("조별 GPU 사용 시간표 — Day 146")
print("=" * 96)
print(sched.to_string(index=False))
print("-" * 96)
print("""
★ 운영 규칙
```

```python
"""watch_training.py — 다른 터미널에서 진행 상황 확인"""
import time
from pathlib import Path

import pandas as pd

RUN = Path("C:/vision/runs/exp01_n_640_50ep")
CSV = RUN / "results.csv"


def show(n_tail=8):
    if not CSV.exists():
        print("아직 results.csv 가 없습니다 (첫 에폭 진행 중)")
        return
    df = pd.read_csv(CSV)
    df.columns = [c.strip() for c in df.columns]

    cols = {
        "epoch": "ep",
        "train/box_loss": "box",
        "train/cls_loss": "cls",
        "train/dfl_loss": "dfl",
        "metrics/precision(B)": "P",
        "metrics/recall(B)": "R",
        "metrics/mAP50(B)": "mAP50",
        "metrics/mAP50-95(B)": "mAP50-95",
    }
    sub = df[[c for c in cols if c in df.columns]].rename(columns=cols)

    print("=" * 84)
    print(f"학습 진행 — {len(df)} 에폭 완료")
    print("=" * 84)
    print(sub.tail(n_tail).to_string(index=False,
                                     float_format=lambda x: f"{x:.4f}"))
    print("-" * 84)

    best_i = sub["mAP50"].idxmax()
    print(f"  ★ 최고 mAP50 {sub['mAP50'].max():.4f} "
          f"(에폭 {int(sub.loc[best_i, 'ep'])})")
    print(f"    현재 mAP50 {sub['mAP50'].iloc[-1]:.4f}")

    # 개선 정체 확인
    since = len(sub) - 1 - best_i
    print(f"    최고 이후 {since}에폭 경과 "
          f"{'★ patience 임박' if since > 20 else ''}")
    print("=" * 84)


show()
```

### (a) 4GB VRAM에서 OOM

**조정 순서**

```
① batch: 16 → 8 → 4              ★ 1순위
② imgsz: 640 → 512               (그래도 안 되면)
③ model: yolo11s → yolo11n       (이미 n이면 다음)
④ workers: 0 (Windows는 원래 0)
⑤ cache=False (기본값 확인)
```

**권장 설정**

```python
model.train(
    data=DATA, epochs=50,
    imgsz=640,
    batch=4,              # ★ 4GB면 4가 안전선
    device=0,
    workers=0,
    amp=True,             # 혼합정밀도 (기본 True) — 메모리 절약
)
```

**batch=4의 부작용과 대응**

```
· 배치 정규화가 불안정 → 학습이 흔들림
· 에폭당 시간이 오히려 늘 수 있음 (GPU 활용률 저하)

★ 대응: 실제 배치를 키우는 대신 "누적"
  Ultralytics 는 nbs(nominal batch size, 기본 64)로
  자동 gradient accumulation 을 합니다
  → batch=4 여도 내부적으로 16스텝 누적해 64처럼 동작
  → 걱정하지 않아도 됩니다
```

> **★ 그래도 안 되면 Colab을 쓰세요.** T4는 15GB입니다.

### (b) 작은 객체를 못 찾음

**★ 조정 순서 (효과 큰 순)**

```
① imgsz: 640 → 960 또는 1280      ★ 가장 효과적
   근거: 30px 객체가 640에서는 10px, 960에서는 15px
        모델이 볼 수 있는 픽셀 수가 1.5배

② mosaic 유지 (기본 1.0)
   근거: Mosaic 은 이미지를 축소해 합치므로 작은 객체 학습에 도움

③ scale 을 조정: 0.5 → 0.3
   근거: 축소를 덜 하면 작은 객체가 더 작아지지 않음

④ 모델 크기 s 로: yolo11n → yolo11s
   근거: 특징 추출 능력 향상. 단 효과는 ①보다 작음

⑤ ★ 데이터: 작은 객체가 있는 이미지를 추가 수집
```

**설정**

```python
model.train(
    data=DATA, epochs=50,
    imgsz=960,            # ★ 640 → 960
    batch=8,              # ★ 해상도가 커지면 배치를 줄여야 함
    device=0, workers=0,
    scale=0.3,            # 축소 폭 제한
    mosaic=1.0,
)
```

**트레이드오프**

```
imgsz 640 → 960
  · 학습 시간   1.0배 → 약 2.2배
  · 추론 속도   16 FPS → 7 FPS      ★ 라즈베리파이에 치명적
  · mAP(소형)   0.31 → 0.52

★ Day 153 · 168 에서 속도와의 균형을 다시 판단합니다
```

```python
]

results = {}
for c in CONDITIONS:
    m = YOLO(c.pop("model"))
```

```
③ seed 하나로는 부족
```
