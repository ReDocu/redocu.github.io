## 2. 막히는 상황

어제 만든 별은 **한 방향으로만** 흐르고 화면 밖으로 나가면 반대편에서 다시 나왔다.

```c
g_stars[i].x += g_stars[i].speed * dt;      // x만 증가

if (g_stars[i].x >= SCREEN_W)
    g_stars[i].x = 0;                        // 반대편으로 순간이동
```

벽돌깨기의 공은 다르다.

```
   별:  →→→→→→→→ (밖으로) ... (반대편에서) →→→→→→→→

   공:      ╲
              ╲
                ●  ← 벽에 닿으면
              ╱      방향을 바꿔서
            ╱        돌아와야 한다
          ●
```

두 가지가 필요하다.

```
   ① 대각선 이동     x와 y가 동시에 변해야 한다
   ② 반사            벽에 닿으면 "방향을 바꾼다"
                      ▲
                      └── 이걸 어떻게 코드로 쓰지?
```

> **방향과 속도를 함께 다루는 방법이 필요하다.** → **속도 벡터**

## 3. 개념

### 3-1. 속도 벡터 — 방향과 빠르기를 한 세트로

**왜 필요한가** — "오른쪽 아래로 초속 30칸" 을 두 개의 숫자로 표현한다.

```c
typedef struct
{
    double x,  y;        // 위치 (position)
    double vx, vy;       // 속도 (velocity)
} Ball;
```

```
   위치 (x, y)  →  지금 어디에 있나
   속도 (vx, vy) →  1초에 x로 얼마, y로 얼마 움직이나

              vy = -18  (위로)
                  ↑
                  │
   vx = -25 ←─────●─────→ vx = +25
                  │
                  ↓
              vy = +18  (아래로)

   vx = +25, vy = -18  →  오른쪽 위로 날아간다
```

**이동은 한 줄**

```c
ball.x += ball.vx * dt;          // Day 21의 델타 타임
ball.y += ball.vy * dt;
```

> **Day 13의 `(dx, dy)`가 발전한 형태다.**
>
> | Day 13 | 오늘 |
> |---|---|
> | `dx, dy`는 -1/0/+1 | `vx, vy`는 실수 (초당 이동량) |
> | 한 칸씩 이동 | 시간에 비례해 이동 |
> | 키 입력 때만 | 매 프레임 자동으로 |

### 3-2. 속력과 방향 — 벡터의 두 성분

**왜 필요한가** — "속도를 20% 올려라" 같은 요구를 처리하려면 분리해서 생각해야 한다.

```
   속도 벡터 (vx, vy)

   속력(speed) = √(vx² + vy²)          ← 얼마나 빠른가 (크기)
   방향        = vx와 vy의 비율          ← 어디로 가는가
```

```
                 ╱│
   speed   ╱      │ vy
        ╱         │
     ●────────────┘
          vx

   피타고라스 정리:  speed² = vx² + vy²
```

```c
#include <math.h>

double GetSpeed(const Ball* b)
{
    return sqrt(b->vx * b->vx + b->vy * b->vy);
}
```

**속력만 바꾸기 (방향 유지)**

```c
void SetSpeed(Ball* b, double newSpeed)
{
    double cur = GetSpeed(b);
    if (cur < 0.0001) return;            // 0으로 나누기 방지

    b->vx = b->vx / cur * newSpeed;      // 비율 유지하며 크기만 조정
    b->vy = b->vy / cur * newSpeed;
}
```

```
   현재  vx=30, vy=40   →  speed = 50
   목표 speed = 100

   vx = 30 / 50 × 100 = 60
   vy = 40 / 50 × 100 = 80
                          →  speed = √(60²+80²) = 100  ✔  방향은 그대로
```

> `vx / cur` 처럼 **속력으로 나누면 크기가 1인 벡터**가 된다.
> 이것을 **정규화(normalize)** 라고 한다. Day 66(포탄 발사), Day 91(차량 조향)에서 다시 쓴다.

### 3-3. 반사 — 부호를 뒤집는다

**왜 필요한가** — 오늘의 핵심. 놀랍도록 간단하다.

```
   왼쪽/오른쪽 벽에 부딪히면  →  vx = -vx      (x 방향만 뒤집기)
   위/아래 벽에 부딪히면      →  vy = -vy      (y 방향만 뒤집기)
```

```
   [ 오른쪽 벽 충돌 ]

        vx=+25              vx=-25
   ●──────────→│        │←──────────●
        vy=+18  │        │  vy=+18
                │        │
                벽        벽

   ★ vy는 그대로. vx만 부호가 바뀐다
     → 입사각과 반사각이 같아진다
```

```
   [ 위 벽 충돌 ]

   ─────────────────────  천장
          ↗   ↘
        ╱       ╲
      ●           ●

   vy = -18  →  vy = +18       vx는 그대로
```

```c
if (ball.x <= 0)          ball.vx = -ball.vx;      // 왼쪽 벽
if (ball.x >= SCREEN_W-1) ball.vx = -ball.vx;      // 오른쪽 벽
if (ball.y <= 0)          ball.vy = -ball.vy;      // 위쪽 벽
if (ball.y >= SCREEN_H-1) ball.vy = -ball.vy;      // 아래쪽 벽
```

> **이게 전부다.** 물리 공식도, 삼각함수도 필요 없다.
> 축에 나란한 벽(axis-aligned wall)이기 때문에 이렇게 단순해진다.
>
> Day 66(포트리스)에서 비스듬한 지형에 튕기려면 진짜 반사 공식이 필요해진다.
> 그때까지는 이 방식으로 충분하다.

### 3-4. ⚠️ 벽에 박히는 문제 — 위치 보정

**왜 필요한가** — 부호만 뒤집으면 공이 벽에 붙어서 부들부들 떤다.

```
   [ 문제 상황 ]

   프레임 1:  x = 39.2   (SCREEN_W = 40)
   프레임 2:  x = 41.7   → 벽 밖! → vx 뒤집기 → vx = -25
   프레임 3:  x = 41.7 - 0.4 = 41.3   → 여전히 벽 밖! → vx 또 뒤집기 → vx = +25
   프레임 4:  x = 41.7   → 또 밖 → 또 뒤집기...

   ★ 공이 벽 밖에서 부들부들 떨며 갇힌다
```

```
              벽
              │
        ●←→●  │     ← 매 프레임 부호가 뒤집혀 진동한다
              │
```

**해결: 뒤집으면서 위치도 벽 안으로 밀어 넣는다**

```c
if (ball.x < 0)
{
    ball.x  = 0;                     // ★ 위치 보정
    ball.vx = -ball.vx;
}

if (ball.x > SCREEN_W - 1)
{
    ball.x  = SCREEN_W - 1;          // ★ 위치 보정
    ball.vx = -ball.vx;
}
```

```
   [ 보정 후 ]

   프레임 2:  x = 41.7  →  x = 39.0 으로 밀어넣고, vx = -25
   프레임 3:  x = 38.6  →  벽 안. 정상 이동  ✔
```

> **"부호 뒤집기 + 위치 보정"은 항상 한 세트다.**
> 하나만 하면 반드시 버그가 난다.

**더 정확한 방법 (참고)**

```c
// 넘어간 만큼 되돌린다 (반사 위치를 정확히 맞춤)
if (ball.x < 0)
{
    ball.x  = -ball.x;               // -2.3 → 2.3
    ball.vx = -ball.vx;
}
```

```
   단순 보정:  벽에 딱 붙여 놓는다      (구현 간단, 미세하게 부정확)
   정확 보정:  넘어간 거리만큼 반사시킨다 (물리적으로 정확)

   게임에서는 대부분 단순 보정으로 충분하다.
```

### 3-5. 터널링 — 빠른 물체가 벽을 뚫는다

**왜 필요한가** — 속도를 올리면 반드시 만나는 문제다. Day 24, Day 67에서 또 나온다.

```
   공 속도 = 초당 3000칸, 화면 폭 = 40칸, dt = 0.016초

   1프레임 이동량 = 3000 × 0.016 = 48칸

   프레임 N   : x = 5
   프레임 N+1 : x = 53      ← 벽(40)을 지나쳐 버렸다
                              그런데 x > 39 이므로 반사는 된다

   더 빠르면?  x = 5  →  x = 405
                          ← 화면을 10번 왕복할 거리를 한 프레임에 갔다
                            반사는 한 번만 일어난다  →  이상해진다
```

**대책**

| 방법 | 설명 | 난이도 |
|---|---|---|
| **속도 상한** | 한 프레임 이동량이 화면 크기를 넘지 않게 제한 | 쉬움 ← **오늘은 이걸로** |
| 이동 분할 | 이동을 여러 조각으로 나눠 각각 검사 | 중간 |
| 연속 충돌 검사 (CCD) | 이동 경로와 벽의 교차점을 계산 | 어려움 |

```c
// 속도 상한
const double MAX_SPEED = 60.0;              // 초당 60칸

double speed = GetSpeed(&ball);
if (speed > MAX_SPEED)
    SetSpeed(&ball, MAX_SPEED);
```

> Unity에서 빠른 물체가 벽을 뚫을 때 `Collision Detection`을 `Continuous`로 바꾸는데(Day 73),
> 그게 바로 CCD다. **원인은 오늘 배운 이 문제와 똑같다.**

### 3-6. 실수 좌표와 정수 화면

**왜 필요한가** — 콘솔은 칸 단위인데 좌표는 실수다. 변환이 필요하다.

```c
double x = 12.7;

int sx = (int)x;                 // 12  (버림)
```

```
   실수 좌표 (물리)          정수 좌표 (화면)

   x = 12.0  ─┐
   x = 12.3   ├─▶  칸 12
   x = 12.9  ─┘
   x = 13.1  ────▶  칸 13

   ★ 위치는 실수로 계산하고, 그릴 때만 정수로 바꾼다
```

> ### ⚠️ 위치를 정수로 저장하면 안 된다
>
> ```c
> int x;
> x += 25 * 0.016;         // 25 × 0.016 = 0.4  →  int라 0이 된다
>                          //  → 공이 절대 안 움직인다!
> ```
>
> **위치와 속도는 `double`, 그릴 때만 `(int)` 캐스팅.**
> 이 원칙은 24주 내내 유지된다.

## 4. 따라 만들기

### Step 1 — 공 구조체와 이동

```c
#include <stdio.h>
#include <conio.h>
#include <windows.h>
#include <time.h>
#include <math.h>

#define SCREEN_W 40
#define SCREEN_H 16

typedef struct
{
    double x, y;
    double vx, vy;
    char   symbol;
    int    active;
} Ball;

Ball g_ball;

void InitBall(void)
{
    g_ball.x  = SCREEN_W / 2.0;
    g_ball.y  = SCREEN_H / 2.0;
    g_ball.vx = 25.0;              // 초당 25칸 오른쪽
    g_ball.vy = 18.0;              // 초당 18칸 아래
    g_ball.symbol = '@';
    g_ball.active = 1;
}

void UpdateBall(Ball* b, double dt)
{
    b->x += b->vx * dt;
    b->y += b->vy * dt;
}
```

**✅ 여기까지 실행하면** — 공이 오른쪽 아래로 날아가서 **화면 밖으로 사라진다.**

### Step 2 — 벽 반사 (위치 보정 없이)

```c
void UpdateBall(Ball* b, double dt)
```

### Step 3 — 위치 보정 추가

```c
void UpdateBall(Ball* b, double dt)
{
    b->x += b->vx * dt;
    b->y += b->vy * dt;

    if (b->x < 0)
    {
        b->x  = 0;                          // ★ 위치 보정

    {
        b->x  = SCREEN_W - 1;               // ★ 위치 보정

    if (b->y < 0)
    {
        b->y  = 0;
        b->vy = -b->vy;
    }
    else if (b->y > SCREEN_H - 1)
    {
        b->y  = SCREEN_H - 1;
        b->vy = -b->vy;
    }
}
```

**✅ 여기까지 실행하면** — 공이 **매끄럽게 벽에 튕기며** 화면 안을 계속 돌아다닌다.

### Step 7 — 터널링 확인

`+`를 계속 눌러 속도를 극단적으로 올린다.

**✅ 여기까지 실행하면**
- 공이 순간이동하는 것처럼 보인다
- 벽을 뚫고 나가거나, 화면 밖에서 튕긴다
- 반사 카운트가 이상하게 올라간다

**속도 상한 추가**

```c

void SetSpeed(Ball* b, double newSpeed)
{
    if (newSpeed > MAX_SPEED) newSpeed = MAX_SPEED;     // ★ 상한
    if (newSpeed < 1.0)       newSpeed = 1.0;

    // ... 이하 동일 ...
}
```

**✅ 여기까지 실행하면** — 아무리 `+`를 눌러도 공이 통제 범위 안에 머문다.

### Step 8 — 공 여러 개 (배열)

```c
#define MAX_BALLS 20

Ball g_balls[MAX_BALLS];
int  g_ballCount = 0;

void AddBall(void)
{
    if (g_ballCount >= MAX_BALLS) return;

    Ball* b = &g_balls[g_ballCount];          // ★ 포인터 (Day 18)

    b->x  = SCREEN_W / 2.0;
    b->y  = SCREEN_H / 2.0;

    // 무작위 방향, 일정한 속력
    double angle = (rand() % 360) * 3.14159265 / 180.0;
    double speed = 20.0 + rand() % 20;

    b->vx = cos(angle) * speed;
    b->vy = sin(angle) * speed;

    b->symbol = "@O*o.+"[g_ballCount % 6];
    b->active = 1;

    g_ballCount++;
}
```

> `cos`/`sin`으로 방향을 만드는 것은 **Day 66(포트리스)** 에서 본격적으로 다룬다.
> 오늘은 "각도를 주면 방향 벡터가 나온다" 정도만 알고 쓴다.

```c
void UpdateAll(double dt)
{
    for (int i = 0; i < g_ballCount; i++)
        if (g_balls[i].active)
            UpdateBall(&g_balls[i], dt);      // ★ 주소 전달 (Day 18)
}
```

## 6. 자주 막히는 곳

| 증상 | 원인 | 해결 |
|---|---|---|
| 공이 벽에서 부들부들 떨림 | **위치 보정 누락** | 부호 뒤집기 + 위치 보정을 세트로 |
| 공이 화면 밖으로 사라짐 | 반사 조건 누락 또는 범위 오류 | `0` ~ `SCREEN_W - 1` 확인 |
| 공이 안 움직임 | 위치를 `int`로 선언 | `double`로 변경 |
| 공이 순간이동 | 속도 과다 (터널링) | 속도 상한 |
| 대각선이 아니라 직선 | `vx` 또는 `vy`가 0 | 둘 다 0이 아니게 초기화 |
| 속도를 바꾸면 방향이 틀어짐 | 정규화 없이 값을 더함 | `SetSpeed`로 비율 유지 |
| 0으로 나누기 크래시 | `GetSpeed`가 0 | `if (cur < 0.0001) return;` |
| 잔상이 남음 | 화면 배열을 안 지움 | 매 프레임 공백으로 초기화 |
| `sqrt`/`cos` 오류 | `<math.h>` 누락 | 포함 |
| 공이 하나만 움직임 | 배열 순회 누락 | `for` 로 전체 갱신 |

## 7. 정리

### 오늘 배운 것

| 개념 | 한 줄 요약 |
|---|---|
| **속도 벡터 `(vx, vy)`** | 방향과 빠르기를 두 숫자로. 이동은 `x += vx * dt` |
| 속력 | `sqrt(vx² + vy²)`. 벡터의 크기 |
| 정규화 | 속력으로 나누면 방향만 남는다. 크기를 따로 조절 가능 |
| **반사** | 축에 나란한 벽은 **부호만 뒤집으면 된다** |
| **위치 보정** | 부호 뒤집기와 **항상 세트**. 없으면 벽에서 진동 |
| 터널링 | 빠른 물체가 한 프레임에 벽을 지나친다. 속도 상한으로 대응 |
| 실수 좌표 | 위치·속도는 `double`, 그릴 때만 `(int)` |
