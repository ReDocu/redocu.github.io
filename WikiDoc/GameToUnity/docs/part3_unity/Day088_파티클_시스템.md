## 3. 개념

### 3-1. 파티클 시스템 구조

**왜 필요한가** — 모듈이 많아 보이지만 원리는 Day 68과 같다.

```
   GameObject → Effects → Particle System
```

| 모듈 | 역할 |
|---|---|
| **Main** | 수명, 시작 속도/크기/색, Simulation Space |
| **Emission** | 초당 방출량, 버스트 |
| **Shape** | 방출 형태 (구, 원뿔, 박스) |
| Velocity over Lifetime | 시간에 따른 속도 |
| Force over Lifetime | 지속적인 힘 (중력, 바람) |
| **Color over Lifetime** | 페이드 아웃 |
| **Size over Lifetime** | 축소/확대 |
| Rotation over Lifetime | 회전 |
| Noise | 불규칙한 흔들림 |
| Collision | 지형 충돌 |
| Sub Emitters | 파티클이 다시 파티클을 |
| **Renderer** | 머티리얼, 정렬, Billboard/Mesh |

```
   ★ Day 68과의 대응

   Part 2                    Unity
   m_life / m_duration   →   Start Lifetime
   radius 증가            →   Size over Lifetime
   alpha 감소             →   Color over Lifetime
   for (k = 0; k < 8)     →   Emission Burst
   m_pool[MAX]            →   Max Particles
```

### 3-2. Main 모듈

**왜 필요한가** — 가장 자주 만진다.

| 필드 | 의미 |
|---|---|
| **Duration** | 방출이 지속되는 시간 |
| **Looping** | 반복 여부 |
| Prewarm | 시작 시 이미 진행된 상태로 |
| Start Delay | 시작 지연 |
| **Start Lifetime** | 파티클 하나의 수명 |
| **Start Speed** | 초기 속도 |
| **Start Size** | 초기 크기 |
| Start Rotation | 초기 회전 |
| **Start Color** | 초기 색 |
| Gravity Modifier | 중력 배율 |
| **Simulation Space** | Local / **World** / Custom |
| Play On Awake | 자동 재생 |
| **Max Particles** | 최대 개수 |

```
   ★ Simulation Space — 오늘 가장 중요한 함정

   Local:  파티클이 부모를 따라 움직인다
   World:  파티클이 방출된 자리에 남는다
```

```
   투사체에 붙은 연기 이펙트

   Local Space                World Space

   ●━━━━━━━▶                 ●━━━━━━━▶
   ✦✦✦✦ (딸려간다)            ✦  ✦  ✦  (뒤에 남는다)
   ↑ 뭉쳐서 이상하다          ↑ 자연스럽다  ★
```

```
   ⚠️ 움직이는 오브젝트의 이펙트는 거의 항상 World
```

```
   ★ 값을 범위로 줄 수 있다

   Start Lifetime 옆 ▾ → Random Between Two Constants
   → 0.3 ~ 0.6

   → 파티클마다 달라 자연스럽다
```

### 3-3. Emission 모듈

**왜 필요한가** — 언제 얼마나 나올지.

| 필드 | 의미 |
|---|---|
| **Rate over Time** | 초당 방출 수 |
| Rate over Distance | 이동 거리당 방출 (궤적) |
| **Bursts** | 특정 시점에 한꺼번에 |

```
   ★ 지속형 vs 순간형

   지속형 (연기, 불)
     Rate over Time: 30
     Bursts: 없음

   순간형 (폭발, 스파크)  ★
     Rate over Time: 0
     Bursts: Time 0, Count 30
```

```
   ⚠️ 폭발인데 Rate over Time을 쓰면

   계속 조금씩 나온다 → 폭발처럼 안 보인다
```

```
   ★ Rate over Distance

   오브젝트가 움직인 거리에 비례해 방출
   → 빠르면 촘촘, 느리면 성글게
   → 차량 먼지, 발자국에 적합
```

### 3-5. over Lifetime 모듈

**왜 필요한가** — Day 68의 핵심을 그대로.

**Color over Lifetime**

```
   ★ 그라디언트 편집기

   색:      ▮────────▮────────▮
           흰색    주황     빨강

   알파:    ▮────────▮────────▮
           255      200       0
           ↑ 시작            ↑ 끝에서 투명
```

```
   ⚠️ 알파가 끝에서 0이 아니면

   파티클이 뚝 사라진다
   → 반드시 마지막 알파를 0으로
```

**Size over Lifetime**

```
   커브 편집

   크기 ↑
      1 │╲
        │ ╲
        │  ╲___
      0 └────────▶ 수명
        0        1

   → 커지면서 시작해 작아지며 사라짐
```

```
   ★ 자주 쓰는 커브

   폭발:    작게 시작 → 급격히 커짐 → 서서히 축소
   스파크:  크게 시작 → 선형 축소
   연기:    작게 시작 → 계속 커짐 (알파로 사라짐)
```

**Velocity over Lifetime**

```
   Linear:  일정한 속도 추가 (바람)
   Orbital: 중심 축을 도는 회전
   Radial:  중심에서 바깥으로

   Speed Modifier: 전체 속도 배율
```

```
   ★ 감속 표현

   Speed Modifier를 커브로
   1 → 0 으로 떨어뜨리면 서서히 멈춘다
```

### 3-6. Renderer 모듈

**왜 필요한가** — 어떻게 그릴지.

| 필드 | 의미 |
|---|---|
| **Render Mode** | Billboard / Stretched / Mesh |
| **Material** | 파티클 머티리얼 |
| Sort Mode | 정렬 방식 |
| **Sorting Fudge** | 다른 오브젝트와의 앞뒤 조정 |
| Max Particle Size | 화면상 최대 크기 |
| Cast Shadows | 그림자 (보통 Off) |

| Render Mode | 설명 | 용도 |
|---|---|---|
| **Billboard** | 항상 카메라를 향함 | 대부분 ★ |
| Stretched Billboard | 속도 방향으로 늘어남 | 스파크, 빗방울 |
| Horizontal/Vertical Billboard | 축 고정 | 바닥 효과 |
| **Mesh** | 3D 메시 | 파편, 잔해 |

```
   ⚠️ 파티클이 안 보이는 1위 원인

   Material이 None
   → 분홍색도 아니고 아예 안 보인다
```

```
   ★ URP 파티클 머티리얼

   Shader: Universal Render Pipeline/Particles/Unlit
   Surface Type: Transparent
   Blending Mode: Additive (빛나는 효과) 또는 Alpha
```

```
   ★ Additive vs Alpha

   Additive:  배경에 색을 "더한다" → 밝게 빛난다
              불, 마법, 레이저

   Alpha:     배경을 "가린다"      → 불투명하게
              연기, 먼지, 파편
```

```
   ★ Day 68의 알파 블렌딩 공식

   Alpha:     결과 = 배경×(1-α) + 색×α
   Additive:  결과 = 배경 + 색×α

   → Additive는 검은색이 투명해진다
```

### 3-9. 이펙트 풀링

**왜 필요한가** — 웨이브 후반에 이펙트가 쏟아진다.

```
   ★ 웨이브 10에서

   적 30기 × 타워 15기 × 초당 1.5발
   → 초당 약 45번의 발사
   → 발사 이펙트 + 피격 이펙트 = 초당 90개
   → Instantiate/Destroy 90회/초
```

```csharp
using UnityEngine;

[RequireComponent(typeof(ParticleSystem))]
public class PooledParticle : MonoBehaviour, IPoolable
{
    private ParticleSystem ps;
    private PooledObject pooled;

    void Awake()
    {
        ps = GetComponent<ParticleSystem>();
        pooled = GetComponent<PooledObject>();

        // ★ 자동 재생 끄기 (풀에서 꺼낼 때 제어)
        var main = ps.main;
        main.playOnAwake = false;
        main.stopAction = ParticleSystemStopAction.Callback;
    }

    public void OnSpawn()
    {
        ps.Clear(true);                        // ★ 이전 파티클 제거
        ps.Play(true);
    }

    public void OnDespawn()
    {
        ps.Stop(true, ParticleSystemStopBehavior.StopEmittingAndClear);
    }

    // ★ Stop Action = Callback 일 때 호출
    void OnParticleSystemStopped()
    {
        if (pooled != null) pooled.ReturnToPool();
    }
}
```

```
   ⚠️ ps.Clear()를 안 하면

   Day 74에서 배운 "이전 상태가 남는" 문제
   → 이전 파티클이 새 위치에서 갑자기 나타난다
```

```
   ★ Clear(true)의 true

   자식 파티클 시스템까지 포함
```

### 3-11. 성능

**왜 필요한가** — 파티클은 쉽게 병목이 된다.

```
   ★ 비용의 원천

   ① 파티클 개수 (CPU 시뮬레이션)
   ② 오버드로우 (같은 픽셀을 여러 번 그림)
   ③ 드로우 콜 (시스템 개수)
```

```
   ★ 오버드로우가 가장 큰 문제

   반투명 파티클 50개가 겹치면
   같은 픽셀을 50번 계산한다

   화면을 가득 채우는 큰 파티클 = 매우 비싸다
```

| 최적화 | 방법 |
|---|---|
| 개수 줄이기 | Max Particles, Burst Count |
| 크기 줄이기 | 화면 대비 작게 |
| **수명 줄이기** | 0.3~0.6초면 충분 |
| 풀링 | Instantiate 제거 |
| Culling | Culling Mode: Automatic |
| 텍스처 | 작게 (128×128이면 충분) |
| **Cast Shadows Off** | 파티클 그림자 불필요 |
| Sub Emitter 자제 | 기하급수적 증가 |

```
   ★ Culling Mode

   Automatic:            화면 밖이면 시뮬레이션 중지  ★
   Pause and Catch-up:   재개 시 따라잡음 (비쌈)
   Always Simulate:      항상 계산
```

```
   ⚠️ Automatic은 World Space에서만 안전하다

   Local Space + 정지 시 위치가 어긋날 수 있다
```
