## ① 학습 목표

이 레슨을 마치면 이렇게 할 수 있습니다.

- 파생 특성 아이디어를 시간 · 공간 · 외부 정보에서 얻고, **누수 검문**을 통과시켜 구현할 수 있다.

- 특성 아이디어의 대부분이 실패함을 받아들이고, **실험으로만** 채택 여부를 정할 수 있다.
- **순열 중요도**로 특성의 기여를 재고, 그 수치의 함정(의존 ≠ 고유 정보량)을 설명할 수 있다.

정보를 만들어낼 수 없습니다. [Day 053](day-053.md)의 오답 노트가 정확히 말해 줬습니다:
"오늘 조용하다가 내일 터지는 날을 오늘 정보만으로는 못 맞힌다." 그렇다면 답은 모델이 아니라
**"내일에 대한 정보"를 입력에 넣는 것**입니다.

내일의 정보를 쓰는 게 누수 아니냐고요? 오늘 그 경계선을 정확히 긋습니다.
이 경계선 하나로 특성 엔지니어링의 절반이 결정됩니다.

## ③ 개념 설명

### 특성 아이디어의 세 광맥

| 광맥 | 질문 | 우리 문제의 예 |
|---|---|---|
| **시간** | 과거의 흐름이 힌트인가? | 어제 값(lag), 3일 평균(rolling), 추세 |
| **공간·집단** | 이웃·집단의 값이 힌트인가? | 서울 전체 평균 pm25, 측정소별 기저(원-핫) |
| **외부·미래** | 예측 시점에 **입수 가능한** 외부 정보는? | 달력(월·요일), **기상 예보** |

### 황금 질문 — "예측 시점에 알 수 있는가"

[Day 052](day-052.md)의 누수 검문을 반대쪽에서 씁니다. **미래에 관한 정보라도, 예측 시점에
입수 가능하면 합법**입니다.

| 특성 | 내일에 관한 정보인가 | 오늘 밤에 알 수 있는가 | 판정 |
|---|---|---|---|
| 내일의 실측 pm25 | 예 | ❌ (내일 돼야 측정) | **누수** — 이게 곧 정답 |
| 내일의 실측 풍속 | 예 | ❌ | 누수 |
| **내일의 풍속 예보** | 예 | ✅ (기상청이 오늘 발표) | **합법!** |
| 내일이 공휴일인지 | 예 | ✅ (달력) | 합법 |

미세먼지는 **내일의 바람과 비가 씻어 가는** 물리량입니다. 그 바람과 비를 기상청이 오늘
알려 줍니다 — 실제 대기질 예보 시스템이 전부 기상 예보를 입력으로 쓰는 이유입니다.

> 실습에서는 "완벽한 예보"(내일 실측값을 예보처럼 사용) 로 먼저 상한을 재고,
> 예보 오차를 노이즈로 흉내 내 현실 성능을 봅니다. **원리(입수 가능성)와 품질(예보 정확도)을
> 분리해서 평가**하는 것이 요령입니다.

### 대부분의 아이디어는 실패한다

특성 엔지니어링의 실제 경험은 "10개 시도 → 1~2개 채택"입니다. 그럴듯함과 유효함은 다르고
(이미 [Day 055](day-055.md)의 기후 베이스라인에서 봤습니다), 유효성은 **오직 실험**으로 판정합니다.
그래서 오늘부터 모든 특성 실험은 (아이디어 / 가설 / 결과 / 채택 여부)로 **기록**합니다 —
이 기록이 산더미가 되는 것이 내일([Day 065](day-065.md))의 사건입니다.

### 해석 도구 — 순열 중요도

**순열 중요도**(permutation importance): 특성 하나의 값을 **무작위로 뒤섞은 뒤** 성능이
얼마나 떨어지는지 잽니다. "이 특성이 고장 나면 모델이 얼마나 아픈가"입니다.

| | 불순도 중요도 ([Day 058](day-058.md)) | 순열 중요도 |
|---|---|---|
| 계산 | 학습 중 분할 기여 합산 | **아무 모델이나**, 평가 데이터에서 측정 |
| 편향 | 고유값 많은 특성 과대평가 | 상관 특성끼리 대체 가능성은 못 봄 (오늘 실습에서 직접 확인) |

개별 예측 한 건("왜 오늘 경보가 떴나")을 특성별 기여로 분해하는 **SHAP**은 이 주제의 심화판입니다.
오늘은 개념만 알아 두고(면접 단골), 관심 있으면 `pip install shap` 후 `shap.TreeExplainer` 를
탐험해 보세요 — MP2 선택 기능입니다.

## ④ 단계별 실습

`day064_features.py` 에 이어 붙입니다.

### Step 1. 특성 공장 — 세 광맥에서 캐 오기 (1~2교시)

```python
# day064_features.py — 특성 엔지니어링: 시간·공간·예보
import numpy as np
import pandas as pd
from lightgbm import LGBMRegressor
from sklearn.compose import ColumnTransformer
from sklearn.impute import SimpleImputer
from sklearn.inspection import permutation_importance
from sklearn.linear_model import LinearRegression
from sklearn.metrics import mean_absolute_error, r2_score
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import OneHotEncoder, StandardScaler

pd.set_option("display.width", 140)
df = pd.read_csv("data/air_daily.csv", parse_dates=["date"]).sort_values(["station", "date"])
NUM = ["pm10", "pm25", "o3", "no2", "co", "so2", "temp", "humidity", "wind_speed", "precip"]
g = df.groupby("station")

# ── 아이디어 ①: 시간 파생 (어제·3일 평균·서울 평균·월) ──
df["pm25_lag1"] = g["pm25"].shift(1)                                   # 어제 (과거 방향 = 안전)
df["pm25_ma3"] = g["pm25"].transform(lambda s: s.rolling(3).mean())    # 그제~오늘 평균
df["seoul_pm25"] = df.groupby("date")["pm25"].transform("mean")        # 오늘 서울 5개 측정소 평균
df["month"] = df.date.dt.month
TIME = ["pm25_lag1", "pm25_ma3", "seoul_pm25", "month"]

# ── 아이디어 ②: 기상 예보 (내일의 바람·습도·강수 — 예보로 알 수 있는 값) ──
df["wind_fc"] = g["wind_speed"].shift(-1)
df["humidity_fc"] = g["humidity"].shift(-1)
df["precip_fc"] = g["precip"].shift(-1)
FC = ["wind_fc", "humidity_fc", "precip_fc"]

d = df[df.pm25_next.notna() & df[FC].notna().all(axis=1)].copy()
tr = d[d.date < "2026-01-01"]; te = d[d.date >= "2026-01-01"]
```

코드에서 누수 검문을 되짚어 보세요.

| 특성 | shift 방향 | 검문 |
|---|---|---|
| `pm25_lag1` | `shift(1)` = 과거 | ✅ 어제 값은 오늘 알 수 있음 |
| `pm25_ma3` | `rolling(3)` 뒤끝 정렬 | ✅ (그제+어제+오늘)/3. `center=True` 였다면 누수([Day 052](day-052.md)) |
| `seoul_pm25` | 오늘의 다른 측정소 | ✅ 같은 시각의 공간 정보 — 미래 아님 |
| `wind_fc` 등 | `shift(-1)` = **미래** | ⚠️ 실측값이면 누수 — **"예보값" 역할**로 사용 (Step 3에서 오차 보정) |

### Step 2. 아이디어별 성적표 (3~4교시)

세트를 하나씩 늘려 가며 [Day 063](day-063.md)의 파이프라인(대치+스케일+원-핫)으로 잽니다.
비교를 위해 [Day 062](day-062.md)에서 튜닝한 LightGBM도 같은 특성으로 함께 달립니다.

```python
def run_linear(feats):
    prep = ColumnTransformer([
        ("num", Pipeline([("i", SimpleImputer(strategy="median")), ("s", StandardScaler())]), feats),
        ("cat", OneHotEncoder(handle_unknown="ignore"), ["station"]),
    ])
    p = Pipeline([("prep", prep), ("m", LinearRegression())]).fit(tr[feats + ["station"]], tr.pm25_next)
    pr = p.predict(te[feats + ["station"]])
    return p, r2_score(te.pm25_next, pr), mean_absolute_error(te.pm25_next, pr)

def run_lgbm(feats):
    dtr = tr[feats].assign(station=tr.station.astype("category"))
    dte = te[feats].assign(station=te.station.astype("category"))
    m = LGBMRegressor(random_state=42, verbosity=-1, num_leaves=15, learning_rate=0.03,
                      n_estimators=700, min_child_samples=40, reg_lambda=1.0,
                      colsample_bytree=0.8).fit(dtr, tr.pm25_next)
    pr = m.predict(dte)
    return r2_score(te.pm25_next, pr), mean_absolute_error(te.pm25_next, pr)

print("== A. 특성 아이디어별 성적표 (test) ==")
print("| 특성 세트 | 선형 R² | 선형 MAE | LGBM튠 R² |")
print("|---|---|---|---|")
for label, feats in [("기본 10 + station", NUM),
                     ("+ 시간 파생 4", NUM + TIME),
                     ("+ 예보 3", NUM + TIME + FC)]:
    _, r_l, mae_l = run_linear(feats)
    r_b, _ = run_lgbm(feats)
    print(f"| {label:<16} | {r_l:.3f} | {mae_l:.2f} | {r_b:.3f} |")
```

실행 결과:

```
== A. 특성 아이디어별 성적표 (test) ==
| 특성 세트 | 선형 R² | 선형 MAE | LGBM튠 R² |
|---|---|---|---|
| 기본 10 + station  | 0.420 | 4.83 | 0.280 |
| + 시간 파생 4        | 0.426 | 4.78 | 0.323 |
| + 예보 3           | 0.519 | 4.26 | 0.508 |
```

이 표에 오늘 배울 것이 전부 있습니다.

1. **시간 파생 4개(그럴듯함의 대명사)는 +0.006** — 사실상 실패입니다. 오늘 pm25가 이미
   최근 흐름을 요약하고 있어서, 어제·3일 평균은 새 정보가 거의 없습니다.
   **그럴듯한 아이디어 절반은 이렇게 죽습니다. 재 보기 전엔 모릅니다.**
2. **예보 3개는 +0.093.** MAE 4.78 → 4.26. 이 단원을 통틀어 가장 큰 단일 개선입니다.
   "내일을 아는 것"의 힘 — 물론 합법적으로.
3. **LGBM의 도약을 보세요: 0.280 → 0.508.** 특성이 빈약할 때 절망적이던(-0.14 차) 부스팅이
   예보 특성이 들어오자 선형과 접전(-0.011 차)까지 따라붙었습니다. [Day 059](day-059.md)의
   결론 그대로 — **순위는 특성 구성의 함수**입니다. (그리고 이 데이터에서는 끝까지
   선형이 왕좌를 지킵니다. 신호가 그만큼 선형적인 판이라는 뜻입니다.)

### Step 3. 현실 보정 — 예보는 완벽하지 않다 (5교시)

Step 2의 `wind_fc` 는 내일의 **실측값**이라 "완벽한 예보"라는 낙관적 가정입니다.
실제 예보 오차를 노이즈로 흉내 내 얼마나 무너지는지 봅니다.

```python
print("\n== B. 현실 보정 — 예보는 완벽하지 않다 ==")
rng = np.random.default_rng(0)
for sigma_w, sigma_p in [(0.0, 0.0), (0.4, 2.0), (0.8, 4.0)]:
    d2 = d.copy()
    d2["wind_fc"] = d2.wind_fc + rng.normal(0, sigma_w, len(d2))
    d2["precip_fc"] = np.maximum(0, d2.precip_fc + rng.normal(0, sigma_p, len(d2)) * (d2.precip_fc > 0))
    tr2 = d2[d2.date < "2026-01-01"]; te2 = d2[d2.date >= "2026-01-01"]
    feats = NUM + TIME + FC
    prep = ColumnTransformer([
        ("num", Pipeline([("i", SimpleImputer(strategy="median")), ("s", StandardScaler())]), feats),
        ("cat", OneHotEncoder(handle_unknown="ignore"), ["station"]),
    ])
    p = Pipeline([("prep", prep), ("m", LinearRegression())]).fit(tr2[feats + ["station"]], tr2.pm25_next)
    pr = p.predict(te2[feats + ["station"]])
    print(f"  예보 오차 σ(바람 {sigma_w}, 강수 {sigma_p}): R² {r2_score(te2.pm25_next, pr):.3f}")
```

실행 결과:

```
== B. 현실 보정 — 예보는 완벽하지 않다 ==
  예보 오차 σ(바람 0.0, 강수 0.0): R² 0.519
  예보 오차 σ(바람 0.4, 강수 2.0): R² 0.511
  예보 오차 σ(바람 0.8, 강수 4.0): R² 0.514
```

풍속 ±0.8m/s, 강수 ±4mm 수준의 예보 오차를 넣어도 R²는 0.51x — **개선분이 노이즈에
강건**합니다. 예보의 가치가 정밀한 수치가 아니라 "내일 바람이 부는가/비가 오는가"라는
굵직한 신호에서 나오기 때문입니다. 이런 민감도 실험까지 붙여야 특성 채택 보고서가 완성됩니다.

### Step 4. 순열 중요도 — 그리고 그 함정 (6~7교시)

```python
print("\n== C. 순열 중요도 — 어떤 특성이 진짜 일하나 ==")
feats = NUM + TIME + FC
pipe, r_full, _ = run_linear(feats)
pi = permutation_importance(pipe, te[feats + ["station"]], te.pm25_next,
                            n_repeats=10, random_state=42, scoring="r2")
order = np.argsort(-pi.importances_mean)
for i in order[:8]:
    name = (feats + ["station"])[i]
    print(f"  {name:<12} R² 하락 {pi.importances_mean[i]:+.3f} ± {pi.importances_std[i]:.3f}")
```

실행 결과:

```
== C. 순열 중요도 — 어떤 특성이 진짜 일하나 ==
  seoul_pm25   R² 하락 +0.445 ± 0.025
  pm10         R² 하락 +0.226 ± 0.016
  station      R² 하락 +0.165 ± 0.013
  wind_fc      R² 하락 +0.146 ± 0.008
  precip_fc    R² 하락 +0.110 ± 0.011
  pm25         R² 하락 +0.089 ± 0.010
  precip       R² 하락 +0.084 ± 0.005
  wind_speed   R² 하락 +0.056 ± 0.006
```

예보 2종(wind_fc, precip_fc)이 상위권 — Step 2의 개선이 어디서 왔는지 확인됩니다.
그런데 **1위가 이상합니다.** seoul_pm25를 섞으면 R²가 0.445나 무너진다는데, Step 2에서
시간 파생 4개(seoul_pm25 포함)를 **추가**했을 때 이득은 겨우 +0.006이었습니다. 모순일까요?

아닙니다 — **순열 중요도는 "모델이 그 특성에 얼마나 기대는가"이지, "그 특성만 가진 고유
정보량"이 아닙니다.** seoul_pm25는 5개 측정소 평균이라 개별 측정소의 노이즈가 지워진,
같은 정보의 **가장 깨끗한 버전**입니다. 모델은 pm25 대신 seoul_pm25에 가중치를 몰아줬고
(그래서 섞으면 크게 아픔), 하지만 seoul_pm25가 없어도 pm25·pm10이 그 역할을 대신할 수
있었습니다(그래서 추가 이득은 작음). **"섞었을 때의 아픔"과 "뺐을 때의 손실"은 다른 질문**입니다 —
후자가 궁금하면 실제로 빼고 재학습해야 합니다.

### Step 5. 단원 여정 정리, 커밋, 과제 (8교시)

```python
print("\n== D. 단원 개선 여정 총정리 ==")
print("  persistence 0.207 → 선형(dropna) 0.390 → Pipeline 0.422 → +예보 특성 0.519")
```

| 단계 | test R² | 무엇이 바꿨나 |
|---|---|---|
| 내일=오늘 | 0.207 | — |
| 선형 회귀 ([053](day-053.md)) | 0.390 | 모델 |
| + 튜닝 108회 ([062](day-062.md)) | (LGBM 0.812 AUC 쪽) +0.015 | 모델 손잡이 |
| Pipeline ([063](day-063.md)) | 0.422 | 데이터를 더 씀 |
| **+ 예보 특성 (오늘)** | **0.519** | **정보를 더 넣음** |


## ⑤ 자주 하는 실수

### shift 방향을 헷갈림

**증상** — `wind_fc = g["wind_speed"].shift(1)` 로 만들고 "예보 특성"이라 부름 — 점수 변화 없음.
**원인** — `shift(1)` 은 **어제** 값입니다(과거로 당김). 미래 값은 `shift(-1)`.
**해결** — 파생 직후 몇 행을 눈으로 검증하세요: `df[["date", "wind_speed", "wind_fc"]].head(3)` 에서 wind_fc가 다음 행의 wind_speed와 같아야 합니다.

### groupby 없이 shift/rolling

**증상** — 에러도 없고 점수도 그럴듯한데 미묘하게 이상함.
**원인** — `df["pm25"].shift(1)` 은 정렬 순서상 **이전 행**을 가져올 뿐이라, 측정소 경계에서
강남구의 마지막 날이 노원구의 "어제"가 됩니다. 조용히 오염되는 버그입니다.
**해결** — 시계열 파생은 반드시 `df.groupby("station")["pm25"].shift(1)` 처럼 그룹 안에서. 만들고 나서 측정소가 바뀌는 경계 행을 꼭 확인하세요.

### rolling에 center=True

**증상** — 이동평균 특성을 넣었더니 R²가 0.7대로 폭등.
**원인** — (어제+오늘+**내일**)/3 — [Day 052](day-052.md) 실험 3의 타깃 누수 재발.
**해결** — 뒤끝 정렬(기본값)만 사용. 점수가 갑자기 뛰면 기뻐하기 전에 계산식을 소리 내어 읽기.

### 순열 중요도를 "고유 정보량"으로 보고

**증상** — "seoul_pm25 중요도 0.445 — 이 특성 덕에 R²가 0.445 높다"고 보고.
**원인** — 순열 중요도는 **현재 모델의 의존도**입니다. 상관된 대체 특성이 있으면 "뺐을 때 손실"은 훨씬 작습니다 (우리 실측: 추가 이득 +0.006).
**해결** — 특성 하나의 존재 가치는 빼고 재학습(ablation)으로, 모델의 의존 구조는 순열 중요도로 — 질문에 맞는 도구를 쓰세요.

### 예보 특성의 품질 가정을 안 적음

**증상** — "R² 0.519 달성"이라고만 보고. 배포 후 실제 예보 오차 때문에 재현이 안 됨.
**원인** — 실습의 예보는 "완벽한 예보"(실측 대입)라는 낙관 가정입니다.
**해결** — Step 3처럼 오차 민감도를 함께 보고하고, 운영 시 실제 예보 API의 오차 통계로 재검증할 것을 문서에 남깁니다. 이런 가정 명시가 [Day 069](day-069.md) 모델 카드의 내용입니다.

## ⑥ 확인 문제

**Q1.** "내일의 풍속"을 특성으로 쓰는 것이 누수인지 아닌지는 무엇으로 갈리나요? 우리 실습에서
이 특성을 정당화한 논리와 그 한계를 함께 쓰세요.

<details>
<summary>답 보기</summary>

값 자체가 아니라 **예측 시점의 입수 가능성**으로 갈립니다. 내일의 실측 풍속은 예측 시점에 알 수 없어
누수지만, 기상청이 오늘 발표하는 내일 풍속 **예보**는 입수 가능하므로 합법입니다. 실습은 실측값을
예보 대용으로 썼기에 "완벽한 예보" 가정이며, 그래서 예보 오차 노이즈 민감도 실험(Step 3)으로 한계를 보정했습니다.

</details>

**Q2.** 시간 파생 4개는 +0.006, 예보 3개는 +0.093이었습니다. 이 차이를 "정보"의 관점에서 설명하세요.

<details>
<summary>답 보기</summary>

시간 파생(어제, 3일 평균 등)은 오늘 pm25가 이미 담고 있는 **기존 정보의 재표현**이라 모델에 새로운 것을
주지 못합니다. 예보 특성은 입력 어디에도 없던 **미래(내일 대기 조건)에 대한 새 정보**를 주므로,
모델이 원리적으로 접근할 수 없던 오차(내일 날씨발 변동)를 줄여 줍니다. 특성의 가치는 형태가 아니라
"새 정보인가"로 결정됩니다.

</details>

**Q3.** 순열 중요도에서 seoul_pm25가 0.445로 1위인데, 이 특성을 실제로 빼고 재학습하면 R²가
0.445만큼 떨어지지 않는 이유는?

<details>
<summary>답 보기</summary>

순열은 **모델을 그대로 둔 채** 그 특성만 고장 내므로, 모델이 seoul_pm25에 몰아 둔 가중치가 전부
손실로 잡힙니다. 재학습하면 모델이 상관된 대체 특성(pm25, pm10)에 가중치를 다시 배분해 대부분의
정보를 복구합니다. 즉 0.445는 "현재 모델의 의존도"이지 "그 특성만 가진 고유 정보량"(+0.006 수준)이 아닙니다.

</details>
