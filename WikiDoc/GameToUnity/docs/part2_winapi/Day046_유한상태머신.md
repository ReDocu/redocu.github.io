## 3. 개념

### 3-1. 유한 상태 머신이란

**왜 필요한가** — 복잡한 행동 규칙을 관리 가능한 형태로 만든다.

```
   Finite State Machine (유한 상태 머신)

   ① 상태(State)는 유한하다        →  14가지
   ② 항상 정확히 하나의 상태에 있다 →  m_state
   ③ 정해진 조건으로만 전이한다     →  전이표
```

```
   ┌─────────┐  이동입력   ┌─────────┐
   │  IDLE   │───────────▶│  WALK   │
   │         │◀───────────│         │
   └────┬────┘  입력없음   └────┬────┘
        │                       │
        │ 공격키                 │ 공격키
        ▼                       ▼
   ┌─────────────────────────────────┐
   │           ATTACK                 │
   │  (이동 불가, 입력 무시)           │
   └────────────┬────────────────────┘
                │ 애니메이션 종료
                ▼
           ┌─────────┐
           │  IDLE   │
           └─────────┘
```

```
   ★ FSM 이 아닌 것 (플래그 방식)

   bool isAttacking, isJumping, isHit, isDown ...

   → 2^n 가지 조합
   → isDown && isAttacking 같은 불가능한 상태가 생길 수 있다
```

### 3-2. 두 가지 구현 방식

**왜 필요한가** — 규모에 따라 선택이 다르다.

```
   [ 방식 A — switch 기반 ]

   void Update(dt) {
       switch (m_state) {
       case IDLE:   UpdateIdle(dt);   break;
       case WALK:   UpdateWalk(dt);   break;
       ...
       }
   }

   장점:  간단하다. 파일 하나로 끝난다
   단점:  상태가 20개 넘으면 파일이 비대해진다
   적합:  상태 5~15개


   [ 방식 B — State 패턴 (클래스) ]

   class IdleState : public IState {
       void Enter(Character*) override;
       void Update(Character*, double dt) override;
       void Exit(Character*) override;
   };

   장점:  상태마다 파일 분리. 확장이 쉽다
   단점:  코드량이 늘고 간접 호출이 많다
   적합:  상태 15개 이상, 팀 작업
```

> **이 과정에서는 방식 A(`switch`)를 쓴다.**
> 상태가 14개이고 한 명이 만들기 때문이다.
> **방식 B는 3-8절에서 소개만 한다.**

### 3-3. FSM의 세 가지 함수

**왜 필요한가** — 어디에 무엇을 쓸지 정한다.

```
   ┌──────────────────────────────────────────────────────────┐
   │  ① CanTransition(from, to)     "그 전이가 허용되는가"     │
   │     → 전이표를 그대로 옮긴다                              │
   │                                                           │
   │  ② OnEnterState / OnExitState  "상태가 바뀔 때 할 일"     │
   │     → 애니메이션 재생, 타이머 시작, 판정 켜고 끄기        │
   │                                                           │
   │  ③ UpdateState(dt)             "그 상태에서 매 프레임"    │
   │     → 물리, 자동 전이(시간·애니메이션 종료)               │
   └──────────────────────────────────────────────────────────┘
```

### 3-4. 전이표를 코드로 — 방법 1: 함수

**왜 필요한가** — 가장 읽기 쉬운 방식.

```cpp
bool Character::CanTransition(State to) const
{
    // 어느 상태에서든 피격은 가능
    if (to == STATE_HIT || to == STATE_DOWN) return true;

    switch (m_state)
    {
    case STATE_IDLE:
    case STATE_WALK:
    case STATE_RUN:
        return true;                          // 대부분 허용

    case STATE_CROUCH:
        return (to == STATE_C_ATTACK || to == STATE_GUARD ||
                to == STATE_IDLE);

    case STATE_JUMP:
    case STATE_FALL:
        return (to == STATE_J_ATTACK || to == STATE_FALL ||
                to == STATE_IDLE || to == STATE_JUMP);

    case STATE_ATTACK:
    case STATE_C_ATTACK:
        return (to == STATE_IDLE || to == STATE_CROUCH);   // 애니 종료 시만

    case STATE_HIT:
        return (to == STATE_IDLE || to == STATE_DOWN);

    case STATE_DOWN:
        return (to == STATE_GETUP);

    case STATE_GETUP:
        return (to == STATE_IDLE);

    case STATE_WIN:
        return false;                         // 아무 데도 못 감

    default:
        return true;
    }
}
```

| | 함수 방식 | 배열 방식 |
|---|---|---|
| 가독성 | 조건이 명확 | **표 전체가 한눈에** |
| 수정 | 코드 수정 | **숫자 하나 수정** |
| 실수 | `case` 누락 가능 | 칸 수를 세면 검증 가능 |
| 확장 | 조건식 추가 가능 | 단순 허용/차단만 |

> **배열 방식을 권한다.** 어제 만든 표가 그대로 코드가 되기 때문이다.
> 복잡한 조건(예: "체력 30% 이하일 때만")이 필요하면 함수 방식과 섞는다.

```cpp
void Character::UpdateAttack(double dt)
{
    m_vx = 0;                                 // 공격 중 이동 정지

    // 애니메이션이 끝나면 복귀
    if (m_animator.IsFinished())
    {
        if (m_state == STATE_C_ATTACK) ChangeState(STATE_CROUCH);
        else if (m_state == STATE_J_ATTACK && m_onGround) ChangeState(STATE_IDLE);
        else if (m_state == STATE_ATTACK) ChangeState(STATE_IDLE);
    }
}

void Character::UpdateHit(double dt)
{
    // 넉백 감쇠
    m_vx *= 0.9;

    if (m_stateTimer >= HIT_STUN_TIME)
        ChangeState(STATE_IDLE);
}

void Character::UpdateDown(double dt)
{
    m_vx = 0;

    if (m_stateTimer >= DOWN_TIME)
        ChangeState(STATE_GETUP);
}
```

### 3-7. 입력 처리 — 표 기반

**왜 필요한가** — 2절의 흩어진 조건을 정리한다.

```cpp
void Character::ProcessInput(double dt)
{
    if (!CanAcceptInput()) return;            // ★ 한 줄로 끝

    Input& in = m_core->GetInput();

    // ── 이동 ──
    if (CanMove())
    {
        double axis = 0.0;
        if (in.IsKeyPress(m_keyLeft))  axis -= 1.0;
        if (in.IsKeyPress(m_keyRight)) axis += 1.0;

        m_isRunning = in.IsKeyPress(m_keyRun);
        m_vx = axis * (m_isRunning ? m_runSpeed : m_walkSpeed);

        if (axis < 0) m_facingLeft = true;
        if (axis > 0) m_facingLeft = false;

        // 지상 상태 전이
        if (m_onGround)
        {
            if (fabs(axis) > 0.1)
                ChangeState(m_isRunning ? STATE_RUN : STATE_WALK);
            else if (m_state == STATE_WALK || m_state == STATE_RUN)
                ChangeState(STATE_IDLE);
        }
    }

    // ── 앉기 ──
    if (in.IsKeyPress(m_keyDown) && m_onGround)
        ChangeState(STATE_CROUCH);
    else if (m_state == STATE_CROUCH && !in.IsKeyPress(m_keyDown))
        ChangeState(STATE_IDLE);

    // ── 점프 ──
    if (in.IsKeyDown(m_keyJump))
        TryJump();

    // ── 공격 ──
    if (in.IsKeyDown(m_keyAttack))
    {
        if (!m_onGround)                   ChangeState(STATE_J_ATTACK);
        else if (m_state == STATE_CROUCH)  ChangeState(STATE_C_ATTACK);
        else                               ChangeState(STATE_ATTACK);
    }

    // ── 가드 ──
    if (in.IsKeyPress(m_keyGuard) && m_onGround)
        ChangeState(STATE_GUARD);
    else if (m_state == STATE_GUARD && !in.IsKeyPress(m_keyGuard))
        ChangeState(STATE_IDLE);
}
```

```
   ★ ChangeState 를 그냥 부르기만 하면 된다

   전이가 허용되지 않으면 CanTransition 이 알아서 막는다
   → 입력 처리 코드에 "공격 중이면 무시" 같은 조건이 없다
```

> **이것이 FSM의 실질적 이득이다.** 조건이 한 곳(전이표)에만 있다.

### 3-8. State 패턴 (참고)

**왜 필요한가** — 상태가 더 늘어나면 이쪽이 낫다.

```cpp
class Character;

class IState
{
public:
    virtual ~IState() = default;
    virtual void Enter(Character* c) {}
    virtual void Update(Character* c, double dt) = 0;
    virtual void Exit(Character* c) {}
    virtual const char* GetName() const = 0;
};

class AttackState : public IState
{
public:
    void Enter(Character* c) override
    {
        c->GetAnimator().Play("attack", true);
        c->SetVx(0);
    }

    void Update(Character* c, double dt) override
    {
        if (c->GetAnimator().IsFinished())
            c->ChangeState(STATE_IDLE);
    }

    const char* GetName() const override { return "ATTACK"; }
};
```

```
   ★ 장단점

   +  상태마다 파일 분리 → 여러 명이 동시 작업 가능
   +  새 상태 추가가 다른 코드에 영향 없음
   -  파일 수가 늘어난다
   -  Character 의 private 멤버에 접근하려면 friend 나 getter 필요

   ★ Unity의 StateMachineBehaviour 가 이 방식이다 (Day 82)
```

## 4. 따라 만들기

### Step 1 — 전이표 배열

Day 45에서 만든 문서의 표를 3-5절 형태로 옮긴다.

```cpp

const bool g_transitionTable[STATE_COUNT][STATE_COUNT] = { /* ... */ };
```

**✅ 여기까지 하면** — 표가 코드가 된다.

> **한 줄씩 문서와 대조하며 옮긴다.** 이 단계에서 실수하면 나중에 원인을 못 찾는다.

### Step 2 — `CanTransition` 연결

```cpp
bool Character::CanTransition(State to) const
{
    if (m_state < 0 || m_state >= STATE_COUNT) return false;
    if (to    < 0 || to    >= STATE_COUNT) return false;
    return g_transitionTable[m_state][to];
}

void Character::ChangeState(State newState)
{
    if (m_state == newState) return;

    if (!CanTransition(newState))
    {
        if (g_logBlockedTransitions)
            DebugLog("[FSM] 차단: %s -> %s\n",
                     g_stateNames[m_state], g_stateNames[newState]);
        return;
    }

    OnExitState(m_state);
    AddHistory(m_state, newState);

    m_prevState  = m_state;
    m_state      = newState;
    m_stateTimer = 0.0;

    OnEnterState(newState);
}
```

**✅ 여기까지 실행하면** — 표에 없는 전이가 차단되고 로그가 찍힌다.

```cpp
void Character::RenderFsmDebug(Renderer& r) const
{
    int x = 20, y = 360;
    const int LH = 18;

    r.DrawRect(x - 8, y - 8, 380, 170, RGB(20, 20, 35));

    // 현재 상태 + 진행 막대
    r.DrawTextF(x, y, RGB(255, 220, 120),
                "상태     %-10s  %.2f 초", g_stateNames[m_state], m_stateTimer);
    y += LH;

    Animation* a = m_animator.GetCurrent();
    if (a && !a->IsLoop())
    {
        int barW = 200;
        r.DrawRect(x, y, barW, 8, RGB(50,50,70));
        r.DrawRect(x, y, (int)(barW * a->GetProgress()), 8, RGB(255,140,60));
        y += 16;
    }

    r.DrawTextF(x, y, RGB(200,200,220),
                "입력수용 %s    이동가능 %s",
                CanAcceptInput() ? "O" : "X",
                CanMove()        ? "O" : "X");
    y += LH;

    if (a)
    {
        r.DrawTextF(x, y, RGB(200,255,200),
                    "애니     \"%s\"  %d/%d  %s",
                    m_animator.GetCurrentName(),
                    a->GetLocalFrame() + 1, a->GetFrameCount(),
                    a->IsLoop() ? "LOOP" : "ONCE");
        y += LH;
    }

    // 전이 가능 목록
    y += 6;
    char allowed[256] = "";
    char blocked[256] = "";

    for (int s = 0; s < STATE_COUNT; s++)
    {
        if (s == m_state) continue;

        if (g_transitionTable[m_state][s])
        {
            strcat_s(allowed, sizeof(allowed), g_stateNames[s]);
            strcat_s(allowed, sizeof(allowed), " ");
        }
        else
        {
            strcat_s(blocked, sizeof(blocked), g_stateNames[s]);
            strcat_s(blocked, sizeof(blocked), " ");
        }
    }

    r.DrawTextF(x, y, RGB(140, 240, 140), "전이가능 %s", allowed); y += LH;
    r.DrawTextF(x, y, RGB(240, 140, 140), "차단됨   %s", blocked);
}
```

### Step 11 — 전이표 시각화 (선택)

```cpp
void RenderTransitionMatrix(Renderer& r, int x, int y, State current)
{
    const int CELL = 14;

    for (int from = 0; from < STATE_COUNT; from++)
    {
        for (int to = 0; to < STATE_COUNT; to++)
        {
            COLORREF c = g_transitionTable[from][to]
                       ? RGB(60, 160, 60)
                       : RGB(60, 60, 70);

            if (from == current) c = g_transitionTable[from][to]
                                   ? RGB(120, 255, 120)
                                   : RGB(120, 60, 60);

            r.DrawRect(x + to * CELL, y + from * CELL, CELL - 1, CELL - 1, c);
        }
    }
}
```

**✅ 여기까지 실행하면** — 전이표 전체가 격자로 보이고, 현재 상태 행이 강조된다.

**정상이라면 이렇게 보인다.**

```
   ┌──────────────────────────────────────────────────────────┐
   │  FSM                                             ─    ✕ │
   ├──────────────────────────────────────────────────────────┤
   │                       ██████▶                             │
   │                      ████████                             │
   │  ────────────────────────●────────────────────────────    │
   │                                                          │
   │  상태     ATTACK      0.18 초                             │
   │  [████████░░░░░░░░░░]                                     │
   │  입력수용 X    이동가능 X                                  │
   │  애니     "attack" 3/6  ONCE                              │
   │                                                          │
   │  전이가능 IDLE CROUCH HIT DOWN                            │
   │  차단됨   WALK RUN JUMP FALL ATTACK C_ATTACK ...          │
   │                                                          │
   │  [←→]이동 [↓]앉기 [⎵]점프 [A]공격 [S]가드 [H]피격         │
   └──────────────────────────────────────────────────────────┘
```

- [ ] `A`로 공격 모션이 재생된다
- [ ] **공격 중에 방향키를 눌러도 움직이지 않는다**
- [ ] 공격 모션이 끝나면 자동으로 대기로 돌아온다
- [ ] 아래 키로 앉고, 앉아서 공격하면 앉아 공격이 나온다
- [ ] 공중에서 공격하면 점프 공격이 나온다
- [ ] `H`로 피격되면 경직이 걸리고 조작이 안 된다
- [ ] 공격 중이어도 피격은 들어간다
- [ ] 체력이 0이면 쓰러지고 일정 시간 후 일어난다
- [ ] 차단된 전이가 로그에 찍힌다
- [ ] **전이표의 숫자만 바꿔서 규칙을 변경할 수 있다**

## 6. 자주 막히는 곳

| 증상 | 원인 | 해결 |
|---|---|---|
| 공격 중에도 움직임 | `CanAcceptInput` 미적용 | `ProcessInput` 맨 위에 |
| 공격이 끊김 | 매 프레임 `IDLE`로 되돌리는 코드 | 전이표로 차단되는지 확인 |
| 전이가 아예 안 됨 | 표의 칸이 0 | 표를 문서와 대조 |
| 표 인덱스가 어긋남 | enum 순서와 표 행 순서 불일치 | 주석으로 상태명 표기 |
| 공격 후 대기로 안 감 | `IsFinished` 미확인 | `UpdateAttack`에서 확인 |
| 피격이 안 먹힘 | HIT 열이 0 | 어느 상태에서든 1로 |
| 앉기가 풀리지 않음 | 키를 뗀 처리 누락 | `else if`로 IDLE 전이 |
| 무한 전이 반복 | A→B→A 조건이 동시에 참 | 로그로 확인 후 조건 조정 |
| DOWN에서 못 나옴 | `DOWN → GETUP` 칸이 0 | 표 수정 |
| 표가 너무 커서 헷갈림 | 상태가 많음 | State 패턴 검토 |

## 7. 정리

### 오늘 배운 것

| 개념 | 한 줄 요약 |
|---|---|
| **FSM** | 상태는 항상 하나, 정해진 조건으로만 전이 |
| 플래그 방식의 문제 | 2^n 조합, 불가능한 상태 발생 |
| `switch` vs State 패턴 | 상태 15개 미만이면 `switch`로 충분 |
| **전이표 배열** | 어제 만든 표가 그대로 코드가 된다 |
| `CanTransition` | 모든 전이 규칙이 여기 한 곳에 |
| `OnEnter` / `OnExit` | 상태 전환 시 한 번만 할 일 |
| 상태별 `Update` | 그 상태의 동작이 자기 함수 안에만 |
| `CanAcceptInput` / `CanMove` | 표의 "—"를 코드로 |
