### 3-2. 측정 자동화

**왜 필요한가** — 손으로 세면 오래 걸린다.

```csharp
namespace OneFloor.Debug
{
    [System.Serializable]
    public class FloorRecord
    {
        public int floor;
        public float duration;
        public int damageTaken;
        public bool died;
        public string weaponId;
    }

    public class PlaytestRecorder : MonoBehaviour
    {
        [SerializeField] private bool enabled = true;

        private readonly List<FloorRecord> records = new();
        private FloorRecord current;
        private float floorStartTime;

        private void OnEnable()
        {
            floorManager.OnFloorStarted += HandleFloorStarted;
            floorManager.OnFloorCleared += HandleFloorCleared;
            playerHealth.OnDamaged += HandleDamaged;
            playerHealth.OnDied += HandleDied;
        }

        private void HandleFloorStarted(FloorData floor)
        {
            floorStartTime = Time.time;

            current = new FloorRecord
            {
                floor = floor.floorNumber,
                weaponId = weaponHolder.Current?.id ?? "none",
            };
        }

        private void HandleFloorCleared(FloorData floor)
        {
            if (current == null) return;

            current.duration = Time.time - floorStartTime;
            records.Add(current);
            current = null;
        }

        private void HandleDamaged(DamageInfo info)
        {
            if (current != null) current.damageTaken += info.amount;
        }

        private void HandleDied()
        {
            if (current == null) return;

            current.duration = Time.time - floorStartTime;
            current.died = true;
            records.Add(current);
            current = null;

            SaveRecords();
        }

        private void SaveRecords()
        {
            string path = Path.Combine(
                Application.persistentDataPath, "playtest.csv");

            var sb = new System.Text.StringBuilder();

            if (!File.Exists(path))
                sb.AppendLine("session,floor,duration,damageTaken,died,weapon");

            string session = System.DateTime.Now.ToString("MMdd_HHmm");

            foreach (FloorRecord r in records)
            {
                sb.AppendLine($"{session},{r.floor},{r.duration:F1}," +
                              $"{r.damageTaken},{r.died},{r.weaponId}");
            }

            File.AppendAllText(path, sb.ToString());

            DebugUtil.Log($"[측정] {records.Count}건 기록");
        }
    }
}
```

```
   ★ CSV로 남기면

   엑셀·스프레드시트에서 분석할 수 있다
   → 평균, 사망률 자동 계산
```

```

   릴리즈에서는 제거

```
   ★ 좋은 곡선

   층별 사망률
   1층   0%
   2층   0%
   3층   5%
   4층  10%
   5층  20%
   6층  25%
   7층  35%
   8층  40%   (보스)

   → 완만하게 상승
```

```
   ⚠️ 나쁜 곡선

   1층   0%
   2층   0%
   3층   0%
   4층  60%   ★ 급격
   5층  20%
   ...

   → 4층에서 벽
   → 좌절 지점
```

```
   ★ 판정 기준

   전 층 사망률 0%       →  너무 쉽다
   한 층만 50%+          →  그 층이 벽
   후반 사망률 70%+      →  너무 어렵다
   완만한 상승           →  적정  ★
```

```
   ★ 소요 시간도 본다

   층별 소요 시간이 갑자기 2배
   → 그 층이 지루하거나 어렵다

### 3-4. 클리어율 목표

**왜 필요한가** — 게임 유형에 따라 다르다.

| 게임 유형 | 목표 클리어율 |
|---|---|
| 캐주얼 | 80~90% |
| **일반** | **50~70%** ★ |
| 도전적 | 30~50% |
| 로그라이크 | 10~30% (반복 전제) |

```
   ★ 4주 프로젝트 권장

   50~70%
   → 테스터가 완주해야 전체를 평가받는다
   → 너무 어려우면 후반을 못 본다
```

```
   ⚠️ 우리 게임은 로그라이크지만

   4주 프로젝트에서는 완주 가능성을 우선
   → 60% 목표
```

### 3-5. 지배 전략 점검

**왜 필요한가** — 하나만 쓰면 다 되면 재미없다.

```
   ★ 확인 방법

   ① 무기별 선택률
   ② 무기별 클리어율
   ③ 팀원에게 "뭐가 제일 좋아?"
```

```
   ★ 측정 결과 예

   무기    선택률  클리어율
   단검     18%     45%
   장검     22%     58%
   활       12%     40%
   대검     48%     72%   ★ 지배 전략
```

```
   ⚠️ 대검이 압도적이다

   ① 선택률 48% (다른 것의 2배)
   ② 클리어율 72% (가장 높다)
   → 조정 필요
```

```
   ★ 조정 방법

   ① 대검 하향 (damage 28 → 24)
   ② 다른 것 상향 (활 사거리 증가)
   ③ 대검의 단점 강화 (attackInterval 1.0 → 1.15)
```

```
   ★ 하향보다 상향이 좋다

   하향: "약해졌다" → 부정적
   상향: "강해졌다" → 긍정적

   ⚠️ 하지만 전체 난이도가 낮아진다
   → 적을 함께 상향
```

### 3-7. 버그 우선순위

**왜 필요한가** — 시간이 한정적이다.

| 등급 | 정의 | 처리 |
|---|---|---|
| **A · 치명** | 크래시, 진행 불가, 저장 손상 | **즉시** |
| **B · 중대** | 핵심 기능 오동작, 심각한 밸런스 붕괴 | **W23 내** |
| **C · 경미** | 표시 오류, 어색한 연출 | 시간 되면 |
| **D · 개선** | 있으면 좋은 것 | **처리하지 않음** |

```
   ★ 판단 기준

   A: 게임을 못 한다
   B: 게임은 되지만 크게 잘못됐다
   C: 눈에 띄지만 진행에 문제없다
   D: 버그가 아니라 개선 요청
```

```
   ⚠️ D를 고치고 있으면 멈춘다

   "이 이펙트를 좀 더 예쁘게"
   → 지금 할 일이 아니다
```
