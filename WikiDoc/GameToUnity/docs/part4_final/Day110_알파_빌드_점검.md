## 3. 개념

### 3-1. 알파의 정의

**왜 필요한가** — 기준을 명확히.

```
   ★ 알파 = "기능은 다 있으나 거칠다"

   ○ 모든 시스템이 동작한다
   ○ 처음부터 끝까지 플레이된다
   ○ 진행 불가 버그가 없다

   × 콘텐츠가 부족하다      (W23)
   × 연출이 없다            (W23)
   × 밸런스가 거칠다        (W23)
   × 자잘한 버그가 있다      (W24)
```

```
   ★ 알파의 목적

   "이 게임이 완성될 수 있는가?"를 확인
```

```
   ⚠️ 알파를 통과 못 하면

   → 남은 10일에 기능을 만들어야 한다
   → W23·W24가 사라진다
   → 완성 실패

   ★ 오늘 안에 해결한다
```

### 3-2. 알파 체크리스트

**왜 필요한가** — 검증 가능한 기준.

| 항목 | 확인 |
|---|:--:|
| 타이틀 → 인게임 → 결과 → 타이틀 흐름이 완결되는가 | ☐ |

| **치트 없이 완주 가능한가** | ☐ |

```
   ★ 6개 전부 체크되어야 알파다

   하나라도 안 되면 오늘 안에 해결
```

```csharp
    // 화면에 오류 표시 (Development Build)
    public class ErrorDisplay : MonoBehaviour
    {
        [SerializeField] private TextMeshProUGUI errorText;
        [SerializeField] private GameObject panel;
        [SerializeField] private int maxLines = 5;

        private readonly Queue<string> lines = new Queue<string>();

        private void OnEnable()
        {
            Application.logMessageReceived += HandleLog;
        }

        private void OnDisable()
        {
            Application.logMessageReceived -= HandleLog;
        }

        private void HandleLog(string msg, string stack, LogType type)
        {
            if (type != LogType.Error && type != LogType.Exception) return;

            lines.Enqueue($"[{type}] {msg}");
            while (lines.Count > maxLines) lines.Dequeue();

            errorText.text = string.Join("\n", lines);
            panel.SetActive(true);
        }
    }
```

### 3-7. 흔한 알파 블로커

**왜 필요한가** — 미리 알면 빨리 찾는다.

| 유형 | 예 | 원인 |
|---|---|---|
| **데이터 누락** | 마지막 층에 적이 없음 | SO 설정 미완 |
| **인덱스 초과** | 마지막 층 클리어 시 크래시 | `>=` vs `>` |
| **null 참조** | 특정 조건에서 예외 | 초기화 순서 |
| **상태 꼬임** | 재시작 후 이상 | static / timeScale |
| **커서 잠금** | UI에서 클릭 불가 | 상태 전환 누락 |
| **풀 고갈** | 적이 안 나옴 | maxSize |
| **이벤트 누적** | 데미지가 2배 | 구독 해제 누락 |
| **씬 전환 데이터** | 결과가 0 | 전달 실패 |

```
   ★ 가장 흔한 것

   ① 마지막 층/웨이브 처리
   ② 재시작 후 상태
   ③ 커서 잠금
```
