## ① 학습 목표

이 레슨을 마치면 이렇게 할 수 있습니다.

- 객체가 20개 있는 이미지를 **누락 없이** 라벨링하는 작업 순서를 실행할 수 있다.

- 반사 · 그림자 · 화면 속 화면을 구분하고 처리할 수 있다.
- 라벨링 중 만난 애매한 사례를 **체계적으로 수집**해 팀 토론에 올릴 수 있다.
- 다중 객체 라벨의 품질을 **누락 중심으로** 점검할 수 있다.

## ② 왜 필요한가

### 객체가 늘면 실수의 종류가 바뀝니다

```
Day 138  person 1~2개 / 장
  주된 실수 : 박스가 큼 · 작게 침

Day 142  person + box, 최대 20개 / 장
  주된 실수 : ★ 놓침 (누락)
```

**누락은 박스 크기 오차와 비교가 안 될 만큼 해롭습니다.**

```
박스가 10% 큼   → 모델이 조금 큰 박스를 예측 → mAP50 소폭 하락
객체 1개 누락    → 모델이 "그건 객체가 아니다"라고 배움
                → ★ 비슷한 상황에서 전부 미검출
```

[Day 138](day-138.md)에서 확인한 숫자입니다.

```
박스를 10% 여유 있게   mAP 0.81 → 0.74
10% 라벨 누락         mAP 0.81 → 0.68     ★ 더 나쁨
```

### 사람이 20개 있는 사진에서 몇 개를 놓칠까요

```
실측 (수업 실습 데이터)

  객체 1~3개   누락률  1%
  객체 4~8개   누락률  4%
  객체 9~15개  누락률 11%
  객체 16개+   누락률 ★ 23%
```

**객체가 많아지면 사람은 반드시 놓칩니다.** 집중력 문제가 아니라 구조적 문제입니다.

```
왜 놓치는가
  · 눈에 띄는 것부터 치고, 다 쳤다고 느낌
  · 이미 친 박스가 화면을 가려 뒤쪽이 안 보임
  · 작은 객체는 스크롤/확대 없이는 인지 못 함
```

> **★ 그래서 "작업 순서"가 필요합니다.**
> 무작정 눈에 보이는 대로 치면 20개 중 5개를 놓칩니다.
> 오늘 배우는 **격자 스캔 순서**가 이 문제를 해결합니다.

### 가림은 "몇 %"로 정할 수 없습니다

어제 정의서에 이렇게 썼을 겁니다.

```
"30% 이상 보이면 라벨링"
```

**막상 사진 앞에서는 판단이 안 됩니다.**

```
문틀에 반쯤 가린 사람 → 45%? 35%? 25%?
→ 잴 수가 없음
→ 사람마다 다르게 판정
→ ★ Day 141 시범 라벨링에서 일치율 20%가 나온 이유
```

**오늘 이것을 "판단 가능한 규칙"으로 바꿉니다.**

### 오늘 하는 일

```
1~4교시 (개념)
  ① 20개 객체 작업 순서 — 격자 스캔
  ② ★ 가림 기준을 조작적 정의로
  ③ 잘림 · 작은 객체 · 군중
  ④ 반사 · 그림자 · 화면 속 화면

5~8교시 (실습)
  ⑤ 다중 객체 100장 라벨링
  ⑥ ★ 애매 사례를 즉시 기록
  ⑦ 누락 중심 자가 점검
  ⑧ 팀 토론으로 기준 확정
```

### 오늘의 목표를 한 줄로

> **"객체가 20개여도 하나도 안 놓치고, 애매한 것은 판단하지 말고 기록한다."**

## ③ 개념 설명

### ★ 20개 객체 작업 순서 — 격자 스캔

**나쁜 방법 — 눈에 띄는 대로**

```
  ┌─────────────────────┐
  │  ①            ③    │      큰 것 · 앞에 있는 것부터
  │      ②              │      → 작은 것 · 뒤에 있는 것을 놓침
  │           · ·  ·    │      → "다 한 것 같은데"
  └─────────────────────┘
```

**좋은 방법 — 격자 스캔**

```
  ┌───────┬───────┬───────┐
  │   1   │   2   │   3   │      화면을 6~9칸으로 나누고
  ├───────┼───────┼───────┤      ★ 칸마다 완전히 끝내고 다음 칸
  │   4   │   5   │   6   │
  └───────┴───────┴───────┘      "이 칸에 더 없나?" 를 칸마다 물음
```

**작업 절차 5단계**

```
[1] 전체를 3초간 훑고 대략 몇 개인지 센다     ★ 목표 개수를 먼저 정함
      "사람 7명, 상자 3개 = 10개"

[2] 격자 순서로 큰 객체부터 라벨링

[3] ★ 확대(Ctrl+휠)해서 작은 객체를 한 번 더 스캔

[4] 박스 표시를 끄고(labelImg: 라벨 숨김) 원본을 다시 본다
      → 놓친 것이 보임

[5] 개수를 [1]의 목표와 대조
      "10개 예상했는데 8개 → 2개 어디 갔지?"
```

> **★ [1]단계가 핵심입니다.**
> 목표 개수를 먼저 세어 두면, 마지막에 **자기 검증**이 가능합니다.
> 이것 하나로 누락률이 23% → 6%로 떨어집니다.

### 가림(occlusion) — 조작적 정의로 바꾸기

**"30% 이상 보이면"은 잴 수 없습니다.** 다음처럼 바꿉니다.

```
✗ 잴 수 없는 정의
    "30% 이상 보이면 라벨링"

✓ 판단 가능한 정의
    "몸통(어깨~허리)이 일부라도 보이면 라벨링"
```

**클래스별 조작적 정의 예시**

| 클래스 | ✗ 모호한 정의 | ✓ 조작적 정의 |
|---|---|---|
| person | 30% 이상 보임 | **몸통(어깨~허리)이 일부라도 보임** |
| car | 절반 이상 보임 | **바퀴 1개 이상 + 차체 일부**, 또는 **앞/뒷유리가 보임** |
| box | 대부분 보임 | **직각으로 만나는 면 2개**가 보임 |
| helmet | — | **머리 윤곽선의 절반 이상** |

```
★ 좋은 조작적 정의의 조건

  ① 1초 안에 판단 가능
  ② 예/아니오로 답이 나옴
  ③ 두 사람이 같은 답을 냄
  ④ ★ 확대하지 않고도 대부분 판단 가능
```

**가림의 3가지 유형**

```
① 다른 객체에 가림 (occlusion)
     ┌──────┐
     │  👤  │   앞사람 뒤에 있는 사람
     │ ▓▓👤 │
     └──────┘

② 화면 밖으로 나감 (truncation)
     ┌──────┐
   👤│      │   왼쪽 절반이 화면 밖
     └──────┘

③ 환경에 가림 (문틀, 기둥, 나무)
     ┌──┬───┐
     │👤│   │
     └──┴───┘
```

**세 유형 모두 처리 원칙은 같습니다.**

```
✓ 보이는 부분만 감싼다
✗ 가려진 부분을 추정해서 늘리지 않는다
```

### 잘린 객체(truncation) 처리

```
  화면 경계
     │
  ██ │              박스: 화면 안쪽 부분만
  ██ │              x1 = 0 (경계에 딱 붙임)
     │              ✗ x1 = -30 (음수 금지)
```

```
판단
  · 화면 안에 보이는 부분이 조작적 정의를 만족하면 → 라벨링
  · 손가락 끝만 보임 → 제외 (몸통 안 보임)
  · 머리와 어깨가 보임 → 라벨링
```

> **잘린 객체는 반드시 라벨링해야 합니다.**
> CCTV 화면 가장자리에는 항상 잘린 사람이 있습니다.
> 이걸 다 빼면 **모델이 가장자리에서 아무것도 못 찾습니다.**

### 아주 작은 객체

```
Day 138 기준: 12 × 12 픽셀 이상
```

**그런데 문제가 있습니다.**

```
1920×1080 원본에서 12px = 0.6%
그런데 학습 시 640×640 으로 리사이즈하면?

  12px × (640/1920) = 4px      ★ 4픽셀
  → 모델이 배울 수 있는 크기가 아님
```

**★ 최소 크기는 "학습 해상도 기준"으로 정해야 합니다.**

```
권장 기준

  학습 imgsz 기준으로 최소 8~10픽셀
  원본 1920 → imgsz 640 이면 축소율 1/3
  ★ 원본에서 최소 24~30픽셀

계산식
  최소_원본_px = 8 / (imgsz / 원본_긴변)
               = 8 × (1920 / 640)
               = 24px
```

| 원본 해상도 | imgsz 640 기준 최소 크기 |
|---|---|
| 640×480 | 8 px |
| 1280×720 | 16 px |
| **1920×1080** | **24 px** |
| 3840×2160 | 48 px |

> **★ 오늘 이 기준으로 [Day 138](day-138.md)의 12px 규칙을 갱신합니다.**
> 우리 촬영 해상도가 1920이라면 **24px 미만은 제외**입니다.
> 이 결정을 [Day 143](day-143.md) 가이드에 반영합니다.

### 군중 — 셀 수 없는 경우

```
  ┌──────────────────────┐
  │  👤👤👤👤👤👤👤👤    │      뒤쪽 30명이 뭉쳐 있음
  │ 👤👤👤👤👤👤👤👤👤   │      개별 구분 불가
  │  👤    👤     👤     │      앞쪽 3명은 명확
  └──────────────────────┘
```

**세 가지 처리 방법**

| 방법 | 설명 | 장단점 |
|---|---|---|
| **① 앞쪽만 라벨링** | 구분 가능한 것만, 나머지는 무시 | ★ 뒤쪽이 "배경"으로 학습됨 |
| **② 전체를 하나로** | 군중 전체에 박스 1개 (`crowd` 클래스) | 별도 클래스 필요 |
| **③ 이미지 제외** | 이런 사진을 데이터셋에서 뺌 | ★ 우리 권장 |

```
★ 우리 프로젝트(현관 CCTV)에서는 ③

  이유
    · 현관에 30명이 몰리는 일은 거의 없음
    · 그런 이미지 몇 장 때문에 기준을 복잡하게 만들 이유가 없음
    · ①은 모순 라벨을 만들고, ②는 클래스가 늘어남

  단, 매장 카운팅 프로젝트라면 ②를 검토해야 합니다
```

**COCO의 방식 — 참고**

```
COCO는 iscrowd=1 로 표시하고 평가에서 제외합니다
→ 학습에도 쓰지 않음
→ 결국 ③과 비슷한 효과
```

### 반사 · 그림자 · 화면 속 화면

```
① 유리·거울 반사        →  제외  (실제 공간에 없음)
② 그림자                →  제외
③ 포스터·인쇄물         →  제외
④ TV·모니터 속 인물     →  제외
⑤ 물웅덩이 반사         →  제외
```

**전부 같은 원칙입니다.**

> **"실제 그 좌표에 물체가 존재하는가?"**

**그런데 예외가 있습니다**

```
목적이 "매장 방문객 수"라면
  · 반사를 세면 → 이중 계수
  · 제외가 맞음

목적이 "사각지대 감시"라면
  · ★ 거울에 비친 것이 유일한 정보일 수 있음
  · 포함을 검토

→ ★ 목적이 정합니다. 정답이 아니라 결정입니다.
```

**어려운 경계 사례**

| 상황 | 판단 | 근거 |
|---|---|---|
| 유리문 너머 실제 사람 | ✓ **포함** | 유리를 통해 보이지만 실제 존재 |
| 유리에 비친 사람 | ✗ 제외 | 반사 |
| **둘 다 겹쳐 보임** | ✓ 실제만 포함 | 구분 가능하면 실제만 |
| 구분 불가 | ✗ **이미지 제외** | 판단 불가한 이미지는 버림 |

> **★ "판단 불가한 이미지는 데이터셋에서 뺀다"는 선택지를 기억하세요.**
> 애매한 이미지 한 장 때문에 기준을 복잡하게 만드는 것보다,
> **그 한 장을 버리는 것**이 데이터 품질에 낫습니다.

### 겹치는 클래스 — 사람이 상자를 들고 있으면

```
  ┌──────────┐
  │    👤    │      person 박스: 사람 전체
  │   [📦]   │      box 박스   : 상자 전체
  │    ││    │      ★ 둘이 겹쳐도 각각 라벨링
  └──────────┘
```

```
원칙: 클래스는 서로 독립적입니다

  ✓ person 박스 안에 box 박스가 있어도 됨
  ✓ box 가 person 에 일부 가려도 보이는 부분만 감쌈
  ✗ "둘 중 하나만" 고르지 않음
```

**단, 상자가 사람에 가려 조작적 정의를 못 만족하면 제외합니다.**

```
상자의 조작적 정의: "직각으로 만나는 면 2개가 보임"
→ 사람이 앞을 가려 한 면만 보이면  →  제외
```

### Step 2. ★ 격자 스캔 보조 도구

**라벨링 전에 격자를 그린 사본을 만들면 순서를 지키기 쉽습니다.**

```python
from pathlib import Path

import cv2

ROOT = Path("C:/vision/day142")


def make_grid_preview(img_path, out_path, cols=3, rows=2):
    """격자와 칸 번호를 그린 미리보기 — 작업 순서 참고용"""
    img = cv2.imread(str(img_path))
    if img is None:
        raise FileNotFoundError(img_path)
    h, w = img.shape[:2]
    overlay = img.copy()

    for i in range(1, cols):
        x = w * i // cols
        cv2.line(overlay, (x, 0), (x, h), (0, 220, 255), 2)
    for j in range(1, rows):
        y = h * j // rows
        cv2.line(overlay, (0, y), (w, y), (0, 220, 255), 2)

    n = 1
    for j in range(rows):
        for i in range(cols):
            cx = w * i // cols + 20
            cy = h * j // rows + 46
            cv2.putText(overlay, str(n), (cx, cy),
                        cv2.FONT_HERSHEY_SIMPLEX, 1.4, (0, 0, 0), 6, cv2.LINE_AA)
            cv2.putText(overlay, str(n), (cx, cy),
                        cv2.FONT_HERSHEY_SIMPLEX, 1.4, (0, 220, 255), 2, cv2.LINE_AA)
            n += 1

    blended = cv2.addWeighted(overlay, 0.75, img, 0.25, 0)
    Path(out_path).parent.mkdir(parents=True, exist_ok=True)
    cv2.imwrite(str(out_path), blended)
    return out_path

import csv
from datetime import datetime
from pathlib import Path

LOG = Path("C:/vision/day142/ambiguous_log.csv")

    "1": "가림 (다른 객체)",

                    CATEGORIES.get(category, "기타"), note, my_choice, "", ""])

    print("애매 사례 기록 (빈 입력으로 종료)")

### Step 6. 자동 누락 탐지 — 사전학습 모델 활용

**사람이 놓친 것을 모델이 찾아 줍니다.**

```python
from pathlib import Path

import cv2
from ultralytics import YOLO

import bbox_utils as B

ROOT = Path("C:/vision/day142")
OUT = ROOT / "check/missing"
OUT.mkdir(parents=True, exist_ok=True)

model = YOLO("yolo11n.pt")
PERSON_COCO = 0          # COCO의 person
PERSON_OURS = 0          # 우리 클래스의 person


def iou(a, b):
    ax1, ay1, ax2, ay2 = a
    bx1, by1, bx2, by2 = b
    ix1, iy1 = max(ax1, bx1), max(ay1, by1)
    ix2, iy2 = min(ax2, bx2), min(ay2, by2)
    iw, ih = max(0, ix2 - ix1), max(0, iy2 - iy1)
    inter = iw * ih
    ua = (ax2-ax1)*(ay2-ay1) + (bx2-bx1)*(by2-by1) - inter
    return inter / ua if ua > 0 else 0


def find_missing(image_dir, label_dir, conf=0.5, iou_thr=0.4, min_px=24):
    """모델이 찾았는데 라벨에 없는 person 을 표시"""
    image_dir, label_dir = Path(image_dir), Path(label_dir)
    report = []

    for p in sorted(image_dir.glob("*.jpg")):
        img = cv2.imread(str(p))
        if img is None:
            continue
        h, w = img.shape[:2]

        # 사람이 친 라벨 (person만)
        gt = []
        txt = label_dir / (p.stem + ".txt")
        if txt.exists():
            for line in txt.read_text(encoding="utf-8").splitlines():
                if not line.strip():
                    continue
                parts = line.split()
                if int(parts[0]) != PERSON_OURS:
                    continue
                gt.append(B.yolo_to_voc(tuple(float(v) for v in parts[1:5]), w, h))

        # 모델 예측
        r = model(str(p), conf=conf, classes=[PERSON_COCO], verbose=False)[0]
        pred = [tuple(b.xyxy[0].tolist()) for b in r.boxes]

        missing = []
        for pb in pred:
            if min(pb[2]-pb[0], pb[3]-pb[1]) < min_px:      # 너무 작은 건 제외
                continue
            if all(iou(pb, g) < iou_thr for g in gt):
                missing.append(pb)

        if missing:
            vis = img.copy()
            for g in gt:
                x1, y1, x2, y2 = B.to_int(g)
                cv2.rectangle(vis, (x1, y1), (x2, y2), (60, 220, 60), 2)
            for m in missing:
                x1, y1, x2, y2 = B.to_int(m)
                cv2.rectangle(vis, (x1, y1), (x2, y2), (0, 0, 255), 3)
                cv2.putText(vis, "MISSING?", (x1 + 3, max(y1 - 6, 18)),
                            cv2.FONT_HERSHEY_SIMPLEX, 0.6, (0, 0, 255), 2, cv2.LINE_AA)
            cv2.imwrite(str(OUT / p.name), vis)
            report.append((p.stem, len(gt), len(pred), len(missing)))

    return report


rep = find_missing(ROOT / "images", ROOT / "labels")

    반사·포스터        →  기준대로 제외 (모델은 구분 못 함)
    너무 작음          →  기준대로 제외

## ⑤ 자주 하는 실수

### 눈에 띄는 것부터 치고 "다 했다"고 느낌

```
객체 17개 사진에서 13개만 라벨링
→ 4개를 놓쳤다는 것을 스스로는 모름
```

**대응**: 작업 전 개수 세기 + 격자 스캔 + 마지막 개수 대조.

### 이미 친 박스가 뒤쪽을 가려서 못 봄

```
labelImg 에서 박스 선이 굵으면 뒤쪽 작은 객체가 안 보임
```

**대응**:

```
· 작은 객체부터 먼저 치기
· 또는 View → Display Labels 를 잠시 꺼서 원본 확인
· ★ 마지막에 반드시 박스를 숨기고 원본을 한 번 더 훑기
```

### 가림 기준을 "%"로 정하고 매번 다르게 판정

```
"30% 이상"  →  잴 수 없음  →  기분대로
```

**대응**: 조작적 정의로 바꾸기. **"몸통이 보이는가"** 처럼 예/아니오로 답나는 규칙.

### 애매한 사진에서 오래 고민

```
반사 하나에 3분 → 100장에 5시간
```

**대응**: **5초 안에 기록하고 넘어가기.** 판단은 팀이 모아서.

### 확대 없이 작은 객체를 대충 침

```
20px 박스에서 5px 오차 → IoU 0.66
```

**대응**: `Ctrl + 휠` 로 200% 이상 확대. **작은 객체일수록 확대는 필수입니다.**

### 겹치는 클래스에서 하나만 고름

```
사람이 상자를 들고 있는데 person 만 라벨링
→ box 인스턴스 누락
```

**대응**: 클래스는 독립. **각각 따로 봅니다.**

### 최소 크기 기준을 원본 해상도로만 생각

```
"12px 이상이면 OK"
→ 1920 원본을 640으로 학습하면 4px
→ ★ 학습 불가능한 크기
```

**대응**: `최소_원본_px = 8 × (원본_긴변 / imgsz)`

### 기준을 바꾸고 기존 데이터를 안 고침

```
Day 138: 12px 기준으로 100장
Day 142: 24px 로 변경
→ 앞의 100장은 여전히 12px 기준
→ ★ 데이터가 모순
```

**대응**: 기준 변경 시 **반드시 기존 데이터를 재처리**합니다. Step 8의 스크립트.

### 군중 사진을 억지로 라벨링

```
30명 뭉친 사진에서 15명만 라벨링
→ 나머지 15명이 "배경"으로 학습됨
→ ★ 데이터가 오염됨
```

**대응**: 개별 구분이 불가능하면 **이미지 자체를 제외**합니다.

### 클래스 판정이 애매한 것을 그때그때 다르게

```
"이게 택배 상자인가 그냥 종이 상자인가"
월요일: box   금요일: 제외
```

**대응**: 정의서의 조작적 정의를 다시 읽고, 없으면 **기록 → 팀 결정 → 정의서에 추가**.

| **1** | ★ **내가 대량 누락** | 작업 시간이 1/3. 초/박스는 비슷 |
| 2 | 팀원이 과잉 라벨링 | 반사·포스터까지 침 |
| 3 | 기준 차이 (크기·가림) | 작은 객체 포함 여부 |
| 4 | 서로 다른 이미지 | ★ 먼저 확인할 것 |

**초/박스가 7.7 vs 10.6 인 것이 핵심 단서입니다.**

```
초/박스가 비슷 → 둘 다 박스 하나에 비슷한 시간을 씀
→ 작업 속도의 문제가 아니라 ★ 박스 개수 자체의 차이
→ 누락 또는 과잉
```

**분포 모양도 말해 줍니다.**

```
나:    1~2개에 집중, 6개 이상 0장
팀원:  고르게 퍼짐, 8개 이상 18장

원본 영상이 복도라면 8명이 동시에 있는 장면이 18장 있는 것이 자연스러움
→ ★ 내 쪽에서 큰 것만 치고 작은 것을 놓쳤을 가능성
```

**내 쪽이 문제일 가능성이 높습니다.**

**근거 1 — 작업 시간**

→ Day 142 절차를 안 지켰을 가능성
```

**근거 2 — 최대 박스 5개**

```
100장 중 6개 이상인 사진이 한 장도 없음
→ ★ 부자연스러움
→ 복도 영상에서 6명 이상이 한 프레임에 없을 리 없음
```

**근거 3 — 0개가 6장뿐**

```
팀원은 4장, 나는 6장 — 비슷
→ "아무도 없는 사진"은 둘 다 비슷하게 판정
→ 즉 ★ 있는 사진에서 개수가 갈림

import cv2

def blur_score(path):
    """라플라시안 분산 — 낮을수록 흐릿"""
    img = cv2.imread(str(path), cv2.IMREAD_GRAYSCALE)
    return cv2.Laplacian(img, cv2.CV_64F).var()

# 전체 분포를 보고 하위 10~15%를 검토 대상으로
scores = [(p, blur_score(p)) for p in Path("images").glob("*.jpg")]
scores.sort(key=lambda x: x[1])
for p, s in scores[:20]:
    print(f"{s:8.1f}  {p.name}")     # ← 이것들을 눈으로 확인
```

| 항목 | 핵심 |
|---|---|
| 주된 실수 변화 | 박스 크기 → ★ **누락** |
| 누락률 | 객체 16개+ 에서 **23%** |
| 작업 순서 | ① **개수 세기** ② 격자 스캔 ③ 확대 재스캔 ④ 박스 숨김 확인 ⑤ 대조 |
| 격자 스캔 | 6~9칸. **칸마다 완전히 끝내고** 이동 |
| 가림 기준 | ✗ "30%" → ✓ **조작적 정의** |
| person 정의 | **몸통(어깨~허리)이 일부라도 보임** |
| box 정의 | **직각으로 만나는 면 2개** |
| 잘림 | **보이는 부분만.** 경계에 붙임. 음수 금지 |
| ★ 최소 크기 | **학습 해상도 기준** 8px → 원본 1920이면 **24px** |
| 계산식 | `최소_원본_px = 8 × (원본_긴변 / imgsz)` |
| 군중 | 개별 구분 불가면 **이미지 제외** |
| 반사·그림자·인쇄물 | 제외 — **"실제 그 좌표에 있는가"** |
| 겹치는 클래스 | **각각 독립적으로** 라벨링 |
| 애매 사례 | ★ **판단하지 말고 5초 안에 기록** |
