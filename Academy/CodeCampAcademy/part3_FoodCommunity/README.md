## Part 3의 한마디 — "내 서비스를, 시스템으로"

Part 1이 *"혼자서 만들 수 있다"*, Part 2가 *"팀처럼, 통제하며 만든다"* 였다면 Part 3는 **"내 서비스를, 시스템으로 만들어, 세상에 내놓는다"** 입니다.

- **Week 4 (Day 17–22)** — 솔로프리너의 기획(PRD)에서 시작해 **디자인 시스템**(토큰 → 파운데이션 → 컴포넌트 23종)을 쌓고, **스토리북을 SSOT 삼아 코드로 핸드오프**합니다.
- **Week 5 (Day 23–25)** — 화면 뒤에 **데이터가 앉을 자리**를 만듭니다. 정규화·썸네일·**BFF**·소프트 삭제.
- **Week 6 (Day 26–29)** — **바깥 API**(네이버 검색/지도)를 붙이고, **배포·도메인·상표권·PWA**로 출시합니다.

> 반복되는 세 문장 — **구현이 아니라 수정이 문제다. 컴포넌트는 복사가 아니라 연결이다. 그리고 프론트엔드 코드에는 비밀이 존재할 수 없다.**

## Day 17 · 나 혼자 MVP 만들기 — 솔로프리너와 PRD

**배우는 것**

- **솔로프리너**가 지금 가능해진 이유 — AI가 **규모의 장벽**(사람·기술·관계)을 한 사람이 넘을 높이로 낮췄다
- 전체 프로세스 **3축**: ① 구성원 및 역할 ② 제품 구성 요소 ③ 전자상거래 유형(B2C·B2B·**B2B2C**·B2G·C2C)
- **하이브리드 앱** — 웹 하나를 만들어 앱으로 씌운다 / 일반 구조도 vs 플랫폼 구조도(**정산**이 생긴다)
- **비즈니스 모델 4가지**(상품 판매·구독·광고·플랫폼 수수료)와 **BM 도식화**
- 시장 유형 두 갈래 — 아이디어 O → **수요 검증** / 아이디어 X → **차별화**

**실습·과제** — 맛집커뮤니티 **PRD** 만들기: 누가(구로 주변 차량 보유 가족/커플) · 무엇을(페이지 5개) · 왜(일상에서 벗어난 색다른 경험).

**이걸 할 수 있으면 통과**

- [ ] "아이디어 좋네요"와 **"돈 내고서라도 쓸게요"** 의 차이를 설명할 수 있다
- [ ] 내 상황(왕초보·생활비·투자·아이디어 유무)에 따라 피해야 할 BM을 판단할 수 있다
- [ ] PRD를 누가·무엇을·왜 + **성공 지표(KR)** 까지 써낼 수 있다

## Day 18 · MVP 디자인 프로세스 — 툴 선택과 반응형

**배우는 것**

- 프로토타입 툴의 한계 = **단방향 핸드오프** — 추가 디자인이 원본으로 돌아오지 않는다
- 상황별 툴: **클로드 디자인**(프로토타입) · **Pencil**(1인 MVP) · **Figma**(팀 협업)
- **적응형 vs 반응형**, 하이브리드 앱은 반응형이 전제
- 반응형은 **작게 만들고 늘인다** — 기준은 **[인기 기기] ∩ [최소 사이즈] = 가로 360**(세로 가변)

**실습·과제** — 레퍼런스 + PRD + **사이즈 가이드(360×780)** + 페이지 가이드(메인·상세·**등록 에러 상태**)로 시안 생성.

**이걸 할 수 있으면 통과**

- [ ] 점유율 1위(384)가 아니라 **360**을 기준으로 잡는 이유를 설명할 수 있다
- [ ] 등록 페이지를 **에러 상태로** 그려야 하는 이유를 말할 수 있다

## Day 19 · 디자인 시스템 ① — 컬러와 디자인 토큰

**배우는 것**

- *"70페이지 다 만들었는데 브랜드 컬러를 바꿔달라"* — 디자인 시스템은 **"예쁘게"가 아니라 "바꿀 수 있게"**
- **프리미티브 → 시맨틱 2층 토큰**, 팔레트 50~950(11단계), **500이 기준**
- 명암비 **일반 텍스트 4.5:1 / 큰 텍스트 3:1**(WCAG 1.4.3) — 눈이 아니라 **숫자로 검증**
- 파운데이션 프롬프트 **5블록 · 3단 서식**(대상 / 명칭 / 주의사항)

**실습·과제** — 프리미티브 → 시맨틱 → 팔레트 렌더 → **기존 시안 리팩토링**.

**이걸 할 수 있으면 통과**

- [ ] `hex 직접 입력 금지` + `프리미티브 토큰 참조` 두 줄이 왜 절대 규칙인지 설명할 수 있다
- [ ] 토큰을 만드는 것과 **적용하는 것(리팩토링)** 이 별개임을 안다

## Day 20 · 디자인 시스템 ② — 타이포·아이콘, 그리고 첫 컴포넌트

**배우는 것**

- 컬러는 **값**으로 끝나지만 타이포·아이콘은 **컴포넌트**까지 가야 끝난다
- 프리미티브 3종(사이즈 9 · 두께 3 · 행간 2) → **구조 10종**(display/heading/body/label), 자간 **-2%(상대값)**
- 루시드 아이콘 **36종 × 4사이즈 = 144개**, 레이아웃을 **문장으로** 지정(20행 / 넘치면 오른쪽 열)
- 첫 UI 컴포넌트 — 아이콘 버튼 **48×48** 안에 아이콘 **24** (여백 12px이 오터치 방지 영역)

**실습·과제** — 타이포 10종 · 아이콘 144개 · 아이콘 버튼 3종 렌더 후 **컴포넌트 전환**.

**이걸 할 수 있으면 통과**

- [ ] 같은 16px인데 `heading-sm`과 `body-lg`가 갈리는 두 값을 말할 수 있다
- [ ] **"안은 컴포넌트, 밖은 프레임"** 규칙이 왜 세 번 반복되는지 설명할 수 있다

## Day 21 · UI 컴포넌트 본편 — 5그룹 23종

**배우는 것**

## Day 22 · 핸드오프 — 스토리북과 SSOT

**배우는 것**

- 문제는 이제 수정이 아니라 **추적** — *"이거 코드로 구현까지 된 건가?"*
- **스토리북 = 코드로 구현된 디자인 시스템 보여주는 홈페이지**, `localhost:6006`
- 핸드오프는 **2번** — 디자인 시스템 → 하이파이. **재료 먼저, 화면 나중**
- ★ `design.md` 가이드 = **확률론** / 스토리북 결과물 갖다쓰기 = **결정론**
- **SSOT 규칙 6줄**을 `CLAUDE.md`에 **강제형**으로

**실습·과제** — Next 프로젝트 + 스토리북 셋팅 → 파운데이션·컴포넌트 핸드오프 → SSOT 규칙 등록.

**이걸 할 수 있으면 통과**

- [ ] `3000`과 `6006`이 각각 무엇을 보여주는지 구분할 수 있다
- [ ] 규칙을 `design.md`가 아니라 `CLAUDE.md`에 두는 이유를 설명할 수 있다

## Day 23 · 맛집 DB 설계와 이미지 썸네일

**배우는 것**

- **DB가 1번이 아니라 4번**인 순서도: 기획/디자인 → 데이터 추출 → **정규화** → DB 생성
- 정규화의 두 질문 — **"몇 번 반복되는가"**(쪼갠다) · **"주인이 누구인가"**(Supabase면 안 만든다)
- 결과물 **3 tables**: `place` · `place_image` · `profile` (유저는 Supabase 몫)
- 느림의 정체는 **다운로드 용량** → 썸네일 **S/M/L**
- 썸네일 2방식: **영구 저장**(등록시) vs **온디맨드 리사이징**(조회시) + **캐시**

**실습·과제** — Supabase 프로젝트 생성 → 맛집·이미지·프로필 테이블 생성.

**이걸 할 수 있으면 통과**

- [ ] 이미지를 `이미지1·이미지2` 컬럼으로 넣으면 안 되는 이유를 표로 설명할 수 있다
- [ ] 두 썸네일 방식의 트레이드오프를 **"저장 공간 vs 계산"** 으로 말할 수 있다

## Day 24 · BaaS와 비즈니스 로직 노출, 그리고 BFF

**배우는 것**

- 자산의 기준은 **"여러 단계로 조합되어 있는가"** — 이달의 우수회원(4단계) ⭕ / 프로필 조회 ❌
- BaaS는 **백엔드 + DB** → 백엔드 자리가 비면 **로직이 브라우저로 밀려난다**
- F12 → Sources → `supabase` 검색이면 **코드·주석·ANON KEY까지** 보인다
- **프록시는 요청을 그대로 대신, BFF는 요청에 맞게 조립** — BFF 자리 둘(Edge Function 150초 / 프론트 서버)
- 판정법 한 줄: Request URL이 `*.supabase.co`면 ❌ / `localhost:3000/api/*`면 ⭕ (**둘 다 200 OK**가 함정)

**실습·과제** — 맛집 조회를 BFF 경유로 바꾸고 **네트워크 탭으로 판정**.

**이걸 할 수 있으면 통과**

- [ ] 서버를 하나 끼웠는데도 로직이 노출되는 경우(프록시)를 설명할 수 있다
- [ ] 브라우저에 내려가는 키를 **공개된 값**으로 취급할 수 있다

## Day 25 · BFF로 CRUD, 소프트 삭제, 그리고 위치 정보

**배우는 것**

- CRUD 프롬프트 **6줄** — 도구·기능(**조회를 목록/상세로 쪼갬**)·저장 위치·검증·**기본값**·**아키텍처**
- 삭제 두 가지: 하드 삭제(+**CASCADE** / No Action) vs **소프트 삭제**(`deleted_at timestamptz`)
- 소프트 삭제는 **자식을 건드리지 않는다** — 대신 모든 조회에 `IS NULL` 조건이 영구히 붙는다
- 위치 두 갈래(주소/우편번호 vs 지도/위치)와 지도 기능 **3종**(지도·지오코딩·**리버스** 지오코딩)
- 네이버 지역 검색 API — `mapx`=**경도**, `mapy`=**위도**(순서 반대) + 소수점 없는 정수

**실습·과제** — BFF로 맛집 등록/목록/상세/수정 + `deleted_at` 컬럼 + Postman으로 지역 검색 호출.

**이걸 할 수 있으면 통과**

- [ ] "조회"를 목록조회·상세조회로 쪼개는 이유를 화면으로 설명할 수 있다
- [ ] `mapx`/`mapy`를 지도 좌표로 바꿀 때 조심할 **두 가지**를 말할 수 있다

## Day 26 · 네이버 검색/지도 API — 무엇을 고를 것인가

**배우는 것**

- 화면 5장에 필요한 API는 **정확히 두 개** — 지역 검색 API · 지도 API
- 지도 API **6종**과 결정적 표기: **JS-API는 동적 지도 하나뿐**, 나머지는 REST-API
- ★ 판서 — **REST-API = 백엔드 / JS-API = 프론트엔드**, 그리고 둘 다 "이미 만들어져 있는 기능"
- 오늘 고른 것은 **동적 지도 + 리버스 지오코딩**, **지오코딩은 ✕**(지역 검색이 좌표를 준다)
- Dynamic Map만 **Web service URL 등록**을 강제한다 — 브라우저에 보이는 키는 **도메인으로 묶어** 보호
- Pencil 증분 디자인과 **Node ID** 핸드오프

**실습·과제** — NCP에서 키 발급 → Postman 요청 테스트 → Pencil 증분 디자인 → PencilMCP 핸드오프.

**이걸 할 수 있으면 통과**

- [ ] JS-API / REST-API 표기 하나로 **키를 어디 둘지**가 정해지는 이유를 설명할 수 있다
- [ ] 핸드오프에 이름 대신 **Node ID**를 쓰는 이유를 말할 수 있다

## Day 27 · 지도·검색 연동 — 컬럼, 환경변수, 왕복 규약

**배우는 것**

- 작업 순서는 **① DB 컬럼 → ② 지도 → ③ 검색** — 저장할 자리부터 만든다
- 추가 컬럼 **`name` · `lat float8` · `lng float8`**, 그리고 **Nullable vs Default**
  (좌표에 `0`은 "모름"이 아니라 **적도**다 → Nullable)
- ★ **`NEXT_PUBLIC_` 한 줄이 비밀/공개의 경계선** — Supabase·검색 키는 금지, 지도 SDK 키는 필수
- `.env.example`(설명서, 커밋 O) / `.env.local`(실값, 커밋 X), **환경변수는 시작 시점에만 읽힌다**
- 화면 왕복 규약 — **무엇을 들고 / 어디로 돌아가 / 어디에 넣는지** 세 가지를 다 적는다

**실습·과제** — 컬럼 추가 → 네이버 지도 연동(핀 고정+지도 이동) → 지역 검색 연동(결과 있음/없음 분기).

**이걸 할 수 있으면 통과**

- [ ] 같은 키인데 접두사가 갈리는 이유를 **누가 호출하는가**로 설명할 수 있다
- [ ] "키를 넣었는데 왜 안 되지?"의 답(**서버 재시작**)을 알고 있다

## Day 28 · 배포 · 도메인 · 상표권 · PWA

**배우는 것**

- 배포는 파이프라인 — **빌드 → 커밋 → 푸쉬 → GitHub → Vercel**, 그리고 **환경변수는 별도 갈래**
- 배포 환경 **4단계의 대가**(도메인4·`.env`4·Supabase4·스토리지4·소셜로그인4·Vercel3) → **1인은 둘로 시작**
- 푸시 전 **두 방향 검사**(내 키 ↔ 저장소 대조 / 시크릿 패턴) · `.gitignore` 정비
- 도메인은 **1년 임대**, `www`와 non-`www` **둘 다 등록**(308 리다이렉트), 자동 부여 주소는 제거
- **상표권 · 디자인권 · 저작권** — 등록 필요 O / O / **X**, 로고 제작 **6단계**
- **PWA 3종** — 홈 화면 설치 · 푸시 알림 · 오프라인 모드

**실습·과제** — 하드코딩 검사 → 커밋·푸시 → Vercel 배포 → 도메인 연결 → 로고 제작 6단계.

**이걸 할 수 있으면 통과**

- [ ] "로컬에선 되는데 배포하면 안 된다"의 1순위 원인을 말할 수 있다
- [ ] **일반명사·지명 단독**으로 브랜드명을 정하면 안 되는 이유를 설명할 수 있다

## Day 29 · 로고와 함께 PWA 배포하기

**배우는 것**

- 유사 상표 검색은 **이름 검색과 다른 검색** — 도형 조건만으로 **국내 2,458건**
- PWA 프롬프트의 4요소: **범위 자르기**(오프라인·푸시알림 제외) · **플랫폼 분기**(iOS엔 설치 API가 없다) · **시스템 UI는 재사용 X** · **변형은 스크립트로**
- `logo.svg` 한 장 → **에셋 16종**(manifest 아이콘 `any`/`maskable`, 파비콘, 스플래시)
- ★ **"너 지금 어떤 브랜치에서 작업하고 있니?"** — `main` 직접 작업은 되돌릴 단위를 없앤다
- 배포는 푸시로 끝나지 않는다 — **하이드레이션 레이스** 버그와 **시크릿 탭** 확인

**실습·과제** — 로고 만들기(6단계) → 로고 다운받기 → PWA 배포(로고·스플래시·파비콘 포함).

**이걸 할 수 있으면 통과**

- [ ] `maskable` 아이콘을 빠뜨리면 무슨 일이 생기는지 설명할 수 있다
- [ ] 배포 후 **실제 기기·처음 방문 상태**에서 확인해야 하는 이유를 말할 수 있다
