## 3. 개념

### 3-1. 게임 루프 — 실시간 게임의 심장

**왜 필요한가** — 앞으로 만들 모든 게임의 뼈대다. WINAPI도, Unity도 결국 이것이다.

```
   ┌───────────────────────────────────────────────────┐
   │  while (running)                                   │
   │                                                    │
   │    ├─ ProcessInput()   "키가 눌렸나?" (기다리지 않음)│
   │    │                                               │
   │    ├─ Update()         "0.016초가 흘렀다.           │
   │    │                    공은 어디로? 충돌했나?"      │
   │    │                                               │
   │    ├─ Render()         "지금 상태를 화면에 그린다"   │
   │    │                                               │
   │    └─ 프레임 제어       "너무 빠르면 잠깐 쉰다"      │
   │                                                    │
   └───────────────────────────────────────────────────┘
```

| 단계 | 하는 일 | 하면 안 되는 일 |
|---|---|---|
| **Input** | 입력 상태를 읽어 변수에 저장 | 여기서 게임 로직 처리 |
| **Update** | 좌표 갱신, 충돌, 상태 변화 | 화면에 그리기 |
| **Render** | 화면에 그리기만 | 상태 변경 |

> **세 단계를 섞지 않는 것이 중요하다.**
> 지금은 사소해 보이지만, Day 39에서 프레임워크를 만들 때 이 분리가 그대로 클래스 구조가 된다.
> Unity의 `Update()` / `LateUpdate()` 도 같은 이유로 나뉘어 있다.

### 3-2. `_kbhit()` — 기다리지 않는 입력 확인

**왜 필요한가** — "키가 눌렸는지"만 확인하고, 안 눌렸으면 바로 지나간다.

```c
#include <conio.h>

if (_kbhit())                    // 눌린 키가 있나? (기다리지 않음)
{
    int key = _getch();          // 있으면 읽는다 (이미 있으니 안 기다림)
    // ... 처리 ...
}
// 없으면 그냥 지나간다
```

```
   _getch() 단독              _kbhit() + _getch()

   [정지] 키 대기...          "키 있나?" → 아니오 → 지나감
      ▼                       "키 있나?" → 아니오 → 지나감
   키 입력                    "키 있나?" → 예 → _getch()로 읽음
      ▼                       "키 있나?" → 아니오 → 지나감
   계속 실행                       ▲
                                   └── 루프가 멈추지 않는다
```

| 함수 | 하는 일 | 기다리나 |
|---|---|:--:|
| `_kbhit()` | 입력 버퍼에 키가 있는지 확인 | **X** |
| `_getch()` | 키를 하나 읽어서 반환 | O (버퍼가 비었을 때) |

### 3-3. 프레임 — 1초에 몇 번 도는가

**왜 필요한가** — 루프를 제어 없이 돌리면 CPU를 100% 먹고, 게임 속도가 통제 불능이 된다.

```
   프레임(frame) = 게임 루프가 한 바퀴 도는 것
   FPS (Frames Per Second) = 1초에 몇 바퀴 도는가

   60 FPS  →  1프레임 = 1/60초 ≈ 16.67ms
   30 FPS  →  1프레임 = 1/30초 ≈ 33.33ms
```

**제어 없이 돌리면**

```c
while (running)
{
    Update();
    Render();
    // 아무 제어 없음
}
```

```
   결과:
   ① CPU 코어 하나가 100%가 된다 (팬이 돈다)
   ② 초당 수십만 번 돈다 → 공이 순간이동한다
   ③ PC 성능에 따라 속도가 완전히 달라진다
```

**`Sleep`으로 제어**

```c
#include <windows.h>

while (running)
{
    Update();
    Render();
    Sleep(16);              // 약 60 FPS (1000ms / 60 ≈ 16.67ms)
}
```

| 목표 FPS | `Sleep` 값 |
|:--:|:--:|
| 60 | 16 |
| 30 | 33 |
| 20 | 50 |
| 10 | 100 |

> ⚠️ **`Sleep(16)`은 정확히 60 FPS가 아니다.**
> - `Sleep`은 "최소 16ms 쉰다"는 뜻이지 정확히 16ms가 아니다 (OS 스케줄러에 달렸다)
> - `Update`와 `Render`에 걸린 시간이 계산에 안 들어갔다
>
> 정확한 제어는 3-5절에서 한다.

### 3-4. 시간 측정 — `clock()`

**왜 필요한가** — FPS를 계산하고, 얼마나 시간이 흘렀는지 알아야 한다.

```c
#include <time.h>

clock_t start = clock();          // 시작 시각 (밀리초 단위)

// ... 작업 ...

clock_t end = clock();
double elapsed = (double)(end - start) / CLOCKS_PER_SEC;   // 초 단위
printf("%.3f초\n", elapsed);
```

| 함수 | 정밀도 | 용도 |
|---|---|---|
| `time(NULL)` | 1초 | 날짜, 긴 경과 시간 |
| **`clock()`** | 약 1ms | **프레임 제어** (오늘) |
| `QueryPerformanceCounter` | 마이크로초 | 정밀 측정 (Day 38) |

```
   CLOCKS_PER_SEC  →  1초에 clock 값이 얼마나 증가하는가
                      Windows에서는 1000 (즉 밀리초 단위)
```

### 3-5. 델타 타임 — PC가 달라도 같은 속도로

**왜 필요한가** — 오늘의 가장 중요한 개념. **Day 38에서 본격적으로 다시 나온다.**

**문제: 프레임마다 고정값으로 움직이면**

```c
ballX += 1;              // 1프레임에 1칸
```

```
   빠른 PC (200 FPS)  →  1초에 200칸 이동
   느린 PC ( 30 FPS)  →  1초에  30칸 이동

   ★ 같은 게임인데 PC마다 속도가 다르다
```

**해결: 흐른 시간만큼 움직인다**

```c
ballX += speed * deltaTime;      // speed = 초당 이동량
```

```
   speed = 60 (초당 60칸)

   200 FPS  →  dt = 0.005초  →  60 × 0.005 = 0.3칸/프레임 × 200 = 60칸/초
    30 FPS  →  dt = 0.033초  →  60 × 0.033 = 2.0칸/프레임 ×  30 = 60칸/초

   ★ 어떤 PC에서도 초당 60칸  ✔
```

**델타 타임 계산**

```c
clock_t prevTime = clock();

while (running)
{
    clock_t now = clock();
    double dt = (double)(now - prevTime) / CLOCKS_PER_SEC;    // 지난 프레임 이후 흐른 시간
    prevTime = now;

    Update(dt);
    Render();
}
```

```
   ┌───────────────────────────────────────────────────┐
   │  now = clock()                                     │
   │  dt  = (now - prevTime) / CLOCKS_PER_SEC           │
   │  prevTime = now          ← 다음 프레임을 위해 갱신  │
   │                                                    │
   │  ballX += speed * dt     ← 흐른 시간만큼 이동       │
   └───────────────────────────────────────────────────┘
```

> ⚠️ **첫 프레임과 긴 멈춤 주의**
>
> ```c
> if (dt > 0.1) dt = 0.1;          // 클램프 (최대 0.1초)
> ```
>
> 창을 드래그하거나 디버거에서 멈췄다가 재개하면 `dt`가 몇 초가 될 수 있다.
> 그러면 공이 화면 밖으로 순간이동한다. **상한을 둔다.**

### 3-6. 정확한 프레임 제어

**왜 필요한가** — `Sleep(16)` 만으로는 작업 시간이 반영되지 않는다.

```
   [Sleep(16) 고정]

   프레임 1:  작업 5ms  + Sleep 16ms = 21ms   →  47 FPS
   프레임 2:  작업 12ms + Sleep 16ms = 28ms   →  35 FPS
                ▲ 작업 시간만큼 느려진다

   [작업 시간을 뺀 만큼만 Sleep]

   목표 16.67ms
   프레임 1:  작업 5ms  → Sleep(11) → 16ms   →  60 FPS  ✔
   프레임 2:  작업 12ms → Sleep(4)  → 16ms   →  60 FPS  ✔
```

```c
const double TARGET_FRAME_TIME = 1.0 / 60.0;      // 0.01667초

clock_t frameStart = clock();

Update(dt);
Render();

// 이번 프레임에 걸린 시간
double worked = (double)(clock() - frameStart) / CLOCKS_PER_SEC;

// 남은 시간만큼만 쉰다
double remain = TARGET_FRAME_TIME - worked;
if (remain > 0)
    Sleep((DWORD)(remain * 1000));
```

### 3-7. FPS 측정

**왜 필요한가** — 게임이 목표 프레임으로 도는지 확인해야 최적화 여부를 판단할 수 있다.

```c
int    frameCount = 0;
double fpsTimer   = 0.0;
double currentFps = 0.0;

// 매 프레임
frameCount++;
fpsTimer += dt;

if (fpsTimer >= 1.0)              // 1초마다
{
    currentFps = frameCount / fpsTimer;
    frameCount = 0;
    fpsTimer   = 0.0;
}
```

```
   1초 동안 몇 프레임이 지났는지 세고, 1초마다 갱신한다

   ★ 매 프레임 1/dt 로 계산하면 값이 심하게 요동친다
     1초 평균이 훨씬 안정적이다
```

### Step 1 — 멈추지 않는 루프

```c
#include <stdio.h>
#include <conio.h>
#include <windows.h>

int main(void)
{
    int running = 1;
    int counter = 0;

    while (running)
    {
        // ── Input ──
        if (_kbhit())                       // ★ 기다리지 않는다
        {
            int key = _getch();
            if (key == 27) running = 0;     // ESC
        }

        // ── Update ──
        counter++;

        // ── Render ──
        printf("\r카운터: %d          ", counter);

        // ── 프레임 제어 ──
        Sleep(16);
    }

    printf("\n종료합니다.\n");
    return 0;
}
```

**✅ 여기까지 실행하면** — **아무 키도 안 눌러도 숫자가 계속 올라간다.**
ESC를 누르면 종료된다.

> `\r`(캐리지 리턴)은 커서를 줄 맨 앞으로 보낸다. 같은 줄에 덮어쓰기 위해 쓴다.

### Step 2 — `Sleep`을 빼 보기 (문제 확인)

```c
        // Sleep(16);          // ← 주석 처리
```

**✅ 여기까지 실행하면**
- 숫자가 **너무 빨리 올라가 읽을 수 없다**
- 작업 관리자에서 CPU 사용률이 한 코어 기준 **100%**가 된다
- 노트북이면 팬이 돌기 시작한다

> 확인했으면 `Sleep(16)`을 되살린다.
> **이 실험을 반드시 해 본다.** 프레임 제어가 왜 필요한지 몸으로 알아야 한다.

### Step 3 — 시간 측정과 델타 타임

```c
#include <time.h>

int main(void)
{
    int running = 1;

    clock_t prevTime  = clock();
    double  totalTime = 0.0;

    while (running)
    {
        // ── 시간 계산 ──
        clock_t now = clock();
        double dt = (double)(now - prevTime) / CLOCKS_PER_SEC;
        prevTime = now;

        if (dt > 0.1) dt = 0.1;             // ★ 클램프

        totalTime += dt;

        // ── Input ──
        if (_kbhit())
        {
            int key = _getch();
            if (key == 27) running = 0;
        }

        // ── Render ──
        printf("\r경과 %6.2f초   dt %.4f초        ", totalTime, dt);

        Sleep(16);
    }

    return 0;
}
```

**✅ 여기까지 실행하면** — 경과 시간이 실제 시간과 일치하고, `dt`가 0.016 근처로 나온다.

```
경과   3.42초   dt 0.0160초
```

### Step 4 — FPS 측정

```c
    int    frameCount = 0;
    double fpsTimer   = 0.0;
    double currentFps = 0.0;
    long   totalFrames = 0;

    while (running)
    {
        // ... 시간 계산 ...

        frameCount++;
        totalFrames++;
        fpsTimer += dt;

        if (fpsTimer >= 1.0)
        {
            currentFps = frameCount / fpsTimer;
            frameCount = 0;
            fpsTimer   = 0.0;
        }

        // ── Render ──
        printf("\r경과 %6.2f초   프레임 %5ld   FPS %5.1f     ",
               totalTime, totalFrames, currentFps);

        Sleep(16);
    }
```

**✅ 여기까지 실행하면** — FPS가 표시된다. `Sleep(16)`이면 약 **55~60** 사이로 나온다.

> 60이 안 나오는 이유가 3-6절의 문제다. 다음 Step에서 고친다.

### Step 5 — 정확한 프레임 제어

```c
    const double TARGET_FPS = 60.0;
    const double TARGET_FRAME_TIME = 1.0 / TARGET_FPS;

    while (running)
    {
        clock_t frameStart = clock();

        // ... 시간 계산, Input, Update, Render ...

        // ── 프레임 제어 ──
        double worked = (double)(clock() - frameStart) / CLOCKS_PER_SEC;
        double remain = TARGET_FRAME_TIME - worked;

        if (remain > 0)
            Sleep((DWORD)(remain * 1000));
    }
```

**✅ 여기까지 실행하면** — FPS가 **59~61** 사이로 안정된다.

### Step 6 — 델타 타임 검증 (핵심 실험)

**고정값 이동 vs 델타 타임 이동을 나란히 비교한다.**

```c
    double fixedX = 0.0;         // 프레임마다 고정값
    double deltaX = 0.0;         // 델타 타임 기반

    while (running)
    {
        // ... dt 계산 ...

        fixedX += 1.0;               // 1프레임에 1칸
        deltaX += 60.0 * dt;         // 초당 60칸

        printf("\r고정 %8.1f   델타 %8.1f   FPS %5.1f   ",
               fixedX, deltaX, currentFps);

        // 프레임 제어
    }
```

**목표 FPS를 바꿔 가며 5초 동안 실행하고 값을 비교한다.**

| 목표 FPS | 5초 후 `fixedX` | 5초 후 `deltaX` |
|:--:|:--:|:--:|
| 60 | 약 300 | **약 300** |
| 30 | 약 150 | **약 300** |
| 120 | 약 600 | **약 300** |

**✅ 여기까지 실행하면** — `deltaX`는 FPS와 무관하게 항상 300 근처, `fixedX`는 FPS에 비례해 달라진다.

> **이것이 델타 타임을 쓰는 이유의 전부다.**
> 이 실험을 직접 해 보지 않으면 Day 38에서 또 헤맨다.

### Step 7 — 목표 FPS 조절

```c
        if (_kbhit())
        {
            int key = _getch();

            if (key == 27) running = 0;
            else if (key == '+' || key == '=') targetFps += 10;
            else if (key == '-' || key == '_') targetFps -= 10;

            if (targetFps < 10)  targetFps = 10;
            if (targetFps > 240) targetFps = 240;
        }
```

**✅ 여기까지 실행하면** — `+`/`-`로 목표 FPS를 바꿀 수 있고, `deltaX`는 여전히 일정하다.

### Step 8 — 흐르는 별 (첫 실시간 화면)

```c
#define STAR_COUNT  30
#define SCREEN_W    46
#define SCREEN_H    12

typedef struct
{
    double x, y;
    double speed;
} Star;

Star g_stars[STAR_COUNT];

void InitStars(void)
{
    for (int i = 0; i < STAR_COUNT; i++)
    {
        g_stars[i].x     = rand() % SCREEN_W;
        g_stars[i].y     = rand() % SCREEN_H;
        g_stars[i].speed = 3.0 + (rand() % 100) / 10.0;   // 초당 3~13칸
    }
}

void UpdateStars(double dt)
{
    for (int i = 0; i < STAR_COUNT; i++)
    {
        g_stars[i].x += g_stars[i].speed * dt;            // ★ 델타 타임

        if (g_stars[i].x >= SCREEN_W)                     // 화면 밖 → 반대편
        {
            g_stars[i].x = 0;
            g_stars[i].y = rand() % SCREEN_H;
        }
    }
}

void RenderStars(void)
{
    char screen[SCREEN_H][SCREEN_W + 1];

    // 배경 지우기
    for (int y = 0; y < SCREEN_H; y++)
    {
        for (int x = 0; x < SCREEN_W; x++)
            screen[y][x] = ' ';
        screen[y][SCREEN_W] = '\0';
    }

    // 별 찍기
    for (int i = 0; i < STAR_COUNT; i++)
    {
        int sx = (int)g_stars[i].x;
        int sy = (int)g_stars[i].y;

        if (sx >= 0 && sx < SCREEN_W && sy >= 0 && sy < SCREEN_H)
            screen[sy][sx] = (g_stars[i].speed > 8.0) ? '*' : '.';
    }

    // 한 번에 출력
    GotoXY(0, 6);                        // Day 15의 함수
    for (int y = 0; y < SCREEN_H; y++)
        printf("   %s\n", screen[y]);
}
```

> **화면 배열에 먼저 그리고, 마지막에 한 번 출력한다.**
> Day 15에서 본 그 방식이다. 이것이 **더블버퍼링의 콘솔 버전**이고,
> **Day 37에서 WINAPI로 같은 일을 한다.**

**✅ 여기까지 실행하면** — 1절의 완성 화면대로 별이 흐른다.
빠른 별은 `*`, 느린 별은 `.` 으로 보인다.

### Step 9 — 게임 루프 골격 정리

```c
// ─── 전역 상태 ───
int    g_running   = 1;
double g_totalTime = 0.0;
double g_fps       = 0.0;

// ─── 세 단계 ───
void ProcessInput(void)
{
    if (_kbhit())
    {
        int key = _getch();
        if (key == 27) g_running = 0;
    }
}

void Update(double dt)
{
    g_totalTime += dt;
    UpdateStars(dt);
}

void Render(void)
{
    GotoXY(0, 0);
    printf("╔═══════════════════════════════════════════╗\n");
    printf("║          GAME LOOP  TEST                  ║\n");
    printf("╚═══════════════════════════════════════════╝\n\n");
    printf("   경과 시간   %02d:%05.2f     \n",
           (int)g_totalTime / 60, fmod(g_totalTime, 60.0));
    printf("   FPS         %5.1f          \n\n", g_fps);

    RenderStars();
}

int main(void)
{
    SetupConsole();          // Day 15
    InitStars();

    clock_t prevTime = clock();

    while (g_running)
    {
        clock_t frameStart = clock();

        double dt = (double)(frameStart - prevTime) / CLOCKS_PER_SEC;
        prevTime = frameStart;
        if (dt > 0.1) dt = 0.1;

        ProcessInput();
        Update(dt);
        Render();

        UpdateFps(dt);
        LimitFrameRate(frameStart);
    }

    return 0;
}
```

**✅ 여기까지 실행하면** — `main`이 게임 루프 세 단계로 깔끔하게 정리된다.

> **이 골격을 잘 봐 둔다.**
>
> | 언제 | 어떻게 바뀌나 |
> |---|---|
> | Day 22~25 | 이 골격 위에 공·패들·블록을 얹는다 |
> | Day 38 | `PeekMessage`로 바꾸고 WINAPI 위에 얹는다 |
> | Day 39 | `Core` 클래스의 `Init/Update/Render/Release`가 된다 |
> | Day 72 | Unity의 `Update()` — 엔진이 이 루프를 대신 돌려준다 |
>
> **형태만 달라질 뿐 같은 것이다.**

## 6. 자주 막히는 곳

| 증상 | 원인 | 해결 |
|---|---|---|
| 루프가 멈춰 있음 | `_kbhit()` 없이 `_getch()` 직접 호출 | `if (_kbhit())` 로 감싸기 |
| CPU 100% | 프레임 제어 없음 | `Sleep` 추가 |
| FPS가 목표보다 낮음 | 작업 시간 미반영 | 남은 시간만큼만 `Sleep` |
| 속도가 PC마다 다름 | 고정값 이동 | `speed * dt` 로 |
| 창 드래그 후 순간이동 | `dt`가 커짐 | `if (dt > 0.1) dt = 0.1;` |
| `dt`가 0 | `clock()` 해상도 한계 | 정상. 다음 프레임에 누적된다 |
| FPS 표시가 요동침 | 매 프레임 `1/dt` 로 계산 | 1초 평균으로 |
| 화면이 심하게 깜빡임 | 부분 출력 반복 | 화면 배열에 그린 뒤 한 번 출력 |
| `Sleep` 관련 오류 | `<windows.h>` 누락 | 포함 |
| `clock` 관련 오류 | `<time.h>` 누락 | 포함 |

## 7. 정리

### 오늘 배운 것

| 개념 | 한 줄 요약 |
|---|---|
| **게임 루프** | Input → Update → Render를 초당 수십 번 반복 |
| 세 단계 분리 | Update는 그리지 않고, Render는 바꾸지 않는다 |
| `_kbhit()` | 기다리지 않는 입력 확인. 게임 루프의 필수 조건 |
| 프레임 / FPS | 1초에 루프가 도는 횟수 |
| 프레임 제어 | 작업 시간을 뺀 나머지만 `Sleep` |
| **델타 타임** | `speed * dt` — PC 성능과 무관하게 같은 속도 |
| dt 클램프 | 창 드래그 등으로 dt가 튀는 것을 막는다 |
| 화면 버퍼 | 배열에 그린 뒤 한 번 출력 → 깜빡임 감소 |
