## 이 문서들을 읽는 법

각 일차 문서는 **6개 블록의 고정 구조**를 갖습니다. 어느 날짜를 펴도 같은 자리에 같은 종류의 내용이 있습니다.

| 블록 | 내용 | 이렇게 쓰세요 |
|---|---|---|
| ① 학습 목표 | 오늘을 마치면 할 수 있게 되는 것 | 수업 전에 읽고, 수업 후에 다시 읽어 체크 |
| ② 왜 필요한가 | 이 개념이 없으면 무엇이 안 되는지 | 이해가 안 갈 때 여기로 돌아오세요 |
| ③ 개념 설명 | 용어와 원리 | 표와 그림 위주. 용어는 처음 나올 때 풀어 씀 |
| ④ 단계별 실습 | Step 1 → N, 코드 + 실행 결과 | **직접 타이핑**하세요. 복사만 하면 안 늡니다 |
| ⑤ 자주 하는 실수 | 에러 메시지 원문 + 원인 + 해결 | 에러가 났을 때 Ctrl+F로 검색 |
| ⑥ 확인 문제 | 3문항, 답은 접혀 있음 | 답을 보기 전에 반드시 먼저 풀어 보세요 |

**코드 블록 규칙** — 실습 코드는 전부 **복사해서 붙여넣으면 그대로 실행되는 완성본**입니다.
터미널 블록은 `$` 로 시작하는 줄이 입력, 그 아래가 실제 출력입니다. `실행 결과:` 아래 블록은 그 코드를 실행했을 때 실제로 나오는 출력입니다.

> **이 단원의 실행 환경과 재현성 주의** — 문서의 실행 결과는 전부
> **Windows 11 + WSL2(Ubuntu 22.04 LTS) + Docker Desktop(Engine 27.x, WSL 통합)** 기준의 실제 출력입니다.
> 인프라 도구의 출력에는 **환경마다·실행마다 달라지는 값**이 섞여 있습니다 — 커밋/이미지 해시,
> 컨테이너 ID, 타임스탬프, 다운로드 속도, 워크플로 실행 번호가 그렇습니다.
> 이런 값이 문서와 다른 것은 **정상**입니다. 반면 **명령의 성공/실패(종료 코드), 테스트 통과 여부,
> API 응답 계약, 이미지 크기의 자릿수 급**은 문서와 같아야 정상입니다.
> 어느 쪽 값인지 헷갈리면 각 문서의 ⑤ 블록을 먼저 보세요.

## 이 단원을 마치면

- [ ] 팀 저장소에서 **브랜치 전략과 PR 리뷰로 협업**할 수 있다
- [ ] Linux 서버에 접속해 **서비스를 배포하고 프로세스·로그를 관리**할 수 있다
- [ ] 서비스를 **Docker 이미지로 만들고 Compose로 다중 컨테이너 구성**을 운영할 수 있다
- [ ] GitHub Actions로 **테스트→빌드→배포가 자동으로 도는 CI/CD**를 만들 수 있다
- [ ] DVC·Airflow·모니터링으로 **데이터/모델 버전 관리와 재학습 파이프라인**을 구성할 수 있다

**단원 완료 조건 (MP4 제출 기준)**

- [ ] 새 서버에서 clone → `docker compose up` 으로 서비스가 뜬다
- [ ] PR에 테스트가 강제되고 main 병합이 자동 배포로 이어진다
- [ ] 시크릿이 저장소·이미지 어디에도 없다
- [ ] 모델을 새 버전으로 교체하고 롤백하는 절차가 문서와 함께 동작한다

**단원 산출물** MP3 저장소의 운영화 완성본 (Compose + CI/CD + 모니터링) → 포트폴리오 저장소 4번 완성

```
mlops-mp3 (Day 105의 그 저장소)
  ├── W22  PR 워크플로의 연습장 (브랜치 보호는 W26에서 강제로)

  └── W28  🏁 MP4 = 이 모든 것의 완성본
```

| **Docker Compose v2** | 다중 컨테이너 구성 | [Day 121](day-121.md) |
| **nginx** (컨테이너) | 리버스 프록시 | [Day 124](day-124.md) |
| **GitHub Actions** | CI/CD (무료 티어로 충분) | [Day 126](day-126.md) |
| **DVC** | 데이터·모델 버전 관리 | [Day 131](day-131.md) |
| **MLflow Registry** | 모델 승격·교체 (MLflow는 Day 067에서 도입) | [Day 132](day-132.md) |

> 실제 클라우드 인스턴스가 있다면 같은 명령이 그대로 적용됩니다 — 최종 프로젝트(W29~)에서는
> 팀별 클라우드 인스턴스로 옮겨 갑니다.

## 자주 나오는 질문

| 질문 | 답 |
|---|---|
| Kubernetes는 왜 안 배우나요? | 컨테이너·CI/CD가 몸에 붙기 전의 K8s는 암기가 됩니다. 개념과 "언제 필요한가"만 [Day 135](day-135.md)에서 다루고, 실전은 취업 후 또는 심화 과정 영역입니다. |
| 클라우드 계정(AWS 등)이 필요한가요? | 아니요. 이 단원은 WSL2 + GitHub 무료 계정으로 전 구간 재현됩니다. 클라우드가 있으면 좋은 지점([Day 129](day-129.md) CD)에는 두 경로를 모두 적어 두었습니다. |

| CI가 로컬에선 되는데 Actions에서 깨져요 | 대부분 환경 차이(버전·경로·환경변수)입니다. Dockerfile 기준으로 CI를 돌리면 재현됩니다 — [Day 128](day-128.md)에서 그 구조로 갑니다. |
| 드리프트 감지는 꼭 해야 하나요? | 모델은 배포 순간부터 낡기 시작합니다. 최소한 입력 분포 로그는 남겨야 "언제 재학습할지"를 답할 수 있습니다 ([Day 134](day-134.md)). |
| Docker Desktop 말고 Docker Engine을 직접 깔면 안 되나요? | 됩니다 — WSL2 Ubuntu 안에 docker-ce를 설치해도 이 단원의 모든 명령이 동일하게 동작합니다. 문서는 W07부터 써 온 Docker Desktop 기준으로 통일했습니다. |
