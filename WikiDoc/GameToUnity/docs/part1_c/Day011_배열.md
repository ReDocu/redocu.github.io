## 2. 막히는 상황

지난주 게임에서 아이템 3종을 이렇게 관리했다.

```c
int hasKey     = 0;
int hasNote    = 0;
int hasLantern = 0;
```

이제 아이템을 10종으로 늘려 보자.

```c
int hasKey = 0, hasNote = 0, hasLantern = 0, hasRope = 0, hasCoin = 0,
    hasMap = 0, hasGem = 0, hasBook = 0, hasKnife = 0, hasPotion = 0;
```

그리고 "가진 아이템 개수"를 세려면?

```c
int count = 0;
if (hasKey) count++;
if (hasNote) count++;
if (hasLantern) count++;
// ... 10줄 ...
```

**반복문을 쓸 수가 없다.** 변수 이름이 전부 다르기 때문이다.

```
   지금:   hasKey  hasNote  hasLantern  hasRope  ...
             ▲       ▲          ▲          ▲
             └───────┴──────────┴──────────┘
             전부 따로. 반복문으로 묶을 방법이 없다

   필요:   items[0]  items[1]  items[2]  items[3]  ...
             ▲                                 ▲
             └────── 번호로 접근 ───────────────┘
             for (i = 0; i < 10; i++) 로 한 번에 처리 가능
```

> **같은 종류를 번호로 접근할 수 있게 묶는 방법이 필요하다.** → **배열**

## 3. 개념

### 3-1. 배열 — 같은 자료형을 줄 세우기

**왜 필요한가** — 반복문으로 한 번에 처리하려면 이름이 아니라 **번호**로 접근할 수 있어야 한다.

```c
int items[5];                          // int 5개짜리 배열
int items[5] = { 1, 2, 3, 4, 5 };      // 선언 + 초기화
int items[5] = { 0 };                  // 전부 0으로 초기화 (자주 쓴다)
int items[]  = { 1, 2, 3 };            // 크기 생략 → 자동으로 3
```

```
   int items[5];

   items[0]  items[1]  items[2]  items[3]  items[4]
   ┌───────┬───────┬───────┬───────┬───────┐
   │       │       │       │       │       │
   └───────┴───────┴───────┴───────┴───────┘
      4B      4B      4B      4B      4B      = 20바이트

   ★ 메모리에 빈틈 없이 연속으로 붙어 있다
   ★ 인덱스는 0부터 시작한다
```

### 3-2. ⚠️ 인덱스는 0부터 — 가장 흔한 실수

**왜 필요한가** — 이 하나로 하루를 날릴 수 있다.

```c
int items[5];        // 만들어진 칸: items[0] ~ items[4]

items[0] = 10;       // ✔ 첫 번째
items[4] = 50;       // ✔ 다섯 번째 (마지막)
items[5] = 60;       // ✘ 존재하지 않는 칸!
```

```
   "5개짜리 배열"의 실제 모습

   번호:      0     1     2     3     4      ← 프로그램이 쓰는 번호
   순서:     첫째  둘째  셋째  넷째  다섯째   ← 사람이 세는 순서
           ┌─────┬─────┬─────┬─────┬─────┐
           │     │     │     │     │     │  ✘ [5]는 여기 없다
           └─────┴─────┴─────┴─────┴─────┘

   ★ 마지막 인덱스 = 크기 - 1
```

**순회할 때의 조건**

```c
for (int i = 0; i < 5; i++)     // ✔  i = 0,1,2,3,4
for (int i = 0; i <= 5; i++)    // ✘  i = 0,1,2,3,4,5  ← 마지막에 범위 초과!
```

> `<` 인지 `<=` 인지 헷갈리면 **"0부터 시작하면 `<`"** 로 외운다.

### 3-3. 배열 범위 초과 — 무슨 일이 일어나나

**왜 필요한가** — C는 범위를 검사해 주지 않는다. 조용히 남의 메모리를 건드린다.

```c
int items[5] = { 0 };
int hp = 100;

items[5] = 999;              // ✘ 범위 밖. 컴파일도 되고 실행도 된다
printf("%d\n", hp);          // 999가 나올 수도 있다!
```

```
   메모리 배치 (실제 배치는 컴파일러마다 다름)

   items[0] items[1] items[2] items[3] items[4]   hp
   ┌──────┬──────┬──────┬──────┬──────┬────────┐
   │  0   │  0   │  0   │  0   │  0   │  100   │
   └──────┴──────┴──────┴──────┴──────┴────────┘
                                        ▲
                            items[5] 는 여기를 가리킨다
                            → hp가 망가진다
```

| 증상 | 원인 |
|---|---|
| 관계없는 변수 값이 갑자기 바뀜 | 배열 범위 초과 쓰기 |
| 이상한 값이 읽힘 | 배열 범위 초과 읽기 |
| 원인 불명의 크래시 | 중요한 메모리를 덮어씀 |

> **이런 버그는 증상이 나타나는 곳과 원인이 있는 곳이 다르다.** 그래서 찾기 어렵다.
> 예방이 유일한 대책이다. **인덱스를 쓸 때마다 범위를 확인하는 습관**을 들인다.

```c
if (index >= 0 && index < ITEM_MAX)     // ★ 항상 이렇게
    items[index] = value;
```

### 3-4. 배열 크기 관리

**왜 필요한가** — 크기를 여기저기 숫자로 박아 두면 크기를 바꿀 때 반드시 빠뜨린다.

```c
#define ITEM_MAX 5              // ★ 한 곳에서 관리

int items[ITEM_MAX] = { 0 };

for (int i = 0; i < ITEM_MAX; i++)      // 여기도 상수 사용
    printf("%d ", items[i]);
```

**`sizeof`로 크기 구하기**

```c
int items[5];
int count = sizeof(items) / sizeof(items[0]);      // 20 / 4 = 5
```

```
   sizeof(items)      → 배열 전체 크기 (20바이트)
   sizeof(items[0])   → 요소 하나 크기 (4바이트)
   나누면             → 요소 개수 (5)
```

> ⚠️ **이 방법은 함수 안에서는 안 통한다.** 배열을 함수에 넘기면 크기 정보가 사라진다.
> (이유는 Day 18 포인터에서 밝혀진다) **함수에는 크기도 같이 넘긴다.**
>
> ```c
> void PrintItems(int arr[], int size)      // size를 따로 받는다
> ```

### 3-5. 배열과 반복문 — 기본 패턴 5종

**왜 필요한가** — 앞으로 나올 배열 코드의 90%가 이 다섯 가지 형태다.

```c
#define ITEM_MAX 5
int items[ITEM_MAX] = { 10, 30, 20, 50, 40 };
```

**① 전체 출력**

```c
for (int i = 0; i < ITEM_MAX; i++)
    printf("[%d] %d\n", i + 1, items[i]);       // 화면에는 1부터 보여준다
```

**② 합계 / 개수**

```c
int sum = 0, count = 0;
for (int i = 0; i < ITEM_MAX; i++)
{
    sum += items[i];
    if (items[i] != 0) count++;
}
```

**③ 최대 / 최소**

```c
int max = items[0];                              // ★ 첫 요소로 시작
for (int i = 1; i < ITEM_MAX; i++)               // ★ 1부터
    if (items[i] > max) max = items[i];
```

> `max = 0`으로 시작하면 **전부 음수일 때 답이 틀린다.** 첫 요소로 시작하는 것이 안전하다.

**④ 검색 — 찾으면 인덱스, 없으면 -1**

```c
int FindItem(int arr[], int size, int target)
{
    for (int i = 0; i < size; i++)
        if (arr[i] == target)
            return i;                            // 찾았다
    return -1;                                   // 없다 (관례)
}
```

**⑤ 빈 칸 찾기 — 삽입 위치**

```c
int FindEmpty(int arr[], int size)
{
    for (int i = 0; i < size; i++)
        if (arr[i] == 0)
            return i;
    return -1;                                   // 가득 참
}
```

> **패턴 ④⑤는 Day 52의 오브젝트 풀링에서 그대로 다시 나온다.**
> "비활성 중 첫 칸을 찾아 켠다"가 정확히 패턴 ⑤다.

### 3-6. 문자 배열과 문자열

**왜 필요한가** — C에는 문자열 자료형이 없다. 문자열은 `char` 배열이다.

```c
char name[10] = "용사";
```

```
   char name[10] = "용사";

   [0]  [1]  [2]  [3]  [4] ... [9]
   ┌────┬────┬────┬────┬────┬────┐
   │ 용 │ 사 │ \0 │    │    │    │
   └────┴────┴────┴────┴────┴────┘
              ▲
              └── 널 문자(\0). "여기서 문자열이 끝난다"는 표시

   ★ '\0' 자리가 반드시 필요하다.
     5글자를 담으려면 char[6] 이상이어야 한다.
```

**널 문자가 없으면**

```c
char bad[3] = { 'a', 'b', 'c' };      // \0 없음
printf("%s\n", bad);                  // abc + 쓰레기값이 줄줄이 출력된다
```

**문자열 함수** (`<string.h>`)

| 함수 | 하는 일 |
|---|---|
| `strlen(s)` | 길이 (`\0` 제외) |
| `strcpy_s(dst, size, src)` | 복사 |
| `strcmp(a, b)` | 비교 (같으면 0) |
| `strcat_s(dst, size, src)` | 이어 붙이기 |

```c
char a[20] = "용사";
char b[20];

strcpy_s(b, sizeof(b), a);            // 복사
if (strcmp(a, b) == 0)                // 비교 — == 로는 비교 안 된다!
    printf("같다\n");
```

> ⚠️ **문자열은 `==`로 비교할 수 없다.** `if (a == b)`는 주소를 비교하는 것이라 늘 거짓이다.
> **`strcmp`를 쓴다.** (왜 주소인지는 Day 18)

### 3-7. 문자열 배열 — 이름 목록

**왜 필요한가** — Day 9에서 쓴 `roomNames[room]`이 이것이다.

```c
const char* itemNames[5] = {
    "(비어 있음)", "녹슨 열쇠", "찢어진 쪽지", "손전등", "황금 동전"
};

printf("%s\n", itemNames[2]);         // 찢어진 쪽지
```

```
   itemNames[0] ──▶ "(비어 있음)"
   itemNames[1] ──▶ "녹슨 열쇠"
   itemNames[2] ──▶ "찢어진 쪽지"      ← 숫자를 이름으로 바꾸는 룩업 테이블
   itemNames[3] ──▶ "손전등"
   itemNames[4] ──▶ "황금 동전"
```

**이 방식이 왜 좋은가**

```c
// if 방식 — 아이템이 늘면 코드가 늘어난다
if (id == 1) printf("녹슨 열쇠");
else if (id == 2) printf("찢어진 쪽지");
else if (id == 3) printf("손전등");

// 배열 방식 — 아이템이 늘어도 코드는 그대로
printf("%s", itemNames[id]);
```

## 4. 따라 만들기

새 프로젝트 `03_maze` 를 만들고, 오늘은 그 안에 인벤토리부터 만든다.

### Step 1 — 배열 선언과 출력

```c
#include <stdio.h>

#define ITEM_MAX 5

int main(void)
{
    int inventory[ITEM_MAX] = { 0 };        // 0 = 빈 칸

    printf("=================================\n");
    printf("        가방\n");
    printf("=================================\n");

    for (int i = 0; i < ITEM_MAX; i++)
        printf("  [%d] %d\n", i + 1, inventory[i]);

    printf("=================================\n");

    return 0;
}
```

**✅ 여기까지 실행하면** — `[1] 0` 부터 `[5] 0` 까지 다섯 줄이 나온다.

### Step 2 — 아이템 이름 붙이기

```c
#define ITEM_COUNT 5

const char* g_itemNames[ITEM_COUNT] = {
    "(비어 있음)", "녹슨 열쇠", "찢어진 쪽지", "손전등", "황금 동전"
};
```

```c
    for (int i = 0; i < ITEM_MAX; i++)
        printf("  [%d] %s\n", i + 1, g_itemNames[inventory[i]]);   // ← 수정
```

```
   inventory[i] 가 2 라면
        ▼
   g_itemNames[2]  →  "찢어진 쪽지"
```

**✅ 여기까지 실행하면** — 숫자 대신 `(비어 있음)` 이 다섯 줄 출력된다.

### Step 3 — 아이템 개수 세기

```c
int CountItems(int inv[], int size)
{
    int count = 0;
    for (int i = 0; i < size; i++)
        if (inv[i] != 0)
            count++;
    return count;
}
```

```c
    printf("        가방 (%d / %d)\n", CountItems(inventory, ITEM_MAX), ITEM_MAX);
```

**✅ 여기까지 실행하면** — 제목에 `가방 (0 / 5)` 가 표시된다. `inventory`를 `{ 1, 2, 0, 0, 0 }`으로
바꿔 보면 `(2 / 5)`로 바뀐다.

### Step 4 — 빈 칸 찾아 줍기 (패턴 ⑤)

```c
int FindEmptySlot(int inv[], int size)
{
    for (int i = 0; i < size; i++)
        if (inv[i] == 0)
            return i;
    return -1;                          // 가득 참
}

// 성공하면 1, 실패하면 0
int AddItem(int inv[], int size, int itemId)
{
    int slot = FindEmptySlot(inv, size);

    if (slot == -1)
    {
        printf("\n가방이 가득 찼다!\n");
        return 0;
    }

    inv[slot] = itemId;
    printf("\n%s(을)를 손에 넣었다!  [%d번 칸]\n", g_itemNames[itemId], slot + 1);
    return 1;
}
```

> 여기서 `inv[]`에 대입한 값이 **함수 밖 `inventory`에도 반영된다.**
> Day 4의 "값 전달"과 다른 결과다. **배열은 이름만 넘겨도 원본이 바뀐다.**
> 이유는 Day 18에서 밝혀진다. 지금은 "배열은 원본이 바뀐다"만 기억한다.

**✅ 여기까지 실행하면** — 아이템을 주우면 빈 칸에 들어가고, 5개를 채우면 "가득 찼다"가 뜬다.

### Step 5 — 버리기와 검색 (패턴 ④)

```c
int RemoveItem(int inv[], int size, int slot)
{
    if (slot < 0 || slot >= size)              // ★ 범위 검사
    {
        printf("\n그런 칸은 없다.\n");
        return 0;
    }
    if (inv[slot] == 0)
    {
        printf("\n그 칸은 비어 있다.\n");
        return 0;
    }

    printf("\n%s(을)를 버렸다.\n", g_itemNames[inv[slot]]);
    inv[slot] = 0;
    return 1;
}

int FindItem(int inv[], int size, int itemId)
{
    for (int i = 0; i < size; i++)
        if (inv[i] == itemId)
            return i;
    return -1;
}
```

**✅ 여기까지 실행하면** — 아이템을 버리면 그 칸이 `(비어 있음)`으로 바뀌고, 검색하면 몇 번 칸인지 알려준다.

### Step 6 — 메뉴 루프로 통합

```c
    int running = 1;

    while (running)
    {
        PrintInventory(inventory, ITEM_MAX);

        printf("\n  1. 아이템 줍기\n");
        printf("  2. 아이템 버리기\n");
        printf("  3. 아이템 검색\n");
        printf("  0. 나가기\n");

        int choice = ReadInt("선택", 0, 3);      // Day 8의 함수 재사용

        switch (choice)
        {
        case 0: running = 0; break;
        case 1:
            {
                int id = ReadInt("주울 아이템 번호", 1, ITEM_COUNT - 1);
                AddItem(inventory, ITEM_MAX, id);
            }
            break;
        case 2:
            {
                int slot = ReadInt("버릴 칸 번호", 1, ITEM_MAX);
                RemoveItem(inventory, ITEM_MAX, slot - 1);      // ★ -1 주의
            }
            break;
        case 3:
            {
                int id = ReadInt("찾을 아이템 번호", 1, ITEM_COUNT - 1);
                int slot = FindItem(inventory, ITEM_MAX, id);
                if (slot >= 0)
                    printf("\n찾았다!  [%d] %s\n", slot + 1, g_itemNames[id]);
                else
                    printf("\n가방에 없다.\n");
            }
            break;
        }
    }
```

> `slot - 1` — **화면은 1부터, 배열은 0부터.** 이 변환을 빠뜨리면 한 칸씩 어긋난다.
> 변환은 **입출력 경계에서 딱 한 번**만 한다.

**✅ 여기까지 실행하면** — 1절의 완성 화면대로 인벤토리를 다룰 수 있다.

### Step 7 — 범위 초과 실험 (직접 확인)

```c
    int guard = 12345;                          // 배열 바로 뒤에 둔다
    printf("실험 전  guard = %d\n", guard);

    inventory[ITEM_MAX] = 999;                  // ✘ 일부러 범위 밖

    printf("실험 후  guard = %d\n", guard);
```

**✅ 여기까지 실행하면** — `guard` 값이 바뀌거나(999), 그대로이거나, 프로그램이 죽는다.
**셋 중 무엇이 나와도 정상이다.** 그게 "정의되지 않은 동작"이라는 뜻이다.

## 5. 실행 결과

**정상이라면 이렇게 보인다.**

```
=================================
        가방 (2 / 5)
=================================
  [1] 녹슨 열쇠
  [2] 찢어진 쪽지
  [3] (비어 있음)
  [4] (비어 있음)
  [5] (비어 있음)
=================================

  1. 아이템 줍기
  2. 아이템 버리기
  3. 아이템 검색
  0. 나가기

선택 (0~3): 1
주울 아이템 번호 (1~4): 3

손전등(을)를 손에 넣었다!  [3번 칸]
```

- [ ] 아이템 번호가 이름으로 표시된다
- [ ] 주우면 첫 번째 빈 칸에 들어간다
- [ ] 5개를 채우면 "가방이 가득 찼다"가 뜬다
- [ ] 버리면 그 칸이 비고, 다시 주우면 그 칸에 들어간다
- [ ] 검색이 정확한 칸 번호를 알려준다
- [ ] 화면 번호(1~5)와 배열 인덱스(0~4)가 어긋나지 않는다

## 6. 자주 막히는 곳

| 증상 | 원인 | 해결 |
|---|---|---|
| 마지막 요소가 안 나옴 | `i < size` 대신 `i < size-1` | 조건 확인 |
| 크래시 / 이상한 값 | `i <= size` — **범위 초과** | `i < size` |
| 한 칸씩 어긋남 | 화면 번호와 인덱스 혼동 | 경계에서 `-1` 한 번만 |
| 초기화 안 한 배열에 쓰레기 값 | `int arr[5];` 만 선언 | `= { 0 }` 으로 초기화 |
| 문자열 비교가 항상 거짓 | `if (a == b)` | `strcmp(a, b) == 0` |
| 문자열 뒤에 쓰레기가 붙음 | `\0` 누락 | 배열 크기를 글자수+1 이상으로 |
| 함수 안 `sizeof(arr)`가 4나 8 | 배열이 함수에 넘어가면 크기 정보 소실 | 크기를 매개변수로 함께 전달 |
| 관계없는 변수가 바뀜 | 배열 범위 초과 쓰기 | 인덱스 검사 추가 |
| `const char*` 관련 경고 | 문자열 리터럴 수정 시도 | `const`를 붙여 읽기 전용으로 |

## 7. 정리

### 오늘 배운 것

| 개념 | 한 줄 요약 |
|---|---|
| 배열 | 같은 자료형을 연속으로. **번호(인덱스)로 접근** |
| 인덱스 0부터 | 마지막 인덱스 = 크기 - 1. 순회는 `i < size` |
| 범위 초과 | C는 검사 안 한다. 남의 메모리를 조용히 망가뜨린다 |
| 크기 관리 | `#define`으로 한 곳에서. 함수에는 크기도 함께 넘긴다 |
| 5가지 패턴 | 출력 / 합계 / 최대 / 검색 / 빈 칸 찾기 |
| 문자열 | `char` 배열 + `\0`. 비교는 `strcmp` |
| 룩업 테이블 | `names[id]` — 숫자를 이름으로. `if` 뭉치를 없앤다 |
| 배열은 원본이 바뀐다 | 함수에 넘겨도 값 복사가 아니다 (이유는 Day 18) |

### 직접 해보기

| 난이도 | 과제 | 힌트 |
|:--:|---|---|
| ★ | 가방 크기를 10칸으로 늘리기 | `ITEM_MAX`만 바꾸면 되어야 정상 |
| ★★ | 같은 아이템을 여러 개 가질 수 있게 (개수 배열 추가) | `int count[ITEM_COUNT]` |
| ★★★ | 아이템을 이름 순서로 정렬해서 출력 | 버블 정렬: 인접한 두 개를 비교해 교환, `strcmp` 사용 |
