## ② 왜 필요한가

이번 주에 배운 것은 **함수 · 리스트 · 튜플 · 세트 · 딕셔너리 · 예외 · 파일**입니다.
낱개로는 다 알 것 같지만, 실제로 하나의 프로그램을 만들려면 매 순간 선택을 해야 합니다.

```
할 일 하나를 무엇으로 표현할까?     → 튜플? 딕셔너리? 클래스?
할 일 목록은?                      → 리스트? 딕셔너리?
태그는?                            → 리스트? 세트?
완료 여부는?                       → bool? 문자열?
파일이 깨졌을 때는?                 → 죽는다? 빈 목록으로 시작한다?
```

**이 선택을 스스로 하는 것이 오늘의 진짜 목표입니다.** 문법은 검색하면 나오지만 설계는 안 나옵니다.

그리고 오늘 만드는 `todo` 는 버려지지 않습니다.

## ③ 개념 설명

### 자료구조 선택 기준

| 질문 | 예 | 아니오 |
|---|---|---|
| 순서가 의미 있는가? | 리스트 | ↓ |
| 이름으로 찾아야 하는가? | 딕셔너리 | ↓ |
| 중복을 막아야 / 포함 검사가 잦은가? | 세트 | ↓ |
| 만든 뒤 안 바뀌어야 하는가? | 튜플 | 리스트 |

**실무에서 가장 흔한 조합은 `리스트 안의 딕셔너리`** 입니다.

```python
todos = [
    {"id": 1, "title": "장보기", "done": False, "tags": {"집안일"}},
    {"id": 2, "title": "보고서 작성", "done": True, "tags": {"업무", "급함"}},
]
```

| 요소 | 선택 | 이유 |
|---|---|---|
| 전체 목록 | 리스트 | 등록 순서가 의미 있고, 추가·삭제가 잦음 |
| 할 일 하나 | 딕셔너리 | 필드가 여러 개고 이름으로 접근해야 함 |
| 태그 | 세트 | 같은 태그를 두 번 달 이유가 없음 |
| 완료 여부 | `bool` | 참/거짓 두 가지뿐 |
| ID | `int` | 정렬·비교가 자연스러움 |

> **"ID로 찾는 게 잦으니 목록도 딕셔너리로 하면 안 되나?"**
> 됩니다. `{1: {...}, 2: {...}}` 형태로요. 조회는 빨라지지만 **순서 관리와 JSON 저장이 번거로워집니다.**
> 할 일이 수천 개가 아니라면 리스트로 충분합니다. **먼저 단순하게 만들고, 느려지면 그때 바꿉니다.**

### ID 부여 전략

```python
# ❌ 위험 — 삭제하면 ID가 겹칩니다
new_id = len(todos) + 1

# ✅ 안전 — 최대값 + 1
new_id = max((t["id"] for t in todos), default=0) + 1
```

`len + 1` 은 3개 중 2번을 지우면 다음 ID가 3이 되어 **기존 3번과 충돌**합니다.
`max(...) + 1` 은 삭제와 무관하게 항상 새 번호를 줍니다.

> `default=0` 은 목록이 비었을 때 `max()` 가 `ValueError` 를 내는 것을 막습니다.

### "하나의 함수 = 하나의 일"

함수를 나누는 실용적 기준입니다.

| 신호 | 의미 |
|---|---|
| 이름에 "그리고"가 들어감 | `save_and_print` → 두 개로 |
| 20줄이 넘음 | 안에 숨은 함수가 있음 |
| 안에서 `print` 와 계산을 같이 함 | 계산과 출력을 분리 |
| 매개변수가 5개 이상 | 관련된 것끼리 묶기 |

**계층으로 나누면 자연스럽습니다.**

```
┌─────────────────────────────────┐
│  화면 계층   메뉴·출력·입력       │  print, input
├─────────────────────────────────┤
│  로직 계층   추가·삭제·검색·집계   │  순수 함수 (테스트하기 쉬움)
├─────────────────────────────────┤
│  저장 계층   JSON 읽기·쓰기       │  파일 I/O
└─────────────────────────────────┘
```

**로직 계층은 `print` 도 `input` 도 `open` 도 하지 않습니다.**
값을 받아 값을 돌려주기만 합니다. 그래야 [Day 014](day-014.md)에서 테스트를 붙일 수 있습니다.

이 3계층 구조는 W19 [Day 093](../04-deep-learning-serving/day-093.md)의
`router / service / repository` 와 정확히 같은 발상입니다.

### 함수 이름 짓기

| 접두사 | 하는 일 | 예 |
|---|---|---|
| `add_` `create_` | 만들기 | `add_todo` |
| `get_` `find_` | 찾기 | `find_by_id` |
| `update_` `set_` | 바꾸기 | `toggle_done` |
| `delete_` `remove_` | 지우기 | `delete_todo` |
| `is_` `has_` | 참/거짓 | `is_valid_title` |
| `load_` `save_` | 입출력 | `load_todos` |
| `show_` `print_` | 화면 출력 | `show_todos` |

### Step 1. 설계 먼저

코드를 쓰기 전에 정합니다.

**데이터 구조**

```python
{
    "id": 1,                          # int  — 고유 번호
    "title": "장보기",                 # str  — 할 일 내용 (필수, 1자 이상)
    "priority": "높음",                # str  — 높음 / 보통 / 낮음
    "tags": ["집안일", "주말"],         # list — JSON 저장 위해 리스트 (메모리에선 세트로 다뤄도 됨)
    "done": False,                    # bool — 완료 여부
    "created_at": "2026-08-12 14:23"  # str  — 생성 시각
}
```

> **태그를 리스트로 둔 이유** — JSON은 세트를 저장할 수 없습니다 (`TypeError`).
> 중복 제거는 저장 직전에 `sorted(set(tags))` 로 처리합니다.

**기능 목록**

| 번호 | 기능 | 계층 |
|---|---|---|
| 1 | 추가 | 화면 → 로직 → 저장 |
| 2 | 목록 보기 (전체/미완료/완료) | 화면 → 로직 |
| 3 | 완료 표시 토글 | 화면 → 로직 → 저장 |
| 4 | 수정 | 화면 → 로직 → 저장 |
| 5 | 삭제 | 화면 → 로직 → 저장 |
| 6 | 검색 (제목·태그) | 화면 → 로직 |
| 7 | 통계 | 화면 → 로직 |
| 0 | 종료 | 저장 |

### Step 2. 저장 계층

`todo.py` 를 만들고 맨 위부터 작성합니다.

```python
"""할 일 관리 CLI (Day 010 버전)."""

import json
import os
from datetime import datetime

DATA_FILE = "todos.json"
PRIORITIES = ("높음", "보통", "낮음")
REQUIRED_KEYS = {"id", "title", "priority", "tags", "done", "created_at"}


# ===================== 저장 계층 =====================

def load_todos(path=DATA_FILE):
    """저장된 할 일을 불러옵니다.

    Returns:
        (할일 리스트, 경고 메시지 또는 None)
    """
    if not os.path.exists(path):
        return [], None

    try:
        with open(path, "r", encoding="utf-8") as f:
            data = json.load(f)
    except json.JSONDecodeError as e:
        return [], f"파일이 손상되었습니다 ({e}). 빈 목록으로 시작합니다."
    except OSError as e:
        return [], f"파일을 읽지 못했습니다 ({e}). 빈 목록으로 시작합니다."

    if not isinstance(data, list):
        return [], "파일 형식이 올바르지 않습니다. 빈 목록으로 시작합니다."

    valid = []
    dropped = 0
    for item in data:
        if isinstance(item, dict) and REQUIRED_KEYS <= item.keys():
            valid.append(item)
        else:
            dropped += 1

    warning = f"형식이 맞지 않는 항목 {dropped}건을 건너뛰었습니다." if dropped else None
    return valid, warning


def save_todos(todos, path=DATA_FILE):
    """할 일 목록을 JSON으로 저장합니다.

    Returns:
        (성공 여부, 에러 메시지 또는 None)
    """
    try:
        with open(path, "w", encoding="utf-8") as f:
            json.dump(todos, f, ensure_ascii=False, indent=2)
        return True, None
    except OSError as e:
        return False, f"저장하지 못했습니다: {e}"
```

### Step 3. 로직 계층

이어서 작성합니다. **이 함수들은 `print` 도 `input` 도 하지 않습니다.**

```python
# ===================== 로직 계층 =====================

def next_id(todos):
    """다음 ID를 계산합니다. 삭제가 있어도 충돌하지 않습니다."""
    return max((t["id"] for t in todos), default=0) + 1


def normalize_tags(raw):
    """'업무, 급함 , 업무' → ['급함', '업무']"""
    tags = {t.strip() for t in raw.split(",") if t.strip()}
    return sorted(tags)


def add_todo(todos, title, priority="보통", tags=None):
    """할 일을 추가하고 만들어진 항목을 돌려줍니다.

    Raises:
        ValueError: 제목이 비었거나 우선순위가 잘못된 경우
    """
    title = title.strip()
    if not title:
        raise ValueError("제목은 비워 둘 수 없습니다.")
    if priority not in PRIORITIES:
        raise ValueError(f"우선순위는 {' / '.join(PRIORITIES)} 중 하나여야 합니다: {priority!r}")

    todo = {
        "id": next_id(todos),
        "title": title,
        "priority": priority,
        "tags": tags or [],
        "done": False,
        "created_at": datetime.now().strftime("%Y-%m-%d %H:%M"),
    }
    todos.append(todo)
    return todo


def find_by_id(todos, todo_id):
    """ID로 할 일을 찾습니다. 없으면 None."""
    for t in todos:
        if t["id"] == todo_id:
            return t
    return None


def toggle_done(todos, todo_id):
    """완료 여부를 뒤집습니다.

    Raises:
        KeyError: 해당 ID가 없는 경우
    """
    todo = find_by_id(todos, todo_id)
    if todo is None:
        raise KeyError(f"{todo_id}번 할 일이 없습니다.")
    todo["done"] = not todo["done"]
    return todo


def update_todo(todos, todo_id, title=None, priority=None, tags=None):
    """할 일을 수정합니다. None인 항목은 건드리지 않습니다."""
    todo = find_by_id(todos, todo_id)
    if todo is None:
        raise KeyError(f"{todo_id}번 할 일이 없습니다.")

    if title is not None:
        title = title.strip()
        if not title:
            raise ValueError("제목은 비워 둘 수 없습니다.")
        todo["title"] = title

    if priority is not None:
        if priority not in PRIORITIES:
            raise ValueError(f"우선순위가 잘못되었습니다: {priority!r}")
        todo["priority"] = priority

    if tags is not None:
        todo["tags"] = tags

    return todo


def delete_todo(todos, todo_id):
    """할 일을 삭제하고 삭제된 항목을 돌려줍니다."""
    todo = find_by_id(todos, todo_id)
    if todo is None:
        raise KeyError(f"{todo_id}번 할 일이 없습니다.")
    todos.remove(todo)
    return todo


def filter_todos(todos, status="all"):
    """상태로 거릅니다. status: all / todo / done"""
    if status == "todo":
        return [t for t in todos if not t["done"]]
    if status == "done":
        return [t for t in todos if t["done"]]
    return list(todos)


def search_todos(todos, keyword):
    """제목 또는 태그에 키워드가 들어간 항목을 찾습니다."""
    keyword = keyword.strip().lower()
    if not keyword:
        return []

    result = []
    for t in todos:
        if keyword in t["title"].lower():
            result.append(t)
            continue
        if any(keyword in tag.lower() for tag in t["tags"]):
            result.append(t)
    return result


def all_tags(todos):
    """사용된 모든 태그를 세트로 모읍니다."""
    tags = set()
    for t in todos:
        tags.update(t["tags"])
    return tags


def stats(todos):
    """통계를 딕셔너리로 돌려줍니다."""
    total = len(todos)
    done = sum(1 for t in todos if t["done"])

    by_priority = {}
    for t in todos:
        by_priority[t["priority"]] = by_priority.get(t["priority"], 0) + 1

    by_tag = {}
    for t in todos:
        for tag in t["tags"]:
            by_tag[tag] = by_tag.get(tag, 0) + 1

    return {
        "total": total,
        "done": done,
        "todo": total - done,
        "rate": done / total if total else 0.0,
        "by_priority": by_priority,
        "by_tag": by_tag,
    }
```

> **`sum(1 for t in todos if t["done"])`** 는 조건에 맞는 개수를 세는 관용구입니다.
> `len([t for t in todos if t["done"]])` 와 같지만 리스트를 만들지 않아 메모리 효율이 좋습니다.
>
> **`any(...)`** 는 "하나라도 참인가"를 확인합니다. 반대는 `all(...)` 입니다.
>
> **`rate` 계산에서 `if total else 0.0`** — 빈 목록에서 `ZeroDivisionError` 를 막는 방어입니다.

### Step 4. 화면 계층

```python
# ===================== 화면 계층 =====================

MARK = {True: "✔", False: " "}
PRIORITY_MARK = {"높음": "!!", "보통": "! ", "낮음": "  "}


def show_menu():
    print()
    print("=" * 52)
    print("                할 일 관리 CLI")
    print("=" * 52)
    print(" 1. 추가        2. 목록        3. 완료 토글")
    print(" 4. 수정        5. 삭제        6. 검색")
    print(" 7. 통계        0. 저장하고 종료")
    print("-" * 52)


def show_todos(todos, title="목록"):
    print(f"\n[{title}] {len(todos)}건")
    if not todos:
        print("  항목이 없습니다.")
        return

    print(f"  {'ID':>3} {'':^3} {'':^3} {'제목':<22}{'태그':<18}{'등록':<16}")
    print("  " + "-" * 68)
    for t in todos:
        tags = ", ".join(t["tags"]) if t["tags"] else "-"
        print(f"  {t['id']:>3} [{MARK[t['done']]}] {PRIORITY_MARK[t['priority']]} "
              f"{t['title']:<22}{tags:<18}{t['created_at']:<16}")


def show_stats(todos):
    s = stats(todos)
    print(f"\n[통계]")
    if s["total"] == 0:
        print("  등록된 할 일이 없습니다.")
        return

    filled = int(s["rate"] * 20)
    bar = "■" * filled + "□" * (20 - filled)
    print(f"  전체 {s['total']}건 · 완료 {s['done']}건 · 미완료 {s['todo']}건")
    print(f"  진행률 {bar} {s['rate']:.1%}")

    print("\n  [우선순위별]")
    for p in PRIORITIES:
        count = s["by_priority"].get(p, 0)
        print(f"    {p:<5}{count:>3}건 {'■' * count}")

    if s["by_tag"]:
        print("\n  [태그별 — 많은 순]")
        ranked = sorted(s["by_tag"].items(), key=lambda kv: kv[1], reverse=True)
        for tag, count in ranked[:5]:
            print(f"    {tag:<12}{count:>3}건 {'■' * count}")


def input_int(prompt):
    """정수를 입력받습니다. 빈 입력이면 None."""
    raw = input(prompt).strip()
    if not raw:
        return None
    try:
        return int(raw)
    except ValueError:
        print(f"  → '{raw}' 는 숫자가 아닙니다.")
        return None


def input_priority(default="보통"):
    """우선순위를 고릅니다. 엔터를 치면 기본값."""
    raw = input(f"  우선순위 ({' / '.join(PRIORITIES)}) [엔터={default}]: ").strip()
    if not raw:
        return default
    if raw not in PRIORITIES:
        print(f"  → 목록에 없어 '{default}' 로 설정합니다.")
        return default
    return raw
```

### Step 5. 메인 루프

def main():
    todos, warning = load_todos()

    print(f"할 일 {len(todos)}건을 불러왔습니다.")

    while True:
        show_menu()
        choice = input("선택 > ").strip()

        # --- 종료 ---
        if choice == "0":
            ok, error = save_todos(todos)
            if ok:
                print(f"{len(todos)}건을 {DATA_FILE} 에 저장했습니다. 안녕히 가세요.")
            else:

        # --- 추가 ---

            save_todos(todos)

            save_todos(todos)

            try:
                update_todo(todos, todo_id, new_title, new_priority, new_tags)
            except (ValueError, KeyError) as e:

            print(f"  ✓ {todo_id}번 수정됨")

## ⑥ 확인 문제

**1.** 할 일의 **태그**를 리스트가 아니라 세트로 저장하면 어떤 장점이 있고, 왜 이 프로그램에서는 결국 리스트로 저장했나요?

<details>
<summary>답 보기</summary>

**세트의 장점**

1. **중복 자동 제거** — `"업무, 급함, 업무"` 를 넣어도 `{"업무", "급함"}`
2. **포함 검사가 빠름** — `"급함" in tags` 가 O(1)
3. **집합 연산** — 여러 할 일의 공통 태그를 `tags1 & tags2` 로 즉시 구할 수 있음

**그런데 리스트로 저장한 이유**

**JSON이 세트를 지원하지 않기 때문입니다.**

```python
json.dump({"tags": {"업무"}}, f)
# TypeError: Object of type set is not JSON serializable
```

JSON 명세에 있는 타입은 object·array·string·number·boolean·null 뿐입니다.
세트에 해당하는 것이 없습니다.

**실무에서 쓰는 절충안**

메모리에서는 세트로 다루고, **저장 직전에만 변환**합니다.

```python
# 입력 처리 — 세트로 중복 제거
tags = {t.strip() for t in raw.split(",") if t.strip()}

# 저장 — 리스트로 (정렬해서 diff가 안정적이게)
todo["tags"] = sorted(tags)

# 검색 — 다시 세트로
if keyword in set(todo["tags"]): ...
```

이 코드의 `normalize_tags()` 가 정확히 그 일을 합니다.
세트 컴프리헨션으로 중복을 없애고 `sorted()` 로 리스트를 돌려줍니다.

**정렬해서 저장하는 이유**도 있습니다. 세트는 순서가 없어서 저장할 때마다 순서가 달라질 수 있는데,
그러면 Git diff에 의미 없는 변경이 계속 잡힙니다.
</details>

**2.** 아래 두 설계 중 어느 쪽을 골라야 할까요? 상황을 나눠 답하세요.

```python
# A) 리스트 안의 딕셔너리
todos = [{"id": 1, "title": "장보기"}, {"id": 2, "title": "청소"}]

# B) ID를 키로 하는 딕셔너리
todos = {1: {"title": "장보기"}, 2: {"title": "청소"}}
```

<details>
<summary>답 보기</summary>

| 기준 | A 리스트 | B 딕셔너리 |
|---|---|---|
| ID로 조회 | O(n) — 전부 훑음 | **O(1) — 즉시** |
| 순서 유지 | **자연스러움** | 삽입 순서는 유지되나 의미가 약함 |
| 전체 순회 | `for t in todos` | `for t in todos.values()` |
| JSON 저장 | 그대로 배열 | **키가 문자열로 바뀜** ⚠ |
| 정렬 | `sorted(todos, key=...)` | `sorted(todos.values(), ...)` |
| ID 중복 | 실수로 가능 | **구조적으로 불가능** |

**B의 함정 — JSON 키는 문자열입니다.**

```python
json.dump({1: {"title": "장보기"}}, f)     # 저장: {"1": {...}}
data = json.load(f)
data[1]        # KeyError!  실제 키는 "1"
```

저장 후 다시 읽으면 정수 키 `1` 이 문자열 `"1"` 이 됩니다. 복원할 때 변환이 필요합니다.

```python
data = {int(k): v for k, v in json.load(f).items()}
```

**상황별 선택**

| 상황 | 선택 |
|---|---|
| 수백 건 이하 · 순서가 의미 있음 · JSON 저장 | **A** ← 이 프로그램 |
| 수만 건 이상 · ID 조회가 매우 잦음 | B (또는 아예 DB) |
| ID 중복을 구조적으로 막고 싶음 | B |

**실무 원칙** — **먼저 단순한 A로 만들고, 느려지는 것이 측정되면 그때 바꿉니다.**
수백 건에서 O(n) 조회는 사람이 체감할 수 없습니다.
그리고 진짜로 수만 건이 되면 자료구조 문제가 아니라 **DB를 써야 할 때**입니다 (W07).
</details>

**3.** `check_todo.py` 가 `todo.py` 의 로직 함수들을 **화면 없이** 검증할 수 있는 이유는 무엇인가요? 만약 `add_todo` 가 아래처럼 작성됐다면 어떤 문제가 생기나요?

```python
def add_todo(todos):
    title = input("제목: ")                  # 입력을 직접 받음
    if not title.strip():
        print("제목이 비었습니다.")            # 화면에 직접 출력
        return
    todos.append({"title": title})
    save_todos(todos)                       # 파일에 직접 저장
    print("등록되었습니다.")
```

<details>
<summary>답 보기</summary>

**검증할 수 있는 이유**

원래의 `add_todo(todos, title, priority, tags)` 는 **값을 받아 값을 돌려주기만** 합니다.
`input` 도 `print` 도 `open` 도 하지 않습니다. 이런 함수를 **순수 함수에 가깝다**고 합니다.

그래서 이렇게 확인할 수 있습니다.

```python
todos = []
t = add_todo(todos, "테스트", "높음", ["태그"])
assert t["id"] == 1
assert t["priority"] == "높음"
```

**바뀐 버전의 문제**

| 문제 | 결과 |
|---|---|
| `input()` 을 직접 호출 | 테스트가 사람의 키보드 입력을 기다리며 **멈춤** |
| `print()` 로 에러를 알림 | 실패했는지 **프로그램이 알 방법이 없음** |
| `save_todos()` 를 직접 호출 | 테스트를 돌릴 때마다 **실제 파일이 덮어써짐** |
| 반환값이 `None` | 무엇이 등록됐는지 **확인할 수 없음** |

특히 두 번째가 치명적입니다. 검증 실패를 `print` 로만 알리면 호출한 쪽이 성공/실패를 구분할 수 없어
**잘못된 데이터가 조용히 흘러갑니다.**

**원칙: 입출력을 가장자리로 밀어낸다**

```
input/print/open  ←  화면·저장 계층 (얇게)
       ↕
   값 ↔ 값        ←  로직 계층 (두껍게, 테스트 대상)
```

로직을 두껍게, 입출력을 얇게 만들수록 테스트할 수 있는 비율이 올라갑니다.

이 원칙은 이 과정 내내 반복됩니다.

</details>
