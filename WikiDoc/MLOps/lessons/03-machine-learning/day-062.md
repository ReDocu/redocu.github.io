## ③ 개념 설명

### 파라미터 vs 하이퍼파라미터

| | 파라미터 | 하이퍼파라미터 |
|---|---|---|
| 예 | 선형 회귀의 계수 w, 트리의 분할값 | learning_rate, num_leaves, α, K |
| 누가 정하나 | **fit이** 데이터에서 학습 | **사람이** 학습 전에 지정 |
| 어떻게 고르나 | 손실 최소화 (자동) | **후보를 돌려 CV 점수로 비교** |

즉 튜닝이란 "CV 점수를 목적 함수로 하는 **바깥쪽 최적화 루프**"입니다. 안쪽(fit)은 초 단위,
바깥쪽은 후보 수 × K폴드 배라서 **예산 관리**가 핵심 기술이 됩니다.

### 탐색 공간 설계 — 절반의 성공

무엇을 어디서 찾을지가 어떻게 찾을지보다 중요합니다.

| 원칙 | 예 |
|---|---|
| 비율형 파라미터는 **로그 눈금** | learning_rate 0.005~0.3: 선형으로 뽑으면 절반이 0.15 위쪽에 몰림. 0.01과 0.02의 차이는 0.28과 0.29의 차이보다 훨씬 큼 |
| 서로 얽힌 쌍을 기억 | learning_rate ↓ ⇄ n_estimators ↑ ([Day 059](day-059.md)) |
| 규제 방향 포함 | num_leaves 작게 · min_child_samples 크게 — 우리처럼 표본이 적으면 이쪽에 최적이 있는 경우가 많음 |

### 세 가지 탐색 전략

| 전략 | 방법 | 강점 | 약점 |
|---|---|---|---|
| **Grid** | 격자 전수조사 | 빠짐없음 · 재현 쉬움 | 차원이 늘면 **폭발** (4축×3값 = 81, 6축이면 729…) |
| **Random** | 공간에서 무작위 n회 | 예산 고정 · **중요한 축에 다양한 값**이 찍힘 | 운에 따라 빈 곳 |
| **Optuna (TPE)** | 이전 시도 결과를 보고 유망한 곳을 **학습하며** 제안 | 같은 예산에서 더 좋은 곳 도달 경향 · 조기 중단(pruning) | 병렬화 제약 · 시도 간 의존 |

Random이 Grid를 이기는 직관: 축이 7개인데 그중 2개만 중요하다면, Grid는 안 중요한 축의
반복에 예산을 태우지만 Random은 **중요한 축에서 36개의 서로 다른 값**을 시험합니다.

### 오늘의 안전 수칙

1. 심판은 **TimeSeriesSplit** ([Day 061](day-061.md)) — 무작위 K-Fold면 0.94짜리 가짜 과녁에 최적화합니다.
2. test는 **금고에** — 튜닝이 다 끝난 뒤 최종 1회.
3. 최고 CV 점수는 **살짝 부풀어 있음**을 기억 — 수십 개 중 1등은 실력+운의 합입니다 (실습 Step 4).

### Step 0. 기준점 박기 (1교시)

```python
# day062_tuning.py — 하이퍼파라미터 튜닝
import time
import numpy as np
import pandas as pd
from lightgbm import LGBMClassifier
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import roc_auc_score
from sklearn.model_selection import GridSearchCV, RandomizedSearchCV, TimeSeriesSplit, cross_val_score
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

pd.set_option("display.width", 140)
df = pd.read_csv("data/air_daily.csv", parse_dates=["date"])
F10 = ["pm10", "pm25", "o3", "no2", "co", "so2", "temp", "humidity", "wind_speed", "precip"]
d = df.dropna(subset=F10).copy()
d["bad_next"] = (d.pm25_next >= 36).astype(int)
d = d.sort_values("date").reset_index(drop=True)
tr = d[d.date < "2026-01-01"]; te = d[d.date >= "2026-01-01"]
Xtr, ytr = tr[F10], tr.bad_next
tss = TimeSeriesSplit(n_splits=5)

print("== A. 기준점: 기본값들의 TSS CV ==")
base = LGBMClassifier(random_state=42, verbosity=-1)
s = cross_val_score(base, Xtr, ytr, cv=tss, scoring="roc_auc")
print(f"  LGBM 기본값     CV {s.mean():.3f} ± {s.std():.3f}")
logit = make_pipeline(StandardScaler(), LogisticRegression(max_iter=5000))
s2 = cross_val_score(logit, Xtr, ytr, cv=tss, scoring="roc_auc")
print(f"  로지스틱(참조)   CV {s2.mean():.3f} ± {s2.std():.3f}")
```

실행 결과:

```
== A. 기준점: 기본값들의 TSS CV ==
  LGBM 기본값     CV 0.751 ± 0.127
  로지스틱(참조)   CV 0.840 ± 0.048
```

튜닝 전 기준점: LGBM 0.751 (± 0.127 — 분산도 큼). 목표는 이 값을 끌어올려
로지스틱(0.840)과의 간격을 좁히는 것입니다.

### Step 1. GridSearchCV — 좁고 확실하게 (2~3교시)

[Day 059](day-059.md) 과제의 손튜닝을 기계화합니다. 규제 방향 위주로 4축 36조합.

```python
print("\n== B. GridSearchCV — 격자 전수조사 ==")
grid = {
    "num_leaves": [7, 15, 31],
    "learning_rate": [0.02, 0.05, 0.1],
    "n_estimators": [200, 600],
    "min_child_samples": [20, 60],
}
t0 = time.perf_counter()
gs = GridSearchCV(LGBMClassifier(random_state=42, verbosity=-1), grid,
                  cv=tss, scoring="roc_auc", n_jobs=-1)
gs.fit(Xtr, ytr)
dt = time.perf_counter() - t0
print(f"  조합 36개 × 5폴드 = 학습 180회, {dt:.0f}초")
print(f"  최고 CV {gs.best_score_:.3f} @ {gs.best_params_}")
```

실행 결과:

```
== B. GridSearchCV — 격자 전수조사 ==
  조합 36개 × 5폴드 = 학습 180회, 50초
  최고 CV 0.806 @ {'learning_rate': 0.02, 'min_child_samples': 60, 'n_estimators': 200, 'num_leaves': 7}
```

학습 180회를 50초에 끝냈습니다 (`n_jobs=-1` 이 전 코어 병렬). 0.751 → **0.806**.
최적 조합을 읽어 보세요 — 잎 7개, 잎당 최소 60일, 느린 학습률. 전부 **"작고 조심스러운 모델"**
방향입니다. 2,600행짜리 데이터가 큰 모델을 부양할 수 없다는 뜻으로, [Day 058](day-058.md)에서
min_samples_leaf=50이 최고였던 것과 같은 결론입니다.

### Step 2. RandomizedSearchCV — 같은 예산, 7차원 (4교시)

Grid로 7축을 보려면 조합이 수천 개가 됩니다. 같은 36회 예산으로 넓게 뽑아 봅니다.

```python
print("\n== C. RandomizedSearchCV — 같은 예산, 더 넓은 공간 ==")
from scipy.stats import loguniform, randint
space = {
    "num_leaves": randint(4, 64),
    "learning_rate": loguniform(0.005, 0.3),       # 로그 눈금!
    "n_estimators": randint(100, 1000),
    "min_child_samples": randint(5, 100),
    "subsample": [0.6, 0.8, 1.0],
    "colsample_bytree": [0.6, 0.8, 1.0],
    "reg_lambda": loguniform(1e-3, 10),
}
t0 = time.perf_counter()
rs = RandomizedSearchCV(LGBMClassifier(random_state=42, verbosity=-1), space, n_iter=36,
                        cv=tss, scoring="roc_auc", n_jobs=-1, random_state=42)
rs.fit(Xtr, ytr)
dt = time.perf_counter() - t0
print(f"  뽑기 36회 (7차원 공간), {dt:.0f}초")
print(f"  최고 CV {rs.best_score_:.3f} @ { {k: (round(v, 4) if isinstance(v, float) else v) for k, v in rs.best_params_.items()} }")
```

실행 결과:

```
== C. RandomizedSearchCV — 같은 예산, 더 넓은 공간 ==
  뽑기 36회 (7차원 공간), 50초
  최고 CV 0.805 @ {'colsample_bytree': 0.8, 'learning_rate': np.float64(0.0122), 'min_child_samples': 92, 'n_estimators': 332, 'num_leaves': 55, 'reg_lambda': np.float64(0.0285), 'subsample': 0.6}
```

같은 예산으로 7차원을 훑어 0.805 — Grid(0.806)와 사실상 동률입니다. 조합은 전혀 다르게
생겼지만(잎 55개 대신 잎당 92일로 조임) **"강하게 규제된 작은 모델"이라는 본질은 같습니다.**
최적점은 하나의 점이 아니라 능선입니다.

### Step 3. Optuna — 학습하며 탐색 (5~6교시)

```python
print("\n== D. Optuna — 이전 결과를 보고 다음 후보를 고른다 ==")
import optuna
optuna.logging.set_verbosity(optuna.logging.WARNING)

def objective(trial):
    params = dict(
        num_leaves=trial.suggest_int("num_leaves", 4, 64),
        learning_rate=trial.suggest_float("learning_rate", 0.005, 0.3, log=True),
        n_estimators=trial.suggest_int("n_estimators", 100, 1000),
        min_child_samples=trial.suggest_int("min_child_samples", 5, 100),
        subsample=trial.suggest_float("subsample", 0.6, 1.0),
        colsample_bytree=trial.suggest_float("colsample_bytree", 0.6, 1.0),
        reg_lambda=trial.suggest_float("reg_lambda", 1e-3, 10, log=True),
    )
    m = LGBMClassifier(random_state=42, verbosity=-1, **params)
    return cross_val_score(m, Xtr, ytr, cv=tss, scoring="roc_auc").mean()

t0 = time.perf_counter()
study = optuna.create_study(direction="maximize", sampler=optuna.samplers.TPESampler(seed=42))
study.optimize(objective, n_trials=36)
dt = time.perf_counter() - t0
print(f"  시도 36회, {dt:.0f}초")
print(f"  최고 CV {study.best_value:.3f} @ { {k: (round(v, 4) if isinstance(v, float) else v) for k, v in study.best_params.items()} }")
```

실행 결과:

```
== D. Optuna — 이전 결과를 보고 다음 후보를 고른다 ==
  시도 36회, 12초
  최고 CV 0.809 @ {'num_leaves': 47, 'learning_rate': 0.0051, 'n_estimators': 405, 'min_child_samples': 79, 'subsample': 0.8726, 'colsample_bytree': 0.6421, 'reg_lambda': 0.5698}
```

`objective` 함수 하나만 쓰면 됩니다 — "파라미터를 제안받아 CV 점수를 반환". TPE 샘플러가
이전 시도들의 성적을 보고 유망한 영역에 후보를 집중시켜, 36회 만에 **0.809**(셋 중 최고 CV)에
닿았습니다. 시간도 12초로 가장 짧았는데, 유망 영역이 마침 학습이 빠른 조합이었던 덕입니다.

### Step 4. 금고 개봉 — 그리고 승자의 저주 (7교시)

세 후보와 기본값을 **처음이자 마지막으로** test에 세웁니다.

```python
print("\n== E. 금고 개봉 — 튜닝의 실제 가치 ==")
yte = te.bad_next
rows = [
    ("LGBM 기본값", LGBMClassifier(random_state=42, verbosity=-1)),
    ("Grid 최적", LGBMClassifier(random_state=42, verbosity=-1, **gs.best_params_)),
    ("Random 최적", LGBMClassifier(random_state=42, verbosity=-1, **rs.best_params_)),
    ("Optuna 최적", LGBMClassifier(random_state=42, verbosity=-1, **study.best_params)),
]
for name, m in rows:
    m.fit(Xtr, ytr)
    print(f"  {name:<10} test AUC {roc_auc_score(yte, m.predict_proba(te[F10])[:, 1]):.3f}")
logit.fit(Xtr, ytr)
print(f"  로지스틱(참조) test AUC {roc_auc_score(yte, logit.predict_proba(te[F10])[:, 1]):.3f}")
```

실행 결과:

```
== E. 금고 개봉 — 튜닝의 실제 가치 ==
  LGBM 기본값   test AUC 0.797
  Grid 최적    test AUC 0.812
  Random 최적  test AUC 0.809
  Optuna 최적  test AUC 0.794
  로지스틱(참조) test AUC 0.818
```

결산표를 읽습니다. 오늘의 진짜 수업이 여기 있습니다.

| 후보 | CV | test | 읽기 |
|---|---|---|---|
| Grid | 0.806 | **0.812** | 튜닝의 실질 이득: 기본값 대비 **+0.015** |
| Random | 0.805 | 0.809 | Grid와 동률 — 능선 위의 다른 점 |
| **Optuna** | **0.809 (CV 1위)** | **0.794 (꼴찌)** | **승자의 저주** — CV를 가장 세게 파고든 후보가 CV의 노이즈까지 학습 |
| 로지스틱 | 0.840 | 0.818 | 108회의 학습 뒤에도 **왕좌는 그대로** |

두 가지 결론:

1. **CV 1등이 test 1등이 아닙니다.** CV 점수 차이 0.003~0.004는 ±0.05 분산 안의 소음인데,
   수십 번 시도 중의 1등은 그 소음의 **운 좋은 쪽 끝**일 확률이 높습니다(승자의 저주).
   그래서 튜닝 보고서에는 best CV가 아니라 **test 최종 1회**를 적는 것입니다.
2. **튜닝의 이득(+0.015)은 특성·문제 정의의 이득보다 작은 경우가 많습니다.** 108번의 학습으로도
   로지스틱을 못 넘었습니다 — 판을 바꾸는 것은 모델 손잡이가 아니라 **데이터**라는 것,
   모레([Day 064](day-064.md)) 확인합니다.

## ⑤ 자주 하는 실수

### 비율형 파라미터를 선형 눈금으로 탐색

**증상** — learning_rate를 `uniform(0.005, 0.3)` 으로 — 뽑힌 값의 절반이 0.15 위쪽에 몰림.
**원인** — 비율형은 0.01→0.02(2배)와 0.29→0.30(1.03배)의 의미가 완전히 다릅니다.
**해결** — `loguniform` / `suggest_float(..., log=True)`. 어느 자릿수인지부터 찾는 것입니다.

### Grid에 축을 계속 추가

**증상** — "subsample도 궁금한데, reg_lambda도…" → 조합 729개 × 5폴드, 점심시간 증발.
**원인** — Grid 비용은 축 수에 **지수적**입니다.
**해결** — 축이 4개를 넘으면 Random/Optuna로 전환하고, Grid는 마지막에 좁은 범위 확인용으로만.

### 시계열인데 기본 cv=5를 씀

**증상** — `GridSearchCV(..., cv=5)` — CV 점수가 0.9대로 훌쩍.
**원인** — 정수 cv는 (Stratified)KFold, 즉 무작위 조각입니다. [Day 061](day-061.md)의 부풀려진 과녁(0.944)에 대고 최적화하게 됩니다.
**해결** — `cv=TimeSeriesSplit(5)` 를 명시. **부풀려진 심판 아래서의 1등은 배포에서 의미가 없습니다.**

### best_score_를 최종 성능으로 보고

**증상** — "Optuna로 AUC 0.809 달성!" — 배포하니 0.794.
**원인** — 승자의 저주: 수십 후보 중 1등의 CV 점수는 낙관 편향을 갖습니다 (오늘 Step 4에서 실측 -0.015).
**해결** — 보고서에는 "CV 0.809, **test 0.794**"를 함께. 후보 선택까지가 CV의 일이고, 성능 주장은 test의 일입니다.

### 튜닝을 실험 기록 없이 돌림

**증상** — "아까 0.81 나온 조합이 뭐였지…" — best_params를 복사해 두지 않아 재탐색.
**원인** — 탐색 36회의 이력은 휘발됩니다. `gs.cv_results_`, `study.trials_dataframe()` 에 다 있는데 안 봅니다.
**해결** — 최소한 (일시, 공간, best_params, best CV, test)를 md 표로 남기세요. 이 수기 기록의 한계가 [Day 065](day-065.md)에서 터지고, [Day 067](day-067.md)의 MLflow로 해결됩니다.
