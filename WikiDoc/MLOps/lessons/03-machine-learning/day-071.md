이 레슨을 마치면 이렇게 할 수 있습니다.

- 평가 설계(분할 전략 · 주 지표)를 **모델을 만들기 전에** 확정할 수 있다.

## ② 왜 필요한가

오늘부터 5일, MP2입니다. 4주간 배운 모든 것을 **여러분의 문제**로 처음부터 실행합니다.

MP1을 해 본 여러분은 이미 압니다 — 5일 프로젝트의 성패는 첫날 기획에서 절반이 결정됩니다.
MP2에는 MP1에 없던 함정이 둘 추가됩니다.

| 함정 | 왜 MP2에서 치명적인가 |
|---|---|
| **누수** | 분석(MP1)은 과거를 설명하면 끝이지만, 예측은 "그 시점에 알 수 있었나"가 전부입니다. 기획 단계에서 타깃과 특성의 시점을 못 박지 않으면, 목요일에 발견된 누수가 프로젝트 전체를 리셋시킵니다 |
| **평가 설계 오류** | 분할·지표를 나중에 정하면, 실험 결과가 쌓인 뒤에는 유리한 쪽으로 고르고 싶은 유혹을 이길 수 없습니다 ([Day 057](day-057.md) ⑤의 체리피킹) |

그래서 오늘의 순서가 중요합니다: **문제 정의 → 평가 설계 → 베이스라인**, 그 다음에야 모델입니다.
평가 기준(방법론 적절성 30점)이 보는 것이 바로 이 순서의 흔적입니다.

### 데이터 선정 기준 — ML판 6항목

MP1의 6기준([Day 046](../02-sql-pipeline/day-046.md))에서 ML용으로 바뀐 부분이 핵심입니다.

| 기준 | 질문 | 탈락 사례 |
|---|---|---|
| **타깃 정의** | 맞힐 값이 데이터에 있거나 만들 수 있는가 (`LEAD`, 라벨) | "고객 만족을 예측" — 만족 컬럼이 없음 |
| **예측 시점 재현** | 그 시점에 알 수 있는 특성만으로 행을 구성할 수 있는가 | 특성 절반이 사후 집계값 |
| **표본 수** | 행 1,000+ · 분류라면 소수 클래스 100+ 권장 | 양성 12건 ([Day 060](day-060.md) 문제 3) |
| **시간 구조** | 시계열인가? 그렇다면 시간 분리 가능한 기간인가 | 3주치 시계열 — test를 뗄 수 없음 |
| 개인정보 | 개인 식별 정보가 없는가 (과정 규정: 사용 금지) | 회원 상담 로그 |
| 적법성 | 출처·라이선스 확인 | 크롤링 금지 사이트 |

**1순위 후보는 MP1에서 구축한 여러분의 DB입니다** — 이미 적법성·개인정보·수집 파이프라인이
검증돼 있고, "수집→적재→예측"으로 포트폴리오 서사가 이어집니다. 이 문서들의 예시 프로젝트가
그랬듯(대기질 DB → 예보 모델). 부족할 때만 Kaggle·공공데이터에서 새로 고릅니다.

## ④ 단계별 실습

### Step 1. 문제 후보 3개 → 1개 (1~2교시)

후보 3개를 6기준 표로 심사하고 하나를 고릅니다. 예시 프로젝트(이 문서들의 대기질 DB)의 심사:

| 기준 | 판정 | 근거 |
|---|---|---|
| 타깃 정의 | ✅ | 익일 pm25 = `LEAD(pm25)` ([Day 051](day-051.md)) |
| 예측 시점 재현 | ✅ | 당일 관측 + 기상 예보(합법 미래 정보, [Day 064](day-064.md)) |
| 표본 수 | ✅ | 3,642행 · 나쁨 543일 (15%) |
| 시간 구조 | ⚠️→✅ | 시계열 — **시간 분리 + TSS 필수**로 설계에 반영 |
| 개인정보 | ✅ | 측정소 단위 집계 |
| 적법성 | ✅ | 공공누리 1유형 (MP1에서 확인) |

⚠️가 하나라도 "대응 불가"면 그 후보는 버립니다. 대응 가능한 ⚠️는 **기획서의 평가 설계로** 넘깁니다.

### Step 2. 기획서 작성 (3~4교시)

`docs/mp2_plan.md`. 예시 프로젝트로 채운 틀입니다 — 여러분의 문제로 바꿔 채우세요.

```markdown
# MP2 기획서 — 서울 초미세먼지 익일 예보

## 1. 문제 정의 (Day 051의 3요소)
- 입력: 예측일 당일의 관측(오염물 6종·기상 4종) + 익일 기상 예보 3종 + 측정소
- 출력: 익일 일평균 pm25 (회귀)
- 주 지표: MAE — ㎍/㎥ 단위 그대로 시민에게 설명 가능
- 보조 지표: RMSE(대형 오보 감시) · 나쁨재현율(경보 관점, 문턱 36)
- 지표 선택 근거: 생활 예보 서비스 — 평균 품질(주) + 나쁜 날 놓침(보조)을 함께 감시

## 2. 데이터
- 출처: MP1 구축 DB의 일평균 집계 · 2024-07-01 ~ 2026-06-29 · 3,642행
- 지문: MD5 21adc01f… · 추출 쿼리: docs/extract.sql
- 알려진 문제: 결측(최대 2%/열) → Pipeline 대치 · 서초구 점검 3일

## 3. 평가 설계 (실험 시작 전에 확정 — 이후 변경 금지)
- 분할: 시간 분리. train < 2026-01-01 ≤ test (test는 최종 1회)
- CV: TimeSeriesSplit(5) — 모든 모델·튜닝 비교의 심판
- 베이스라인: 전체 평균 · 내일=오늘 · (참고) 측정소×월 평균

## 4. 범위
### 필수: 요구 기능 7종 + 선형/LGBM 비교
### 확장: 예보 특성 · Optuna 30회 · 측정소별 편향 리포트
### 제외: 시간 단위 예보(일평균만) · '매우나쁨' 경보(표본 2건) · 서빙 API(MP3 범위)

## 5. 일정
| 일 | 목표 | 완료 기준 (퇴근 조건) |
|---|---|---|
| 071 | 기획·저장소·EDA·베이스라인 | 기획서 커밋 + 베이스라인 3종 점수 확보 |
| 072 | 파이프라인 + 모델 후보 비교 | MLflow run 6개+ · 후보 2종 CV 비교표 |
| 073 | 특성·튜닝 실험 + 최종 모델 | run 10개+ · 최종 모델 저장·검증 통과 |
| 074 | CLI·테스트·카드·보고서 | clone 리허설 통과 · 문서 3종 초안 |
| 075 | 발표 | 5분 발표 + 질의응답 |

## 6. 위험 요소
| 위험 | 대응 |
|---|---|
| 누수 의심 특성 발견 | 특성마다 "예측 시점" 칸을 기획서에 두고 매일 검문 |
| 성능이 베이스라인 근처 | **그 자체를 보고** (개선 실패의 분석도 성과) — 지표 바꿔치기 금지 |
```

## ⑤ 자주 하는 실수

### 데이터부터 찾고 문제를 나중에 정함

**증상** — "캐글에서 재밌는 데이터 찾았어요! 이걸로 뭘 예측하죠?"
**원인** — 문제 없는 데이터는 답 없는 질문입니다. 타깃·지표·쓸모가 전부 후처리로 꿰맞춰집니다.
**해결** — 순서는 문제 → 타깃 → 데이터. MP1 DB로 시작하면 이 순서가 자연스럽습니다 ("우리 데이터로 무엇을 미리 알면 좋은가?").

### 타깃 정의가 한 문장으로 안 됨

**증상** — "고객이 이탈할 것 같은지"를 예측 — '이탈'이 언제 기준인지, 어떻게 계산되는지 사람마다 다름.
**원인** — 타깃이 애매하면 뒤의 모든 것(라벨 생성·지표·평가)이 흔들립니다.
**해결** — "시점 T의 행에 대해, y = (T+1일의 pm25)" 처럼 **시점과 계산식**이 든 한 문장으로. 이 문장이 곧 `LEAD` 쿼리가 됩니다.

### 평가 설계를 실험 후에 정함

**증상** — 실험을 다 돌린 뒤 "MAE보단 R²가 좋아 보이니 R²로 보고".
**원인** — 결과를 보고 지표를 고르면 그것이 체리피킹입니다. 심사(방법론 30점)에서 가장 먼저 걸립니다.
**해결** — 오늘 기획서 3절에 지표·분할을 날짜와 함께 박고 "이후 변경 금지"를 명시. 바꿀 사정이 생기면 변경 이력을 남깁니다.

### 시간 구조를 무시한 분할 설계

**증상** — 시계열인데 기획서에 "train_test_split 8:2"라 적음.
**원인** — [Day 052](day-052.md)·[061](day-061.md)의 그 함정이 기획 단계에서 심어진 것입니다.
**해결** — EDA의 시간 구조 확인(자기상관)이 이 결정의 근거입니다. 시간이 흐르는 데이터면 시간 분리 + TSS, 근거와 함께 기획서에.

### 필수를 다 하기 전에 확장에 손댐

**증상** — 화요일에 SHAP·앙상블·대시보드를 벌여 놓고 목요일에 테스트·카드가 없음.
**원인** — 확장은 재밌고 필수는 지루하기 때문입니다. 하지만 채점표는 필수에 있습니다.
**해결** — 기획서 4절의 필수/확장/제외를 지키고, 확장은 **필수 완료 커밋 이후**에만 시작합니다.
