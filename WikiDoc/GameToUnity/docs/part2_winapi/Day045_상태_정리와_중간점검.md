## 2. 막히는 상황

어제 만든 `UpdateAnimation`을 다시 보자.

```cpp
void Character::UpdateAnimation()
{
    if (!m_onGround)
    {
        if (m_vy < 0) m_animator.Play("jump");
        else          m_animator.Play("fall");
    }
    else if (fabs(m_vx) > 0.1)
    {
        m_animator.Play(m_isRunning ? "run" : "walk");
    }
    else
    {
        m_animator.Play("idle");
    }
}
```

여기에 격투게임에 필요한 것들을 추가해 보자.

```cpp
    if (m_isDown)                          { ... }      // 쓰러짐
    else if (m_isGettingUp)                { ... }      // 기상
    else if (m_isHit)                      { ... }      // 피격
    else if (m_isGuarding)                 { ... }      // 가드
    else if (m_isAttacking && !m_onGround) { ... }      // 점프 공격
    else if (m_isAttacking && m_isCrouch)  { ... }      // 앉아 공격
    else if (m_isAttacking)                { ... }      // 서서 공격
    else if (m_isCrouch)                   { ... }      // 앉기
    else if (!m_onGround)                  { ... }      // 점프
    else if (fabs(m_vx) > 0.1)             { ... }      // 걷기
    else                                   { ... }      // 대기
```

**그리고 이런 규칙들이 코드 여기저기에 흩어진다.**

```
   "공격 중에는 이동 불가"          →  ProcessInput 안 어딘가
   "피격 중에는 입력 무시"          →  또 다른 곳
   "다운 중에는 아무것도 못 함"     →  또 다른 곳
   "가드 중에는 이동 속도 절반"     →  또 다른 곳
   "점프 중에는 앉기 불가"          →  또 다른 곳
```

```
   문제 ①  bool 플래그가 8개  →  2^8 = 256가지 조합
           그중 대부분은 있으면 안 되는 상태다
           (예: m_isDown && m_isAttacking)

   문제 ②  규칙이 코드에 흩어져 전체를 파악할 수 없다

   문제 ③  새 동작을 추가하면 모든 if 를 재검토해야 한다
```

```
   지금:   플래그 여러 개 + 조건문 사슬

   필요:   ① 상태는 항상 하나뿐
           ② 전이 규칙을 한 곳에 표로 정리
           ③ 코드가 그 표를 그대로 따르게
```

> **오늘은 코드를 쓰기 전에 표를 만든다.**

## 3. 개념

### 3-1. 상태 목록 정하기

**왜 필요한가** — 무엇이 상태이고 무엇이 아닌지 구분한다.

```
   ★ 상태(State)의 조건

   ① 그 순간 하나만 참이다
   ② 고유한 애니메이션이 있다
   ③ 입력에 대한 반응이 다르다
```

| 상태 | 애니메이션 | 이동 | 입력 | 설명 |
|---|---|:--:|:--:|---|
| `IDLE` | idle | X | O | 대기 |
| `WALK` | walk | O | O | 걷기 |
| `RUN` | run | O | O | 달리기 |
| `CROUCH` | crouch | X | O | 앉기 |
| `JUMP` | jump | O | 제한 | 상승 중 |
| `FALL` | fall | O | 제한 | 하강 중 |
| `ATTACK` | attack | **X** | **X** | 서서 공격 |
| `CROUCH_ATTACK` | c_attack | X | X | 앉아 공격 |
| `JUMP_ATTACK` | j_attack | O | X | 점프 공격 |
| `GUARD` | guard | X | 제한 | 가드 |
| `HIT` | hit | X(넉백만) | **X** | 피격 경직 |
| `DOWN` | down | X | X | 쓰러짐 |
| `GETUP` | getup | X | X | 기상 |
| `WIN` | win | X | X | 승리 포즈 |

**상태가 아닌 것**

```
   m_facingLeft   →  방향은 어느 상태에서든 가질 수 있다  →  변수
   m_hp           →  상태와 무관                          →  변수
   m_isRunning    →  WALK/RUN 을 상태로 나눴으면 불필요    →  제거
   m_jumpCount    →  JUMP 상태의 부가 정보                →  변수
```

> **"이것도 상태인가?"가 헷갈리면 위 3조건을 대입해 본다.**

### 3-3. 상태 진입/유지/이탈

**왜 필요한가** — 상태가 바뀔 때 해야 할 일이 있다.

```
   ┌─────────────────────────────────────────────────────┐
   │  Enter   상태에 들어올 때 한 번                       │
   │            애니메이션 재생, 속도 초기화, 타이머 시작   │
   │              ▼                                       │
   │  Update  매 프레임                                    │
   │            물리, 입력 처리, 전이 조건 확인            │
   │              ▼                                       │
   │  Exit    상태를 떠날 때 한 번                         │
   │            판정 박스 끄기, 이펙트 정리                │
   └─────────────────────────────────────────────────────┘
```

```cpp
void Character::ChangeState(State newState)
{
    if (m_state == newState) return;          // 같은 상태면 무시

    OnExitState(m_state);                     // 이탈

    m_prevState  = m_state;
    m_state      = newState;
    m_stateTimer = 0.0;                       // ★ 타이머 초기화

    OnEnterState(newState);                   // 진입
}
```

**`OnEnter` 예시**

```cpp
void Character::OnEnterState(State s)
{
    switch (s)
    {
    case STATE_IDLE:    m_animator.Play("idle");  m_vx = 0; break;
    case STATE_WALK:    m_animator.Play("walk");            break;
    case STATE_ATTACK:  m_animator.Play("attack", true);
                        m_vx = 0;                            break;
    case STATE_HIT:     m_animator.Play("hit", true);
                        m_hitStunTimer = HIT_STUN_TIME;      break;
    }
}
```

> **`Play(..., true)`** — 공격·피격은 항상 처음부터 재생해야 한다 (Day 43).

### 3-4. 상태 타이머

**왜 필요한가** — "0.3초 후 자동 전이" 같은 규칙에 필요하다.

```cpp
    double m_stateTimer = 0.0;

    // Update
    m_stateTimer += dt;

    // 예: 다운 상태는 1.2초 후 기상
    if (m_state == STATE_DOWN && m_stateTimer >= 1.2)
        ChangeState(STATE_GETUP);
```

| 상태 | 지속 시간 결정 방식 |
|---|---|
| ATTACK | 애니메이션 종료 |
| HIT | 고정 시간 (경직 시간) |
| DOWN | 고정 시간 |
| GETUP | 애니메이션 종료 |
| IDLE/WALK | 무제한 (입력으로 전이) |

### 3-6. 디버그 오버레이 — 개발의 필수 도구

**왜 필요한가** — 상태가 눈에 안 보이면 버그를 못 찾는다.

```
   ★ 게임 개발에서 디버그 표시는 "여유가 있으면"이 아니라
     "먼저 만드는 것"이다

   상태 이름을 화면에 띄우는 데 5분,
   그게 없어서 버그 찾는 데 2시간
```

**표시할 것**

| 항목 | 왜 |
|---|---|
| 현재 상태 + 경과 시간 | 전이가 제대로 되나 |
| 이전 상태 | 어디서 왔나 |
| 애니메이션 이름 + 프레임 | 상태와 애니메이션이 맞나 |
| 위치 / 속도 | 물리가 정상인가 |
| 바닥 접촉 / 점프 잔여 | 판정이 맞나 |
| 입력 상태 | 입력이 들어오나 |
| FPS / dt | 성능 문제인가 |

**상태 전이 히스토리**

```cpp
    struct StateLog { State from, to; double time; };

    StateLog m_history[16];
    int      m_historyCount = 0;

    // ChangeState 안
    if (m_historyCount < 16)
    {
        m_history[m_historyCount].from = m_state;
        m_history[m_historyCount].to   = newState;
        m_history[m_historyCount].time = m_core->GetTimer().GetTotalTime();
        m_historyCount++;
    }
    else
    {
        // 오래된 것부터 밀어낸다
        for (int i = 0; i < 15; i++) m_history[i] = m_history[i+1];
        m_history[15] = { m_state, newState, ... };
    }
```

```
   화면 표시 예

   전이 히스토리 (최근 5개)
     12.3s  IDLE   → WALK
     13.1s  WALK   → JUMP
     13.8s  JUMP   → FALL
     14.2s  FALL   → IDLE
     15.0s  IDLE   → ATTACK
```

> **이 히스토리가 "왜 저 상태로 갔지?"를 밝혀 준다.**

```cpp
void Character::ChangeState(State newState)
{
    if (m_state == newState) return;

    OnExitState(m_state);

    DebugLog("[State] %s -> %s (%.2fs)\n",
             g_stateNames[m_state], g_stateNames[newState], m_stateTimer);

    AddHistory(m_state, newState);

    m_prevState  = m_state;
    m_state      = newState;
    m_stateTimer = 0.0;

    OnEnterState(newState);
}
```

### Step 4 — 어제 로직을 상태로 옮기기 (최소한만)

```cpp
void Character::UpdateState(double dt)
{
    m_stateTimer += dt;

    // 공중/지상 전이만 우선 적용
    if (!m_onGround)
    {
        if (m_vy < 0 && m_state != STATE_JUMP)  ChangeState(STATE_JUMP);
        if (m_vy > 0 && m_state != STATE_FALL)  ChangeState(STATE_FALL);
    }
    else
    {
        if (m_state == STATE_JUMP || m_state == STATE_FALL)
            ChangeState(STATE_IDLE);

        if (fabs(m_vx) > 0.1)
        {
            if (m_state == STATE_IDLE) ChangeState(STATE_WALK);
        }
        else
        {
            if (m_state == STATE_WALK) ChangeState(STATE_IDLE);
        }
    }
}
```

### Step 7 — 전이 히스토리

```cpp
struct StateLog { State from, to; double time; };

    StateLog m_history[8];
    int      m_historyCount = 0;

void Character::AddHistory(State from, State to)
{
    double now = m_core->GetTimer().GetTotalTime();

    if (m_historyCount >= 8)
    {
        for (int i = 0; i < 7; i++) m_history[i] = m_history[i + 1];
        m_historyCount = 7;
    }

    m_history[m_historyCount].from = from;
    m_history[m_historyCount].to   = to;
    m_history[m_historyCount].time = now;
    m_historyCount++;
}

void Character::RenderHistory(Renderer& r) const
{
    if (!g_showHistory) return;

    int x = 420, y = 380;

    r.DrawTextF(x, y, RGB(255, 220, 120), "─ 전이 히스토리 ─"); y += 20;

    for (int i = 0; i < m_historyCount; i++)
    {
        r.DrawTextF(x, y, RGB(180, 200, 220),
                    "%6.1fs  %-8s -> %s",
                    m_history[i].time,
                    g_stateNames[m_history[i].from],
                    g_stateNames[m_history[i].to]);
        y += 16;
    }
}
```

**✅ 여기까지 실행하면** — 최근 8개 전이가 화면에 표시된다.

## 6. 자주 막히는 곳

| 증상 | 원인 | 해결 |
|---|---|---|
| 상태가 계속 바뀜 | 전이 조건이 서로 물림 | 로그로 어느 전이가 반복되는지 확인 |
| 애니메이션이 안 바뀜 | `OnEnterState` 미구현 | `switch`에 case 추가 |
| 같은 상태로 계속 전환 | `if (m_state == newState) return;` 누락 | 추가 |
| 상태 타이머가 안 맞음 | `ChangeState`에서 초기화 누락 | `m_stateTimer = 0` |
| 히스토리가 안 밀림 | 배열 시프트 오류 | 인덱스 확인 |
| 디버그 글자가 안 보임 | 배경색과 같음 | 어두운 사각형을 먼저 그린다 |
| 로그가 너무 많음 | 매 프레임 전환 | 전이 조건 재검토 |
| 상태가 늘어나니 헷갈림 | 표 없이 코드부터 씀 | **표를 먼저 그린다** |
