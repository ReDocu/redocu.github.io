## 2. 막히는 상황

어제 만든 것을 실행하고 손을 뗀다.


움직이려면 이 두 가지가 필요하다.

```

   ② 다시 그린다          InvalidateRect(hWnd, NULL, TRUE);
```

그런데 **누가 이걸 시켜 주는가?**

```
   콘솔 게임 (Day 21)                  창 프로그램 (지금)

   while (running)                     while (GetMessage(...))
   {                                   {
```

## 3. 개념

### 3-1. 화면 좌표계 — y가 아래로

**왜 필요한가** — 이걸 헷갈리면 별이 반대로 날아간다. 오늘 반드시 못 박는다.

```
   수학 좌표계                     화면(클라이언트) 좌표계

        y↑                         (0,0)──────────────▶ x
         │                           │
         │  (3, 2)                   │      ★ (120, 80)
         │    ●                      │
   ──────┼──────▶ x                  │
         │                           ▼ y
         │
```

| | 수학 | 화면 |
|---|---|---|
| 원점 | 가운데 (또는 임의) | **왼쪽 위** |
| x 증가 | 오른쪽 | 오른쪽 (같다) |
| **y 증가** | **위** | **아래** ← 반대! |
| 각도 증가 | 반시계 | 시계 (y가 뒤집혔으므로) |

```
   결과적으로 이런 차이가 생긴다

   "위로 이동"     →  y -= speed      (빼기!)
   "아래로 이동"   →  y += speed
   "45도 위로 발사" →  vy = -sin(45°) * P    (부호 반전, Day 66)
```

> **Day 12의 `map[y][x]`, Day 13의 `(dx, dy)`와 같은 방향이다.**
> 콘솔에서 이미 익힌 것이라 낯설지 않다.

**중심 기준으로 그리기**

```cpp
    // 좌상단 기준 (GDI 기본)
    Ellipse(hdc, x, y, x + 20, y + 20);

    // 중심 기준 (게임에서 편하다)
    int r = 10;
    Ellipse(hdc, x - r, y - r, x + r, y + r);
```

```
   좌상단 기준            중심 기준
   (x,y)                       (x,y)
     ┌──────┐                ┌───●───┐
     │      │                │       │
     │      │                │       │
     └──────┘                └───────┘

   게임에서는 중심 기준이 편하다
   → 충돌 판정, 회전, 크기 변경이 자연스럽다
```

### 3-2. `SetTimer` — 주기적 알람

**왜 필요한가** — Windows가 일정 간격으로 `WM_TIMER` 메시지를 보내 준다.

```cpp
    SetTimer(hWnd, 1, 16, NULL);
    //       ▲     ▲   ▲    ▲
    //       │     │   │    └── 콜백 함수 (NULL = WM_TIMER로 받겠다)
    //       │     │   └────── 간격 (밀리초)
    //       │     └────────── 타이머 ID (여러 개 쓸 때 구분)
    //       └──────────────── 대상 창
```

```cpp
    case WM_TIMER:
        if (wParam == 1)                  // 타이머 ID
        {
            // 여기가 Update()
            g_starX += 3;

            InvalidateRect(hWnd, NULL, TRUE);      // 다시 그려 달라
        }
        return 0;
```

```cpp
    KillTimer(hWnd, 1);                   // 타이머 해제 (WM_DESTROY에서)
```

```
   ┌────────────────────────────────────────────────────┐
   │  SetTimer(hWnd, 1, 16, NULL)                        │
   │        ↓                                            │
   │  16ms 마다 Windows가 WM_TIMER 를 큐에 넣는다         │
   │        ↓                                            │
   │  WM_TIMER  →  좌표 갱신  →  InvalidateRect          │
   │                                    ↓                │
   │                               WM_PAINT  →  그리기    │
   │        ↑                                            │
   │        └───────── 16ms 후 반복 ────────────────────┘
```

**타이머 여러 개**

```cpp
    SetTimer(hWnd, TIMER_UPDATE, 16,   NULL);      // 화면 갱신용
    SetTimer(hWnd, TIMER_SPAWN,  1000, NULL);      // 1초마다 적 생성

    case WM_TIMER:
        switch (wParam)
        {
        case TIMER_UPDATE: UpdateGame(); break;
        case TIMER_SPAWN:  SpawnEnemy(); break;
        }
        return 0;
```

### 3-3. `InvalidateRect` — 다시 그리기 요청

**왜 필요한가** — 좌표를 바꿔도 화면은 저절로 안 바뀐다.

```cpp
    InvalidateRect(hWnd, NULL, TRUE);
    //             ▲     ▲     ▲
    //             │     │     └── 배경을 지울 것인가
    //             │     └──────── 어느 영역 (NULL = 전체)
    //             └────────────── 대상 창
```

```
   InvalidateRect 를 안 하면

   좌표:  (100, 80)  →  (103, 80)  →  (106, 80)  →  ...
   화면:  (100, 80)에 그려진 그대로 멈춰 있다

   ★ 데이터는 바뀌는데 화면이 안 따라온다
```

**세 번째 인자 `bErase`**

| 값 | 동작 |
|:--:|---|
| `TRUE` | `WM_ERASEBKGND`를 보내 배경을 지운다 → **깜빡임의 원인** |
| `FALSE` | 배경을 안 지운다 → 잔상이 남는다 |

```
   TRUE  :  지움 → (빈 화면 순간!) → 그림     ← 깜빡인다
   FALSE :  그림 (지우지 않음)                ← 이전 그림이 남는다

   ★ 둘 다 문제다. 이 딜레마가 Day 36~37의 주제다
```

**부분 무효화 — 최적화**

```cpp
    RECT dirty = { x - 20, y - 20, x + 20, y + 20 };
    InvalidateRect(hWnd, &dirty, TRUE);       // 그 영역만 다시 그린다
```

> 부분 갱신은 깜빡임을 줄이지만, 움직이는 물체가 많아지면 관리가 복잡해진다.
> **Day 37의 더블버퍼링이 근본 해결책이다.**

### 3-4. `UpdateWindow` — 즉시 그리기

**왜 필요한가** — `InvalidateRect`는 요청만 한다. 언제 그려질지는 Windows가 정한다.

```cpp
    InvalidateRect(hWnd, NULL, TRUE);
    UpdateWindow(hWnd);                       // ★ 지금 당장 WM_PAINT 처리
```

```
   InvalidateRect 만:  "더러워졌다" 표시 → 큐가 한가할 때 WM_PAINT
   + UpdateWindow    :  즉시 WndProc(WM_PAINT) 를 직접 호출
```

> 게임에서는 대부분 `InvalidateRect`만으로 충분하다.
> 다만 **정확한 프레임 제어**가 필요하면 `UpdateWindow`를 쓴다.

### 3-5. ⚠️ 타이머의 한계 — 게임 루프로는 부족하다

**왜 필요한가** — 오늘 배우는 방식을 **Day 38에서 버린다.** 그 이유를 알아 둔다.

**① 정확도가 낮다**

```
   SetTimer(hWnd, 1, 16, NULL)  →  실제로는 15.6ms 단위로 반올림된다

   요청 16ms  →  실제 약 15.6ms 또는 31.2ms
   요청 10ms  →  실제 약 15.6ms  (더 짧게 못 한다)

   ★ Windows 기본 타이머 해상도가 약 15.6ms (1초/64)
```

**② 메시지 큐에 밀린다**

```
   WM_TIMER 는 우선순위가 가장 낮다

   다른 메시지가 많으면  →  타이머 메시지가 뒤로 밀린다
   처리가 오래 걸리면    →  타이머 메시지가 합쳐진다 (누락)

   ★ 정확한 프레임 간격을 보장할 수 없다
```

**③ 델타 타임을 직접 재야 한다**

```
   16ms 간격을 요청했지만 실제로는 15.6ms, 31.2ms, 15.6ms...
   → 이동량을 고정값으로 하면 속도가 들쭉날쭉해진다
   → 결국 시간을 직접 재야 한다 (Day 21에서 배운 것)
```

**④ 제어권이 없다**

```
   게임 루프의 이상적인 형태

   while (running)
   {
       ProcessInput();     ← 내가 순서를 정한다
       Update(dt);
       Render();
   }

   타이머 방식

   WM_TIMER 가 올 때마다 조각조각 실행
   → 언제 무엇이 실행되는지 통제가 어렵다
```

| | 타이머 (오늘) | 게임 루프 (Day 38) |
|---|---|---|
| 정확도 | 약 15.6ms | 마이크로초 |
| 제어권 | Windows | **나** |
| 프레임 보장 | X | O |
| 구현 난이도 | 쉽다 | 중간 |
| 적합한 곳 | UI 갱신, 저빈도 이벤트 | **게임** |

> **오늘은 타이머로 애니메이션의 원리를 익힌다.**
> Day 38에서 `PeekMessage` 루프로 바꾸면 이 한계들이 전부 해결된다.

### 3-6. 시간 재기 — 델타 타임 (콘솔에서 하던 그대로)

**왜 필요한가** — 타이머 간격이 부정확하므로 실제 흐른 시간을 재야 한다.

```cpp
#include <windows.h>

DWORD g_prevTick = 0;

    case WM_CREATE:
        g_prevTick = GetTickCount();
        return 0;

    case WM_TIMER:
        {
            DWORD now = GetTickCount();
            double dt = (now - g_prevTick) / 1000.0;      // 초 단위
            g_prevTick = now;

            if (dt > 0.1) dt = 0.1;                       // 클램프 (Day 21)

            g_starX += g_speed * dt;                      // ★ 시간에 비례

            InvalidateRect(hWnd, NULL, TRUE);
        }
        return 0;
```

| 함수 | 정밀도 | 비고 |
|---|---|---|
| `GetTickCount()` | 약 15.6ms | 부팅 후 밀리초. 49.7일에 한 번 오버플로 |
| `GetTickCount64()` | 약 15.6ms | 오버플로 없음. **이걸 쓴다** |
| `timeGetTime()` | 1ms | `winmm.lib` 필요 |
| **`QueryPerformanceCounter`** | 마이크로초 | **Day 38에서 쓴다** |

### 3-7. 움직임 패턴 세 가지

**왜 필요한가** — 애니메이션의 기본형. 앞으로 계속 변형해서 쓴다.

**① 직선 이동 + 화면 밖 래핑**

```cpp
    g_starX += g_speed * dt;

    if (g_starX > clientW + 20)
        g_starX = -20;                    // 반대편에서 다시 등장
```

**② 왕복 (반사)**

```cpp
    g_boxY += g_boxVy * dt;

    if (g_boxY < 20)          { g_boxY = 20;          g_boxVy = -g_boxVy; }
    if (g_boxY > clientH - 20) { g_boxY = clientH - 20; g_boxVy = -g_boxVy; }
```

> Day 22의 벽 반사와 똑같다. 위치 보정도 그대로.

**③ 원운동**

```cpp
    g_angle += g_angularSpeed * dt;        // 라디안/초

    int cx = clientW / 2;
    int cy = clientH / 2;
    int r  = 100;

    g_circleX = cx + (int)(cos(g_angle) * r);
    g_circleY = cy + (int)(sin(g_angle) * r);
```

```
   각도 θ 에서의 원 위의 점

            (cx, cy + r)
                 ●
                 │
   (cx - r) ●────┼────● (cx + r)      x = cx + cos(θ) × r
                 │                     y = cy + sin(θ) × r
                 ●
            (cx, cy - r)

   ★ 화면 y가 아래로 증가하므로 시계 방향으로 돈다
```

> **Day 66(포탄 발사)** 에서 이 계산을 정식으로 다룬다.

## 4. 따라 만들기

### Step 1 — 타이머 켜기

```cpp
#define TIMER_MAIN 1

int    g_starX = 50;
int    g_starY = 150;
int    g_tickCount = 0;

    case WM_CREATE:
        SetTimer(hWnd, TIMER_MAIN, 16, NULL);      // 약 60fps 목표
        return 0;

    case WM_TIMER:
        if (wParam == TIMER_MAIN)
        {
            g_tickCount++;
            g_starX += 3;

            InvalidateRect(hWnd, NULL, TRUE);
        }
        return 0;

    case WM_DESTROY:
        KillTimer(hWnd, TIMER_MAIN);               // ★ 반드시 해제
        PostQuitMessage(0);
        return 0;
```

```cpp
    // WM_PAINT 안
    DrawStar(hdc, g_starX, g_starY, 20, RGB(255, 220, 0));
```

아무것도 안 눌러도 계속 간다.

### Step 4 — 델타 타임 적용

```cpp
DWORD  g_prevTick = 0;
double g_totalTime = 0.0;
double g_starSpeed = 150.0;              // 초당 150픽셀

    case WM_CREATE:
        g_prevTick = GetTickCount();
        SetTimer(hWnd, TIMER_MAIN, 16, NULL);
        return 0;

    case WM_TIMER:
        {
            DWORD now = GetTickCount();
            double dt = (now - g_prevTick) / 1000.0;
            g_prevTick = now;

            if (dt > 0.1) dt = 0.1;

            g_totalTime += dt;
            g_tickCount++;

            g_starXd += g_starSpeed * dt;         // double 로 유지

            if (g_starXd > g_clientW + 30)
                g_starXd = -30;

            InvalidateRect(hWnd, NULL, TRUE);
        }
        return 0;
```

> **좌표는 `double`로, 그릴 때만 `(int)`** — Day 22의 원칙 그대로.

**✅ 여기까지 실행하면** — 타이머 간격을 바꿔도(`SetTimer`의 16 → 33) **이동 속도가 같다.**

### Step 6 — 원운동 추가

```cpp
#include <cmath>

double g_angle = 0.0;
double g_angularSpeed = 1.5;             // 라디안/초 (약 86도/초)

    // WM_TIMER 안
    g_angle += g_angularSpeed * dt;

    if (g_angle > 6.283185)              // 2π
        g_angle -= 6.283185;
```

```cpp
    // WM_PAINT 안
    int cx = g_clientW / 2;
    int cy = g_clientH / 2;
    int r  = 120;

    int px = cx + (int)(cos(g_angle) * r);
    int py = cy + (int)(sin(g_angle) * r);

    // 궤도 표시
    HPEN dotPen = CreatePen(PS_DOT, 1, RGB(80, 80, 100));
    HPEN oldPen = (HPEN)SelectObject(hdc, dotPen);
    SelectObject(hdc, GetStockObject(NULL_BRUSH));
    Ellipse(hdc, cx - r, cy - r, cx + r, cy + r);
    SelectObject(hdc, oldPen);
    DeleteObject(dotPen);

    // 도는 원
```

### Step 8 — 속도 조절과 일시정지

```cpp
bool g_paused = false;

    case WM_KEYDOWN:
        switch (wParam)
        {
        case VK_SPACE:
            g_paused = !g_paused;
            g_prevTick = GetTickCount();          // ★ dt 폭증 방지
            break;

        case VK_OEM_PLUS:
        case VK_ADD:
            g_starSpeed *= 1.2;
            break;

        case VK_OEM_MINUS:
        case VK_SUBTRACT:
            g_starSpeed /= 1.2;
            break;

        case VK_ESCAPE:
            PostMessage(hWnd, WM_CLOSE, 0, 0);
            break;
        }
        return 0;

    case WM_TIMER:
        {
            DWORD now = GetTickCount();
            double dt = (now - g_prevTick) / 1000.0;
            g_prevTick = now;

            if (g_paused) { InvalidateRect(hWnd, NULL, TRUE); return 0; }

            // ... 갱신 ...
        }
        return 0;
```

**✅ 여기까지 실행하면** — SPACE로 멈추고, `+`/`-`로 속도를 바꿀 수 있다.
**일시정지를 풀어도 별이 순간이동하지 않는다** (Day 25의 그 처리).

### Step 9 — 타이머 여러 개

```cpp
#define TIMER_MAIN   1
#define TIMER_SPAWN  2

    case WM_CREATE:
        SetTimer(hWnd, TIMER_MAIN,  16,   NULL);
        SetTimer(hWnd, TIMER_SPAWN, 1000, NULL);      // 1초마다
        return 0;

    case WM_TIMER:
        switch (wParam)
        {
        case TIMER_MAIN:
            UpdateAnimation();
            InvalidateRect(hWnd, NULL, TRUE);
            break;

        case TIMER_SPAWN:
            SpawnRandomStar();                        // 1초마다 별 하나
            break;
        }
        return 0;

    case WM_DESTROY:
        KillTimer(hWnd, TIMER_MAIN);
        KillTimer(hWnd, TIMER_SPAWN);
        PostQuitMessage(0);
        return 0;
```

**✅ 여기까지 실행하면** — 1초마다 새 별이 생긴다.

### Step 10 — 깜빡임 관찰 (내일의 씨앗)

`InvalidateRect`의 세 번째 인자를 바꿔 가며 관찰한다.

```cpp
    InvalidateRect(hWnd, NULL, TRUE);      // 배경 지움 → 깜빡임
    InvalidateRect(hWnd, NULL, FALSE);     // 배경 안 지움 → 잔상
```

**✅ 여기까지 실행하면**

```
   TRUE  :  움직이는 물체가 심하게 깜빡인다
   FALSE :  잔상이 줄줄이 남는다 (별이 지나간 자리가 다 남는다)
```

> **둘 다 문제다.** 이 딜레마가 **Day 36~37의 주제**다.
> 지금은 `TRUE`로 두고 깜빡임을 감수한다.

## 6. 자주 막히는 곳

| 증상 | 원인 | 해결 |
|---|---|---|
| 안 움직임 | **`InvalidateRect` 누락** | `WM_TIMER`에서 호출 |
| 안 움직임 | `SetTimer` 누락 또는 ID 불일치 | `wParam == TIMER_ID` 확인 |
| 좌표는 바뀌는데 화면 그대로 | `WM_PAINT`에서 옛 변수 참조 | 변수명 확인 |
| 너무 빠름/느림 | 이동량 또는 타이머 간격 | 델타 타임 적용 |
| 위아래가 반대 | y축 방향 착각 | 위는 `-`, 아래는 `+` |
| 일시정지 풀면 순간이동 | `dt` 폭증 | 재개 시 `g_prevTick` 갱신 |
| 종료 후에도 타이머 동작 | `KillTimer` 누락 | `WM_DESTROY`에서 해제 |
| 5ms로 해도 15.6ms | 타이머 해상도 한계 | 정상. Day 38에서 해결 |
| 심하게 깜빡임 | `bErase = TRUE` | 정상. **Day 37에서 해결** |
| 잔상이 남음 | `bErase = FALSE` | 정상. **Day 37에서 해결** |
| `cos`/`sin` 오류 | `<cmath>` 누락 | 포함 |

## 7. 정리

### 오늘 배운 것

| 개념 | 한 줄 요약 |
|---|---|
| **화면 좌표계** | 원점은 왼쪽 위, **y는 아래로 증가** |
| 중심 기준 그리기 | `x-r, y-r, x+r, y+r` — 게임에서 편하다 |
| `SetTimer` / `WM_TIMER` | 주기적으로 메시지를 받는다 |
| `KillTimer` | `WM_DESTROY`에서 반드시 해제 |
| **`InvalidateRect`** | "다시 그려 달라" 요청. **없으면 화면이 안 바뀐다** |
| `bErase` | `TRUE`=깜빡임 / `FALSE`=잔상. **둘 다 문제** |
| 델타 타임 | 타이머가 부정확하므로 실제 시간을 잰다 |
| 움직임 3종 | 직선+래핑 / 왕복 / 원운동 |
| **타이머의 한계** | 15.6ms 해상도, 우선순위 낮음, 제어권 없음 |
