## ① 학습 목표

이 레슨을 마치면 이렇게 할 수 있습니다.

- `pipeline` 세 줄로 사전학습 모델 추론을 실행할 수 있다.
- pipeline이 **토크나이저 + 모델 + 후처리**의 포장임을 해부할 수 있다.
- 모델의 **학습 범위 밖 입력이 만드는 조용한 실패**를 재현하고 경계할 수 있다.
- 모델 허브에서 **모델 카드와 라이선스를 확인**하는 절차를 안다 (실무 의무).

## ② 왜 필요한가

[Day 083](day-083.md)에서 우리는 ImageNet으로 사전학습된 ResNet을 빌려 245장으로 분류기를
만들었습니다. 텍스트 세계에는 그 "빌려 쓰기"가 훨씬 크게 조직화되어 있습니다 —
**Hugging Face 허브**에는 수십만 개의 사전학습 모델이 올라와 있고, 감성 분류·요약·번역·
임베딩이 이미 만들어져 있습니다.

MLOps 엔지니어 관점에서 이것은 관점의 전환입니다:

```
대단원 03:  모델을 "만드는" 일 (데이터 → 학습 → 평가)
오늘:       모델을 "조달하는" 일 (허브 검색 → 카드 확인 → 라이선스 확인 → 추론 → 서빙)
```

실무 텍스트 과제의 첫 질문은 "어떻게 학습시키지?"가 아니라 **"이미 있는 모델로 되나?"**
입니다. 그리고 조달에는 조달의 규율이 있습니다 — 출처·용도·라이선스 확인. [Day 018](../01-python-data/day-018.md)에서
데이터를 수집할 때 저작권·robots.txt를 확인했듯이, 모델을 가져올 때도 같은 절차가 있습니다.
오늘 그 규율까지 포함해 "받아서 쓰는 법"을 완성합니다.

## ③ 개념 설명

### pipeline — 3층 포장

```
pipeline("sentiment-analysis", model="...")
  = ① 토크나이저 (문장 → ID들)          ← Day 087
  + ② 모델      (ID들 → 로짓)           ← Day 086의 Transformer
  + ③ 후처리    (로짓 → {"label", "score"})
```

새 마법이 아니라 이번 주 배운 부품의 **포장**입니다. 포장은 프로토타입에 좋고,
서빙([Day 100](day-100.md))에서는 필요에 따라 뜯어서 씁니다.

### Auto 클래스 — 이름 하나로 쌍 맞추기

| 클래스 | 가져오는 것 |
|---|---|
| `AutoTokenizer.from_pretrained(name)` | 그 모델의 토크나이저 (어휘집 포함) |
| `AutoModel.from_pretrained(name)` | 몸통 (문맥 벡터까지) — 어제 임베딩에 사용 |
| `AutoModelForSequenceClassification` | 몸통 + **분류 머리** — 내일 파인튜닝에 사용 |

`from_pretrained(같은 이름)` 이 [Day 087](day-087.md)의 "모델과 토크나이저는 한 몸" 원칙을
코드로 보장합니다. 파일은 로컬 캐시(`~/.cache/huggingface`)에 저장되어 두 번째부터는 다운로드가 없습니다.

### 모델 카드와 라이선스 — 조달의 의무

[Day 069](../03-machine-learning/day-069.md)에서 우리가 **쓴** 모델 카드를, 오늘은 **읽는** 입장입니다.
허브에서 모델을 고르면 최소 네 칸을 확인합니다:

| 확인 | 왜 | 오늘 예 (klue/bert-base) |
|---|---|---|
| 학습 데이터·언어 | 범위 밖 입력 = 조용한 실패 (실습 B) | 한국어 말뭉치 (뉴스·위키 등) |
| 용도·비대상 | 우리 과제에 맞나 | 한국어 이해 계열 과제의 몸통 |
| **라이선스** | 상업 서비스 탑재 가능 여부 | CC-BY-SA-4.0 (작성 시점 기준 — **직접 확인**) |
| 평가 결과 | 기대 성능의 근거 | KLUE 벤치마크 수치 |

> 라이선스는 법무 이슈입니다. Apache-2.0/MIT(대체로 자유), CC-BY-SA(동일조건 공유 —
> 파생물 공개 의무 검토), 연구 전용/독점 라이선스(상업 불가)가 섞여 있습니다.
> **모델을 고른 근거와 라이선스 확인 기록을 남기는 것**까지가 조달입니다 (MP3 기획서 항목).

## ④ 단계별 실습

`day088_hub.py` 에 이어 붙입니다.

### Step 1. 세 줄로 감성 분류 (1교시)

```python
# day088_hub.py — Hugging Face: 받아서 쓰는 법
from transformers import pipeline

print("== A. 세 줄로 감성 분류 ==")
clf = pipeline("sentiment-analysis",
               model="distilbert-base-uncased-finetuned-sst-2-english")
result = clf(["This air quality forecast service is amazing!",
              "The API keeps crashing and nobody fixed it."])
for r in result:
    print(f"  {r['label']:<8} {r['score']:.3f}")
```

실행 결과:

```
== A. 세 줄로 감성 분류 ==
  POSITIVE 1.000
  NEGATIVE 1.000
```

우리가 안 한 것을 세어 보세요: 데이터 수집 0, 라벨링 0, 학습 0. 영어 감성 분류가
**조달 즉시 확신도 1.000으로** 동작합니다. `model=` 을 명시한 것에 주목 — 생략해도
기본 모델로 돌아가지만, 재현성([Day 066](../03-machine-learning/day-066.md))을 배운 우리는
버전 고정과 같은 이유로 모델 이름을 박습니다.

### Step 2. 조용한 실패 재현 — 학습 범위 밖 입력 (2교시)

이 영어 모델에 한국어를 넣으면 어떻게 될까요? 에러가 날까요?

```python
print("\n== B. 같은 모델에 한국어를 넣으면? ==")
result = clf(["이 서비스 정말 최고예요!", "최악이에요. 환불해 주세요."])
for r in result:
    print(f"  {r['label']:<8} {r['score']:.3f}")
```

실행 결과:

```
== B. 같은 모델에 한국어를 넣으면? ==
  POSITIVE 0.985
  POSITIVE 0.715
```

**"최악이에요. 환불해 주세요."가 POSITIVE 0.715.** 에러는 없습니다 — [Day 087](day-087.md)
Step 2에서 봤듯 한국어는 자모 조각으로 부서져 들어가고, 모델은 본 적 없는 입력에
아무 숫자나 냅니다. 첫 문장이 맞은 것(0.985)은 우연이라 더 위험합니다 — "테스트해 봤는데
되던데요?"가 이렇게 만들어집니다. **모델 카드의 학습 범위(languages: en)를 읽는 것**이
이 사고의 유일한 예방입니다.

### Step 3. 한국어 모델로 빈칸 맞히기 — 사전학습이 배운 것 (3~4교시)

klue/bert-base의 원래 특기(사전학습 과제였던 빈칸 맞히기)를 시켜 봅니다.

```python
print("\n== C. 한국어 모델로 빈칸 맞히기 — 사전학습이 배운 것 ==")
fill = pipeline("fill-mask", model="klue/bert-base")
for r in fill("서울의 [MASK]가 심각하다")[:5]:
    print(f"  {r['score']:.3f}  {r['sequence']}")
```

실행 결과:

```
== C. 한국어 모델로 빈칸 맞히기 — 사전학습이 배운 것 ==
  0.447  서울의 미세먼지 가 심각하다
  0.050  서울의 메르스 가 심각하다
  0.037  서울의 위기 가 심각하다
  0.025  서울의 고령화 가 심각하다
  0.022  서울의 가 심각하다
```

1위가 **미세먼지(0.447)** — 우리 과정 전체의 주제를 모델이 이미 알고 있습니다.
누가 가르친 게 아니라, 한국어 말뭉치에서 "서울의 ___가 심각하다" 자리에 미세먼지가
압도적으로 자주 나왔기 때문입니다. **사전학습 = 언어와 세상 지식의 압축**이라는 것,
그리고 내일 파인튜닝이 이 지식 위에 얹힌다는 것 — 이 결과 하나가 W18의 요지입니다.

(로드 시 `bert.pooler.*` 등 UNEXPECTED 안내가 뜹니다 — 과제(fill-mask)에 필요 없는
부품이 버려진다는 뜻으로 정상입니다. 어제 본 것과 같은 "머리 갈아 끼우기"의 흔적입니다.)

### Step 4. 포장 뜯어 보기 (5교시)

```python
print("\n== D. pipeline의 정체 — 어제 배운 것의 포장 ==")
print("pipeline = 토크나이저(Day 087) + 모델 + 후처리(라벨 변환)를 한 상자로")
print(f"클래스: {type(clf.model).__name__} / {type(clf.tokenizer).__name__}")
print(f"라벨 사전: {clf.model.config.id2label}")
```

실행 결과:

```
== D. pipeline의 정체 — 어제 배운 것의 포장 ==
pipeline = 토크나이저(Day 087) + 모델 + 후처리(라벨 변환)를 한 상자로
클래스: DistilBertForSequenceClassification / BertTokenizer
라벨 사전: {0: 'NEGATIVE', 1: 'POSITIVE'}
```

상자 안은 낯익은 부품입니다. `id2label` — 로짓의 0/1번 자리를 사람 말로 바꾸는 사전 —
까지 모델 설정에 들어 있습니다. 서빙 API가 응답에 라벨을 담을 때 이 사전을 쓰게 됩니다.

### Step 5. 허브에서 모델 카드 읽기 (6~7교시)

브라우저에서 [huggingface.co/klue/bert-base](https://huggingface.co/klue/bert-base)를 열고
③의 네 칸(학습 데이터 · 용도 · **라이선스** · 평가)을 직접 확인하세요. 그리고 오늘 쓴
두 모델에 대해 `docs/model_sourcing.md` 에 조달 기록을 남깁니다:

|---|---|---|---|---|
| klue/bert-base | 한국어 이해 몸통 (파인튜닝 재료) | CC-BY-SA-4.0 | 한국어 말뭉치 | 2026-.. |
| distilbert-...-sst-2-english | 영어 감성 (데모용) | Apache-2.0 | 영어(SST-2) — **한국어 비대상** | 2026-.. |

## ⑤ 자주 하는 실수

### 모델을 명시하지 않고 pipeline을 씀

**증상** — `pipeline("sentiment-analysis")` — 오늘은 되는데 몇 달 뒤 기본 모델이 바뀌어 결과가 달라짐.
**원인** — 기본 모델은 라이브러리가 정하는 값이지 여러분의 선택이 아닙니다.
**해결** — 항상 `model="..."` 명시 + 조달 기록. [Day 066](../03-machine-learning/day-066.md) 재현성 4요소에서 "모델 출처"가 추가된 셈입니다 (엄밀하게는 리비전 해시까지: `revision="..."`).

### 범위 밖 입력을 확신도로 걸러낼 수 있다고 믿음

**증상** — "확신도 0.7 이상만 쓰면 되지 않나요?" — Step 2에서 한국어 오답이 0.715, 우연 정답이 0.985였습니다.
**원인** — 범위 밖 입력에 대한 확신도는 **보정되지 않은 무의미한 숫자**입니다.
**해결** — 입력이 모델 범위 안인지(언어·도메인·형식)를 확신도 이전에 검증합니다. 서빙에서는 입력 검증 계층([Day 092](day-092.md)·[097](day-097.md))의 일입니다.

### 라이선스를 확인하지 않고 서비스에 탑재

**증상** — 출시 직전 법무 검토에서 "이 모델 연구 전용입니다" — 모델 교체로 일정 붕괴.
**원인** — 허브의 모델이 전부 자유 라이선스라는 착각.
**해결** — 조달 시점에 라이선스를 기록(Step 5)하고, CC-BY-SA(동일조건)·비상업 조건은 서비스 형태와 대조해 판단을 문서로 남깁니다.

### 첫 실행이 느리다고 매번 느린 줄 앎

**증상** — "pipeline 한 번에 2분 걸리던데 서빙 불가능 아닌가요?"
**원인** — 첫 실행은 **다운로드**(수백 MB)가 포함된 시간입니다. 이후에는 로컬 캐시에서 로드됩니다.
**해결** — 다운로드(1회)·로드(프로세스 시작마다 수 초)·추론(요청마다 수십 ms)을 구분해 재세요. 이 3단 구분이 [Day 096](day-096.md) 서버 수명주기 설계의 뼈대가 됩니다.

### LOAD REPORT의 UNEXPECTED를 에러로 오해

**증상** — `cls.predictions.* UNEXPECTED` 를 보고 "모델이 깨졌다"며 재다운로드를 반복.
**원인** — 저장소에는 사전학습 과제용 머리까지 들어 있는데, 지금 용도(AutoModel 등)에 필요 없는 부분이 버려진다는 **안내**입니다.
**해결** — 어떤 키가 "새로 초기화"되는지가 중요한 쪽입니다 — 내일 분류 머리를 새로 달 때 그 경고를 일부러 확인합니다.
