## ② 왜 필요한가

[Day 054](day-054.md)에서 Lasso의 α를 고르다 멈췄던 것을 기억하나요? "test로 고르면 안 된다"까지는
알았는데, 그럼 **무엇으로** 고르나? — train에서 떼어낸 검증 세트입니다. 그런데 여기 함정이 있습니다.

```
당신:  검증 AUC 0.929입니다.
동료:  어? 난 같은 코드로 0.954 나왔는데?
당신:  ...seed가 달랐네요.
```

검증 세트 하나로 잰 점수는 **어느 20%가 뽑혔느냐는 운**에 좌우됩니다. 모델 A(0.94)와 B(0.93)를
비교한다면서 실제로는 ±0.01의 운을 비교하고 있다면, 튜닝 전체가 동전 던지기입니다.
내일(Day 062) 수백 개의 하이퍼파라미터 조합을 비교하려면, 오늘 **점수의 오차 막대**부터
만들 줄 알아야 합니다. 그것이 교차검증(cross-validation)입니다.

그리고 우리 데이터는 시계열이라 한 겹이 더 있습니다 — **잘못된 교차검증은 정밀하게 부풀려진
점수**를 줍니다. 오늘 그 규모를 직접 잽니다 (스포일러: 0.944 vs 진짜 0.818).

## ③ 개념 설명

### K-Fold — 모두가 한 번씩 시험지가 된다

```
train 데이터를 5조각으로:      [①][②][③][④][⑤]

시험 1:  검증=① 학습=②③④⑤     → 점수₁
시험 2:  검증=② 학습=①③④⑤     → 점수₂
…
시험 5:  검증=⑤ 학습=①②③④     → 점수₅

결과: 평균 ± 표준편차            (점수 하나가 아니라 분포!)
```

| 얻는 것 | 뜻 |
|---|---|
| 평균 | 운이 덜 낀 성능 추정 |
| **표준편차** | 점수의 불확실성 — "0.944 ± 0.008" 의 ± 부분 |
| 비용 | 학습을 K번 (5-Fold = 5배 시간) |

두 모델의 평균 차이가 표준편차 안에 있으면 "차이 없음"으로 읽는 것이 안전합니다.

### Stratified — 조각마다 클래스 비율 유지

무작위로 조각내면 운 나쁜 조각에는 양성이 몰리거나 사라질 수 있습니다.
StratifiedKFold는 **모든 조각의 클래스 비율을 원본과 같게** 맞춥니다. 분류에서는 기본 선택입니다.

### TimeSeriesSplit — 시계열의 유일한 정직

그런데 K-Fold에는 우리가 이미 아는 문제가 숨어 있습니다 — 조각을 무작위로 섞으면
**검증 조각의 이웃 날짜가 학습 조각에** 들어갑니다. [Day 052](day-052.md)의 시점 누수가
교차검증 안에서 재발하는 것입니다.

```
TimeSeriesSplit(5):   train은 자라고, 검증은 항상 그 뒤 시점

폴드1:  [tr――]        [va]
폴드2:  [tr――――――]    [va]
폴드3:  [tr――――――――――][va]
…                              ← 모든 폴드가 "과거로 배워 미래를 검증"
```

| 상황 | 올바른 분할 |
|---|---|
| 행이 서로 독립 (환자별, 이미지별) | KFold / StratifiedKFold |
| **시간이 흐르는 데이터 (우리!)** | **TimeSeriesSplit** |
| 그룹이 있는 데이터 (같은 환자의 여러 검사) | GroupKFold (그룹째로 나눔) |

### 세 개의 데이터, 세 개의 역할

이제 데이터 역할 분담이 완성됩니다. 이 그림은 MP2와 실무에서 그대로 씁니다.

```
전체 데이터
├── train (2024-07 ~ 2025-12) ── 학습 + 교차검증 (모델·튜닝 선택 전부 여기서)
│     └── CV가 내부에서 학습/검증을 반복
└── test  (2026-01 ~)         ── 금고. 모든 선택이 끝난 뒤 최종 1회
```

## ④ 단계별 실습

`day061_cv.py` 에 이어 붙입니다.

### Step 1. 검증 한 번짜리 점수는 복불복 (1교시)

```python
# day061_cv.py — 교차검증: 점수의 신뢰구간과 올바른 분할
import numpy as np
import pandas as pd
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import roc_auc_score
from sklearn.model_selection import (KFold, StratifiedKFold, TimeSeriesSplit,
                                     cross_val_score, train_test_split)
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

pd.set_option("display.width", 140)
df = pd.read_csv("data/air_daily.csv", parse_dates=["date"])
F10 = ["pm10", "pm25", "o3", "no2", "co", "so2", "temp", "humidity", "wind_speed", "precip"]
d = df.dropna(subset=F10).copy()
d["bad_next"] = (d.pm25_next >= 36).astype(int)
d = d.sort_values("date").reset_index(drop=True)          # 시간 순 정렬 (시계열 분할용)
tr = d[d.date < "2026-01-01"]; te = d[d.date >= "2026-01-01"]
Xtr, ytr = tr[F10], tr.bad_next

print("== A. 검증 세트 하나짜리 점수는 복불복이다 ==")
for seed in [0, 1, 2, 3, 4]:
    X1, X2, y1, y2 = train_test_split(Xtr, ytr, test_size=0.2, random_state=seed, stratify=ytr)
    m = make_pipeline(StandardScaler(), LogisticRegression(max_iter=5000)).fit(X1, y1)
    print(f"  seed={seed}: 검증 AUC {roc_auc_score(y2, m.predict_proba(X2)[:, 1]):.3f}")
```

실행 결과:

```
== A. 검증 세트 하나짜리 점수는 복불복이다 ==
  seed=0: 검증 AUC 0.929
  seed=1: 검증 AUC 0.949
  seed=2: 검증 AUC 0.933
  seed=3: 검증 AUC 0.941
  seed=4: 검증 AUC 0.954
```

**같은 데이터, 같은 모델, 점수는 0.929~0.954.** seed 하나가 0.025를 좌우합니다.
어제까지 우리가 "모델 A가 B보다 0.01 좋다"고 말했던 비교들, 사실 이 노이즈 안에서
헤엄치고 있었을 수 있습니다. (참고: `make_pipeline` 은 스케일러+모델을 한 몸으로 묶는
도구입니다 — 정식 소개는 [Day 063](day-063.md)에서.)

### Step 2. K-Fold — 평균과 오차 막대 (2교시)

```python
print("\n== B. K-Fold 교차검증 — 다섯 번 시험 본 평균 ==")
model = make_pipeline(StandardScaler(), LogisticRegression(max_iter=5000))
cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)
scores = cross_val_score(model, Xtr, ytr, cv=cv, scoring="roc_auc")
print(f"  폴드별: {np.round(scores, 3)}")
print(f"  평균 {scores.mean():.3f} ± {scores.std():.3f}")
```

실행 결과:

```
== B. K-Fold 교차검증 — 다섯 번 시험 본 평균 ==
  폴드별: [0.936 0.951 0.94  0.936 0.956]
  평균 0.944 ± 0.008
```

`cross_val_score` 한 줄로 다섯 번의 학습·검증이 끝났습니다. 이제 점수에 **오차 막대**가 생겼습니다:
0.944 ± 0.008. 앞으로 두 모델의 평균 차이가 이 ± 안에 있으면 "차이 없음"으로 읽습니다.
…그런데 이 0.944라는 값, 어제의 test AUC(0.818)보다 이상하게 높지 않나요? 기억해 두세요. Step 4에서 돌아옵니다.

### Step 3. 폴드 안을 들여다보기 — Stratified와 시간의 문제 (3~4교시)

```python
print("\n== C. 폴드의 클래스 비율 — Stratified가 하는 일 ==")
kf = KFold(n_splits=5)                     # 섞지 않음 → 시간 순 조각
skf = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)
print("  KFold(순서대로):     ", [f"{ytr.iloc[idx].mean()*100:.0f}%" for _, idx in kf.split(Xtr)])
print("  StratifiedKFold:  ", [f"{ytr.iloc[idx].mean()*100:.0f}%" for _, idx in skf.split(Xtr, ytr)])
```

실행 결과:

```
== C. 폴드의 클래스 비율 — Stratified가 하는 일 ==
  KFold(순서대로):      ['2%', '46%', '19%', '2%', '7%']
  StratifiedKFold:   ['15%', '15%', '15%', '15%', '15%']
```

섞지 않은 KFold의 폴드별 나쁨 비율이 **2%에서 46%까지** 널뜁니다 — 시간 순 조각이라
여름 폴드(2%)와 겨울 폴드(46%)가 갈린 것입니다. Stratified는 전 폴드를 15%로 맞춰 줍니다.
독립 표본 분류에서 Stratified가 기본인 이유입니다.

하지만 우리 데이터에서 "무작위로 섞어 15%씩" 만드는 것은 계절을 부수는 일이기도 합니다.
시계열의 정답은 따로 있습니다.

```python
print("\n== D. TimeSeriesSplit — 항상 과거로 배워 미래를 검증 ==")
tss = TimeSeriesSplit(n_splits=5)
scores_t = []
for i, (itr, iva) in enumerate(tss.split(Xtr)):
    m = make_pipeline(StandardScaler(), LogisticRegression(max_iter=5000)).fit(Xtr.iloc[itr], ytr.iloc[itr])
    a = roc_auc_score(ytr.iloc[iva], m.predict_proba(Xtr.iloc[iva])[:, 1])
    scores_t.append(a)
    print(f"  폴드{i+1}: train {len(itr):>5}행 → 검증 {len(iva)}행  AUC {a:.3f}")
print(f"  평균 {np.mean(scores_t):.3f} ± {np.std(scores_t):.3f}")
```

실행 결과:

```
== D. TimeSeriesSplit — 항상 과거로 배워 미래를 검증 ==
  폴드1: train   439행 → 검증 438행  AUC 0.770
  폴드2: train   877행 → 검증 438행  AUC 0.853
  폴드3: train  1315행 → 검증 438행  AUC 0.888
  폴드4: train  1753행 → 검증 438행  AUC 0.800
  폴드5: train  2191행 → 검증 438행  AUC 0.889
  평균 0.840 ± 0.048
```

폴드마다 train이 자라고(439 → 2,191행), 검증은 항상 그 **뒤** 구간입니다 — 다섯 번의
미니 배포 리허설인 셈입니다. 점수의 분산이 큰 것(± 0.048)도 정보입니다: 검증 구간이
어느 계절이냐에 따라 난이도가 실제로 다르다는 뜻입니다 (폴드1은 데이터도 적고 첫 겨울 직전).

### Step 4. 심판 — CV 추정 vs 진짜 test (5교시)

두 교차검증이 서로 다른 값을 주장합니다: 0.944 vs 0.840. 누가 옳은가? 금고를 엽니다.

```python
print("\n== E. 최종 대조 — CV 추정 vs 진짜 test ==")
m_full = make_pipeline(StandardScaler(), LogisticRegression(max_iter=5000)).fit(Xtr, ytr)
test_auc = roc_auc_score(te.bad_next, m_full.predict_proba(te[F10])[:, 1])
print(f"  Stratified 5-Fold(무작위) 추정: {scores.mean():.3f}")
print(f"  TimeSeriesSplit 추정        : {np.mean(scores_t):.3f}")
print(f"  진짜 test (2026년)          : {test_auc:.3f}")
```

실행 결과:

```
== E. 최종 대조 — CV 추정 vs 진짜 test ==
  Stratified 5-Fold(무작위) 추정: 0.944
  TimeSeriesSplit 추정        : 0.840
  진짜 test (2026년)          : 0.818
```

| 방법 | 추정 | 실제와의 거리 | 판정 |
|---|---|---|---|
| Stratified 5-Fold (무작위) | 0.944 ± 0.008 | **+0.126** | **정밀하게 틀림** — 시점 누수를 5번 반복한 평균 |
| TimeSeriesSplit | 0.840 ± 0.048 | +0.022 | 덜 정밀하지만 정직함 |

오늘의 가장 중요한 문장입니다: **정밀(precision)과 정확(correctness)은 다릅니다.**
무작위 K-Fold는 ±0.008이라는 촘촘한 오차 막대로 0.944를 가리켰지만, 그 과녁 자체가
잘못 걸려 있었습니다(검증 조각의 이웃 날짜가 늘 학습에 있었으므로). 내일부터의 모든 튜닝은
**TimeSeriesSplit 위에서** 진행합니다.

## ⑤ 자주 하는 실수

### 시계열에 무작위 K-Fold를 씀

**증상** — CV 점수(0.944)는 훌륭한데 배포(≈test 0.818)에서 무너짐. 오늘 Step 4가 그 현장입니다.
**원인** — 폴드를 섞는 순간 검증 조각의 앞뒤 날짜가 학습에 들어갑니다 — [Day 052](day-052.md) 시점 누수의 교차검증 판.
**해결** — 시간이 흐르는 데이터는 TimeSeriesSplit. "행 사이에 시간·그룹 의존이 있는가"를 분할 전에 반드시 묻습니다.

### CV 안에서 전처리를 밖에 둠

**증상** — `sc.fit_transform(Xtr)` 을 한 번 해 두고 그 결과로 `cross_val_score` 실행.
**원인** — 각 폴드의 검증 조각이 "전체 train으로 fit한 스케일러"를 통과 — 폴드 입장에선 전처리 누수입니다.
**해결** — Step 2처럼 `make_pipeline(StandardScaler(), 모델)` 을 통째로 `cross_val_score` 에 넘기면
폴드마다 스케일러가 **그 폴드의 학습 조각으로만** fit됩니다. 이 구조의 정식 명칭이 [Day 063](day-063.md)의 Pipeline입니다.

### 평균만 보고 표준편차를 버림

**증상** — "A(0.842)가 B(0.838)보다 좋다"며 A 채택.
**원인** — ±0.048짜리 측정에서 0.004 차이는 소음입니다.
**해결** — 평균 ± 표준편차를 함께 보고, 차이가 ± 안이면 "동률"로 취급해 더 단순한 쪽을 고릅니다.

### 폴드 수를 늘리면 무조건 좋다고 믿음

**증상** — "10-Fold, 아니 LOO(행 수만큼)로 하면 더 정확하겠지" — 시간만 10배, 결론은 그대로.
**원인** — 폴드 수는 추정의 분산을 조금 줄일 뿐, 잘못된 분할(누수)은 폴드가 많아져도 그대로입니다.
**해결** — 5가 관례적 기본값입니다. 폴드 수보다 **분할 방식**(시간·그룹 존중)이 백 배 중요합니다.

### CV 점수를 최종 성능으로 보고함

**증상** — 보고서에 "성능: CV 0.840"이라고만 씀.
**원인** — CV는 **모델 선택용** 추정입니다. 여러 후보를 CV로 비교하는 동안 CV 점수에도 선택 낙관이 조금씩 스며듭니다.
**해결** — 선택이 다 끝난 뒤 금고의 test로 최종 1회 확인한 값을 함께 보고합니다: "CV 0.840 ± 0.048, test 0.818".

## ⑥ 확인 문제

**Q1.** Step 1에서 seed만 바꿔도 검증 AUC가 0.929~0.954로 변했습니다. 이 사실이 "검증 세트 하나로
하이퍼파라미터를 고르는 것"에 대해 말해 주는 바는?

<details>
<summary>답 보기</summary>

후보 간 점수 차이가 0.025(운의 크기)보다 작으면, 검증 세트 하나로는 **어느 쪽이 진짜 나은지 구분할 수
없다**는 뜻입니다. 그런 비교는 사실상 seed를 고르는 행위가 됩니다. 교차검증으로 평균 ± 표준편차를 만들어
"운의 크기"부터 재야 합니다.

</details>

**Q2.** Stratified 5-Fold는 ±0.008로 정밀했지만 +0.126 부풀었고, TimeSeriesSplit은 ±0.048로
덜 정밀했지만 test에 근접했습니다. "정밀"과 "정확"의 차이를 이 예로 설명하세요.

<details>
<summary>답 보기</summary>

정밀은 **반복 측정끼리 서로 가까움**(작은 분산), 정확은 **참값에 가까움**(작은 편향)입니다.
무작위 K-Fold는 시점 누수라는 체계적 편향을 다섯 폴드 모두에서 똑같이 반복했기 때문에, 서로 일치하는
(정밀한) 그러나 전부 부풀려진(부정확한) 값을 냈습니다. 측정을 아무리 반복해도 잘못 걸린 과녁은 고쳐지지 않습니다.

</details>

**Q3.** `cross_val_score` 에 스케일러를 통과시킨 데이터를 넘기는 대신 `make_pipeline(StandardScaler(), 모델)`
을 넘겨야 하는 이유는?

<details>
<summary>답 보기</summary>

파이프라인을 넘기면 각 폴드에서 스케일러가 **그 폴드의 학습 조각으로만 fit**되고 검증 조각은 transform만
거칩니다. 미리 전체 train으로 fit해 두면 검증 조각의 통계가 스케일러에 이미 스며든 전처리 누수가 되어,
폴드 점수가 미세하게 부풀고 원칙([Day 052](day-052.md): fit은 학습 데이터에만)이 깨집니다.

</details>
