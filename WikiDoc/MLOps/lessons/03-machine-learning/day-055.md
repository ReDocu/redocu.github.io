## ② 왜 필요한가

이번 주 마지막 날입니다. 새 개념은 없습니다. 대신 이 질문에 답합니다.

> "선형 회귀 R² 0.390 — **이게 잘한 겁니까?**"

이 질문은 0.390이라는 숫자만으로는 **원리적으로 답할 수 없습니다.** 잘했는지는 언제나
"무엇에 비해서"입니다. 그 비교 대상을 만드는 작업이 베이스라인이고, 이것이 없으면:

```
상황 A: 신입이 2주 걸려 만든 모델, R² 0.39
        → "찍으면 -0.04, 어제 값 쓰면 0.21이니까, 의미 있는 개선입니다"  ← 채택
상황 B: 외주사가 가져온 딥러닝 모델, R² 0.35
        → "내일=오늘 규칙(0.21)보다는 낫지만... 우리 선형 회귀(0.39)보다 못하네요?"  ← 반려
```

베이스라인이 없으면 상황 B에서 딥러닝이라는 말에 홀려 더 나쁜 모델을 삽니다.
**베이스라인은 성능의 자(尺)입니다.** MP2 평가 기준 1번("베이스라인 대비 개선 폭 제시")이 이것이고,
실무에서도 "베이스라인 없이 가져온 성능 보고"는 보고가 아닙니다.

## ③ 개념 설명

### 베이스라인 사다리

아래층부터 순서대로 세웁니다. **각 층은 위층의 존재 이유를 검증합니다.**

| 층 | 모델 | 비용 | 이 층이 답하는 질문 |
|---|---|---|---|
| 0층 | **전체 평균**으로 찍기 | 1분 | 지표 계산이 맞는가, 문제가 성립하는가 |
| 1층 | **집단·계절 평균** (측정소×월) | 10분 | 주기성만으로 얼마나 되나 |
| 2층 | **단순 규칙** (내일=오늘) | 10분 | 관성만으로 얼마나 되나 |
| 3층 | **단순 모델** (선형 회귀) | 1시간 | 특성들이 정보를 더하는가 |
| 4층+ | 복잡한 모델 (W12~) | 며칠 | **3층을 이기는가? 못 이기면 왜 쓰나?** |

> 규칙: **아래층을 못 이기는 위층은 배포하지 않습니다.** 복잡성은 공짜가 아니기 때문입니다
> (서빙 비용, 디버깅, 재학습 — 대단원 04·05에서 체감하게 됩니다).

## ④ 단계별 실습 — 회귀 베이스라인 리포트

오늘 산출물은 `baseline_report.py` 와 `report_w11.md` 입니다. 문제를 순서대로 풉니다.

### 문제 1. 평가 뼈대 — 시간 분리와 지표 함수 (1~2교시)

이번 주 내내 반복한 코드를 **재사용 가능한 형태**로 정리합니다. 다음 주부터 매일 씁니다.

```python
# baseline_report.py — W11 종합: 베이스라인 사다리와 리포트
import numpy as np
import pandas as pd
from sklearn.linear_model import LinearRegression
from sklearn.metrics import mean_absolute_error, r2_score

pd.set_option("display.width", 140)
F10 = ["pm10", "pm25", "o3", "no2", "co", "so2", "temp", "humidity", "wind_speed", "precip"]
F5 = ["pm10", "pm25", "wind_speed", "humidity", "precip"]

def load_split(features):
    """공통 데이터셋을 읽어 시간 기준으로 나눈다 (train: ~2025-12, test: 2026~)."""
    df = pd.read_csv("data/air_daily.csv", parse_dates=["date"])
    d = df.dropna(subset=features).copy()
    d["month"] = d.date.dt.month
    return d[d.date < "2026-01-01"], d[d.date >= "2026-01-01"]

def rmse(y, p):
    return float(np.sqrt(((y - p) ** 2).mean()))

tr, te = load_split(F10)
yte = te.pm25_next

def report(name, p):
    print(f"| {name:<22} | {mean_absolute_error(yte, p):5.2f} | {rmse(yte, p):5.2f} | {r2_score(yte, p):6.3f} |")
```

### 문제 2. 베이스라인 사다리 세우기 (3~5교시)

```python
print("| 모델 | MAE | RMSE | R² |")
print("|---|---|---|---|")

# 0층: train 전체 평균
report("0층 · 전체 평균", np.full(len(te), tr.pm25_next.mean()))

# 1층: 측정소×월 평균 (기후 베이스라인 — "3월의 강남구는 보통 이랬다")
clim = tr.groupby(["station", "month"]).pm25_next.mean()
p_clim = te.apply(lambda r: clim.loc[(r["station"], r["month"])], axis=1)
report("1층 · 측정소×월 평균", p_clim)

# 2층: 내일=오늘 (persistence)
report("2층 · 내일=오늘", te.pm25.to_numpy())

# 3층: 선형 회귀 5특성
m5 = LinearRegression().fit(tr[F5], tr.pm25_next)
report("3층 · 선형 회귀(5특성)", m5.predict(te[F5]))

# 4층: 선형 회귀 10특성
m10 = LinearRegression().fit(tr[F10], tr.pm25_next)
p10 = m10.predict(te[F10])
report("4층 · 선형 회귀(10특성)", p10)
```

실행 결과:

```
| 모델 | MAE | RMSE | R² |
|---|---|---|---|
| 0층 · 전체 평균             |  6.14 |  7.97 | -0.043 |
| 1층 · 측정소×월 평균          |  7.83 |  9.84 | -0.590 |
| 2층 · 내일=오늘             |  5.58 |  6.95 |  0.207 |
| 3층 · 선형 회귀(5특성)        |  4.90 |  6.10 |  0.389 |
| 4층 · 선형 회귀(10특성)       |  4.87 |  6.09 |  0.390 |
```

사다리가 완성됐습니다. 그런데 **1층이 0층보다 낮습니다.** -0.590 — "측정소별·월별 평균"이라는
그럴듯한 베이스라인이 아무 생각 없는 전체 평균보다 한참 나쁩니다. 넘어가지 말고 파야 합니다.

### 문제 3. 그럴듯한 베이스라인의 배신 — 원인 조사 (5~6교시)

```python
print("\n== 1층은 왜 무너졌나: 월별 프로필 비교 ==")
cmp = te.groupby("month").pm25_next.mean().round(1).to_frame("실제 2026")
cmp["기후평균(train)"] = [round(clim.xs(m, level="month").mean(), 1) for m in cmp.index]
print(cmp.to_string())
```

실행 결과:

```
== 1층은 왜 무너졌나: 월별 프로필 비교 ==
       실제 2026  기후평균(train)
month
1         28.6         41.4
2         30.6         31.2
3         26.1         32.4
4         34.6         24.7
5         25.1         21.5
6         23.5         22.5
```

원인이 보입니다. train에서 1~6월 데이터는 **2025년 한 해뿐**인데, 2025년은 황사가 유난한
해였습니다(특히 1월 평균 41.4). 기후 베이스라인은 **한 해의 사건을 계절의 법칙으로 착각**해
2026년 1월(실제 28.6)을 크게 높여 부르고, 반대로 4월(실제 34.6)은 낮춰 불렀습니다.

| 교훈 | 어디서 다시 만나나 |
|---|---|
| 그럴듯함 ≠ 정확함. **모든 베이스라인도 평가 대상** | MP2에서 베이스라인 점수도 표에 넣는 이유 |
| 집단별 통계는 **표본 수**를 따져야 함 (월별 train = 1~2년치뿐) | [Day 061](day-061.md) 점수의 분산 |
| 연도가 바뀌면 분포가 변한다 | 대단원 05의 드리프트 모니터링 |

### 문제 4. 경보 관점 분석 — 리포트의 "오답 분석" (6~7교시)

이 모델을 "나쁨 경보"에 쓴다면? [Day 053](day-053.md)의 잔차 분석을 경보의 언어로 바꿉니다.

```python
print("\n== 경보 관점: '나쁨'(>=36) 적중 분석 (선형 10특성) ==")
actual_bad = yte >= 36
pred_bad = p10 >= 36
n_bad = actual_bad.sum()
hit = (actual_bad & pred_bad).sum()
false_alarm = (~actual_bad & pred_bad).sum()
print(f"실제 나쁨 {n_bad}일 중 예보가 잡은 날: {hit}일 ({hit / n_bad * 100:.0f}%)")
print(f"나쁨 예보 {pred_bad.sum()}일 중 헛경보: {false_alarm}일")

p_pers = te.pm25.to_numpy()
hit_p = (actual_bad & (p_pers >= 36)).sum()
print(f"(참고) 내일=오늘 베이스라인이 잡은 날: {hit_p}일 ({hit_p / n_bad * 100:.0f}%)")
```

실행 결과:

```
== 경보 관점: '나쁨'(>=36) 적중 분석 (선형 10특성) ==
실제 나쁨 121일 중 예보가 잡은 날: 43일 (36%)
나쁨 예보 91일 중 헛경보: 48일
(참고) 내일=오늘 베이스라인이 잡은 날: 49일 (40%)
```

충격적인 결과입니다. R²에서 압승(0.390 vs 0.207)한 선형 회귀가, **나쁨 잡기에서는
"내일=오늘" 규칙에 집니다**(36% vs 40%). [Day 053](day-053.md)에서 본 "고농도를 낮춰 부르는"
성질 때문입니다 — 평균 오차에 최적화된 모델은 문턱(36) 근처의 나쁜 날을 자꾸 문턱 아래로 부릅니다.

**"값을 잘 맞히는 것"과 "나쁨을 잘 잡는 것"은 다른 문제입니다.** 후자를 제대로 푸는 방법 —
문제 자체를 분류로 다시 정의하고, 잡기/헛경보를 직접 지표로 삼는 것 — 이 다음 주(W12) 전체의 내용입니다.

</details>

**Q3.** R² 최강(0.390)인 선형 회귀가 "나쁨 잡기"에서는 내일=오늘 규칙에 지는(36% vs 40%) 이유를
[Day 053](day-053.md)의 잔차 분석과 연결해 설명하세요.

<details>
<summary>답 보기</summary>

선형 회귀는 평균 제곱 오차를 줄이도록 학습되어 **고농도를 체계적으로 낮춰 부릅니다**(고농도 날 잔차 평균 +7.7,
평균으로의 회귀). 그래서 실제 36을 갓 넘는 날들을 문턱 아래로 예측해 경보를 놓칩니다. 반면 내일=오늘 규칙은
오늘 이미 나쁜 날을 그대로 나쁨으로 부르므로, 이어지는 고농도 구간을 놓치지 않습니다.

</details>

## 주간 퀴즈 10 — W11 (머신러닝 개요와 회귀)

<details>
<summary>1. ML 문제 정의의 3요소는?</summary>

**입력(X) · 출력(y) · 지표.** 특히 입력은 "예측 시점에 알 수 있는 정보"여야 합니다.

</details>

<details>
<summary>2. 지도학습에서 회귀와 분류를 가르는 기준은?</summary>

**출력(타깃)의 형태.** 연속된 숫자면 회귀, 범주(클래스)면 분류입니다.

</details>

<details>
<summary>3. 과적합을 학습 점수와 평가 점수의 관계로 정의하면?</summary>

학습 데이터 점수는 매우 높은데 **본 적 없는 데이터** 점수가 크게 낮은 상태. 모델이 일반 구조 대신 학습 데이터 자체를 외운 것입니다.

</details>

<details>
<summary>4. 데이터 누수 3유형을 각각 한 줄로.</summary>

**타깃 누수**(정답·미래가 특성에 유입 — 예: `rolling(center=True)`), **시점 누수**(미래 행이 train에 유입 — 예: 시계열 무작위 분할), **전처리 누수**(test 통계량이 전처리에 유입 — 예: 전체 데이터로 스케일러 fit).

</details>

<details>
<summary>5. test 세트를 "한 번만" 써야 하는 이유는?</summary>

test 점수를 보고 모델을 고치는 순간 test에 (사람이) 과적합하기 시작해, test가 더 이상 "본 적 없는 데이터"가 아니게 되기 때문입니다.

</details>

<details>
<summary>6. "오늘 pm25 → 내일 pm25" 회귀의 기울기가 1보다 작은(0.77) 현상의 이름과 의미는?</summary>

**평균으로의 회귀.** 극단값 다음 날은 평균 쪽으로 돌아오는 경향이 있어, 모델이 극단적인 오늘 뒤의 내일을 덜 극단적으로 예측합니다.

</details>

<details>
<summary>7. 계수 크기로 특성 중요도를 비교하려면 무엇을 먼저 해야 하나?</summary>

**표준화(스케일링).** 원 단위 계수는 특성의 단위·스케일에 종속되기 때문입니다 (so2 +217의 착시).

</details>

<details>
<summary>8. MAE와 RMSE 중 "가끔 크게 틀리는" 모델에 더 가혹한 것은? 이유는?</summary>

**RMSE.** 오차를 제곱하므로 큰 오차 하나가 작은 오차 여럿보다 훨씬 큰 벌점을 받습니다 (두 예보관: MAE 동률, RMSE 4.00 vs 8.94).

</details>

<details>
<summary>9. test R²가 음수라는 것의 의미는?</summary>

그 데이터의 **평균으로 찍기보다 못한** 예측이라는 뜻입니다. 버그가 아니라 정보입니다 (모델이 나쁘거나, train과 test의 분포가 달라졌거나).

</details>

<details>
<summary>10. Ridge와 Lasso의 공통점과 결정적 차이는?</summary>

공통점: 손실에 **계수 크기 벌점**을 더해 과적합을 누름 (둘 다 스케일링 필수).
차이: Ridge(L2)는 계수를 고르게 줄이고, Lasso(L1)는 덜 중요한 계수를 **정확히 0**으로 만들어 특성 선택을 겸합니다.

</details>
