## 2. 막히는 상황

공격 모션은 나온다. 이제 상대를 때려 보자.

**시도 1 — 스프라이트가 겹치면 히트**

```cpp
    RectF a = { m_x - 32, m_y - 96, 64, 96 };
    RectF b = { other->GetX() - 32, other->GetY() - 96, 64, 96 };

    if (IsOverlap(a, b)) other->TakeHit(10);
```

```
   ┌──────┐┌──────┐
   │  A   ││  B   │     ← 스프라이트가 살짝 겹쳤을 뿐인데
   │      ││      │        A가 아무것도 안 해도 B가 맞는다
   └──────┘└──────┘
```

**시도 2 — 공격 상태일 때만 판정**

```cpp
    if (m_state == STATE_ATTACK && IsOverlap(a, b))
        other->TakeHit(10);
```

```
   여전히 문제

   ① 공격 모션 시작 프레임(팔을 아직 안 뻗음)에도 맞는다
   ② 스프라이트 전체가 판정이라 캐릭터 뒤쪽도 판정된다
   ③ 한 번의 공격이 매 프레임 히트해서 6번 데미지가 들어간다
```

```
   지금:   스프라이트 = 판정

   필요:   ① 때리는 부위와 맞는 부위를 나눈다
           ② 프레임마다 판정이 다르다
           ③ 한 번의 공격은 한 번만 맞는다
```

> **판정을 스프라이트와 분리해야 한다.** → **hitbox / hurtbox**

## 3. 개념

### 3-1. hitbox와 hurtbox

**왜 필요한가** — 격투게임 판정의 기본 개념.

```
   hurtbox (피격 판정)   "여기를 맞으면 데미지를 입는다"
   hitbox  (공격 판정)   "여기에 닿으면 데미지를 준다"
```

```
        캐릭터 A (공격 중)                  캐릭터 B (대기)

        ┌─────────┐                        ┌─────────┐
        │ ┌─────┐ │                        │ ┌─────┐ │
        │ │hurt │ │▓▓▓▓▓  ← hitbox         │ │hurt │ │
        │ │ box │ │▓▓▓▓▓                   │ │ box │ │
        │ └─────┘ │                        │ └─────┘ │
        └─────────┘                        └─────────┘
         스프라이트                          스프라이트

   ★ A.hitbox 와 B.hurtbox 가 겹치면  →  B가 맞는다
   ★ A.hurtbox 와 B.hurtbox 는 판정하지 않는다 (그냥 겹칠 뿐)
```

| 박스 | 언제 존재하나 | 개수 |
|---|---|---|
| **hurtbox** | 거의 항상 (무적 상태 제외) | 1~3개 (머리/몸/다리) |
| **hitbox** | 공격 모션의 특정 프레임에만 | 0~2개 |

**push box (참고)**

```
   격투게임에는 보통 세 번째 박스가 있다

   pushbox  "캐릭터끼리 겹치지 않게 밀어내는 영역"

   ★ 이 과정에서는 Day 49에서 간단히 처리한다
```

### 3-2. 프레임별 판정 — 공격의 3단계

**왜 필요한가** — 공격은 시간에 따라 성질이 변한다.

```
   공격 모션 6프레임의 구조

   프레임    0     1     2     3     4     5
           ┌────┬────┬────┬────┬────┬────┐
           │준비 │준비 │발생 │발생 │후딜 │후딜 │
           └────┴────┴────┴────┴────┴────┘
   hitbox    X    X    O    O    X    X
```

| 구간 | 이름 | 설명 |
|---|---|---|
| 프레임 0~1 | **발생 전(startup)** | 팔을 들어올리는 중. 아직 안 맞는다 |
| 프레임 2~3 | **지속(active)** | hitbox 활성. 이때만 맞는다 |
| 프레임 4~5 | **후딜(recovery)** | 팔을 거두는 중. 무방비 |

```
   ★ 이 구조가 격투게임의 전략을 만든다

   발생이 빠른 기술  →  선제권
   지속이 긴 기술    →  맞히기 쉽다
   후딜이 긴 기술    →  빗나가면 반격당한다
```

### 3-3. 판정 데이터 구조

**왜 필요한가** — 박스를 데이터로 관리해야 프레임마다 다르게 할 수 있다.

```cpp
struct HitboxData
{
    int    startFrame;      // 활성 시작 프레임
    int    endFrame;        // 활성 종료 프레임 (포함)

    float  offsetX;         // 캐릭터 기준점으로부터의 오프셋
    float  offsetY;
    float  width;
    float  height;

    int    damage;
    float  knockbackX;
    float  knockbackY;
    double hitStun;         // 경직 시간
};
```

```cpp
// 상태별 판정 데이터
const HitboxData g_attackHitbox = {
    2, 3,                   // 3~4번째 프레임
    30.0f, -70.0f,          // 앞쪽 위
    44.0f, 28.0f,
    10,                     // 데미지
    220.0f, -60.0f,         // 넉백
    0.25                    // 경직 0.25초
};

const HitboxData g_crouchAttackHitbox = {
    1, 2,
    28.0f, -28.0f,          // 낮은 위치
    40.0f, 24.0f,
    7,
    150.0f, 0.0f,
    0.20
};
```

```

                    ▼

        │           │▓▓▓▓▓▓▓▓▓▓▓▓│  offsetY = -70

### 3-4. ⚠️ 방향 반전 시 박스도 반전

**왜 필요한가** — 왼쪽을 보고 공격했는데 오른쪽에 판정이 생기면 안 된다.

```cpp
RectF Character::GetHitboxRect(const HitboxData& data) const
{
    RectF r;

    if (m_facingLeft)
        r.x = (float)m_x - data.offsetX - data.width;     // ★ 미러링
    else
        r.x = (float)m_x + data.offsetX;

    r.y = (float)m_y + data.offsetY;
    r.w = data.width;
    r.h = data.height;

    return r;
}
```

```
   오른쪽을 볼 때 (facingLeft = false)

        ●━━━━━━━━━━┫▓▓▓▓▓▓▓┃
        m_x    offsetX   width
              (=30)      (=44)
        x = m_x + 30


   왼쪽을 볼 때 (facingLeft = true)

   ┃▓▓▓▓▓▓▓┣━━━━━━━━━━●
    width  offsetX    m_x
    (=44)   (=30)
   x = m_x - 30 - 44
```

> **넉백 방향도 함께 반전한다.**
>
> ```cpp

### 3-5. ⚠️ 히트 기록 — 다단 히트 방지

**왜 필요한가** — 한 번 공격했는데 6번 맞는 문제.

```
   hitbox 가 프레임 2~3에서 활성

   60fps 에서 애니메이션 12fps 라면
   → 한 프레임이 5번의 게임 프레임 동안 유지된다
   → 2프레임 × 5 = 10번 충돌 검사가 통과한다
   → 데미지 10 × 10 = 100
```

**해결 — 이번 공격에 이미 맞은 대상 기록**

```cpp
class Character
{
    static const int MAX_HIT_RECORD = 8;

    GameObject* m_hitRecord[MAX_HIT_RECORD];
    int         m_hitRecordCount = 0;

public:
    void ClearHitRecord() { m_hitRecordCount = 0; }

    bool HasHit(GameObject* target) const
    {
        for (int i = 0; i < m_hitRecordCount; i++)
            if (m_hitRecord[i] == target) return true;
        return false;
    }

    void AddHitRecord(GameObject* target)
    {
        if (m_hitRecordCount < MAX_HIT_RECORD)
            m_hitRecord[m_hitRecordCount++] = target;
    }
};
```

```cpp
    // OnEnterState(STATE_ATTACK) 안에서
    ClearHitRecord();                         // ★ 새 공격 시작 시 초기화
```

```cpp
    // 충돌 검사
    if (HasHit(target)) return;               // 이미 맞았으면 무시

    target->TakeHit(...);
    AddHitRecord(target);
```

```
   ★ 다단 히트 기술을 만들려면?

   여러 hitbox 를 두고, 각 hitbox 마다 히트 기록을 따로 관리한다
   또는 일정 시간이 지나면 기록을 지운다
```

### 3-6. 애니메이션 프레임과 판정 동기화

**왜 필요한가** — Day 43의 애니메이션 이벤트를 여기에 쓴다.

```cpp
bool Character::IsHitboxActive() const
{
    if (m_state != STATE_ATTACK &&
        m_state != STATE_C_ATTACK &&
        m_state != STATE_J_ATTACK) return false;

    Animation* a = m_animator.GetCurrent();
    if (!a) return false;

    const HitboxData* data = GetCurrentHitboxData();
    if (!data) return false;

    int frame = a->GetLocalFrame();

    return (frame >= data->startFrame && frame <= data->endFrame);
}
```

```
   ★ 애니메이션의 "지금 몇 번째 프레임인가"가
     판정의 활성 여부를 결정한다

   → 애니메이션과 게임 로직이 자동으로 동기화된다
   → 애니메이션 속도를 바꾸면 판정 타이밍도 함께 바뀐다
```

### 3-7. 무적 프레임

**왜 필요한가** — 기상 직후나 회피 동작에는 hurtbox가 없어야 한다.

```cpp
bool Character::IsInvincible() const
{
    switch (m_state)
    {
    case STATE_DOWN:
        return true;                          // 다운 중 무적

    case STATE_GETUP:
        return m_stateTimer < GETUP_INVINCIBLE_TIME;   // 기상 초반만

    case STATE_HIT:
        return m_stateTimer < 0.05;           // 피격 직후 짧게

    default:
        return false;
    }
}

RectF Character::GetHurtbox() const
{
    if (IsInvincible())
        return RectF{ 0, 0, 0, 0 };           // 크기 0 = 판정 없음
    // ...
}
```

```
   ★ 무적이 없으면

   쓰러진 상대를 계속 때려서 영원히 못 일어나게 할 수 있다
   → 게임이 성립하지 않는다
```

### 3-8. 디버그 렌더링 — 필수 도구

**왜 필요한가** — 판정은 눈에 안 보인다. 그려야 디버그가 된다.

```cpp
void Character::RenderDebugBoxes(Renderer& r) const
{
    if (!g_showHitboxes) return;

    // hurtbox — 파랑
    RectF hurt = GetHurtbox();
    if (hurt.w > 0)
        r.DrawRect((int)hurt.x, (int)hurt.y, (int)hurt.w, (int)hurt.h,
                   RGB(60, 120, 255), false);

    // hitbox — 빨강 (활성일 때만)
    if (IsHitboxActive())
    {
        RectF hit = GetActiveHitbox();
        r.DrawRect((int)hit.x, (int)hit.y, (int)hit.w, (int)hit.h,
                   RGB(255, 60, 60), false);

        // 두껍게 (강조)
        r.DrawRect((int)hit.x - 1, (int)hit.y - 1,
                   (int)hit.w + 2, (int)hit.h + 2,
                   RGB(255, 60, 60), false);
    }

    // 기준점 — 초록
    r.DrawCircle((int)m_x, (int)m_y, 3, RGB(60, 255, 60));

    // 무적 표시
    if (IsInvincible())
        r.DrawTextF((int)m_x - 20, (int)m_y - 130, RGB(255,255,0), "INVINCIBLE");
}
```

**색 규약 (업계 관행)**

| 색 | 의미 |
|---|---|
| **파랑** | hurtbox (맞는 부위) |
| **빨강** | hitbox (때리는 부위) |
| 초록 | 기준점, pushbox |
| 노랑 | 무적, 특수 상태 |

### Step 4 — hitbox 활성 판정

```cpp
const HitboxData* Character::GetCurrentHitboxData() const
{
    switch (m_state)
    {
    case STATE_ATTACK:   return &g_hitboxAttack;
    case STATE_C_ATTACK: return &g_hitboxCrouchAttack;
    case STATE_J_ATTACK: return &g_hitboxJumpAttack;
    default:             return nullptr;
    }
}

bool Character::IsHitboxActive() const
{
    const HitboxData* d = GetCurrentHitboxData();
    if (!d) return false;

    Animation* a = m_animator.GetCurrent();
    if (!a) return false;

    int f = a->GetLocalFrame();
    return (f >= d->startFrame && f <= d->endFrame);
}

RectF Character::GetActiveHitbox() const
{
    const HitboxData* d = GetCurrentHitboxData();
    if (!d) return RectF{ 0, 0, 0, 0 };

    RectF r;

    if (m_facingLeft) r.x = (float)m_x - d->offsetX - d->width;
    else              r.x = (float)m_x + d->offsetX;

    r.y = (float)m_y + d->offsetY;
    r.w = d->width;
    r.h = d->height;

    return r;
}
```

**✅ 여기까지 실행하면** — 공격할 때 빨간 박스가 **3~4번째 프레임에만** 나타난다.

### Step 6 — 방향 반전 확인

왼쪽을 보고 공격해 본다.

### Step 7 — 충돌 검사

```cpp
void FightScene::CheckHits()
{
    Character* chars[2] = { m_player1, m_player2 };

    for (int a = 0; a < 2; a++)
    {
        Character* attacker = chars[a];
        Character* defender = chars[1 - a];

        if (!attacker->IsHitboxActive()) continue;
        if (attacker->HasHit(defender))  continue;     // ★ 이미 맞음

        RectF hit  = attacker->GetActiveHitbox();
        RectF hurt = defender->GetHurtbox();

        if (hurt.w <= 0) continue;                      // 무적

        if (IsOverlap(hit, hurt))
        {
            const HitboxData* d = attacker->GetCurrentHitboxData();

            double kbX = attacker->IsFacingLeft() ? -d->knockbackX : d->knockbackX;

            defender->TakeHit(d->damage, kbX, d->knockbackY, d->hitStun);
            attacker->AddHitRecord(defender);

            DebugLog("[HIT] 데미지 %d  넉백 (%.0f, %.0f)\n",
                     d->damage, kbX, d->knockbackY);

            m_totalHits++;
        }
    }
}
```

**✅ 여기까지 실행하면** — 공격이 상대에게 닿으면 히트가 한 번만 발생한다.

const double GETUP_INVINCIBLE_TIME = 0.4;

bool Character::IsInvincible() const
{
    switch (m_state)
    {
    case STATE_DOWN:  return true;
    case STATE_GETUP: return m_stateTimer < GETUP_INVINCIBLE_TIME;
    case STATE_HIT:   return m_stateTimer < 0.05;
    default:          return false;
    }
}
```

   │  ─ 판정 ─                                                 │

- [ ] F1로 파란 hurtbox가 보인다
- [ ] 앉으면 hurtbox가 낮아진다
- [ ] 공격 시 3~4번째 프레임에만 빨간 hitbox가 나타난다

## 6. 자주 막히는 곳

| 증상 | 원인 | 해결 |
|---|---|---|
| 한 번 공격에 여러 번 맞음 | **히트 기록 없음** | `HasHit` / `AddHitRecord` |
| 반전 시 판정이 반대편 | 미러링 누락 | `m_x - offsetX - width` |
| 넉백이 반대 방향 | 넉백 부호 미반전 | `facingLeft ? -kb : kb` |
| 항상 맞음 | 활성 프레임 조건 없음 | `IsHitboxActive` 확인 |
| 판정이 안 들어감 | `startFrame`/`endFrame` 범위 오류 | 0부터 시작인지 확인 |
| 쓰러진 상대를 계속 때림 | 무적 미구현 | `IsInvincible` |
| 판정 위치가 이상함 | 기준점 혼동 | 발밑 중앙 기준 확인 |
| 박스가 안 보임 | `DrawRect`의 `fill=false` 누락 | 테두리만 그리기 |

## 7. 정리

### 오늘 배운 것

| 개념 | 한 줄 요약 |
|---|---|
| **hurtbox / hitbox** | 맞는 부위 / 때리는 부위. **스프라이트와 별개** |
| 공격 3단계 | 발생 전(startup) → 지속(active) → 후딜(recovery) |
| 판정 데이터 | 프레임 범위 + 오프셋 + 크기 + 데미지 + 넉백 |
| **방향 반전** | 박스와 넉백을 함께 미러링 |
| **히트 기록** | 한 번의 공격은 한 번만. 없으면 다단 히트 |
| 애니메이션 동기화 | 애니메이션 프레임이 판정 활성을 결정 |
| 무적 프레임 | 다운·기상 중 무적. 없으면 게임이 성립 안 함 |
| **디버그 렌더링** | 파랑=hurt, 빨강=hit. 안 보이면 디버그 불가 |
| 프레임 정지 | 판정 타이밍 확인의 필수 도구 |
