## 2. 막히는 상황

어제 만든 프로그램을 실행하고 숫자 대신 **`abc`** 를 입력해 보자.

```
선택: abc

그런 선택지는 없다. (시간은 흐르지 않는다)
선택: 그런 선택지는 없다. (시간은 흐르지 않는다)
선택: 그런 선택지는 없다. (시간은 흐르지 않는다)
선택: 그런 선택지는 없다. (시간은 흐르지 않는다)
선택: 그런 선택지는 없다. (시간은 흐르지 않는다)
... 화면이 끝없이 흘러간다 ...
```

**`Ctrl + C`를 눌러야 겨우 멈춘다.** 어제 만든 `continue` 검증은 아무 도움이 안 됐다.

### 왜 이런 일이 벌어지나

```
   scanf_s("%d", &choice);  가 하는 일

   ① 입력 버퍼를 본다:   [ a ][ b ][ c ][ \n ]
                          ▲
                          └── "정수를 읽어야 하는데 'a'다"

   ② 변환 실패 → choice에 아무것도 안 넣고 그냥 반환

   ③ ★ 버퍼는 그대로 둔다:  [ a ][ b ][ c ][ \n ]
                             ▲ 여전히 여기

   ④ 다음 루프에서 다시 scanf_s → ① 로 돌아감 → 무한 반복
```

> **핵심** — `scanf`는 변환에 실패해도 **입력 버퍼를 비우지 않는다.**
> 그래서 같은 쓰레기를 계속 다시 읽으며 폭주한다.

> **막히는 상황이 오늘의 개념을 정확히 지목한다.**
> ① 실패했는지 어떻게 아는가 → **반환값**
> ② 남은 쓰레기를 어떻게 치우는가 → **버퍼 비우기**

## 3. 개념

### 3-1. `scanf`의 반환값 — 성공했는지 묻기

**왜 필요한가** — 실패를 감지하지 못하면 대응할 수도 없다.

`scanf_s`는 **성공적으로 읽어서 저장한 항목의 개수**를 돌려준다.

```c
int choice;
int result = scanf_s("%d", &choice);
```

| 입력 | 반환값 | 뜻 |
|---|:--:|---|
| `5` | `1` | 1개 성공 |
| `abc` | `0` | 변환 실패 |
| `Ctrl+Z` (EOF) | `EOF` (-1) | 입력 끝 |

```c
if (scanf_s("%d", &choice) != 1)
{
    printf("숫자를 입력해 주세요.\n");
    // ★ 여기서 버퍼를 비워야 한다
}
```

> 지금까지 우리는 이 반환값을 **버리고 있었다.** 오늘부터는 반드시 확인한다.

### 3-2. 입력 버퍼 비우기

**왜 필요한가** — 반환값으로 실패를 알았어도, 쓰레기를 치우지 않으면 다음에 또 걸린다.

```c
void ClearInputBuffer(void)
{
    int c;
    while ((c = getchar()) != '\n' && c != EOF)
        ;                    // 개행이나 EOF가 나올 때까지 한 글자씩 버린다
}
```

```
   버퍼:  [ a ][ b ][ c ][ \n ]

   getchar() → 'a' 버림      [ b ][ c ][ \n ]
   getchar() → 'b' 버림      [ c ][ \n ]
   getchar() → 'c' 버림      [ \n ]
   getchar() → '\n' 만남 → 루프 종료, 버퍼가 깨끗해짐

   ★ EOF 검사가 없으면 Ctrl+Z 입력 시 무한 루프가 된다
```

> **`fflush(stdin)`은 쓰지 않는다.**
> 입력 스트림에 대한 `fflush`는 C 표준이 정의하지 않은 동작(undefined behavior)이다.
> Windows에서 우연히 동작하기도 하지만, 다른 환경에서는 아무 일도 안 하거나 이상하게 동작한다.
> **위의 `getchar` 루프를 쓴다.**

### 3-3. 안전 입력 함수 만들기

**왜 필요한가** — 이 검증을 입력받는 곳마다 복붙할 수는 없다. (Day 4에서 배운 그것)

```c
// min ~ max 범위의 정수를 받을 때까지 계속 물어본다
int ReadInt(const char* prompt, int min, int max)
{
    int value = 0;

    while (1)
    {
        printf("%s (%d~%d): ", prompt, min, max);

        int result = scanf_s("%d", &value);

        if (result != 1)                       // ① 변환 실패
        {
            ClearInputBuffer();
            printf("  숫자를 입력해 주세요.\n\n");
            continue;
        }

        ClearInputBuffer();                    // ② 성공해도 남은 개행을 치운다

        if (value < min || value > max)        // ③ 범위 검사
        {
            printf("  %d ~ %d 사이로 입력해 주세요.\n\n", min, max);
            continue;
        }

        return value;                          // ④ 통과
    }
}
```

```
   ┌──────────────────────────────────────────────┐
   │  ReadInt(prompt, min, max)                    │
   │                                               │
   │   프롬프트 출력                                │
   │        ▼                                      │
   │   scanf_s ─── 실패 ──▶ 버퍼 비우기 ──▶ 재시도  │
   │        │ 성공                                 │
   │        ▼                                      │
   │   버퍼 비우기                                  │
   │        ▼                                      │
   │   범위 검사 ─── 밖 ──▶ 안내 ──▶ 재시도         │
   │        │ 안                                   │
   │        ▼                                      │
   │      return value                             │
   └──────────────────────────────────────────────┘

   ★ 이 함수를 통과한 값은 "반드시 min~max 사이의 정수"다
```

**사용**

```c
int choice = ReadInt("선택", 0, 3);
// 여기 도달했다면 choice는 0, 1, 2, 3 중 하나다. 더 검사할 필요 없다.
```

> 이런 함수를 **방어선**이라고 생각하면 된다.
> 방어선을 통과한 데이터는 이후 코드에서 의심하지 않아도 된다.

### 3-4. 성공했을 때도 버퍼를 비우는 이유

**왜 필요한가** — `5`를 입력하면 버퍼에 `5`와 **`\n`** 이 들어온다. `\n`이 남으면 다음 입력이 씹힌다.

```
   입력 "5" + Enter →  버퍼: [ 5 ][ \n ]

   scanf_s("%d", &n)  →  5를 읽음.  버퍼: [ \n ]  ← 개행이 남는다
                                            ▲
   다음에 문자를 읽으려 하면 이 '\n'이 먼저 들어간다
```

```c
char c;
printf("계속하시겠습니까? (y/n): ");
scanf_s("%c", &c, 1);      // ✘ 이전에 남은 '\n'이 들어온다

scanf_s(" %c", &c, 1);     // ✔ %c 앞의 공백이 공백류를 건너뛴다
```

| 서식 | 개행 처리 |
|---|---|
| `%d`, `%f` | 앞의 공백·개행을 **자동으로 건너뛴다** |
| `%c` | 건너뛰지 않는다 → 앞에 공백 `" %c"` 필요 |
| `%s` | 공백을 건너뛰지만, **공백에서 멈춘다** (한 단어만 읽음) |

### 3-5. 문자열 입력 — `fgets`

**왜 필요한가** — 이름 입력 등에서 `scanf("%s")`는 공백이 있는 이름을 못 받고, 버퍼 오버플로 위험도 있다.

```c
char name[20];

fgets(name, sizeof(name), stdin);      // 한 줄 통째로 읽는다 (공백 포함)
```

**`fgets`는 개행 문자까지 함께 넣는다.** 잘라내야 한다.

```c
// 개행 제거
size_t len = strlen(name);
if (len > 0 && name[len - 1] == '\n')
    name[len - 1] = '\0';
```

```
   fgets 결과:  [ 용 ][ 사 ][ \n ][ \0 ]
                              ▲
                              └── 이걸 '\0'으로 바꾸면
   결과:        [ 용 ][ 사 ][ \0 ][ \0 ]   →  "용사"
```

| 함수 | 공백 포함 | 크기 제한 | 개행 |
|---|:--:|:--:|---|
| `scanf("%s")` | ✘ | ✘ 위험 | 남김 |
| `scanf_s("%s", buf, size)` | ✘ | ✔ | 남김 |
| **`fgets`** | ✔ | ✔ | **포함됨 → 잘라야 함** |

### 3-6. 방어적 프로그래밍의 감각

**왜 필요한가** — 이 습관 하나가 앞으로의 디버깅 시간을 크게 줄인다.

> **사용자는 반드시 이상한 것을 넣는다.** 악의가 아니라 실수로.

| 예상 입력 | 실제로 들어오는 것 |
|---|---|
| `1` | `1 ` (뒤에 공백), `０` (전각), `abc`, 빈 입력, 아주 긴 문자열 |
| 좌표 | 화면 밖 좌표, 음수 |
| 파일 경로 | 없는 파일, 권한 없는 경로 |

**검증의 3단계**

```
   ① 형식 검사    "정수인가?"          → scanf 반환값
   ② 범위 검사    "0~3 사이인가?"      → if (v < min || v > max)
   ③ 논리 검사    "지금 할 수 있는가?" → if (열쇠가 없으면 문을 못 연다)
```

> ①②는 오늘 만든 `ReadInt`가 담당한다. ③은 게임 규칙이므로 각자의 자리에서 검사한다.

## 4. 따라 만들기

### Step 1 — 문제 재현

어제 코드를 그대로 두고 `abc`를 입력해 폭주를 **직접 확인**한다.

```
선택: abc
그런 선택지는 없다.
선택: 그런 선택지는 없다.
선택: 그런 선택지는 없다.
...
```

`Ctrl + C`로 종료한다.

**✅ 여기까지 하면** — 문제를 눈으로 봤다. 이제 고칠 차례다.

### Step 2 — 반환값 확인해 보기

```c
        int choice = 0;
        int result = scanf_s("%d", &choice);         // ← 반환값 받기

        printf("[디버그] 반환값 %d, choice %d\n", result, choice);   // ← 추가
```

`abc` 입력 시:

```
[디버그] 반환값 0, choice 0        ← 0 = 실패
[디버그] 반환값 0, choice 0
[디버그] 반환값 0, choice 0        ← 계속 실패. 버퍼가 안 비워졌다
```

**✅ 여기까지 실행하면** — 반환값이 계속 `0`으로 찍히는 것이 보인다. 원인이 확인됐다.

### Step 3 — 버퍼 비우기 함수

```c
void ClearInputBuffer(void);        // ← 원형 선언

// ...

void ClearInputBuffer(void)         // ← 정의
{
    int c;
    while ((c = getchar()) != '\n' && c != EOF)
        ;
}
```

```c
        int result = scanf_s("%d", &choice);

        if (result != 1)                       // ← 추가
        {
            ClearInputBuffer();                // ★ 쓰레기 치우기
            printf("\n숫자를 입력해 주세요.\n");
            continue;
        }

        ClearInputBuffer();                    // ← 성공해도 개행 치우기
```

**✅ 여기까지 실행하면** — `abc`를 입력해도 폭주하지 않고 "숫자를 입력해 주세요"가 **한 번만** 뜨고 다시 물어본다.

### Step 4 — `ReadInt` 함수로 정리

```c
int ReadInt(const char* prompt, int min, int max)
{
    int value = 0;

    while (1)
    {
        printf("%s (%d~%d): ", prompt, min, max);

        if (scanf_s("%d", &value) != 1)
        {
            ClearInputBuffer();
            printf("  숫자를 입력해 주세요.\n\n");
            continue;
        }

        ClearInputBuffer();

        if (value < min || value > max)
        {
            printf("  %d ~ %d 사이로 입력해 주세요.\n\n", min, max);
            continue;
        }

        return value;
    }
}
```

메인 루프가 이렇게 줄어든다:

```c
        int choice = ReadInt("선택", 0, 3);       // ← 한 줄!

        // 여기 도달하면 choice는 반드시 0~3
        if (choice == 0) { running = 0; ending = 2; continue; }

        switch (choice) { /* ... */ }
```

**✅ 여기까지 실행하면** — 메인 루프에서 입력 검증 코드가 전부 사라지고 한 줄이 된다. 동작은 동일하다.

### Step 5 — 이름 입력 (`fgets`)

```c
#include <string.h>              // ← strlen을 위해 추가

void ReadLine(const char* prompt, char* buffer, int size)
{
    printf("%s: ", prompt);

    if (fgets(buffer, size, stdin) == NULL)
    {
        buffer[0] = '\0';
        return;
    }

    // 개행 제거
    size_t len = strlen(buffer);
    if (len > 0 && buffer[len - 1] == '\n')
        buffer[len - 1] = '\0';
}
```

```c
    char playerName[20];
    ReadLine("당신의 이름은", playerName, sizeof(playerName));

    printf("\n%s(이)가 방에서 눈을 떴다.\n", playerName);
```

**✅ 여기까지 실행하면** — 공백이 포함된 이름(`김 용사`)도 정상적으로 받아진다.

### Step 6 — Week 1 RPG에도 적용

`01_rpg_battle` 프로젝트를 열어 `ReadInt`와 `ClearInputBuffer`를 복사해 넣고,
행동 선택을 `int choice = ReadInt("행동을 고르세요", 1, 3);` 로 교체한다.

**✅ 여기까지 실행하면** — RPG도 어떤 입력에 대해 폭주하지 않는다.

## 6. 자주 막히는 곳

| 증상 | 원인 | 해결 |
|---|---|---|
| 여전히 폭주함 | **실패했을 때** 버퍼를 안 비움 | `if (result != 1)` 블록 안에 `ClearInputBuffer()` |
| 첫 입력이 씹힘 | 이전 입력의 `\n`이 남음 | 성공했을 때도 버퍼 비우기 |
| `%c` 입력이 이상함 | 개행이 먼저 들어감 | `scanf_s(" %c", ...)` — 앞에 공백 |
| `Ctrl+Z` 넣으면 무한 루프 | `ClearInputBuffer`에 EOF 검사 없음 | `&& c != EOF` 추가 |
| `fflush(stdin)`이 안 먹힘 | 표준 미정의 동작 | `getchar` 루프로 교체 |
| `fgets` 결과 뒤에 줄바꿈이 붙음 | `\n`이 포함됨 | `strlen`으로 마지막 문자 확인 후 `\0` |
| `1 2 3` 입력 시 뒤 값들이 자동 입력됨 | 버퍼에 남은 값이 다음 `scanf`에 들어감 | 매번 버퍼 비우기 |
| `strlen`에서 오류 | `<string.h>` 누락 | `#include <string.h>` |

## 7. 정리

### 오늘 배운 것

| 개념 | 한 줄 요약 |
|---|---|
| `scanf` 반환값 | 성공적으로 읽은 항목 수. `!= 1`이면 실패 |
| **버퍼 비우기** | 실패해도 버퍼는 안 비워진다. `getchar` 루프로 직접 치운다 |
| `fflush(stdin)` | **쓰지 않는다.** 표준 미정의 동작 |
| `ReadInt` | 형식·범위를 통과한 값만 돌려주는 방어선 함수 |
| `%c` 앞 공백 | `" %c"` 로 개행 건너뛰기 |
| `fgets` | 공백 포함 한 줄 입력. 개행을 직접 잘라낸다 |
| 방어적 프로그래밍 | 사용자는 반드시 이상한 것을 넣는다 |

### 직접 해보기

| 난이도 | 과제 | 힌트 |
|:--:|---|---|
| ★ | `ReadYesNo("계속하시겠습니까")` — y/n만 받는 함수 | `" %c"` + 대소문자 모두 허용 |
| ★★ | `ReadFloat(prompt, min, max)` — 실수 버전 | `%f`, 자료형만 바꾸면 구조는 동일 |
| ★★★ | 입력이 5번 연속 실패하면 "입력을 확인해 주세요" 후 종료 | 실패 카운터를 함수 안에 |
