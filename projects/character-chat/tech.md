이 문서는 "어떻게 만들었나"를 다룬다. 기준일은 2026-10-15.

## 1. 한눈에

| 항목 | 값 |

| 앱 코드 | JS 모듈 5개 약 680줄 + `index.html` 160줄 + CSS 91줄 |
| 런타임 의존성 | **0개** — npm 패키지·프레임워크·번들러 없음 |
| 빌드 | 없음. 정적 서버로 `index.html`을 연다 |

| 테스트 | Node 내장 `node:assert` |

## 3. 아키텍처

서버가 없다. 브라우저가 사용자 PC의 LLM 서버를 직접 부른다.

```text
[브라우저: index.html + app/*.js]
   │ 1. 프롬프트 조립 (캐릭터 카드 + 호감도 + 시각·일정·날씨 + 메모 + 과거 + 포즈·배경 목록 + 최근 40개 메시지)
   ▼
[로컬 LLM 서버 — OpenAI 호환 /chat/completions, stream: true, response_format: json_schema]
   │ 2. SSE 조각 → "dialogue" 부분만 먼저 꺼내 타이핑
   ▼
[parseReply] 3. 완료 후 JSON 전체 파싱 · ID 검증 · 호감도 clamp
   ▼
[연출] 4. 포즈·배경 크로스페이드 + 호감도 바 + 레벨업 토스트 + TTS
   ▼
[IndexedDB] 5. 메시지 단위로 저장 (사건·메모도 메시지에 붙어 있다)
```

**핵심 결정**

- **LLM 접속은 OpenAI 호환 API 하나.** 런타임이 무엇이든 주소만 바꾸면 된다. 연결 테스트는 `GET /models`로 모델 목록을 받아 자동완성에 채운다.
- **연출은 LLM이 직접 고른다.** 감정 분류 모델을 따로 두지 않았다. 포즈 설명 목록을 프롬프트에 넣고 JSON으로 고르게 한다.
- **그림은 미리 만든 것만 쓴다.** 대화 중 이미지 생성이 없어서 지연이 없고 캐릭터 외형이 흔들리지 않는다.

## 4. 핵심 설계 포인트

### 4.1 JSON 스키마로 "고를 수 있는 것"만 허용

응답 규격은 JSON 하나다.

```json
{ "dialogue": "...", "pose": "12", "background": "", "outfit": "", "affection": 2, "event": "", "memo": "..." }
```

`response_format: json_schema` (strict)를 쓰고, 스키마의 `enum`을 **매 턴 다시 만든다.**

| 필드 | enum에 들어가는 것 |
|---|---|
| `pose` | 지금 호감도로 해금됐고, **지금 입은 옷**의 포즈 ID만 |
| `background` | 해금된 배경 ID. 아직 배경이 없으면 `""`를 빼서 반드시 하나 고르게 한다 |
| `outfit` | `""` + 지금과 다른, 해금된 포즈가 있는 옷차림 |
| `affection` | 정수 -2 ~ 2 |

그림이 없는 캐릭터는 `pose`의 `enum`을 아예 넣지 않는다 (빈 `enum`은 서버가 거부한다). 사고형 모델이 `max_tokens`를 추론에 다 써서 대사가 비는 문제는 `reasoning_effort: "none"` 옵션으로 막는다.

### 4.2 스트리밍 중 부분 파싱

JSON이 다 오기 전에도 대사를 먼저 보여 준다. 쌓인 텍스트에서 `"dialogue":"` 뒤 문자열만 정규식으로 꺼내고, 끝에 잘린 이스케이프(`\`, `\u12`)를 떼어 낸 뒤 `JSON.parse`로 복원한다.

```js
const m = text.match(/"dialogue"\s*:\s*"((?:[^"\\]|\\.)*)/);
const s = m[1].replace(/\\(u[0-9a-fA-F]{0,3})?$/, '');
```

타이핑 연출은 목표 문자열이 스트리밍으로 늘어나면 그만큼 계속 친다. 완료 후 `parseReply`가 전체를 파싱한다. 실패하면 응답 원문을 대사로 보여 주고 포즈·호감도는 바꾸지 않는다. 앱은 멈추지 않는다.

### 4.3 옷차림 고정

LLM에게 260장을 전부 주면 대사마다 옷이 바뀐다. 그래서 현재 옷차림을 **현재 포즈에서** 정한다.

1. 후보 포즈 = 해금된 포즈 중 현재 옷차림과 같은 것.
2. LLM이 `outfit`을 적은 턴에만 갈아입고, 그 턴의 포즈는 그 옷의 기본 포즈로 바꾼다 (고른 포즈는 이전 옷 목록에서 나온 것이므로).
3. 다른 옷의 포즈를 골라 오면 무시하고 직전 포즈를 유지한다.

### 4.4 호감도와 재생성

호감도는 따로 저장하지 않고 **메시지마다 붙은 변화량을 다시 합산**한다 (하한 0). 그래서 재생성은 마지막 메시지를 지우고 다시 합산하는 것만으로 호감도·포즈·배경이 함께 되돌아간다.

| Lv | 누적 | 단계 |
|---|---|---|
| 1 | 0~9 | 어색함 |
| 2 | 10~29 | 친구 |
| 3 | 30~59 | 호감 |
| 4 | 60~99 | 설렘 |
| 5 | 100+ | 연인 |

포즈·배경의 `minAffectionLv`, 과거 `lore`의 `minLevel`이 단계별 해금을 맡는다. 단계가 모자란 과거는 내용 대신 "아직 털어놓지 않는다" 회피 지시만 들어간다.

### 4.5 기억

- **사건(`event`)과 메모(`memo`)는 메시지에 붙는다.** 의미 있는 일이 있었던 턴에만 LLM이 채운다. 메시지와 함께 저장·재생성되므로 따로 동기화할 필요가 없다.
- 최근 메모 30개를 `[○○가 사용자에 대해 알고 있는 것·생각]`으로 매 턴 넣는다.
- **공략 완료**: 처음 Lv.5에 닿으면 사건·메모 전체를 별도 요청으로 캐릭터 1인칭 회상 한 단락으로 요약해 이후 프롬프트에 항상 넣는다. 실패하면 다음 응답 뒤 다시 시도한다. 공략 기록은 별도 키에 쌓여 "처음부터"를 눌러도 남는다.

### 4.6 현실 시간

매 턴 프롬프트에 지금 시각·요일, 사는 곳의 실제 날씨, 캐릭터의 현재 일정, 마지막 대화 이후 경과를 넣는다. 일정은 요일·시간 구간 목록이고, 자정을 넘는 구간(예: 23:00~02:00)도 처리한다. 30분 넘게 비면 대화 기록에 `(3시간 뒤)` 같은 표시를 붙이고, 1시간 넘게 지나서 열면 캐릭터가 먼저 말을 건다. 화면 배경의 기본 그라데이션도 시간대(새벽·오전·오후·저녁·밤)를 따른다.

### 4.7 모델 호환

Gemma 계열은 user/assistant 교대와 user 시작을 강제한다. 그래서 같은 역할이 연속되면 합치고, 대화가 캐릭터 인사로 시작하면 앞에 입장 지문(`*스튜디오에 들어선다*`)을 user 메시지로 넣는다. "혼잣말"과 "오랜만의 재방문"은 로그에 보이지 않는 숨은 user 지문으로 처리한다.

### 4.8 연출

`<img>` 두 장을 번갈아 쓰는 크로스페이드 하나로 포즈(300ms)와 배경(500ms)을 모두 처리한다. 같은 ID면 생략하고, 그림을 못 불러오면 기본 포즈로 대체한다.

## 5. 데이터

| 저장 위치 | 키 | 내용 |
|---|---|---|
| IndexedDB `characterchat/kv` | `cc_save_<캐릭터>` | 이름, 호감도, 현재 포즈·배경, 메시지 전체(포즈·호감도 변화·사건·메모 포함), 공략 정보 |
| IndexedDB | `cc_clears_<캐릭터>` | 공략 기록 누적 (날짜, 턴 수, 이름, 회상) |
| localStorage | `cc_settings` | LLM·음성·날씨 설정 (캐릭터 공통) |
| localStorage | `cc_profile` | 사용자 프로필 — 호칭·나이·직업·성격 등 (캐릭터 공통) |

- localStorage(약 5MB)는 대화가 길어지면 넘치므로 대화는 IndexedDB에 둔다. 예전 localStorage 저장분은 첫 실행 때 한 번 옮긴다. `navigator.storage.persist()`로 브라우저가 지우지 않도록 요청한다.
- 대화는 JSON 파일로 내보낼 수 있다 (열람·백업용, 가져오기는 없음).

## 6. 음성

| 방향 | 방식 |
|---|---|
| 입력 | `MediaRecorder` → `OfflineAudioContext`로 16kHz mono 리샘플 → PCM16 WAV를 직접 써서 multipart POST. 결과는 입력창에 채워 사용자가 고친 뒤 보낸다 |
| 출력 | 행동 묘사 `*…*`를 뺀 대사를 GPT-SoVITS `GET /tts`로 합성. 그 서버는 CORS 헤더가 없어서 `fetch`가 아닌 `<audio src>`로 재생한다 (미디어 요소는 CORS가 필요 없다) |

둘 다 설정에서 주소를 비우면 꺼진다.

## 7. 테스트

```bash
node app/parse.test.mjs   # → ok
```

브라우저와 같은 모듈(`parse.js`·`time.js`·`wav.js`)을 Node에서 그대로 불러 단언 24개를 돌린다.

| 대상 | 확인하는 것 |
|---|---|
| 부분 파싱 | 줄바꿈 이스케이프, 잘린 `\`, dialogue 없는 조각 |
| 응답 파싱 | 코드펜스 감싼 JSON, 호감도 clamp, 없는 포즈·배경·옷 ID → null, 깨진 JSON → 원문 대사 |
| 호감도 단계 | 경계값 0·9·10·59·60·100 |
| 일정 | 수업 시간 안/끝, 자정 넘는 구간 |
| 경과·날씨 | 분·시간·일 문구, 날씨 코드 → 한국어 |
| WAV | 헤더 44바이트, 샘플레이트, 범위 밖 값 clamp |

LLM 응답 품질(포즈가 대사에 맞는지)은 자동 테스트가 아니라 직접 대화해 보며 확인했다.

## 8. 알려진 제한

- **로컬 LLM이 있어야 한다.** 웹에 올려 바로 플레이할 수 있는 형태가 아니다. 12B급 모델이 돌아가는 GPU가 필요하다.
- **브라우저 → 로컬 서버 직접 호출**이라 LLM 서버에서 CORS를 허용해야 한다.
- **기억은 단순한 형태다.** 기획서에 있는 사건 경계 판정·점수 기반 검색·망각 단계는 아직 구현하지 않았고, 지금은 최근 메모 30개와 공략 회상만 넣는다.
- 컨텍스트는 최근 메시지 40개(20턴)로 자른다. 그보다 오래된 대화는 메모·사건으로만 남는다.
- 그림이 있는 캐릭터는 아직 1명이다. 나머지 2명은 대사만 나온다.
- 데스크톱 앱 포장(Tauri), 선택지 이벤트, 캐릭터 가져오기는 계획 단계다.
