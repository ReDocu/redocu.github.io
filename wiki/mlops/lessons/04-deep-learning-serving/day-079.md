## ② 왜 필요한가

어제까지 우리는 train 2,629행을 **한 번에** 모델에 넣었습니다(풀배치). 데이터가 3,570행이라

DataLoader(운반차)이고, PyTorch 생태계의 모든 데이터가 이 규격으로 흐릅니다 —
내일도, CNN도, Hugging Face도, 여러분이 만들 커스텀 데이터도.

덤으로 얻는 것도 있습니다. [Day 007](../01-python-data/day-007.md)에서 세트의 프로토콜을,

데이터셋이 됩니다.**

## ③ 개념 설명

### 왜 미니배치인가 — 세 가지 이유

| 이유 | 설명 |
|---|---|
| **메모리** | 한 번에 배치 하나(예: 64행)만 올림 — 데이터가 아무리 커도 OK |
| **수렴** | 배치마다 갱신 → 1 에폭에 35걸음 (풀배치는 1걸음). 같은 계산량으로 더 많이 걸음 |
| 일반화 | 배치마다 조금씩 다른 기울기(노이즈)가 얕은 협곡 탈출을 돕는 경향 |

용어 정리: **배치** = 한 번에 처리하는 묶음, **스텝** = 배치 하나로 1회 갱신,
**에폭(epoch)** = 전체 데이터를 한 바퀴.

### Dataset — 약속 두 개짜리 계약

```python
class 무엇이든Dataset(Dataset):
    def __len__(self):        # ① 전부 몇 건인가
    def __getitem__(self, i): # ② i번째 견본을 (입력, 정답)으로 달라
```

이 둘만 구현하면 DataLoader가 알아서 섞고, 묶고, 실어 나릅니다. CSV든 이미지 폴더든
DB 쿼리든 — **출처가 무엇이든 규격이 같아지는 것**이 이 설계의 힘입니다.

### DataLoader — 옵션 세 개만 우선

| 옵션 | 뜻 | 우리 선택 |
|---|---|---|
| `batch_size` | 묶음 크기 | 64 (메모리와 걸음 수의 흥정) |
| `shuffle` | 에폭마다 순서를 섞나 | **train만 True** |
| `num_workers` | 데이터 준비 병렬 프로세스 | 0 (기본) — 이미지처럼 로딩이 비쌀 때 올림 |

### "시계열인데 shuffle=True라고?" — 좋은 질문입니다

[Day 052](../03-machine-learning/day-052.md)를 제대로 배운 사람이라면 반드시 걸리는 지점입니다. 구분하세요:

```
분할(어느 행이 train인가)  →  시간 기준. 여기가 새면 누수 (Day 052)
배치(train 안에서의 순서)   →  섞어도 됨. train 안에서의 순서는 정보 유출이 아님
```

오히려 시간 순서대로 배치를 만들면 "여름 배치들 → 겨울 배치들"처럼 기울기가 한쪽으로
쏠렸다가 반대로 쏠리는 요동이 생깁니다. **분할은 엄격하게, 배치는 자유롭게.**

### 오늘부터 3분할이 기본

어제 test AUC로 정점(epoch 50)을 고르는 반칙을 했습니다. 오늘부터 교정합니다:

```
train (2024-07 ~ 2025-09) ── 학습
valid (2025-10 ~ 2025-12) ── 에폭마다 감시 (멈출 곳, 구조 선택은 여기서)

```

DL에서는 학습이 비싸 CV 대신 **고정 검증 세트** 하나를 쓰는 것이 관례라는 점만 다릅니다.

### Step 1. 커스텀 Dataset (1~2교시)

```python
# day079_dataset.py — Dataset과 DataLoader
import numpy as np
import pandas as pd
import torch
import torch.nn as nn
from sklearn.metrics import roc_auc_score
from torch.utils.data import DataLoader, Dataset

torch.manual_seed(42)

F10 = ["pm10", "pm25", "o3", "no2", "co", "so2", "temp", "humidity", "wind_speed", "precip"]

print("== A. 커스텀 Dataset — 약속은 두 개뿐 ==")
class AirDataset(Dataset):
    """행 하나를 (특성 텐서, 타깃) 쌍으로 내주는 데이터셋."""

    def __init__(self, frame, mu, sigma):
        x = ((frame[F10] - mu) / sigma).to_numpy()
        self.X = torch.tensor(x, dtype=torch.float32)
        self.y = torch.tensor((frame.pm25_next >= 36).to_numpy(), dtype=torch.float32)

    def __len__(self):                    # 약속 1: 몇 건인가
        return len(self.X)

    def __getitem__(self, i):             # 약속 2: i번째 견본을 달라
        return self.X[i], self.y[i]

df = pd.read_csv("data/air_daily.csv", parse_dates=["date"])
d = df.dropna(subset=F10)
tr = d[d.date < "2025-10-01"]                                  # 학습
va = d[(d.date >= "2025-10-01") & (d.date < "2026-01-01")]     # 검증 (train에서 떼어냄)
te = d[d.date >= "2026-01-01"]                                 # test (금고)
mu, sigma = tr[F10].mean(), tr[F10].std()

train_ds = AirDataset(tr, mu, sigma)
valid_ds = AirDataset(va, mu, sigma)
test_ds = AirDataset(te, mu, sigma)
print(f"train {len(train_ds)} / valid {len(valid_ds)} / test {len(test_ds)}")
x0, y0 = train_ds[0]
print(f"train_ds[0] → x shape {tuple(x0.shape)}, y = {y0.item()}")
```

실행 결과:

```
== A. 커스텀 Dataset — 약속은 두 개뿐 ==
train 2192 / valid 437 / test 868
train_ds[0] → x shape (10,), y = 0.0
```

디테일 두 개를 챙기세요. ① 표준화 통계(mu, sigma)는 **train으로만** 계산해 세 데이터셋에
같은 값을 넘깁니다 — [Day 052](../03-machine-learning/day-052.md)의 원칙이 Dataset 설계에
들어온 것입니다. ② `__getitem__` 은 **한 건**을 돌려줍니다 — 배치로 묶는 건 DataLoader의 일입니다.

### Step 2. DataLoader (3교시)

```python
print("\n== B. DataLoader — 배치를 만들어 주는 컨베이어 ==")

valid_dl = DataLoader(valid_ds, batch_size=256)
xb, yb = next(iter(train_dl))
print(f"배치 하나: X {tuple(xb.shape)} · y {tuple(yb.shape)}")
print(f"에폭당 배치 수: {len(train_dl)}  (= {len(train_ds)}/64 올림)")
```

실행 결과:

```

배치 하나: X (64, 10) · y (64,)
에폭당 배치 수: 35  (= 2192/64 올림)
```

`(10,)` 짜리 견본들이 `(64, 10)` 배치로 — [Day 076](day-076.md)에서 예고한 배치 차원이
이렇게 만들어집니다. 검증 로더는 섞지 않고(순서 무관) 배치만 크게(갱신이 없어 메모리 여유) 잡습니다.

### Step 3. 미니배치 학습 루프 — 표준 완성형 (4~6교시)

이번 주의 최종 형태입니다. 어제 루프에서 바뀐 곳은 **배치 for문**과 **검증 감시** 둘뿐입니다.

```python
print("\n== C. 미니배치 학습 루프 — 표준 완성형 ==")
class MLP(nn.Module):
    def __init__(self, n_in):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(n_in, 32), nn.ReLU(),
            nn.Linear(32, 16), nn.ReLU(),
            nn.Linear(16, 1),
        )

    def forward(self, x):
        return self.net(x).squeeze(1)

def evaluate(model, dl):
    model.eval()                          # 평가 모드
    probs, ys = [], []
    with torch.no_grad():
        for xb, yb in dl:
            probs.append(torch.sigmoid(model(xb)))
            ys.append(yb)
    model.train()                         # 학습 모드로 복귀
    return roc_auc_score(torch.cat(ys).numpy(), torch.cat(probs).numpy())

model = MLP(10)
optimizer = torch.optim.Adam(model.parameters(), lr=0.001)
loss_fn = nn.BCEWithLogitsLoss()

for epoch in range(1, 41):
    running = 0.0
    for xb, yb in train_dl:               # 배치 단위로 5단계
        logits = model(xb)
        loss = loss_fn(logits, yb)
        loss.backward()
        optimizer.step()
        optimizer.zero_grad()
        running += loss.item() * len(xb)
    if epoch in (1, 2, 5, 10, 20, 40):
        print(f"  epoch {epoch:>2}: train loss {running/len(train_ds):.4f} · valid AUC {evaluate(model, valid_dl):.3f}")
```

실행 결과:

```
== C. 미니배치 학습 루프 — 표준 완성형 ==
  epoch  1: train loss 0.6919 · valid AUC 0.866
  epoch  2: train loss 0.5125 · valid AUC 0.887
  epoch  5: train loss 0.2279 · valid AUC 0.897
  epoch 10: train loss 0.2023 · valid AUC 0.886
  epoch 20: train loss 0.1947 · valid AUC 0.874
  epoch 40: train loss 0.1884 · valid AUC 0.860
```

어제는 test를 훔쳐봐야 보이던 곡선이, 오늘은 **합법적으로** 보입니다: valid AUC가
epoch 5(0.897)에서 꺾여 내려갑니다. train loss는 여전히 내려가는데도요. 이제 "5쯤에서
멈춰야 한다"를 **학습 중에** 알 수 있습니다 — 자동으로 멈추고 최고 시점을 저장하는 것은
[Day 081](day-081.md)에서 완성합니다.

`evaluate` 안의 `model.eval()` / `model.train()` 전환도 오늘부터의 습관입니다 — 지금은 차이가
없지만, 모레 드롭아웃이 들어오는 순간 이 전환을 잊으면 **평가 점수가 무작위로 출렁**입니다.

## ⑤ 자주 하는 실수

### __getitem__에서 배치를 돌려줌

**증상** — DataLoader를 통과하면 shape가 `(64, 64, 10)` 처럼 한 겹 더 생김.
**원인** — Dataset은 **한 건**, DataLoader가 묶음 — 이 분업을 어기고 `__getitem__` 이 여러 건을 반환했습니다.
**해결** — `__getitem__(self, i)` 는 i번째 견본 하나만. 묶음 크기는 DataLoader의 batch_size로만 조절합니다.

### 검증·test 로더에도 shuffle=True

**증상** — 평가 점수 자체는 같지만(순서 무관 지표), 예측을 원본 행과 짝지으려는 순간 전부 어긋남.
**원인** — 평가 로더를 섞을 이유가 없는데 습관적으로 켰습니다.
**해결** — shuffle은 train 로더에만. 반대로 **train에 shuffle을 빼먹는 것**도 흔한 실수입니다 — 시간순 배치는 기울기 쏠림을 만듭니다 (③의 구분 참조).

### 표준화 통계를 분할마다 따로 계산

**증상** — valid/test 점수가 미묘하게 이상함. 서빙에서 재현 불가.
**원인** — `AirDataset` 을 만들 때마다 그 조각의 mu/sigma를 새로 계산하면, 세 데이터가 **서로 다른 자**로 측정됩니다 (+ valid/test 통계 사용은 전처리 누수).
**해결** — Step 1처럼 train의 mu/sigma를 **인자로 주입**해 셋이 같은 자를 씁니다. 이 (mu, sigma)는 나중에 서빙에도 따라가야 합니다 ([Day 097](day-097.md)).

### 에폭 손실을 마지막 배치 손실로 보고

**증상** — train loss가 에폭마다 널뜀 — 사실은 마지막 배치 하나의 손실이었음.
**원인** — `print(loss.item())` 을 루프 밖에서 호출하면 마지막 배치 값만 남습니다.
**해결** — Step 3처럼 `running += loss.item() * len(xb)` 로 가중 누적 후 전체 건수로 나눕니다.

### model.eval()을 잊거나, eval 후 train 복귀를 잊음

**증상** — (드롭아웃 도입 후) 평가 점수가 실행마다 다름 / 또는 어느 순간부터 학습이 안 됨.
**원인** — eval 모드는 드롭아웃·배치정규화의 동작을 바꿉니다. 평가 때 안 끄면 예측이 무작위로 흔들리고, 평가 후 train으로 안 돌아오면 이후 학습이 평가 모드로 진행됩니다.
**해결** — `evaluate` 함수 안에 eval/train 전환을 **내장**해 두세요 (Step 3의 구조). 사람이 기억할 일을 구조가 기억하게 — [Day 063](../03-machine-learning/day-063.md)의 철학 그대로입니다.

## ⑥ 확인 문제

**Q1.** Dataset의 두 약속(`__len__`, `__getitem__`)만으로 DataLoader가 "섞기"를 구현할 수 있는
이유를 설명해 보세요.

<details>
<summary>답 보기</summary>

`__len__` 으로 전체 크기 n을 알면 인덱스 [0..n-1]을 만들 수 있고, 에폭마다 이 **인덱스 목록만 섞은 뒤**
`__getitem__(i)` 를 섞인 순서로 호출하면 데이터 자체를 옮기지 않고 셔플이 됩니다. 데이터 접근을
"번호표 뽑기"로 추상화한 덕에 셔플·배치·병렬화가 전부 DataLoader 쪽에서 해결됩니다.

</details>

**Q2.** "시계열 데이터는 무작위로 나누면 안 된다(Day 052)"와 "train DataLoader는 shuffle=True로
섞는다(오늘)"가 모순이 아닌 이유를 설명하세요.

<details>
<summary>답 보기</summary>

누수는 **분할** 단계의 문제입니다 — 미래 행이 train에 들어가면 모델이 볼 수 없어야 할 정보를 봅니다.
반면 셔플은 이미 확정된 train 집합 **안에서 학습 순서**만 바꾸는 것이라 새 정보가 유입되지 않습니다.
오히려 시간순 학습은 계절별 기울기 쏠림을 만들므로, "분할은 시간으로, 배치는 섞어서"가 정답입니다.

</details>

**Q3.** 오늘 루프에서 valid AUC의 역할과 test AUC의 역할을 구분하고, 어제(Day 078)의 어떤 반칙이
교정됐는지 쓰세요.

<details>
<summary>답 보기</summary>

valid는 **학습 중 감시·결정용**(언제 멈출까, 어떤 구조가 나을까 — 여러 번 봐도 됨), test는 모든 결정이
끝난 뒤의 **최종 성능 보고용**(한 번만). 어제는 "몇 에폭이 정점인가"를 test 곡선으로 골랐는데(0.821@50),
그건 에폭 수를 test로 튜닝한 반칙이었습니다. 오늘은 같은 결정을 valid(정점 0.897@5)로 내리고
test는 마지막에 한 번(0.812)만 열었습니다.

</details>
