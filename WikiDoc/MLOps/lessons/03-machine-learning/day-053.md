이 레슨을 마치면 이렇게 할 수 있습니다.

- 선형 회귀가 **무엇을 최소화**하며 직선을 긋는지(손실 함수) 설명할 수 있다.

- **잔차 분석**으로 모델이 어떤 날 틀리는지 찾아내고, 다음 개선 방향을 도출할 수 있다.

## ② 왜 필요한가

어제 시간 분리로 정직하게 잰 선형 회귀는 R² 0.400이었습니다. KNN(0.258)보다 훨씬 낫습니다.
그런데 선형 회귀가 **무엇을 어떻게 배운 것인지** 설명할 수 있나요?

실무에서 모델은 점수만으로 채택되지 않습니다.

```
팀장: "그 모델, 뭘 보고 예측하는 겁니까?"
당신: "……계수가 있는데…… so2가 217이고……"
팀장: "아황산가스가 미세먼지의 200배 중요하다고요?"
```

이 대화에서 살아남는 것이 오늘의 목표입니다. 선형 회귀는 **설명 가능한 모델의 대표**라서
실무에서 기준 모델(baseline)로 가장 오래 살아남는 모델이고, 이후 배울 모든 복잡한 모델은
"선형 회귀보다 얼마나 나은가"로 평가받습니다. 그 기준을 오늘 확실히 다집니다.

또 하나 — 위 대화의 "so2가 217"은 **실제로 오늘 우리 모델이 내놓는 숫자**입니다.
이 숫자를 그대로 읽으면 완전히 틀린 해석이 됩니다. 왜 그런지, 어떻게 읽어야 하는지 배웁니다.

## ③ 개념 설명

### 선형 회귀 — 가장 그럴듯한 직선 긋기

특성이 하나면 직선, 여러 개면 평면(초평면)을 데이터에 맞춥니다.

```
내일pm25 = w₁·pm10 + w₂·pm25 + w₃·풍속 + … + b

w (계수, coefficient) : 각 특성이 1 단위 오를 때 예측이 얼마나 변하나
b (절편, intercept)   : 모든 특성이 0일 때의 예측값
```

`fit(X, y)` 이 하는 일은 **w와 b를 찾는 것**이 전부입니다. 그럼 "가장 그럴듯한" 직선의 기준은?

### 손실 함수 — 틀림을 숫자 하나로

모델이 얼마나 틀렸는지를 숫자 하나로 만든 것이 **손실 함수**(loss function)입니다.
선형 회귀는 **평균 제곱 오차**(MSE)를 씁니다.

```
MSE = (실제₁-예측₁)² + (실제₂-예측₂)² + … 의 평균
```

| 왜 하필 제곱? | 효과 |
|---|---|
| 부호 제거 | +5 틀림과 -5 틀림이 상쇄되지 않음 |
| 큰 오차에 벌점 집중 | 10 틀림(100)은 5 틀림(25)의 **4배** 벌점 → 크게 틀리는 걸 극도로 싫어함 |
| 수학적으로 미분 가능 | 최적의 w, b를 공식으로 바로 구할 수 있음 |

`fit` 은 "MSE를 최소로 만드는 w, b"를 찾습니다. 오늘 실습 Step 1에서 가장 단순한 경우
(직선도 아니고 **상수 하나**로 예측)를 손으로 최적화해 이 감각을 잡습니다.

### "회귀"라는 이상한 이름

regression은 "되돌아감"이라는 뜻입니다. 19세기에 골턴(F. Galton)이 아버지와 아들의 키를
분석했더니, 키 큰 아버지의 아들은 크긴 한데 **아버지만큼은 아니었습니다** — 평균 쪽으로
"되돌아가는" 경향. 이를 **평균으로의 회귀**라 불렀고 그 분석 도구가 지금의 이름이 됐습니다.

오늘 실습 Step 2에서 이 현상을 직접 목격합니다. "오늘 pm25 → 내일 pm25" 회귀의 기울기는
1이 아니라 **0.77**입니다. 오늘 심하게 나쁜 날의 내일은, 나쁘긴 해도 **오늘만큼은 아닌** 쪽에 겁니다.

### 계수 해석의 두 가지 함정

**함정 1 — 계수 크기는 중요도가 아닙니다.** 계수의 단위는 "타깃 단위 / 특성 단위"입니다.
so2는 ppm 단위로 0.003~0.012 사이의 **아주 작은 수**라서, 계수가 커 보여야 겨우 영향을 줍니다.
계수 217은 "so2 1ppm 상승당 217㎍/㎥"인데, so2는 1ppm은커녕 0.01도 잘 안 움직입니다.
**중요도를 비교하려면 특성들을 같은 자(표준편차)로 잰 뒤의 계수**를 봐야 합니다 (Step 4).

**함정 2 — 계수는 "다른 특성이 그대로일 때"의 이야기입니다.** 특성끼리 강하게 상관되어 있으면
(우리 데이터의 pm10·no2·so2·co가 그렇습니다) 역할을 서로 나눠 갖다가 **부호가 뒤집히기도** 합니다.
"o3 계수가 음수네? 오존이 미세먼지를 줄이나?" — 아닙니다. 그런 인과 해석은 금물입니다.

### 스케일링 — 무엇이 바뀌고 무엇이 안 바뀌나

표준화(StandardScaler)는 각 특성을 `(값 - 평균) / 표준편차` 로 바꿔 **평균 0, 표준편차 1**로 만듭니다.

| 모델 | 스케일링하면 |
|---|---|
| 선형 회귀 | 성능 **불변** (직선은 단위를 바꿔도 같은 직선) · 계수가 **비교 가능**해짐 |
| KNN 등 거리 기반 | 성능이 **변함** (거리 계산의 축이 바뀜 — 어제 실험 4) |
| 트리 계열 (W12) | 성능 불변 (분할 기준은 순서만 봄) |

> "스케일링은 항상 해야 한다"가 아니라 **"모델과 목적에 따라 효과가 다르다"** 가 정답입니다.
> fit은 언제나 train에만 — 어제의 원칙은 여기서도 유효합니다.

### 잔차 분석 — 모델의 오답 노트

**잔차**(residual) = 실제 − 예측. 잔차를 뜯어보는 것은 **모델의 오답 노트를 읽는 일**입니다.

| 잔차의 모습 | 뜻 |
|---|---|
| 평균이 0 근처, 패턴 없음 | 모델이 구조를 다 뽑아먹음 — 남은 건 노이즈 |
| 특정 구간에서 한쪽으로 쏠림 | **아직 배우지 못한 구조가 있음** — 개선 여지 |
| 특정 날짜·집단에서 큼 | 그 상황의 특성이 입력에 없음 |

오늘 우리 모델의 오답 노트에는 뚜렷한 패턴이 남아 있습니다 — 그것이 W12(트리 모델)와
[Day 064](day-064.md)(특성 엔지니어링)의 예고편입니다.

## ④ 단계별 실습

### Step 1. 가장 단순한 모델을 손으로 최적화 (1교시)

직선 이전에, **상수 하나로 예측하는 모델**부터. "내일 pm25는 무조건 b다"라고 할 때 최선의 b는?

```python
# day053_linear.py — 선형 회귀: 손실, 계수, 잔차
import numpy as np
import pandas as pd
from sklearn.linear_model import LinearRegression
from sklearn.metrics import mean_absolute_error, r2_score
from sklearn.preprocessing import StandardScaler

pd.set_option("display.width", 140)
df = pd.read_csv("data/air_daily.csv", parse_dates=["date"])
F5 = ["pm10", "pm25", "wind_speed", "humidity", "precip"]

print("== A. 손실 함수 직관: 상수 예측 b의 MSE ==")
d = df.dropna(subset=F5)
tr = d[d.date < "2026-01-01"]; te = d[d.date >= "2026-01-01"]
y = tr.pm25_next
for b in [20, 24, y.mean(), 30, 34]:
    print(f"  b={b:5.1f} → MSE {((y - b) ** 2).mean():7.2f}")
print(f"  (train 평균 = {y.mean():.1f})")
```

실행 결과:

```
== A. 손실 함수 직관: 상수 예측 b의 MSE ==
  b= 20.0 → MSE  134.32
  b= 24.0 → MSE   98.61
  b= 26.5 → MSE   92.53
  b= 30.0 → MSE  105.03
  b= 34.0 → MSE  149.32
  (train 평균 = 26.5)
```

b를 움직여 보면 MSE가 골짜기 모양이고, 바닥이 정확히 **train 평균(26.5)** 입니다.
"MSE를 최소화하는 상수 = 평균" — 그래서 **평균 예측이 모든 회귀 모델의 0층**입니다.
선형 회귀의 `fit` 은 이 골짜기 찾기를 w 10개 + b 의 고차원에서 공식으로 푸는 것뿐입니다.

### Step 2. 특성 1개짜리 회귀 — "평균으로의 회귀" 목격 (2교시)

```python
print("\n== B. 특성 1개짜리 선형 회귀: pm25 → pm25_next ==")
m1 = LinearRegression().fit(tr[["pm25"]], tr.pm25_next)
r2_1 = m1.score(te[["pm25"]], te.pm25_next)
print(f"  기울기 {m1.coef_[0]:.3f} · 절편 {m1.intercept_:.2f} · test R² {r2_1:.3f}")
print(f"  해석: 내일 ≈ {m1.coef_[0]:.2f} × 오늘 + {m1.intercept_:.1f}")
```

실행 결과:

```
== B. 특성 1개짜리 선형 회귀: pm25 → pm25_next ==
  기울기 0.770 · 절편 6.09 · test R² 0.343
  해석: 내일 ≈ 0.77 × 오늘 + 6.1
```

기울기가 1이 아니라 **0.77**입니다. 오늘 60인 극단적인 날의 예측은 0.77×60+6.1 = **52.3** —
모델은 "내일도 나쁘겠지만 오늘만큼은 아닐 것"에 겁니다. 극단값 다음엔 평균 쪽으로
돌아오는 경향이 실제로 있고(정체는 언젠가 풀리므로), 이것이 골턴의 **평균으로의 회귀**이며
이 알고리즘 이름의 유래입니다.

특성 **하나**로 R² 0.343 — 어제 5특성 KNN(0.258)보다 낫습니다. 출발이 좋습니다.

### Step 3. 다특성 회귀 — 특성이 늘면 늘 좋아질까 (3교시)

```python
print("\n== C. 5특성 vs 10특성 (같은 행에서 공정 비교) ==")
F10 = ["pm10", "pm25", "o3", "no2", "co", "so2", "temp", "humidity", "wind_speed", "precip"]
d10 = df.dropna(subset=F10)
tr10 = d10[d10.date < "2026-01-01"]; te10 = d10[d10.date >= "2026-01-01"]
print(f"  행: train {len(tr10)} test {len(te10)}")
m5 = LinearRegression().fit(tr10[F5], tr10.pm25_next)
m10 = LinearRegression().fit(tr10[F10], tr10.pm25_next)
p5, p10 = m5.predict(te10[F5]), m10.predict(te10[F10])
print(f"  5특성 : R² {r2_score(te10.pm25_next, p5):.3f}  MAE {mean_absolute_error(te10.pm25_next, p5):.2f}")
print(f"  10특성: R² {r2_score(te10.pm25_next, p10):.3f}  MAE {mean_absolute_error(te10.pm25_next, p10):.2f}")
```

실행 결과:

```
== C. 5특성 vs 10특성 (같은 행에서 공정 비교) ==
  행: train 2629 test 868
  5특성 : R² 0.389  MAE 4.90
  10특성: R² 0.390  MAE 4.87
```

특성을 **두 배**로 늘렸는데 R²는 0.001 올랐습니다. o3·no2·co·so2는 pm10과 강하게 상관된
"거의 같은 정보"라서 새 정보가 별로 없기 때문입니다. **특성 수 ≠ 정보량**입니다.
(공정 비교를 위해 두 모델 모두 10특성 기준 dropna를 한 같은 행으로 학습했습니다 —
행이 다르면 점수를 비교할 수 없습니다.)

### Step 4. 계수의 함정 — 그리고 표준화 (5교시)

②의 "so2가 217" 대화 현장입니다.

```python
print("\n== D. 계수 해석 — 원 단위 계수는 중요도가 아니다 ==")
for f, c in sorted(zip(F10, m10.coef_), key=lambda x: -abs(x[1])):
    print(f"  {f:<12} {c:+9.3f}")

print("\n== E. 표준화 후 계수 (중요도 비교 가능) ==")
sc = StandardScaler().fit(tr10[F10])
m_std = LinearRegression().fit(sc.transform(tr10[F10]), tr10.pm25_next)
p_std = m_std.predict(sc.transform(te10[F10]))
print(f"  표준화 후 test R²: {r2_score(te10.pm25_next, p_std):.3f}  (성능은 그대로)")
for f, c in sorted(zip(F10, m_std.coef_), key=lambda x: -abs(x[1])):
    print(f"  {f:<12} {c:+7.2f}")
```

실행 결과:

```
== D. 계수 해석 — 원 단위 계수는 중요도가 아니다 ==
  so2           +217.264
  no2            +76.672
  o3             -11.891
  co              -1.077
  pm10            +0.232
  pm25            +0.229

  humidity        +0.019

== E. 표준화 후 계수 (중요도 비교 가능) ==
  표준화 후 test R²: 0.390  (성능은 그대로)
  pm10           +4.41
  pm25           +2.20
  precip         +1.49
  temp           -1.16
  no2            +0.86
  so2            +0.25
  humidity       +0.20
  wind_speed     +0.15
  o3             -0.11
  co             -0.10
```

같은 모델, 같은 성능(0.390), 그런데 순위가 완전히 뒤집혔습니다.

| | 원 단위 계수 | 표준화 계수 |
|---|---|---|
| so2 | **+217.3 (1위)** | +0.25 (6위) |
| pm10 | +0.232 (5위) | **+4.41 (1위)** |

원 단위 계수 +217은 "so2가 **1ppm** 오르면"의 이야기인데, so2는 0.001~0.012 사이에서만
움직입니다. 표준화 계수는 "각 특성이 **자기 표준편차 하나만큼** 움직일 때"로 자를 통일한
것이라 비로소 비교가 됩니다. 진짜 주력은 **pm10과 pm25** — 상식과 일치합니다.

> 팀장의 질문에 대한 정답: "원 단위 계수는 단위 때문에 크기 비교가 안 됩니다.
> 표준편차 기준으로 통일하면 pm10·pm25가 주력이고, so2는 하위권입니다."

두 가지 더 관찰하세요. ① 표준화해도 R²는 0.390 그대로 — **선형 회귀에서 스케일링은
성능이 아니라 해석의 문제**입니다. ② o3·co 계수가 음수 — "오존이 미세먼지를 줄인다"가
아니라, 상관된 특성끼리 역할을 나누다 생긴 잔재입니다. **계수에서 인과를 읽지 마세요.**

### Step 5. 잔차 분석 — 오답 노트 읽기 (6~7교시)

```python
print("\n== F. 잔차 분석 ==")
res = te10.pm25_next - p10
print(f"  잔차 평균 {res.mean():+.2f} · 표준편차 {res.std():.2f}")
worst = te10.assign(pred=p10, resid=res).nlargest(5, "resid")
print("  가장 크게 놓친 날 (실제 ≫ 예측):")
print(worst[["date", "station", "pm25", "pred", "pm25_next", "resid"]].round(1).to_string(index=False))

hi = te10.pm25_next >= 40
print(f"\n  pm25_next ≥ 40 인 날({hi.sum()}일)의 잔차 평균: {res[hi].mean():+.2f}")
lo = te10.pm25_next < 20
print(f"  pm25_next < 20 인 날({lo.sum()}일)의 잔차 평균: {res[lo].mean():+.2f}")
```

실행 결과:

```
== F. 잔차 분석 ==
  잔차 평균 -0.28 · 표준편차 6.09
  가장 크게 놓친 날 (실제 ≫ 예측):
      date station  pm25  pred  pm25_next  resid
2026-04-25     강남구  32.1  30.3       50.6   20.3
2026-04-15     마포구  43.9  38.9       57.6   18.7
2026-03-27     강남구  15.1  16.2       33.1   16.9
2026-04-25     서초구  33.7  30.9       47.4   16.5
2026-04-21     마포구  27.1  27.2       43.6   16.4
```

오답 노트에서 읽어낼 것:

| 관찰 | 해석 | 다음 액션 |
|---|---|---|
| 전체 잔차 평균 -0.28 | 전반적 치우침은 없음 | — |
| 고농도(≥40)에서 잔차 평균 **+7.74** | 나쁜 날을 **일관되게 낮춰** 부름 | 예보 관점에서 최악의 성질 — 나쁜 날을 놓침 |
| 저농도(<20)에서 잔차 평균 **-5.93** | 좋은 날을 높여 부름 | Step 2의 "평균으로의 회귀"가 양방향으로 작동 중 |
| 최악 오답이 전부 **2026년 3~4월** | 봄 황사 **에피소드 시작일**을 예측 못 함 | 오늘 조용하다 내일 터지는 날 — 오늘 정보만으론 한계 |

이 패턴이 남았다는 것은 **모델이 아직 배우지 못한 구조가 있다**는 뜻입니다.
직선으로 잡히지 않는 구조(문턱·상호작용)는 W12의 트리 모델이, "내일 터질 조짐" 정보는
[Day 064](day-064.md)의 예보 특성이 공략합니다. 오답 노트가 곧 로드맵입니다.

## ⑤ 자주 하는 실수

### 계수가 큰 특성이 중요하다고 보고함

**증상** — "so2 계수가 +217로 압도적 1위입니다"라고 발표 자료에 씀.
**원인** — 원 단위 계수는 특성의 **단위와 스케일**에 종속됩니다. 작은 스케일의 특성일수록 계수가 커 보입니다.
**해결** — 중요도 비교는 **표준화 후 계수**로. 원 단위 계수는 "1단위당 효과"의 해석에만 씁니다.

### 문자열 컬럼을 특성에 넣음

```
ValueError: could not convert string to float: '강남구'
```

**원인** — `station` 을 FEATURES에 추가했습니다. 선형 회귀는 숫자만 받습니다.
**해결** — 범주형은 원-핫 인코딩으로 숫자화해야 하며, 올바른 방법(파이프라인 안에서)은 [Day 063](day-063.md)에서 배웁니다. 그때까지는 수치 컬럼만 씁니다.

### 스케일링하면 선형 회귀 점수가 오를 거라 기대함

**증상** — 표준화를 적용했는데 R²가 0.390 그대로라 "적용이 안 됐나?" 의심.
**원인** — 선형 회귀는 축의 단위를 바꿔도 같은 최적 직선을 찾습니다. 성능이 변하는 건 KNN 같은 거리 기반 모델입니다.
**해결** — 정상입니다. 선형 회귀에서 표준화의 목적은 **계수 비교(해석)** 입니다.

### 계수의 부호로 인과관계를 주장함

**증상** — "o3 계수가 음수이므로 오존이 높으면 미세먼지가 줄어든다"고 결론.
**원인** — 상관된 특성들(o3·no2·co·so2·pm10)이 설명력을 나눠 가지면서 개별 부호가 뒤틀립니다(다중공선성).
**해결** — 계수는 "**다른 특성이 고정일 때**"의 조건부 기울기이며, 그마저 상관 구조에 흔들립니다.
인과 주장은 하지 않습니다. 중요도가 필요하면 표준화 계수와 [Day 064](day-064.md)의 중요도 도구를 씁니다.

### 특성 집합이 다른 모델의 점수를 다른 행으로 비교함

**증상** — 5특성 모델은 dropna 후 3,570행, 10특성 모델은 3,497행으로 각각 학습·평가하고 R²를 비교.
**원인** — 결측 패턴이 달라 **시험 범위가 다른 두 시험**의 점수를 비교한 셈입니다.
**해결** — Step 3처럼 **넓은 쪽 기준으로 dropna 한 같은 행**에서 두 모델을 학습·평가합니다.

**Q1.** Step 2에서 "오늘 pm25 → 내일 pm25" 회귀의 기울기는 0.77이었습니다. 오늘 pm25가 70인 날,
모델의 예측은 얼마이며, 이것이 "회귀"라는 이름과 무슨 관련이 있나요?

<details>
<summary>답 보기</summary>

0.77 × 70 + 6.1 = **60.0**. 오늘이 극단적으로 나쁘면 내일은 "나쁘지만 오늘보다는 평균에 가까운" 쪽으로
예측합니다 — 극단값 뒤에는 평균 쪽으로 되돌아가는 경향(**평균으로의 회귀**)이 있고, 이 현상을 분석하던
골턴의 용어가 알고리즘 이름이 됐습니다.

</details>

**Q2.** 원 단위 계수에서 so2(+217.3)가 pm10(+0.232)의 900배가 넘는데, 표준화하면 pm10이 훨씬 중요해집니다.
어느 쪽이 "진짜 중요도"에 가깝고, 왜인가요?

<details>
<summary>답 보기</summary>

**표준화 계수** 쪽입니다. 원 단위 계수는 "특성 1단위당 효과"인데 so2의 1단위(1ppm)는 실제 변동 범위(0.001~0.012)의
100배가 넘는 비현실적 크기라 커 보일 뿐입니다. 표준화 계수는 모든 특성을 "자기 표준편차 1개만큼 움직일 때"로
통일해 실제 변동 대비 영향력을 비교합니다.

</details>
