## ① 학습 목표

이 레슨을 마치면 이렇게 할 수 있습니다.

- `OVER` · `PARTITION BY` 로 **행을 유지한 채** 집계값을 옆에 붙일 수 있다.
- `ROW_NUMBER` · `RANK` · `DENSE_RANK` 의 차이를 알고 **그룹별 상위 N**을 뽑을 수 있다.
- `LAG` · `LEAD` 로 전월 대비 증감을, 프레임 지정으로 **누적·이동 집계**를 만들 수 있다.
- 같은 질문을 서브쿼리로 풀 때와 비교해 **왜 윈도우 함수가 나은지** 설명할 수 있다.

---

## ② 왜 필요한가

`GROUP BY` 에는 치명적인 한계가 하나 있습니다. **행이 사라집니다.**

```sql
SELECT category, SUM(매출) FROM ... GROUP BY category;
--  12개 상품 → 3행.  개별 상품은 볼 수 없음
```

그런데 실무 질문은 **개별 행과 집계값을 나란히** 요구합니다.

| 질문 | `GROUP BY` 로는 |
|---|---|
| "각 상품의 매출과 **그 상품이 속한 카테고리 매출 대비 비중**" | 두 번 쿼리해서 조인 |
| "카테고리별 매출 **1~3위** 상품" | CTE 두 단계 + 조인 ([Day 036](day-036.md)) |
| "월별 매출과 **전월 대비 증감**" | CTE + self join ([Day 036](day-036.md) Step 6) |
| "월별 **누적 매출**" | `JOIN ON b.월 <= a.월` — 행이 제곱으로 폭발 |
| "각 고객의 **직전 주문 이후 며칠 만인지**" | 사실상 불가능 |

어제 이 문제들을 CTE로 우회했습니다. 오늘은 **정면으로 푸는 도구**를 배웁니다.

```sql
-- 어제: CTE 2개 + self join, 12줄
-- 오늘:
SELECT 월, 매출, LAG(매출) OVER (ORDER BY 월) AS 전월매출 FROM 월별매출;
```

**윈도우 함수는 실무 분석 SQL과 SQL 면접의 분수령**입니다.
여기까지 오면 "SQL 좀 한다"는 소리를 듣고, 못 넘으면 매번 Python으로 데이터를 끌어와 처리하게 됩니다.

## ③ 개념 설명

### 한 문장 정의

> **집계는 하되, 행은 그대로 두는 것.**

```
GROUP BY                          윈도우 함수
─────────────────────             ─────────────────────────────
상품 12행                          상품 12행
    ↓ 뭉침                             ↓ 그대로
카테고리 3행                       상품 12행 + 옆에 카테고리 합계 열
(개별 상품 정보 소실)              (개별 정보 유지 ★)
```

### 문법

```sql
집계함수(열) OVER (
    PARTITION BY 그룹기준        -- 어떻게 나눌까 (생략하면 전체가 한 덩어리)
    ORDER BY 정렬기준            -- 어떤 순서로 (누적·순위·LAG에 필요)
    ROWS BETWEEN ... AND ...     -- 어디부터 어디까지 (프레임)
)
```

| 부분 | 역할 | 생략하면 |
|---|---|---|
| `PARTITION BY` | `GROUP BY` 와 같은 "묶는 기준" | **전체가 한 창(window)** |
| `ORDER BY` | 창 안에서의 순서 | 창 전체를 한 번에 집계 |
| 프레임 | 창 안에서 볼 범위 | `ORDER BY` 가 있으면 **처음부터 현재 행까지** |

```sql
SUM(매출) OVER ()                                   -- 전체 합계 (모든 행에 같은 값)
SUM(매출) OVER (PARTITION BY category)              -- 카테고리별 합계
SUM(매출) OVER (ORDER BY 월)                        -- 누적 합계 ★ ORDER BY 만 넣어도 달라짐
SUM(매출) OVER (PARTITION BY category ORDER BY 월)  -- 카테고리별 누적
```

> **`ORDER BY` 를 넣는 순간 "누적"이 됩니다.** 이것이 가장 헷갈리는 지점입니다.
> `ORDER BY` 가 있으면 기본 프레임이 **"창의 시작부터 현재 행까지"** 로 바뀌기 때문입니다.

### 순위 함수 3형제

동점이 있을 때 셋이 갈립니다.

| 함수 | 동점 처리 | 값 예시 (100, 90, 90, 80) |
|---|---|---|
| `ROW_NUMBER()` | 무조건 다른 번호 | 1, 2, 3, 4 |
| `RANK()` | 동점은 같은 등수, **다음은 건너뜀** | 1, 2, 2, **4** |
| `DENSE_RANK()` | 동점은 같은 등수, **다음은 연속** | 1, 2, 2, **3** |

| 언제 쓰나 | 함수 |
|---|---|
| "각 그룹에서 딱 1개만" (중복 제거) | `ROW_NUMBER()` |
| "매출 3위까지" (동점이면 4명이어도 됨) | `RANK()` |
| "상위 3개 가격대" (등수 값 자체가 중요) | `DENSE_RANK()` |

> **`ROW_NUMBER()` 는 `ORDER BY` 에 타이브레이커를 넣으세요.**
> 동점일 때 어느 행이 1번이 될지 정해져 있지 않아, 실행할 때마다 결과가 바뀔 수 있습니다.

### 위치 함수

| 함수 | 하는 일 |
|---|---|
| `LAG(열, n, 기본값)` | **n행 앞**의 값 (기본 n=1) |
| `LEAD(열, n, 기본값)` | **n행 뒤**의 값 |
| `FIRST_VALUE(열)` | 창의 첫 값 |
| `LAST_VALUE(열)` | 창의 마지막 값 (**프레임 주의**) |
| `NTILE(n)` | 창을 n등분해 번호 부여 (사분위 등) |

```sql
LAG(매출) OVER (ORDER BY 월)                    -- 전월 매출
LAG(ordered_at) OVER (PARTITION BY customer_id ORDER BY ordered_at)  -- 직전 주문일
```

### 프레임 — 창 안에서 볼 범위

```sql
ROWS BETWEEN 2 PRECEDING AND CURRENT ROW    -- 직전 2행 + 현재 = 3행 이동 집계
ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW   -- 처음부터 현재까지 (누적, 기본값)
ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING  -- 창 전체
```

> **`LAST_VALUE` 의 함정** — `ORDER BY` 만 쓰면 프레임이 "현재 행까지"라
> `LAST_VALUE` 가 **자기 자신**을 돌려줍니다. 창 전체의 마지막 값을 원하면
> `ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING` 을 명시해야 합니다.

### 실행 순서에서의 위치 ★

```
FROM → WHERE → GROUP BY → HAVING → [윈도우 함수] → SELECT → ORDER BY → LIMIT
                                        ⑤
```

**`WHERE` 와 `HAVING` 보다 나중**입니다. 그래서 두 가지 결과가 나옵니다.

| 결과 | 설명 |
|---|---|
| **`WHERE` 에 윈도우 함수를 쓸 수 없다** | `WHERE RANK() OVER (...) <= 3` ❌ |
| 순위로 걸러내려면 **CTE로 감싸야 한다** | `WITH r AS (...RANK()...) SELECT * FROM r WHERE 순위 <= 3` ✅ |

이 "**윈도우 함수로 순위 매기고 → CTE 밖에서 필터**" 패턴이
**오늘 배우는 것 중 실무에서 가장 많이 쓰는 형태**입니다.

### 집계 함수 vs 윈도우 함수 비교

| | `GROUP BY` | 윈도우 함수 |
|---|---|---|
| 결과 행 수 | 그룹 수 | **원본 그대로** |
| 개별 값 접근 | 불가 | 가능 |
| 순위 | 불가 | `RANK()` 등 |
| 이전/다음 행 | 불가 | `LAG`/`LEAD` |
| 누적·이동 | 불가 (self join 필요) | 프레임으로 |

### Step 1. `OVER ()` — 전체 합계를 옆에 붙이기

어제 CTE 3단계로 했던 "비중" 계산이 **한 줄**이 됩니다.

```

shop-#        SUM(SUM(oi.quantity * oi.unit_price)) OVER () AS 전체매출,
shop-#        ROUND(SUM(oi.quantity * oi.unit_price) * 100.0
shop-#              / SUM(SUM(oi.quantity * oi.unit_price)) OVER (), 2) AS 비중
shop-# FROM order_items oi
shop-# JOIN orders   o ON oi.order_id   = o.order_id
shop-# JOIN products p ON oi.product_id = p.product_id
shop-# WHERE o.status <> 'cancelled'
shop-# GROUP BY p.category, p.name
shop-# ORDER BY 매출 DESC;

**`SUM(SUM(...)) OVER ()` 라는 이상한 모양**에 주목하세요.

```

```

**윈도우 함수는 `GROUP BY` 다음에 실행**되므로, 집계 결과 위에 다시 집계를 얹을 수 있습니다.
이 이중 구조가 처음엔 낯설지만, 익숙해지면 CTE 세 개가 한 줄로 줄어듭니다.

### Step 2. `PARTITION BY` — 그룹별 합계를 옆에

### Step 3. 순위 3형제 비교 ★

```
shop=# WITH 주문금액 AS (
shop(#     SELECT o.order_id, SUM(oi.quantity * oi.unit_price) AS 금액
shop(#     FROM orders o JOIN order_items oi ON o.order_id = oi.order_id
shop(#     WHERE o.status <> 'cancelled'
shop(#     GROUP BY o.order_id
shop(# )
shop-# SELECT order_id, 금액,
shop-#        ROW_NUMBER() OVER (ORDER BY 금액 DESC, order_id) AS row_number,
shop-#        RANK()       OVER (ORDER BY 금액 DESC)           AS rank,
shop-#        DENSE_RANK() OVER (ORDER BY 금액 DESC)           AS dense_rank
shop-# FROM 주문금액
shop-# ORDER BY 금액 DESC, order_id
shop-# LIMIT 10;
 order_id |  금액  | row_number | rank | dense_rank
----------+--------+------------+------+------------
       11 | 518000 |          1 |    1 |          1
        5 | 293000 |          2 |    2 |          2
       21 | 259000 |          3 |    3 |          3
       30 | 259000 |          4 |    3 |          3
       17 | 133000 |          5 |    5 |          4
       10 | 114000 |          6 |    6 |          5
       25 |  94000 |          7 |    7 |          6
        3 |  89000 |          8 |    8 |          7
       26 |  89000 |          9 |    8 |          7
       20 |  79000 |         10 |   10 |          8
(10 rows)
```

**259,000원 동점 두 건(21·30번)에서 셋이 갈립니다.**

| 함수 | 21번 | 30번 | 다음(17번) | 성질 |
|---|---|---|---|---|
| `ROW_NUMBER` | 3 | **4** | 5 | 무조건 다름 |
| `RANK` | 3 | 3 | **5** | 동점 뒤 건너뜀 (**"공동 3위, 다음은 5위"**) |
| `DENSE_RANK` | 3 | 3 | **4** | 동점 뒤 연속 |

> **`ROW_NUMBER` 에 `, order_id` 를 넣은 이유** — 없으면 21번과 30번 중 누가 3번인지 정해지지 않아
> 실행할 때마다 결과가 바뀔 수 있습니다. **`ROW_NUMBER` 에는 항상 타이브레이커를 넣으세요.**

### Step 4. 그룹별 상위 N — 오늘의 핵심 패턴 ★★

[Day 036](day-036.md)에서 CTE 두 단계로 겨우 풀었던 "카테고리별 1위"입니다.
이제 **순위를 매기고 밖에서 거르면** 됩니다. 게다가 "상위 2개"로 바꾸는 것도 숫자 하나만 고치면 끝입니다.

```
shop=# WITH 상품매출 AS (
shop(#     SELECT p.category, p.name, SUM(oi.quantity * oi.unit_price) AS 매출
shop(#     FROM order_items oi
shop(#     JOIN orders   o ON oi.order_id   = o.order_id
shop(#     JOIN products p ON oi.product_id = p.product_id
shop(#     WHERE o.status <> 'cancelled'
shop(#     GROUP BY p.category, p.name
shop(# ),
shop(# 순위 AS (
shop(#     SELECT category, name, 매출,
shop(#            RANK() OVER (PARTITION BY category ORDER BY 매출 DESC) AS 순위
shop(#     FROM 상품매출
shop(# )
shop-# SELECT category AS 카테고리, 순위, name AS 상품, 매출
shop-# FROM 순위
shop-# WHERE 순위 <= 2
shop-# ORDER BY category, 순위;
 카테고리 | 순위 |     상품     |  매출
----------+------+--------------+---------
 사무용품 |    1 | 노트북거치대 |  170000
 사무용품 |    2 | 데스크매트   |   88000
 생활용품 |    1 | 무드등       |  128000
 생활용품 |    2 | 텀블러       |  126000
 전자기기 |    1 | 27인치모니터 | 1295000
 전자기기 |    2 | 기계식키보드 |  356000
(6 rows)
```

**이 3단 구조를 외우세요.**

```
① 집계 CTE        →  원하는 단위로 값을 만든다
② 순위 CTE        →  RANK() OVER (PARTITION BY 그룹 ORDER BY 값 DESC)
③ 바깥 WHERE      →  순위 <= N
```

`WHERE 순위 <= 2` 를 ② 안에 쓸 수 없다는 점이 중요합니다.
**윈도우 함수는 `WHERE` 보다 나중에 실행**되므로 반드시 한 겹 밖에서 걸러야 합니다.

### Step 5. `LAG` — 전월 대비 증감

[Day 036](day-036.md) Step 6의 12줄짜리 self join이 **한 줄**로 줄어듭니다.

```
shop=# WITH 월별매출 AS (
shop(#     SELECT TO_CHAR(o.ordered_at, 'YYYY-MM')  AS 월,
shop(#            SUM(oi.quantity * oi.unit_price)  AS 매출
shop(#     FROM orders o JOIN order_items oi ON o.order_id = oi.order_id
shop(#     WHERE o.status <> 'cancelled'
shop(#     GROUP BY 1
shop(# )
shop-# SELECT 월, 매출,

**1월의 전월매출이 NULL**입니다. 앞 행이 없으니 당연합니다. 기본값을 주려면 세 번째 인자를 씁니다.

> `division by zero` 에러로 배치가 죽는 것보다 낫습니다.

## ⑤ 자주 하는 실수

### `window functions are not allowed in WHERE`

```
shop=# SELECT name, RANK() OVER (ORDER BY price DESC) AS r FROM products WHERE r <= 3;
ERROR:  column "r" does not exist
LINE 1: ...ANK() OVER (ORDER BY price DESC) AS r FROM products WHERE r <...
                                                                    ^

shop=# SELECT name FROM products WHERE RANK() OVER (ORDER BY price DESC) <= 3;
ERROR:  window functions are not allowed in WHERE
```

**원인** — 윈도우 함수는 `WHERE` **다음**에 실행됩니다. `WHERE` 시점엔 순위가 없습니다.
**해결** — CTE(또는 서브쿼리)로 한 겹 감싸고 **밖에서** 거릅니다.

```sql
WITH r AS (SELECT name, price, RANK() OVER (ORDER BY price DESC) AS 순위 FROM products)
SELECT * FROM r WHERE 순위 <= 3;
```

**이 패턴은 예외가 없습니다.** 순위로 거르려면 **무조건 한 겹 더** 필요합니다.

### `column "매출" must appear in the GROUP BY clause`

```
shop=# SELECT category, name, SUM(매출) OVER (PARTITION BY category) FROM 상품매출;
```

**원인** — 윈도우 함수 안의 `SUM` 은 집계가 아니라 **창 계산**입니다.
`GROUP BY` 와 섞어 쓸 때는 **안쪽이 집계, 바깥쪽이 창**이라는 이중 구조가 필요합니다.
**해결** — `SUM(SUM(매출)) OVER (PARTITION BY category)` 또는 CTE로 집계를 먼저 끝냅니다.

**CTE로 나누는 쪽을 권장합니다.** `SUM(SUM(...)) OVER (...)` 는 동작하지만 읽기 어렵습니다.

### `ORDER BY` 를 넣었더니 합계가 누적으로 바뀜

```sql
SUM(매출) OVER ()             -- 2796500 (전체)
SUM(매출) OVER (ORDER BY 월)  -- 182900, 621100, ... (누적) ★
```

**원인** — `ORDER BY` 가 있으면 기본 프레임이 `UNBOUNDED PRECEDING ~ CURRENT ROW` 로 바뀝니다.
**해결** — 전체 합계를 원하면 `ORDER BY` 를 빼거나, 프레임을 명시합니다.

```sql
SUM(매출) OVER (ORDER BY 월 ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING)
```

### `LAST_VALUE` 가 자기 자신을 돌려줌

```sql
LAST_VALUE(매출) OVER (ORDER BY 월)   -- 각 행의 매출값 그대로 ★
```

**원인** — 위와 같은 이유입니다. 프레임이 "현재 행까지"라 마지막 값 = 현재 값입니다.
**해결**

```sql
LAST_VALUE(매출) OVER (ORDER BY 월 ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING)
--  또는 그냥 FIRST_VALUE 를 역순으로:
FIRST_VALUE(매출) OVER (ORDER BY 월 DESC)
```

### `ROW_NUMBER` 결과가 실행할 때마다 다름

```sql
ROW_NUMBER() OVER (ORDER BY 금액 DESC)   -- 동점 21번·30번 중 누가 3등?
```

**원인** — 동점의 순서가 정의돼 있지 않습니다.
**해결** — **타이브레이커를 넣습니다.** `ORDER BY 금액 DESC, order_id`

이 문제는 테스트에서는 안 보이다가 **운영에서 "어제와 결과가 다른데요?"로 터집니다.**
[Day 043](day-043.md)의 멱등성과 같은 종류의 문제입니다.

### `PARTITION BY` 를 빠뜨려 전체 순위가 나옴

```sql
RANK() OVER (ORDER BY 매출 DESC)                        -- 전체 1~12위
RANK() OVER (PARTITION BY category ORDER BY 매출 DESC)  -- 카테고리마다 1위부터
```

**증상** — 에러가 안 납니다. "카테고리별 1위"를 뽑으려 했는데 전체 1위 하나만 나옵니다.
**해결** — `WHERE 순위 <= N` 결과의 **행 수를 확인**하세요.
카테고리 3개에서 1위씩이면 3행이어야 합니다. 1행이면 `PARTITION BY` 가 빠진 것입니다.

### 증감률 계산에서 `division by zero`

```
ERROR:  division by zero
```

**원인** — 전월 매출이 0인 달이 있습니다.
**해결** — `NULLIF(분모, 0)` 으로 0을 NULL로 바꿉니다. 결과는 NULL이 되고 에러는 안 납니다.

```sql
ROUND((매출 - LAG(매출) OVER (ORDER BY 월)) * 100.0
      / NULLIF(LAG(매출) OVER (ORDER BY 월), 0), 2)
```

[Day 044](day-044.md)의 파이프라인에서는 **에러로 배치가 죽는 것**이 최악이라, 이런 방어를 습관으로 넣습니다.

### 같은 `OVER (...)` 를 여러 번 반복해서 씀

```sql
LAG(매출) OVER (ORDER BY 월),
매출 - LAG(매출) OVER (ORDER BY 월),
ROUND((매출 - LAG(매출) OVER (ORDER BY 월)) * 100.0 / LAG(매출) OVER (ORDER BY 월), 2)
```

**증상** — 동작하지만 길고, 하나만 고치면 어긋납니다.
**해결** — `WINDOW` 절로 이름을 붙입니다.

```sql
SELECT 월, 매출,
       LAG(매출) OVER w                                    AS 전월,
       매출 - LAG(매출) OVER w                             AS 증감,
       ROUND((매출 - LAG(매출) OVER w) * 100.0
             / NULLIF(LAG(매출) OVER w, 0), 2)             AS 증감률
FROM 월별매출
WINDOW w AS (ORDER BY 월)
ORDER BY 월;
```

또는 CTE로 `전월` 열을 먼저 만들고, 다음 단계에서 계산하세요. 그쪽이 더 읽기 쉽습니다.

"정렬했다고 써 있으니 정렬됐겠지"가 데이터 분석에서 가장 위험한 태도입니다.

**결과 해석** — 평균 간격이 짧은 김민수·이서연 님이 충성 고객이고,
박지훈(89일)·임채원(83일) 님은 재구매 주기가 깁니다.
단, **재구매 횟수가 1회인 고객의 "평균"은 그냥 그 1회 값**입니다.
표본이 1인 평균으로 이탈을 판단하면 안 됩니다 ([Day 035](day-035.md) 문제 6과 같은 함정).
</details>

**2.** "각 고객의 가장 비싼 주문 1건씩"을 뽑으려 합니다. `RANK()` 와 `ROW_NUMBER()` 중 무엇을 써야 하며, 그 이유는 무엇인가요? 쿼리도 작성하세요.

<details>
<summary>답 보기</summary>

**`ROW_NUMBER()` 를 써야 합니다.**

`RANK()` 를 쓰면 **동점일 때 여러 행이 나옵니다.** "1건씩"이라는 요구를 어깁니다.
어떤 고객이 같은 금액의 주문을 두 번 했다면 그 고객만 2행이 되어, 결과 행 수가 고객 수와 달라집니다.

```sql
WITH 주문금액 AS (
    SELECT o.order_id, o.customer_id, o.ordered_at,
           SUM(oi.quantity * oi.unit_price) AS 금액
    FROM orders o JOIN order_items oi ON o.order_id = oi.order_id
    WHERE o.status <> 'cancelled'
    GROUP BY o.order_id, o.customer_id, o.ordered_at
),
순위 AS (
    SELECT *, ROW_NUMBER() OVER (PARTITION BY customer_id
                                 ORDER BY 금액 DESC, order_id) AS rn
    FROM 주문금액
)
SELECT c.name AS 고객, r.order_id, r.ordered_at AS 주문일, r.금액
FROM 순위 r
JOIN customers c ON r.customer_id = c.customer_id
WHERE r.rn = 1
ORDER BY r.금액 DESC;
```

```
  고객  | order_id |   주문일   |  금액
--------+----------+------------+--------
 윤도현 |       11 | 2025-03-07 | 518000
 최수아 |        5 | 2025-02-02 | 293000
 이서연 |       30 | 2025-06-25 | 259000
 정우진 |       17 | 2025-04-11 | 133000
 조은비 |       10 | 2025-03-03 | 114000
 김민수 |       25 | 2025-05-29 |  94000
 강하은 |       20 | 2025-04-28 |  79000
 한지민 |       24 | 2025-05-24 |  64000
 임채원 |       27 | 2025-06-09 |  29100
 박지훈 |       19 | 2025-04-22 |  27800
(10 rows)
```

**행 수가 10** — 구매 고객 수와 정확히 같습니다. 이것이 `ROW_NUMBER()` 를 쓴 증거입니다.

**`, order_id` 타이브레이커**를 넣은 것도 중요합니다. 없으면 동점일 때 매번 다른 주문이 뽑힙니다.

> **정리** — "그룹마다 정확히 N개" → `ROW_NUMBER()` / "N위까지, 동점 허용" → `RANK()`
</details>

**3.** 아래 두 쿼리의 `누적` 열은 값이 다릅니다. 무엇이 다르며, 어느 쪽이 "한 행씩 누적"인가요?

```sql
-- A
SELECT 월, 매출, SUM(매출) OVER (ORDER BY 월) AS 누적 FROM 월별매출;
-- B
SELECT 월, 매출, SUM(매출) OVER (ORDER BY 월
       ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS 누적 FROM 월별매출;
```

<details>
<summary>답 보기</summary>

**월 값에 중복이 없으면 두 쿼리는 같은 결과를 냅니다.** 이 데이터에서는 6개월이 모두 달라 A = B입니다.

**차이는 `ORDER BY` 열에 동점이 있을 때 드러납니다.**

| | 기본 프레임 | 동점 처리 |
|---|---|---|
| A | `RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW` | **같은 값인 행을 한꺼번에** 포함 |
| B | `ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW` | **정확히 현재 행까지** |

```
값이 [10, 20, 20, 30] 일 때
  A (RANGE):  10, 50, 50, 80    ← 20 두 개를 동시에 처리
  B (ROWS) :  10, 30, 50, 80    ← 한 행씩
```

**"한 행씩 누적"은 B입니다.**

**실무에서 왜 중요한가** — Step 10의 파레토 분석에서 구매액이 동점인 고객이 있으면
A는 두 고객의 누적비중이 **같은 값**으로 나옵니다. "상위 몇 명까지가 80%인가"를 볼 때
경계가 흐려져 잘못된 컷을 잡게 됩니다.

**규칙 — 누적을 계산할 때는 `ROWS` 를 명시하세요.**
`ORDER BY` 열이 유일하다고 확신할 수 없다면 항상입니다. 오늘 배운 것 중 가장 미묘하고,
가장 늦게 발견되는 버그입니다.
</details>

## 오늘의 정리

| 구문 | 하는 일 |
|---|---|
| `SUM(x) OVER ()` | 전체 합계를 **모든 행에** |
| `SUM(x) OVER (PARTITION BY g)` | 그룹 합계를 각 행에 |
| `SUM(x) OVER (ORDER BY t)` | **누적** 합계 |
| `AVG(x) OVER (ORDER BY t ROWS BETWEEN 2 PRECEDING AND CURRENT ROW)` | 3구간 **이동평균** |
| `ROW_NUMBER()` / `RANK()` / `DENSE_RANK()` | 1,2,3,4 / 1,2,2,4 / 1,2,2,3 |
| `LAG(x)` / `LEAD(x)` | 이전 / 다음 행의 값 |
| `PERCENTILE_CONT(0.5) WITHIN GROUP (ORDER BY x)` | 중앙값 |
| `NULLIF(분모, 0)` | 0으로 나누기 방어 |
| `WINDOW w AS (...)` | 반복되는 `OVER` 에 이름 붙이기 |

| 핵심 패턴 | 코드 |
|---|---|
| **그룹별 상위 N** | ① 집계 CTE → ② `RANK() OVER (PARTITION BY ... ORDER BY ... DESC)` → ③ 바깥 `WHERE 순위 <= N` |
| **전월 대비** | `LAG(매출) OVER (ORDER BY 월)` |
| **비중** | `x * 100.0 / SUM(x) OVER ()` |
| **파레토** | `SUM(x) OVER (ORDER BY x DESC ROWS ...) / SUM(x) OVER ()` |

| 함정 | 방어 |
|---|---|
| `WHERE` 에 윈도우 함수 | **CTE로 감싸고 밖에서** 필터 |
| `ORDER BY` 넣으면 누적으로 변함 | 의도한 것인지 확인 |
| `LAST_VALUE` 가 자기 자신 | 프레임을 `UNBOUNDED FOLLOWING` 까지 |
| `ROW_NUMBER` 결과가 매번 다름 | `ORDER BY` 에 **타이브레이커** |
| 동점에서 누적이 껑충 뜀 | `ROWS` 프레임 명시 |

**오늘의 습관** — `OVER (...)` 를 쓸 때마다 **"이 창이 몇 행짜리인가"** 를 소리 내어 말해 보세요.
전체인가, 카테고리별인가, 처음부터 여기까지인가. **창의 크기를 모르면 결과도 모르는 것입니다.**
