## 3. 기획

리듬 게임 *A Dance of Fire and Ice*를 먼저 역기획해 핵심 규칙을 정리했다. "길의 각도가 곧 박자"라는 원버튼 문법이 여기서 나왔다. 그 위에 GDD v1.2를 쓰고, 그림 에셋 없이 도형만으로 움직이는 플레이어블 목업을 만들었다.

GDD에서 정한 것 중 구현에 그대로 남은 것:

| 결정 | 이유 |
|---|---|
| 한 곡을 세 문법(오빗 · 폴 · 스위치)으로 | 게임의 전제 "하나의 곡, 세 개의 문법" |
| 세 모드가 판정 코어 하나를 공유 | 스위치 모드를 별도 엔진 없이 "모드가 섞인 채보"로 만든다 |
| 판정은 DSP 클록 기준 | 화면 프레임과 오디오가 어긋나도 판정은 소리에 붙는다 |
| 전환 직후 1.5배 유예 | 스위치 모드에서 손이 문법을 바꿀 시간을 준다 |
| 스위치는 해금제 | 하드코어 모드라 곡별로 오빗 + 폴을 모두 깨야 열린다 |

## 4. 구현과 검증 순서

### 4.1 웹에서 시작해 데스크톱으로, 다시 웹으로

1. **웹판 초기 구현.** 3모드와 판정 코어, 싱크 스튜디오까지 한 번에 세웠다. 이 시점의 채보는 장르 프로파일 기반 절차 생성이었다.
2. **음원 분석 채보.** 같은 날 바로 온셋 분석으로 바꿨다. 절차 생성 채보는 음악과 따로 놀았기 때문이다.
3. **데스크톱판.** 개발 환경의 브라우저 자동화에서는 소리를 실제로 들으며 확인할 수 없었다. 실제 오디오를 재생하는 pygame판을 따로 만들어 청취 검증 수단으로 삼았다.
4. **데스크톱판에서 먼저 확장.** AUTO · 난이도 · 경로 배치 · 4막을 데스크톱판에서 먼저 만들고 확인했다.
5. **웹판을 데스크톱판에 맞춤.** 쌓인 기능을 웹으로 옮기고, 채보 결과가 숫자로 같은지 대조했다(edm-02 오빗 타일 · 반전 · 솎기 수가 세 난이도 모두 일치).

### 4.2 커밋마다 검증을 남긴다

모든 기능 커밋 메시지 끝에 "검증:" 줄을 두고, 그 변경을 무엇으로 확인했는지 적었다.

| 커밋 | 검증 |
|---|---|
| 온셋 보간 | 브라우저 실측 — 1/4박 그리드 편차 중앙값 20~40 ms |
| 데스크톱판 | 분석 CLI 결과가 웹과 일치, headless 스모크, 화면별 PNG 렌더 |
| AUTO | headless 시간 가속으로 세 모드 578타일 100% PERFECT · 사망 0 |
| 난이도 | edm-02 타일 수 초급 432 < 중급 614 < 고급 892 |
| 경로 배치 | 비인접 타일 최소 49 px, 교차 0, 곡당 솎기 0~1개 |
| 배포 패키징 | ffmpeg 없이 90개 채보 생성, zip을 새로 풀어 exe 실행 |

검증하지 못한 것도 적었다. 데스크톱판 첫 커밋은 "실제 오디오-판정 동기 정확도는 GUI 실행 필요"라고 남겼고, 이후 AUTO 모드가 그 확인 수단이 됐다.

### 4.3 AUTO 모드: 사람의 귀로 확인하는 도구

판정이 음악에 맞는지는 결국 들어 봐야 안다. AUTO 모드는 게임이 정확한 시각에 직접 입력해 전부 PERFECT로 플레이하므로, 사람은 소리와 판정 연출이 맞는지만 들으면 된다. 노트가 음악보다 일정하게 빠르거나 늦으면 오디오 오프셋 문제다.

## 5. Claude Code 협업

세 세션이 이어서 작업했다.

| 세션 | 범위 |
|---|---|
| 1 | 웹판 초기 구현 → 온셋 분석 → 데스크톱판 → AUTO · 난이도 |
| 2 | 오빗 경로 겹침 방지 배치 (데스크톱 → 웹 이식) |
| 3 | 4막 · 웹판 맞춤 · 출시 가이드 · 음원 정리 · 배포 패키징 · 조작 정리 |

- **같은 알고리즘을 두 언어로.** 웹(JS)과 데스크톱(Python)이 분석 · 채보 · 경로 배치를 각자 갖고 있다. 한쪽을 고치면 다른 쪽으로 옮기고, 같은 곡의 결과 숫자를 대조해 맞췄다.
- **넣었다가 뺀 기능.** 플레이 중 Space로 오토를 켜고 끄는 기능을 넣었다가 마지막 커밋에서 뺐다. 오토는 곡 선택에서 고르는 설정으로 되돌리고 Space는 평범한 오빗 탭으로 돌려놨다. itch에 웹판과 윈도우판이 함께 올라가므로 두 판의 조작을 같이 바꿨다.
- **틀린 판단을 고쳐 적기.** 출시 가이드는 처음에 윈도우판을 "지금 형태로는 불가"로 적었다. 이후 분석 캐시를 번들에 구우면 ffmpeg가 필요 없다는 걸 확인하고, 패키징 커밋 메시지에 그 판단이 틀렸다고 남긴 뒤 가이드를 고쳤다.
- **문서는 같은 커밋에서.** 조작이 바뀌면 README 2종 · 배포판 안내문 · 출시 가이드의 한/영 설명문을 같은 커밋에서 고쳤다.

## 6. 배포

itch.io에 웹판(브라우저 실행)과 Windows판을 함께 올린다. 배포 주소는 `eqmentstudio.itch.io/dourbit`이다.

등록 절차는 저장소의 출시 가이드(`docs/itch-release-guide.md`)에 정리했다.

| 장 | 내용 |
|---|---|
| 등록 전 체크리스트 | 화면 잘림 수정(완료) · 음원 라이선스 확인(필수) · 개발용 UI 정리 · 모바일 메모리 |
| zip 만들기 | `build-itch.py` 기준 웹 · 윈도우 절차 |
| 프로젝트 설정값 | 뷰포트 960×640 이상, SharedArrayBuffer 끄기, 생성형 AI 공개(Sound) |
| 페이지 설명문 | 한국어 · 영어 초안 |
| 업로드 후 테스트 | Draft 상태에서 데스크톱 · 모바일 확인 항목 |
| 업데이트 | 웹 UI 재업로드 또는 butler CLI |

itch 임베드 환경은 다른 오리진의 960×540 iframe으로 재현해 확인했다. 이때 곡 선택 화면 위쪽이 잘리는 문제(960×540에서 72 px)를 찾았고, CSS 한 줄(`justify-content: safe center`)로 고쳤다.

## 7. 회고

### 7.1 잘 된 것

- **청취 검증 수단을 따로 만들었다.** 브라우저 자동화로는 소리를 들을 수 없다는 한계를 데스크톱판과 AUTO 모드로 풀었다.
- **두 구현을 숫자로 대조했다.** 웹과 데스크톱의 채보가 타일 수까지 같아서, 한쪽에서 확인한 것을 다른 쪽에도 믿고 쓸 수 있었다.
- **검증을 커밋에 남겼다.** 무엇을 확인했고 무엇을 못 했는지가 히스토리에 남아, 나중에 이어받은 세션이 같은 확인을 반복하지 않았다.
- **배포판 의존을 없앴다.** 분석 결과를 구워 넣어 ffmpeg 없이 실행되게 했고, 첫 로딩 대기도 같이 없앴다.

### 7.2 아쉬운 것

- 자동 테스트 스위트가 없다. 검증이 커밋 시점의 일회성 확인이라, 같은 확인을 다시 돌리려면 사람이 손으로 해야 한다.
- 같은 알고리즘이 두 언어로 있어 고칠 때마다 두 번 고쳐야 한다.
- 템포 자동 추정이 4막 4곡을 못 맞춰 실측값을 박아 넣었다. 추정기의 해상도 문제를 고치지 않고 우회했다.
- 플레이 중 오토 토글처럼, 넣었다가 빼는 기능이 있었다.

### 7.3 다음 단계

1. 음원 라이선스 확인 (출시 가이드의 필수 항목)
2. 곡을 바꿀 때 이전 곡 오디오 버퍼 해제 — 모바일 메모리 문제
3. 채보 일치 대조를 스크립트로 만들어 매번 돌리기
4. 템포 추정의 BPM 해상도 개선 (lag 보간)
