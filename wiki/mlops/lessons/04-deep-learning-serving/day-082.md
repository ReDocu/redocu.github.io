## ② 왜 필요한가

어제의 결론: 규제를 다 발라도 MLP는 valid 0.43대를 못 넘었습니다. **구조가 병목**입니다.

무엇이 문제였나? `Flatten` 이 이미지를 3,072개의 독립된 숫자로 펴는 순간, 두 가지 정보가
파괴됩니다:

```
① 이웃 관계: 픽셀 (3,5)와 (3,6)이 붙어 있다는 사실 — 펴는 순간 남남이 됨
② 위치 불변성: 왼쪽 위의 고양이 귀와 오른쪽 아래의 고양이 귀는 같은 "귀"
   — MLP는 위치마다 별도의 가중치로 다시 배워야 함
```

CNN(합성곱 신경망)은 이 둘을 **구조에 새긴** 부품입니다: 작은 필터가 이미지 전체를
미끄러지며 훑으므로(가중치 공유) 어디에 있든 같은 패턴을 같은 눈으로 보고, 필터가
지역(3×3)만 보므로 이웃 관계가 보존됩니다. 오늘 같은 조건에서 MLP와 정면 대결을 붙여
이 구조의 값어치를 숫자로 확인합니다.

## ③ 개념 설명

### 합성곱 — 필터로 훑기

3×3 필터(커널)가 이미지 위를 한 칸씩 미끄러지며, 겹친 자리의 곱의 합을 출력합니다.
필터의 9개 숫자가 **학습되는 파라미터**이고, 어떤 값이냐에 따라 모서리·질감·색 대비 등
서로 다른 "감지기"가 됩니다 — 오늘 첫 실습에서 모서리 감지기를 손으로 만들어 봅니다.

| 용어 | 뜻 |
|---|---|
| **커널(필터)** | 훑는 작은 창 (보통 3×3). 출력 채널 수만큼 여러 장 |
| **채널** | 감지기의 종류 수. 입력 RGB=3, `Conv2d(3, 32)` 는 감지기 32종을 만든다는 뜻 |
| **패딩** | 가장자리에 0을 둘러 출력 크기를 유지 (`padding=1` + 3×3 → 크기 보존) |
| **풀링** | 구역의 최댓값만 남겨 크기를 절반으로 — "어디쯤 있었는지"만 남기는 요약 |

### CNN의 표준 문법 — 좁아지며 깊어진다

```
(3, 32, 32) ── Conv(3→32)+ReLU ── (32, 32, 32)     감지기 32종의 반응 지도
            ── MaxPool(2)      ── (32, 16, 16)     공간 절반, 요점만
            ── Conv(32→64)+ReLU ── (64, 16, 16)    반응들의 조합 = 더 복잡한 패턴
            ── MaxPool(2)      ── (64, 8, 8)
            ── Flatten + Linear ── 10개 클래스 점수
```

층이 깊어질수록 **공간은 좁아지고 채널(의미)은 깊어집니다** — 앞층은 모서리·색 같은
저수준 특징, 뒷층은 그 조합(질감→부위→물체)을 봅니다. "특성을 손으로 만들지 않고
학습으로 만든다"([Day 076](day-076.md) ②의 약속)가 실현되는 자리가 바로 이 계층입니다.

### 왜 파라미터가 적은가

| | MLP 첫 층 | CNN 첫 층 |
|---|---|---|
| 계산 | 3072 × 512 가중치 | 3×3×3 필터 × 32장 |
| 파라미터 | 1,572,864 | **896** |
| 이유 | 픽셀마다 제 가중치 | **한 필터를 온 이미지가 공유** |

같은 감지기를 전 위치에서 재사용하는 것 — 파라미터가 준다는 것은 곧 암기 용량이 줄고
일반화가 쉬워진다는 뜻입니다 (어제의 언어로: 분산이 작은 구조).

### Step 1. 합성곱을 손으로 — 모서리 감지기 (1~2교시)

```python
# day082_cnn.py — CNN: 이미지의 전용 부품
import torch
import torch.nn as nn
from torch.utils.data import DataLoader, Subset
from torchvision import datasets, transforms

torch.manual_seed(42)

print("== A. 합성곱이 하는 일 — 3×3 필터를 손으로 ==")
img = torch.tensor([[0., 0., 1., 1., 1.],
                    [0., 0., 1., 1., 1.],
                    [0., 0., 1., 1., 1.],
                    [0., 0., 1., 1., 1.],
                    [0., 0., 1., 1., 1.]])          # 왼쪽 어둡고 오른쪽 밝은 이미지
kernel = torch.tensor([[-1., 0., 1.],
                       [-1., 0., 1.],
                       [-1., 0., 1.]])              # 세로 경계 검출 필터
conv = nn.Conv2d(1, 1, kernel_size=3, bias=False)
conv.weight.data = kernel.reshape(1, 1, 3, 3)
out = conv(img.reshape(1, 1, 5, 5)).detach().squeeze()
print("입력(5×5, 왼쪽 어두움/오른쪽 밝음):")
print(img.int())
print("3×3 세로 경계 필터 적용 결과 (3×3):")
print(out.int())
```

실행 결과:

```
== A. 합성곱이 하는 일 — 3×3 필터를 손으로 ==
입력(5×5, 왼쪽 어두움/오른쪽 밝음):
tensor([[0, 0, 1, 1, 1],
        [0, 0, 1, 1, 1],
        [0, 0, 1, 1, 1],
        [0, 0, 1, 1, 1],
        [0, 0, 1, 1, 1]], dtype=torch.int32)
3×3 세로 경계 필터 적용 결과 (3×3):
tensor([[3, 3, 0],
        [3, 3, 0],
        [3, 3, 0]], dtype=torch.int32)
→ 밝기가 바뀌는 경계(2번째 열)에서만 큰 값 — '모서리 감지기'가 됐다
```

필터 `[-1, 0, 1]` 은 "오른쪽에서 왼쪽을 뺀 값" — 밝기가 **변하는 곳**에서만 크게 반응합니다.
균일한 구역(오른쪽 열)에서는 0. 우리가 손으로 설계한 이 감지기를, CNN은 **학습으로 수십 장**
만들어 냅니다 — 어떤 감지기가 유용한지도 데이터가 정합니다.

### Step 2. 두 선수 준비 — 파라미터부터 비교 (3교시)

```python
class SmallCNN(nn.Module):
    def __init__(self):
        super().__init__()
        self.features = nn.Sequential(
            nn.Conv2d(3, 32, 3, padding=1), nn.ReLU(),    # (3,32,32) → (32,32,32)
            nn.MaxPool2d(2),                              # → (32,16,16)
            nn.Conv2d(32, 64, 3, padding=1), nn.ReLU(),   # → (64,16,16)
            nn.MaxPool2d(2),                              # → (64,8,8)
        )
        self.head = nn.Sequential(
            nn.Flatten(),
            nn.Linear(64 * 8 * 8, 128), nn.ReLU(),
            nn.Dropout(0.5),
            nn.Linear(128, 10),
        )

    def forward(self, x):
        return self.head(self.features(x))
```

```
MLP 파라미터: 1,578,506
CNN 파라미터: 545,098
```

CNN이 **3분의 1** 크기입니다. 특징 추출부(features)와 분류부(head)를 나눈 구조도 봐 두세요 —
내일 전이학습에서 "features는 빌리고 head만 교체"가 이 경계선에서 일어납니다.

축소 조건의 숫자입니다 — GPU에서 전체 데이터 + 증강이면 이 구조로도 0.8대에 갑니다 (과제 🖥️).

### Step 4. shape 여행 — 디버깅의 지도 (7교시)

```python
print("\n== D. 중간 텐서의 여행 (CNN 안에서 shape 추적) ==")
x = torch.zeros(1, 3, 32, 32)
for name, layer in cnn.features.named_children():
    x = layer(x)
    print(f"  {layer.__class__.__name__:<10} → {tuple(x.shape)}")
```

실행 결과:

```
== D. 중간 텐서의 여행 (CNN 안에서 shape 추적) ==
  Conv2d     → (1, 32, 32, 32)
  ReLU       → (1, 32, 32, 32)
  MaxPool2d  → (1, 32, 16, 16)
  Conv2d     → (1, 64, 16, 16)
  ReLU       → (1, 64, 16, 16)
  MaxPool2d  → (1, 64, 8, 8)
```

"공간은 절반씩(32→16→8), 채널은 배로(3→32→64)" — ③의 표준 문법이 shape로 보입니다.
head의 `Linear(64 * 8 * 8, ...)` 의 4096이 어디서 왔는지도 이제 자명하죠. CNN을 수정할 때
이 여행표를 먼저 그리는 습관이 shape 에러([Day 076](day-076.md) ⑤)의 예방약입니다.

## ⑤ 자주 하는 실수

### Linear 입력 크기를 손으로 잘못 계산

```
RuntimeError: mat1 and mat2 shapes cannot be multiplied (128x4096 and 2048x128)
```

**원인** — 풀링 횟수를 착각해 `Linear(32*8*8, ...)` 처럼 선언 — Flatten 결과(4096)와 안 맞습니다.
**해결** — Step 4의 shape 여행을 먼저 출력해 보고 그 숫자로 선언하세요. (아예 `nn.LazyLinear(128)` 로 첫 호출 때 자동 결정하게 할 수도 있지만, 먼저 손으로 따라갈 줄 알아야 합니다.)

### 채널 순서(HWC vs CHW) 혼동

**증상** — 외부 이미지(넘파이/PIL, (높이,너비,채널))를 그대로 넣어 shape 에러, 또는 транспose를 잘못해 색이 뒤틀린 채 조용히 학습.
**원인** — PyTorch는 (채널, 높이, 너비) 순서입니다. 다른 생태계(OpenCV·PIL)는 (높이, 너비, 채널).
**해결** — 입구에서 `transforms.ToTensor()` 를 통과시키면 변환·스케일링까지 처리됩니다. 수동 변환 시엔 `permute(2, 0, 1)`.

### 증강을 평가 데이터에도 적용

**증상** — valid 점수가 실행마다 다르고 실제보다 낮게 나옴.
**원인** — 무작위 뒤집기·크롭이 평가 이미지까지 흔들었습니다.
**해결** — train용 transform과 평가용 transform을 **따로** 만듭니다. 증강은 학습 데이터만의 권리입니다 (드롭아웃이 학습 때만이듯).

### 정규화 통계를 대충 씀

**증상** — 학습은 되는데 사전학습 모델(내일)과 붙이면 성능이 이상함.
**원인** — Normalize의 평균·표준편차는 "그 모델이 학습할 때 쓴 값"과 같아야 합니다.
**해결** — 자기 데이터로 학습할 땐 그 데이터의 통계(오늘 CIFAR 값), 사전학습 모델을 쓸 땐 **그 모델의 통계**(내일 ImageNet 값 — [Day 097](day-097.md) 전처리 일치의 이미지판).

### 풀링을 빼먹어 파라미터 폭발

**증상** — CNN인데 파라미터가 수천만 — Flatten 직전이 (64, 32, 32)라 Linear가 거대해짐.
**원인** — 공간 축소(풀링 또는 stride) 없이 채널만 늘렸습니다.
**해결** — "공간 절반, 채널 배로"의 리듬을 지키세요. Flatten 직전 크기가 수천을 넘으면 설계를 다시 봅니다.

<details>
<summary>답 보기</summary>

구조가 데이터의 성질(위치 불변·지역성)과 맞아 상한이 오히려 높아진 것입니다.

**Q3.** features/head 분리 구조가 내일(전이학습)에 왜 중요한지, [Day 089](day-089.md)의 "몸통과
머리" 언어로 미리 설명해 보세요.

<details>
<summary>답 보기</summary>

features(합성곱부)는 모서리→질감→부위로 이어지는 **범용 시각 특징**을 배우는 부분이라 다른 과제에도
재사용 가치가 크고, head(분류부)는 "이 과제의 10개 클래스"에 묶인 부분입니다. 전이학습은 대형
데이터로 학습된 features(몸통)를 빌리고 head(머리)만 우리 클래스 수로 교체하는 것 — 텍스트에서
klue/bert-base 몸통 + 분류 머리와 완전히 같은 구도입니다.

</details>
