### 3-1. WINAPI 기초 (Week 7)

| 개념 | 핵심 |
|---|---|
| `WinMain` | 콘솔의 `main` 대신. `hInstance`, `nCmdShow` |

| `SetTimer` | 주기적 `WM_TIMER`. 정밀도 낮음 |

```
   ★ SelectObject 패턴 (GDI 누수 방지)

   HPEN old = (HPEN)SelectObject(hdc, newPen);
   // ... 그리기 ...
   SelectObject(hdc, old);        // ① 원본 복원
   DeleteObject(newPen);          // ② 삭제
```

### 3-5. 성능 (Week 11)

| 개념 | 핵심 |
|---|---|
| `new`/`delete` 비용 | 실측하면 수백 ns. 프레임당 수백 번이면 문제 |
| 캐시 미스 | 흩어진 메모리 접근이 느린 진짜 이유 |
| **오브젝트 풀** | 미리 만들어 두고 재사용. free list로 O(1) |
| 생명주기 | Reset → Spawn → Update → Despawn → Return |
| 지연 큐 | 순회 중 생성/삭제 금지 → 큐에 모았다가 처리 |
| 공간 분할 | 그리드. O(n²) → O(n) |

```
   ★ 최적화의 순서

   ① 측정한다        (QueryPerformanceCounter)
   ② 병목을 찾는다   (추측 금지)
   ③ 고친다
   ④ 다시 측정한다   (진짜 빨라졌나)
```

### 3-6. 좌표계 (Week 12)

| 개념 | 핵심 |
|---|---|
| **3개 좌표계** | 화면 / 월드 / 타일 |
| 화면 → 월드 | `world = screen / zoom + camera` |
| 월드 → 타일 | `tile = floor(world / TILE)` |
| **`floor` vs `/`** | 음수에서 다르다. 반드시 `floor` |
| 카메라 줌 | 마우스 위치 기준으로 |
| **아이소메트릭** | `sx = (x-y)·W/2`, `sy = (x+y)·H/2` |
| 역변환 | 연립방정식을 풀어서 유도 |
| Undo/Redo | 스트로크 단위 |
| 바이너리 포맷 | 매직 + 버전 + 검증 + 안전 저장 |

```
   ★ 아이소메트릭 역변환 유도

   sx = (x - y) × W/2      ... ①
   sy = (x + y) × H/2      ... ②

   ①/(W/2):  x - y = 2sx/W
   ②/(H/2):  x + y = 2sy/H

   더하기:  2x = 2sx/W + 2sy/H   →  x = sx/W + sy/H
   빼기:    2y = 2sy/H - 2sx/W   →  y = sy/H - sx/W
```

### 3-7. 알고리즘 (Week 13)

| 알고리즘 | 자료구조 | 용도 | 복잡도 |
|---|---|---|:--:|
| **BFS** | 큐 | 균일 비용 최단 경로 | O(V+E) |
| **다익스트라** | 우선순위 큐 | 가중치 최단 경로 | O(E log V) |
| **A\*** | 우선순위 큐 + 휴리스틱 | 목표 지정 최단 경로 | O(E log V) 이하 |

```
   ★ 셋의 관계

   BFS       = 다익스트라에서 모든 비용이 1
   다익스트라 = A* 에서 h = 0

   → A* 가 가장 일반적. h 를 잘 고르면 가장 빠르다
```

```
   ★ A* 의 f = g + h

   g = 시작점부터 실제 비용
   h = 목표까지 추정 비용 (휴리스틱)

   h 가 실제보다 작거나 같으면(허용 가능)  →  최적 경로 보장
   h 를 키우면                            →  빠르지만 최적 아닐 수 있음
```

### 3-8. 수학·물리 (Week 14)

| 개념 | 핵심 |
|---|---|
| 라디안 | `rad = deg × π / 180` |
| `cos`/`sin` | `cos` = x, `sin` = y |
| **y축 반전** | 화면은 아래가 +. `vy = -sin(θ)·P` |
| **중력** | `vy += g·dt`. 위치가 아니라 속도 |
| 사거리 | `R = v²·sin(2θ)/g`. **45도 최대** |
| 바람 | `vx += wind·dt`. 시간 제곱으로 누적 |
| Verlet | `y += vy·dt + ½g·dt²`. 프레임 독립 |
| 원형 파괴 | `dy = √(r² - dx²)` |

### Step 4 — FPS 안정성 검사

```cpp
class FpsMonitor
{
public:
    void Update(double dt)
    {
        m_samples[m_index] = dt;
        m_index = (m_index + 1) % SAMPLE_COUNT;
        if (m_count < SAMPLE_COUNT) m_count++;
    }

    void Report(const char* label)
    {
        double sum = 0, worst = 0;
        for (int i = 0; i < m_count; i++)
        {
            sum += m_samples[i];
            if (m_samples[i] > worst) worst = m_samples[i];
        }

        double avg = sum / m_count;

        DebugLog("[FPS] %-12s  평균 %.1f   최악 %.1f (%.1f ms)\n",
                 label, 1.0/avg, 1.0/worst, worst * 1000);
    }

private:
    static const int SAMPLE_COUNT = 300;
    double m_samples[SAMPLE_COUNT] = {};
    int m_index = 0, m_count = 0;
};
```

```
   ② 안 고쳐도 된다
   ③ 게임 코드는 Renderer 만 알면 된다
   ④ 새 클래스 하나 + 등록 한 줄
```

```
   ⚠️ 게임 코드에 HDC/HWND 가 흩어져 있으면

   → 나중에 렌더러를 바꿀 수 없다
   → Unity/DirectX 로 못 옮긴다
```

### Step 8 — 최종 정리

```cpp
    // 릴리즈 빌드로 전환
    // Debug → Release
    // 디버그 로그 비활성화
```

```cpp
#ifdef _DEBUG
    #define DebugLog(...) OutputDebugStringFmt(__VA_ARGS__)
#else
    #define DebugLog(...) ((void)0)              // ★ 릴리즈에서 제거

```

**✅ 여기까지 실행하면** — 릴리즈 빌드가 정상 동작하고 더 빠르다.

```
   ★ Debug vs Release 성능

   Release : 총알 500개에서 FPS 60+
```

### 평가 A — 개념 확인 (30점)

**서술형. 코드 없이 설명한다.**

| # | 문제 | 배점 |
|:--:|---|:--:|
| 1 | 더블 버퍼링이 깜빡임을 없애는 원리를 설명하라 | 4 |
| 2 | 델타 타임이 왜 필요한가? 없으면 무슨 일이 생기나 | 4 |
| 3 | `SelectObject`를 쓸 때 반드시 지켜야 할 두 가지는? | 3 |
| 4 | 오브젝트 풀이 `new`/`delete`보다 빠른 이유 두 가지 | 4 |
| 5 | BFS, 다익스트라, A\*의 관계를 설명하라 | 5 |
| 6 | A\*의 휴리스틱이 "허용 가능"해야 하는 이유 | 4 |
| 7 | 화면 좌표에서 `vy = -sin(θ)·P`인 이유 | 3 |
| 8 | 바람을 속도가 아니라 가속도로 처리하는 이유 | 3 |

<details>
<summary>모범 답안 요약</summary>

1. 그리는 과정을 메모리 DC에서 다 끝낸 뒤 완성된 그림을 `BitBlt` 한 번으로 옮긴다. 화면에는 "지우는 중간 상태"가 절대 나타나지 않는다.
2. 프레임률이 기기/부하마다 다르기 때문. 없으면 빠른 PC에서 캐릭터가 빨리 움직인다.
3. ① 이전 객체를 저장했다가 원본으로 복원 ② `DeleteObject`로 삭제.
4. ① 힙 할당/해제 호출 자체가 사라진다 ② 연속된 메모리라 캐시 적중률이 높다.
5. BFS는 모든 비용이 1인 다익스트라. 다익스트라는 `h=0`인 A\*.
6. `h`가 실제 비용보다 크면 더 짧은 경로가 있어도 먼저 닫아 버려 최적 경로를 놓친다.
7. 수학 좌표계는 위가 +y지만 화면은 아래가 +y. 부호를 뒤집어야 위로 쏜다.
8. 가속도라야 비행 시간의 제곱으로 누적된다. 높이 쏠수록 크게 밀리는 것이 현실적이고 전략을 만든다.

</details>

```cpp
    SelectObject(m_hdc, old);          // ★
    DeleteObject(brush);
```
</details>

**문제 5 (5점)**

```cpp
bool AStar::FindPath(...)
{
    while (!openList.empty())
    {
        Node* cur = openList.top();
        openList.pop();

        if (cur == goal) return true;

        for (each neighbor)
        {
            double g = cur->g + cost;

            if (g < neighbor->g)
            {
                neighbor->g = g;
                neighbor->parent = cur;
                openList.push(neighbor);
            }
        }
    }
    return false;
}
```

<summary>답</summary>

`closed` 검사가 없다. 이미 확정된 노드를 다시 처리해 무한 루프에 빠질 수 있다 (지연 삭제도 없음).

```cpp
        if (cur->closed) continue;             // ★
        cur->closed = true;
```

</details>

| 증상 | 원인 | 해결 |
|---|---|---|

| Release에서만 느림 | 측정을 Debug로 함 | Release로 측정 |
| 최악 FPS가 나쁨 | 스파이크 | 로그로 원인 추적 |
| 씬 재진입 시 상태 남음 | `Enter`에서 초기화 누락 | 모든 상태 리셋 |
