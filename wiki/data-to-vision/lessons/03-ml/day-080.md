## ② 왜 필요한가

### 정확도 99%짜리 암 진단 모델

이런 모델을 만들었다고 합시다.

```python
class 암진단모델:
    def predict(self, X):
        return np.zeros(len(X))      # 무조건 "정상"
```

**아무것도 안 하는 모델입니다.** 그런데 검진 데이터에서 암 환자가 1%라면?

```
1000명 중 990명 정상, 10명 암
전부 "정상"이라고 답함 → 990명 맞힘 → 정확도 99%
```

**정확도 99%인데 암 환자를 한 명도 못 찾았습니다.**

이 모델을 병원에 납품하면 어떻게 됩니까? 10명이 진단을 놓칩니다.

### 정확도가 무너지는 조건

| 상황 | 정확도가 |
|---|---|
| 클래스가 균형 (50:50) | 잘 작동함 |
| 약간 불균형 (70:30) | 그럭저럭 |
| **심한 불균형 (99:1)** | **완전히 무의미** |
| 오류의 비용이 다름 | **의미가 왜곡됨** |

**실무 데이터는 대부분 불균형입니다.**

```
사기 거래 탐지     : 0.1%
설비 고장 예측     : 0.5%
암 검진           : 1%
이탈 고객 예측     : 5%
스팸 메일         : 30%     ← 이 정도면 양호한 편
```

### 그리고 "틀리는 방식"이 두 가지입니다

```
암인데 정상이라고 함     →  환자가 치료를 못 받음.  치명적
정상인데 암이라고 함     →  추가 검사를 받음.      번거로움
```

**둘 다 "틀림"이지만 무게가 완전히 다릅니다.**
정확도는 이 둘을 구분하지 못합니다. 그래서 다른 지표가 필요합니다.

> **오늘 배우는 것이 프로젝트 평가 설계의 기준이 됩니다.**
> [Day 101](day-101.md)에서 늑대 vs 허스키 프로젝트의 성공 기준을 정할 때,
> "정확도 90% 이상"이라고 쓰기 전에 오늘 배운 것을 떠올려야 합니다.

## ③ 개념 설명

### 혼동행렬 (Confusion Matrix)

**예측 결과를 실제 정답과 교차해 세는 표입니다.**

```
                    예측
                음성(0)    양성(1)
        음성(0)   TN         FP
실제              (정상을    (정상을
                  정상이라)   양성이라)
        양성(1)   FN         TP
                  (양성을    (양성을
                  정상이라)   양성이라)
```

| 약어 | 이름 | 의미 | 다른 이름 |
|---|---|---|---|
| **TP** | True Positive | 양성을 양성이라 함 (**맞힘**) | — |
| **TN** | True Negative | 음성을 음성이라 함 (**맞힘**) | — |
| **FP** | False Positive | 음성을 양성이라 함 (**틀림**) | 오탐, **1종 오류**, 거짓 경보 |
| **FN** | False Negative | 양성을 음성이라 함 (**틀림**) | 미탐, **2종 오류**, 놓침 |

> **약어 읽는 법** — 앞 글자는 "맞았나(True/False)", 뒤 글자는 "무엇이라 예측했나(Positive/Negative)".
> `FN` = "False Negative" = **음성이라고 예측했는데 틀림** = 실제로는 양성인데 놓침.

**암 진단 예시로 채워 보면**

```
                    예측
                정상       암
        정상    985       5      ← 5명이 헛되이 놀람 (FP)
실제
        암        7       3      ← 7명을 놓침 (FN) ★ 치명적
```

```
정확도 = (985 + 3) / 1000 = 98.8%      ← 좋아 보이지만
암 환자 10명 중 3명만 찾음               ← 실제로는 실패
```

### 주요 지표 4개

```
정확도 (Accuracy)  = (TP + TN) / 전체
                     "전체 중 맞힌 비율"

정밀도 (Precision) = TP / (TP + FP)
                     "양성이라 한 것 중 진짜 양성 비율"
                     → 헛다리를 안 짚는가

재현율 (Recall)    = TP / (TP + FN)
                     "진짜 양성 중 찾아낸 비율"
                     → 놓치지 않는가

F1 점수            = 2 × (정밀도 × 재현율) / (정밀도 + 재현율)
                     "정밀도와 재현율의 조화 평균"
```

**위 암 진단 예시로 계산**

| 지표 | 계산 | 값 |
|---|---|---|
| 정확도 | (985+3)/1000 | **0.988** |
| 정밀도 | 3/(3+5) | **0.375** |
| 재현율 | 3/(3+7) | **0.300** |
| F1 | 2×(0.375×0.3)/(0.375+0.3) | **0.333** |

**정확도 0.988 vs F1 0.333.** 같은 모델입니다. 어느 쪽이 실상을 말합니까?

### 정밀도와 재현율 — 외우는 법

```
정밀도(Precision) : 예측을 기준으로 센다
                    "양성이라고 한 것들" 중에서
                    ┌─────────────┐
                    │  TP  │  FP  │   ← 분모
                    └─────────────┘

재현율(Recall)    : 실제를 기준으로 센다
                    "실제 양성인 것들" 중에서
                    ┌──────┐
                    │  TP  │           ← 분모
                    ├──────┤
                    │  FN  │
                    └──────┘
```

| 한 문장으로 | |
|---|---|
| **정밀도** | "네가 양성이라 한 것, 믿어도 되니?" |
| **재현율** | "진짜 양성, 다 찾았니?" |

### 트레이드오프 — 하나를 올리면 하나가 내려간다

```
극단 1: 전부 양성이라고 답한다
        → 재현율 100% (다 찾음)
        → 정밀도 최저 (거의 다 헛다리)

극단 2: 확실한 것 하나만 양성이라 한다
        → 정밀도 100% (틀린 게 없음)
        → 재현율 최저 (대부분 놓침)
```

**둘 다 100%는 불가능합니다.** 그래서 **문제에 따라 무엇을 우선할지 정해야 합니다.**

| 문제 | 우선 지표 | 이유 |
|---|---|---|
| **암 진단** | **재현율** | 놓치면 사람이 죽음. 헛경보는 재검사로 해결 |
| **스팸 필터** | **정밀도** | 중요 메일이 스팸함에 가면 큰일. 스팸 몇 개 통과는 참을 만함 |
| **사기 거래 탐지** | 재현율 우선, 정밀도도 고려 | 놓치면 손실. 그런데 정상 거래 차단도 고객 이탈 |
| **추천 시스템** | **정밀도** | 추천한 것이 마음에 들어야 함. 좋은 걸 몇 개 놓쳐도 괜찮음 |
| **불량품 검사** | **재현율** | 불량이 출하되면 리콜. 정상품 재검사는 비용만 듦 |

> **"어떤 지표를 쓸까"는 기술적 질문이 아니라 **비즈니스 질문**입니다.
> **틀렸을 때 누가 무슨 손해를 보는가**를 먼저 정해야 지표가 정해집니다.

### F1과 그 변형

**F1** — 정밀도와 재현율의 **조화 평균**입니다. 산술 평균이 아닙니다.

```
정밀도 1.0, 재현율 0.0 인 경우
  산술 평균 = 0.5      ← 괜찮아 보임 (잘못된 인상)
  조화 평균 = 0.0      ← 쓸모없다고 정확히 말함
```

**조화 평균은 낮은 쪽에 끌려갑니다.** 그래서 한쪽만 높은 모델을 걸러 냅니다.

**F-beta** — 어느 쪽을 더 중시할지 조절합니다.

```
F_β = (1 + β²) × (정밀도 × 재현율) / (β² × 정밀도 + 재현율)
```

| β | 이름 | 성격 |
|---|---|---|
| 0.5 | F0.5 | **정밀도** 중시 |
| 1 | F1 | 균형 |
| 2 | **F2** | **재현율** 중시 (암 진단 등) |

### 임계값 조정

[Day 078](day-078.md)에서 배운 `predict_proba` 를 씁니다.

```python
proba = model.predict_proba(X_test)[:, 1]      # 양성 확률
pred = (proba >= 0.5).astype(int)              # 기본 임계값
pred = (proba >= 0.3).astype(int)              # 낮춤 → 재현율↑ 정밀도↓
pred = (proba >= 0.8).astype(int)              # 높임 → 정밀도↑ 재현율↓
```

```
임계값 낮춤 (0.3)                임계값 높임 (0.8)
양성이라 판정하는 범위 ↑          양성이라 판정하는 범위 ↓
→ 더 많이 찾음 (재현율↑)         → 확실한 것만 (정밀도↑)
→ 헛다리도 늘어남 (정밀도↓)       → 많이 놓침 (재현율↓)
```

> **`model.predict()` 는 임계값 0.5를 쓴 결과일 뿐입니다.**
> 0.5는 기본값이지 정답이 아닙니다. 불균형 데이터에서는 조정이 거의 필수입니다.

### ROC 곡선과 AUC

**임계값을 0부터 1까지 다 바꿔가며 성능을 그린 곡선입니다.**

```
TPR (재현율) = TP / (TP + FN)      ← 진짜 양성을 얼마나 잡나
FPR          = FP / (FP + TN)      ← 음성을 얼마나 잘못 잡나
```

```
TPR
1.0│      ╭────────────  ← 완벽한 모델 (AUC=1.0)
   │    ╱
   │  ╱  ╱ ← 좋은 모델 (AUC≈0.9)
0.5│ ╱ ╱
   │╱╱  ╱ ← 랜덤 (AUC=0.5)
   │  ╱
0.0└─────────────── FPR
   0.0          1.0
```

**AUC (Area Under Curve)** — 곡선 아래 면적.

| AUC | 해석 |
|---|---|
| 1.0 | 완벽 |
| 0.9~1.0 | 매우 좋음 |
| 0.8~0.9 | 좋음 |
| 0.7~0.8 | 쓸 만함 |
| **0.5** | **랜덤 찍기와 동일** |
| < 0.5 | 반대로 예측 중 (라벨을 뒤집으면 됨) |

**AUC의 의미** — 무작위로 양성 1개, 음성 1개를 뽑았을 때, **모델이 양성에 더 높은 확률을 줄 확률**입니다.

| AUC의 장점 | AUC의 함정 |
|---|---|
| 임계값과 무관 | **심한 불균형에서 낙관적으로 보임** |
| 모델끼리 비교하기 좋음 | 실제 운영 임계값의 성능을 못 보여 줌 |

> ⚠️ **불균형이 심하면 ROC 대신 PR 곡선(Precision-Recall)** 을 보세요.
> ROC의 FPR은 분모가 TN인데, 음성이 압도적으로 많으면 FP가 좀 늘어도 FPR이 거의 안 움직입니다.
> **AUC 0.95인데 정밀도가 0.05인 모델**이 나올 수 있습니다. 실습 Step 5에서 직접 봅니다.

### classification_report

```python
from sklearn.metrics import classification_report
print(classification_report(y_test, y_pred, target_names=["정상", "암"]))
```

```
              precision    recall  f1-score   support

        정상       0.99      0.99      0.99       990
          암       0.38      0.30      0.33        10

    accuracy                           0.99      1000
   macro avg       0.68      0.65      0.66      1000
weighted avg       0.98      0.98      0.98      1000
```

| 행 | 의미 |
|---|---|
| 클래스별 행 | 각 클래스를 양성으로 봤을 때의 지표 |
| `support` | 그 클래스의 실제 개수 |
| `accuracy` | 전체 정확도 |
| **`macro avg`** | 클래스별 지표의 **단순 평균** (소수 클래스도 동등하게) |
| `weighted avg` | 개수로 가중 평균 (다수 클래스에 끌려감) |

> **불균형 데이터에서는 `macro avg` 를 보세요.** `weighted avg` 는 정확도와 비슷하게 왜곡됩니다.
> 위 예시에서 weighted avg f1은 0.98이지만 macro avg는 0.66입니다. **후자가 실상입니다.**

## ④ 단계별 실습

### Step 1. 99% 함정 직접 만들어 보기

```python
import numpy as np
from sklearn.datasets import make_classification
from sklearn.dummy import DummyClassifier
from sklearn.ensemble import RandomForestClassifier
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import (accuracy_score, classification_report,
                             confusion_matrix, f1_score, precision_score,
                             recall_score)
from sklearn.model_selection import train_test_split

# 99 : 1 불균형 데이터
X, y = make_classification(
    n_samples=10000,
    n_features=20,
    n_informative=6,
    n_redundant=2,
    weights=[0.99, 0.01],       # ← 클래스 비율
    flip_y=0.01,
    class_sep=0.9,
    random_state=42,
)

X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.3, random_state=42, stratify=y
)

print("=" * 62)
print("불균형 데이터 (99 : 1)")
print("=" * 62)
print(f"전체     : {len(y):,}건")
print(f"  음성(0): {(y == 0).sum():,}건 ({(y == 0).mean():.2%})")
print(f"  양성(1): {(y == 1).sum():,}건 ({(y == 1).mean():.2%})")
print(f"테스트셋 : {len(y_test):,}건 (양성 {(y_test == 1).sum()}건)")
print("=" * 62)

models = {
    "무조건 음성 (DummyClassifier)": DummyClassifier(strategy="most_frequent"),
    "로지스틱 회귀": LogisticRegression(max_iter=5000, random_state=42),
    "랜덤포레스트": RandomForestClassifier(n_estimators=200, random_state=42, n_jobs=-1),
}

print(f"\n{'모델':<32}{'정확도':>9}{'정밀도':>9}{'재현율':>9}{'F1':>9}")
print("-" * 70)

for name, m in models.items():
    m.fit(X_train, y_train)
    pred = m.predict(X_test)
    print(f"{name:<31}"
          f"{accuracy_score(y_test, pred):>9.4f}"
          f"{precision_score(y_test, pred, zero_division=0):>9.4f}"
          f"{recall_score(y_test, pred):>9.4f}"
          f"{f1_score(y_test, pred):>9.4f}")

print("-" * 70)
print("아무것도 안 하는 모델의 정확도가 0.99 입니다.")
print("정확도로 모델을 고르면 이 모델이 '좋은 모델'이 됩니다.")
print("=" * 70)

# 혼동행렬로 보면 명백합니다
dummy = DummyClassifier(strategy="most_frequent").fit(X_train, y_train)
cm = confusion_matrix(y_test, dummy.predict(X_test))
print("\n[무조건 음성 모델의 혼동행렬]")
print(f"              예측음성   예측양성")
print(f"  실제음성   {cm[0, 0]:>8}   {cm[0, 1]:>8}")
print(f"  실제양성   {cm[1, 0]:>8}   {cm[1, 1]:>8}   ← 양성을 하나도 못 찾음")
```

```python
print()

recall = tp / (tp + fn) if (tp + fn) else 0

specificity = tn / (tn + fp)

print("[손으로 계산한 지표]")
```

```python
ax.grid(alpha=0.3)
```

### Step 5. 불균형 대응 — class_weight

```python

     make_pipeline(StandardScaler(), LogisticRegression(max_iter=5000, random_state=42))),
    ("로지스틱 + class_weight",
     make_pipeline(StandardScaler(),
                   LogisticRegression(max_iter=5000, class_weight="balanced", random_state=42))),
    ("RF (기본)",
     RandomForestClassifier(n_estimators=200, random_state=42, n_jobs=-1)),

     RandomForestClassifier(n_estimators=200, class_weight="balanced",

     RandomForestClassifier(n_estimators=200, class_weight="balanced_subsample",
                            random_state=42, n_jobs=-1)),

    m.fit(X_train, y_train)

    rows.append({
        "설정": name,
        "TP": tp, "FP": fp, "FN": fn,
        "정밀도": round(precision_score(y_test, pred, zero_division=0), 4),
        "재현율": round(recall_score(y_test, pred), 4),
        "F1": round(f1_score(y_test, pred, zero_division=0), 4),
        "PR-AUC": round(average_precision_score(y_test, proba), 4),
    })

print("=" * 96)

print("=" * 96)

print(f"  가중치 = 전체 / (클래스수 × 클래스별 개수)")
n0, n1 = (y_train == 0).sum(), (y_train == 1).sum()
print(f"    클래스 0: {len(y_train)} / (2 × {n0}) = {len(y_train) / (2 * n0):.4f}")

      f"   ← 약 {(len(y_train) / (2 * n1)) / (len(y_train) / (2 * n0)):.0f}배 무겁게")
print()
```

```python
from pathlib import Path

    try:
```

| 상황 | 지표 |
|---|---|
| 균형 데이터, 오류 비용 동일 | 정확도 |
| 불균형, 균형 잡힌 판단 | **F1** |
| 놓치면 안 됨 | **F2**, 재현율 |
| 오탐이 비쌈 | **F0.5**, 정밀도 |
| 모델 판별력 자체 비교 | **PR-AUC** |
| 비용을 계산할 수 있음 | **총비용** ← 가장 좋음 |

### ROC-AUC만 보고 불균형 데이터를 판단

```python
print(f"AUC = {roc_auc_score(y_test, proba):.4f}")     # 0.95 — 좋아 보임
```

**해결** — 불균형이 심하면 **PR-AUC(`average_precision_score`)** 를 함께 보세요.
실습 Step 4에서 KNN의 ROC-AUC 0.881, PR-AUC 0.391을 확인했습니다.

| `"micro"` | 전체 TP/FP/FN을 모아서 계산 (= 정확도와 같아짐) |

## ⑥ 확인 문제

**1.** 아래 혼동행렬을 보고 정확도·정밀도·재현율·F1을 손으로 계산하고, 이 모델을 실제로 배포해도 되는지 판단하세요.

```
스팸 필터 (양성 = 스팸)

                예측: 정상   예측: 스팸
  실제: 정상        8,850        150
  실제: 스팸          320        680
```

<details>
<summary>답 보기</summary>

**지표 계산**

```
TN = 8850,  FP = 150,  FN = 320,  TP = 680      전체 = 10,000

정확도 = (680 + 8850) / 10000 = 0.9530
정밀도 = 680 / (680 + 150)    = 0.8193
재현율 = 680 / (680 + 320)    = 0.6800
F1     = 2 × (0.8193 × 0.68) / (0.8193 + 0.68) = 0.7432
```

**코드로 검산**

```python
import numpy as np
from sklearn.metrics import classification_report

tn, fp, fn, tp = 8850, 150, 320, 680

y_true = np.array([0] * (tn + fp) + [1] * (fn + tp))
y_pred = np.array([0] * tn + [1] * fp + [0] * fn + [1] * tp)

print(classification_report(y_true, y_pred,
                            target_names=["ham", "spam"], digits=4))

cost_fp = 5000    # 정상 메일이 스팸함으로 → 업무 손실 (원)
cost_fn = 100     # 스팸이 받은편지함으로 → 삭제 수고 (원)
print(f"\n비용 추정")
print(f"  FP {fp}건 × {cost_fp:,}원 = {fp * cost_fp:,}원")
print(f"  FN {fn}건 × {cost_fn:,}원 = {fn * cost_fn:,}원")
print(f"  합계 {fp * cost_fp + fn * cost_fn:,}원")
```

**배포 판단: 이 상태로는 부적합합니다.**

| 근거 | 설명 |
|---|---|
| **FP 150건이 문제** | 정상 메일 150통이 스팸함으로 갔습니다. **계약서·면접 안내가 사라질 수 있습니다** |
| 정밀도 0.819 | 스팸이라 한 것 5통 중 1통은 정상 메일 |
| 비용 구조 | FP 비용이 FN의 50배. **정밀도를 올려야 합니다** |
| 재현율 0.68은 참을 만함 | 스팸 320통이 통과해도 사용자가 지우면 됩니다 |

**개선 방향**

```
임계값을 높인다 (0.5 → 0.8)
  → 정밀도 ↑ (FP 감소)
  → 재현율 ↓ (FN 증가)  ← 이건 괜찮음

목표: 정밀도 0.98 이상 (스팸함에 간 것 50통 중 1통만 정상)
```

**평가 지표 선택** — F1이 아니라 **F0.5**(정밀도 중시) 또는 **"재현율 ≥ 0.5 제약 하에서 정밀도 최대화"** 로 설정해야 합니다.

> **"정확도 95.3%인 스팸 필터"** 는 그럴듯하게 들립니다.
> 그런데 실제로는 **한 달에 정상 메일 150통을 잃는 시스템**입니다.
> 이것이 지표를 잘못 고르면 생기는 일입니다.

```python
import numpy as np

# 임계값별 총비용 계산
COST_FN = 2_000_000     # 연체 손실
COST_FP = 500_000       # 고객 상실

best = None
for t in np.arange(0.05, 0.96, 0.05):
    pred = (proba >= t).astype(int)
    tn, fp, fn, tp = confusion_matrix(y_test, pred).ravel()
    total = fn * COST_FN + fp * COST_FP
    if best is None or total < best[1]:
        best = (t, total, fn, fp)

print(f"최적 임계값 {best[0]:.2f} → 총비용 {best[1]:,}원 (FN {best[2]}, FP {best[3]})")
```

> **(c)에는 추가 제약이 있습니다 — 공정성(fairness).**
> 특정 지역·성별·연령에 대해 거절률이 부당하게 높으면 **법적 문제**가 됩니다.
> 정확도가 높아도 배포할 수 없습니다.
> 실제 금융 모델은 **설명 가능성**(왜 거절했는지 고객에게 설명할 수 있어야 함) 때문에
> 성능이 조금 낮아도 로지스틱 회귀를 쓰는 경우가 많습니다. ([Day 078](day-078.md))

**(d)의 추가 고려 — 불균형 0.3%**

```

반드시 PR-AUC 또는 재현율@정밀도 기준으로 평가해야 합니다.
```

**3.** `make_classification` 으로 불균형 데이터(95:5)를 만들고, 아래를 수행하는 **평가 리포트**를 작성하세요.
① 모델 4종 비교 (Dummy 포함) ② 최고 모델의 혼동행렬·classification_report
③ 임계값 0.05~0.95 튜닝 표와 그래프 ④ FN 비용이 FP의 20배일 때 최적 임계값과 총비용
⑤ ROC와 PR 곡선을 나란히 그리고 어느 쪽을 봐야 하는지 판단

<details>
<summary>답 보기</summary>

```python
import matplotlib.pyplot as plt
import numpy as np
import pandas as pd
import seaborn as sns
from sklearn.datasets import make_classification
from sklearn.dummy import DummyClassifier
from sklearn.ensemble import RandomForestClassifier
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import (average_precision_score, classification_report,
                             confusion_matrix, f1_score, fbeta_score,
                             precision_recall_curve, precision_score,
                             recall_score, roc_auc_score, roc_curve)
from sklearn.model_selection import StratifiedKFold, cross_val_score, train_test_split
from sklearn.neighbors import KNeighborsClassifier
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

# ── 데이터 ──
X, y = make_classification(
    n_samples=8000, n_features=25, n_informative=8, n_redundant=4,
    weights=[0.95, 0.05], flip_y=0.02, class_sep=0.85, random_state=7,
)
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.3, random_state=7, stratify=y
)

print("=" * 70)
print("불균형 데이터 평가 리포트 (95 : 5)")
print("=" * 70)
print(f"학습셋 {len(y_train):,}건 (양성 {y_train.sum()}건, {y_train.mean():.2%})")
print(f"테스트셋 {len(y_test):,}건 (양성 {y_test.sum()}건, {y_test.mean():.2%})")

# ── ① 모델 비교 ──
cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=7)
candidates = {
    "Dummy": DummyClassifier(strategy="most_frequent"),
    "KNN(k=9)": make_pipeline(StandardScaler(), KNeighborsClassifier(n_neighbors=9)),
    "로지스틱": make_pipeline(StandardScaler(),
                             LogisticRegression(max_iter=5000, random_state=7)),
    "랜덤포레스트": RandomForestClassifier(n_estimators=300, random_state=7, n_jobs=-1),
}

rows = []
probas = {}
for name, m in candidates.items():
    try:
        cv_ap = cross_val_score(m, X_train, y_train, cv=cv,
                                scoring="average_precision", n_jobs=-1)
        cv_str = f"{cv_ap.mean():.3f}±{cv_ap.std():.3f}"
    except Exception:
        cv_str = "-"

    m.fit(X_train, y_train)
    pred = m.predict(X_test)
    tn, fp, fn, tp = confusion_matrix(y_test, pred).ravel()

    try:
        p = m.predict_proba(X_test)[:, 1]
        probas[name] = p
        roc, pr = roc_auc_score(y_test, p), average_precision_score(y_test, p)
    except Exception:
        roc = pr = float("nan")

    rows.append({
        "모델": name, "CV_PR-AUC": cv_str,
        "정확도": round((tp + tn) / len(y_test), 4),
        "정밀도": round(precision_score(y_test, pred, zero_division=0), 4),
        "재현율": round(recall_score(y_test, pred), 4),
        "F1": round(f1_score(y_test, pred, zero_division=0), 4),
        "ROC_AUC": round(roc, 4), "PR_AUC": round(pr, 4),
    })

comp = pd.DataFrame(rows)
print("\n[① 모델 비교]")
print(comp.to_string(index=False))

best_name = comp.loc[comp["PR_AUC"].idxmax(), "모델"]
print(f"\n→ PR-AUC 기준 최고: {best_name}")
print(f"   ※ 정확도로 고르면 Dummy({comp.loc[0, '정확도']:.4f})가 "
      f"KNN({comp.loc[1, '정확도']:.4f})보다 나아 보입니다.")

# ── ② 최고 모델 상세 ──
best_model = candidates[best_name]
proba = probas[best_name]
pred = (proba >= 0.5).astype(int)

print(f"\n[② {best_name} — 기본 임계값 0.5]")
print(classification_report(y_test, pred, target_names=["정상", "이상"], digits=4))

# ── ③ 임계값 튜닝 ──
COST_FN, COST_FP = 20, 1        # ④ FN이 FP의 20배

th_rows = []
for t in np.arange(0.05, 0.96, 0.05):
    p = (proba >= t).astype(int)
    tn, fp, fn, tp = confusion_matrix(y_test, p).ravel()
    th_rows.append({
        "임계값": round(t, 2), "TP": tp, "FP": fp, "FN": fn,
        "정밀도": round(precision_score(y_test, p, zero_division=0), 4),
        "재현율": round(recall_score(y_test, p), 4),
        "F1": round(f1_score(y_test, p, zero_division=0), 4),
        "F2": round(fbeta_score(y_test, p, beta=2, zero_division=0), 4),
        "총비용": fn * COST_FN + fp * COST_FP,
    })

th = pd.DataFrame(th_rows)
print("[③ 임계값 튜닝]")
print(th.to_string(index=False))

best_f1_t = th.loc[th["F1"].idxmax()]
best_cost_t = th.loc[th["총비용"].idxmin()]

print(f"\n[④ 비용 분석 — FN:FP = {COST_FN}:{COST_FP}]")
print(f"  F1 최고 임계값   : {best_f1_t['임계값']:.2f}  "
      f"→ 총비용 {int(best_f1_t['총비용']):>5,}")
print(f"  비용 최소 임계값 : {best_cost_t['임계값']:.2f}  "
      f"→ 총비용 {int(best_cost_t['총비용']):>5,}   ★ 이쪽을 선택")
print(f"  절감액           : {int(best_f1_t['총비용'] - best_cost_t['총비용']):,} "
      f"({(1 - best_cost_t['총비용'] / best_f1_t['총비용']):.1%} 감소)")
print(f"\n  선택한 지점: 재현율 {best_cost_t['재현율']:.4f}, "
      f"정밀도 {best_cost_t['정밀도']:.4f}")
print(f"    양성 {y_test.sum()}건 중 {int(best_cost_t['TP'])}건 발견, "
      f"{int(best_cost_t['FN'])}건 놓침, 오탐 {int(best_cost_t['FP'])}건")

# ── ⑤ 시각화 ──
fig, axes = plt.subplots(2, 2, figsize=(14, 10))

# ROC
ax = axes[0, 0]
for name, p in probas.items():
    fpr, tpr, _ = roc_curve(y_test, p)
    ax.plot(fpr, tpr, linewidth=2, label=f"{name} ({roc_auc_score(y_test, p):.3f})")
ax.plot([0, 1], [0, 1], "k--", alpha=0.5)
ax.set_xlabel("FPR")
ax.set_ylabel("TPR")
ax.set_title("ROC — all models look good (0.9+)")
ax.legend(fontsize=8)
ax.grid(alpha=0.3)

# PR
ax = axes[0, 1]
for name, p in probas.items():
    prec, rec, _ = precision_recall_curve(y_test, p)
    ax.plot(rec, prec, linewidth=2,
            label=f"{name} ({average_precision_score(y_test, p):.3f})")
ax.axhline(y_test.mean(), color="k", linestyle="--", alpha=0.5,
           label=f"random ({y_test.mean():.3f})")
ax.set_xlabel("Recall")
ax.set_ylabel("Precision")
ax.set_title("PR — differences are clear")
ax.legend(fontsize=8)
ax.grid(alpha=0.3)

# 임계값
ax = axes[1, 0]
ax.plot(th["임계값"], th["정밀도"], "o-", label="Precision")
ax.plot(th["임계값"], th["재현율"], "s-", label="Recall")
ax.plot(th["임계값"], th["F1"], "^--", label="F1")
ax.axvline(best_cost_t["임계값"], color="green", linestyle="--",
           label=f"min-cost t={best_cost_t['임계값']:.2f}")
ax.set_xlabel("threshold")
ax.set_title("Threshold tuning")
ax.legend(fontsize=8)
ax.grid(alpha=0.3)

# 비용
ax = axes[1, 1]
ax.plot(th["임계값"], th["총비용"], "o-", color="crimson", linewidth=2)
ax.axvline(best_cost_t["임계값"], color="green", linestyle="--")
ax.scatter([best_cost_t["임계값"]], [best_cost_t["총비용"]], s=140,
           color="green", zorder=5, label="minimum")
ax.set_xlabel("threshold")
ax.set_ylabel(f"total cost (FN×{COST_FN} + FP×{COST_FP})")
ax.set_title("Cost curve — this is what actually matters")
ax.legend()
ax.grid(alpha=0.3)

fig.tight_layout()
plt.show()
```

**결론 4가지**

- **정확도는 완전히 무용지물입니다.** Dummy 0.9483 vs 최고 모델 0.9750. 2.7%p 차이인데 실제 성능은 천지 차이입니다.
- **PR-AUC로 모델을 고르고, 임계값으로 운영 지점을 정합니다.** 두 단계는 분리된 결정입니다.
- **F1 최고 임계값(0.40)과 비용 최소 임계값(0.10)이 다릅니다.** F1은 정밀도와 재현율을 1:1로 보는데, 실제 비용은 20:1이기 때문입니다. **비용을 아는 순간 F1은 쓸 이유가 없습니다.**
- **선택한 지점의 정밀도가 0.356입니다.** 오탐 208건이 발생합니다. 그런데 이것이 최적입니다. 놓침 1건이 오탐 20건의 가치를 갖기 때문입니다. **"정밀도가 낮은 모델을 일부러 고르는 것"이 합리적일 수 있습니다.**

## 오늘의 정리 · W16 총정리

| 개념 | 핵심 |
|---|---|
| 정확도의 함정 | 불균형에서는 **아무것도 안 해도 99%** |
| `DummyClassifier` | **항상 베이스라인으로** 비교하세요 |
| 혼동행렬 | `tn, fp, fn, tp = cm.ravel()` — 순서 외우기 |
| **FN** | 놓침. 암 진단·불량 검사에서 **치명적** |
| **FP** | 헛경보. 스팸 필터·추천에서 **치명적** |
| 정밀도 | `TP/(TP+FP)` — "네 말을 믿어도 되니?" |
| 재현율 | `TP/(TP+FN)` — "다 찾았니?" |
| F1 / F2 / F0.5 | 조화 평균. **β가 크면 재현율 중시** |
| 임계값 | 0.5는 기본값일 뿐. **불균형에서는 조정 필수** |
| ROC-AUC | 임계값 무관. **불균형에서 낙관적** |
| **PR-AUC** | 불균형 데이터의 **표준 지표** |
| `macro avg` | 클래스 동등 취급. **불균형 보고서에는 이것** |
| `class_weight` | 소수 클래스 오류에 큰 벌점. **임계값 조정과 유사** |
| **최종 기준** | 계산 가능하면 **총비용**. F1보다 설득력 있음 |
