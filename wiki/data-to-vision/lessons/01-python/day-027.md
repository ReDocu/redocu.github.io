## ② 왜 필요한가

어제 모듈로 나눴지만, 프로젝트가 커지면 **파일이 다시 쌓입니다.**

```
슈팅게임/
├── main.py
├── settings.py
├── player.py
├── bullet.py
├── enemy.py
├── boss.py
├── item.py
├── particle.py
├── screenshake.py
├── sound.py
├── title_scene.py
├── play_scene.py
├── gameover_scene.py
├── db.py
├── ranking.py
└── utils.py            ← 16개 파일이 한 폴더에
```

**폴더가 평평하면 무엇이 무엇인지 안 보입니다.**
`player.py` 와 `title_scene.py` 는 성격이 완전히 다른데 나란히 있습니다.

**패키지는 관련된 모듈을 폴더로 묶는 것**입니다.

```
슈팅게임/
├── main.py
└── game/
    ├── __init__.py
    ├── settings.py
    ├── entities/          ← 게임 객체
    │   ├── __init__.py
    │   ├── player.py
    │   ├── bullet.py
    │   └── enemy.py
    ├── effects/           ← 연출
    │   ├── __init__.py
    │   ├── particle.py
    │   └── shake.py
    └── scenes/            ← 화면
        ├── __init__.py
        ├── title.py
        └── play.py
```

**어디에 무엇이 있는지 폴더 이름만 봐도 압니다.**

그리고 대단원 02부터 쓰는 라이브러리가 전부 패키지입니다.

```python
from sklearn.model_selection import train_test_split
     └패키지┘ └─── 하위 모듈 ───┘  └──── 함수 ────┘
```

## ③ 개념 설명

### 패키지란

**패키지(package)** = 모듈을 담은 폴더.

```
mypackage/
├── __init__.py     ← 이 파일이 있으면 패키지
├── module1.py
└── module2.py
```

```python
import mypackage.module1
from mypackage import module2
from mypackage.module1 import some_function
```

### `__init__.py` 의 역할

| 역할 | 설명 |
|---|---|
| **패키지 표시** | 이 폴더가 패키지임을 알림 (파이썬 3.3+ 에서는 없어도 되지만 명시 권장) |
| **초기화 코드** | 패키지를 import 할 때 실행할 코드 |
| **공개 API 정의** | 하위 모듈의 이름을 패키지 수준으로 끌어올림 |

**비어 있어도 됩니다.**

```python
# mypackage/__init__.py
# (빈 파일)
```

**하지만 이렇게 쓰면 편해집니다.**

```python
# game/entities/__init__.py
from .player import Player
from .bullet import Bullet
from .enemy import Enemy, FastEnemy, TankEnemy

__all__ = ["Player", "Bullet", "Enemy", "FastEnemy", "TankEnemy"]
```

이제 쓰는 쪽이 짧아집니다.

```python
# 이렇게 안 써도 되고
from game.entities.player import Player
from game.entities.bullet import Bullet

# 이렇게 쓸 수 있습니다
from game.entities import Player, Bullet
```

> **`__all__`** 은 `from 패키지 import *` 로 가져올 이름 목록입니다.
> `import *` 를 쓰지 않더라도, **"이것이 이 패키지의 공개 API"** 라는 문서 역할을 합니다.

### 절대 import vs 상대 import

**절대 import** — 최상위부터의 전체 경로

```python
from game.entities.player import Player
from game.settings import SCREEN_WIDTH
import game.effects.particle
```

**상대 import** — 현재 위치 기준

```python
from .player import Player            # 같은 폴더
from ..settings import SCREEN_WIDTH   # 한 단계 위 폴더
from ..effects.particle import Particle
```

| 기호 | 의미 |
|---|---|
| `.` | 현재 패키지 (같은 폴더) |
| `..` | 부모 패키지 (한 단계 위) |
| `...` | 조부모 패키지 |

**어느 쪽을 쓸 것인가**

| | 절대 import | 상대 import |
|---|---|---|
| 가독성 | 출처가 명확 | 짧음 |
| 이동 | 패키지 이름 바뀌면 전부 수정 | 폴더 안에서 이동해도 안전 |
| 실행 | 어디서든 동작 | **패키지 안에서만** 동작 |

> **권장** — **패키지 내부끼리는 상대 import, 밖에서는 절대 import.**
> 파이썬 공식 스타일 가이드(PEP 8)는 절대 import 를 권장하지만, 패키지 내부에서는 상대 import 도 명시적이라면 괜찮다고 봅니다.

> ⚠️ **상대 import 는 그 파일을 직접 실행하면 에러가 납니다.**
> ```
> ImportError: attempted relative import with no known parent package
> ```
> `python game/entities/player.py` 는 안 되고, `python -m game.entities.player` 로 실행해야 합니다.
> 그래서 **상대 import 를 쓴 파일에는 `if __name__ == "__main__":` 테스트를 넣기 어렵습니다.**

### 하위 패키지

패키지 안에 패키지를 넣을 수 있습니다.

```
game/
├── __init__.py
├── settings.py
└── entities/
    ├── __init__.py
    ├── player.py
    └── enemies/
        ├── __init__.py
        ├── basic.py
        └── boss.py
```

```python
from game.entities.enemies.boss import Boss
```

> **깊이는 3단계까지가 적당합니다.** 그 이상이면 import 문이 너무 길어집니다.

### 패키지 구조 설계 원칙

| 원칙 | 설명 |
|---|---|
| **역할별로 나눈다** | 데이터 / 로직 / 화면 / 유틸 |
| **의존 방향을 한쪽으로** | `scenes → entities → settings` (역방향 ❌) |
| **`settings` 는 아무것도 import 안 함** | 최하위. 순환 참조를 원천 차단 |
| **공통 유틸은 별도로** | 어느 계층에서든 쓸 수 있게 |

```
     main.py
        ↓
     scenes/        화면 전환, 입력 처리
        ↓
     entities/      게임 객체
        ↓
     effects/       연출
        ↓
     settings.py    상수 (아무것도 import 안 함)
```

**화살표 방향으로만 import 합니다.** 역방향이 생기면 순환 참조입니다.

### 실행 방법 두 가지

**① 진입점 스크립트 (권장)**

```
프로젝트/
├── main.py        ← 여기서 실행
└── game/
    └── ...
```

```powershell
python main.py
```

**② 패키지를 모듈로 실행**

```
프로젝트/
└── game/
    ├── __init__.py
    ├── __main__.py    ← 특별한 이름
    └── ...
```

```powershell
python -m game
```

> `__main__.py` 는 `python -m 패키지명` 으로 실행할 때 자동으로 실행되는 파일입니다.
> `python -m http.server` 같은 명령이 이 방식입니다.

"""기본 사칙연산."""


def add(a, b):
    return a + b


def subtract(a, b):
    return a - b


def multiply(a, b):
    return a * b


def divide(a, b):
    if b == 0:
        return None
    return a / b


def average(numbers):
    """리스트의 평균. 비어 있으면 0."""
    if not numbers:
        return 0.0
    return sum(numbers) / len(numbers)

**`mathkit/geometry.py`**

```python
"""도형 계산."""

import math

PI = math.pi


def circle_area(r):
    """원의 넓이."""
    return PI * r ** 2


def circle_perimeter(r):
    """원의 둘레."""
    return 2 * PI * r


def rectangle_area(w, h):
    """직사각형의 넓이."""
    return w * h


def triangle_area(a, b, c):
    """세 변으로 삼각형 넓이 (헤론의 공식). 불가능하면 None."""
    if a + b <= c or b + c <= a or a + c <= b:
        return None
    s = (a + b + c) / 2
    return math.sqrt(s * (s - a) * (s - b) * (s - c))


def distance(x1, y1, x2, y2):
    """두 점 사이의 거리."""
    return math.sqrt((x2 - x1) ** 2 + (y2 - y1) ** 2)
```

### Step 2. 상대 import 사용하기

**`mathkit/stats.py` 추가**

```python
"""통계 계산. basic 모듈의 기능을 재사용합니다."""

from .basic import average          # 상대 import — 같은 패키지 안


def variance(numbers):
    """분산."""
    if len(numbers) < 2:
        return 0.0
    avg = average(numbers)
    return sum((x - avg) ** 2 for x in numbers) / len(numbers)


def std_dev(numbers):
    """표준편차."""
    return variance(numbers) ** 0.5


def median(numbers):
    """중앙값."""
    if not numbers:
        return 0.0

    s = sorted(numbers)
    n = len(s)
    mid = n // 2

    if n % 2 == 1:
        return float(s[mid])
    return (s[mid - 1] + s[mid]) / 2


def mode(numbers):
    """최빈값. 여러 개면 가장 작은 것."""
    if not numbers:
        return None

    counter = {}
    for n in numbers:
        counter[n] = counter.get(n, 0) + 1

    max_count = max(counter.values())
    return min(k for k, v in counter.items() if v == max_count)


def summary(numbers):
    """요약 통계를 딕셔너리로 반환합니다."""
    if not numbers:
        return {}

    return {
        "개수": len(numbers),
        "합계": sum(numbers),
        "평균": average(numbers),
        "중앙값": median(numbers),
        "최빈값": mode(numbers),
        "표준편차": std_dev(numbers),
        "최솟값": min(numbers),
        "최댓값": max(numbers),
    }
```

**`game/utils.py`** — settings 만 참조

```python
"""공통 유틸리티."""

import pygame

from .settings import FONT_NAME, FONT_SIZE_NORMAL


def clamp(value, low, high):
    """값을 범위로 제한합니다."""
    return max(low, min(value, high))


def normalize(dx, dy):
    """방향 벡터를 정규화합니다. (0,0) 이면 그대로 반환."""
    length = (dx ** 2 + dy ** 2) ** 0.5
    if length == 0:
        return 0.0, 0.0
    return dx / length, dy / length


def make_font(size=FONT_SIZE_NORMAL):
    """한글 폰트를 만듭니다."""
    return pygame.font.SysFont(FONT_NAME, size)


def draw_text(surface, text, font, color, pos, center=False):
    """텍스트를 그립니다."""
    t = font.render(text, True, color)
    rect = t.get_rect(center=pos) if center else t.get_rect(topleft=pos)
    surface.blit(t, rect)
    return rect


def draw_bar(surface, x, y, w, h, ratio, color, bg_color, border_color=None):
    """진행 바를 그립니다."""
    ratio = clamp(ratio, 0.0, 1.0)
    pygame.draw.rect(surface, bg_color, (x, y, w, h))
    pygame.draw.rect(surface, color, (x, y, int(w * ratio), h))
    if border_color:
        pygame.draw.rect(surface, border_color, (x, y, w, h), 2)
```

from ..settings import SCREEN_WIDTH, SCREEN_HEIGHT      # 두 단계 위


class Entity(pygame.sprite.Sprite):

    def __init__(self, x, y, image):
        super().__init__()
        self.image = image
        self.rect = self.image.get_rect(center=(x, y))
        self.pos_x = float(x)
        self.pos_y = float(y)

    def sync_rect(self):
        """float 위치를 rect 에 반영합니다."""
        self.rect.center = (int(self.pos_x), int(self.pos_y))

    def sync_pos(self):
        """rect 위치를 float 에 되돌립니다. (경계 보정 후 호출)"""
        self.pos_x = float(self.rect.centerx)
        self.pos_y = float(self.rect.centery)

    def clamp_to_screen(self):
        """화면 안으로 제한합니다."""
        self.rect.clamp_ip(pygame.Rect(0, 0, SCREEN_WIDTH, SCREEN_HEIGHT))
        self.sync_pos()

    def is_out_of_screen(self, margin=0):
        """화면 밖이면 True."""
        return (self.rect.bottom < -margin
                or self.rect.top > SCREEN_HEIGHT + margin
                or self.rect.right < -margin
                or self.rect.left > SCREEN_WIDTH + margin)

    def kill_if_out(self, margin=0):
        """화면 밖이면 제거합니다."""
        if self.is_out_of_screen(margin):
            self.kill()
            return True
        return False
```

"""총알."""

import pygame

from .base import Entity
from ..settings import BULLET_SPEED, BULLET_DAMAGE, COLOR_BULLET


def make_bullet_surface(w=6, h=18, color=COLOR_BULLET):
    surf = pygame.Surface((w, h), pygame.SRCALPHA)
    pygame.draw.rect(surf, color, (0, 0, w, h), border_radius=3)
    return surf


class Bullet(Entity):
    """위로 날아가는 총알."""

    SPEED = BULLET_SPEED
    DAMAGE = BULLET_DAMAGE

    def __init__(self, x, y, vel_x=0.0):
        super().__init__(x, y, make_bullet_surface())
        self.vel_x = float(vel_x)
        self.vel_y = float(self.SPEED)
        self.damage = self.DAMAGE

    def update(self):
        self.pos_x += self.vel_x
        self.pos_y += self.vel_y
        self.sync_rect()
        self.kill_if_out()

"""슈팅게임 진입점."""

import pygame

from game.settings import (SCREEN_WIDTH, SCREEN_HEIGHT, FPS, TITLE,
                           COLOR_BG, COLOR_TEXT)
from game.entities import Bullet
from game.utils import make_font, draw_text


def main():
    pygame.init()
    screen = pygame.display.set_mode((SCREEN_WIDTH, SCREEN_HEIGHT))
    pygame.display.set_caption(TITLE)
    clock = pygame.time.Clock()
    font = make_font()

    bullets = pygame.sprite.Group()

    running = True
    while running:
        for event in pygame.event.get():
            if event.type == pygame.QUIT:
                running = False
            elif event.type == pygame.KEYDOWN and event.key == pygame.K_ESCAPE:
                running = False
            elif event.type == pygame.MOUSEBUTTONDOWN:
                bullets.add(Bullet(*event.pos))

        bullets.update()

        screen.fill(COLOR_BG)
        bullets.draw(screen)

        draw_text(screen, "클릭하면 총알이 발사됩니다", font, COLOR_TEXT, (12, 12))
        draw_text(screen, f"총알 {len(bullets)}개", font, COLOR_TEXT, (12, 40))
        draw_text(screen, f"FPS {clock.get_fps():.0f}", font, COLOR_TEXT, (12, 68))

        pygame.display.flip()
        clock.tick(FPS)

    pygame.quit()


if __name__ == "__main__":
    main()
```

"""온도 단위 변환."""

ABSOLUTE_ZERO_C = -273.15


def celsius_to_fahrenheit(c):
    return c * 9 / 5 + 32


def fahrenheit_to_celsius(f):
    return (f - 32) * 5 / 9


def celsius_to_kelvin(c):
    if c < ABSOLUTE_ZERO_C:
        raise ValueError(f"절대영도({ABSOLUTE_ZERO_C}℃) 아래는 불가능합니다")
    return c - ABSOLUTE_ZERO_C


def kelvin_to_celsius(k):
    if k < 0:
        raise ValueError("켈빈은 0 미만일 수 없습니다")
    return k + ABSOLUTE_ZERO_C

<details>
<summary>답 보기</summary>

**원인**

```
player.py  →  gameover.py  →  player.py  →  ...
```

`entities` 계층이 `scenes` 계층을 import 하고 있습니다. **의존 방향이 역행**했습니다.

```
정상:  scenes → entities → settings
현재:  scenes ⇄ entities            ← 순환
```

**개념적으로도 잘못되었습니다.**
`Player` 는 **자기 상태만 관리**해야 합니다. "게임 오버 화면을 띄우는 일"은 화면 담당(`scenes`)의 몫입니다.

**해결 — 플레이어는 상태만 알리고, 판단은 상위가 합니다.**

```python
# game/entities/player.py — 아무것도 import 하지 않음
class Player:
    def __init__(self, name):
        self.name = name
        self.hp = 100
        self.lives = 3
        self.score = 0

    @property
    def is_alive(self):
        return self.hp > 0 and self.lives > 0

    def take_damage(self, amount):
        """피해를 입습니다. 목숨을 잃으면 True."""
        self.hp -= amount
        if self.hp <= 0:
            self.lives -= 1
            self.hp = 100 if self.lives > 0 else 0
            return True
        return False
```

```python
# game/scenes/play.py — 상위가 판단하고 전환
from ..entities.player import Player
from .gameover import GameOverScene


class PlayScene:
    def __init__(self):
        self.player = Player("홍길동")

    def update(self):
        # ... 충돌 처리 ...

**핵심 원칙 세 가지**

| 원칙 | 설명 |
|---|---|
| **하위는 상위를 모른다** | `Player` 는 화면이 있는지도 모릅니다 |
| **상태만 노출한다** | `is_alive` 같은 속성으로 알리고, 판단은 상위가 |
| **필요한 값만 전달한다** | `GameOverScene(score)` — `Player` 객체 전체를 넘기지 않음 |

> **교훈** — **순환 참조는 대부분 "책임을 잘못 나눴다"는 신호**입니다.
> "이 클래스가 이 일까지 해야 하나?" 를 물어보면 답이 나옵니다.
>
> `Player.die()` 가 화면을 띄우면, 나중에 이 `Player` 를 서버나 테스트 코드에서 쓸 수 없게 됩니다.
> **한 클래스는 한 가지 책임만** — 이것이 [Day 008](day-008.md)의 "하나의 함수는 하나의 일" 을 클래스 수준으로 확장한 것입니다.
</details>

## 오늘의 정리

| 개념 | 핵심 |
|---|---|
| 패키지 | 모듈을 담은 폴더 + `__init__.py` |
| `__init__.py` | 패키지 표시 · 초기화 · **공개 API 정의** |
| `__all__` | `import *` 대상 목록 (문서 역할) |
| 절대 import | `from game.entities import Player` — 밖에서 |
| 상대 import | `.` 같은 폴더 · `..` 한 단계 위 — 패키지 안에서 |
| 상대 import 주의 | 직접 실행 불가 (`python -m` 필요) |
| 의존 방향 | `scenes → entities → settings` **한쪽으로만** |
| `settings.py` | 아무것도 import 하지 않는 최하위 |
| 깊이 | 3단계까지가 적당 |

**오늘 반드시 기억할 세 가지**
> ① 패키지 안에서는 `from .모듈 import 이름` (점을 붙입니다).
> ② **의존 방향은 한쪽으로만** — 하위가 상위를 import 하면 순환 참조입니다.
> ③ `settings.py` 는 아무것도 import 하지 않게 두면 순환 참조가 원천 차단됩니다.

**과제** — 오늘 만든 `game` 패키지에 `game/entities/player.py`, `game/entities/enemy.py` 를 추가하세요.
`Entity` 를 상속받고, `settings.py` 의 상수만 참조해야 합니다. 패키지 구조 다이어그램도 그려서 제출합니다.
