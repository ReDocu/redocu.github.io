## ② 왜 필요한가

### 어제의 모델은 왜 그 구조였습니까

[Day 106](day-106.md) Step 4에서 이 모델을 썼습니다.

```python
Dense(64, activation="relu")
Dense(32, activation="relu")
Dense(1)
```

**왜 64입니까? 왜 32입니까? 왜 2층입니까?**

정직하게 답하면 — **"그냥 그렇게 썼습니다."** 관행입니다.
오늘은 이 질문에 **근거를 가지고** 답할 수 있게 만드는 날입니다.

> ⚠️ 미리 밝히면, 이 질문에 **수학적 정답은 없습니다.**
> 하지만 "아무거나 써도 된다"와 "근거 있게 고른다" 사이에는 큰 차이가 있습니다.
> 오늘 배우는 것은 **실험으로 좁혀 가는 절차**입니다.

### 픽셀과 열은 전혀 다른 것입니다

대단원 03에서 CNN을 배울 때 이런 말을 했습니다.

> "이미지를 Flatten하면 픽셀의 위치 관계가 사라진다" ([Day 086](../03-ml/day-086.md))

정형 데이터에는 **애초에 그런 관계가 없습니다.**

```
[이미지]
픽셀 (10, 20) 과 (10, 21) 은 붙어 있음  →  같이 봐야 의미가 있음
                                          →  CNN이 필요한 이유

[표]
"평균 방 개수" 열과 "위도" 열은 붙어 있음?  →  아무 관계 없음
                                            →  열 순서를 바꿔도 결과가 같아야 함
```

**표에서 열 순서를 바꿔도 모델 성능은 변하지 않습니다.** 실제로 실습에서 확인합니다.
그래서 **정형 데이터에는 CNN을 쓰지 않습니다.** Dense만 씁니다.

### 대신 다른 어려움이 생깁니다

| | 이미지 | 표 |
|---|---|---|
| 특성 하나의 의미 | 픽셀 하나 = 의미 없음 | **열 하나 = 명확한 의미** |
| 특성 간 스케일 | 전부 0~255로 동일 | **위도(-124)와 인구(35,682)가 섞임** |
| 특성 수 | 수만~수백만 (픽셀) | 보통 5~200개 |
| 데이터 양 | 수천~수백만 장 | **수백~수만 행** (적음) |
| 결측치 | 없음 | **흔함** |
| 범주형 | 없음 | **흔함** (장르, 지역) |

**세 번째와 네 번째가 결정적입니다.**

```
이미지: 특성 150,528개(224×224×3), 데이터 100만 장   →  데이터가 특성보다 훨씬 많음
표:     특성 8개,                   데이터 2만 행     →  이것도 괜찮음
표:     특성 300개(원-핫 후),        데이터 800행      →  ★ 위험. 금방 과적합
```

**정형 데이터는 데이터가 적습니다.** 그래서 신경망이 힘을 못 쓰는 경우가 많습니다.
[Day 108](day-108.md)에서 트리 앙상블에게 지는 것을 직접 확인합니다.

### 그래서 오늘 무엇을 하는가

```
① 입력 shape을 정확히 지정한다               ← 안 되면 아무것도 못 함
② 층 수·노드 수를 정하는 경험칙을 익힌다
③ 파라미터 수를 손으로 계산한다               ← 과적합 위험을 미리 안다
④ 구조 3가지를 만들어 비교 실험을 한다
⑤ BatchNorm·Dropout을 올바른 위치에 넣는다
```

**③이 오늘의 숨은 핵심입니다.**
`Dense(512)` 를 두 층 쌓으면 파라미터가 몇 개인지 **계산할 수 있어야** 800행짜리 데이터에 그걸 쓰면 안 된다는 걸 압니다.

## ③ 개념 설명

### 입력 shape — 표 데이터는 `(특성 수,)`

```python
X_train.shape          # (13209, 8)   행 13,209개, 열 8개
                       #    ↑     ↑
                       #  샘플 수  특성 수

layers.Input(shape=(8,))        # ★ 샘플 수는 빼고 특성 수만
```

| 데이터 | X.shape | input_shape |
|---|---|---|
| 표 (특성 8개) | `(13209, 8)` | `(8,)` |
| 흑백 이미지 28×28 | `(60000, 28, 28)` | `(28, 28)` |
| 컬러 이미지 32×32 | `(50000, 32, 32, 3)` | `(32, 32, 3)` |

**규칙은 하나입니다 — 맨 앞(샘플 수)만 빼면 됩니다.**

```python
input_shape = X_train.shape[1:]        # ★ 이렇게 쓰면 절대 안 틀립니다
layers.Input(shape=input_shape)
```

> **`(8,)` 의 쉼표를 빠뜨리지 마세요.** `(8)` 은 그냥 정수 8입니다. 튜플이 아닙니다.
> Keras가 알아서 처리해 주는 경우도 있지만, 안 되는 경우도 있습니다. **항상 쉼표를 쓰세요.**

### 파라미터 수 계산 — 손으로 할 수 있어야 합니다

```
Dense 층의 파라미터 수 = (입력 노드 수 × 출력 노드 수) + 출력 노드 수
                       └─── 가중치 W ───┘   └─ 편향 b ─┘
```

**어제 모델로 계산해 봅시다.**

```
입력 8개 → Dense(64) → Dense(32) → Dense(1)

Dense(64)  : 8 × 64 + 64  =  512 + 64  =    576
Dense(32)  : 64 × 32 + 32 = 2048 + 32  =  2,080
Dense(1)   : 32 × 1 + 1   =   32 + 1   =     33
                                       ─────────
                                합계      2,689
```

`model.summary()` 출력과 정확히 일치합니다.

```
 dense (Dense)               (None, 64)                576
 dense_1 (Dense)             (None, 32)                2080
 dense_2 (Dense)             (None, 1)                 33
=================================================================
Total params: 2,689
```

> **왜 이걸 손으로 계산해야 하나** — **과적합 위험을 미리 알기 위해서**입니다.
> 데이터가 800행인데 파라미터가 50,000개면 **모델이 데이터를 통째로 외울 수 있습니다.**
> [Day 079](../03-ml/day-079.md)에서 본 "샘플 수 대비 특성 수" 문제의 신경망 버전입니다.

### 파라미터 수와 데이터 양의 관계

| 비율 (파라미터 / 샘플 수) | 상태 |
|---|---|
| < 1 | 안전 |
| 1 ~ 10 | 보통. 규제 필요 |
| 10 ~ 100 | 위험. 강한 규제 필수 |
| > 100 | **거의 확실히 과적합** |

```
California Housing:  2,689 파라미터 / 13,209 샘플 = 0.20     ← 안전
스팀 데이터(가정):    50,000 파라미터 / 800 샘플  = 62.5     ← 위험
```

> ⚠️ **이것은 엄밀한 법칙이 아니라 감각 잡는 도구입니다.**
> 실제 과적합 여부는 학습 곡선으로 판단합니다. ([Day 117](day-117.md))
> 하지만 **모델을 만들기 전에 이 비율을 계산해 보면** 무모한 설계를 피할 수 있습니다.

### 층 수 — 정형 데이터에서는 깊이가 답이 아닙니다

| 층 수 | 언제 | 비고 |
|---|---|---|
| **0층 (Dense(1)만)** | 관계가 선형일 때 | 선형 회귀와 동일 |
| **1~2층** | **대부분의 정형 데이터** | ★ 여기서 시작하세요 |
| 3~4층 | 특성이 많고(50+) 데이터도 많을 때(수만+) | |
| 5층 이상 | 정형 데이터에서는 거의 이득 없음 | 이미지/텍스트의 영역 |

**"딥러닝인데 깊게 안 쌓나요?"**

```
이미지: 층이 깊어질수록 저수준(선) → 고수준(눈, 얼굴) 특징이 쌓임
        → 깊이가 표현력이 됨

표:     처음부터 "평균 소득", "위도" 같은 고수준 특성이 주어짐
        → 더 추상화할 것이 별로 없음
```

> **정형 데이터에서 층을 늘리면 대개 성능이 떨어집니다.** 학습만 어려워집니다.
> 실습 Step 4에서 직접 확인합니다.

### 노드 수 — 경험칙 4가지

| 경험칙 | 내용 | 평가 |
|---|---|---|
| **깔때기형** | 입력 → 큰 층 → 작은 층 → 출력 (64 → 32 → 1) | **가장 무난.** 기본으로 채택 |
| **동일 폭** | 모든 은닉층 노드 수 동일 (64 → 64 → 1) | 실험이 단순해짐. 나쁘지 않음 |
| **2의 거듭제곱** | 16, 32, 64, 128, 256 | GPU 효율. 관행. 성능과는 무관 |
| **입력의 1~3배** | 특성 8개면 첫 층 8~24개 | 특성이 적을 때 유용 |

**시작점 추천**

```
특성 수      첫 은닉층      구조 예시
─────────────────────────────────────────
  ~10       32~64        (8) → 64 → 32 → 1
 10~50      64~128       (30) → 128 → 64 → 1
50~200     128~256       (100) → 256 → 128 → 64 → 1
```

> ⚠️ **이 표는 출발점일 뿐입니다.** 근거는 "많은 사람이 이렇게 해서 대체로 됐다"입니다.
> **진짜 답은 실험입니다.** 오늘 Step 4에서 그 실험을 합니다.
>
> **경험칙의 한계** — 데이터가 800행이면 위 표를 그대로 쓰면 안 됩니다.
> 표에는 **데이터 양이 안 들어 있습니다.** 파라미터/샘플 비율을 함께 봐야 합니다.

### 튜닝 우선순위 — 노드 수는 1순위가 아닙니다

```
1순위: 학습률 (learning rate)        ← 영향이 압도적
2순위: 전처리 (스케일링, 로그 변환)    ← 정형 데이터에서 특히
3순위: 층 수 · 노드 수
4순위: 배치 크기
5순위: 옵티마이저, 초기화
```

> **초보자가 가장 많이 하는 실수** — 노드 수만 1000번 바꿔 봅니다.
> **학습률을 0.001에서 0.01로 바꾸는 것이 노드를 64→256으로 늘리는 것보다 대개 영향이 큽니다.**
> [Day 123](day-123.md)에서 이 우선순위를 실험으로 확인합니다.

### 배치 정규화 (BatchNormalization)

**각 층의 출력을 평균 0, 표준편차 1로 정규화하는 층입니다.**

```python
layers.Dense(64),
layers.BatchNormalization(),        # ★ 활성화 앞
layers.Activation("relu"),
```

| 효과 | 설명 |
|---|---|
| 학습 안정화 | 층을 지날수록 값이 커지거나 작아지는 것을 막음 |
| **학습률을 높게 쓸 수 있음** | 가장 큰 실용적 이득 |
| 약한 규제 효과 | 배치마다 통계가 조금씩 달라 노이즈처럼 작동 |

**위치 논쟁** — Dense → BN → Activation 인가, Dense → Activation → BN 인가?

```python
# 원 논문 방식 (권장)
Dense(64), BatchNormalization(), Activation("relu")

# 많이 쓰이는 방식 (실전에서 성능 차이 거의 없음)
Dense(64, activation="relu"), BatchNormalization()
```

> **논문 방식을 권장하지만, 차이는 대개 미미합니다.** 팀 안에서 하나로 통일하는 것이 더 중요합니다.
> 이 과정에서는 **`Dense → BN → Activation`** 으로 통일합니다.

> ⚠️ **BN을 쓰면 `use_bias=False` 로 두는 것이 정석입니다.**
> BN이 어차피 평균을 빼므로 편향이 무의미해집니다. 파라미터만 낭비합니다.
> ```python
> layers.Dense(64, use_bias=False),
> layers.BatchNormalization(),
> layers.Activation("relu"),
> ```

### 드롭아웃 (Dropout)

**학습 중 노드 일부를 무작위로 끄는 규제 기법입니다.** ([Day 096](../03-ml/day-096.md))

```python
layers.Dense(64, activation="relu"),
layers.Dropout(0.3),                 # 30%를 끔
```

| 비율 | 언제 |
|---|---|
| 0.1 ~ 0.2 | 약한 규제. 정형 데이터 기본 |
| 0.3 ~ 0.5 | 과적합이 뚜렷할 때 |
| 0.5 이상 | 이미지 CNN에서. **정형 데이터에는 대개 과함** |

**넣으면 안 되는 위치**

```python
Dense(1),
Dropout(0.3),        # ✗ 출력층 뒤 — 예측값을 30% 확률로 0으로 만듦
```

```python
Input(shape=(8,)),
Dropout(0.5),        # △ 입력에 드롭아웃 — 특성을 절반 버림. 특수한 경우만
```

### BN과 Dropout을 함께 쓸 때

**순서: Dense → BN → Activation → Dropout**

```python
layers.Dense(64, use_bias=False),
layers.BatchNormalization(),
layers.Activation("relu"),
layers.Dropout(0.2),
```

> ⚠️ **BN과 Dropout을 함께 쓰면 오히려 나빠지는 경우가 보고되어 있습니다.**
> Dropout이 배치 통계를 흔들어 BN의 추정을 망가뜨리기 때문입니다.
>
> **정형 데이터 권장 순서**
> ```
> ① 규제 없이 먼저 학습 → 과적합이 있는지 확인
> ② 과적합이 있으면 Dropout(0.2)부터
> ③ 학습이 불안정하면 BN 추가
> ④ 둘 다 넣었는데 나빠지면 하나를 빼기
> ```
> **"일단 다 넣고 보자"가 가장 나쁩니다.**

### 구조를 비교하는 실험 설계

**한 번에 하나만 바꿔야 원인을 알 수 있습니다.**

| 실험 | 층 수 | 노드 | 규제 | 무엇을 알 수 있나 |
|---|---|---|---|---|
| A | 0 | — | — | 선형 관계로 충분한가 |
| B | 1 | 64 | — | 비선형이 도움 되는가 |
| C | 2 | 64-32 | — | 층을 늘리면 나아지는가 |
| D | 3 | 128-64-32 | — | 더 늘리면? |
| E | 2 | 64-32 | Dropout 0.2 | 규제가 도움 되는가 |
| F | 2 | 64-32 | BN | 학습이 안정되는가 |

**공정한 비교의 조건**

```
✓ 같은 데이터, 같은 분할, 같은 seed
✓ 같은 학습률, 같은 에폭 수, 같은 배치 크기
✓ 같은 지표로 평가
✗ "A는 100에폭, B는 50에폭" — 비교 불가
```

> **[Day 090](../03-ml/day-090.md)의 구조 비교 실험과 같은 원칙입니다.**
> 오늘은 이것을 정형 데이터에 적용합니다.

## ④ 단계별 실습

### Step 1. 데이터 준비와 shape 확인

```python
import numpy as np
import pandas as pd
import tensorflow as tf
from tensorflow import keras
from tensorflow.keras import layers
from sklearn.datasets import fetch_california_housing
from sklearn.model_selection import train_test_split
from sklearn.preprocessing import StandardScaler

SEED = 42
np.random.seed(SEED)
tf.random.set_seed(SEED)

housing = fetch_california_housing()
X, y = housing.data, housing.target
feature_names = housing.feature_names

# ── 분할 → 스케일링 (순서 엄수) ──
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.2, random_state=SEED)
X_train, X_val, y_train, y_val = train_test_split(X_train, y_train, test_size=0.2, random_state=SEED)

scaler = StandardScaler()
X_train = scaler.fit_transform(X_train)
X_val = scaler.transform(X_val)

import numpy as np

SEED = 42


def build(hidden_units, dropout=0.0, batchnorm=False, input_shape=(8,)):
    """구조를 파라미터로 받아 모델을 만드는 함수"""
    tf.random.set_seed(SEED)
    model = keras.Sequential([layers.Input(shape=input_shape)])

        if batchnorm:
            model.add(layers.Dense(u, use_bias=False))
            model.add(layers.BatchNormalization())
            model.add(layers.Activation("relu"))
        else:
            model.add(layers.Dense(u, activation="relu"))
        if dropout > 0:
            model.add(layers.Dropout(dropout))
    model.add(layers.Dense(1))
    model.compile(optimizer=keras.optimizers.Adam(1e-3), loss="mse", metrics=["mae"])
    return model

SEED = 42


def build(hidden, dropout=0.0, bn=False, lr=1e-3, input_shape=(8,)):
    tf.random.set_seed(SEED)
    m = keras.Sequential([layers.Input(shape=input_shape)])
    for u in hidden:
        if bn:
            m.add(layers.Dense(u, use_bias=False))
            m.add(layers.BatchNormalization())
            m.add(layers.Activation("relu"))

            m.add(layers.Dense(u, activation="relu"))
        if dropout > 0:
            m.add(layers.Dropout(dropout))
    m.add(layers.Dense(1))

    return m

## ⑤ 자주 하는 실수

### `input_shape` 에 샘플 수를 포함

```python
layers.Input(shape=X_train.shape)          # ✗ (13209, 8)
layers.Input(shape=(13209, 8))             # ✗
layers.Input(shape=X_train.shape[1:])      # ✓ (8,)
```

**에러 메시지**

```
ValueError: Input 0 of layer "dense" is incompatible with the layer:
expected axis -1 of input shape to have value 8, but received input with shape (None, 13209, 8)
```

**원인** — Keras는 첫 차원을 **배치 크기**로 자동 처리합니다. 넣으면 안 됩니다.

### 튜플에 쉼표를 빠뜨림

```python
layers.Input(shape=(8))        # ✗ 이건 정수 8
layers.Input(shape=(8,))       # ✓ 원소 1개짜리 튜플
```

```python
type((8))      # <class 'int'>
type((8,))     # <class 'tuple'>
```

> **파이썬 문법 문제입니다.** 괄호만으로는 튜플이 되지 않습니다. **쉼표가 튜플을 만듭니다.**

### `y` 를 2차원으로 만들어야 한다고 착각

```python
y_train = y_train.reshape(-1, 1)      # 안 해도 됩니다
```

Keras는 `(n,)` 과 `(n, 1)` 을 모두 받습니다. **다만 섞어 쓰면 문제가 생깁니다.**

```python
y_train.shape                       # (13209,)
model.predict(X_val).shape          # (3303, 1)
y_val - model.predict(X_val)        # (3303, 3303) ← ★ 사고
```

**해결** — 예측에 `.ravel()` 을 붙여 **1차원으로 통일**하세요.

### 정형 데이터에 Conv1D를 씀

```python
layers.Conv1D(32, 3, activation="relu")     # ✗ 표에는 의미 없음
```

**원인** — "딥러닝이니까 Conv를 써야 하나?"라는 오해.
**해결** — Conv는 **인접한 것끼리 관계가 있을 때** 씁니다. 표의 열은 인접성이 없습니다. (Step 5)

> **예외** — 시계열 데이터를 표로 만든 경우(`t-1, t-2, t-3` 열)에는 인접성이 있으므로 Conv1D가 유효합니다.
> 하지만 그건 "시계열"이지 일반 정형 데이터가 아닙니다.

### Dropout을 출력층 뒤에 넣음

```python
layers.Dense(1),
layers.Dropout(0.3),        # ✗
```

**증상** — 예측값이 무작위로 0이 됩니다. 학습 손실이 이상하게 튑니다.
**해결** — 규제는 **은닉층 뒤**에만.

### BatchNorm을 쓰면서 `use_bias=True` 를 그대로 둠

```python
layers.Dense(64, activation="relu"),         # 편향 64개
layers.BatchNormalization(),                 # BN이 평균을 빼므로 편향이 무의미
```

**해결** — `use_bias=False` 로. 성능 차이는 미미하지만 파라미터 낭비를 막습니다.

### 규제를 넣었는데 왜 val이 train보다 좋은지 이해 못 함

```
train_MAE 0.3948   val_MAE 0.3903      ← val이 더 좋다?
```

**정상입니다.** 원인 2가지:

| 원인 | 설명 |
|---|---|
| **Dropout** | 학습 시에는 노드를 끄고, 검증 시에는 전부 켬 → 검증이 유리 |
| 손실 계산 시점 | `train_loss` 는 에폭 **도중** 평균, `val_loss` 는 에폭 **끝**에 측정 |

> **[Day 117](day-117.md)의 패턴 ⑤가 이것입니다.** 문제가 아니라 정상 동작입니다.
> **단, 격차가 크면(0.1 이상)** 검증셋이 너무 쉽거나 분할이 잘못된 것일 수 있습니다.

### 층을 늘렸는데 성능이 떨어짐

```
2층: val_MAE 0.384
5층: val_MAE 0.412        ← 왜 나빠지지?
```

**원인 3가지**

| 원인 | 확인 | 해결 |
|---|---|---|
| 과적합 | train은 좋아졌는가 | 규제 추가 |
| 학습이 안 됨 | train도 나쁜가 | 학습률 조정, BN 추가 |
| **깊이가 불필요** | 2층에서 이미 충분한가 | **되돌리기** |

> **정형 데이터에서는 세 번째가 가장 흔합니다.** 되돌리는 것이 답입니다.
> **"층을 늘렸는데 나빠졌다"는 것은 실패가 아니라 유용한 실험 결과입니다.** 기록표에 남기세요.

파라미터 / 샘플 = 53,377 / 1,200 = 44.5
```

| 비율 | 상태 |
|---|---|
| 44.5 | **위험 구간 (10~100)** |

**샘플 하나당 파라미터가 44개**입니다. 모델이 데이터를 외울 여력이 충분합니다.

```

```

```
학습 샘플 수 × (0.3 ~ 3) = 목표 파라미터 수
```

예: 800행이면 파라미터 240~2,400개 → `[32, 16]` 정도가 출발점.

```

  val_MAE   0.7215   ← 가장 나쁨
  격차      +0.5311  ← 파국적
```

**train_MAE만 보고 있었다면 "이 모델이 최고"라고 결론 냈을 것입니다.**
[Day 079](../03-ml/day-079.md)의 진단 순서(train이 낮은가 → 격차가 큰가)가 여기서도 그대로 적용됩니다.

**4. 데이터가 많으면 큰 모델의 피해가 줄어듭니다.**

```
최적 대비 [512,512,512]의 손해:
    500행: +0.1728  (31% 나빠짐)
  2,000행: +0.1042  (23%)

```

**데이터가 충분하면 모델이 좀 커도 크게 손해 보지 않습니다.**
"일단 크게 만들고 규제로 잡는다"는 전략이 **데이터가 많을 때만** 유효한 이유입니다.

**실무 판단 순서**

```
① 학습 샘플 수를 센다
② 파라미터 목표 = 샘플 수 × 0.3 ~ 3
③ 그 범위에서 구조를 잡는다
④ 학습 후 격차를 본다
      격차 < 0.02  → 모델을 키워 볼 여지가 있음
      격차 > 0.05  → 규제를 넣거나 모델을 줄임
⑤ 데이터를 더 모을 수 있으면 그게 최선  (Day 079 결론)
```

> **데이터가 500행이면 딥러닝이 아니라 릿지 회귀나 랜덤포레스트를 써야 합니다.**

## 오늘의 정리

| 개념 | 핵심 |
|---|---|
| 정형 vs 이미지 | 표는 **열 순서에 의미가 없음** → CNN 불필요, Dense만 |
| `input_shape` | **`X_train.shape[1:]`** — 샘플 수는 빼고. 하드코딩 금지 |
| `(8)` vs `(8,)` | 쉼표가 튜플을 만듭니다 |
| Dense 파라미터 | **(입력 × 출력) + 출력** |
| BN 파라미터 | 노드당 4개 (γ, β, 이동평균, 이동분산). **뒤의 2개는 non-trainable** |
| 파라미터/샘플 | **0.3~3이 적정.** 10 넘으면 위험, 100 넘으면 확정적 과적합 |
| 층 수 | 정형 데이터는 **1~2층에서 시작.** 깊이가 답이 아님 |
| 노드 수 | 깔때기형(64→32) 기본. **2의 거듭제곱은 관행일 뿐** |
| 튜닝 우선순위 | **학습률 > 전처리 > 구조** |
| BN 위치 | `Dense(use_bias=False) → BN → Activation` |
| Dropout 위치 | **은닉층 뒤에만.** 출력층 뒤는 금지 |
| BN + Dropout | 함께 쓰면 나빠질 수 있음. **하나씩 넣어 보기** |
| val < train | Dropout이 있으면 **정상** |
| 공정한 비교 | 같은 데이터·분할·seed·에폭·학습률. **한 번에 하나만 변경** |

**오늘 반드시 기억할 세 가지**

> ② **정형 데이터에서 깊이는 답이 아닙니다.** 1~2층에서 시작해 필요할 때만 늘리세요.
> ③ **구조를 17배 키워 얻는 것보다 학습률 하나를 잘못 잡아 잃는 것이 큽니다.**
