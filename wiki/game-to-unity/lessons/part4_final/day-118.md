## 3. 개념

### 3-1. 릴리즈 빌드 설정

**왜 필요한가** — 베타와 다르다.

| 항목 | 베타 | **릴리즈** |
|---|---|---|
| Development Build | ✔ | **✗** |
| Autoconnect Profiler | ✗ | ✗ |
| Script Debugging | ✗ | ✗ |
| Compression | LZ4 | **LZ4HC** |
| Scripting Backend | Mono | Mono 또는 **IL2CPP** |
| 치트 | 비활성 | **제거** |
| 디버그 HUD | 활성 | **제거** |
| 오류 표시 | 활성 | **제거** |

```
   ★ Development Build를 끄면

   ① #if DEVELOPMENT_BUILD 코드가 자동 제거
   ② 성능이 약간 향상
   ③ 프로파일러 연결 불가
```

```csharp
    // ★ 이미 처리돼 있어야 한다 (Day 106·117)
#if UNITY_EDITOR || DEVELOPMENT_BUILD
    // 치트, 디버그 HUD, 측정 도구
#endif
```

```
   ★ 확인 방법

   릴리즈 빌드에서 F1~F5, F3을 눌러 본다
   → 아무 일도 안 일어나야 한다
```

### 3-2. IL2CPP 판단

**왜 필요한가** — 시간과 이득의 교환.

| | Mono | IL2CPP |
|---|---|---|
| 빌드 시간 | 2~5분 | **15~40분** |
| 실행 속도 | 보통 | **빠름** (10~30%) |
| 빌드 크기 | 작음 | 약간 큼 |
| 역컴파일 | 쉬움 | **어려움** |
| 안정성 | 높음 | 높음 (하지만 새 빌드) |

```
   ★ 4주 프로젝트 판단

   시간이 충분하면:  IL2CPP  (성능·보안)
   오늘 여유가 없으면: Mono   ★ 안전
```

```
   ⚠️ 오늘 처음 IL2CPP를 시도하면

   ① 빌드가 40분 걸린다
   ② 새로운 오류가 날 수 있다 (Managed Stripping)
   → Day 120 전날에 위험

   ★ Mono로 가는 것도 정당한 선택
```

```
   ★ 시도한다면

   ① 먼저 Mono로 빌드해 둔다 (안전판)
   ② IL2CPP를 시도한다
   ③ 문제가 있으면 Mono를 쓴다
```


```csharp
    // ★ 고해상도 스크린샷 (개발 빌드)
#if UNITY_EDITOR || DEVELOPMENT_BUILD
    private void Update()
    {
        if (Input.GetKeyDown(KeyCode.F12))
        {
            string path = $"Screenshot_{System.DateTime.Now:HHmmss}.png";
            ScreenCapture.CaptureScreenshot(path, 2);   // 2배 해상도
            DebugUtil.Log($"[스크린샷] {path}");
        }
    }
#endif
```
