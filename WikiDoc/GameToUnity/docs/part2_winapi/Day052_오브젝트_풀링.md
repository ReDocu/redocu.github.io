## 3. 개념

### 3-1. 오브젝트 풀링이란

**왜 필요한가** — 생성/소멸 비용을 0으로 만든다.

```
   ┌──────────────────────────────────────────────────────────┐
   │  프로그램 시작 시 (한 번만)                                │
   │                                                           │
   │    Bullet 1000개를 미리 만든다  →  전부 "비활성"           │
   │                                                           │
   ├──────────────────────────────────────────────────────────┤
   │  게임 중                                                   │
   │                                                           │
   │    발사     →  비활성 중 하나를 찾아 "활성"으로            │
   │    화면 밖  →  그 오브젝트를 "비활성"으로                  │
   │                                                           │
   │    ★ new / delete 가 한 번도 일어나지 않는다              │
   ├──────────────────────────────────────────────────────────┤
   │  프로그램 종료 시 (한 번만)                                │
   │                                                           │
   │    1000개를 전부 delete                                   │
   └──────────────────────────────────────────────────────────┘
```

```
   풀 크기 8 (실제로는 1000개)

   idx    0    1    2    3    4    5    6    7
         [●]  [●]  [○]  [●]  [○]  [○]  [○]  [○]      ● 활성  ○ 비활성

   [발사]   비활성 중 하나(idx 2)를 켠다   ──▶  new 없음
   [화면밖] 그 칸을 끈다 (idx 0 → ○)      ──▶  delete 없음
   [꽉 참]  이번 발사는 무시               ──▶  풀 크기 = 성능 상한
```

### 3-3. 가장 단순한 풀 — 선형 탐색

**왜 필요한가** — 원리를 먼저 이해한다.

```cpp
template <typename T>
class SimplePool
{
public:
    void Init(int capacity)
    {
        m_capacity = capacity;
        m_objects = new T[capacity];          // ★ 한 번만
        m_active  = new bool[capacity];

        for (int i = 0; i < capacity; i++)
            m_active[i] = false;
    }

    void Release()
    {
        delete[] m_objects;
        delete[] m_active;
        m_objects = nullptr;
        m_active  = nullptr;
    }

    T* Get()
    {
        for (int i = 0; i < m_capacity; i++)  // ★ Day 11 패턴 ⑤
        {
            if (!m_active[i])
            {
                m_active[i] = true;
                m_activeCount++;
                return &m_objects[i];
            }
        }
        return nullptr;                        // 풀이 꽉 참
    }

    void Return(T* obj)
    {
        int idx = (int)(obj - m_objects);      // 포인터 뺄셈으로 인덱스 계산
        if (idx < 0 || idx >= m_capacity) return;

        if (m_active[idx])
        {
            m_active[idx] = false;
            m_activeCount--;
        }
    }

private:
    T*    m_objects  = nullptr;
    bool* m_active   = nullptr;
    int   m_capacity = 0;
    int   m_activeCount = 0;
};
```

```
   ★ 문제: Get() 이 O(n)

   풀 크기 1000, 900개가 활성이면
   → 빈 칸 하나 찾는 데 900번 검사
   → 초당 30번 발사면 27,000번 검사

   개선이 필요하다
```

### 3-4. 개선 ① — 마지막 위치 기억

**왜 필요한가** — 대부분의 경우 바로 다음 칸이 비어 있다.

```cpp
    T* Get()
    {
        for (int i = 0; i < m_capacity; i++)
        {
            int idx = (m_lastIndex + i) % m_capacity;      // ★ 마지막 위치부터

            if (!m_active[idx])
            {
                m_active[idx] = true;
                m_lastIndex = (idx + 1) % m_capacity;
                m_activeCount++;
                return &m_objects[idx];
            }
        }
        return nullptr;
    }

private:
    int m_lastIndex = 0;
```

```
   ★ 대부분 첫 검사에서 찾는다

   O(n) → 평균 O(1)에 가까워진다
```

### 3-5. 개선 ② — 자유 목록 (free list)

**왜 필요한가** — 진짜 O(1). 실무에서 쓰는 방식.

```cpp
template <typename T>
class ObjectPool
{
public:
    void Init(int capacity)
    {
        m_capacity = capacity;
        m_objects  = new T[capacity];
        m_freeList = new int[capacity];
        m_active   = new bool[capacity];

        // 처음엔 전부 비어 있다
        for (int i = 0; i < capacity; i++)
        {
            m_freeList[i] = i;
            m_active[i]   = false;
        }
        m_freeCount = capacity;
    }

    T* Get()
    {
        if (m_freeCount <= 0) return nullptr;             // 꽉 참

        int idx = m_freeList[--m_freeCount];              // ★ O(1)
        m_active[idx] = true;
        return &m_objects[idx];
    }

    void Return(T* obj)
    {
        int idx = (int)(obj - m_objects);
        if (idx < 0 || idx >= m_capacity) return;
        if (!m_active[idx]) return;                       // 이중 반환 방지

        m_active[idx] = false;
        m_freeList[m_freeCount++] = idx;                  // ★ O(1)
    }

    int GetActiveCount() const { return m_capacity - m_freeCount; }
    int GetCapacity()    const { return m_capacity; }

private:
    T*    m_objects  = nullptr;
    int*  m_freeList = nullptr;                           // 비어 있는 인덱스 목록
    bool* m_active   = nullptr;
    int   m_capacity  = 0;
    int   m_freeCount = 0;
};
```

```
   자유 목록 동작 (풀 크기 5)

   초기:
     freeList = [0, 1, 2, 3, 4]   freeCount = 5

   Get() 3번:
     freeList = [0, 1, ?, ?, ?]   freeCount = 2
     반환된 인덱스: 4, 3, 2

   Return(2):
     freeList = [0, 1, 2, ?, ?]   freeCount = 3

   ★ 스택처럼 동작한다. 전부 O(1)
```

### 3-6. ⚠️ 재사용 시 초기화 — 가장 흔한 버그

**왜 필요한가** — 이전 값이 남아 있으면 이상하게 동작한다.

### 3-7. 풀 크기 결정

**왜 필요한가** — 너무 작으면 발사가 씹히고, 너무 크면 메모리 낭비.

```
   필요한 크기 = 최대 동시 존재 개수 × 여유(1.2~1.5배)

   플레이어 총알
     초당 20발 × 화면 체류 1.2초 = 24발
     × 여유 1.5 = 36  →  50개로 잡는다

   적 총알
     적 20기 × 8발 × 초당 1.5회 × 체류 2초 = 480발
     × 여유 1.3 = 624  →  1000개

   이펙트
     동시 폭발 5개 × 6조각 = 30
     × 여유 2.0 = 60  →  100개
```

**메모리 계산**

```
   Bullet 하나 약 64바이트

   1000개 × 64바이트 = 64KB      ← 아무것도 아니다

   ★ 오브젝트 풀의 메모리 비용은 대부분 무시할 수준이다
     넉넉하게 잡는다
```

**풀이 꽉 찼을 때의 정책**

| 정책 | 동작 | 적합 |
|---|---|---|
| **무시** | 이번 발사를 안 한다 | 총알 ← **기본** |
| 가장 오래된 것 재사용 | 강제로 하나 회수 | 이펙트 |
| 풀 확장 | `realloc`으로 늘린다 | 예측 불가한 경우 |
| 경고 후 무시 | 로그 남기고 무시 | 개발 중 ← **권장** |

```cpp
    Bullet* b = m_bulletPool.Get();

    if (!b)
    {
        DebugLog("[Pool] 총알 풀 부족! (크기 %d)\n", m_bulletPool.GetCapacity());
        return;                               // 이번 발사 무시
    }
```

> **개발 중에는 로그를 남긴다.** 풀 크기가 부족한지 알 수 있다.

### 3-8. `Scene`과의 통합

**왜 필요한가** — Day 40의 `Scene`은 `delete`를 한다. 풀 오브젝트는 `delete`하면 안 된다.

```
   문제

   Scene::RemoveInactive()
       delete m_objects[i];        ← 풀 오브젝트를 delete 하면 크래시
```

**해결 방법 3가지**

| 방법 | 설명 |
|---|---|
| A. 풀 오브젝트를 Scene에 안 넣는다 | 풀이 직접 Update/Render |
| **B. Scene이 소유권을 구분한다** | `IsPooled()` 플래그 ← **이걸 쓴다** |
| C. Scene 자체를 풀 기반으로 | 전면 개편 |

```cpp
class GameObject
{
public:
    bool IsPooled() const { return m_pooled; }
    void SetPooled(bool p) { m_pooled = p; }

    virtual void OnReturnToPool() {}          // 풀로 돌아갈 때

protected:
    bool m_pooled = false;
};
```

```cpp
void Scene::RemoveInactive()
{
    for (int i = m_count - 1; i >= 0; i--)
    {
        if (m_objects[i]->IsActive()) continue;

        if (m_objects[i]->IsPooled())
        {
            m_objects[i]->OnReturnToPool();   // 풀로 반환
            // delete 하지 않는다!
        }
        else
        {
            m_objects[i]->Release();
            delete m_objects[i];
        }

        m_objects[i] = m_objects[--m_count];
        m_objects[m_count] = nullptr;
    }
}
```

**더 깔끔한 방법 — 풀이 관리하는 매니저**

```cpp
class BulletManager
{
public:
    void Init(int capacity) { m_pool.Init(capacity); }

    Bullet* Fire(double x, double y, double vx, double vy, int tag)
    {
        Bullet* b = m_pool.Get();
        if (!b) return nullptr;

        b->Setup(x, y, vx, vy, tag);
        return b;
    }

    void Update(double dt)
    {
        for (int i = 0; i < m_pool.GetCapacity(); i++)
        {
            Bullet* b = m_pool.GetAt(i);
            if (!b || !b->IsActive()) continue;

            b->Update(dt);

            if (!b->IsActive())               // Update 중에 비활성화됨
                m_pool.Return(b);
        }
    }

    void Render(Renderer& r)
    {
        for (int i = 0; i < m_pool.GetCapacity(); i++)
        {
            Bullet* b = m_pool.GetAt(i);
            if (b && b->IsActive()) b->Render(r);
        }
    }

private:
    ObjectPool<Bullet> m_pool;
};
```

> **이 방식이 더 명확하다.** 풀 오브젝트는 `Scene`에 안 넣고 매니저가 직접 관리한다.
> `Scene`은 플레이어처럼 개수가 고정된 것만 담는다.

### 3-9. 캐시 친화성

**왜 필요한가** — 오브젝트 풀의 숨은 이득. 어제 3-3절의 문제 해결.

```
   [ new/delete 방식 ]  힙 여기저기에 흩어짐

   0x1000  0x8420  0x3F10  0xA800 ...
   → 순회 시 캐시 미스 다발


   [ 오브젝트 풀 ]  연속된 배열

   T* m_objects = new T[1000];

   0x1000  0x1040  0x1080  0x10C0 ...
   → 한 번 읽으면 캐시에 여러 개가 들어온다
   → 순회가 훨씬 빠르다
```

```
   ★ 이것이 성능 개선의 큰 부분이다

   할당 비용 절감:  약 20%
   캐시 개선:       약 30~50%
```

### Step 1 — `ObjectPool` 템플릿

3-5절의 코드를 `Engine/ObjectPool.h`로 만든다.

```cpp
#pragma once
#include "EngineCommon.h"

template <typename T>
class ObjectPool
{
public:
    ~ObjectPool() { Release(); }

    bool Init(int capacity)
    {
        Release();
        if (capacity <= 0) return false;

        m_objects  = new T[capacity];
        m_freeList = new int[capacity];
        m_active   = new bool[capacity];

        for (int i = 0; i < capacity; i++)
        {
            m_freeList[i] = i;
            m_active[i]   = false;
        }

        m_capacity  = capacity;
        m_freeCount = capacity;

        DebugLog("[Pool] 초기화: %d개 (%.1f KB)\n",
                 capacity, capacity * sizeof(T) / 1024.0);
        return true;
    }

    void Release()
    {
        delete[] m_objects;   m_objects = nullptr;
        delete[] m_freeList;  m_freeList = nullptr;
        delete[] m_active;    m_active = nullptr;
        m_capacity = m_freeCount = 0;
    }

    T* Get()
    {
        if (m_freeCount <= 0)
        {
            m_failCount++;
            return nullptr;
        }

        int idx = m_freeList[--m_freeCount];
        m_active[idx] = true;

        m_objects[idx].Reset();               // ★ 자동 초기화
        m_getCount++;

        return &m_objects[idx];
    }

    void Return(T* obj)
    {
        if (!obj) return;

        int idx = (int)(obj - m_objects);
        if (idx < 0 || idx >= m_capacity) return;
        if (!m_active[idx]) return;           // 이중 반환 방지

        m_active[idx] = false;
        m_freeList[m_freeCount++] = idx;
        m_returnCount++;
    }

    T*   GetAt(int i)      { return (i >= 0 && i < m_capacity) ? &m_objects[i] : nullptr; }
    bool IsActiveAt(int i) const { return (i >= 0 && i < m_capacity) && m_active[i]; }

    int  GetCapacity()    const { return m_capacity; }
    int  GetActiveCount() const { return m_capacity - m_freeCount; }
    int  GetFailCount()   const { return m_failCount; }

private:
    T*    m_objects  = nullptr;
    int*  m_freeList = nullptr;
    bool* m_active   = nullptr;
    int   m_capacity = 0, m_freeCount = 0;

    int   m_getCount = 0, m_returnCount = 0, m_failCount = 0;
};
```

**✅ 여기까지 하면** — 범용 풀이 준비된다.

### Step 3 — `BulletManager`

3-8절의 코드를 구현한다.

```cpp
class BulletManager
{
public:
    bool Init(Core* core, int capacity)
    {
        m_core = core;
        return m_pool.Init(capacity);
    }

    Bullet* Fire(double x, double y, double vx, double vy, int tag)
    {
        Bullet* b = m_pool.Get();

        if (!b)
        {
            DebugLog("[Pool] 총알 부족 (크기 %d)\n", m_pool.GetCapacity());
            return nullptr;
        }

        b->Setup(x, y, vx, vy, tag);
        b->SetCore(m_core);
        return b;
    }

    void Update(double dt)
    {
        int cap = m_pool.GetCapacity();

        for (int i = 0; i < cap; i++)
        {
            if (!m_pool.IsActiveAt(i)) continue;

            Bullet* b = m_pool.GetAt(i);
            b->Update(dt);

            if (!b->IsActive())
                m_pool.Return(b);             // ★ 자동 회수
        }
    }

    void Render(Renderer& r)
    {
        int cap = m_pool.GetCapacity();

        for (int i = 0; i < cap; i++)
            if (m_pool.IsActiveAt(i))
                m_pool.GetAt(i)->Render(r);
    }

    void Clear()
    {
        int cap = m_pool.GetCapacity();
        for (int i = 0; i < cap; i++)
            if (m_pool.IsActiveAt(i))
                m_pool.Return(m_pool.GetAt(i));
    }

    ObjectPool<Bullet>& GetPool() { return m_pool; }

private:
    ObjectPool<Bullet> m_pool;
    Core* m_core = nullptr;
};
```

**✅ 여기까지 하면** — 총알 관리가 매니저로 모인다.

## 6. 자주 막히는 곳

| 증상 | 원인 | 해결 |
|---|---|---|
| 이상한 방향으로 날아감 | **`Reset` 누락** | `Get()`에서 자동 호출 |
| 총알이 안 나감 | 풀이 꽉 참 | 크기 늘리기, 회수 확인 |
| 크래시 | 풀 오브젝트를 `delete` | `IsPooled()` 구분 또는 매니저 방식 |
| 이중 반환 크래시 | 같은 오브젝트를 두 번 `Return` | `m_active` 검사 |
| 활성 수가 계속 증가 | 회수 조건 미충족 | 화면 밖 판정 확인 |
| 성능이 그대로 | 풀을 만들었는데 여전히 `new` | 발사 코드 확인 |
| `obj - m_objects` 오류 | 다른 풀의 오브젝트 | 인덱스 범위 검사 |
| 템플릿 링크 오류 | `.cpp`에 정의 | 템플릿은 **헤더에 전부** |
| 메모리 사용량 급증 | 풀 크기 과다 | 최대 활성 × 1.3 |
